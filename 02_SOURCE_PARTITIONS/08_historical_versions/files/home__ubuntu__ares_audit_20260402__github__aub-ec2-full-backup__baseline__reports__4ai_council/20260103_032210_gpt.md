아래 5개를 **24~48시간 우선순위 TOP5(코드/아키텍처/전략)**로 고정하고, 각 항목을 **48시간 자동 루프(1 실험 정의 → 2 게이트 → 3 기대 관측치)**로 돌려라.  
(우선 점검 순서: **누수 → 과최적화/폴드 퇴화 → 서바이버십 → 비용 미반영 → 운영 리스크**)

## TOP1) (운영/신뢰성) 리밸런스 로그/해시/MDD 결손을 “재현 가능” 상태로 패치
### (a) 왜 필요한가
- 현재 ONE TRUTH에서 **lane_hash/run_hash None**, **worst_mdd None**, **rebalance pinpoint가 파일 포맷/경로 오류로 실패**.  
- 이 상태에선 “성능이 안 움직임”이 **전략 문제인지/로그 결손인지** 분리가 불가능 → 자동루프가 무의미해짐(운영 리스크 최상).

### (b) 위험/부작용
- 로깅/요약 지표 산출이 바뀌면서 **기존 챔피언과 수치 비교가 흔들릴 수 있음**(단, 그게 정상: 이전 수치가 불완전할 가능성).
- IO 증가로 런타임 소폭 증가.

### (c) 최소 실험(1개) 안의 ablation 2~3개
- **실험 정의(패치 + ablation)**
  1) 백테스트 결과 JSON에 `lane_hash`, `run_hash`, `worst_mdd`, `turnover`, `trade_count`, `cost_drag_bps`를 **필수 필드**로 넣어라.
  2) 리밸런스 로그를 **항상** `rebalance.jsonl`(line-delimited)로 저장하고, 필요 시 `rebalance.csv`도 같이 뽑아라.
  3) ablation(같은 코드패치에서 모드만 바꿔 확인):
     - A: jsonl만
     - B: jsonl+csv 동시
     - C: pinpoint tool이 jsonl 직접 읽도록 수정(레거시 csv 의존 제거)
- **게이트**
  - `aub_rebalance_pinpoint.py`가 base/cand 모두에서 **에러 없이 리포트 생성**해야 통과.
  - 챔피언/캔디데이트 모두 `worst_mdd != None`, `lane_hash/run_hash != None` 필수.
- **기대 관측치**
  - “성능 정체” 원인 분해가 가능한 최소 로그셋 확보(리밸런스 타이밍/턴오버/비용/익절손절 등).

### (d) PASS 조건
- 2회 연속 자동루프에서 **pinpoint 리포트 생성 100% 성공** + 필수 필드 결손 0건.

## TOP2) (누수 최우선) 시점 정렬(lookahead) 강제 + ETF는 “관측 지표”로만 사용
### (a) 왜 필요한가
- OOS가 높은데 **degenerate_folds(1,2,3,8)**가 있다는 건 “일부 구간에서 트레이드가 안 됨/신호가 깨짐/시점 오류로 필터링됨” 가능성이 큼.  
- 특히 Tech/Healthcare는 갭/뉴스 반응이 커서 **당일 종가 기반 특징이 체결 시점과 섞이면** 쉽게 누수.

### (b) 위험/부작용
- 누수 제거 시 **성능이 즉시 하락**할 수 있음(하지만 그게 진짜 성능).
- 시프트로 신호가 약해져 거래 빈도 감소 가능.

### (c) 최소 실험(1개) 안의 ablation 2~3개
- **실험 정의**
  1) 모든 특징/라벨에 대해 `asof_timestamp`를 도입하고, **주문 시점 이전 데이터만** 사용하도록 강제해라.
     - 예: “D일 종가로 계산한 신호”는 **D+1일 시가(또는 D+1일 VWAP)**에서만 체결되도록 룰을 박아라.
  2) ETF는 매매 금지, 관측만: `QQQ`, `XLV`, `SPY`(옵션: `VIX` 대체 지표가 데이터에 있으면 사용)로 **레짐/리스크 오프 신호**만 만들고 **항상 1일 이상 시프트**해라.
  3) ablation:
     - A: 현재 체결 가정 유지 + feature 1일 시프트
     - B: 체결을 다음날 시가로 강제 + feature 시프트
     - C: B + ETF 레짐 신호 추가(관측만)
- **게이트**
  - 누수 방지 유닛체크(샘플): “어떤 피처도 체결 타임스탬프 이후 값을 참조하지 않음”을 assertion으로 실패시키는 테스트를 넣어라.
  - OOS min이 과도하게 좋아지는(비현실) 패턴이 사라지는지 확인해라(예: min이 갑자기 양(+)으로 고정되는 등).
- **기대 관측치**
  - OOS 평균은 하락 가능하지만, **폴드 퇴화 감소** 및 성능 분산이 더 현실화.
  - 레짐 신호(C)에서 **드로다운 구간 노출 감소** 신호가 관측.

### (d) PASS 조건
- degenerate_folds 개수 감소(예: 4개 → 1개 이하) + OOS mean이 급락하더라도 **재현성/현실성 개선**(거래수, 노출, 비용 포함 리포트가 일관).

## TOP3) (과최적화/서바이버십/폴드 퇴화) “폴드 유효성 게이트”와 Purge/Embargo 적용
### (a) 왜 필요한가
- degenerate_folds는 대개 **데이터 분할/거래가능 일수/필터 조건**이 맞물려 “학습/검증이 사실상 빈 구간”이 되는 현상.
- 이 상태에서 하이퍼파라미터가 **우연히 특정 구간만 맞추는 과최적화**를 유발.

### (b) 위험/부작용
- 게이트가 엄격하면 실험이 자주 FAIL → 탐색 속도 저하.
- 데이터 사용량 감소로 평균 성능이 내려갈 수 있음.

### (c) 최소 실험(1개) 안의 ablation 2~3개
- **실험 정의**
  1) 폴드별 최소 조건을 코드로 강제해라:
     - `trade_count >= N` (예: 30)
     - 평균 노출(`avg_exposure`)이 너무 낮지 않기(예: >= 0.10)
     - 검증기간 최소 거래일(예: 60 trading days)
  2) 시계열 CV에 **purge window + embargo**(예: purge 5일, embargo 1~2일) 추가해라(라벨/피처 겹침 제거).
  3) ablation:
     - A: 기존 split + 유효성 게이트만
     - B: A + purge/embargo
     - C: B + “폴드 실패 시 해당 실험 전체 FAIL”(챔피언 후보로 승격 금지)
- **게이트**
  - 유효 폴드 비율 >= 90% (예: 10폴드 중 9폴드 유효) 아니면 FAIL.
- **기대 관측치**
  - OOS mean이 내려가도 **폴드 간 변동/퇴화가 줄고**, “안 움직임”이 데이터 문제인지 전략 문제인지 분리됨.

### (d) PASS 조건
- degenerate_folds = 0(또는 1 이하) + OOS mean이 동일/소폭 하락하더라도 **OOS min/분산이 더 안정적**이면 통과.

## TOP4) (비용 미반영) 비용/슬리피지/턴오버를 “의사결정 게이트”로 승격
### (a) 왜 필요한가
- 현재 로그 흐름에서 리밸런스 데이터가 깨져 있어 **실제 매매 비용/턴오버가 모델에 반영되지 않았을 가능성**이 큼.
- Tech/Healthcare 대형주는 스프레드가 좁아도 잦은 리밸런스는 비용 누적이 큼 → “백테스트만 좋고 실전 붕괴” 대표 원인.

### (b) 위험/부작용
- 비용을 넣으면 백테스트 성능이 하락.
- 과도한 비용 가정은 기회를 과소평가.

### (c) 최소 실험(1개) 안의 ablation 2~3개
- **실험 정의**
  1) 비용 모델을 명시적으로 넣어라(최소):
     - 고정 커미션(0으로 둬도 됨) + **거래대금 대비 bps 슬리피지**(예: 2~10bps 범위)
     - (가능하면) 변동성/거래대금 기반 슬리피지(단순 함수)
  2) 의사결정에 “턴오버 상한” 또는 “리밸런스 최소 변화량(Δweight threshold)”을 넣어라.
  3) ablation:
     - A: 비용 0 (기준선)
     - B: 5bps 슬리피지 + Δweight threshold
     - C: 10bps 슬리피지 + turnover cap
- **게이트**
  - net-of-cost OOS mean이 **비용 0 대비 급락**하면(예: -30% 이상) 해당 전략군은 FAIL(구조적으로 과매매).
  - `turnover`, `cost_drag_bps`가 리포트에 항상 찍혀야 함.
- **기대 관측치**
  - 비용 민감한 전략은 자동으로 걸러지고, 살아남는 전략은 거래 빈도/리밸런스 폭이 줄어듦.

### (d) PASS 조건
- 비용(B 또는 C)에서도 OOS mean 유지(또는 소폭 하락) + cost_drag가 설명 가능한 수준으로 고정.

## TOP5) (노출/레짐) 8~14 종목 고정 바스켓 + 리스크오프(현금) 오버레이로 MDD 제어
### (a) 왜 필요한가
- 현재 exposure max가 0.84까지 올라가며, worst_mdd가 비어있음 → **리스크 예산이 통제되지 않았을 가능성**.  
- 자동루프에서 안정적으로 굴리려면 “수익” 이전에 **노출/드로다운/레짐 대응**이 먼저.

### (b) 위험/부작용
- 리스크오프가 과하면 수익 기회 손실(언더인베스트).
- 바스켓 고정은 단기 알파를 제한할 수 있음(대신 운영 안정성↑).

### (c) 최소 실험(1개) 안의 ablation 2~3개
- **실험 정의**
  1) 매매 유니버스를 **미국 Tech+Healthcare 8~14개**로 고정해라(서바이버십 리스크 최소화 목적: 초대형주 중심).
     - 예시(12): AAPL, MSFT, NVDA, AMZN, GOOGL, META, AVGO, ORCL / UNH, LLY, JNJ, ABBV  
       *(실험 동안 목록 고정; ETF 매매 금지)*
  2) 포지션 사이징을 **변동성 타겟(예: 목표 포트폴리오 vol)** 또는 **최대 노출 상한(예: 0.60)**으로 강제해라.
  3) ETF 관측 기반 리스크오프(현금 비중 확대):
     - 예: `QQQ < QQQ_50DMA` 또는 `SPY < SPY_200DMA`면 총 노출을 0.3으로 축소
  4) ablation:
     - A: 노출 상한만(0.6)
     - B: A + vol targeting
     - C: B + ETF 레짐 리스크오프
- **게이트**
  - worst_mdd가 산출되어야 하고, 이전 대비 개선(또는 동일) 없으면 FAIL.
  - OOS min이 극단적으로 나빠지는 케이스가 줄어야 함.
- **기대 관측치**
  - 평균 수익이 동일하지 않아도 **좌측 꼬리(OOS min, MDD)가 개선**되고, 레짐 구간에서 노출이 자동으로 줄어듦.

### (d) PASS 조건
- worst_mdd 개선(또는 동일) + OOS min 개선(또는 동일) + 폴드 퇴화 없음.

# 24~48시간 실행 순서(명령형 체크리스트)
1) **로그/요약 패치부터 적용**해라(TOP1). 핀포인트 리포트가 2회 연속 생성될 때까지 다른 실험을 “승격”시키지 마라.  
2) **누수 방지 시점 정렬 강제**해라(TOP2). 체결 시점/피처 시프트/ETF 지표 시프트를 assertion으로 봉인해라.  
3) **폴드 유효성 게이트 + purge/embargo**를 넣어라(TOP3). degenerate_folds가 남는 실험은 자동 FAIL 처리해라.  
4) **비용/턴오버를 의사결정 게이트로 올려라**(TOP4). net-of-cost 기준으로만 챔피언을 바꿔라.  
5) **유니버스 고정 + 노출/레짐 오버레이**를 마지막에 붙여라(TOP5). 드로다운/좌측꼬리 개선을 1순위로 평가해라.

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **각 런마다 자동 리포트**로 뽑아 “어디서 죽는지”를 바로 고정해라.

## 1) Trigger(신호 발생) 문제
- 지표: `signal_rate`(일별/종목별 신호 발생 비율), 연속 0 구간 길이
- 테스트: 특정 폴드에서 signal_rate가 0에 수렴하면 **피처 NaN/필터 과도/시점 오류** 의심

## 2) Apply(주문/체결/리밸런스 적용) 문제
- 지표: `orders_submitted`, `orders_filled`, `fill_ratio`, 리밸런스 이벤트 수
- 테스트: 신호는 있는데 포지션이 안 바뀌면 **Δweight threshold/리밸런스 스케줄/현금제약** 문제

## 3) Exposure(노출/사이징) 문제
- 지표: `avg_exposure`, `exposure_min/max`, 종목별 weight 분포, 상위 1~2종목 집중도(HHI)
- 테스트: OOS mean이 정체인데 exposure가 낮으면 **언더인베스트**; exposure가 높은데 MDD가 크면 **리스크 오버**

## 4) Cost(비용/턴오버) 문제
- 지표: `turnover`, `cost_drag_bps`, “gross vs net” 격차
- 테스트: gross는 괜찮은데 net이 죽으면 **과매매/슬리피지 민감** → Δweight threshold/턴오버 캡 강화

## 5) Regime(레짐) 문제
- 지표: 레짐별 성과 테이블(예: QQQ>50DMA vs <50DMA, SPY>200DMA vs <200DMA), 베타/상관 변화
- 테스트: 특정 레짐에서만 돈 벌면 **레짐 필터/노출 스케일링**이 필요(ETF는 관측만)

---

이 5개를 끝내면, 지금처럼 “OOS mean은 보이는데(3.32) 폴드는 퇴화하고 로그는 깨져서” 발생하는 **정체/혼란**을 먼저 제거할 수 있다. 이후에야 전략 아이디어(알파) 추가가 의미가 생긴다.
