[분석 요약]
현재 `oos_mean: 3.32`는 비정상적으로 높으며, `degenerate_folds`가 4개(약 40%)나 존재한다는 것은 모델이 특정 구간에 심하게 과적합되었거나, 생존 편향(Look-ahead)이 포함되었을 확률이 매우 높음. `worst_mdd: None`과 로그 로딩 실패는 현재 시스템이 '눈을 감고 운전 중'임을 시사함. 

따라서 **알파 탐색보다 파이프라인 무결성 확보와 과적합 제거가 최우선**임.

### 1. 24~48시간 우선순위 TOP 5 제안

1.  **[System] 로깅 파이프라인 및 MDD 계산 복구 (BLOCKER)**
    *   **이유:** `rebalance.csv` 포맷 에러 및 `worst_mdd: None` 해결 없이는 어떤 실험 결과도 신뢰 불가.
2.  **[Validation] 비용/슬리피지 스트레스 테스트 (Sanity Check)**
    *   **이유:** OOS Mean 3.32는 거래 비용이 과소평가되었을 때 나타나는 전형적인 수치. 현실적인 비용(bps) 적용 시 성능 붕괴 여부 확인 필요.
3.  **[Logic] Exposure Lower Bound 설정 (Zero-Exposure 방지)**
    *   **이유:** `exposure_min: 0.0`은 시장 이탈을 의미. 현금 비중 100%가 의도된 전략(Cash Protection)인지, 시그널 소실(Bug)인지 검증 필요.
4.  **[Strategy] Tech/Healthcare Sector Rotation 단순화**
    *   **이유:** Degenerate Fold를 줄이기 위해, 복잡한 ML 대신 섹터 모멘텀 기반의 단순 룰(Rule-based)로 Baseline을 재설정하여 안정성 확보.
5.  **[Robustness] Volatility Scaling 적용**
    *   **이유:** 변동성이 큰 구간에서 모델이 깨지는(Degenerate) 현상을 막기 위해, 포트폴리오 변동성을 특정 목표(Target Vol)에 맞추어 포지션 크기 조절.

### 2. 제안별 상세 실행 계획 (48h Loop)

#### (1) 비용/슬리피지 스트레스 테스트 (Cost Injection)
*   **(a) 필요성:** OOS Mean 3.32가 '잦은 매매'로 인한 착시인지 확인.
*   **(b) 위험:** 챔피언 모델이 즉시 폐기될 수 있음(성능 급락).
*   **(c) 실험 정의 (3 cases):**
    *   `EXP_COST_LOW`: 편도 수수료 5bps + 슬리피지 0bps (Base)
    *   `EXP_COST_MID`: 편도 수수료 10bps + 슬리피지 5bps (Realistic)
    *   `EXP_COST_HIGH`: 편도 수수료 15bps + 슬리피지 10bps (Conservative)
*   **(d) PASS 조건:** `EXP_COST_MID`에서 OOS Mean > 1.0 유지 & MDD < 20%.

#### (2) Exposure Min/Max 클램핑 (Exposure Clamping)
*   **(a) 필요성:** `exposure_min: 0.0` 상태에서 기회비용 발생 및 모델의 비정상적 'Zero Signal' 상태 디버깅.
*   **(b) 위험:** 하락장에서 손실 방어 실패 가능성.
*   **(c) 실험 정의 (3 cases):**
    *   `EXP_EXP_03`: Min Exposure 0.3 강제 (항상 30% 투자)
    *   `EXP_EXP_05`: Min Exposure 0.5 강제
    *   `EXP_EXP_DYNAMIC`: VIX < 20 일 때만 Min 0.5, 그 외 0.0 허용
*   **(d) PASS 조건:** Degenerate Folds 개수 감소(4개 미만) & OOS Sharpe > 1.5.

#### (3) Tech/Healthcare Top-Tier Momentum (Universe Refining)
*   **(a) 필요성:** Tech/Healthcare 중심 포트폴리오의 안정성 확보. 8~14개 종목으로 압축.
*   **(b) 위험:** 특정 섹터 붕괴 시 MDD 급증.
*   **(c) 실험 정의 (3 cases):**
    *   `EXP_UNIV_MOM`: Tech Top 5 + Health Top 5 (12개월 모멘텀 기준)
    *   `EXP_UNIV_LOWVOL`: Tech Top 5 + Health Top 5 (저변동성 기준)
    *   `EXP_UNIV_HYBRID`: Tech(모멘텀) + Health(저변동성) 혼합
*   **(d) PASS 조건:** `degenerate_folds`가 0~1개로 감소.

### 3. 48시간 자동 루프 정의 (Checklist)

#### A. 실험 정의 (Experiment Definition)

#### B. 게이트 (Gate - Go/No-Go)

- [ ] `degenerate_folds` 리스트가 현재(4개)보다 줄어들 것.

- **안정성 증가:** Min Exposure 설정 시, Degenerate Fold(특히 하락장이 아닌 횡보장에서 죽는 fold)가 회생해야 함.

### 4. 성능 정체 시 원인 분해 아이디어 (Decomposition Tree)

성능이 움직이지 않거나(개선 없음), 모든 Fold가 망가질 경우 다음 순서로 디버깅:

1.  **트리거(Trigger) 확인:**
    *   매매 신호가 너무 적게 발생하는가? (일주일 평균 거래 횟수 < 2회) -> *진입 장벽(Threshold) 완화*
2.  **노출(Exposure) 확인:**
    *   Min Exposure를 0.3으로 올렸는데도 수익이 안 나는가? -> *종목 선정(Universe) 자체가 열위함 (Tech/Health 대장주로 교체)*
3.  **비용(Cost) 확인:**
    *   Cost를 넣자마자 수익이 마이너스로 가는가? -> *평균 보유 기간(Holding Period)이 너무 짧음. 스캘핑 로직 제거 필요.*
4.  **레짐(Regime) 확인:**
    *   특정 연도(Fold 1, 2, 3)에서만 계속 죽는가? -> *해당 연도의 매크로 지표(금리, VIX)를 Feature에 강제 주입하여 모델이 학습하게 유도.*
