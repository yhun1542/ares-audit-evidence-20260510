## TOP5 우선순위 제안 (24~48h)

### 1) (누수 최우선) “시점(availability) 강제 + 1D 지연” 하드 게이트 추가
**(a) 왜 필요한지**
- 현재 candidate가 **tuning_min 0.05**로 극단적으로 흔들림(챔피언 0.43) → 정보가 “간헐적으로 과도하게 맞는” 패턴은 **시점 누수/리밸런싱 타이밍 누수**에서 자주 발생.
- Tech/Healthcare는 **실적/가이던스/임상 이벤트**로 점프가 많아, *발표 시각/정정/리비전*이 섞이면 백테스트가 쉽게 “미래를 봄”.

**(b) 위험/부작용**
- 성능이 단기적으로 하락할 수 있음(정상).  
- 너무 보수적으로 지연을 걸면 신호가 무뎌져 turnover만 남을 수 있음.

**(c) 최소 실험(1개 실험 안에 3-arm으로 동시 수행)**
- **EXP1: Availability/PIT Enforcement 3-arm**
  1. **ARM-A(베이스):** 현재 그대로
  2. **ARM-B:** 모든 피처/라벨/타깃 생성 입력을 **+1 trading day shift**(실거래 가능 시점 강제)
  3. **ARM-C:** 이벤트성 데이터(실적, 컨센서스, 공시, 의료 이벤트 등)가 있다면 **공식 발표 시각 기준 +1D**(EOD 체결 가정이면 특히 필수)

**(d) PASS 조건(게이트)**
- **Lockbox_mean 유지/개선**(챔피언 대비 -0.03 이내 열화 허용)하면서,
- **tuning_min이 0.20 이상**(극단 붕괴 제거)이고,
- **worst_mdd가 -0.10 이내**(현재 챔피언 worst_mdd ≈ -0.093 근처 유지)

**(48h 자동 루프 형태)**
- (1) 실험 정의: `EXP1 availability_1d_shift_multiarm`
- (2) 게이트: `tuning_min>=0.20 AND worst_mdd>=-0.10 AND lockbox_mean not worse than -0.03`
- (3) 기대 관측치: “평균은 비슷/소폭↓, 대신 min/분산 개선, 폴드별 급락 감소”

### 2) (서바이버십/기업행동) “Delist/CorpAction 무결성 + Universe 고정(8~14 Tech+HC)” 강제
**(a) 왜 필요한지**
- 미국주식 백테스트에서 **서바이버십(상장폐지/합병/티커변경)** 누락은 “평균 수익이 꾸준히 좋아 보이는” 전형적 원인.
- “Tech+Healthcare 8~14 종목” 제약이 있으면, **티커 교체/상장폐지 처리**가 성능을 왜곡할 확률이 더 커짐(소수 종목에 성과가 과의존).

**(b) 위험/부작용**
- 데이터 소스에 따라 delist 리턴을 정확히 못 넣으면 오히려 노이즈 증가.
- Universe 고정을 잘못하면 진짜 운용 가능 종목이 과도하게 줄 수 있음.

**(c) 최소 실험(1개 실험 안에 2-arm + 1 진단)**
- **EXP2: Survivorship & CorpAction Integrity**
  1. **ARM-A:** 현재 파이프라인
  2. **ARM-B:** (가능한 범위에서) **delist/merge/ticker-change 이벤트를 “관측 불가 시 0으로 두지 말고” 명시적으로 제거/대체 규칙 적용**  
     - 예: delist 시점 이후 데이터 사용 금지, 마지막 거래일 가격/리턴 처리 일관화
  3. **DIAG:** 종목별 PnL 기여도 Top/Bottom 및 “사라지는 티커” 리스트 리포트 자동 생성

**(d) PASS 조건(게이트)**
- Universe가 **항상 8~14 (Tech+HC)**를 만족하고(못 채우면 cash 비중 처리 규칙 명시),
- **상위 1~2종목 PnL 기여도 편중이 완화**(예: Top1 기여도 35% 이하 같은 내부 기준)되며,
- lockbox 성능이 **챔피언 대비 동급(-0.03 이내 열화)**

**(48h 자동 루프 형태)**
- (1) 실험 정의: `EXP2 survivorship_corpaction_integrity`
- (2) 게이트: `universe_count in [8,14] AND pnl_concentration_ok AND lockbox_mean>=champion-0.03`
- (3) 기대 관측치: “대박 폴드가 깎이고, 대신 최악 폴드/최대DD가 안정화”

### 3) (비용 미반영) “Turnover/슬리피지 내재화 + 거래빈도 캡”을 목적함수에 강제
**(a) 왜 필요한지**
- 8~14종목 전략은 리밸런싱이 잦으면 **슬리피지/스프레드**가 성과를 쉽게 잡아먹음.
- tuning에서는 좋아도 lockbox에서 흔들리면 **미세한 매매가 ‘우연히 맞은’ 구간 의존**일 수 있음.

**(b) 위험/부작용**
- 비용을 넣으면 샤프가 떨어져 보일 수 있음(정상).  
- 지나친 turnover 캡은 신호 반응성을 죽일 수 있음.

**(c) 최소 실험(1개 실험 안에 3-arm)**
- **EXP3: Cost & Turnover-aware Objective**
  1. **ARM-A:** 비용=0(현 상태)
  2. **ARM-B:** 고정비용(예: bps 단위) + 체결 슬리피지(스프레드 기반 or 고정 bps)를 **PnL에서 차감**
  3. **ARM-C:** ARM-B + **turnover penalty/캡**(예: 일/주 단위 총 매매대금 비율 제한)

**(d) PASS 조건(게이트)**
- 비용 포함(ARM-B/C)에서
  - **lockbox_mean이 ARM-A 대비 과도 붕괴하지 않을 것**(예: -0.10 이내),
  - **worst_mdd가 개선 또는 동일**,
  - **turnover가 목표 범위 내**(내부 기준으로 고정: 예 “주간 1.0x 이하” 같은 식으로)

**(48h 자동 루프 형태)**
- (1) 실험 정의: `EXP3 cost_slippage_turnover_multiarm`
- (2) 게이트: `costed_lockbox_drop<=0.10 AND worst_mdd not worse AND turnover<=cap`
- (3) 기대 관측치: “평균은 소폭↓, 대신 lockbox 안정성↑ 및 실거래 가능성↑”

### 4) (과최적화/레짐) “Purged Walk-Forward + Embargo”로 검증 체계 강화
**(a) 왜 필요한지**
- fold 기반에서 **학습-평가 경계가 너무 촘촘**하면(특히 시계열 피처, 이벤트 피처) “옆 날짜 정보”가 새는 형태의 과최적화가 발생.
- champion 대비 candidate의 worst_mdd 악화(-0.1118) + tuning_min 붕괴는 **검증 스킴이 약할 때** 자주 동반.

**(b) 위험/부작용**
- 성능이 “정직하게” 떨어질 수 있음(정상).
- 실험 시간이 늘어날 수 있음(48시간 루프에서 fold 수/윈도 길이 제한 필요).

**(c) 최소 실험(1개 실험 안에 2-arm + 1 게이트 강화)**
- **EXP4: Validation Hardening**
  1. **ARM-A:** 현재 fold 스킴
  2. **ARM-B:** **purged walk-forward** + **embargo(예: 5~10 trading days)**  
  3. **Gate 강화:** “tuning_mean만” 보지 말고 **tuning_min / fold별 분산 / worst_mdd**를 1차 게이트로 승격

**(d) PASS 조건(게이트)**
- ARM-B에서
  - **tuning_min이 ARM-A 대비 개선**(최저 폴드 붕괴 제거),
  - lockbox_mean이 챔피언 대비 **동급(-0.03 이내)**,
  - worst_mdd가 **-0.10 이내**

**(48h 자동 루프 형태)**
- (1) 실험 정의: `EXP4 purged_wf_embargo`
- (2) 게이트: `tuning_min improves AND lockbox_mean>=champion-0.03 AND worst_mdd>=-0.10`
- (3) 기대 관측치: “평균은 비슷/소폭↓, 대신 ‘운 좋았던’ 후보가 사라지고 재현성↑”

### 5) (운영 리스크) “재현성/데이터 신선도/드리프트” 자동 차단 스위치 추가
**(a) 왜 필요한지**
- 48시간 자동 루프는 성능보다 먼저 **운영 리스크(재현 불가/데이터 누락/소스 갱신 지연)**가 장애 원인.
- 챔피언-후보 간 미세 차이 상황에서, “같은 코드인데 매번 결과가 흔들리면” 연구가 정체됨.

**(b) 위험/부작용**
- 실패가 늘어 보일 수 있음(하지만 조기 실패가 비용 절감).
- 너무 엄격하면 실험이 자주 중단됨(허용 범위 설정 필요).

**(c) 최소 실험(1개 실험 안에 2-arm + 회귀테스트)**
- **EXP5: Ops Guardrails**
  1. **ARM-A:** 현 상태
  2. **ARM-B:** 아래 가드레일을 켠 상태로 동일 실험 재실행
     - seed 고정, 패키지 버전 고정/로그
     - 입력 데이터 체크섬/row count/최신일 검사
     - 결측/중복/비정상 가격(0, 급격한 split 미반영) 탐지 시 fail-fast
  3. **REPLAY:** 최근 N일(예: 20영업일) 구간 “리플레이 백테스트”로 결과 오차 허용폭(예: PnL diff < ε) 확인

**(d) PASS 조건(게이트)**
- 같은 실험을 2회 돌렸을 때 주요 지표가 허용오차 내 재현
- 데이터 신선도/무결성 체크에서 경고 0 또는 허용 범위 이하
- 누락/비정상 감지 시 “조용히 통과”가 아니라 **명시적 실패 처리**

**(48h 자동 루프 형태)**
- (1) 실험 정의: `EXP5 ops_reproducibility_guardrails`
- (2) 게이트: `reproducible_within_eps AND data_fresh AND no_silent_fail`
- (3) 기대 관측치: “성능↑가 아니라 ‘실험 신뢰도/속도↑’ (가짜 개선 제거)”

## 24~48시간 실행 순서(명령형 체크리스트)

1. **EXP1(시점 누수)부터 즉시 실행** → 통과 못 하면 아래 실험 결과 해석이 무의미해질 수 있으니 최우선.

## 성능이 안 움직일 때 “원인 분해” 아이디어 (트리거/적용/노출/비용/레짐)

아래를 **한 번에 다 하지 말고**, 자동 리포트로 “항목별로 분해된 표”만 만들면 다음 액션이 자동으로 정해집니다.

### A) 트리거(신호 발생) 문제
- **신호 발생 빈도(일/주당), 신호 강도 분포**가 후보마다 같은지 비교
- 신호가 특정 이벤트(실적 주간, FOMC, CPI)로만 몰리는지 확인(= 데이터 시점/이벤트 의존 의심)
- “상위 k% 신호만” 남겼을 때 성능이 유지되는지(에지 희석 vs 노이즈)

### B) 적용(실행/리밸런싱) 문제
- 리밸런싱 직후 1~3일 PnL이 항상 나쁜지(= 체결/타이밍/슬리피지)
- **포지션 유지기간별 성과(1D/3D/5D/10D)** 분해 → 알파의 반감기 확인
- 체결 가정(Open/Close/VWAP) 변경에 대한 민감도(민감하면 과최적화/누수 가능)

### C) 노출(Exposure) 문제 — Tech+HC에서 특히 중요
- **시장 베타(SPY 회귀), 금리 민감도(IEF/TLT 지표), 변동성(VIX 지표)**에 대한 노출을 측정(ETF는 “관측지표”로만)
- 종목 수(8~14)에서 **상관 구조가 높아 ‘사실상 1~2개 팩터 베팅’**이 되는지 확인
- 종목별 PnL 기여도/드로다운 기여도(상위 1~2종목 과의존이면 구조 문제)

### D) 비용(거래비용/turnover) 문제
- 총수익 vs 비용 차감 후 수익의 갭을 **폴드별**로 표시(폴드마다 비용 민감도가 다르면 레짐/유동성 문제)
- turnover가 성능과 양(+)의 상관이면 “노이즈 추적” 가능성

### E) 레짐(시장 국면) 문제
- 국면을 단순 2~3개로만 자르고 성과 분해(케이스 폭발 금지):
  1) **Risk-on/off**: QQQ 모멘텀(+/-)  
  2) **금리 상승/하락**: 10Y proxy(IEF/TLT 수익률)  
  3) **변동성 고/저**: VIX 상/하 분위
- 국면별로 “어떤 피처/규칙이 성과를 내는지”가 바뀌면 → 고정 모델보다 **가드레일(리스크 스케일링/노출 캡)**이 먼저

## 요약(자동 루프 관점)
- **EXP1~EXP2로 ‘거짓 개선(누수/서바이버십)’을 먼저 제거**
- **EXP3로 ‘실거래 성능’을 스코어의 정식 기준으로 승격**
- **EXP4로 ‘검증이 센 환경에서 살아남는지’ 확인**
- **EXP5로 ‘재현성/데이터 무결성’ 없이는 연구가 정체됨을 차단**

이 5개만 48시간 루프에 넣으면, “성능이 왜 안 움직이는지”가 수치로 분해되면서 다음 액션이 자동으로 좁혀집니다.
