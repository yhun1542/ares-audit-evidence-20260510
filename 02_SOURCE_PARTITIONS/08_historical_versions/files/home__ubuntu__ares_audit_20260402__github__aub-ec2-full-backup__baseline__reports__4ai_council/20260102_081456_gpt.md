## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — 명령형 체크리스트
> 우선 점검 순서: **누수 → 과최적화 → 서바이버십 → 비용/슬리피지 → 운영 리스크**  
> 제약: **미국주식 only, Tech+Healthcare 중심 8~14종목, ETF 매매 금지(관측지표만)**

---

# 1) (P0) 데이터 누수/정렬(시점) 하드닝: “Point-in-time 강제 + Purged CV”
### (a) 왜 필요한지
- 현재 Champion의 tuning 성능 대비 lockbox 격차가 크지 않더라도, **미세 누수(특히 재무/이벤트/리밸런싱 시점)** 는 장기적으로 가장 치명적이며, 48시간 자동 루프에서 “성능이 안 움직임/불안정”의 1순위 원인.
- **Purged+Embargo** 없이 시계열 CV를 돌리면, 분할 경계 주변에서 정보가 새어 과최적화로 lockbox 둔화.

### (b) 위험/부작용
- 성능(평균 수익/샤프) 단기 하락 가능. 대신 **재현성/안정성** 개선.
- 데이터 소스에 따라 결측 증가(피처 수 감소) → 모델 단순화 필요.

### (c) 최소 실험 2~3개 (48h 루프용)
**실험 1A — Purged K-fold + Embargo 적용(기본 5~10거래일)**
- (1) 실험 정의: CV splitter 교체(경계 주변 샘플 purge, embargo 적용) + 학습/검증 기간 strict 분리
- (2) 게이트:
  - 누수 탐지 유닛테스트: feature timestamp ≤ decision timestamp 강제(assert)
  - tuning_mean 하락 폭 제한: Champion 대비 -15% 이내면 진행
  - lockbox_min이 음수로 크게 붕괴(-0.5 이하) 시 즉시 중단
- (3) 기대 관측치:
  - tuning_mean 감소, **tuning↔lockbox 갭 축소**
  - worst_mdd 악화 없이 유지 또는 소폭 개선

**실험 1B — 피처 “공시/이벤트 딜레이” 강제(재무/가이던스/실적 관련)**
- (1) 실험 정의: 재무/펀더멘털/실적 피처를 +1~+3영업일 지연 버전으로만 사용(선택 토글)
- (2) 게이트: 피처 중요도 상위가 이벤트성 피처로 쏠릴 때만 활성화(상위 10개 중 4개 이상)
- (3) 기대 관측치: lockbox_min 개선(바닥이 덜 깨짐), 변동성↓, turnover 변화 관찰

**실험 1C — Corporate action 정합성(분할/배당) 재검증**
- (1) 실험 정의: Adj close/volume, split/dividend 반영 전후가 혼용되지 않도록 단일 기준 강제
- (2) 게이트: 가격 갭/거래량 스파이크 이상탐지(예: 일간 수익률 |r|>40% 빈도) 감소 확인
- (3) 기대 관측치: 특정 폴드의 이상수익/이상손실이 사라지고 fold 간 편차 감소

### (d) PASS 조건
- **lockbox_mean ≥ Champion의 95%** 또는 **lockbox_min 개선(+0.1 이상)**  
- worst_mdd **악화 금지**(Champion -0.093 대비 더 나쁘지 않게)  
- tuning-lockbox 갭(평균 기준) **축소**

# 2) (P0) 서바이버십/유니버스 하드 고정: “8~14 Tech+Healthcare, 동적 편입 금지(또는 규칙화)”
### (a) 왜 필요한지
- 서바이버십(현재 생존 종목만)이나, 학습기간 전체를 통과한 종목만 쓰는 실수는 **락박스에서 성능 정체/왜곡**을 유발.
- “8~14 종목” 제약이 느슨하면 결과가 **유니버스 효과**로 변질(전략이 아니라 종목선정이 성능을 결정).

### (b) 위험/부작용
- 종목 수가 적어져 분산 저하 → MDD 악화 가능(따라서 리스크 관리 패치와 함께 봐야 함).
- 너무 고정하면 레짐 변화에 둔감.

### (c) 최소 실험 2~3개
**실험 2A — 유니버스 고정 리스트(Tech+Healthcare 8~14) + 룰 기반 대체**
- (1) 실험 정의: (예) AAPL/MSFT/NVDA/GOOGL/AMZN/META + UNH/LLY/JNJ/ABBV/TMO 등에서 8~14 선택 후, 데이터 결측/상장 이슈 발생 시 “동일 섹터/동일 시총대 1개”로만 대체
- (2) 게이트: 섹터 비중/종목 수가 규칙을 위반하면 즉시 실패 처리
- (3) 기대 관측치: 폴드별 성능 변동성 감소, 설명 가능성↑

**실험 2B — 생존편향 체크 스위트(Delist/정지/합병 처리 로그)**
- (1) 실험 정의: 학습/검증에 사용된 종목의 “첫 등장/마지막 등장”과 사유 로그 출력(자동 리포트)
- (2) 게이트: 검증 구간에 “사라진 종목”이 0으로만 나오면(의심) 경고 → 데이터 소스 재검증
- (3) 기대 관측치: 이상적으로는 이벤트가 기록되고, 성능이 과도하게 떨어지지 않으면 데이터가 건강함

### (d) PASS 조건
- 유니버스 제약 위반 0건(자동 검사 통과)
- lockbox_mean 큰 훼손 없이(Champion 대비 -10% 이내) **fold 분산 감소**
- 전략 성능이 “특정 1~2종목”에 과도 의존(기여도 60%+)하지 않음

# 3) (P1) 비용/슬리피지/충격비용(Impact) 반영 + Turnover 게이트
### (a) 왜 필요한지
- 성능이 “안 움직이는” 가장 흔한 원인: **실현 불가능한 체결 가정** + 과도한 매매.  
- 특히 8~14종목 집중은 turnover가 커지면 비용이 성능을 잠식.

### (b) 위험/부작용
- 백테스트 성능 하락(정상).  
- 비용 파라미터를 과대 설정하면 신호가 죽음.

### (c) 최소 실험 2~3개
**실험 3A — 보수적 비용 모델(커미션+스프레드+슬리피지) 단일 표준화**
- (1) 실험 정의:  
  - 커미션: 0.5~1.0 bps  
  - 스프레드/슬리피지: 1~5 bps(대형주 기준)  
  - 리밸런싱 체결: 다음날 VWAP 근사(또는 open/close 중 하나로 고정)
- (2) 게이트: 비용 2배/0.5배 민감도 스모크 테스트(순위 역전이 심하면 실패)
- (3) 기대 관측치: turnover 높은 모델이 자연히 탈락, lockbox_min 안정화

**실험 3B — Turnover 패널티(목표: 월 100~200% 이내)**
- (1) 실험 정의: 목적함수에 turnover 페널티 추가 또는 리밸런스 빈도/최소 변경폭(threshold) 적용
- (2) 게이트: turnover가 목표 범위를 벗어나면 후보 자동 제외
- (3) 기대 관측치: 샤프 유지하며 거래비용 반영 후 성능 보존

### (d) PASS 조건
- 비용 반영 후에도 lockbox_mean이 후보들 중 상위 유지
- turnover가 설정 상한을 안정적으로 만족
- 비용 민감도(0.5x~2x)에서 성능이 “부호 반전”하지 않음

# 4) (P1) 레짐(리스크-오프) 게이트: ETF는 “관측지표”로만 사용
### (a) 왜 필요한지
- Candidate가 MDD가 더 낮은데 평균이 낮은 상태 → **거래를 “언제 쉬는가”**로 개선 여지 큼.
- ETF 매매는 금지이므로 **QQQ/XLK/XLV/SPY/IEF/VIX 등은 관측 신호로만** 사용해 리스크-오프 구간 노출을 줄임.

### (b) 위험/부작용
- 상승장에서 기회비용(수익 상단 깎임).
- 게이트가 너무 잦으면 과최적화/스위칭 비용 증가.

### (c) 최소 실험 2~3개
**실험 4A — Risk-off 시 “노출 축소(현금 비중)” 게이트**
- (1) 실험 정의:  
  - 조건 예: QQQ < 200D MA 또는 VIX 급등(예: 20D z-score > 2) 시 포지션 30~50%로 축소
- (2) 게이트: 게이트 발동 비율이 전체의 5~25% 범위 이탈 시 실패(너무 잦거나 너무 없음)
- (3) 기대 관측치: worst_mdd 개선, lockbox_min 개선(바닥 방어)

**실험 4B — 섹터 로테이션 관측(Tech vs Healthcare 상대강도)**
- (1) 실험 정의: XLK/XLV 상대강도가 Healthcare 우세면 Tech 비중 상한 낮추기(예: Tech max 60%)
- (2) 게이트: 섹터 캡 위반 0건 + 비중 변화가 과도(주당 30%p 이상)면 실패
- (3) 기대 관측치: 레짐 전환기 손실 축소, 성과 곡선 평활화

### (d) PASS 조건
- worst_mdd가 Champion(-0.093) 대비 **개선** 또는 최소 **동일**
- lockbox_min **+0.1 이상 개선** 또는 lockbox_mean 손실을 -5% 이내로 제한

# 5) (P2) 운영 리스크/재현성: 48시간 자동 루프 “결과 신뢰도” 강화
### (a) 왜 필요한지
- 자동 루프에서 성능이 안 움직일 때, **코드/데이터 버전/시드/캐시** 문제로 “실험이 실제로 바뀌지 않는” 경우가 빈번.
- 운영 장애(데이터 결측, API 실패, 스케줄 중복) = 장기 성과 훼손.

### (b) 위험/부작용
- 로그/검증 추가로 실행 시간이 늘어남.
- 엄격한 실패 처리로 후보 수가 줄 수 있음(정상).

### (c) 최소 실험 2~3개
**실험 5A — 실험 해시(데이터+피처+코드) 서명/캐시 무효화 규칙**
- (1) 실험 정의: 입력 데이터 범위, 피처 리스트, 비용모델, 시드, 코드 커밋(또는 파일 checksum)으로 run_id 생성 → 동일 run_id면 재실행 금지/경고
- (2) 게이트: “서명이 같은데 성능이 달라짐” 발생 시 실패(비결정성 탐지)
- (3) 기대 관측치: 결과 재현성↑, 성능 정체 원인이 “실험 미변경”인지 즉시 드러남

**실험 5B — 데이터 결측/이상치 자동 차단(거래 중지)**
- (1) 실험 정의: 종목별 결측률/급격한 갭/volume=0 등 탐지 시 해당 종목 비중 0 또는 전체 거래 중지
- (2) 게이트: 이상 이벤트 발생 시 반드시 로그/알람 기록(침묵 금지)
- (3) 기대 관측치: 돌발 손실/운영 사고 감소

### (d) PASS 조건
- 동일 run_id 재실행 결과가 통계적으로 동일(허용 오차 내)
- 결측/이상치 이벤트가 “조용히 성능을 흔드는” 케이스가 사라짐(리포트에서 추적 가능)

1) **Patch A: Purged+Embargo CV + 시점 assert** (위 1A 핵심)  
2) **Patch B: Universe 하드 고정 + 서바이버십 로그** (위 2A+2B 핵심)

4) **Patch D: Risk-off 노출 축소 게이트(ETF 관측)** (위 4A 핵심)  
5) **Patch E: Run 서명/재현성 + 데이터 이상치 차단** (위 5A+5B 핵심)

# 성능이 안 움직일 때: 원인 분해(트리거/적용/노출/비용/레짐) — 명령형 진단 트리
## 0) “실험이 실제로 바뀌었는지”부터 확인(운영/재현성)
- **run_id(데이터범위/피처/시드/비용/코드) 출력 비교** → 동일이면 성능 정체는 정상(새 실험 아님)
- 학습 데이터 샘플 수/피처 수/유니버스 종목 수가 이전 run과 동일한지 diff

## 1) Trigger(신호 생성) 문제
- 상위 피처 중요도가 이벤트성/미래정보성(실적/가이던스)으로 쏠리면 **누수 의심**
- 신호 분포가 지나치게 좁음(스코어 표준편차↓) → 모델이 “아무것도 안 함”
- 폴드별 성능이 특정 구간에서만 과대 → 레짐 적합/과최적화

**즉시 적용**: 피처 timestamp assert, embargo, 딜레이 피처

## 2) Apply(적용/리밸런싱/체결 가정) 문제
- 리밸런싱 룰이 실전과 다름(동일 시점 종가로 체결 등) → 백테스트 착시
- 리밸런스 빈도가 과도해 turnover 폭발 → 비용에 즉시 잠식

**즉시 적용**: 체결 시점 고정(다음날), 리밸런스 threshold, turnover 상한

## 3) Exposure(노출/포트 구성) 문제
- 8~14종목인데 실질적으로 2~3종목이 PnL 대부분 기여 → 사실상 단일종목 베팅
- Tech/Healthcare 섹터 캡이 깨지거나, 메가캡 편중이 심해 벤치마크 베타만 추종

**즉시 적용**: 섹터/종목 캡, 기여도 리포트(종목별 PnL/리스크 기여)

## 4) Cost(비용) 문제
- 비용 0 가정에서만 성능이 나오면 실전 불가
- 비용 민감도(0.5x~2x)에서 성능 부호가 바뀌면 신호가 약함

**즉시 적용**: 표준 비용모델 + 민감도 게이트, turnover 페널티

## 5) Regime(레짐) 문제
- 위험자산 급락 구간에서만 크게 깨지면 “노출을 줄이는 룰”이 필요
- 레짐 게이트가 없다면 lockbox_min/worst_mdd가 구조적으로 나빠짐

**즉시 적용**: ETF(관측) 기반 risk-off 노출 축소, 섹터 상대강도 기반 캡 조절

## PASS 판정 공통 템플릿(모든 패치에 동일 적용 권장)
- **데이터/누수 게이트 통과(필수)**: timestamp assert, embargo 적용 로그 OK
- **비용 포함 성능 기준**: lockbox_mean이 Champion의 90~95% 이상(패치 성격에 따라) 또는 lockbox_min 개선
