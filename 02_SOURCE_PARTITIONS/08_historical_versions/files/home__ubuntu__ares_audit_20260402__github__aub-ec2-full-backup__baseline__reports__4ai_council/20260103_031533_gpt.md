## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — 명령형 체크리스트

### TOP1) **누수/서바이버십(포인트-인-타임) 먼저 고정**
- [ ] **8~14개 미국 Tech+Healthcare 종목 유니버스를 “고정 리스트”로 잠금**(ETF 매매 제외, ETF는 관측지표로만).
- [ ] 가격/거래량/기업행사(분할·배당) **적용 시점(포인트-인-타임) 검증**: “미래 조정값”이 과거에 섞이지 않도록 스냅샷 기준 확정.
- [ ] 실적/뉴스 기반 피처가 있다면 **발표 시각(Timestamp) 기준으로 다음 바(bar)부터만 반영** 강제.
- [ ] “데이터 업데이트 실패 → 이전 캐시 재사용” 같은 **무음(stale) 동작 금지**(실패 시 실험 FAIL 처리).

**(a) 왜 필요한지**
- 현재 챔피언에서 `degenerate_folds: [1,2,3,8]`가 보이고, OOS가 “안 움직이는” 케이스에서 가장 흔한 원인이 **(1) 데이터 스냅샷 불일치 (2) 유니버스 생존편향 (3) 피처 시간정렬 누수**임.

**(b) 위험/부작용**
- 누수 제거 후 단기적으로 OOS mean이 떨어질 수 있음(“진짜 성능”으로 내려앉는 정상 현상).
- 유니버스 고정 시 분산/기회 감소.

**(c) 최소 실험 (공유 실험 세트에서 선택)**
- 적용 실험: **E5 + E2**

**(d) PASS 조건**
- [ ] 동일 기간 재실행 시 유니버스/피처 수/결측 패턴이 재현 가능(해시 일치).
- [ ] 누수 의심 지표(예: 과도한 단일 피처 중요도, 비정상적으로 높은 IS/OOS 갭)가 완화.
- [ ] OOS min(현재 -0.0257)이 **더 이상 극단으로 튀지 않고** 분포가 안정화.

---

### TOP2) **비용(슬리피지/스프레드/수수료) 미반영을 즉시 차단**
- [ ] 백테스트/평가 리포트에 **Gross와 Net을 반드시 동시에 출력**(Net이 없으면 FAIL).
- [ ] 최소 비용모델(스프레드+슬리피지+수수료)부터 넣고, **회전율(turnover) 캡**을 함께 적용.
- [ ] 비용 반영 전후의 성능 차이를 **자동 리그레션 테스트**로 고정.

**(a) 왜 필요한지**
- OOS가 “안 움직이는” 경우, 실제로는 신호가 미세하게 좋아져도 **비용이 전부 상쇄**하는 상황이 흔함.
- 현재 리밸런스 로그가 깨져있어(파일 로드/JSON 파싱 실패) 비용/매매 빈도 진단이 막혀 있음.

**(b) 위험/부작용**
- 비용모델을 보수적으로 잡으면 전략이 과도하게 느려져 알파가 희석될 수 있음.
- 회전율 캡이 신호 반영을 지연.

**(c) 최소 실험**
- 적용 실험: **E3 + E1**

**(d) PASS 조건**
- [ ] Net 기준 지표가 리포트에 기본 탑재되고, 비용 파라미터가 실험 메타에 기록됨.
- [ ] Net Sharpe 또는 Net OOS mean이 **Gross 대비 과도하게 붕괴하지 않음**(비용이 설명 가능한 수준으로 분해됨).
- [ ] turnover/거래횟수/평균 체결비용이 리포트로 노출됨.

---

### TOP3) **과최적화/퇴화 폴드( degenerate folds ) 제거**
- [ ] Walk-forward를 **purged/embargo** 형태로 고정(라벨 누수 방지).
- [ ] 폴드별 최소 샘플/최소 거래 수 미달 시 **폴드 자체를 FAIL 처리**(점수 계산에 포함 금지).
- [ ] “성능이 안 움직임”을 만드는 **무효 학습(학습이 사실상 스킵)**을 감지하는 가드레일 추가.

**(a) 왜 필요한지**
- `degenerate_folds`가 있다는 건 지금 점수가 “제대로 평가되지 않은 구간”이 존재한다는 신호.
- 폴드가 퇴화하면 실험이 바뀌어도 OOS가 둔감(=안 움직임)해질 수 있음.

**(b) 위험/부작용**
- 사용 가능한 데이터가 줄어 단기 점수 변동이 커질 수 있음.
- 이전 챔피언 대비 성능이 내려갈 수 있음(평가가 더 엄격해짐).

**(c) 최소 실험**
- 적용 실험: **E2 + E4**

**(d) PASS 조건**
- [ ] `degenerate_folds`가 0이거나, 퇴화 폴드는 자동 제외되고 이유가 로그로 남음.
- [ ] OOS 분산(폴드 간)이 감소하거나, 최소한 “폴드별 거래수=0” 같은 케이스가 사라짐.

---

### TOP4) **운영 리스크(로그/리밸런스 아티팩트) 복구 — 지금 당장**
- [ ] `aub_rebalance_pinpoint`가 읽을 **정상 포맷(rebalance.csv 또는 jsonl) 생성**을 파이프라인 필수 산출물로 강제.
- [ ] run_hash/lane_hash/commit hash/데이터 스냅샷 hash를 **모든 실험 산출물에 동봉**.
- [ ] worst_mdd가 None인 상태를 금지: **MDD 계산/저장 실패는 실험 FAIL**.

**(a) 왜 필요한지**
- 현재 상태에서 `Error loading --base-log` 및 JSON 파싱 오류로 **리밸런스/매매 단계 진단이 불가**.
- worst_mdd가 None이면 리스크 관리/비용/노출 디버깅이 막힘.

**(b) 위험/부작용**
- 로깅/아티팩트 강제는 파이프라인을 더 자주 실패시키지만, 이 실패는 “좋은 실패(조기 감지)”임.

**(c) 최소 실험**
- 적용 실험: **E1 + E4**

**(d) PASS 조건**
- [ ] `aub_rebalance_pinpoint.py`가 base/cand 모두에서 정상 리포트를 생성.
- [ ] worst_mdd가 항상 숫자로 채워지고, 계산 경로가 로그로 남음.
- [ ] run_hash/lane_hash가 None이 아님.

---

### TOP5) **노출/게이트/스케일링(‘신호는 있는데 포지션이 안 나가는’ 문제) 해부**
- [ ] 사전(pre) 신호 → 스케일링 → 제약/게이트 → 최종 주문까지 **단계별 델타(분포/제로비율)**를 기록.
- [ ] `exposure_min/max: 0.0 / 0.8388`에서 **0 노출 구간이 왜 발생하는지**(게이트/현금비중/제약 바인딩) 원인 태깅.
- [ ] “48시간 루프”에서는 노출이 0이 되는 날이 반복되면 **자동으로 FAIL/경고** 처리.

**(a) 왜 필요한지**
- “성능이 안 움직임”의 흔한 원인: 신호가 바뀌어도 **게이트/스케일링/제약 때문에 최종 포지션이 동일**(=no-delta).
- 이미 No-Delta Diagnoser가 돌아간 정황이 있어, **델타가 사라지는 구간**을 단계별로 찍어야 함.

**(b) 위험/부작용**
- 스케일링 완화/노출 하한을 넣으면 변동성과 MDD가 커질 수 있음.
- 과도한 모니터링 로그로 저장비용 증가(단, 48시간 범위에선 허용).

**(c) 최소 실험**
- 적용 실험: **E4 + E3**

**(d) PASS 조건**
- [ ] “pre 신호 분산은 있는데 post 가중치가 0/동일” 같은 패턴이 사라지거나, 발생 시 원인이 자동 분류됨.
- [ ] OOS min 개선(극단 손실 완화) 또는 거래가 실제로 발생하는 빈도가 증가/정상화.

## 48시간 자동 루프용 “실행 가능한 Patch/실험” (총 5개로 제한)

아래 E1~E5를 **48시간 동안 자동 반복** 실행하도록 구성 (각 실험은 (1)정의 (2)게이트 (3)기대 관측치 포함).

### E1) **Rebalance 로그/아티팩트 표준화 패치**
1) **실험 정의**
- 백테스트 종료 시 반드시 `rebalance.csv`(또는 `rebalance.jsonl`) 생성.
- `worst_mdd`, run_hash, lane_hash, 데이터스냅샷 hash를 결과 JSON에 저장.
- `--base-log` 같은 “파일 경로 자리”에 문자열이 들어가면 즉시 FAIL(현재 에러 재발 방지).

2) **게이트**
- `aub_rebalance_pinpoint.py`가 base/cand 둘 다에서 **에러 없이 리포트 생성**.
- `worst_mdd is not None`, `run_hash is not None`, `lane_hash is not None`.

3) **기대 관측치**
- “No rebalance data found”가 사라지고, 리밸런스 구간별 성능/비용/체결 변화가 드러남.
- 성능이 안 움직일 때 “거래가 실제로 없어서”인지 즉시 확인 가능.

---

### E2) **Degenerate fold 제거 + Purged Walk-forward**
1) **실험 정의**
- purged/embargo 적용한 walk-forward로 재평가.
- 폴드별 최소 거래 수/최소 표본 수 미달 시 폴드를 제외하고, 제외 사유를 로그로 남김.

2) **게이트**
- `degenerate_folds == []` 또는 “제외 처리 + 사유 로그”가 존재.
- 폴드별 거래수 0인 폴드가 점수 계산에 포함되지 않음.

3) **기대 관측치**
- OOS mean이 단기 하락할 수 있으나, OOS min과 폴드 분산이 안정화.
- “실험해도 점수가 그대로” 현상이 줄어듦(평가가 민감해짐).

---

### E3) **비용 반영(Net) + Turnover 캡**
1) **실험 정의**
- Net 성과를 기본 지표로 승격.
- (최소) 스프레드/슬리피지/수수료 모델 추가.
- turnover 상한(예: 일/리밸런스당 최대 %)을 제약으로 추가.

2) **게이트**
- 리포트에 Gross/Net 동시 출력.
- Net 기준으로도 metric이 계산 가능(누락/NaN이면 FAIL).

3) **기대 관측치**
- Gross는 좋아 보이는데 Net이 안 움직였다면 **원인이 비용으로 확정**.
- turnover 감소와 함께 OOS min이 완만해질 가능성.

---

### E4) **No-Delta(신호→포지션) 단계별 델타 모니터링**
1) **실험 정의**
- 단계별 로그: pre-signal 분포, post-scale 분포, 제약 바인딩(어떤 제약이 활성화됐는지), 최종 weight의 0 비율, exposure.
- “가중치 변화량 L1”, “종목별 유지율”, “거래 발생 여부”를 저장.

2) **게이트**
- 델타 지표(예: weight_L1_change, zero_weight_ratio, active_constraints)가 실험 산출물에 존재.
- exposure=0 상태가 연속 발생 시 경고/FAIL(운영 리스크).

3) **기대 관측치**
- 성능 정체가 **(A) 신호 자체 정체인지 (B) 스케일링/게이트로 소멸인지 (C) 비용으로 상쇄인지** 즉시 분해됨.

---

### E5) **유니버스/데이터 포인트-인-타임 고정(서바이버십 방지)**
1) **실험 정의**
- 미국주식 only, Tech+Healthcare 8~14개 **고정 티커 리스트**로 구성(ETF 매매 제외).
- 데이터 로더가 “해당 티커의 해당 시점 데이터만” 읽도록 스냅샷 버전 고정.

2) **게이트**
- 유니버스 해시/데이터 해시가 동일 기간 재실행 시 일치.
- 결측/정지/기업행사 처리 규칙이 로그로 남음.

3) **기대 관측치**
- 누수/서바이버십 제거로 지표가 “현실적인 범위”로 이동.
- 실험 간 비교가 의미 있어짐(데이터 흔들림 제거).

---

## 성능이 안 움직일 때 “원인 분해” 아이디어 (트리거/적용/노출/비용/레짐)

아래 트리를 **E4 로그 + E1 리밸런스 로그**로 1~2회전(48시간) 내 자동 판별하도록 고정.

### 1) Trigger(신호 생성) 레벨
- **증상**: pre-signal 분산이 거의 0, 상관/랭킹이 매번 동일
- **원인 후보**: 피처 업데이트 정지(stale), 데이터 캐시 재사용, 학습이 스킵/조기 종료, 피처 정규화가 전부 클립
- **필수 관측치**: pre-signal std, feature missing rate, 학습 스텝 수, 데이터 스냅샷 hash

### 2) Apply(스케일링/게이트/제약) 레벨
- **증상**: pre-signal은 변하는데 post-weight가 거의 동일(=no-delta)
- **원인 후보**: 스케일링이 너무 보수적(전부 0 근처로 수축), 게이트가 상시 OFF, 제약(섹터/단일종목/현금비중)이 항상 바인딩
- **필수 관측치**: active_constraints, zero_weight_ratio, weight_L1_change, gate_on_rate

### 3) Exposure(노출) 레벨
- **증상**: exposure가 자주 0 또는 상한(0.8388) 근처로 고정
- **원인 후보**: 레짐 필터가 상시 risk-off, 현금/헤지 규칙이 과도, 리스크 타깃 변동성 계산 오류
- **필수 관측치**: exposure timeseries, regime state, vol-target inputs, 포지션 수

### 4) Cost(비용) 레벨
- **증상**: gross는 개선되는데 net이 정체/악화
- **원인 후보**: 회전율 과다, 슬리피지 과소추정/과대추정, 체결 단가 모델 부정확
- **필수 관측치**: turnover, 거래횟수, 평균 체결비용, gross-net gap

### 5) Regime(시장 국면) 레벨
- **증상**: 특정 구간에서만 성과/노출이 붕괴
- **원인 후보**: 국면 필터 기준이 Tech/Healthcare에 비적합, 이벤트(실적 시즌) 타이밍 미스, 상관 구조 변화
- **필수 관측치**: (관측지표로만) QQQ/XLV/IWM 같은 ETF 수익률/변동성, VIX/금리(있다면), 전략 알파 vs 시장 팩터 상관

---

### 48시간 운영 순서(권장 실행 순서 고정)
- [ ] **E1** 먼저 통과(리밸런스/로그 없으면 나머지 진단 불가)
- [ ] 다음으로 **E4**(no-delta/노출 원인 분해)
