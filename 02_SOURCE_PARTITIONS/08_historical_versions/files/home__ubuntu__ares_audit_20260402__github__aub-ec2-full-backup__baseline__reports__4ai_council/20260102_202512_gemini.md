[명령형 체크리스트: AUB 48H Action Plan]

### 1. [긴급] 로깅 파이프라인 및 데이터 무결성 복구
*   **Why:** `AUB Rebalance Pinpoint`에서 JSON 파싱 에러(Expecting value: line 1 column 1) 발생. 거래 내역(Log)을 볼 수 없으면 백테스트 결과(OOS Mean 3.32)는 신뢰 불가. 'Blind Optimization' 상태임.
*   **Risk:** 로깅 오버헤드로 인한 속도 저하(미미함), 포맷 변경 시 기존 도구 호환성 깨짐.
*   **Experiments:**
    1.  `fix_logger_format`: `rebalance.csv`를 표준 JSONL 포맷으로 강제 변환 및 헤더 검증 로직 추가.
    2.  `verify_data_integrity`: Degenerate Folds(1,2,3,8) 기간의 OHLCV 데이터가 `NaN`인지 0인지 확인하는 전처리기 실행.
*   **PASS 조건:** `aub_rebalance_pinpoint.py`가 에러 없이 실행되고, 거래 내역(Ticker, Qty, Price)이 출력될 것.

### 2. [핵심] Degenerate Folds(1, 2, 3, 8) 소생술
*   **Why:** 전체 폴드 중 4개가 작동 불능(Degenerate)임에도 OOS Mean이 높다는 것은, 특정 구간에서 비정상적인 수익이 났거나, 거래가 아예 없어 0으로 처리된 것을 평균 낸 착시일 가능성 높음. 과최적화의 전형적 징후.
*   **Risk:** 필터를 느슨하게 풀면 MDD 급증 가능성.
*   **Experiments:**
    1.  `relax_regime_filter`: ETF(QQQ, XLV) 기반 레짐 필터(Trend/Vol) 임계값 20% 완화.
    2.  `force_min_exposure`: Cash 비중이 90% 이상인 기간이 5일 지속되면, 최소 분산 포트폴리오로 강제 진입(Tech/Healthcare 상위 3종).
    3.  `volatility_floor_check`: 진입 시 요구하는 최소 변동성 기준을 제거(저변동성 구간 매매 허용).
*   **PASS 조건:** Degenerate Folds 개수가 0 또는 1로 감소 & OOS Mean > 1.5 유지.

### 3. [비용] 슬리피지/수수료 스트레스 테스트 (Reality Check)
*   **Why:** OOS Mean 3.32는 비현실적. Tech/Bio 종목(높은 Beta) 특성상 슬리피지가 수익을 잠식했을 가능성 배제 불가. 현재 설정된 비용 모델이 너무 낙관적일 수 있음.
*   **Risk:** 수익률 급감으로 챔피언 모델 폐기 가능성(그러나 이는 필요한 과정).
*   **Experiments:**
    1.  `cost_bps_10`: 매매 수수료+슬리피지 통합 10bps(0.1%) 적용.
    2.  `cost_bps_25`: 매매 수수료+슬리피지 통합 25bps(0.25%) 적용 (보수적 기준).
*   **PASS 조건:** 25bps 적용 시에도 OOS Mean > 1.0 유지 & 거래 횟수(Turnover)가 폭증하지 않을 것.

### 4. [유니버스] Tech/Healthcare Focus 강제화 및 노이즈 제거
*   **Why:** 8~14개 종목 제한 상황에서 섹터가 섞이면 ETF 대비 엣지가 사라짐. 현재 챔피언이 어떤 종목을 잡는지 확인 불가(로그 에러). 명시적 제약 필요.
*   **Risk:** 유니버스 축소로 인한 분산 효과 감소.
*   **Experiments:**
    1.  `sector_constraint_strict`: 유니버스를 GICS 기준 IT, Healthcare 섹터 시총 상위 50위 이내로 한정 후 14개 선별.
    2.  `exclude_earnings_days`: 실적 발표일 전후 1일 거래 제한(Earnings plays 제거).
*   **PASS 조건:** 포트폴리오 내 Tech+Health 비중 100% & Exposure Max 0.84 유지(현상 유지).

### 5. [실행] 매매 회전율(Turnover) 제어
*   **Why:** 비용 미반영 리스크 점검. OOS Mean이 높다면 잦은 매매로 인한 것일 수 있음. 불필요한 노이즈 매매 차단.
*   **Risk:** 반응 속도 저하(Lagging).
*   **Experiments:**
    1.  `holding_period_5d`: 최소 보유 기간 5일 강제.
    2.  `rebalance_threshold_05`: 타겟 비중과 현재 비중 차이가 5% 이상일 때만 리밸런싱(Buffer).
*   **PASS 조건:** 일평균 회전율 < 10% & 샤프 지수(Sharpe) 개선.

### [성능 정체 시 원인 분해 프로토콜]

성능이 움직이지 않거나(0 근처), Degenerate 상태가 지속될 경우 다음 순서로 디버깅:

1.  **트리거(Trigger) 확인:**
    *   ETF(QQQ/XLV) 지표가 '진입 금지' 영역에 고착되어 있는가? -> *조치: 레짐 필터 임계값 확인.*
2.  **유니버스(Universe) 확인:**
    *   선택된 8~14개 종목의 데이터가 해당 기간에 존재하는가? (상장폐지/티커 변경/데이터 누락) -> *조치: Data Loader에서 `dropna` 로직 점검.*
3.  **알파(Alpha) 소멸:**
    *   사용 중인 팩터(모멘텀/변동성 역가중 등)가 횡보장에서 시그널을 0으로 수렴시키는가? -> *조치: 상대 모멘텀(Relative Strength) 팩터 비중 확대.*
4.  **비용(Cost) 장벽:**
    *   기대 수익이 비용(슬리피지)보다 낮아 거래가 체결되지 않는 로직(Optimizer)이 있는가? -> *조치: 최적화 목적함수에서 비용 페널티 일시 제거 후 관측.*
5.  **레짐(Regime) 불일치:**
    *   특정 매크로 지표(금리/VIX)가 하드코딩된 컷오프를 넘었는가? -> *조치: 외부 변수 의존성 제거 후 순수 가격 기반(Price Action only) 실행.*
