아래 TOP5는 **24~48시간 내에 바로 패치/실험으로 돌릴 수 있는 것만** 추렸고, 우선순위는 **누수 → 과최적화 → 서바이버십 → 비용 → 운영 리스크** 순서로 잡았습니다.  
또한 전체 실험/패치는 **5개(E1~E5)로 제한**하고, 각 제안에는 **E1~E5 중에서 2~3개만 재사용**해 “케이스 폭발”을 막습니다. (미국주식 only, Tech+Healthcare 중심, **8~14개 종목**, ETF는 **관측지표만**)

## 실험/패치 풀(총 5개) — 48시간 자동 루프 형태
각 실험은 (1)정의 (2)게이트 (3)기대 관측치로 고정합니다.

### E1) As-Of/Leakage Sentinel + 메트릭 일관성(Champion OOS 불일치 포함)
1) **실험 정의**
- 모든 피처/라벨/가격에 대해 **as-of timestamp 강제**(t 시점 의사결정에 t 이후 데이터 접근 차단).
- 학습/검증 split마다 **“미래 참조율(lookahead hit rate)”** 자동 리포트 생성.
- 현재 관측된 **OOS mean 불일치(1.88 vs 2.63)** 원인(집계 기간/스케일/수수료 반영/리턴 정의) 자동 diff 리포트.

2) **게이트**
- Lookahead hit rate = **0.0%** (허용오차 0).
- Champion 메트릭 재계산 시, 파이프라인 간 OOS mean 차이 **|Δ| ≤ 1%p** (정의 차이 있으면 정의를 하나로 고정).

3) **기대 관측치**
- “성능이 안 움직임”이 실제로는 **지표 정의/집계 불일치** 때문인지 즉시 분리.
- 누수가 있었으면 OOS 급락/분산 증가로 드러남(정상).

---

### E2) Survivorship/Corporate Actions/Point-in-time Universe 고정
1) **실험 정의**
- 거래 가능 유니버스를 매 리밸런스 시점에 **당시 존재하던 종목만** 포함(상장폐지/합병/티커변경 반영).
- 가격은 split/dividend 조정 기준을 **하나로 고정**(Adj Close vs Raw 혼용 금지).
- Tech+Healthcare 섹터 분류도 **시점 기준(point-in-time)**으로 고정(현재 섹터로 과거를 덮지 않기).

2) **게이트**
- 백테스트 전 기간에서 “미래에만 존재하는 티커” 포함 비율 **0%**.
- delist 이벤트 있는 구간에서 리턴/공백 처리 규칙 위반 **0건**.

3) **기대 관측치**
- 과거 성능이 약간 내려가도(정상), OOS 안정성/재현성 상승.
- “특정 연도만 과도하게 좋음” 패턴이 완화.

---

### E3) 비용/슬리피지/회전율 + 리밸런스 로그 스키마 고정(현재 rebalance pinpoint 에러 해결)
1) **실험 정의**
- 거래비용(수수료+슬리피지)을 **거래대금/변동성 기반**으로 모델링(최소한 bps 상수라도 강제 반영).
- turnover cap(예: 일/주 단위)과 포지션 변경 임계값(Δw threshold) 도입.
- 리밸런스 로그를 **CSV/JSONL 스키마로 고정**하고, 항상 artifact에 저장.
  - 현재 에러: `--base-log` 누락, `rebalance.csv`가 JSON/빈 파일로 파싱 실패 → **출력 포맷 강제**가 먼저.

2) **게이트**
- 모든 run에서 `rebalance.csv` 또는 `rebalance.jsonl` **파싱 100% 성공**.
- 비용 반영 후 OOS mean 저하가 **사전 정의 범위 내**(예: -10% 이내)이고, 대신 **분산/턴오버가 감소**.

3) **기대 관측치**
- “좋아 보이는데 실거래에서 깨짐” 원인(비용/턴오버)을 즉시 수치화.
- Rebalance pinpoint가 정상 동작하여, “왜 노델타인지(리밸런스가 안 일어나는지)” 추적 가능.

### E4) 노출/리스크 게이트(8~14종목, Tech+Healthcare) + MDD 계산 누락(None) 제거
1) **실험 정의**
- 포트폴리오 제약을 엔진에 강제:
  - 보유 종목수 **8~14** 고정
  - **미국주식 only** 필터(ADR/OTC 제외 규칙 포함)
  - 섹터는 **Tech+Healthcare 합산 100%**(혹은 90%+현금/헤지)로 제한
- 노출(exposure) 목표 밴드 고정(현재 0.47~0.84 변동 큼):
  - 예: **0.60~0.75** 유지(리스크온/오프라도 밴드 밖이면 강제 스케일)
- `worst_mdd: None` → MDD 산출 파이프라인/인덱스 누락을 패치해서 **항상 값 생성**.

2) **게이트**
- 모든 리밸런스에서 종목수 8~14 위반 **0회**.
- exposure가 목표 밴드 이탈 비율 **< 5%**.
- worst_mdd가 None인 run **0개**.

3) **기대 관측치**
- 성능 평균이 크게 안 올라가도, **테일리스크/운영 일관성**이 개선.
- “성능 노델타”가 사실은 **노출/리밸런스 제약 때문에 변화가 막힌 것**인지 판별 가능.

---

### E5) 레짐/트리거/적용/노출/비용 분해 리포트(노델타 진단 자동화)
1) **실험 정의**
- OOS를 레짐별로 자동 분해(ETF는 거래X, 관측만):
  - 관측지표 예: **XLK/XLV 상대강도**, **SPY 추세**, **VIX 구간**, **금리(UST 2Y/10Y)**  
- “노델타” 원인 분해를 표준 템플릿으로 출력:
  - Trigger(신호 발생 빈도) → Apply(필터로 탈락) → Exposure(스케일/제약으로 축소) → Cost(턴오버로 상쇄) → Regime(특정 구간만 성과)
- lane_hash/run_hash 기준으로 **동일 설정인데 결과가 다른지**(비결정성/시드/데이터 변동) 체크섬 리포트.

2) **게이트**
- 레짐별 성과표(샤프/드로우다운/승률/턴오버)가 run마다 **항상 생성**.
- 노델타 분해에서 “어느 단계에서 죽는지”가 **단일 병목(Top1)으로 식별**되는 비율 ↑ (예: 80% 이상).

3) **기대 관측치**
- “성능이 왜 안 움직이는지”를 감(추측)이 아니라 **단계별 병목**으로 고정.
- 이후 실험이 ‘전략 변경’이 아니라 **병목 제거 패치**로 수렴.

# 3) 성능이 안 움직일 때 “원인 분해 아이디어”(트리거/적용/노출/비용/레짐)

## A. Trigger(신호 발생) 문제
- 체크: 리밸런스 시점당 신호 발생 종목 수 분포(평균/중앙/0 비율)

  - 신호 0이 잦음 → 피처 결측/정규화 오류/임계값 과도
  - 신호는 뜨는데 순위가 매번 동일 → 피처가 상수화(스케일/클리핑 버그)

## B. Apply(필터/제약에서 탈락) 문제
- 체크: 필터 단계별 통과율(US only → 섹터 → 유동성 → 시총 → 이벤트)
- 병목 패턴
  - Tech+Healthcare로 제한했더니 통과 풀이 너무 작음 → 유동성/가격 필터가 과도
  - 서바이버십 테이블 오류로 유니버스가 “현재 구성”으로 고정 → 변화가 사라짐

## C. Exposure(스케일/리스크) 문제
- 체크: exposure 분포(현재 0.47~0.84), 포지션 수(8~14 유지 여부), 현금 비중
- 병목 패턴
  - 스케일러가 항상 0.5 근처로 눌림 → 변동성 추정이 과대/리스크 예산 과소
  - 종목수 제약 때문에 상위 신호가 잘려 동일 포트 반복 → 델타 감소

## D. Cost(회전율/슬리피지) 문제
- 체크: turnover, 거래횟수, 거래대금 대비 비용(bps), 비용 차감 전/후 성과 갭
- 병목 패턴
  - 비용 차감 전후 갭이 크다 → 신호가 미세해서 비용에 먹힘(미세 알파)
  - 리밸런스가 너무 잦다 → 임계값/턴오버 캡 필요(E3)

## E. Regime(특정 구간 성과 편중) 문제
- 체크: 레짐별(저/고 VIX, 금리상승/하락, XLK/XLV 상대강도) 성과/드로우다운
- 병목 패턴
  - 특정 레짐에서만 플러스 → 범용성 부족(과최적화) / 헤지·노출 밴드 재설계(E4)
  - 최근 레짐이 학습 구간과 완전히 다름 → 모델 구조 변경보다 노출/비용/필터 안정화가 우선

## 마무리: 48시간 루프에서의 “성공 순서”
- **1순위(E3→E1)**: 로그/메트릭이 고정되어야 “움직임”을 측정 가능  
- **2순위(E4)**: 운영 제약과 리스크 산출이 살아야 배포 가능  
- **3순위(E2)**: 백테스트 진실성 확보  
- **4순위(E5)**: 노델타 병목을 한 방에 특정하고 다음 패치를 자동으로 유도
