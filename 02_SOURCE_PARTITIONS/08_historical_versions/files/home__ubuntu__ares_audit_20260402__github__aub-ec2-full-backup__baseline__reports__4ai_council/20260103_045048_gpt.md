아래는 **24~48시간 내 우선순위 TOP5**를 “명령형 체크리스트”로 정리한 것이고, **각 TOP5마다 48시간 자동 루프에서 돌릴 수 있는 ‘패치/실험(총 5개)’**만 제시한다. (각 실험은 2~3개 arm을 포함해 “최소 실험 2~3개” 요구를 충족)

---

## TOP1) 누수/서바이버십/타임스탬프 무결성 “하드 게이트” 추가 (최우선)
### (a) 왜 필요한지
- 현재 Champion의 lockbox_mean(≈4.01)이 비정상적으로 높게 보일 정도로 강함 → **미세한 lookahead(특히 corporate action, fundamentals 발표시점, split/dividend 조정, index 구성 종목의 생존편향)**이 끼면 lockbox에서 과대 성능이 쉽게 나온다.
- 이 레벨의 성능에서는 “신호 개선”보다 **데이터 무결성 검증**이 기대값이 더 큼.

### (b) 위험/부작용
- 진짜 알파까지 “누수로 오인”하여 성능이 크게 꺾일 수 있음(하지만 장기적으로는 필수 손절).
- 데이터 소스/ETL이 point-in-time을 지원하지 않으면, 구조적으로 해결 비용이 커짐.

### (c) 최소 실험(패치/실험 #1: Data Integrity Sentinel, 3-arm)
**(1) 실험 정의**
- **Arm A (Baseline)**: 기존 파이프라인 그대로.
- **Arm B (AsOf 강제)**: 모든 feature/라벨에 `asof_ts <= decision_ts` 강제(하루/바 단위), 위반 시 해당 feature drop + 로그.
- **Arm C (Leakage Sentinel)**: 의도적으로 “미래 정보”가 섞인 센티널 feature 1개를 주입해(예: next-day close/return의 변형) 학습 시 성능이 폭발하면 경보. 반대로 B에서 성능이 거의 동일하면 누수 가능성 낮음.

**(2) 게이트(자동 중단/패스 조건)**
- **Hard Fail**: Arm B에서 Arm A 대비 성능이 “과도하게 붕괴”하면서(예: lockbox_mean -50% 이상) 동시에 센티널에 민감(Arm C 성능 급증) → 누수 가능성 “높음”으로 판정, 즉시 원인 추적 모드로 전환.
- **PASS**: Arm B가 Arm A 대비 lockbox_mean 하락폭이 제한적(예: -15% 이내)이고, Arm C에서만 성능 폭증(센티널 검출이 정상 작동)하며, worst_mdd 악화가 없을 것.

**(3) 기대 관측치**
- 정상 파이프라인이면: Arm B ≈ Arm A(소폭 하락), Arm C만 비정상 상승.
- 누수 있으면: Arm B 급락 + Arm C 급등 + 특정 feature set/모듈에서 위반 로그 집중.

---

## TOP2) 비용(슬리피지/수수료/충격) + 회전율을 “락박스 기준”으로 반영
### (a) 왜 필요한지
- 8~14개 종목의 테크+헬스케어 집중 포트는 **리밸런싱/회전율**에 따라 성과가 비용에 잠식되기 쉽다.
- 비용 미반영 상태에서 튜닝이 진행되면, 가장 먼저 **과최적화(미세한 예측의 빈번한 매매)**가 발생한다.

### (b) 위험/부작용
- 비용 모델이 과도하면 진짜 알파도 죽임(보수적 과잉).
- 비용 적용 후 성능이 줄면서 “개선 방향”이 바뀌는 혼란이 생김.

### (c) 최소 실험(패치/실험 #2: Cost & Turnover Reality Check, 3-arm)
**(1) 실험 정의**
- **Arm A**: 현재 비용 가정(또는 0 비용이면 0).
- **Arm B**: 보수적 비용(예: 거래당 고정 수수료 + bps 슬리피지 + 일 거래대금 대비 충격함수 간단형).
- **Arm C**: **회전율 상한**(예: 48시간/일 단위 리밸런싱에서 turnover cap) + 비용은 Arm B 동일.

**(2) 게이트**
- **PASS**: Arm B/C에서 모두 lockbox_mean이 “의미 있게” 유지되고(예: Champion 대비 절대치가 아니라도 **Arm A 대비 보존율**이 높을 것), worst_mdd가 악화되지 않으며, turnover가 목표 범위 내(예: 일평균 turnover 상한)로 들어올 것.
- **Fail**: 비용 적용 시 lockbox_mean 급락 + turnover 과다 → 전략이 비용 민감형(미세 알파 과매매)으로 판정.

**(3) 기대 관측치**
- 정상 알파면 Arm B에서도 성과가 크게 무너지지 않고, Arm C에서 mdd가 개선/안정화될 가능성이 큼.

---

## TOP3) 과최적화(튜닝-락박스 갭) 방지: Purged/Embargo Walk-Forward로 교체
### (a) 왜 필요한지
- 현재 지표에 tuning_mean/min, lockbox_mean/min, fold/worst_mdd가 존재 → **CV 설계가 약하면** 튜닝에서만 먹고 락박스에서 깨지는 전형적인 패턴이 생김.
- 특히 단일 종목/섹터 집중에서는 **자기상관/레짐 지속성** 때문에 “겉보기 성능”이 과장된다.

### (b) 위험/부작용
- 학습 표본이 줄어 성능이 하락할 수 있음(그러나 신뢰도는 상승).
- 실험 시간이 늘어날 수 있음(48시간 루프에서 fold 수 관리 필요).

### (c) 최소 실험(패치/실험 #3: Purged WF + Stability Gate, 3-arm)
**(1) 실험 정의**
- **Arm A**: 기존 CV/튜닝 방식.
- **Arm B**: **Purged Walk-Forward + Embargo**(라벨 호라이즌/보유기간만큼 purge, 이벤트 누수 차단).
- **Arm C**: Arm B + **하이퍼파라미터 공간 축소/정규화 강화**(예: feature 수 상한, L1/L2 강화, early-stopping stricter).

**(2) 게이트**
- **PASS**: (i) tuning_mean과 lockbox_mean의 갭이 감소, (ii) lockbox_min이 음수로 떨어지지 않거나 개선, (iii) worst_mdd가 악화되지 않을 것.
- **Fail**: Arm A만 좋고 B/C에서 급락 → 기존 방식 과최적화 가능성 높음.

**(3) 기대 관측치**
- 진짜 알파면 B/C에서도 성능이 “덜 화려하지만” 안정적으로 남고, min/ mdd 쪽이 개선되는 형태가 나옴.

## TOP4) 운영 리스크/익스포저 제어: 섹터·단일종목·베타/변동성 상한을 “하드 제약”으로
*(미국주식 only, Tech+Healthcare 중심 8~14종목 유지 / ETF 매매 금지, 단 관측지표 가능)*

### (a) 왜 필요한지
- 테크/헬스케어 내에서도 특정 메가캡 쏠림이 발생하면 “사실상 QQQ/XLV 베타”가 되어 알파가 아닌 시장 노출이 된다.
- 운영 관점에서 **단일 종목 사고(갭다운/뉴스/규제)**가 worst_mdd를 지배할 수 있다.

### (b) 위험/부작용
- 제약이 강하면 수익률이 깎일 수 있음(알파의 표현력이 제한).
- 제약 충족을 위해 불필요한 매매가 늘 수 있음(→ TOP2 비용 패치와 같이 봐야 함).

### (c) 최소 실험(패치/실험 #4: Constraint Portfolio Layer, 3-arm)
**(1) 실험 정의**
- **Arm A**: 현 포지션 산출 방식.
- **Arm B**: 제약 추가  
  - 8~14 names 유지  
  - 단일 종목 weight cap  
  - 섹터(Tech/Healthcare) 내 서브산업 편중 완화(간단히 weight cap)  
- **Arm C**: Arm B + **관측지표 기반 노출 상한**(ETF는 매매 X, 관측만)  
  - 예: QQQ/SPY/XLV에 대한 회귀 beta 상한(soft/hard) 또는 realized beta 상한  
  - 변동성 타겟(포트폴리오 ex-ante vol cap)

**(2) 게이트**
- **PASS**: lockbox_mean 보존(과도한 손상 없이), **worst_mdd 감소** 또는 최소 악화 없음, 그리고 beta/weight cap 위반 0.
- **Fail**: 제약 위반 다발(운영 불가) 또는 성능 급락 + turnover 급등.

**(3) 기대 관측치**
- 평균 수익은 약간 줄어도 worst_mdd와 fold14_mdd가 안정화되는 방향이 정상.

## TOP5) 레짐(리스크온/오프) 스케일링: “노출(총 익스포저)만” 조절하는 얇은 레이어
### (a) 왜 필요한지
- 성능이 안 움직이는 구간은 보통 **레짐 미스매치(같은 신호가 먹히는 구간/안 먹히는 구간)**에서 발생.
- 신호 자체를 복잡하게 바꾸기보다, 48시간 루프에서는 **총 익스포저 스케일링(리스크 레이어)**가 가장 빠르고 안전한 개선 포인트.

### (b) 위험/부작용
- 리스크오프가 잦으면 기회비용 증가(상승장 수익률 감소).
- 관측지표(VIX, QQQ/XLV 추세 등)에 대한 임계값 튜닝이 과최적화될 수 있음.

### (c) 최소 실험(패치/실험 #5: Regime Exposure Scaling, 3-arm)
**(1) 실험 정의** *(ETF는 “관측지표”로만 사용)*
- **Arm A**: 기존 gross exposure = 1.0(또는 기존).
- **Arm B**: 단순 레짐 스케일  
  - 조건 예: VIX↑ 또는 QQQ < 200DMA이면 gross exposure 0.5  
  - 그 외 1.0
- **Arm C**: 연속 스케일(변동성 기반)  
  - ex-ante/realized vol이 목표 초과 시 gross exposure를 선형 축소(0.3~1.0 범위)

**(2) 게이트**
- **PASS**: worst_mdd 개선(또는 최소 악화 없음) + lockbox_min 개선/유지 + turnover 과증가 없음.
- **Fail**: 수익률만 깎고 mdd 개선이 없거나, 스케일링이 잦아 turnover 증가.

**(3) 기대 관측치**
- 맞으면: 하락장/급변동 구간에서 손실 꼬리(worst_mdd, lockbox_min)가 먼저 개선됨.

# 48시간 자동 루프 운영(권장 실행 순서: 누수→비용→CV→제약→레짐)
아래 순서로 “하드 게이트”를 앞단에 둬서, 뒤 실험들이 오염된 데이터/비용 착시 위에서 최적화되는 것을 막아라.

**명령형 체크리스트**
1) **패치/실험 #1(Data Integrity Sentinel)** 실행 → 누수 의심이면 즉시 원인 추적(해당 feature/module 격리)  
2) **패치/실험 #2(Cost & Turnover)** 실행 → 비용 민감형이면 turnover cap/리밸런싱 주기부터 조정  
3) **패치/실험 #3(Purged WF)** 실행 → 튜닝-락박스 갭 안정화 확인  
4) **패치/실험 #4(Constraint Layer)** 실행 → 운영 가능 제약 세팅 고정  
5) **패치/실험 #5(Regime Scaling)** 실행 → 꼬리위험 개선 확인  

---

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래는 질문 없이 바로 붙일 수 있는 **진단 트리 + 로그/리포트 지표**다.

### 1) Trigger(신호 발생) 문제
- **체크**: 신호 분산(종목간 score std), 상위/하위 score gap, 신호 0/NaN 비율
- **증상**: score가 평평하거나 NaN 급증 → 성능 정체
- **조치**: feature 누락/정규화 오류/리샘플링 오류 우선 확인(=TOP1과 직결)

### 2) Apply(포지션 변환/제약) 문제
- **체크**: 제약 때문에 목표 포지션이 얼마나 잘렸는지(clip ratio), 주문 불가/스킵 횟수
- **증상**: 신호는 있는데 포지션이 안 바뀜(항상 비슷한 holdings)
- **조치**: 제약 레이어에서 “신호 전달률(signal-to-position pass-through)” 리포트 추가

### 3) Exposure(원치 않는 시장/팩터 노출) 문제
- **체크**: QQQ/SPY/XLV(관측지표) 대비 beta, 섹터/메가캡 집중도(HHI), 상관 클러스터 편중
- **증상**: 알파가 아니라 베타/섹터 모멘텀만 먹고 있었음 → 레짐 바뀌면 정체/역전
- **조치**: TOP4의 beta/weight cap을 게이트로 승격

### 4) Cost(비용/회전율) 문제
- **체크**: turnover, 평균 보유기간, 거래 횟수, 비용 차감 전/후 PnL 갭, 체결가정 민감도
- **증상**: gross는 좋은데 net이 정체 → 매매가 너무 잦거나 미세 알파
- **조치**: TOP2의 비용/turnover cap 우선 적용 후 다시 튜닝

### 5) Regime(레짐) 문제
- **체크**: 성과를 VIX 수준/금리 구간/QQQ 추세 구간으로 조건부 분해(conditional performance table)
- **증상**: 특정 레짐에서만 성과가 존재 → 전체 평균 정체
- **조치**: TOP5처럼 “신호 변경”이 아니라 “총 익스포저 스케일”만 얇게 추가

---

## PASS 조건(전체 공통, 지금 상태 기준으로 “현실적인” 기준)
Champion이 매우 강하므로 “무조건 lockbox_mean 갱신”만 고집하면 개선이 막힌다. 48시간 루프에선 아래처럼 **신뢰도/운영성 개선형 PASS**를 허용하라.

**명령형 체크리스트(PASS)**
- 누수 게이트 통과(센티널 정상 작동 + asof 위반 0 또는 관리 가능)
- 비용 차감 후에도 lockbox_min이 안정(음수로 무너지는 패턴 제거 우선)
- worst_mdd 악화 금지(특히 -0.08보다 더 나빠지면 Fail로 두기)
- turnover/제약 위반 0(운영 불가 후보는 즉시 폐기)

---

원하면, 위 5개 패치를 **현재 autopilot 파이프라인에 “게이트 모듈”로 끼워 넣는 방식(레지스트리/스펙 파일 수준)**으로만 더 좁혀서(코드 변경 포인트 3~6개) 정리해도 되지만, 여기서는 “48시간 루프에서 바로 돌릴 수 있는 실험 정의/게이트/관측치”까지로 제한했다.
