## 다음 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — 명령형 체크리스트

### 1) **누수(lookahead)·정렬 오류·코퍼레이트 액션 정합성 “하드 게이트” 추가**
**(a) 왜 필요한지**
- 현재 챔피언/후보가 **lockbox가 안정적으로 개선**되고 있어도, 가장 먼저 의심/제거해야 할 리스크가 **미세 누수(리밸런싱 시점과 가격/펀더멘털 스탬프 불일치)**임.
- Tech/Healthcare(8~14종목)처럼 종목 수가 적으면, **단 1~2개 종목의 정렬 오류**가 성과를 가짜로 끌어올릴 수 있음.

**(b) 위험/부작용**
- 누수 차단 후 성과가 **즉시 하락**할 수 있음(정상).
- 데이터 정합성 검증이 빡세지면 **실험 처리량 감소**.

**(c) 최소 실험 2~3개(단일 “멀티암” 실험으로 묶어서 48시간 루프에 투입)**
- 실험(멀티암 3개): `E1_time_alignment_gate`
  1. **ARM-A(현행)**: 기존 정렬 로직 유지
  2. **ARM-B(보수)**: 모든 피처/라벨을 `t-1`로 강제 시프트(리밸런싱은 t시점 종가 체결이면 피처는 t-1 종가/지표까지만)
  3. **ARM-C(초보수)**: 펀더멘털/이벤트성 피처(실적/가이던스 등)가 있다면 **공시+N 영업일 지연(N=1~2)** 적용

**(d) PASS 조건(게이트)**
- **필수 게이트(누수/정렬)**: ARM-B/C가 ARM-A 대비 성과가 떨어지더라도,
  - 성과가 “완전 붕괴”가 아니라면(예: lockbox_mean이 **0.0 이하로 추락**하거나 worst_mdd가 **-0.12 이하로 악화** 같은 급락이 아니면) → **현행이 누수일 가능성 낮음**으로 판정
  - 반대로 ARM-B/C에서 성과가 **비슷하게 유지**되면(예: lockbox_mean 차이 |Δ| ≤ 0.02) → **정렬 내구성 통과**
- **성능 PASS(선택)**: ARM-B 또는 ARM-C가
  - `lockbox_mean ≥ 1.339`(= 직전 PASS 후보 1.3388 소폭 상회)
  - `worst_mdd ≤ -0.082`보다 **더 나쁘지 않을 것**
  - `lockbox_min ≥ -0.0534`(현재 lockbox_min) **유지 또는 개선**

### 2) **비용(슬리피지/스프레드/임팩트) 미반영/과소반영을 “우선 반영”하고 전략을 재튜닝**
**(a) 왜 필요한지**
- 소수 종목(8~14) + 리밸런싱이 잦으면 **거래비용이 알파를 쉽게 잠식**.
- 지금 수치가 좋아도, 비용이 보수적으로 들어가면 **실전 기대값이 뒤집힐 수 있음**.

**(b) 위험/부작용**
- 비용을 올리면 단기적으로 **모든 후보 성능이 내려가** 탐색이 답답해질 수 있음.
- 과도하게 보수적이면 트레이딩이 **거의 멈추는 과최적화**로 이동.

**(c) 최소 실험 2~3개(단일 멀티암)**
- 실험(멀티암 3개): `E2_cost_stress_and_retune`
  1. **ARM-A(현행 비용)**: 현재 cost model
  2. **ARM-B(스트레스1)**: 체결가격에 고정 슬리피지(예: bps) + 왕복 수수료 상향(보수치)
  3. **ARM-C(스트레스2)**: 거래대금/변동성 기반 임팩트(간단 모델) 추가 + 스프레드 하한 적용  
     - “ETF는 매매 제외” 유지, 단 **관측지표로만** VIX/XLK/XLV/QQQ/SMH 등 사용 가능

**(d) PASS 조건**
- 비용 스트레스 ARM-B 또는 ARM-C에서:
  - `lockbox_mean`이 ARM-A 대비 **하락폭이 제한적**일 것(예: Δ ≥ -0.05)
  - 동시에 **회전율(turnover)**이 자연스럽게 낮아지며(예: -10%p 이상) 성과가 유지되면 최상
- **운영 게이트**: 비용 반영 후에도 포트폴리오가 8~14종목을 꾸준히 유지(0종목/현금쏠림 금지)

### 3) **서바이버십/유니버스 정의를 “점-시점(point-in-time)”으로 고정 + Tech/Healthcare 편중 제약을 코드로 강제**
**(a) 왜 필요한지**
- 미국주식만, Tech+Healthcare 중심, 8~14개라는 조건에서 가장 흔한 함정이:
  - **현 시점 티커 기준으로 과거를 백테스트**(서바이버십)
  - 상장폐지/합병/티커변경 처리 누락
- 이건 성능이 “안 움직일 때”가 아니라 **움직여도 믿으면 안 되는** 영역.

**(b) 위험/부작용**
- 과거 가능한 종목 풀이 바뀌면서 성과가 하락할 수 있음(정상).
- 유니버스가 너무 빡세지면 신호가 희소해져 거래가 줄 수 있음.

**(c) 최소 실험 2~3개(단일 멀티암)**
- 실험(멀티암 2~3개): `E3_universe_point_in_time`
  1. **ARM-A(현행 유니버스)** 유지
  2. **ARM-B(PIT 유니버스)**: 월/분기 단위로 “그 시점에 거래 가능했던” Tech+Healthcare 후보 리스트를 고정(상폐/합병 처리 포함)
  3. **ARM-C(제약 강화)**: 8~14종목 유지 + 섹터 비중 상한/하한(예: Tech 30~70%, Healthcare 30~70%)을 최적화가 아니라 **하드 제약**으로 강제

**(d) PASS 조건**
- ARM-B/C에서:
  - `lockbox_min`이 **현행(-0.0534)보다 더 나빠지지 않거나**, 나빠지더라도 `worst_mdd`가 동반 악화되지 않을 것
  - **포트폴리오 구성 로그**에서 “미존재 티커/가격 NA로 인한 스킵”이 0에 수렴
- 운영 게이트: 티커 이벤트(merger/split) 발생 시에도 백테스트/루프가 **중단 없이 완료**

### 4) **과최적화/레짐 민감도 완화: “레짐-인식 리스크 거버너(변동성/드로우다운)”를 전략 위에 얹기**
**(a) 왜 필요한지**
- 현재 worst_mdd가 -0.08~-0.09로 관리되고 있지만, Tech/Healthcare는 **레짐 전환(금리/리스크오프)**에 급격히 흔들림.
- “알파 생성”을 바꾸지 않고도, **노출(레버/비중/현금)**만 잘 제어하면 lockbox 안정성이 오르는 케이스가 많음.

**(b) 위험/부작용**
- 거버너가 과하면 상승장에서 **수익 상단을 잘라먹음**.
- 룰이 많아지면 디버깅 비용 증가(운영 리스크).

**(c) 최소 실험 2~3개(단일 멀티암)**
- 실험(멀티암 3개): `E4_regime_risk_governor`
  1. **ARM-A(현행)**: 거버너 없음/기존
  2. **ARM-B(Vol 타겟)**: 20D realized vol 기준으로 포트폴리오 총 노출 스케일링(상/하한만)
  3. **ARM-C(리스크오프 필터)**: 관측지표(ETF는 지표만)  
     - 예: `XLK/XLV 상대강도` + `SPY 추세` + `VIX` 조합으로 리스크오프면 **현금/저노출**, 리스크온이면 정상 운용

**(d) PASS 조건**
- ARM-B 또는 ARM-C에서:
  - `worst_mdd`가 **-0.082(직전 후보 worst_mdd)보다 개선**하거나,
  - 최소한 개선이 없더라도 `lockbox_mean`이 **1.33 이상 유지**하며 `fold14_mdd` 악화 금지(현재 -0.0495 대비)
- 추가 관측: 리스크오프 구간에서 **순노출이 실제로 줄어드는지**(로그로 확인)

### 5) **48시간 자동 루프 운영 리스크 축소: 재현성/실패 내성/캐시·로그 표준화**
**(a) 왜 필요한지**
- 성능이 “안 움직이는” 원인이 모델이 아니라 **파이프라인 변동(데이터 갱신, seed, 캐시 오염, 설정 드리프트)**일 때가 많음.
- 자동 루프는 성능보다 먼저 **신뢰성(같은 입력→같은 출력)**을 확보해야 함.

**(b) 위험/부작용**
- 로깅/스냅샷이 늘어 **디스크·시간 비용 증가**.
- 너무 엄격한 체크로 실험이 자주 fail-fast 될 수 있음(단, 이게 운영상 이득일 때가 많음).

**(c) 최소 실험 2~3개(단일 멀티암이 아니라 “운영 패치”로 1회 적용 후 검증)**
- 실험(멀티암 2개): `E5_repro_and_failure_guard`
  1. **ARM-A(현행)**  
  2. **ARM-B(강화)**:
     - run마다 `config + data hash + git sha + seed + universe snapshot` 저장
     - 가격/피처 NA 비율, 거래 불능(호가/가격 없음) 카운트, 체결 실패 카운트 **게이트화**
     - 결과물(백테스트/리포트) 스키마 고정(JSON schema)

**(d) PASS 조건**
- ARM-B에서:
  - 동일 입력 재실행 시 핵심 지표(`lockbox_mean`, `worst_mdd`, turnover)가 **허용 오차 내 일치**(예: |Δ| ≤ 1e-6 ~ 1e-4 범위)
  - 데이터 NA/미존재 티커/거래불능 카운트가 **기준치 초과 시 자동 중단**이 정상 작동

## 48시간 자동 루프에 바로 넣는 형태(실험 정의 → 게이트 → 기대 관측치)
아래 5개를 “각각 1개 실험(멀티암)”으로 등록해 **case 폭발 없이** 48시간 루프에서 회전시키기.

1) `E1_time_alignment_gate`  
- **게이트**: 누수 의심(ARM-A만 월등) 시 fail  
- **기대 관측치**: ARM-B/C가 비슷한 성과면 신뢰도 상승, 아니면 누수/정렬 문제 후보 확정

2) `E2_cost_stress_and_retune`  
- **게이트**: 비용 스트레스에서 turnover 감소 없이 성과만 붕괴하면 fail(전략이 비용 민감)  
- **기대 관측치**: 거래가 줄면서 lockbox_mean 하락폭 제한

3) `E3_universe_point_in_time`  
- **게이트**: PIT 적용 후 NA/스킵 0에 수렴, 8~14 유지  
- **기대 관측치**: 평균 성과는 일부 낮아져도 min/mdd가 개선되면 성공

4) `E4_regime_risk_governor`  
- **게이트**: 리스크오프 구간 노출 축소 미작동 시 fail  
- **기대 관측치**: worst_mdd 개선(또는 lockbox_min 개선) 중심

5) `E5_repro_and_failure_guard`  
- **게이트**: 재현성 불일치 시 fail(파이프라인 원인 확정)  
- **기대 관측치**: 실험 결과 변동 폭 감소, 원인 추적 속도 증가

## 성능이 안 움직일 때: 원인 분해(트리거/적용/노출/비용/레짐) — 실행 체크리스트

### A) Trigger(신호 발생) 문제
- **신호 발생 빈도**(일/주/월)를 로그로 고정 출력하라: “리밸런싱 시그널 발생일 비율”, “상위/하위 스코어 분포”.
- **스코어 분해**(feature contribution/단순 상관): 상위 3개 피처가 기간별로 바뀌는지 확인하라.
- **게이트**: 특정 기간에 신호가 0에 수렴하거나 스코어 분산이 급감하면 → 데이터/피처 업데이트 문제로 분류하라.

### B) Apply(적용/체결) 문제
- “의사결정 포지션” vs “실제 체결 포지션” 차이를 저장하라(주문 실패/가격 NA/거래정지).
- 리밸런싱 시점 가격 사용(시가/종가/VWAP)과 피처 시점이 일치하는지 강제 검증하라.
- **게이트**: 체결 누락률(%)이 임계치 초과면 성능 정체의 원인을 “전략”이 아니라 “실행”으로 확정하라.

### C) Exposure(노출/제약) 문제
- 8~14 종목 조건에서 **실제 보유 종목 수 분포**를 매 run 리포트에 박아라.
- 섹터 비중(Tech/Healthcare)과 단일 종목 최대비중이 실제로 제한되는지 확인하라.
- 베타/듀레이션(금리 민감) 간이 프록시로 `QQQ`, `XLV`, `TLT(지표만)` 상관을 기간별로 추적하라.

### D) Cost(비용) 드래그 문제
- 총 수익을 “총알파 - 비용 - 슬리피지”로 분해해서 출력하라.
- turnover와 성과의 상관(기간별)을 계산해 **비용 민감도**를 수치로 박아라.
- **게이트**: 비용 항이 PnL의 x% 이상(예: 30%+)을 지속적으로 잠식하면 → 전략 개선보다 회전율 억제가 우선이다.

### E) Regime(레짐) 미스매치 문제
- 관측지표(ETF는 지표만): `SPY 추세`, `VIX`, `XLK/XLV 상대강도`, `HYG 스프레드(지표)`로 간단 레짐 라벨을 만들고,
- 레짐별 성과표(평균/최악/MDD/승률)를 자동 생성하라.
- **게이트**: 특정 레짐에서만 성과가 나고 나머지에서 0 근처면 → “레짐 필터/거버너”를 전략 위에 얹는 쪽으로 분류하라(알파 자체 변경은 후순위).

## 실행 순서(24~48h)
- [ ] **E5(재현성/운영 게이트)**를 먼저 넣어 실험 결과 변동 원인을 제거하라.  
- [ ] 그 다음 **E1(정렬/누수)** → **E3(서바이버십/PIT)** → **E2(비용 스트레스)** → **E4(레짐 거버너)** 순으로 루프에 태워라.  
- [ ] PASS 판단은 “평균”보다 **lockbox_min / worst_mdd / 비용분해 / 체결누락률**을 우선으로 하라.

(현 상태 수치 기준으로는, 성능 개선 자체는 이미 미세하게 진행 중이므로 **신뢰성(누수/서바이버십/비용/운영)**을 먼저 고정시키는 게 48시간 ROI가 가장 크다.)
