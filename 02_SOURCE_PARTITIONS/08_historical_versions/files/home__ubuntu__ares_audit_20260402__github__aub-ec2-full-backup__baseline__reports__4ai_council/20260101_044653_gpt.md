## 24~48시간 TOP5 우선순위(명령형 체크리스트)

### P0) **누수/과최적화/서바이버십/비용/운영 리스크를 “게이트”로 강제**
- [ ] **Purged/Embargo CV**(라벨-피처 겹침 제거) + **데이터 타임스탬프 정합성**(EOD/next-open) 검증을 “실험 전 필수 게이트”로 추가하라.
- [ ] **서바이버십/상장폐지/머지/스핀오프/티커 변경** 반영 여부를 자동 점검하고, 미반영 시 실험을 FAIL 처리하라.
- [ ] **거래비용(스프레드+슬리피지+충격+수수료+세금/ADR fee)**을 백테스트에 강제 반영하고, 비용 파라미터 민감도(2~3단계)를 동시에 돌려라.
- [ ] **운영 리스크(가격 누락, 분할/배당 처리, 리밸런싱 시간, 캘린더, 홀리데이, 서킷브레이커/거래정지)**를 “런타임 체크”로 만들고 위반 로그를 리포팅하라.
- [ ] **튜닝↔락박스 갭(일반화 갭)**과 **거래회전율(TO)**을 고정된 경보 지표로 추가하라.

## 실행 가능한 Patch/실험(5개 번들, 48시간 자동 루프형)
아래 5개만 돌려서 케이스 폭발을 막아라. 각 번들은 **(1) 실험 정의 → (2) 게이트 → (3) 기대 관측치**로 구성한다. (미국주식 only, Tech+Healthcare 8~14종목 유지, ETF는 관측지표로만)

---

# 1) [BUNDLE-1] 데이터 누수/시간정렬/서바이버십 “하드 게이트” 추가
### (a) 왜 필요한지
- 현재 Champion이 양호해도, **시간정렬(EOD→체결시점), 액션 데이터(배당/분할), 상장폐지 수익률** 누락은 성능을 “가짜로” 만든다.
- 이 유형은 개선보다 먼저 **부정확한 승리**를 제거해야 한다(최우선).

### (b) 위험/부작용
- 누수 제거 후 성능이 하락할 수 있음(정상).
- 데이터 소스가 미완이면 FAIL이 잦아져 파이프라인이 멈출 수 있음(대신 원인 로그가 남아야 함).

### (c) 최소 실험(한 번들 안에 3-arm)
- **Arm A (Purged+Embargo on/off 비교):** Purged CV + Embargo(예: 1~5일) 적용 vs 미적용
- **Arm B (가격/체결시점 강제):** “신호 t일 산출 → 주문 t+1 open(또는 close+슬리피지)”만 허용
- **Arm C (서바이버십/상폐 체크):** 유니버스 생성 시점에 delisted/merged 처리 가능한지 검증(불가 시 해당 기간 제외가 아니라 FAIL)

### (d) PASS 조건(게이트)
- **Leakage Gate:** 동일 파라미터에서 *미래정보 의심 지표* 0건(예: 신호 시점 이후 공시/가격 사용 흔적)
- **Generalization Gate:** `lockbox_mean`이 **동일하거나 -0.03 이내 하락**(누수 제거에 따른 자연감소 허용 범위) & `worst_mdd` 악화 **+1.5%p 이내**
- **Data Integrity Gate:** corporate action/상폐 이벤트 처리 누락 0건(또는 명시적 제외 정책을 로그로 남김)

**기대 관측치**
- 튜닝 성능은 조금 깎일 수 있으나, **튜닝↔락박스 갭이 줄고** fold 간 분산이 감소해야 정상이다.

---

# 2) [BUNDLE-2] 거래비용/슬리피지/충격 “현실화” + 민감도 테스트
### (a) 왜 필요한지
- Tech/Healthcare 대형주라도 회전율이 높으면 **스프레드+슬리피지**가 샤프를 갉아먹는다.
- 성능 정체는 종종 “엣지 부족”이 아니라 **비용 미반영/과소평가**에서 발생한다.

### (b) 위험/부작용
- 비용을 올리면 전략이 무너질 수 있음(그 전략은 실전에 부적합).
- 비용 모델을 과격하게 잡으면 과소투자/저회전으로 수렴할 수 있음.

### (c) 최소 실험(3-arm 비용 민감도, 같은 신호 유지)
- **Arm A:** 현재 비용 모델(기준)
- **Arm B:** 슬리피지/스프레드 2배
- **Arm C:** 슬리피지/스프레드 3배 + 거래충격(ADV 기반 단순 impact) 추가

### (d) PASS 조건
- **Cost Robustness Gate:** Arm B에서도 `lockbox_mean`이 **기준 대비 -0.05 이내**, `worst_mdd` **+2%p 이내**
- **Turnover Gate:** 연환산 TO 상한(예: 6~12회 내) 위반 시 FAIL(상한값은 현재 챔피언 TO를 기준으로 “+30% 이내”로 고정)

**기대 관측치**
- 진짜 엣지면 비용을 올려도 성능이 **완만히 감소**한다. 비용 2~3배에서 붕괴하면 신호가 얕거나 회전이 과도하다는 뜻.

---

# 3) [BUNDLE-3] 유니버스/노출 제약(US Tech+Healthcare 8~14) “규칙 기반 고정” + 레짐 관측(ETF는 지표)
### (a) 왜 필요한지
- 성능 정체가 “신호”가 아니라 **유니버스 드리프트/섹터 편향**으로 생길 수 있다.
- 요청 제약(미국주식 only, Tech+Healthcare 8~14)을 **코드 레벨에서 고정**해야 결과가 일관된다.

### (b) 위험/부작용
- 제약이 강해져 기회가 줄어 수익이 감소할 수 있음.
- 특정 메가캡 쏠림이 커지면 tail risk가 늘 수 있음(특히 NVDA/MSFT 등).

### (c) 최소 실험(2~3-arm, 유니버스/노출만 변형)
- **Arm A (고정 유니버스):** 사전 정의된 8~14개(Tech+Healthcare, US, 대형/고유동)로 고정하고 모든 실험 동일 적용
- **Arm B (룰 기반 유니버스):** “시총/유동성/섹터” 룰로 8~14개 자동 선정(단, 룰은 고정; 학습으로 최적화 금지)
- **Arm C (노출 캡):** 단일 종목 최대 비중(예: 15~20%), 섹터 내 합산 캡, 베타 캡을 추가

> ETF는 매매하지 말고 관측만: **XLK/XLV, QQQ, IHI(의료기기), SMH(반도체)** 등을 레짐 지표로 로그에만 남겨라(리스크 설명력 확인용).

### (d) PASS 조건
- **Constraint Gate:** 항상 8~14종목 유지, US 상장, Tech/Healthcare 분류 위반 0건
- **Concentration Gate:** 단일 종목 익스포저 상한 위반 0건
- **Lockbox Gate:** `lockbox_mean` **+0.02 이상 개선** 또는 `worst_mdd` **-1%p 이상 개선** 중 하나 달성(둘 다면 즉시 승격 후보)

**기대 관측치**
- 성능이 크게 안 오르더라도 MDD/분산이 줄어야 한다. 정체의 원인이 “쏠림”이면 여기서 개선이 나온다.

---

# 4) [BUNDLE-4] 포지션/리밸런싱 “회전율 억제 + 변동성 타겟” 패치
### (a) 왜 필요한지
- 같은 신호라도 **리밸런싱 정책** 때문에 알파가 비용으로 새는 경우가 많다.
- 48시간 루프에서 가장 빠르게 효과가 나는 레버는 보통 **포지션 스무딩/리밸런싱 게이트**다.

### (b) 위험/부작용
- 반응이 느려져 급변 국면에서 수익 기회를 놓칠 수 있음.
- 변동성 타겟이 잘못되면 저변동 구간 과노출 위험이 있음.

### (c) 최소 실험(3-arm, 신호는 그대로 두고 실행부만)
- **Arm A:** 현행 리밸런싱(기준)
- **Arm B:** 거래 임계값(de-minimis) 추가: 목표비중 변화가 X% 이하면 거래 금지
- **Arm C:** 변동성 타겟(예: 포트폴리오 ex-ante vol 일정) + 최대 레버리지/현금 비중 캡

### (d) PASS 조건
- **TO/MDD Gate:** 회전율 **-15% 이상 감소**하면서 `lockbox_mean` **-0.02 이내 유지**(또는 `worst_mdd` **-1%p 개선**)
- **Stability Gate:** 월별 손익 분산 감소(표준편차) 또는 tail loss(하위 1% 일수익) 개선

**기대 관측치**
- 샤프가 그대로면 성공이다(비용/운영 안정성이 개선되기 때문). 특히 비용 민감도(BUNDLE-2)에서 견고해져야 한다.

---

# 5) [BUNDLE-5] 레짐 필터(“매매 금지/축소”만) + 실패구간 원인태깅
### (a) 왜 필요한지
- 성능이 안 움직일 때는 신호 자체보다 **“언제 하지 말아야 하는가”**가 부족한 경우가 많다.
- ETF는 지표로만 사용 가능하므로, 레짐은 **시장 스트레스/섹터 스트레스 관측치로 ‘게이트’**만 두는 방향이 안전하다.

### (b) 위험/부작용
- 필터가 과하면 기회 손실(undertrading).
- 레짐 정의를 최적화하면 과최적화 위험(그러므로 룰은 단순/고정).

### (c) 최소 실험(2~3-arm, 필터는 “on/off/강도”만)
- **Arm A:** 필터 없음(기준)
- **Arm B:** 스트레스 게이트(예: QQQ/XLK 변동성 급증, 시장 갭/급락, VIX 대용지표 등)에서 **신규 진입 금지** 또는 익스포저 50%로 축소
- **Arm C:** 헬스케어/테크 상대강도(예: XLK vs XLV)로 **섹터 노출 비중만 기계적으로 조절**(매매 종목은 동일, 비중만 축소/확대)

### (d) PASS 조건
- **Drawdown Gate:** `worst_mdd` **-1.5%p 이상 개선**(수익이 조금 줄어도 허용)
- **Overfit Gate:** 튜닝 성능 증가 없이도 락박스에서 DD가 개선되면 PASS(레짐 필터는 DD개선 목적)

**기대 관측치**
- 평균수익이 크게 안 늘어도, **최악 DD/왼꼬리 리스크**가 줄어드는 형태가 정상이다.

## 48시간 자동 루프에 바로 끼우는 운영 지시(명령형)
- [ ] 각 번들 실험 결과를 **동일 리포트 포맷**으로 저장하라: `lockbox_mean/min`, `worst_mdd`, TO, 비용 민감도 표, 제약 위반 카운트, 데이터 무결성 로그.
- [ ] “승격 후보”는 **락박스 우선**으로만 선정하고, 튜닝 개선만 있는 후보는 자동 폐기하라.
- [ ] 실험 실행 순서를 고정하라: **BUNDLE-1 → BUNDLE-2 → BUNDLE-4 → BUNDLE-3 → BUNDLE-5**
  - (데이터/비용이 정리되기 전 제약/레짐을 건드리면 해석이 흐려진다)

# 성능이 안 움직일 때: 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래를 “분해 로그”로 강제 출력해 원인을 빠르게 고정하라.

## 1) Trigger(신호 생성) 문제
- **발생 빈도/희소성:** 트리거가 너무 적거나 너무 잦아 분포가 망가졌는지
- **라벨-피처 타이밍:** 신호 시점에 사용 가능한 데이터만 썼는지(누수 재점검)
- **신호 강도 분포:** 상위/하위 분위별 미래수익이 단조(monotonic)인지

## 2) Apply(적용/리밸런싱) 문제
- **리밸런싱 타이밍:** close에서 계산하고 open에 체결하는지(혹은 그 반대) 일관성
- **스무딩/임계값:** 작은 목표비중 변화가 비용만 유발하는지(TO vs 알파 기여 분해)
- **지연/체결 실패 모델:** 체결 불가/부분체결을 0으로 가정하고 있지 않은지

## 3) Exposure(노출/집중) 문제
- **종목/섹터 집중:** 1~2개 메가캡이 PnL 대부분을 설명하는지(서바이버십+쏠림)
- **베타/팩터 노출:** QQQ/XLK에 대한 숨은 베타가 커서 “알파처럼 보이는지”
- **헷지 부재:** 헤지 없이도 레짐에서 살아남는지(헤지는 금지할 필요 없지만, 요청상 ETF 매매는 제외이므로 “노출 축소”로 대응)

## 4) Cost(비용) 문제
- **비용이 수익을 상쇄:** 거래당 기대 알파(%) vs 추정 비용(%)를 항상 같이 출력
- **비용 민감도 곡선:** 비용 1x/2x/3x에서 성능이 선형으로 깎이는지, 특정 지점에서 붕괴하는지(붕괴면 회전 과다/체결 가정 오류 가능)

## 5) Regime(시장 국면) 문제
- **스트레스 구간 손실 기여도:** 최악 DD 구간에서 손실의 70%가 특정 2~3주에 몰리는지
- **섹터 상대강도:** Tech 리스크오프에서 Healthcare로 완충이 되는지(안 되면 유니버스/비중 제약이 필요)
- **변동성/갭 리스크:** 갭다운 구간에서 손실이 과도하면 “진입 금지/익스포저 축소 게이트”가 1순위

## 최종 실행 순서(그대로 복사해 운영하라)
- [ ] **BUNDLE-1**부터 누수/서바이버십 게이트를 통과시키고, 통과 못 하면 그 다음 실험을 돌리지 말아라.
- [ ] 통과 후 **BUNDLE-2 비용 민감도**로 “실전 가능성”을 먼저 확인하라.
- [ ] 그 다음 **BUNDLE-4(회전율 억제/볼 타겟)**로 비용-조정 성능을 끌어올려라.
- [ ] 제약 준수와 해석 안정성을 위해 **BUNDLE-3(8~14, Tech+Healthcare 고정/룰)**을 적용하라.
- [ ] 마지막으로 **BUNDLE-5(레짐 게이트)**는 DD개선 목적일 때만 승격시켜라.

이 5개 번들만 48시간 루프에 넣으면, “성능 정체”가 **데이터/비용/집중/실행/레짐** 중 어디에서 생기는지 빠르게 분리되고, 락박스 기준으로 다음 챔피언 업데이트가 가능한 형태로 수렴한다.
