### [Phase 1: 48시간 내 실행 우선순위 TOP 5]

#### 1. (Ops/Code) Rebalance Log 파이프라인 긴급 복구
*   **(a) 필요성:** 현재 `rebalance.csv/jsonl` 로딩 실패로 인해 슬리피지/수수료 차감 후의 진짜 성과(Net Profit)를 모름. 챔피언 점수(3.32)가 허수일 확률 90% 이상.
*   **(b) 위험:** 로그 포맷 변경 시 이전 데이터와 호환성 깨짐(Backfill 필요).
*   **(c) 실험:**
    *   `FIX_LOG_FORMAT`: JSONL 저장 시 `flush()` 강제 호출 및 인코딩 UTF-8 명시.
    *   `VERIFY_PARSER`: 빈 파일일 경우 Default(Empty DataFrame) 리턴하는 예외 처리 추가.
*   **(d) PASS 조건:** `aub_rebalance_pinpoint.py`가 에러 없이 실행되고, Turnover가 0이 아닌 값으로 출력될 것.

#### 2. (Strategy) Degenerate Folds(1,2,3,8) 타겟 Regime Filter 도입
*   **(a) 필요성:** 절반 가까운 폴드가 망가졌다는 것은 특정 시장 국면(예: 금리 인상기, 하락장)에서 전략이 전멸한다는 의미.
*   **(b) 위험:** 필터가 너무 강력하면(Too strict), 거래 기회 자체를 박탈(OOS Mean 급락).
*   **(c) 실험:**
    *   `EXP_MACRO_FILTER`: SPY(ETF)가 200일 이동평균선 아래일 때 Long 포지션 진입 금지.
    *   `EXP_VIX_SCALING`: VIX > 25 구간에서 포지션 사이즈 50% 축소.
    *   `EXP_SHORT_WINDOW`: Lookback window를 절반으로 줄여 반응 속도 높임(Lag 제거).
*   **(d) PASS 조건:** Degenerate Folds 개수가 4개 -> 1개 이하로 감소 & OOS Min > -0.05 방어.

#### 3. (Universe) Tech/Healthcare 유동성/섹터 하드 코딩
*   **(a) 필요성:** Tech/Bio는 변동성이 큼. 유동성이 낮은 종목이 포함되면 백테스트에선 체결되지만 실전에선 슬리피지로 박살남.
*   **(b) 위험:** 유니버스가 너무 좁아지면 분산 효과 감소.
*   **(c) 실험:**
    *   `EXP_LIQUID_TOP`: ADV(일평균거래대금) 상위 100개 중 Tech/HC 섹터만 필터링 후 랭킹.
    *   `EXP_VOL_CAP`: ATR(변동성) 상위 10% 종목 제외(급등락 잡주 제거).
*   **(d) PASS 조건:** 포트폴리오 내 종목 수 평균 8~14개 유지, OOS Sharpe 비율 상승.

#### 4. (Cost) Turnover Penalty 항 추가 (Objective Function 수정)
*   **(a) 필요성:** 현재 비용 미반영 리스크가 큼. 잦은 매매를 억제해야 함.
*   **(b) 위험:** 신호가 와도 매매를 안 해서 추세를 놓칠 수 있음.
*   **(c) 실험:**
    *   `EXP_COST_AWARE`: 목적함수에 `Penalty = Turnover * 0.002` (20bp) 항 추가하여 최적화.
    *   `EXP_HOLD_MIN`: 최소 보유 기간 3일 강제(Early exit 금지).
*   **(d) PASS 조건:** 일평균 Turnover < 15%, Net Return(비용 차감 후) 개선.

#### 5. (Architecture) Exposure Min/Max 밴드 축소
*   **(a) 필요성:** 현재 0.0 ~ 0.84로 변동폭이 큼. 0.0(전량 현금)은 기회비용 발생, 0.84는 풀베팅 리스크.
*   **(b) 위험:** 폭락장에서 피신을 못하거나, 상승장에서 레버리지 효과 감소.
*   **(c) 실험:**
    *   `EXP_EXPOSURE_CLIP`: Exposure 범위를 0.3 ~ 0.7로 강제 고정(항상 시장 참여하되 풀베팅 금지).
*   **(d) PASS 조건:** MDD 감소 및 Equity Curve의 변동성(Standard Deviation) 감소.

### [Phase 3: 성능 정체(No-Delta) 원인 분해 아이디어]

성능이 움직이지 않는다면 다음 5가지 단계 중 어디가 막혔는지 점검하라.

1.  **트리거(Trigger) 불감증:**
    *   *가설:* 시장 노이즈가 커서 신호 발생 임계값(Threshold)을 넘지 못함.
    *   *액션:* 진입 Threshold를 0.5 * StdDev 만큼 낮춰서 거래 빈도 강제 증가 테스트.

2.  **적용(Application) 단계의 상쇄:**
    *   *가설:* Long 시그널과 Hedge(Short) 시그널이 동시에 떠서 Net Exposure가 0이 됨.
    *   *액션:* Long Only 모드로 한 번 돌려서 Hedge 로직이 수익을 갉아먹는지 확인.

3.  **노출(Exposure) 제한:**
    *   *가설:* 리스크 관리 모듈이 Volatility가 높다고 판단하여 포지션 크기를 강제로 줄이고 있음.
    *   *액션:* 변동성 타겟팅(Vol Targeting) 로직을 일시적으로 끄고 Raw Signal 대로 진입.

4.  **비용(Cost)의 장벽:**
    *   *가설:* 수익은 나는데 슬리피지/수수료 모델이 너무 보수적이라 백테스트 엔진이 거래를 '손해'로 인식하고 컷함.
    *   *액션:* 거래 비용을 0으로 설정 후 돌려봄 (이때 수익이 나면 비용 효율화 문제임).

5.  **레짐(Regime) 미스매치:**
    *   *가설:* 현재 로직은 '추세장'용인데, 테스트 구간이 '박스권'임.
    *   *액션:* 최근 3개월 데이터만 잘라서 단기 모멘텀 전략이 작동하는지 확인 (최신 경향성 체크).
