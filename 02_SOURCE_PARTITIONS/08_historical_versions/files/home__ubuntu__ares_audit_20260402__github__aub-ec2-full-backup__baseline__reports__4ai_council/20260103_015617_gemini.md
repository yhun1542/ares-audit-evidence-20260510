[명령형 체크리스트: 즉시 실행]

1.  **로그 파이프라인 긴급 복구**: `AUB Rebalance Pinpoint` 오류(Errno 2, JSON parsing error) 수정. 거래 로그가 없으면 원인 분석 불가.
    *   `rebalance.csv` -> `rebalance.jsonl` 포맷 표준화 및 경로 하드코딩 제거.
2.  **Degenerate Folds(1,2,3,8) 강제 트리거**: 해당 폴드에서 거래가 '0'건이거나 변동성이 '0'임. 이는 과적합이 아니라 **"회피(Survival by Inaction)"** 전략임.
    *   폴드별 최소 거래 횟수 제약(Min Trades > 5) 또는 최소 노출도(Min Exposure > 0.1) 강제 설정.
3.  **Cost Model 현실화**: `oos_mean` 3.32는 비현실적. 슬리피지(Slippage) 모델을 `Fixed`에서 `Volatility Based`로 변경하거나, 매매 수수료를 2배로 설정하여 스트레스 테스트 수행.

*   **(b) 위험**: 코드 수정 중 기존 실험 데이터와의 호환성 파괴 가능성.
*   **(c) 실험 (Patch)**

#### 제안 2: "Anti-Degeneracy Constraints" (과적합 방지)
*   **(a) 필요성**: Fold 1, 2, 3, 8 (전체 데이터의 40%)에서 모델이 작동하지 않음(Degenerate). 특정 하락장(2022년 등)에서 아예 거래를 포기하여 점수를 방어했을 가능성 99%.
*   **(b) 위험**: 강제로 거래하게 만들면 `oos_mean`이 급락할 수 있음 (오히려 진실을 마주하는 과정).
*   **(c) 실험**
    *   `EXP_03_FORCE_EXP`: `min_exposure`를 0.0에서 0.2로 상향 조정 (현금 100% 보유 금지).
    *   `EXP_04_PENALIZE_IDLE`: 3일 이상 포지션 변동 없을 시 Reward에 페널티 부여.
*   **(d) PASS 조건**: `degenerate_folds` 리스트가 비어있거나([ ]), 1개 이하로 줄어들 것. `oos_mean` > 1.5 유지.

#### 제안 3: "Tech/Healthcare Rotation Logic Check" (전략)
*   **(a) 필요성**: 8~14개 종목 제한. 특정 섹터(예: Tech Only)에만 몰빵되어 있는지 확인 필요. Bio/Healthcare는 방어적 성격이나 임상 리스크가 큼.
*   **(b) 위험**: 섹터 분산 강제로 인해 주도주(Momentum) 효과 감소.
*   **(c) 실험**
    *   `EXP_05_SECTOR_LIMIT`: 단일 섹터 비중 Max 60% 제한 (Tech 몰빵 방지).
    *   `EXP_06_BIO_BULL`: 헬스케어(XLV 구성 종목) 비중 최소 20% 강제 할당 실험.
*   **(d) PASS 조건**: 샤프지수(Sharpe) 개선보다는 MDD 감소 확인.

#### 제안 4: "Cost Sensitivity Stress Test" (비용 검증)
*   **(a) 필요성**: 잦은 리밸런싱이 예상되나 현재 `oos_mean`이 너무 높음. 수수료 과소 계상 의심.
*   **(b) 위험**: 전략 폐기 수순으로 갈 수도 있음 (수익성 증발).
*   **(c) 실험**
    *   `EXP_07_COST_2X`: Transaction Cost를 기본값(예: 10bps)의 2배로 설정.
    *   `EXP_08_SLIPPAGE_VOL`: 변동성(ATR) 기반 슬리피지 모델 적용.
*   **(d) PASS 조건**: `oos_mean`이 2.0 이상 유지되면 강력한 알파로 인정.

#### 제안 5: "Look-ahead Bias Purge" (데이터 누수 점검)
*   **(a) 필요성**: `oos_min`이 -0.02로 거의 손실이 없음. 미래 데이터를 참조(Look-ahead)했을 가능성(예: 종가 기준 진입인데 당일 종가 데이터 사용).
*   **(b) 위험**: 코드 구조 전체 리팩토링 필요 가능성.
*   **(c) 실험**
    *   `EXP_09_LAG_1`: 모든 입력 Feature에 `shift(1)` 강제 적용 후 성능 비교.
    *   `EXP_10_NOISE_INJECTION`: Feature에 랜덤 노이즈 10% 섞었을 때 성능이 서서히 하락하는지(정상) 아니면 급락/유지되는지 확인.
*   **(d) PASS 조건**: `Lag(1)` 적용 시에도 성능 급락 폭이 30% 이내일 것.

### 2) 성능 정체 원인 분해 (Diagnosis Logic)

성능이 움직이지 않거나 `degenerate` 상태가 지속될 때 다음 순서로 점검:

1.  **트리거(Trigger) 확인**: 신호가 발생하는가?
    *   *Check*: 예측값(Prediction)의 표준편차가 0에 수렴하는지 확인.
    *   *Action*: 모델 출력값 분포(Histogram) 로그 확인.
2.  **적용(Apply) 확인**: 신호가 포트폴리오 변경으로 이어지는가?
    *   *Check*: Target Weight와 Current Weight의 차이(Delta)가 Threshold(0.01 등)보다 작은지.
    *   *Action*: Rebalance Threshold를 0으로 낮춰서 민감도 테스트.
3.  **노출(Exposure) 확인**: 현금 비중이 너무 높은가?
    *   *Check*: 전체 기간 평균 Exposure 확인.
    *   *Action*: `exposure_max`가 0.838임. 이를 0.95 이상으로 올려서 Active Share 증대.
4.  **레짐(Regime) 불일치**: 모델이 특정 장세만 기다리는가?
    *   *Check*: Degenerate Folds의 날짜 구간이 횡보장/하락장인지 매핑.
    *   *Action*: 하락장 전용 로직(Inverse ETF 혹은 현금 비중 확대가 아닌 Short)이 없으면 0.0으로 수렴하는 것이 수학적으로 최적이라 판단했을 수 있음. (Short 불가 시 Cash 100%가 최선인 구간).

1.  **실험 정의**: `EXP_03_FORCE_EXP` (최소 노출 0.2 설정)
2.  **게이트(Gate)**:
    *   IF `degenerate_folds` count < 2: **GO** (유효한 실험)
    *   ELSE: **NO GO** (여전히 거래 안 함 -> 모델 구조/Feature 문제)
3.  **기대 관측치**: `oos_mean`은 3.32에서 2.0~2.5 수준으로 하락하더라도, `oos_min`이 현실적인 음수 값(예: -0.1)을 보이며 데이터 포인트가 확보되어야 함.

    *   IF `rebalance.jsonl` exists AND size > 10KB: **SUCCESS**
