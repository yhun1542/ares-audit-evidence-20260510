## 24~48시간 우선순위 TOP5 (명령형 체크리스트, 48h 자동루프 친화)

### 공통 게이트(모든 실험에 강제 적용)
- **[게이트] 누수/시점 정렬 테스트 PASS**: 모든 feature/label이 `t 시점에 관측 가능`(lookahead 0)임을 자동 검사
- **[게이트] 비용 반영 후 성능**: 비용/슬리피지 적용 백테스트 결과만 “점수”로 인정
- **[게이트] 과최적화 방지**: purged/embargo CV 또는 walk-forward에서 일관성 확인(튜닝만 좋고 lockbox 흔들리면 FAIL)
- **[게이트] 운영 리스크**: 데이터 결측/리밸런싱 실패/주문 불능(거래정지, halt) 시 안전 동작(포지션 축소/현금화) 확인
- **[관측지표(ETF)]**: XLK, VHT, QQQ, IHI, XBI, SPY, TLT는 **레짐/리스크 지표로만** 사용(매매 금지)

## 1) (최우선) 누수/시점/코퍼레이트액션 정렬 “하드닝 패치”
### (a) 왜 필요한지
- 현재 후보가 **tuning_min=0.05로 매우 불안정** → 미세 누수/시점 엇갈림/액션 처리 오류가 있으면 튜닝에서만 과대평가되고 fold/lockbox에서 흔들림.
- Tech/Healthcare는 **실적/가이던스/임상 이벤트**가 많아, “발표 후 데이터가 과거로 스며드는” 형태의 누수가 자주 발생.

### (b) 위험/부작용
- 정렬을 엄격히 하면 **단기적으로 성능이 하락**할 수 있음(가짜 알파 제거).
- corporate actions(분할/병합) 재처리로 과거 수익률이 바뀌어 회귀 테스트가 흔들릴 수 있음.

### (c) 최소 실험 2~3개 (하나의 ‘하드닝 실험팩’으로 수행)
1. **Leak Sentinel 테스트 추가**
   - feature별로 “최신 타임스탬프 ≤ 주문결정 시각” 위반 건수 로깅/FAIL.
2. **가격/거래량/펀더멘털/이벤트 데이터 소스별 Lag 명시**
   - 예: 일봉 close 기반이면 의사결정은 **다음날 open**만 허용.
3. **Split/Dividend 총수익률 정합성 회귀**
   - 조정종가/비조정종가 혼용 탐지(한 종목이라도 혼용이면 FAIL).

### (d) PASS 조건
- **누수 위반 0건**(자동 리포트).
- lockbox_mean **챔피언 대비 -0.01 이내로 유지**(가짜 알파 제거로 하락 가능성 감안) + worst_mdd 악화 없음.
- tuning_min이 **0.30 이상**으로 회복(극단적 불안정 감소).

### 48h 루프 형태
- (1) 실험 정의: `exp_data_hardening_v1`
- (2) 게이트: leak_sentinel=0, corp_action_consistency=PASS
- (3) 기대 관측치: 튜닝 성능 소폭↓ 가능, 대신 **튜닝-락박스 괴리 축소**, min 성능 상승

## 2) (최우선) 비용/슬리피지/턴오버를 “학습 목표함수에 내재화” 패치
### (a) 왜 필요한지
- Tech/Healthcare의 개별주(8~14개)는 신호가 조금만 흔들려도 **턴오버가 급증**하기 쉬움.
- 비용 미반영은 “움직이지 않는 성능”의 대표 원인: 실제로는 알파가 있어도 비용으로 상쇄되거나, 백테스트에서만 존재하는 알파일 수 있음.

### (b) 위험/부작용
- 과도한 비용 페널티는 트레이드 빈도를 줄여 **알파 포착이 둔화**될 수 있음.
- 슬리피지 모델을 보수적으로 잡으면 lockbox가 과하게 낮아질 수 있음(그러나 운영 현실성은 상승).

### (c) 최소 실험 2~3개 (비용-인지 실험팩)
1. **2단 비용모델(고정+유동) 적용**
   - 고정: 왕복 bps(커미션/스프레드)
   - 유동: `k * (|order|/ADV)` 형태(간단 impact)
2. **목표함수에 turnover penalty 삽입**
   - 예: `Score = Sharpe - λ * Turnover` 또는 순수익률 기준으로 최적화
3. **리밸런싱 데드밴드(거래 억제)**
   - 목표 비중과 현재 비중 차이가 threshold 이하이면 거래 스킵.

### (d) PASS 조건
- lockbox_mean **챔피언 대비 +0.02 이상** 또는 lockbox_min **+0.15 이상 개선**(현재 챔피언 min=1.1337 기준)
- 연환산 turnover가 **상한(예: 6~12회/월 수준)** 내로 감소(프로젝트 내부 기준이 있으면 그 기준 적용)
- worst_mdd 악화 없음(≤ -0.0931 유지 권장)

### 48h 루프 형태
- (1) 실험 정의: `exp_cost_aware_objective_v1`
- (2) 게이트: 비용 ON 백테스트만 채택, turnover 상한 통과
- (3) 기대 관측치: gross 성능↓ 가능, **net 및 min 성능↑**, 과최적화 감소

## 3) (상) 과최적화/서바이버십 편향 방지: Purged CV + “유니버스 고정/이력화” 패치
### (a) 왜 필요한지
- 후보는 lockbox_mean은 비슷하지만 **worst_mdd가 악화(-0.1118)** → 특정 구간에 취약(레짐/이벤트/표본 편향).
- 8~14개 집중 포트폴리오는 유니버스 편향(현재 살아남은 대형주 위주) 시 **서바이버십 알파**가 생기기 쉬움.

### (b) 위험/부작용
- purged/embargo 적용 시 학습 샘플이 줄어 **점수 하락** 가능.
- 유니버스 이력화(편입/편출)로 거래 불능 구간이 생기며 운영 복잡도 증가.

### (c) 최소 실험 2~3개 (일관성 실험팩)
1. **Purged K-fold + embargo(예: 5~20일)**
   - 이벤트 주변 정보 누수/자기상관 방지.
2. **유니버스 스냅샷(월 1회) 고정**
   - 월초 확정된 8~14개만 해당 월 거래(중간 편입 금지).
3. **“상장폐지/합병” 처리 시나리오**
   - delist 리턴(가능하면) 또는 거래 중지 시 강제 청산/현금 대체 룰 백테스트 포함.

### (d) PASS 조건
- tuning_mean 하락이 있더라도 **lockbox_mean 유지(+/-0.01)** + lockbox_min 상승 또는 유지
- 튜닝-락박스 갭 축소(예: `tuning_mean - lockbox_mean`이 챔피언 대비 악화 금지)
- 유니버스 룰 변경 후에도 **거래 가능일 비율 ≥ 99%**(운영 리스크 억제)

### 48h 루프 형태
- (1) 실험 정의: `exp_purgedcv_universe_snapshot_v1`
- (2) 게이트: purgedcv 적용, 스냅샷 유니버스, delist 시뮬레이션 포함
- (3) 기대 관측치: 점수 과대평가↓, 대신 **최악 구간(worst_mdd) 개선** 기대

## 4) (상) 노출/집중/이벤트 리스크 제어: 리스크 오버레이 패치 (Tech+Healthcare 유지)
### (a) 왜 필요한지
- 8~14개 포트는 개별 이벤트(실적, FDA/임상, 규제)로 MDD가 튀기 쉬움.
- 후보의 worst_mdd 악화는 **단일/소수 종목 기여**일 가능성이 큼(집중 리스크).

### (b) 위험/부작용
- 상한/중립화는 알파를 깎아 **수익률 상단을 제한**할 수 있음.
- 변동성 타겟팅은 저변동 레짐에서 레버리지 성향을 만들 수 있어(만약 허용 시) 별도 제한 필요.

### (c) 최소 실험 2~3개 (오버레이 실험팩)
1. **단일 종목 비중 상한 + 섹터 내부 분산 강제**
   - 예: 1종목 max 15~20%, 상위 3종목 합 max 45~55%.
2. **베타/시장노출 캡(ETF는 지표로만)**
   - SPY(또는 QQQ) 대비 포트 베타가 임계 초과 시 전체 노출 축소.
3. **이벤트 캘린더 기반 거래 제한(하드 룰)**
   - 실적 발표 전후 N일(예: -1~+1) 신규 진입 금지 또는 포지션 감축(Healthcare는 임상 이벤트도 동일 룰).

### (d) PASS 조건
- worst_mdd **챔피언과 동등 또는 개선(≥ -0.0931)**  
- lockbox_mean **-0.01 이내 유지**(리스크 감소 대가 허용) + lockbox_min 개선이면 베스트
- 포트 상위 기여 종목의 PnL 비중 쏠림 완화(예: top1 PnL 기여 < 35% 등 내부 기준)

### 48h 루프 형태
- (1) 실험 정의: `exp_risk_overlay_concentration_v1`
- (2) 게이트: 단일비중 캡/베타캡/이벤트룰 모두 ON
- (3) 기대 관측치: 평균 수익 약간↓ 가능, 대신 **꼬리 손실↓, min 성능↑**

## 5) (중) 레짐/트리거 “관측지표(ETF) 기반 게이팅” 패치 (매매는 개별주만)
### (a) 왜 필요한지
- 성능이 안 움직일 때는 종종 “신호는 있는데 **레짐에서만 작동**”하거나, 트리거가 레짐을 무시해 상쇄됨.
- XLK/VHT/QQQ/XBI의 추세/변동성은 Tech/Healthcare 알파의 성공확률에 직접적인 조건을 제공.

### (b) 위험/부작용
- 게이팅은 거래 빈도↓로 기회 손실 가능.
- 레짐 정의가 과최적화되면 또 다른 튜닝 포인트가 됨(단순 규칙 유지 필요).

### (c) 최소 실험 2~3개 (레짐 게이트 실험팩)
1. **변동성 레짐 게이트**
   - VIX 대용(예: SPY realized vol) 또는 QQQ realized vol 상위 분위수면 포지션 스케일다운.
2. **섹터 상대강도 게이트(지표로만)**
   - XLK/SPY, VHT/SPY 상대강도 하락 구간에서 신규 진입 제한.
3. **신호-레짐 상호작용 리포트 자동화**
   - 레짐별 hit-rate, avg trade, turnover를 자동 출력(게이팅의 정당성 확인).

### (d) PASS 조건
- 레짐별로 성능 분산 감소(최악 레짐에서 손실 축소)
- lockbox_min 개선(또는 worst_mdd 개선) 중 하나는 반드시 달성
- 전체 트레이드 수 급감 시에도(예: -40% 이상 감소) net 성능 유지

### 48h 루프 형태
- (1) 실험 정의: `exp_regime_gate_etf_indicators_v1`
- (2) 게이트: ETF는 feature/필터로만, 거래 대상 제외 검증
- (3) 기대 관측치: **나쁜 레짐에서 거래 억제**, min 성능↑

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **자동 리포트로 쪼개서**, 어디가 병목인지 1~2회전 안에 확정하는 형태로 고정.

## A) 트리거(신호 생성) 문제
- **신호 분포 드리프트**: 예전 대비 z-score 분산이 줄었는지(신호가 평평해짐)
- **hit-rate vs payoff 분해**: 승률은 유지되는데 이익/손실 비대칭이 깨졌는지
- **신호-가격 반응 지연**: 1일/2일/5일 지연별 IC(또는 수익 기여) 비교

## B) 적용(실행 로직) 문제
- **리밸런싱 타이밍**: close→next open 강제 후 성능이 변하는지(시점 오류 탐지)
- **거래 억제 규칙의 과도함**: 데드밴드/캡 때문에 목표 포지션을 못 따라가는지(“tracking error” 증가)
- **포지션 생성 실패율**: 결측/가격 0/거래정지로 인해 주문이 스킵되는 비율

## C) 노출(익스포저) 문제
- **베타/섹터/팩터 노출 시계열**: QQQ/SPY에 대한 베타가 의도와 다르게 떠있는지
- **단일 종목 기여도**: PnL 상위 1~3개 종목 의존도가 커졌는지(서바이버십/집중의 신호)
- **롱/쇼트(있다면) 비대칭**: 한쪽만 지속 손실인지

## D) 비용(거래비용/슬리피지) 문제
- **gross→net 브리지**: gross Sharpe는 유지인데 net이 죽는지(턴오버/impact 탓)
- **ADV 대비 주문크기 분포**: 작은 종목/낮은 ADV에서 impact가 집중되는지
- **체결가 가정 민감도**: mid/close/open 가정 바꿔 성능이 크게 변하면 실행 리스크 큼

## E) 레짐(시장 환경) 문제
- **레짐 버킷 성능표**: (추세/역추세)×(저/고변동) 4분면으로 성능/턴오버/MDD 분해
- **Tech vs Healthcare 분리 성능**: 두 섹터가 서로 다른 레짐에서 엇갈려 상쇄되는지
- **이벤트 구간 제외 테스트**: 실적/FDA 전후만 제거했을 때 성능이 회복되면 이벤트 리스크가 원인
