### [TOP 1] 시스템 무결성 복구 (Blind Flying 중단)
**왜 필요한가:** `Rebalance data not found` 및 `worst_mdd: None` 상태에서는 그 어떤 백테스트 결과도 신뢰할 수 없음. 현재 수익률은 거래 비용이 0이거나 데이터 누수(Look-ahead)일 가능성이 99%.
**위험:** 로깅 수정 시, 실제 승률이 급락할 수 있음(진실을 마주함).

**명령형 체크리스트:**
1. `worst_mdd` 계산 로직 내 `NaN` 처리 및 `0` 나누기 예외 처리 추가.
2. `experiment_system` 내 리밸런싱 로그 저장 포맷을 `csv`에서 `jsonl`로 강제 단일화(파싱 에러 제거).
3. 벤치마크 ETF(SPY/QQQ) 데이터가 모든 Fold에 존재하는지 무결성 검사 코드 실행.

### [TOP 3] 레짐 필터링 (Degenerate Folds 해결)
**왜 필요한가:** 특정 Fold(1, 2, 3, 8)가 전멸한다는 것은 하락장/횡보장에서 전략이 역배팅하거나 과매수 상태를 유지한다는 뜻. ETF(SPY/QQQ)를 관측 지표(Regime Oracle)로 사용하여 현금 비중을 강제해야 함.
**위험:** 추세 전환 시 진입이 늦어져 Upside 포기.

**48시간 자동 루프 실험:**
*   **(1) 실험 정의:**
    *   `Exp_Regime_VIX`: VIX > 25 (또는 파생변수) 일 때 현금 비중 50% 강제.
    *   `Exp_Regime_MA`: SPY < 200일 이평선일 때 `Exposure_Max`를 0.84 → 0.4로 축소.
    *   `Exp_Regime_Corr`: 포트폴리오 내 종목 간 평균 상관계수가 0.8 이상이면(동반 하락 위험) 포지션 절반 청산.
*   **(2) 게이트:** `worst_mdd`가 -20% 이내로 진입.
*   **(3) 기대 관측치:** OOS Mean 감소폭 대비 MDD 개선폭이 2배 이상 클 것 (Calmar Ratio 상승).

### [TOP 4] 과최적화 및 비용 검증 (Turnover Brake)
**왜 필요한가:** 리밸런싱 로그 부재로 인해 잦은 매매로 수익을 갉아먹고 있을 가능성 큼. 노이즈에 의한 매매를 차단해야 함.
**위험:** 빠른 추세 변화에 대응 못할 수 있음.

**48시간 자동 루프 실험:**
*   **(1) 실험 정의:**
    *   `Exp_Hold_3d`: 최소 보유 기간 3일 강제.
    *   `Exp_Buffer_05`: 목표 비중과 현재 비중 차이가 5%p 미만이면 리밸런싱 Skip (No-trade zone).
    *   `Exp_Fee_Impact`: 슬리피지/수수료 설정을 현재의 2배(예: 10bps → 20bps)로 설정 후 백테스트.
*   **(2) 게이트:** 기존 `oos_mean` 대비 하락폭이 15% 이내여야 함 (로직 견고성 확인).
*   **(3) 기대 관측치:** 거래 횟수가 30% 이상 감소하고 승률(Win Rate)이 소폭 상승해야 함.

### [TOP 5] 피처 안정성 테스트 (Look-ahead Check)
**왜 필요한가:** `oos_mean` 3.32는 현실에서 불가능에 가까운 수치. 피처 생성 시점(종가 사용 여부 등)에 미래 데이터 참조가 있는지 의심됨.
**위험:** 전략 자체가 폐기될 수 있음(버그였음을 발견).

**48시간 자동 루프 실험:**
*   **(1) 실험 정의:**
    *   `Exp_Lag_1`: 모든 입력 피처를 `t-1` 시점으로 강제 Shift.
    *   `Exp_Noise_Add`: OHLC 데이터에 0.1% 랜덤 노이즈 추가 후 성능 변화 관측.
*   **(2) 게이트:** `Exp_Lag_1`의 성능이 `Base`의 60% 이상 유지될 것. (급락하면 기존 전략은 사기).
*   **(3) 기대 관측치:** 성능이 적당히 하락하며 현실적인 우상향 곡선을 그려야 함.

### [성능 정체 시 원인 분해 아이디어]

성능이 개선되지 않거나(Flat), Degenerate Folds가 사라지지 않을 경우 아래 순서로 디버깅:

1.  **트리거(Trigger) 불량:**
    *   진입 신호가 너무 희귀하여(Rare Event) 특정 Fold에서는 매매가 0건인지 확인.
    *   *Action:* 강제 진입 로직을 넣어 신호 빈도 체크.

2.  **노출(Exposure) 왜곡:**
    *   특정 섹터(예: BioTech)가 포트폴리오의 80%를 점유하여 변동성을 키우는지 확인.
    *   *Action:* 종목당 최대 비중(Max Position Size)을 15%로 제한.

3.  **레짐(Regime) 불일치:**
    *   Fold 1, 2, 3, 8이 2022년 하락장이나 2008년 금융위기 구간인지 매핑 확인.
    *   *Action:* 해당 구간에서는 'Short' 전략이 아닌 이상 'Cash 100%'가 최선임을 인정하고 로직 수정.

4.  **데이터(Data) 오염:**
    *   액면분할(Split)이나 배당락이 조정(Adjusted)되지 않은 데이터가 튀어서 수익률을 왜곡했는지 확인.
    *   *Action:* 수익률이 +20%/-20% 이상인 단일 거래 건 전수 조사.
