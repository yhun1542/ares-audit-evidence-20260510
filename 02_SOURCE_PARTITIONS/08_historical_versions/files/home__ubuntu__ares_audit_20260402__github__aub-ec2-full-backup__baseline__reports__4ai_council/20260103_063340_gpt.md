## 24~48시간 TOP5 우선순위(코드/아키텍처/전략) — **명령형 체크리스트**
우선순위는 **누수 → 과최적화/서바이버십 → 비용 미반영 → 운영 리스크** 순으로 배치.

---

# 1) **데이터 누수(lookahead/as-of) + Fold Degeneracy(현재 degenerate_folds) 최우선 제거**
### (a) 왜 필요한지
- 현재 **degenerate_folds: [1,2,3,8]** 는 “학습/검증 분리 실패”, “샘플 0/동일”, “피처 누수로 fold가 무의미” 같은 치명적 신호.
- Champion에 **lane_hash/run_hash=None**, **worst_mdd=None** 도 함께 떠서, “성능이 좋은 것처럼 보이지만 실제로는 검증이 깨진 상태” 가능성이 큼.
- OOS mean이 비정상적으로 유지될 때(“No-Delta”)는 누수/검증 구조 문제가 1순위 원인.

### (b) 위험/부작용
- 누수 제거하면 **OOS 성능이 급락**할 수 있음(정상).
- fold 로직을 바꾸면 과거 챔피언과 **비교 불연속** 발생.

### (c) 최소 실험(아래 공용 실험 E1~E5 중 참조) 2~3개
- **E1(Placebo time-shift 누수 테스트)**  
- **E2(Walk-forward/폴드 재구성 + degenerate 0화 게이트)**  
- **E5(관측/로그/리포트 강제 산출: worst_mdd 포함)**

### (d) PASS 조건
- **degenerate_folds = []** (0개) 강제.
- **E1에서 성능이 의미 있게 붕괴**(예: OOS mean이 baseline 대비 크게 하락)해야 “누수 없음” 방향으로 해석 가능. *(time-shift인데 성능 유지되면 누수 의심 지속)*
- **worst_mdd 산출 + run_hash/lane_hash 기록**이 항상 생성.

---

# 2) **비용/슬리피지/턴오버/체결현실 미반영 제거(“순성과”로 재평가)**
### (a) 왜 필요한지
- 비용 모델이 약하면 전략이 “움직이지 않는 것처럼(=No-Delta)” 보이거나, 반대로 **가짜 고성과**가 나옴.
- 특히 8~14종목 소수 바스켓은 **리밸런스 회전율**이 성과를 좌우.

### (b) 위험/부작용
- 비용 반영 즉시 OOS mean 하락 가능(정상).
- 과도한 비용 가정은 실제보다 비관적이 되어 신호를 죽일 수 있음.

### (c) 최소 실험(공용) 2~3개
- **E3(비용모델 패치: 슬리피지/스프레드/수수료 + 순/총 성과 동시리포트)**  
- **E5(리밸런스 로그 강제 생성: turnover, trade blotter)**

### (d) PASS 조건
- **gross vs net 성과 차이**가 상식 범위로 들어옴(예: net이 gross 대비 과도하게 동일하면 비용 미반영 의심, 과도하게 붕괴하면 비용 과대/턴오버 폭발 의심).
- 리포트에 **turnover/day, avg holding period, 거래횟수, 비용 기여도**가 자동 포함.

# 3) **서바이버십/유니버스 드리프트 제거: “US Tech+Healthcare 8~14” 고정 바스켓으로 PIT 정합**
### (a) 왜 필요한지
- 유니버스가 매번 바뀌면, 모델 개선이 아니라 **구성 변경 효과**로 “성능이 안 움직이거나(노이즈)”, 반대로 가짜 개선이 생김.
- “Tech+Healthcare only(8~14)” 요구 조건을 **데이터/전략 레벨에서 강제**해야 함.

### (b) 위험/부작용
- 종목 수가 줄면 분산이 감소 → 변동성/MDD 상승 가능.
- 유니버스 고정은 특정 레짐에서 불리할 수 있음.

### (c) 최소 실험(공용) 2~3개
- **E4(유니버스 PIT 고정: 8~14 종목 하드-가드 + 데이터 커버리지 게이트)**  
- **E2(폴드 재구성: 유니버스 고정 상태에서 walk-forward 검증)**

### (d) PASS 조건
- 백테스트 전 기간 **유니버스 불변(8~14)**, 결측/중단 데이터 비율 < 1% (자동 fail-fast).
- 종목 액션(분할/배당) 반영 오류로 인한 **가격 점프/수익률 스파이크** 탐지 시 자동 실패.

> 실행용 예시(고정 바스켓 후보, 변경 금지):  
> Tech: AAPL, MSFT, NVDA, GOOGL, AMZN, META, AVGO, ORCL  
> Healthcare: LLY, UNH, JNJ, ABBV, MRK, TMO  
> (여기서 8~14로 고정 선택 후, 실험 동안 고정 유지)

# 4) **노출(Exposure)·헤지·중립화가 “실제로 적용되는지” 검증 (ETF는 지표로만)**
### (a) 왜 필요한지
- 현재 exposure_min/max가 **0.0 / 0.8388** → “현금 구간”과 “부분투자”가 섞여 있을 수 있음.  
  성능이 안 움직일 때 흔한 원인이 **신호는 있는데 게이트/제약 때문에 포지션이 안 잡힘**.
- ETF 매매는 제외 조건이므로, **SPY/QQQ/XLV는 ‘헤지/레짐 관측 지표’로만** 사용하고 실제 포지션은 개별주로 구현해야 함.

### (b) 위험/부작용
- 중립화(베타/섹터/달러중립) 강제 시 알파가 줄어들 수 있음.
- 제약을 과하게 걸면 “항상 0 포지션” 퇴화 가능.

### (c) 최소 실험(공용) 2~3개
- **E5(포지션/게이트 관측 강화: target vs filled, cash%, beta, net/gross 노출 로그)**  
- **E3(비용+턴오버 포함 상태에서 노출 제약이 실제 성과에 미치는 영향 확인)**

### (d) PASS 조건
- 각 리밸런스 시점에 **(신호→목표비중→실제체결)** 3단 로그가 남고, “신호는 있는데 포지션 0” 케이스가 자동 집계됨.
- net/gross, cash%, (관측지표로서) SPY/QQQ/XLV 레짐값과 성과가 리포트에서 연결됨.

# 5) **운영 리스크/관측 불능(현재 rebalance pinpoint 실패) 제거: 로그·아티팩트 표준화**
### (a) 왜 필요한지
- 지금 상태는 `rebalance.csv/jsonl`을 못 읽어서 pinpoint가 실패:  
  `Error loading --base-log ... No such file` / `Expecting value ...`  
  → **자동 루프가 “원인 추적 불가” 상태**.
- run_hash/lane_hash None, worst_mdd None 역시 “파이프라인 출력 계약(contract)”이 깨진 징후.

### (b) 위험/부작용
- 로깅 증가로 저장공간/실행시간 증가.
- 표준화 도중 기존 스크립트 호환성 깨질 수 있음(하지만 지금이 더 위험).

### (c) 최소 실험(공용) 2~3개
- **E5(아티팩트 계약 강제: rebalance.jsonl/csv, run_hash/lane_hash, worst_mdd, fold stats)**  
- **E2(각 fold별 샘플 수/기간/종목 커버리지 로그 포함)**

### (d) PASS 조건
- `aub_rebalance_pinpoint.py`가 **base/cand 모두에서 0 에러로 실행**되고, 리밸런스 차이가 리포트로 남음.
- 모든 실험 산출물이 “경로/포맷/필드” 기준을 만족 못 하면 **파이프라인이 자동 실패**.

## 공용 “48시간 자동 루프” 실험 5개(이 5개만 돌려서 위 TOP5를 커버)
아래 5개만 고정으로 돌리고, 각 TOP5 제안은 이 5개 관측치로 PASS/FAIL을 가른다. (케이스 폭발 방지)

---

### **E1) Placebo time-shift 누수 테스트**
1) **실험 정의**  
- 모든 주요 피처/시그널을 **+1 trading day 지연**(또는 예측을 다음날부터만 체결)한 버전으로 동일 백테스트 실행.
2) **게이트(자동 실패 조건)**  
- 지연했는데도 OOS mean이 baseline과 큰 차이가 없으면(예: 감소폭이 매우 작음) **누수 의심으로 FAIL**.
3) **기대 관측치**  
- 정상이라면 성과가 **유의미하게 악화**되어야 함(누수/동일일 종가 사용 등이 없다는 증거).

---

### **E2) Walk-forward 폴드 재구성 + degenerate 0화**
1) **실험 정의**  
- fold 생성 로직을 walk-forward로 재구성하고, 각 fold에 대해: 기간/샘플수/종목커버리지/결측률을 로그로 남김.
2) **게이트**  
- `degenerate_folds`가 1개라도 나오면 FAIL.  
- fold별 샘플수가 임계치 미달이면 FAIL(임계치는 코드 상수로 고정).
3) **기대 관측치**  
- OOS 평균이 다소 낮아져도, fold 간 분산이 “정상 범위”로 수렴.  
- 챔피언 갱신이 느려져도 “검증 신뢰도”가 올라감.

---

### **E3) 비용모델 패치(순성과 리포트 강제)**
1) **실험 정의**  
- 고정 수수료 + 스프레드/슬리피지(예: ATR/달러볼륨 기반) 비용을 적용.  
- gross/net, turnover, 거래횟수, 평균 보유기간을 동일 리포트에 기록.
2) **게이트**  
- turnover 폭발(상한 초과) 또는 net이 gross 대비 비정상적으로 동일/붕괴하면 FAIL.
3) **기대 관측치**  
- 전략 간 차이가 “순성과(net)”에서 갈리기 시작(지금의 No-Delta가 비용 항목에서 분해됨).

---

### **E4) US Tech+Healthcare 8~14 종목 유니버스 PIT 고정**
1) **실험 정의**  
- 유니버스를 8~14로 하드 고정(Tech+Healthcare만). 기간 내 종목 변경 금지.  
- 데이터 결측/거래정지/가격 스파이크 감지 시 fail-fast.
2) **게이트**  
- 결측률/가격 스파이크/분할 미반영 의심 이벤트 발견 시 FAIL.
3) **기대 관측치**  
- 유니버스 변동 노이즈가 제거되어, 실험 간 “성능 변화”가 신호/제약/비용 변화로만 설명 가능해짐.

---

### **E5) 관측성/운영 계약(contract) 강제 패치**
1) **실험 정의**  
- 매 실행마다 필수 산출물 생성:  
  - `rebalance.jsonl`(또는 csv), trade blotter, 일별 포지션/노출(net/gross/cash%),  
  - `worst_mdd`, fold stats, `run_hash`, `lane_hash`  
- `aub_rebalance_pinpoint`가 읽는 경로/포맷을 단일 표준으로 맞춤.
2) **게이트**  
- 필수 파일/필드 하나라도 누락되면 **실험 자체 FAIL**(성능이 좋아도 폐기).
3) **기대 관측치**  
- “왜 성능이 안 움직였는지”가 로그로 분해 가능(신호 미적용 vs 노출 제약 vs 비용 vs 데이터).

# 성능이 안 움직일 때(=No-Delta) 원인 분해 아이디어 — 트리거/적용/노출/비용/레짐 체크 트리
아래 순서대로 **자동 판정 지표를 로그에서 뽑아** 원인 범주를 확정한다(질문 없이 바로 적용).

## A. Trigger(신호가 변했나?)
- 지표: 일별/리밸런스별 **signal variance**, 상위/하위 종목 rank 변동률
- 판정:
  - 신호 분산이 거의 0 → 피처 상수화/스케일링 버그/데이터 결측 대체가 과도

## B. Apply(신호가 포지션으로 적용됐나?)
- 지표: `target_weight` vs `filled_weight` 괴리, 리밸런스 발생 횟수
- 판정:
  - 신호는 움직이는데 target이 0 → 게이트/리스크 제약이 신호를 차단
  - target은 있는데 filled가 0 → 체결/캘린더/심볼 매핑/데이터 동기화 버그

## C. Exposure(노출이 성과를 만들 구조인가?)
- 지표: cash%, net/gross, 종목별 기여도, beta(관측용 SPY/QQQ), 섹터 편중(Tech vs HC)
- 판정:
  - cash%가 높고 변동 → 포지션 생성 실패 또는 과도한 리스크 오프 로직
  - net이 계속 0 근처 → 중립화 과도, 알파가 상쇄

## D. Cost(비용이 덮어버렸나? 혹은 비용이 0이라 가짜인가?)
- 지표: turnover, 거래비용/일, gross-net 스프레드, 평균 보유기간
- 판정:
  - turnover 과다 + net 급락 → “좋은 신호”가 아니라 “거래가 알파를 먹음”
  - gross≈net(항상) → 비용 미반영 가능성

## E. Regime(레짐이 달라졌나?)
- 지표(관측 전용 ETF): SPY/QQQ/XLV의 추세/변동성(예: 20d mom, 20d vol), VIX(가능하면)
- 판정:
  - 특정 레짐 구간에서만 성과 발생 → 레짐 게이트/포지션 스케일을 “관측지표 기반”으로 분기(단, ETF 매매 금지 유지)

## 실행 순서(24~48시간) — 그대로 수행
1) **E5 먼저 적용**: 로그/아티팩트 계약부터 고치고 pinpoint가 돌게 만들어라(운영 리스크 최우선).  
2) **E2 적용**: degenerate fold 0화.  
3) **E1 실행**: time-shift로 누수 판정.  
4) **E3 실행**: 비용 반영 후 gross/net 분해.  
5) **E4 실행**: 8~14 Tech+HC 고정 유니버스로 결과 재현성 확보.

이 루프가 돌아가면, “성능이 안 움직이는 이유”가 **(신호가 없어서 / 적용이 안 돼서 / 노출이 막혀서 / 비용이 먹어서 / 레짐이 달라서)** 중 어디인지 48시간 내에 강제 분해된다.
