## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — 명령형 체크리스트

### 1) 누수(look-ahead) 최우선 차단: “asof 정렬 + 거래시점 분리”를 강제
- **(a) 왜 필요한지**
  - Tech/Healthcare 종목은 이벤트(실적/가이던스) 반영이 급격해 **1일/1바 인덱스 누수**가 성능을 “안 움직이거나 과도하게 좋아지게” 만들고, 이후 락박스에서 정체/붕괴를 유발.
- **(b) 위험/부작용**
  - 누수 제거 즉시 성능 하락 가능(정상). 대신 락박스-튜닝 간 괴리/분산 감소가 기대.
- **(c) 최소 실험(2~3 arms, 단일 실험으로 묶기)**
  - **실험 #1: ASOF/EXEC 분리 강제 스위프**
    1) **(1) 실험 정의**
       - Arm A: 기존(현행)
       - Arm B: 모든 feature를 `t-1 close 기준 asof`, 주문/체결은 `t open` 또는 `t close`로 고정(둘 중 하나로 시스템 표준화)
       - Arm C: fundamentals/estimates류가 있으면 **발표일+1영업일 이후부터만 유효**(point-in-time lag 강제)
    2) **(2) 게이트**
       - 데이터 검증 게이트(실행 전): “feature timestamp ≤ decision timestamp” 위반 건수=0
       - 백테스트 게이트(실행 후): 락박스 `min` 하락 폭 제한(아래 PASS 조건)
    3) **(3) 기대 관측치**
       - 튜닝 평균은 하락/유지 가능, 대신 **fold 간 분산 감소**, 락박스 min이 안정 또는 상승.
- **(d) PASS 조건**
  - `lockbox_min` **챔피언 대비 악화 금지**(≤ -0.00 허용) 또는 +0.01 이상 개선
  - `worst_mdd` **-0.115 이하로 악화 금지**
  - 누수 위반 0건(하드 PASS)

---

### 2) 비용 미반영(슬리피지/스프레드/임팩트) 패치: “성과 정체의 가짜 알파” 제거
- **(a) 왜 필요한지**
  - 8~14개 집중 포트폴리오는 회전율이 높아지면 **거의 항상 비용이 성능을 잠식**. 비용이 없으면 튜닝은 좋아도 락박스가 정체/불안정.
- **(b) 위험/부작용**
  - 단기적으로 성과 하락(정상), 대신 **회전율이 줄며 MDD 안정** 가능.
- **(c) 최소 실험(2~3 arms)**
  - **실험 #2: 비용모델 3단계 스윕 + 회전율 페널티**
    1) **(1) 실험 정의**
       - Arm A: 비용 0(현행)
       - Arm B: 고정비용(왕복) = 10~20bp + 스프레드 5~10bp(보수적 범위로 1안 고정)
       - Arm C: Arm B + **유동성 기반 임팩트**(예: `k * |dq| / ADV` 형태, k는 작은 상수로 시작) + turnover penalty(목표 turnover 초과분 페널티)
    2) **(2) 게이트**
       - 비용 포함 후에도 “연간 회전율/일평균 turnover”가 상한 이내인지 검사(상한은 시스템에서 고정값으로 강제)
       - 비용 도입으로 전략이 거래를 거의 못 하면(현금 비중 과대/포지션 0) FAIL
    3) **(3) 기대 관측치**
       - 튜닝 수익률은 낮아지되, **락박스 min/MDD가 개선**되거나 최소한 악화 폭이 제한됨.
- **(d) PASS 조건**
  - Arm B 또는 C에서 `lockbox_min` **악화 ≤ 0.02** 이내 + `worst_mdd` 개선 또는 동일
  - Turnover가 상한을 지속적으로 위반하지 않음(하드 FAIL 조건)

### 3) 서바이버십/유니버스 고정: “그때 존재하던 Tech+Healthcare만” + delisting 처리
- **(a) 왜 필요한지**
  - 유니버스가 현재 생존 종목/현재 섹터로 고정되면 **서바이버십 편향**으로 과거 성능이 부풀고, 락박스/실거래에서 정체.
- **(b) 위험/부작용**
  - 데이터 소스에 따라 delisting return이 없으면 구현 난이도↑. 대체 규칙(0 처리 등)은 왜곡 위험.
- **(c) 최소 실험(2~3 arms)**
  - **실험 #3: 유니버스/상장폐지(Delist) 규칙 스윕**
    1) **(1) 실험 정의**
       - Arm A: 현행 유니버스
       - Arm B: **Point-in-time 유니버스 스냅샷**(해당 일자에 Tech/Healthcare로 분류된 종목만) + “데이터 존재 여부로 생존필터 금지”
       - Arm C: Arm B + delisting 이벤트 처리(가능 시 delisting return 반영, 불가 시 **보수적 패널티** 규칙을 명시적으로 적용)
    2) **(2) 게이트**
       - 각 날짜별 유니버스 크기/섹터 비율 로그 출력(변동 폭이 비정상적으로 작으면 서바이버십 의심 → FAIL)
       - delist 발생 시 포지션 청산/가격 처리 규칙이 일관적으로 적용되는지 테스트(재현성)
    3) **(3) 기대 관측치**
       - 과거 수익률 하향 가능(정상) + **MDD/분산이 현실화**. 락박스에서 “갑자기” 무너지는 케이스 감소.
- **(d) PASS 조건**
  - Arm B/C에서 `lockbox_min` 악화 금지 또는 `worst_mdd` 개선
  - 유니버스 로그가 “현재 생존 종목 고정” 패턴을 보이지 않음(정성 게이트지만 자동 규칙화)

### 4) 과최적화 방지: “Purged Walk-forward + 선택 규칙 고정(anti-cherry-pick)”
- **(a) 왜 필요한지**
  - tuning_mean이 챔피언 대비 흔들리고(lockbox는 동일) → **탐색이 신호를 못 찾는 게 아니라, 선택 규칙이 불안정**하거나 fold 누수가 섞여 “선발이 무의미”할 수 있음.
- **(b) 위험/부작용**
  - 성능(특히 튜닝)이 내려가고, 후보 PASS가 줄어듦. 대신 “진짜 개선”만 남음.
- **(c) 최소 실험(2~3 arms)**
  - **실험 #4: Purge/Embargo + 안정성 선택규칙 스윕**
    1) **(1) 실험 정의**
       - Arm A: 현행 CV
       - Arm B: Purged CV(이벤트/리밸런스 윈도우에 purge) + embargo N일(예: 5~10영업일 중 1안 고정)
       - Arm C: Arm B + **선택 기준을 lockbox_min 우선**(mean이 아니라 min/하방 안정성 우선)으로 고정
    2) **(2) 게이트**
       - fold 간 성능 분산(표준편차/최악 fold) 임계치 초과 시 FAIL
       - 선택 규칙이 “튜닝 최상위만 고르는” 형태로 되돌아가면 FAIL
    3) **(3) 기대 관측치**
       - 평균수익은 비슷/하락 가능, 대신 **worst fold, lockbox_min 안정**.
- **(d) PASS 조건**
  - Arm B/C에서 `lockbox_min` +0.01 이상 또는 `worst_mdd` 0.005 이상 개선
  - fold 최악 성능(예: fold14_mdd 포함) 악화 금지

### 5) 운영 리스크/자동루프 안정화: “결정론 + 실패-폐쇄(fail-closed) + 관측지표 대시”
- **(a) 왜 필요한지**
  - 48시간 루프에서 “가끔 잘 되고 가끔 안 되는” 비결정론/데이터 결측/캐시 불일치가 있으면 **성능 정체처럼 보이는 운영 이슈**가 발생.
- **(b) 위험/부작용**
  - 실패-폐쇄로 인해 실행이 더 자주 중단될 수 있음(정상). 대신 잘못된 PASS를 차단.
- **(c) 최소 실험(2~3 arms)**
  - **실험 #5: 재현성/모니터링 패치 A/B**
    1) **(1) 실험 정의**
       - Arm A: 현행
       - Arm B: 난수 seed/데이터 버전/피처 해시 고정 + 결과 메타데이터(커밋/데이터스냅샷/설정해시) 저장
       - Arm C: Arm B + “결측/비정상 유니버스/비용모델 미적용/포지션 수(8~14) 위반” 시 즉시 FAIL(리포트 자동 출력)
    2) **(2) 게이트**
       - 동일 입력 재실행 시 결과 해시 동일(또는 허용 오차 내) 아니면 FAIL
       - 포지션 수 8~14 위반 발생 시 FAIL
    3) **(3) 기대 관측치**
       - PASS 수는 줄어도 **PASS의 신뢰도 상승**, 원인분해 시간이 급감.
- **(d) PASS 조건**
  - 재실행 재현성 통과(결과 변동 허용범위 내)
  - 자동 리포트에 “위반 원인 1줄 요약 + 재현 커맨드”가 남음

## 성능이 안 움직일 때: 원인 분해 아이디어(트리거/적용/노출/비용/레짐) — 명령형 진단 트리

### A. Trigger(신호 생성) 문제
- [ ] 신호 히트율(방향 적중률) vs 페이오프(평균 이익/손실) 분리 로그
- [ ] 상위 신호일(Top-K)만 따로 성과 측정 → “강한 날만 먹는지/약한 날이 발목인지” 확인
- [ ] 피처 중요도/상관 구조를 기간별로 저장(레짐별 drift 탐지)

### B. Apply(적용/체결 타이밍) 문제
- [ ] decision 시점(t-1 close)과 execution 시점(t open/close) 수익을 분리해 기록
- [ ] “신호는 맞는데 체결이 역행” 패턴(갭/오버나잇)에 대한 별도 리포트 생성
- [ ] 리밸런스 빈도(일/주) 바꿨을 때 성능 민감도 체크(너무 민감하면 과최적화/비용 이슈)

### C. Exposure(노출/구성) 문제 — 8~14개 집중 조건 하에서 특히 중요
- [ ] 섹터(Tech/Healthcare) 내에서도 **서브산업 노출**(예: semis vs software, biotech vs pharma) 분해
- [ ] 베타/팩터(시장, 퀄리티, 모멘텀) 노출을 회귀로 기록 → “알파가 아니라 팩터 베팅”인지 확인
- [ ] 종목 수(8~14) 준수 + 상위 1~2종목 집중도(최대 비중) 상한 적용 후 성능 변화 체크

### D. Cost(비용/회전율) 문제
- [ ] gross alpha(비용 전) vs net alpha(비용 후) 를 항상 함께 출력
- [ ] turnover 기여도 분석: “수익 기여 상위 트레이드” vs “비용만 낸 트레이드” 분리
- [ ] ADV 대비 거래비중 분포 기록(임팩트 리스크 상시 감시)

### E. Regime(레짐) 문제
- [ ] 변동성(예: VIX), 금리(예: 10Y), 크레딧 스프레드(관측지표로만; ETF 매매 금지) 구간별 성과 분해
- [ ] 실적 시즌/연말/리스크오프 구간에서만 깨지는지 이벤트 캘린더로 태깅
- [ ] 레짐별로 “같은 신호가 반대로 작동”하면: 신호 자체를 스위칭하기보다 **리스크(포지션 사이징/현금비중)만 조절**하는 게 우선

### PASS 평가 기준(전체 공통, 48시간 루프용)
- [ ] **하드 PASS:** 누수 0건, 비용모델 적용 확인, 포지션 수 8~14 준수, 재현성 통과
- [ ] **소프트 PASS:** `lockbox_min` 악화 금지(또는 +0.01 개선), `worst_mdd` -0.115 이하로 악화 금지
- [ ] **채택 우선순위:** mean 개선보다 **min/MDD 안정 개선**을 1순위로 채택(현재 챔피언이 이미 안정적이므로)

위 5개를 “각 1개 실험(arms 2~3)”로 고정하면, 24~48시간 안에 누수/비용/서바이버십/과최적화/운영리스크를 동시에 정리하면서도 케이스 폭발 없이 자동 루프에 안정적으로 태울 수 있음.
