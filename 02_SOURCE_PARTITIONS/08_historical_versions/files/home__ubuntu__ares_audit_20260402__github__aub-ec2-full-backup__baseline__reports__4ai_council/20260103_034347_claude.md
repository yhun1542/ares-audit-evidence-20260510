## 1. 우선순위 TOP 5 액션

### ━━━ P1: Degenerate Fold 원인 규명 ━━━

**(a) 왜 필요한지**
- 4/10 폴드가 무효 = OOS Mean 신뢰도 붕괴
- 유효 폴드 6개만으로 계산 시 실제 성능 불명

**(b) 위험/부작용**
- 폴드 제거 시 샘플 수 감소 → 분산 증가
- 원인이 데이터면 전략 문제 아님

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P1-A | 각 degenerate fold에서 `trade_count`, `exposure_mean` 로깅 | 자동 | trade=0이면 시그널 미발생, exposure<0.1이면 진입조건 과잉 |
| P1-B | Fold 1,2,3,8 기간만 별도 백테스트 (동일 파라미터) | OOS>0 | 해당 구간 레짐 특성 확인 |
| P1-C | 시그널 발생 횟수 vs 실제 체결 횟수 비교 | 차이<5% | 슬리피지/필터 과잉 여부 |

**(d) PASS 조건**
```
✅ PASS: degenerate 원인 식별 + 유효폴드 OOS Mean ±0.3 이내 재현
❌ FAIL: 원인 미식별 → 전략 동결, 인프라 점검
```

---

### ━━━ P2: MDD/Risk 메트릭 복구 ━━━

**(a) 왜 필요한지**
- `worst_mdd: None` = 드로다운 미측정 상태에서 라이브 불가
- 과최적화 여부 판단 불가

**(b) 위험/부작용**
- MDD 계산 로직 버그 시 다른 지표도 오염 가능성

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P2-A | `equity_curve` 출력 후 수동 MDD 계산 대조 | 일치 | 계산 로직 검증 |
| P2-B | 인위적 -20% 구간 삽입 후 MDD 탐지 확인 | MDD≥0.20 | 센서 작동 확인 |

**(d) PASS 조건**
```
✅ PASS: worst_mdd 수치 출력 + 수동계산과 오차 <1%
❌ FAIL: 버그 수정 후 전체 백테스트 재실행
```

---

### ━━━ P3: OOS 점프 누수 점검 ━━━

**(a) 왜 필요한지**
- 2.63 → 3.32 (+26%) 점프는 비정상
- 미래 정보 누수 or 서바이버십 바이어스 의심

**(b) 위험/부작용**
- 누수 발견 시 모든 과거 실험 무효화 필요

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P3-A | `t+1` 시그널로 `t` 가격 진입 여부 코드 리뷰 | 자동 | look-ahead 없음 확인 |
| P3-B | 랜덤 시그널 대체 후 OOS 측정 | OOS<1.0 | 랜덤이 1.0 넘으면 인프라 버그 |
| P3-C | Train/Test 날짜 경계에서 종목 리스트 일치 여부 | 100% 일치 | 서바이버십 배제 |

**(d) PASS 조건**
```
✅ PASS: 랜덤 OOS<1.0 + look-ahead 없음 + 종목 일치
❌ FAIL: 누수 지점 식별 후 파이프라인 전면 수정
```

### ━━━ P4: 비용 모델 현실화 ━━━

**(a) 왜 필요한지**
- rebalance 로그 파싱 실패 = 거래비용 미반영 가능성
- 높은 exposure_max(0.84)에서 턴오버 비용 누락 시 OOS 과대계상

**(b) 위험/부작용**
- 비용 반영 시 OOS 급락 가능 (예상: -0.3~-0.8)

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P4-A | 거래당 10bp 비용 적용 후 OOS 재측정 | 자동 | OOS 변화량 기록 |
| P4-B | 턴오버율 계산 (월간 교체 종목 수) | <30%/월 | 과잉매매 여부 |

**(d) PASS 조건**
```
✅ PASS: 비용 적용 후 OOS > 2.0 유지
❌ FAIL: 턴오버 제한 조건 추가 (max 20%/월)
```

### ━━━ P5: 레짐 필터 점검 ━━━

**(a) 왜 필요한지**
- degenerate fold 4개가 특정 레짐(예: 고변동/약세장)에 집중 시 전략 구조적 약점

**(b) 위험/부작용**
- 레짐 필터 과잉 적용 시 거래 기회 소멸

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P5-A | Fold 1,2,3,8 기간의 SPY 수익률/VIX 평균 계산 | 자동 | 레짐 특성 식별 |
| P5-B | VIX>25 구간 제외 후 OOS 재측정 | OOS 변화<10% | 레짐 의존도 낮음 확인 |

**(d) PASS 조건**
```
✅ PASS: 레짐 제외 시 OOS 변화 <10%
❌ FAIL: 레짐별 파라미터 분리 또는 해당 레짐 헷지 추가
```

## 2. 성능 미변동 시 원인 분해 트리

```
성능 안 움직임
    │
    ├─ [트리거] 시그널 발생 안 함?
    │     └─ 점검: signal_count / day → 0이면 조건 과잉
    │
    ├─ [적용] 시그널 있는데 진입 안 함?
    │     └─ 점검: signal vs entry 비율 → <50%면 필터/슬리피지 과잉
    │
    ├─ [노출] 진입했는데 포지션 작음?
    │     └─ 점검: avg_position_size → <5%면 사이징 보수적
    │
    ├─ [비용] 수익 났는데 비용이 까먹음?
    │     └─ 점검: gross_return vs net_return → 차이 >30%면 턴오버 문제
    │
    └─ [레짐] 특정 구간만 작동?
          └─ 점검: 월별 OOS 분포 → 분산 >2x 평균이면 레짐 의존
```

## 3. 48시간 자동 루프 설정

```yaml
# autopilot_config.yaml
loop_interval: 6h
max_iterations: 8

experiments:
  - id: P1-A
    cmd: python3 tools/fold_diagnostics.py --folds 1,2,3,8
    gate: trade_count > 0
    on_fail: ALERT + PAUSE
    
  - id: P2-B
    cmd: python3 tools/mdd_sensor_test.py --inject -0.20
    gate: detected_mdd >= 0.19
    on_fail: ALERT + PAUSE
    
  - id: P3-B
    cmd: python3 backtest.py --signal RANDOM --seed 42
    gate: oos_mean < 1.0
    on_fail: CRITICAL + STOP_ALL
    
  - id: P4-A
    cmd: python3 backtest.py --cost-bps 10
    gate: oos_mean > 2.0
    on_fail: LOG + CONTINUE
    
  - id: P5-A
    cmd: python3 tools/regime_analyzer.py --folds 1,2,3,8
    gate: auto_log
    on_fail: LOG + CONTINUE

promotion_gate:
  - all P1,P2,P3 PASS
  - oos_mean > 2.5 (with costs)
  - degenerate_folds <= 2
```
