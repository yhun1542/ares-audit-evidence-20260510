[우선순위 및 실행 계획]

현재 상태 분석 결과, **Last PASS Candidate와 Champion의 Lockbox 성능이 소수점 16자리까지 완전히 동일함**을 식별했습니다. 이는 모델 파라미터가 변경되었음에도 실제 홀드아웃 데이터에서의 의사결정 로직에 전혀 영향을 주지 않았거나(유효성 없음), 파이프라인 상의 캐싱/시드 고정 버그일 가능성이 높습니다. 따라서 다음 48시간은 '새로운 전략 탐색'보다 '변화 민감도 확인' 및 '리스크 제어'에 집중해야 합니다.

### 1. TOP 5 우선순위 (코드/아키텍처/전략)

1.  **[Critical/Bug] Lockbox 민감도 검증 (Sensitivity Check)**: 변경된 하이퍼파라미터가 실제 거래 시그널을 생성하는지 확인. 코드가 헛돌고 있을 확률 90% 이상.
2.  **[Risk] 동적 레짐 필터(Dynamic Regime Filter) 도입**: `tuning_min`이 개선되지 않는 점은 특정 하락장(Crash)에서 방어 로직이 작동하지 않음을 의미. ETF(QQQ/XLV)의 변동성을 관측지표로 삼아 진입 차단.
3.  **[Universe] 상관관계 기반 종목 필터링 (Decorrelation)**: Tech+Healthcare 8~14종목은 금리 민감도가 비슷하여 공멸 가능성 높음. 상관계수 임계값 적용.
4.  **[Cost] 슬리피지/지연 거래 강제 적용**: 2026년 시점의 유동성 변화 반영. 주문 후 1-bar 지연(Open 거래) 혹은 거래비용 보수적 책정(5bps -> 10bps) 시 생존 여부 확인.
5.  **[Logic] 손절매(Stop-loss) 로직 분리**: 모델 예측과 별개로 작동하는 Hard Stop-loss(-5%~-7%)가 `tuning_min`을 방어하는지 테스트.

### 2. 실행 가능한 Patch / 실험 (48시간 루프용)

#### 실험 A: 파라미터 민감도 및 다양성 강제 (Sanity Check)
*   **(a) 필요성**: `lockbox_mean`이 완전히 동일한 현상은 비정상. 전략이 과적합되었거나 변경 사항이 실제 웨이트(Weight) 산출에 반영되지 않음.
*   **(b) 위험/부작용**: 기존 챔피언 폐기 가능성(기존 성과가 우연일 수 있음).
*   **(c) 실험 정의 (3-5개)**
    1.  `EXP_SENS_01`: 랜덤 시드(Seed)를 변경하여 Lockbox 점수 변동폭 측정 (변동 없으면 데이터 파이프라인 버그).
    2.  `EXP_SENS_02`: Lookback Window를 강제로 2배 늘리거나 줄여서 Lockbox 점수 변화 확인.
    3.  `EXP_SENS_03`: Feature 중 상위 50%를 강제로 0으로 마스킹(Masking) 후 성능 변화 확인.
*   **(d) PASS 조건**:
    *   Lockbox Mean/Min 값이 기존 `1.3295...`와 **달라야 함** (소수점 4자리 이상).
    *   성능이 하락하더라도 변화가 관측되어야 실험 유효성 입증.

#### 실험 B: XLV/XLK 내재변동성 기반 레짐 필터 (Regime Filter)
*   **(a) 필요성**: `tuning_min`(-1.349)의 개선이 없음. 헬스케어(XLV)와 테크(XLK) ETF의 변동성이 튈 때 포지션을 강제 청산(Cash 전환)해야 함.
*   **(b) 위험/부작용**: 잦은 진입/청산으로 인한 거래비용(Turnover) 증가, 상승장 초입 놓침(Whipsaw).
*   **(c) 실험 정의 (3-5개)**
    1.  `EXP_REGIME_VIX`: $VIX > 25 (or Rolling 95%ile) 시 현금 비중 100%.
    2.  `EXP_REGIME_MA`: 주식 유니버스 평균이 MA200 하회 시 매수 금지.
    3.  `EXP_REGIME_COV`: 유니버스 내 종목 간 평균 상관계수가 0.8 이상일 때 포지션 50% 축소.
*   **(d) PASS 조건**:
    *   `tuning_min` > -1.2 (최악의 경우 방어).
    *   `worst_mdd` > -0.07 (MDD 7% 이내 방어).
    *   Turnover < 5.0 (과도한 매매 방지).

#### 실험 C: 최소 분산 최적화 + 상관관계 페널티 (Portfolio Optimizer)
*   **(a) 필요성**: 8~14개 종목 집중 투자 시, 특정 섹터 악재에 취약. 단순 시총 가중이나 Equal Weight 대신 리스크 분산 필요.
*   **(b) 위험/부작용**: Momentum이 강한 주도주 비중이 축소되어 수익률(`tuning_mean`) 저하 가능성.
*   **(c) 실험 정의 (3-5개)**
    1.  `EXP_OPT_HIER`: HRP(Hierarchical Risk Parity) 적용하여 클러스터링 기반 비중 배분.
    2.  `EXP_OPT_PENALTY`: 공분산 행렬에 페널티 항 추가하여 특정 종목 비중 15% 초과 금지.
    3.  `EXP_OPT_INVVOL`: 단순 역변동성(Inverse Volatility) 비중 가중.
*   **(d) PASS 조건**:
    *   Fold14 MDD 개선 (기존 -0.0495 대비 상향).
    *   Sharpe Ratio 유지 또는 상승.

### 3. 성능 정체 원인 분해 (Debugging Checklist)

성능 지표가 움직이지 않거나 `tuning_min`이 개선되지 않을 경우, 다음 순서로 원인을 규명하고 로그를 남기십시오.

1.  **트리거 실패 (Trigger Logic)**:
    *   예측 스코어가 임계값(Threshold)을 넘지 못해 매매 자체가 발생하지 않았는가?
    *   *Check*: `Signal_Count` 및 `Trade_Count` 로그 확인.
2.  **적용 실패 (Allocation Logic)**:
    *   매수 신호는 떴으나, `min_weight` 제약이나 `cash_buffer` 때문에 실제 포지션 크기가 0에 수렴했는가?
    *   *Check*: 최적화 결과 `w` 벡터의 `sum()` 및 0이 아닌 요소 개수 확인.
3.  **노출 부족 (Exposure/Beta)**:
    *   포트폴리오가 시장(SPY/QQQ)과 너무 유사하게 움직여(Beta ~ 1) Alpha를 생성하지 못하는가?
    *   *Check*: Benchmark와의 Correlation 및 Active Share 비율.
4.  **비용 잠식 (Cost Impact)**:
    *   Gross Return은 개선되었으나, 잦은 리밸런싱으로 Net Return이 제자리인가?
    *   *Check*: `Gross_Sharpe` vs `Net_Sharpe` 스프레드 확대 여부.
5.  **레짐 불일치 (Regime Mismatch)**:
    *   훈련 데이터의 최근 구간(2025년 하반기 등)이 과거 패턴과 완전히 다른 "Data Drift" 구간인가?
    *   *Check*: 최근 6개월 데이터의 Feature 분포(Mean, Std)가 전체 기간과 2-sigma 이상 차이 나는지 확인.
