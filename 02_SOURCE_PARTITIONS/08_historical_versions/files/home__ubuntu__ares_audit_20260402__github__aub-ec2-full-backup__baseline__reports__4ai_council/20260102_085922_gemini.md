### 2. 제안별 상세 명세

#### 1) [CRITICAL] MDD Calculation Fix & NaN Handling
*   **(a) 필요성**: `worst_mdd: None`은 리스크 측정 불가를 의미. 0으로 나누기, NaN 전파, 혹은 데이터 윈도우 부족으로 인한 치명적 오류. 현재 `oos_mean: 1.88`의 신뢰도 0.
*   **(b) 위험/부작용**: MDD가 정상 산출될 경우 현재 Champion 폐기 가능성 매우 높음(Hidden Risk 노출).
*   **(c) 최소 실험**:
    *   **Exp 1**: 수익률 곡선(Cumulative Returns)에 `.fillna(0)` 전처리 후 MDD 재계산.
    *   **Exp 2**: Lookback window를 전체 기간으로 강제 확장하여 MDD 산출 로직 디버깅.
    *   **Exp 3**: 극단적 하락 구간(2022년 Tech Bear Market)만 잘라내어 MDD 산출되는지 확인.
*   **(d) PASS 조건**:
    *   (1) 실험 정의: Fix MDD function -> Run Backtest
    *   (2) 게이트: `worst_mdd` is not None AND `worst_mdd` < -0.05 (현실적 수치)
    *   (3) 기대 관측치: OOS Mean 하락 하더라도 MDD 수치 확보 필수.

#### 2) [REALITY] Cost Model Aggression
*   **(a) 필요성**: Tech/Bio 종목은 변동성이 크고 스프레드가 넓음. 현재 `oos_mean` 1.88이 과소평가된 비용 구조(Zero impact assumption) 덕분인지 확인 필요.
*   **(b) 위험/부작용**: 전략 전면 수정 필요성 대두(Sharpe < 1.0 으로 급락 가능).
*   **(c) 최소 실험**:
    *   **Exp 1**: 편도 수수료(bps) 5 -> 15 상향.
    *   **Exp 2**: 슬리피지 모델을 'Fixed'에서 'Volume Share' 기반(유동성 부족 시 비용 급증)으로 변경.
*   **(d) PASS 조건**:
    *   (1) 실험 정의: Apply High Cost Model -> Run
    *   (2) 게이트: `oos_mean` > 1.2 (비용 증가 후에도 우위 유지)
    *   (3) 기대 관측치: 회전율(Turnover) 감소, 거래 횟수 감소.

#### 3) [BIAS] Dynamic Universe Validation
*   **(a) 필요성**: 8~14개 종목 선정 시, 현재 시점의 대장주(NVDA, LLY 등)를 과거 데이터에 고정한 채 백테스트하는지(Look-ahead Bias) 확인.
*   **(b) 위험/부작용**: 유니버스 동적 변경 시 데이터 로딩 속도 저하 및 구현 복잡도 증가.
*   **(c) 최소 실험**:
    *   **Exp 1**: 고정 리스트(Static) vs 월별 시가총액 상위 재선정(Dynamic) 성과 비교.
    *   **Exp 2**: 상장폐지/인수합병 종목 2~3개 강제 포함 후 로직 에러 체크.
*   **(d) PASS 조건**:
    *   (1) 실험 정의: Dynamic Universe(Monthly Rebal) -> Run
    *   (2) 게이트: `oos_mean` 드랍율 < 20%
    *   (3) 기대 관측치: 생존 편향 제거 후에도 알파 유지 확인.

#### 4) [ROBUSTNESS] Feature Neutralization
*   **(a) 필요성**: Tech/Healthcare 섹터는 금리/규제 뉴스에 동조화(Correlation) 심함. 단순 베타 플레이인지 고유 알파인지 분리 필요.
*   **(b) 위험/부작용**: 수익률 대폭 감소 가능성(베타 수익 포기).
*   **(c) 최소 실험**:
    *   **Exp 1**: 입력 Feature에서 'SPY' 또는 'QQQ'와의 상관관계 제거(Orthogonalization).
    *   **Exp 2**: 섹터 지수(XLK, XLV) 수익률을 Feature에서 차감 후 학습.
*   **(d) PASS 조건**:
    *   (1) 실험 정의: Neutralize Features -> Train -> Run
    *   (2) 게이트: `exposure_min` > 0.2 (완전 헷지 상태가 아닐 것), `oos_min` > 0
    *   (3) 기대 관측치: MDD 개선, 샤프 비율 유지/상승.

#### 5) [EXECUTION] Signal Decay & Lag Simulation
*   **(a) 필요성**: 시그널 발생 후 체결까지 지연(1분~1일) 발생 시 성능 유지 여부. 과최적화된 타이밍 의존도 체크.
*   **(b) 위험/부작용**: 단타성 전략일 경우 성능 파괴됨.
*   **(c) 최소 실험**:
    *   **Exp 1**: `trade_at = close` -> `trade_at = next_open` (1일 지연).
    *   **Exp 2**: 시그널 강도에 Random Noise(5%) 추가 후 진입/청산 테스트.
*   **(d) PASS 조건**:
    *   (1) 실험 정의: Lag Execution 1 bar -> Run
    *   (2) 게이트: `oos_mean` > 1.0
    *   (3) 기대 관측치: 성능 하락폭 확인 (민감도 측정).

### 3. 성능 정체(Stagnation) 시 원인 분해 아이디어

성능 지표가 움직이지 않거나 `oos_mean`이 개선되지 않을 때 다음 순서로 점검:

1.  **트리거(Trigger) 실패**:
    *   *Check*: `trade_count`가 0이거나 매우 낮은가?
    *   *Action*: 진입 임계값(Threshold) 완화. 변동성 필터(VIX)가 너무 엄격한지 확인.

2.  **적용(Application) 오류**:
    *   *Check*: `exposure_max`가 0.84에 도달하지 못하고 낮은 수준(0.2~0.3)에서 횡보하는가?
    *   *Action*: 포지션 사이징 로직(Kelley Criterion 등)의 레버리지 제한 파라미터 확인.

3.  **노출(Exposure) 상쇄**:
    *   *Check*: Long/Short 비율이 5:5에 수렴하여 Spread 수익만 남기고 베타가 0이 되었는가?
    *   *Action*: Net Exposure 허용 범위 확대 (+-0.1 -> +-0.3).

4.  **비용(Cost) 잠식**:
    *   *Check*: Gross Profit은 우상향인데 Net Profit이 횡보하는가?
    *   *Action*: 회전율 강제 제한(Holding Period 최소 3일 이상 설정).

5.  **레짐(Regime) 불일치**:
    *   *Check*: 특정 연도(2022 등)에만 손실이 집중되는가?
    *   *Action*: 레짐 디텍터(Regime Classifier) 추가하여 하락장/횡보장 전용 로직 분기.
