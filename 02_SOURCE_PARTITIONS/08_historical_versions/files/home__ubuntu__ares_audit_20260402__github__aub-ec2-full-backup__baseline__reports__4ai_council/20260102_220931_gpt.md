# TOP5 우선순위 제안 (코드/아키텍처/전략)

### (b) 위험/부작용
- 로그/스키마 강제 시 기존 실험 일부가 실패할 수 있음(단, 그게 정상: 실패를 조기 노출).

  - `rebalance.jsonl`과 `rebalance.csv`가 **파싱 성공**
  - `run_hash/lane_hash`가 **None이 아님**

## 2) [누수/과최적화] Fold 퇴화(degenerate) 제거 + Purge/Embargo 적용
### (a) 왜 필요한지
- degenerate fold는 **실제 OOS가 아닌 “가짜 OOS”**를 만들고, 신호가 좋아 보여도 실거래에서 죽는다.
- 누수/중복구간이 끼면 “성능이 안 움직이거나” “갑자기 무너지는” 패턴이 자주 나온다.

### (b) 위험/부작용
- OOS 평균이 단기적으로 떨어질 수 있음(정상: 거품 제거).
- 샘플 수가 줄어 분산 증가 → 게이트 기준을 같이 조정해야 함.

### (c) 최소 실험(아래 실험 #E2로 통합)
- (E2-1) **시간기반 CV**에서 purge window(예: 5~20거래일) + embargo 적용
- (E2-2) fold별 샘플 수/클래스 비율/거래일 수 최소 기준 미달 시 **fold 자체를 drop**
- (E2-3) “훈련/검증 기간 겹침(날짜 중복)” 자동 탐지 후 FAIL

### (d) PASS 조건
- degenerate_folds가 **빈 리스트** 또는 전체 fold의 **≤10%**
- OOS mean이 낮아져도:
  - OOS min(최악 fold)이 **지속적으로 음수 확대되지 않을 것**
  - fold별 성능 분산이 과도(예: 상/하 10배)하지 않을 것

## 3) [비용/현실성] 비용/슬리피지/회전율(turnover) 미반영 제거(핵심)
### (a) 왜 필요한지
- Tech/Healthcare 8~14종목 롱/숏/헤지 구조에서 성과가 “안 움직이는” 가장 흔한 원인은
  - **알파는 있는데 비용이 먹어치움**
  - 또는 **회전이 너무 커서 비용 반영 시 0으로 수렴**
- 현재 리밸런스 로그가 깨져 있어 비용 기여도를 못 보고 있음 → 반드시 같이 고쳐야 함(=E1과 짝).

### (b) 위험/부작용
- 비용 반영하면 대부분 전략 성과가 하락(정상).
- 과도한 비용 페널티는 “거래 안 하는” 해로 수렴할 수 있음 → 최소 거래 빈도/노출 게이트 필요.

### (c) 최소 실험(아래 실험 #E3로 통합)
- (E3-1) 거래비용 모델(고정+체결비율+스프레드 대용)을 **백테스트 PnL에 강제 반영**
- (E3-2) turnover 상한 또는 페널티(예: 일/주 단위) 적용
- (E3-3) 숏/레버리지 사용 시 borrow/financing 대용 비용 추가(단순 상수로 시작)

### (d) PASS 조건
- 비용 반영 후에도:
  - OOS mean이 **유의미하게 양수 유지**
  - turnover가 목표 범위로 수렴(예: 상한 초과 빈도 < 5%)
  - “거래 0” 해(노출 0에 수렴)가 아닌지 확인(아래 #E4 게이트와 함께)

# 성능이 “안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래 순서로 **반드시 로그로 수치화**해서 병목을 찾는다(질문 없이 바로 실행 항목).

## A) Trigger(신호 발생) 단계
- 신호가 거의 안 바뀌는가?
  - 지표: 일별/주별 score 분산, 종목별 rank 변동률, 신규 진입/청산 빈도
- 레짐 필터(ETF 관측: XLK/XLV)로 인해 대부분 “거래 금지” 상태인가?
  - 지표: 게이트 통과율(%), 통과일의 성과 vs 미통과일

## B) Apply(리밸런스/체결 규칙) 단계
- 리밸런스가 실제로 실행되는가, 아니면 규칙 충돌로 스킵되는가?
  - 지표: 리밸런스 시점 수, 스킵 사유 카운트(제약 위반/유동성 부족/데이터 결측)

## C) Exposure(노출/포지션) 단계
- 노출이 0에 수렴(알파가 있어도 “안 삼”) 또는 과도(0.84까지 튐)한가?
  - 지표: gross/net 노출 시계열, 종목 수(8~14 유지 여부), 상위 1종목 비중
- Tech/Healthcare 제약이 깨져 “우연히 먹은” 성과가 사라져 정체처럼 보이는가?
  - 지표: 섹터 위반 횟수(0이어야 함), 위반일 성과 기여

## D) Cost(비용) 단계
- 비용이 알파를 먹어치우는가?
  - 지표: 총 PnL을 “gross alpha / 비용 / 슬리피지 / 금융비용”으로 분해
- turnover가 높은가?
  - 지표: 일/주 turnover, turnover 상한 위반일의 성과

## E) Regime(레짐/시장 상태) 단계
- 특정 레짐에서만 성과가 나고 최근은 레짐 밖인가?
  - ETF는 관측만: XLK/XLV 추세/변동성, VIX 대용 지표(가능하면)로 구간 분리
  - 지표: 레짐별 OOS mean, MDD, hit-rate, 평균 보유기간

## 실행 순서(24~48h) — 명령형 체크리스트
1) **E1 적용 후 1회 루프 즉시 통과**(로그/해시/리밸런스 파싱/리스크 지표 산출)시키기  
2) **E2로 degenerate fold 제거 + purge/embargo** 적용 → OOS 재계산  
3) **E3로 비용/turnover 반영** → “알파 vs 비용” 분해 테이블 생성  
4) **E4로 유니버스/포지션 제약 하드게이트** → 8~14 / Tech+HC / ETF 거래 0 검증  
5) **E5로 lookahead/서바이버십 감사** → 위반 0 만들기(위반 시 즉시 FAIL)

이 5개가 통과되면 그 다음에야 “신호 개선(피처/모델)”을 만질 자격이 생긴다. 현재는 성능이 안 움직여도 이상하지 않은 상태(로그/폴드/비용/누수/리스크 산출이 동시에 흔들림)라서, 위 5개를 먼저 고정하는 것이 가장 빠른 수익/시간 비율이다.
