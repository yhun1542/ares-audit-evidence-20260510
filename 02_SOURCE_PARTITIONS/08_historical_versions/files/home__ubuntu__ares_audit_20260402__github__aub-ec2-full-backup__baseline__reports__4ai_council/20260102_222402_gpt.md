## 24~48시간 TOP5 우선순위(코드/아키텍처/전략) — 명령형 체크리스트

1) **누수/시간정렬(Data “as-of”) 센티넬을 CI 게이트로 고정**
2) **CV(검증) 재구성: degenerate fold 0개로 만들고 “purged walk-forward”로 통일**
3) **비용(수수료/스프레드/슬리피지) + 턴오버 상한을 OOS에 강제 반영**
4) **리밸런스 로그/재현성 패치: rebalance pinpoint가 “항상” 돌게 만들기(현재 에러 우선 제거)**
5) **유니버스/섹터/보유종목수(8~14) 강제 + ETF는 “관측지표(레짐)”로만 사용**

아래는 **총 5개 실험/패치(E1~E5)**로 제한하고, 각 제안은 이들 중 2~3개를 재사용해서 요구조건(최소 실험 2~3개)을 충족하도록 구성함.

# 공통 48시간 자동 루프 형태 (E1~E5)

각 실험은 동일 포맷으로 운영: **(1) 실험 정의 → (2) 게이트 → (3) 기대 관측치**  
그리고 **실패 시 즉시 롤백/원인로그 남기기**.

---

## E1) Leakage/시간정렬 센티넬 (최우선)
### (1) 실험 정의
- 모든 feature/라벨/체결가격에 대해 **as-of timestamp**를 강제하고, 모델 입력은 **t 시점에 존재 가능한 데이터만** 사용하도록 “shift/lag 규칙”을 코드로 고정.
- **의도적 누수 버전(cheat feature)** 도 1개 만들어서, 센티넬이 이를 “확실히 검출”하는지 같이 테스트.

### (2) 게이트
- `leakage_unit_tests` 전부 PASS (미래 데이터 참조/인덱스 역전/룩어헤드 검출 0건)
- “cheat feature”는 성능이 급등해야 하며(검출용), 동시에 센티넬이 이를 FAIL 처리해야 함

### (3) 기대 관측치
- 성능이 떨어질 수도 있으나, **OOS 변동이 줄고** fold 간 일관성이 좋아짐
- “no-delta(개선 없음)”의 원인이 누수/정렬 문제였다면, 이후 실험에서 **개선 시그널이 다시 움직이기 시작**

---

## E2) CV 재구성: degenerate folds 제거 + purged walk-forward
현재 `degenerate_folds: [1,2,3,8]` 는 “검증이 성립하지 않는 구간”이 있다는 뜻이라 **과최적화/허상 성능/무변화(no-delta)** 를 최상단에서 유발 가능.

### (1) 실험 정의
- Walk-forward를 **고정 길이(훈련/검증)** 로 만들고,
- 리밸런스 주기/홀딩기간이 있으면 그만큼 **purge(완충구간)** 삽입
- 각 fold에 대해 **최소 샘플 수/거래일 수** 미달이면 fold 자체를 생성하지 않음(“생성 로직에서 차단”)

### (2) 게이트
- degenerate fold = 0
- fold별 테스트 구간 길이가 동일하거나 최소 기준 이상
- OOS mean만 보지 말고 **OOS min, 하위 10% 분위**가 악화되지 않는지 같이 통과조건에 포함

### (3) 기대 관측치
- 기존 “개선이 안 움직임”이 fold 붕괴/평가무력화였다면, 실험 간 순위가 바뀌고 분산이 정상화됨
- oos_mean이 약간 감소해도 신뢰구간이 좁아지는 것이 정상 신호

---

## E3) 비용/슬리피지/턴오버 상한을 OOS에 강제
현재 리포트에 **worst_mdd: None**, 그리고 리밸런스 로그도 부재라면, 비용/운영 리스크가 사실상 미반영일 가능성이 큼.

### (1) 실험 정의
- 종목별 **거래비용(고정 커미션+bps)**, **스프레드/슬리피지(ATR 또는 ADV 기반 bps)** 를 net return에 반영
- **턴오버 상한**(예: 일/주 단위) 또는 거래량 기반 상한(ADV의 x%)을 강제
- 체결은 “다음날 VWAP/오픈+슬리피지” 등 보수적으로 통일(백테스트 체결가 환상 제거)

### (2) 게이트
- turnover(연환산/월평균) < 사전 상한
- net OOS mean이 gross 대비 급락한다면(예: 30~50%+), 원인이 비용인지 분해 로그가 남아야 PASS
- 비용 민감도(슬리피지 2배)에서 전략이 즉시 붕괴하면 FAIL(운영 불가)

### (3) 기대 관측치
- “좋아 보이는데 실전에서 안 됨” 패턴이 비용 때문인지 즉시 드러남
- 이후 개선 실험은 **비용을 이기는 방향**으로만 진화(과최적화 방지)

---

## E4) 리밸런스 로그/재현성 패치(운영 리스크 최우선)
현재 상태:
- `lane_hash/run_hash: None`
- `aub_rebalance_pinpoint` 가 `--base-log` 경로 오류 + csv/json 파싱 실패
- 즉, **무엇이 언제 어떻게 거래됐는지 비교 불가** → “no-delta” 원인 추적도 불가

### (1) 실험 정의
- 백테스트/시뮬레이터에서 리밸런스 이벤트를 **항상** 남김:
  - `rebalance.csv` (필수 컬럼: ts, symbol, target_w, prev_w, trade_qty, trade_notional, fill_px, cost_bps, reason)
  - `rebalance.jsonl` (동일 내용 + 디버그 필드)
- `lane_hash/run_hash` 를 실험 아티팩트에 강제 기록하고, diagnoser/pinpoint가 이를 기준으로 비교
- `aub_rebalance_pinpoint.py` 입력 포맷을 **csv/jsonl 자동 탐지**로 고정(파일 없으면 즉시 실패시키고 원인 메시지 명확화)

### (2) 게이트
- pinpoint 툴이 base/cand 모두에서 **에러 없이 실행**
- “차이점(diff)”이 0이면 그 이유(신호 동일/게이트로 트레이드 스킵/클리핑 등)가 로그로 설명돼야 PASS

### (3) 기대 관측치
- “성능이 안 움직임”이 실제로는 **리밸런스가 거의 안 일어나는 문제**인지 즉시 판별 가능
- 운영/감사 가능성 확보(실전 이행 전 필수)

---

## E5) 유니버스/섹터/보유수(8~14) 강제 + ETF는 레짐 “관측지표”로만
요구사항(미국주식 only, Tech+Healthcare 중심, 8~14 종목, ETF 매매 제외)을 **코드 레벨 제약조건**으로 박아야 과최적화/서바이버십/드리프트가 줄어듦.

### (1) 실험 정의
- 유니버스는 **point-in-time 섹터 분류**(GICS 등)로 Tech/Healthcare만 필터
- 포트폴리오 생성 단계에서 **보유 종목 수 8~14 강제**(rank top-K + tie-break 규칙 고정)
- ETF는 거래하지 않고, 관측지표로만 사용:
  - 예: `QQQ(tech)`, `XLV(healthcare)`, `SPY(시장)`의 모멘텀/변동성/크로스오버로 레짐 태그 생성 → 포지션 사이징/노출 상한 조정에만 사용
- survivorship 방지: 백테스트 시점에 존재하지 않는 종목/섹터 정보를 쓰면 즉시 FAIL (E1과 결합)

### (2) 게이트
- 매일/매 리밸런스마다 holdings_count ∈ [8,14] (예외 0)
- 섹터 비중(Tech+Healthcare) 최소치(예: 80%+) 유지
- ETF는 주문/체결 로그에 단 1건도 등장하면 FAIL

### (3) 기대 관측치
- 노출/종목수 드리프트가 사라지고 실험 간 비교가 공정해짐
- 레짐 관측치로 “트레이드 스킵/사이징 변화”가 생기면, 성능이 안 움직이던 상태에서 **노출 변화가 먼저 관측**될 가능성 큼

# 요청 1) TOP5 제안 요약(우선순위)
1. **E1 누수 센티넬** (누수/서바이버십 최상단 리스크 제거)
2. **E2 CV 재구성** (degenerate folds 제거 → 평가가 움직이게 함)
3. **E4 리밸런스 로그/재현성** (운영 리스크 + no-delta 원인추적 불가 상태 해소)
4. **E3 비용/턴오버 강제** (비용 미반영 리스크 제거)
5. **E5 유니버스/제약조건 강제 + ETF 레짐 관측** (요구사항 준수 + 과최적화 억제)

# 요청 2) 각 제안별 (a)(b)(c)(d)

아래 “최소 실험 2~3개”는 **E1~E5를 재사용**해서 충족.

## 제안 1: 누수/시간정렬 센티넬 고정
- (a) 왜: 누수는 OOS 평균을 올리거나(가짜 개선) 혹은 반대로 “변화가 의미 없게” 만들어 no-delta를 유발. Tech/HC는 이벤트/갭이 많아 더 취약.
- (b) 위험/부작용: 단기적으로 성능 급락 가능(정상). 기존 챔피언이 “사실상 무효”로 판정될 수 있음.
- (c) 최소 실험: **E1 + E2 + E5**
- (d) PASS: E1 누수 테스트 PASS, degenerate fold 0(E2), 섹터/보유수 제약 위반 0(E5)

## 제안 2: CV 재구성(purged walk-forward)
- (a) 왜: degenerate fold가 존재하면 실험 간 미세 차이를 구분 못해 “아무것도 개선되지 않는 것처럼” 보임.
- (b) 위험/부작용: 학습 데이터 감소로 oos_mean 하락 가능. 실험 속도 느려질 수 있음.
- (c) 최소 실험: **E2 + E1**
- (d) PASS: degenerate fold 0, fold별 OOS 분포가 정상(최소/분위값이 NaN/동일값으로 붕괴하지 않음)

## 제안 3: 비용/턴오버/체결 보수화
- (a) 왜: 비용을 빼면 개선이 “환상”이거나, 비용을 안 빼서 모델이 과도 매매로 도망가는 것을 못 잡음.
- (b) 위험/부작용: 성능 저하로 실험들이 전부 FAIL처럼 보일 수 있음(하지만 실전 적합성은 상승).
- (c) 최소 실험: **E3 + E4** (비용이 실제로 언제 발생했는지 로그로 확인 필수)
- (d) PASS: turnover 상한 준수, net 성과가 민감도 테스트에서 붕괴하지 않음, 비용 항목별 기여 로그 확보

## 제안 4: 리밸런스 로그/재현성(핀포인트 복구)
- (a) 왜: 지금은 pinpoint가 파일을 못 읽어 “왜 no-delta인지”를 영원히 못 봄. 운영 리스크도 최상.
- (b) 위험/부작용: 로그 스키마 변경으로 기존 리포트 파서가 깨질 수 있음(버전 태깅 필요).
- (c) 최소 실험: **E4 + E2 + E3** (검증/비용/거래가 모두 한 흐름으로 이어져야 함)
- (d) PASS: pinpoint 무에러 실행, base vs cand 리밸런스 diff가 “원인코드(reason)”로 설명됨

## 제안 5: 유니버스/제약조건 강제 + ETF 레짐은 관측만
- (a) 왜: 유니버스 드리프트/보유수 변동/섹터 혼입은 과최적화/서바이버십/비교불능을 유발. 요구사항 준수도 필수.
- (b) 위험/부작용: 종목수 강제는 집중도를 높여 MDD가 커질 수 있음(그래서 E3 비용+슬리피지와 같이 봐야 함).
- (c) 최소 실험: **E5 + E1 + E4**
- (d) PASS: 8~14 보유 강제 100% 준수, Tech/HC 비중 기준 충족, ETF 주문 0, 제약 위반 시 즉시 FAIL 로그

# 요청 3) 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)

아래를 **트리 형태로 로그/지표를 고정**해서 48시간 루프에서 자동 판별하게 만들기.

## A. 트리거(신호 생성) 레이어
- **신호가 상수화**: 스코어 분산(일별/종목별)이 0에 수렴하면 “모델/피처 적용 안 됨”
- **데이터 결측으로 전부 drop**: 유효 샘플 수(time×symbol) 급감 여부
- **시간정렬로 전부 한 칸 밀려 0효과**: E1에서 “shift 결과” 샘플 확인 로그 고정

**관측지표(필수)**: daily score std, NaN rate, valid universe count

## B. 적용(포트폴리오 구성/제약) 레이어
- **게이트가 전부 막음**: 레짐 필터/리스크 필터가 계속 OFF면 거래 0
- **클리핑/정규화가 전부 동일 포트**: weights가 항상 균등(또는 동일 8~14)으로 굳는지 확인
- **보유수 강제가 tie-break로 같은 종목만 반복**: 타이브레이크 규칙(시총/유동성/이전보유 우선 등) 고정 및 로그

**관측지표**: gate pass rate, holdings turnover(종목 교체율), weight entropy

## C. 노출(리스크/익스포저) 레이어
- 현재 `exposure_max ~0.84` 인데 **대부분 0 근처면** 전략이 사실상 꺼져 있음
- 반대로 **항상 상한에 붙어있으면** 신호 차이가 노출로 전달 안 됨

**관측지표**: gross/net exposure 시계열, exposure clipping 횟수, 섹터 노출

## D. 비용(현실성) 레이어
- 비용 반영 후 수익이 0 근처로 “납작”해지면, no-delta는 모델 문제가 아니라 **마찰비용이 알파를 먹는 구조**일 가능성
- 슬리피지 민감도(1x/2x)에서 결과가 급변하면 운영 불가

**관측지표**: 비용 기여도(commission/spread/impact), turnover 분해

## E. 레짐(시장 국면) 레이어 — ETF는 관측만
- `QQQ vs XLV 상대강도`, `SPY 추세`, `VIX proxy`(가능하면 지수 데이터)로 레짐 태그를 달고,
- 레짐별로 성과가 동일하면: 신호가 레짐과 무관(또는 신호 미적용)
- 레짐별로 성과가 갈리면: 레짐 기반 사이징/게이트로 개선 여지

**관측지표**: regime tag별 거래수/성과/노출, gate pass rate by regime

## 즉시 실행 순서(48시간)
1) **E4부터 고쳐서**(로그/핀포인트 복구) “무슨 일이 일어났는지”를 보이게 만든 뒤  
2) **E1/E2로 평가체계 정상화**(누수/degenerate fold 제거)하고  
3) **E3로 실전 제약을 강제**한 다음  
4) **E5로 유니버스/제약+레짐 관측**을 붙여 실험이 “움직이는지” 확인
