[명령형 체크리스트]

1.  **데이터 무결성 검증 (즉시 실행)**: Champion 모델의 `lockbox_min` (1.13)이 비정상적으로 높음. `Look-ahead Bias`(미래 참조) 여부 전수 조사. Feature 생성 시점과 Target 시점의 Lag 확인.
2.  **유니버스 편향 제거**: 현재 포트폴리오 내 수익 기여도 상위 1개 종목(예: NVDA, LLY 등)을 강제로 제외한 상태에서 Backtest 재구동 (`Kill-the-Winner` 테스트).
3.  **비용 파라미터 2배 적용**: `champion_v5`와 `candidate` 모델 모두 슬리피지/수수료 설정을 현재의 2배로 설정 후 MDD 변화 관측.
4.  **섹터 베타 분리**: Tech/Healthcare 개별 종목 수익률에서 XLK/XLV ETF 수익률을 뺀 `Idiosyncratic Alpha`만으로 시그널 테스트.
5.  **실험 대기열 주입**: 아래 제안된 5가지 Patch 중 상위 3개를 `experiment_system` 파이프라인에 등록.

### [제안 1] "Kill-the-Winner" 민감도 테스트 (Overfitting/Survivorship 점검)
*   **유형**: 리스크 점검 / 스트레스 테스트
*   **이유**: Champion의 Lockbox 성능이 너무 좋음. 특정 '슈퍼 스탁(예: 2023~2025 NVDA)'에 우연히 편승했을 가능성 배제 필요. Tech/Healthcare 섹터는 소수 종목이 지수를 왜곡함.
*   **위험/부작용**: 전략 자체의 논리가 맞아도, 주도주가 빠지면 샤프지수가 급락하여 멀쩡한 로직을 폐기할 위험 있음.
*   **실험 정의 (48hr Loop)**:
    1.  **실험**: 학습/검증 데이터셋에서 수익 기여도 1위, 2위 종목을 제외하고 동일 로직 구동.
    2.  **게이트**: `Original CAGR` 대비 하락폭이 40% 이내일 것. (60% 이상 방어)
    3.  **기대 관측치**: 수익률은 하락하더라도 MDD와 승률(Win Rate)이 유지되어야 함.

### [제안 2] Volatility Targeting (VolTarget) 오버레이 적용
*   **유형**: 전략/머니매니지먼트
*   **이유**: Candidate(`mrd_fsa`)는 MDD 방어가 탁월함(-4%). Champion의 높은 수익성과 Candidate의 방어력을 결합하기 위해, 개별 종목의 변동성이 특정 임계치(예: 연환산 30%)를 넘으면 포지션 사이즈를 강제로 줄이는 로직 추가.
*   **위험/부작용**: 강한 모멘텀 장세(변동성 동반 상승)에서 수익 기회 상실(Under-exposure).
*   **실험 정의 (48hr Loop)**:
    1.  **실험**: `Position_Size = Target_Vol / Rolling_Vol_20d`. (Tech/Bio 변동성 감안하여 Target Vol을 20~30%로 설정).
    2.  **게이트**: `Champion` 대비 MDD가 20% 이상 개선(-9% -> -7.2% 이하) 되고, CAGR 감소가 10% 미만일 것.
    3.  **기대 관측치**: 급락 구간에서 레버리지가 축소되며 MDD 개선.

### [제안 3] 실행 지연(Lag) 시뮬레이션 (운영 리스크 점검)
*   **유형**: 비용 미반영/운영 리스크
*   **이유**: 2026년 시점 시뮬레이션이므로, 실제 매매 시그널 발생 후 체결까지의 괴리(Slippage)나 데이터 수집 지연이 치명적일 수 있음.
*   **위험/부작용**: 단기 Mean Reversion 로직의 경우 성능이 파괴될 수 있음.
*   **실험 정의 (48hr Loop)**:
    1.  **실험**: 시그널 생성(Close) -> 매매 실행을 `Next Open`이 아닌 `Next Close` 혹은 `Next Open + 0.5% Penalty`로 설정.
    2.  **게이트**: `Lockbox Sharpe` > 1.0 유지.
    3.  **기대 관측치**: 성능 하락폭 확인을 통해 전략의 Time-Sensitivity 측정.

### [제안 4] 상대 모멘텀 필터 (Regime Filter)
*   **유형**: 로직 개선
*   **이유**: Tech/Healthcare가 시장(SPY)보다 약할 때도 롱 포지션을 잡는 것은 위험. 섹터 자체가 하락세일 때는 현금 비중을 늘려야 함.
*   **위험/부작용**: 대세 상승장 초입에서 진입이 늦어질 수 있음 (Lagging).
*   **실험 정의 (48hr Loop)**:
    1.  **실험**: `if (XLK or XLV) > SPY (Relative Strength 60d)` 조건일 때만 해당 섹터 개별주 매수 허용. 아니면 Cash.
    2.  **게이트**: `Worst MDD` < -7.0% (Champion보다 개선).
    3.  **기대 관측치**: 하락장에서 매매 횟수(Frequency) 급감, 방어력 상승.

### [제안 5] 앙상블 (Champion + Candidate)
*   **유형**: 아키텍처
*   **이유**: Champion(추세 추종 추정)과 Candidate(평균 회귀 추정)의 상관관계가 낮다면, 두 시그널을 50:50 또는 70:30으로 섞는 것이 최적.
*   **위험/부작용**: 로직 복잡도 증가, 코드 유지보수 비용 상승.
*   **실험 정의 (48hr Loop)**:
    1.  **실험**: `Final_Score = 0.7 * Champion_Score + 0.3 * Candidate_Score`. 상위 10개 종목 선정.
    2.  **게이트**: `Sharpe`가 두 모델의 단순 평균보다 높을 것 (Diversification Effect).
    3.  **기대 관측치**: 수익 곡선의 변동성(Variance) 감소.

### [성능 정체 시 원인 분해 (Debugging Guide)]

성능이 개선되지 않거나(Flat), 랜덤하게 움직일 때 다음 5가지 관점에서 점검:

1.  **Trigger (진입/청산)**:
    *   시그널이 너무 빈번한가? (Over-trading으로 인한 비용 누적)
    *   시그널이 너무 드문가? (Sample size 부족으로 인한 통계적 유의성 결여) -> *Action: Threshold 완화/강화 테스트.*
2.  **Application (체결)**:
    *   유동성이 낮은 종목(Small cap Bio)에 진입하려 했는가?
    *   매수 호가와 실제 체결가 사이의 괴리가 반영되었는가? -> *Action: 유동성 하위 20% 종목 블랙리스트 처리.*
3.  **Exposure (비중)**:
    *   특정 종목에 비중이 20% 이상 쏠리는가?
    *   포트폴리오가 현금만 들고 있는 날이 많은가? -> *Action: 개별 종목 Cap 10~15% 설정 강제.*
4.  **Cost (비용)**:
    *   Turnover(회전율) 대비 기대 수익이 낮은가?
    *   작은 수익을 자주 먹으려다 수수료에 녹는가? -> *Action: 최소 기대 수익률(Hurdle Rate) 미만 진입 금지.*
5.  **Regime (시장 국면)**:
    *   Tech/Bio 섹터 전체가 횡보장(Choppy Market)인가?
    *   현재 로직이 특정 금리/환율 구간에서만 작동하는가? -> *Action: 매크로 변수(10년물 금리 등)와의 상관계수 확인.*
