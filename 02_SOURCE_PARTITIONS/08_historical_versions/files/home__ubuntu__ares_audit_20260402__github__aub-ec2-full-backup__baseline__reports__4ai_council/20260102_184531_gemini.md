## 1. 우선순위 TOP 5 제안 (48시간 루프)

현재 **Champion(v5)**의 Lockbox 성과(4.01)가 Tuning 성과(2.32)를 크게 상회하는 것은 **Look-ahead Bias(미래 참조)** 또는 **특정 구간 과적합**의 강력한 신호임. 즉시 현실성 검증(Sanity Check)이 필요.

### [Priority 1] 미래 참조(Look-ahead) 강제 차단 검증
*   **(a) 이유:** Tuning보다 Lockbox가 1.7배 높은 Sharpe/Yield를 보이는 것은 일반적이지 않음. Feature 생성 시점이나 Target Labeling에서 `shift` 오류 가능성 높음.
*   **(b) 위험:** Champion 모델 폐기 가능성(수익률 급락).
*   **(c) 실험 (Experiments):**
    1.  `EXP_LAG_INJECT`: 모든 입력 Feature에 강제로 `shift(1)` 적용 후 재학습.
    2.  `EXP_EXEC_DELAY`: 신호 발생 후 매수/매도 실행을 `Open` 대신 `Close` 또는 `Next Open`으로 변경하여 시뮬레이션.
*   **(d) PASS 조건:**
    *   (1) 실험 정의: Feature/Execution Lag 적용 모델 생성.
    *   (2) 게이트: Tuning Mean > 1.0 AND Drawdown < -15%.
    *   (3) 기대 관측치: 기존 Champion 대비 성능이 30% 이상 하락하면 기존 모델은 폐기(Leakage 확정). 하락폭이 10% 이내면 유효.

### [Priority 2] 거래 비용 및 슬리피지 스트레스 테스트
*   **(a) 이유:** 높은 회전율(Turnover) 기반 전략일 경우, 백테스트 비용 미반영이 과도한 수익률의 원인일 수 있음.
*   **(b) 위험:** 거래 횟수가 많은 전략의 경우 Alpha 소멸.
*   **(c) 실험 (Experiments):**
    1.  `EXP_COST_2X`: 수수료/슬리피지 설정값을 현재의 2배로 증액 (예: 5bps -> 10bps).
    2.  `EXP_LIQUIDITY_FILTER`: 하위 20% 유동성 종목(Health Small-cap 등) 제외.
*   **(d) PASS 조건:**
    *   (1) 실험 정의: 비용 파라미터 증액 후 Re-run.
    *   (2) 게이트: Lockbox Mean > 1.5 유지.
    *   (3) 기대 관측치: 수익률 하락이 선형적이어야 함. 기하급수적으로 무너지면 모델은 '수수료 따먹기' 중임.

### [Priority 3] Tech/Healthcare 동적 밸런싱 (Sector Bias 제거)
*   **(a) 이유:** 현재 Tech 강세장에 편승했을 가능성. Tech 하락/Healthcare 상승 국면에서 방어력 확인 필요.
*   **(b) 위험:** 강세 섹터(Tech) 비중 축소로 인한 단기 수익률 저하.
*   **(c) 실험 (Experiments):**
    1.  `EXP_SECTOR_CAP`: 포트폴리오 내 Tech와 Healthcare 비중을 각각 Max 60%로 강제 제한.
    2.  `EXP_REL_MOMENTUM`: XLK vs XLV의 상대 모멘텀(Relative Strength)에 따라 상위 섹터 비중 가중.
*   **(d) PASS 조건:**
    *   (1) 실험 정의: 섹터별 할당 로직(Constraints) 수정.
    *   (2) 게이트: Worst MDD 개선 (기존 -8% 대비 -7% 이상 방어).
    *   (3) 기대 관측치: Lockbox 수익률은 소폭 감소하더라도 MDD 안정성 확보.

### [Priority 4] 변동성 기반 포지션 사이징 (Volatility Targeting)
*   **(a) 이유:** 개별 종목(특히 Bio/Tech)의 급등락 리스크 제어. 단순 균등 배분(Equal Weight)은 위험함.
*   **(b) 위험:** 저변동성 종목(수익성 낮음) 비중 확대로 인한 Alpha 희석.
*   **(c) 실험 (Experiments):**
    1.  `EXP_INV_VOL`: ATR(14) 또는 역사적 변동성의 역수(Inverse)로 개별 종목 비중 조절.
    2.  `EXP_ETF_VETO`: XLK/XLV의 변동성이 임계치 초과 시 현금 비중 확대.
*   **(d) PASS 조건:**
    *   (1) 실험 정의: 사이징 모듈 교체.
    *   (2) 게이트: Tuning Min Return > 0 (손실 방어력 증대).
    *   (3) 기대 관측치: 급락 구간에서의 MDD 개선 확인.

### [Priority 5] 특성(Feature) 가지치기 (Feature Selection)
*   **(a) 이유:** 과최적화 방지. 의미 없는 지표가 우연히 맞아떨어진 경우(Spurious Correlation) 배제.
*   **(b) 위험:** 유의미한 비선형 패턴 정보 손실.
*   **(c) 실험 (Experiments):**
    1.  `EXP_FEAT_SHAP`: SHAP Value 하위 30% Feature 제거 후 재학습.
    2.  `EXP_SIMPLE_MODEL`: 복잡한 모델(LSTM/Transformer 등) 대신 Ridge/RandomForest로 동일 Feature 학습.
*   **(d) PASS 조건:**
    *   (1) 실험 정의: Feature Set 축소 및 모델 단순화.
    *   (2) 게이트: Champion 성능의 85% 이상 유지.
    *   (3) 기대 관측치: 성능 저하가 크지 않다면 단순 모델/적은 Feature가 운영상 우위(Ockham's Razor).

## 2. 성능 정체 시 원인 분해 (Diagnosis Checklist)

성능이 개선되지 않거나 횡보할 경우 다음 순서로 원인을 파악하고 로그를 남길 것.

1.  **Trigger (신호 발생):**
    *   예측 모델이 충분한 분산(Variance)을 가진 점수를 내놓고 있는가?
    *   *Check:* 예측값의 표준편차가 0에 가까우면 모델이 '평균'만 뱉고 있음 (Feature 불량).

2.  **Application (주문 생성):**
    *   신호는 있으나 제약조건(Min Weight, Max Assets) 때문에 주문이 필터링되는가?
    *   *Check:* `Filtered_Orders_Count` 메트릭 확인. 8~14 종목 풀이 너무 좁아 선택지가 없는지 점검.

3.  **Exposure (시장 노출):**
    *   현금 비중이 의도치 않게 높은가?
    *   *Check:* 평균 Cash Ratio 확인. 시장이 오를 때 현금 들고 있으면 성능 저하.

4.  **Cost (비용 효율):**
    *   수익을 거래 비용이 다 갉아먹는가?
    *   *Check:* Gross Profit vs Net Profit 비율 확인. (비율 < 0.5면 전략 수정 필수).

5.  **Regime (시장 국면):**
    *   현재 전략이 '역추세'인데 시장이 '강한 추세'인가?
    *   *Check:* 벤치마크(QQQ/XLV) 대비 Alpha가 음수인지 확인. ETF 지표와 전략 성향 불일치 확인.
