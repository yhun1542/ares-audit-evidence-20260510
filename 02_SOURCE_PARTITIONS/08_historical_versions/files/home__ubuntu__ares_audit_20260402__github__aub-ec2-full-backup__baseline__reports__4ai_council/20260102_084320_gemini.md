### 1. 24~48시간 내 수행할 TOP 5 우선순위 체크리스트

#### P1. `worst_mdd: None` 버그 픽스 및 무결성 검증 (Code)
*   **이유:** MDD가 `None`인 상태는 리스크 측정 로직이 붕괴되었거나, 거래가 체결되지 않았음을 암시함. 리스크 평가 없는 OOS 성과는 무의미함.
*   **위험:** 계산 오류 수정 시 OOS 성과가 급락하거나 전략 폐기 등급으로 떨어질 가능성.
*   **실험 (Patch):**
    1.  `calc_stats()` 함수 내 `Nan`/`Inf` 처리 로직 강제 주입 (Division by zero 방지).
    2.  거래 내역(Trade log)이 비어있는지 확인하는 Assert 추가.
    3.  Benchmark(SPY) 대비 MDD 계산 로직을 절대값(Peak-to-Valley) 방식으로 단순화하여 재실행.
*   **PASS 조건:** `worst_mdd`가 0.0 ~ -1.0 사이 실수(float)로 출력될 것.

#### P2. 슬리피지/수수료 페널티 2배 적용 스트레스 테스트 (Cost)
*   **이유:** `oos_mean: 1.88`은 과도하게 높음. Tech/Healthcare(변동성 큼) 8~14개 종목 회전 시 비용이 수익을 잠식하는지 확인 필요.
*   **위험:** 전략의 기대 수익률이 마이너스로 전환될 수 있음(False Positive 제거).
*   **실험 (Patch):**
    1.  거래당 수수료 $0 -> $0.005/share 또는 bps 모델로 변경.
    2.  슬리피지(Slippage)를 기존 모델의 200%로 설정 (예: 5bps -> 10bps).
*   **PASS 조건:** `oos_mean` > 1.0 유지 및 `turnover`가 급증하지 않음.

#### P3. ETF(XLK, XLV) 기반 변동성 필터링 게이트 (Strategy)
*   **이유:** 개별 주식(Tech+Health)만 매매하더라도, 섹터 전체 하락장(Systemic Risk)에서는 현금 비중을 늘려야 함. 현재 Exposure Max 0.84는 위험할 수 있음.
*   **위험:** 진입 시점을 놓쳐 Upside 포기 가능성 (Lagging issue).
*   **실험 (Patch):**
    1.  XLK(Tech) 또는 XLV(Health)의 20일 이동평균 하회 시 해당 섹터 종목 매수 금지 로직 추가.
    2.  VIX > 25 구간에서 Max Exposure 0.5로 강제 제한.
*   **PASS 조건:** `oos_min`(최악의 성과)이 0.43에서 0.6 이상으로 개선.

#### P4. 유니버스 동적 선택 로직(Survivorship Bias) 점검 (Data)
*   **이유:** 2026년 시점 데이터에서 과거 데이터를 볼 때, 현재 상장 폐지된 종목이 유니버스에서 누락되었는지 확인 필요. Tech/Bio는 상폐/인수합병 빈번.
*   **위험:** 과거 데이터 재구축 비용 및 시뮬레이션 속도 저하.
*   **실험 (Patch):**
    1.  매월 리밸런싱 시점에 `Dollar Volume` 하위 20% 종목 강제 제외 (유동성 함정 회피).
    2.  최근 3개월 내 주가 데이터 결측치(Null)가 1개라도 있는 종목 블랙리스트 처리.
*   **PASS 조건:** 종목 수가 8~14개 범위 내에서 일정하게 유지되며, `degenerate_folds`가 발생하지 않음.

#### P5. 상관계수 기반 포트폴리오 압축 (Architecture)
*   **이유:** Tech와 Healthcare는 때로 강한 양의 상관관계를 가짐. 14개 종목이 사실상 1개 종목처럼 움직이면 분산 효과 없음.
*   **위험:** 주도주(Alpha source)가 상관관계 필터에 걸려 제외될 수 있음.
*   **실험 (Patch):**
    1.  보유 종목 간 평균 상관계수 > 0.7 시, 변동성 낮은 종목 우선 매도.
    2.  Tech와 Healthcare 비중을 최소 3:7 ~ 7:3 범위 내로 강제 밸런싱.
*   **PASS 조건:** `worst_mdd` 개선 및 샤프 지수(Sharpe Ratio) 상승.

### 2. 자동 루프(48h) 실행 정의

#### 실험 A: 리스크 지표 정상화 및 비용 현실화
*   **(1) 실험 정의:** MDD 계산 로직 수정 + 슬리피지 10bps 적용 + 종목수 10개 고정.
*   **(2) 게이트:** `worst_mdd` is not None AND `worst_mdd` > -0.25 (25% 미만 손실).
*   **(3) 기대 관측치:** `oos_mean`은 1.4대로 하락하더라도, 신뢰 구간 내에 안착.

#### 실험 B: 섹터 레짐 필터 적용
*   **(1) 실험 정의:** XLK/XLV 60일 이평선 아래일 때 해당 섹터 Exposure 0으로 셧다운.
*   **(2) 게이트:** 거래 횟수(Trade Count) > 50 (과도한 필터링으로 거래 실종 방지).
*   **(3) 기대 관측치:** `exposure_min`이 0.0에 근접하게 떨어지며 하락장 방어 확인.

#### 실험 C: 종목 집중도 완화
*   **(1) 실험 정의:** 단일 종목 최대 비중 15% 제한 (기존 로직이 없다면 추가).
*   **(2) 게이트:** 포트폴리오 내 종목 수 >= 8 유지.
*   **(3) 기대 관측치:** `oos_min` 성과 개선 (개별 종목 악재로 인한 폭락 방지).

### 3. 성능 정체 시 원인 분해 (Debugging Tree)

성능 지표(`oos_mean`, `oos_min`)가 48시간 동안 유의미하게 변하지 않을 경우, 아래 순서로 원인을 타격:

1.  **트리거(Trigger) 확인:**
    *   진입 신호(Entry Signal)가 너무 보수적인가? -> *Threshold 값을 10% 완화하여 신호 발생 빈도 체크.*
2.  **노출(Exposure) 확인:**
    *   현금 비중이 너무 높은가? -> *`exposure_min`이 0.47임에도 실제 베팅 금액은 더 낮게 설정되었는지 자금 관리 모듈 점검.*
3.  **비용(Cost) 확인:**
    *   작은 수익을 비용이 다 먹고 있는가? -> *Gross Return vs Net Return 괴리율 차트 출력.*
4.  **레짐(Regime) 불일치:**
    *   현재 전략이 '추세 추종'인데 시장이 '박스권'인가? -> *ADX 지표 등으로 시장 추세 강도 측정 후 전략 On/Off 스위칭 고려.*
5.  **데이터(Data) 오류:**
    *   특정 종목(예: 엔비디아, 일라이릴리 등 대장주)의 액면분할 등이 반영 안 되어 가격 데이터가 튀었는가? -> *가격 변동률(ROC) > 20% 이상인 데이터 포인트 전수 조사.*
