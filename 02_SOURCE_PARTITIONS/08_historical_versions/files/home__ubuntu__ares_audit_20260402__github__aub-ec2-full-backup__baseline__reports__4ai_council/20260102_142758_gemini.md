### 1. 24~48시간 우선순위 TOP 5 제안 (Imperative Checklist)

#### P1. [INFRA] Rebalance Logging 및 Cost Model 강제 복구
*   **(a) 필요성:** 로그 파싱 에러로 인해 슬리피지와 수수료가 반영된 '진짜 수익률'을 모름. MDD None 수정 필수.
*   **(b) 위험:** 코드를 수정하다가 실행 파이프라인이 멈출 수 있음(Syntax Error 주의).
*   **(c) 실험 (Patch):**
    *   **Patch A:** `aub_rebalance_pinpoint.py`의 JSONL 파싱 로직에 예외 처리 추가 및 `commission=0.001`(10bps), `slippage=0.0005`(5bps) 강제 주입.
    *   **Patch B:** 백테스트 엔진에서 `calculate_mdd` 함수가 `NaN`을 반환하는 경우 0이 아닌 -1.0 등으로 치환하여 디버깅.
*   **(d) PASS 조건:** `rebalance.csv` 생성 확인 AND `worst_mdd`가 음수로 산출됨.

#### P2. [STRATEGY] Tech/Bio Sector Beta Hedge (ETF Indicator 활용)
*   **(a) 필요성:** 8~14개 종목 집중 투자 시 섹터 하락장에 취약. ETF 매매 금지 규칙 하에, QQQ/XLV를 **관측 지표(Regime Filter)**로만 사용하여 현금 비중 조절.
*   **(b) 위험:** 과도한 헷징으로 상승장 수익(Upside) 제한.
*   **(c) 실험:**
    *   **(1) Exp_Regime_None:** 기존 로직 유지 (Control).
    *   **(2) Exp_Regime_MA:** QQQ 또는 XLV가 20일 이평선 하회 시, 타겟 포트폴리오 노출도(Exposure) 상한을 0.5로 제한.
    *   **(3) Exp_Regime_VIX:** VIX > 25 일 때 신규 진입 금지(Hold or Sell only).
*   **(d) PASS 조건:** MDD가 기존 대비 15% 이상 개선(감소) AND Sharpe Ratio 유지/상승.

#### P3. [HYPERPARAM] FSA Score Scaling 민감도 테스트
*   **(a) 필요성:** 현재 `scale_090`은 과최적화 가능성 높음. Tech/Healthcare는 펀더멘털보다 모멘텀/센티먼트 반응 속도가 빠름.
*   **(b) 위험:** 파라미터 변경 시 승률(Win Rate) 급락 가능성.
*   **(c) 실험:**
    *   **(1) Exp_Scale_080:** FSA Score 임계값 0.80으로 완화 (종목 풀 확대).
    *   **(2) Exp_Scale_095:** FSA Score 임계값 0.95로 강화 (핵심 종목 압축).
    *   **(3) Exp_Scale_Dynamic:** 시장 변동성(ATR) 상위 구간에서는 Scale 0.95, 하위 구간에서는 0.85 적용.
*   **(d) PASS 조건:** OOS Mean 변동폭이 10% 이내이면서 종목 교체율(Turnover)이 낮은 설정값 선택.

#### P4. [RISK] 개별 종목 Max Allocation Cap 적용
*   **(a) 필요성:** 소수 종목(8-14) 포트폴리오에서 특정 바이오 종목의 임상 실패 등으로 인한 -30% Gap 하락 방어.
*   **(b) 위험:** 주도주(Alpha Driver)의 비중을 깎아먹어 총수익 저하.
*   **(c) 실험:**
    *   **(1) Exp_Cap_15:** 단일 종목 최대 비중 15% 제한 (Hard Cap).
    *   **(2) Exp_Cap_Vol_Adj:** 개별 종목 변동성 역가중(Inverse Volatility) 방식으로 비중 할당.
*   **(d) PASS 조건:** 특정 종목 기여도가 전체 수익의 40%를 초과하지 않을 것 (수익 다변화 확인).

#### P5. [EXECUTION] 매매 회전율(Turnover) 강제 억제
*   **(a) 필요성:** 잦은 리밸런싱은 슬리피지 누적으로 OOS 성과를 갉아먹음. 현재 OOS 1.88이 비용 반영 전이라면 실제는 마이너스일 수 있음.
*   **(b) 위험:** 시장 변화에 느리게 반응하여 손실 확정 지연.
*   **(c) 실험:**
    *   **(1) Exp_Delay_1:** 신호 발생 후 1일 대기 후 진입 (Signal Persistence 확인).
    *   **(2) Exp_Buffer_05:** 기존 목표 비중과 5% 이상 차이 날 때만 리밸런싱 수행.
*   **(d) PASS 조건:** 연환산 회전율(Turnover) < 5.0 (연 500% 이하) AND Net Profit > 0.

### 2. 자동 루프(Auto-Loop) 실행 정의 (48h Plan)

**Loop A: 인프라 정상화 및 베이스라인 재수립 (0~12h)**
1.  **실험 정의:** `fix_logger_and_mdd` 브랜치 배포. 수수료 10bps/슬리피지 5bps 적용 백테스트 재구동.
2.  **게이트:** `worst_mdd` is not None AND `rebalance.csv` size > 0.
3.  **기대 관측치:** OOS Mean이 1.88에서 1.2~1.4 수준으로 하락(정상화) 예상. MDD 수치 확보.

**Loop B: Tech/Bio Regime Filter 적용 (12~36h)**
1.  **실험 정의:** Loop A 승자 코드 + `Exp_Regime_MA` (QQQ/XLV MA 필터) 적용.
2.  **게이트:** Downside Deviation 감소 확인. OOS Sharpe > 1.0.
3.  **기대 관측치:** 상승장에서 수익 일부 반납하더라도, 하락장에서 Cash 비중 증가로 방어력 입증.

**Loop C: 종목 압축 및 비중 최적화 (36~48h)**
1.  **실험 정의:** Loop B 승자 코드 + `Exp_Cap_15` (종목당 15% 캡).
2.  **게이트:** Exposure Min > 0.3 (지나치게 현금만 보유하지 않는지 체크).
3.  **기대 관측치:** 특정 "대박" 종목 의존도 감소, 포트폴리오 안정성 증가.

### 3. 성능 정체 시 원인 분해 (Decomposition)

성능이 움직이지 않을(Flat) 경우, 다음 트리를 따라 디버깅하시오:

*   **Trigger (신호 발생 여부):**
    *   FSA Score가 너무 엄격(0.90)하여 매수 대상이 0개인가? -> `Signal Count` 로그 확인.
    *   ETF 지표(QQQ/XLV)가 계속 하락세라 진입을 차단 중인가? -> `Regime Status` 확인.
*   **Application (주문 집행):**
    *   현금 부족(Buying Power)으로 주문이 거부되는가? -> `Order Reject` 로그 확인.
    *   최소 주문 금액(Min Notional) 미달인가?
*   **Cost (비용 잠식):**
    *   Gross Profit은 우상향인데 Net Profit이 횡보/하락인가? -> **회전율(Turnover) 과다.** (P5 적용 시급)
*   **Regime (시장 불일치):**
    *   현재 시장이 Value/Energy 강세이고 Tech/Bio 약세인가? -> **Beta Decomposition** 확인 (전략이 시장을 못 이기는 것이 자연스러운지 판단).
