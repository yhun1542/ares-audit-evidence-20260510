현재 시스템은 **"불완전한 가시성(Blindness)"**과 **"과적합 의심(Overfitting)"** 상태입니다.
1. `worst_mdd: None` 및 `degenerate_folds: [1, 2, 3, 8]`은 치명적 결함입니다. 특정 구간에서 거래가 아예 없거나(Zero variance), 계산 로직이 깨졌습니다.
2. `rebalance.csv` 로딩 실패로 인해 실제 회전율과 비용 충격을 확인할 수 없습니다.
3. OOS Mean 3.32는 비정상적으로 높습니다. 이는 생존 편향(Survivorship Bias)이나 룩어헤드(Look-ahead)가 강하게 의심됩니다.

### 1. 24~48시간 우선순위 TOP 3 제안

#### 제안 1: 파이프라인 무결성 확보 및 MDD 계산 수정 (System Fix)
*   **(a) 필요성:** `worst_mdd: None` 상태에서는 리스크 평가 불가능. `rebalance.csv` JSON 파싱 에러로 거래 내역 분석 불가.
*   **(b) 리스크:** 코드 수정 중 로깅 포맷 변경으로 기존 도구 호환성 일시적 저하 가능성.
*   **(c) 실행 실험:**
    1.  `fix_mdd_calc`: MDD 계산 시 `NaN` 또는 `inf` 처리 로직 추가 및 `rebalance.csv`를 표준 JSONL 포맷으로 강제 변환.
    2.  `force_min_trade`: 폴드별 최소 거래 횟수(예: 10회) 미달 시 강제 Fail 처리하는 로직 추가.
*   **(d) PASS 조건:** 모든 Fold에서 유효한 MDD 수치 산출(0.0 아님) + Rebalance 로그 파싱 성공.

#### 제안 2: 퇴화 폴드(Degenerate Folds) 복구 패치 (Robustness)
*   **(a) 필요성:** Fold 1, 2, 3, 8의 실패는 전략이 특정 시장 국면(Regime)에서만 작동함을 의미. 과적합의 강력한 증거.
*   **(b) 리스크:** 제약 완화 시 OOS Mean(3.32)이 대폭 하락할 가능성 높음(그러나 이는 '정상화' 과정임).
*   **(c) 실행 실험:**
    1.  `relax_signal_threshold`: 진입 임계값(Threshold)을 현재의 80% 수준으로 하향 조정.
    2.  `expand_universe_fallback`: Tech/Health 유니버스 내에서 신호 강도가 낮더라도 상위 8개 종목 강제 할당(Force Allocation).
    3.  `fill_missing_data`: 결측 데이터 구간에 대해 `ffill` 제한을 2일에서 5일로 완화(데이터 누락으로 인한 거래 중단 확인).
*   **(d) PASS 조건:** Degenerate Folds 개수가 0~1개로 감소 + OOS Min > -0.05 유지.

#### 제안 3: 시차 적용 및 유니버스 강제화 (Leakage Check)
*   **(a) 필요성:** OOS Mean 3.32는 미래 참조(Look-ahead) 없이는 달성하기 어려운 수치. Tech+Healthcare 섹터 편중이 실제 포트폴리오에 반영되는지 확인 필요.
*   **(b) 리스크:** 룩어헤드 제거 시 성능이 마이너스로 전환될 수 있음(전략 폐기 위험).
*   **(c) 실행 실험:**
    1.  `lag_execution_1d`: 신호 생성 후 **체결을 익일 시가(Open) 대신 익일 종가(Close) 혹은 익익일 시가**로 강제 지연.
    2.  `enforce_sector_balance`: 포트폴리오 내 Tech:Healthcare 비율을 최소 3:3 이상 보유하도록 하드 코딩 제약 추가.
*   **(d) PASS 조건:** Lag 적용 후에도 OOS Mean > 1.0 유지 + 섹터 비중 준수.

- **Secondary:** `worst_mdd`는 -0.10 ~ -0.25 사이의 현실적인 값으로 관측되어야 함.
