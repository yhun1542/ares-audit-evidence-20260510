### P5. 운영 리스크: Stale Signal 감지 로직
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한가**
- 48시간 자동 루프에서 **데이터 피드 실패 시** 어제 시그널로 거래
- 이 경우 손실 누적되어도 감지 불가

**(b) 위험/부작용**
- 과도한 halt 조건은 거래 기회 상실
- 적정 threshold 설정 필요

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 5-1 | signal_timestamp vs current_time 비교 로직 추가 | 즉시 | 24h 초과 시 WARN 로그 |
| 5-2 | 48h 초과 시 자동 HALT + 알림 | 5-1 완료 | HALT 트리거 테스트 |
| 5-3 | 과거 로그에서 실제 stale 발생 빈도 확인 | 병렬 | 월 1회 이하면 OK |

**(d) PASS 조건**
```
stale_detection_coverage == 100% AND false_halt_rate < 1%
```

**실행 명령**
```bash
# 신규 가드레일 추가
cat >> experiment_system/guards/stale_signal.py << 'EOF'
def check_signal_freshness(signal_ts, threshold_hours=24):
    age = (datetime.now() - signal_ts).total_seconds() / 3600
    if age > threshold_hours:
        return {"status": "WARN", "age_hours": age}
    return {"status": "OK"}
EOF
```
