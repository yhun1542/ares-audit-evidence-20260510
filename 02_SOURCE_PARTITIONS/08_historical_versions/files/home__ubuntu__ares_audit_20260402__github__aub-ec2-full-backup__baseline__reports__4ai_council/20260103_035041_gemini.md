[진단: EMERGENCY]
현재 `oos_mean: 3.32`는 허상일 가능성이 높음. `degenerate_folds: [1, 2, 3, 8]`은 전체 검증 구간의 40%에서 전략이 붕괴(거래 없음, 파산, 또는 NaN)했음을 의미. 로그 파일 로딩 에러로 인해 원인 파악조차 불가능한 상태. **수익률 개선보다 '시스템 정상화'가 최우선.**

### 1. 24~48시간 우선순위 TOP 5

#### P1. [INFRA] 로그/파이프라인 입출력 포맷 정상화 (Blocker 해결)
- **이유:** `Error loading... Expecting value` 에러로 인해 리밸런싱 근거 추적 불가. '눈 가리고 운전' 중.
- **위험:** 코드 수정 중 이전 실험 데이터와의 호환성 깨짐.
- **실험 (Patch):**
    1. **Patch_Log_Fix:** `jsonl` 쓰기 모드를 `append`가 아닌 `atomic write`로 변경 및 UTF-8 강제.
    2. **Patch_Path_Resolve:** 절대 경로 대신 상대 경로 기반의 아티팩트 참조 로직으로 통일.
- **PASS 조건:** `aub_rebalance_pinpoint.py`가 에러 없이 실행되고, 거래 내역이 파싱될 것.

#### P2. [LOGIC] Degenerate Folds(1,2,3,8) 원인 소거: 유니버스 방어 로직
- **이유:** 특정 시기(아마도 하락장)에 Tech/Bio 종목들이 필터링에 모두 걸려 포트폴리오가 비어버리거나(0), 손절만 반복됨.
- **위험:** 방어 로직이 상승장에서의 진입을 막아 수익률 저하 (False Negative).
- **실험:**
    1. **Exp_Fallback_Cash:** 유효 시그널 종목이 0개일 때, 강제로 거래를 쉬고 현금 100% 보유 처리 (NaN 방지).
    2. **Exp_Min_Vol_Relax:** 변동성 필터(Low Vol)가 너무 엄격한지 확인. 하한선을 10% 낮춤.
    3. **Exp_Fill_Forward:** 데이터 누락 구간에 대해 `ffill` 적용 제한적 허용 (데이터 공백 확인용).
- **PASS 조건:** `degenerate_folds` 개수가 0~1개로 감소.

#### P3. [STRATEGY] XLK/XLV 레짐 필터 (Regime Filter) 적용
- **이유:** Tech/Healthcare는 금리/섹터 로테이션에 민감. 하락 레짐에서 매수 시그널 차단 필요.
- **위험:** 윕소(Whipsaw) 구간에서 잦은 진입/청산으로 비용 발생.
- **실험:**
    1. **Exp_Sector_MA:** XLK(기술) 또는 XLV(헬스케어)가 200일 이동평균선 아래면 `Max_Exposure`를 0.4로 제한.
    2. **Exp_VIX_Gate:** VIX > 30 구간에서 신규 진입 금지 (기존 포지션 청산만 허용).
- **PASS 조건:** MDD 10% 이상 개선 및 Degenerate Fold 중 하락장 구간(예: 2022년) 회복.

#### P4. [UNIVERSE] 유동성/생존편향(Survivorship) 점검
- **이유:** 소형 바이오주가 상장폐지되거나 틱 데이터가 깨져서 폴드가 터졌을 가능성.
- **위험:** 유니버스가 너무 좁아져서 과최적화될 위험.
- **실험:**
    1. **Exp_Cap_Filter:** 시가총액 하위 20% 및 일평균 거래대금 $10M 미만 종목 영구 제외.
    2. **Exp_Ticker_Fix:** S&P500 Health/Tech 구성 종목 중 현재 상장된 종목만으로 백테스트하여 생존 편향 영향도 측정 (Benchmark).
- **PASS 조건:** `oos_mean`이 하락하더라도 `oos_min`이 양수 전환 또는 `-0.01` 이내 방어.

#### P5. [EXECUTION] 비용 반영 현실화 (Slippage Stress Test)
- **이유:** 현재 `oos_mean` 3.32는 슬리피지/수수료가 과소평가된 결과일 수 있음.
- **위험:** 전략의 기대 수익률이 급감하여 폐기해야 할 수도 있음 (False Hope 제거).
- **실험:**
    1. **Exp_Cost_10bps:** 편도 비용 10bps(0.1%) 강제 적용.
    2. **Exp_Turnover_Limit:** 월 회전율 200% 초과 시 패널티 부여 또는 거래 횟수 제한.
- **PASS 조건:** 비용 적용 후에도 `Sharpe Ratio > 1.0` 유지.

### 2. 48시간 자동 루프 정의 (Auto-Loop Definition)

#### Loop A: 안정성 확보 (Degenerate Fix)
1. **실험 정의:** `Exp_Fallback_Cash` + `Exp_Cap_Filter` 동시 적용.
2. **게이트(Gate):** `degenerate_folds`가 빈 리스트([]) 이거나 [1] 하나만 남아야 함.
3. **기대 관측치:** `oos_mean`은 2.0대로 하락하더라도, `oos_min` > -0.1 확보.

#### Loop B: 섹터 레짐 최적화 (Tech/Bio Alpha)
1. **실험 정의:** 유니버스를 XLK/XLV 상위 30개로 고정하고, `Exp_Sector_MA` 레짐 필터 적용.
2. **게이트(Gate):** MDD < 20%.
3. **기대 관측치:** 상승장(2020, 2023)에서의 수익률 유지, 하락장(2022)에서의 손실 방어 확인.

### 3. 성능 정체(No Delta) 시 원인 분해 아이디어

성능 지표가 움직이지 않을 때, 다음 순서로 체크리스트 실행:

1.  **트리거 부재 (Trigger Absence):**
    *   *진단:* 진입/청산 조건이 너무 까다로워 거래 자체가 발생하지 않음.
    *   *액션:* 임계값(Threshold)을 표준편차 0.5~1.0 수준으로 낮춰서 거래 강제 발생 확인.
2.  **포지션 잠김 (Stale Position):**
    *   *진단:* 손절/익절 조건이 만족되지 않아 기존 포트폴리오가 '좀비' 상태로 유지됨.
    *   *액션:* `Max_Holding_Days` (예: 20일) 강제 청산 규칙 추가.
3.  **데이터 무결성 (Data Integrity):**
    *   *진단:* 특정 기간의 데이터(Feature)가 전부 `NaN`이라 모델이 `Neutral`만 출력.
    *   *액션:* Feature 계산 단계에서 `fillna(0)` 혹은 `ffill` 적용 여부 코드 레벨 확인.
4.  **비용 상쇄 (Cost Erosion):**
    *   *진단:* 알파는 있으나 슬리피지가 이를 정확히 상쇄하여 0에 수렴.
    *   *액션:* 거래 비용 0으로 설정 후 백테스트 -> 수익 발생 시 비용 구조 문제, 아니면 알파 부재.
