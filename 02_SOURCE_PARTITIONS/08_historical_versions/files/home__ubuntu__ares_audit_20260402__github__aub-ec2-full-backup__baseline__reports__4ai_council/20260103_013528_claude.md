## 1. 우선순위 TOP 5 실험 (48h 내 실행)

---

### ① MDD 페널티 캘리브레이션 (Risk Gate 재조정)

**□ 왜 필요한가**
- Champion의 tuning_min = -2.57%인데 fold14_mdd = -3.95% → **MDD가 수익률 대비 과도**
- 현재 게이트가 MDD를 충분히 벌점화하지 않아 OOS에서 깨질 가능성

**□ 위험/부작용**
- 페널티 과다 시 alpha 신호가 억제되어 수익률 전체 하락
- fold별 MDD 분산이 크면 단일 임계값이 불안정

**□ 최소 실험**
| ID | 설명 | 변경점 |
|----|------|--------|
| E1-a | MDD penalty ×1.5 | `mdd_coef: 0.15 → 0.225` |
| E1-b | MDD penalty ×2.0 + cap | `mdd_coef: 0.30, mdd_cap: -0.10` |
| E1-c | Conditional penalty (MDD > 5%일 때만 ×2) | `if mdd > 0.05: penalty *= 2` |

**□ PASS 조건**
```
tuning_mean ≥ 2.0 AND worst_mdd ≥ -0.06 AND lockbox_mean ≥ 3.5
```

---

### ② 시그널 Decay/Freshness 검증 (Lookahead Leak 점검)

**□ 왜 필요한가**
- tuning → lockbox 성능 격차 (2.32 vs 4.01) **역전** → 과적합 또는 시그널 구조 불일치 의심
- lockbox가 더 높으면 **tuning 기간에 regime이 다르거나, 시그널이 stale**

**□ 위험/부작용**
- lag 추가 시 alpha decay 가속 → 전체 수익 하락
- 과도한 freshness 필터는 거래 빈도 급감

**□ 최소 실험**
| ID | 설명 | 변경점 |
|----|------|--------|
| E2-a | Signal lag +1일 | 모든 feature에 `shift(1)` 추가 |
| E2-b | Stale signal 필터 | `if signal_age > 5d: weight *= 0.5` |
| E2-c | Rolling z-score 윈도우 축소 | `lookback: 60 → 40` |

**□ PASS 조건**
```
|tuning_mean - lockbox_mean| < 1.0 AND tuning_mean ≥ 1.8
```

### ③ Sector Concentration 리스크 캡

**□ 왜 필요한가**
- Tech+Healthcare 중심 8~14종목 → 단일 섹터 쏠림 시 regime 전환에 취약
- worst_mdd -8.15%의 원인이 특정 섹터 동반 하락일 가능성

**□ 위험/부작용**
- 강한 캡은 best performer 비중 축소 → alpha 희석
- 섹터 분류 기준 불일치 시 의도치 않은 리밸런싱

**□ 최소 실험**
| ID | 설명 | 변경점 |
|----|------|--------|
| E3-a | 섹터당 max 40% | `sector_cap: 0.40` |
| E3-b | 섹터당 max 50% + 종목당 15% | `sector_cap: 0.50, stock_cap: 0.15` |
| E3-c | Tech/HC 외 1종목 강제 편입 | `min_other_sector: 1` |

**□ PASS 조건**
```
worst_mdd ≥ -0.07 AND tuning_mean ≥ 2.0 AND max_sector_exposure ≤ 0.50
```

### ④ 거래비용 현실화 (Slippage + Tax 반영)

**□ 왜 필요한가**
- 현재 비용 모델 누락 시 실거래 대비 **연 1~3% 과대 추정**
- Champion의 lockbox_mean 4.01이 실현 불가능 수치일 가능성

**□ 위험/부작용**
- 과도한 비용 추정 시 모든 전략이 FAIL → 개발 루프 정체
- 슬리피지 모델이 종목별로 달라야 하나 단일 값 적용 시 왜곡

**□ 최소 실험**
| ID | 설명 | 변경점 |
|----|------|--------|
| E4-a | Slippage 10bp 추가 | `slippage: 0.0010` |
| E4-b | Slippage 10bp + 단기매매세 22% | `slippage: 0.0010, st_tax: 0.22` |
| E4-c | 턴오버 기반 동적 비용 | `cost = turnover * 0.002` |

**□ PASS 조건**
```
lockbox_mean (after cost) ≥ 2.5 AND tuning_mean ≥ 1.5
```

### ⑤ Regime Detector 업그레이드 (VIX + Credit Spread)

**□ 왜 필요한가**
- fold14_mdd 격차 (Champion -3.95% vs Candidate -9.97%) → **특정 기간에 regime 전환 미감지**
- 현재 regime 로직이 VIX 단일 지표면 credit event 놓칠 수 있음

**□ 위험/부작용**
- 복합 지표 추가 시 과적합 위험 ↑
- Credit spread 데이터 lag (T+1) 있으면 실시간 적용 불가

**□ 최소 실험**
| ID | 설명 | 변경점 |
|----|------|--------|
| E5-a | VIX > 25 AND HYG < -1% → 방어 모드 | `regime_trigger: vix_hyg_dual` |
| E5-b | VIX percentile 90th → 현금 50% | `vix_pct_threshold: 0.90, cash_alloc: 0.50` |
| E5-c | Regime 전환 시 2일 대기 | `regime_cooldown: 2` |

**□ PASS 조건**
```
worst_mdd ≥ -0.06 AND lockbox_mean ≥ 3.0 AND regime_accuracy ≥ 0.7
```
