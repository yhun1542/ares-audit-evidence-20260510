## 1. 우선순위 TOP 5 (인프라 → 전략 순서)

### P1. 데이터 파이프라인 무결성 복구
```
WHY: OOS Mean 불일치(1.88 vs 2.63), rebalance.csv 로드 실패
     → 현재 모든 실험 결과 신뢰도 0
RISK: 복구 중 기존 artifact 손상 가능
```

**실험 체크리스트:**
- [ ] **EXP-1a**: JSON/CSV 스키마 검증 스크립트 추가
  - Gate: `python validate_artifacts.py --dir artifacts/` 에러 0건
  - 기대치: 파싱 에러 원인 식별 (빈 파일 vs 포맷 불일치)
  
- [ ] **EXP-1b**: Handoff vs Diagnoser 수치 추적
  - Gate: `abs(handoff_oos - diagnoser_oos) < 0.01`
  - 기대치: 동일 champion 파일 참조 확인

- [ ] **EXP-1c**: Rebalance 로그 포맷 통일
  - Gate: `aub_rebalance_pinpoint.py` 정상 실행
  - 기대치: CSV→JSONL 마이그레이션 완료

**PASS 조건**: 3개 도구 모두 에러 없이 실행, OOS 수치 일관성 확보

### P2. MDD 계산 복구 (Risk Observability)
```
WHY: worst_mdd: None → 리스크 게이트 무력화
     drawdown 없이 Sharpe만 보면 과최적화 감지 불가
RISK: MDD 계산 로직 버그 시 false confidence
```

**실험 체크리스트:**
- [ ] **EXP-2a**: MDD 계산 로직 단위 테스트
  - Gate: 합성 시계열 3종(flat, -50% crash, V-shape)에서 정확한 MDD 출력
  - 기대치: MDD 함수 정상 작동 확인

- [ ] **EXP-2b**: Champion 파일에 MDD 필드 강제 추가
  - Gate: `champion.json`에 `worst_mdd` 필드 존재 & 값 != None
  - 기대치: 현재 champion MDD 수치 확인 (예상: -15% ~ -25%)

**PASS 조건**: `worst_mdd > -30%` (과도한 드로다운 아님 확인)

### P3. Exposure 하한 리스크 점검
```
WHY: exposure_min 47.5% → 절반 이상 현금 보유 구간 존재
     저노출 = 비용(기회비용) + 레짐 민감도 ↑
RISK: 강제 노출 상향 시 하락장 MDD 폭증
```

**실험 체크리스트:**
- [ ] **EXP-3a**: 저노출 구간(exposure < 50%) 발생 조건 추출
  - Gate: 로그에서 저노출 트리거 이유 3개 이상 식별
  - 기대치: "변동성 스파이크" or "시그널 약화" 등 원인 분류

- [ ] **EXP-3b**: exposure_floor=55% 실험
  - Gate: OOS Mean ≥ 1.80 AND worst_mdd ≤ champion_mdd × 1.1
  - 기대치: 수익 유지하면서 노출 하한 상승 가능 여부

- [ ] **EXP-3c**: 저노출 구간 수익률 분리 분석
  - Gate: `returns_when_exposure<50%` vs `returns_when_exposure>70%` 비교
  - 기대치: 저노출이 실제로 방어 역할 했는지 확인

**PASS 조건**: 저노출 구간이 명확한 방어 효과 있거나, floor 조정 후 성능 유지

### P4. 폴드별 성능 분산 점검 (Survivorship 의심)
```
WHY: oos_min=0.43 vs oos_mean=1.88 → 최악 폴드가 평균의 23%
     특정 레짐에서 전략 붕괴 가능성
RISK: 분산 줄이려다 평균도 하락 (과최적화 역방향)
```

**실험 체크리스트:**
- [ ] **EXP-4a**: 최악 폴드(0.43) 기간/레짐 특성 분석
  - Gate: 해당 기간 시장 레짐(상승/하락/횡보) 식별
  - 기대치: "2022 베어마켓" 등 특정 레짐 취약점 확인

- [ ] **EXP-4b**: 레짐별 전략 가중치 분해
  - Gate: 최악 폴드에서 어떤 팩터/종목이 손실 주도했는지 TOP3 추출
  - 기대치: 집중 리스크(단일 종목 > 20%) 여부 확인

**PASS 조건**: 최악 폴드 원인 식별 & 해당 레짐 재발 시 대응 로직 존재

### P5. 비용 반영 검증 (Hidden Cost)
```
WHY: Sharpe 계산에 슬리피지/세금/배당 누락 시 실전 괴리
     특히 rebalance 빈도 높으면 turnover cost 과소평가
RISK: 비용 과다 반영 시 시뮬레이션 비관적 → 좋은 전략 폐기
```

**실험 체크리스트:**
- [ ] **EXP-5a**: 현재 비용 가정 추출
  - Gate: config에서 `slippage_bps`, `commission`, `tax_rate` 값 확인
  - 기대치: 슬리피지 5-10bps, 수수료 반영 여부 명시

- [ ] **EXP-5b**: Turnover 계산 & 비용 민감도
  - Gate: 연간 turnover 계산 → turnover × cost = 연간 비용 drag
  - 기대치: 비용 drag < 50bps/년 (Sharpe 영향 < 0.05)

**PASS 조건**: 비용 가정 명시적 문서화 & Sharpe 조정 후에도 > 1.5

## 3. 48시간 자동 루프 형식

```yaml
# autopilot_config.yaml
experiments:
  - id: P1_data_integrity
    cmd: "python validate_artifacts.py && python check_oos_consistency.py"
    gate: "exit_code == 0 AND oos_diff < 0.01"
    observe: [parse_errors, oos_handoff, oos_diagnoser]
    
  - id: P2_mdd_restore
    cmd: "python compute_mdd.py --champion latest"
    gate: "mdd != None AND mdd > -0.30"
    observe: [worst_mdd, mdd_date, recovery_days]
    
  - id: P3_exposure_floor
    cmd: "python run_experiment.py --param exposure_floor=0.55"
    gate: "oos_mean >= 1.80 AND mdd_ratio <= 1.1"
    observe: [oos_mean, worst_mdd, exposure_min]
    
  - id: P4_worst_fold
    cmd: "python analyze_fold.py --fold worst"
    gate: "regime_identified == True"
    observe: [fold_period, regime_label, top3_losers]
    
  - id: P5_cost_check
    cmd: "python cost_analysis.py --champion latest"
    gate: "cost_drag_annual < 0.005"
    observe: [turnover, slippage_assumed, net_sharpe]

sequence: [P1_data_integrity, P2_mdd_restore, P4_worst_fold, P3_exposure_floor, P5_cost_check]
stop_on_fail: P1_data_integrity  # 인프라 깨지면 전체 중단
```
