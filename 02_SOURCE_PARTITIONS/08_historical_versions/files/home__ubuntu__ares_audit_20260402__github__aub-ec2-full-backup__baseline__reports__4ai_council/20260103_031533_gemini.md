[분석 요약]
현재 `oos_mean: 3.32`는 극도로 의심스러운 수치입니다. 특히 `degenerate_folds: [1, 2, 3, 8]` (전체 폴드의 약 40-50% 추정)가 발생했다는 것은, 특정 시기(아마도 하락장이나 데이터 공백기)에 모델이 거래를 전혀 하지 못했거나 로직이 붕괴되었음을 의미합니다. 로그 파일 로딩 에러(`Errno 2`, `Expecting value`)는 실제 거래 비용 분석이 불가능한 상태(Blind)임을 나타냅니다.

다음 48시간 내 수행해야 할 필수 액션 3가지를 명령형으로 하달합니다.

### Action 1. Degenerate Fold 원인 규명 및 강제 할당 (Data Integrity)

**(a) 필요성**
`degenerate_folds`가 4개나 존재하는 상태에서의 OOS Mean은 허상입니다. 해당 구간에서 NaN 또는 0.0 수익률이 평균을 왜곡하고 있을 가능성이 100%입니다. 데이터 정합성(Survivorship/Lookahead) 또는 로직의 극단적 보수성을 해결해야 합니다.

**(b) 위험/부작용**
- 수정 시 OOS Mean이 급격히 하락할 수 있음(현실화).
- 강제 거래 로직 주입 시 MDD가 급증할 수 있음.

**(c) 실행 실험 (Patch Experiments)**
1.  **`EXP_DATA_FILL`**: Degenerate 구간(Fold 1,2,3,8)의 데이터가 비어있는지 확인하고, 해당 구간에 'Cash Hold(수익률 0)' 대신 'Benchmark(SPY) Buy & Hold'를 강제 주입하여 모델의 상대적 열위를 측정.
2.  **`EXP_LOOSE_ENTRY`**: 진입 임계값(Threshold)을 현재의 50% 수준으로 낮춰 강제로 거래를 발생시킴. 거래가 발생하지 않는다면 데이터 누락, 발생한다면 로직 과최적화임.
3.  **`EXP_ERROR_FAIL`**: Fold 계산 중 예외 발생 시 해당 Fold를 0 처리하지 말고 즉시 `System Exit` 처리하여 디버깅 로그 확보.

**(d) PASS 조건**
- Degenerate Folds 개수 0개.
- OOS Mean > 1.5 (3.32에서 현실화된 수치).
- 전체 Fold에서 최소 거래 횟수 > 10회.

### Action 2. 로깅 시스템 복구 및 비용 현실화 (Ops/Cost)

**(a) 필요성**
로그 파일(`rebalance.csv`) 로딩 에러는 치명적입니다. 슬리피지와 수수료가 반영되지 않은 `3.32`는 'Paper Trading'일 뿐입니다. Tech/Bio 섹터는 변동성이 커 슬리피지 영향이 큽니다.

**(b) 위험/부작용**
- 시스템 I/O 오버헤드 증가.
- 기존 Champion 모델 폐기 가능성 높음(비용 반영 후 성과 급락).

**(c) 실행 실험 (Patch Experiments)**
1.  **`EXP_LOG_FIX`**: 로깅 형식을 JSONL로 통일하고, 파일 생성 시 헤더 강제 쓰기(Empty file 방지). 거래가 없어도 'No Trade' 로그를 타임스탬프와 함께 기록.
2.  **`EXP_COST_HEAVY`**: 매매당(Turnover) Slippage 10bps(0.1%) + Fee 5bps 강제 적용 후 백테스트 재구동.
3.  **`EXP_DELAY_EXEC`**: 시그널 발생 다음 봉(Next Bar) 시가(Open) 체결로 로직 변경 (Lookahead Bias 제거).

**(d) PASS 조건**
- `aub_rebalance_pinpoint.py` 툴이 에러 없이 실행됨.
- 비용 반영 후 OOS Sharpe > 1.0 유지.

**(b) 위험/부작용**

- ETF 지표 자체의 래깅(Lagging) 현상.

**(c) 실행 실험 (Patch Experiments)**

**(d) PASS 조건**

- 하락장(Fold 8 등)에서의 방어율 개선 확인.

### [성능 정체 시 원인 분해 아이디어]

만약 위 조치 후에도 성능이 움직이지 않거나(Flat), 여전히 OOS가 비현실적으로 높다면 다음을 점검하십시오.

1.  **트리거(Trigger) 불감:** 주가 데이터가 수정주가(Adjusted Close)가 아닌 원본 데이터라 액면분할 등이 반영 안 되어 지표가 왜곡되었는지 확인.
2.  **적용(Execution) 실패:** 시뮬레이터가 유동성이 낮은 소형 바이오주를 타겟팅하고 있으나, 실제 백테스트 엔진은 무한 유동성을 가정하고 있는지(Volume Filter 확인).
3.  **노출(Exposure) 왜곡:** 현금 비중이 90% 이상 유지되면서, 아주 가끔 터지는 대박 종목 하나가 전체 평균을 끌어올리고 있는지 확인(Trade Count 확인 필수).
4.  **레짐(Regime) 불일치:** 학습 데이터(In-sample)에 포함된 Tech Bull Market의 패턴을 강제로 하락장 Fold에 끼워 맞추고 있는지 확인.
