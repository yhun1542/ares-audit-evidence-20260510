# Patch/Experiment Pack 1) 누수·과최적화 차단 (시간정렬 + Purged/Embargo + Permutation)

### (a) 왜 필요한지
- 현재 `tuning_mean` 대비 `lockbox_mean`이 더 좋은 후보가 존재(과적합이 아니라 “검증체계가 느슨해서 운 좋게 통과”했을 가능성도 동시에 존재).  
- **시간정렬/중첩구간 누수**는 lockbox까지 번지면 “좋아 보이는데 실거래에서 붕괴” 패턴이 가장 흔함.

### (b) 위험/부작용
- 성능이 단기적으로 크게 하락할 수 있음(정상 반응일 수 있음).
- 학습 데이터가 실질적으로 줄어 분산 증가.

### (c) 최소 실험(2~3개, 한 패키지로 일괄 스윕)
1. **Purged Walk-Forward + Embargo CV 도입**
   - 정의: 기존 폴드 대신, 테스트 구간과 학습 구간 사이에 embargo(예: 5~20거래일 후보)를 둔 walk-forward.
2. **Feature/Label Shift 강제 테스트**
   - 정의: 모든 피처를 1바(또는 1일) 뒤로 밀어 “미래 참조” 가능성을 구조적으로 제거한 설정과 비교.
3. **Permutation Test(라벨 셔플)**
   - 정의: 라벨을 구간별로 셔플한 뒤에도 성능이 유지되면 누수 의심으로 즉시 FAIL.

### (d) PASS 조건 (게이트)
- **Permutation 성능**: lockbox_mean이 기준(예: 0 근처)으로 붕괴해야 PASS. (유지/상승 시 즉시 FAIL)
- **Purged/Embargo 적용 후에도**:
  - `worst_mdd`가 **-0.05 이하로 악화되지 않을 것**(현재 후보 worst_mdd ≈ -0.048)  
  - `lockbox_min`이 **0 이상 유지**(현재 후보 lockbox_min ≈ +0.334)  
  - `tuning_mean - lockbox_mean` 괴리가 과도하게 벌어지지 않을 것(과최적화 신호)

### 기대 관측치
- 성능이 소폭 하락하더라도 **분산 감소 + 최악 케이스 안정**(min 개선/유지)이 관측되면 “진짜 개선” 신호.

# Patch/Experiment Pack 2) 비용·턴오버 반영 (슬리피지 + 페널티 + 노트레이드밴드)

### (a) 왜 필요한지
- 비용 미반영은 가장 전형적인 “백테스트만 좋음” 원인.  
- 특히 Tech/Healthcare 대형주라도 리밸런싱 빈도가 높으면 슬리피지/스프레드가 성과를 갉아먹음.

### (b) 위험/부작용
- 거래가 줄면서 기회 손실로 수익이 감소할 수 있음.
- 비용 모델이 과도하면 보수적으로 굳어 레짐 전환에 둔감해질 수 있음.

### (c) 최소 실험(2~3개, 비용 파라미터 스윕)
1. **고정 bps 비용 모델 주입**
   - 정의: 왕복 비용(예: 5/10/20 bps)을 시나리오로 넣고 lockbox 재평가.
2. **턴오버 페널티 목표함수 추가**
   - 정의: 목적함수에 `- λ * turnover` 항(λ 2레벨) 추가.
3. **노트레이드밴드(리밸런싱 완충)**
   - 정의: 목표비중 대비 변경폭이 임계값 이하이면 미체결(불필요 거래 제거).

### (d) PASS 조건
- 비용 10bps(또는 보수 시나리오)에서:
  - `lockbox_mean`이 챔피언 대비 **비슷하거나 개선(≥ +0.02)**  
  - `worst_mdd` 악화 없음(예: -0.05 이내 유지)
- **턴오버가 의미 있게 감소**(예: -20% 이상)하면서 성과 급락이 없을 것.

### 기대 관측치
- “수익 유지 + 턴오버 감소” 조합이 나오면 실거래 생존력 급상승.  
- 반대로 성과가 비용에 민감하면, 알파가 “마찰 없는 가정”에 기댄 신호일 가능성.

# Patch/Experiment Pack 3) 운영/데이터 리스크 봉합 (서바이버십·액션·재현성)

### (a) 왜 필요한지
- 서바이버십/심볼변경/split 미처리/결측은 **조용히 성과를 부풀리거나** 실거래에서 즉시 오류를 냄.
- 48시간 자동 루프에서 “가끔 터지는” 운영 실패가 누적되면 실험 속도가 급감.

### (b) 위험/부작용
- 초기 구현 비용 증가, 단기 성과 개선과 무관해 보일 수 있음.
- 엄격한 검증으로 인해 일부 데이터/구간이 제외될 수 있음.

### (c) 최소 실험(2~3개, 빠른 테스트 중심)
1. **Corporate Action 회귀 테스트**
   - 정의: split/dividend 발생 구간에서 가격/수량 조정이 일관되는지 체크(전후 수익률 점프 탐지).
2. **데이터 무결성 프리플라이트**
   - 정의: (중복바/누락바/거래일 캘린더/타임존/정렬) 검증 실패 시 실험 시작 자체를 중단.
3. **재현성 체크(결과 해시)**
   - 정의: 동일 입력에서 지표(핵심 metric) 해시가 변하면 FAIL(비결정성/외부 의존 의심).

### (d) PASS 조건
- 프리플라이트 100% 통과 + 재현성 해시 안정.
- corporate action 구간에서 비정상 갭이 사라지거나 설명 가능(조정 처리됨).

### 기대 관측치
- 성과 수치의 “불안정한 출렁임”이 줄고, 후보 간 비교 신뢰도가 상승.

# Patch/Experiment Pack 4) 레짐 게이트(ETF 관측지표만)로 익스포저 스케일링

### (a) 왜 필요한지
- Tech/Healthcare는 국면(금리/리스크온오프)에 따라 **드로다운 구조가 달라짐**.
- ETF를 매매하지 않고도, QQQ/XLK/XLV 같은 관측지표로 “진입/익스포저”만 조절하면 MDD가 줄어드는 경우가 많음.

### (b) 위험/부작용
- 레짐 필터가 과도하면 상승장 수익을 깎을 수 있음(지연/오탐).
- 지표 의존이 커지면 특정 기간 최적화 위험.

### (c) 최소 실험(2~3개)
1. **Risk-on/off 트렌드 필터**
   - 정의: QQQ(또는 XLK) 추세(예: 100/200DMA 상하)로 총 익스포저 0~1 스케일.
2. **Tech↔Healthcare 틸트(상대강도)**
   - 정의: XLV/XLK 비율 z-score로 헬스케어 비중 상향/하향(단, 실제 매매는 개별주만).
3. **변동성 캡(옵션대용 관측)**
   - 정의: VXX(또는 SPY 변동 proxy) 고변동 구간에서 포지션 상한 축소.

### (d) PASS 조건
- `worst_mdd`가 **유의미하게 감소(예: -0.05 → -0.04 이하)**  
- `lockbox_min`이 유지/개선(0 이상 유지 우선)
- 평균 수익 저하가 크지 않을 것(예: lockbox_mean -0.03 이내)

### 기대 관측치
- 레짐별 성과 분해에서 “하락장 방어” 구간의 손실이 줄어야 함(특정 구간에만 과도한 개선이면 과최적화 의심).

# Patch/Experiment Pack 5) 8~14 종목 포트폴리오 제약 고정(집중/상관/섹터캡)

### (a) 왜 필요한지
- 소수 종목(8~14)에서는 **상관 높은 대형 테크에 동시 베팅**이 쉽게 발생 → 드로다운 꼬리 위험(worst case)이 커짐.
- 유니버스가 흔들리면 백테스트가 “우연히 좋은 종목만 남는” 효과(서바이버십/선정 편향)에 취약.

### (b) 위험/부작용
- 제약으로 알파가 희석될 수 있음.
- 성과가 단기적으로 감소할 수 있음(대신 tail risk 감소가 목적).

### (c) 최소 실험(2~3개)
1. **고정 유니버스(12종) + 고정 리밸런싱**
   - 정의(예시 12종): AAPL, MSFT, NVDA, GOOGL, AMZN, META, AVGO (Tech 7) + LLY, UNH, JNJ, ABBV, ISRG (HC 5)  
   - 리밸런싱 주기 고정(예: 주간/격주 중 하나로 통일).
2. **비중/섹터/상관 제약**
   - 정의: 종목 max 15~20%, 섹터(Tech/HC) max 65~70%, 상관 높은 페어 동시 최대 보유 제한.
3. **리스크 패리티 라이트(변동성 기반 가중)**
   - 정의: 동일 신호라도 고변동 종목 비중 자동 축소(추가 파라미터 최소화).

### (d) PASS 조건
- `worst_mdd` 개선 또는 동일 유지 + `lockbox_min` 유지(0 이상 우선)
- 포지션 집중도(HHI 등) 감소 + 최대 단일종목 기여 손실 축소

### 기대 관측치
- “평균 수익은 비슷, 꼬리 위험이 줄어드는” 형태가 이상적(소수 종목 운용의 현실적 목표).

## 성능이 안 움직일 때: 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)

아래를 **고정 리포트 템플릿**으로 만들어 48시간 루프마다 자동 출력(비교 가능하게)하라.

### 1) Trigger(신호 발생 품질) 문제
- [ ] 신호 발생 빈도(월/분기별) 추적: “너무 드묾/너무 잦음” 확인
- [ ] 구간별 hit-rate(방향 적중률), 평균 보유기간, 신호-수익 지연(lag) 분석
- [ ] permutation/shift 테스트에서 성능이 유지되는지 재점검(유지되면 누수 의심)

### 2) Application(적용 로직) 문제
- [ ] 신호→주문 변환(리밸런싱 타이밍, 체결 시점 t+1 강제) 일관성 검증
- [ ] 포지션 업데이트 순서(동일 봉에서 신호+체결 동시 처리)로 인한 lookahead 제거
- [ ] 리밸런싱 완충(노트레이드밴드) 유무에 따른 성과 민감도 체크

### 3) Exposure(익스포저/구성) 문제
- [ ] 순노출/섹터노출/단일종목 최대비중의 시계열
- [ ] 상관 클러스터 동시 보유 여부(예: NVDA+AVGO+MSFT 동시 과다)
- [ ] 팩터 노출(대형성장/퀄리티/저변동 등) 간접 추정: 특정 레짐에서만 먹히는지 확인

### 4) Cost(비용) 문제
- [ ] 거래당 비용, 월별 비용 합계, 비용/총수익 비율
- [ ] turnover 분해(신호 변경 vs 리밸런싱 잡음)
- [ ] “비용 5/10/20bps” 민감도 곡선이 급경사면 신호가 얇다는 뜻

### 5) Regime(국면) 문제
- [ ] QQQ 추세(상/하), XLV/XLK 상대강도, 변동성(예: VXX percentile)별 성과 테이블
- [ ] 레짐별 MDD/승률/턴오버: 특정 레짐에서만 망가지는지 확인
- [ ] 레짐 필터 적용 시 “손실 구간이 줄었는지”를 우선 평가(평균수익보다 tail 먼저)

원칙: **(1) 누수 차단 → (2) 비용 반영 → (3) 데이터/운영 안정 → (4) 레짐 게이트 → (5) 포트폴리오 제약** 순서로만 앞으로 진행하라. 이 순서가 뒤집히면, 좋아진 수치의 “원인”을 영영 분리하지 못한다.
