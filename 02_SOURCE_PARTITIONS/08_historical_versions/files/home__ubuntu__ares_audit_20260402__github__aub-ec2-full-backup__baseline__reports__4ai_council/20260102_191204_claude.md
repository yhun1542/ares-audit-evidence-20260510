### PATCH 2: Degenerate Fold 원인 격리 (Fold 1,2,3,8)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

- 8개 폴드 중 4개(50%) degenerate → **OOS 신뢰도 붕괴**
- 서바이버십 또는 레짐 편향 가능성 높음

**(b) 위험/부작용**
- 폴드 제거 시 학습 데이터 감소

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|---|---|---|---|
| P2-A | Fold 1,2,3,8 기간 별 시장 레짐 라벨링 (SPY drawdown >10% 등) | 라벨 생성 | 4개 폴드 중 3개 이상이 특정 레짐에 집중? |

| P2-C | Purge/Embargo 기간 2배로 늘려 재실행 | degenerate 폴드 수 변화 | 3개 이하로 감소 시 누수 의심 확정 |

**(d) PASS 조건**
```bash
☐ degenerate_folds 수 ≤ 2 (전체의 25% 이하)
☐ 또는 degenerate 원인이 "데이터 희소"로 명확히 분류됨
```

## 성능 안 움직일 때 원인 분해 트리

```
[성능 Δ ≈ 0]
    │
    ├─(1) 트리거 미발동
    │      └─ 시그널 생성 건수 확인 → 0건이면 팩터/필터 과잉
    │
    ├─(2) 적용 미반영  
    │      └─ 포지션 변화 diff → 리밸런스 실제 발생 여부
    │
    ├─(3) 노출 상쇄
    │      └─ long/short 동시 → net exposure ≈ 0 확인
    │
    ├─(4) 비용 흡수
    │      └─ gross return - cost ≈ 0 → 회전율 체크
    │
    └─(5) 레짐 상쇄
           └─ bull 구간 +, bear 구간 - → 평균 ≈ 0
```
