### P1. Fold-Specific Failure 분석 (누수/과최적화 점검)

**(a) 필요성**
- tuning_min 0.05 = 14개 폴드 중 1개가 거의 전멸
- 단일 폴드 실패가 전체 신뢰도 훼손 → 원인 분리 필수

**(b) 위험/부작용**
- 분석만으로 성능 개선 없음 (시간 소모)
- 해당 폴드가 진짜 "운 없는 구간"일 가능성

**(c) 실험 체크리스트**
```yaml
EXP-P1-1:
  name: "fold_failure_autopsy"
  action: |
    - 최악 폴드 식별 (tuning 0.05 기여 폴드)
    - 해당 기간 섹터별 수익 분해
    - 동일 기간 SPY 대비 상대성과 확인
  gate: "분석 완료"
  expect: "실패 원인 1개 이상 식별"

EXP-P1-2:
  name: "signal_leak_check"
  action: |
    - 해당 폴드의 시그널 생성일 vs 실제 매매일 검증
    - look-ahead bias 유무 체크 (feature timestamp audit)
  gate: "누수 없음 확인"
  expect: "all signals use t-1 data only"
```

**(d) PASS 조건**
- 누수 발견 시 → 즉시 수정 후 전체 재실행
- 누수 없음 → P2로 이동
