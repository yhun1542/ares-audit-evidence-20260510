# AUB 48H 실행 패치 플랜

## 🚨 긴급 진단: 현재 상태 해석

| 지표 | 값 | 판정 |
|------|-----|------|
| OOS Mean | 3.32 → 2.63 (진단기 기준) | ⚠️ **20% 하락, 불안정** |
| Degenerate Folds | [1,2,3,8] = 4/10 | 🔴 **40% 폴드 실패 = 과최적화 신호** |
| Worst MDD | None | 🔴 **측정 누락 = 리스크 블라인드** |
| Rebalance 로그 | 파일 없음/파싱 실패 | 🔴 **운영 검증 불가** |

**핵심 문제**: 챔피언이 특정 폴드에서만 작동 → **서바이버십 + 과최적화 의심**

## 📋 TOP 5 우선순위 패치

### PATCH 1: Degenerate Fold 원인 분해
```
WHY: 4/10 폴드 실패 = 전략이 특정 레짐에서만 작동
     이 상태로 라이브 불가
```

| 실험 ID | 정의 | 게이트 | 기대 관측치 |
|---------|------|--------|-------------|
| `P1-A` | 폴드 1,2,3,8의 공통점 추출 (기간/변동성/섹터) | 자동완료 | 레짐 클러스터 라벨 |
| `P1-B` | Degenerate 폴드 제외 후 OOS 재계산 | OOS_mean > 2.0 | 6-fold OOS 분포 |
| `P1-C` | 폴드별 exposure 히트맵 생성 | 시각적 확인 | 패턴 일관성 여부 |

**PASS 조건**: Degenerate 원인 1개 이상 특정 + 해당 레짐 정의 문서화

**위험/부작용**: 
- 유효 폴드만 남기면 N↓ → 통계적 신뢰도↓
- 레짐 필터 추가 시 복잡도 증가

---

### PATCH 2: MDD 측정 파이프라인 복구
```
WHY: worst_mdd=None → 리스크 메트릭 블라인드
     드로다운 없이 샤프만 보면 꼬리 리스크 무시
```

| 실험 ID | 정의 | 게이트 | 기대 관측치 |
|---------|------|--------|-------------|
| `P2-A` | `calc_mdd()` 함수 로깅 추가, None 원인 추적 | 에러로그 확보 | 실패 라인 특정 |
| `P2-B` | 일별 equity curve 덤프 → 수동 MDD 계산 | MDD 값 산출 | -15% ~ -40% 범위 |

**PASS 조건**: `worst_mdd` 숫자값 출력 + 폴드별 MDD 분포

**위험/부작용**: 
- MDD 측정 후 챔피언 탈락 가능 (좋은 것임)

---

### PATCH 3: Rebalance 로그 파이프라인 수정
```
WHY: 로그 파싱 실패 → 실제 매매 시점/슬리피지 검증 불가
     백테스트 ≠ 실거래 괴리 원인 추적 불가
```

| 실험 ID | 정의 | 게이트 | 기대 관측치 |
|---------|------|--------|-------------|
| `P3-A` | rebalance.csv 생성 코드 확인, 경로/포맷 수정 | 파일 존재 | 파싱 성공 |
| `P3-B` | JSONL → CSV 변환기 작성 또는 진단기 수정 | 진단기 정상 실행 | diff 리포트 출력 |

**PASS 조건**: `aub_rebalance_pinpoint.py` 정상 실행 + 리밸런스 횟수/비용 산출

**위험/부작용**: 
- 포맷 변경 시 기존 로그 호환성 깨짐

---

### PATCH 4: 비용 모델 현실화 (슬리피지 스트레스)
```
WHY: OOS 3.32인데 실거래 수익 0이면 비용 모델 문제
     현재 비용 가정치 불명확
```

| 실험 ID | 정의 | 게이트 | 기대 관측치 |
|---------|------|--------|-------------|
| `P4-A` | 슬리피지 0bp/5bp/10bp/20bp 그리드 백테스트 | 전체 완료 | OOS 민감도 곡선 |
| `P4-B` | 리밸런스 빈도 vs 비용 트레이드오프 산출 | 그래프 생성 | 최적 빈도 구간 |

**PASS 조건**: 10bp 슬리피지에서 OOS_mean > 1.5 유지

**위험/부작용**: 
- 비용 현실화 → 대부분 전략 사망 가능 (정상)

---

### PATCH 5: Exposure 상한 검증
```
WHY: exposure_max=0.84 → 레버리지 없이도 집중도 높음
     단일 종목 쏠림 리스크 점검 필요
```

| 실험 ID | 정의 | 게이트 | 기대 관측치 |
|---------|------|--------|-------------|
| `P5-A` | 종목별 max exposure 분포 추출 | 자동완료 | Top3 종목 비중 |
| `P5-B` | 종목당 상한 20%/15%/10% 강제 후 OOS | 전체 완료 | OOS 변화량 |

**PASS 조건**: 단일 종목 < 25% 유지하면서 OOS_mean > 2.0

**위험/부작용**: 
- 집중 투자가 알파 원천이면 분산 시 성능↓

## 🔬 성능 불변 시 원인 분해 트리

```
OOS 변화 없음
├─ [트리거] 시그널이 안 바뀜
│   └─ 점검: 시그널 변경 횟수/실험 간 diff
├─ [적용] 시그널 → 포지션 변환 로직 불변
│   └─ 점검: position diff 로그
├─ [노출] 포지션은 바뀌는데 exposure 상한에 막힘
│   └─ 점검: exposure clipping 빈도
├─ [비용] 수익은 나는데 비용이 상쇄
│   └─ 점검: gross return vs net return 분리
└─ [레짐] 테스트 기간이 특정 레짐에 편중
    └─ 점검: 폴드별 VIX/SPY 수익률 분포
```
