### 2. 제안별 상세 실행 계획 (Imperative Checklist)

#### (1) Infra: Rebalance Logger 복구 (JSONL 포맷팅)
*   **왜 필요한가:** 현재 `rebalance.csv` 및 jsonl 파일이 깨져있어(`Expecting value...`) 어떤 종목이 선택되었는지 사후 분석 불가. 맹목적 비행 상태.
*   **위험/부작용:** 로깅 오버헤드로 인한 미세한 속도 저하(무시 가능 수준).
*   **실행 Patch:**
    1.  `experiment_system/logging.py` (추정 경로) 내 파일 Write 모드를 `w`에서 `a`로 변경하거나, JSON Dump 시 `flush()` 강제 호출.
    2.  CSV 포맷 대신 구조적 데이터인 `JSONL`로 단일화하여 입출력 무결성 확보.
*   **PASS 조건:** 백테스트 종료 후 생성된 로그 파일이 `jq` 또는 `pandas.read_json`으로 오류 없이 로드됨.

#### (2) Risk: Degenerate Folds (1, 2, 3, 8) 소생 실험
*   **왜 필요한가:** 전체 Fold의 약 40%가 붕괴됨. 해당 기간(예: 2022년 하락장 등)에 아예 거래를 안 했거나(0 exposure), 시작하자마자 손절되어 멈췄을 가능성 높음.
*   **위험/부작용:** 강제 거래로 인한 MDD 증가. 그러나 이는 '숨겨진 리스크'를 드러내는 과정임.
*   **실험 정의:**
    *   `EXP_01_FORCE_ENTRY`: 진입 임계값(Threshold)을 기존 대비 50% 낮춤.
    *   `EXP_02_MIN_EXPOSURE`: 포트폴리오 최저 노출 비중을 0.0 -> 0.2로 강제 설정.
*   **게이트(Gate):** 4개 붕괴 Fold 중 2개 이상에서 `Trade Count > 10` 발생.
*   **기대 관측치:** OOS Mean은 하락하더라도, 모든 Fold에서 생존(Degenerate 해제) 확인.

#### (3) Allocation: Tech/Healthcare Balance Enforcement
*   **왜 필요한가:** 현재 미국주식 Tech+Healthcare 집중 전략이나, 8~14개 종목 선정 시 특정 섹터(예: Tech) 몰빵 후 헬스케어 방어주 기능을 상실했을 수 있음.
*   **위험/부작용:** 수익성 높은 섹터 비중 축소로 인한 Alpha 감소.
*   **실험 정의:**
    *   `EXP_03_SECTOR_CAP`: 포트폴리오 내 `Tech < 60%`, `Healthcare < 60%` 제약 조건 추가.
    *   `EXP_04_UNIVERSE_FLOOR`: 최소 보유 종목 수를 8개로 강제(현재 8~14개 내외 조건 준수).
*   **게이트(Gate):** 리밸런싱 로그 상 Tech/Health 비율이 7:3 ~ 3:7 범위 유지.
*   **기대 관측치:** MDD 개선 및 붕괴된 Fold의 샤프지수 회복.

#### (4) Cost: Reality Check (비용 미반영 점검)
*   **왜 필요한가:** OOS Mean 3.32는 비현실적. 슬리피지와 수수료가 과소평가되었을 가능성 99%.
*   **위험/부작용:** 전략 폐기 가능성(성능 급락).
*   **실험 정의:**
    *   `EXP_05_DOUBLE_COST`: 시뮬레이터 내 `bps` 및 `slippage` 파라미터를 현재의 2배로 설정.
*   **게이트(Gate):** OOS Mean > 1.5 유지.
*   **기대 관측치:** OOS Mean이 3.32 -> 1.8~2.0 수준으로 현실화. 만약 마이너스로 전환되면 전략 로직 전면 재검토 필요.

### 3. 성능 정체/이상 시 원인 분해 아이디어

성능이 움직이지 않거나(Flat), Degenerate 상태가 지속될 경우 다음 체크리스트를 순차적으로 수행하십시오.

1.  **트리거(Trigger) 확인:**
    *   시장 지표(VIX, SPY MA200 등)가 'Trading Ban' 상태로 고정되어 있는지 확인. (ETF 관측지표 오류 가능성)
2.  **유니버스(Universe) 노출:**
    *   Tech/Healthcare 티커 리스트가 정확한지, 상장 폐지 종목이나 데이터 결측 종목이 `Top K`를 점유하고 있지 않은지 확인(Survival Bias).
3.  **적용(Execution) 실패:**
    *   시뮬레이터가 `Cash` 부족으로 매수를 거부하고 있는지 확인 (로그 복구 후 확인 가능).
4.  **레짐(Regime) 불일치:**
    *   Fold 1,2,3,8의 날짜 구간을 특정하여, 해당 기간의 벤치마크(QQQ/XLV) 대비 상관계수(Correlation) 측정. 음의 상관관계가 심하면 역추세(Counter-trend) 로직 오작동 의심.
