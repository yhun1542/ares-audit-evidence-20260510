## 48시간 자동 루프용 “공통 실험 5개” (3~5개 제한 준수)
아래 5개만 돌리고, 위 TOP5는 이 실험들을 조합해서 판정합니다.

### E1) **Rebalance 로그/스키마 계약 실험**
- **(1) 실험 정의**: 백테스트 실행 시 `rebalance.jsonl`(또는 csv) 강제 생성 + 스키마 버전/필수 필드 검증 + pinpoint가 읽는 포맷으로 변환 어댑터 추가
- **(2) 게이트**: 로그 파일 누락/파싱 실패/필수 필드 결측이면 실험 실패로 즉시 중단
- **(3) 기대 관측치**: 각 리밸런스에 대해 {timestamp, holdings(8~14), sector tags, turnover, costs, exposure}가 출력되고 base/cand diff가 가능

### E2) **누수/타이밍 “미래 시프트 붕괴” 실험**
- **(1) 실험 정의**: feature를 +1D~+5D 미래로 인위 시프트한 버전을 만들어 동일 학습/평가
- **(2) 게이트**: 시프트 후에도 성능이 유지되면(예: OOS mean이 거의 동일) 누수 의심으로 해당 파이프라인 차단
- **(3) 기대 관측치**: 시프트가 커질수록 OOS가 단조롭게 악화

### E3) **PIT 유니버스/상폐 수익률 포함 재현 실험**
- **(1) 실험 정의**: point-in-time universe + delisting return + corporate action 정합 버전으로 재평가
- **(2) 게이트**: 상폐/합병 케이스에서 가격/수익률 불연속(0 처리, NaN 연쇄)이 발견되면 실패
- **(3) 기대 관측치**: tail 이벤트 구간의 손익이 더 현실적으로 바뀌고, 백테스트/운영 간 괴리 감소

### E4) **거래비용/턴오버 3점 스윕 실험**
- **(1) 실험 정의**: 비용(낮음/기준/높음) + turnover cap(없음/중간/강함) 매트릭스를 “3점”만으로 축약 실행(케이스 폭발 금지)
- **(2) 게이트**: 기준 비용에서 net 성능이 gross 대비 과도 붕괴하거나, turnover가 상한을 지속 위반하면 실패
- **(3) 기대 관측치**: 가장 안정적인 조합에서 OOS min 및 변동성이 개선, 실거래 가능성 상승

### E5) **레짐-기반 노출 클램프(ETF는 지표) 실험**
- **(1) 실험 정의**: QQQ/XLV/VIX 계열을 “관측 지표”로만 사용하여 risk-on/off 레짐 산출 → exposure 하한/상한 동적 조정 + 변화율 제한
- **(2) 게이트**: exposure가 레짐 전환 시 과도 진동하거나(whipsaw), OOS min이 악화되면 실패
- **(3) 기대 관측치**: 변동성 구간에서 손실 꼬리 감소, 노출 프로파일 안정화

## 성능이 안 움직일 때: 원인 분해 아이디어(트리거/적용/노출/비용/레짐) — 실행 체크리스트

### A) Trigger(신호 생성) 레벨
- [ ] 신호 분포가 실험 간 거의 동일한지 확인: 예측값 상관(>0.98) / 랭크 변동 미미하면 “실험이 실험이 아님”
- [ ] 시그널이 특정 소수 종목에만 몰리는지 확인(Tech mega-cap 편향 등)
- [ ] 이벤트(실적/임상) 주변에서 신호가 “발표 전”에 튀면 누수 의심(E2로 컷)

### B) Apply(포트폴리오 매핑/제약 적용) 레벨
- [ ] 상위 N(8~14) 제약이 실제로 성능을 눌러 “모든 실험이 같은 바스켓”이 되는지 확인
- [ ] 리밸런스 규칙(빈도/리밸 버킷/최소 변경량)이 결과를 고정시키는지 확인(E1 로그로 검증)
- [ ] 섹터 제약(Tech+Healthcare)이 사실상 동일 종목군을 강제하는지 확인

### C) Exposure(베타/현금비중/레버리지) 레벨
- [ ] 성능 차이가 전부 exposure(0.47~0.84)에서 나오고, 알파는 0인지 분해(시장수익률/섹터 ETF 대비)
- [ ] 노출 상한/하한이 너무 타이트/너무 느슨한지(E5로 동적 클램프 후 tail 개선 여부)

### D) Cost(비용/충격) 레벨
- [ ] gross는 좋아지는데 net이 안 움직이면 turnover가 원인(E4로 즉시 확인)
- [ ] 리밸런스 때만 손익이 크게 새는지(장 마감/시가 가정, 슬리피지 모델 부정합) → E1+E4에서 “리밸런스 이벤트별 비용”으로 pinpoint

### E) Regime(시장 국면) 레벨
- [ ] 전체 OOS 평균이 아니라 “레짐별 성능표”(risk-on/off, 금리상승/하락, 변동성 상/하)로 분해
- [ ] 특정 레짐에서만 성능이 죽으면: 그 레짐에서 exposure를 줄이는 게 1차 처방(E5)
- [ ] 레짐 피처 추가가 과적합이면: 레짐을 예측하지 말고 **관측 지표 기반 규칙(클램프)**으로 제한(E5가 이 방식)
