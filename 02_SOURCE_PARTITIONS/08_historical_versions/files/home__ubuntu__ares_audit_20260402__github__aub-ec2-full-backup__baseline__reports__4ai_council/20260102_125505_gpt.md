## 24~48시간 TOP5 우선순위(명령형 체크리스트) — 누수/과최적화/서바이버십/비용/운영리스크 우선

### 1) **평가/로깅 파이프라인 “ONE TRUTH” 정합성 복구 (운영 리스크 최우선)**
- **즉시 조치**
  - `champion file:` 공란 원인 제거(아티팩트 경로/심볼릭 링크/권한) → *항상* `baseline/champion_latest.json`에 실체 파일 기록.
  - `aub_rebalance_pinpoint` 입력 포맷 고정: `rebalance.csv` 또는 `rebalance.jsonl`을 *반드시* 생성(현재 “Expecting value…”는 JSON이 아닌 텍스트/빈파일 가능성).
  - `worst_mdd: None` 제거: 백테스트 종료 시 **MDD 계산 강제**(None이면 PASS 불가).
  - `Champion OOS Mean 1.88` vs Diagnoser `2.63` 불일치 원인 제거: **동일 데이터 컷/동일 스코어러/동일 수수료/동일 기간**을 run_hash에 포함해 재현성 확보.
- **왜 필요한지**
  - 성능이 “안 움직임”의 1순위 원인은 실제로는 **실험이 안 먹히거나(로그/아티팩트 깨짐)**, **다른 기준으로 비교**하는 경우가 많음.
- **위험/부작용**
  - 로그 강제는 디스크/IO 비용 증가.
  - 스코어러/기간을 고정하면 단기적으로 OOS가 하락할 수 있음(기존이 착시였던 경우).
- **최소 실험(=48h 루프용, 2~3개 마이크로-실험/패치)**
  1) **[Patch] Run Manifest 강제**
     - 실험정의: 모든 run에 `run_manifest.json`(데이터 컷, scorer 버전, 비용모델 버전, universe 해시, 기간)을 저장하고, diagnoser가 manifest mismatch면 비교 중단.
     - 게이트: manifest mismatch=0, champion file path non-empty, 파일 존재.
     - 기대 관측치: OOS Mean 불일치(1.88 vs 2.63) 재발 0건.
  2) **[Patch] Rebalance 로그 표준화**
     - 실험정의: 리밸런스 이벤트를 `rebalance.jsonl`로 append(주문/체결/포지션/비용 breakdown 포함).
     - 게이트: pinpoint 스크립트가 에러 없이 리포트 생성.
     - 기대 관측치: “No rebalance data found” 재발 0건, turnover/비용이 리포트에 표시.
  3) **[Patch] worst_mdd 강제 계산**
     - 실험정의: 백테스트 종료 시 `worst_mdd` None이면 실패 처리 + 산출 로직 추가.
     - 게이트: champion/cand 모두 worst_mdd 실수값(0~1) 보유.
     - 기대 관측치: 리스크 비교 가능해지고 “성능 정체” 원인분해에서 MDD/변동성 사용 가능.

- **PASS 조건**
  - (필수) `champion file` non-empty + 존재, `worst_mdd` None=0건, rebalance pinpoint 리포트 생성 성공.
  - (필수) 동일 base/cand 비교 시 스코어 불일치 재발 0건(±1e-6 수준 제외).

### 2) **누수(lookahead)·시점정렬(point-in-time)·라벨/피처 shift 감리**
- **즉시 조치**
  - 모든 feature에 대해 “사용 가능 시점(ts_available)” 컬럼/룰을 강제하고, **리밸런스 시각 이전 데이터만 join**.
  - 라벨(미래수익)과 피처(과거정보) 간 **최소 1 bar 이상 shift**를 테스트로 고정.
  - “training fold ↔ validation fold” 사이 **embargo 기간**(예: 5~20 거래일) 설정(과최적화/정보누수 방지).
- **왜 필요한지**
  - Tech+Healthcare는 이벤트(실적/임상/가이던스) 민감 → 시점 누수 한 번이면 OOS가 허수로 뜨고, 이후 “실험이 안 움직이는” 상태가 됨.
- **위험/부작용**
  - 누수 제거 후 OOS 평균이 급락할 수 있음(정상).
  - embargo/shift로 학습 데이터 유효량 감소.
- **최소 실험(마이크로-실험/패치)**
  1) **[Patch] 피처-라벨 시점 정렬 유닛테스트**
     - 실험정의: 샘플 n개에 대해 `max(feature_ts) < decision_ts`를 강제 검증(위반 시 런 실패).
     - 게이트: 위반 0건.
     - 기대 관측치: “갑자기 높은 OOS” 형태의 이상치 런 감소.
  2) **[Experiment] Embargo on/off A/B**
     - 실험정의: 동일 설정에서 embargo=0 vs embargo=10d 비교(동일 seed/동일 universe).
     - 게이트: embargo 적용 시에도 oos_min이 급락하지 않을 것(예: 기존 대비 -X% 이내) + degenerate fold=0.
     - 기대 관측치: 과최적화된 설정이면 embargo에서 OOS 하락폭이 크게 나타남(신호).
  3) **[Patch] 데이터 join의 asof 규칙 강제**
     - 실험정의: asof-join(이전값 유지)만 허용, forward-fill 금지(특히 재무/펀더멘털).
     - 게이트: forward-fill 사용 라인 0.
     - 기대 관측치: “레짐 전환일” 주변에서 성능 착시 감소.

- **PASS 조건**
  - 누수 관련 테스트 100% 통과.
  - embargo 실험에서 OOS 변동이 설명 가능한 범위로 수렴(극단적 붕괴가 있으면 기존 신호가 누수였을 확률 ↑).

### 3) **서바이버십/유니버스 편향 제거 + Tech/Healthcare 8~14종목 제약을 “운영 가능”하게 고정**
- **즉시 조치**
  - 유니버스 생성 시 **delisting 포함(point-in-time constituent)**, 최소 유동성/가격/거래정지 필터를 룰로 박제.
  - “오늘 기준 종목 리스트”를 과거에 투영하는 방식 금지.
  - 8~14개 유지 로직을 **결측/상장폐지/거래정지 시 대체 규칙**으로 안정화.
- **왜 필요한지**
  - 상장폐지/인수합병/티커 변경이 빈번한 영역(바이오 포함)에서 survivorship bias는 OOS를 장기적으로 마비시킴.
- **위험/부작용**
  - 딜리스팅 포함 시 성능 하락 가능(정상), 데이터 소싱 비용 증가.
- **최소 실험(마이크로-실험/패치)**
  1) **[Patch] 유니버스 해시 고정 + 재현성**
     - 실험정의: 매 리밸런스 시점의 top-eligible 리스트를 저장(`universe_snapshot.jsonl`)하고 해시 비교.
     - 게이트: 동일 백테스트 재실행 시 해시 100% 동일.
     - 기대 관측치: “랜덤하게 성능이 흔들리는” 재현성 문제 감소.
  2) **[Experiment] liquidity floor 민감도**
     - 실험정의: ADV(예: $20M vs $50M) 2수준으로만 비교(케이스 폭발 금지).
     - 게이트: turnover/슬리피지 추정이 개선되며 oos_min 악화가 제한적.
     - 기대 관측치: 낮은 ADV에서만 먹던 신호는 현실성 낮음이 드러남.
  3) **[Patch] 8~14 유지 failover**
     - 실험정의: 종목 수가 8 미만이면 현금/노출 축소가 아니라 “차순위 편입”으로 복구(단, 필터 통과 종목만).
     - 게이트: live-sim에서 포트 종목 수 분포가 8~14에 99% 이상.
     - 기대 관측치: exposure_min(현재 0.47) 비정상 저하 구간 감소.

- **PASS 조건**
  - 유니버스 재현성 100%, 종목수 제약(8~14) 위반률 <1%.
  - survivorship 의심되는 성능 과대 구간이 줄고, OOS 변동성이 낮아짐.

### 4) **비용(거래비용/슬리피지/borrow) 미반영 방지 + 민감도 게이트**
- **즉시 조치**
  - 거래비용을 3요소로 분해해 로그에 기록: `spread + slippage + fees` (+공매도면 `borrow`).
  - 비용 모델 버전을 manifest에 고정하고, **비용 0/1x/2x 민감도**를 자동으로 같이 산출(루프 내 3-암 밴드).
- **왜 필요한지**
  - Tech/Healthcare 소수 종목 집중은 turnover가 커지기 쉬움 → 비용이 성능을 “안 움직이게” 만드는 진짜 원인일 가능성 큼.
- **위험/부작용**
  - 비용 반영 후 샤프/수익 급락 가능(정상).
  - 과도한 비용 가정은 전략을 과소평가.
- **최소 실험(마이크로-실험/패치)**
  1) **[Patch] 비용 breakdown 로깅**
     - 실험정의: 주문별 추정비용과 누적비용을 `rebalance.jsonl`에 기록.
     - 게이트: 비용 breakdown 결측 0.
     - 기대 관측치: “OOS가 안 오르는” 구간이 비용 급증(스프레드/슬리피지)과 동행하는지 관측 가능.
  2) **[Experiment] cost sensitivity 0/1x/2x (단일 런에서 3스코어)**
     - 실험정의: 동일 트레이드 시퀀스를 비용배수만 바꿔 성능 재평가(전략 비교의 기준선).
     - 게이트: 2x 비용에서도 oos_min이 임계치 이상 유지.
     - 기대 관측치: 비용탄력도가 크면 “turnover/리밸런스 빈도”가 다음 타깃임이 확정.
  3) **[Patch] turnover cap 옵션**
     - 실험정의: 일/주간 turnover 상한을 두고 초과 주문을 스케일 다운(운영 안전장치).
     - 게이트: turnover 상한 준수 + 성능 급락 없음.
     - 기대 관측치: 비용과 MDD가 함께 안정화.

- **PASS 조건**
  - 비용 민감도 리포트가 매 런 자동 생성.
  - 2x 비용에서도 전략이 “완전 붕괴”하지 않음(붕괴 시 신호보다 마찰이 지배적).

### 5) **노출(exposure)·레짐·리밸런스 트리거를 분리 관측(“안 움직임” 해소용 계측)**
- **즉시 조치**
  - 트리거(진입/청산 신호)와 포지션 사이징(노출/리스크)을 분리 로깅:  
    `signal_strength`, `target_weight`, `final_weight`, `clip_reason`(리스크/유동성/종목수/turnover 등).
  - ETF는 매매 금지 준수 + **관측 지표**로만 사용(예: XLK/XLV/QQQ/IBB 등): 레짐 태그만 생성.
- **왜 필요한지**
  - 현재 exposure_min/max(0.47~0.84)로 보아, 신호가 아니라 **클리핑/제약**이 성능을 눌러 “안 움직이는” 상태일 수 있음.
- **위험/부작용**
  - 노출 규칙을 바꾸면 MDD 증가 가능.
  - 레짐 게이트가 과하면 기회비용 증가.
- **최소 실험(마이크로-실험/패치)**
  1) **[Patch] clip_reason 계측**
     - 실험정의: 최종 주문이 줄어든 모든 케이스에 이유코드 부여(제약 탓인지 신호 탓인지 분리).
     - 게이트: clip_reason 미기록 0.
     - 기대 관측치: “노출이 낮아지는 구간”이 어떤 제약 때문에 발생하는지 즉시 식별.
  2) **[Experiment] 노출 목표 0.8 고정 vs 변동(현행)**
     - 실험정의: 동일 신호에서 exposure 타깃만 고정/변동 2버전 비교.
     - 게이트: worst_mdd가 임계치 내에서 유지되며 oos_mean 개선 또는 oos_min 개선 중 하나 달성.
     - 기대 관측치: 성능 정체가 노출 정책 때문인지 분리됨.
  3) **[Experiment] 레짐 태그(관측) 기반 “거래 빈도만” 제어**
     - 실험정의: 레짐이 불리할 때 포지션을 줄이는 대신 **리밸런스 빈도/turnover만 낮춤**(매매 금지 아님).
     - 게이트: 비용/turnover 감소 + 성능 유지.
     - 기대 관측치: 레짐이 비용과 변동성에 어떤 영향을 주는지 분리 관측.

- **PASS 조건**
  - 신호→사이징→클리핑의 병목이 로그로 100% 설명됨.
  - 노출/빈도 제어 실험에서 비용과 oos_min이 동시에 악화되지 않음.

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **각 런마다 자동 계산/대시보드화**하면, 1~2회전 내에 정체 원인이 분해됨.

### A) Trigger(신호) 문제인지?
- **관측치**
  - `signal hit-rate`(신호 발생 빈도), 신호 분포가 0 근처로 붕괴했는지
  - 신호가 나왔을 때의 **조건부 기대수익**(signal decile별 다음기간 수익)
- **판정**
  - 신호 빈도↓ + 조건부 수익도↓ → 알파 자체 소멸/레짐 변화 가능성

### B) Apply(주문/체결/제약)에서 막히는지?
- **관측치**
  - `target_weight` vs `final_weight` 괴리, `clip_reason` 비중(리스크/유동성/종목수/turnover)
  - 주문 미체결/부분체결률(시뮬이라도 추정)
- **판정**
  - 신호는 있는데 final이 줄어든다 → 제약/집행이 원인(전략이 아니라 운영 규칙 문제)

### C) Exposure(노출) 정책이 성능을 눌러서 정체인지?
- **관측치**
  - exposure_min/max, 시간가중 평균 노출
  - 노출과 PnL의 상관(노출 낮을 때 기회손실 발생 여부)
- **판정**
  - 노출이 구조적으로 낮아져 있음(현재 min 0.47) + 신호는 정상 → 사이징/리스크 버짓 재설계 필요

### D) Cost(비용)가 알파를 먹는지?
- **관측치**
  - 총비용/일, 비용을 spread/slippage/fees/borrow로 분해
  - “총수익 - 비용 = 순수익”에서 비용 기여율
  - turnover와 비용의 탄력도
- **판정**
  - 비용 기여율이 높고 turnover와 동행 → 리밸런스 빈도/turnover cap/유동성 필터가 우선 타깃

### E) Regime(시장/섹터/변동성) 변화로 신호가 무력화됐는지?
- **관측치(ETF는 관측만)**
  - XLK/XLV/QQQ/IBB의 추세/변동성/크로스(예: 20/60MA), 금리 proxy(예: TLT 수익률 변동) 등으로 레짐 태그
  - 레짐별 성능 분해(OOS mean/min, MDD, turnover)
- **판정**
  - 특정 레짐에서만 성능이 멈춤 → 레짐별 리밸런스 빈도/노출만 조정(매매 금지 아님), 또는 신호 가중치 축소
