### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### [P1] Tuning-Lockbox 갭 정규화
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한가**
- Champion: tuning(3.47) vs lockbox(2.89) = **0.58 갭**
- 갭 > 0.3이면 과최적화 경고 → 실전 성능 하락 예상

**(b) 위험/부작용**
- 정규화 과하면 alpha 자체가 소멸
- 계산 비용 증가 (rolling 통계 필요)

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 |
|----|-----------|--------|
| P1-A | `penalty = 0.1 * (tuning_score - lockbox_score)` 적용 | 갭 < 0.25 |
| P1-B | 파라미터당 L2 정규화 λ=0.01 추가 | tuning_mean 감소 < 15% |
| P1-C | Walk-forward 5→7 fold 확장 | lockbox_min 개선 |

**(d) PASS 조건**
```
tuning_mean - lockbox_mean < 0.30 AND lockbox_min > 1.0
```

## 2. 성능 미동 시 원인 분해 트리

```
성능 안 움직임
├─ [트리거] 시그널 자체가 안 바뀜
│   ├─ 파라미터 변경이 임계값 못 넘음
│   └─ 데이터 구간이 동일 → 시그널 캐싱 확인
│
├─ [적용] 시그널 바뀌는데 포지션 불변
│   ├─ 리밸런싱 주기 > 실험 구간
│   └─ 사이즈 로직이 시그널 무시
│
├─ [노출] 포지션 바뀌는데 수익 불변
│   ├─ 헤지/상쇄 포지션 존재
│   └─ 종목간 상관관계 0.9+ → 실질 노출 동일
│
├─ [비용] 수익 발생하나 비용에 잠식
│   └─ 회전율 증가분 > 알파 개선분
│
└─ [레짐] 실험 구간이 특정 레짐에 편중
    └─ Fold 분포 확인 → 레짐 라벨링 추가
```
