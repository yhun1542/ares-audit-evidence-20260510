[우선순위 제안 및 실행 체크리스트]

현재 `tuning_min`(-1.35)과 `lockbox_mean`(1.33)의 괴리가 심각합니다. 이는 특정 시장 국면(Fold)에서의 치명적 실패와 홀드아웃 데이터(Lockbox)에 대한 과적합(또는 운)이 공존함을 시사합니다. 이를 해결하기 위한 48시간 내 실행 과제입니다.

---

### 1. `tuning_min` 방어를 위한 손절/변동성 제어 (Risk Patch)
*   **이유:** `tuning_min` -1.35는 전략 폐기 수준의 위험입니다. 헬스케어(바이오) 섹터의 개별 종목 급락이나 테크 섹터의 베타 하락을 방어하지 못하고 있습니다.
*   **위험:** 손절이 너무 잦으면 휩소(Whipsaw)로 인해 `tuning_mean`이 1.0 미만으로 하락할 수 있음.
*   **실험:**
    1.  **EXP_STOP_ATR:** 개별 종목 진입 시 ATR(14) * 2.5배 하락 시 강제 청산 로직 추가.
    2.  **EXP_VOL_TARGET:** 포트폴리오 전체 변동성 목표(Target Vol)를 15%로 제한하고 초과 시 현금 비중 확대.
    3.  **EXP_MAX_DRAWDOWN_CUT:** Fold 내 MDD가 -7% 도달 시 해당 월 거래 중단(Cool-off).
*   **PASS 조건:** `tuning_min` > -0.5 (대폭 개선), `tuning_mean` > 1.0 유지.

### 2. Lockbox 과적합(Leakage) 검증 (Data Audit)
*   **이유:** Tuning(1.06)보다 Lockbox(1.33) 성능이 월등히 좋은 것은 비정상적입니다. 미래 참조(Look-ahead Bias)나 생존 편향(Survivorship Bias)이 의심됩니다.
*   **위험:** 실제 알파가 없음을 확인하게 되어 프로젝트가 원점으로 돌아갈 수 있음(심리적 타격).
*   **실험:**
    1.  **EXP_PURGE_SURVIVOR:** 현재 유니버스(8~14종목)가 2026년 기준 우량주로만 구성되었는지 확인. 과거 시점(2020, 2021 등)에 상장 폐지되거나 하락한 종목을 강제로 2개 포함하여 백테스트.
    2.  **EXP_LAG_FEATURE:** 모든 피처 생성 시 `shift(1)`을 강제 적용하여 미래 참조 가능성 차단.
*   **PASS 조건:** `lockbox_mean`과 `tuning_mean`의 격차가 0.1 이내로 축소되며, 여전히 Sharpe > 1.0 유지.

### 3. Tech/Healthcare 상관관계 디커플링 (Portfolio Logic)
*   **이유:** 두 섹터가 동시에 무너지는 구간(금리 인상기 등)에서 방어력이 없습니다. 두 섹터 간 상관계수가 높을 때 현금 비중을 늘려야 합니다.
*   **위험:** 강세장에서 수익 기회를 놓쳐 `tuning_mean` 하락 가능성.
*   **실험:**
    1.  **EXP_CORR_FILTER:** 포트폴리오 내 Tech와 Healthcare 종목 간 평균 상관계수가 0.7 이상이면 현금 비중 50% 강제.
    2.  **EXP_RS_RANKING:** 단순 모멘텀 대신, 섹터 ETF(XLK, XLV) 대비 상대강도(Relative Strength) 상위 종목만 선별.
*   **PASS 조건:** `worst_mdd` > -7% (방어력 개선).

### 4. 비용 구조 현실화 (Cost Reality)
*   **이유:** 잦은 리밸런싱이 포함된 1.06의 성과는 실제 매매 비용 반영 시 마이너스가 될 수 있습니다.
*   **위험:** 겉보기에 훌륭한 전략이 폐기될 수 있음.
*   **실험:**
    1.  **EXP_HIGH_SLIPPAGE:** 슬리피지를 현재 설정의 2배(예: 5bps -> 10bps)로 설정 후 테스트.
    2.  **EXP_TO_LIMIT:** 월간 회전율(Turnover)을 20% 이하로 제한하는 페널티 텀 추가.
*   **PASS 조건:** 비용 2배 적용 후에도 `tuning_mean` > 0.8 유지.

### 5. 아키텍처 최적화: 동적 유니버스 (Architecture)
*   **이유:** 고정된 8-14개 종목 풀은 시장 변화(Regime Change)에 취약합니다.
*   **위험:** 구현 복잡도 증가, 데이터 로딩 시간 증가.
*   **실험:**
    1.  **EXP_DYN_UNIVERSE:** 분기별로 Tech/Healthcare 시총 상위 30개 중 모멘텀 상위 10개를 동적으로 재선정하는 로직 적용.
*   **PASS 조건:** `tuning_min`의 변동폭 축소 (특정 종목 의존도 하락 확인).

### [성능 정체 시 원인 분해 (Diagnosis)]

성능 지표가 움직이지 않을 경우 다음을 점검하십시오.

1.  **트리거 부재 (Trigger):** 시장 상황이 로직의 진입/청산 조건(Threshold)에 도달하지 않아 매매가 발생하지 않음. -> *해결: Threshold 완화.*
2.  **적용 실패 (Application):** 코드 상의 버그로 인해 새로운 로직(예: 손절)이 실제 시뮬레이션에 반영되지 않음. -> *해결: 로그(Log)에서 `SELL_REASON` 확인.*
3.  **노출 부족 (Exposure):** 포트폴리오 내 현금 비중이 너무 높아 알파가 희석됨. -> *해결: 레버리지나 포지션 사이즈 확대.*
4.  **비용 상쇄 (Cost):** 개선된 수익이 늘어난 거래 비용으로 상쇄됨. -> *해결: 거래 횟수(Frequency) 확인.*
5.  **레짐 불일치 (Regime):** 현재 테스트 기간이 Tech/Health 섹터가 횡보하는 구간임. -> *해결: 백테스트 기간 확장 또는 단기 변동성 전략으로 전환.*
