## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — 명령형 체크리스트

### 1) **운영/로깅 단절(리밸런스 로그·메타데이터) 즉시 복구**
- **왜 필요한지**
  - `aub_rebalance_pinpoint`가 `--base-log`/`rebalance.csv|jsonl` 로드 실패 → “왜 성능이 안 움직였는지(리밸런스/비용/회전율/체결)”의 원인 추적이 불가능.
  - `lane_hash/run_hash: None`, `worst_mdd: None` → 챔피언 비교의 재현성/감사추적이 깨짐(운영 리스크 최우선).
- **위험/부작용**
  - 로깅 추가로 I/O 증가(미세한 속도 저하).
  - 로그 스키마 변경 시 기존 도구/대시보드 깨질 수 있음 → 버전 필드 필수.
- **최소 실험 2~3개 (아래 “실험 E1~E5” 중 사용)**
  - **E1**(로깅 스키마/핀포인트 복구), **E2**(누수/정렬 검증 게이트)
- **PASS 조건**
  - 매 런마다 `rebalance.jsonl`(또는 csv) 생성 + `pinpoint report` 자동 생성 성공.
  - 모든 런에서 `lane_hash/run_hash` 채워지고 `worst_mdd` 계산값이 채워짐.
  - 리밸런스 이벤트(주문 수/턴오버/비용)가 “0인데 성능만 변동” 같은 모순이 없어야 함.

---

### 2) **누수(lookahead) + 폴드 퇴화(degenerate_folds) 우선 차단**
- **왜 필요한지**
  - `degenerate_folds: [1,2,3,8]`은 “폴드에서 거래가 거의 없거나, 예측/스코어가 상수로 붕괴, 라벨 정렬 문제” 가능성이 큼.
  - OOS가 움직이지 않는 가장 흔한 원인: **신호가 안 켜짐(트리거 0)** 또는 **정렬 오류로 신호가 무력화**.
- **위험/부작용**
  - 게이트 강화로 “돌던 실험”이 대거 FAIL(단기적으로 산출물 감소).
  - purge/embargo 적용 시 OOS 평균이 낮아질 수 있음(그러나 정직해짐).
- **최소 실험 2~3개**
  - **E2**(시계열 정렬·purge/embargo·degenerate 게이트), **E3**(노출/트리거 최소 활동성 보장)
- **PASS 조건**
  - degenerate_folds 비율: **0 또는 전체 폴드의 ≤10%**.
  - 각 폴드에서 최소 거래/리밸런스 횟수, 예측 분산, 포지션 분산이 하한을 만족.
  - “shift(1)”/asof merge 규칙 위반 0건.

---

### 3) **비용(슬리피지/스프레드/턴오버) 미반영을 강제 반영 + 비용 민감도 실험**
- **왜 필요한지**
  - 비용 모델이 빈약하면 OOS가 “계속 비슷하게” 보이거나, 개선이 비용에 묻혀 관측 불가.
  - 특히 Tech/Healthcare 대형주는 유동성 좋지만, **회전율이 커지면** 알파가 상쇄되기 쉬움.
- **위험/부작용**
  - 비용을 넣으면 성능이 떨어질 수 있음(정상).
  - 비용 파라미터가 과도하면 과보수적 전략만 남음 → 민감도 범위로 다뤄야 함.
- **최소 실험 2~3개**
  - **E4**(비용/턴오버 모델 + 3점 민감도), **E1**(리밸런스 로그로 비용 분해)
- **PASS 조건**
  - 비용 포함 후에도 OOS mean이 **유의미하게 유지(예: -20% 이내 손상)** 또는 비용 대비 성능(Sharpe/turnover)이 개선.
  - 비용이 PnL의 어디서 발생했는지(슬리피지 vs 회전율 vs 갭)가 로그로 분해됨.

---

### 4) **노출(Exposure)·리밸런스 규칙을 “48시간 자동 루프 친화”로 정규화**
- **왜 필요한지**
  - 현재 `exposure_max ~0.84`, `exposure_min 0` → “현금 비중이 들쭉날쭉”한데, degenerate와 결합하면 신호가 거의 안 들어가는 구간이 생김.
  - 자동 루프에서는 “너무 자주/너무 드물게” 리밸런스가 발생하면 학습이 멈춤(관측치 부족).
- **위험/부작용**
  - 최소 노출을 강제하면 하락장 방어력이 낮아질 수 있음 → 레짐 게이트와 같이 적용.
- **최소 실험 2~3개**
  - **E3**(노출 하한/상한 + 최소 활동성), **E5**(레짐 필터로 방어 구간 분리)
- **PASS 조건**
  - 월간/주간 리밸런스 횟수와 턴오버가 “관측 가능한 범위”로 안정화(예: 주 0~3회 수준).
  - 포지션 수(8~14) 충족률 95%+.

---

### 5) **레짐(시장 상태) 분해: ETF는 ‘관측지표’로만 사용**
- **왜 필요한지**
  - “성능이 안 움직임”은 종종 레짐 미스매치(리스크온/오프, 금리/헬스케어 방어 국면)에서 발생.
  - ETF 매매는 금지이므로 **QQQ/XLV/SMH/ARKK(선택)** 등을 “게이팅 신호”로만 사용해 전략 모드 전환.
- **위험/부작용**
  - 레짐 필터가 과하면 거래가 사라져 또 degenerate가 발생 → 최소 활동성 게이트 필수.
- **최소 실험 2~3개**
  - **E5**(ETF 기반 레짐 게이트 + 모드별 노출), **E2**(레짐 피처의 누수 점검)
- **PASS 조건**
  - 레짐별 성과/노출/턴오버가 분해 리포트로 나오고, “한 레짐에서만 망하는” 패턴이 줄어듦.
  - 레짐 필터 적용 후 degenerate 증가 없음.

---

## 48시간 자동 루프용 “실행 가능한 Patch/실험” 5개만 제시 (각각: ①정의 ②게이트 ③기대 관측치)

### E1) **리밸런스 로그/메타데이터 스키마 고정 + pinpoint 복구**
1) **실험 정의**
   - 리밸런스 이벤트를 **단일 포맷(jsonl 권장)** 으로 강제 기록: timestamp, universe_hash, holdings_before/after, target_weights, fills(가정 체결), turnover, est_cost, realized_cost, exposure, signal_strength 요약.
   - 런 메타데이터에 `lane_hash/run_hash/code_git_sha/data_version/feature_version` 강제 저장.
   - `aub_rebalance_pinpoint.py`가 csv/jsonl 둘 다 읽도록 입력 어댑터 추가(또는 생성물을 csv로 고정).
2) **게이트**
   - 런 종료 시 파일 존재/파싱 성공 아니면 FAIL.
   - `worst_mdd` 계산 결과 None이면 FAIL.
3) **기대 관측치**
   - “성능 불변” 케이스에서 **리밸런스 횟수 0 / 신호 0 / 비용 과다 / 특정일 갭** 중 하나가 반드시 드러남.

---

### E2) **누수 방지(정렬/시프트) + Purge/Embargo + Degenerate 폴드 차단**
1) **실험 정의**
   - 모든 피처/라벨 생성에 대해 “asof 타임스탬프”를 명시하고, 라벨은 반드시 `t+1` 이후 수익률로 고정.
   - Walk-forward CV에 **purge window + embargo** 적용(예: 5~10 trading days 범위; 고정 값으로 시작).
   - degenerate 탐지: 폴드별 (a) 거래일 비율 (b) 예측 분산 (c) 포지션 분산 (d) 유효 종목수(8~14 충족률) 기록.
2) **게이트**
   - degenerate_folds > 10%면 FAIL.
   - 폴드별 예측 분산/포지션 분산이 임계값 미만이면 FAIL.
   - 피처 타임스탬프가 라벨 이후를 참조한 흔적 1건이라도 있으면 FAIL(정렬 유닛 테스트).
3) **기대 관측치**
   - OOS mean이 하락할 수 있으나, 대신 폴드 안정성이 올라가고 “가짜 개선/정체”가 줄어듦.

---

### E3) **노출·활동성(트리거) 정규화: 8~14 종목 고정 유니버스 + 최소 거래 보장**
1) **실험 정의**
   - 매매 유니버스를 **미국 대형 Tech+Healthcare 12개 내외로 고정**(서바이버십/운영 단순화):
     - Tech 예: MSFT, AAPL, NVDA, GOOGL, AMZN, META, AVGO, CRM
     - Healthcare 예: LLY, JNJ, UNH, ABBV  
     (총 12; 필요 시 8~14 범위 내에서만 조정)
   - 포지션 규칙: 항상 8~14개를 유지(스코어 상위 N), 단 레짐/리스크오프 시 노출만 축소.
   - 신호가 너무 약해 거래가 사라지지 않도록 **최소 리밸런스 주기/최소 변경폭** 도입(예: 목표비중 변화가 작으면 skip).
2) **게이트**
   - 유효 종목수 평균이 8 미만이면 FAIL.
   - 월간 거래 횟수/턴오버가 0에 수렴하면 FAIL(“전략이 안 켜짐” 차단).
3) **기대 관측치**
   - 노출/리밸런스가 규칙화되어, OOS가 “안 움직이는” 원인이 신호냐 비용이냐로 분리됨.

---

### E4) **비용 모델 패치 + 3점 민감도(낮음/기준/높음)**
1) **실험 정의**
   - 비용 = 고정 수수료(0 가정 가능) + **슬리피지(bps) × 거래대금** + (옵션) 스프레드/임팩트 단순 모델.
   - 3점 민감도: 슬리피지 2bps / 5bps / 10bps 같은 식으로 3개 런을 자동 생성.
   - 결과 리포트에 “총비용, 비용/턴오버, 비용 차감 전후 성과”를 반드시 포함.
2) **게이트**
   - 턴오버가 특정 상한(예: 연환산 800% 등) 초과 시 FAIL(과최적화/현실성 결여).
   - 비용 차감 전후 성과 격차가 비정상적으로 크면(예: 비용이 PnL의 대부분) 경고/FAIL.
3) **기대 관측치**
   - 성능이 정체라면 “비용이 알파를 덮는지”가 즉시 드러남.
   - 좋은 전략이면 비용을 올려도 성과 순위가 어느 정도 유지됨(로버스트).

---

### E5) **ETF 관측지표 기반 레짐 게이트(매매 금지) + 모드별 노출**
1) **실험 정의**
   - ETF는 **지표로만** 사용(매매 없음):
     - QQQ(나스닥 리스크온), XLV(헬스케어 상대강도), SMH(반도체 리스크), IEF/TLT(금리 민감 대체지표 중 택1)
   - 레짐 규칙(단순부터):  
     - 예: `QQQ 50D < 200D` 이면 risk-off → 총 노출 상한을 0.4로, 아니면 0.8로.
     - 예: `XLV/QQQ` 상대강도 상승 시 Healthcare 비중 상향(유니버스 내에서만).
2) **게이트**
   - 레짐 필터로 거래가 0에 수렴하면 FAIL(E3 활동성 게이트와 결합).
   - 레짐 피처가 미래를 참조하면 FAIL(E2 누수 게이트와 결합).
3) **기대 관측치**
   - “특정 장세에서만 성능이 묶임”이 레짐별 리포트로 분해되어, 정체 원인을 시장구간으로 격리 가능.

---

## 성능이 안 움직일 때 “원인 분해” 아이디어 (트리거/적용/노출/비용/레짐) — 실행 순서 체크리스트

### A) 트리거(신호 발생) 분해
- **신호가 켜졌는지 확인하라**: 일별 상위 스코어 분포(평균/표준편차), 임계값 통과 횟수, 리밸런스 시점 수.
- **거래가 0이라면**: (1) 임계값 과도 (2) 결측/정렬 오류로 신호가 NaN (3) 레짐 필터 과도 (4) 유니버스 필터로 남는 종목 0.

### B) 적용(리밸런스/포지션 업데이트) 분해
- **타겟은 바뀌는데 체결/포지션이 안 바뀌는지 확인하라**
  - 최소 변경폭(Δw) 조건이 너무 크면 “항상 skip”될 수 있음.
  - 리밸런스 로그에서 `target_weights != holdings_after` 빈도 체크.

### C) 노출(Exposure) 분해
- **exposure time-series를 레짐/신호강도와 함께 그려라**
  - 노출이 계속 0 근처면 전략 비활성(트리거/게이트 문제).
  - 노출이 0.84 상한에 계속 붙으면 리스크 제어 부족(비용/변동성에 눌릴 가능성).

### D) 비용(턴오버·슬리피지) 분해
- **PnL을 3조각으로 나눠라**
  1) 알파(가격변동으로 인한 총수익)
  2) 비용(슬리피지/스프레드)
  3) 실행지연/갭(다음날 시가 갭 등)
- **정체 패턴**
  - 알파는 있는데 비용이 동일 규모로 상쇄 → 회전율/리밸런스 규칙을 먼저 손봐야 함(E4).

### E) 레짐 분해
- **레짐별 성과표를 강제 생성하라**
  - 예: QQQ 추세 상/하, 변동성 상/하(예: QQQ 20D realized vol), XLV 상대강도 상/하.
- **정체 패턴**
  - 특정 레짐에서만 성과가 0 근처로 붕괴 → 그 레짐에서 노출을 줄이거나(게이트) 종목군 비중만 바꾸는 방향이 효율적(E5).

## 24~48시간 실행 순서(권장) — 명령형
1) **E1을 먼저 적용해 로깅/메타데이터/핀포인트를 복구하라.** (운영 리스크 차단)
2) **E2로 누수·정렬·degenerate 폴드를 게이트로 막아라.** (가짜 정체/가짜 개선 제거)
3) **E3로 유니버스(8~14)와 활동성을 고정해 “신호가 도는지”를 관측 가능하게 만들어라.**
4) **E4로 비용 민감도를 걸어 “개선이 비용에 묻히는지”를 즉시 판정하라.**
5) **E5는 마지막에 붙여 레짐별 정체를 분리하고, 모드별 노출로 안정화하라.**

이 구성은 “케이스 폭발” 없이도(실험 5개 고정) 현재 보이는 핵심 이상징후(리밸런스 데이터 부재, degenerate_folds, MDD 미계산, 노출 비정규, 비용/레짐 미분해)를 48시간 자동 루프에서 바로 수습하도록 설계했다.
