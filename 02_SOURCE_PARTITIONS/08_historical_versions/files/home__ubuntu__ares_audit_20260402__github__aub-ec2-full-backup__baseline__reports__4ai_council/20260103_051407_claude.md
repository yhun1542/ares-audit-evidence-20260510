### P1. 데이터 파이프라인 복구 (Gate Blocker)

**(a) 왜 필요한지**
- rebalance.csv 로드 실패 → 실제 트레이드 추적 불가
- OOS mean 불일치 (3.32 vs 2.63) → 어떤 숫자가 진실인지 불명확
- 이 상태로 실험 진행 = garbage in/garbage out

**(b) 위험/부작용**
- 파이프라인 수정 중 기존 로직 regression 가능
- 시간 소모 (실험 시간 감소)

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|----------|--------|-------------|
| P1-1 | `aub_rebalance_pinpoint.py` input format 검증 - JSON vs CSV 호환성 확인 | 에러 없이 로드 | rebalance diff 테이블 출력 |
| P1-2 | champion JSON 내 OOS mean 재계산 스크립트 실행 | 3.32 vs 2.63 원인 규명 | 단일 ground truth 확정 |
| P1-3 | worst_mdd 계산 로직 추가/복구 | MDD 값 출력 | MDD < -15% 시 alert |

**(d) PASS 조건**
```
✅ rebalance 로드 성공
✅ OOS mean 단일값 확정 (오차 < 0.01)
✅ worst_mdd 숫자 출력
```

### P2. Degenerate Fold 원인 분해 (과최적화 검증)

**(a) 왜 필요한지**
- 10개 중 4개 폴드 퇴화 = 전략이 특정 구간에서만 작동
- Survivorship bias 또는 regime dependency 가능성 높음
- 실제 운영 시 40% 확률로 전략 무력화

**(b) 위험/부작용**
- 폴드 제거 시 백테스트 기간 축소
- 원인이 데이터(레짐)인지 로직인지 구분 필요

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|----------|--------|-------------|
| P2-1 | 퇴화 폴드 [1,2,3,8] 기간 매핑 → 시장 레짐 분류 (bull/bear/sideways) | 매핑 완료 | 레짐별 폴드 분포 |
| P2-2 | 퇴화 폴드에서 exposure=0 구간 비율 측정 | 데이터 추출 | exposure_zero_ratio > 80%면 신호 부재 |
| P2-3 | 비퇴화 폴드 [4,5,6,7,9,10]만으로 OOS 재계산 | OOS mean 산출 | 6-fold OOS vs 10-fold OOS 비교 |

**(d) PASS 조건**
```
✅ 퇴화 원인 1개 이상 특정 (레짐/신호부재/로직)
✅ 6-fold OOS mean > 2.0 (전략 유효성 잔존)
```

### P3. Exposure 상한 검증 (0.84 = 과집중?)

**(a) 왜 필요한지**
- exposure_max = 0.84 = 84% 단일 방향 노출
- 실제 운영 시 슬리피지/유동성 비용 급증 구간
- MDD 미계산 상태에서 고노출 = 블라인드 리스크

**(b) 위험/부작용**
- exposure cap 낮추면 수익도 감소
- cap 조정 시 과거 신호와 불일치 발생

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|----------|--------|-------------|
| P3-1 | exposure > 0.7 구간 추출 → 해당 거래 PnL 분포 | 추출 완료 | 고노출 구간 Sharpe vs 전체 Sharpe |
| P3-2 | exposure_cap = 0.6으로 제한 후 backtest | OOS mean 산출 | OOS 하락폭 < 20%면 cap 채택 |

**(d) PASS 조건**
```
✅ 고노출 구간 Sharpe < 전체 Sharpe → cap 정당화
✅ cap 적용 시 OOS mean > 2.5
```

**(a) 왜 필요한지**

- Tech/Healthcare 종목 특성상 bid-ask spread 차이 큼

**(b) 위험/부작용**
- 비용 추가 시 OOS mean 급락 가능 (환상 깨짐)
- 과도한 비용 가정 시 신호 대부분 필터링

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|----------|--------|-------------|

### P5. 신호 강도 vs 실행 빈도 분석 (회전율 검증)

**(a) 왜 필요한지**
- 잦은 리밸런싱 = 비용 누적
- 신호 강도 약한데 자주 거래하면 수익 갉아먹음
- 현재 리밸런싱 빈도 데이터 없음

**(b) 위험/부작용**
- 리밸런싱 빈도 낮추면 신호 반영 지연
- 빈도 조정 시 과거 실험과 비교 불가

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|----------|--------|-------------|
| P5-1 | 월간 거래 횟수 히스토그램 생성 | 데이터 추출 | 평균 거래/월 |
| P5-2 | 리밸런싱 주기 2배로 늘림 (신호 threshold 상향) | OOS mean 산출 | 비용 절감 vs 신호 손실 trade-off |

**(d) PASS 조건**
```
✅ 거래 빈도 -30% 시 OOS 하락 < 10%
```
