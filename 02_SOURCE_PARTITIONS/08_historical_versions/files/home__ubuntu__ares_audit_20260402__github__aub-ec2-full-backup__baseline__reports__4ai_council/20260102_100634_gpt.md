## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — 명령형 체크리스트

1) **리밸런스/트레이드 로그 파이프라인 복구(운영 리스크 최우선)**
- `aub_rebalance_pinpoint`가 현재 입력을 못 읽는 상태(`--base-log` 경로/CSV·JSON 파싱 실패) → **원인-행동-비용** 분석이 막혀있음.
- “No rebalance data found”를 **즉시 0으로 만들기**.

2) **비용(슬리피지/스프레드/수수료/차입) 모델을 스코어링에 강제 반영**
- 지금 OOS가 움직이지 않거나 비정상적으로 좋아 보이는 경우의 1순위 원인: **비용 미반영/부분 반영**.
- 특히 “항상 노출(0.47~0.84)” + 리밸런스가 존재한다면 비용 민감.

3) **누수/과최적화/서바이버십(PIT) 자동 감사 하네스 추가**
- OOS Mean 숫자도 컨텍스트에 두 값(1.88 vs 2.62)이 보임 → **평가 파이프라인/데이터 버전/피처 시점** 불일치 가능.
- Tech+Healthcare(8~14 종목)에서 종목 선정 자체가 PIT가 아니면 **서바이버십 편향** 즉시 발생.

4) **리스크/노출(현금화/스케일링) 게이트 추가 + MDD 산출 누락 제거**
- `worst_mdd: None`은 리스크 평가가 깨져있거나 계산 경로가 빠져있다는 신호.
- 항상 투자형(노출 최저 0.47) 구조면 레짐 변화에서 성능이 “안 움직이거나” “갑자기 붕괴” 두 가지로 가기 쉬움.

5) **검증 구조를 “purged/embargo + 안정성 지표”로 고정해 과최적화 억제**
- `degenerate_folds: []`는 좋지만, “No-Delta Diagnoser가 실험 9개”인데 델타가 없다는 건 **탐색 공간/평가 분해능** 문제가 잦음.
- 폴드 간 “선정 종목·가중치” 안정성(재현성) 없으면 OOS 개선은 대부분 잡음.

## 48시간 자동 루프용 “실행 가능한 Patch/실험” 5개(총 5개로 제한)
각 실험은 (1) 실험 정의 (2) 게이트 (3) 기대 관측치 형태로 작성.

### E1) Rebalance/Trade 로그 스키마 표준화 + Pinpoint 복구
1) **실험 정의**
- 백테스트/실행 산출물에 `rebalance.jsonl`(또는 parquet) **필수 생성**:
  - timestamp, symbol, side, target_weight, prev_weight, fill_price, close_price, shares, notional, est_slip_bps, fee_usd, borrow_usd, reason(신호/게이트) 등
- `aub_rebalance_pinpoint.py` 입력을 “csv/jsonl 자동 감지”로 확장하고, `--base-log`가 플레이스홀더면 즉시 실패(exit code != 0) 처리.
2) **게이트**
- 모든 러닝에서 로그 파일 존재율 100%
- `pinpoint report` 생성 성공 + “0 trades인데 0으로 표시”가 아닌 “진짜 트레이드 없음”을 구분 표시
3) **기대 관측치**
- “성능 무변화” 케이스에서 **(a) 트레이드가 없어서**, **(b) 트레이드는 있는데 동일 주문**, **(c) 비용/게이트로 상쇄** 중 무엇인지 즉시 분해 가능

---

### E2) 비용 모델(슬리피지/스프레드/수수료/차입) 강제 적용 A/B
1) **실험 정의**
- 체결가 = close ± slippage(bps, ADV/변동성 기반) 적용
- 고정 수수료 + bid-ask(심볼별 평균 스프레드) 반영
- 헤지/숏이 존재하면 borrow fee(보수적으로 연 2~5% 범위 기본값) 반영
- 스코어링/OOS 리포트에 “gross vs net” 둘 다 필수 출력
2) **게이트**
- net 성과가 gross 대비 합리적으로 감소(비용이 0으로 나오면 실패)
- turnover 증가 시 비용 증가가 동행(비정상 감지)
3) **기대 관측치**
- “좋아 보이던” 후보가 비용에서 무너지는지/아닌지 판별
- 델타가 안 나는 이유가 **비용 상쇄**인지 **신호 무력**인지 분리

---

### E3) 누수/PIT/서바이버십 자동 감사(Shift·Purge·Universe Snapshot)
1) **실험 정의**
- 피처 전체에 대해 `t` 시점 예측에 `t+1` 데이터를 쓰지 않는지:
  - 강제 `feature_lag = +1day`(의도적 누수 제거) / `-1day`(의도적 누수 주입) 테스트
- Purged K-Fold + embargo(예: 5~20 trading days)로 재평가
- 유니버스는 “오늘의 구성”이 아니라 **시점 스냅샷**(Tech+Healthcare 내 8~14개)으로 고정 저장
2) **게이트**
- `-1day(누수 주입)`에서 성과가 비정상 급등하면 경고(탐지 성공)
- `+1day(보수 lag)`에서 성과가 합리적으로 하락(너무 안 떨어지면 누수 의심)
- 유니버스 스냅샷 누락 시 즉시 실패
3) **기대 관측치**
- 델타가 안 나는 원인이 “평가/데이터가 이미 누수 또는 PIT 깨짐”인지 명확해짐
- 실험 간 OOS 수치(1.88 vs 2.62) 불일치 원인을 “데이터 버전/스코어 경로”로 귀속 가능

---

### E4) 레짐/노출 게이트(현금화/스케일링) + MDD 계산 경로 복구
1) **실험 정의**
- ETF는 매매 금지(지표로만): `QQQ`, `XLV` 등을 **레짐 관측 지표**로 사용
- 예시 게이트(둘 중 1개만 넣고 A/B):
  - (a) QQQ 50D 아래 + 변동성 급증 시 전체 익스포저 0.3~0.5로 스케일다운
  - (b) XLV/QQQ 상대강도 악화 시 Tech 비중 축소, Healthcare 비중 확대(총 8~14 종목 유지)
- `worst_mdd`가 None이 되지 않도록 리포트 경로/지표 계산을 강제(없으면 실패)
2) **게이트**
- worst_mdd가 항상 수치로 출력(Null 금지)
- 익스포저 최소/최대가 게이트에 따라 실제로 변동(항상 0.47~0.84면 실패)
3) **기대 관측치**
- OOS 평균이 크게 안 오르더라도 **하방 리스크(DD) 개선** 또는 tail 완화가 관측
- “성능 무변화”가 사실은 “리스크만 악화/개선”인 케이스를 분리

---

### E5) 과최적화 억제: 안정성(선정 종목·가중치) 점수 + 탐색 제한
1) **실험 정의**
- 폴드별 상위 종목(8~14)의 **선정 빈도/가중치 분산**을 안정성 지표로 추가
- 하이퍼파라미터 탐색은 “개선이 있는 축”만 제한(실험 9개에서 무의미한 폭발 방지)
- 결과 리포트에 “성능 vs 안정성 vs turnover vs 비용” 4축 요약을 고정 출력
2) **게이트**
- 안정성 지표가 일정 기준 이상(예: Top 종목 중 50% 이상이 폴드에서 반복 등장) 아니면 탈락
- OOS 분산(폴드 간) 감소 또는 최소 성능(oos_min) 개선 중 하나를 충족
3) **기대 관측치**
- “개선이 없는 것처럼 보이는” 상황에서 **실은 불안정/잡음**인 후보를 빠르게 제거
- 델타를 평균이 아니라 “최저치(oos_min)”로도 끌어올리는 방향으로 수렴

## TOP5 제안별 (a) 필요성 (b) 위험/부작용 (c) 최소 실험 (d) PASS 조건
> 아래 (c)는 위 5개 실험(E1~E5)을 **공유**해서 총 실험 수 폭발을 막음.

### 1) 로그/핀포인트 복구
- (a) 왜: 지금 상태는 “전략이 안 움직임”을 **트레이드가 없어서인지/로깅이 없어서인지** 구분 불가
- (b) 위험: 로깅이 성능에 영향(디스크 I/O), 스키마 변경으로 레거시 리포트 깨짐
- (c) 최소 실험: **E1 + (보조로) E2**
- (d) PASS: pinpoint 리포트가 항상 생성되고, 실험 간 “트레이드 수/회전율/비용”이 설명 가능하게 출력

### 2) 비용 반영
- (a) 왜: 비용이 빠지면 OOS 개선이 “환상”이거나, 반대로 net에서 **개선이 상쇄**되어 “No-delta”로 보임
- (b) 위험: 과도한 비용 가정으로 알파를 과소평가, 슬리피지 모델 튜닝이 또 과최적화가 될 수 있음
- (c) 최소 실험: **E2 + E1**
- (d) PASS: gross/net 동시 출력, turnover와 비용이 일관되게 동행, net 기준으로 후보 순위가 안정적으로 재정렬

### 3) 누수/PIT/서바이버십 감사
- (a) 왜: Tech+Healthcare 소수 종목(8~14)일수록 PIT/서바이버십 한 번만 깨져도 성과가 “고정적으로 과대”
- (b) 위험: 데이터 소스 제약으로 완전한 PIT 구성이 어려울 수 있음(이 경우 최소한 탐지/경고라도 필수)
- (c) 최소 실험: **E3 + (보조로) E5**
- (d) PASS: shift 테스트에서 기대한 방향으로 성과 변화가 나타나고, 유니버스 스냅샷이 강제되며, OOS 수치 불일치 원인이 로그로 귀속

### 4) 노출/레짐 게이트 + MDD 복구
- (a) 왜: `worst_mdd None`은 리스크 통제가 “없음”과 동일. 또한 익스포저가 너무 좁게 고정이면 레짐에서 대응 불가
- (b) 위험: 게이트가 신호를 과도하게 억제해 평균 수익을 깎을 수 있음(대신 tail 개선이 목표)
- (c) 최소 실험: **E4 + (보조로) E2**
- (d) PASS: MDD 수치가 항상 산출되고, 익스포저가 레짐에 따라 실제로 변하며, tail(최악 구간)에서 개선 신호가 보임

### 5) 검증 구조 고정(과최적화 억제)
- (a) 왜: “실험을 더 해도 델타가 없다”는 건 대개 **탐색/검증이 잡음에 갇힘** 또는 지표가 평균만 봐서 민감도 부족
- (b) 위험: 안정성 제약이 너무 강하면 새 알파 발견이 느려질 수 있음
- (c) 최소 실험: **E5 + (보조로) E3**
- (d) PASS: 폴드 간 분산 감소 또는 oos_min 개선, 선정 종목/가중치 안정성 개선, 재현 가능한 lane_hash 변동 관리

## 성능이 안 움직일 때 원인 분해 아이디어(트리거/적용/노출/비용/레짐) — 명령형 트리
아래는 “48시간 루프”에서 자동으로 찍히게 만들 분해 순서.

### A) 트리거(신호 발생) 문제
- **신호 발생률**(일별/주별) 출력: 0이면 피처/임계값/게이트 과도
- “상위 n종목(8~14)” 선정이 매일 동일한지 체크: 동일하면 점수 분포가 납작하거나 랭킹 로직 오류
- 피처 분포 드리프트(평균/표준편차/결측률) 로그: 결측이 늘면 신호가 죽음

### B) 적용(주문/리밸런스) 문제
- 타겟 웨이트 ≠ 실제 체결 웨이트 여부를 로그로 비교(슬리피지/현금부족/라운딩)
- 리밸런스가 “계산은 되는데 실행이 0”인지(미체결/게이트) 분리
- **E1로 해결**: reason 필드(“게이트로 컷”, “현금 부족”, “리스크 제한”) 강제

### C) 노출(익스포저/집중도) 문제
- 총 익스포저(min/max) + 상위 1종목 비중 + 섹터(Tech/Health) 비중 출력
- 익스포저가 거의 고정이면 “레짐 대응 불가” → **E4**
- 집중도가 너무 높으면 성과가 “평균은 비슷, 분산만 증가” → 안정성/리스크로 컷(**E5/E4**)

### D) 비용(거래비용/차입/스프레드) 문제
- gross가 움직이는데 net이 안 움직이면 비용 상쇄 → **E2**
- turnover 변화가 없는데 비용만 커지면 비용 모델/스프레드 매핑 오류
- 심볼별 비용 기여도(Top 5) 출력: 특정 종목이 비용을 다 먹는지 확인

### E) 레짐(시장 상태) 문제
- 관측지표(매매X): QQQ 추세, XLV 상대강도, VIX 대용(가능하면 지수/선물 데이터; 아니면 변동성 지표)로 구간 라벨링
- 레짐별 성과 테이블(상승/하락/고변동)로 “안 움직임”이 특정 레짐에서 상쇄되는지 확인
- 레짐 게이트의 효과는 평균보다 **oos_min / worst_mdd**에서 먼저 확인(**E4**)

## 48시간 운영 순서(권장 실행 순)
1) **E1 즉시 적용** → pinpoint 리포트가 “항상 생성”되게 만들기  
2) **E2 동시 적용** → gross/net 분리로 No-delta 원인 1차 확정  
3) **E3 실행** → 누수/PIT/서바이버십 플래그 제거/경고 체계화  
4) **E4 실행** → worst_mdd None 제거 + 익스포저 제어로 tail 확인  
5) **E5로 탐색 제한** → 안정성 없는 후보 자동 탈락, 실험 낭비 방지
