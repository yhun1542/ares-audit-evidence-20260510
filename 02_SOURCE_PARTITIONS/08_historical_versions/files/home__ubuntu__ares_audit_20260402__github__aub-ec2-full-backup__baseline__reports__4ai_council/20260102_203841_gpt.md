## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — 명령형 체크리스트

### 1) **운영/재현성 파이프라인 패치 (로그/메트릭/해시/리밸런스 로더)**
- **왜 필요?**
  - 현재 `worst_mdd: None`, `lane_hash/run_hash: None` → 결과 비교/롤백/원인추적 불가(운영 리스크 최우선).
  - `aub_rebalance_pinpoint.py`가 `--base-log`를 문자열로 받고 실제 파일이 없어 실패 + `rebalance.csv`가 JSON parse 에러 → 리밸런스/비용/턴오버 분석이 막혀 “성능이 안 움직이는” 원인 분해가 불가능.
- **위험/부작용**
  - 로깅/포맷 변경 시 과거 아티팩트와 호환성 깨질 수 있음(리더 어댑터로 완화).
  - 메트릭 추가로 런타임/저장용량 증가.
- **연결 실험(아래 공용 실험 풀에서 선택)**: **E1 + E2** (필요 시 E3)
- **PASS 조건**
  - 모든 런에서 `worst_mdd` 산출 + `lane_hash/run_hash` 고정 생성.
  - `rebalance_pinpoint`가 base/cand 모두에서 리밸런스 이벤트를 읽고 “거래/턴오버/비용” 요약을 출력.

---

### 2) **Degenerate folds 제거 (시간분할 CV/Walk-forward 게이트 강화)**
- **왜 필요?**
  - `degenerate_folds: [1,2,3,8]`는 OOS Mean이 좋아도 “통계적으로 무의미/불안정” 가능성이 큼(과최적화/평가누수 우선 점검).
  - fold가 비거나 표본이 극단적으로 작으면, 실험 간 delta가 안 뜨거나(노이즈) 반대로 가짜 개선이 뜸.
- **위험/부작용**
  - 더 엄격한 split/embargo 적용 시 성능이 일시적으로 하락(정상 신호).
  - 표본 감소로 분산 증가 → 장기적으로는 신뢰도 상승.
- **연결 실험**: **E2 + E3**
- **PASS 조건**
  - degenerate fold = 0
  - OOS 결과가 fold별로 일관(최소한 방향성/분산이 설명 가능) + “셔플/시프트 센티넬”에서 성능 붕괴 확인(누수 부재 증거).

---

### 3) **비용/슬리피지/턴오버를 ‘평가-학습-게이트’에 강제 반영**
- **왜 필요?**
  - 리밸런스 로그가 없어서(또는 파싱 실패) 비용/회전율을 못 보고 있음 → “실제 운용 성능”과 “리서치 성능” 괴리 위험 최상.
  - Tech+Healthcare 8~14종목 집중은 체결/슬리피지/갭 리스크가 성능을 먹기 쉬움(특히 변동성 구간).
- **위험/부작용**
  - 비용을 넣으면 백테스트 수익률 하락(정상) → 대신 현실성이 올라감.
  - 회전율 제한은 알파를 일부 포기할 수 있음.
- **연결 실험**: **E4 + E1**
- **PASS 조건**
  - (비용 포함 net)에서 OOS mean이 “의미 있게 유지”되거나, 최소한 gross→net 감소가 설명 가능한 범위로 안정화.
  - turnover 상한 적용 시 성능이 완전 붕괴하지 않고, 리스크 지표(MDD/변동성)가 개선.

---

### 4) **서바이버십/기업행동(상폐/합병/스플릿) 방어막 추가**
- **왜 필요?**
  - 미국주식에서 서바이버십/상폐수익률 미반영은 가장 흔한 “좋아 보이는 OOS” 원인(누수 다음으로 위험).
  - Tech/Healthcare는 M&A/임상 이벤트로 종목 생명주기가 짧고, 상폐/인수 프리미엄 처리에 따라 성능이 왜곡될 수 있음.
- **위험/부작용**
  - 데이터 소스/정합성 이슈로 universe가 줄고, 신호가 약해질 수 있음.
  - 과거 결과와 단절(하지만 “진짜 성능”에 가까워짐).
- **연결 실험**: **E3 + E2** (서바이버십이 CV 퇴행을 유발하는지 확인)
- **PASS 조건**
  - “상장폐지 포함/미포함” 결과 차이가 과도하지 않거나(차이가 크면 그 자체가 리스크 신호), 원인이 리밸런스/데이터 규칙으로 추적 가능.
  - 특정 연도/레짐에만 성능이 몰리는 현상(서바이버 편향 징후)이 완화.

---

### 5) **노출(Exposure)·레짐 게이트 도입: ETF는 ‘관측지표’로만 사용**
- **왜 필요?**
  - 현재 exposure max가 ~0.84인데, 언제/왜 노출이 줄거나 늘어나는지(트리거/게이트) 불명확 → “성능이 안 움직이는” 흔한 원인: 신호는 있는데 적용 단계에서 노출이 죽음.
  - QQQ(Tech), XLV(Healthcare), VIX 등은 매매하지 않고도 레짐 판단 지표로 유효(요구사항 충족).
- **위험/부작용**
  - 레짐 게이트가 과도하면 거래 기회 감소로 수익 감소.
  - 게이트 튜닝 과최적화 위험 → 고정 규칙/단순 임계치로 시작.
- **연결 실험**: **E5 + E4**
- **PASS 조건**
  - OOS min(최악 구간) 개선 또는 MDD 개선이 확인되고, “노출/거래 빈도/비용”이 함께 설명 가능.
  - 8~14종목 유지하면서도 특정 스트레스 구간에서 현금/저노출로 전환되는 패턴이 재현됨.

---

## 공용 “최소 실험 풀(총 5개)” — 48시간 자동 루프용 (1) 실험 정의 (2) 게이트 (3) 기대 관측치  
> 위 TOP5 제안은 아래 5개 실험을 조합해서만 수행(케이스 폭발 방지).

### E1) **Rebalance 로그/포맷 어댑터 + 메트릭 필수산출 패치**
1) **실험 정의**
   - `aub_rebalance_pinpoint.py` 입력을 `csv/json/jsonl` 자동 탐지로더로 통합.
   - `--base-log`에 잘못된 기본값(문자열 리터럴) 방지: “파일 없음이면 즉시 fail-fast + 사용 가능한 대체 경로 탐색”.
   - 런 종료 시 `worst_mdd`, `turnover`, `#rebalances`, `avg names(=8~14 확인)` 강제 기록.
2) **게이트**
   - 로더 유닛테스트: 샘플 csv/jsonl 각각 parse 성공.
   - CI/런타임에서 `worst_mdd is None` 발생 시 런 실패 처리.
3) **기대 관측치**
   - pinpoint 리포트에 리밸런스 이벤트 타임라인이 출력되고, 실험 간 delta가 “비용/턴오버/노출”로 분해되기 시작.

---

### E2) **시간분할 CV 교정(퍼지드+엠바고) + degenerate fold 차단**
1) **실험 정의**
   - Purged Walk-forward split + embargo(lookahead 방지)를 적용.
   - fold 생성 후 `min_samples_per_fold`, `min_trades_per_fold` 미달 시 즉시 실패.
2) **게이트**
   - `degenerate_folds == []` 필수.
   - 각 fold에서 최소 종목수/거래수/노출률 기준 충족(기준 미달이면 실험 자동 중단).
3) **기대 관측치**
   - OOS mean이 내려가더라도 fold 간 편차가 줄고, “움직이지 않던 성능”이 원인(평가 불량)이었는지 분리됨.

---

### E3) **누수/서바이버십 센티넬 테스트(셔플·시프트·유니버스 스냅샷)**
1) **실험 정의**
   - (누수 탐지) 타깃/리턴을 기간 내에서 랜덤 셔플한 더미 실험(성능 0 근처가 정상).
   - (룩어헤드 탐지) 모든 feature를 +1 bar(또는 +1 day) 시프트해 성능이 과도하게 좋아지면 누수 의심.
   - (서바이버십) 유니버스 구성 시점 스냅샷(당시 상장종목만) vs 현재종목 기반 비교.
2) **게이트**
   - 셔플 실험 OOS mean이 기준 이하(예: 0 근처, 기존 대비 대폭 하락)여야 PASS.
   - 시프트(+1)에서 성능 급등 시 FAIL(즉시 중지하고 feature/label alignment 점검).
3) **기대 관측치**
   - “성능이 안 움직이는” 원인이 진짜 한계인지, 평가/데이터 문제인지 빠르게 판별.

---

### E4) **비용/슬리피지 + turnover cap (평가에 강제 포함)**
1) **실험 정의**
   - 거래비용 모델(최소: 고정 bps + 스프레드 기반 bps)을 net 성과에 반영.
   - turnover 상한(예: 일/주 단위) 또는 거래량 기반 완만화(리밸런스 빈도 제한).
2) **게이트**
   - net 성과 리포트가 항상 생성되고, gross→net 갭/턴오버가 함께 출력.
   - turnover cap 적용 시 “거래 수 0에 수렴”하면 FAIL(전략이 사실상 꺼진 상태).
3) **기대 관측치**
   - OOS mean이 약간 낮아져도 oos_min/MDD가 개선되거나, 최소한 성과-비용의 관계가 설명 가능해짐.

---

### E5) **레짐/노출 게이트(ETF는 관측만) + 8~14종목 유지**
1) **실험 정의**
   - QQQ, XLV, VIX(또는 시장 변동성 지표)를 “매매 없이” 관측해 risk-on/off 게이트를 적용:
     - 예: 변동성 급등/추세 하락 구간에서 목표 노출 축소.
   - 종목선정은 Tech+Healthcare 중심 8~14개 유지, 포지션 캡/섹터 캡 적용.
2) **게이트**
   - 평균 보유 종목 수가 8~14 범위를 벗어나면 FAIL.
   - 노출이 장기간 0 또는 상한에 고착되면 FAIL(게이트가 죽었거나 과도).
3) **기대 관측치**
   - 스트레스 구간에서 oos_min 개선 또는 MDD 감소.
   - “노출이 안 나와서 성능이 안 움직이는” 경우 노출 곡선이 정상화.

---

## 성능이 안 움직일 때 “원인 분해” 아이디어 (트리거/적용/노출/비용/레짐) — 실행 체크리스트

### A) 트리거(신호 생성) 문제
- **점검**
  - 신호 분포가 극단(항상 0 근처/항상 상한)인지 확인.
  - 예측값/랭크의 분산이 fold/기간별로 사라지는지 확인.
- **진단 지표**
  - daily signal std, 상/하위 분위수 스프레드, IC(정보계수) 추이.
- **트리거**
  - E3(셔플/시프트)로 “진짜 알파 vs 누수” 즉시 구분.

### B) 적용(게이트/필터)에서 죽는 문제
- **점검**
  - 신호는 있는데 “리밸런스 규칙/리스크필터”가 대부분 차단하는지 확인.
  - 8~14 종목 제약, 섹터 캡, 최소 유동성 필터가 너무 빡센지 확인.
- **진단 지표**
  - 후보 종목 수 → 최종 선정 종목 수 funnel(퍼널) 로그화.
  - “차단 사유 카운트”(유동성/가격/이벤트/리스크/레짐 등).
- **트리거**
  - E1로 퍼널/리밸런스 로그를 먼저 살려야 분해 가능.

### C) 노출(Exposure) 문제
- **점검**
  - 노출이 특정 구간에서 0에 붙는지, 반대로 상한에 붙는지(현재 max 0.84) 확인.
  - 노출 변화 타이밍이 신호 타이밍과 어긋나는지(딜레이/리밸런스 주기 문제).
- **진단 지표**
  - exposure time series + rebalance timestamps + “signal→position lag”.
- **트리거**
  - E5로 레짐 기반 노출 타깃을 명시화(설명 가능한 노출 곡선 확보).

### D) 비용(슬리피지/스프레드/회전율)로 잠식되는 문제
- **점검**
  - gross는 괜찮은데 net이 안 움직이는지 확인.
  - 이벤트 드리븐(특히 헬스케어) 갭으로 인해 비용이 비선형으로 커지는지 확인.
- **진단 지표**
  - turnover, 거래횟수, 평균 보유기간, 비용의 기여도 분해(gross - cost = net).
- **트리거**
  - E4로 net을 “기본 성과”로 강제.

### E) 레짐(시장 환경) 문제
- **점검**
  - 특정 레짐(예: 금리 급변, 변동성 급등)에서만 죽는지.
  - Tech/Healthcare 내부 로테이션에서 신호가 뒤집히는지.
- **진단 지표**
  - 레짐별(저/고 변동성, 추세/역추세) 성과 매트릭스.
  - QQQ/XLV 상대강도(관측지표)와 전략 성과 상관.
- **트리거**
  - E5로 레짐 게이트를 최소 규칙으로 도입해 “레짐 민감도”를 계측 가능하게 만들기.

---

### 48시간 실행 순서(권장, 그대로 실행)
1) **E1 먼저**: 로그/메트릭/리밸런스 파싱을 살려서 “보이는 상태” 만들기  
2) **E2 + E3**: degenerate fold 제거 + 누수/서바이버십 센티넬로 평가 신뢰도 확보  
3) **E4**: 비용/턴오버를 net 기준으로 고정  
4) **E5**: 레짐/노출 게이트로 최악구간(oos_min/MDD) 개선 시도  

이 순서로 돌리면, 성능이 안 움직여도 “왜 안 움직이는지”가 로그/게이트/관측치로 남아서 다음 루프에서 자동으로 수렴합니다.
