# 48시간 내 실행 우선순위 TOP 5 제안

### 1. [CODE/CRITICAL] MDD 계산 로직 수정 및 무결성 검증
*   **이유**: `Worst MDD: None`은 리스크 측정 불가 상태를 의미. 치명적 버그이거나 데이터 누락. 3.32라는 높은 OOS Mean과 결합 시, 하락장 데이터를 건너뛰었거나(Look-ahead Bias), 수익이 난 날만 계산되었을 가능성 농후.
*   **위험/부작용**: 실제 MDD가 드러날 경우 챔피언 모델이 즉시 폐기될 수 있음(False Hope 제거).
*   **실험 정의**:
    *   `EXP_FIX_METRIC_01`: MDD 계산 함수에 예외 처리 추가 및 `NaN` 처리 로직 강제 할당(0.0 대신 -1.0 등으로 플래그).
    *   `EXP_DATA_INTEGRITY`: Degenerate Folds(1,2,3,8) 구간의 벤치마크(SPY/QQQ) 데이터 존재 여부 확인.
*   **PASS 조건**: `Worst MDD`가 `None`이 아닌 `float` 값(음수)으로 산출됨 & OOS Mean이 현실적 범위(0.5~1.5)로 수렴.

### 2. [STRATEGY] Degenerate Folds(1, 2, 3, 8) 활성화 실험
*   **이유**: 전체 Fold의 거의 절반이 `degenerate`(거래 없음/계산 실패)임에도 OOS Mean이 높다는 것은 특정 구간 과최적화의 방증. 해당 구간에서 매매가 트리거되지 않는 제약 조건(변동성 필터 등)을 완화해야 함.
*   **위험/부작용**: 강제로 거래를 일으키면 전체 OOS Mean은 하락할 가능성 높음(손실 거래 포함).
*   **실험 정의**:
    *   `EXP_LOOSEN_VOL_FILTER`: 변동성 진입 제한(Vix threshold 등)을 20% 상향 조정.
    *   `EXP_FORCE_MIN_EXP`: 포트폴리오 최소 노출 비중(Minimum Exposure)을 0.0 -> 0.3으로 강제 설정.
    *   `EXP_SECTOR_REBALANCE`: Tech/Healthcare 유니버스 내 방어주(Large Cap Pharma 등) 비중 강제 할당.
*   **PASS 조건**: `degenerate_folds` 리스트 개수가 1개 이하로 감소.

### 3. [INFRA] 로깅 파이프라인 복구 (JSON 포맷 에러 수정)
*   **이유**: `aub_rebalance_pinpoint.py`가 파일 경로 에러 및 JSON 파싱 에러로 실패 중. 진단 도구 없이 맹목적 실험(Blind Trial)은 자원 낭비.
*   **위험/부작용**: 없음(인프라 수정).
*   **실험 정의**:
    *   `EXP_LOG_PATH_FIX`: `rebalance.csv` 및 `rebalance.jsonl` 경로 생성 로직 절대경로로 변경.
    *   `EXP_JSON_FORMATTER`: 로그 저장 시 `json.dump` 포맷 검증 단계 추가(Trailing comma 제거 등).
*   **PASS 조건**: `aub_rebalance_pinpoint.py` 실행 시 에러 없이 리포트 생성.

### 4. [STRATEGY] 노출도(Exposure) 상한 확대 및 현금 비중 축소
*   **이유**: 현재 Max Exposure가 0.83 수준. 상승장에서 17% 이상의 Cash Drag 발생 중. Tech/Bio 섹터의 Beta를 충분히 활용하지 못함.
*   **위험/부작용**: MDD 증가, 변동성 확대.
*   **실험 정의**:
    *   `EXP_SCALE_UP_095`: 최대 노출 한도를 0.95로 상향.
    *   `EXP_POS_CONC`: 개별 종목 최대 비중 제한을 기존 대비 1.2배 확대(집중 투자 유도).
*   **PASS 조건**: OOS Mean 상승 유지하면서 Max Exposure > 0.9 기록.

### 5. [COST] 슬리피지/비용 스트레스 테스트 (과최적화 방지)
*   **이유**: OOS Mean 3.32는 비현실적. 거래 비용이 0이거나 매우 낮게 설정되었을 가능성. 잦은 리밸런싱 비용 반영 필요.
*   **위험/부작용**: 성과 지표 대폭 하락 예상.
*   **실험 정의**:
    *   `EXP_COST_2X`: 거래 비용(Bps) 및 슬리피지 가정을 현재의 2배로 설정.
    *   `EXP_DELAY_EXEC`: 시그널 발생 후 체결을 1 tick 혹은 1일 지연(Execution Lag) 시뮬레이션.
*   **PASS 조건**: 비용 2배 적용 후에도 OOS Mean > 1.0 유지 (강건성 입증).

# 48시간 자동 루프 정의

**Loop A: Degenerate Repair (안정성 확보)**
1.  **실험 정의**: `EXP_LOOSEN_VOL_FILTER` (변동성 필터 20% 완화) + `EXP_FIX_METRIC_01` (MDD 계산 수정)
2.  **게이트**: `degenerate_folds` < 2 AND `Worst MDD` is not None
3.  **기대 관측치**: OOS Mean은 2.0대로 하락하더라도, 모든 Fold에서 거래 발생 및 MDD 수치화.

**Loop B: Pipeline & Verification (신뢰성 확보)**
1.  **실험 정의**: `EXP_LOG_PATH_FIX` (로깅 수정) + `EXP_COST_2X` (비용 증가)
2.  **게이트**: 진단 툴 정상 작동 AND OOS Mean > 1.2 (비용 반영 후)
3.  **기대 관측치**: 로그 파일 정상 생성, 비용 반영된 현실적 수익률 곡선 확인.

# 성능 정체 시 원인 분해 (Diagnosis Checklist)

성능 지표가 움직이지 않을 경우 아래 순서로 점검:

1.  **트리거(Trigger) 실패**:
    *   *현상*: 시그널 자체가 0으로만 출력됨.
    *   *체크*: 데이터 피드(Tech/Health Ticker)의 `Close` 값이 `NaN`이거나 업데이트가 멈췄는지 확인. (2026년 시뮬레이션이므로 미래 데이터 생성 로직 확인 필수)
2.  **필터(Filter) 과다**:
    *   *현상*: 시그널은 있으나 주문이 안 나감.
    *   *체크*: `Degenerate Folds` 구간의 시장 변동성(VIX 등)이 설정된 임계값을 초과하여 'All Cash' 모드로 강제 전환되었는지 확인.
3.  **비용(Cost) 잠식**:
    *   *현상*: 총 자산은 제자리, 거래 횟수는 폭증.
    *   *체크*: 평균 수익(Avg Trade Return) < 편도 비용(Cost bps). 노이즈 매매로 수수료만 지불 중인지 확인.
4.  **레짐(Regime) 불일치**:
    *   *현상*: 특정 연도만 수익, 나머지 손실.
    *   *체크*: 현재 로직이 'Momentum' 기반이라면 횡보장에서 손실 누적. 'Mean Reversion' 로직 믹스(Ensemble) 필요.
