## 다음 24~48시간 우선순위 TOP5 (코드/아키텍처/전략)

### 1) **누수(Leakage)·시점정렬(Time alignment)·서바이버십(Survivorship) “하드 감사”를 1순위로 고정**
- (a) 왜 필요한지  
  - 현재 Champion이 tuning/lockbox 모두 높은데, 이런 형태는 **미세 누수**(특히 공시/실적/리비전/기업행동 반영시점)가 섞이면 “안 움직이는 것처럼 보이다가” 특정 구간에서 과도하게 잘 나오기도 함.  
  - Tech+Healthcare 단일종목 8~14개는 신호가 강해 보이는 만큼, **시점 오류 1개가 성능 전체를 밀어올리는** 리스크가 큼.
- (b) 위험/부작용  
  - 누수 제거 후 성능 급락 가능(정상).  
  - 데이터 지연(예: 재무/실적) 적용으로 트레이드 타이밍이 늦어져 turnover 감소/수익 감소 가능.
- (c) 최소 실험(공유 실험 E1, E2로 커버)  
  - E1: “데이터 지연/가용시점 강제” 패치  
  - E2: “거래비용+슬리피지+리밸런싱 시간” 패치(누수처럼 보이는 성능을 비용으로 상쇄하는지 검증)
- (d) PASS 조건  
  - **Leakage gate 통과(아래 E1 게이트)** + lockbox에서 **min이 음수로 급락하지 않을 것**(안정성 유지)  
  - lockbox_mean이 다소 하락해도, **worst_mdd가 구조적으로 개선**되면(예: -0.09 → -0.07 이하) “안정화 성공”으로 우선 인정

### 2) **거래비용/슬리피지/리밸런싱 비용을 “실전 수준”으로 상향 고정(비용 미반영 우선 점검)**
- (a) 왜 필요한지  
  - 8~14개 집중 포트폴리오는 **리밸런싱/교체가 곧 성과**를 좌우. 비용이 낮게 잡히면 후보는 계속 “좋아 보이는데” 실전 성능이 안 움직이는 현상이 발생.
- (b) 위험/부작용  
  - 비용 상향 시 수익률이 크게 내려갈 수 있음(정상).  
  - 지나친 비용 가정은 과도한 보수화로 알파를 죽일 수 있음.
- (c) 최소 실험(공유 실험 E2, E4로 커버)  
  - E2: 비용모델 캘리브레이션(수수료+슬리피지+스프레드+충격비용 근사)  
  - E4: 리밸런싱 주기/교체율 상한(턴오버 게이트) 실험
- (d) PASS 조건  
  - 비용 상향 후에도 lockbox_mean이 **Champion 대비 큰 훼손 없이** 유지(예: 1.79 → 1.70 이상) + turnover가 목표 범위로 통제

### 3) **과최적화(Overfitting) 방지: “모듈/하이퍼파라미터 자유도”를 게이트로 잠금**
- (a) 왜 필요한지  
  - Champion이 tuning_mean이 매우 높고 lockbox도 높지만, 다음 후보가 tuning이 급락하는 패턴은 **검색공간이 넓고 후보가 불안정**할 때 자주 발생.
- (b) 위험/부작용  
  - 탐색 폭을 줄이면 단기적으로 개선 속도 둔화.  
  - 지나친 제약은 진짜 알파도 차단.
- (c) 최소 실험(공유 실험 E3로 커버)  
  - E3: 레짐/리스크 오버레이를 “단순 1~2개 파라미터”로 제한해 추가(자유도 최소)
- (d) PASS 조건  
  - tuning_mean 상승보다 **tuning_min, lockbox_min**이 악화되지 않을 것(바닥 성능 방어)  
  - fold별 성능 분산(표준편차/범위) 감소

### 4) **운영 리스크(48시간 자동 루프 안정성): 재현성/결정론/데이터 스냅샷/감사로그 강화**
- (a) 왜 필요한지  
  - “성능이 안 움직임”의 상당수가 사실은 **실험 재현 불가, 데이터 버전 드리프트, 시드 비고정, 평가구간 혼선**에서 발생.
- (b) 위험/부작용  
  - 초기엔 로그/스냅샷 저장으로 저장공간/런타임 증가.
- (c) 최소 실험(공유 실험 E1~E4 실행 전 공통 게이트로 처리)  
  - 모든 실험 실행 전: 데이터 fingerprint + 코드 commit hash + 시드 + 피처 목록 + 비용모델 파라미터를 결과에 강제 기록
- (d) PASS 조건  
  - 동일 스펙 재실행 시 주요 지표(lockbox_mean/worst_mdd)가 허용오차 내 재현(예: ±1~2%)

### 5) **전략 노출(Exposure) 점검: Tech+Healthcare 8~14 내에서 “사실상 QQQ 베타”인지 분해**
- (a) 왜 필요한지  
  - Tech 중심 단일종목은 베타가 강해져서 “알파는 없고 레짐만 탄다” 상태일 수 있음.  
  - ETF는 매매 금지이므로 **관측지표로만(QQQ/XLV/VIX 등)** 노출 진단이 핵심.
- (b) 위험/부작용  
  - 베타 중립/변동성 타게팅을 잘못 걸면 상승장에서 수익을 깎음.
- (c) 최소 실험(공유 실험 E3로 커버)  
  - E3: 레짐 필터(예: VIX, QQQ 추세, XLV 상대강도)로 리스크만 조절
- (d) PASS 조건  
  - 베타 노출을 줄였는데도 lockbox_mean이 유지되거나, 유지가 어렵다면 **worst_mdd가 유의미하게 개선**되어야 함

## 48시간 자동 루프에 맞춘 “실행 가능한 Patch/실험” 4개 (3~5개 제한 준수)

아래 4개만 돌리고, TOP5는 이 4개로 커버되게 매핑함.

---

### E1) **Leakage/시점정렬 하드 패치**
**(1) 실험 정의 (Patch)**
- [ ] 모든 피처/라벨에 대해 `asof_timestamp` 강제(“그 시점에 실제로 알 수 있었나” 기준)
- [ ] 재무/실적/애널리스트 리비전/가이던스 계열은 **최소 1~2 거래일 지연**(또는 데이터벤더 실제 제공시각 기반 지연)
- [ ] 기업행동(분할/배당) 반영 시점이 **미래를 참조하지 않는지** 확인(특히 조정종가/조정거래량)
- [ ] delisted 포함(가능한 데이터면) 또는 최소한 **유니버스 생성 시점에 생존편향 방지 규칙** 적용

**(2) 게이트 (Fail fast)**
- [ ] “라벨 산출 시점 < 피처 최신시점” 위반 0건
- [ ] split-adjusted 사용 시, 조정 인자가 미래 시점 참조하는지 정적 점검(위반 0건)
- [ ] 유니버스가 전체 기간 동일 티커 고정이면 즉시 FAIL(서바이버십 의심)

**(3) 기대 관측치**
- tuning_mean 하락 가능(정상)  
- 대신 fold 간 성능 분산 감소, lockbox_min 방어가 개선되면 “정상화” 신호

**PASS**
- lockbox_min이 급락하지 않음 + worst_mdd 악화 없음(또는 개선)

---

### E2) **비용모델 상향/고정 + 비용 민감도 실험**
**(1) 실험 정의 (Patch)**
- [ ] 수수료(commission) + 고정 슬리피지(bps) + 스프레드/충격비용(거래대금 대비) 단순 모델을 하나로 고정  
- [ ] 리밸런싱 시점(예: 종가/익일 시가)을 명시하고 동일 적용
- [ ] (공매도 있으면) 대차비용/리콜 리스크는 최소한 보수적으로 추가, 아니면 롱온리로 고정

**(2) 게이트**
- [ ] 평균 일회전율(turnover) 상한(예: 월 200~300% 같은 내부 기준) 초과 시 FAIL  
- [ ] 비용 0으로 했을 때만 성능이 좋은 후보는 FAIL(비용 민감도 과다)

**(3) 기대 관측치**
- 절대 수익률 하락 대신, 후보 간 순위가 바뀌면 “그간 비용 미반영”이 원인으로 확정

**PASS**
- 비용 상향 후에도 lockbox_mean이 Champion 대비 과도 훼손 없이 유지 + worst_mdd 유지/개선

---

### E3) **레짐/리스크 오버레이(관측지표 ETF 사용, 매매 금지)**
**(1) 실험 정의 (Patch)**
- [ ] 관측지표: QQQ(테크), XLV(헬스케어), VIX(변동성)  
- [ ] 오버레이는 “진입/청산 신호를 바꾸지 않고” **포지션 스케일만 조절**  
  - 예: `risk_scale = clip( target_vol / realized_vol , 0.5, 1.0 )`  
  - 또는 VIX/QQQ 추세가 위험구간이면 총익스포저 50~70%로 축소
- [ ] 파라미터 1~2개만 허용(과최적화 방지)

**(2) 게이트**
- [ ] 오버레이 파라미터 그리드 과확대 금지(예: 3개 이내 조합)
- [ ] 레짐 판정에 미래 데이터 참조 금지(롤링 윈도우 엄수)

**(3) 기대 관측치**
- mean은 소폭 감소 가능  
- worst_mdd 및 tail loss가 의미 있게 개선되면 성공(후보가 Champion보다 “안정형”으로 전환)

**PASS**
- worst_mdd: Champion(-0.093) 대비 개선(예: -0.07 이상) + lockbox_mean 1.70 이상 유지(가이드)

---

### E4) **포트폴리오 구성/리밸런싱 규칙 최소 수정(8~14 Tech+Healthcare 강제)**
**(1) 실험 정의 (Patch)**
- [ ] 유니버스: 미국주식, 섹터는 Tech+Healthcare로 필터  
- [ ] 보유종목수 8~14 강제(예: 목표 10, ±2 허용)  
- [ ] 리밸런싱: 주 1회 또는 2주 1회로 고정(비용/오버트레이딩 억제)  
- [ ] 단일종목 최대비중/섹터 내 과집중 상한(예: max weight 15~20%)

**(2) 게이트**
- [ ] 보유종목수 규칙 위반 0회  
- [ ] 유동성 필터(최소 $ADV 등) 미충족 종목 진입 금지  
- [ ] 리밸런싱 외 “수시 교체” 발생 시 FAIL(운영/비용 리스크)

**(3) 기대 관측치**
- turnover 감소 → 비용 후 성능이 상대적으로 개선  
- fold 성능 안정화(특히 lockbox_min 개선)

**PASS**
- 비용 포함 기준으로 lockbox_min 개선 + 성능 분산 감소(안정성 지표 개선)

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)

아래 순서로 “증상 → 진단지표 → 처방”을 고정 루틴화.

### A) 트리거(신호 발생) 문제
- **증상**: 포지션 교체는 많은데 PnL 기여가 없음 / 히트율 낮음  
- **진단**  
  - 신호별 기여도(Feature/alpha bucket별 IC, PnL attribution)  
  - 엔트리 후 1/5/20일 조건부 기대수익(holding-period edge curve)  
- **처방**  
  - 신호를 바꾸기 전에 “체결가 기준”으로 재평가(아래 B, D 우선)

### B) 적용(실행/체결 타이밍) 문제
- **증상**: 백테스트는 좋은데 실전 가정(익일 시가/종가) 바꾸면 급락  
- **진단**  
  - 종가 체결 vs 익일 시가 체결 민감도  
  - 신호 산출 시각과 주문 시각의 간격(룩어헤드 가능성)  
- **처방**  
  - E1(시점정렬) + E2(비용/슬리피지)로 강제 표준화

### C) 노출(베타/섹터/팩터) 문제
- **증상**: QQQ가 좋을 때만 좋고, 나쁠 때 같이 무너짐  
- **진단**  
  - QQQ/XLV에 대한 회귀 베타, 업/다운 캡처 비율  
  - 팩터(모멘텀/밸류/퀄리티/사이즈) 노출의 시간변화  
- **처방**  
  - E3 오버레이로 “레짐에서 익스포저만” 조절(신호는 유지)

### D) 비용(매매비용/슬리피지/충격비용) 문제
- **증상**: gross는 괜찮은데 net이 계속 죽음 / turnover 높은 후보만 우승  
- **진단**  
  - gross vs net PnL 갭, 거래대금 대비 비용 기여  
  - 종목별 슬리피지 민감도(ADV 낮은 종목이 성과를 좌우하는지)  
- **처방**  
  - E2 비용 상향 고정 + E4 turnover/리밸런싱 규칙

### E) 레짐(시장 상태) 문제
- **증상**: 특정 구간에서만 알파 존재(예: 저변동 강세장에서만)  
- **진단**  
  - VIX 구간별 성과, QQQ 추세/역추세 구간별 성과 매트릭스  
  - drawdown 시작 트리거(변동성 급등, 섹터 로테이션 등)  
- **처방**  
  - E3로 레짐별 리스크 스케일(단순, 저자유도)

## 실행 순서(명령형 체크리스트, 24~48h)
- [ ] **E1 먼저 적용**(누수/정렬/서바이버십 게이트) → 실패 시 다른 실험 중단
- [ ] E2 적용(비용모델 상향 고정) 후 Champion/Candidate 재평가
- [ ] E4 적용(보유 8~14, 리밸런싱 규칙 고정, 유동성 필터)로 turnover 안정화
- [ ] E3 적용(관측지표 기반 레짐 리스크 스케일)로 worst_mdd 개선 시도
- [ ] 각 런 결과에 데이터 fingerprint/commit hash/비용파라미터/시드 로그 강제 저장(운영 리스크 차단)

위 4개 패치만으로 “누수/과최적화/서바이버십/비용/운영”을 우선순위대로 잠그고, Champion 대비 **(mean 유지 + MDD 개선)**이 가능한지 48시간 루프로 판정하면 됨.
