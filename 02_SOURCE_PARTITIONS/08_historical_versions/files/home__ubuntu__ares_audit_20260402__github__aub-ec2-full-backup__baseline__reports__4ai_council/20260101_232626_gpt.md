## 24~48시간 TOP5 우선순위(코드/아키텍처/전략) — 명령형 체크리스트

### 1) **누수/과최적화 “하드 차단” 회귀검증(Champion 승격 전 관문 강화)**
**(a) 왜 필요한지**
- 현재 `candidate_20260101_230410_exp_mrd_fsa.json`는 **lockbox_mean/min이 크게 개선(1.55 / 0.334)** 되었는데, 이런 급개선은 (i) 진짜 개선일 수도 있지만 (ii) **미세한 누수/평가절차 편향**으로도 자주 발생.
- “승격” 자체보다 **승격을 방어할 수 있는 감사 루틴**이 먼저임(자동루프 안정성의 핵심).

**(b) 위험/부작용**
- 게이트 강화로 단기 PASS 비율 하락(하지만 장기적으로 운영 안정성↑).
- 과도한 보수성으로 개선이 느려질 수 있음.

**(c) 최소 실험 2~3개 (단, 48시간에 1개만 우선 실행 / 나머지는 fallback)**
- **E1-1 (우선 실행): Purged/Embargo CV 적용 실험**
  - 목적: 라벨/피처 시점이 섞이는 “경계 누수” 제거.
- **E1-2 (fallback): Feature timestamp 감사 + shift 강제 단위테스트 추가**
  - 목적: “t 시점에 t+1 정보 접근”을 코드레벨에서 차단.
- **E1-3 (fallback): Lockbox 완전 동결 + 모든 튜닝/선정은 tuning만 사용하도록 강제**
  - 목적: 선택 편향(반복 관측 후 선택) 제거.

**(d) PASS 조건**
- **Gate(필수):**
  - Purged/Embargo 적용 후에도 **lockbox_mean ≥ 기존 champion(1.3295)** 유지
  - lockbox_min **≥ 0** 유지(현재 후보는 양수)
  - worst_mdd **≤ -0.09(기존 최악) 보다 개선**, 목표: **≤ -0.06**
- **추가 관측치(기대):**
  - fold별 성능 분산 감소(“한두 fold만 과대” 현상 완화)

**48시간 자동 루프 형태**
- (1) 실험 정의: “Purged/Embargo CV + 동일 후보 재평가”
- (2) 게이트: lockbox_mean/min, worst_mdd, fold 분산
- (3) 기대 관측치: 성능 소폭 하락하더라도 **min이 무너지지 않으면** 진짜 개선 신호

### 2) **비용/슬리피지/체결현실성 “선반영” (비용 미반영 리스크 최우선 제거)**
**(a) 왜 필요한지**
- lockbox_min이 양수로 나온 후보는 좋지만, **비용 모델이 약하면** 자동루프에서 “돌아가는 동안만 좋아 보이고 실거래에서 붕괴”가 가장 흔함.
- Tech/Healthcare 8~14종목은 **회전율 증가 시 비용 민감**.

**(b) 위험/부작용**
- 백테스트 성능 하락(진짜 성능이 드러나는 과정).
- 지나치게 보수적 비용 가정 시, 전략이 무의미해질 수 있음(하지만 운영 안전).

**(c) 최소 실험 2~3개 (48시간에 1개 우선 실행)**
- **E2-1 (우선 실행): “하드 비용모델 v1” 도입**
  - 왕복비용 = (고정 bps + 스프레드/2 + 슬리피지(변동성/거래대금 기반))  
  - 최소한: **고정 5~15bps 범위 sweep는 금지**, 일단 단일 보수값으로 고정(과최적화 방지).
- **E2-2 (fallback): Turnover Budget 제약**
  - 예: 일간 turnover 상한/페널티를 목적함수에 추가(“비용을 직접 최소화”).
- **E2-3 (fallback): 체결지연(1 bar delay) + 리밸런싱 캘린더 고정(예: 2일/주 1회)**
  - 신호-체결 시점 괴리로 인한 과대추정 제거.

**(d) PASS 조건**
- 비용 반영 후에도:
  - lockbox_mean **≥ 1.33**(현 champion 수준 방어)
  - worst_mdd **≤ -0.09 개선 유지**
  - 평균 turnover(정의된 메트릭) **기존 대비 증가하지 않거나**, 증가 시 성과 개선 폭이 비용을 상회

**48시간 자동 루프 형태**
- (1) 실험 정의: 비용모델 v1 적용한 동일 후보/챔피언 재평가
- (2) 게이트: 비용차감 후 lockbox_mean/min, turnover, worst_mdd
- (3) 기대 관측치: 평균 수익률 일부 감소하되 **min과 MDD가 더 현실적으로 안정**

### 3) **서바이버십/유니버스/기업행위(분할·상폐) “운영급” 정합성 점검**
**(a) 왜 필요한지**
- US 주식에서 **상폐/인수/티커변경/스플릿 처리 누락**은 대표적 서바이버십/데이터 누수 원인.
- 8~14종목 집중 포트폴리오는 **유니버스 구성 오류 1건이 성과 전체를 왜곡**.

**(b) 위험/부작용**
- 유니버스가 바뀌면 과거 성능이 크게 변동(하지만 그게 현실).
- 데이터 파이프라인 복잡도 증가.

**(c) 최소 실험 2~3개 (48시간에 1개 우선 실행)**
- **E3-1 (우선 실행): “동적 유니버스 스냅샷” 강제**
  - 매 리밸런싱 시점에: Tech+Healthcare 내 **유동성/시총 기준 상위 N에서 8~14개 선택**(룰 고정)
  - 금지: 미래 시총/미래 생존 여부로 필터링
- **E3-2 (fallback): 기업행위/상폐 처리 회계감사 리포트 생성**
  - “price adjustment, delisting return, cash-in-lieu” 처리 누락 탐지.
- **E3-3 (fallback): 데이터 소스 이중화(가격/액션) 후 불일치 경보**
  - 운영 리스크(공급자 오류) 방지.

**(d) PASS 조건**
- 동적 유니버스 적용 후:
  - lockbox_mean이 **기존 champion 대비 -10% 이내**로 방어(급락 시 서바이버십 가능성 큼)
  - 종목 수(8~14) 준수율 100%
  - “상폐/티커변경 이벤트”가 있는 기간의 PnL 급왜곡 제거(이벤트 윈도우 이상치 감소)

**48시간 자동 루프 형태**
- (1) 실험 정의: 동적 유니버스 스냅샷 + 동일 전략 재측정
- (2) 게이트: 성능 방어, 종목수 준수, 이벤트 윈도우 이상치
- (3) 기대 관측치: 평균 수익률 소폭 하락하더라도 **왜곡 리스크가 크게 감소**

### 4) **노출/리스크 관리(8~14종목 집중에 맞춘 “하드 가드레일”)**
**(a) 왜 필요한지**
- 집중 포트폴리오는 알파보다 먼저 **리스크 예산과 단일종목/섹터 편향**이 성패를 좌우.
- “성능이 안 움직임”의 원인이 사실은 **항상 비슷한 팩터/베타 노출**일 가능성이 큼.

**(b) 위험/부작용**
- 상한 제약이 알파를 깎을 수 있음.
- 과도한 제약은 전략을 “중간값”으로 수렴시킴.

**(c) 최소 실험 2~3개 (48시간에 1개 우선 실행)**
- **E4-1 (우선 실행): 단일종목/섹터/베타 가드레일**
  - 예: 단일종목 max weight, 섹터(Tech/Healthcare 내부 서브산업) 편중 상한
  - 시장베타(예: SPY/QQQ 회귀) 상한 또는 변동성 타겟팅
- **E4-2 (fallback): Drawdown 기반 디레버리징(규칙 고정)**
  - 예: 최근 n일 DD가 임계 초과 시 총노출 단계적 축소(현금 비중 허용)
- **E4-3 (fallback): 상관 구조 기반 중복제거(클러스터링으로 유사종목 동시보유 제한)**
  - 8~14개에서 “사실상 같은 종목 6개”가 되는 현상 방지.

**(d) PASS 조건**
- worst_mdd **개선**(목표: -0.06 이내)
- lockbox_mean **유지(≥ 1.33)** 또는 소폭 하락하더라도 lockbox_min, MDD가 명확히 개선
- 평균 보유종목 수 8~14 범위 유지

**48시간 자동 루프 형태**
- (1) 실험 정의: 가드레일 추가(가중치/베타/섹터/클러스터 중 1개 우선)
- (2) 게이트: MDD, min, 종목수 준수
- (3) 기대 관측치: 수익률 약간 희생 vs **꼬리위험 감소**

### 5) **레짐(시장 상태) 인식: ETF는 “관측지표”로만 사용해 게이팅/사이징**
**(a) 왜 필요한지**
- Tech/Healthcare 알파는 레짐(금리/리스크온오프, 성장주 선호)에 민감.
- ETF 매매는 제외해야 하므로, **QQQ/XLK/XLV/IHI(등)는 “신호 인풋(관측)”으로만** 써서 리밸런싱 강도를 조절.

**(b) 위험/부작용**
- 레짐 분류가 과최적화되면 성능 악화/지연 반응.
- 게이팅이 잦으면 거래비용 증가(→ 2번과 동시 관리 필요).

**(c) 최소 실험 2~3개 (48시간에 1개 우선 실행)**
- **E5-1 (우선 실행): 단순 2-레짐 게이트(룰 고정, 파라미터 최소화)**
  - 예: QQQ(또는 XLK) 200D 추세 + VIX/실현변동성 조건으로 risk-on/off
  - risk-off에서는: 총노출 축소 또는 “신호 강도 임계치 상향”으로 트레이드 빈도 감소
- **E5-2 (fallback): Healthcare/Tech 상대강도( XLV vs XLK )로 섹터 tilt만 조정**
  - 매매는 개별주식만, 단 섹터 비중을 룰로 기울임.
- **E5-3 (fallback): 이벤트-레짐(실적 시즌) 기간 리밸런싱 빈도 제한**
  - 갭/슬리피지 확대 국면 완화.

**(d) PASS 조건**
- 레짐별 성과 분해에서:
  - risk-off 구간의 MDD/손실폭 유의미 감소
  - 전체 lockbox_mean **유지(≥ 1.33)** 또는 min/MDD 개선이 명확
- “게이트 발동률”이 극단적(예: 5% 미만/95% 초과)이지 않을 것(레짐이 상수화되면 무의미)

**48시간 자동 루프 형태**
- (1) 실험 정의: ETF 관측지표 기반 2-레짐 게이트 추가
- (2) 게이트: 레짐별 MDD/손익, 발동률, 비용 영향
- (3) 기대 관측치: 전체 수익률은 비슷해도 **나쁜 구간 방어**가 개선

1. E1-1 Purged/Embargo CV 재평가  
2. E2-1 하드 비용모델 v1 적용  
3. E3-1 동적 유니버스 스냅샷 강제  
4. E4-1 리스크 가드레일(단일종목/섹터/베타)

## 성능이 안 움직일 때 “원인 분해” 아이디어 (트리거/적용/노출/비용/레짐)
질문 없이 바로 적용 가능한 분해 체크리스트만 제시.

### A) Trigger(신호 발생) 문제
- **신호 발동률(일/주 단위)**, “상위 K 후보 점수 분포”를 로그로 저장해 **신호가 죽었는지/과밀인지** 확인
- 신호가 죽었으면: (i) 피처 결측 증가 (ii) 유니버스 축소 (iii) 룰 충돌(가드레일이 전부 차단) 가능성

### B) Application(집행/리밸런싱) 문제
- 목표 포지션 대비 **실제 포지션 괴리율**, 리밸런싱 실패/스킵(데이터 없음/가격 0/상폐) 카운트
- 체결 시점/가격(다음날 시가 체결 등) 적용이 일관적인지 감사  
- “포지션 수 8~14 준수율”이 떨어지면 성능이 정체되기 쉬움(사실상 다른 전략이 됨)

### C) Exposure(노출/집중) 문제
- 일별 **gross/net exposure**, 단일종목 최대비중, 상관 클러스터 중복보유율
- 팩터 노출: (QQQ/SPY 회귀 베타, 금리 민감도 대용 지표, 성장/가치 대용)  
- 성능 정체가 “알파 부족”이 아니라 **베타/팩터가 먹히는 구간이 종료**된 것인지 분리

### D) Cost(비용) 문제
- turnover, 거래횟수, 평균 보유기간, 슬리피지 추정치의 시계열 추적
- “비용 차감 전/후” 성과 격차가 커지면: (i) 회전 과다 (ii) 이벤트/갭 취약 (iii) 유동성 필터 미흡

### E) Regime(레짐) 문제
- 레짐별(예: risk-on/off, 고변동/저변동)로 **승률/평균손익/MDD**를 분해
- 레짐이 바뀌었는데 동일한 사이징/빈도로 거래하면 정체가 발생 → **게이팅/사이징 조정으로만 해결 가능**한 경우가 많음

### 즉시 “판단”을 위한 한 줄 요약
- 지금 단계에서 가장 먼저 해야 할 건 **(1) 누수 차단 재평가 + (2) 비용 선반영**이고, 그 다음이 **(3) 서바이버십/유니버스 정합성**입니다. 이 3개가 통과하면, 그 다음에야 **(4) 가드레일**과 **(5) 레짐 게이팅(ETF 관측)**이 “성능을 올리는 실험”으로 의미가 생깁니다.
