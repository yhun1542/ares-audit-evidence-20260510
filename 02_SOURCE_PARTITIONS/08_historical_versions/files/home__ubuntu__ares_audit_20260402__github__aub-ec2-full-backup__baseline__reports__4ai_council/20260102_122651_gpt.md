## 24~48시간 TOP5 우선순위(코드/아키텍처/전략) — “명령형 체크리스트”
우선순위는 **누수 → 과최적화 → 서바이버십 → 비용 미반영 → 운영 리스크** 순으로 점검/패치가 먼저입니다. (미국주식 only, Tech+Healthcare 8~14종목 유지, ETF는 관측지표로만)

---

# 1) 데이터 누수(lookahead) / 학습-거래 시점 정합성 “하드닝”
### (a) 왜 필요한지
- Champion이 tuning/lockbox 모두 높지만, **누수가 있으면 두 구간이 같이 좋아질 수 있음**.
- 특히 “feature 계산 윈도우”와 “리밸런싱 체결 시점”이 어긋나면 **미세 누수**가 생겨 성능이 과대평가됩니다.

### (b) 위험/부작용
- 누수 제거 후 성능 급락 가능(정상).
- feature lag/shift를 잘못 적용하면 실제로 쓸 수 있는 신호까지 상실.

### (c) 최소 실험 2~3개 (48h 루프용: 1개만 즉시 실행 + 1~2개는 후순위)
**실험 1 (RUN NOW): “T+1 실행 강제 + feature availability gate”**
- (1) 실험 정의  
  - 모든 예측은 **t일 종가까지의 데이터로 생성**, 거래는 **t+1 시가(또는 VWAP) 체결**로 강제  
  - “당일 종가로 신호 만들고 당일 종가 체결” 같은 구조를 전면 금지
- (2) 게이트(자동)  
  - 백테스트 엔진에 `assert(signal_time < execution_time)` 수준의 하드 체크(실패 시 실험 중단)  
  - feature마다 `available_from` 메타(예: 재무/추정치는 공시/업데이트 지연 반영) 없으면 해당 feature drop
- (3) 기대 관측치  
  - tuning/lockbox mean이 **소폭 하락**하더라도 정상  
  - 대신 fold별 분산 감소, 극단적 샤프/히트레이트 완화가 관측되면 “누수 제거 효과” 가능성↑

**실험 2 (LATER): “퍼뮤테이션(시간셔플) 누수 테스트”**
- (1) 실험 정의: 타깃/리턴 시계열을 제한적으로 섞어도 성능이 유지되면 누수 의심
- (2) 게이트: 섞었을 때 성능이 **랜덤 수준으로 붕괴**해야 PASS
- (3) 기대 관측치: 정상이라면 lockbox_mean ~ 0 근처로 수렴

**실험 3 (LATER): “피처 윈도우 경계 검사”**
- (1) 정의: 각 feature의 rolling/window 계산이 미래값을 참조하지 않는지 unit-test 추가
- (2) 게이트: 100% 통과 아니면 배포 금지
- (3) 기대 관측치: 특정 feature 제거 시 성능 급락이면 “누수형 피처” 후보

### (d) PASS 조건
- 누수 하드 체크 통과(필수)
- lockbox_mean이 Champion 대비 **-10% 이내**이고, worst_mdd가 **악화되지 않음(≤ -0.093 유지)**  
  - 또는 lockbox_mean이 더 떨어지더라도, 이후 #4 비용 반영 포함 실험에서 “실현 성능”이 더 견고해지면 유지

# 2) 과최적화/불안정성 줄이기: “선택 안정성(8~14종목) + 파라미터 민감도 게이트”
### (a) 왜 필요한지
- 현재 Champion이 평균 성능은 높지만, 모델이 특정 구간/몇 종목에 의존하면 **lockbox는 좋아도 실전에서 불안정**합니다.
- Tech+Healthcare 8~14종목은 소수 포트이므로 **종목 선택 안정성**이 특히 중요.

### (b) 위험/부작용
- 안정성 제약을 걸면 평균 수익이 내려갈 수 있음.
- 과도한 규제(제약)가 알파를 희석.

### (c) 최소 실험 2~3개
**실험 1 (RUN NOW): “선택 안정성 페널티(턴오버+구성변동) 정규화”**
- (1) 실험 정의  
  - 목표함수에 아래를 추가(소프트 페널티):  
    - 리밸런싱 시 **구성 종목 변경 비율**, **가중치 L1 변화(턴오버)**  
  - Tech+Healthcare 내에서 **항상 8~14개 유지**(하드)
- (2) 게이트  
  - 월간/주간 턴오버 상한(예: 주간 200% 초과 시 FAIL)  
  - 종목 수 8~14 범위 벗어나면 FAIL
- (3) 기대 관측치  
  - tuning_mean 소폭↓, lockbox_mean 유지/소폭↓  
  - fold간 편차↓, lockbox min 개선(바닥 성능이 올라가는지)

**실험 2 (LATER): “파라미터 민감도 스윕(±10%) 통과 게이트”**
- (1) 정의: 핵심 하이퍼파라미터를 ±10% 흔들어도 lockbox_mean 급락 없게
- (2) 게이트: 스윕 중 최악 lockbox_mean이 기준 대비 -X% 이하로 떨어지면 FAIL
- (3) 기대: 견고한 설정은 성능 곡선이 매끈

### (d) PASS 조건
- lockbox_mean ≥ Champion의 **0.97배**(또는 절대치 1.74 이상 등 내부 기준)  
- lockbox min이 개선(예: 1.13 → **1.20 이상**) 또는 worst_mdd가 **동일/개선**

# 3) 서바이버십/코퍼레이트 액션 리스크: “유니버스/가격/상장폐지 처리 고정”
### (a) 왜 필요한지
- US 개별주 backtest에서 가장 흔한 함정:  
  - **상장폐지 종목 누락**, 과거 시점에 존재하지 않았던 종목 포함, split/dividend 조정 불일치  
- Tech/Healthcare는 M&A/상폐/티커 변경이 비교적 잦아 누락 시 성능이 과대평가됩니다.

### (b) 위험/부작용
- 데이터 정합성 강화 후 성능 하락 가능(정상).
- 유니버스가 줄어 8~14 유지가 어려워질 수 있음 → 대체 규칙 필요.

### (c) 최소 실험 2~3개
**실험 1 (RUN NOW): “PIT(Point-in-Time) 유니버스 스냅샷 + delist 리턴 반영”**
- (1) 실험 정의  
  - 매 리밸런스 시점에 **그 시점에 거래 가능했던 티커만** 후보로  
  - 상장폐지 시 delist 리턴(가능하면) 또는 보수적 청산(0 또는 큰 손실) 규칙을 명시
- (2) 게이트  
  - “미래에만 존재하는 티커” 탐지 시 FAIL  
  - split/dividend 조정 방식이 가격/체결/수익률 계산에서 일관되지 않으면 FAIL
- (3) 기대 관측치  
  - 극단적 tail 성능 감소(좋은 방향으로 “현실화”)  
  - worst_mdd가 소폭 악화될 수도 있으나, 이후 비용/실행 반영 시 갭이 줄어듦

**실험 2 (LATER): “티커 변경/합병 이벤트 회귀 테스트”**
- (1) 정의: 과거 이벤트가 있는 샘플 구간에 대해 수익률 연속성 검사
- (2) 게이트: 이벤트 전후 PnL 점프/누락 탐지되면 FAIL
- (3) 기대: 데이터 버그 제거

### (d) PASS 조건
- PIT/상폐/CA 관련 게이트 100% 통과(필수)
- lockbox_mean이 크게 손상되지 않거나(≤ -10%) **성과-현실 괴리(추정-실현 갭)**가 감소

# 4) 비용/실행/슬리피지 “보수적으로 강제” (성능이 안 움직일 때 가장 먼저 현실화되는 부분)
### (a) 왜 필요한지
- Champion/ Candidate의 차이가 MDD/턴오버 구조에서 기인 가능.  
- 비용 미반영은 대개 **lockbox에서도 과대평가**를 만들고, 실전에선 성능이 “안 움직이거나” 악화됩니다.

### (b) 위험/부작용
- 성능 하락 가능(정상).  
- 비용 모델이 과도하면 알파가 다 죽을 수 있음 → “보수적이되 일관”이 목표.

### (c) 최소 실험 2~3개
**실험 1 (RUN NOW): “하드 비용모델 + 체결지연(최소 1 bar)”**
- (1) 실험 정의  
  - 거래당: commission + spread/2 + 슬리피지(bps) + (필요 시) borrow/locate(숏이면)  
  - 체결은 신호 생성 이후 최소 1 bar 지연(= #1과 결합 가능)
- (2) 게이트  
  - 비용 포함 후에도 **포지티브 기대값** 유지(예: lockbox_mean > 0)  
  - 턴오버가 비용을 잠식하면 FAIL(예: 비용이 총 알파의 50% 초과)
- (3) 기대 관측치  
  - 고턴오버 전략 성능이 크게 깎임  
  - 안정적인 전략(= #2의 안정성 패치) 상대 우위가 나타남

**실험 2 (LATER): “유동성/임팩트 근사(ADV 기반) 페널티”**
- (1) 정의: 포지션 크기/거래량이 ADV 대비 커지면 슬리피지 증가
- (2) 게이트: ADV 대비 주문 비율 상한 초과 시 FAIL
- (3) 기대: 소형주/얇은 종목 알파가 정리됨

### (d) PASS 조건
- 비용 포함 lockbox_mean이 Champion 대비 **0.90배 이상**(또는 절대 1.6+ 등)  
- worst_mdd가 **동일 또는 개선**, 그리고 비용 차감 후에도 Sharpe-like 지표가 0 이상 유지

- 게이트가 과도하면 실험이 지나치게 FAIL될 수 있음(초기엔 정상).

### (c) 최소 실험 2~3개
**실험 1 (RUN NOW): “실험 스냅샷 고정(데이터+코드+설정 해시) + 결과 검증 게이트”**

- (2) 게이트

- (3) 기대 관측치  
  - 성능 변화가 “진짜 개선”인지 “우연/드리프트”인지 분리 가능

**실험 2 (LATER): “워치독(중단/재시도/롤백) 자동화”**
- (1) 정의: 연속 실패 N회면 이전 Champion 고정 + 알림 + 원인 로그 요약
- (2) 게이트: N회 실패 후에도 계속 실행되면 FAIL
- (3) 기대: 루프 안정화

### (d) PASS 조건
- 실험 재현성(동일 입력→동일 출력) 통과
- 자동 루프 실패율 감소(예: 24h 내 실패율 < 10%)

# 성능이 “안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래는 **원인-증상-확인 로그** 형태로 바로 분해할 수 있는 체크리스트입니다.

## A) 트리거(신호 발생) 문제
- **증상**: 포지션 변경이 거의 없거나(너무 보수), 반대로 매번 뒤집힘(너무 민감)
- **확인**  
  - 신호 분포(스코어 히스토그램) 드리프트: 평균/분산이 기간별로 붕괴하는지  
  - “상위 k개 선택”에서 점수 동률/노이즈로 순위가 흔들리는지
- **패치 방향**  
  - 점수에 온도(softmax temperature)/min-margin을 둬서 애매한 순위를 덜 매매  
  - 스코어 표준화가 fold별로 새나가지 않는지(학습구간 통계만 사용)

## B) 적용(포트폴리오 구성/리밸런싱 로직) 문제
- **증상**: 백테스트 성능은 좋은데 실전형 제약 넣으면 급락 / MDD만 커짐
- **확인**  
  - 리밸런스 빈도 vs 턴오버 vs 성과 기여 분해  
  - 상위 몇 종목이 수익 대부분을 차지(집중 리스크)
- **패치 방향**  
  - 8~14 내에서 섹터(Tech/Healthcare) 균형 하드/소프트 제약  
  - 최대 비중/최소 비중/단일 종목 손실 제한(리스크 패리티까지는 과함, 간단 제약부터)

## C) 노출(팩터/섹터/레버리지) 문제
- **증상**: QQQ 급락 때 같이 무너지고, 회복도 같이 못함 / XLV 국면에서만 먹힘
- **확인(ETF는 관측지표로만)**  
  - 노출 리그레션: 포트 수익 ~ QQQ + XLV + SPY (+ IEF 같은 금리)  
  - 베타/섹터 노출이 의도보다 커지는 구간 탐지
- **패치 방향**  
  - “레짐별 포지션 스케일” (예: 변동성↑이면 총 익스포저 축소)  
  - QQQ/XLV 상태(추세/변동)로 리밸런스 빈도 조절(매매는 주식만)

## D) 비용(슬리피지/스프레드/임팩트) 문제
- **증상**: gross는 괜찮은데 net이 0 근처로 눌림 / turnover와 상관계수 높음
- **확인**  
  - 거래비용 기여도(일별 비용 합계)와 PnL을 같이 플롯  
  - 종목별 평균 스프레드/ADV 대비 체결량 점검
- **패치 방향**  
  - 거래량 얇은 종목 자동 제외(Tech/Healthcare 내에서도 대형/중형 우선)  
  - 리밸런스 “밴드”(목표비중에서 일정 오차 내면 거래 안 함)

## E) 레짐(시장 국면) 문제
