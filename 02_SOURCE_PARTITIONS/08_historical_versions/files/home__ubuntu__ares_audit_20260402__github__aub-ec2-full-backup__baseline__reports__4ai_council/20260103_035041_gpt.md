## 24~48시간 TOP5 우선순위(코드/아키텍처/전략) — **명령형 체크리스트**
(우선순위는 **누수/과최적화/서바이버십/비용 미반영/운영 리스크** 순)

---

# 1) **백테스트 무결성(누수/과최적화) 1차 차단: Purged WF + Embargo + 타임스탬프 검증**
### (a) 왜 필요한지
- 현재 `degenerate_folds: [1,2,3,8]` 는 **검증 분할 자체가 깨졌거나(데이터 부족/중복/정렬 문제), 누수/오버랩으로 성능이 “안 움직이거나” 허상**일 확률이 큼.
- OOS가 움직이지 않는 가장 흔한 원인 = **평가 파이프라인이 실제로는 같은 구간을 반복 평가**하거나 **미래 정보가 섞여 신호가 과적합→실전에서 무력화**.

### (b) 위험/부작용
- 진짜 누수가 있었다면 성능이 **급락**할 수 있음(정상).
- Embargo로 학습 샘플이 줄어 **분산 증가** 가능.

### (c) 최소 실험(아래 공용 실험 E1~E5 중 사용)
- **E1** 실행: *Purged Walk-Forward + Embargo + “결정시점(decision_time) ≤ feature_timestamp” 하드 게이트*
- **E4** 실행(부분): *fold별 trade_count / unique_days / overlap ratio 로그 추가*

### (d) PASS 조건
- `degenerate_folds == []` (0개)
- fold별 `unique_test_days`가 최소 기준 충족(예: 60 trading days 이상) + **train/test 날짜 오버랩 0**
- feature 누수 테스트(타임스탬프/라벨 정렬)에서 **위반 0건**
- OOS mean이 떨어지더라도 **분산/일관성 지표(폴드 간 표준편차)**가 개선되면 PASS

---

# 2) **운영 리스크 제거: 아티팩트/리밸런스 로그 포맷 고정 + run_hash/lane_hash 강제**
(현재 `file:`, `lane_hash: None`, `run_hash: None`, rebalance pinpoint가 파일/JSON 로드 실패)

### (a) 왜 필요한지
- 지금 상태는 **챔피언 재현/비교/회귀분석이 불가능**(운영 리스크 최상).
- “성능이 안 움직임”의 상당 비중이 **실험이 실제로는 동일 설정으로 돌거나**, 결과 로깅이 깨져 **델타 분석이 불가능**해서 발생.

### (b) 위험/부작용
- 스키마 고정/검증 추가로 초기에는 실험이 더 자주 실패(정상).
- 로그가 늘어 IO 비용 증가.

### (c) 최소 실험
- **E2** 실행: *아티팩트 스키마 버저닝 + rebalance JSONL 강제 출력 + base-log 경로 자동 탐색/생성*
- **E4** 실행(부분): *“why-no-rebalance”/“why-no-trade” 이벤트 로그*

### (d) PASS 조건
- 매 run마다 `run_hash`, `lane_hash`, `champion_file_path`가 **non-null**
- `aub_rebalance_pinpoint`가 **항상** base/cand를 로드하고 리포트를 생성(에러 0)
- 동일 run_hash 재실행 시 핵심 지표(oos_mean, turnover, exposure)가 **허용오차 내 재현**

---

# 3) **비용 미반영/실행가능성 점검: 슬리피지/스프레드/턴오버/지연을 “게이트로”**
### (a) 왜 필요한지
- Tech/Healthcare 대형주는 스프레드가 좁아도, **빈번한 리밸런스/과도한 회전율**이면 실거래 성과가 0으로 수렴.
- “OOS가 잘 안 움직임”은 종종 **비용을 넣으면 다 비슷해지는** 현상(알파가 작음)으로 설명됨.

### (b) 위험/부작용
- 비용/지연을 넣으면 성능이 하락(정상). 대신 **실거래 가능 전략만 생존**.
- 지나친 비용 가정은 유망 전략을 조기 폐기할 수 있음(보수/공격 시나리오 2개로 고정).

### (c) 최소 실험
- **E3** 실행: *2단 비용모델(보수/공격) + 턴오버 상한 게이트 + 1-bar execution lag*
  - 예: 보수 = `slippage = max(2bp, 0.5*spread)` / 공격 = `max(1bp, 0.25*spread)`  
  - commission(고정) 포함, 체결은 next bar VWAP/close 중 하나로 고정

### (d) PASS 조건
- Net OOS mean이 Champion 대비 **동등 이상** 또는 하락폭이 비용가정 범위 내에서 합리적
- `turnover`가 상한(예: 월 200% 등) 이내
- Gross→Net 갭이 과도(예: 연 -8%p 이상)하면 **전략/리밸런스 폐기 또는 빈도 축소로 자동 회귀**

---

# 4) **노출(Exposure)·리밸런스 동작 점검: “왜 0% 노출인가/왜 84%에서 멈추나” 분해**
(현재 exposure max 0.84, min 0.0 — 신호/게이트/리스크제약 중 하나가 매번 발목)

### (a) 왜 필요한지
- 성능이 안 움직일 때 1순위 확인은 “알파가 없냐”가 아니라 **(i) 신호가 트리거되나 (ii) 포지션이 실제로 나가나 (iii) 노출이 충분히 붙나**임.
- 0 노출 구간이 길면, OOS mean은 **현금 수익률에 수렴**해서 델타가 안 보임.

### (b) 위험/부작용
- 진단 로그/메트릭 추가로 파이프라인 복잡도 증가.
- 노출을 무리하게 올리면 MDD 급증 가능(게이트로 방지).

### (c) 최소 실험
- **E4** 실행: *포지션/주문/게이트 단계별 카운터 추가*
  - 단계 예: `signal_generated → passed_filters → sized → tradable(ADV/spread) → executed`
  - “막힌 이유(reason code)”를 day-level로 집계

### (d) PASS 조건
- 48시간 내 리포트에서 다음이 명확히 숫자로 드러남:
  - 노출 0% 일수 비중, 평균 홀딩기간, 월별 거래횟수, 게이트별 탈락률 TOP3
- 노출이 의도(리스크오프)일 때는 **레짐 지표와 일치**, 의도가 아니면 원인(reason code)로 수정 포인트가 특정됨

---

# 5) **전략 패치(US Tech+Healthcare 8~14종, ETF는 지표만): 단순·검증가능 알파 + 레짐 필터 + 변동성 타게팅**
### (a) 왜 필요한지
- “No-Delta”가 뜨는 상황은 종종 **전략이 너무 복잡해 실제로는 신호가 희석**되거나, 반대로 **제약 때문에 거래가 거의 발생하지 않음**.
- 24~48시간 내에는 **단순하지만 검증 가능한** 베이스라인이 필요(복잡도 줄이고, 원인 분해 가능).

### (b) 위험/부작용
- 단순 알파는 절대 성과가 낮을 수 있음. 목적은 **델타/원인 분해 가능한 기준선 확보**.
- 레짐 필터는 잘못 잡으면 과도한 캐시화(=수익 둔화).

### (c) 최소 실험
- **E5** 실행: *12종(Tech+HC) 고정 유니버스 + 주간 리밸런스 + 모멘텀/저변동 랭킹 + 레짐 필터(ETF는 관측만)*
  - 예 유니버스(12): **AAPL, MSFT, NVDA, GOOGL, AMZN, META** + **LLY, UNH, JNJ, ABBV, MRK, TMO**
  - 알파(예): 60D 모멘텀(+), 20D 단기 리버설(-), 60D 변동성(-) 가중 합
  - 레짐 지표(관측/필터만): **SPY 추세/드로우다운**, **XLK/XLV 상대강도**
  - 포지션: 상위 N 롱(예 6), 현금 혼합, 변동성 타게팅(예 연 10%)  
  - ETF는 **매매 금지**, 지표로만 사용

### (d) PASS 조건
- degenerate fold 0 + 비용(E3) 포함 조건에서도 **OOS mean이 Champion 근처 이상**이거나,
- 최소한 **worst-case MDD / 변동성 / 노출 안정성**이 개선(“운영 가능한 형태”로 수렴)

## 공용 “실행 가능한 Patch/실험” 5개 (48시간 자동 루프에 바로 넣기)
아래 **E1~E5만** 돌리면 됨(케이스 폭발 방지). 각 실험은 (1)정의 (2)게이트 (3)기대 관측치 포함.

### **E1 — Purged Walk-Forward + Embargo + 누수 단위테스트**
1) **실험 정의**: 시간축 purge/embargo 적용한 WF CV, feature_timestamp/label 정렬 테스트 추가  
2) **게이트**: degenerate_folds=0, train/test overlap=0, timestamp 위반=0  
3) **기대 관측치**: OOS가 “현실적인 범위”로 재정렬, 폴드 간 성능 분산 감소

### **E2 — 아티팩트/로그 스키마 고정(재현성/운영성)**
1) **실험 정의**: run_hash/lane_hash 강제, champion file path 필수, rebalance JSONL 스키마 버전 고정, base-log 자동 생성  
2) **게이트**: 로더 에러 0, pinpoint 리포트 생성 100%  
3) **기대 관측치**: “No-Delta”의 상당수가 **로깅/비교 불능 문제**였는지 즉시 판별 가능

### **E3 — 비용/체결 지연 포함 Net 백테스트**
1) **실험 정의**: 보수/공격 2단 비용 + 1-bar lag + turnover cap  
2) **게이트**: turnover 상한 준수, net 성과가 극단적으로 붕괴 시(비용 민감) 전략 자동 fail  
3) **기대 관측치**: gross→net 갭/턴오버로 “알파 크기 vs 비용” 관계가 수치화

### **E4 — 트리거→적용→주문→체결→노출 단계별 원인 코드 계측**
1) **실험 정의**: 각 단계 통과율과 탈락 사유(reason code) day-level 집계  
2) **게이트**: 노출0% 비중/거래횟수/탈락사유 TOP3가 리포트에 필수 출력  
3) **기대 관측치**: “왜 성능이 안 움직이는지”가 **알파 문제가 아니라 파이프라인 문제**인지 즉시 분리

### **E5 — 단순 Tech+HC 12종 베이스라인(주간, 랭킹, 레짐 필터, 변동성 타게팅)**
1) **실험 정의**: 12종 고정, 주간 리밸, 단순 랭킹 알파 + 레짐 필터(ETF 관측) + vol targeting  
2) **게이트**: 비용(E3) 포함에서도 최소 거래 빈도 충족, MDD 상한 준수  
3) **기대 관측치**: 복잡 전략 대비 “기준선” 확보 → 이후 모든 개선이 델타로 측정 가능

## 성능이 안 움직일 때 “원인 분해” 체크리스트 (트리거/적용/노출/비용/레짐)
아래를 **리포트 1장으로 고정 출력**(E4에서 생성)하면 48시간 루프가 자동으로 원인을 좁힘.

1) **Trigger(신호 발생)**
- 지표: `signal_generated_days / total_days`, 상위/하위 신호 분포(0 근처 몰림 여부)
- 트리거가 적으면: 피처 스케일/결측/필터(거래가능성)에서 막힘 가능

2) **Apply(필터·제약 통과)**
- 지표: 필터별 탈락률(예: 변동성 상한, 레짐 오프, 데이터 결측, ADV/스프레드)
- 탈락률 TOP1이 70%+면: 그 제약이 사실상 “상시 OFF 스위치”

3) **Exposure(포지션/노출 형성)**
- 지표: 노출 0% 일수, 평균 노출, 포지션 수 분포, 평균 홀딩기간, 리밸런스 횟수
- 노출이 낮으면: sizing/리스크 타게팅/캐시 비중 로직이 과보수적이거나 레짐 필터 과민

4) **Cost(비용 민감도)**
- 지표: gross-net 갭, 거래당 비용, 턴오버 기여도, 비용 시나리오(보수/공격) 간 성과 차
- 비용 시나리오 간 성과 차가 크면: 알파가 얕고 회전율 과다 → 빈도/엔트리 조건 조정

5) **Regime(시장 국면)**
- 지표(관측 ETF): SPY 추세/드로우다운 구간별 성과, XLK/XLV 상대강도 구간별 노출/성과
- 특정 국면에서만 성과가 나오면: 레짐 조건을 **명시적으로 gating**하고 OOS를 국면별로 분해 평가
