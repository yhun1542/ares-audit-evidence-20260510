## TOP5 우선순위(24~48h) — **명령형 체크리스트**
(누수/과최적화/서바이버십/비용/운영리스크 순으로 잠금)

---

# 1) **운영 리스크 차단: 리밸런스/로그 포맷·경로를 “무조건 생성”으로 고정**
### (a) 왜 필요한지
- 현재 `aub_rebalance_pinpoint`가 **입력 파일 부재/JSON 파싱 실패**로 무력화됨 → “왜 성능이 안 움직이는지”가 **관측 불가능**.
- Champion 메타에 `lane_hash/run_hash/worst_mdd=None` 등 **추적 불능 신호**가 섞여 있음 → 실험 자동 루프에서 서바이벌(살아남은 것만 보임)·재현성 붕괴.

### (b) 위험/부작용
- 로깅 강제는 저장공간/IO 증가.
- 스키마 강제는 기존 결과 일부를 “실패”로 처리할 수 있음(단, 이게 의도된 안전장치).

### (c) 최소 실험(2~3개)  → 아래 **E1**로 통일(변형 2개 포함)
- **E1-a**: 모든 run 종료 시 `rebalance.jsonl` + `rebalance.csv` **동시 출력**(필수) + 경로를 run_hash 기반으로 고정.
- **E1-b**: 결과 JSON에 `lane_hash/run_hash/seed/git_sha/data_version/cost_version` **필수 필드** 검증(없으면 FAIL).
- **E1-c**: `aub_rebalance_pinpoint` 입력을 “폴더”만 주면 자동 탐색하도록 수정(“--base-log” 같은 플레이스홀더 금지).

### (d) PASS 조건(게이트)
- **Gate**: 10회 연속 자동 루프에서 `rebalance_pinpoint.md` 생성 성공률 100%, 파싱 오류 0건.
- **기대 관측치**: 성능 변화 이전에, 최소한 “리밸런스 횟수/턴오버/비용/노출”이 실험별로 비교 가능해짐.

---

# 2) **누수/과최적화 우선 제거: Degenerate fold 원인 제거 + Purged Walk-Forward 고정**
### (a) 왜 필요한지
- `degenerate_folds: [1,2,3,8]`은 거의 확실히  
  - (i) 라벨/피처 타임얼라인 오류(미래정보 유입),  
  - (ii) 폴드별 샘플 부족/결측 폭발,  
  - (iii) purging/embargo 부재  
  중 하나.
- 이 상태에서 OOS mean이 높아도 **신뢰 불가(과최적화/누수)**.

### (b) 위험/부작용
- 누수 제거 후 성능이 **즉시 하락**할 수 있음(정상).
- 학습 데이터가 줄어 분산 증가 가능.

### (c) 최소 실험(2~3개) → 아래 **E2**로 통일(변형 2개 포함)
- **E2-a**: Purged Walk-Forward CV + embargo(예: 5~20 trading days) 고정 적용.
- **E2-b**: 폴드 건강도 게이트 추가: 각 폴드별 유효샘플수/결측률/레이블 분산/포지션 발생률 출력.
- **E2-c**: 피처 타임스탬프 강제 규칙: “t 시점 의사결정에 t 종가/거래량 사용 금지(다음날 체결 기준)” 같은 룰을 코드로 assert.

### (d) PASS 조건(게이트)
- **Gate**: degenerate_folds = 빈 리스트.
- **Gate**: 폴드별 `position_rate`(포지션 발생 비율)가 0% 또는 100%로 쏠리지 않음(예: 5~95% 구간).
- **기대 관측치**: OOS mean이 내려가더라도 **OOS min 개선** 또는 변동성 감소(“진짜” 전략으로 수렴).

# 3) **비용/슬리피지/턴오버를 먼저 박아 넣기(비용 미반영 방지)**
### (a) 왜 필요한지
- Tech+Healthcare 단일주(8~14종) 운용은 리밸런스 빈도/턴오버에 매우 민감.
- 비용이 빠지면 고빈도 미세 신호가 OOS에서 “좋아 보이는 착시”를 만들고, 실제는 **마이너스**가 되기 쉬움.
- 현재 rebalance 로그가 없어서 비용/턴오버가 사실상 블랙박스.

### (b) 위험/부작용
- 비용을 넣는 순간 수익률 급락 가능(정상).
- 비용 파라미터가 또 다른 과최적화 축이 될 수 있음(버전 고정 필요).

### (c) 최소 실험(2~3개) → 아래 **E3**로 통일(변형 2개 포함)
- **E3-a**: 단일 비용 모델 버전 고정(예: 수수료+스프레드+슬리피지, ADV 기반 임팩트는 1단계로 단순화).
- **E3-b**: “턴오버 페널티/리밸런스 쿨다운(예: 2~5일)”을 전략 레이어에 추가(모델이 아닌 포트폴리오 레이어).
- **E3-c**: 비용 분해 로그(수수료/슬리피지/임팩트/대차비용(숏이면))를 rebalance 단위로 저장.

### (d) PASS 조건(게이트)
- **Gate**: 비용 포함 PnL 기준으로 OOS mean이 비용 미포함 대비 20~40% 이내로만 감소(너무 크면 턴오버 과다).
- **Gate**: 연환산 턴오버 상한(예: 300~600% 등 팀 기준)을 초과하면 FAIL.
- **기대 관측치**: 성능이 안 오르더라도 “턴오버/비용 때문에 눌리는지”가 즉시 판별됨.

# 4) **서바이버십/데이터 무결성: point-in-time 유니버스 + corporate action 검증**
### (a) 왜 필요한지
- 미국주식 백테스트에서 가장 흔한 “조용한 누수”가  
  - 지수 편입/상장폐지 반영(서바이버십),  
  - 액면분할/병합/배당 조정 오류,  
  - 티커 변경  
  이슈.
- Tech/Healthcare는 M&A/티커 변경/스핀오프 이벤트도 잦음.

### (b) 위험/부작용
- 유니버스가 줄어들거나 과거 데이터가 “사라져” 성능 하락 가능(정상).
- 데이터 소스 교체/정제 비용 증가.

### (c) 최소 실험(2~3개) → 아래 **E4**로 통일(변형 2개 포함)
- **E4-a**: “point-in-time 종목 리스트” 생성(매일 기준으로 그날 거래 가능했던 종목만) + 캐시/버전 고정.
- **E4-b**: corporate action sanity 체크(분할일 전후 수익률 극단치, 가격 점프 탐지) → 자동 제외/수정 로직.
- **E4-c**: delisted 종목 포함 여부/처리방식(마지막 거래일 가격, 현금 정산 등) 명시 및 로그화.

### (d) PASS 조건(게이트)
- **Gate**: 특정 날짜에 “미거래/상장폐지” 종목이 포트폴리오에 남아 있으면 즉시 FAIL.
- **Gate**: corporate action 플래그가 선행 누수(미래 이벤트로 과거 수정) 없이 재현됨(data_version 고정).
- **기대 관측치**: 성능이 크게 흔들리면 그 자체가 “서바이버십 의존”의 증거로 원인 확정 가능.

# 5) **전략/아키텍처 정렬: 8~14개 Tech+Healthcare만, ETF는 ‘관측 지표’로만 쓰는 포트폴리오 레이어 고정**
### (a) 왜 필요한지
- 현재 `exposure_min/max: 0.0 / 0.8388` → 전략이 “대부분 현금”으로도 살아남을 수 있음. 이 경우 OOS 개선이 **노출 변화**인지 **예측력**인지 분리 불가.
- “미국주식 only + Tech/Healthcare 중심 8~14종 + ETF 매매 제외”를 **코드 레벨에서 강제**해야 실험이 의미를 가짐.

### (b) 위험/부작용
- 제약을 걸면 성능이 내려갈 수 있음(정상).
- 섹터 분류(GICS 등) 데이터 의존도 증가(버전 고정 필요).

### (c) 최소 실험(2~3개) → 아래 **E5**로 통일(변형 2개 포함)
- **E5-a**: 포트폴리오 빌더에서 **종목 수 8~14 강제**, 섹터 필터(Tech+Healthcare) 강제, 나머지 0.
- **E5-b**: 노출 하한/상한 게이트(예: gross exposure 0.6~1.0 등 팀 기준)로 “현금 회피 성능” 차단.
- **E5-c**: ETF(예: XLK, XLV, SPY, QQQ, IWM, TLT, HYG)는 **피처/레짐 지표로만 허용**, 주문 라우팅 레벨에서 ETF 주문은 즉시 FAIL.

### (d) PASS 조건(게이트)
- **Gate**: 매 리밸런스 시 보유 종목 수가 8~14 범위 밖이면 FAIL.
- **Gate**: ETF 체결/주문 로그가 1건이라도 있으면 FAIL.
- **기대 관측치**: 성능이 안 움직여도 “노출/종목수/섹터 준수”가 보장되어 원인분해가 쉬워짐.

## 48시간 자동 루프용 — **실험(3~5개)만 운영**(재사용 구조)
아래 5개만 돌리고(중복 변형은 같은 실험의 플래그로 처리), 나머지 케이스 확장은 금지.

### **E1: Logging & Rebalance Artifacts Hardening**
- **정의**: run 종료 시 rebalance 로그/스키마/메타 필수화 + pinpoint 도구가 폴더 오토탐색
- **Gate**: 10회 연속 산출물 생성 100%, 파싱 0에러
- **기대 관측치**: 실험 간 turnover/비용/노출 비교표 자동 생성

### **E2: Purged WF + Embargo + Fold Health**
- **정의**: purged walk-forward CV, embargo, 폴드 건강도/타임 얼라인 assert
- **Gate**: degenerate_folds=0, 폴드별 position_rate 극단 방지
- **기대 관측치**: OOS min/분산 개선 또는 “누수였음”이 확정

### **E3: Cost+Turnover Control (versioned)**
- **정의**: 비용모델 버전화 + 쿨다운/턴오버 페널티 + 비용분해 로그
- **Gate**: 비용 포함 성능 붕괴 방지(감소폭 과다/턴오버 상한 초과 시 FAIL)
- **기대 관측치**: 성능 정체가 “비용 탓인지 신호 탓인지” 분리

### **E4: Point-in-time Universe + Corporate Action Sanity**
- **정의**: PIT 유니버스, 상폐/티커변경 처리, corporate action 이상치 감지
- **Gate**: 미거래 종목 보유/거래 시 FAIL
- **기대 관측치**: 성능 변동이 크면 서바이버십 의존 확정

### **E5: Portfolio Constraint Layer (8~14, Tech+HC only, ETF indicator only)**
- **정의**: 종목수/섹터/노출 하한 강제 + ETF 주문 금지(지표로만)
- **Gate**: 제약 위반 즉시 FAIL
- **기대 관측치**: “현금/제약 회피” 제거 후의 순수 예측력 관측

# 성능이 안 움직일 때: 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래를 **로그로 분해해서 48h 루프에서 자동 리포트**로 고정.

## A) Trigger(신호가 실제로 발생하는가?)
- **지표**: `signal_nonzero_rate`, `entry_rate`, `avg_rank_gap(상위-하위 점수차)`
- **증상→원인**
  - 신호 거의 0%: 임계값/정규화/결측처리로 신호가 죽음
  - 신호 100%: 스코어가 포화(클리핑/스케일 오류) 또는 과도한 모멘텀 편향

## B) Apply(신호→주문 변환이 망가졌는가?)
- **지표**: target weight vs filled weight 괴리, 주문 거절/리밸런스 스킵 비율
- **증상→원인**
  - 스코어는 변하는데 포지션이 고정: 제약/라운딩/최소 주문단위/쿨다운이 과함
  - 리밸런스가 거의 없음: 스케줄러/캘린더/타임존/거래일 처리 버그

## C) Exposure(노출이 성능을 가리고 있는가?)
- **지표**: gross/net exposure, cash weight, sector concentration, top-1 weight
- **증상→원인**
  - OOS mean은 괜찮은데 min이 나쁨: 특정 기간에 노출이 갑자기 커짐(리밸런스/제약 실패)
  - 성능 변화가 “노출 변화”와 동행: 예측력이 아니라 베타/현금타이밍

## D) Cost(비용이 다 먹는가?)
- **지표**: turnover, cost_per_rebalance, cost_as_%gross_pnl, slippage tail(상위 5% 비용)
- **증상→원인**
  - gross PnL은 +인데 net이 0: 회전율 과다/슬리피지 과소추정/체결가 모델 오류
  - 특정 종목만 비용 폭탄: ADV 대비 주문이 큼(포지션 상한 필요)

## E) Regime(레짐 의존인데 관측/분리가 안 됐는가?)
- **레짐 지표(ETF는 관측만)**: SPY/QQQ 수익률, XLK-XLV 상대강도, TLT/HYG(금리·크레딧), VIX(변동성)
- **분해 리포트**: 레짐 버킷별(저변동/고변동, 금리상승/하락, Tech 상대강도↑/↓) 성과/턴오버/노출 비교
- **증상→원인**
  - 전체는 정체인데 특정 레짐에서만 작동: 레짐 필터(거래 on/off) 또는 포지션 스케일링 필요
  - 레짐별로 비용이 급증: 변동성 레짐에서 리밸런스 과다

## 실행 순서(48h 내)
1. **E1 먼저 통과**(관측 불가 상태 해소) → 실패하면 나머지 실험 의미 없음  
2. **E2로 누수/degenerate fold 제거**(신뢰 가능한 OOS 확보)  
3. **E3로 비용/턴오버를 net 기준으로 고정**  
4. **E4로 서바이버십/PIT 무결성 잠금**  
5. **E5로 전략 제약(8~14, Tech+HC, ETF 주문 금지) 강제**  

이 순서대로면 “성능이 안 움직이는 이유”가 **데이터/누수/비용/노출/레짐** 중 어디에 고정되어 있는지 48시간 내에 강제로 드러나게 됩니다.
