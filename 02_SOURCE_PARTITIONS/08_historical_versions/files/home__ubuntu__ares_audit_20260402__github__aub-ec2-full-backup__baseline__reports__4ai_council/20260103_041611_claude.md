## 1. 우선순위 TOP 5 Patches

---

### PATCH-1: Degenerate Fold 부검 (ROOT CAUSE)

#### (a) 왜 필요한지
- 4/8 폴드 퇴화 = 전략이 특정 시장 레짐에서 **시그널 자체를 생성 못함**
- 이 상태로 다른 실험 → 노이즈만 측정

#### (b) 위험/부작용
- 원인이 데이터 품질이면 전략 자체 폐기 가능
- 분석 시간 소모 (4-6h)

#### (c) 최소 실험

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| 1.1 | 폴드 1,2,3,8의 기간/종목 덤프 → 공통 패턴 추출 | 완료 | "YYYY-MM 구간" 또는 "특정 섹터 집중" 발견 |
| 1.2 | 해당 폴드에서 alpha factor 분포 vs 정상 폴드 비교 | KS-test p < 0.05 | factor가 상수화(분산 → 0) 여부 |
| 1.3 | 해당 기간 VIX/SPY 레짐 태깅 → 레짐 상관 확인 | 상관 > 0.7 | "고변동 구간 = 퇴화" 등 |

#### (d) PASS 조건
```
퇴화 원인 1개 이상 명확히 식별 
AND 재현 조건 코드화 완료
```

---

### PATCH-2: MDD 게이트 구축 (리스크 인프라)

#### (a) 왜 필요한지
- `worst_mdd: None` = 백테스트 리스크 미측정
- 실전 배포 시 -30% 낙폭 가능성 모름

#### (b) 위험/부작용
- 게이트 과도 → 모든 전략 탈락
- 계산 오버헤드 미미

#### (c) 최소 실험

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| 2.1 | 현 champion에 rolling MDD (21d) 계산 추가 | 완료 | worst_mdd 수치 확보 |
| 2.2 | MDD > 15% 구간 마킹 → 폴드 퇴화와 오버랩 확인 | 오버랩 > 50% | 퇴화 = 드로다운 구간 가설 검증 |
| 2.3 | MDD 게이트 -12%, -15%, -18% 3단계 시뮬 | 통과율 기록 | 적정 임계값 탐색 |

#### (d) PASS 조건
```
worst_mdd 수치 리포트 자동화 
AND 게이트 임계값 1개 확정 (예: -15%)
```

---

### PATCH-3: Exposure 안정화 (시그널 품질)

#### (a) 왜 필요한지
- 0% ~ 84% 스윙 = 시그널 on/off가 너무 극단적
- 거래비용 폭증 + 슬리피지 리스크

#### (b) 위험/부작용
- 강제 평활화 → 알파 희석 가능
- 최적 smoothing 파라미터 찾기 필요

#### (c) 최소 실험

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| 3.1 | exposure 일간 변동폭(Δ) 히스토그램 | 완료 | Δ > 30% 빈도 확인 |
| 3.2 | 시그널에 EMA(5d) 적용 후 exposure 재측정 | exposure_max < 70% | 변동폭 축소 + oos 유지 |
| 3.3 | position sizing cap 50% 하드코딩 테스트 | oos_mean 유지 ±10% | 강제 제한 영향도 |

#### (d) PASS 조건
```
exposure_max < 70% 
AND oos_mean > 3.0 유지
AND 일간 Δ > 30% 빈도 < 5%
```

### PATCH-4: 비용 모델 반영 (현실 보정)

#### (a) 왜 필요한지
- 현재 수익률에 거래비용 미반영 추정
- 실제 슬리피지+수수료 = 연 1~3% 차감 가능

#### (b) 위험/부작용
- 비용 반영 시 oos_mean 급락 → 전략 폐기 가능
- 하지만 **지금 안 하면 실전에서 발견**

#### (c) 최소 실험

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| 4.1 | 턴오버율 계산 (연간 회전율) | 완료 | 예: 400% = 4회전 |
| 4.2 | 비용 시나리오: 5bp, 10bp, 20bp 적용 | oos_mean > 2.0 @ 10bp | 비용 민감도 파악 |
| 4.3 | 턴오버 페널티 팩터 추가 (리밸런싱 억제) | 턴오버 -30% | 비용 최적화 |

#### (d) PASS 조건
```
비용 10bp 반영 후 oos_mean > 2.5
AND 턴오버 < 연 600%
```

### PATCH-5: Survivorship Bias 점검 (데이터 무결성)

#### (a) 왜 필요한지
- 상장폐지/인수 종목 제외 시 과거 수익률 과대 추정
- Tech+Healthcare = M&A 빈번 섹터

#### (b) 위험/부작용
- 데이터 소스 교체 필요 시 파이프라인 재구축
- 점검 자체는 저비용

#### (c) 최소 실험

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| 5.1 | 유니버스 내 상폐/인수 종목 리스트 추출 | 완료 | 예: 12개 발견 |
| 5.2 | 해당 종목 제거 전/후 oos 비교 | 차이 < 0.3 | 바이어스 경미 확인 |
| 5.3 | Point-in-time 유니버스 재구축 (가능 시) | 완료 | 정확한 백테스트 |

#### (d) PASS 조건
```
survivorship 종목 리스트 문서화
AND 영향도 정량화 완료 (oos 차이 수치)
```
