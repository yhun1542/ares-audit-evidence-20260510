# 1) **리밸런스/체결 로그 파이프라인 복구 + MDD/비용 지표 “None” 제거 (운영 리스크 1순위)**
### (a) 왜 필요한지
- 현재 상태에서 **`worst_mdd: None`** → 리스크 게이트가 사실상 무력화.
- `aub_rebalance_pinpoint`가 **base-log 경로/CSV 파싱 실패** → “왜 성능이 안 움직이는지”를 **거래/회전/비용 관점에서 추적 불가**.
- “48시간 자동 루프”에서 **관측 불능은 곧 과최적화·오작동 은폐**로 연결됨.

### (b) 위험/부작용
- 로그 스키마를 바꾸면 과거 리포트/툴이 깨질 수 있음.
- 비용/슬리피지 반영을 켜면 **수익이 즉시 하락**(하지만 이게 정상).

### (c) 최소 실험(2~3개 변형을 하나의 실험 배치로)
**실험 E1: Rebalance 로그 표준화 + Pinpoint 재가동**
- 변형 A: rebalance를 `jsonl`로만 기록(단일 소스).
- 변형 B: `csv + jsonl` 동시 기록(역호환).
- 변형 C: “기록만” 켜고 리포트는 off(오버헤드 확인).

**실행 패치(필수)**
- `--base-log`에 literal 문자열이 들어가는 문제 방지: CLI 인자 없으면 **기본 경로 자동 탐색**(최근 run 폴더).
- `rebalance.csv` 파서가 깨지는 경우 대비: **JSONL 우선**, CSV는 optional.
- 백테스트 산출물에 **항상 `mdd`, `turnover`, `cost`, `slippage`, `borrow`** 필드를 non-null로 저장.

### (d) PASS 조건 (게이트)
- Gate-1(운영): 48시간 루프에서 **rebalance 로그 생성률 100%**, pinpoint 리포트 생성 성공률 100%.
- Gate-2(리스크): `worst_mdd`가 **항상 수치로 산출**되고, NaN/None 0건.
- 기대 관측치: “성능 정체” 구간에서 **turnover/cost 스파이크 여부가 즉시 식별**됨(원인 분해 가능).

# 3) **시간정렬/특징 누수(lookahead) 자동 탐지 게이트 추가 (누수 1순위)**
### (a) 왜 필요한지
- Tech/Healthcare 단일주(8~14개)에서 신호가 강하게 나오면 **누수일 확률이 급증**.
- 특히(빈번한 누수 유형)
  - 종가 기반 특징을 같은 날 체결에 사용
  - 기업 이벤트(실적 발표/가이던스) 타임스탬프가 거래가능 시점보다 빠름
  - 리밸런스 시점과 피처 스냅샷 시점 불일치

### (b) 위험/부작용
- 누수 게이트를 넣으면 단기 성능이 하락할 수 있음(정상).
- 일부 피처가 “사실상 사용 불가” 판정될 수 있음.

### (c) 최소 실험(2~3개 변형을 하나의 실험 배치로)
**실험 E3: Leak Sentinel (자동 위반 탐지 + 강제 시프트)**
- 변형 A: 모든 price-derived feature를 **t-1로 강제 shift** 후 재평가.
- 변형 B: 이벤트/펀더멘털 피처를 **공시 후 +1 영업일**로 강제 지연.
- 변형 C: “의심 피처군”을 그룹으로 drop하여 성능 민감도 측정.

### (d) PASS 조건 (게이트)
- Gate-1(누수 의심): 변형 A/B에서 성능이 **비정상적으로 급락**하면(예: oos_mean -30% 이상) → 기존 파이프 **누수 가능성 HIGH**로 fail.
- Gate-2(정상 기대): 누수 제거 후에도 oos_min이 **유의미하게 유지**되고(급락 없음), fold 간 편차 감소.
- 기대 관측치: 정체 원인이 “누수 제거로 성능이 내려간 탓”인지, 아니면 **다른 병목(비용/노출/레짐)**인지 분리됨.

  이 상태에서 리밸런스가 잦으면 **비용이 알파를 상쇄**하기 쉬움.

### (b) 위험/부작용
- 비용 반영 즉시 성능 하락 가능.
- 턴오버 캡은 “기회를 놓쳐” 총수익이 줄 수 있음.

### (c) 최소 실험(2~3개 변형을 하나의 실험 배치로)
**실험 E4: Cost-On + Turnover Governor**
- 변형 A: 고정 슬리피지(bps) + 커미션 적용, turnover 캡 없음(베이스라인).

## 48시간 자동 루프 형태 요약 (실험 정의 → 게이트 → 기대 관측치)
- **E1(로그/리밸런스)**: 기록/파싱 표준화 → 리포트 100% 생성, MDD non-null → 원인 추적 가능해짐  
- **E2(지표 버전락)**: metric 정의 고정 → 동일 run 재평가 오차 <0.5% → “정체” 판단이 유효해짐  
- **E3(누수 센티넬)**: 강제 시프트/지연 → 성능 급락 시 누수 확정 fail → 누수 여부 빠른 결론  
- **E4(비용/턴오버 게이트)**: cost-on + governor → cost 포함 기준 승격, turnover 초과 fail → 비용이 원인인지 확정  
- **E5(유니버스 고정/ETF 관측)**: 8~14 하드 제약 → 위반 0건 → 서바이버십/운영 흔들림 제거

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래 순서대로 **자동 리포트에 숫자로 찍히게** 만들어야 “정체”를 분해 가능.

## A) 트리거(신호 발생) 문제
- 신호 발생 빈도(일별/주별)와 “무신호 기간” 길이 분포를 기록
- 상위 피처의 값 분포가 최근 1~3개월에 **붕괴/클리핑**되는지 감시  
  - 관측치: z-score 분산 급감, 동일 값 반복 증가

## B) 적용(실행/리밸런스) 문제
- 신호는 나오는데 포지션이 안 바뀌면:  
  - 최소 주문 단위/리밸런스 임계치/리스크 캡이 과도할 가능성
- 관측치: “target weight vs filled weight” 괴리, 리밸런스 스킵 사유 카운트

## C) 노출(Exposure) 문제
- 현재 노출 범위 0.47~0.84:  
  - 레짐이 나쁠 때도 고정 노출이면 성과가 둔해질 수 있음
- 관측치: 레짐(예: QQQ 추세/변동성)별 노출 평균, 손익 기여 분해

## D) 비용(회전/슬리피지/차입) 문제
- 관측치(필수):  
  - gross pnl vs net pnl, cost ratio(net/gross), turnover, 슬리피지 기여
- 정체 트리거: gross는 늘는데 net이 안 늘면 비용/회전이 병목

## E) 레짐(시장 상태) 문제 — ETF는 “관측 지표”
- ETF(예: QQQ, XLK, XLV)로 레짐을 구간화(상승/횡보/하락, 저/고변동)하고,
  - 구간별 hit-rate, 평균 보유기간, 노출, 비용을 테이블화
- 관측치: 특정 레짐에서만 성능이 살아있으면 **레짐 필터/노출 스케일링**이 다음 단계 실험이 됨(단, 이번 48시간은 위 5개 게이트 우선)

## 지금 당장 실행 순서 (우선순위 그대로)
1. **E1**부터: 로그/리밸런스/MDD non-null 보장 → 원인 추적 가능 상태 만들기  
2. **E2**: OOS 지표 정의/스케일 고정 → “안 움직임”이 측정오류인지 제거

5. **E5**: 유니버스 하드 제약/ETF 관측 전용 → 운영/서바이버십 흔들림 제거
