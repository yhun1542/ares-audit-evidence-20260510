## 1. 우선순위 TOP 5 실행 패치

### PATCH-1: Degenerate Fold 원인 분리 (누수/과최적화 점검)

**(a) 필요성**
- 4개 폴드가 degenerate = 해당 기간 **시그널 무효 또는 데이터 누수**
- 누수 시 OOS 3.32는 허상, 실전 배포 시 손실 확정

**(b) 위험/부작용**
- 누수 발견 시 Champion 전체 폐기 가능성
- 진단 시간 4-8h 소요

**(c) 실험 체크리스트**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P1-A | 각 degenerate fold의 날짜 범위 추출 → 해당 기간 feature importance 확인 | fold별 top3 feature 리스트 | 미래 데이터 참조 feature 발견 여부 |
| P1-B | Degenerate 판정 기준 로깅: `return < -2%` or `sharpe < 0` 중 어느 조건? | 판정 로직 명시 | 4개 폴드 공통 패턴 (레짐? 데이터?) |
| P1-C | Fold 1,2,3,8 기간의 시장 레짐 태깅 (bear/sideways/bull) | 레짐 라벨 | 특정 레짐 집중 시 전략 한계 확인 |

**(d) PASS 조건**
```
✅ 누수 feature 없음 AND degenerate 원인이 "레짐 불일치"로 명확히 분류됨
❌ 누수 발견 시 → 즉시 Champion 교체 프로세스 가동
```

### PATCH-2: MDD 계산 파이프라인 복구 (리스크 블라인드 해소)

**(a) 필요성**
- `worst_mdd: None` = 드로다운 리스크 완전 미측정
- 실전 배포 불가 상태

**(b) 위험/부작용**
- MDD 계산 시 equity curve 필요 → 없으면 역산 필요 (정합성 리스크)

**(c) 실험 체크리스트**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P2-A | `backtest_engine.py`에서 MDD 계산 로직 추적 → None 반환 지점 특정 | line number + 조건 | cummax 누락 or divide-by-zero |
| P2-B | Champion JSON에서 daily_equity 키 존재 확인 | key 존재 여부 | 없으면 backtest 출력 포맷 수정 필요 |

**(d) PASS 조건**
```
✅ worst_mdd 값이 수치로 출력 (-15% ~ -40% 범위 예상)
❌ 여전히 None → backtest output schema 전면 점검
```

### PATCH-3: Rebalance/비용 파이프라인 복구

**(a) 필요성**
- `rebalance.csv` 파일 없음 = **거래 비용 미반영**
- 실제 수익률 = OOS Mean - (turnover × cost) → 현재 cost=0 가정

**(b) 위험/부작용**
- 비용 반영 시 OOS Mean 20-50% 하락 가능
- 턴오버 높으면 전략 자체 무효화

**(c) 실험 체크리스트**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P3-A | Backtest 실행 시 `--export-rebalance` 플래그 존재 여부 확인 | 플래그 문서화 | 있으면 활성화, 없으면 구현 |
| P3-B | 수동으로 턴오버 추정: `avg(abs(weight_diff))` per rebalance | turnover % | >100%/월 시 비용 폭탄 경고 |
| P3-C | 슬리피지+수수료 시나리오: 10bp, 20bp, 30bp 적용 후 OOS 재계산 | 3개 시나리오 OOS | break-even cost 역산 |

**(d) PASS 조건**
```
✅ 20bp 비용 반영 후 OOS Mean > 1.5
❌ 비용 반영 시 OOS < 0.5 → 턴오버 감소 패치 필요
```

### PATCH-4: OOS Mean 불일치 해소 (3.32 vs 2.63)

**(a) 필요성**
- Handoff와 Diagnoser 간 OOS Mean 0.7 차이 = **동일 Champion인지 의심**
- One Truth 원칙 위반

**(b) 위험/부작용**
- 파이프라인 신뢰도 전체 의심 → 수동 검증 비용 증가

**(c) 실험 체크리스트**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P4-A | Handoff JSON과 Diagnoser 입력 JSON의 MD5 해시 비교 | 해시 일치 여부 | 불일치 시 버전 관리 버그 |
| P4-B | OOS Mean 계산 로직 비교: `mean(fold_returns)` vs `weighted_mean` | 계산식 명시 | 가중치 차이 여부 |

**(d) PASS 조건**
```
✅ 단일 OOS Mean 값으로 통일 (오차 < 0.05)
❌ 불일치 지속 → Champion 선정 기준 재정의
```

## 2. 성능 미변동 시 원인 분해 트리

```
OOS 변화 없음
│
├─ [1] 트리거 미작동
│   └─ 시그널이 생성되지 않음 (threshold 과잉)
│   └─ 점검: signal_count per fold
│
├─ [2] 적용 실패
│   └─ 시그널 → 포지션 전환 로직 버그
│   └─ 점검: signal vs actual_position 일치율
│
├─ [3] 노출 부족
│   └─ 포지션은 잡았으나 sizing 너무 작음
│   └─ 점검: avg_position_size
│
├─ [4] 비용 상쇄
│   └─ 수익 ≈ 거래비용 → 순수익 0
│   └─ 점검: gross_return vs net_return
│
└─ [5] 레짐 불일치
    └─ 실험 기간이 전략 무효 레짐
    └─ 점검: 해당 기간 VIX, SPY trend
```
