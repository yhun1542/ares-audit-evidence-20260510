1.  **Degenerate Folds [1, 2, 3, 8] 긴급 디버깅**: 전체 Fold의 40%가 학습 실패 혹은 상수(Constant) 출력 중. 모델의 신뢰도 0에 수렴. 즉시 해결 필요.
2.  **Look-ahead Bias(미래 참조) 강제 차단 테스트**: OOS Mean 3.32는 현실적으로 불가능한 수치(Leakage 강력 의심). Feature Lag 강제 적용 필요.
3.  **거래 비용/슬리피지 하드코딩 검증**: Rebalance 로그 로딩 실패로 인해, 실제 거래 횟수와 비용이 0으로 계산되었을 가능성 농후.
4.  **Tech/Healthcare Universe 압축**: 8~14개 종목으로 유니버스 강제 축소 및 Sector Bias(특정 섹터 과몰입) 확인.
5.  **Logging Pipeline 복구**: `Errno 2` 및 JSON 파싱 에러 수정. 관측 불가능한 시스템은 개선 불가능.

### [제안 1] Data Leakage Stress Test (Lag Enforcement)

**a) 필요성**: `oos_mean: 3.32`는 과최적화 혹은 미래 데이터 참조 없이는 불가능함. 현재 성과는 허상일 확률 99%.
**b) 위험/부작용**: 성과가 0.5 이하로 급락할 수 있음(그러나 이것이 진실임).
**c) 실험 계획 (48h Loop)**

*   **실험 1 (Global Lag)**
    *   **(1) 정의**: 모든 Input Feature 생성 시점에서 `shift(1)` 강제 적용 (Open/Close 시점 불일치 제거).
    *   **(2) 게이트**: 코드 실행 에러 없을 것.
    *   **(3) 기대 관측치**: OOS Mean이 0.8~1.2 수준으로 하락하되, 양수(+) 유지. 만약 0 근처로 가면 기존 모델 폐기.

*   **실험 2 (Target Definition Check)**
    *   **(1) 정의**: Target(Y) 생성 시 `shift(-1)`이 정확히 적용되었는지, 당일 Close로 당일 수익을 예측하는지 검증.
    *   **(2) 게이트**: 논리적 오류 발견 시 즉시 수정.
    *   **(3) 기대 관측치**: 기존 코드와 차이점 발견.

**d) PASS 조건**: Lag 적용 후에도 OOS Sharpe > 1.0 유지.

### [제안 2] Fix Degenerate Folds (Fold 1, 2, 3, 8)

**a) 필요성**: 특정 시점(Fold)에서 모델이 전혀 작동하지 않음. 이는 해당 기간의 데이터 결측(Null)이나, Feature의 분산(Variance)이 0인 경우 발생.
**b) 위험/부작용**: 문제 있는 기간을 강제로 학습시키려다 전체 모델의 일반화 성능 저하 가능성.
**c) 실험 계획 (48h Loop)**

*   **실험 1 (Feature Pruning)**
    *   **(1) 정의**: 상관계수(Correlation) > 0.95 Feature 제거 및 결측치 10% 이상 Feature 삭제. PCA 적용 고려.
    *   **(2) 게이트**: 학습 시간 감소 확인.
    *   **(3) 기대 관측치**: Degenerate Folds 개수가 0~1개로 감소.

*   **실험 2 (Fill Method Change)**
    *   **(1) 정의**: 결측치 처리 방식을 `ffill`에서 `median` 또는 `0`으로 변경하여 모델이 NaN에 죽는 현상 방지.
    *   **(2) 게이트**: 전처리 파이프라인 통과.
    *   **(3) 기대 관측치**: 모든 Fold에서 유의미한 예측값 분산(Variance > 0.001) 발생.

**d) PASS 조건**: Degenerate Folds = 0.

### [제안 3] Cost & Turnover Calibration

**a) 필요성**: Rebalance 로그가 없는 상태에서 높은 성과는 잦은 매매(Churning)를 비용 0으로 계산했을 가능성이 큼.
**b) 위험/부작용**: 실제 비용 반영 시 전략이 손실로 전환될 수 있음.
**c) 실험 계획 (48h Loop)**

*   **실험 1 (Hard Cost Penalty)**
    *   **(1) 정의**: Backtest 엔진에 편도 15bps (0.15%) 수수료 및 슬리피지 강제 주입.
    *   **(2) 게이트**: 시뮬레이션 완료.
    *   **(3) 기대 관측치**: OOS Mean 하락폭 확인. 3.32 -> 1.5 수준이면 양호, 마이너스면 전략 수정 필수.

*   **실험 2 (Log Fix)**
    *   **(1) 정의**: `aub_rebalance_pinpoint.py` 경로 및 JSON 포맷 수정하여 실제 일별 회전율(Turnover) 측정.
    *   **(2) 게이트**: `Error loading` 메시지 소멸.
    *   **(3) 기대 관측치**: 일별 회전율 10~20% 이내 확인.

**d) PASS 조건**: 비용 반영 후 Sharpe > 1.2, 일별 회전율 < 20%.

**b) 위험/부작용**: 분산 효과 감소로 인한 MDD 증가.
**c) 실험 계획 (48h Loop)**

**d) PASS 조건**: 포트폴리오 구성 종목 수 8 <= N <= 14, Tech/Bio 비중 100%.

    *   *Check*: 현금 비중이 지속적으로 90% 이상인지 확인.
