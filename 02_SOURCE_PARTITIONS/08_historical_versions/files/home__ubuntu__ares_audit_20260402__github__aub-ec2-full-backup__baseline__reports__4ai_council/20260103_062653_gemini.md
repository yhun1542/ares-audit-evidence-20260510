# 1. 우선순위 TOP 5 제안 (48시간 루프)

현재 `degenerate_folds: [1, 2, 3, 8]` 상태는 치명적입니다. 전체 Fold의 절반 가까이가 거래를 못했거나(Zero Trades), 로직이 붕괴(Error/NaN)했다는 뜻입니다. OOS Mean 3.32는 생존한 Fold만의 편향된 결과일 가능성이 높으므로 **"안정성 확보"**가 최우선입니다.

### 1) [Stability] Degenerate Fold 강제 해제 실험
*   **이유:** Fold 1,2,3,8의 실패 원인이 '엄격한 유니버스 필터'로 인한 종목 선별 실패인지, '데이터 누락'인지 확인 필요. OOS 수치의 신뢰도 0 상태임.
*   **위험/부작용:** 필터 완화 시 쓰레기 종목(Penny stock 등) 혼입 가능성, MDD 급증 가능성.
*   **실험 정의:**
    *   `EXP-001-Relax-Liq`: 유동성(Volume) 필터 하위 20% -> 50%로 완화.
    *   `EXP-002-Force-Alloc`: 신호 강도가 낮아도 Top N 종목에 강제 최소 비중(min weight 0.02) 할당.
    *   `EXP-003-Fallback-Cash`: Fold 내 가용 종목 0개일 때, 현금 100%가 아닌 ETF(QQQ/XLV) 대용치 매핑 테스트(로직 동작 확인용).
*   **PASS 조건:** `degenerate_folds` 개수 = 0.
*   **기대 관측치:** OOS Mean은 3.32에서 1.5~2.0 수준으로 하락하더라도, 전 구간 거래 로그 생성.

### 2) [Ops/Vis] Rebalance Log 파서 긴급 패치
*   **이유:** `Error loading ... Expecting value` 로그 확인됨. 매매 회전율(Turnover)과 비용(Cost)을 볼 수 없어, 현재 수익률이 슬리피지로 삭제될지 알 수 없음.
*   **위험/부작용:** 백테스트 엔진 코드 수정에 따른 일시적 파이프라인 중단.
*   **실험 정의:**
    *   `PATCH-001-Log-Format`: `rebalance.csv` 생성 로직을 JSONL(`rebalance.jsonl`)로 통일하거나, 파서가 두 형식을 모두 지원하도록 수정.
    *   `EXP-004-Cost-Audit`: 수정된 파서로 최근 3개월치 로그 분석하여 `Avg. Daily Turnover` 계산.
*   **PASS 조건:** `aub_rebalance_pinpoint.py` 정상 실행 및 리포트 생성.
*   **기대 관측치:** 일평균 회전율 10% 미만 확인 (고빈도 매매 여부 식별).

### 3) [Cost/Overfit] 수수료 가중 스트레스 테스트
*   **이유:** Tech/Healthcare 8~14 종목은 변동성이 큼. 현재 OOS Mean 3.32는 과최적화된 진입/청산 타이밍일 수 있음.
*   **위험/부작용:** 기존 Champion 폐기 가능성 높음.
*   **실험 정의:**
    *   `EXP-005-Cost-15bps`: 편도 수수료(슬리피지 포함)를 기존(가정 5bps)에서 15bps로 상향 적용.
    *   `EXP-006-Delay-Execution`: 시그널 발생 후 `Close`가 아닌 `Next Open` 체결로 로직 변경.
*   **PASS 조건:** OOS Sharpe Ratio > 1.2 유지.
*   **기대 관측치:** 수익률 곡선의 기울기가 완만해지되, 우상향 추세 유지 여부.

### 4) [Regime] 하락장(Bear Market) 방어 기제 점검
*   **이유:** `oos_min: -0.02`는 의심스러움. 2022년 같은 하락장에서 손실이 거의 없었다는 것은 '거래를 안 했거나(Degenerate)', '운이 좋았거나'임.
*   **위험/부작용:** 과도한 방어로 상승장(Upside) 수익 포기.
*   **실험 정의:**
    *   `EXP-007-Regime-Filter`: VIX 25 이상 or SPY 200일선 하회 시 현금 비중 50% 강제.
    *   `EXP-008-Sector-Hedge`: Tech 비중만큼 Inverse ETF(PSQ 등) 데이터로 헷지 시뮬레이션(실매매 X, 지표만 관측).
*   **PASS 조건:** 2022년 구간(또는 하락 Fold) MDD < -15%.
*   **기대 관측치:** OOS Min 값이 현실적인 수준(-0.1 ~ -0.2)으로 내려가고 데이터 정합성 확보.

### 5) [Universe] 헬스케어 섹터 편향성 검증
*   **이유:** Tech는 시장 베타를 따라가지만, Healthcare(Bio)는 임상 결과 등 이벤트 드리븐 성격이 강함. 특정 "대박 종목" 1~2개가 수익률을 왜곡시켰을 가능성.
*   **위험/부작용:** 유니버스 축소로 분산 효과 감소.
*   **실험 정의:**
    *   `EXP-009-Exclude-Top-Winner`: 기여도 상위 2개 종목 제외 후 백테스트 재구동.
*   **PASS 조건:** OOS Mean 하락폭 30% 이내.
*   **기대 관측치:** 특정 종목 의존도 확인.

# 2. 성능 정체 시 원인 분해 (Diagnosis Logic)

수익률이 움직이지 않거나 0에 수렴할 때 다음 순서로 디버깅하십시오.

1.  **트리거(Trigger) 레벨:**
    *   *현상:* 매수/매도 시그널 자체가 0개.
    *   *체크:* 기술적 지표(RSI, Boll)의 임계값이 너무 극단적인가? (예: RSI < 10)
    *   *액션:* 임계값 완화 (Relax Thresholds).

2.  **적용(Application) 레벨:**
    *   *현상:* 시그널은 있는데 주문이 안 나감.
    *   *체크:* `min_capital_per_trade`가 잔고보다 큰가? 혹은 `risk_manager`가 변동성 초과로 거래를 차단했는가?
    *   *액션:* 자금 관리 룰(Position Sizing) 축소 확인.

3.  **노출(Exposure) 레벨:**
    *   *현상:* 주문은 나갔는데 포지션이 미미함.
    *   *체크:* 최적화 엔진(Optimizer)이 현금 비중을 높게 잡도록 설정되었는가? (Max Cash constraint).
    *   *액션:* `target_exposure` 강제 상향(0.8 이상).

4.  **비용/레짐(Cost/Regime) 레벨:**
    *   *현상:* 거래는 활발한데 계좌가 녹음.
    *   *체크:* 잦은 손절(Whipsaw) 구간인가? 슬리피지가 수익을 초과하는가?
    *   *액션:* 노이즈 필터 추가 또는 타임프레임 확장(Daily -> Weekly).
