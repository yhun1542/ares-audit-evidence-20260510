## 24~48시간 TOP5 우선순위 (코드/아키텍처/전략) — 명령형 체크리스트

### 1) **누수/과최적화 방지: “Leakage & Fold Health Sentinel”를 자동 게이트로 고정**
- **왜 필요**
  - 현재 챔피언 메타에 `worst_mdd: None`, `file:` 공란 등 “평가 산출물 누락/부분 실행” 징후가 있고, OOS 평균만으로는 누수·평가 스킵·폴드 붕괴를 못 잡음.
  - 48시간 루프에서 “성능이 안 움직이는” 가장 흔한 원인이 **(a) 실제로는 실험이 무효**(평가 실패/스킵) 또는 **(b) 누수로 OOS가 가짜 안정화**되는 케이스임.
- **위험/부작용**
  - 게이트 강화로 통과 실험 수가 줄어 단기 탐색 속도 저하.
  - 기존에 “운 좋게” 살아남던 실험들이 대거 탈락(정상).
- **최소 실험 2~3개 (아래 E1 재사용)**
  - (E1-a) 폴드별 feature timestamp 검사 + “t0 이후 데이터 참조” 탐지
  - (E1-b) label/리턴 계산 구간과 feature 계산 구간 겹침 탐지
  - (E1-c) 폴드별 샘플 수/결측률/분산 붕괴(상수 피처) 탐지
- **PASS 조건**
  - 모든 폴드에서 **leak flag = 0**
  - 폴드별 샘플 수 편차/결측률이 정의된 한계 이내(게이트로 강제)
  - `worst_mdd`/rebalance log/metrics가 **항상 생성**(없으면 FAIL)

### 2) **비용/슬리피지 미반영 제거: “Cost Stress Harness”로 챔피언을 비용 민감도 기준으로 교체**
- **왜 필요**
  - 현재 노출(exposure) 0.47~0.84로 상시 투입에 가까운데, 비용/회전율이 조금만 커져도 OOS 평균이 “안 움직이거나” 가짜로 좋아 보이는 현상이 발생.
  - Tech+Healthcare 8~14종목 집중 포트는 체결/스프레드/갭 비용에 취약.
- **위험/부작용**
  - 단기 성과 하락(현실 반영).
  - 회전 억제로 모멘텀/리밸런스 알파 일부 희생.
- **최소 실험 2~3개 (E2 재사용)**
  - (E2-a) 비용 0bp/5bp/15bp 3단 스트레스에서 성능·턴오버 탄력도 측정
  - (E2-b) 슬리피지 모델: 고정 bp vs (ATR/달러거래대금) 기반 가변 모델 비교
  - (E2-c) 비용 포함 시 **리밸런스 빈도(일/주)** 민감도 측정
- **PASS 조건**
  - 비용 5~15bp 구간에서도 **OOS mean이 의미 있게 유지**(예: 0bp 대비 성능 감소율이 임계 이하)
  - 턴오버 상한 준수 + 성능의 대부분이 “비용 없는” 구간에서만 나오지 않을 것(스트레스에서 붕괴하면 FAIL)

### 3) **운영 리스크/재현성: rebalance pinpoint 파이프라인을 “실행 가능” 상태로 복구**
- **왜 필요**
  - 로그에 명시적으로 실패:
    - `Error loading --base-log: No such file or directory: '--base-log'`
    - `rebalance.csv` JSON 파싱 실패
  - 즉, 현재 루프는 “리밸런스/체결/턴오버 원인”을 관측할 수 없어 비용/노출/리스크 문제를 근본적으로 못 고침.
- **위험/부작용**
  - 로그 포맷 변경 시 과거 비교 깨짐 → 버전 태깅 필요.
  - 저장 I/O 증가(하지만 필수).
- **최소 실험 2~3개 (E3 재사용)**
  - (E3-a) `--base-log` 인자 검증(존재/확장자/포맷) + 실패 시 즉시 FAIL
  - (E3-b) rebalance 로그 단일 포맷으로 강제(JSONL 권장) + “헤더/빈파일” 방지
  - (E3-c) 리밸런스 이벤트마다 (timestamp, target_w, prev_w, delta, est_cost, est_slip) 기록
- **PASS 조건**
  - rebalance pinpoint가 **0 에러로 리포트 생성**
  - 리밸런스 로그에서 **턴오버/비용/노출 변화**가 재현 가능(같은 seed/run에서 동일)

### 4) **노출/퇴화 방지: “Exposure & Turnover Controller”를 모델 밖에서 강제(가드레일)**
- **왜 필요**
  - 노출 범위가 0.47~0.84로 높은데, 시장 레짐(금리/리스크오프)에서 헬스케어·빅테크가 동시에 흔들리면 MDD가 급증.
  - “성능이 안 움직임”은 종종 **노출이 이미 포화**(항상 비슷한 포지션)라서 발생 → 신호 변화가 포트에 반영되지 않음.
- **위험/부작용**
  - 노출 캡이 알파를 눌러 OOS 평균이 내려갈 수 있음(대신 MDD/비용 안정화 기대).
- **최소 실험 2~3개 (E4 재사용)**
  - (E4-a) 노출 목표를 0.55 고정 vs 0.35~0.65 동적(레짐 기반) 비교
  - (E4-b) 턴오버 상한(예: 일 15%/주 35%) 도입 전후 비교
  - (E4-c) 포지션 변화량에 deadband(소액 변경 무시) 적용
- **PASS 조건**
  - OOS mean이 크게 훼손되지 않으면서(임계 내) **턴오버/비용/MDD 지표 개선**
  - “리밸런스 빈도는 높은데 실효 포지션 변화는 작은” 비효율이 감소(로그로 확인)

### 5) **서바이버십/유니버스 고정: “8~14 Tech+Healthcare 하드 유니버스” + 생존편향 점검**
- **왜 필요**
  - US 주식 only + Tech/Healthcare 중심 + 8~14개 집중은 **유니버스 변동/상장폐지/편입편출**에 의한 생존편향이 치명적.
  - 유니버스가 매 시점마다 바뀌면 성능이 “안 움직이는” 형태(비교 불가/평가가 섞임)로 나타남.
- **위험/부작용**
  - 하드 유니버스는 기회 축소.
  - 종목 선택이 잘못되면 구조적으로 성능 상한이 낮아짐(그래도 편향 제거가 우선).
- **최소 실험 2~3개 (E5 재사용)**
  - (E5-a) **고정 12종목**(Tech 6 + Healthcare 6)으로만 학습/매매, 전 기간 동일
  - (E5-b) “당시점 이용가능(상장/거래가능)” 필터를 엄격 적용(결측/거래정지 처리 포함)
  - (E5-c) 심볼 변경/인수합병 매핑 테이블 고정(없으면 FAIL)
- **PASS 조건**
  - 유니버스가 전 폴드/전 기간에서 **정의대로 유지**(예외는 로그로 명시)
  - 생존편향 의심 신호(예: delist 종목이 데이터에서 사라져 손실 구간 누락)가 0

## 48시간 자동 루프용 “실행 가능한 Patch/실험” 5개 (3~5 제한 준수)
아래 5개만 돌리고, 위 TOP5 제안들은 이 5개 실험을 **재사용**해서 검증하도록 고정.

---

### (E1) Leakage & Fold Health Sentinel (게이트 실험)
1) **실험 정의**
   - 폴드별로 feature timestamp/label window/리턴 계산 window 정합성 검사.
   - 상수 피처, 결측률 급증, 샘플 수 급감, fold degenerate 탐지.
2) **게이트**
   - leak flag > 0 이면 즉시 FAIL
   - degenerate fold 발생 시 FAIL
   - 산출물 누락(`worst_mdd None`, champion file empty 등) 시 FAIL
3) **기대 관측치**
   - “성능이 안 움직임” 케이스 중 일부가 **평가 무효/스킵**으로 분해되어 원인 제거
   - 유효 실험만 남아 OOS 변동이 정상화

---

### (E2) Cost Stress Harness (비용 민감도 실험)
1) **실험 정의**
   - 동일 전략에 비용/슬리피지 모델 2종(고정bp, 유동성/ATR 기반)을 붙이고 0/5/15bp 스트레스.
2) **게이트**
   - 5bp 이상에서 성능이 과도 붕괴하면 FAIL(“비용 없는 알파”로 판정)
   - 턴오버 상한 초과 시 FAIL
3) **기대 관측치**
   - OOS mean이 비용에 대해 얼마나 탄력적인지 곡선으로 확보
   - “성능 정체”가 사실은 비용으로 상쇄되는지 확인 가능

---

### (E3) Rebalance Log Canonicalization (운영/관측 복구 실험)
1) **실험 정의**
   - rebalance 로그를 JSONL 단일 규격으로 저장하고, `aub_rebalance_pinpoint`가 반드시 읽도록 경로/포맷 검증 로직 추가.
2) **게이트**
   - base-log/cand-log 없으면 즉시 FAIL(조용히 넘어가지 않기)
   - pinpoint 리포트 생성 실패 시 FAIL
3) **기대 관측치**
   - “언제/왜/얼마나” 리밸런스가 발생했는지 관측 가능
   - 비용/노출/턴오버 최적화가 데이터 기반으로 가능

---

### (E4) Exposure & Turnover Controller (가드레일 실험)
1) **실험 정의**
   - 모델 출력 후단에서 (노출 캡 + 턴오버 캡 + deadband) 적용.
   - 레짐 지표는 **ETF를 관측지표로만 사용**: QQQ(Tech), XLV(Healthcare), IWM(리스크), TLT(금리) 등으로 “risk-on/off” 스코어 산출 → 노출 목표만 조정(ETF 매매 없음).
2) **게이트**
   - 노출/턴오버 한도 위반 시 FAIL
   - 비용 포함 성능(E2 기준)에서 붕괴 시 FAIL
3) **기대 관측치**
   - 성능 평균이 크게 떨어지지 않으면서 MDD/비용 안정화
   - “항상 비슷한 포지션” 현상 감소(포지션 변화의 효율 증가)

---

### (E5) Hard Universe + Survivorship Guard (유니버스 고정 실험)
1) **실험 정의**
   - Tech+Healthcare 8~14개 **하드 고정 리스트**로만 매매(예: 12개 고정).
   - 데이터 레이어에서 “당시점 거래가능” 검증 및 심볼 이벤트(변경/합병) 매핑을 강제.
2) **게이트**
   - 유니버스 구성 종목 수가 8~14를 벗어나면 FAIL
   - 거래불가/결측이 발생했는데 대체 규칙 없이 포지션 계산하면 FAIL
3) **기대 관측치**
   - 서바이버십/유니버스 드리프트로 인한 가짜 안정화 제거
   - 실험 간 비교 가능성(사과-사과) 확보

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐) — 실행 순서 트리
아래 순서대로 **관측→격리→수정**만 수행(질문 없이 자동 점검 가능).

### A. 트리거(신호 생성) 레벨
- **점검**
  - 신호 분포가 폴드/기간별로 거의 동일(분산 축소) → 과도한 정규화/클리핑/결측 대체가 신호를 죽임
  - 상위/하위 점수 종목이 항상 같은 종목 → 유니버스/피처가 사실상 고정
- **격리 실험**
  - E1 결과에서 상수 피처/결측률 상승 폴드 확인
  - E5로 유니버스 고정 후에도 동일 현상이면 피처/스코어링 문제

### B. 적용(포지션 매핑) 레벨
- **점검**
  - 신호는 변하는데 포지션이 거의 안 변함 → 포지션 맵핑(스케일링/클램프/라운딩) 또는 리밸런스 규칙이 “무시”시키는 중
- **격리 실험**
  - E3 로그에서 `target_w - prev_w` 분포 확인(대부분 0이면 적용 레이어 문제)
  - E4에서 deadband/턴오버 캡 변화가 포지션 변화에 미치는 영향 관측

### C. 노출(익스포저) 레벨
- **점검**
  - 노출이 상단에 붙어서 움직이지 않으면(0.84 근방 고정) 성능이 레짐에 의해 잠김
- **격리 실험**
  - E4로 노출 목표를 낮추거나 레짐 기반 동적화 후, MDD/샤프/mean 반응을 관측

### D. 비용(슬리피지/수수료/스프레드) 레벨
- **점검**
  - 비용 0bp에서는 개선되는데 5~15bp에서 이익이 사라짐 → “현실에서는 정체”
- **격리 실험**
  - E2의 비용 민감도 곡선으로 원인 확정
  - E3 로그로 어떤 리밸런스가 비용을 만드는지 pinpoint

### E. 레짐(시장 국면) 레벨
- **점검**
  - Tech/Healthcare 동시 하락(금리 급등, 리스크오프) 구간에서만 성능이 멈춤/역전
- **격리 실험**
  - ETF(관측지표) 기반 레짐 스코어로 구간을 나누고, 구간별 성능/노출/턴오버를 분해(E4에서 동시에 수행)

---

## 즉시 실행 순서(48시간 루프에 그대로 넣기)
1) **E3 먼저**: 로그/핀포인트가 돌아가야 이후 비용/노출 실험이 의미 있음(실패 시 즉시 FAIL).
2) **E1 병행**: 누수/폴드 무효를 먼저 제거(게이트 강화).
3) **E2 실행**: 비용 민감도 곡선 확보(정체 원인이 비용인지 확정).
4) **E4 실행**: 노출/턴오버 가드레일로 MDD/비용 안정화 확인.
5) **E5 실행**: 서바이버십/유니버스 드리프트 제거로 비교 가능성 고정.

이 5개만 돌려도, “성능 정체”의 대부분이 **(1) 평가 무효/관측 불능 (2) 비용 상쇄 (3) 노출 포화 (4) 유니버스 드리프트 (5) 레짐 잠김** 중 어디인지 48시간 내에 갈라낼 수 있게 구성돼 있음.
