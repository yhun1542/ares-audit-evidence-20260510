[분석 요약]
현재 `worst_mdd: None` 상태는 치명적 결함(Metric Calculation Error 또는 NaN Data)을 의미합니다. 리스크 측정이 불가능한 상태에서의 OOS Mean 1.88은 신뢰할 수 없습니다. 또한 Rebalance 로그 로딩 실패로 인해 거래 비용 분석이 차단되었습니다. 48시간 내 최우선 과제는 **"계측기 수리(Metric Fix)"**와 **"비용 가시화(Cost Visibility)"**입니다.

### 1) 향후 24~48시간 우선순위 TOP 5 제안

#### #1. [URGENT] MDD Calculation & NaN Handling Patch
*   **이유:** `worst_mdd: None`은 백테스팅 엔진의 신뢰성을 0으로 만듭니다. 주식 데이터의 결측치(NaN)가 전파되었거나, 수익률 계산 로직이 0으로 나누기 등의 에러를 묵살했을 가능성이 큽니다.
*   **위험/부작용:** MDD가 정상 계산되면 현재 Champion의 점수가 급락하여 폐기될 수 있음(False Hope 제거).
*   **실험 (Patch):**
    1.  **EXP-FIX-001:** 수익률 배열(Returns Array)에 `fillna(0)` 처리 후 MDD 재계산 로직 적용.
    2.  **EXP-FIX-002:** 2022년 하락장 구간(Tech Sector Crash) 강제 백테스트로 MDD 수치 발생 여부 확인.
    3.  **EXP-FIX-003:** 보유 종목이 0개일 때의 Equity Curve 처리 로직(Flat 유지) 검증.
*   **PASS 조건:** `worst_mdd`가 `None`이 아니고 `0.0` ~ `-1.0` 사이의 실수(float)로 출력될 것.

#### #2. [CRITICAL] Rebalance Logger Pipeline Restore
*   **이유:** `aub_rebalance_pinpoint.py` 실패는 거래 회전율과 슬리피지/수수료 분석이 불가능함을 뜻합니다. 8~14개 종목 집중 투자 시 잦은 교체는 수익을 모두 잠식합니다.
*   **위험/부작용:** 로그 파일 용량 증가. I/O 오버헤드.
*   **실험 (Infrastructure):**
    1.  **EXP-LOG-001:** `rebalance.csv` 생성 경로를 절대 경로로 하드코딩하여 파일 생성 확인.
    2.  **EXP-LOG-002:** JSONL 포맷터가 `NaN` 값을 `null`로 변환하여 기록하도록 직렬화(Serialization) 로직 수정.
    3.  **EXP-LOG-003:** 10분 단위 짧은 루프 실행 후 로그 파서가 에러 없이 파일을 읽는지 확인.
*   **PASS 조건:** `aub_rebalance_pinpoint.py` 실행 시 "No such file" 및 "Expecting value" 에러 없이 Report 생성.

#### #3. [RISK] Tech/Healthcare Concentration Stress Test
*   **이유:** Tech와 Healthcare는 상관관계가 변동적입니다. 특정 시점에 두 섹터가 동반 하락할 때 방어 로직(Cash 전환)이 작동하는지 확인해야 합니다.
*   **위험/부작용:** 과도한 방어 로직 추가 시 상승장 수익률(Upside) 제한.
*   **실험 (Strategy):**
    1.  **EXP-STR-001:** Tech/Healthcare ETF(XLK, XLV)의 20일 상관계수가 0.8 이상일 때, 현금 비중 30% 강제 확보 규칙 추가.
    2.  **EXP-STR-002:** 개별 종목 변동성(ATR)이 상위 10% 급등 시 매수 금지(Filter) 적용.
    3.  **EXP-STR-003:** 포트폴리오 내 단일 종목 비중 상한을 15%로 강제 제한(Hard Cap).
*   **PASS 조건:** MDD가 기존 대비(수치 복구 후) 10% 이상 개선되거나, 하락장에서 Cash 비중이 증가하는 것이 관측될 것.

#### #4. [EXECUTION] Lookahead Bias Check (Lag Implementation)
*   **이유:** "ONE TRUTH" 날짜가 2026년입니다. 미래 시뮬레이션 중 `Close` 가격으로 당일 매매하는 선행 편향(Lookahead Bias)이 흔히 발생합니다.
*   **위험/부작용:** 신호 지연으로 인한 진입/청산 타이밍 손실(Slippage와 유사).
*   **실험 (Validation):**
    1.  **EXP-VAL-001:** 시그널 생성 데이터에 `.shift(1)` 강제 적용 후 성과 비교.
    2.  **EXP-VAL-002:** 매매 실행 가격을 `Next Open`으로 변경하여 테스트.
*   **PASS 조건:** `shift(1)` 적용 후에도 OOS Mean이 0.5 이상 유지될 것 (알파가 데이터 누수에 의존하지 않음을 증명).

#### #5. [UNIVERSE] Survivorship Bias Filter
*   **이유:** 현재 시점(2026) 기준으로 존재하는 8~14개 종목만 과거(2020~)로 돌리면, 상장폐지된 종목이 제외된 생존 편향이 발생합니다.
*   **위험/부작용:** 과거 데이터(Delisted stocks) 확보 비용 또는 데이터 부재.
*   **실험 (Data):**
    1.  **EXP-DAT-001:** 유니버스 선정 시 "현재 시가총액 상위"가 아닌 "당시 시점 시가총액 상위" 로직 적용(Point-in-Time).
    2.  **EXP-DAT-002:** 유동성 하위 20% 종목을 유니버스에서 영구 배제.
*   **PASS 조건:** 유니버스 변경 후에도 승률(Win Rate)이 5%p 이상 급락하지 않을 것.

### 2) 48시간 자동 루프 실행 포맷

**Loop Configuration:**
- **Target:** Fix MDD & Logger -> Validate Strategy
- **Universe:** US Tech/Healthcare High Cap (Dynamic 8~14)

**(1) 실험 정의 (Experiment Definitions)**
1.  `fix_mdd_nans`: Metrics 계산 모듈에서 `np.nan_to_num` 적용 및 Division by Zero 예외 처리.
2.  `enable_jsonl_logging`: 주문/체결 로그를 JSONL로 기록하고, 경로 오류 수정.
3.  `constraint_sector_corr`: Tech/Health 상관계수 > 0.8 시 Exposure Max 0.7로 제한.
4.  `execution_lag_1d`: 모든 진입/청산 신호에 `lag=1` 적용 (오늘 신호 -> 내일 시가 진입).

**(2) 게이트 (Gates)**
- **Gate 1 (Integrity):** `worst_mdd` is not None AND `worst_mdd` < 0.
- **Gate 2 (Ops):** `rebalance.jsonl` 파일 크기 > 0KB.
- **Gate 3 (Performance):** OOS Sharpe > 1.0 (MDD 수정 후 기준).

**(3) 기대 관측치 (Expected Observations)**
- **Obs 1:** MDD 수정 후 `oos_mean`은 1.88에서 1.2~1.4 수준으로 하향 조정될 것(정상화).
- **Obs 2:** Lag 적용 시 수익률 약 15~20% 감소 예상(실제 집행 비용 반영).
- **Obs 3:** 하락장에서 Tech/Health 동반 하락 시 Cash 비중이 20% 이상으로 유지되는지 로그에서 확인.

### 3) 성능 정체(Stagnation) 시 원인 분해 아이디어

만약 위 수정 후에도 성능이 오르지 않거나(flat), 예상대로 작동하지 않을 때 점검할 트리:

*   **트리거(Trigger) 실패:**
    *   *가설:* 변동성 축소로 인해 돌파(Breakout) 신호 자체가 발생하지 않음.
    *   *확인:* `trade_count`가 0에 수렴하는지 확인.
*   **적용(Application) 누락:**
    *   *가설:* 자금 부족(Buying Power)으로 주문이 거부됨(Rejected). 현금 관리 로직 오류.
    *   *확인:* `rebalance.jsonl` 내 `order_status`가 'CANCELED' 또는 'REJECTED'인지 확인.
*   **노출(Exposure) 왜곡:**
    *   *가설:* 특정 1~2개 종목(예: NVDA)이 포트폴리오의 90%를 차지하여 분산 효과 실종.
    *   *확인:* 포트폴리오 내 종목별 Weight 시계열 플롯 확인.
*   **비용(Cost) 과다:**
    *   *가설:* 잦은 손절(Whipsaw)로 거래 비용이 알파를 초과.
    *   *확인:* Gross Return vs Net Return 괴리율 측정.
*   **레짐(Regime) 불일치:**
    *   *가설:* 추세 추종 전략을 횡보장(Range market)에 적용 중.
    *   *확인:* ADX(평균방향성지수) < 20 인 구간에서의 손익분기 확인.
