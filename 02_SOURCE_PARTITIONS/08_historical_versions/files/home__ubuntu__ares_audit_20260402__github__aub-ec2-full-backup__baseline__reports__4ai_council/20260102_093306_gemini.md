### 1) 향후 48시간 우선순위 TOP 5

#### 1. MDD 계산 로직 및 데이터 정합성 복구 (Critical)
*   **(a) 필요성:** `worst_mdd: None`은 리스크 관리 모듈이 붕괴되었음을 의미. 배포 불가능 상태. 데이터 결측치(NaN)나 초기 자본 설정 오류 가능성.
*   **(b) 위험:** MDD가 실제로는 -50% 이상일 수 있음. 은폐된 리스크.
*   **(c) 실험 제안:**
    *   `fix_mdd_calc`: 수익률 시계열에 `dropna()` 및 `ffill()` 전처리 강제 적용 후 MDD 재계산.
    *   `force_initial_capital`: 초기 자본금 하드코딩 및 첫 거래일 NAV 강제 초기화 테스트.
*   **(d) PASS 조건:** `worst_mdd`가 `None`이 아닌 음수 값(예: -0.15 등)으로 출력될 것.

#### 2. 거래 로그(Rebalance Log) 포맷 표준화 (Observability)
*   **(a) 필요성:** `Error loading... Expecting value` 에러 발생. JSONL과 CSV가 혼용되어 파싱 실패. 트레이딩 근거 추적 불가.
*   **(b) 위험:** 블랙박스 트레이딩. 주문 실패나 로직 오류를 감지 못 함.
*   **(c) 실험 제안:**
    *   `log_format_unification`: 모든 리밸런싱 로그를 `jsonl` 포맷으로 통일하고, 기존 CSV 파서 제거.
    *   `schema_validation`: 출력 로그에 필수 필드(ticker, weight, reason, timestamp) 존재 여부 검증 테스트.
*   **(d) PASS 조건:** `aub_rebalance_pinpoint.py`가 에러 없이 실행되고, 100건 이상의 거래 내역이 파싱될 것.

#### 3. 유니버스 축소 및 Tech/Bio 집중도 검증 (Targeting)
*   **(a) 필요성:** 8~14개 종목 집중이 목표이나, `exposure_min: 0.47`로 보아 현금이 너무 많거나 잡다한 종목이 섞일 수 있음. ETF 제외 로직 재확인.
*   **(b) 위험:** 과도한 현금 보유로 인한 벤치마크 언더퍼폼(Cash Drag).
*   **(c) 실험 제안:**
    *   `filter_etf_strict`: `sector` 정보가 없거나 `ETF` 키워드 포함 시 유니버스에서 영구 제외.
    *   `force_sector_tech_health`: GICS 기준 IT/Healthcare 섹터 비중 합이 포트폴리오의 80% 이상 유지되도록 제약 추가.
    *   `min_exposure_lift`: 최저 노출도를 0.47 -> 0.70으로 상향 조정.
*   **(d) PASS 조건:** 포트폴리오 내 ETF 비중 0%, IT+Health 비중 > 80%, 일평균 보유 종목 수 8~14개.

#### 4. 수수료/슬리피지 스트레스 테스트 (Cost Reflection)
*   **(a) 필요성:** OOS Mean 1.88이 비용 반영 전이라면 허상임. 회전율이 높은 8-14개 종목 전략은 비용에 취약.
*   **(b) 위험:** 실계좌 투입 시 우상향 곡선이 횡보/하락으로 반전.
*   **(c) 실험 제안:**
    *   `high_cost_simulation`: 편도 수수료+슬리피지를 보수적으로 15bps(0.15%)로 설정하여 백테스트.
    *   `turnover_penalty`: 일일 회전율이 20% 초과 시 패널티 부여 로직 추가.
*   **(d) PASS 조건:** 15bps 비용 적용 후에도 OOS Sharpe > 1.2 유지.

#### 5. 2022년 하락장 구간 집중 검증 (Regime Check)
*   **(a) 필요성:** `oos_min: 0.43`으로 보아 특정 구간 성과가 저조함. Tech/Health가 동반 하락했던 2022년 방어력 확인 필요.
*   **(b) 위험:** 과최적화(Overfitting)로 최근 상승장(2023-2024)에만 맞춰져 있을 가능성.
*   **(c) 실험 제안:**
    *   `backtest_2022`: 2022-01-01 ~ 2022-12-31 구간만 분리하여 백테스트 수행.
    *   `volatility_hedge_logic`: VIX 혹은 시장 변동성 상위 구간에서 현금 비중 확대 로직(FSA Score 기반) 테스트.
*   **(d) PASS 조건:** 2022년 구간 MDD < -25% (나스닥 대비 방어 성공).

### 3) 성능 정체 시 원인 분해 (Debugging Tree)

성능(Score)이 움직이지 않거나 `oos_min`이 개선되지 않을 때 다음 순서로 체크:

1.  **트리거(Trigger) 불발:**
    *   FSA(Fundamental/Sentiment/Algo) 점수가 임계값을 넘지 못해 매매가 아예 안 일어나는가? -> *조치: 임계값(Threshold) 완화 실험.*
2.  **자산군(Asset) 편향:**
    *   Tech/Healthcare 내에서 특정 초대형주(NVDA, LLY) 1~2개만 계속 잡히는가? -> *조치: 개별 종목 비중 상한(Cap) 15% 설정.*
3.  **비용(Cost) 잠식:**
    *   잦은 리밸런싱으로 수익이 수수료로 삭제되는가? -> *조치: 리밸런싱 주기를 일간 -> 주간 변경 또는 밴드형 리밸런싱 도입.*
4.  **레짐(Regime) 불일치:**
    *   현재 전략이 '추세 추종'인데 시장이 '횡보' 중인가? -> *조치: ADX 지표 등을 필터로 추가하여 비추세 구간 거래 중지.*
5.  **데이터(Data) 오류:**
    *   가격 데이터에 액면분할 등이 미반영되어 수익률이 튀는 구간이 있는가? -> *조치: 수익률 절댓값이 20% 이상인 날짜의 데이터 원본 대조.*
