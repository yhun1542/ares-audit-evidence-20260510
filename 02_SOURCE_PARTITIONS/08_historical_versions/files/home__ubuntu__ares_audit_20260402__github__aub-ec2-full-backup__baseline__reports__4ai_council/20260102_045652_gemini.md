# 48시간 내 실행 우선순위 TOP 5 (명령형 체크리스트)

## 1. [검증] 동적 유니버스(Dynamic Universe) 적용 (서바이버십 바이어스 제거)
*   **이유:** 현재 8~14개 종목이 고정 리스트라면, 현재 시점의 승자(NVDA, LLY 등)를 과거에 강제로 편입한 '사후 확증 편향'일 확률 매우 높음.
*   **위험/부작용:** 비상장 상태였거나 시총 하위였던 종목이 제외되며 백테스트 성과(CAGR) 급락 가능성. 데이터 로딩 부하 증가.
*   **실행 계획 (48hr Loop):**
    1.  **실험 정의:** 매 분기 첫 거래일 기준, Nasdaq Tech/Healthcare 섹터 시총 상위 20위 중 10개 무작위 또는 상위 순 선택 로직(Rebalancing) 구현.
    2.  **게이트(Pass/Fail):** 기존 Champion 대비 `Sharpe` 하락폭 20% 이내 방어 시 합격.
    3.  **기대 관측치:** `tuning_mean`은 하락하나 `lockbox_min`의 신뢰도 상승.

## 2. [전략] 변동성 레짐 필터(VIX/Sector ETF 활용) 추가
*   **이유:** Champion의 `worst_mdd`(-7%)는 레버리지 사용 시 치명적일 수 있음. 하락장이 아닌 '변동성 폭발' 구간에서 손실을 차단해야 함.
*   **위험/부작용:** 거래 기회(Opportunity Cost) 감소로 인한 총수익 저하. 지표(ETF) 데이터 룩어헤드(Look-ahead) 주의.
*   **실행 계획 (48hr Loop):**
    1.  **실험 정의:** `VIX` > 20 또는 `XLV/XLK` 20일 이격도가 -5% 하회 시 매수 금지/포지션 50% 축소 로직 `MarketRegimeFilter` 모듈 추가.
    2.  **게이트:** `worst_mdd` -5% 이내 진입 AND `tuning_mean` 3.0 이상 유지.
    3.  **기대 관측치:** MDD 개선, 거래 횟수 감소, 승률(Win Rate) 소폭 상승.

## 3. [비용] 슬리피지/수수료 페널티 함수 강화
*   **이유:** Tech/Bio 주는 변동성이 커 슬리피지가 큼. 백테스트 상의 수익이 실제 체결 오차로 증발할 가능성(Over-estimation) 차단.
*   **위험/부작용:** 진입 장벽이 높아져 거래 횟수가 0에 수렴(Zero Trades)할 위험.
*   **실행 계획 (48hr Loop):**
    1.  **실험 정의:** 최적화 목적 함수(Objective Function)를 `Return`에서 `Return - (Turnover * 0.15%)`로 변경하여 재학습.
    2.  **게이트:** `Turnover`가 기존 대비 30% 이상 감소하면서도 `Net Profit` 유지.
    3.  **기대 관측치:** 보유 기간(Holding Period) 증가, 노이즈 거래 제거.

## 4. [아키텍처] 앙상블(Ensemble): Champion + Stability Candidate
*   **이유:** `Champion_v5`(수익 추구)와 `candidate_exp_mrd_fsa`(안정성 추구)의 성격이 상반됨. 이를 6:4 또는 7:3으로 혼합하여 샤프지수 극대화.
*   **위험/부작용:** 시스템 복잡도 증가, 코드 유지보수 비용 상승.
*   **실행 계획 (48hr Loop):**
    1.  **실험 정의:** 두 모델의 시그널을 가중 평균(Weighted Avg)하여 최종 포지션 결정하는 `SignalBlender` 모듈 배포.
    2.  **게이트:** `Sortino Ratio`가 단일 모델 대비 10% 이상 향상.
    3.  **기대 관측치:** 수익 곡선의 스무딩(Smoothing), MDD -4%~-5% 구간 안착.

## 5. [검증] 노이즈 주입 테스트 (Overfitting Check)
*   **이유:** 현재 Tuning Min(0.45)보다 Lockbox Min(1.53)이 좋은 현상은 운이 좋았거나(Lockbox 기간이 평온), 과최적화 신호일 수 있음.
*   **위험/부작용:** 모든 모델이 탈락하여 Champion이 공석이 될 위험.
*   **실행 계획 (48hr Loop):**
    1.  **실험 정의:** OHLCV 데이터에 랜덤 노이즈(±1%)를 10회 주입하여 몬테카를로 시뮬레이션 수행 (`MonteCarloValidator`).
    2.  **게이트:** 하위 10% 시나리오에서도 `CAGR` > 0 유지.
    3.  **기대 관측치:** 모델의 강건성(Robustness) 확인 및 파라미터 민감도 파악.

# 성과 정체(Stagnant Performance) 시 원인 분해

성능 지표가 움직이지 않을 때 다음 순서로 디버깅하라.

1.  **트리거(Trigger) 확인:**
    *   진입 조건이 너무 까다로운가? (예: `RSI < 20` AND `Bollinger Lower Hit` 동시 만족 등 희귀 조건 확인)
    *   *Action:* 논리 연산자(AND -> OR) 완화 또는 임계값(Threshold) 확장 실험.

2.  **필터(Filter) & 노출(Exposure) 확인:**
    *   시그널은 발생했으나 `RegimeFilter`나 `RiskManager`가 모든 주문을 거절(Reject)하고 있는가?
    *   포지션 사이징이 너무 작아(예: 자산의 5%만 투입) 수익이 전체 계좌에 기여하지 못하는가?
    *   *Action:* `Order_Log` 전수 조사하여 Reject 사유(Reason Code) 파악.

3.  **비용 구조(Cost Impact) 확인:**
    *   총 수익은 높은데 수수료/슬리피지 차감 후 0에 수렴하는가? (고빈도 매매의 함정)
    *   *Action:* `Avg_Profit_Per_Trade`가 `Cost_Per_Trade`의 2배 이상인지 확인.

4.  **레짐 불일치(Regime Mismatch) 확인:**
    *   현재(최근 데이터) 시장 성격이 학습 데이터(과거)와 완전히 다른가? (예: 금리 인상기 vs 인하기)
    *   *Action:* 최근 6개월 데이터만으로 단기 튜닝(Fine-tuning) 후 성과 비교.
