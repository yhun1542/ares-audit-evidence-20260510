## 1. 우선순위 TOP 5 제안

### ① [LEAK CHECK] Tuning Fold 붕괴 원인 격리

**(a) 왜 필요한가**
- tuning_min -1.42는 단일 fold에서 -140% 손실 의미 → 레버리지 없는 전략에서 불가능
- **계산 버그 or 데이터 누수** 가능성 높음

**(b) 위험/부작용**
- 버그 아닐 경우 시간 낭비 (2h 소요)
- 실제 전략 결함이면 Champion도 재검증 필요

**(c) 최소 실험**
```
EXP-1A: tuning fold별 개별 수익률 분포 출력
        → 어느 fold가 -1.42 유발했는지 특정
        
EXP-1B: 해당 fold 기간의 raw signal vs position 비교
        → look-ahead 누수 여부 확인
        
EXP-1C: 동일 기간 Champion 수익률과 diff
        → 신규 모듈이 원인인지 격리
```

**(d) PASS 조건**
- [ ] 모든 fold의 tuning 수익률 > -0.5
- [ ] signal 생성 timestamp < position 적용 timestamp (전 구간)

---

### ② [COST REALITY] 거래비용·슬리피지 반영 검증

**(a) 왜 필요한가**
- lockbox_mean 1.66 → 연 166% 수익은 **비현실적** (비용 미반영 의심)
- 실전 괴리 시 전체 시스템 무의미

**(b) 위험/부작용**
- 비용 반영 시 수익률 급락 → 심리적 충격
- 과도한 비용 가정 시 전략 조기 폐기

**(c) 최소 실험**
```
EXP-2A: 현재 assumed cost 파라미터 출력
        → slippage, commission, spread 값 확인
        
EXP-2B: cost_multiplier = [1x, 2x, 3x] 시뮬레이션
        → 민감도 분석
        
EXP-2C: 연간 turnover 계산 → 실제 거래횟수 기반 비용 추정
```

**(d) PASS 조건**
- [ ] 비용 2x 반영 후에도 lockbox_mean > 0.3 (연 30%)
- [ ] 연간 turnover < 24 (월 2회 미만 리밸런싱)

---

### ③ [MDD TRADE-OFF] Champion MDD -9.6% 개선 실험

**(a) 왜 필요한가**
- Candidate가 MDD -4.2%로 개선했으나 수익 희생
- **MDD 개선 + 수익 유지** 경로 탐색 필요

**(b) 위험/부작용**
- MDD 최적화 → 수익률 하락 트레이드오프 불가피
- 과도한 hedge → 상승장 underperform

**(c) 최소 실험**
```
EXP-3A: Candidate의 cash 전환 threshold만 10% 완화
        → mdd_trigger = current * 1.1
        
EXP-3B: Champion에 soft drawdown brake 추가
        → DD > 5%일 때 position 20% 감소
        
EXP-3C: Sector rotation 속도 조절
        → rebalance_cooldown = 5d → 10d
```

**(d) PASS 조건**
- [ ] lockbox_mean ≥ 1.5 AND worst_mdd ≥ -0.07
- [ ] lockbox_min > 0.8 (최악 fold 개선)

---

### ④ [REGIME EXPOSURE] 레짐별 성과 분해

**(a) 왜 필요한가**
- fold14_mdd만 보면 특정 기간 집중 위험
- 상승/하락/횡보장 각각에서 어떻게 작동하는지 불명

**(b) 위험/부작용**
- 레짐 정의 임의성 → 과최적화 유발 가능
- 분석 복잡도 증가

**(c) 최소 실험**
```
EXP-4A: VIX 기준 레짐 분류 (VIX<15/15-25/25+)
        → 각 레짐별 sharpe, mdd 분리 출력
        
EXP-4B: SPY 추세 기준 (20d MA 상/하)
        → bull/bear 구간 성과 분리
        
EXP-4C: 최악 성과 구간 상위 3개 특정
        → 공통 시장 특성 추출
```

**(d) PASS 조건**
- [ ] 어떤 단일 레짐에서도 sharpe < 0 아님
- [ ] bear 구간 mdd < bull 구간 mdd * 2

---

### ⑤ [SURVIVOR BIAS] 유니버스 고정 vs 동적 검증

**(a) 왜 필요한가**
- Tech+Healthcare 8~14종목 → 현재 생존 종목 기준이면 편향
- 과거 탈락 종목 미포함 시 수익률 과대계상

**(b) 위험/부작용**
- 과거 상장폐지 종목 데이터 확보 어려움
- 동적 유니버스 전환 시 백테스트 복잡도 급증

**(c) 최소 실험**
```
EXP-5A: 현재 유니버스 리스트 + 선정일자 출력
        → 언제부터 해당 종목들이 포함되었는지 확인
        
EXP-5B: 2020년 기준 S&P500 Tech/Healthcare 상위 종목으로
        유니버스 재구성 → 결과 비교
        
EXP-5C: 최소 1개 "실패 종목" (예: DOCU, ZM) 포함 후 재실행
```

**(d) PASS 조건**
- [ ] 동적 유니버스 적용 시 lockbox_mean 하락폭 < 20%
- [ ] 유니버스 선정일이 백테스트 시작일 이전
