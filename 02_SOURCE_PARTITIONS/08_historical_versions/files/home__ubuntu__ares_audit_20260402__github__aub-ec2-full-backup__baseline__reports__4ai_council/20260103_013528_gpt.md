## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — 명령형 체크리스트

### 1) **누수/서바이버십/룩어헤드 “즉시 차단” (최우선)**
- **왜 필요한지**
  - 현재 Champion은 lockbox가 튜닝 대비 과도하게 좋아 보이지 않지만(오히려 lockbox가 큼), 최근 후보에서 MDD가 급격히 악화되는 패턴이 있어 **데이터 타이밍/유니버스 구성의 미세 누수**가 있으면 후보군이 “좋아 보이다가” 특정 구간에서 무너지는 형태가 자주 발생함.
  - Tech/Healthcare 종목군은 상장/합병/상폐 이벤트가 잦아 **서바이버십 편향**이 성과를 쉽게 부풀림.
- **위험/부작용**
  - 누수 차단 후 단기적으로 성능이 “하락”처럼 보일 수 있음(실제로는 과대추정 제거).
  - 데이터 소스/피처가 일부 무효 처리되어 모델 입력이 줄 수 있음.
- **최소 실험(2~3개)** → 아래 **Experiment 1**로 통합
- **PASS 조건**
  - (필수) lockbox 결과가 “개선”이 아니어도 **붕괴 방지**: `worst_mdd`가 Champion 대비 **악화 폭 ≤ 1.5%p**
  - (필수) tuning↔lockbox 갭이 비정상적으로 커지지 않음: `lockbox_mean - tuning_mean`이 기존 대비 과도하게 확대되지 않음(경고 플래그 제거)
  - (권장) “누수 감지 테스트(샘플 시프트/라벨 시프트)”에서 성과가 비정상적으로 유지되지 않음(= 정상적으로 하락)

---

### 2) **비용/슬리피지/체결 현실화 + 회전율 제한**
- **왜 필요한지**
  - Tech/Healthcare는 변동성/갭이 커서 **슬리피지 미반영 시 과최적화**가 쉽게 발생.
  - 후보에서 MDD가 커지는 패턴은 “실제 비용/체결”이 들어가면 더 악화될 소지가 큼.
- **위험/부작용**
  - 단기적으로 평균수익률 하락(현실화 비용 반영).
  - 거래 제한이 알파를 일부 억제할 수 있음.
- **최소 실험(2~3개)** → 아래 **Experiment 2**로 통합
- **PASS 조건**
  - (필수) 비용 포함 lockbox_mean이 Champion 대비 **하락 폭 ≤ 0.3** (방어적 기준)
  - (필수) turnover(48h 루프 기준 리밸런싱당) **상한 준수** + 비용이 PnL의 특정 비율(예: 20%) 이상 잠식하지 않음
  - (권장) `worst_mdd` 개선 또는 동일(±0.5%p)

---

### 3) **포트폴리오 생성기(8~14개 보유) 강제 + 단일종목/섹터 리스크 제한**
- **왜 필요한지**
  - “US Tech+Healthcare 8~14개” 제약이 느슨하면, 실제로는 몇 종목 쏠림/유사 팩터 쏠림으로 **숨은 레버리지**가 생겨 MDD 확대.
  - 현재 지표에서 후보의 MDD 악화는 포지션 집중/베타 과다 노출 가능성이 큼.
- **위험/부작용**
  - 제약 강화로 샤프/수익률이 소폭 감소할 수 있음(대신 tail risk 감소).
  - 종목 수 강제는 신호가 약할 때 성과를 희석할 수 있음.
- **최소 실험(2~3개)** → 아래 **Experiment 3**로 통합
- **PASS 조건**
  - (필수) 항상 **보유 종목 수 8~14 유지**(예외 0회)
  - (필수) `worst_mdd`가 Champion 대비 **개선(≥ 0.5%p)** 또는 최소 악화 없음(≤0.5%p)
  - (권장) 상위 1~2개 종목 기여도가 전체 PnL/리스크를 지배하지 않음(집중도 지표 하락)

---

### 4) **레짐(리스크-온/오프) 게이트: ETF는 “관측지표”로만 사용**
- **왜 필요한지**
  - Tech/Healthcare는 레짐 전환(금리/리스크오프)에서 동시 급락이 잦음. 후보의 MDD 확대는 레짐 방어 부재 신호일 수 있음.
  - ETF(XLK/XLV/QQQ 등)는 거래하지 않고도 레짐 감지 신호로 유용.
- **위험/부작용**
  - 게이트가 과민하면 “좋은 구간”도 회피해 수익률 감소.
  - 게이트 설계가 누수(미래 변동성)로 이어지지 않도록 주의 필요.
- **최소 실험(2~3개)** → 아래 **Experiment 4**로 통합
- **PASS 조건**
  - (필수) lockbox에서 tail 구간(최악 낙폭) 방어: `worst_mdd` **개선(≥1.0%p)** 또는 동일
  - (권장) 리스크오프 구간에서 노출(순익스포저/베타/변동성)이 자동으로 감소하는 로그가 명확

---

### 5) **운영 리스크(48h 자동 루프) 안전장치: 데이터 결측/급변/스플릿/거래정지 대응**
- **왜 필요한지**
  - 자동 루프는 “한 번의 데이터 이상치”가 48시간 내 대규모 포지션 변형을 유발할 수 있음.
  - Tech/Healthcare는 임상/규제 뉴스로 **갭/거래정지** 빈도가 상대적으로 높음.
- **위험/부작용**
  - 방어 로직이 과도하면 거래 기회 상실.
- **최소 실험(2~3개)** → **Experiment 1 + 2 + 3**에 “가드레일”로 포함(추가 케이스 폭발 방지)
- **PASS 조건**
  - (필수) 결측/이상치/기업행사 발생 시에도 포트 생성 실패 없이 **안전 모드(포지션 동결/축소)**로 전환
  - (필수) 포지션 제한/현금 비중 제한/주문 상한이 항상 준수(위반 0회)

## 실행 가능한 Patch/실험 (총 4개만) — 48시간 자동 루프 형태 (정의→게이트→기대 관측치)

### Experiment 1) **Leakage/Survivorship Sentinel + Purged/Embargo Walk-Forward**
1) **실험 정의**
   - 데이터 타임스탬프 강제: `feature_time <= decision_time - lag_buffer`를 모든 피처에 적용(최소 1바/1일 버퍼).
   - 유니버스 구성 시점 고정: “당시점에 거래 가능/상장 상태/시총 필터”만 사용(미래 생존 종목 사용 금지).
   - 검증 프로토콜에 purge+embargo 적용(이벤트/리밸런싱 윈도우 누수 차단).
2) **게이트(자동 FAIL 조건)**
   - tuning 성과가 소폭 올라가는데 lockbox가 급락(과최적화 전형): `tuning_mean - lockbox_mean > 1.0`이면 FAIL.
   - 특정 피처가 “미래값”으로 의심되는 패턴 탐지(시프트 테스트에서 성과 유지) 발생 시 FAIL.
3) **기대 관측치(성공 시)**
   - 튜닝 성과가 다소 하락해도 lockbox 변동이 안정화.
   - 후보들의 MDD 분산이 줄고, “갑자기 터지는 fold”가 감소.

---

### Experiment 2) **비용/슬리피지 모델 삽입 + Turnover 페널티 + 리밸런싱 스케줄 고정**
1) **실험 정의**
   - 고정 수수료 + 변동 슬리피지(예: `k * vol * sqrt(notional/ADV)` 형태) 반영.
   - 목적함수에 turnover 페널티(또는 리밸런싱 시 변경폭 L1 제한) 추가.
   - 리밸런싱 빈도/시각을 고정(48h 루프에서 “데이터 갱신 시점”과 일치).
2) **게이트**
   - 비용 반영 후 lockbox_mean이 Champion 대비 과도하게 악화: `lockbox_mean < (champion_lockbox_mean - 0.3)`이면 FAIL.
   - turnover 상한 위반(예: 일/리밸런스당 총 교체 비중 > X) 발생 시 FAIL.
3) **기대 관측치**
   - 거래가 줄고 PnL의 비용 민감도가 낮아짐.
   - 실전 유사 성능에서 “좋아 보이는 후보”가 걸러짐.

---

### Experiment 3) **8~14 종목 강제 포트폴리오 최적화 + 집중/섹터 리스크 제한**
1) **실험 정의**
   - 종목 수: 항상 8~14개(정수 제약이 어려우면 “상위 N 스코어 + 최소/최대 컷” 규칙으로 강제).
   - 단일 종목 max weight, 상위 3개 합산 max, 섹터(Tech/Healthcare) 비중 범위(예: 30~70%) 설정.
   - 변동성 타깃(또는 ex-ante risk scaling)으로 총 리스크를 일정하게 맞춤.
2) **게이트**
   - 보유 종목 수 규칙 위반 1회라도 발생 시 FAIL.
   - 집중도 지표(예: HHI)가 기준 초과 시 FAIL.
3) **기대 관측치**
   - 후보의 최악 낙폭이 줄고, fold 간 성과 편차 감소.
   - 특정 1~2종목에 의해 성과가 왜곡되는 현상 완화.

---

### Experiment 4) **레짐 게이트(ETF 관측 전용): 리스크오프에서 노출 축소**
1) **실험 정의**
   - 관측지표: QQQ, XLK, XLV, VIX(가능하면), IBB/XBI(바이오) 등 “거래 없이” 지표로만 사용.
   - 신호 예: (a) 20일 모멘텀 음전환 + (b) 변동성 급등 + (c) 드로우다운 임계치 초과 시 **총 익스포저 스케일 다운(현금 비중 증가)** 또는 방어적(저베타/저변동) 종목으로 점진 이동.
   - 게이트는 “완전 on/off”보다 2~3단계(정상/주의/위험)로 단순화.
2) **게이트**
   - 레짐 게이트 적용 후에도 `worst_mdd`가 개선되지 않고 평균만 감소: `worst_mdd`가 Champion 대비 악화(>0.5%p)면 FAIL.
   - 레짐 판정이 과도하게 빈번(스위칭 과다)하여 turnover를 증가시키면 FAIL(Experiment 2의 turnover 상한 연동).
3) **기대 관측치**
   - tail 구간에서 손실이 줄고, 특히 후보에서 관측된 MDD 악화 패턴이 완화.
   - 리스크오프 국면에서 노출 감소 로그가 명확히 남음(재현 가능).

---

## 성능이 안 움직일 때 “원인 분해” 아이디어 (트리거/적용/노출/비용/레짐)

### A) Trigger(신호 발생) 문제
- **해야 할 로그/진단**
  - 신호 분포(스코어 평균/표준편차), 상위/하위 종목 스코어 간격, 신호가 0 근처로 붕괴하는지 체크.
  - 신호 리프레시 시점과 데이터 업데이트 시점 불일치 탐지(48h 루프에서 흔함).
- **전형적 원인**
  - 피처 결측/정규화 스케일 변화로 신호가 평평해짐.
  - purge/embargo 후 실질적으로 사용 가능한 학습 정보가 줄어 신호 약화.

### B) Apply(적용/포트 생성) 문제
- **해야 할 로그/진단**
  - “의도한 8~14개”가 실제로 지켜지는지, 리밸런스 때 교체가 과도한지(상위 N이 매번 뒤집히는지).
  - 포트 제약(섹터/비중/현금)이 신호를 얼마나 깎는지(제약 그림자 가격/클리핑 횟수).
- **전형적 원인**
  - 제약이 너무 강해 알파가 포트로 전달되지 않음(알파 전송률 저하).
  - 반대로 제약이 약해 집중이 커져 tail에서 무너짐.

### C) Exposure(노출) 문제
- **해야 할 로그/진단**
  - 베타(대 QQQ), 섹터 민감도(Tech/Healthcare 내), 사이즈/밸류/퀄리티/모멘텀 같은 공통 팩터 노출(단순 회귀로 충분).
  - 최대 기여 종목/팩터가 무엇인지(리스크 기여도/성과 기여도 분해).
- **전형적 원인**
  - “Tech+Healthcare” 내부에서도 사실상 고베타/고성장에만 몰림 → 레짐 전환에 취약.

### D) Cost(비용) 문제
- **해야 할 로그/진단**
  - 총 PnL 대비 비용 비중, turnover와 성과의 상관(회전이 높을수록 성과가 좋아 보이는지=착시).
  - ADV 대비 주문 크기 비율(슬리피지 급증 구간 탐지).
- **전형적 원인**
  - 비용 0 가정에서만 성립하는 미세 알파(실거래에선 소멸).

### E) Regime(레짐) 문제
- **해야 할 로그/진단**
  - QQQ/XLK/XLV의 모멘텀·변동성·드로우다운 상태별로 성과를 조건부 분해(조건부 기대수익/조건부 MDD).
  - 레짐 전환 직후 성과 급락 여부(특히 후보에서 worst_mdd를 만든 구간).
- **전형적 원인**
  - 한 레짐(리스크온) 특화 신호를 전 구간에 강제 적용 → tail에서 붕괴.

## 24~48시간 운영 실행 순서(명령형)
1) **Experiment 1(누수/서바이버십/프로토콜)부터 적용하고, 기존 Champion을 동일 프로토콜로 재평가해 기준선을 재고정하라.**
2) **Experiment 2(비용/슬리피지/turnover)로 “실전형 성과”로 스코어보드를 교체하라.**
3) **Experiment 3(8~14 강제 + 집중/섹터 제한)로 MDD를 먼저 누르고, 평균은 그 다음에 최적화하라.**
4) **Experiment 4(레짐 게이트)를 마지막에 얹어 tail 방어가 실제로 재현되는지 lockbox에서 확인하라.**
5) **각 실험은 “게이트 FAIL 즉시 롤백”을 기본 동작으로 하고, 48시간 루프에서 로그(신호/노출/비용/레짐 상태)를 필수로 남겨 원인분해가 가능하게 하라.**
