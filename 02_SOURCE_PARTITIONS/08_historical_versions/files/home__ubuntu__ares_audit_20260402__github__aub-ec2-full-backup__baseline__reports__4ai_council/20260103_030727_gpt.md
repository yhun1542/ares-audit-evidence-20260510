## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — **명령형 체크리스트**

> 우선순위는 **누수 → 과최적화 → 서바이버십 → 비용 미반영 → 운영 리스크** 순서로 배치.  
> **미국 주식 only**, **Tech+Healthcare 중심 8~14종목**, **ETF 매매 금지(관측지표만)**.

# 1) (누수/정합성) **Point-in-Time 누수 차단 + 리비전/타임존/코퍼레이트액션 정합성 게이트 추가**
### (a) 왜 필요한지
- 현재 Champion은 lockbox 성능이 강함(≈4.01)인데, 이런 형태는 **미세 누수/리비전 데이터(추후 수정되는 펀더멘털)/시간정렬 오류**로 “잠깐 좋아 보이는” 패턴이 섞일 때가 가장 위험합니다.
- 특히 48시간 자동 루프에서는 **한 번 섞인 누수 패턴이 지속적으로 선택(best-select)될 위험**이 큼.

### (b) 위험/부작용
- 누수 제거 후 성능이 “진짜로” 내려갈 수 있음(정상).
- 데이터 파이프라인 변경으로 과거 결과 재현성이 깨질 수 있음(캐시/리샘플 규칙 차이).

### (c) 최소 실험 2~3개  → **단일 패치 실험 안에 ‘누수 탐지 서브테스트’로 포함(케이스 폭발 방지)**
**[실험 정의] Patch E1: `PIT_Leak_Guard + Leak_Test_Suite`**
- 서브테스트(한 번의 러닝에서 같이 산출):
  1) **Feature +1 bar shift 테스트**: 모든 특징을 1일(또는 1bar) 미래로 당겨서 학습/예측(정상이라면 성능 급락해야 함)
  2) **라벨 -1 bar shift 테스트**: 라벨을 과거로 당겨(예측 불가능하게) 성능이 0 근처로 수렴하는지 확인
  3) **Purged/Embargo CV 강제**: 이벤트/리밸런스 윈도우 기준 purge+embargo 적용(겹침 제거)

### (d) PASS 조건(게이트)
- **Leak Test Gate**
  - (+1 bar feature shift) 성능이 **유의하게 하락**: tuning_mean 또는 lockbox_mean이 **기준 대비 ≥50% 감소**(또는 0 근처)  
  - (purged/embargo 적용) Champion 성능이 **큰 폭 붕괴하지 않음**: lockbox_mean **≥ 0.85×기존**(≈3.41 이상), worst_mdd **악화폭 ≤ 1.5%p**
- **기대 관측치**
  - 누수 징후가 있으면: shift 테스트에서도 성능 유지/상승(=위험 신호)  
  - 누수 없으면: shift에서 성능 급락, purged CV에서만 완만한 하락

# 2) (비용 미반영/과최적화) **슬리피지/스프레드/충격 기반 ‘보수적 비용 모델’과 턴오버 게이트**
### (a) 왜 필요한지
- Champion이 강한 경우라도, **턴오버가 높으면 실거래 성능이 급락**합니다.
- 비용이 약하게 들어가 있으면 자동선택 루프에서 “거래로 이기는 모델”이 계속 뽑힐 수 있음(과최적화).

### (b) 위험/부작용
- 순익이 크게 내려가 모델간 순위가 바뀔 수 있음(정상).
- 너무 보수적으로 잡으면 트레이드 자체가 사라질 수 있음(과도한 페널티).

### (c) 최소 실험 2~3개 → **단일 패치 실험에서 3수준 비용 민감도 같이 산출**
**[실험 정의] Patch E2: `CostModel_v2 + Turnover_Gates`**
- 동일 전략/신호에 대해 **3가지 비용 시나리오를 한 번에 리포트**:
  1) **Base**: 고정 수수료 + 보수적 half-spread
  2) **High**: half-spread 2배 + 변동성/거래대금 기반 임팩트(단순 √(order/ADV) 형태)
  3) **Stress**: 장 급변(고변동) 구간에서 비용 상향(예: VIX/QQQ 변동성 상위 분위에서 스프레드 확대)

### (d) PASS 조건(게이트)
- **Net Robustness Gate**
  - lockbox_mean(High) **≥ 0.75×lockbox_mean(Base)**  
  - worst_mdd(High) **절대값 악화 ≤ 1.0%p**
- **Turnover Gate**
  - 연환산 턴오버(또는 평균 리밸런스 교체율)가 기준 상한 이하(프로젝트 내부 기준이 없다면: “기존 Champion 대비 증가 금지”로 게이트)
- **기대 관측치**
  - 진짜 알파면 High/Stress에서도 성능이 “남음”
  - 가짜 알파면 비용을 넣는 순간 급락 + 턴오버 급증 패턴

# 3) (서바이버십/유니버스 리스크) **Tech+Healthcare 8~14종목 ‘동적 유니버스’ + 상장폐지/정지 처리 게이트**
### (a) 왜 필요한지
- 고정 티커 리스트는 서바이버십/룩어헤드(나중에 살아남은 기업만 포함) 위험이 큼.
- 8~14종목 소수 포트폴리오는 **단일 종목 데이터 이슈/상폐/거래정지**가 치명적.

### (b) 위험/부작용
- 동적 유니버스 도입 시 백테스트 성능이 내려가거나 변동성이 증가할 수 있음(현실 반영).
- 구현 실수 시 유니버스가 빈 상태가 되는 운영 사고 가능.

### (c) 최소 실험 2~3개 → **단일 패치 실험에서 유니버스 규칙 2안 비교(동일 러닝)**
**[실험 정의] Patch E3: `DynamicUniverse_TechHealth + DelistHandling`**
- 서브테스트(동일 기간/동일 신호로 비교 리포트):
  1) **Universe A (Large/Liquid)**: Tech+Healthcare에서 시총/거래대금 상위 + 최소 가격/거래대금 필터
  2) **Universe B (Quality Tilt)**: A 조건 + 변동성/스프레드 상한(거래가능성 강화)
  3) **Delist/Trading Halt 처리**: delist return 반영(가능하면), 불능 시 보수적 청산 규칙(다음 유효 체결가)

### (d) PASS 조건(게이트)
- **Survivorship Gate**
  - 유니버스가 기간 내 “사실상 고정”으로 굳지 않음(구성 변화율이 0에 수렴하면 경고)
- **Liquidity/Tradability Gate**
  - 포트 종목의 거래대금/스프레드 지표가 하한/상한을 만족(미충족 시 강제 제외)
- **성과 Gate**
  - lockbox_mean **유지(≥0.9×Champion)** 또는 worst_mdd **개선(절대값 ≤ -0.075 목표)** 중 하나 충족
- **기대 관측치**
  - 진짜면 유니버스가 바뀌어도 성능이 크게 무너지지 않고, 비용/충격에 더 안정적

# 4) (레짐/노출 관리) **QQQ·XLV를 ‘관측지표’로만 쓰는 레짐-게이팅 + 변동성 타겟팅**
### (a) 왜 필요한지
- 후보가 fold14/worst MDD가 크게 악화(-0.10~-0.11)된 전례가 있어, **레짐 전환에서 손실이 커지는 구조**일 가능성이 큼.
- ETF를 매매하지 않고도(QQQ/XLV는 관측만) **시장/섹터 레짐을 감지해 포지션 사이징을 조절**할 수 있음.

### (b) 위험/부작용
- 게이팅이 과하면 기회 손실(수익 상단이 깎임).
- 레짐 분류가 불안정하면 매매 빈도만 늘 수 있음(턴오버 증가).

### (c) 최소 실험 2~3개 → **단일 패치 실험에서 게이트 강도 2수준 비교**
**[실험 정의] Patch E4: `RegimeGate(QQQ,XLV) + VolTarget`**
- 레짐 입력(관측): QQQ 수익률/변동성, XLV 상대강도(예: XLV/QQQ 모멘텀), 시장 변동성(가능하면 VIX/QQQ realized vol)
- 서브테스트:
  1) **Soft Gate**: 위험구간에서 목표 노출 100%→60%
  2) **Hard Gate**: 위험구간에서 100%→30% (또는 현금 비중 확대)
  3) **Vol Target**: 포트 변동성 목표로 레버리지/노출 스케일

### (d) PASS 조건(게이트)
- **Drawdown Gate**
  - worst_mdd **절대값 10~20% 개선**(예: -0.081 → -0.070~-0.073 수준 목표)
- **Return Preservation Gate**
  - lockbox_mean **≤10% 이상 훼손 금지**(Champion 대비 ≥0.9×)
- **기대 관측치**
  - 위험 레짐에서 손실 꼬리가 줄고, 정상 레짐에서 참여율은 크게 떨어지지 않음

# 5) (운영 리스크) **48시간 자동 루프 안정화: 재현성/롤백/이상탐지(데이터 갭·NaN·주문불가)**
### (a) 왜 필요한지
- 자동 `--select-best`는 운영상 “안전장치 없는 자동 배포”가 되기 쉽습니다.
- 데이터 결측/분할조정 오류/휴장 캘린더 어긋남은 **조용히 성능을 훼손하거나 가짜 개선을 만들 수 있음**.

### (b) 위험/부작용
- 게이트가 빡세지면 실험 통과율이 떨어져 탐색 속도가 느려질 수 있음.
- 로그/리포트 증가로 실행 시간이 늘 수 있음.

### (c) 최소 실험 2~3개 → **단일 패치 실험에서 ‘운영 게이트’ 자동 리포트**
**[실험 정의] Patch E5: `OpsGuardrails + Determinism + AutoRollback`**
- 서브테스트(동일 러닝):
  1) **Determinism**: 같은 seed/환경에서 2회 연속 실행 시 핵심 지표 차이 허용오차 내
  2) **Data Health**: NaN/Inf 비율, 비정상 갭, split/dividend 이벤트 처리 누락 체크
  3) **Rollback Rule**: 새 best가 Champion 대비 lockbox_mean이 낮거나 worst_mdd가 악화 시 자동 “승격 금지”

### (d) PASS 조건(게이트)
- **재현성 Gate**: tuning_mean/lockbox_mean 차이 **절대 1~2% 이내**(프로젝트 특성에 맞게 허용오차 설정)
- **데이터 건전성 Gate**: 결측/이상치가 임계치 초과 시 FAIL
- **승격 Gate**: (lockbox_mean ≥ Champion×1.02) **또는** (worst_mdd 개선 ≥ 15%) 둘 중 하나 충족 못하면 승격 금지
- **기대 관측치**
  - “조용한 고장”이 실험 결과에 반영되기 전에 차단되고, Champion이 안정적으로 유지됨

# 성능이 안 움직일 때: 원인 분해 아이디어(트리거/적용/노출/비용/레짐) — 실행형 진단 트리

## A. Trigger(신호 발생) 문제
- **명령형 진단**
  - 신호 발생 빈도(일/주)와 “무신호 기간” 길이를 시계열로 출력
  - 예측 스코어 분포(엔트로피/분산)가 학습기간 대비 잠겼는지(스코어가 0 근처로 몰림) 확인
- **관측 포인트**
  - 신호가 너무 적으면: 수익/리스크 모두 정체(거래가 안 일어남)
  - 신호가 너무 많으면: 턴오버↑ → 비용에 눌림

## B. Apply(적용/리밸런스) 문제
- **명령형 진단**
  - 리밸런스 타이밍(장중/종가/익일시가)별 성능을 동일 리포트에서 비교
  - “예측 생성 시점”과 “체결 시점” 사이 데이터 참조가 섞였는지(PIT) 재검증
- **관측 포인트**
  - 종가 체결 가정이 실제보다 과대평가면 성능이 정체/붕괴

## C. Exposure(노출/포트 구성) 문제
- **명령형 진단**
  - 포트 **Gross/Net 노출**, 상위 1~2종목 기여도, 섹터(Tech vs Health) 비중을 시간축으로 출력
  - QQQ/XLV 상관·베타(관측지표)로 “사실상 시장추종”이 됐는지 확인
- **관측 포인트**
  - 수익이 안 나는 기간에 특정 종목/섹터로 쏠림이 커지면 리스크만 커짐

## D. Cost(비용/충격) 문제
- **명령형 진단**
  - 거래별 예상비용 vs 실현비용(모델) 분해: spread/impact/수수료 항목별 기여도 출력
  - ADV 대비 주문비율 분포를 출력해 “충격구간 거래”가 많은지 확인
- **관측 포인트**
  - gross는 유지되는데 net만 정체면 비용 모델/턴오버가 1순위 원인

## E. Regime(레짐) 문제
- **명령형 진단**
  - QQQ 변동성/추세, XLV 상대강도 구간별로 성과를 **레짐 매트릭스(2×2)**로 출력
  - 레짐별 MDD/승률/평균보유기간을 분해
- **관측 포인트**
  - 특정 레짐(예: QQQ 고변동+하락)에서만 깨지면 E4 같은 게이팅이 정답 방향

## 요약: 24~48시간 “움직이는” 우선순위
- **먼저 안전장치(E1/E2/E5)로 누수·비용·운영 리스크를 봉인**  
- 그 다음에만 **유니버스 현실화(E3)**와 **레짐 기반 MDD 절감(E4)**로 성능/안정성 트레이드오프를 조정  
- 승격은 “평균”이 아니라 **worst_mdd와 비용 강건성**을 통과한 것만 허용
