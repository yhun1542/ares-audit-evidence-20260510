## 1. 우선순위 TOP-5 실험 (실행 가능 Patch)

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### EXP-1: Lockbox Stagnation 원인 분해
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

| 항목 | 내용 |
|------|------|
| **왜 필요** | lockbox_mean 1.329 고정 → 신규 모듈이 OOS에 기여 0, 누수/과적합 가능성 |
| **위험** | 분석 시간만 소모, 실제 fix 미도출 |
| **실험** | |

```
EXP-1a: Attribution Decomposition
────────────────────────────────
정의: 각 모듈별 lockbox 기여도(Shapley-like) 계산
게이트: 기여도 상위 3 모듈 → 기여도 합 > 80%
기대치: 특정 1~2모듈이 전체 alpha 독점 확인

EXP-1b: Tuning-Only Module Pruning
────────────────────────────────
정의: tuning에서만 활성화된 모듈 제거 후 lockbox 재측정
게이트: lockbox_mean 변화 < 1%
기대치: 제거해도 OOS 불변 → 해당 모듈 = pure overfit

EXP-1c: Timestamp Leakage Audit
────────────────────────────────
정의: feature 생성 시점 vs trade 시점 gap 검증
게이트: gap < 0 인 row 발견 시 FAIL
기대치: 0건 (clean) 또는 즉시 bug fix
```

**PASS 조건**: 1a에서 독점모듈 식별 + 1b에서 overfit 모듈 ≥1 제거 + 1c 클린

## 3. 성능 정체 시 원인 분해 트리

```
성능 불변
├─ [트리거 실패] 신호 발생 빈도 확인
│   └─ metric: trades_per_month < 2 → 트리거 과민/과둔
│
├─ [적용 실패] 신호 → 실제 포지션 전환율
│   └─ metric: signal_to_trade_ratio < 70% → 실행 로직 버그
│
├─ [노출 부족] 포지션 크기/기간 불충분
│   └─ metric: avg_position_days < 5 OR avg_weight < 3% → alpha 희석
│
├─ [비용 침식] gross → net 변환 시 손실
│   └─ metric: gross_return - net_return > 15% → turnover 과다
│
└─ [레짐 미스매치] 백테스트 구간 vs 현재 시장 괴리
    └─ metric: rolling_12m_sharpe 추세 하락 → 전략 decay
```
