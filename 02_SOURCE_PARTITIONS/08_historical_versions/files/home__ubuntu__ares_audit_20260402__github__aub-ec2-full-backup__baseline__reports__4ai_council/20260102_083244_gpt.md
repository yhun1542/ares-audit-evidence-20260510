## 24~48시간 TOP5 우선순위(코드/아키텍처/전략) — 명령형 체크리스트

1) **누수(lookahead)·정렬(as-of)·체결지연(1D lag) 감사 패치 적용**
- **필수 이유**: OOS가 “그럴듯하게” 보일 때 가장 먼저 무너지는 지점이 시간정렬/동일봉 체결/미래 데이터 참조임.
- **위험/부작용**: 성능 급락(정상). 기존 챔피언이 “착시”였다는 결론이 나올 수 있음.
- **실험/패치**: **[E1]**로 통합 실행
- **PASS 조건**: (아래 E1 참조) 누수 의심 패턴 제거 후에도 OOS가 의미 있게 유지(특히 oos_min 방어).

2) **비용(수수료·스프레드·슬리피지·임팩트) 미반영 제거 + 회전율 게이트 도입**
- **필수 이유**: Tech/Healthcare 대형주라도 잦은 리밸은 비용에 취약. 비용 미반영은 과최적화와 사실상 동급.
- **위험/부작용**: 거래 횟수 줄이면 단기 수익률 하락 가능. 모델이 “덜 잘 맞는 것처럼” 보일 수 있음.
- **실험/패치**: **[E2]**
- **PASS 조건**: 비용 반영 후에도 net 성능이 생존 + turnover가 운영 가능한 수준.

3) **서바이버십/유니버스 정의 고정(Tech+Healthcare 8~14) + delist 처리 점검**
- **필수 이유**: “현재 살아남은 종목만” 쓰는 순간 OOS가 과대평가. 특히 헬스케어는 이벤트로 드랍/합병도 잦음.
- **위험/부작용**: 유니버스 축소 시 분산 저하, 특정 메가캡 편향 증가.
- **실험/패치**: **[E3]**
- **PASS 조건**: 유니버스/서바이버십 변경에도 성능이 과도하게 붕괴하지 않음(구조적 착시가 아님).

4) **레짐(리스크온/오프) 게이트: ETF는 “매매 금지”, 관측지표로만 사용**
- **필수 이유**: Tech/Healthcare는 금리/리스크 프리미엄 레짐에 민감. 단일 신호로는 oos_min(꼬리)이 깨지기 쉬움.
- **위험/부작용**: 게이트가 과도하면 기회 손실(under-invest)·타이밍 실패.
- **실험/패치**: **[E4]**
- **PASS 조건**: oos_min 및 최대낙폭(산출 필수)이 개선되거나, 최소한 tail 악화 없이 안정화.

5) **운영 리스크 제거: 결과물/메트릭 산출 누락(worst_mdd=None, file empty) 즉시 차단**
- **필수 이유**: “worst_mdd=None”은 리스크 관리가 공백이라는 뜻. 자동루프에서 가장 위험한 형태(모르고 돈을 걸게 됨).
- **위험/부작용**: 없음(오히려 실행 안정성 증가). 다만 기존 비교가 끊길 수 있어 마이그레이션 필요.
- **실험/패치**: E1~E4 공통 “실행 게이트”로 포함(아래 공통 게이트)
- **PASS 조건**: 매 실행마다 아티팩트/메트릭/재현성 해시가 남고, MDD/턴오버/비용이 항상 산출됨.

## 48시간 자동 루프용 “실행 가능한 패치/실험” (총 4개로 제한)

아래 4개만 돌리되, 각 실험은 **(1) 실험 정의 → (2) 게이트 → (3) 기대 관측치**로 고정 운영.

### [E1] 누수/정렬/체결지연(1D lag) 강제 패치
1) **실험 정의**
- 모든 피처/라벨을 “decision_time 기준 as-of join”으로 재정렬.
- 시그널 생성 시점 T의 정보로 **주문은 T+1 시가(또는 VWAP proxy)**에 체결되도록 강제(동일봉 종가 체결 금지).
- “shift 테스트”: 주요 피처를 +1일 시프트했을 때 성능이 비정상적으로 올라가는지(누수 신호) 자동 리포트.

2) **게이트(실패 시 즉시 롤백)**
- 실행 산출물 강제: `file`/run artifact 경로 non-empty, `worst_mdd` 계산 완료(Null 금지), turnover/cost 리포트 생성.
- **누수 의심 게이트**:  
  - 동일봉 체결 vs 1D lag 성능 괴리가 과도(예: oos_mean이 30%+ 급락)하면 “누수 가능성 HIGH”로 플래그하고 다음 실험(E2~E4)보다 먼저 원인 로그를 남김.
- 데이터 타임스탬프 무결성: feature_timestamp <= decision_timestamp 위반 0건.

3) **기대 관측치**
- 대개 성능 하락(정상). 대신 **oos_min이 더 “현실적인 수준”으로 재측정**되고, 과도한 샤프/승률이 완화됨.


### [E2] 거래비용/회전율(턴오버) 반영 + 비용 기반 게이트
1) **실험 정의**
- 비용모델(보수적으로 시작): `commission + half-spread + slippage_bps * (daily_turnover)` 형태.  
  - 예: 대형주 기준 고정 bps(예: 1~5bps) + 거래비용 상한/하한.
- **턴오버 상한 게이트**: 리밸 빈도/변동 시 포지션 변경폭 제한(예: 일 변경 총합 <= X).

2) **게이트**
- net 성능(비용 차감 후) 리포트가 gross와 함께 항상 산출.
- turnover가 운영 상한 초과 시 FAIL.
- 비용 반영 후 oos_mean이 gross 대비 급락하더라도, “비용이 원인임”을 분해할 수 있도록 **거래 PnL vs 보유 PnL**을 분리 리포트.

3) **기대 관측치**
- gross는 유지되나 net이 크게 깎이면 “전략이 비용 먹는 구조”임을 빠르게 확정.
- 턴오버 제한 후 oos_min이 개선되면 과최적화/노이즈 트레이딩 가능성이 줄었다는 신호.


### [E3] 서바이버십/유니버스 고정(Tech+Healthcare 8~14) + delist/합병 처리 점검
1) **실험 정의**
- **유니버스를 명시적으로 고정**(예: Tech 4~7 + Healthcare 4~7, 합계 8~14).  
  - 기준: 대형/유동성 높은 US 상장 종목(ETF 매매 금지).
- 데이터에 **delisted ticker 처리(가격 0/NaN, 마지막 거래일 이후 리턴 처리)** 규칙을 명문화.
- “현재 구성만”과 “기간 중 존재했던 구성 포함” 간 성능 차이를 비교해 서바이버십 편향을 측정.

2) **게이트**
- 유니버스 목록과 각 종목의 유효 데이터 구간을 artifact로 저장(재현성).
- delist 이벤트/상장폐지 구간에서 리턴 계산이 비정상(무한대/결측 방치)이면 FAIL.

3) **기대 관측치**
- 서바이버십이 있었으면 oos_mean이 과거 대비 눈에 띄게 하락.  
- 유니버스 고정 후에도 성능이 유지되면 “운 좋게 살아남은 종목 덕”이 아니라 구조적 신호 가능성 상승.


### [E4] 레짐 게이트(ETF는 지표만): 노출(exposure) 자동 조절로 꼬리 방어
1) **실험 정의**
- 매매 대상은 개별주(8~14)로 유지.  
- 레짐 관측지표로만 ETF 사용(예: QQQ/XLK, XLV, IHI, TLT 등)하여  
  - “리스크오프”에서 **목표 노출을 낮추거나(예: 0.2~0.4)**  
  - “리스크온”에서만 **기존 노출(예: 0.5~0.85)** 허용.
- 현재 챔피언 노출 min/max가 0.47/0.84로 고정에 가까우므로, **노출의 ‘하방 자유도’**를 열어 tail을 줄이는 실험.

2) **게이트**
- 노출 규칙이 신호를 “사후적으로” 보고 결정하지 않도록, 레짐 지표도 1D lag로 적용(E1 규칙 준수).
- worst_mdd 산출 필수 + oos_min 악화 시 FAIL.

3) **기대 관측치**
- oos_mean이 소폭 희생되더라도 **oos_min 및 MDD가 개선**되면 운영 가능한 전략으로 진화.
- 반대로 성능이 그대로인데 변동성만 줄면 “운영 리스크 절감” 성과로 채택 가능.

## 공통 PASS 기준(4개 실험 모두에 적용)
- 산출물 완전성: `worst_mdd != None`, turnover/cost/hold-vs-trade PnL 분해 리포트 존재, run_hash+lane_hash+데이터 스냅샷 해시 기록.
- 누수 위반 0건(타임스탬프/체결지연 규칙).
- 비용 반영 net 기준으로 의사결정(“gross 개선”만으로 승격 금지).
- tail 기준 강화: **oos_min 방어**(개선 또는 악화폭 제한) + MDD 측정/상한 관리.

## 성능이 안 움직일 때(또는 흔들릴 때) 원인 분해 아이디어 — 트리거/적용/노출/비용/레짐 순서

아래는 “진단 순서” 자체를 자동 리포트로 고정하라는 체크리스트(질문 금지, 실행만).

1) **트리거(신호 발생) vs 적용(체결/리밸) 분해**
- 신호가 자주 바뀌는데 체결은 거의 없으면: 게이트/턴오버 제한이 과도.
- 신호는 안정적인데 PnL이 출렁이면: 포지션 사이징/노출이 문제.
- 신호-리턴 상관을 **0D(동일봉), 1D, 2D lag별**로 리포트해서 “신호 decay” 확인.

2) **노출(exposure) 분해**
- 현재 노출이 0.47~0.84로 꽤 높음 → 손실 국면에서 방어가 어려움.  
- “노출이 성과를 대부분 설명”하는지 확인:  
  - 동일 전략을 **항상 0.5 노출 고정** vs **동적 노출** 비교  
  - 성과 차이가 거의 없으면 “신호가 아니라 베타” 가능성.

3) **비용(cost) 분해**
- net PnL = 보유 PnL + 거래 PnL − 비용을 항상 분리.  
- 성능이 정체면 보통 두 케이스:
  - (A) 보유 PnL은 좋은데 비용이 갉아먹음 → 턴오버/리밸 규칙 수정
  - (B) 보유 PnL 자체가 약함 → 신호 무의미/레짐 미스

4) **레짐(regime) 분해(ETF는 관측지표)**
- QQQ/XLK 강세·약세, 금리(TLT proxy), 변동성(VIX proxy) 구간으로 샤프/승률을 조건부로 쪼개 리포트.
- 특정 레짐에서만 수익이면: 레짐 게이트(E4)가 “성능 정체”를 “운영 가능”으로 바꾸는 가장 빠른 길.

5) **과최적화/서바이버십 분해**
- CV 폴드별 성능 분산 + “특정 종목 1~2개가 대부분 기여”하는지 기여도 리포트.
- 유니버스/기간을 바꿨을 때 성능이 급변하면: 구조가 아니라 우연(또는 누수/서바이버십).

## 즉시 적용(운영 리스크 차단) 하드 게이트 3개
- `worst_mdd` 미산출이면 **거래/승격/챔피언 업데이트 금지**
- 비용 모델(net) 미산출이면 **성과 비교 금지**
- 체결지연(1D) 미적용이면 **누수 의심으로 자동 FAIL 처리**

위 4개 실험(E1~E4)을 48시간 루프에 그대로 넣고, PASS 조건을 만족하는 변경만 챔피언에 반영하라.
