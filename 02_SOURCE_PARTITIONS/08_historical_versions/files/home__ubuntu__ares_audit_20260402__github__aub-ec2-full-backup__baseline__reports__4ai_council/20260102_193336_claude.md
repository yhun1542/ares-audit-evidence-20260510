## 1. 우선순위 TOP 5 액션

### P1. Degenerate Fold 원인 분해
```
WHY: 40% 폴드 실패 = 전략 자체의 robustness 문제
RISK: 원인 오진 시 잘못된 방향으로 수정
```

**실험 체크리스트:**
- [ ] **EXP-1A**: 폴드 1,2,3,8의 시장 레짐 태깅 (VIX>25, SPY 하락>10%, 금리 상승기)
- [ ] **EXP-1B**: 정상 폴드(4,5,6,7,9,10) vs 실패 폴드의 종목 노출 diff 추출
- [ ] **EXP-1C**: 실패 폴드에서 시그널 발화 횟수 vs 정상 폴드 비교

**GATE 조건:**
```python
# PASS: 레짐 분류 완료 + 실패 원인 1개 이상 특정
degenerate_cause_identified = True
regime_coverage = len(identified_regimes) >= 2
```

**기대 관측치:** 실패 폴드가 특정 레짐(예: 2022 금리인상기)에 집중되어 있으면 레짐 필터 추가, 무작위 분포면 시그널 자체 재검토

---

### P2. MDD 계산 파이프라인 복구
```
WHY: 리스크 메트릭 없이 전략 비교 불가능
RISK: 낮음 (인프라 수정)
```

**실험 체크리스트:**
- [ ] **EXP-2A**: `backtest_core.py`에서 MDD 계산 로직 추적, None 반환 지점 특정
- [ ] **EXP-2B**: 일별 NAV 시계열 → rolling MDD 계산 유틸 추가
- [ ] **EXP-2C**: 폴드별 MDD 분포 출력 추가

**GATE 조건:**
```python
# PASS: 모든 폴드에서 MDD 수치 출력
all(fold['mdd'] is not None for fold in results['folds'])
```

**기대 관측치:** MDD 분포 확인 시 degenerate 폴드가 MDD > 30%일 가능성 높음

---

### P3. Rebalance 로그 파이프라인 정상화
```
WHY: 실제 매매 시점/비용 검증 불가 → 백테스트 신뢰도 0
RISK: 로그 포맷 변경 시 기존 분석 스크립트 호환성
```

**실험 체크리스트:**
- [ ] **EXP-3A**: 백테스트 실행 시 `rebalance.jsonl` 출력 강제 활성화
- [ ] **EXP-3B**: 로그 스키마 정의 (`date`, `ticker`, `action`, `shares`, `price`, `cost`)
- [ ] **EXP-3C**: `aub_rebalance_pinpoint.py` 입력 경로 하드코딩 제거 → config 기반

**GATE 조건:**
```python
# PASS: pinpoint 도구가 에러 없이 diff 출력
rebalance_pinpoint_exit_code == 0
len(parsed_trades) > 0
```

**기대 관측치:** 거래 빈도, 회전율, 슬리피지 추정치 확보

---

### P4. OOS Min ≈ 0 원인 분해
```
WHY: 최악 폴드가 본전 = 엣지 불안정
RISK: 과최적화 확인 전 파라미터 조정 시 상황 악화
```

**실험 체크리스트:**
- [ ] **EXP-4A**: 최악 폴드(OOS=-0.026) 단독 실행 → 월별 수익 분해
- [ ] **EXP-4B**: 해당 폴드 기간의 벤치마크(SPY) 대비 상관관계
- [ ] **EXP-4C**: 시그널 precision/recall 해당 폴드만 추출

**GATE 조건:**
```python
# PASS: 수익 0의 원인 특정 (시그널 미발화 vs 발화했으나 손실)
signal_fired = trade_count > 10
if signal_fired:
    cause = "signal_wrong"
else:
    cause = "signal_not_fired"
```

**기대 관측치:** 시그널이 발화했으나 틀렸으면 시그널 로직 문제, 발화 안했으면 트리거 조건 과적합

---

### P5. 비용 모델 현실화 점검
```
WHY: 거래비용 미반영 시 OOS 수치 무의미
RISK: 비용 추가 시 수익이 음수 전환 가능 (좋은 발견)
```

**실험 체크리스트:**
- [ ] **EXP-5A**: 현재 비용 설정 값 추출 (`slippage`, `commission`)
- [ ] **EXP-5B**: 비용 0 → 10bp → 20bp 단계별 OOS 변화 측정
- [ ] **EXP-5C**: 연간 회전율 계산 → 비용 민감도 추정

**GATE 조건:**
```python
# PASS: 20bp 비용에서도 OOS > 1.0 유지
oos_with_20bp_cost > 1.0
turnover_annual < 12  # 월 1회 이하
```

**기대 관측치:** 비용 20bp 적용 시 OOS가 50% 이상 감소하면 전략이 비용에 취약

## 3. 48H 자동 루프 명세

```yaml
# autopilot_48h.yaml
loop_interval: 6h
max_iterations: 8

experiments:
  - id: exp_fold_regime_tag
    script: tools/fold_regime_tagger.py
    gate: regime_coverage >= 2
    on_fail: HALT_AND_ALERT
    
  - id: exp_mdd_fix
    script: patches/mdd_calculator_patch.py
    gate: all_folds_have_mdd == True
    on_fail: RETRY_ONCE
    
  - id: exp_rebalance_log
    script: patches/rebalance_logger_patch.py
    gate: pinpoint_exit_code == 0
    on_fail: RETRY_ONCE
    
  - id: exp_cost_sensitivity
    script: experiments/cost_sweep.py
    params: [0, 10, 20]  # bps
    gate: oos_20bp > 1.0
    on_fail: FLAG_COST_SENSITIVE
    
  - id: exp_worst_fold_dissect
    script: tools/fold_dissector.py
    params: {fold_id: "min_oos"}
    gate: cause_identified == True
    on_fail: MANUAL_REVIEW

alerts:
  - condition: degenerate_folds > 4
    action: PAUSE_ALL_EXPERIMENTS
  - condition: oos_mean < 1.0
    action: ROLLBACK_TO_BASELINE
```
