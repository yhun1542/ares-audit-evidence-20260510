| 신호 | 값 | 판정 |

## 1. 우선순위 TOP-5 실행 패치

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### PATCH-1: 퇴화 폴드 원인 분해 (최우선)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- 4/10 폴드가 퇴화 → 전략이 특정 시장 레짐에서 완전 무력화
- OOS mean 3.32가 실제론 **6개 폴드에서만** 나온 수치 → 과대 추정

**(b) 위험/부작용**
- 퇴화 폴드 제거 시 survivorship bias 발생 가능
- 폴드 수 줄이면 통계 검정력 저하

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| D1-a | 퇴화 폴드 [1,2,3,8] 기간 추출 → 시장 레짐 태깅 (drawdown/sideways/rally) | 자동 | 레짐별 퇴화 비율 |
| D1-b | 퇴화 폴드에서 `exposure == 0` 비율 측정 | exposure_zero > 80% | 시그널 미발생 vs 필터 과잉 구분 |
| D1-c | 시그널 임계값 0.3 → 0.2 완화 후 퇴화 폴드 재실행 | degenerate ≤ 2 | 비퇴화 시 OOS 변화 |

**(d) PASS 조건**
```
degenerate_folds ≤ 2 AND oos_min > 0 AND exposure_min > 0.05
```

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### PATCH-2: MDD 계산 파이프라인 복구
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- `worst_mdd: None` → 리스크 게이트 작동 불가
- 48H 루프에서 MDD 체크 없이 승격하면 **꼬리 위험** 무방비

**(b) 위험/부작용**
- MDD 계산 버그 시 false reject 증가
- 일별 vs 분봉 기준 MDD 불일치 가능

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| D2-a | `backtest_engine.py`에서 MDD 계산 로직 단위 테스트 추가 | assert worst_mdd is not None | MDD 값 반환 확인 |
| D2-b | 챔피언 JSON에 `equity_curve` 필드 존재 여부 확인 | 필드 존재 | 곡선 있으면 MDD 후계산 가능 |

**(d) PASS 조건**
```
worst_mdd is not None AND worst_mdd > -0.25
```

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### PATCH-3: 로깅/재현성 파이프라인 수리
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- `rebalance.csv` 파싱 실패 → 어떤 종목이 언제 거래됐는지 추적 불가
- `lane_hash`, `run_hash` = None → 실험 재현 불가능

**(b) 위험/부작용**
- 로깅 오버헤드로 백테스트 속도 저하 (5~10%)
- 디스크 사용량 증가

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| D3-a | `rebalance_pinpoint.py` 입력 경로 하드코딩 제거 → config 기반으로 수정 | 파일 로드 성공 | Error 0건 |
| D3-b | 모든 실험 출력에 `run_hash = sha256(config + data_version)` 자동 삽입 | hash is not None | 재현성 확보 |

**(d) PASS 조건**
```
rebalance.csv 로드 성공 AND run_hash is not None
```

### PATCH-4: 비용 모델 현실화 검증
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- OOS mean 3.32인데 실제 운용 시 **슬리피지 + 스프레드 + 세금** 미반영 가능
- exposure_max 84% → 높은 회전율 시 비용 누적 심각

**(b) 위험/부작용**
- 비용 과다 반영 시 모든 전략 reject 위험
- 종목별 유동성 차이 반영 어려움

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| D4-a | 현재 비용 설정 출력: `slippage_bps`, `commission_bps` | 설정값 확인 | 현재 가정치 파악 |
| D4-b | 비용 2x 스트레스 테스트 (슬리피지 10bps → 20bps) | oos_mean > 1.5 | 비용 민감도 측정 |
| D4-c | 연간 회전율 계산 (`turnover = Σ|Δweight|`) | turnover < 12x | 과다 매매 여부 |

**(d) PASS 조건**
```
oos_mean(cost_2x) > 0.5 * oos_mean(base) AND turnover < 15x/year
```

### PATCH-5: 시그널 누수 점검 (Forward Leak)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- OOS mean 3.32 but degenerate 40% → **"잘 맞는 폴드만 잘 맞음"** 패턴
- 피처 계산에서 미래 데이터 참조 가능성

**(b) 위험/부작용**
- 누수 발견 시 전체 챔피언 무효화 필요
- 점검 시간 소요 (수동 코드 리뷰)

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| D5-a | 타겟 변수 시점 +1일 shift 후 재실행 | oos_mean 급락 없음 | 급락 시 누수 의심 |
| D5-b | 랜덤 셔플된 날짜로 백테스트 | oos_mean ≈ 0 | 0 아니면 누수 확정 |

**(d) PASS 조건**
```
oos_mean(shuffle) < 0.5 AND oos_mean(shift+1) > 2.0
```
