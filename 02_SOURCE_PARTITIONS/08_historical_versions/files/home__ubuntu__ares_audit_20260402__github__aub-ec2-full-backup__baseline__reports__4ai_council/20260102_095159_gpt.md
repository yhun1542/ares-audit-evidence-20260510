## 24~48시간 TOP5 우선순위(코드/아키텍처/전략) — **명령형 체크리스트**
> 우선순위는 **누수 → 과최적화 → 서바이버십 → 비용 미반영 → 운영 리스크** 순으로 강제 정렬.  
> 전제: **미국주식 only**, **Tech+Healthcare 8~14종목**, **ETF는 관측지표만(매매 금지)**, 48시간 자동루프에서 바로 돌릴 수 있는 형태.

---

# 1) 시간누수(Leakage) / as-of 무결성 “즉시” 봉인
### (a) 왜 필요한지
- 현재 Champion이 튜닝/락박스 평균은 높지만, 이런 구조에서 **가장 흔한 원인**이 “as-of 날짜가 어긋난 피처/라벨” 또는 “룩어헤드 결측처리”입니다.
- 누수는 **튜닝 평균↑, 락박스 min/분산↓** 형태로도 나타나며, 장기적으로 운영에서 바로 붕괴합니다.

### (b) 위험/부작용
- 누수를 제거하면 성능이 **단기 급락**할 수 있음(정상).
- 데이터 로딩/피처 계산이 느려질 수 있음(as-of join, embargo 등).

### (c) 최소 실험(2개) — 48시간 루프용
**실험 1: Feature “1-bar/1-day shift” 누수 탐지**
- (1) 실험 정의: 모든 피처를 `shift(+1)` 강제(오늘 의사결정에 오늘 종가/재무/지표가 섞이면 성능이 급락해야 정상적으로 탐지됨)
- (2) 게이트: 튜닝/락박스 **Sharpe(또는 mean) 급락 폭**을 기록하고, 급락이 과도하면 해당 피처군을 누수 후보로 플래그
- (3) 기대 관측치:  
  - **정상(누수 적음)**: 성능 소폭 하락/유사  
  - **비정상(누수 큼)**: 튜닝/락박스가 비정상 급락

**실험 2: Purged/Embargo CV 강제(라벨 중첩 제거)**
- (1) 실험 정의: 학습/검증 경계에 **purge + embargo**(예: 예측지평 H, embargo=H~2H) 적용
- (2) 게이트: 기존 CV 대비 락박스 min이 개선/유지되는지 확인(과최적화 억제 목적)
- (3) 기대 관측치: 튜닝 평균은 내려가도 **락박스 min/최악폴드 안정성↑**

### (d) PASS 조건
- 누수 탐지 실험에서 “의심 피처”가 명확히 드러나거나(급락), 반대로 shift에도 과도한 급락이 없고(정상),  
- Purged/Embargo 적용 후 **lockbox_min ≥ 0**, **worst_mdd 악화 없음(±0.01 이내)**.

# 2) 서바이버십/유니버스 바이어스(8~14 Tech+HC) 고정 규칙화
### (a) 왜 필요한지
- “현재 상장/현재 섹터분류/현재 시총”으로 과거 유니버스를 만들면 **서바이버십**이 생깁니다.
- 특히 8~14개 소수 종목에서 유니버스 편향은 성능을 크게 왜곡합니다.

### (b) 위험/부작용
- 과거에 사라진 종목/티커 변경/합병이 들어오면 데이터 결측/매핑 이슈 증가.
- 성능 하락 가능(정상).

### (c) 최소 실험(2개)
**실험 1: “as-of 유니버스” 생성 패치**
- (1) 실험 정의: 매 리밸런스 시점 t에 대해  
  - 섹터(Tech/Healthcare) 분류, 시총/유동성 필터를 **t 시점 기준(as-of)** 으로만 결정  
  - “현재 기준” 분류/시총 사용 금지
- (2) 게이트: 유니버스 변경 로그(편입/편출), 결측률, 룰 위반(종목 수 8~14 유지) 체크
- (3) 기대 관측치: 유니버스가 과거로 갈수록 “현재 스타” 편중이 완화됨

**실험 2: 유니버스 고정 vs 동적(둘 다 8~14 유지) A/B**
- (1) 실험 정의:  
  - A: 시작시점에 선정된 8~14를 고정(단, 상폐 시 처리 규칙 필요)  
  - B: as-of 동적 선정
- (2) 게이트: 락박스 min, turnover, 상폐/결측 처리 안정성 비교
- (3) 기대 관측치: 동적은 현실성↑, 고정은 안정성↑ (둘 중 운영가능한 쪽 선택)

### (d) PASS 조건
- **룰 위반 0건(8~14 유지)**, 결측/상폐 처리로 인한 런타임 실패 0건,  
- lockbox_mean이 Champion 대비 **-10% 이내**, 대신 **lockbox_min 개선 또는 worst_mdd 개선** 중 1개 이상 달성.

# 3) 비용/체결(슬리피지·스프레드·턴오버) “락박스에 선반영”
### (a) 왜 필요한지
- 지금 지표가 좋더라도 비용 미반영이면 운영 성과는 쉽게 역전됩니다.
- Tech/HC 8~14 집중 포트는 리밸런스가 잦으면 **슬리피지 + 스프레드**가 치명적입니다.

### (b) 위험/부작용
- 비용 반영 후 성능 하락 가능(정상).
- 너무 보수적 비용모델은 유망 전략을 과도하게 제거할 수 있음.

### (c) 최소 실험(2개)
**실험 1: 거래비용 모델 2단(기본/스트레스) 동시 리포팅**
- (1) 실험 정의:  
  - 기본: bps 기반(예: 5~15bps) + 고정 커미션(옵션)  
  - 스트레스: 기본×2 + 체결지연(다음 바/다음 시가 체결)
- (2) 게이트: 순수익(비용후) 기준으로 champion/candidate 재평가
- (3) 기대 관측치: 튜닝은 내려가도 락박스가 “더 현실적으로” 수렴

**실험 2: Turnover cap / turnover penalty 도입**
- (1) 실험 정의: 일/주 단위 turnover 상한(예: 20~40%) 또는 목적함수에 turnover 패널티 추가
- (2) 게이트: turnover↓, lockbox_min↑ 여부
- (3) 기대 관측치: 평균은 소폭 감소, **최악 케이스/실전 안정성** 개선

### (d) PASS 조건
- “스트레스 비용모델”에서도 **lockbox_min > 0** 유지(또는 0 근처라도 worst_mdd 유의 개선),  
- turnover가 기준 대비 **유의미하게 감소(예: -20% 이상)**.

# 4) 레짐/리스크 게이팅(ETF는 관측지표만)으로 최악 MDD 방어
### (a) 왜 필요한지
- Last PASS candidate는 MDD가 더 얕음(≈ -0.04) → **리스크 제어가 성능 안정성에 기여**할 가능성이 큼.
- ETF 매매는 금지지만, **QQQ/XLV/IWM/SPY, VIX(가능시), TLT** 같은 “상태변수”로 리스크 오프를 거는 건 운영 리스크를 크게 낮춥니다.

### (b) 위험/부작용
- 게이트가 지나치면 “수익구간을 스킵”하여 평균 성과 하락.
- 레짐 신호가 누수/재계산 이슈를 만들 수 있음(반드시 as-of/종가 확정 이후 사용).

### (c) 최소 실험(2개)
**실험 1: 변동성 타게팅(포트폴리오 레버리지/노출 스케일)**
- (1) 실험 정의: QQQ 또는 포트 변동성(rolling)으로 목표 변동성 맞추기(노출 0~1 범위)
- (2) 게이트: worst_mdd 및 fold14_mdd 개선 여부
- (3) 기대 관측치: 평균은 약간 낮아져도 tail 손실 감소

**실험 2: Risk-off 게이트(관측 ETF 추세/크로스)**
- (1) 실험 정의: 예) QQQ < MA(200) 또는 QQQ 모멘텀 음수면 “현금(=포지션 축소)” 비중 확대  
  - 종목 매매는 계속하되 **총 익스포저만 줄임**
- (2) 게이트: 리스크오프 구간의 손실 압축 vs 기회손실 측정
- (3) 기대 관측치: 최악구간 방어, lockbox_min 개선 가능

### (d) PASS 조건
- champion 대비 **worst_mdd 개선(최소 +0.02p 이상; 예: -0.09 → -0.07 이하)**,  
- lockbox_mean 감소가 **-10% 이내**.

# 5) 운영 리스크(재현성/데이터 버전/실패 복구) 먼저 잠그기
### (a) 왜 필요한지
- 48시간 자동 루프에서 가장 큰 실전 장애는 “성능”이 아니라 **재현 불가/부분 실패/데이터 업데이트로 인한 회귀**입니다.
- 자동 선택(`--select-best`)은 특히 “데이터/시드가 바뀐 성능 착시”에 취약합니다.

### (b) 위험/부작용
- 개발 시간이 들고, 단기 성능은 그대로일 수 있음.
- 로그/아티팩트 저장량 증가.

### (c) 최소 실험(2개)
**실험 1: 결정론적 재현성(Seed/데이터 스냅샷) 강제**
- (1) 실험 정의: 동일 커밋+동일 데이터 해시에서 결과 해시(메트릭/선정 종목/거래) 동일해야 함
- (2) 게이트: 3회 연속 실행 결과가 완전 동일(허용오차 0)
- (3) 기대 관측치: “가끔 좋아지는 런”이 사라지고 신뢰도 상승

**실험 2: 결측/이상치/상폐 이벤트 주입(고장 주입 테스트)**
- (1) 실험 정의: 가격 NaN, 급락 스파이크, 거래정지(0 volume) 등을 인위 주입하여 파이프라인이 죽지 않게 함
- (2) 게이트: 예외 없이 종료 + 안전한 포지션 축소/스킵 동작 확인
- (3) 기대 관측치: 운영 중단 확률 급감

### (d) PASS 조건
- 48시간 루프에서 **실패 0회**, 결과 재현성 100%, 아티팩트(설정/데이터해시/결과) 완전 저장.

## 48시간 자동 루프에 “바로 붙이는” 실행 패치(3~5개로 제한)
아래 5개를 “패치 단위”로 고정하고, 각 패치는 위 실험들을 플래그로 온/오프 가능하게 구성:

1. `patch_asof_guard`: 피처/라벨 as-of 검증 + 1-step shift 옵션  
2. `patch_purged_cv`: purge+embargo CV 옵션  
3. `patch_universe_asof`: Tech/HC as-of 유니버스(8~14 유지)  
4. `patch_cost_turnover`: 비용모델(기본/스트레스) + turnover cap  
5. `patch_regime_gate`: ETF 관측지표 기반 노출 스케일/리스크오프

# 성능이 안 움직일 때: 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래 순서로 “관측 지표”를 쪼개서 **어디서 신호가 죽는지**를 분해합니다(질문 없이 실행 가능).

## 1) Trigger(신호 생성) 문제
- **진단 체크**
  - 예측 스코어 분산이 너무 작아졌는지(랭킹이 평평해짐)
  - 피처 상관이 급증(모두 같은 정보)
  - 라벨 분포/이벤트 빈도 변화
- **관측치**
  - 일자별 스코어 표준편차, 상위-하위 스프레드, IC(정보계수), hit-rate

## 2) Application(적용: 리밸런스/제약) 문제
- **진단 체크**
  - 8~14 제약 때문에 좋은 신호가 포트로 못 들어오는지
  - turnover cap이 과도해 신호 반영이 지연되는지
- **관측치**
  - “원하는 포지션 vs 실제 체결 포지션” 괴리(implementation shortfall)
  - 리밸런스당 변경비율, 체결지연 효과

## 3) Exposure(노출: 베타/섹터/팩터) 문제
- **진단 체크**
  - Tech/HC 내에서 특정 팩터(대형 성장/고밸류 등)에 쏠려 레짐에 취약한지
  - 시장 베타가 커져서 사실상 QQQ 추종이 된 건 아닌지
- **관측치**
  - SPY/QQQ에 대한 회귀 베타, 섹터/서브산업 비중, 상위 1~2종목 기여도

## 4) Cost(비용) 문제
- **진단 체크**
  - 총 수익은 있는데 거래비용이 다 깎는지
  - 특정 종목이 비용을 과도하게 발생시키는지
- **관측치**
  - Gross vs Net 갭, 종목별 turnover·비용 기여도, 스프레드/볼륨 기반 비용 추정

## 5) Regime(레짐) 문제
- **진단 체크**
  - 금리/변동성 레짐 전환에서 신호가 붕괴하는지
  - 리스크오프 게이트가 너무 늦거나 너무 잦은지
- **관측치**
  - 레짐별 성과 분해(상승/하락/횡보, 고/저 변동성), 게이트 on/off 구간의 손익 기여

## 마지막 정렬(실행 우선순위)
1) `patch_asof_guard` + shift 누수탐지  
2) `patch_purged_cv`  
3) `patch_universe_asof`  
4) `patch_cost_turnover`  
5) `patch_regime_gate`  

위 순서대로 48시간 루프에 태우면, “성능을 올리는 것”보다 먼저 **거짓 양성(누수/바이어스/비용착시)**을 제거하고, 그 다음에 **MDD/락박스 min 안정화**로 넘어갈 수 있습니다.
