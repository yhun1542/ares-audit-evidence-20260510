## 24~48시간 TOP5 우선순위(명령형 체크리스트)
> 원칙: **누수 → 과최적화 → 서바이버십 → 비용 미반영 → 운영 리스크** 순으로 먼저 잠그고, 그 다음에 알파를 만진다.  
> 아래 5개는 **총 5개의 “실행 가능한 patch/실험(#1~#5)”**로만 돌린다(케이스 폭발 방지).

---

# P1) 데이터 누수(lookahead) / 라벨-피처 시간정렬 먼저 봉인
### (a) 왜 필요한지
- 지금 Champion 성능이 높을수록, **아주 작은 시점 누수**가 평균을 과대추정할 위험이 커진다.
- 특히 테크/헬스케어에서 **어닝/가이던스/리비전/공시 데이터**는 timestamp가 흐릿하면 1~2일 누수로도 백테스트가 “깨끗해 보이게” 튄다.

### (b) 위험/부작용
- 누수 제거 후 성능이 하락할 수 있음(진짜 성능으로 수렴).
- 데이터 소스/피처가 “사용 불가”로 바뀌며 파이프라인이 깨질 수 있음(운영 리스크 동반).

### (c) 최소 실험(2~3개) → **실험 #1**로 통합
- (1) 피처별 **as-of timestamp 강제** + “t 시점에 관측 가능한 것만” 조인
- (2) 어닝/이벤트 피처는 **공식 발표 시간(장전/장후) 기준으로 다음 거래일 반영** 강제
- (3) 라벨 생성(미래수익률)과 피처 계산 사이 **embargo(예: 1 bar)** 강제

### (d) PASS 조건
- **데이터 누수 감사 로그가 0건**(금지된 미래 컬럼/조인) + 재현 가능(시드/버전 고정)
- 성능 조건(최소 방어선):  
  - lockbox_mean ≥ (champion_lockbox_mean - 0.35)  
  - worst_mdd ≤ (champion_worst_mdd + 0.01)  
  - (즉, “진짜로 누수 없는데도” 유지되면 강한 승리)

---

# P2) 서바이버십/유니버스 변동(상장폐지/티커 변경) 처리 고정
### (a) 왜 필요한지
- “미국주식 only + 8~14 종목 집중”은 **서바이버십 편향**에 특히 취약.  
  (좋은 종목만 남겨두면 MDD/수익이 과대평가)
- 티커 변경/합병/스핀오프는 조용히 누수/결측을 만든다.

### (b) 위험/부작용
- 과거 특정 종목이 빠지며 과거 트레이드 수가 줄어 성능이 떨어질 수 있음.
- 데이터 정합성 패치가 운영 복잡도를 올릴 수 있음.

### (c) 최소 실험 → **실험 #1, #5**로 통합
- (1) **point-in-time universe 스냅샷**(날짜별 유니버스) 적용
- (2) delist 리턴/합병 이벤트 처리를 명시(가능하면) 또는 최소한 “거래 불가”로 반영
- (3) 종목 마스터(티커-식별자 매핑) 버전 고정

### (d) PASS 조건
- 유니버스 재현성: 같은 run_id에서 **동일 날짜 유니버스 100% 일치**
- 챔피언 대비 성능 저하가 과도하지 않을 것(상동 방어선) + **turnover/포지션 수 정상 범위 유지**

---

# P3) 거래비용/슬리피지/체결 제약(특히 8~14 집중) 반영
### (a) 왜 필요한지
- 8~14개 집중 전략은 보통 **리밸런싱이 성과를 깎는 1순위 원인**이다.
- 비용 미반영이면 튜닝이 “턴오버 높은 파라미터”로 빨려 들어가 과최적화가 된다.

### (b) 위험/부작용
- 비용을 넣는 순간 평균 수익률이 하락할 수 있음(정상).
- 비용 모델이 과보수면 알파를 과도하게 억제.

### (c) 최소 실험 → **실험 #2**로 통합
- (1) 거래비용: fixed bps + spread/vol proxy 기반 가변 bps(최소한 단순식이라도 일관 적용)
- (2) **턴오버 패널티(목표 turnover cap)** 또는 리밸런싱 빈도 제한(예: 2일/3일)
- (3) 체결가: next-open 또는 VWAP 근사 중 하나로 고정(일관되게)

### (d) PASS 조건
- 비용 포함 성능 기준:  
  - lockbox_mean ≥ (champion_lockbox_mean - 0.20) **AND** worst_mdd 개선(≤ champion_worst_mdd - 0.005) 또는 동일
- 운영 기준:  
  - 평균 일간 turnover가 상한(예: 30~50%) 이하  
  - 거래 횟수/비용 항목이 리포트에 누락 없이 출력

---

# P4) 과최적화 방지(검증 구조/게이트) + 안정성 메트릭 추가
### (a) 왜 필요한지
- 현재 Candidate가 tuning 대비 lockbox가 버티는 편이지만, **MDD 악화**가 나타남 → “파라미터가 특정 구간에만 맞는” 과최적화 가능성이 높다.
- “성능이 안 움직이는” 상황은 실제로는 **게이트가 잘못되어 변화가 잠김** 또는 **변화가 모두 lockbox에서 깨짐** 둘 중 하나다.

### (b) 위험/부작용
- 게이트 강화로 PASS가 잘 안 날 수 있음(정상).
- 실험 속도 저하(하지만 48시간 루프에서는 오히려 손실을 줄임).

### (c) 최소 실험 → **실험 #5**로 통합
- (1) purged/embargo walk-forward(라벨 중첩 구간 제거)로 튜닝-검증 분리 강화
- (2) “평균” 외에 **min / tail / stability(분산, fold 간 일관성)**를 게이트에 포함
- (3) 챔피언 대비 “개선이 아니면 reject”하는 2단 게이트(성능 보존 + 리스크 개선)

### (d) PASS 조건
- 튜닝 향상뿐 아니라, **lockbox의 tail 리스크 지표(worst_mdd, lockbox_min)**가 개선 또는 유지
- fold 간 성능 분산(예: 표준편차)이 챔피언 대비 악화되지 않을 것

---

# P5) 레짐(tech/healthcare 공통 리스크) + 노출(베타/섹터/단일종목) 관리
### (a) 왜 필요한지
- 8~14 집중에서 MDD의 대부분은 “알파”가 아니라 **노출(베타/퀄리티/금리 민감/리스크온-오프)**에서 온다.
- ETF는 매매 금지지만 **관측지표로는 최적**: QQQ/XLV, TLT(금리), VXX/IVV 등으로 레짐 감지.

### (b) 위험/부작용
- 레짐 게이트가 과도하면 트레이드 수가 줄고 수익이 평평해질 수 있음.
- 노출 제한이 알파까지 같이 깎을 수 있음.

### (c) 최소 실험 → **실험 #3, #4**로 통합
- (1) 포지션 캡/섹터 밸런스: 단일종목 max weight, Tech/HC 비중 범위 고정
- (2) 베타/시장노출 제어: IVV(또는 SPY) 대비 포트폴리오 베타 상한(또는 beta-neutral 근사)
- (3) 레짐 게이트:  
  - risk-off: (VXX 상승 & QQQ 모멘텀 약화) 시 gross 축소  
  - 금리 쇼크: TLT 급락(금리 급등) 시 duration/고밸류 테크 노출 축소

### (d) PASS 조건
- worst_mdd가 챔피언 대비 **의미 있게 감소(예: 0.5~1.5%p)**  
- lockbox_mean은 챔피언 대비 소폭 열세 허용(예: -0.20~-0.30)하되 **lockbox_min 개선** 필수

## 48시간 자동 루프용 “실행 가능한 patch/실험” 5개 (정의/게이트/기대 관측치)
아래 5개만 돌리고, 각 TOP5 우선순위는 이 5개에 매핑해서 해결한다.

### 실험 #1 — Point-in-time 조인 + 이벤트 타임스탬프 봉인(누수/서바이버십 동시)
- (1) 실험 정의  
  - feature join을 `asof`로 강제, 이벤트(earnings 등)는 “발표 이후 첫 거래일”에만 반영  
  - universe를 날짜별 스냅샷으로 고정(티커-식별자 매핑 버전 고정)
- (2) 게이트  
  - 누수 스캐너(금지 컬럼, 미래시점 join) 0건  
  - lockbox_mean ≥ champ - 0.35 AND worst_mdd ≤ champ + 0.01
- (3) 기대 관측치  
  - tuning_mean은 내려가도 lockbox는 덜 흔들림(일관성↑)  
  - fold 간 분산 감소

### 실험 #2 — 비용/슬리피지 + turnover cap(비용 미반영/과최적화 완화)
- (1) 실험 정의  
  - 거래당 비용(bps) + 슬리피지(변동성/스프레드 proxy) 반영  
  - turnover 패널티 또는 리밸런싱 최소 간격 도입
- (2) 게이트  
  - 평균 turnover 상한 충족  
  - lockbox_mean ≥ champ - 0.20 AND (worst_mdd 개선 또는 동일)
- (3) 기대 관측치  
  - 과도한 빈번매매 해소 → 실현 성능 안정화  
  - candidate류의 MDD 악화가 완화될 가능성

### 실험 #3 — 포지션/섹터/단일종목 캡 + 베타 상한(노출/운영 리스크)
- (1) 실험 정의  
  - 8~14 종목 유지하되: 단일종목 max weight, Tech/HC 비중 범위  
  - IVV/SPY에 대한 포트 베타 상한(또는 gross 조절)
- (2) 게이트  
  - worst_mdd ≤ champ - 0.005(개선 요구)  
  - 포지션 수 8~14 유지, 단일종목 캡 위반 0
- (3) 기대 관측치  
  - tail 리스크 감소, 레짐 급변 시 방어력↑

### 실험 #4 — ETF “관측지표” 레짐 게이트(매매 금지, 신호만)
- (1) 실험 정의  
  - QQQ/XLV 상대강도, TLT 추세, VXX 레벨/추세로 risk-on/off 상태를 분류  
  - 상태별로 gross exposure/리밸런싱 강도만 조절(종목 선택 로직은 유지)
- (2) 게이트  
  - 거래 수 급감 방지(예: trades/day 하한)  
  - lockbox_min 개선 또는 worst_mdd 개선 둘 중 하나 필수
- (3) 기대 관측치  
  - 특정 기간(fold14 같은) MDD 스파이크가 완화되면 “레짐 원인” 확정에 가까워짐

### 실험 #5 — 검증 구조 강화(purged WF + stability gate)(과최적화/누수 재확인)
- (1) 실험 정의  
  - purged walk-forward + embargo, fold별 stability 메트릭(분산/최저치/일관성) 산출  
  - “평균만 높으면 통과” 금지: tail/stability 동시 게이트
- (2) 게이트  
  - lockbox_mean ≥ champ - 0.20 AND lockbox_min ≥ champ_min - 0.10  
  - fold 성능 표준편차가 champ 대비 악화되지 않을 것
- (3) 기대 관측치  
  - PASS 후보 수는 줄지만, PASS의 “실전형” 확률이 올라감

## “성능이 안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래는 **질문 없이 바로 로그/리포트로 뽑아 확인**하는 분해 체크리스트다.

### A) Trigger(신호 발생) 문제
- [ ] 신호 발생 빈도(일/주 단위)가 챔피언 대비 줄었는지(=임계값/필터가 신호를 죽임)
- [ ] 신호의 선행성: feature-lag를 0/1/2 bar로 바꿨을 때 수익이 뒤집히는지(=시점 민감/누수 의심)
- [ ] 상관구조: 알파 신호가 QQQ 모멘텀/IVV 베타와 과도하게 동행하는지(=알파가 아니라 베타)

### B) Apply(체결/리밸런싱 적용) 문제
- [ ] 주문 방식(next-open vs close) 변경에 성능이 크게 흔들리는지(=미세구조/체결 가정 과민)
- [ ] 리밸런싱 주기 변경 시 수익이 사라지는지(=턴오버 알파/비용 취약)
- [ ] 포지션 캡/라운딩/최소주문단위가 실제로 신호를 왜곡하는지

### C) Exposure(노출) 문제
- [ ] 단일종목 기여도 상위 1~2개가 성과 대부분을 차지하는지(=집중 리스크/서바이버십)
- [ ] Tech/HC 내부에서도 팩터(밸류/성장/퀄리티/금리민감) 노출이 한쪽으로 기울었는지
- [ ] 포트 베타/변동성 타겟이 레짐별로 튀는지(=MDD 스파이크 원인)

### D) Costs(비용) 문제
- [ ] 총 수익 중 비용이 차지하는 비율이 특정 구간에서 급증하는지(=고변동/스프레드 확대)
- [ ] 비용 포함 후에만 성능이 “안 움직이면” → 모델 개선이 아니라 **턴오버 구조 개선**이 우선

### E) Regime(레짐) 문제
- [ ] 손실 구간이 VXX 급등, TLT 급락(금리 급등), QQQ 급락과 동시인지(=레짐 민감)
- [ ] 레짐별 성능 분해: risk-on에서는 OK인데 risk-off에서만 깨지는지(=게이트/노출 필요)
- [ ] 레짐 전환 직후(1~2주)만 깨지는지(=전환기 완충 규칙 필요)
