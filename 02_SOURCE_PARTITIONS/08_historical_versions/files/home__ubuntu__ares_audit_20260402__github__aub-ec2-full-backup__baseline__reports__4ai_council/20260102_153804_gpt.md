## TOP1) 누수(lookahead)·리밸런스 캘린더·라벨 정렬 “하드 가드” 추가
### (a) 왜 필요한지
- tuning에서만 좋은데 lockbox에서 둔화/불안정이면 **미세 누수(특히 EOD/익일시가, 인덱스/ETF 종가, 재무 업데이트 시점)** 가능성이 큼.
- 특히 “리밸런스 시각”과 “특징(feature) 생성 기준 시각”이 어긋나면 성능이 조용히 부풀어 오름.

### (b) 위험/부작용
- 누수 제거 시 tuning_mean이 떨어질 수 있음(정상).  
- 신호가 약해져 turnover 감소/신호 빈도 감소 가능.

### (c) 최소 patch/실험(서브실험 2~3개 포함) — **PATCH #1**
**실험 정의**
- “시간 정렬 강제 + 누수 스캐너”를 백테스트 파이프라인에 삽입.
- 서브실험(같은 patch 안에서 토글로 2~3개만):
  1) **Feature lag 강제**: 모든 입력을 `t-1 close`까지만 사용(익일 체결이면 최소 1 bar lag).
  2) **리밸런스 시각 고정**: “신호 산출 시각=EOD” / “체결=다음 거래일 VWAP(또는 open+slip)” 중 하나로 통일.
  3) **라벨/피처 정렬 검사**: `corr(feature_t, return_{t+1})` 과도 상관/스파이크 탐지(특정 피처만 비정상적으로 강하면 누수 의심).

**게이트(자동 중단/격리 조건)**
- 누수 스캐너에서 아래 하나라도 발생 시 후보를 “FAIL(Leakage Suspect)”로 라벨:
  - 특정 피처가 여러 폴드에서 **비정상적으로 높은 단기 상관(예: |corr| > 0.2~0.3)** 지속
  - 리밸런스 시각 변경 시 성능이 비정상적으로 급변(구현 의존성)

**기대 관측치**
- tuning_mean은 소폭 하락 가능하나, **lockbox_min/최악 MDD가 개선**되거나 최소 유지.
- fold별 성능 분산(variance)이 감소.

### (d) PASS 조건
- `lockbox_mean`이 챔피언(1.7925) 대비 **동급 이상(≥ 1.79)** 유지하면서
- `lockbox_min`이 **챔피언(1.1337) 대비 비열화 없음(≥ 1.13)**  
- `worst_mdd`가 **챔피언(-0.0931) 대비 악화 없음(≥ -0.095)**  
(누수 제거 패치의 목적은 “상승”보다 “신뢰도/안정성 확보”에 둠)

## TOP2) 비용(슬리피지/스프레드/충격)·회전율(턴오버) 반영을 “강제 계량화”
### (a) 왜 필요한지
- 현재 지표가 괜찮아 보여도 **비용 반영이 약하면** 실거래에서 붕괴.
- Tech/Healthcare는 대형주라도 이벤트/갭/변동성에 의해 **체결비용 체감이 커짐**.

### (b) 위험/부작용
- 전략이 “비용에 견디는 알파”가 아니면 성능이 크게 하락(정상 진단).
- 거래 빈도/리밸런스가 줄며 샤프는 떨어질 수 있음.

### (c) 최소 patch/실험 — **PATCH #2**
**실험 정의**
- 비용 모델을 2단계로 상향하고, “턴오버 페널티”를 포트폴리오 최적화/스코어링에 직접 반영.
- 서브실험(2~3개):
  1) **슬리피지 상향 스트레스**: 기본/2배/3배 비용(고정 bps + 변동성 비례) 3수준 동시 리포트
  2) **충격비용(impact) 근사**: `k * (order_value / ADV)` 형태(ADV는 20일 평균 거래대금)
  3) **턴오버 캡**: 일/주간 turnover 상한(예: 0.5~1.0) 적용 버전 비교

**게이트**
- 비용 2배 스트레스에서 `lockbox_mean`이 기준 대비 **급락(예: -15% 이상)**하면 “비용 취약”으로 FAIL.
- turnover가 상한을 자주 초과하면 FAIL(운영 불가).

**기대 관측치**
- 무비용 성능은 떨어질 수 있으나, 비용 스트레스 곡선이 완만해지고,
- “순수 알파(비용 차감 후)”가 폴드별로 안정.

### (d) PASS 조건
- **비용 2배**에서도 `lockbox_mean ≥ 1.70` 수준 유지(급락 방지)  
- `turnover`가 캡 내에서 관리되고, `worst_mdd` 비열화 없음

## TOP3) 서바이버십/코퍼레이트 액션(상장폐지/합병/티커변경) “데이터 무결성 테스트”
### (a) 왜 필요한지
- Tech/Healthcare는 M&A/티커 변경/스핀오프가 잦아 **서바이버십 바이어스**가 쉽게 들어감.
- “락박스는 괜찮은데 특정 폴드에서만 이상”이면 데이터 정합성 이슈 가능.

### (b) 위험/부작용
- 제대로 반영하면 과거 성과가 내려갈 수 있음(정상).
- 데이터 소스/매핑이 복잡해져 운영 리스크 증가(대신 자동 점검으로 완화).

### (c) 최소 patch/실험 — **PATCH #3**
**실험 정의**
- 유니버스/가격/리턴 생성 단계에 “상장폐지/액션 검증” 유닛 테스트 + 리포트 추가.
- 서브실험:
  1) **delisting return 처리**: 마지막 거래일 이후 0으로 고정 같은 처리 금지(가능하면 delisting return 반영/대체)
  2) **split/dividend 조정 일관성 검사**: adj/unadj 혼용 탐지(갭 스파이크 탐지)
  3) **티커 매핑 고정**: 과거 티커를 현재 티커로 덮어씌우는지 탐지(영업일 기준 이상 구간 검출)

**게이트**
- 폴드별로 “이상 갭(예: |daily return| > 40~60%) 빈도”가 특정 종목에 쏠리면 FAIL(데이터 이슈 가능성)
- 조정 방식 혼용(Adj Close vs Close)이 감지되면 FAIL

**기대 관측치**
- fold14 같은 단일 폴드에서 MDD/성과가 튀는 현상이 완화.
- 극단치(outlier)로 얻던 가짜 알파 제거.

### (d) PASS 조건
- 데이터 이슈 플래그 0건(또는 허용 임계 이하) + 성능이 챔피언 대비 크게 무너지지 않음  
- 특히 `worst_mdd` 개선 또는 동일

## TOP4) 포트폴리오 구성 제약(미국 Tech+Healthcare 8~14, 집중/노출 관리) “하드코딩”
### (a) 왜 필요한지
- “전략 성능”이 아니라 “운영 가능한 포트폴리오”가 목표.  
- 종목 수(8~14)와 섹터(Tech+Healthcare 중심), 단일 종목 집중/베타 과다 노출을 제약해야 **과최적화/우연 적중**을 줄임.

### (b) 위험/부작용
- 샤프가 단기 하락 가능(제약이 알파를 제한).
- 신호가 약한 구간에서 현금비중/리밸런스 감소로 성과 둔화.

### (c) 최소 patch/실험 — **PATCH #4**
**실험 정의**
- 포트 구성기를 “제약 최적화”로 바꾸거나(간단히는 규칙 기반) 다음을 강제.
- 서브실험:
  1) **종목 수 제약**: 항상 8~14 유지(신호 부족 시 상위 N만)
  2) **단일 종목 상한**: 예: 12~15% cap
  3) **섹터/서브산업 밸런스**: Tech/Healthcare 합 70~100% 범위, 그 외 0~30% (ETF는 매매하지 않고 **QQQ/XLK/XLV** 같은 지표로만 “리스크-온/오프” 감지에 사용)

**게이트**
- 제약 위반(종목수/가중치 cap/섹터 비중) 발생 시 FAIL(운영 불가).
- 제약 적용 후 turnover가 과도하게 증가하면 FAIL(비용 악화).

**기대 관측치**
- 성과는 비슷하더라도 **폴드 간 편차 감소**, worst_mdd 안정화.
- “한두 종목 적중” 의존이 줄어듦(서바이버십/이벤트 리스크 완화).

### (d) PASS 조건
- 제약 100% 준수 + `worst_mdd` 비악화  
- `lockbox_min` 개선(최저 성과 바닥이 올라가면 성공으로 간주)

## TOP5) 레짐(변동성/금리/리스크온) 기반 “거래 게이트”로 과최적화 억제
### (a) 왜 필요한지
- Tech/Healthcare 알파는 레짐(금리/나스닥 변동성/리스크온)에 민감.  
- “항상 거래”는 비용만 늘리고, 특정 레짐에서만 먹히는 신호를 전체 기간에 강제로 적용하는 과최적화로 이어짐.

### (b) 위험/부작용
- 거래 빈도 감소로 수익 기회 손실 가능.
- 레짐 지표 자체가 또 다른 누수/과최적화 대상이 될 수 있음(단순·고정 룰로 제한).

### (c) 최소 patch/실험 — **PATCH #5**
**실험 정의**
- ETF를 매매하지 않고 **관측 지표**로만 사용해 “진입/리밸런스 게이트”를 둔다.
- 서브실험:
  1) **리스크오프 게이트**: QQQ(또는 XLK) 20D 모멘텀 < 0 이면 신규 진입 축소(리밸런스 빈도/포지션 스케일 다운)
  2) **변동성 게이트**: VIX(가능하면) 또는 QQQ realized vol 상단 구간에서 포지션 스케일링
  3) **금리 민감 게이트(단순)**: 10Y 금리 급등 구간(예: 20D 변화량 상위 분위)에서 Tech 비중 상한 강화

**게이트**
- 게이트가 전체 기간의 과도 비중을 “거의 미거래”로 만들면 FAIL(예: 거래일의 70% 이상에서 신규진입 차단)
- 레짐 룰이 폴드별로만 유리하게 작동(특정 폴드에서만 성능 급상승)하면 FAIL(과최적화 의심)

**기대 관측치**
- lockbox에서 **min 성능/최악 MDD**가 개선되거나 안정.
- 비용 대비 성과(비용 스트레스에서의 성능) 개선.

### (d) PASS 조건
- `lockbox_min` 개선이 최우선(바닥 올리기) + `worst_mdd` 개선 또는 동일  
- 비용 2배 스트레스에서도 성능 급락 완화

# 성능이 안 움직일 때: 원인 분해(트리거/적용/노출/비용/레짐) 아이디어
아래는 “왜 개선이 안 되는지”를 **관측 가능한 지표**로 쪼개는 순서입니다(질문 없이 바로 로그/리포트 추가 대상으로 쓰면 됨).

## 1) Trigger(신호 생성) 문제
- [ ] **신호 발생 빈도**(trade rate): 너무 낮으면 분산 부족, 너무 높으면 비용 민감
- [ ] **신호 강도 분포**: 스코어 상위/하위 tail이 얇으면 랭킹 의미 없음
- [ ] **피처 기여 안정성**: 폴드별 top feature가 계속 바뀌면 과최적화

관측치
- 일/주간 signal count, score quantile 별 다음날/다음주 수익률

## 2) Apply(적용/리밸런스/체결) 문제
- [ ] 리밸런스 시각(EOD vs next open/VWAP) 변경에 민감하면 구현 의존/누수 의심
- [ ] 주문 크기 대비 ADV가 크면 체결 악화

관측치
- “이론가격 vs 체결모형가격” 차이, 슬리피지 민감도 곡선

## 3) Exposure(노출) 문제: 알파가 아니라 베타/섹터로 먹는지
- [ ] 포트의 QQQ(또는 XLK) 회귀 beta가 높으면 “나스닥 레버리지”일 뿐
- [ ] 섹터/팩터(대형/모멘텀/퀄리티) 편향이 폴드마다 튀면 불안정

관측치
- 포트 수익을 `alpha + beta*QQQ`로 분해(rolling)
- 섹터 비중/상위 1~2종목 기여도

## 4) Cost(비용) 문제: 그로스는 있는데 네트가 없다
- [ ] turnover의 80%가 소수 종목/특정 레짐에서 발생하면 구조적 비용 문제
- [ ] 비용 2배 스트레스에서 급락하면 실전 불가

관측치
- 비용 차감 전/후 성과, turnover 기여도(종목별)

## 5) Regime(레짐) 문제: 특정 국면에서만 유효
- [ ] 레짐별(리스크온/오프, 고변동/저변동)로 성과를 **조건부**로 쪼개기
- [ ] “락박스 구간 레짐이 다름”이면 평균 성과는 안 움직이는 게 정상

관측치
- QQQ 모멘텀/실현변동 분위별 성과 테이블(조건부 샤프/승률/MDD)
