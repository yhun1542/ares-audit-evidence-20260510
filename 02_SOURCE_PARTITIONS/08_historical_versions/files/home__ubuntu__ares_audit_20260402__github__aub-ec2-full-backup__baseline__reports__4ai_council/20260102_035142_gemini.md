[명령형 체크리스트]

### 1. 24~48시간 우선순위 TOP 5 (실행 중심)

**P1. 유동성 및 슬리피지 스트레스 테스트 (비용/운영 리스크)**
*   **이유:** `Champion_v5`의 Tuning Mean(3.47)이 비정상적으로 높음. 8~14개 종목의 Tech/Healthcare 집중 투자 시, 얇은 호가창이나 슬리피지가 반영되지 않은 "종이 수익"일 가능성 높음.
*   **위험:** 실제 라이브 트레이딩 시 수익 곡선 붕괴.
*   **실험 (Patch):**
    *   (1) **Exp_Cost_2x:** 기존 수수료/슬리피지 설정을 2배로 상향하여 백테스트 재구동.
    *   (2) **Exp_Liq_Filter:** 일평균 거래대금(ADV) 하위 20% 종목 강제 제외 후 성능 변화 관측.
*   **PASS 조건:** Cost 2x 상황에서도 Tuning Mean > 2.0 유지, ADV 필터 적용 시 Lockbox Min > 1.0 유지.

**P2. 섹터 ETF(XLK, XLV) 기반 레짐 필터 추가 (과최적화 방지)**
*   **이유:** Tech/Health 100% 포트폴리오는 섹터 붕괴 시 공멸함. ETF는 매매하지 않더라도 '기상청'으로 사용해야 함.
*   **위험:** 필터가 너무 민감하면(False Positive) 기회비용 발생.
*   **실험 (Patch):**
    *   (1) **Exp_Regime_SMA:** XLK 또는 XLV가 200일선 하회 시 현금 비중 50% 강제 확보 로직 주입.
    *   (2) **Exp_Vol_Target:** 섹터 ETF의 변동성(VIX 등) 급등 시 포지션 사이징 0.5배 축소.
*   **PASS 조건:** `worst_mdd`가 -5% 이내로 개선되면서, `lockbox_mean` 하락폭이 10% 미만일 것.

**P3. 'Candidate(Low MDD)'의 진입/청산 로직 부분 이식 (서바이버십/과최적화)**
*   **이유:** `candidate_..._exp_mrd_fsa`는 수익은 낮지만(-1.41 tuning min이 우려되나), MDD 방어력(-4.2%)이 탁월함. 이 방어 기제(Stop Loss 혹은 변동성 역가중 등)만 추출하여 `Champion_v5`에 장착.
*   **위험:** `Candidate`의 낮은 MDD가 단순히 운 좋은 종목 선정(Survivorship) 때문일 수 있음. 로직 때문인지 확인 필요.
*   **실험 (Patch):**
    *   (1) **Exp_Logic_Graft:** Champion의 알파(Alpha) 팩터 + Candidate의 리스크(Risk) 컷오프 규칙 결합.
*   **PASS 조건:** `Champion`의 MDD가 -6% 이하로 내려가고, Sharpe가 3.0 이상 유지될 것.

**P4. 종목 유니버스 재검증 (Tech/Health 편중 리스크)**
*   **이유:** 8~14개 종목은 개별 이슈(임상 실패, 어닝 쇼크)에 취약. 바이오텍(BioTech) 비중이 과도하게 높게 잡히는지 확인.
*   **위험:** 특정 시기(코로나 등)에 과적합된 바이오 종목들이 성과를 왜곡.
*   **실험 (Patch):**
    *   (1) **Exp_Cap_Limit:** 시가총액 Top 50 이내 대형주로만 유니버스 한정하여 재실험.
*   **PASS 조건:** 대형주 한정 시에도 `lockbox_mean` > 2.0 유지 (알파가 소형주 잡주 펌핑이 아님을 증명).

**P5. 룩어헤드(Look-ahead) 및 데이터 누수 정밀 감사**
*   **이유:** Tuning Mean 3.47은 의심스러운 수치임. 종가(Close) 배정 시점, 재무 데이터 발표일(Lag) 등을 점검해야 함.
*   **위험:** 미래 데이터를 참조한 모델은 실전에서 무가치.
*   **실험 (Patch):**
    *   (1) **Exp_Lag_1d:** 모든 피처(Feature)에 강제로 1일 지연(Lag)을 주고 성능 하락폭 측정.
*   **PASS 조건:** 성능 하락폭이 20% 이내일 것. (급락하면 누수 존재).

### 2. 48시간 자동 루프용 실험 정의 (3~5개)

아래 포맷을 시스템 입력값으로 변환하여 실행할 것.

**Experiment A: [Robustness] Slippage Stress Test**
1.  **실험 정의:** `baseline/champion_v5_latest.json` 설정에서 `slippage_model` 파라미터를 현재 값의 3배(`3.0x`)로 설정.
2.  **게이트:** `Tuning Min` > 0 AND `Lockbox Mean` > 2.0
3.  **기대 관측치:** 수익률은 감소하겠으나, 여전히 우상향해야 함. 마이너스로 전환 시 현재 모델은 '슬리피지 과소평가' 상태임.

**Experiment B: [Regime] Sector Moving Average Filter**
1.  **실험 정의:** `XLK`(Tech ETF)의 현재가가 `SMA(60)`보다 낮을 경우, 전체 포트폴리오의 `Max_Exposure`를 1.0 -> 0.5로 제한하는 로직 추가.
2.  **게이트:** `Worst MDD` > -0.06 (즉, -6%보다 얕아야 함) AND `Lockbox Min` > 1.2
3.  **기대 관측치:** 하락장에서 MDD 방어 효과 입증. 상승장에서의 수익 포기는 허용 범위 내여야 함.

**Experiment C: [Selection] Volatility-Adjusted Momentum**
1.  **실험 정의:** 종목 선정 점수(Score) 계산 시, 단순 모멘텀 대신 `Return / Realized_Volatility(20d)` 팩터 비중을 50% 이상으로 상향.
2.  **게이트:** `Fold14 MDD` > `Champion_v5`'s Fold14 MDD (현재 -0.052)
3.  **기대 관측치:** 변동성이 큰 바이오/테크 급등주가 제외되고, 꾸준히 오르는 종목이 선택되어 샤프 비율 개선.

### 3. 성능 정체(Stagnation) 시 원인 분해 및 디버깅 가이드

성능 지표가 움직이지 않거나(개선 없음), 실험 결과가 noise 수준일 때 다음 트리를 점검.

*   **트리거(Trigger) 확인:**
    *   제안한 로직(예: XLK 하락 시 매도)이 테스트 기간 동안 *한 번이라도 발동했는가?*
    *   발동 횟수가 0이면 조건이 너무 엄격함. (예: SMA 200 대신 SMA 20으로 완화 테스트)
*   **적용(Application) 확인:**
    *   신호는 발생했는데 *자금(Capital)이 부족*해서 매수를 못 했거나, *이미 풀 포지션*이라 리밸런싱이 안 일어났는가?
    *   `rebalance_freq`를 높여서 확인.
*   **노출(Exposure) 확인:**
    *   선택된 8~14개 종목의 비중이 *균등(Equal Weight)*한가? 아니면 특정 1~2개 종목에 *몰빵*되어 전체 성과를 지배하는가?
    *   비중 상한(`max_weight_per_asset`)을 강제(예: 10% -> 8%)하여 분산 유도.
*   **비용(Cost) 장벽:**
    *   잦은 매매(Churn)로 인해 *알파가 수수료로 다 나가는가?*
    *   회전율(Turnover) 지표 확인. 회전율이 높고 수익이 제자리라면 진입 장벽을 높여야 함.
*   **레짐(Regime) 불일치:**
    *   테스트 구간이 *강력한 상승장*이라 헷지/방어 로직이 오히려 수익을 깎아먹기만 하는가?
    *   특정 하락 구간(2022년 등)만 따로 떼어내어(Slicing) 로직 작동 여부 검증.
