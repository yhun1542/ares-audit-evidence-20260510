## 24~48시간 우선순위 TOP5 (명령형 체크리스트)

1) **누수(Leakage)·시점정렬(Time alignment) 최우선 감사**
- 모든 피처/라벨/리밸런싱 시점이 “그 시점에 알 수 있었던 정보만” 쓰는지 강제 검증하라.
- 특히 macro/alpha-shadow 류(지표·서프라이즈·리비전·리포트 집계) 피처는 **발표시각/리비전** 때문에 누수 확률이 높으니 먼저 걸러라.

2) **비용(수수료+슬리피지+스프레드) 미반영/과소추정 제거**
- 현재 챔피언이 lockbox가 강한데(4.01), 후보들이 MDD가 커지는 패턴이면 “실현가능 수익”이 비용·충격에 취약할 가능성이 크다.
- 비용모델을 **기본값이 아니라 게이트로** 넣어 “비용 포함 성능”이 안 나오면 자동으로 탈락시키게 만들어라.

3) **서바이버십/기업행동(스플릿·M&A)·상장폐지 리스크 제거**
- 미국 개별주 only(Tech+Healthcare, 8~14종목)면 데이터 정합성/생존편향이 성능을 가장 쉽게 “가짜로” 만든다.
- 유니버스 구성/리밸런싱 시점의 “당시 존재하던 종목”만 사용하도록 파이프라인을 고정하라.

4) **과최적화(Overfitting) 억제: 안정성·단순성 게이트 강화**
- tuning↔lockbox 갭, fold별 MDD 편차가 커지면 “특정 구간/레짐 맞춤” 신호다.
- 파라미터/피처 안정성, turnover 안정성, 섹터 노출 안정성을 “PASS 조건”에 넣어라.

5) **운영 리스크(48h 자동루프): 재현성·데이터 신선도·Kill-switch**
- 데이터 지연/부분 결측/리런 시 seed 변동이 생기면 48h 루프가 “우연 승자”를 챔피언으로 올릴 수 있다.
- 실패 안전장치(원자적 스냅샷, 재시도, 아웃라이어 탐지, 자동 롤백)를 먼저 박아라.

## 실행 가능한 Patch/실험 (총 5개로 제한, 48h 루프 형태로)

아래 5개(E1~E5)만 실제로 굴려라. 각 우선순위 항목은 이 5개를 조합해서 충족한다.

---

### E1) **Leakage/시점정렬 자동 감사 패치**
**(1) 실험 정의**
- 피처별 `asof_timestamp`를 강제하고, **리밸런싱 컷오프 이후에 생성된 데이터는 사용 불가**로 하라.
- “발표지표/리비전 가능 데이터”는 **발표시각 이후에만 유효**하도록 변환하라.
- 훈련/검증 분할에 **embargo(예: 1~5 trading days)** 를 추가해 근접 누수를 제거하라.

**(2) 게이트**
- “미래 참조 의심” 로그가 1건이라도 나오면 해당 실험 런 전체를 FAIL로 마킹하라.
- embargo 적용 후 tuning 성능이 과도하게 붕괴(예: tuning_mean 20%+ 급락)하면 기존 성능이 누수 의심으로 분류되도록 리포트에 플래그하라.

**(3) 기대 관측치**
- 정상이라면: tuning은 소폭 하락, lockbox는 유지/개선, fold별 편차 감소.
- 누수였다면: tuning 급락 + lockbox 불안정(또는 유지되더라도 turnover/신호 구조가 크게 변함).

**PASS 조건(정량)**
- `lockbox_mean >= champion_lockbox_mean - 0.10` 이면서  
- `worst_mdd <= champion_worst_mdd + 0.01`  
- 그리고 누수 플래그 0건.

---

### E2) **비용·슬리피지·충격 포함 PnL 게이트 패치**
**(1) 실험 정의**
- 종목별 스프레드/체결비용을 “보수적” 기본치로 강제(예: bps 단위, 거래대금/변동성 기반 단순모형)하고, turnover에 따라 선형/준선형 충격을 반영하라.
- 비용 포함 성능을 **선발(Select-best) 기준의 1순위 메트릭**으로 격상하라.

**(2) 게이트**
- `net_return`(비용후) 기준으로만 챔피언/후보를 비교하라.
- turnover 상한(예: 일/주 단위)을 초과하면 자동 FAIL 또는 포지션 스무딩(아래 E4와 연계) 강제.

**(3) 기대 관측치**
- 과거에 “좋아 보이던” 후보가 비용후 급락하면서 탈락.
- 챔피언이 진짜 강하면 비용후에도 상대 우위 유지.

**PASS 조건(정량)**
- 비용후 `lockbox_mean_net >= champion_lockbox_mean_net` (또는 최소 `-0.05` 이내 열세)  
- 비용후 `fold14_mdd_net >= -0.05` (현재 챔피언 fold14_mdd ≈ -0.039 감안)  
- 평균 turnover가 사전 정의 상한 이내.

---

### E3) **서바이버십/유니버스 고정(Tech+Healthcare 8~14) 재구성 패치**
**(1) 실험 정의**
- 유니버스를 “현재 구성 종목”이 아니라 **리밸런싱 시점에 상장되어 있고 거래가능했던 종목**에서만 구성하도록 변경하라.
- 섹터 필터는 Tech/Healthcare만 허용하고, 종목수 8~14를 강제하라(ETF 매매 제외).
- 기업행동(스플릿/심볼변경/M&A) 정합성 검증(가격·거래량 급변 감지)을 추가하라.

**(2) 게이트**
- 어떤 시점이든 유니버스가 8 미만 또는 14 초과면 FAIL.
- 상장폐지/거래정지 이벤트 처리 누락이 탐지되면 FAIL(해당 구간 마스킹/대체 규칙 없으면 중단).

**(3) 기대 관측치**
- “너무 매끈한” 백테스트 수익이 현실화되며 보수적으로 내려올 수 있음.
- 대신 lockbox/실거래 일관성이 개선.

**PASS 조건(정량)**
- 비용후 기준 `worst_mdd_net <= -0.09` 를 넘지 말 것(챔피언 worst_mdd ≈ -0.081 근처 유지 목표)  
- 그리고 유니버스/기업행동 오류 0건.

---

### E4) **과최적화 억제: 신호 안정화(턴오버/노출) 패치**
**(1) 실험 정의**
- 포지션 변화율에 패널티(예: L1 turnover penalty) 또는 리밸런싱 스무딩(예: 목표비중의 일부만 반영)을 추가하라.
- 섹터 내 상관/집중도(상위 1~2종목 비중) 상한을 두어 “한 종목 베팅”을 차단하라.
- ETF는 매매하지 말고 **관측지표**로만 사용(예: QQQ/XLV 리턴·변동성, TLT 금리 민감도, VIX 등)하여 레짐일 때만 리스크를 줄이는 게이트를 붙여라.

**(2) 게이트**
- 평균 turnover, 최대 단일종목 비중, 최대 섹터 편향(Tech vs Healthcare) 모두 상한 이내여야 PASS.
- 레짐 게이트가 “과도하게” 트레이드 수를 줄여서 표본이 붕괴하면 FAIL(거래횟수 하한 설정).

**(3) 기대 관측치**
- gross 성능은 약간 하락해도 net 성능과 MDD가 개선.
- fold별 성능 분산이 줄고 lockbox 안정화.

**PASS 조건(정량)**
- 비용후 `lockbox_mean_net` 개선 또는 유지(챔피언 대비 -0.05 이내)  
- `worst_mdd_net` 개선(더 덜 음수) 또는 최소 챔피언+0.01 이내  
- turnover 20%+ 감소(현재 대비 상대 기준) 또는 단일종목 최대비중 하향.

---

### E5) **48h 자동루프 운영 패치(재현성·데이터 신선도·롤백)**
**(1) 실험 정의**
- 각 런에 대해: 입력데이터 스냅샷 해시, 코드 커밋, seed, 환경(라이브러리 버전)을 강제 기록하라.
- 데이터 신선도(최근 바/펀더멘털 업데이트 시각) 체크 후 기준 미달이면 런을 “보류” 상태로 종료하라(잘못된 데이터로 챔피언 교체 금지).
- 챔피언 교체는 **2회 연속 PASS + 운영게이트 통과**일 때만 허용하라.

**(2) 게이트**
- 동일 스냅샷+seed에서 결과가 재현되지 않으면 FAIL.
- 데이터 신선도/결측률 기준 위반 시 FAIL(자동 재시도 1회 후 중단).
- “성능 급등(아웃라이어)” 감지 시(예: tuning_mean z-score) 자동 보수모드(선정 보류)로 전환.

**(3) 기대 관측치**
- 챔피언 교체 빈도 감소, 대신 교체될 때의 신뢰도 상승.
- “우연 승자”가 상위로 올라오는 현상 감소.

**PASS 조건(정량/정성)**
- 재현성 100%(동일 조건 동일 결과)  
- 데이터 신선도/결측률 위반 0회  
- 챔피언 승격은 “연속 2회 PASS”에서만 발생.

## TOP5 우선순위별 매핑 (a,b,c,d) — *실험은 E1~E5만 사용*

### 1) 누수/시점정렬
- (a) 필요: tuning이 강한데 lockbox/실전에서 흔들리면 가장 먼저 의심할 원인.
- (b) 위험: 정상 피처까지 제거해 성능이 내려갈 수 있음(단, 내려가는 게 “진실”일 수 있음).
- (c) 최소 실험: **E1 + E5 + (보조로 E3)**  
- (d) PASS: E1 PASS 조건 충족 + E5 재현성 통과.

### 2) 비용 미반영
- (a) 필요: 챔피언/후보 비교가 “gross”면 교체 의사결정이 틀어진다.
- (b) 위험: 비용모델이 과보수면 거래가 과도하게 줄어 알파를 못 먹음.
- (c) 최소 실험: **E2 + E4 + E5**  
- (d) PASS: 비용후 lockbox 유지/개선 + turnover/집중도 상한 만족.

### 3) 서바이버십/기업행동
- (a) 필요: 미국 개별주 백테스트에서 가장 흔한 “가짜 알파” 원인.
- (b) 위험: 데이터 소스/정합성 이슈가 드러나면서 단기적으로 실험 실패가 늘어남(정상).
- (c) 최소 실험: **E3 + E1 + E5**
- (d) PASS: 유니버스 규칙 위반 0 + 기업행동 오류 0 + lockbox 손상 제한.

### 4) 과최적화 억제
- (a) 필요: 후보에서 MDD가 커지는 패턴은 파라미터/레짐 과적합 가능성.
- (b) 위험: 제약이 과하면 수익이 평준화되어 “움직이지 않는” 상태가 될 수 있음.
- (c) 최소 실험: **E4 + E1 + E2**
- (d) PASS: 비용후 성능 유지/개선 + MDD/분산 감소 + 노출/턴오버 안정화.

### 5) 운영 리스크(48h 루프)
- (a) 필요: 자동 승격/강등이 잦아지면 실전에서 계좌가 “실험체”가 된다.
- (b) 위험: 게이트가 빡세면 승격이 느려짐(의도된 안정성 비용).
- (c) 최소 실험: **E5 + (E2 또는 E1) + E3**
- (d) PASS: 재현성/데이터 신선도/롤백 정책 100% 준수.

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐) — 명령형 트리

### A) 트리거(신호 생성) 문제
- 피처 분포를 훈련구간 vs 최근구간으로 나눠 **드리프트 통계(평균/분산/상관 변화)** 를 기록하라.
- “신호 발생 빈도(진입 횟수)”가 과거 대비 줄었는지 확인하라.  
  - 줄었다면: 레짐 게이트(E4) 과잉, 데이터 신선도(E5) 실패, 또는 피처 드리프트(E1 정렬 변경 영향) 가능성이 크다.

### B) 적용(집행/리밸런싱) 문제
- 목표비중→실제비중 차이를 로그로 남기고, 차이가 커지는 날의 공통 원인(거래정지/유동성/스프레드)을 태깅하라.
- 리밸런싱 캘린더(빈도/시간대)가 바뀌었는지 확인하라(장중/장마감 정렬 오류는 성능 “정지”를 만든다).

### C) 노출(Exposure) 문제
- Tech vs Healthcare 비중, 단일종목 최대비중, 팩터 근사(모멘텀/퀄리티/저변동) 노출을 **시간에 따라 추적**하라.
- 성능이 정지인데 노출도 안 변하면: 신호가 사실상 0이거나(트리거 문제), 제약이 너무 강함(E4 과도) 가능성.

### D) 비용(슬리피지/스프레드) 문제
- gross는 유지되는데 net만 죽으면: 거래비용 과대(또는 시장 유동성 악화)다.  
  - E2에서 “비용 구성요소별 기여도(수수료/스프레드/충격)”를 분해 출력하라.
- turnover가 높지 않은데도 net이 죽으면: **스프레드 확대 구간에 거래가 몰리는지**(체결 타이밍) 점검하라.

### E) 레짐(시장 국면) 문제
- ETF는 매매 금지, **관측지표로만** 레짐 태그를 만들고(예: QQQ/XLV 상대강도, VIX 수준/변화, TLT 방향)  
  - 레짐별 성능/턴오버/MDD를 슬라이스해서 “어느 국면에서만 죽는지” 표로 고정 출력하라.
- 특정 레짐에서만 죽으면: 그 레짐에서만 리스크를 줄이는 **게이트형 규칙(E4)** 로 제한적으로 대응하라(케이스 확장 금지).

## 48시간 루프에 바로 넣을 실행 순서 (명령형)

1) **E5(운영) 먼저 적용**: 스냅샷/재현성/데이터 신선도/연속2회 PASS 승격 규칙을 박아라.  
2) **E1(누수감사) 적용 후 전 실험 공통 게이트로 승격**하라.  
3) **E2(비용모델)로 net 기준 선발로 바꿔라.**  
4) **E3(유니버스/서바이버십) 고정**으로 종목수 8~14 + Tech/Healthcare 강제하라.  
5) **E4(턴오버/노출 안정화) 최소 제약만 추가**하고, 레짐은 관측지표(ETF)로만 태깅/게이트하라.
