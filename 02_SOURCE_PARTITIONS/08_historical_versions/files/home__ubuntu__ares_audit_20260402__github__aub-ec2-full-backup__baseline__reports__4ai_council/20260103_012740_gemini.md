### 2. 실행 가능한 Patch / 실험 (3~5개)

#### 실험 A: [OPS/FIX] Logger Integrity Patch
*   **목적:** Rebalance 로그가 없어 비용/슬리피지 분석 불가. 파일 경로 및 JSON 포맷팅 오류 수정.
*   **위험:** 모델 성능 자체는 변하지 않으나, 기존 기록된 '가짜 성과'가 드러날 수 있음.
*   **정의:**
    1.  `aub_rebalance_pinpoint.py`의 `Expecting value` 에러 핸들링 추가 (빈 파일/잘린 JSON 무시).
    2.  백테스트 엔진에서 `rebalance.jsonl` flush 주기 단축.
*   **Gate:** 로그 파일이 정상적으로 로드되고, `pandas.read_json`이 에러 없이 수행될 것.
*   **기대 관측치:** `rebalance.csv` 로드 성공 → 실제 건당 거래 비용 및 회전율 확인 가능.

#### 실험 B: [COST] High-Friction Reality Check
*   **목적:** OOS Mean 3.32가 거래 비용 무시에서 온 것인지 확인.
*   **위험:** 성과(Mean)가 급격히 하락하여 마이너스로 전환될 가능성(사실상 이것이 진짜 성능임).
*   **정의:**
    1.  Transaction Cost: 0.0 → 0.0015 (15bps) 설정.
    2.  Slippage Model: Volume Share Slippage (Not Fixed).
*   **Gate:** OOS Mean > 0.5 (비용 반영 후에도 양의 기대값이 유지되어야 함).
*   **기대 관측치:** OOS Mean이 3.32 → 0.8~1.2 수준으로 하락. 만약 < 0이면 현재 모델 폐기.

#### 실험 C: [UNIVERSE] Anti-Degeneracy Volatility Expansion
*   **목적:** Fold 1, 2, 3, 8의 '무거래(Degenerate)' 현상 해결. 변동성 제한이 너무 타이트하여 Tech/Bio 종목 진입을 막고 있을 가능성.
*   **위험:** MDD(Maximum Drawdown) 증가.
*   **정의:**
    1.  진입 허용 변동성(ATR or StdDev) 상한선을 기존 대비 1.5배 확장.
    2.  Target Universe: Tech/Healthcare Only (ETF 제외).
*   **Gate:** `degenerate_folds` 개수가 4개 → 1개 이하로 감소.
*   **기대 관측치:** `exposure_max`가 Degenerate 구간에서 0.0 초과로 잡힘. OOS Min이 개선되거나 악화되더라도 '매매'가 발생해야 함.

#### 실험 D: [CONSTRAINT] Concentration Penalty
*   **목적:** 소수 종목(예: NVDA, LLY 등)에 몰빵하여 수익률이 왜곡되었는지 확인.
*   **위험:** 수익률 감소.
*   **정의:**
    1.  단일 종목 최대 비중(Max Weight) < 0.15 (15%) 강제.
    2.  보유 종목 수(Count) >= 8 강제 (Soft Constraint).
*   **Gate:** Exposure가 8개 이상의 종목에 분산됨.
*   **기대 관측치:** 특정 종목 폭등 구간을 제외하고도 OOS 성과가 유지되는지 확인.

### 3. 성능 정체 시 원인 분해 (Debugging Tree)

성능이 움직이지 않거나 0에 수렴할 경우, 아래 순서로 원인을 분해하여 로그를 확인하라.

1.  **Trigger (신호 발생 여부):**
    *   Feature 값들이 `NaN`이거나 `0`으로 클리핑되고 있는지 확인.
    *   *Action:* Feature Engineering 단계의 `fillna` 정책 확인.

2.  **Filter (진입 장벽):**
    *   "유동성 필터(Min Dollar Volume)"가 Tech/Bio 소형주를 다 잘라내고 대형주만 남겼는데, 대형주는 변동성 필터에 걸리는지 확인.
    *   *Action:* 필터 임계값 로깅.

3.  **Optimization (최적화 해):**
    *   최적화 솔버(Solver)가 `Infeasible`을 반환하여 이전 포지션을 유지하거나 0포지션으로 fallback 하는지 확인.
    *   *Action:* Solver Status (Optimal vs Fail) 카운팅.

4.  **Cost/Regime (비용 및 시장):**
    *   수익이 나는데 비용(매매회전율)이 다 깎아먹는지 확인.
    *   특정 연도(Regime)에만 수익이 쏠려 있는지 확인(서바이버십).
    *   *Action:* 연도별(Yearly) Sharpe Ratio 분해.
