## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — **명령형 체크리스트**
> 우선 점검 순서: **누수 → 과최적화 → 서바이버십 → 비용 미반영 → 운영 리스크**  
> 제안은 **실행 가능한 patch/실험 5개**로 제한(각 patch 안에서 2~3개 변형 run만 허용).  
> 미국주식 only, **Tech+Healthcare 8~14개** 유지. **ETF는 관측지표로만** 사용.

---

# 1) **Point-in-time(시점정합) + 누수 차단 패치**
### (a) 왜 필요한지
- 현 Champion의 튜닝 성능 대비 lockbox가 낮아질 수 있는 가장 큰 원인 후보가 **미세한 시점 누수(발표/리밸런싱 타이밍/가격 사용 시점)**임.
- 누수는 튜닝에서만 과대평가되고, lockbox/실전에서 급격히 붕괴하는 패턴을 유발.

### (b) 위험/부작용
- 누수 제거 시 단기적으로 튜닝 성능이 내려갈 수 있음(정상).
- 과도한 지연(shift)을 주면 신호가 사라져 **언더피팅** 가능.

### (c) 최소 실험(동일 patch 안 변형 3개만)
- **E1-1 (Hard shift)**: 모든 feature를 **+1 trading day shift**(t 시점 예측에 t 종가/거래대금이 섞였는지 차단).
- **E1-2 (Event lag rule)**: 실적/가이던스/리비전 등 “발표 기반” feature가 있다면 **발표+1일 이후만 반영**(release-lag 강제).
- **E1-3 (Rebalance timestamp audit)**: 주문 생성 시각을 “t close 기준 생성 → t+1 open 체결”로 고정(같은 날 종가로 체결되는 가정 금지).

### (d) PASS 조건(게이트)
- **Gate-1(누수 탐지 게이트)**: 튜닝_mean 하락이 있더라도 **lockbox_mean 유지 또는 개선**, 그리고 **tuning_mean - lockbox_mean 격차가 감소**.
- **Gate-2(다운사이드)**: lockbox_min이 **Champion(1.5367) 대비 크게 악화 금지**(예: -10% 초과 악화 시 FAIL).
- **Gate-3(운영)**: 데이터 파이프라인에서 “as-of date” 로그(각 feature의 사용 가능일)가 출력되도록 강제.

### 48시간 자동 루프 형태
- (1) 실험 정의: `pit_shift=1`, `event_lag=1d`, `rebalance_exec=t+1_open`
- (2) 게이트: 위 Gate-1~3
- (3) 기대 관측치: **튜닝 하락(정상)** + **lockbox 안정/개선**, fold별 성능 분산 감소

# 2) **서바이버십/심볼/기업행동(스플릿/상폐) 리스크 패치**
### (a) 왜 필요한지
- 미국 개별주식에서 상폐/합병/심볼변경/스플릿 처리가 어긋나면 **과거 백테스트가 “살아남은 종목만”으로 왜곡**되거나 수익률이 인위적으로 튐.
- Tech/Healthcare는 M&A/심볼 변경 이벤트가 상대적으로 빈번.

### (b) 위험/부작용
- delisting return 반영 시 과거 성과가 떨어질 수 있음(정상).
- 심볼 매핑이 잘못되면 오히려 데이터가 깨질 수 있으므로 검증 로그가 필수.

### (c) 최소 실험(변형 2개)
- **E2-1 (Delist return on)**: delisting return(가능하면 CRSP식)을 반영하고, 불가하면 **상폐일 -100% 가정 대신 보수적 규칙(예: -30%~ -100% 구간 스트레스 테스트)**로 민감도 확인.
- **E2-2 (Corporate action invariant price)**: split/dividend 조정(Adj Close)만 쓰지 말고, **수익률 계산 소스(Adj/Raw) 일관성 검사** + 괴리 발생 시 런 중단.

### (d) PASS 조건
- **Gate-1**: 조정/상폐 반영 후에도 **worst_mdd가 급격히 악화되지 않을 것**(Champion worst_mdd -0.0704 대비 -0.080 이하로 악화 시 FAIL).
- **Gate-2**: “종목별 이벤트 로그(심볼 변경, split, delist)”가 리포트로 남을 것(운영 리스크 게이트).

### 48시간 루프
- (1) 실험 정의: `delist_return=on`, `corp_action_check=on`
- (2) 게이트: MDD/로그
- (3) 기대 관측치: 평균 성과보다 **분산/꼬리 리스크(MDD, lockbox_min)**의 해석 가능성 상승

# 3) **거래비용/슬리피지/회전율(턴오버) “현실 반영” 패치**
### (a) 왜 필요한지
- Tech/Healthcare 개별주 8~14개 운용은 리밸런싱 빈도가 높아지면 **슬리피지/스프레드/시장충격**이 성과를 잠식.
- “비용 미반영 알파”는 lockbox/실전에서 거의 항상 무너짐.

### (b) 위험/부작용
- 비용을 넣으면 단기 성과가 내려갈 수 있음(정상).
- 턴오버 제한이 과하면 반응성이 떨어져 레짐 전환에 취약.

### (c) 최소 실험(변형 3개)
- **E3-1 (Cost model baseline)**: 수수료+고정 슬리피지(bps) + 스프레드 근사(예: `slip = a + b * (vol/ADV)` 형태) 중 하나를 선택해 **일관 적용**.
- **E3-2 (No-trade band)**: 목표 비중 대비 괴리가 일정 수준 이하이면 거래 금지(미세 조정 제거).
- **E3-3 (Turnover cap)**: 일/주간 턴오버 상한(예: 30~50%)을 걸고 초과분은 다음 바로 이월.

### (d) PASS 조건
- **Gate-1**: 비용 반영 후 **lockbox_mean이 Champion 대비 -5% 이내 유지**(또는 개선이면 즉시 후보 상향).
- **Gate-2**: 턴오버가 의미 있게 하락(예: median turnover 20%+ 감소)하면서 lockbox_min 악화가 없을 것.
- **Gate-3(운영)**: 체결가 가정(다음날 시가/가중평균 등)과 비용 파라미터를 **리포트에 고정 출력**.

### 48시간 루프
- (1) 실험 정의: `cost_model=v1`, `no_trade_band=on`, `turnover_cap=on`
- (2) 게이트: lockbox_mean 유지 + turnover 감소
- (3) 기대 관측치: 평균은 소폭 감소 가능, 대신 **실전 갭 축소/다운사이드 안정화**

# 4) **레짐(리스크온/오프) 오버레이 패치 — ETF는 “관측지표”로만 사용**
### (a) 왜 필요한지
- Tech/Healthcare 집중 포트는 레짐 변화(금리/변동성/리스크오프)에서 급격히 흔들림.
- ETF(QQQ/XLV/SPY 등)는 매매하지 않고 **레짐 감지 센서**로만 쓰면 과최적화를 줄이면서 방어력을 올릴 수 있음.

### (b) 위험/부작용
- 레짐 필터가 과민하면 수익 구간을 놓쳐 **기회비용** 발생.
- 레짐 지표를 너무 많이 쓰면 또 다른 과최적화 축이 됨(지표 최소화 필요).

### (c) 최소 실험(변형 2개)
- **E4-1 (Risk-off throttle)**: 관측지표 1~2개만 사용(예: `QQQ 추세`, `SPY 변동성/드로우다운`) → risk-off면 **총 익스포저(또는 베타) 50% 축소**.
- **E4-2 (Vol targeting)**: 포트 변동성이 특정 목표를 넘으면 비중 축소(현금 비중 증가). *ETF 매매 없이도 포트 레벨에서 가능.*

### (d) PASS 조건
- **Gate-1**: worst_mdd가 Champion(-0.0704)보다 **동일 또는 개선**, 최소한 악화 금지.
- **Gate-2**: lockbox_min이 개선(Champion 1.5367 대비 상향)하거나, 개선이 없더라도 **MDD 개선 폭이 충분**하면 통과.
- **Gate-3**: 레짐 로직이 “관측지표 2개 이하”로 고정(복잡도 게이트).

### 48시간 루프
- (1) 실험 정의: `regime=on`, `indicators=[QQQ_trend, SPY_dd]`, `throttle=0.5`
- (2) 게이트: MDD/lockbox_min 개선
- (3) 기대 관측치: 평균 수익 일부 희생 가능, 대신 **꼬리 리스크 완화**

# 5) **8~14개 종목 포트폴리오: 사이징/상관/단일종목 리스크 패치**
### (a) 왜 필요한지
- 종목 수가 적을수록 성능 변동은 “알파”가 아니라 **사이징/집중**에서 결정되는 경우가 많음.
- 특히 Tech 대형주 몇 개에 과집중되면 성과가 레짐 의존적으로 변함.

### (b) 위험/부작용
- 분산/제약을 추가하면 최고 성과 구간을 깎을 수 있음(정상).
- 제약이 많아지면 모델 출력이 “항상 비슷한 포트”가 될 수 있음.

### (c) 최소 실험(변형 3개)
- **E5-1 (Vol-scaled weights)**: 신호는 그대로 두고 **비중만 1/vol로 스케일**(리스크 패리티 근사).
- **E5-2 (Max weight cap)**: 단일 종목 최대 비중(예: 12~15%) 강제 + 섹터(Tech/Healthcare) 최소/최대 비중 범위 부여.
- **E5-3 (Correlation penalty lite)**: 최근 상관이 높은 종목 동시 보유를 약하게 패널티(복잡한 최적화 대신 “고상관 쌍은 둘 중 점수 낮은 쪽 비중 절반” 같은 룰 기반).

### (d) PASS 조건
- **Gate-1**: lockbox_min 개선 또는 fold별 성과 분산 감소(안정성 게이트).
- **Gate-2**: worst_mdd 악화 금지.
- **Gate-3(운영)**: 제약 위반 시 자동 클립/정규화가 항상 재현 가능해야 함(결정적/디터미니스틱).

### 48시간 루프
- (1) 실험 정의: `weighting=vol_scaled`, `max_weight=0.15`, `corr_penalty=lite`
- (2) 게이트: lockbox_min / 분산 / MDD
- (3) 기대 관측치: **샤프보다 min/드로우다운 지표 개선** 쪽으로 이동

---

## 실행 순서(48시간 내) — 운영용 “명령형 플로우”
1. **E1(누수 차단) → E3(비용/턴오버) → E4(레짐) → E5(사이징) → E2(서바이버십)** 순서로 돌려라.  
   - 이유: 누수/비용이 정리되지 않으면 나머지 개선이 “가짜 개선”이 될 확률이 높다.
2. 각 patch는 **변형 run 2~3개만**, 나머지는 고정하라(케이스 폭발 금지).
3. 각 run마다 **tuning vs lockbox 갭, lockbox_min, worst_mdd, turnover, 비용차감 후 수익**을 동일 포맷으로 저장하라.
4. PASS는 “평균”이 아니라 **(lockbox_min, worst_mdd) 우선**으로 판정하라(운영 리스크 최소화).

# 성능이 안 움직일 때: 원인 분해 아이디어(트리거/적용/노출/비용/레짐) — 체크리스트
아래를 “한 번에 하나씩” 고정/변경하며 원인을 격리하라.

## A. Trigger(신호 발생) 문제
- [ ] **신호 발생 빈도**를 로그로 남겨라(일별 “포지션 변경 신호 수”, 종목별 히트율).
- [ ] 신호가 거의 안 뜨면: feature가 과도하게 스무딩/정규화되어 **상수화**됐는지 확인하라.
- [ ] 신호가 너무 자주 뜨면: 노이즈 추종 → **턴오버 폭발** 경로로 연결된다.

## B. Apply(신호 적용/체결 가정) 문제
- [ ] “t에서 예측 → t에 체결” 같은 **즉시체결 가정**이 숨어 있는지 탐지하라(누수).
- [ ] 체결 지연(t+1 open)으로 바꿨을 때 성능이 급락하면: 알파가 **초단기 마이크로구조**에 의존했을 가능성이 크다.

## C. Exposure(노출/집중) 문제
- [ ] 포트의 **상위 3종목 기여도**, 섹터 비중, 베타(대략)를 매일 출력하라.
- [ ] 성능이 안 움직이면: 신호는 있어도 제약/클리핑이 먹어서 **항상 비슷한 포트**가 되고 있을 수 있다.
- [ ] 성능이 흔들리면: 단일종목/고상관 쏠림을 의심하라(E5로 격리).

## D. Cost(비용) 문제
- [ ] 비용 전/후 성과를 분리 출력하라: `gross_return`, `cost`, `net_return`.
- [ ] net이 안 나오면: 알파가 아니라 **리밸런싱이 비용으로 소각**되고 있다(E3로 해결).
- [ ] ADV 대비 주문 크기 비율(간단히라도)을 기록하라(시장충격 근사).

## E. Regime(레짐) 문제
- [ ] 성과를 레짐별로 쪼개라: (QQQ 추세 up/down) × (SPY 변동성 high/low) 4칸 매트릭스.
- [ ] 특정 칸에서만 수익이면: 구조적으로 **조건부 전략**이다 → E4(레짐 오버레이)로 방어하라.
- [ ] 모든 칸에서 비슷하면: 오히려 신호가 약하거나(Trigger 문제) 비용/적용 문제일 확률이 높다.

## PASS 판정의 “우선순위 규칙”(고정)
1) **누수 의심 감소(갭 축소) + lockbox_min 유지/개선**  
2) **worst_mdd 개선 또는 악화 금지**  
3) 그 다음에야 lockbox_mean 개선을 보너스로 취급

위 5개 patch만으로 24~48시간 동안 “가짜 개선을 걷어내고(누수/서바이버십/비용), 다운사이드를 먼저 안정화(MDD/min), 그 다음 평균을 끌어올리는” 루프가 돌아가도록 설계했다.
