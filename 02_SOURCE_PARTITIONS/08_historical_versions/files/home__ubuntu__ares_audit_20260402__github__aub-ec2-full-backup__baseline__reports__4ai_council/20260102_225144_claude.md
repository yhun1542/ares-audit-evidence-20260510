## 1. 우선순위 TOP-5 패치/실험

---

### P1. 📂 데이터 파이프라인 무결성 복구

**(a) 왜 필요한가**
- rebalance.csv/jsonl 파싱 실패 → 비용/슬리피지 반영 여부 확인 불가
- OOS mean 괴리(3.32 vs 2.63) → 어느 숫자가 진짜인지 모름
- **이게 안 되면 모든 실험 결과 신뢰 불가**

**(b) 위험/부작용**
- 복구 과정에서 기존 로그 덮어쓰기 가능
- 시간 소모 (4~6h)

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 1-1 | `aub_validate_pipeline.py` 작성 → champion_v5 재실행, 로그 포맷 검증 | JSON schema 통과 | rebalance.jsonl 100% 파싱 |
| 1-2 | OOS mean 재계산: raw equity curve에서 직접 산출 | \|delta\| < 0.05 | 3.32 또는 2.63 확정 |

**(d) PASS 조건**
```
✅ rebalance_pinpoint.py 정상 실행
✅ OOS mean 단일 값 확정, 문서 갱신
```

---

### P2. 🔬 Degenerate Fold 원인 분해

**(a) 왜 필요한가**
- 4/10 fold 실패 = 40% 시장 환경에서 전략 작동 안 함
- 과최적화 또는 레짐 의존성 높음

**(b) 위험/부작용**
- 원인이 "데이터 부족"이면 구조적 해결 어려움
- 폴드별 튜닝 시 추가 과최적화 위험

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 2-1 | fold 1,2,3,8 기간 추출 → 레짐 태깅 (VIX>25, 금리상승기, 섹터로테이션) | 레짐 레이블 확보 | 공통 패턴 식별 |
| 2-2 | 해당 폴드만 별도 IS/OOS 분리 → 신호별 hit-rate 측정 | hit-rate > 0.45 | 어떤 신호가 죽는지 특정 |
| 2-3 | exposure=0 구간 overlay → "현금 전환 규칙"이 과민한지 점검 | 현금 비율 < 30% | 불필요한 현금화 제거 |

**(d) PASS 조건**
```
✅ degenerate fold 원인 1개 이상 특정
✅ 해당 레짐에서 exposure > 0.2 유지하는 대안 규칙 도출
```

---

### P3. 💰 거래비용·슬리피지 명시적 반영 검증

**(a) 왜 필요한가**
- MDD=None → 드로우다운 계산 안 됨 = 비용 빠졌을 가능성
- 실제 운영 시 연 2~3% 비용 누수 흔함

**(b) 위험/부작용**
- 비용 반영 시 OOS 급락 가능 (심리적 충격)
- 과도한 비용 가정 시 전략 포기 오류

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 3-1 | 비용 0bp/5bp/10bp 3단계 백테스트 | OOS 하락폭 측정 | Δ < 0.5/1% per 5bp |
| 3-2 | 턴오버 계산: 연간 회전율 산출 | turnover < 400% | 과다매매 아님 확인 |

**(d) PASS 조건**
```
✅ 10bp 비용 반영 후 OOS mean > 2.0 유지
✅ MDD 값 정상 출력
```

---

### P4. 📊 Exposure 정규화 — 완전현금(0%) 구간 축소

**(a) 왜 필요한가**
- exposure_min=0 → 특정 구간 완전 현금
- 이 구간이 "회피 성공"인지 "신호 부재"인지 구분 필요

**(b) 위험/부작용**
- 강제 노출 시 MDD 증가 가능
- 레짐 필터 무력화 위험

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 4-1 | exposure_floor=0.15 강제 → OOS/MDD 재측정 | MDD 증가 < 5%p | 방어적 현금화 가치 검증 |
| 4-2 | 현금 전환 트리거 로깅 → 어떤 조건이 0% 만드는지 추적 | 트리거 빈도 확보 | top-2 트리거 특정 |

**(d) PASS 조건**
```
✅ exposure=0 구간 비율 < 10%
✅ 또는 해당 구간 MDD 회피 효과 정량 증명
```

---

### P5. 🧪 신호 단순화 실험 (과최적화 역진단)

**(a) 왜 필요한가**
- 복잡한 신호 조합 → fold별 편차 큼 = 과최적화 신호
- 단순 신호로 80% 성능 나오면 나머지는 노이즈

**(b) 위험/부작용**
- 단순화 시 엣지 소실 가능
- 기존 로직 롤백 비용

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 5-1 | Top-3 신호만 사용 (FSA/momentum/vol 중 선택) | OOS > 2.0 | 복잡도 기여 측정 |
| 5-2 | 신호 파라미터 ±20% 섭동 → OOS 민감도 | Δ OOS < 0.3 | 파라미터 안정성 확인 |

**(d) PASS 조건**
```
✅ 신호 3개 조합으로 OOS mean > 2.0
✅ 파라미터 섭동 시 OOS 표준편차 < 0.25
```

## 3. 성능 불변 시 원인 분해 트리

```
OOS 안 움직임
│
├─ [트리거 문제] 신호 발생 자체가 없음
│   └─ 점검: signal_count / day < 0.1 → 임계값 완화 실험
│
├─ [적용 문제] 신호는 있으나 포지션 미반영
│   └─ 점검: signal→order 전환율 < 50% → 필터/리스크 규칙 점검
│
├─ [노출 문제] 포지션 있으나 사이즈 미미
│   └─ 점검: avg_exposure < 0.3 → 사이징 로직 점검
│
├─ [비용 문제] 수익은 나나 비용에 잠식
│   └─ 점검: gross vs net return 괴리 > 1% → 턴오버 축소
│
└─ [레짐 문제] 특정 시장 환경에서만 작동
    └─ 점검: fold별 분산 > 1.5 → 레짐 필터 추가/제거
```
