[우선순위 TOP 5 제안: 향후 48시간]

### 1. [CRITICAL] `degenerate_folds` 및 `MDD: None` 해결을 위한 강제 거래 주입
*   **이유:** Fold 1,2,3,8이 망가졌고(degenerate), MDD가 `None`인 것은 치명적 결함. 전략이 거래를 **전혀 안 했거나**, 수익 곡선 계산이 깨짐. 현재 `oos_mean` 3.32는 신뢰 불가(데이터 부족으로 인한 허수일 가능성 99%).
*   **위험:** 로직 강제 수정 시 기존의 보수적 진입 장벽이 무너져 MDD 급증 가능성.
*   **실험 (Experiments):**
    1.  `EXP_FORCE_ENTRY`: 진입 임계값(Threshold)을 현행 대비 50% 하향 조정 (e.g., Signal 0.7 -> 0.35).
    2.  `EXP_MIN_EXPOSURE`: 포트폴리오 최소 노출 비중(min_exposure)을 0.0 -> 0.2로 강제 설정.
    3.  `EXP_DATA_ALLOWANCE`: 데이터 결측 허용 범위(max_nan_tolerance)를 완화(0% -> 5%)하여 초기 Fold(1~3) 데이터 로드 강제.
*   **PASS 조건:**
    *   `degenerate_folds` 개수 = 0
    *   `worst_mdd`가 수치로 산출됨 ( != None)
    *   `trade_count` > 30 per fold

### 2. [SYSTEM] 로깅 파이프라인 복구 (Rebalance logs)
*   **이유:** `Error loading ... rebalance.csv` 오류 발생. 트랜잭션 로그 없이는 비용 분석, 슬리피지, 비체결 원인 파악 불가능. 맹목적 최적화 상태.
*   **위험:** 디스크 I/O 증가로 백테스트 속도 저하(미미함).
*   **실험 (Experiments):**
    1.  `EXP_LOG_FORMAT_FIX`: 로그 포맷을 CSV/JSON 혼용에서 `Parquet` 또는 `Strict JSONL`로 단일화 및 경로 하드코딩 수정.
    2.  `EXP_EMPTY_LOG_HANDLE`: 거래가 0건이어도 헤더(Header)만 있는 빈 로그 파일을 생성하도록 예외 처리 추가.
*   **PASS 조건:**
    *   `aub_rebalance_pinpoint.py` 실행 시 에러 코드 0 반환.
    *   생성된 로그 파일 용량이 > 1KB.

### 3. [STRATEGY] Tech/Bio 섹터 전용 변동성 필터(VIX/ATR) 재조정
*   **이유:** Tech/Bio는 기본 변동성이 큼. 범용 필터(S&P500 기준 등)를 쓰면 노이즈로 인식해 거래를 포기(Fold 1~3 degenerate 원인 추정). 섹터 특성에 맞는 '높은 변동성 수용'이 필요.
*   **위험:** 하락장 변동성(Downside Vol)을 기회로 오인하여 칼날 잡기 시도 가능성.
*   **실험 (Experiments):**
    1.  `EXP_VOL_SCALE_UP`: 변동성 차단 기준(Stop limit)을 현재의 1.5배로 확장.
    2.  `EXP_ATR_TARGET`: 고정 손절폭 대신 `3 * ATR` 기반 동적 범위를 적용하여 휩소(Whipsaw) 방지.
*   **PASS 조건:**
    *   Tech/Healthcare 종목군의 `exposure_time`(시장 참여 시간)이 30% 이상 증가.
    *   Sharpe Ratio > 1.2 유지.

### 4. [COST] 슬리피지 및 비용 모델 현실화 (보수적 적용)
*   **이유:** `oos_mean` 3.32는 비현실적. Tech/Bio 소형주 포함 시 슬리피지 큼. 현재 비용 '0' 혹은 과소 산정 의심.
*   **위험:** 수익률 대폭 하락으로 챔피언 모델 폐기 가능성(그러나 이는 '진짜' 성능을 찾는 과정).
*   **실험 (Experiments):**
    1.  `EXP_COST_BPS_15`: 왕복 수수료+슬리피지를 15bps(0.15%)로 강제 주입.
    2.  `EXP_LIQUIDITY_PENALTY`: 일평균 거래대금 하위 20% 종목 매매 시 비용 2배(30bps) 적용.
*   **PASS 조건:**
    *   비용 적용 후에도 `oos_mean` > 1.0 유지.
    *   `turnover`(회전율)이 과도하게 높지 않은지 확인 (연 500% 이하 권장).

### 5. [UNIVERSE] 동적 유니버스(Dynamic Universe) 검증
*   **이유:** "8~14 tickers". 고정된 리스트(Survivorship bias)인지, 시점별 시가총액/유동성 상위 종목을 동적으로 뽑는지 불명확. 고정 리스트라면 2000년대 초반 Tech 종목 데이터가 없어 Fold 1,2가 죽었을 수 있음.
*   **위험:** 유니버스 선정 로직 오류 시 엉뚱한 잡주 매매.
*   **실험 (Experiments):**
    1.  `EXP_UNIVERSE_ROLLING`: 매월 리밸런싱 시점에 Tech/Health 섹터 시총 상위 20위 내에서 10종목 선정 로직 적용.
    2.  `EXP_MIN_PRICE_FILTER`: 동전주($5 미만) 제외 로직 추가.
*   **PASS 조건:**
    *   Fold 1,2,3(과거 구간)에서 유효 유니버스 개수 > 8 확보.
    *   상장 폐지 종목 보유 이력 0건.

[성능 정체 시 원인 분해 아이디어]

성능이 움직이지 않거나(Flat), 개선되지 않을 때 다음 트리를 따라 디버깅:

1.  **트리거(Trigger) 확인:** 신호가 발생했는가?
    *   *Check:* `raw_signal` 값의 분포 확인. 0.0 근처에 몰려있다면 Feature Scaling이나 정규화 로직 오류.
2.  **적용(Execution) 확인:** 신호가 주문으로 이어졌는가?
    *   *Check:* `signal` > `threshold`인데 주문이 안 나갔다면 -> `cash_balance` 부족 or `risk_manager` 거부 or `market_open` 체크 오류.
3.  **노출(Exposure) 확인:** 체결 후 보유했는가?
    *   *Check:* 매수 직후 다음 틱에서 바로 매도(손절/익절) 나가는지 확인 (Too tight stop-loss).
4.  **비용(Cost) 확인:** 수익이 비용에 잠식되었는가?
    *   *Check:* `gross_profit`은 우상향인데 `net_profit`이 횡보하면 -> 과잉 매매(Over-trading). 회전율 제한 필요.
5.  **레짐(Regime) 불일치:** 시장과 전략이 엇박자인가?
    *   *Check:* 시장(SPY/QQQ) 상승 구간에 현금 보유, 하락 구간에 진입하는지 상관관계(Correlation) 체크. Tech/Bio 섹터 ETF(XLK, XLV)와 내 포트폴리오의 Beta 확인.
