(규칙 준수: 질문 없음, 누수·과최적화·서바이버십·비용·운영리스크 우선, **미국주식 only / Tech+Healthcare 8~14종목 / ETF는 관측지표만**)

## 0) 즉시 관찰된 “빨간불”(ONE TRUTH 기반)
- **degenerate_folds: [1,2,3,8]** → 폴드가 깨졌거나(표본 부족/NaN/동일값), 누수/정렬 오류/분할 로직 문제가 있을 확률이 큼.
- **worst_mdd: None** → 리스크 핵심 지표 계산/로그가 누락(운영 리스크).
- **lane_hash/run_hash: None**, rebalance pinpoint에서 **base-log/cand-log 로딩 실패** → 재현성/감사 가능성/자동 비교가 막힘(운영 리스크 + 실험 무의미화).

# 1) TOP5 우선순위 제안 (24~48h)

## P1) “로그/아티팩트/리밸런스 체인”을 먼저 고쳐서 자동 비교가 되게 만들기 (운영 리스크 제거)
### (a) 왜 필요한지
- 지금은 **리밸런스 로그를 못 읽어서** “무슨 거래가 일어났는지/비용이 반영됐는지/턴오버가 어떤지”를 검증 불가.
- **run_hash/lane_hash 없음** → 같은 실험을 다시 돌려도 동일성 보장이 안 되고, No-Delta 원인 규명이 불가능.

### (b) 위험/부작용
- 성능이 좋아지기보다 **진실이 드러나며** 일시적으로 성능이 낮아질 수 있음(특히 비용/슬리피지 반영 시).
- 로그 포맷 변경이 기존 툴을 깨뜨릴 수 있음(버전 태깅 필요).

### (c) 최소 실험(공유 실험 중 선택)
- **E1 + E3** 실행(아래 “공유 실험팩” 참조)

### (d) PASS 조건
- 모든 run에서 **run_hash/lane_hash 생성**, 아티팩트 경로 고정 저장.
- `aub_rebalance_pinpoint`가 **base/cand 모두 로드 성공**하고, 리밸런스/체결/포지션 타임라인을 diff 가능.
- worst_mdd가 **None이 아닌 숫자**로 산출되고, OOS 리포트에 함께 출력.

---

## P2) Degenerate folds 제거: 분할/정렬/누수(lookahead) 1차 차단
### (a) 왜 필요한지
- degenerate fold는 대개 다음 중 하나:
  - **시간정렬 오류**(t 시점 피처에 t+1 가격 포함)
  - **purge/embargo 없는 CV**(인접 구간 누수)
  - 특정 구간 데이터 품질 문제(NaN/거래정지/기업행동)로 학습/평가가 붕괴
- 폴드가 깨지면 OOS mean이 의미가 없어지고, “No-Delta”가 구조적으로 발생.

### (b) 위험/부작용
- purge/embargo를 넣으면 표본이 줄어 **추정 분산 증가**, 성능이 흔들릴 수 있음.
- 누수 제거 후 성능이 하락할 수 있음(그게 정상).

### (c) 최소 실험
- **E2 + (필요 시 E1)**

### (d) PASS 조건
- degenerate_folds가 **빈 배열**이거나, 발생 시 **명확한 데이터 에러로 격리**(폴드 스킵이 아닌 “원인 로그” 남김).
- OOS 성능이 떨어져도, **폴드별 성능 분포/분산이 정상화**(일부 폴드만 비정상 급등/급락 제거).
- 누수 검증(shift test) 통과: “피처를 +1일 쉬프트하면 성능이 유의미하게 악화” 같은 sanity check를 만족.

---

## P3) 비용(수수료+슬리피지+스프레드+턴오버) 반영 및 “비용 게이트”로 과최적화 억제
### (a) 왜 필요한지
- Tech/Healthcare 대형주라도 리밸런스가 잦으면 **슬리피지/스프레드가 OOS를 갉아먹음**.
- 비용 미반영 상태에서 하이퍼파라미터/스케일 튜닝은 **과최적화의 대표 패턴**.

### (b) 위험/부작용
- 단기적으로 OOS mean 하락 가능(현실화).
- 비용 모델이 과하게 보수적이면 전략이 “움직이지 않는” 쪽으로 붕괴 가능(게이트/한도 설계 필요).

### (c) 최소 실험
- **E3 + E4**

### (d) PASS 조건
- “비용 포함 OOS mean”이 **비용 미포함 대비 과도하게 붕괴하지 않음**(예: -30% 이상 급락이면 턴오버/슬리피지 과다 가능성).
- **턴오버 상한**(예: 48h 루프에서 일평균 turnover 제한) 내에서 성능이 유지/개선.
- 리밸런스 횟수·체결수·추정 비용이 리포트에 항상 출력.

---

## P4) 노출/집중 리스크 통제: 8~14 Tech+Healthcare 바스켓에 “포지션/섹터/리밸런스 규율” 강제
### (a) 왜 필요한지
- exposure max가 **0.84**로 보이며(현금 비중 존재), 어떤 시점에 **쏠림/공백**이 생기는지 불명확.
- 8~14 종목 소수 바스켓은 작은 오류가 **MDD/운영 사고로 직결**(특히 단일 종목 과집중).

### (b) 위험/부작용
- 상한/하한 규율이 알파를 깎을 수 있음.
- “항상 투자” 규율을 강제하면 레짐 불리 구간에 손실 확대 가능(레짐 게이트와 같이 써야 함).

### (c) 최소 실험
- **E4 + E5** (레짐 관측으로 리스크 완화)

### (d) PASS 조건
- 종목별 최대 비중, 섹터별 최대 비중, 현금비중 범위가 **항상 제약 내**.
- worst_mdd가 계산되고, 제약 도입 후 **MDD가 의미 있게 감소**하거나(또는) OOS mean 대비 **리스크 조정 성과 개선**.

---

## P5) 레짐(시장 상태) 기반 “거래/노출 게이트” 추가: ETF는 ‘관측 지표’로만 사용
### (a) 왜 필요한지
- Tech/Healthcare는 레짐(금리/변동성/리스크온오프)에 따라 성과가 크게 갈림.
- “No-Delta”는 종종 **레짐 불리 구간에서 신호가 다 죽어** 발생(아무리 튜닝해도 안 움직임).

### (b) 위험/부작용
- 게이트가 과하면 거래가 줄어 “움직이지 않는 전략”이 될 수 있음.
- 레짐 지표가 사실상 미래를 맞추려는 형태가 되면 과최적화 위험(단순/안정적 지표만).

### (c) 최소 실험
- **E5 + E3** (레짐 게이트가 턴오버/비용에 미치는 영향도 같이 확인)

### (d) PASS 조건
- 레짐 불리 구간에서 **거래 빈도/노출이 자동 감소**하고, 유리 구간에서만 재개.
- OOS mean이 소폭이더라도, **worst_mdd 또는 tail loss가 개선**.
- 게이트로 인해 “항상 0% 투자”로 붕괴하지 않음(최소 활동률 조건 충족).

# 2) 공유 “실행 가능한 Patch/실험” 5개 (48시간 자동 루프 형식)
아래 5개만 돌려도 위 TOP5 요구를 커버하도록 설계했습니다. (**케이스 폭발 방지**)

---

## E1) 아티팩트/로그 표준화 패치 (재현성 + 리밸런스 diff 가능)
### (1) 실험 정의
- 모든 run에 대해:
  - `run_hash = hash(config + code_commit + data_snapshot_id)`
  - `lane_hash = hash(universe + feature_set + cost_model + split_scheme)`
  - 산출물: `rebalance.jsonl`(각 리밸런스 시점의 target/filled/price/slippage/cost), `positions.parquet`, `metrics.json`(oos_mean, worst_mdd 포함)
- `aub_rebalance_pinpoint` 입력을 **파일 경로 실존 + 포맷 고정(JSONL/CSV 스키마 고정)**으로 맞춤.

### (2) 게이트
- 파일 누락/파싱 실패 시: 해당 run은 **실패로 처리(성능 비교 금지)**.
- `worst_mdd is None`이면 실패.

### (3) 기대 관측치
- pinpoint 리포트가 생성되고, “어느 날짜에 어떤 종목을 얼마나 갈아탔는지” diff가 보임.
- No-Delta가 “실제로 거래가 없어서”인지, “거래는 있는데 성과가 없어서”인지 분리 가능.

---

## E2) Purged Walk-Forward + Embargo CV로 누수/degenerate folds 제거
### (1) 실험 정의
- 시간축 CV를 **Purged Walk-Forward**로 교체:
  - train/test 경계에 **purge window**(예: 5~20 trading days)
  - test 직후 **embargo**(예: 5 trading days)로 인접 정보 누수 차단
- 피처 생성 단계에서 강제 체크:
  - 모든 피처는 `t` 시점 데이터까지만 사용(미래 참조 방지)
  - “가격 기반 피처”는 반드시 `shift(1)` 이후 계산(룰로 고정)

### (2) 게이트
- degenerate fold 발생 시:
  - 폴드를 조용히 스킵하지 말고 **원인(결측률/상수열/표본수) 로그**를 남기고 실패 처리.
- “피처 +1일 쉬프트” sanity run에서 성능이 원래보다 **유의미하게 하락하지 않으면** 누수 의심으로 실패.

### (3) 기대 관측치
- degenerate_folds가 제거되고, 폴드별 성능이 과도하게 튀지 않음.
- 평균은 내려갈 수 있으나 **신뢰 가능한 OOS 분포** 확보.

---

## E3) 비용 모델 + 비용 리포팅(턴오버 포함) + 비용 게이트
### (1) 실험 정의
- 거래비용을 최소 구성으로라도 반영:
  - 고정 수수료(0에 가깝더라도 명시)
  - 슬리피지: `k * ATR` 또는 `bps`(예: 2~10bps) 중 하나로 고정
  - 스프레드: 대형주 기준 보수적 bps로 고정(혹은 OHLC 기반 근사)
- 리포트에 항상 출력:
  - turnover/day, trades/day, cost/day, net vs gross return

### (2) 게이트
- 일평균 turnover가 상한 초과 시 실패(예: 설정한 한도).
- gross는 좋은데 net이 크게 무너지면(예: net/gross < 임계) 실패.

### (3) 기대 관측치
- “성능 무변화”가 비용 때문인지 즉시 확인 가능.
- 과최적화로 나온 고턴오버 전략이 자동으로 걸러짐.

---

## E4) 8~14 종목 Tech+Healthcare 바스켓 제약(집중/노출/리밸런스 규율)
### (1) 실험 정의
- 거래 유니버스: **미국주식, Tech+Healthcare로만** 8~14개 유지(ETF 매매 제외).
- 제약 예시(구현 가능한 수준으로 단순화):
  - 단일 종목 최대 비중 cap(예: 12~20%)
  - 섹터별 최대 비중 cap(Tech/HC 각각 상한)
  - 리밸런스 최소 간격(예: 2~5일) 또는 변화량 threshold(드리프트 허용)
  - 현금 비중 범위(예: 0~30%) 또는 최소 투자비율

### (2) 게이트
- 제약 위반 포지션이 1회라도 발생하면 실패.
- 리밸런스가 “0회”로 고착되면 실패(활동률 최소치).

### (3) 기대 관측치
- exposure max/min, 종목별 최대 비중이 안정화.
- MDD가 줄거나 tail risk가 줄어 리스크-조정 성과가 개선.

---

## E5) 레짐 관측 지표(ETF) 기반 노출 게이트 (ETF는 지표로만)
### (1) 실험 정의
- ETF를 **거래하지 않고**, 관측 지표로만 사용:
  - 예: QQQ(tech risk-on), XLV(healthcare defensiveness), IEF/TLT(금리 민감도), VIX 대용(가능하면 지표)
- 단순 게이트 1~2개만:
  - 변동성/추세가 불리하면 목표 노출을 0.5x 또는 cash 상향
  - 리스크온이면 정상 노출 복귀
- 목표: “신호가 죽는 레짐”에서 거래·노출 자동 축소.

### (2) 게이트
- 게이트가 전체 기간의 대부분을 차단(예: 투자일 < 최소 비율)하면 실패.
- 게이트 적용 후 turnover가 과도하게 증가하면 실패(오히려 뒤집기만 하는 경우).

### (3) 기대 관측치
- 불리 레짐에서 손실 꼬리(worst_mdd, 하위 분위수 손실)가 완화.
- No-Delta 구간이 “레짐 차단으로 의도된 정지”인지 명확히 분리.

---

# 3) 성능이 안 움직일 때(No-Delta) 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래는 **48시간 루프에서 자동으로 찍히게 할 체크리스트(명령형)** 입니다.

## A. 트리거(신호 생성) 레벨
- **[체크] 피처가 상수/결측으로 붕괴했는지**: 피처별 분산, 결측률, 상수열 비율 리포트.
- **[체크] 시점 정렬/shift 규칙 위반**: “피처 +1일 쉬프트” 성능 비교 자동 수행.
- **[체크] 종목별 신호 분포**: 상위/하위 신호가 특정 종목에만 과도 집중되는지.

## B. 적용(포지션 변환) 레벨
- **[체크] 신호→목표비중 매핑이 포화(saturation)됐는지**: 클리핑/스케일 파라미터로 대부분이 동일 비중이 되는 현상.
- **[체크] 리밸런스 조건이 너무 빡빡/너무 느슨한지**: 리밸런스 횟수, 평균 변경률(%), 드리프트 허용폭 로그.

## C. 노출(리스크/제약) 레벨
- **[체크] 제약 때문에 항상 현금/부분노출로 눌리는지**: exposure time-series + 제약 활성화 카운트.
- **[체크] 단일 종목 cap/섹터 cap이 알파를 계속 잘라내는지**: 제약에 걸려 “의도한 목표비중→실현비중” 괴리율 로그.

## D. 비용(현실성) 레벨
- **[체크] gross는 움직이는데 net이 평평한지**: gross vs net, 비용/일, turnover/일 상관 확인.
