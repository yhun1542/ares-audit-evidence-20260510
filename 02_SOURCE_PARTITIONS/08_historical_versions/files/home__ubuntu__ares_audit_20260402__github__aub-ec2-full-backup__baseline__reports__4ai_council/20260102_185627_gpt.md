## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — **명령형 체크리스트**
(중요: 아래 TOP5는 **총 5개 패치/실험(E1~E5)**로 수렴시키고, 각 우선순위는 해당 실험을 “공유”해서 케이스 폭발을 막는다.)

---

### 1) **누수/과최적화/폴드 퇴화(degenerate_folds) 최우선 제거**
**(a) 왜 필요한지**
- 현재 챔피언에서 `degenerate_folds: [1,2,3,8]`는 **검증 체계가 깨졌거나(라벨/피처 정렬, 결측 처리, purge 미적용), 데이터가 폴드별로 사실상 상수**인 상태일 가능성이 높다.
- OOS 평균이 나와도, 폴드 퇴화는 **누수/과최적화/우연 적합** 신호로 취급해야 한다.

**(b) 위험/부작용**
- Purged/Embargo 적용 후 OOS가 급락할 수 있음(“진짜 실력”만 남음).
- 학습 데이터가 줄어 수익률이 단기적으로 낮아질 수 있음.

**(c) 최소 실험 2~3개 (E1로 통합 수행)**
- (E1-1) **Purged + Embargo Walk-forward**로 CV 재실행(기존 fold 로직 대체)
- (E1-2) **시간 쉬프트 누수 감지**(피처를 +1 bar 쉬프트해도 성능이 유지되는지 확인)
- (E1-3) **폴드별 라벨/피처 분산 리포트**(표준편차 0 또는 결측 과다 폴드 탐지 시 즉시 fail)

**(d) PASS 조건**
- `degenerate_folds == []`
- Purged/Embargo 적용 후에도 **OOS Mean이 “0 근처로 붕괴”하지 않을 것**(붕괴 시 기존 성과는 누수/우연으로 간주)
- 폴드별 라벨/피처 분산이 최소 기준 이상(상수 폴드 없음)

---

### 2) **서바이버십/코퍼레이트 액션(분할·상폐·M&A) 반영 + 유니버스 고정**
**(a) 왜 필요한지**
- “미국주식 only + Tech/Healthcare 8~14” 조건을 **명시적으로 고정**하지 않으면, 데이터 제공자/백테스트 시점에 따라 **구성 종목이 암묵적으로 변형(서바이버십 편향)**된다.
- 유니버스가 흔들리면 OOS가 “안 움직이거나”, 실험 간 델타가 0에 가까워지는 현상도 동반된다.

**(b) 위험/부작용**
- 고정 유니버스는 분산이 줄어 성과가 낮아질 수 있음.
- 상폐/합병 처리 로직이 잘못되면 인위적 손실/이익이 생김.

**(c) 최소 실험 2~3개 (E2로 통합 수행)**
- (E2-1) **고정 유니버스 12종목**으로만 전체 파이프라인 강제 실행  
  - Tech: `AAPL, MSFT, NVDA, GOOGL, AMZN, META, AVGO, ORCL`  
  - Healthcare: `LLY, UNH, JNJ, ABBV`
- (E2-2) **Point-in-time 가격/조정(Adj) 일관성 검사**(split/dividend 반영 방식 단일화)
- (E2-3) **상폐/티커변경 이벤트 처리**(거래 불가 시 현금화/대체 규칙을 명시적으로 적용)

**(d) PASS 조건**
- 같은 기간/같은 설정에서 **리런(run) 결과가 재현**될 것(해시/로그 포함)
- 서바이버십 편향 신호(특정 구간에서만 비정상 급등)가 완화
- 유니버스/가격조정 방식이 실험마다 변하지 않음(설정으로 강제)

---

### 3) **비용(슬리피지/수수료/스프레드/차입) 미반영 제거: “Gross → Net”로 전환**
**(a) 왜 필요한지**
- 비용 미반영은 가장 흔한 “움직이는 성능의 착시” 원인이다.  
- 특히 Tech/Healthcare 대형주는 유동성이 좋더라도 **리밸런스 빈도/턴오버**가 높으면 Net이 크게 깎인다.

**(b) 위험/부작용**
- Net 성과가 떨어져 보일 수 있음(하지만 이게 정상).
- 비용 모델이 과도하게 보수적이면 전략이 불필요하게 위축.

**(c) 최소 실험 2~3개 (E3로 통합 수행)**
- (E3-1) **고정 bps 슬리피지 + 수수료**(예: 진입/청산 각각 X bps)로 Net PnL 재계산
- (E3-2) **턴오버 기반 가변 비용**(턴오버↑ 시 비용↑) + 리밸런스 빈도별 민감도
- (E3-3) (공매도 사용 시) **차입비용/리콜 리스크 보수 항목**을 상한치로 반영

**(d) PASS 조건**
- Net 기준으로도 **OOS Mean이 의미 있게 양수**이며,
- `oos_min`(최악 케이스)가 비용 반영 전 대비 **비정상적으로 붕괴하지 않을 것**
- 턴오버/비용이 리포트로 남고, 실험 간 비교 가능

---

### 4) **운영 리스크(노출/현금 비중/리밸런스) 게이트 추가: 노출 거버넌스**
**(a) 왜 필요한지**
- 현재 노출 범위 `0.0 ~ 0.8388`은 “상당 기간 100% 현금(또는 포지션 없음)”이 섞였다는 뜻일 수 있다.  
  → 성능이 안 움직이는 원인이 **트리거 부족/진입 억제/신호 소실**일 수 있음.
- 노출 거버넌스가 없으면 OOS 평균이 좋아도 **최악구간(oos_min) 방어 실패**가 잦다.

**(b) 위험/부작용**
- 노출 상한/하한이 성과를 제한할 수 있음.
- 변동성 타게팅은 추세장에서 수익을 일부 포기할 수 있음.

**(c) 최소 실험 2~3개 (E4로 통합 수행)**
- (E4-1) **최소 투자비중 floor**(예: 신호가 있어도 0%로 내려가지 않게) vs 기존 비교
- (E4-2) **변동성 타게팅**(관측지표로만 ETF 사용: `QQQ, XLV`의 최근 변동/드로우다운을 위험 스위치로 사용. *ETF 매매 금지*)
- (E4-3) **리밸런스 게이트**: 신호 변화가 미미하면 거래 생략(턴오버↓, 비용↓)

**(d) PASS 조건**
- 노출 분포가 “의도한 형태”로 수렴(0% 체류가 과도하면 fail)
- 비용 반영(Net)에서도 `oos_min` 개선 또는 MDD 완화
- 거래 횟수/턴오버가 과도하지 않음(운영 가능 수준)

---

### 5) **실험 인프라 “No-Delta/리밸런스 로그 누락” 즉시 복구 (재현성/감사 가능성)**
**(a) 왜 필요한지**
- 현재 로그에서:
  - `lane_hash: None`, `run_hash: None`
  - `Error loading --base-log`, `rebalance.csv/jsonl 파싱 실패`, “No rebalance data found”
- 이 상태는 **실험이 실제로 다른지(델타), 리밸런스가 언제 왜 발생했는지, 비용이 어떻게 쌓였는지**를 추적 불가 → 48시간 자동 루프가 망가진다.

**(b) 위험/부작용**
- 로깅/해시 추가로 러닝타임/저장공간 증가
- fail-fast로 인해 단기적으로 “실험 완료 수”가 줄어들 수 있음(대신 품질↑)

**(c) 최소 실험 2~3개 (E5로 통합 수행)**
- (E5-1) **config 해시(run_hash/lane_hash) 강제 생성** + 결과물에 항상 기록
- (E5-2) **리밸런스 로그를 단일 포맷(JSONL)로 고정**하고, 도구가 읽는 경로/확장자를 일치
- (E5-3) **No-Delta 감지 게이트**: 후보가 베이스와 파라미터/신호/거래가 동일하면 즉시 중단+원인 출력

**(d) PASS 조건**
- 모든 실험에서 `run_hash/lane_hash != None`
- rebalance 로그가 항상 생성되고 pinpoint 도구가 오류 없이 읽음
- “9 experiments but no delta” 같은 상황을 **게이트에서 자동 차단**

## 48시간 자동 루프용: 패치/실험(E1~E5) 정의 (실험 정의 → 게이트 → 기대 관측치)
아래 5개만 돌려라(추가 실험 금지). 각 실험은 위 TOP5 요구를 동시에 커버한다.

### E1) Purged/Embargo Walk-forward + 폴드 퇴화 진단
- **실험 정의**: 기존 CV를 purged+embargo walk-forward로 교체, 폴드별 라벨/피처 분산 리포트 자동 생성
- **게이트**:
  - degenerate fold 감지 시 즉시 실패 처리
  - 쉬프트(+1 bar) 누수 테스트에서 성능이 비정상 유지되면 실패 처리
- **기대 관측치**:
  - 누수가 있었다면 OOS Mean 하락 + 성능 분산 증가
  - 정상이라면 OOS Mean 큰 변화 없이 폴드 퇴화가 사라짐

### E2) 고정 유니버스(12) + PIT/조정/상폐 처리 강제
- **실험 정의**: 위 12종목만 거래 대상으로 고정, 가격 조정 규칙과 상폐 처리 규칙을 코드로 고정
- **게이트**:
  - 유니버스가 한 번이라도 변하면 실패
  - split/dividend 처리 불일치(가격 점프/음수/결측 급증) 탐지 시 실패
- **기대 관측치**:
  - 재현성 상승, 실험 간 델타가 “진짜”로 나타남
  - 특정 구간의 비정상 수익(서바이버십 착시) 감소

### E3) Net 비용 모델(고정bps + 턴오버 연동)
- **실험 정의**: 거래별 슬리피지/수수료 + 턴오버 연동 비용을 Net PnL에 반영
- **게이트**:
  - 턴오버/비용 리포트 누락 시 실패
  - Net에서 oos_min이 특정 하한(운영 불가 수준) 밑이면 실패
- **기대 관측치**:
  - Gross 대비 OOS Mean 하락(정상)
  - 대신 “현실적인” 전략만 남아 이후 최적화가 유효해짐

### E4) 노출 거버넌스(최소 투자비중/변동성 타게팅/리밸런스 억제)
- **실험 정의**: (1) exposure floor/ceiling (2) QQQ/XLV 관측 기반 위험 스위치 (3) 신호 변화 미미 시 거래 생략
- **게이트**:
  - 노출이 0%에 과도하게 머물면 실패(트리거/적용 문제로 분류)
  - 비용 반영 Net에서 MDD가 악화되면 실패
- **기대 관측치**:
  - 노출 분포가 안정화, oos_min 개선 기대
  - 거래 수/턴오버 감소 → Net 개선 여지

### E5) 재현성/감사 가능 인프라(해시/리밸런스 로그/No-Delta 차단)
- **실험 정의**: run_hash/lane_hash 강제 + rebalance JSONL 표준화 + no-delta 게이트 추가
- **게이트**:
  - 해시/로그 누락 시 실패
  - base/cand가 동일 신호·동일 거래면 “No-Delta”로 자동 중단
- **기대 관측치**:
  - pinpoint/diagnoser가 즉시 유효해지고, 48시간 루프에서 “의미 없는 반복”이 사라짐

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래 트리를 그대로 대시보드/리포트 항목으로 고정 출력해라.

1) **Trigger(신호 발생) 문제**
- 체크: 종목별/기간별 “신호 발생률(%)”, 연속 무신호 구간 길이, 신호 상관(모든 종목 동시 무신호 여부)
- 전형 원인: 피처 결측/스케일링 버그, 임계값 과도, 유니버스 필터가 과하게 보수적

2) **Application(신호→주문 변환) 문제**
- 체크: 신호 대비 실제 주문 발생률, 주문이 0으로 클리핑되는 비율(포지션 제한/리스크 규칙)
- 전형 원인: position sizing이 0에 수렴, 정수주/라운딩, 거래 단위/최소 주문 금액

3) **Exposure(노출) 문제**
- 체크: 시간대별 gross/net exposure 분포, 0% 체류 시간, 종목별 기여도, 포지션 상한에 “붙는” 시간
- 전형 원인: 과도한 현금화, 상한/하한 충돌, 리밸런스 억제 규칙이 과도

4) **Cost(비용/마찰) 문제**
- 체크: 턴오버, 거래 횟수, 평균 체결 비용(bps), 비용이 PnL에서 차지하는 비율
- 전형 원인: 잦은 리밸런스, 작은 알파를 비용이 상쇄, 공매도 비용/리콜

5) **Regime(레짐) 문제**
- 체크(관측지표만): `QQQ`, `XLV`의 추세/변동(예: 20일 변동, 60일 드로우다운), 금리 민감(간단히 HYG 같은 크레딧 스프레드 ETF를 “관측”만)
- 전형 원인: 모델이 특정 국면(저변동/상승장)에만 최적화, 레짐 전환 감지 실패

6) **Leakage/Overfit(누수/과최적화) 문제**
- 체크: purged CV 적용 전후 성능 갭, 쉬프트 테스트 성능 유지 여부, 폴드 퇴화 여부
- 전형 원인: 라벨 미래 참조, 리밸런스 시점과 가격 사용 시점 불일치(close로 의사결정+close 체결), 데이터 정렬 오류

---

### 실행 순서(48시간 내) — 그대로 수행
1. **E5 먼저 적용**(해시/리밸런스 로그/No-Delta 차단) → 실험이 “측정 가능”해진 뒤
2. **E1 수행**(purged CV + degenerate fold 제거) → 검증 체계 정상화
3. **E2 수행**(고정 유니버스 + PIT/조정/상폐) → 편향 제거
4. **E3 수행**(Net 비용) → 현실화
5. **E4 수행**(노출 거버넌스) → 운영 가능성/최악구간 방어

이 5개가 PASS 되기 전에는, 알파 개선/모델 복잡도 추가/종목 확장 같은 작업을 전부 금지해라.
