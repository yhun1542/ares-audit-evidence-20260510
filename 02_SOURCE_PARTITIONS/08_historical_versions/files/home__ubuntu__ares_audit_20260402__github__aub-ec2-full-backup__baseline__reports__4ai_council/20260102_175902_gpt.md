아래는 **24~48시간 내 우선순위 TOP5**를 “명령형 체크리스트”로 정리한 것입니다.  
단, **48시간 자동 루프에서 돌릴 ‘고유 실험/패치’를 5개(E1~E5)로 제한**하고, 각 TOP5 제안은 **이 5개를 재사용**해서 “각 제안별 2~3개 실험” 요구를 만족시키는 형태로 구성했습니다(케이스 폭발 방지).

## 공통 운영 전제(고정)
- **미국주식 only / ETF 매매 금지(관측지표로만 사용)**  
- **Tech+Healthcare 중심 8~14종목 유니버스 고정(예시 12)**

  - Healthcare: **LLY, UNH, JNJ, ABBV, MRK, ISRG**

- 현재 상태에서 즉시 위험 신호:
  - **degenerate_folds: [1,2,3,8]** → CV/워크포워드가 무너져 OOS가 “움직이지 않거나(무효)”, 과최적화/누수 탐지가 어려움
  - **worst_mdd: None** → 리스크 평가 미완(운영 리스크)
  - **rebalance pinpoint 로그 로딩 실패(JSON/경로 문제)** → 실험 간 “무변화(no-delta)” 원인 추적 불가(관측 불능)

# TOP5 (24~48h) 우선순위 제안

## 1) (전략/아키텍처) 누수·OOS 무결성부터 복구
### (a) 왜 필요한지
- **degenerate folds**가 존재하면, OOS mean/min이 좋아 보여도 “검증이 깨진 착시” 가능성이 큼.
- 누수(리포트 날짜/정정, forward-fill, 종가/체결시점 혼동) 있으면 개선이 **영구적으로 재현 불가**.

### (b) 위험/부작용
- 누수 제거/워크포워드 정비 후 **성능이 단기적으로 하락**할 수 있음(정상).
- 데이터 사용량/계산량 증가(embargo/purge)로 런타임 증가.

### (c) 최소 실험(재사용): **E1 + E2**
- E1: 누수 차단 패치 + 라벨/피처 시점 정렬
- E2: Purged walk-forward + fold health 게이트(퇴화 fold 제거)

### (d) PASS 조건(요약)
- **degenerate_folds = 0**
- OOS 지표가 “좋아졌다”가 아니라 최소한 **안정적으로 측정 가능**:
  - OOS min이 **지속적으로 음수 깊게 빠지지 않거나**(악화 방지)
  - fold별 성능 분산이 “무의미하게 0”이거나 “비정상 폭발”하지 않음

---

## 2) (전략) 비용/슬리피지/턴오버 미반영으로 인한 “가짜 개선” 제거
### (a) 왜 필요한지
- 지금은 **rebalance 로그도 깨져** 있어 실제 매매 빈도/회전율/비용이 관측 불가.  
- 비용 미반영 상태에서는 과최적화가 **턴오버로 숨는 경우**가 많음.

### (b) 위험/부작용
- 비용 모델을 넣으면 성능이 꺾일 수 있음(정상).
- 턴오버 제한이 신호 반응성을 둔화시킬 수 있음.

### (c) 최소 실험(재사용): **E3 + (E4로 관측 복구)**
- E3: 거래비용(스프레드+슬리피지+임팩트 단순화) + 턴오버 패널티/캡
- E4: 리밸런스 로그 스키마 고정(JSONL)으로 비용/턴오버 관측 복구

### (d) PASS 조건(요약)
- 비용 반영 후에도 **OOS mean이 과도하게 붕괴하지 않을 것**
- **턴오버/거래횟수/평균 보유기간**이 상식적인 범위로 수렴
- “개선”이 나올 경우, **gross→net 차이가 설명 가능**해야 함

---

## 3) (코드/운영) 관측 불능(로그/아티팩트) 먼저 고치기: No-Delta의 1순위 원인
### (a) 왜 필요한지
- 현재 메시지 그대로 **rebalance pinpoint가 파일/JSON 파싱 실패** → “실험이 실제로 포지션을 바꿨는지” 증명 불가.
- 관측이 깨지면 자동 루프는 **무의미한 반복**(서바이버십/선택 편향 강화).

### (b) 위험/부작용
- 로그를 자세히 남기면 디스크 사용량 증가.
- 스키마 변경 시 기존 리포트 파서 깨질 수 있음(버전 관리 필요).

### (c) 최소 실험(재사용): **E4 (+ E2의 게이트를 로그로 노출)**
- E4: 아티팩트/로그 표준화 + run_hash/lane_hash 강제 기록 + JSONL 고정
- E2: fold health를 “실험 실패 사유”로 로그에 남겨 자동 스킵 가능하게

### (d) PASS 조건(요약)
- `aub_rebalance_pinpoint.py`가 **base/cand 모두 로딩 성공**
- 각 실험마다 아래가 반드시 남음:
  - `run_hash`, `lane_hash`, 데이터 스냅샷 해시, 비용모델 버전, 유니버스 목록
- “No-Delta”가 발생하면 **원인 분류(게이트 실패/신호 0/포지션 캡/비용 패널티)**가 로그로 자동 출력

---

## 4) (전략) 노출/캐시/리밸런스 트리거가 “움직이지 않는” 문제 제거
### (a) 왜 필요한지
- 현재 exposure max가 ~0.84이고 min 0.0 → **현금 구간이 길면** 성능이 “안 움직이는” 구간이 길어질 수 있음(특히 Tech/HC 강세장에서).
- No-Delta는 종종 “신호는 변했지만 게이트/캡/반올림/최소 주문단위”에서 포지션이 0으로 떨어져 발생.

### (b) 위험/부작용
- 노출을 올리면 변동성과 MDD가 증가 가능.
- 리밸런스 빈도를 올리면 비용이 증가.

### (c) 최소 실험(재사용): **E5 + E3**
- E5: 레짐/리스크 기반 노출 게이트(ETF 관측지표 사용, 트레이드 금지)
- E3: 잦은 리밸런스는 비용으로 제어(턴오버 패널티)해 폭주 방지

### (d) PASS 조건(요약)
- “포지션이 실제로 바뀌는지”가 확인되어야 함:
  - 48시간 내 백테스트/시뮬에서 **리밸런스 이벤트 수가 0이 아님**
  - 평균 노출/현금비중이 레짐에 따라 설명 가능(예: 위험 OFF에서만 노출 감소)

---

## 5) (전략) Tech+Healthcare 8~14종목 고정에서의 과최적화/서바이버십 방어
### (a) 왜 필요한지
- 소수 종목(8~14) + 강한 섹터 편중은 **서바이버십/레짐 편향**에 취약.
- 개선이 특정 종목(예: NVDA/LLY) 1~2개에만 의존하면 실전 취약.

### (b) 위험/부작용
- 종목 기여를 평탄화하면 강한 트렌드 수익을 일부 반납.
- 너무 강한 제약은 알파를 죽일 수 있음.

### (c) 최소 실험(재사용): **E1 + E5**
- E1: 데이터/라벨 시점 정렬로 “특정 종목 이벤트 누수” 제거
- E5: 레짐에서 섹터/리스크 기반으로 동일 섹터 쏠림을 완화(예: XLK vs XLV 상대강도 관측)

### (d) PASS 조건(요약)
- 종목별 PnL 기여 상위 1~2개 종목 의존도가 완화(최소한 리포트로 확인 가능)
- 레짐 변화(금리/변동성/섹터 로테이션)에 따라 노출이 비상식적으로 고정되지 않음

# 48시간 자동 루프용 “고유 패치/실험” 5개 (E1~E5)
각 실험은 (1) 실험 정의 (2) 게이트 (3) 기대 관측치로 작성.

---

## E1) 누수 차단 + 시점 정렬 하드 패치
1) **실험 정의**
- 모든 feature를 “t 시점 의사결정” 기준으로 강제 정렬:
  - 가격: t-1 close까지만 사용(체결은 t open 가정 등 명시)
  - 펀더멘털/실적: **발표일/공시일 이후**에만 반영, forward-fill은 “공시 이후 구간”으로만 제한
  - corporate action/리비전 데이터는 “당시 이용 가능했던 값”만 사용(가능하면 point-in-time)
- 라벨(수익률) 산출 구간과 피처 구간이 겹치면 자동 실패 처리.

2) **게이트(자동 실패 조건)**
- feature timestamp > decision timestamp 발견 시 즉시 FAIL
- 라벨 구간과 피처 구간 overlap 탐지 시 FAIL
- (리포트) 종목별로 “피처 최신시점 - 의사결정시점” 분포가 0을 초과하면 FAIL

3) **기대 관측치**
- 누수 의심 실험에서 흔한 “OOS가 갑자기 과도하게 좋아짐” 패턴이 줄어듦
- 대신 fold별 성능이 더 현실적인 분산을 보이며, 이후 개선이 재현 가능해짐

---

## E2) Purged Walk-Forward + Fold Health Gate로 degenerate_folds 제거
1) **실험 정의**
- K-fold 랜덤 CV 금지, **시간순 워크포워드**로 고정
- **purge + embargo(예: 5~20 trading days)** 적용
- 각 fold에 대해:
  - 최소 샘플/최소 거래일/최소 리밸런스 이벤트 수 기준을 충족해야 “유효 fold”로 인정

2) **게이트**
- `degenerate_folds`가 1개라도 발생하면 전체 실험 FAIL(챔피언 후보 제외)
- fold별 리밸런스 이벤트가 0이면 FAIL
- worst_mdd가 None이면 FAIL(리스크 리포팅 누락)

3) **기대 관측치**
- OOS mean/min이 “움직이는 지표”로 정상화
- “No-Delta”의 원인이 CV 붕괴였는지 즉시 분리 가능

---

## E3) 거래비용+턴오버 제어(과최적화/가짜 개선 방지)
1) **실험 정의**
- net PnL에 비용을 반영:
  - 고정수수료(0으로 둬도 됨) + 스프레드/슬리피지(예: bps 단순 모델) + 거래대금 비례 임팩트(단순 선형)
- 목적함수에 turnover penalty 추가 또는 일/주간 turnover cap 적용
- 포지션 변경 최소단위/반올림 정책을 명시적으로 모델링(“변했는데 0으로 떨어지는” 현상 방지/탐지)

2) **게이트**
- turnover가 상한을 초과하면 FAIL
- gross는 좋아지는데 net이 급락하면 “비용 민감”으로 태깅하고 챔피언 승격 금지

3) **기대 관측치**
- 개선이 “거래를 많이 해서 만든 착시”인지 즉시 드러남
- 전략이 덜 흔들리고 실전형으로 수렴

---

## E4) 리밸런스 로그/아티팩트 표준화(관측 복구)
1) **실험 정의**
- rebalance 로그를 **JSONL 고정 스키마**로 저장(한 줄=한 이벤트):
  - timestamp, symbol, target_weight, prev_weight, delta_weight, price, est_cost, realized_cost(가능 시), reason_code
- 실행 메타데이터 필수 기록:
  - `run_hash`, `lane_hash`, 코드 커밋 해시, 데이터 스냅샷 해시, 비용모델 버전, 유니버스 목록
- `aub_rebalance_pinpoint.py`가 요구하는 입력 포맷에 맞춰 **파일 경로/생성 규칙을 고정**하고, 실패 시 즉시 원인 출력.

2) **게이트**
- pinpoint 도구가 base/cand 둘 다 로딩 성공 못 하면 FAIL
- JSON 파싱 에러 발생 시 FAIL
- run_hash/lane_hash 누락 시 FAIL

3) **기대 관측치**
- “실험이 성능을 못 움직이는 이유”가 로그에서 바로 분류됨  
  (예: 신호 0 / 게이트 차단 / 포지션 캡 / 비용 패널티 / 반올림)

---

## E5) 레짐/리스크 기반 노출 게이트(ETF는 관측만)
1) **실험 정의**
- 포지션은 12종목(Tech+HC)만, 대신 노출을 레짐으로 조절:
  - 관측지표 예:  
    - 섹터 상대강도: XLK/XLV 모멘텀(관측만)  
    - 시장 리스크: SPY 추세, VIX 상승 구간  
    - 성장/금리 민감도 간접: QQQ vs SPY, XBI 변동성
- 규칙 예:
  - Risk-Off(예: VIX 급등 + SPY 하락 추세) → 총 노출 상한 축소, 현금 비중 확대
  - Risk-On → 총 노출 상한 확대(단, E3 비용/턴오버로 제어)

2) **게이트**
- 노출 상한이 레짐과 무관하게 고정이면 FAIL(게이트 로직 비작동)
- 레짐 전환 시 리밸런스가 0회면 FAIL(적용 단계 문제)

3) **기대 관측치**
- MDD/급락 구간 방어가 생기고, 반대로 Risk-On에서는 “너무 현금”인 문제를 완화
- 성능이 안 움직이던 구간에서 **노출의 설명력**이 생김

---

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래 트리를 **로그로 자동 분류(reason_code)** 하도록 E4에 붙여 운영 리스크를 줄여라.

## A. 트리거(신호 생성) 단계
- 신호가 0/NaN으로 평평: 피처 결측/스케일링 오류/윈도우 길이 과대
- 신호는 변하는데 동일 종목/동일 방향만 반복: 과최적화/단일 팩터 종속

**관측 지표**
- 시점별 신호 분산, NaN 비율, 상위 3종목 신호 점유율

## B. 적용(게이트/필터) 단계
- 게이트가 과도하게 막음: 변동성 필터/리스크 필터/컴플라이언스 캡이 상시 활성
- CV fold 퇴화로 실험이 사실상 무효: degenerate_folds 재발

**관측 지표**
- “신호→주문” 전환율(accept rate), 게이트별 차단 횟수

## C. 노출/포지션 사이징 단계
- 노출이 너무 낮아 PnL이 안 움직임(현금 과다)
- 반올림/최소 단위로 델타가 0이 됨(= No-Delta 핵심 원인)

**관측 지표**
- 평균/중앙 노출, 현금 비중, 평균 |delta_weight|, 0-delta 비율

## D. 비용 단계
- gross는 개선인데 net이 정체/악화: 턴오버/슬리피지 민감
- 비용모델 부재로 “좋아 보였던” 실험들이 전부 무효

**관측 지표**
