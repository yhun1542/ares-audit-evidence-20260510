# TOP5 우선순위 제안 (각 항목: a/b/c/d)

## P1) (최우선) **시점 누수/정렬(lookahead) 완전 차단**
### (a) 왜 필요한지
- 현재 Champion이 lockbox가 tuning보다 높은 형태라 “겉보기엔” 괜찮아 보이지만, **부분 누수/정렬 오류는 특정 폴드/구간에서만 성능을 과대**시키고, 운영 투입 시 재현 실패로 이어집니다.
- 특히 “일봉 close 기반 feature + same-day 체결” 류는 흔한 잠복 누수입니다.

### (b) 위험/부작용
- 누수를 막으면 **단기 성능 하락**이 정상입니다(그게 정상 신호).
- lag 강제 시 신호가 약해져 turnover/보유기간이 바뀔 수 있습니다.

### (c) 최소 실험 2~3개 (고유 실험 재사용)
- **E1**(누수/정렬 패치) + **E4**(제약 강제)  
- **E1** + **E3**(비용모델 포함 재평가)  
- **E1** + **E5**(레짐 지표를 쓰더라도 시점 정렬 안전성 확인)

### (d) PASS 조건
- **게이트(필수)**:  
  - 신호 생성 timestamp ≤ 주문 timestamp - 1 bar (일봉이면 최소 1일 lag) 강제 통과  
  - “same-bar 체결” 탐지 플래그 0건
- **성능(락박스)**:  
  - lockbox_mean **≥ 3.6** (Champion 4.01의 90% 하한)  
  - worst_mdd **≥ -0.085** (Champion -0.081 근처에서 과도 악화 방지)  
  - lockbox_min **≥ 0.7** (Champion 0.735 근처 유지)

## P2) **서바이버십/상장폐지/기업행동 반영(특히 delist return)**
### (a) 왜 필요한지
- 미국주식 백테스트에서 가장 흔한 구조적 과대평가 원인 중 하나가 **서바이버십 + 상폐 미반영**입니다.
- Tech/Healthcare는 M&A/상폐/스핀오프 이벤트 영향이 크고, “살아남은 대형주만 남는 데이터”면 전략이 과대평가됩니다.

### (b) 위험/부작용
- 데이터 소스/정합성 이슈로 결측이 늘고, 거래가능성 필터가 빡세져 종목 풀이 줄 수 있습니다.
- lockbox 변동성이 증가할 수 있습니다(정상).

### (c) 최소 실험 2~3개
- **E2**(PIT universe + delist + corp action 패치) + **E3**(비용 포함)  
- **E2** + **E4**(8~14종목/섹터 강제 시 “종목 부족” 발생 여부 확인)  
- **E2** + **E1**(정렬/누수까지 같이 잠가 “정상 하락인지” 분리)

### (d) PASS 조건
- **게이트(필수)**:  
  - universe membership이 **as-of** 로딩임을 로그로 증명(미래 편입 금지)  
  - delist 처리된 종목이 테스트 기간 내 존재하면, 해당 거래일 수/수익 반영 리포트 출력
- **성능(락박스)**:  
  - lockbox_mean **≥ 3.6**  
  - worst_mdd **≥ -0.09** (서바이버십 제거로 악화 허용폭 소폭 확대)  
  - 폴드 간 성능 분산이 급증하지 않을 것(예: fold Sharpe 표준편차 상한)

### (a) 왜 필요한지

### (b) 위험/부작용
- 비용모델 강화 시 성능이 크게 내려갈 수 있습니다(그게 현실).
- 턴오버 제한은 알파 소실 위험이 있습니다.

### (c) 최소 실험 2~3개
- **E3**(ADV/변동성 기반 슬리피지 + 수수료 + 턴오버 게이트) 단독  
- **E3** + **E4**(포지션 상한/집중도 상한으로 임팩트 감소)  
- **E3** + **E5**(레짐이 나쁠 때 리밸런싱 빈도/위험 예산 축소)

### (d) PASS 조건
- **게이트(필수)**:  
  - 평균 일간 턴오버 상한(예: **≤ 25~35%**) 통과

- **성능(락박스)**:

## P5) **레짐(ETF 관측지표 기반)로 위험 예산/리밸 빈도만 조절(신호 과최적화 방지)**
### (a) 왜 필요한지

- ETF는 거래하지 않고 **관측지표**로만 써서 “과최적화 폭발”을 억제할 수 있습니다.

### (b) 위험/부작용
- 레짐 필터는 잘못 만들면 “필터가 알파를 죽이는” 결과가 납니다.
- 지표가 많아지면 튜닝 공간이 커져 과최적화 위험이 다시 증가합니다(지표는 최소로).

### (c) 최소 실험 2~3개
- **E5**(관측지표: QQQ/XLV 상대강도, VIX, TNX 등 2~3개만)로

- **E5** + **E3**(레짐 나쁠 때 turnover 감소가 비용에 주는 효과 확인)  
- **E5** + **E4**(레짐에 따라 섹터 밴드만 살짝 조절하되 8~14 유지)

### (d) PASS 조건
- **게이트(필수)**:  
  - 레짐 변수는 “관측 시점”이 명확해야 함(E1 정렬 규칙 준수)  
  - 레짐 적용이 “종목 선정 로직”을 바꾸지 않고 **위험 예산/리밸 빈도**만 건드릴 것(과최적화 방지)
- **성능(락박스)**:  
  - worst_mdd **개선 또는 유지**(예: -0.081 → -0.075~ -0.085 범위 내)  
  - lockbox_mean **≥ 3.6** 또는 lockbox_mean 소폭 하락해도 drawdown/분산이 유의미하게 개선되면 통과(운영 관점)

# 고유 실험 정의 (E1~E5): 48시간 자동 루프 포맷
아래는 각 실험을 **(1) 실험 정의 (2) 게이트 (3) 기대 관측치**로 고정합니다.

## E1) Leak/Alignment Hardening
1) **실험 정의**
- feature 생성 시점에 **최소 1 bar lag** 강제
- asof-merge(또는 equivalent)로 데이터 결합
- “same-bar trade” 자동 탐지/차단
2) **게이트**
- same-bar 체결 0건
- feature timestamp > trade timestamp 사례 0건
3) **기대 관측치**
- tuning 성능 일부 하락 가능(정상)
- lockbox 변동성 감소/재현성 증가가 관측되면 긍정

## E2) PIT Universe + Delist + Corporate Actions
1) **실험 정의**
- Point-in-time universe membership 강제
- delisting return 반영
- split/dividend 조정 일관성 점검(가격/수익률 계산 통일)
2) **게이트**
- 미래 편입 종목 탐지 0건
- delist 이벤트 로깅/반영 확인
3) **기대 관측치**
- 과거 급등/급락 구간에서 성능이 현실화(대체로 하향)
- 폴드 간 “가짜 안정성”이 사라지고 진짜 안정성만 남음

## E3) Cost/Impact Model + Turnover Gate
1) **실험 정의**
- 거래비용 = 고정 수수료 + (k * volatility) 또는 (k * spread proxy)  
- 가능하면 ADV 기반 임팩트(단순함수로도 됨)
- turnover 상한으로 리밸 과다 차단
2) **게이트**
- 평균/상위 분위 turnover 상한 통과
- gross/net 분리 리포트 생성
3) **기대 관측치**
- net 성능의 “진짜 하한”이 잡힘
- 성능 정체의 원인이 비용인지 즉시 분해 가능

## E4) Constraint Enforcement (US only / Tech+HC / 8~14 / concentration caps)
1) **실험 정의**
- 포트폴리오 생성 단계에서 제약 위반 시 리밸 거부 또는 강제 보정
- single-name cap, sector band, 현금 처리 규칙 고정
2) **게이트**
- 전 기간 제약 위반 0 또는 사전 정의된 예외만
3) **기대 관측치**
- 운용 가능성(운영 리스크) 대폭 감소
- mdd 꼬리 리스크 완화 가능

## E5) Regime Overlay using ETF Observables (non-tradable)
1) **실험 정의**
- 관측지표(예: QQQ vs XLV 상대강도, VIX, TNX)로  
  - 총 익스포저(0.6~1.0) 또는 리밸 빈도만 스케일
- 종목 선정/랭킹 로직은 가급적 불변
2) **게이트**
- 레짐 지표의 시점 정렬(E1 규칙) 통과
- 지표 수 최소(2~3개)로 고정(과최적화 방지)
3) **기대 관측치**
- 변동성 급등 구간에서 worst_mdd 개선
- 성능이 안 오르더라도 tail 개선이면 운영적으로 가치 있음

# 성능이 “안 움직일 때” 원인 분해 아이디어 (Trigger/적용/노출/비용/레짐)
아래를 **리포트 항목으로 고정**해서, 매 루프마다 같은 프레임으로 진단하세요(질문 없이 실행 가능).

## 1) Trigger(신호 발생) 문제
- [ ] 신호 활성화 비율(포지션 변경 발생 일수 / 전체 일수)
- [ ] 신호 강도 분포(상위 5%만 의미 있는지, 전부 노이즈인지)
- [ ] “항상 비슷한 종목만” 드는지(다양성 부족=알파 고갈/제약 과강)

## 2) 적용(Execution/리밸) 문제
- [ ] 리밸 빈도/지연으로 알파가 희석되는지(신호→체결 시차)
- [ ] 제약 보정 때문에 “원래 신호”가 얼마나 왜곡되는지(보정량 로그)

## 3) 노출(Exposure) 문제
- [ ] 베타/섹터/스타일(대형/성장) 노출이 사실상 전부인지  
  - ETF 관측: QQQ, XLV와의 상관/회귀(거래는 X)
- [ ] 상위 1~2개 종목이 성과 대부분을 좌우하는지(집중 리스크)

## 4) 비용(Fees/Slippage/Turnover) 문제
- [ ] gross vs net 갭(비용이 알파를 몇 % 잠식하는지)
- [ ] turnover와 성과의 관계(턴오버 높은 구간에서만 성과가 나오는지)

## 5) 레짐(Regime) 문제
- [ ] VIX 상승/금리 급변(TNX) 구간에서 성과가 구조적으로 깨지는지
- [ ] QQQ(Tech) vs XLV(Healthcare) 상대강도 레짐별로 어느 쪽이 유리한지  
  → 레짐 오버레이(E5)는 “종목선정 고정 + 위험예산만 조절”로 최소개입
