아래는 **24~48시간 안에 자동 루프(48h)로 바로 돌릴 수 있는 우선순위 TOP5**입니다. 단, “케이스 폭발 방지(3~5개 실험)” 절대 규칙을 지키기 위해 **고유 실험은 E1~E5(총 5개)**로만 정의하고, 각 TOP5 작업은 **이 5개 실험을 재사용**해 2~3개씩 연결합니다.

---

## 0) 즉시 경고(현재 ONE TRUTH에서 보이는 실패 징후)
- **degenerate_folds: [1,2,3,8]** → CV/워크포워드가 무너져 **OOS가 안 움직이거나 과최적화**로 굳을 수 있음(최우선).
- **worst_mdd: None** → 리스크 지표가 계산/로그 누락(운영 리스크 + 게이트 불가).
- **lane_hash/run_hash: None** → 재현성/추적성 붕괴(“왜 안 움직였는지” 원인 분해 불가).
- **Rebalance Pinpoint가 입력을 못 읽음**(base-log 경로 오류, CSV/JSON 파싱 실패) → “성능 차이 = 리밸런스 차이” 분석이 막힘.
- **exposure max 0.84** + oos_min 음수 → 노출/비용/리스크 제약이 약하거나 비용이 목적함수에서 누락 가능성.

# 1) TOP5 우선순위 제안(코드/아키텍처/전략)

## TOP1) 누수/서바이버십/타임라인 정합성 “차단 패치”
**(a) 왜 필요한지**
- OOS가 멈출 때 1순위 원인은 **라벨 누수, 재구성 누수(룩어헤드), survivorship**입니다.
- Tech+Healthcare 소수 종목(8~14)일수록 “데이터 한 줄”의 누수가 성능을 영구 고정시킵니다.

**(b) 위험/부작용**
- 누수 차단 후 단기적으로 OOS가 하락할 수 있음(“진짜 성능”으로 수렴).
- 종목 액션(스플릿/머지/심볼변경) 정합성 엄격화로 표본이 줄 수 있음.

**(c) 최소 실험(아래 E1~E5 재사용, 2~3개)**
- **E1 + E3 + E4**  

**(d) PASS 조건**
- (필수) 누수 체크 통과 + fold degeneracy 0  
- (필수) OOS mean이 과도하게 튀지 않고(±비정상 급등락 감소) OOS min 개선 또는 비용 포함 후 손익 구조가 합리화  
- (필수) lane_hash/run_hash 및 rebalance trace 생성

---

## TOP2) 비용 미반영(수수료/슬리피지/임팩트/턴오버) “목적함수에 주입”
**(a) 왜 필요한지**
- 자동 리밸런스 시스템은 비용이 목적함수에 없으면 **“수익=거래량”**으로 과적합됩니다.
- 특히 8~14 종목 집중이면 리밸런스가 잦아질 때 비용이 수익을 잡아먹어 **OOS가 안 움직이는 착시**가 생깁니다.

**(b) 위험/부작용**
- 비용을 넣으면 총수익이 떨어져 보일 수 있음(현실화).
- 지나친 비용 페널티는 기회 상실(너무 안 움직이는 포트폴리오).

**(c) 최소 실험**
- **E2 + E4** (+ 필요 시 E5)

**(d) PASS 조건**
- (필수) “Gross Sharpe 개선”이 아니라 **Net(비용 차감) 기준** 개선
- (필수) turnover 상한(예: 일/주 기준)을 넘지 않음
- (필수) 비용 기여도(비용으로 깎인 PnL)가 리포트에 분해되어 출력

---

## TOP3) 과최적화/degenerate fold 제거: 워크포워드·Purged CV 정비
**(a) 왜 필요한지**
- degenerate_folds가 있다는 건 **학습/검증 분할이 무효**라는 뜻이고, 이 상태에선 실험을 100개 돌려도 “안 움직임”이 정상입니다(평가가 고장).

**(b) 위험/부작용**
- 더 엄격한 CV는 OOS 평균이 낮아질 수 있음(하지만 신뢰도는 증가).
- 계산량/시간 증가.

**(c) 최소 실험**
- **E3 + E4** (+ 누수 의심이면 E1)

**(d) PASS 조건**
- (필수) degenerate_folds = [] (0개)
- (필수) 각 fold의 표본수/거래수 최소치 충족(게이트로 강제)
- (필수) 동일 run_hash에서 재실행 시 결과 동일(재현성)

---

## TOP4) 운영/아키텍처: 리밸런스 로그/아티팩트 계약(Artifact Contract) 고정
**(a) 왜 필요한지**
- 지금은 pinpoint 도구가 **입력을 못 읽고** 있고, lane_hash/run_hash가 None이라 **원인분해가 구조적으로 불가**합니다.
- “안 움직임”의 절반은 성능 문제가 아니라 **관측 불능** 문제입니다.

**(b) 위험/부작용**
- 로그/아티팩트가 늘어 스토리지 비용 증가(하지만 48h 루프 안정성이 훨씬 중요).

**(c) 최소 실험**
- **E4 + E3**

**(d) PASS 조건**
- (필수) rebalance.csv 또는 jsonl이 항상 생성되고 파싱 가능
- (필수) base-log 경로/형식 자동 탐지 또는 실패 시 즉시 hard-fail(조용히 넘어가지 않기)
- (필수) worst_mdd, exposure_min/max, turnover, cost가 모두 리포트에 채워짐(None 금지)

---

## TOP5) 노출/리스크/레짐: 8~14 종목(Tech+Healthcare) 집중 운영을 “게이트화”
**(a) 왜 필요한지**
- 노출 상한이 0.84까지 열려 있고, 비용/리스크가 결합되면 레짐에 따라 결과가 굳을 수 있습니다.
- ETF는 매매 금지이므로 **QQQ/XLV 같은 ETF는 ‘관측 지표’로만 레짐 게이트**에 써야 합니다.

**(b) 위험/부작용**
- 리스크 게이트가 과하면 포지션이 비어 성능이 낮아질 수 있음(하지만 손실/운영 안정성 개선).

**(c) 최소 실험**
- **E5 + E2** (+ 데이터 정합성 불안하면 E1)

**(d) PASS 조건**
- (필수) 종목 수 8~14 유지(집중/분산 규칙 준수)
- (필수) max exposure / sector tilt / single-name cap이 위반되지 않음
- (필수) 레짐 분할(예: QQQ 추세/변동성 상태)에서 극단적 손실 구간 감소

# 2) 48시간 자동 루프용 “실행 가능한” 고유 실험 5개 (E1~E5)
각 실험은 **(1) 실험 정의 → (2) 게이트 → (3) 기대 관측치**로 고정합니다.

---

## E1) Leakage/Survivorship Hardening 패치
1) **실험 정의**
- 피처/라벨 생성에 **t 시점 데이터만 사용** 강제(룩어헤드 차단)
- corporate action 조정(스플릿/배당)과 심볼 변경을 포함한 **survivorship-safe universe 스냅샷** 사용
- 추천 운영 유니버스(예시, 8~14):  
  Tech: AAPL, MSFT, NVDA, GOOGL, AMZN, META, AVGO  
  Health: LLY, UNH, ABBV, MRK, JNJ (필요시 8~14로 컷)

2) **게이트**
- “feature timestamp <= decision timestamp” 위반 0건
- 학습 구간에만 존재하는 종목(서바이버십 편향) 사용 금지 체크 통과
- 누수 탐지(간단히: 미래 수익률과 동시/미래 피처 상관 급등) 알람 임계치 이하

3) **기대 관측치**
- OOS mean이 일시 하락해도 **OOS min 개선/변동성 감소**
- 실험 간 성능 분산이 줄고(덜 튐) 재현성이 증가

---

## E2) 비용 내재화: Net Objective + Turnover Penalty
1) **실험 정의**
- 거래비용 모델(최소): commission + spread proxy + slippage(변동성 기반)  
- 목적함수/스코어를 **net PnL 기준**으로 변경
- turnover penalty(예: |Δw| L1) 추가

2) **게이트**
- 비용 차감 전/후 성능을 둘 다 저장(비용이 “0”으로 기록되면 실패)
- turnover 상한(예: 일간/주간) 위반 시 실험 즉시 FAIL
- 거래 체결 불가능(유동성/가격 누락) 발생률 임계치 이하

3) **기대 관측치**
- gross 성능이 낮아져도 **net 성능의 신뢰도 상승**
- “실험 성능이 안 움직임”이 사실 비용에 상쇄되던 현상인지 분해 가능

---

## E3) degenerate fold 제거: Purged Walk-Forward + 최소 거래수 게이트
1) **실험 정의**
- 시간순 walk-forward로 통일 + purge/embargo(인접 구간 누수 차단)
- fold별 최소 거래수/최소 일수/최소 변동성 조건을 미달하면 fold를 버리고 **실험 자체를 FAIL** 처리(조용히 진행 금지)

2) **게이트**
- degenerate_folds = 0
- 각 fold에 대해 (i) N_days >= 임계치 (ii) trades >= 임계치 만족
- 동일 seed/run_hash 재실행 시 결과 동일(완전 결정론)

3) **기대 관측치**
- OOS가 “의미 있게” 변하기 시작(평가계가 복구)
- 극단적 OOS mean 튐이 감소

---

## E4) Rebalance Trace/Artifact Contract 패치(운영 필수)
1) **실험 정의**
- 매 리밸런스마다 다음을 **단일 jsonl**로 강제 기록:  
  timestamp, universe, signal, target_w, prev_w, Δw, fill_price, cost, reason_codes
- run_hash/lane_hash 생성 규칙 고정(설정+코드+데이터 스냅샷 해시)
- aub_rebalance_pinpoint 입력 포맷을 **항상 파싱 가능**하게 맞춤

2) **게이트**
- rebalance 로그 파일 1) 생성 2) 파싱 3) 행 수>0 모두 통과
- worst_mdd / exposure / turnover / cost 지표가 None이면 FAIL
- base-log 경로 오류 시 hard-fail(지금처럼 “없음”으로 진행 금지)

3) **기대 관측치**
- “안 움직임”의 원인이 **거래가 없어서인지/게이트로 막혀서인지/비용 때문인지** 즉시 분해 가능

---

## E5) 노출/레짐 게이트: ETF는 관측만(매매 금지)
1) **실험 정의**
- 포트폴리오 제약:  
  - names: 8~14 유지  
  - single-name cap(예: 12~15%)  
  - sector tilt cap(Tech/Health 쏠림 제한)  
  - max gross exposure(예: 0.70~0.85 중 하나로 고정)
- 레짐 관측(예: QQQ, XLV): 추세/변동성 상태에 따라 **리밸런스 빈도 또는 max exposure를 조절**(매매는 주식만)

2) **게이트**
- 제약 위반 0회
- 레짐별(상승/하락/고변동) 성능 리포트 자동 생성
- 현금 비중이 과도(예: >60% 장기간)하면 FAIL(“아무것도 안 해서 안전” 방지)

3) **기대 관측치**
- 특정 레짐에서의 급락/급등 민감도 감소
- 노출이 일정 범위에 머물며 OOS min 개선 기대

---

# 3) “성능이 안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래는 **질문 없이 바로 점검 가능한 트리거 기반 분해 체크리스트**입니다.

## A. Trigger(신호가 안 바뀜)
- 신호 분포(각 종목 score 히스토그램)가 실험 전후 거의 동일한지 확인  
- 상위 k 선택 종목이 항상 동일(“항상 NVDA/MSFT만”)이면 **특징량 포화/정규화 버그** 의심  
- 레짐 지표(ETF 관측)가 항상 같은 상태로 분류되면 **레짐 로직/데이터 인덱싱 오류** 의심

## B. Apply(신호는 바뀌는데 포지션이 안 바뀜)
- 목표비중(target_w) vs 실제 주문(Δw) 0이 반복되면:
  - 제약(캡/턴오버 상한/리밸런스 쿨다운)이 과도
  - 리밸런스 조건문(if)이 항상 false
  - 가격/거래가능 플래그가 누락되어 “스킵” 처리
- 해결: **E4의 reason_codes**로 “왜 스킵했는지”를 코드화해서 로그로 남김

## C. Exposure(노출이 결과를 고정)
- gross/net exposure 시계열이 거의 일정하면:
  - 스케일링(예: vol targeting)이 신호를 다 눌러버림
  - max exposure가 너무 낮거나 cash gate가 과도
- 해결: E5에서 노출 게이트를 수치로 강제하고, 레짐별 노출을 리포트로 분해

## D. Cost(비용이 알파를 상쇄)
- gross PnL은 개선인데 net PnL은 정체면 100% 비용 문제
- turnover/거래횟수/평균 Δw가 증가했는지 확인
- 해결: E2로 목적함수를 net으로 바꾸고 비용 기여도를 자동 출력(거래당 비용, 총비용, 비용/수익 비율)

## E. Regime(특정 장에서만 죽음)
- 전체 OOS 평균이 정체여도 레짐별로는 개선/악화가 섞여 평균이 상쇄될 수 있음
- QQQ(Tech), XLV(Health) 관측으로 최소 4분면(추세×변동성) 분해:
  - 상승·저변동 / 상승·고변동 / 하락·저변동 / 하락·고변동
- 해결: E5 레짐 게이트로 “하락·고변동”에서 노출 축소/리밸런스 완화 등 운영 룰을 실험

---

# 24~48시간 실행 순서(명령형 체크리스트)
1) **E4(로그 계약) 먼저 적용** → 다음 런부터 관측 불능 제거  
2) **E3(CV 복구) 적용** → degenerate_folds 0 만들기  
3) **E2(비용 내재화) 적용** → net 기준으로 목적함수 전환  
4) **E1(누수/서바이버십) 적용** → 데이터 정합성 하드닝  
5) **E5(노출/레짐 게이트) 적용** → 운영 리스크/레짐 손실 꼬리 제거

이 순서로 돌리면, “성능이 안 움직임”이 **진짜 전략 한계인지 / 평가계 고장인지 / 비용 상쇄인지 / 운영로그 부재인지**가 48시간 내에 갈라집니다.
