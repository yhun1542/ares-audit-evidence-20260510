## TOP 5 우선순위 제안

### #1. Champion lockbox 분산 원인 분해 (과최적화 점검)

#### (a) 왜 필요한가
- lockbox_mean/min 비율 5.4x → 특정 fold에서 비정상 수익 집중
- tuning vs lockbox 괴리 (2.32 vs 4.01) → 튜닝셋 대비 lockbox 과대성과 = 역방향 누수 의심

#### (b) 위험/부작용
- 분석 결과 Champion이 폐기 대상이 될 수 있음
- 분석 시간 소요 (4-8시간)

#### (c) 최소 실험

```yaml
EXP-1.1: lockbox_fold_decomposition
  action: 각 lockbox fold별 수익률/MDD 개별 출력
  gate: 자동 (스크립트 실행)
  expected: 특정 1-2개 fold가 전체 수익의 70%+ 차지 여부 확인

EXP-1.2: champion_feature_ablation  
  action: Champion의 상위 3개 신호 각각 제거 후 lockbox 재평가
  gate: 72시간 이내
  expected: 단일 신호 제거 시 성과 50%+ 하락 → 과의존 확정

EXP-1.3: regime_attribution
  action: lockbox 기간을 VIX 레짐(low/mid/high)별로 분리 측정
  gate: 자동
  expected: 단일 레짐에서 수익 80%+ → 레짐 과의존
```

#### (d) PASS 조건
- [ ] 모든 fold의 수익률 표준편차가 mean의 50% 이하
- [ ] 상위 신호 ablation 시 성과 하락 30% 이내
- [ ] 레짐별 수익 기여도 최대 60% 이하
