**B. 리스크:** 없음(시스템 안정화). 단, 로그 용량 증가 가능성.
**C. 실행 계획 (3 Checkpoints):**
1.  **Format Unification:** `rebalance_logger`가 CSV가 아닌 `JSON Lines (.jsonl)` 형태로만 기록하도록 강제 변경. (Nested structure 호환)

3.  **Path Fix:** `AUB Rebalance Pinpoint` 실행 시 `--base-log` 경로가 실제 생성된 timestamp 폴더를 가리키도록 동적 바인딩 스크립트 수정.

**D. PASS 조건:**
*   `rebalance.jsonl` 파일 정상 생성 및 `AUB Rebalance Pinpoint` 툴이 에러 없이 파싱 성공.

### [성능 정체 시 원인 분해 아이디어]

만약 위 실험 후에도 성능이 개선되지 않는다면, 다음 트리를 따라 디버깅하십시오.

1.  **Trigger Failure (신호 부재):**
    *   *증상:* 거래 횟수가 너무 적음.
    *   *확인:* 진입 임계값(Threshold)이 너무 높은지 확인. 변동성이 죽은 시장에서 신호가 안 나가는지 체크.

2.  **Allocation Failure (비중 실패):**
    *   *증상:* 승률은 55% 이상인데 계좌는 우하향.
    *   *확인:* 이기는 종목에 비중을 적게 싣고(0.05), 지는 종목에 많이 싣는지(0.15) 확인. `Equal Weight`로 변경하여 실험.

3.  **Cost Impact (비용 누수):**
    *   *증상:* Gross Return은 우상향, Net Return은 횡보/하락.
    *   *확인:* 턴오버(회전율) 확인. Tech/Bio 종목의 스프레드 비용이 과소평가되었는지 확인 (Bps를 5 -> 10으로 올려서 스트레스 테스트).

4.  **Regime Mismatch (레짐 불일치):**
    *   *증상:* 특정 연도(예: 2022)에만 손실 집중.
    *   *확인:* 전략이 "추세 추종"인데 "횡보장"에서 톱질(Whipsaw) 당하는지 확인. 횡보장 필터(ADX < 20 시 매매 중단 등) 도입 검토.
