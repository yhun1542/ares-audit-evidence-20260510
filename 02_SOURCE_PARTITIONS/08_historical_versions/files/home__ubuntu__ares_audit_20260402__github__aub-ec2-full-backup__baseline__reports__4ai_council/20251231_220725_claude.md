**(b) 위험/부작용**
- 분석만으로 끝나면 actionable 아님
- Fold 재분할 시 전체 백테스트 무효화 위험

**(c) 최소 실험**

| 실험 | 정의 | 게이트 | 기대 관측치 |
|------|------|--------|-------------|
| 1-A | fold14 구간 trade-by-trade PnL 히트맵 생성 | 완료 | 손실 > 2σ 집중일 식별 |
| 1-B | 해당 구간 VIX/SPY 레짐 태그 교차 | 완료 | 레짐='crisis' 비율 확인 |
| 1-C | fold14 제외 후 lockbox 재평가 (민감도) | Δlockbox < 3% | 제외 전후 mean 비교 |

**(d) PASS 조건**
```
fold14 손실의 70% 이상이 단일 레짐(crisis/high-vol)에 집중
→ 레짐 필터 PATCH #5로 위임

### PATCH #4: Entry Threshold 재보정

**(a) WHY**
- 성능 정체 = 트리거가 너무 느슨(노이즈 진입) 또는 너무 엄격(기회 누락)
- tuning_min = 0.05 (거의 0) → 일부 fold에서 거의 비활성

**(b) 위험/부작용**
- Threshold 조정 = 전형적 과최적화 유혹
- 양방향 민감도 모두 테스트 필수

**(c) 최소 실험**

| 실험 | 정의 | 게이트 | 기대 관측치 |
|------|------|--------|-------------|
| 4-A | 현재 threshold ±10%, ±20% 그리드 (5점) | lockbox 비교 | 최적점 이동 여부 |
| 4-B | 진입 빈도(trades/month) 시계열 | 완료 | 빈도 vs 성과 상관 |
| 4-C | Threshold 동적화 (VIX 연동) 프로토타입 | Δlockbox ≥ +2% | 개선 여부 |

**(d) PASS 조건**
```
그리드 내 lockbox 분산 < 5%
→ threshold 민감도 낮음 확인 (robust)
분산 > 10%
→ 과최적화 위험, 중앙값 고정
```

### PATCH #5: VIX Regime Gate 추가

**(a) WHY**
- fold14 MDD 집중 구간 = 고변동 레짐 가능성
- 현재 전략: 레짐 무관 동일 로직 → tail 방어 없음

**(b) 위험/부작용**
- VIX 임계값 설정 = 새로운 파라미터 (과최적화 1개 추가)
- 레짐 필터 과도 시 기회비용 급증

**(c) 최소 실험**

| 실험 | 정의 | 게이트 | 기대 관측치 |
|------|------|--------|-------------|
| 5-A | VIX > 25 구간 수익률 분리 | 완료 | 해당 구간 Sharpe |
| 5-B | VIX > 30 시 포지션 50% 축소 규칙 | worst_mdd ≥ -0.09 | MDD 개선 |
| 5-C | VIX > 35 시 전량 현금화 규칙 | lockbox_mean ≥ 1.70 | 수익률 유지 |

**(d) PASS 조건**
```
5-B 또는 5-C에서 worst_mdd ≥ -0.09 AND lockbox_mean ≥ 1.75
→ PASS (레짐 게이트 채택)
```

## 3. 성능 정체 원인 분해 트리

```
성능 불변 (Δ ≈ 0)

├─ [트리거] 신호 자체가 발동 안 함

├─ [적용] 신호 발동 but 포지션 미반영
