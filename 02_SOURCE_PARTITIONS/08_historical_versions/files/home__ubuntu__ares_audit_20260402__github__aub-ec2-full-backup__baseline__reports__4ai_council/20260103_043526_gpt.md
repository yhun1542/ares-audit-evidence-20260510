## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — 명령형 체크리스트

### 1) **리밸런스/아티팩트 로깅 복구(운영 리스크 최우선)**
- **(a) 왜 필요한지**
  - `aub_rebalance_pinpoint`가 **로그 경로/포맷 오류**로 완전 실패 → “왜 성능이 안 움직였는지(트레이드가 났는지/노출이 먹었는지/비용이 반영됐는지)”를 추적 불가.
  - `lane_hash/run_hash=None`, `worst_mdd=None` → 재현성/리스크 산출 파이프라인이 깨진 상태.
- **(b) 위험/부작용**
  - 로깅/스키마 변경으로 **기존 리포트 호환성 깨짐**.
  - 메타데이터 강제 시 일부 실험이 “실행은 됐지만 저장 실패”로 중단될 수 있음(초기에 좋음: 조기 실패가 운영 안정성을 올림).
- **(c) 최소 검증(2~3개)**
  - (실험) **E1** 수행(아래 “48시간 자동 루프 실험” 참조)
  - (체크) `rebalance.csv` 또는 `rebalance.jsonl` **단일 표준 포맷**으로 강제 저장(빈 파일/깨진 JSON 방지)
  - (체크) 리포트 생성 단계에서 `worst_mdd`, `lane_hash`, `run_hash` **필수 필드 누락 시 하드 실패**
- **(d) PASS 조건**
  - `aub_rebalance_pinpoint.py`가 **에러 없이 실행**되고, 리포트에 “리밸런스 이벤트(일자/종목/수량/비용/슬리피지)”가 표시됨
  - 모든 런에서 `lane_hash/run_hash` 채워짐 + `worst_mdd` 계산됨

---

### 2) **누수/과최적화/degenerate folds(교차검증 붕괴) 즉시 봉합**
- **(a) 왜 필요한지**
  - `degenerate_folds: [1,2,3,8]`는 **검증 구간이 붕괴**했거나(표본 0/극단적 편향), 시계열 분리/퍼지/엠바고가 깨졌거나, 데이터 결측으로 학습-검증 경계가 무의미해진 신호.
  - 이 상태에선 OOS mean이 좋아도 **그냥 운/누수**일 확률이 큼.
- **(b) 위험/부작용**
  - 제대로 된 walk-forward로 바꾸면 OOS가 **즉시 하락**할 수 있음(정상).
  - 샘플 수가 줄어 통계적 변동성 증가.
- **(c) 최소 검증(2~3개)**
  - (실험) **E2** 수행(퍼지드 워크포워드 + 엠바고)
  - (체크) fold별 거래 수/노출 평균/결측률을 리포트에 강제 출력(“fold가 텅 비면 실패”)
  - (체크) 피처/라벨 생성에서 **미래 데이터 참조(lookahead)**를 정적 검사(shift 방향/리샘플링 타임스탬프)
- **(d) PASS 조건**
  - degenerate fold가 0개
  - fold별 “거래 수/평균 노출/결측률”이 임계치 내(예: 거래수=0인 fold 없음)
  - 누수 의심 지표(학습-검증 성능 괴리, 비정상적 hit-rate 급등) 완화

---

### 3) **서바이버십/유니버스 PIT(운영+백테스트 신뢰성) 우선 고정**
- **(a) 왜 필요한지**
  - “미국주식 Tech+Healthcare 8~14개”처럼 소수 집중일수록, 유니버스가 **현재 기준(서바이버)**로 고정되면 성능이 과대평가되기 쉬움.
  - 합병/상폐/티커 변경이 데이터 파이프라인에서 누락되면, 실제 운용과 백테스트가 달라짐.
- **(b) 위험/부작용**
  - PIT(당시 시점 가용 종목)로 바꾸면 성능이 떨어질 수 있음(정상).
  - 데이터 소스/라이선스/스토리지 비용 증가 가능.
- **(c) 최소 검증(2~3개)**
  - (실험) **E3** 수행(PIT 유니버스/상폐 포함 시 민감도 측정)
  - (체크) 종목 마스터에 “상장/상폐일, 액션(합병/분할)” 필수 필드 추가
  - (체크) 리밸런스 시점에 “거래 불가(상폐/거래정지)” 발생 시 대체 규칙(캐시 유지 등) 로그로 강제 기록
- **(d) PASS 조건**
  - PIT 적용 버전에서도 **전략이 실행 가능**(거래 불가 종목 처리 로직이 깨지지 않음)
  - 성능 하락이 있더라도 “하락 원인(거래 불가/대체/결측)”이 리포트로 설명 가능

---

### 4) **비용(스프레드/슬리피지/회전율) 미반영 즉시 차단**
- **(a) 왜 필요한지**
  - OOS mean이 움직이지 않거나 과대평가되는 가장 흔한 원인이 **비용 누락/과소**.
  - 집중 포트(8~14)일수록 리밸런스가 잦으면 비용이 성능을 씹어먹음.
- **(b) 위험/부작용**
  - 비용 모델 도입 직후 OOS 급락 가능(정상).
  - 지나친 비용 페널티는 트레이드가 줄어 “아무것도 안 하는 전략”으로 퇴화 가능.
- **(c) 최소 검증(2~3개)**
  - (실험) **E4** 수행(턴오버 페널티 + 슬리피지/스프레드)
  - (체크) 리포트에 “총 턴오버, 비용 합, 비용 차감 전/후 성과” 강제 출력
  - (체크) 거래 단가/유동성 기반으로 종목별 비용 상한(예: ADV 대비 주문 비율) 가드 추가
- **(d) PASS 조건**
  - **Net OOS(비용 차감 후)**가 최소 기준을 만족(또는 기존 대비 하락해도 원인이 비용/회전율로 분해됨)
  - 턴오버가 목표 구간으로 수렴(예: 주간/월간 기준 상한)

---

### 5) **레짐(Tech/Healthcare) 전용 게이트 + 노출 스케일링(ETF는 지표만)**
- **(a) 왜 필요한지**
  - “성능이 안 움직임”은 종종 신호가 아니라 **레짐 미스매치**(리스크-온/오프, 금리/헬스케어 디펜시브) 때문.
  - 현재 `exposure_max ~0.84`로 보이는데, 노출이 상황에 따라 들쭉날쭉하면 OOS가 평평해질 수 있음.
- **(b) 위험/부작용**
  - 게이트가 과하면 시장 상승 구간을 놓쳐 언더퍼폼.
  - 지표(ETF/인덱스)가 신호와 상관이 낮으면 단순히 노출만 줄이는 부작용.
- **(c) 최소 검증(2~3개)**
  - (실험) **E5** 수행(ETF/인덱스는 “관측 지표”로만 사용해 레짐 게이트)
  - (체크) 게이트 발동 횟수/기간, 발동 시 노출/성과를 별도 테이블로 로깅
  - (체크) 섹터 편중(Tech/Healthcare 내부) 한도 + 8~14 종목 유지 강제
- **(d) PASS 조건**
  - MDD 또는 왼쪽 꼬리(최악 구간 손실)가 개선
  - 게이트가 “자주/무작위”가 아니라 특정 스트레스 국면에 집중(설명 가능)

## 48시간 자동 루프용 “실행 가능한 patch/실험” 5개 (정의/게이트/기대 관측치)

### E1) **Rebalance 로그/아티팩트 스키마 표준화(핀포인트 도구 복구)**
1) **실험 정의**
   - 매 런에서 다음을 강제 생성:  
     - `rebalance.jsonl`(표준) + 요약 `rebalance.csv`(옵션)  
     - `metrics.json`(oos_mean/oos_min/worst_mdd/exposure_minmax/turnover/cost)  
     - `meta.json`(lane_hash/run_hash/git_sha/data_sha/seed)
2) **게이트**
   - `aub_rebalance_pinpoint.py`가 base/cand 모두에서 무에러 실행
   - 필수 필드 누락 시 런 실패(조기 실패)
3) **기대 관측치**
   - “리밸런스가 없어서 성능이 안 움직임” vs “있는데 비용/게이트 때문에 상쇄”가 분리됨  
   - `worst_mdd`가 None → 값으로 채워짐

---

### E2) **Purged Walk-Forward + Embargo로 degenerate folds 제거**
1) **실험 정의**
   - 시계열 분할을 “워크포워드”로 고정, 경계에 **embargo(예: 5~20거래일)** 적용
   - fold별 최소 표본/거래수 조건 미달 시 그 fold는 실패 처리
2) **게이트**
   - degenerate_folds = 0
   - fold별 거래 수 0인 구간 없음
3) **기대 관측치**
   - OOS가 하락하더라도 더 “현실적인” 분포로 수렴  
   - 성능이 안 움직이던 원인이 “검증 붕괴/누수”였는지 판별 가능

---

### E3) **PIT 유니버스(서바이버십 제거) 민감도 테스트**
1) **실험 정의**
   - 유니버스를 “현재 티커 리스트”가 아니라 **시점별 거래 가능 종목(PIT)** 기준으로 구성
   - 상폐/합병 케이스에서 “대체/현금 유지” 규칙을 명시
2) **게이트**
   - 거래 불가 이벤트 발생 시에도 런이 깨지지 않고, 이벤트가 로그에 남음
3) **기대 관측치**
   - 성과가 크게 흔들리면: 기존 성과가 서바이버십/유니버스 정의에 의존했음을 의미  
   - 흔들림이 작으면: 다음 단계(비용/레짐)로 우선순위 이동

---

### E4) **비용/회전율 내재화(슬리피지+스프레드+턴오버 페널티)**
1) **실험 정의**
   - 비용 = (고정 커미션) + (스프레드/2) + (슬리피지: k * 일중변동성 * 주문비율)  
   - 최적화 목적함수에 turnover penalty 추가 또는 리밸런스 임계치(밴드) 도입
2) **게이트**
   - 리포트에 gross/net 성과와 총 비용/턴오버가 항상 출력
   - 턴오버가 상한을 초과하면 런 실패(운영 가드)
3) **기대 관측치**
   - “움직이는 알파”가 비용에 의해 상쇄되는지 즉시 드러남  
   - 비용 반영 후에도 남는 신호만 생존

---

### E5) **레짐 게이트(ETF는 지표만) + 노출 스케일링**
1) **실험 정의**
   - 매매는 미국 개별주(Tech+Healthcare 8~14)만  
   - 관측 지표로만 사용: 예) QQQ/XLK/XLV 수익률, (가능하면) VIX 지수  
   - 조건 예: (QQQ 모멘텀<0 AND 변동성↑)이면 목표 노출 0.3, 그 외 0.7 등
2) **게이트**
   - 게이트 발동 로그가 남고, 발동 시 노출이 목표대로 변함
   - “항상 게이트 ON/OFF” 같은 붕괴 상태 감지 시 실패
3) **기대 관측치**
   - MDD/좌측 꼬리 개선, oos_min 개선 가능  
   - 성능이 평평한 원인이 “노출 스케일/레짐 미스”인지 분리

---

## 성능이 안 움직일 때 “원인 분해” 아이디어(트리거/적용/노출/비용/레짐) — 실행형 디버그 트리

### A) 트리거(신호 생성) 문제
- **증상**: 예측 점수 분산이 매우 작음, 랭크가 매일 비슷, 상위 8~14 종목이 거의 고정
- **즉시 로그로 분해**
  - 일자별 score 분산/상위종목 교체율(top-k churn)
  - 피처 결측률/클리핑률(스케일링으로 눌렸는지)
- **주요 원인**
  - 정규화/스케일이 과도 → 신호가 “0으로 수렴”
  - 데이터 업데이트 타이밍(earnings/revision)이 늦어 신호가 무력

### B) 적용(포지션 반영/리밸런스) 문제
- **증상**: 점수는 바뀌는데 거래가 거의 없음(또는 반대로 과다)
- **즉시 로그**
  - “목표비중 vs 체결비중 vs 미체결 사유”
  - 리밸런스 임계치/밴드로 인해 trade skip된 횟수
- **주요 원인**
  - 최소 거래 단위/밴드가 너무 커서 변경이 무시
  - 거래 불가(상폐/거래정지) 처리로 현금화만 반복

### C) 노출(스케일/제약) 문제
- **증상**: `exposure_max`는 높은데 평균 노출이 낮거나, 특정 구간에서 노출이 계속 0 근처
- **즉시 로그**
  - 일자별 gross/net exposure, 현금비중, 섹터별 노출(Tech/Healthcare 내부)
- **주요 원인**
  - 리스크 타겟(볼 타겟) 계산이 과도하게 보수적
  - 게이트가 과하게 발동해 상시 디레버

### D) 비용 문제
- **증상**: gross는 괜찮은데 net이 평평/마이너스
- **즉시 로그**
  - 일자별 turnover, 비용(스프레드/슬리피지) 구성요소
- **주요 원인**
  - 소수 종목 집중 + 잦은 리밸런스 → 비용 누적
  - 유동성 고려 없이 주문(ADV 대비 과대)

### E) 레짐 문제(시장 국면 미스매치)
- **증상**: 특정 구간에서만 성과가 나오고 나머지 구간은 0 근처
- **즉시 로그**
  - QQQ/XLK/XLV 모멘텀, 변동성 레짐 태그별 성과 분해(ETF는 지표만)
- **주요 원인**
  - Tech 모멘텀 전략이 금리 급등/리스크오프에서 무력
  - Healthcare 디펜시브가 위험선호 장에서 상대 약세

---

### 즉시 실행 순서(24~48h)
1) **E1 → 도구 복구/재현성 확보(가장 먼저)**  
2) **E2 → degenerate folds 제거(누수/검증붕괴 차단)**  
3) **E4 → 비용 내재화(현실 성과로 정렬)**  
4) **E3 → PIT 유니버스 민감도(서바이버십 제거)**  
5) **E5 → 레짐 게이트로 tail 리스크/노출 안정화**
