### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### P1. 인프라 정합성 복구 (BLOCKING)
### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한가**
- Rebalance CSV/JSONL 파싱 실패 → 어떤 종목이 언제 매매됐는지 검증 불가
- OOS 수치 불일치 (3.32 vs 2.63) → 어떤 값이 진실인지 불명
- MDD=None → 최대 손실 모름 = 실전 배포 불가

**(b) 위험/부작용**
- 시간 소모 (전략 개선 지연)
- 근본 원인이 코드가 아닌 데이터일 경우 더 깊은 수정 필요

**(c) 실험 체크리스트**

```
[ ] EXP-1A: 로그 포맷 통일
    - 정의: rebalance 출력을 JSON Lines로 강제, 스키마 검증 추가
    - 게이트: python -c "import json; [json.loads(l) for l in open('rebalance.jsonl')]" 성공
    - 기대치: 파싱 에러 0건

[ ] EXP-1B: OOS 수치 단일화
    - 정의: handoff.json과 diagnoser 출력이 같은 champion 파일 참조하는지 확인
    - 게이트: diff champion_v5_latest.json (두 경로) → 0 lines
    - 기대치: OOS Mean 동일값 출력

[ ] EXP-1C: MDD 계산 강제화
    - 정의: backtest 파이프라인에 mdd=None이면 raise ValueError 추가
    - 게이트: 모든 실험에서 worst_mdd 숫자값 출력
    - 기대치: MDD ∈ [-0.50, 0.00] 범위 내
```

**(d) PASS 조건**
- [ ] 3개 실험 모두 게이트 통과
- [ ] 다음 autopilot 실행 시 로그 파싱 성공 + OOS/MDD 정합

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### P2. Degenerate Fold 원인 분리
### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한가**
- Fold 1,2,3,8 = 초기 + 중간 구간 실패 → 특정 시장 레짐에서 전략 무력화
- 40% 실패율은 OOS 신뢰도 심각 훼손

**(b) 위험/부작용**
- Fold별 디버깅에 시간 소모
- 원인이 "해당 기간 시장 자체"면 전략 수정으로 해결 안 됨

**(c) 실험 체크리스트**

```
[ ] EXP-2A: Fold별 시장 레짐 태깅
    - 정의: 각 fold 기간의 SPY 수익률/VIX 평균 계산, degenerate fold 특성 추출
    - 게이트: 레짐 리포트 생성 (bull/bear/sideways/high-vol 태그)
    - 기대치: degenerate fold가 특정 레짐(예: high-vol)에 집중되는지 확인

[ ] EXP-2B: Degenerate 판정 기준 검토
    - 정의: 현재 degenerate 판정 로직 출력 (threshold가 뭔지 확인)
    - 게이트: degenerate_threshold 값 명시적 로깅
    - 기대치: threshold가 너무 높아서 정상 fold도 실패 처리하는지 확인

[ ] EXP-2C: Fold 1,2,3 데이터 품질 점검
    - 정의: 해당 기간 종목 데이터 결측치/서바이버십 체크
    - 게이트: missing_rate < 5%, delisted 종목 0개
    - 기대치: 데이터 문제 → 수정 / 문제 없음 → 전략 문제 확정
```

**(d) PASS 조건**
- [ ] Degenerate 원인 1개 이상 특정
- [ ] 수정 후 degenerate fold ≤ 2개
