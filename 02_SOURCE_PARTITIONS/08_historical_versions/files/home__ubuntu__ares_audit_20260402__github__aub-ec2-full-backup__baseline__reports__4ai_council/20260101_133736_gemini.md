현재 `candidate_exp_mrd_fsa`가 `worst_mdd`를 개선(-9.0% -> -8.2%)했으나, **`tuning_min`(-1.349)이 Champion과 완전히 동일**하다는 점은 매우 위험한 신호입니다. 이는 특정 재난 구간(예: 2020 코로나, 2022 하락장)에서 로직이 **전혀 방어하지 못하고 그대로 노출**되고 있음을 의미합니다. Lockbox 성과(1.33)는 해당 구간이 포함되지 않아 생긴 '운'일 가능성이 큽니다.

### 1. 우선순위 TOP 5 제안 (48시간 루프)

#### **Proposal A: 동적 변동성 타겟팅 (Vol-Targeting) 강제 적용**
*   **(a) 이유:** `tuning_min`이 변하지 않았다는 것은, 하락장에서 포지션 사이즈가 줄어들지 않았다는 뜻입니다. 개별 종목(Tech/Health)의 변동성이 튈 때 비중을 강제로 깎아야 합니다.
*   **(b) 위험:** 상승장에서 수익률(CAGR)이 다소 둔화될 수 있음 (보수적 진입).
*   **(c) 실험 설계:**
    1.  **Exp_VolScale_Fixed:** 포트폴리오 전체 변동성 목표(Target Vol)를 15%로 고정하고 초과 시 현금 비중 확대.
    2.  **Exp_InvVol_Weight:** 개별 종목 비중을 `1/Volatility`로 산정 (Risk Parity 접근).
    3.  **Exp_VIX_Filter:** VIX > 30 구간에서 진입 금지 (ETF 관측지표 활용).
*   **(d) PASS 조건:** `tuning_min` > -1.0 (손실폭 25% 이상 개선), `lockbox_mean` 하락폭 10% 이내.

#### **Proposal B: 섹터 상대강도(RS) 필터 추가 (XLK/XLV vs SPY)**
*   **(a) 이유:** Tech/Healthcare는 모멘텀 섹터입니다. 시장(SPY)보다 약세인 구간에서 저점 매수(Mean Reversion)를 시도하다가 물렸을 가능성이 큽니다.
*   **(b) 위험:** 횡보장에서 잦은 진입/청산(Whipsaw) 발생 가능.
*   **(c) 실험 설계:**
    1.  **Exp_RS_Filter_Tech:** Tech 종목은 `RS(XLK, SPY) > 0` 일 때만 Long.
    2.  **Exp_RS_Filter_Health:** Healthcare 종목은 `RS(XLV, SPY) > 0` 일 때만 Long.
    3.  **Exp_Sector_MA:** 섹터 ETF(XLK, XLV)가 200일선 아래면 해당 섹터 종목 매수 금지.
*   **(d) PASS 조건:** `tuning_min` 개선 및 `worst_mdd` -7%대 진입.

#### **Proposal C: 상관관계 페널티 (Correlation Penalty) 도입**
*   **(a) 이유:** 8~14개 종목이 동시에 무너지는 상황입니다. 종목 간 상관계수가 높은 것들만 뽑혔을 확률이 높습니다.
*   **(b) 위험:** 연산 비용 증가 (Covariance Matrix 계산).
*   **(c) 실험 설계:**
    1.  **Exp_Corr_Pruning:** 후보 종목군 내 상관계수 > 0.8 인 쌍(pair) 중 점수 낮은 종목 강제 제외.
    2.  **Exp_Div_Bonus:** 기존 스코어링 함수에 `(1 - Avg_Correlation)` 팩터 가산.
*   **(d) PASS 조건:** `tuning_mean` 유지되면서 `worst_mdd` 개선.

#### **Proposal D: 비용 구조 스트레스 테스트 (Slippage x2)**
*   **(a) 이유:** Tech/Bio 중소형주가 포함될 경우 슬리피지 충격이 큽니다. 현재 Lockbox 수익률이 과대평가되었는지 확인 필요.
*   **(b) 위험:** 모든 전략이 기각될 수 있음(현실 자각).
*   **(c) 실험 설계:**
    1.  **Exp_Cost_Double:** 수수료/슬리피지 설정을 현재의 2배로 설정 후 Backtest.
    2.  **Exp_Liquidity_Filter:** 일거래대금(ADV) 하위 20% 종목 강제 제외 (유동성 리스크 제거).
*   **(d) PASS 조건:** `lockbox_mean` > 1.0 유지 (손익분기점 방어).

#### **Proposal E: 룩백 윈도우(Lookback Window) 단축 실험**
*   **(a) 이유:** `candidate_exp_mrd_fsa`의 개선폭이 미미한 것은 과거 너무 긴 데이터(lag)를 보느라 최근 트렌드 변화에 둔감해서일 수 있습니다.
*   **(b) 위험:** 노이즈에 취약해짐 (Over-trading).
*   **(c) 실험 설계:**
    1.  **Exp_Window_Half:** 모든 기술적 지표의 기간을 절반으로 단축 (e.g., MA50 -> MA25).
    2.  **Exp_Adaptive_Lookback:** 변동성이 높을수록 윈도우를 짧게 가져가는 로직 적용.
*   **(d) PASS 조건:** `fold14_mdd` (최근 구간) 개선 확인.

### 3. 성능 정체 시 원인 분해 (Debugging Logic)

성능 지표가 움직이지 않을 경우, 다음 순서로 원인을 파악하십시오.

1.  **트리거 (Triggering):**
    *   *Check:* 제안한 로직(예: VolTarget)이 실제로 발동했는가?
    *   *Action:* 로그에서 `VolTarget Active: True` 횟수 카운트. 0이면 임계값(Threshold) 조정 필요.
2.  **적용 (Application):**
    *   *Check:* 시그널은 나왔는데 포트폴리오 제약조건(최소 비중 등) 때문에 무시되었는가?
    *   *Action:* `min_weight` 제약 일시 해제 후 재실험.
3.  **노출 (Exposure):**
    *   *Check:* 8~14개 종목 중 특정 1~2개 종목(Dominant Stocks)이 PnL 전체를 지배하는가?
    *   *Action:* 종목당 최대 비중(Max Weight)을 10%로 제한(`hard_cap`)하여 실험.
4.  **레짐 (Regime Mismatch):**
    *   *Check:* Tech/Health가 동시에 하락하는 구간(상관계수 1.0 접근)인가?
    *   *Action:* 이 경우엔 개별 종목 로직으론 해결 불가. `Proposal A`의 현금 비중 확대만이 답임.

**즉시 실행:** `Proposal A` (Vol-Targeting) 구현을 최우선으로 진행하여 `tuning_min`의 꼬리 위험을 자르십시오.
