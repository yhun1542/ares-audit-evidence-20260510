## 0. 현황 진단: 왜 성능이 안 움직이나?

| 레이어 | 체크포인트 | 현재 상태 |
|--------|------------|-----------|
| **트리거** | 시그널이 실제로 발생하는가? | Champion = Candidate → **동일 config가 promote된 것** (변화 0) |
| **적용** | 시그널 → 포지션 변환 로직 | 검증 필요: 실제 weight 변화 폭 |
| **노출** | 베팅 크기 / 집중도 | tuning_min 0.05 → 과거 극단 fold에서 거의 청산 |
| **비용** | 슬리피지/수수료 반영 | 미확인 (lockbox > tuning이면 **비용 미반영 의심**) |
| **레짐** | OOS 레짐과 학습 레짐 불일치 | fold14 MDD -9.9% vs worst -11.1% → 갭 존재 |

> ⚠️ **핵심 문제**: Champion과 Candidate가 동일 파일 → 탐색 공간 소진 또는 게이트 너무 tight.

## 1. 우선순위 TOP-5 실험 패치

### PATCH-1: 탐색 공간 확장 (Config Diversity)

| 항목 | 내용 |
|------|------|
| **(a) 필요성** | 동일 candidate 반복 → 현재 module_registry의 조합이 포화 상태 |
| **(b) 리스크** | 조합 폭발 → 실험 시간 급증; 과최적화 유입 |
| **(c) 최소 실험** | |

```
EXP-1A: volatility_lookback ∈ {10,20,40} 추가 (현재 20 고정 추정)
EXP-1B: rebalance_freq ∈ {weekly, biweekly} 분기
EXP-1C: sector_cap 0.35 → {0.25, 0.40} 범위 테스트
```

| **(d) PASS 조건** | lockbox_mean ≥ 1.80 AND worst_mdd > -0.12 AND candidate ≠ champion |

---

### PATCH-2: 비용 모델 명시적 반영

| 항목 | 내용 |
|------|------|
| **(a) 필요성** | lockbox > tuning → 백테스트에 슬리피지/수수료 누락 가능성 |
| **(b) 리스크** | 과다 비용 가정 시 전략 사망; 과소 시 실전 괴리 |
| **(c) 최소 실험** | |

```
EXP-2A: slippage_bps = 5 적용 후 tuning 재계산
EXP-2B: slippage_bps = 10 + commission 0.1% 적용
EXP-2C: turnover penalty (연 회전율 × 0.002) 추가
```

| **(d) PASS 조건** | tuning_mean 하락폭 < 5% AND lockbox-tuning gap < 0.05 |

---

### PATCH-3: Min-Fold 방어 강화 (Tail-Risk Gate)

| 항목 | 내용 |
|------|------|
| **(a) 필요성** | tuning_min = 0.05 → 특정 fold에서 95% 손실; 서바이버십 위험 |
| **(b) 리스크** | 방어 과다 → 평균 수익 하락 |
| **(c) 최소 실험** | |

```
EXP-3A: gate 조건에 tuning_min ≥ 0.50 추가
EXP-3B: CVaR(95) 기반 position sizing 도입
EXP-3C: max_drawdown_exit = -0.08 hard-stop 적용
```

| **(d) PASS 조건** | tuning_min ≥ 0.50 AND tuning_mean ≥ 1.70 |

| **(a) 필요성** | fold14 vs worst MDD 갭 → 특정 레짐에서 전략 붕괴 |
| **(b) 리스크** | 레짐 정의 과적합; 관측치 부족 시 노이즈 |

| **(d) PASS 조건** | worst_mdd > -0.10 AND lockbox_mean ≥ 1.75 |

### PATCH-5: 파이프라인 누수 점검 (Look-Ahead Audit)

| 항목 | 내용 |
|------|------|

| **(b) 리스크** | 누수 발견 시 전체 결과 무효화 |

```

EXP-5C: T+1 delay 강제 적용 후 재실행
```

| **(d) PASS 조건** | shuffle test CAGR < 1.05 AND T+1 결과 gap < 3% |

## 2. 48h 자동 루프 스펙

```yaml
# experiment_48h_loop.yaml
experiments:
  - id: EXP-1A
    module: volatility_lookback
    values: [10, 20, 40]
    gate:
      lockbox_mean: ">=1.80"
      worst_mdd: ">-0.12"
      unique_config: true
    observe: [tuning_mean, tuning_min, turnover]

  - id: EXP-2A
    module: cost_model
    params: {slippage_bps: 5}
    gate:
      tuning_drop: "<0.05"
      lockbox_tuning_gap: "<0.05"
    observe: [tuning_mean, lockbox_mean, cost_drag]

  - id: EXP-3A
    module: gate_rule
    params: {tuning_min_floor: 0.50}
    gate:
      tuning_min: ">=0.50"
      tuning_mean: ">=1.70"
    observe: [tuning_min, fold_variance]

  - id: EXP-4A
    module: regime_filter
    params: {vix_threshold: 25, action: cash_50}
    gate:
      worst_mdd: ">-0.10"
      lockbox_mean: ">=1.75"
    observe: [regime_days, avg_exposure]

  - id: EXP-5B
    module: audit
    type: shuffle_test
    gate:
      shuffle_cagr: "<1.05"
    observe: [shuffle_cagr, shuffle_sharpe]
```
