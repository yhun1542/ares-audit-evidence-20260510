## 24~48시간 TOP5 우선순위(코드/아키텍처/전략) — 명령형 체크리스트

1) **누수(lookahead)·정렬(as-of)·리샘플링 감사 패치 적용**
2) **서바이버십/상장폐지·M&A·스플릿/배당(corporate actions) 처리 강제**
3) **비용(스프레드/슬리피지/임팩트)·체결지연을 “락박스와 동일”하게 강제**
4) **운영 리스크(데이터 결손/리밸 실패/급변장) 대응용 가드레일(킬스위치·폴백) 추가**
5) **과최적화 방지(워크포워드·purge/embargo·안정성 점수)로 선택 기준을 재정의**

> 현재 ONE TRUTH 상, Champion은 **tuning_mean 1.90 vs lockbox_mean 1.79**로 괜찮지만, 후보에서 **tuning_min 급락(0.05)** 같은 “꼬리 불안정” 신호가 보여서, 다음 48시간은 **누수/서바이버십/비용/운영/과최적화**를 먼저 잠그는 것이 기대값이 큼.

# TOP5 제안별 상세 (각 48시간 자동 루프: (1)실험정의 (2)게이트 (3)기대관측치)

아래는 **실험 5개(=TOP5)**로 제한하고, 각 실험 안에 **2~3개 변형(variants)**을 포함시킴.

---

## 1) 누수·정렬(as-of)·리샘플링 감사 패치
### (a) 왜 필요한지
- tuning/lockbox 괴리가 줄어들지 않거나 후보의 tuning_min이 바닥으로 가는 경우, 흔한 원인이 **시점 정렬 누수(특히 리샘플/FFill/지표 계산 창)**임.
- “EOD로 신호 만들고 같은 날 종가로 체결” 같은 미세 누수는 샤프를 크게 부풀림.

### (b) 위험/부작용
- 성능이 즉시 하락할 수 있음(진짜 누수였던 알파 제거).
- 데이터 파이프라인 느려짐(추적 로그/검증 추가).

### (c) 최소 실험(1개 실험 + 3 variants)
**실험 E1: `asof_alignment_lockdown`**
- Variant A: **모든 feature에 최소 1-bar lag 강제**(예: D 신호 → D+1 체결 기준)
- Variant B: 리샘플/FFill 규칙을 **“과거만 사용”**으로 고정(미래값 혼입 탐지 포함)
- Variant C: 지표 계산에서 **윈도우 경계 엄격화**(rolling이 현재 바를 포함하는지/배제하는지 명시)

### (d) PASS 조건(게이트)
- **Leak Gate**: (자동 테스트) 모든 feature timestamp ≤ decision timestamp 만족, 위반 0건.
- **Perf Gate**: lockbox_mean이 Champion 대비 **-2% 이내**로 유지하면서, **tuning_mean - lockbox_mean gap 감소**(예: gap 0.11 → 0.07 이하).
- **Risk Gate**: worst_mdd가 Champion(-0.093) 대비 **악화 폭 0.01 이내**(즉, -0.103보다 나쁘지 않게).

### (3) 기대 관측치
- 누수가 있었다면: tuning은 하락, lockbox는 상대적으로 덜 하락 → **일반화 갭 축소**.
- 누수가 없었다면: 성능 변화는 작고, 대신 “신뢰 가능한 실패/성공”으로 실험 해상도가 올라감.

## 2) 서바이버십/상장폐지·Corporate Actions 강제 처리
### (a) 왜 필요한지
- US 개별주 백테스트에서 **상장폐지/인수합병/티커변경** 누락은 서바이버십 편향을 만든다.
- Tech+Healthcare(8~14종목)처럼 집중 포트폴리오는 특정 이벤트 한 번이 성능을 왜곡.

### (b) 위험/부작용
- 데이터 소스에 따라 delisted 가격/리턴을 대체해야 하며(0 처리 금지), 구현 실수 시 성능 급락/NaN 전파.
- 우주(universe) 재구성 방식이 바뀌면 과거 성능 비교가 어려워짐.

### (c) 최소 실험(1개 실험 + 2~3 variants)
**실험 E2: `survivorship_corpact_hardening`**
- Variant A: **delisted 포함 우주**로 재생성(가능한 데이터 범위 내), 결측은 “거래정지/현금화” 규칙으로 처리
- Variant B: split/dividend **adj close 사용 강제 + 검증**(raw close 대비 급변 탐지)
- Variant C: M&A/티커변경 매핑 테이블 적용(가능 시), 불가 시 **해당 날짜 강제 청산 룰**로 대체

### (d) PASS 조건(게이트)
- **Integrity Gate**: 가격 시계열에서 스플릿/병합일 급변 탐지 후, adj 적용 시 급변이 합리 수준으로 감소(탐지 규칙 통과).
- **Backtest Gate**: lockbox_min이 Champion(1.1337) 대비 **동등 이상**(≥ 1.13) 또는 worst_mdd **동등 이하 악화**.
- **Ops Gate**: NaN 전파/0 division/가격 음수 등 예외 0건.

### (3) 기대 관측치
- 성능이 약간 떨어져도 **MDD/꼬리 리스크가 개선**되거나, 최소한 “진짜 성능”으로 정규화.
- 종종 lockbox가 더 안정화(서바이버십 제거로 과대추정 제거).

## 3) 비용·체결지연 현실화(락박스와 동일 모델로 강제)
### (a) 왜 필요한지
- Tech/HC 개별주에서 회전이 조금만 올라가도 **스프레드/슬리피지/임팩트**가 샤프를 잠식.
- “비용 미반영”은 가장 흔한 과대평가 요인이고, 48시간 루프에서 빨리 고칠수록 낭비가 줄어듦.

### (b) 위험/부작용
- 수익률이 하락할 수 있음(현실화로 정상).
- 과도한 비용 모델은 알파를 과소평가할 수 있음(보수성 과다).

### (c) 최소 실험(1개 실험 + 3 variants)
**실험 E3: `execution_cost_lockbox_parity`**
- Variant A: **체결 = next open(또는 next VWAP)**로 고정(동일 바 체결 금지)
- Variant B: 비용 = `max(고정 bps, k * ATR/Price, k2 * spread)` 형태로 “상한/하한” 포함
- Variant C: 유동성 필터 추가(예: 20D $ADV 하위 종목은 비중 상한 또는 제외)

### (d) PASS 조건(게이트)
- **Realism Gate**: turnover 대비 비용이 0으로 수렴하지 않도록 하한 적용 확인(로그로 검증).
- **Perf Gate**: lockbox_mean이 Champion 대비 **-3% 이내**이면서, 비용 차감 전/후 민감도가 과도하지 않음(예: 비용 on/off 시 샤프 차이가 비정상적으로 크면 FAIL).
- **Risk Gate**: fold14_mdd가 -0.093에서 **악화 폭 0.015 이내**.

### (3) 기대 관측치
- 회전이 높은 규칙은 자연스럽게 약화되고, **저회전·안정 신호가 상대적으로 부각**.
- 후보들 사이 “진짜 우위”가 더 분명해짐(락박스에서 뒤집힘 감소).

## 4) 운영 리스크 가드레일(데이터 결손/리밸 실패/급변장) 추가
### (a) 왜 필요한지
- 48시간 자동 루프에서 진짜 문제는 “성능”보다 **실행 불능/데이터 결손/리밸 실패로 인한 숨은 손실**.
- 집중 포트폴리오는 단 1개 종목 데이터 결손에도 포지션이 비정상화될 수 있음.

### (b) 위험/부작용
- 가드레일이 과하게 발동하면 기회 손실(캐시 비중 증가).
- 구현이 잘못되면 오히려 잦은 청산/재진입(회전 증가).

### (c) 최소 실험(1개 실험 + 2 variants)
**실험 E4: `ops_guardrails_fail_closed`**
- Variant A: 데이터 결손/가격 이상치 발생 시 **fail-closed**(해당 종목 0비중, 현금 대체)
- Variant B: 리밸 실패/주문 미체결 시 **hold-last**(직전 포지션 유지) + 재시도 백오프
- Variant C(선택): 급변장(관측 ETF: QQQ/XLV/VIX proxy 등) 시 **리스크 타겟 하향**(ETF는 지표로만)

### (d) PASS 조건(게이트)
- **Ops Gate**: 시뮬레이션 중 “결손/이상치” 주입 테스트에서 예외 0건, 포지션 합 100% 유지(현금 포함).
- **Risk Gate**: worst_mdd 악화 없음(Champion 대비 0.0~0.005 이내).
- **Churn Gate**: 가드레일 도입 후 turnover가 **기존 대비 +10% 초과 증가 시 FAIL**(운영 리스크가 비용 리스크로 전이 방지).

### (3) 기대 관측치
- 성능 평균은 거의 비슷하더라도 **극단 손실/꼬리 이벤트가 줄어듦**.
- “실전에 올릴 수 있는 후보”만 남음(운영 통과율 상승).

## 5) 과최적화 방지: 선택 기준을 “수익”에서 “안정성”으로 재정의
### (a) 왜 필요한지
- Candidate에서 tuning_min 급락(0.05)은 파라미터/표본에 과민한 신호일 가능성이 큼.
- 지금은 “더 높은 평균”보다 **최저치(min), 갭, MDD** 중심으로 걸러야 다음 48시간이 효율적.

### (b) 위험/부작용
- 단기적으로 best-case 수익은 낮아질 수 있음.
- 너무 보수적으로 걸면 알파 탐색이 느려짐.

### (c) 최소 실험(1개 실험 + 3 variants)
**실험 E5: `selection_criteria_stability_first`**
- Variant A: 모델/전략 선택 점수 = `lockbox_mean - λ*gap - μ*|worst_mdd|` (gap=tuning-lockbox)
- Variant B: **purged/embargo walk-forward**로 교차검증(이벤트 주변 누수 차단)
- Variant C: “shadow/ensemble”는 평균이 아니라 **min(혹은 20% quantile)** 최대화로 튜닝

### (d) PASS 조건(게이트)
- **Stability Gate**: tuning_min이 **0.4 이상**(현재 Champion min 0.43 수준 방어) 또는 최소한 Candidate 같은 바닥(0.05) 재발 금지.
- **Generalization Gate**: lockbox_mean이 Champion 대비 **동등(±1%)**이면서 gap 감소.
- **Drawdown Gate**: worst_mdd가 Champion보다 나쁘지 않거나(≤ -0.093), 나빠질 경우 lockbox_mean이 그만큼 보상(+2%p 이상)해야 PASS.

### (3) 기대 관측치
- 락박스에서 “가끔 대박” 후보가 사라지고, **꾸준히 통과하는 후보 비중 증가**.
- 자동 루프가 평균을 올리기보다 **하방을 잠그는 방향**으로 수렴.

# 성능이 안 움직일 때: 원인 분해 아이디어(트리거/적용/노출/비용/레짐) — 명령형 진단 트리

## A. Trigger(신호 생성) 문제
- **특징량 중요도/기여도 상위 5개를 출력하고 시간 이동(+1bar) 시 성능이 유지되는지 확인하라.**
- **신호가 “특정 이벤트(실적주/빅테크 몇 종목)”에만 반응하는지, 종목별 성과 분해(8~14개)로 확인하라.**
- **rolling/window 경계(포함/배제) 바꿨을 때 성능이 급변하면 누수/불안정 신호로 간주하라.**

## B. Apply(적용/체결) 문제
- **동일-바 체결을 금지하고(next open 고정), 성능 변화폭을 로그로 기록하라.**
- **리밸 주기/리밸 임계값(리밸 안 하는 구간)별로 turnover-성능 곡선을 그려라.**
- **포지션 생성 실패/가격 NaN 시 fallback이 수익률을 망치는지(강제 현금화 vs hold-last) 비교하라.**

## C. Exposure(노출) 문제
- **섹터/팩터 노출(성장/가치, 금리민감, 메가캡 편중)을 주간으로 추적하라.**
- **상위 1~2종목 기여도가 전체 PnL의 과반이면 집중 리스크로 분류하고 비중 상한을 테스트하라.**
- **관측 ETF(예: QQQ, XLV 등)는 매매하지 말고 레짐 라벨링(리스크온/오프) 지표로만 사용하라.**

## D. Cost(비용) 문제
- **turnover × (bps)로 “손익분기 비용”을 계산하고, 현실적 비용 범위에서 알파가 남는지 먼저 확인하라.**
- **ADV 낮은 종목이 성과를 주도하면 비용 착시 가능성이 높으니 유동성 필터를 강제하라.**
- **슬리피지 민감도(0.5x/1x/2x)에서 랭킹이 뒤집히는 전략은 실전 부적합으로 분류하라.**

## E. Regime(레짐) 문제
- **기간을 3~4개 레짐(상승/하락/고변동/저변동)으로 나눠 성과 표를 만들고 “한 레짐만 먹는지” 확인하라.**
- **레짐별로 다른 규칙(리스크 타겟/현금비중)을 둬야 한다면, 먼저 ‘발동 조건의 단순성’부터 게이트로 걸어라(복잡도↑ = 과최적화↑).**
- **레짐 라벨이 하루만 바뀌어도 성능이 크게 출렁이면, 레짐 신호 자체가 노이즈일 확률이 크니 제거/완화하라.**

---

## 실행 순서(48시간 루프에 바로 얹기)
- **E1 → E2 → E3 순으로 “진실성(누수/서바이버십/비용)”을 먼저 잠그고**, 그 다음
- **E4(운영 가드레일)로 실전 안정성 확보**, 마지막에
- **E5(선택 기준 안정성 우선)로 자동 선택의 목표함수를 교정**하라.

위 5개가 통과되면, 이후에야 신호 자체(알파) 확장을 건드리는 것이 비용 대비 효율이 좋다.
