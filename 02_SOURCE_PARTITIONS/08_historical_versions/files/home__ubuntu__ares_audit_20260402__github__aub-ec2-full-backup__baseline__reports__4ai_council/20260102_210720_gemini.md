[우선순위 TOP 5 제안: 24~48시간 실행 계획]

### 1. Degenerate Folds 긴급 복구 (안정성 확보)
*   **(a) 이유:** `degenerate_folds: [1, 2, 3, 8]`은 전체 기간의 40%에서 모델이 학습 실패했거나 Cash(Exposure 0)로 도피했음을 의미함. OOS Mean 3.32는 나머지 과적합된 Fold의 착시일 가능성이 매우 높음.
*   **(b) 위험:** 성능 수치(Mean)가 급격히 하락할 수 있음(현실화 과정).
*   **(c) 실험 (Experiments):**
    1.  `EXP_FORCE_EXPOSURE`: 학습 Loss 함수에 `UnderExposurePenalty` 추가 (최소 0.3 이상 강제).
    2.  `EXP_RELAX_BOUNDS`: 개별 자산 Weight Constraint를 기존 대비 1.5배 완화 (솔버 수렴 유도).
    3.  `EXP_CLIP_OUTLIER`: 입력 Feature의 극단값(Outlier)을 `winsorize(1%, 99%)` 처리 후 학습.
*   **(d) PASS 조건:** Degenerate Folds 개수 0개.

### 2. Rebalance Log 파이프라인 정합성 수정 (관측성 확보)
*   **(a) 이유:** `Error loading ... Expecting value: line 1` 에러로 인해 거래 회전율(Turnover)과 실제 비용 추적이 불가능. '보이지 않는 비용'이 수익을 갉아먹고 있을 확률 99%.
*   **(b) 위험:** 코드 수정 중 로깅 오버헤드 발생 가능성.
*   **(c) 실험 (Experiments):**
    1.  `PATCH_LOG_FORMAT`: `rebalance.csv` 저장 로직을 `to_csv` 대신 `jsonl` stream append 방식으로 통일.
    2.  `PATCH_PATH_FIX`: `--base-log` 경로가 실제 존재하는 Artifact 디렉토리를 가리키도록 상대경로/절대경로 매핑 수정.
*   **(d) PASS 조건:** `aub_rebalance_pinpoint.py` 스크립트가 에러 없이 Report를 생성하고, Turnover가 0이 아닌 값으로 출력됨.

### 3. Tech/Bio 섹터 편중 및 유동성 리스크 제어 (운영 리스크)
*   **(a) 이유:** 8~14개 종목의 Tech+Healthcare 집중 포트폴리오는 변동성이 극심함. 특정 종목(예: 임상 실패 바이오) 하락 시 MDD 방어 불가.
*   **(b) 위험:** "대박" 종목 비중 축소로 인한 Alpha 감소.
*   **(c) 실험 (Experiments):**
    1.  `EXP_HARD_CAP`: 단일 종목 최대 비중 15% 제한 (현재 83% 노출은 위험).
    2.  `EXP_SECTOR_BALANCE`: Tech와 Healthcare 간 비중 격차 최대 20%p 이내로 강제.
    3.  `EXP_REMOVE_ILLIQUID`: 평균 거래대금 하위 20% 종목 Universe에서 제외.
*   **(d) PASS 조건:** Worst MDD가 -15% 이내로 개선 (수익률 하락 감수).

### 4. 비용 구조 현실화 (과최적화 방지)
*   **(a) 이유:** 현재 OOS Mean 3.32는 슬리피지와 수수료가 0이거나 매우 낮게 설정되었을 때만 가능한 수치임.
*   **(b) 위험:** 전략 폐기(전략이 비용을 이기지 못해 마이너스로 전환).
*   **(c) 실험 (Experiments):**
    1.  `EXP_COST_10BPS`: 매매당 비용 10bps(0.1%) 강제 주입 후 재검증.
    2.  `EXP_COST_20BPS`: 매매당 비용 20bps(0.2%) 강제 주입 (보수적 관점).
*   **(d) PASS 조건:** 비용 반영 후에도 OOS Mean > 1.0 유지.

### 5. 서바이버십 바이어스 점검 (데이터 무결성)
*   **(a) 이유:** Tech/Healthcare는 상장폐지/인수합병이 잦음. 현재 Universe에 과거에 존재했으나 지금 사라진 종목이 포함되어 있는지, 혹은 살아남은 종목만으로 백테스트했는지 확인 필요.
*   **(b) 위험:** 백테스트 신뢰도 전체 붕괴.
*   **(c) 실험 (Experiments):**
    1.  `AUDIT_DELISTED`: 2020~2024년 사이 상장폐지된 Tech/Bio 종목 3개를 Universe에 강제 포함시켜 로직이 매도 처리하는지 확인.
*   **(d) PASS 조건:** 상장폐지 종목 보유 시, 마지막 거래일 전량 매도 로직 작동 확인.

### [48시간 자동 루프 실행 정의]

**Cycle 1: 안정화 (0~12h)**
1.  **실험 정의:** `EXP_FORCE_EXPOSURE` + `PATCH_LOG_FORMAT`
2.  **게이트:** Degenerate Folds = 0 AND Log 파일 생성 확인.
3.  **기대 관측치:** OOS Mean은 3.32에서 1.5~2.0 수준으로 하락하나, OOS Min이 양수(+) 전환 혹은 -0.02에서 개선됨.

**Cycle 2: 비용 및 리스크 주입 (12~36h)**
1.  **실험 정의:** `EXP_HARD_CAP` (Max 15%) + `EXP_COST_15BPS`
2.  **게이트:** MDD < 20% AND Sharpe > 1.0
3.  **기대 관측치:** "꿈의 수익률"이 사라지고 현실적인 우상향 곡선 확인. Turnover가 과도할 경우(일 >200%), 회전율 제어 로직 추가 필요성 발견.

**Cycle 3: 유니버스 정제 (36~48h)**
1.  **실험 정의:** Tech/Health 종목 풀 재선정 (유동성 필터 적용)
2.  **게이트:** 특정 Fold에서의 급락(Crash) 방어.
3.  **기대 관측치:** 섹터 로테이션 시그널 작동 확인.

### [성능 정체 시 원인 분해 (Debug Checklist)]

성능 지표가 움직이지 않는다면 다음 순서로 점검:

1.  **Trigger (신호 발생):** 예측값(`y_pred`)의 분산(Variance)이 0에 수렴했는가? (모든 종목에 대해 동일한 점수를 주고 있는가?)
2.  **Application (비중 변환):** 최적화 Solver가 `Min Weight` 제약조건 때문에 예측값과 무관하게 `1/N` 포트폴리오를 만들고 있는가?
3.  **Exposure (현금 비중):** 시장 하락을 감지하고 Cash 100%를 들고 있어서 변동이 없는 것인가? (이는 긍정적 정체임).
4.  **Cost (비용 상쇄):** 알파가 발생했으나, 잦은 리밸런싱 비용이 이를 정확히 상쇄하고 있는가? (로그 확인 필수).
5.  **Regime (구간 특성):** Tech/Bio 섹터 전체가 횡보하는 구간인가? (Benchmark ETF인 XLK, XLV와 상관계수 확인).
