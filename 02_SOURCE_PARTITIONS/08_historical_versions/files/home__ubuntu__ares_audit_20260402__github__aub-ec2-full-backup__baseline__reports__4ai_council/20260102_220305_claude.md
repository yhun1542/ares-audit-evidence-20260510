## 1. 우선순위 TOP-5 Patch 제안

### PATCH-1: Degenerate Fold 원인 분해 (P0 - 가장 급함)

**(a) 왜 필요한지**
- 40% 폴드가 degenerate → OOS 3.32가 cherrypicking 결과일 가능성
- 생존편향 제거 없이 실전 배포 시 대형 손실 리스크

**(b) 위험/부작용**
- 진짜 원인이 데이터 부족이면 전략 자체 폐기 필요
- 디버깅 시간 소모 (24h+)

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|---|---|---|---|
| P1-A | 각 degenerate fold에서 `exposure=0`인 날짜 비율 계산 | exposure_zero_ratio < 0.7 | 폴드별 리포트 |
| P1-B | degenerate fold 기간의 시장 레짐 태깅 (VIX>25, SPY DD>10%) | 레짐 overlap > 80% | 레짐 == "crisis" 확인 |
| P1-C | min_holding_period 제거 후 fold 1,2,3,8 재실행 | degenerate 수 ≤ 1 | oos_mean ≥ 2.0 유지 |

**(d) PASS 조건**
```
✅ degenerate_folds ≤ 2개 AND oos_mean ≥ 2.5
```

**(b) 위험/부작용**
- MDD 계산 추가 시 기존 백테스트 속도 10~15% 저하

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|---|---|---|---|
| P2-A | `calc_mdd()` 함수 존재 여부 + 호출 여부 체크 | 함수 호출 True | stack trace |
| P2-B | champion 전체 기간 equity curve에서 수동 MDD 계산 | MDD 값 출력 | -15% ~ -25% 예상 |

**(d) PASS 조건**
```
✅ worst_mdd 필드에 실수값 출력 AND -30% < mdd < 0%
```

### PATCH-4: Hash 재현성 복구 (P1)

**(a) 왜 필요한지**
- `lane_hash: None, run_hash: None` → A/B 비교 신뢰 불가

**(b) 위험/부작용**
- 해시 계산 로직 버그 시 false positive 발생

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|---|---|---|---|
| P4-A | config dict → sha256 해시 함수 구현 확인 | hash != None | 64char hex |
| P4-B | 동일 config 2회 실행 → 동일 hash 확인 | hash_1 == hash_2 | deterministic |

**(d) PASS 조건**
```
✅ lane_hash, run_hash 필드에 유효한 hex 출력 AND 재현 성공
```
