## 24~48시간 TOP5 우선순위(코드/아키텍처/전략) — **명령형 체크리스트**
(누수/과최적화/서바이버십/비용 미반영/운영 리스크를 최우선으로 고정)

### 1) **운영/재현성 파이프라인 무결성 복구(로그·해시·지표)**
- **즉시 조치**
  - `aub_rebalance_pinpoint`가 읽는 **rebalance 로그 포맷/경로를 단일화**하고, 실패 시 즉시 fail-fast 하게 만들어라.
  - 산출물에 `lane_hash/run_hash`를 **강제 생성**하고(현재 None), 모든 리포트/아티팩트에 동봉해 “같은 설정=같은 결과”를 보장해라.
  - `worst_mdd`가 None으로 남지 않도록 **MDD 계산을 평가 단계에서 강제**하고, 결측이면 실험을 실패로 처리해라.
- **왜 필요한지**
  - 지금 상태는 “성능이 안 움직이는 원인”이 전략이 아니라 **관측/평가 자체가 흔들리는 상태**일 가능성이 큼(리밸런스 로그 로딩 실패, hash None, MDD None).
- **위험/부작용**
  - 엄격한 fail-fast로 **실험 실패율 증가**(단, 잘못된 성공을 막는 게 이득).
- **최소 실험(공유 실험 ID 사용)**: `E1`, `E3`
- **PASS 조건**
  - rebalance pinpoint가 **에러 없이 실행**되고, `lane_hash/run_hash`가 항상 채워지며, `worst_mdd`가 모든 런에서 숫자로 기록될 것.
  - 동일 seed/config에서 결과가 **완전 재현**될 것(핵심 지표 ±오차 0 또는 허용 오차 이내).

---

### 2) **CV/평가 퇴행(“degenerate_folds”) 제거 → 누수/과최적화 1차 차단**
- **즉시 조치**
  - `degenerate_folds: [1,2,3,8]` 원인을 분해해서(표본 부족/전처리 누락/라벨 결측/리밸런스 일정 불일치) **폴드가 비지 않게** 만들어라.
  - 시계열용으로 **Purged Walk-Forward + embargo**로 교체(또는 강제 옵션화)해서, 피처 윈도우/리밸런스가 겹치며 새는 케이스를 막아라.
- **왜 필요한지**
  - degenerate fold가 있으면 OOS mean이 높아도 **통계적 의미가 붕괴**하고, “안 움직임/갑자기 움직임”이 모두 관측 오류가 된다.
- **위험/부작용**
  - 누수를 제거하면 성능이 **눈에 띄게 하락**할 수 있음(하지만 그게 진짜 성능).
- **최소 실험**: `E3`, `E4`
- **PASS 조건**
  - `degenerate_folds`가 **빈 배열**이 될 것.
  - seed 변동/기간 변동에서 OOS mean이 “비슷한 수준”으로 유지(급등락 감소), 특히 **oos_min 개선**(현재 음수) 또는 tail 리스크가 줄어들 것.

---

### 3) **서바이버십/유니버스 편향 제거(미국주식 8~14, Tech+Healthcare 고정)**
- **즉시 조치**
  - 백테스트 유니버스를 “현재 살아남은 종목 리스트”로 두지 말고, **Point-in-Time(당시 접근 가능) 유니버스**로 고정해라.
  - 종목 수를 **8~14개로 강제**하고(Tech+Healthcare 중심), 종목 교체 규칙이 있으면 **미래정보(재무발표/편입/상장폐지 반영 시점) 누수**가 없는지 점검해라.
- **왜 필요한지**
  - Tech/Healthcare는 장기 생존자가 강해서, 서바이버십이 있으면 OOS가 “좋게 보이는데” 실전에서 안 움직이는 전형적인 함정이 된다.
- **위험/부작용**
  - PIT로 바꾸면 데이터 공백/상장폐지 처리로 구현 복잡도↑, 성능↓ 가능.
- **최소 실험**: `E4`, `E2`
- **PASS 조건**
  - PIT 전환 후에도 성능이 완전 붕괴하지 않고(예: OOS mean 급락 방지), 거래 가능한 바/데이터 결측이 관리되며, 결과가 “특정 생존자”에 과도 의존하지 않을 것.

---

### 4) **비용(수수료/슬리피지/스프레드) 미반영 제거 + 회전율(턴오버) 게이트**
- **즉시 조치**
  - 거래비용 모델을 “옵션”이 아니라 **평가 필수 항목**으로 강제해라.
  - 턴오버 상한을 두고, 초과 시 성능이 좋아도 **실험 FAIL** 처리해라(운영 가능성 우선).
- **왜 필요한지**
  - “성능이 안 움직임”의 흔한 원인이 비용/슬리피지로 alpha가 상쇄되는 것. 특히 8~14 집중 포트는 리밸런스가 잦으면 비용이 치명적.
- **위험/부작용**
  - 비용 반영 시 백테스트 성능 하락(정상), 전략이 “천천히 움직이게” 변할 수 있음.
- **최소 실험**: `E2`, `E5`
- **PASS 조건**
  - 비용 포함 후에도 OOS mean이 **치명적으로 붕괴하지 않을 것**(예: -20% 이내 하락 같은 내부 기준을 둬서 자동 게이트).
  - 비용이 성능을 잡아먹는 비중(총 PnL 대비 비용)이 **상식 범위**로 내려올 것 + 턴오버가 상한 이하.

---

### 5) **노출/리스크 오버레이(레짐 기반)로 oos_min·드로우다운부터 안정화**
- **즉시 조치**
  - 현재 `exposure_max ≈ 0.84`를 “상황 무관 상단”으로 두지 말고, 변동성/레짐에 따라 **동적 노출 캡**을 적용해라.
  - ETF는 매매 금지(규칙 준수)로 두되, **관측 지표**로만 사용해라(예: QQQ/XLV/ARKK/IEF 등으로 risk-on/off 판단).
- **왜 필요한지**
  - oos_mean이 높아도 `oos_min`이 음수면 48시간 루프에서 다음 단계(운영)로 못 간다. 먼저 tail을 줄여야 실험이 “움직임”을 만든다.
- **위험/부작용**
  - 과도한 노출 억제로 수익 기회 상실, 평균 수익률 감소.
- **최소 실험**: `E5`, `E3`
- **PASS 조건**
  - `worst_mdd`가 유의미하게 감소(최소한 baseline 대비 개선)하고, `oos_min`이 개선(덜 음수 또는 양수화).
  - 노출이 [min,max] 규칙을 안정적으로 만족하고(예: max 0.75 같은 내부 상한), 극단적 포지션이 줄어들 것.

## 48시간 자동 루프용 “실행 가능한 Patch/실험” 5개(3~5개 제한 준수)
아래 5개만 돌려도 위 TOP5를 모두 커버하도록 설계(각 우선순위는 이 5개를 재사용).

### E1) **리밸런스 로그/해시/지표 강제 패치**
1) **실험 정의**
   - rebalance 출력(orders/fills/positions)을 **JSONL 단일 포맷**으로 저장
   - `lane_hash/run_hash` 생성 강제
   - `worst_mdd` 산출 강제(결측 시 FAIL)
2) **게이트**
   - pinpoint 도구가 경로 에러/파싱 에러 없이 종료코드 0
   - `worst_mdd is not None`, `lane_hash != None`, `run_hash != None`
3) **기대 관측치**
   - “성능이 안 움직임” 이슈 중 일부가 **관측 실패였는지** 즉시 분리됨
   - 리밸런스 구간별 기여도(언제/무엇을 샀는지)가 추적 가능

### E2) **거래비용/슬리피지 모델 ON + 턴오버 게이트**
1) **실험 정의**
   - per-share/per-dollar 수수료 + spread/slippage(보수적으로) 포함
   - 턴오버 상한(일/주 단위)을 초과하면 FAIL
2) **게이트**
   - 비용 포함 OOS mean 하락폭이 내부 기준 이내
   - 턴오버/거래횟수 상한 만족
3) **기대 관측치**
   - “이익이 비용으로 사라지는지”가 수치로 분해됨
   - 비용 민감 구간(장 급변/리밸런스 직후)이 드러남

### E3) **Purged Walk-Forward + Embargo CV로 교체**
1) **실험 정의**
   - 시계열 CV를 purge/embargo 포함 구조로 전환
   - seed 2~3개 고정 반복(루프 내 소량)
2) **게이트**
   - `degenerate_folds == []`
   - seed 간 성능 분산이 과도하지 않을 것(급격한 출렁임 감소)
3) **기대 관측치**
   - 누수/윈도우 겹침 제거 후의 “진짜 OOS”로 수렴
   - oos_min(왼꼬리)이 안정화되는지 확인 가능

### E4) **PIT 유니버스(8~14, Tech+Healthcare) 강제 + 서바이버십 감사**
1) **실험 정의**
   - 유니버스 선정 시점/데이터 접근 시점을 PIT로 고정
   - 종목 수 8~14 강제, 섹터(Tech/Healthcare) 비중 룰 고정
2) **게이트**
   - 미래데이터 접근 탐지(발표일 이후 반영 등) 0건
   - 데이터 결측률/상장폐지 처리로 인한 “거래 불가 바” 비율이 임계 이하
3) **기대 관측치**
   - 성능이 특정 생존 종목에 의해 과장되었는지 즉시 드러남
   - 운용 가능 유니버스로 수렴

### E5) **레짐(ETF 관측) 기반 노출 캡 + 리스크 오버레이**
1) **실험 정의**
   - ETF(예: QQQ, XLV, IEF)를 “관측 지표”로만 사용해 risk-on/off 스코어 산출
   - risk-off 시 gross/net exposure 상한 축소, 변동성 타겟팅, 손실구간 리밸런스 억제(쿨다운)
2) **게이트**
   - `worst_mdd` 개선 + `oos_min` 개선(둘 중 하나가 아니라 둘 다를 1차 목표로)
   - 노출 상한 준수(예: max 0.75) 및 급격한 포지션 뒤집힘 감소
3) **기대 관측치**
   - “평균은 좋은데 최저가 나쁜” 형태가 완화
   - 레짐별 성과 분해가 가능해져 다음 신호 개선 방향이 명확해짐

## 성능이 “안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래 순서대로 보면, 48시간 루프에서 원인을 빠르게 격리 가능(질문 없이 실행 가능 형태).

### A) 트리거(신호가 실제로 발생하나?)
- **점검**
  - 신호 값 분포(평균/표준편차/0 비율)가 기간별로 고정되어 있지 않은지 확인
  - 리밸런스 이벤트 수(주/월)가 0에 수렴하는 구간이 있는지 확인
- **의심 시나리오**
  - 전처리 결측 처리로 신호가 0으로 눌림
  - CV/폴드 문제로 특정 구간 신호 계산이 스킵됨(=degenerate fold 원인)

### B) 적용(신호→주문/포지션으로 변환이 먹히나?)
- **점검**
  - 목표 포지션 vs 실제 체결 포지션 괴리(리밸런스 로그로)
  - 제약조건(최소 거래단위/포지션 캡/현금 제약) 때문에 주문이 잘리는 비율
- **의심 시나리오**
  - 포지션 캡/라운딩/거래 불가로 “항상 비슷한 포지션”만 들고 있음

### C) 노출(포트가 실제로 위험을 지고 있나?)
- **점검**
  - gross/net exposure 시계열이 거의 평평한지(항상 0.3~0.4로 고정 등)
  - 섹터 편향(Tech/Healthcare 내부에서도 mega-cap으로 쏠림) 심한지
- **의심 시나리오**
  - 노출이 너무 낮거나(성능이 안 나옴), 너무 높고 변동성에 눌려 tail만 커짐(oos_min 악화)

### D) 비용(알파를 상쇄하나?)
- **점검**
  - 턴오버, 거래횟수, 평균 스프레드 구간(오픈/클로즈 근처) 집중 여부
  - PnL 대비 비용 비중(비용/총이익)이 일정 임계 이상인지
- **의심 시나리오**
  - 신호는 유효하지만 “자주 바뀌는” 구조라 비용에 먹힘

### E) 레짐(언제만 되나? 언제는 완전히 죽나?)
- **점검**
  - risk-on/off(ETF 관측 지표)로 구간을 나눠 성과를 분해
  - 금리 민감(IEF/TLT), 성장주 민감(QQQ), 헬스케어 방어(XLV)에서 조건부 성과 확인(관측만)
- **의심 시나리오**
  - 특정 레짐에서만 작동하는데, 현재 OOS 구간이 반대 레짐이라 “안 움직이는 것처럼” 보임  
  - 해결은 신호 추가보다 **레짐 기반 노출/쿨다운(E5)**가 빠름

---

### 실행 우선순위(48시간 내 실제 순서)
1) **E1 먼저**(로그/지표/해시가 서야 나머지 실험이 의미 있음)  
2) **E3**(degenerate fold 제거로 누수/평가 불능 제거)  
3) **E2**(비용 반영으로 운영 가능성 확보)  
4) **E4**(서바이버십 제거로 진짜 성능 확인)  
5) **E5**(oos_min/MDD 안정화로 루프의 “움직임” 확보)

이 5개만 고정 루프로 돌리면, 지금 보이는 “성능 정체/무의미한 개선”을 **관측 문제인지(파이프라인) / 평가 문제인지(CV) / 편향인지(PIT) / 비용인지 / 레짐-리스크 문제인지**로 48시간 안에 대부분 분리 가능하다.
