### PATCH-1: Degenerate Fold 원인 분해 및 수정
**(Infrastructure / 최우선)**

#### (a) 왜 필요한지
- 10개 fold 중 4개 퇴화 = 크로스밸리 신뢰도 붕괴
- 이 상태로 전략 개선해도 과최적화 여부 판단 불가
- **원인 후보**: exposure=0 기간, 시그널 임계값 과도, 데이터 누락

#### (b) 위험/부작용
- Fold 재설계 시 기존 champion과 비교 기준 변경
- 디버깅에 시간 소모 → 전략 개선 지연

#### (c) 최소 실험

```yaml
EXP-1A: fold_exposure_audit
  action: |
    for fold in [1,2,3,8]:
      - dump exposure_timeseries[fold]
      - count days where exposure > 0.01
      - identify signal_threshold vs price_data coverage
  gate: 로그 생성 완료
  expect: 퇴화 원인 1개 이상 식별

EXP-1B: fold_signal_relaxation  
  action: |
    signal_threshold: 0.5 → 0.3 (퇴화 fold만)
    재실행 CV
  gate: degenerate_folds ≤ 1
  expect: OOS mean 변동 ±15% 이내

EXP-1C: fold_boundary_shift
  action: |
    fold split 방식: sequential → purged_kfold(embargo=5d)
    전체 재실행
  gate: 모든 fold exposure_min > 0.05
  expect: OOS 분산 감소
```

#### (d) PASS 조건
```
✅ degenerate_folds ≤ 1 AND oos_std < 1.5
```

### PATCH-4: MDD 게이트 복구
**(Risk Management)**

#### (a) 왜 필요한지
- `worst_mdd: None` = 리스크 제한 장치 꺼진 상태
- 전략이 -30% MDD 허용해도 탐지 불가
- 프로덕션 전환 시 치명적

#### (b) 위험/부작용
- MDD 계산 추가 시 연산 비용 증가 (미미)
- 과거 champion 재평가 필요 가능

#### (c) 최소 실험

```yaml
EXP-4A: mdd_calculation_inject
  action: |
    backtest_engine.py 내 equity_curve에서:
    running_max = equity.cummax()
    drawdown = (equity - running_max) / running_max
    worst_mdd = drawdown.min()
    결과를 champion JSON에 포함
  gate: worst_mdd 값 출력
  expect: worst_mdd ∈ [-0.5, 0] 범위 내 유효값

EXP-4B: mdd_gate_integration
  action: |
    승격 조건에 추가:
    if worst_mdd < -0.25: reject("MDD exceeded 25%")
  gate: 게이트 로직 작동 확인
  expect: MDD 초과 실험 자동 기각 로그
```

#### (d) PASS 조건
```
✅ worst_mdd ≠ None AND mdd_gate 작동 확인
```

#### (b) 위험/부작용
- 복잡도 증가 → 과최적화 위험
- 시그널 추가 시 look-ahead bias 주의

