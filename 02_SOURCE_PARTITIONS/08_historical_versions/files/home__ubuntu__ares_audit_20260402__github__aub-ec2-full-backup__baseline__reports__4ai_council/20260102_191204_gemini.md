### 1. Degenerate Folds 격리 및 수정 (안정성 확보)
*   **Why:** 10개 중 4개 폴드(1, 2, 3, 8)가 붕괴됨. OOS Mean 3.32는 생존한 폴드의 편향일 가능성 높음. 최적화 솔버(Solver) 실패 혹은 데이터 NaN 처리가 원인.
*   **Risk:** 수정 후 전체 평균 성능이 급락할 수 있음(생존 편향 제거).
*   **Action Plan:**
    1.  `debug_mode=True` 활성화하여 폴드 붕괴 직전의 포트폴리오 상태 스냅샷 저장.
    2.  `MinWeight` 제약조건 완화 (0.0 -> 0.01 or Allow Cash 100%).
*   **Experiments (48h Loop):**
    *   **(1) 실험 정의:** `EXP_FIX_NAN_SOLVER` - 자산 수익률이 NaN/Inf인 경우 0으로 치환 후 최적화 수행, 현금 비중 제약 100% 허용.
    *   **(2) 게이트:** `degenerate_folds count == 0` AND `OOS Mean > 1.5`.
    *   **(3) 기대 관측치:** OOS Mean 하락(3.3 -> 2.x), 그러나 모든 폴드 정상 종료.

### 2. Rebalance Logger 수정 (관측 불가 해결)
*   **Why:** `Expecting value: line 1 column 1` 에러로 리밸런싱 내역 확인 불가. 전략이 '무엇을' 샀는지 모르면 개선 불가능.
*   **Risk:** 코드 수정 중 로깅 오버헤드 발생 가능성 (미미함).
*   **Action Plan:**
    1.  JSON/CSV 쓰기 모드를 `w`에서 `a`(append)로 변경 확인.
    2.  파일 경로 생성 시점과 쓰기 시점의 Race Condition 점검.
*   **Experiments (48h Loop):**
    *   **(1) 실험 정의:** `EXP_LOG_FORMAT_FIX` - 로거를 atomic write 방식으로 변경하고 포트폴리오 가중치 소수점 4자리에서 Truncate.
    *   **(2) 게이트:** `log_file_size > 0` AND `json_validity_check == PASS`.
    *   **(3) 기대 관측치:** `rebalance_pinpoint.py`가 정상 실행되어 종목별 턴오버 확인 가능.

### 3. 고강도 비용 구조 적용 (과최적화 필터링)
*   **Why:** Tech/Health 8-14 종목 집중 투자에서 OOS Mean 3.32는 과도함. 슬리피지 미반영 혹은 유동성 적은 소형 바이오/테크주 과매수 의심.
*   **Risk:** 샤프 지수 급락으로 기존 챔피언 폐기 가능성.
*   **Action Plan:**
    1.  기존 비용(bps)에 +10bps 가산 (Penalty Model).
    2.  유동성 하위 20% 종목 매매 제한.
*   **Experiments (48h Loop):**
    *   **(1) 실험 정의:** `EXP_HIGH_COST_STRESS` - Transaction Cost 20bps 적용, 매매 회전율(Turnover) 상한 20% 설정.
    *   **(2) 게이트:** `OOS Sharpe > 1.2` (Mean 수익률보다 샤프 방어력 중시).
    *   **(3) 기대 관측치:** 수익률은 하락하나, MDD가 개선되고 'Degenerate Folds'에서 살아남는 로직 발견.

### 4. Tech/Health 상관관계 제약 (Universe Risk)
*   **Why:** 두 섹터는 금리 민감도가 높음. 동조화 현상 시 MDD 방어 불가. 8~14개 종목이 동시에 하락할 때 현금 비중을 늘려야 함.
*   **Risk:** 상승장에서 수익 기회 상실 (Upside Capping).
*   **Action Plan:**
    1.  포트폴리오 내 종목 간 평균 상관계수가 0.7 이상일 때, 최대 노출도(Exposure)를 0.8 -> 0.5로 축소.
*   **Experiments (48h Loop):**
    *   **(1) 실험 정의:** `EXP_CORR_CAP` - Rolling 60일 상관계수 > 0.65 시 Cash 비중 최소 40% 강제.
    *   **(2) 게이트:** `worst_mdd > -0.15` (MDD 15% 이내 방어).
    *   **(3) 기대 관측치:** Exposure Max 수치가 0.84에서 0.6 수준으로 낮아지며 변동성 축소.

### 5. ETF 지표 활용 레짐 스위칭 (Rule-based Filter)
*   **Why:** 개별 주식(Tech/Health)만으로는 거시경제 충격 방어 어려움. ETF(XLK, XLV) 매매는 금지되어 있으나, 이를 '신호등'으로 사용.
*   **Risk:** 지표 휩소(Whipsaw)로 인한 잦은 진입/청산 비용.
*   **Action Plan:**
    1.  XLK(기술) 또는 XLV(헬스케어)의 20일 변동성이 상위 90%ile 도달 시, 해당 섹터 개별주 매수 금지.
*   **Experiments (48h Loop):**
    *   **(1) 실험 정의:** `EXP_ETF_VOL_FILTER` - XLK/XLV Volatility Breakout 시 해당 섹터 보유량 50% 컷.
    *   **(2) 게이트:** `Total Turnover < 기존 대비 80%`. (불필요한 하락장 매매 감소 확인).
    *   **(3) 기대 관측치:** 하락 구간에서 Exposure Min이 0.0에 가까게 유지되는 기간 증가.

### [성능 정체 시 원인 분해 아이디어]

만약 위 실험 후에도 성능이 개선되지 않거나 정체될 경우, 아래 트리 구조로 원인을 파악할 것.

1.  **Trigger Failure (신호 부재)**
    *   *Check:* 8~14개 유니버스 중 유효한 Alpha Score(상위 20%)가 뜨는 종목이 0개인가?
    *   *Solution:* 유니버스 필터 조건(시가총액, 거래량) 완화.

2.  **Execution Block (실행 불가)**
    *   *Check:* 신호는 있는데 `MinWeight`나 `RiskBudget` 제약 때문에 할당이 0이 되는가?
    *   *Solution:* 최적화 목적함수를 'Sharpe'에서 'Equal Risk Contribution'으로 변경 실험.

3.  **Cost Erosion (비용 잠식)**
    *   *Check:* 총 수익(Gross)은 우상향인데 순수익(Net)이 횡보하는가?
    *   *Solution:* 리밸런싱 주기를 주간 -> 월간으로 변경하거나, 진입 임계값(Threshold) 상향.

4.  **Regime Mismatch (시장 불일치)**
    *   *Check:* Tech/Health 섹터 전체가 하락하는 구간(Beta 하락)인가?
    *   *Solution:* 위 5번 제안(ETF 지표 활용) 강화 또는 Short 포지션(허용 시) 도입 검토.
