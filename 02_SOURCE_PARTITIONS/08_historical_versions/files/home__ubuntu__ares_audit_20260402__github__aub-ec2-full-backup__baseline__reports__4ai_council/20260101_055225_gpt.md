## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — **명령형 체크리스트**
(우선순위는 **누수 → 서바이버십 → 비용 → 과최적화 → 운영리스크** 순으로 배치)

---

# 1) 누수(lookahead)·체결시점 불일치 하드닝 (최우선)
### (a) 왜 필요한지
- Champion의 lockbox가 튼튼해 보여도, **“특정 시점 체결 가정(종가 체결 vs 익일 시가 체결)”** 또는 **feature 정렬(shift)** 한 줄로 샤프/수익이 과대평가되는 케이스가 가장 흔함.
- 특히 Tech/Healthcare는 갭이 커서 **체결시점 누수**가 있으면 성능이 “안 움직이면서도 계속 좋아 보이는” 착시가 생김.

### (b) 위험/부작용
- 누수 제거 후 성능 하락(정상).
- 체결 로직 변경으로 turnover/비용이 증가해 보일 수 있음(정상).

### (c) 최소 실험(스윕 1개 = 2~3 arms, 48시간 루프형)
**실험 1: `EXECUTION_TIMING_SWEEP`**
- (1) 실험 정의(arms)
  - Arm A: **신호 t일 종가 계산 → t일 종가 체결(기존)**  
  - Arm B: **신호 t일 종가 계산 → t+1일 시가 체결(권장 기본값)**  
  - Arm C: **모든 price/feature를 1 bar 추가 shift(강제 보수정렬) + t+1 시가 체결**
- (2) 게이트(자동 중단/판정)
  - Arm B가 Arm A 대비 lockbox_mean이 **-5% 이하로 급락**하면: 기존에 누수/불일치 가능성 “높음”으로 플래그 → 즉시 Arm C 결과를 우선 채택해 원인 확정.
  - Arm C까지 급락하면: 데이터/피처의 시간정렬을 전수 점검 대상으로 승격.
- (3) 기대 관측치(정상 범위)
  - 정상 시스템이면: Arm B가 Arm A 대비 **소폭 하락(0~5%)** 또는 유사
  - 누수 있으면: Arm B가 **유의미하게 붕괴**(예: 샤프/수익 급락, MDD 악화)

### (d) PASS 조건
- “권장 현실 체결(Arm B)” 기준으로도  
  - `lockbox_mean >= 1.75` 유지(Champion 1.79 근처 방어)  
  - `worst_mdd <= -0.115` 악화 제한(Champion -0.112 근처 방어)  
  - 그리고 Arm A/B 간 성능 차이가 과도하지 않을 것(누수 의심 제거)

---

# 2) 서바이버십·기업행동(스플릿/상장폐지)·유니버스 PIT(Point-in-Time) 점검
### (a) 왜 필요한지
- **US 개별주 8~14종 집중**은 유니버스 편향에 매우 민감.
- Tech/Healthcare는 과거 상장폐지/인수합병/티커 변경이 잦아 **PIT 미적용**이면 “살아남은 종목만” 학습하는 순간 성능이 잠김(lockbox 고정처럼 보임).

### (b) 위험/부작용
- 데이터 소스 교체/추가(상장폐지 수익률 포함)로 리서치 파이프라인 변경 비용 발생.
- 결과가 나빠지면 심리적으로 “후퇴”처럼 보임(정상적인 정화 과정).

### (c) 최소 실험(스윕 1개)
**실험 2: `PIT_UNIVERSE_STRESS`**
- (1) 실험 정의(arms)
  - Arm A: 현 유니버스(기존)
  - Arm B: **유니버스 리밸런싱 지연**(예: 분기/월말 기준으로만 종목 편입/제외 허용) + “as-of” 스냅샷 고정
  - Arm C: **랜덤 드랍아웃 스트레스**(각 리밸런스 시 1종목을 무작위로 제외 후 나머지로 재정규화) → 서바이버십/집중 의존도 탐지
- (2) 게이트
  - Arm B에서 성능이 크게 무너지면: PIT/편입 규칙이 과거를 참조하고 있을 가능성 ↑ → 데이터 조인/필터 조건 전수 점검.
  - Arm C에서 성능이 붕괴하면: 소수 “우승 종목” 의존(서바이버십 또는 단일종목 베팅) 가능성 ↑ → 포지션 상한/동일가중/리스크패리티 실험을 4번 우선순위로 당겨 실행.
- (3) 기대 관측치
  - 정상: Arm B/C에서도 lockbox 성능이 “완만히”만 약화
  - 비정상: Arm C에서 급락(특정 1~2종목에 성과가 잠겨 있음)

### (d) PASS 조건
- Arm B 기준 `lockbox_mean`이 Champion 대비 **-3% 이내** 방어
- Arm C에서도 `worst_mdd`가 **-0.13 이내**(집중 의존 과도 방지)

# 3) 비용(슬리피지/스프레드/수수료)·회전율 미반영 리스크를 “락박스 PASS 게이트”에 강제 편입
### (a) 왜 필요한지
- 성능이 “안 움직이는” 이유가 실제로는 **비용이 0 가정**이라 후보들이 전부 비슷하게 보이는 경우가 많음.
- 8~14종 소수 포트는 리밸런싱 빈도에 따라 **비용 탄력도**가 커서, 비용 모델이 없으면 전략 비교가 무의미해짐.

### (b) 위험/부작용
- 비용을 넣는 순간, 기존 챔피언 포함 전부가 “나빠져서” 기준 재설정 필요.
- 너무 보수적 비용 가정이면 유효 전략을 다 죽일 수 있음(스윕으로 감도 확인 필수).

### (c) 최소 실험(스윕 1개)
**실험 3: `COST_MODEL_SWEEP`**
- (1) 실험 정의(arms)
  - Arm A: 0 bps(진단용, 기존)
  - Arm B: **고정 왕복 10 bps**(수수료+슬리피지 합산의 보수적 기본)
  - Arm C: **변동 비용 = k * (일변동성 또는 ATR) + min_spread_floor** (간이 유동성 대체)
- (2) 게이트
  - Arm B에서 lockbox_mean이 Arm A 대비 **-10% 초과 하락**이면: turnover가 과도 → 4번(노출/리밸런스 제어) 즉시 착수.
  - Arm C에서만 붕괴하면: 변동성/갭에 취약한 체결 방식 → 1번(체결시점/시가체결) 결과와 교차검증.
- (3) 기대 관측치
  - 정상: 비용이 들어가도 순위(전략 간 상대 우열)가 유지되거나, turnover 낮은 쪽이 우세해짐
  - 비정상: 모든 전략이 동시 붕괴(리밸런스/체결이 과도하게 비현실적)

### (d) PASS 조건
- Arm B(왕복 10bps) 기준:
  - `lockbox_mean >= 1.70` 유지
  - `worst_mdd <= -0.12` 유지
  - 그리고 turnover 상위 10% 구간에서 성과 급락 패턴이 완화될 것(4번으로 연결)

# 4) 노출(집중/섹터)·리밸런스 제어: 8~14종 포트의 “과도한 베팅”을 자동 제한
### (a) 왜 필요한지
- worst_mdd가 약 -11%면 나쁘지 않지만, **소수종목 포트는 특정 이벤트에서 MDD가 급격히 커질 수 있음**(특히 Healthcare: 임상/규제 갭).
- 성능이 안 움직이는 이유가 “이미 한두 종목이 모든 걸 결정”하는 구조일 수 있음(2번 Arm C로 탐지).

### (b) 위험/부작용
- 상한/변동성 타게팅은 수익 상단을 깎을 수 있음.
- 과도한 안전장치는 lockbox_mean을 낮출 수 있음(하지만 MDD 개선이 목표).

### (c) 최소 실험(스윕 1개)
**실험 4: `EXPOSURE_CONTROL_SWEEP`**
- (1) 실험 정의(arms)
  - Arm A: 기존 포지션 사이징
  - Arm B: **단일 종목 비중 상한(예: 12~15%) + 동일 섹터 상한(Tech/Healthcare 내 세부 그룹 상한)**  
  - Arm C: **변동성 타게팅(포트 목표 연환산 변동성) + 리밸런스 밴드(±x% 이탈 시에만 거래)** → turnover 동시 억제
- (2) 게이트
  - Arm B에서 MDD가 개선되면(예: worst_mdd **+1%p 이상 개선**) → 집중 베팅 의존 구조 확정, Arm C를 기본 후보로 승격.
  - Arm C에서 lockbox_mean이 과도하게 깎이면(Champion 대비 **-5% 초과**) → 밴드/목표변동성만 완화하고 상한은 유지.
- (3) 기대 관측치
  - 정상: lockbox_mean 소폭 하락 또는 유지 + MDD/변동성 개선
  - 비정상: 성과가 유지되는데도 MDD가 전혀 개선되지 않음(그럼 트리거 자체가 문제 → 5번으로)

### (d) PASS 조건
- `worst_mdd <= -0.105` 수준으로 개선(Champion -0.112 대비 개선)
- `lockbox_mean >= 1.75` 방어

# 5) 과최적화·선정편향 방지: “락박스 고정/정체”를 깨는 실험 설계(검증 프로토콜 패치)
### (a) 왜 필요한지
- 현재 보고상 Candidate들이 lockbox가 “동일하게” 찍히는 형태가 반복되면,
  - (i) 실험이 실제로는 같은 전략을 재현하고 있거나(파라미터가 적용 안 됨),
  - (ii) 선택 과정이 tuning만 바뀌고 lockbox는 둔감하거나,
  - (iii) CV 누수(폴드 경계/중복)로 다양성이 사라졌을 가능성이 큼.

### (b) 위험/부작용
- purged/embargo CV 적용 시 tuning_mean 하락(정상).
- 탐색공간 축소 시 “대박” 후보가 줄어듦(대신 재현성↑).

### (c) 최소 실험(스윕 1개)
**실험 5: `ROBUSTNESS_PROTOCOL_SWEEP`**
- (1) 실험 정의(arms)
  - Arm A: 기존 CV/선정 프로토콜
  - Arm B: **Purged walk-forward + embargo(예: 5~10 trading days)** 적용
  - Arm C: **탐색공간 축소(상식적 범위) + 시드/폴드 다중 재현성 점수(분산 패널티)**를 스코어에 반영
- (2) 게이트
  - Arm B에서 성능이 급락하면: 기존 CV가 정보 누수/중복 가능성 ↑ → Arm B를 기본으로 고정.
  - Arm C에서 lockbox 분산이 줄고(폴드 간 편차↓) mean이 유지되면: 과최적화 완화 성공.
- (3) 기대 관측치
  - 정상: mean은 비슷하거나 소폭 하락, 대신 **최저 성능(min)과 분산이 개선**
  - 비정상: 모든 arm에서 lockbox가 동일 → 파라미터 미적용/실험 파이프라인 버그 가능성(운영/코드 레벨 점검으로 전환)

### (d) PASS 조건
- Arm B 또는 C에서:
  - `lockbox_min`이 유지 또는 개선(Champion min 1.3469 방어/상향)
  - 폴드 성과 분산(표준편차)이 유의미하게 감소
  - 동일 lockbox 반복 현상이 해소(다른 후보 간 lockbox가 구분됨)

## 48시간 자동 루프 실행 순서(총 5개 스윕만 돌려 “케이스 폭발” 방지)
아래 순서대로 **1개 스윕 결과가 게이트를 통과하면 다음 스윕 진행**, 실패하면 해당 패치로 고정하고 재런.

1. `EXECUTION_TIMING_SWEEP`
2. `PIT_UNIVERSE_STRESS`
3. `COST_MODEL_SWEEP`
4. `EXPOSURE_CONTROL_SWEEP`
5. `ROBUSTNESS_PROTOCOL_SWEEP`

(현재 제공된 autopilot 커맨드는 그대로 사용하되, 위 5개 스윕 spec을 candidate yaml에 추가/우선순위 고정)

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐) — **명령형 진단 트리**
아래는 “전략이 정체”일 때 **어디가 막혔는지**를 48시간 내 로그/리포트로 확정하는 분해 체크리스트.

## A) Trigger(신호 발생) 문제
- **신호 발생률(hit-rate)·포지션 변경률**을 일자별로 출력하라.
- “거의 매일 같은 포지션”이면: 신호가 둔감하거나 임계값이 과도.
- “매일 뒤집힘”이면: 노이즈 추종(→ 비용/리밸런스 밴드 필요).

## B) Apply(적용/체결) 문제
- “신호 시점”과 “체결 가격(OHLC 중 무엇)”을 분리해 저장하라.
- **신호 생성 시점(t)** / **주문 생성(t or t+1)** / **체결(t+1 open 등)** 타임라인을 강제 출력하라.
- 체결 타이밍만 바꿨는데 성능이 붕괴하면: 누수/갭 민감(→ 1번).

## C) Exposure(노출/구성) 문제
- 종목별 PnL 기여도 top/bottom을 고정 리포트로 뽑아라.
- “상위 1~2개 종목이 전체 성과 대부분”이면: 서바이버십 또는 단일 이벤트 베팅(→ 2번/4번).
- 포트폴리오의 **유효 종목 수(Effective N = 1/Σw²)**를 기록하라(8~14 목표 대비 실제가 3~4면 위험).

## D) Cost(비용) 문제
- 거래당 비용, 일별 총비용, 비용/수익 비율을 저장하라.
- “비용이 수익의 20~30% 이상”이면: 리밸런스 밴드/상한/회전 제한이 1순위(→ 3번/4번).

## E) Regime(레짐) 문제 — ETF는 **매매 금지**, 관측지표로만
- 다음 ETF/지표로 레짐 라벨을 붙여 **성과를 조건부 분해**하라:
  - Tech: `XLK` 또는 `QQQ`
  - Healthcare: `XLV`, (바이오 민감도) `XBI`/`IBB`
  - 위험회피/변동성: `VIX`(또는 VIX proxy), 금리: `TLT`(또는 10Y 수익률)
- 레짐 예시 라벨(간단 4분면)
  - Risk-on/off: QQQ(또는 SPY) 200D 상/하
  - Rates up/down: TLT 50D 모멘텀 상/하
- 특정 레짐에서만 돈 벌면: “레짐 게이트(진입/익스포저 축소)”가 필요(→ 4번에 흡수)

## 운영 리스크(자동 루프에서 반드시 넣을 것: 실패 시 거래/백테스트 중지 게이트)
- 데이터 최신성 체크: **마지막 바 timestamp가 기대보다 오래되면 FAIL-STOP**
- 코퍼레이트 액션 누락 감지: split/dividend 급변 시 경고
- 실험 파이프라인 무효 감지: 서로 다른 후보인데 lockbox 결과가 “완전히 동일”이 반복되면 **파라미터 미적용/캐시 오염**으로 FAIL 처리

---

위 TOP5는 “다음 48시간에 실제로 결과가 갈라지는” 항목만 남긴 구성이다. 가장 먼저 **체결시점(1) + PIT/서바이버십(2) + 비용(3)** 을 통과시켜야, 그 다음 전략 개선(4~5)이 의미 있게 움직인다.
