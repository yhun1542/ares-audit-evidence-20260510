# 1. 24~48시간 우선순위 TOP 5 제안 (Actionable Checklist)

현재 'Degenerate Folds [1, 2, 3, 8]' 현상과 로깅 시스템 붕괴(FileNotFound/JSON Error)는 시스템이 **'보이지 않는 상태로 과적합(Survivor Bias)'**되고 있음을 시사함. 성능 개선보다 **'시스템 정상화'**가 급선무.

1.  **[CRITICAL] Degenerate Folds(1,2,3,8) 원인 규명 및 수정**
    *   *진단:* 특정 기간(Folds) 데이터 전무 혹은 로직 에러(NaN)로 인해 학습/검증이 스킵됨. 생존 편향(Survivorship Bias)의 가장 강력한 증거.
    *   *액션:* `MinDataPoints` 제약 해제 혹은 해당 Fold 기간 내 존재하지 않는 종목(Tech/Bio 신규 상장주) 제외 로직 수정.

2.  **[SYSTEM] Rebalance/Signal Logger 복구**
    *   *진단:* `[Errno 2]`, `Expecting value` 에러. 최적화 근거 데이터(거래 내역)가 기록되지 않음.
    *   *액션:* JSONL Atomic Write 적용, 경로(Path) 하드코딩 제거 및 상대 경로 정규화.

3.  **[STRATEGY] Tech/Healthcare Sector Hard-Filter 적용 (8~14 Stocks)**
    *   *진단:* 현재 Exposure Max ~0.84이나, 섹터 및 종목 수 제약 준수 여부 불투명.
    *   *액션:* 유니버스 구성 단계에서 ETF 제외 + GICS Sector(Info Tech, Health Care) 필터 강제 + Top-K(Liquidty * Volatility) 로직 주입.

4.  **[RISK] Cost Model(Slippage+Fee) 강제 주입**
    *   *진단:* 높은 OOS Mean(3.32)은 비용 미반영일 확률 높음. 8~14 종목 집중 투자는 리밸런싱 비용에 취약.
    *   *액션:* bps(base points) 기반 슬리피지 모델(최소 10bps) 적용 후 OOS 재산출.

5.  **[OP] Execution Fail-safe (Max Drawdown Limit)**
    *   *진단:* `oos_min: -0.02`는 아직 안정적이나, 레짐 변화 시 급락 위험.
    *   *액션:* 개별 종목 MDD > 15% 발생 시 해당 종목 강제 청산(Cut-off) 로직 추가.

# 2. 제안별 상세 명세 (Why / Risk / Experiments / Pass Condition)

### Proposal 1: Fix Degenerate Folds (데이터 생존 편향 제거)
*   **(a) Why:** 실패한 Fold(1,2,3,8)를 제외한 평균 성과(3.32)는 허상임. 전 기간 검증 없이는 배포 불가.
*   **(b) Risk:** 수정 시 OOS Mean이 대폭 하락할 수 있음(현실화). 이는 버그가 아니라 '진실'을 마주하는 과정.
*   **(c) Experiments (48hr Loop):**
    *   **(1) 실험 정의:** `EXP-FIX-NAN`: 유니버스 선정 시 `dropna()` 대신 `fillna(0)` 혹은 `ffill` 적용 여부 확인. `EXP-DYNAMIC-UNIV`: 각 Fold 기간에 실제 거래 가능했던 Tech/Health 종목만으로 유니버스 재구성(Look-ahead 방지).
    *   **(2) 게이트:** 모든 Fold(0~9)에서 `Sharpe != None` 및 `TradeCount > 0`.
    *   **(3) 기대 관측치:** `degenerate_folds: []` (빈 리스트), OOS Mean 하락(1.5~2.0 수준으로 정상화).

### Proposal 2: Logger Repair (가시성 확보)
*   **(a) Why:** `AUB Rebalance Pinpoint` 도구가 작동하지 않음. 팩터 기여도 분석 불가.
*   **(b) Risk:** 로깅 I/O 오버헤드로 백테스트 속도 소폭 저하.
*   **(c) Experiments (48hr Loop):**
    *   **(1) 실험 정의:** `EXP-LOG-DEBUG`: 매 리밸런싱 시점마다 (Date, Ticker, TargetWeight, AlphaScore)를 CSV가 아닌 JSONL로 Append 모드 기록.
    *   **(2) 게이트:** `rebalance_pinpoint.py` 실행 시 에러 없이 Report 생성.
    *   **(3) 기대 관측치:** `diagnosis report` 생성 성공.

### Proposal 3: Tech+Healthcare Concentration (8~14 Stocks)
*   **(a) Why:** [절대 규칙] 준수. Tech/Bio는 변동성이 커서 분산(8~14)이 필수적이나 과도한 분산은 수익 희석.
*   **(b) Risk:** 특정 섹터 악재(예: 금리 인상, 약가 인하) 시 MDD 급증. 상관계수 높은 종목 쏠림 현상.
*   **(c) Experiments (48hr Loop):**
    *   **(1) 실험 정의:** `EXP-SECTOR-CONC`: Universe = (GICS Tech | GICS Health) & (Exclude ETF). Rank = Liquidity(30d) 상위 50 -> Volatility 조정 -> Top 12 Pick.
    *   **(2) 게이트:** 포트폴리오 내 `Sector != Tech/Health` 비중 0%. 보유 종목 수 `Min 8, Max 14` 유지율 95% 이상.
    *   **(3) 기대 관측치:** 기존 대비 Volatility 상승, Sharpe 유지/소폭 상승.

# 3. 성능 정체 시 원인 분해 (Decomposition Logic)

성능(OOS Mean)이 개선되지 않거나, `Degenerate Folds` 해결 후 성능이 급락할 경우 다음 트리거를 점검.

1.  **트리거(Trigger) 불발:**
    *   *현상:* Tech/Health 특성상 모멘텀이 강할 때만 신호가 발생해야 함.
    *   *점검:* 시그널 임계값(Threshold)이 너무 높아 거래가 없는지(Zero Trade in Folds), 너무 낮아 노이즈에 진입하는지 확인.

2.  **적용(Apply) 실패 - 유동성 필터:**
    *   *현상:* 시뮬레이션에서는 사지는데 실전(혹은 비용 포함 백테스트)에서 박살남.
    *   *점검:* 선택된 8~14개 종목이 Micro-cap Bio 종목인지 확인(Penny Stock 제외 필터 필수).

3.  **노출(Exposure) 왜곡:**
    *   *현상:* `Max Exposure 0.83` -> 현금이 17% 놀고 있음.
    *   *점검:* 14개 종목에 균등 배분(Equal Weight) 시도 중 자투리 현금이 남는지, 혹은 변동성 역가중(Risk Parity) 로직이 지나치게 보수적인지 확인. Target Exposure를 0.95~0.99로 상향 조정 실험.

4.  **레짐(Regime) 불일치 (Fold 1,2,3 실패 원인):**
    *   *현상:* 2022년 하락장, 2010년대 초반 횡보장 등 특정 레짐에서 전략 붕괴.
    *   *점검:* 하락장에서의 Short 포지션 부재가 원인이라면, `Cash Padding`(현금 비중 확대) 로직이 MDD 방어 기제로서 작동하는지 확인. (미국주식 Long Only 전제 시 Cash가 유일한 헷지 수단).
