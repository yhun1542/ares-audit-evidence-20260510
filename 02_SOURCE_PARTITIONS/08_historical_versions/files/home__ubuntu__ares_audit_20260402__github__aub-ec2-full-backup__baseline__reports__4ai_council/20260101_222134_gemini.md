### 1. [Critical] Candidate `exp_mrd_fsa` 무결성 검증

**제안 A: Feature Selection Leakage Audit (데이터 누수 점검)**
*   **(a) 이유:** 파일명의 `fsa`(Feature Selection Algorithm)가 CV Fold 외부에서 전체 데이터를 보고 특징을 선택했을 가능성이 높음. 이는 실전에서 100% 실패함.
*   **(b) 위험:** 누수가 확인되면 해당 모델 폐기 및 Baseline 복귀로 인한 시간 손실.
*   **(c) 실험 정의 (Experiments):**
    1.  **`EXP_LEAK_01` (Strict Separation):** Feature Selection 로직을 `fit()` 내부로 강제 이동 후, Training Set으로만 `select_k_best` 수행.
    2.  **`EXP_LEAK_02` (Shuffle Test):** Target(y)을 무작위 셔플링한 상태에서 동일한 Feature Selection 수행 시 성능이 0에 수렴하는지 확인.
*   **(d) PASS 조건:**
    *   `EXP_LEAK_01`의 Sharpe Ratio가 원본 `candidate` 대비 20% 이상 하락하지 않음.
    *   `EXP_LEAK_02`의 Sharpe가 0.0 근처(노이즈)여야 함. (여전히 높으면 코드 구조적 버그).

**제안 B: Cost & Slippage Torture Test (비용 민감도 테스트)**
*   **(a) 이유:** `mrd`(Mean Reversion Daily 추정) 전략은 잦은 매매를 동반할 수 있음. 0.05% 슬리피지에서 작동하던 전략이 0.1%에서 붕괴되면 운영 불가.
*   **(b) 위험:** 높은 기대 수익률이 수수료로 모두 증발함을 확인(False Hope 제거).
*   **(c) 실험 정의 (Experiments):**
    1.  **`EXP_COST_HI`:** Transaction Cost를 기존 설정의 2배(예: 10bps → 20bps)로 설정 후 Backtest.
    2.  **`EXP_LIQ_LOW`:** 유동성 하위 20% 종목(Health/Bio small cap 등) 거래 시 패널티 3배 부과.
*   **(d) PASS 조건:**
    *   `EXP_COST_HI` 실행 시 Tuning Mean > 1.0 유지.
    *   Worst MDD가 -10%를 초과하지 않음.

### 성능 정체 시 원인 분해 (Debug Logic)

성능 지표(Sharpe/MDD)가 48시간 이상 개선되지 않을 경우, 다음 순서로 원인을 제거하십시오:

1.  **Trigger (신호 발생):**
    *   *증상:* 거래 횟수가 너무 적음(월 5회 미만).
    *   *조치:* 진입 임계값(Threshold) 완화 또는 `Vol Scaled Threshold` 적용.
2.  **Exposure (비중):**
    *   *증상:* 신호는 맞는데 수익 기여도가 낮음.
    *   *조치:* 베팅 사이즈(Kelly Criterion 등)가 너무 보수적인지 확인. 현금 보유 비중이 50% 이상 지속되는지 체크.
3.  **Regime (시장 국면):**
    *   *증상:* 특정 연도(2022년 등)에만 MDD가 박살남.
    *   *조치:* ETF(QQQ, XLV)의 200일 이평선 하회 시 Long-Only 전략 중단(Cash out) 로직 추가.
4.  **Survivorship (생존 편향):**
    *   *증상:* 과거 데이터에서는 잘 되는데 최근 데이터(Fold14)에서만 안 됨.
    *   *조치:* 상장폐지된 종목이 유니버스 데이터셋에 포함되어 있는지(Delisted Asset Handling) 확인.
