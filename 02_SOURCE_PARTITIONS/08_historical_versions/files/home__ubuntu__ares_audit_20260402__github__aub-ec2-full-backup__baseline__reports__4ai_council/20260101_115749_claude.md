## 1. 우선순위 TOP-5 Patch 제안

### PATCH-1: Signal Decay 측정 및 Freshness Gate 도입

| 항목 | 내용 |
|------|------|
| **왜 필요** | 현재 시그널이 생성 후 며칠까지 유효한지 측정 없음 → 과거 최적화된 decay가 현재 작동하는지 불명 |
| **위험/부작용** | Gate 너무 짧으면 거래 빈도↓ → 노출 부족; 너무 길면 기존과 동일 |
| **PASS 조건** | lockbox_mean ≥ 1.33 AND decay_halflife ≥ 3일 (통계적 유의) |

```
실험 정의:
┌─────────────────────────────────────────────────────────┐
│ EXP-1A: signal_age 1~7일별 forward return 분해         │
│ EXP-1B: freshness_gate=3일 적용 후 lockbox 재평가      │
│ EXP-1C: decay_halflife 추정 → adaptive holding 연동    │
└─────────────────────────────────────────────────────────┘
GATE: decay_halflife < 2일이면 시그널 자체 재설계 필요 → PATCH-3 선행
기대 관측치: signal_age vs return 상관계수 테이블 (7×1)
```

### PATCH-2: 비용 모델 현실화 (Slippage Stress Test)

| 항목 | 내용 |
|------|------|
| **왜 필요** | 현재 비용 가정이 낙관적이면 실거래 손실 발생. lockbox 성과가 live에서 재현 안 될 위험 |
| **위험/부작용** | 비용 상향 시 기존 전략 수익률 급락 → false negative 가능 |
| **PASS 조건** | slippage 2× stress에서도 lockbox_mean ≥ 1.20 |

```
실험 정의:
┌─────────────────────────────────────────────────────────┐
│ EXP-2A: 현재 비용 가정 문서화 (bps, spread, impact)    │
│ EXP-2B: slippage ×1.5, ×2.0 시나리오 lockbox 재실행   │
│ EXP-2C: 종목별 ADV 대비 position size 검증            │
└─────────────────────────────────────────────────────────┘
GATE: ×2.0에서 lockbox_mean < 1.10이면 sizing 축소 필수
기대 관측치: cost_sensitivity_curve.png (3-point)
```

### PATCH-3: 알파 소스 분해 (Factor Attribution)

| 항목 | 내용 |
|------|------|
| **왜 필요** | 수익 정체 원인 불명 → 시그널 vs 타이밍 vs 사이징 중 어디가 병목인지 분리 필요 |
| **위험/부작용** | 분해 과정에서 추가 자유도 → 과최적화 유혹 |
| **PASS 조건** | 단일 컴포넌트가 전체 alpha의 60%+ 설명 시 해당 컴포넌트 강화 |

```
실험 정의:
┌─────────────────────────────────────────────────────────┐
│ EXP-3A: return = α_signal + α_timing + α_sizing + ε   │
│         OLS 분해 (lockbox 기간)                        │
│ EXP-3B: signal만 사용 (equal weight, no timing) 성과  │
│ EXP-3C: timing만 사용 (random signal) 성과            │
└─────────────────────────────────────────────────────────┘
GATE: 어떤 컴포넌트도 30% 미만이면 시스템 복잡도 대비 효과 의심
기대 관측치: attribution_pie.json {signal: %, timing: %, sizing: %, residual: %}
```

### PATCH-4: Regime Filter 강건성 (False Positive Rate)

| 항목 | 내용 |
|------|------|
| **왜 필요** | worst_mdd -9%는 특정 regime에서 filter 실패 의심. Filter가 "늦게" 작동하면 손실 확대 |
| **위험/부작용** | Filter 민감도↑ → 정상 구간도 회피 → 노출 부족 |
| **PASS 조건** | regime_filter FPR ≤ 15% AND worst_mdd ≥ -7% |

```
실험 정의:
┌─────────────────────────────────────────────────────────┐
│ EXP-4A: regime 전환점 ±5일 window에서 filter 정확도   │
│ EXP-4B: filter lag 1일/2일/3일 시뮬레이션             │
│ EXP-4C: VIX 20/25/30 threshold 민감도 분석            │
└─────────────────────────────────────────────────────────┘
GATE: FPR > 25%면 filter 로직 재설계
기대 관측치: confusion_matrix.json {TP, FP, TN, FN}
```

|------|------|

| **위험/부작용** | 분산 강제 시 edge 있는 종목 노출 감소 |
| **PASS 조건** | HHI < 0.25 AND top3_contribution < 50% of total return |

```
실험 정의:

│ EXP-5C: max_position_weight 15%/20%/25% 비교          │
└─────────────────────────────────────────────────────────┘
GATE: top3 제외 시 lockbox_mean < 1.0이면 전략 robustness 의심
```

```yaml
    duration_hours: 24

      - freshness_gate_3d
      - regime_filter_vix25

      lockbox_mean: "≥ 1.33"

  - name: handoff
    duration_hours: 6
```
