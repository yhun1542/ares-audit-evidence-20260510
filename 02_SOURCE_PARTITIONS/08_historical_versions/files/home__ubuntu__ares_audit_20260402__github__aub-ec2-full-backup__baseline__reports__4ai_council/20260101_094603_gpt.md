아래 5개를 **다음 24~48시간 TOP5 우선순위**로 고정하고, 각각을 **48시간 자동 루프에서 바로 돌릴 수 있는 “명령형 체크리스트”**로 제시한다.  
(우선 점검 순서: **누수 → 과최적화 → 서바이버십 → 비용 미반영 → 운영 리스크** / **미국주식 only, Tech+Healthcare 중심, 8~14종목, ETF 매매 금지(관측지표만)**)

## 1) [운영/평가 무결성] Lockbox가 “항상 동일”하게 찍히는 현상부터 차단 (가짜 정체/가짜 개선 방지)
**(a) 왜 필요한지**  
현재 로그에서 **Champion과 Last PASS Candidate의 lockbox_mean/min, MDD가 동일**하게 보인다. 이것이 “우연히 동일”일 확률보다, (1) lockbox 평가 미실행 (2) 캐시/아티팩트 재사용 (3) 후보 파일이 lockbox로 안 들어감 (4) seed/기간 고정으로 결과가 덮어쓰기 되는 **운영 버그**일 확률이 더 크다. 이 상태면 성능이 “안 움직이는 원인”이 전략이 아니라 **평가 파이프라인**일 수 있다.

**(b) 위험/부작용**  
- 캐시 무효화/재계산으로 **런타임·비용 증가**
- 지금까지의 기록 일부가 “재현 불가”로 판정될 수 있음(하지만 빨리 드러내는 게 이득)

**(c) 최소 실험(단일 실험 ID 내 2~3 아블레이션 스위치)**  
**Experiment P1: `exp_eval_integrity_lockbox_v1`**
1) **아티팩트 해시 강제**: (candidate config + 데이터 컷오프 + 코드 git sha + seed)로 run_id 생성하고 lockbox 결과에 run_id를 박아라. run_id 불일치 시 결과 폐기.  
2) **캐시 금지 1회 런**: lockbox만 `--no-cache`로 강제 재평가하고, 기존 lockbox 아티팩트를 임시 격리 디렉토리로 이동하라.  
3) **락박스 구간/샘플 수 로그 강제**: lockbox 기간, 바 수, 종목 수, 결측률을 리포트에 “필수 필드”로 추가하고 누락 시 실패 처리하라.

**(d) PASS 조건 (게이트 포함)**  
- **Gate(필수)**: lockbox 리포트에 run_id/기간/샘플수/종목수/결측률이 모두 존재. 누락 시 FAIL.  
- **PASS**: 서로 다른 candidate 2개를 돌렸을 때 lockbox 결과가 **바이너리 동일**하게 반복되지 않아야 함(최소 1개 지표라도 차이).  
- **기대 관측치**: “성능 정체”가 진짜 전략 문제인지, 평가/캐시 문제인지 즉시 분리된다.

## 2) [비용 미반영/과매매] 슬리피지·스프레드·거래세(수수료) + 턴오버 페널티를 “하드 게이트”로
**(a) 왜 필요한지**  
미국주식(특히 테크/헬스케어 대형주)은 표면상 유동성이 좋아 보여도, **리밸 빈도/오더 크기/변동성 레짐**에 따라 실현 슬리피지가 커진다. 비용을 약하게 반영하면 튜닝에서만 좋아지고 lockbox에서 안 움직이는 전형적 원인이 된다.

**(b) 위험/부작용**  
- 순수 샤프/수익률이 하락할 수 있음(현실화)
- 과도한 페널티는 “거의 안 바꾸는 포트”로 굳어 신호가 죽을 수 있음

**(c) 최소 실험**  
**Experiment P2: `exp_cost_turnover_gate_v1`**
1) **거래비용 모델 2단**: (고정 bps 수수료) + (일별 ATR 또는 고저폭 기반 슬리피지 bps)로 구성해라.  
2) **턴오버 상한 게이트**: 48시간 루프 기준(=2일 단위 또는 1일 리밸 기준) 예상 턴오버가 임계치 초과 시 포지션 변경을 “부분 체결(clip)”로 줄여라.  
3) **8~14종목 유지 + 최소 홀딩**: 종목 수(8~14) 유지하면서 **min holding days**(예: 2~3일) 옵션을 온/오프로 비교해라.

**(d) PASS 조건**  
- **Gate(필수)**: 백테스트 리포트에 (총 거래횟수, turnover, 비용 차감 전/후 성과, 평균 슬리피지 bps) 출력. 누락 시 FAIL.  
- **PASS**: 비용 차감 후 lockbox_mean이 Champion 대비 **-0.03 이내 유지**하면서(또는 개선), worst_mdd가 **악화되지 않을 것(ΔMDD ≥ -0.01)**.  
- **기대 관측치**: “튜닝만 좋고 실전 약한” 후보가 자동으로 걸러지고, 개선이 비용 내성에서 나와야만 통과한다.

## 3) [누수/서바이버십] Point-in-time 정합성 강제(특히 헬스케어 이벤트/실적/가이던스)
**(a) 왜 필요한지**  
헬스케어는 FDA/임상/실적 수정 등 이벤트가 잦아 **발표 시점 누수**가 쉽게 생긴다. 테크도 실적/가이던스 반영에서 lookahead가 흔하다. “성능이 안 움직임”이 실제론 **누수 제거로 성능이 내려가며 상쇄**되고 있을 수도 있고, 반대로 누수가 남아 있으면 챔피언이 과대평가일 수 있다.

**(b) 위험/부작용**  
- 누수 제거 후 성과 하락 가능(정상)
- 데이터 소스에 따라 PIT 강제가 구현 난이도/비용 증가

**(c) 최소 실험**  
**Experiment P3: `exp_pit_survivorship_audit_v1`**
1) **릴리즈 랙 강제**: 재무/펀더멘털/컨센서스(있다면) 피처는 “발표일+N일(예: +1~2영업일)” 이후부터만 사용하도록 마스킹하라.  
2) **가격 피처 T-1 고정**: 당일 종가로 신호를 만들고 당일 체결한 것처럼 보이는 경로를 차단(신호는 t-1까지, 체결은 t 종가/익일 시가 중 택1로 고정).  
3) **델리스트/심볼 변경 처리 로그**: 유니버스 구성 시점에 “생존편향 방지” 체크(델리스트 리턴 포함 여부, 데이터 공백 처리)를 리포트에 강제 출력하라.

**(d) PASS 조건**  
- **Gate(필수)**: 피처별 “최신 사용 가능 시점” 검사(lookahead unit test) 1개라도 실패 시 전체 FAIL.  
- **PASS**: 누수 제거 후에도 lockbox_mean이 Champion 대비 **-0.05 이내**이고, fold14_mdd / worst_mdd가 **동일하거나 개선**.  
- **기대 관측치**: 헬스케어 이벤트 구간에서의 비정상적 초과성과(너무 매끈한 승률/IC)가 정상 수준으로 내려가며, 대신 비용/리스크 내성이 개선된 후보만 남는다.

## 4) [노출/리스크] “8~14종목 Tech+Healthcare”를 유지하면서 단일종목/팩터/베타 과노출을 하드 제한
**(a) 왜 필요한지**  
소수 종목(8~14) 운용은 좋지만, 테크/헬스케어는 **팩터(모멘텀/퀄리티/저변동) 쏠림**과 **메가캡 단일 종목 리스크**가 크다. 성과가 안 움직이는 이유가 신호가 아니라 “리스크가 이미 포화”라서일 수 있다(추가 알파가 노출에 묻힘).

**(b) 위험/부작용**  
- 강한 제약은 알파를 깎아먹을 수 있음
- 제약 튜닝이 과최적화로 번질 수 있음(최소 파라미터로 고정)

**(c) 최소 실험**  
**Experiment P4: `exp_risk_constraints_v1`**
1) **단일 종목 상한**: 8~14종목 내에서 개별 비중 cap(예: 12~15%) 강제.  
2) **섹터 바스켓 균형(Tech/Healthcare)**: 두 섹터 합은 100% 유지하되, 어느 한 섹터가 과도하게(예: >75%) 치우치면 리밸 시 페널티/클립.  
3) **베타/변동성 타겟팅**: QQQ(Tech 대리)·XLV(Healthcare 대리)·SPY는 **관측 지표**로만 사용하여, 포트폴리오 20~60일 realized vol이 목표 밴드 밖이면 총 익스포저를 스케일링.

**(d) PASS 조건**  
- **Gate(필수)**: 리포트에 (max single-name weight, Tech/HC 비중, realized vol, market beta proxy) 출력.  
- **PASS**: worst_mdd가 Champion 대비 **개선(덜 음수) 또는 동일(+/-0.005 이내)** 이면서 lockbox_mean **동일 이상**.  
- **기대 관측치**: 샤프가 큰 폭으로 뛰기보다, **최저 MDD/꼬리 리스크**가 먼저 개선되는 형태가 정상.

## 5) [레짐/트리거] ETF “관측지표”로만 레짐 게이트를 추가해 신호 적용 구간을 제한
**(a) 왜 필요한지**  
테크/헬스케어는 레짐(금리/리스크온오프/변동성)에 따라 같은 신호가 전혀 다르게 동작한다. 성능이 안 움직이는 이유는 신호가 평균적으로는 맞아도 **나쁜 레짐에서 다 까먹는 구조**일 수 있다. ETF는 매매하지 않고 “상태 관측”에만 써서 운영 단순성을 유지한다.

**(b) 위험/부작용**  
- 레짐 게이트가 지나치면 거래 기회 상실(언더트레이딩)
- 레짐 정의가 과최적화되면 lockbox에서 붕괴

**(c) 최소 실험**  
**Experiment P5: `exp_regime_gate_etf_indicators_v1`**
1) **변동성 게이트**: VIX(또는 VIX 유사 지표) 수준/추세가 임계 초과면 신규 진입을 줄이고(또는 익스포저 스케일 다운) 기존 포지션만 관리.  
2) **리스크온/오프 필터**: QQQ/SPY 상대강도, XLV/QQQ 상대강도 같은 단순 비율 지표로 “테크 우위/헬스 우위” 국면만 선택 적용.  
3) **이벤트 주간 완화**: (관측 기반) 변동성 급등 + 주요 실적 시즌 구간에는 리밸 빈도를 줄이는 옵션(턴오버 억제와 결합).

**(d) PASS 조건**  
- **Gate(필수)**: 레짐별(예: high vol vs low vol) 성과 분해 리포트 생성. 없으면 FAIL.  
- **PASS**: 나쁜 레짐 구간의 손실이 줄어 **worst_mdd 개선**이 확인되고, 전체 lockbox_mean이 Champion 대비 **-0.02 이내**(또는 개선).  
- **기대 관측치**: 전체 평균 성과가 크게 안 움직여도, **레짐별 분산**이 줄어드는 방향이 먼저 나타난다.

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래는 질문 없이 바로 실행 가능한 **진단 트리(로그/리포트 항목 추가 중심)**다.

## A) Trigger(신호 발생) 문제인지
- **체크**: 일별 신호 발생 빈도, 상위 랭크 종목의 교체율, 신호 값 분포(평균/분산/클리핑 여부)
- **이상 징후**: 신호 분산이 너무 작음(모두 비슷) / 상위 종목이 고정 / 특정 날짜에만 폭발
- **조치**: 신호 표준화 방식(zscore, winsor) 변경은 최후. 먼저 **데이터 결측/정규화 버그**를 의심.

## B) Apply(적용/체결 모델) 문제인지
- **체크**: 신호 생성 시점(t-1)과 체결 시점(t 또는 t+1) 일관성, 리밸 타이밍 고정 여부
- **이상 징후**: 성과가 체결가 정의에 따라 급변 → 누수/체결 가정 의존
- **조치**: 체결가 2안(익일 시가 vs 당일 종가)을 **고정 1안으로만** 운영해 변동 원인을 줄여라.

## C) Exposure(노출) 문제인지
- **체크**: 단일종목 비중, 섹터(Tech/HC) 비중 편향, 팩터 프록시(모멘텀/저변동) 노출, 상위 1~2종목 기여도
- **이상 징후**: 성과의 대부분이 1~2종목/1개 레짐에서만 발생(서바이버십/운빨 가능)
- **조치**: P4의 하드 캡/스케일링이 먼저.

## D) Cost(비용/턴오버) 문제인지
- **체크**: turnover, 거래 횟수, 평균 보유기간, 비용 차감 전후 성과 격차
- **이상 징후**: 비용 차감 전은 개선되는데 차감 후는 정체/악화
- **조치**: P2의 턴오버 게이트 + min holding으로 구조적으로 해결.

## E) Regime(국면) 문제인지
- **체크**: 고변동/저변동, 금리 급등기 유사 구간, 리스크온/오프 구간별 성과
- **이상 징후**: 특정 국면에서만 지속 손실 → 평균 성과가 안 움직이는 핵심 원인
- **조치**: P5처럼 **ETF는 관측만**으로 레짐 게이트를 추가.

---

## 48시간 루프에 바로 넣는 실행 순서(명령형)
1) **P1 먼저 실행**: lockbox 평가 무결성부터 확정해라(캐시/아티팩트/기간 로그 강제).  
2) **P2를 P1 다음으로 고정**: 비용·턴오버를 게이트로 올려 후보군을 현실화해라.  
3) **P3로 누수/서바이버십 테스트를 강제**: PIT/릴리즈 랙/델리스트 로그를 실패 조건으로 만들어라.  
4) **P4로 노출 상한을 하드코딩**: 8~14종목 유지하면서 단일종목/섹터/볼 타겟만 최소 제약으로 추가해라.  
5) **P5는 마지막으로 얹어라**: 레짐 게이트는 분해 리포트가 나오는 상태에서만 적용해라.

위 5개만으로도 “전략이 정체”인지 “평가/비용/노출/레짐이 가리는지”가 48시간 내에 분리된다.
