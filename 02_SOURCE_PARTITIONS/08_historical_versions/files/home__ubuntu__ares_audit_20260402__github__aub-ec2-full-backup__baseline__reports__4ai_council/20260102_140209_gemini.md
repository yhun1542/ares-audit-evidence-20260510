### 1. 24~48시간 우선순위 TOP 3 (시스템/전략 복합)

현재 가장 치명적인 문제는 **"리밸런싱 로그 소실(No rebalance data)"**입니다. 최적화 도구(Pinpoint)가 작동하지 않으면 승자(Champion)의 1.88 OOS Mean이 '운'인지 '실력'인지 검증할 수 없습니다.

#### **PRIORITY 1: Rebalance Logger 복구 및 포맷 정규화**
*   **Action:** `experiment_system` 내 로깅 모듈 긴급 패치. CSV/JSONL 파싱 에러(line 1 column 1) 해결.
*   **(a) Why:** 매매 원인(Trigger)과 거래 비용을 추적 불가. '비용 미반영' 리스크가 극대화된 상태.
*   **(b) Risk:** 로깅 오버헤드로 인한 백테스트 속도 저하(미미함). 기존 로그와 호환성 단절.
*   **(c) Experiments:**
    1.  `fix_log_format_jsonl`: JSON 구조체 강제(Valid JSON check).
    2.  `verify_log_path_creation`: 디렉토리 생성 로직 선행 확인(`FileNotFound` 방지).
    3.  `stress_io_write`: 틱 단위 쓰기 대신 배치(Batch) 쓰기로 I/O 부하 테스트.
*   **(d) PASS 조건:** `aub_rebalance_pinpoint.py` 실행 시 에러 없이 리포트가 생성되고, Turnover(회전율)가 0보다 큰 값이 찍힐 것.

#### **PRIORITY 2: Turnover Brake (매매 회전율 제한 실험)**
*   **Action:** 8~14개 종목의 Tech+Healthcare 집중 포트폴리오에서 '잦은 교체'를 막는 Hysteresis(이력현상) 로직 추가.
*   **(a) Why:** OOS Min(0.43)이 낮음. 과도한 리밸런싱 비용이 하방을 뚫었을 가능성 높음. Tech 섹터의 노이즈에 과민 반응 중일 수 있음.
*   **(b) Risk:** 급락장(Regime Change)에서 손절이 늦어질 수 있음(Lag).
*   **(c) Experiments:**
    1.  `exp_inertia_10`: 기존 보유 종목의 점수가 신규 진입 후보보다 10% 낮아지기 전까지 교체 금지.
    2.  `exp_min_holding_5d`: 최소 보유 기간 5일 강제 (단기 노이즈 필터링).
    3.  `exp_transaction_penalty_increase`: 시뮬레이션 상 거래 비용(bps)을 2배로 설정 후 생존성 테스트.
*   **(d) PASS 조건:** OOS Mean 유지(>1.8) 하되, Turnover가 기존 대비 30% 이상 감소. OOS Min > 0.6 상승.

#### **PRIORITY 3: ETF 기반 Regime Filter (Sector Defense)**
*   **Action:** XLK(Tech), XLV(Health) ETF를 '관측 지표'로만 활용하여 진입 차단(Gate) 로직 적용.
*   **(a) Why:** 개별 종목 14개만으로는 섹터 전체의 붕괴(Systemic Risk)를 피하기 어려움. 서바이버십 편향 방지.
*   **(b) Risk:** ETF 시그널 지연으로 인한 진입 기회비용 발생(Over-filtering).
*   **(c) Experiments:**
    1.  `exp_gate_xlk_ma50`: XLK가 50일 이동평균선 아래일 때 Tech 종목 매수 금지.
    2.  `exp_gate_xlv_rsi`: XLV RSI(14) < 30 (과매도) 구간에서만 Healthcare 비중 확대.
    3.  `exp_sector_exposure_cap`: 단일 섹터(Tech or Health) 비중 최대 60% 제한 (강제 분산).
*   **(d) PASS 조건:** MDD(최대 낙폭) 10% 개선, Sharpe Ratio 증가.

### 2. 48시간 자동 루프 정의 (Auto-Loop Configuration)

다음 포맷을 `experiment_config.json` 또는 오토파일럿 큐에 주입하십시오.

```yaml
loop_id: "RECOVERY_AND_STABILIZE_V6"
cycle_duration: "48h"

experiment_1:
  definition: "LOG_FIX_AND_COST_REALITY"
  params:
    logger_mode: "batch_jsonl"
    sim_slippage_bps: 20  # 비용 현실화
  gate:
    metric: "system_health"
    condition: "log_file_exists AND log_size_bytes > 1024"
  expected_obs:
    - "Pinpoint Tool 정상 작동"
    - "OOS Mean 소폭 하락(비용 반영분), OOS Min 상승 기대"

experiment_2:
  definition: "SECTOR_HYSTERESIS_TEST"
  params:
    score_buffer: 1.10  # 교체 저항선
    universe: ["US_TECH_TOP20", "US_HEALTH_TOP20"]
    target_count: 12
  gate:
    metric: "oos_sharpe"
    condition: ">= 1.5" # 1.88에서 너무 떨어지지 않는지 확인
  expected_obs:
    - "Turnover 50% 감소"
    - "Exposure Min 0.47 -> 0.60 수준으로 안정화 (현금 보유 축소)"

experiment_3:
  definition: "ETF_REGIME_FILTER_XLK_XLV"
  params:
    regime_signal: ["XLK", "XLV"]
    regime_logic: "ma_200_trend"
  gate:
    metric: "worst_mdd"
    condition: "better_than_champion"
  expected_obs:
    - "대세 하락장에서 현금 비중 100% 도달 여부 확인"
```

### 3. 성능 정체(Stagnation) 원인 분해 아이디어

성능 지표(OOS Mean 1.88)가 개선되지 않을 때 체크할 **진단 트리**:

1.  **트리거(Trigger) 불발:**
    *   *가설:* Tech/Healthcare 종목 간 상관관계가 너무 높아(Correlation > 0.8), 분산 효과 없이 다 같이 죽고 다 같이 사는 중.
    *   *확인:* `aub_no_delta_diagnoser`에서 종목 간 Pairwise Correlation 매트릭스 출력.

2.  **적용(Apply) 실패:**
    *   *가설:* 리밸런싱 로직이 "Target Weight"를 계산했으나, 최소 주문 금액(Lot Size)이나 잔고 부족으로 실제 주문이 거부됨.
    *   *확인:* (로그 복구 후) `target_weight` vs `executed_weight` 델타 확인.

3.  **노출(Exposure) 과소/과대:**
    *   *가설:* 현재 Exposure Min(0.47)은 너무 낮음. 상승장에서 현금을 53%나 들고 있어 벤치마크 대비 언더퍼폼.
    *   *확인:* Exposure와 S&P500(SPY) 지수의 상관계수 확인.

4.  **비용(Cost) 누수:**
    *   *가설:* 8~14개 종목을 유지하기 위해 매일 미세한 리밸런싱(0.1% 비중 조절)을 수행하여 슬리피지 누적.
    *   *확인:* "Do Nothing" 구간(Threshold) 도입 시 성능 변화 추적.

5.  **레짐(Regime) 불일치:**
    *   *가설:* 현재 전략이 '추세 추종(Momentum)'인데 시장이 '박스권(Mean Reversion)'임.
    *   *확인:* 최근 3개월 시장 변동성 대비 전략 수익률 비교.
