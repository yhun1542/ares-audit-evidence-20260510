[우선순위 제안 및 실행 체크리스트]

### 1. MDD 계산 로직 디버깅 및 무결성 검증 (최우선)
**(a) 필요성:** `worst_mdd: None`은 심각한 결함임. 계산 로직 오류거나, 거래가 거의 없거나, 데이터가 비정상임. 이 상태의 `oos_mean` 1.88은 신뢰 불가.
**(b) 위험:** 로직 수정 후 퍼포먼스가 급락하거나(현실화), 시스템이 멈출 수 있음.
**(c) 실험:**
   1. `Fix_MDD_Calc`: MDD 계산식에 `dropna()` 및 0 나누기 예외처리 추가 후 재실행.
   2. `Force_Drawdown`: 강제로 손실 거래를 주입하여 MDD가 음수로 찍히는지 단위 테스트.
   3. `Sanity_Check`: 거래 횟수가 30회 미만인지 확인 (과소 거래로 인한 MDD None 가능성).
**(d) PASS 조건:** `worst_mdd`가 음수(예: -0.01 이상)로 산출되고, 로그에 NaN 에러가 없을 것.

### 2. 엄격한 Tech/Health 유니버스 하드 캡(Hard Cap) 적용
**(a) 필요성:** Tech+Healthcare 8~14 종목 제한 준수 필수. 현재 챔피언이 이 제약을 위반하고 전체 유니버스에서 수익을 냈을 가능성 배제.
**(b) 위험:** 선택 종목 수 감소로 분산 효과 저하, 변동성 증가.
**(c) 실험:**
   1. `Sector_Filter_Loose`: XLK(Tech), XLV(Health) 편입 종목 중 시총 상위 50개만 화이트리스트 지정.
   2. `Selection_Top12`: 매일 모멘텀/변동성 점수 상위 12개(Tech 6: Health 6)로 포트폴리오 강제 리밸런싱.
**(d) PASS 조건:** 일별 보유 종목 수 `8 <= count <= 14` 유지, Tech/Health 비중이 90% 이상일 것.

### 3. 미래 참조(Look-ahead) 차단 및 지연(Lag) 강제
**(a) 필요성:** `oos_mean` 1.88은 과도하게 높음. 종가(Close) 피처를 당일 진입에 사용하는 '데이터 누수' 의심.
**(b) 위험:** 예측력(Signal)의 급격한 소멸, Sharpe Ratio 급락.
**(c) 실험:**
   1. `Shift_1_All`: 모든 피처 생성 후 `shift(1)` 강제 적용, 익일 시가(Open) 진입으로 백테스트.
   2. `Open_Execution`: 시그널 발생 시 당일 Close가 아닌 익일 Open으로 체결 가격 변경.
**(d) PASS 조건:** `oos_mean`이 0.8 이상 유지되면서 `exposure`가 0이 되지 않을 것.

### 4. 슬리피지 및 수수료 페널티 모델 강화
**(a) 필요성:** 8-14개 종목 집중 투자 시 충격 비용(Impact Cost) 무시 불가. 비용 미반영 수익률은 허상임.
**(b) 위험:** 잦은 매매(High Turnover) 전략의 경우 수익 곡선이 우하향으로 반전될 수 있음.
**(c) 실험:**
   1. `Fee_20bps`: 편도 수수료+슬리피지 합산 20bps(0.2%) 적용 테스트.
   2. `Slippage_Vol_Adj`: 변동성(ATR) 상위 종목에 대해 슬리피지 가중치 1.5배 적용.
**(d) PASS 조건:** 비용 반영 후에도 연환산 수익률(CAGR) > 15%, MDD < 20% 유지.

### 5. ETF 관측 기반의 동적 노출(Exposure) 제어
**(a) 필요성:** 개별 주식(Tech/Health) 매매만 허용되나, 시장 위험 관리는 QQQ/XLV ETF 지표를 참조해야 함. `exposure_min` 0.47은 하락장에서 위험할 수 있음.
**(b) 위험:** 헷지 시그널 오작동 시 상승장에서 노출 축소로 기회비용 발생(Underperformance).
**(c) 실험:**
   1. `QQQ_MA_Filter`: QQQ가 50일 이평선 하회 시 전체 타겟 비중(Target Exposure) 0.5배로 축소.
   2. `VIX_Gate`: VIX > 25 구간에서 신규 진입 금지 및 기존 포지션 50% 청산.
**(d) PASS 조건:** `worst_mdd`가 기존 대비 10% 이상 개선(감소)되고, 하락장 방어력 확인.

### [48시간 자동 루프 정의]

**Cycle 1: 무결성 확보 (MDD & Leakage)**
1. **실험 정의:** `Fix_MDD_Calc` + `Shift_1_All` (동시 적용)
2. **게이트:** `worst_mdd` is not None AND `oos_mean` > 0.5
3. **기대 관측치:** 수익률 하락은 필연적이나, 현실적인 MDD(-10% ~ -30%)가 관측되어야 함.

**Cycle 2: 유니버스 및 비용 현실화**
1. **실험 정의:** Cycle 1 통과 모델에 `Selection_Top12` + `Fee_20bps` 적용
2. **게이트:** `turnover_ratio` < 5.0 (월간 회전율 체크)
3. **기대 관측치:** Tech/Health 밸런스 유지 여부 확인, 비용 차감 후 생존 여부.

### [성능 정체 시 원인 분해 (Debugging Stagnation)]

성능 지표가 움직이지 않거나 0에 수렴할 경우 아래 순서로 점검:

1.  **트리거(Trigger) 확인:**
    *   진입 조건(`threshold`)이 너무 높아 시그널 자체가 0건인지 확인.
    *   *Action:* 진입 임계값을 50% 낮춰 거래 강제 발생 유도.
2.  **노출(Exposure) 확인:**
    *   포지션 사이징 로직이 리스크 패리티 등으로 인해 비중을 0.01% 미만으로 잡는지 확인.
    *   *Action:* `Equal Weight`로 고정하여 로직 테스트.
3.  **레짐(Regime) 불일치:**
    *   현재 백테스트/라이브 구간이 Tech/Health가 횡보하는 구간(Choppy Market)인지 확인.
    *   *Action:* 추세추종(Trend) 로직에서 평균회귀(Mean Reversion) 로직으로 스위칭 테스트.
4.  **데이터 무결성:**
    *   특정 종목의 가격 데이터가 결측되어 전체 연산이 Skip 되는지 확인.
    *   *Action:* 데이터 전처리 단계에서 `Forward Fill` 적용 여부 체크.
