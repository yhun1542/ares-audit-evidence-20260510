(우선 점검: **누수 → 과최적화/서바이버십 → 비용 미반영 → 운영 리스크**)

# 1) (P0) 데이터 누수/룩어헤드/기업행사 처리 “하드 게이트” 고정
### (a) 왜 필요한지
- 현재 Champion 대비 Candidate가 **MDD가 크게 악화**(-0.081 → -0.112)된 상태라, “알파가 약해짐” 외에 **룩어헤드/리밸런싱 타임스탬프/조정가 적용 오류**가 섞이면 CV가 즉시 깨짐.
- 자동선정(--select-best) 루프에서 누수 1건은 “계속 이기는 모델”을 만들고, 실계좌에서 즉시 붕괴.

### (b) 위험/부작용
- 데이터/타임스탬프 엄격화로 **백테스트 성능이 떨어질 수 있음**(정상).
- 구현 시 “최신 바만 거래 가능” 제약이 생겨 turnover/진입 타이밍이 바뀔 수 있음.

### (c) 최소 실험 2~3개 (하나의 ‘누수 감사 실험 세트’로 묶어 실행)
**실험세트 #1: Leak-Audit Pack (성능 실험이 아니라 ‘게이트’ 실험)**
1) **Timestamp Gate**: 시그널 생성 시점(T)과 체결 시점(T+1 open 또는 T close) 강제 분리 토글(2안 비교)  
2) **Adj/Unadj Gate**: 조정주가 사용 구간을 “학습/시그널=unadj, 수익률계산=total-return(배당/분할 반영)”로 분리하는 토글  
3) **Corporate Action Shock Test**: 분할/합병/배당 이벤트일 주변 ±3일 수익률/포지션 급변 플래그 로깅

### (d) PASS 조건 (게이트)
- (필수) 룩어헤드 의심 로그 0건: **미래 바 참조/동일 바 체결** 탐지 0  
- (필수) 조정가/비조정가 혼용으로 인한 **단일 일자 수익률 20%+ 스파이크**(대형주 기준) 원인 설명 가능(기업행사로 라벨링)  
- (권장) 게이트 적용 후에도 Champion의 **worst_mdd가 -0.09 이하로 악화되지 않을 것**

**48h 루프 형태**
- (1) 실험 정의: Leak-Audit Pack 실행(2~3 토글)  
- (2) 게이트: 위 PASS(필수) 미달 시 이후 실험 전부 중단  
- (3) 기대 관측치: “성능 수치”보다 **이상치 로그 감소/체결시점 일관성**이 관측

# 2) (P0) 비용/슬리피지/턴오버 현실화(“비용 미반영” 제거) + 비용 민감도 게이트
### (a) 왜 필요한지
- Tech+Healthcare 8~14종목은 유동성이 좋아도, 자동 루프가 미세한 우위를 추구하면 **턴오버로 알파가 증발**하기 쉬움.
- Champion의 lockbox_mean이 4.01로 높아서, “조금 더”를 찾다가 **비용 민감한 취약 전략**을 고를 리스크가 큼(서바이버십/다중검정 결합).

### (b) 위험/부작용
- 비용을 올리면 단기적으로 대부분 성능 하락 → 선택 편향 방지에는 유리하나, “개선이 안 보이는” 구간이 올 수 있음.

### (c) 최소 실험 2~3개 (하나의 ‘비용 캘리브레이션 실험 세트’)
**실험세트 #2: Cost-Sensitivity Pack**
1) **슬리피지 3점 민감도**: 0.5bp / 2bp / 5bp(체결가 스프레드+임팩트 단순모델)  
2) **수수료/SEC/TAF 포함 토글**: 0bp vs 현실치(브로커 가정 고정)  
3) **턴오버 캡 오버레이**: 48h 루프용으로 “일일 목표 turnover 상한(예: 20~30%)” 적용 vs 미적용

### (d) PASS 조건
- (필수) **5bp 슬리피지**에서도 lockbox_mean이 **Champion 대비 -15% 이내**로 유지(취약전략 배제 목적)  
- (필수) turnover 캡 적용 시 worst_mdd가 **동일하거나 개선**(악화 금지)  
- (권장) 비용 상향에도 수익률 급락이 없고(민감도 완만), 성과가 “한 점”이 아니라 **곡선으로 안정적**

**48h 루프**
- (1) 실험 정의: 비용 3점 + turnover 캡 토글  
- (2) 게이트: 5bp에서 붕괴(락박스 급락)하면 해당 후보군 폐기  
- (3) 기대 관측치: “평균 개선”보다 **비용 곡선의 기울기(취약도)**가 낮아짐

# 3) (P0) 서바이버십/유니버스 고정(미국 Tech+Healthcare 8~14) + 리밸런싱 규칙 단순화
### (a) 왜 필요한지
- 유니버스가 흔들리면(편입/편출/상장폐지/데이터 공백) 자동선정 루프에서 **서바이버십 편향**과 “우연히 남은 종목” 효과가 발생.
- “ETF 매매 제외” 조건상, 종목 수를 8~14로 고정하고 **리밸런싱 규칙을 단순화**해야 운영 리스크가 내려감.

### (b) 위험/부작용
- 유니버스를 고정하면 특정 기간(예: 헬스케어 약세)엔 기회가 줄어 성능이 둔해질 수 있음.
- 너무 대표주만 쓰면 팩터(빅테크 모멘텀) 편향이 커질 수 있음.

### (c) 최소 실험 2~3개 (하나의 ‘유니버스 고정 실험 세트’)
**실험세트 #3: US 8~14 Fixed-Universe Pack** (예시 12종목)
- Tech: AAPL, MSFT, NVDA, AMZN, GOOGL, META, AVGO, ORCL  
- Healthcare: LLY, UNH, JNJ, ABBV  *(총 12, 필요 시 8~14로 조정하되 “고정 리스트” 유지)*

토글 3개만:
1) **12종 고정 vs 8종(더 집중)**: 12종(위) vs 8종(Tech 5 + HC 3)  
2) **리밸런싱 빈도**: 매일 vs 주 2회(예: 화/금)  
3) **동일가중 vs 변동성역가중**(간단 risk parity)

### (d) PASS 조건
- (필수) 어떤 고정 유니버스에서도 **lockbox 최악 구간(worst_mdd)**가 Champion(-0.081) 대비 **동일 또는 개선**  
- (권장) 종목 수 축소(8종) 시에도 비용/턴오버가 상식 범위로 감소하고, 성과가 “한두 종목 기여”로 쏠리지 않을 것(기여도 상위 1종목 < 35% 등)

**48h 루프**
- (1) 실험 정의: 12 vs 8, 리밸런싱 2안, 가중치 2안  
- (2) 게이트: 기여도 쏠림/턴오버 폭증/락박스 MDD 악화 시 폐기  
- (3) 기대 관측치: 성과가 약간 낮아져도 **안정성/재현성 지표 개선**

# 4) (P1) 과최적화(다중검정) 억제: “선택-편향 방지 게이트”와 결과 저장(실패도 보존)
### (a) 왜 필요한지
- `--select-best`는 필연적으로 **서바이버십/다중검정 편향**을 키움.
- 지금 Champion이 강한데, 계속 후보를 뽑으면 “언젠가” 운 좋게 락박스에서 이긴 모델을 고르게 됨(실전 붕괴 확률↑).

### (b) 위험/부작용
- 단기적으로 “선정되는 모델 수”가 줄어 진행이 느려 보일 수 있음.
- 로그/아카이빙이 늘어 운영 비용(스토리지/시간)이 증가.

### (c) 최소 실험 2~3개 (하나의 ‘선택편향 완화 패치’)
**실험세트 #4: Anti-Overfit Selection Patch**
1) **락박스 1회성 승리 금지**: “락박스 평균”뿐 아니라 **락박스 하위 10% 분위 성과**도 기준에 포함  
2) **복수 지표 동시 게이트**: mean만 보지 말고 (mean, worst_mdd, turnover, cost_sensitivity slope) 동시 통과  
3) **실패 후보도 아카이브**: 후보별 설정/지표/로그를 영구 저장 → 이후 원인분해 가능

### (d) PASS 조건
- (필수) 신규 Candidate가 Champion 대비 lockbox_mean이 개선되지 않아도, **worst_mdd 개선(+ 비용 민감도 개선)** 없으면 “승격 금지”  
- (필수) 동일 기간 재실행 시 결과 변동이 작아야 함(결정론적 시드/데이터 버전 고정)

**48h 루프**
- (1) 실험 정의: Selection gate를 “다지표”로 강화 + 아카이빙  
- (2) 게이트: 다지표 미달은 자동 폐기  
- (3) 기대 관측치: “가끔 대박” 후보가 사라지고 **안정적 후보만 남음**

# 5) (P1) 레짐(Tech risk-on/off, 금리, 방어장) 노출 제어: ETF는 “관측지표”로만 사용
### (a) 왜 필요한지
- Candidate(exp_macro_alpha_shadow)가 MDD를 키운 것은 “매크로 피처가 알파를 준다”기보다 **레짐 전환에서 오작동**했을 가능성이 큼.
- ETF 매매는 금지지만, QQQ/XLV/SPY/TLT/VIX 등의 변화를 **거래 게이트(리스크 오프)**로만 쓰면 안정성이 좋아질 수 있음.

### (b) 위험/부작용
- 게이트가 과하면 수익 기회를 놓쳐 **mean 하락** 가능.
- 레짐 정의가 복잡하면 다시 과최적화로 돌아감 → 규칙을 1~2개로 제한.

### (c) 최소 실험 2~3개 (하나의 ‘레짐 게이트 실험 세트’)
**실험세트 #5: Regime-Gate Pack (indicator-only)**
1) **리스크 오프 감지**: VIX 급등(예: 20 상향 돌파 or 5일 z-score) 시 포지션 총 익스포저 50%로 축소  
2) **Tech vs Healthcare 로테이션 게이트**: QQQ 상대 XLV 모멘텀 약화 시 Tech 비중 상한(예: 70%→40%)  
3) **금리 스트레스 게이트(관측)**: TLT 급락(금리 급등) 구간에서 고밸류 Tech 노출 축소(상한만)

### (d) PASS 조건
- (필수) worst_mdd가 Champion 대비 **개선(덜 음수)** 또는 최소 동일  
- (권장) lockbox_mean이 소폭 하락하더라도 **하위 꼬리(최악 구간) 개선이 더 클 것**  
- (권장) 게이트 발동률이 과도하지 않을 것(예: 전체 기간의 30% 초과 시 과제어로 간주)

**48h 루프**
- (1) 실험 정의: 3개 게이트를 독립 토글로 실행(조합 폭발 금지: 단독/핵심 1개+1개까지만)  
- (2) 게이트: 발동률 과다 또는 mean 급락 시 폐기  
- (3) 기대 관측치: “평균”보다 **왼쪽 꼬리와 드로우다운 경로**가 완만해짐

# 성능이 안 움직일 때 “원인 분해” 아이디어(트리거/적용/노출/비용/레짐)
아래를 **로그/리포트에 강제 출력**해서 어디서 막히는지 분해하라.

## A) Trigger(시그널 생성) 문제
- 피처 드리프트: 학습 구간 vs 락박스에서 피처 분포(z-score/KS-test) 변화
- 신호 세기 약화: 예측 점수 분산/상위-하위 스프레드 감소
- 라벨 정의 문제: 리턴 산식(조정/배당) 불일치로 학습 신호가 희석

**관측치**: 예측 점수 분산, 상하위 분위 수익률 스프레드, 피처 분포 변화 리포트

## B) Apply(집행/리밸런싱) 문제
- 리밸런싱 타이밍 불일치(T close에서 계산하고 T close에 체결하는 오류)
- 포지션 라운딩/최소 주문 단위/체결 방식 때문에 신호가 제대로 반영되지 않음
- 리밸런싱 빈도가 너무 잦아 신호가 비용으로 상쇄

**관측치**: 신호→주문→체결→포지션 반영 지연, 주문 미체결/부분체결 비율, 실현 turnover

## C) Exposure(노출) 문제
- 종목 기여도 쏠림: “NVDA 하나가 다 함” 같은 구조면 락박스가 레짐에 종속
- 팩터 편향: 빅테크 모멘텀/장기 듀레이션 노출이 과도(금리 레짐에 취약)
- 섹터 밸런스 붕괴: Tech 과대 → 드로우다운 확대

**관측치**: 종목별 PnL 기여도, 섹터 비중 시계열, 단순 팩터(모멘텀/베타/볼) 노출

## D) Cost(비용) 문제
- 백테스트 상 알파가 대부분 “미세한 엣지”라서 슬리피지 2~5bp에 붕괴
- 턴오버가 성능을 잠식(특히 일일 리밸런싱)

**관측치**: 비용 전/후 수익률 차이, 비용 민감도 곡선 기울기, turnover와 성과 상관

## E) Regime(레짐) 문제
- QQQ/XLV, VIX, 금리(TLT) 구간별로 성과가 반대로 움직임
- 특정 이벤트(긴축/리스크오프)에서만 MDD가 집중

**관측치**: 레짐 버킷(예: VIX 상/하, QQQ-XLV 상대모멘텀 상/하, TLT 추세 상/하)별 성과 테이블, 최악 5개 구간의 공통 조건

## 추가 운영 리스크(자동 루프) 즉시 완화 체크
- 데이터 버전/시드/환경 해시를 결과 파일명에 강제 포함(재현성)
- “승격 조건”을 mean 단일 지표에서 **worst_mdd + 비용 민감도 + turnover** 동시 통과로 변경
- 실패 후보도 저장(나중에 원인분해/회귀 테스트에 필수)

위 5개 실험 세트는 48시간 루프에서 “게이트→관측→승격/폐기”가 자동으로 돌아가도록 설계되어 있으며, Champion(v5)의 강점을 해치지 않으면서 **드로우다운/비용 취약성/선택편향**을 우선적으로 줄이는 방향이다.
