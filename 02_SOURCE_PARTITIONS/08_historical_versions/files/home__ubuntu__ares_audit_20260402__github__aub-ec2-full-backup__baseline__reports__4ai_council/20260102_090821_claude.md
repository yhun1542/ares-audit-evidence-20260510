## 1. 우선순위 TOP 5 실행 항목

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### P1. MDD 계산 파이프라인 복구 (BLOCKER)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- worst_mdd=None → 리스크 게이트 우회, 실제 손실 노출 미파악
- 과최적화된 전략이 통과할 가능성

**(b) 위험/부작용**
- 수정 시 과거 champion 무효화 가능
- 계산 로직 버그면 전체 백테스트 재실행 필요

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 1-1 | `compute_mdd()` 함수 단위테스트 (합성 equity curve) | MDD = 정답±0.1% | 함수 정상 작동 확인 |
| 1-2 | Champion run 재실행 + MDD 강제 로깅 | MDD ≠ None | 수치 출력 (예상: -15%~-25%) |
| 1-3 | MDD > -30% 게이트 추가 후 기존 champion 재검증 | PASS/FAIL 명시 | champion 유지 또는 탈락 |

**(d) PASS 조건**
```
worst_mdd ∈ [-35%, -5%] AND mdd_gate actively rejects at least 1 bad run
```

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### P2. OOS Min Fold 취약점 분석
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- OOS Mean 1.88 vs Min 0.43 → **4.4배 편차**
- 특정 레짐(금리 급등? 섹터 로테이션?)에서 전략 붕괴 가능성

**(b) 위험/부작용**
- 해당 fold 제거 시 survivorship bias 유입
- 과도한 레짐 필터 추가 시 트레이드 수 급감

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 2-1 | 최악 fold 기간 식별 + VIX/금리/섹터 오버레이 | 리포트 생성 | 레짐 라벨링 (예: "2022-Q2 금리급등") |
| 2-2 | 해당 기간 포지션별 기여도 분해 | 상위 3 손실 종목 식별 | 집중 리스크 여부 판단 |
| 2-3 | Min fold Sharpe ≥ 0.7 되는 파라미터 존재 여부 탐색 | Δ Mean Sharpe ≤ -0.3 | 트레이드오프 수용 가능 범위 |

**(d) PASS 조건**
```
min_fold_sharpe ≥ 0.6 AND mean_sharpe ≥ 1.5 (동시 충족)
```

### P3. 거래비용 현실화 검증
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- 비용 미반영 시 OOS 1.88 → 실제 1.2 이하 가능
- Tech/Healthcare 일부 mid-cap은 스프레드 15-30bps

**(b) 위험/부작용**
- 과도한 비용 가정 시 false negative (좋은 전략 탈락)
- 슬리피지 모델 복잡화 → 유지보수 부담

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 3-1 | 현재 비용 가정 로깅 (bps 단위) | 문서화 | 예: "5bps one-way" |
| 3-2 | 10bps / 15bps / 20bps 시나리오별 Sharpe 재계산 | Sharpe@15bps ≥ 1.3 | 민감도 테이블 |
| 3-3 | 턴오버 계산 + 연간 총비용 추정 | 총비용 < 2% AUM/yr | 운영 가능성 확인 |

**(d) PASS 조건**
```
sharpe_after_15bps_cost ≥ 1.3 AND annual_turnover_cost < 2.5%
```

### P4. 누수(Leakage) 체크리스트 실행
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- OOS Sharpe 1.88은 "너무 좋음" 영역 → 누수 의심 필수
- 특히 earnings date, rebalance date 주변 미래정보 유입 가능

**(b) 위험/부작용**
- 누수 발견 시 전체 파이프라인 재작성 필요
- False alarm 시 시간 낭비

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 4-1 | 시그널 생성 시점 vs 가격 사용 시점 1일 lag 강제 | Sharpe 변화 < 20% | 누수 없음 확인 |
| 4-2 | Train/Val/Test date 경계에서 데이터 중복 체크 | 중복 row = 0 | 분리 정상 |
| 4-3 | T+0 수익률과 시그널 상관관계 (당일 정보 사용 여부) | corr < 0.05 | look-ahead 없음 |

**(d) PASS 조건**
```
all_leakage_tests = PASS AND sharpe_with_lag ≥ 0.8 * sharpe_original
```

## 3. 성능 미변동 시 원인 분해 트리

```
성능 안 움직임
│
├─[1] 트리거 실패
│   └─ 시그널이 생성 안 됨 (필터 과도, 데이터 누락)
│   → 체크: daily_signal_count > 0
│
├─[2] 적용 실패  
│   └─ 시그널 → 오더 변환 안 됨 (로직 버그, 조건 미충족)
│   → 체크: order_generated / signal_generated ratio
│
├─[3] 노출 실패
│   └─ 오더 → 체결 안 됨 (유동성, 가격 제한)
│   → 체크: fill_rate, partial_fill_count
│
├─[4] 비용 상쇄
│   └─ 수익 < 거래비용 (고빈도 턴오버)
│   → 체크: gross_return vs net_return gap
│
└─[5] 레짐 불일치
    └─ 현재 시장 ≠ 학습 시장 (변동성, 상관관계 변화)
    → 체크: rolling_sharpe 60d vs full_period
```
