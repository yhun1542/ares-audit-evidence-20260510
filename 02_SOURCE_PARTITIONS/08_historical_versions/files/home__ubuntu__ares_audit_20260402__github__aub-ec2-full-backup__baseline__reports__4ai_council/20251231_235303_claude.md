## 1. TOP-5 우선순위 제안

### P1. 폴드별 성능 분산 원인 분석 (진단 우선)
```
WHY: tuning_min=0.05 → 특정 폴드에서 거의 전멸. 이게 해결 안 되면 모든 개선은 노이즈
RISK: 진단에 시간 소요, 실행 지연
```

**실험 정의:**
```yaml
exp_fold_diagnosis_v1:
  action: "각 폴드별 CAGR/MDD/거래수 분해"
  gate: "자동 - 데이터 수집"
  expected: "worst 폴드 식별 + 해당 기간 시장 레짐 매핑"

exp_fold_regime_v1:
  action: "worst 폴드 기간의 VIX/SPY drawdown 상관관계"
  gate: "worst 폴드가 2022 또는 2018Q4 등 특정 레짐에 집중되는지"
  expected: "레짐 집중 시 → 레짐 필터 후보 확보"

exp_fold_exposure_v1:
  action: "worst 폴드 기간 평균 포지션 수/섹터 집중도"
  gate: "노출 부족 vs 잘못된 노출 구분"
  expected: "노출<30% → 진입 조건 완화 후보"
```

**PASS 조건:**
- [ ] worst 폴드 원인이 (a)레짐 (b)노출부족 (c)종목선택 중 하나로 귀결
- [ ] 다음 실험 방향이 1개로 수렴

### P2. 진입/청산 트리거 민감도 분석
```
WHY: 성능 안 움직임 = 트리거가 너무 tight하거나 이미 포화
RISK: 완화 시 노이즈 트레이드 증가
```

**실험 정의:**
```yaml
exp_trigger_relax_v1:
  action: "진입 조건 1단계 완화 (예: score threshold 0.6→0.5)"
  gate: |
    - 거래 수 +20% 이상 증가
    - 승률 -5%p 이내 유지
  expected: "CAGR +5% 또는 INCONCLUSIVE"

exp_trigger_tight_v1:
  action: "진입 조건 1단계 강화 (예: score threshold 0.6→0.7)"
  gate: |
    - 거래 수 -20% 이상 감소
    - 승률 +3%p 이상 증가
  expected: "MDD 개선 또는 CAGR 하락 확인"

exp_exit_speed_v1:
  action: "청산 조건 1일 빠르게 (trailing stop 민감도 +10%)"
  gate: "평균 보유일 -1일 이상"
  expected: "MDD 개선 여부 관측"
```

**PASS 조건:**
- [ ] 거래수/승률/CAGR 중 하나 이상 유의미하게 변화
- [ ] 최적 threshold 범위 0.1 단위로 좁혀짐

### P3. 비용 모델 현실화 점검
```
WHY: 현재 비용 가정이 낙관적이면 실제 수익률 30-50% 하락 가능
RISK: 너무 보수적이면 모든 전략 기각
```

**실험 정의:**
```yaml
exp_cost_realistic_v1:
  action: |
    슬리피지: 0.05% → 0.10%
    수수료: 0 → $1/trade
  gate: "lockbox_mean 10% 이상 하락 여부"
  expected: "Yes → 거래 빈도 축소 방향 확정"

exp_cost_extreme_v1:
  action: |
    슬리피지: 0.15%
    수수료: $2/trade
  gate: "lockbox_mean > 1.3 유지 여부"
  expected: "Yes → 전략 robust, No → 구조 재검토"
```

**PASS 조건:**
- [ ] 현실 비용에서 lockbox_mean > 1.5 유지
- [ ] 비용 민감도 곡선 확보 (비용 vs CAGR 플롯)

### P4. 종목 유니버스 집중도 리스크
```
WHY: Tech+Healthcare 8-14종목 = 개별 종목 영향 극대화
RISK: 특정 종목 제거 시 성능 붕괴 → 과적합 증거
```

**실험 정의:**
```yaml
exp_leave_one_out_v1:
  action: "Top5 기여 종목 각각 제외 후 백테스트"
  gate: "제외 시 CAGR 20% 이상 하락 종목 수"
  expected: |
    - 0개: robust
    - 1-2개: 경계
    - 3개+: 과적합 확정

exp_sector_balance_v1:
  action: "Tech 비중 상한 60% 적용"
  gate: "CAGR 10% 이상 하락 여부"
  expected: "하락 시 → 현재 Tech 과의존 확인"
```

**PASS 조건:**
- [ ] Leave-one-out 최대 하락 < 15%
- [ ] 섹터 상한 적용 후 lockbox_mean > 1.6

### P5. 레짐 필터 최소 실험
```
WHY: MDD -11.2%가 특정 레짐(예: 2022 베어마켓)에 집중됐을 가능성
RISK: 레짐 필터 = 미래 레짐 판단 불가 → 실전 적용 어려움
```

**실험 정의:**
```yaml
exp_regime_vix_v1:
  action: "VIX > 25 시 신규 진입 금지"
  gate: |
    - MDD 개선 2%p 이상
    - CAGR 하락 5% 이내
  expected: "PASS 시 간단한 방어 로직 확보"

exp_regime_spy_trend_v1:
  action: "SPY 50MA < 200MA 시 포지션 50% 축소"
  gate: |
    - MDD 개선 3%p 이상
    - 샤프 유지 또는 개선
  expected: "트렌드 필터 효과 검증"
```

**PASS 조건:**
- [ ] MDD 개선이 CAGR 손실보다 risk-adjusted로 유리
- [ ] 필터 발동 빈도 연 2-4회 수준 (과발동 아님)

## 2. 성능 미변화 원인 분해 프레임워크

```
성능 불변 시 체크 순서:

[1] 트리거 (신호 발생)
    └─ 신호가 발생은 하는가?
       ├─ No → 조건 완화 필요
       └─ Yes → [2]로

[2] 적용 (포지션 진입)
    └─ 신호 → 실제 진입 전환율?
       ├─ <50% → 필터/리스크 로직이 블로킹
       └─ >50% → [3]으로

[3] 노출 (시장 익스포저)
    └─ 평균 투자 비중?
       ├─ <40% → 현금 과다 → 기회비용
       └─ >40% → [4]로

[4] 비용 (실현 손익)
    └─ 거래당 평균 비용 vs 평균 수익
       ├─ 비용 > 수익의 30% → 거래 빈도 문제
       └─ <30% → [5]로

[5] 레짐 (시장 환경)
    └─ 특정 기간에 손실 집중?
       ├─ Yes → 레짐 필터 또는 인정(구조적 한계)
       └─ No → 종목 선택 로직 자체 재검토
```
