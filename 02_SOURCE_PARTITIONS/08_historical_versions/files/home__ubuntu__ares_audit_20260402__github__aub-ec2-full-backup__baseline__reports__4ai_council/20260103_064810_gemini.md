[액션 체크리스트: 긴급 점검 및 실험 계획]

### 1. 우선순위 TOP 5 (시스템 및 전략)

**[P0] 'MDD None' 및 메트릭 무결성 긴급 수정**
*   **(a) 이유:** `worst_mdd: None`은 치명적 오류. 하락폭을 모르는 상태의 Sharpe 3.32는 허상일 가능성 99%. 평가 지표 계산 로직이 깨졌거나, 자산 곡선(Equity Curve) 데이터가 비어있음.
*   **(b) 리스크:** 수정 후 실제 MDD가 -30% 이상으로 드러나 현재 챔피언이 즉시 폐기될 수 있음.
*   **(c) 실험 (Patch):**
    1.  `patch_metric_calc_safety`: MDD 계산 시 Division by Zero 및 NaN 처리 로직 강제 주입.
    2.  `audit_daily_returns`: 일별 수익률이 0 또는 결측치로 연속되는 구간 탐지 로그 추가.
*   **(d) PASS 조건:** `worst_mdd`가 유효한 음수(float)로 출력될 것.

**[P1] Degenerate Folds (1, 2, 3, 8) 해소: Solver 제약 완화**
*   **(a) 이유:** 전체 Fold의 40%가 실패(Degenerate)함. 이는 특정 기간(시장 충격기 등)에 Optimizer가 'Tech+Healthcare 8~14종목' 제약 조건을 만족하는 해를 찾지 못했음을 의미. 과적합된 '생존자 편향' 모델일 확률 높음.
*   **(b) 리스크:** 제약을 풀면 종목 수가 너무 적어지거나(집중 투자), 너무 많아져(ETF화) Alpha가 희석될 수 있음.
*   **(c) 실험:**
    1.  `relax_min_weights`: 최소 비중 제약을 0.0에서 더 낮추거나, 현금 비중 허용 범위 확대.
    2.  `fallback_equal_weight`: Solver 실패 시, 해당 유니버스 동일 비중(1/N)으로 강제 진입하는 로직 추가.
*   **(d) PASS 조건:** Degenerate Folds 개수가 0~1개로 감소. OOS Mean이 다소 하락하더라도 전체 Fold 생존 필수.

**[P2] Rebalance Log 파이프라인 복구**
*   **(a) 이유:** `Error loading... Expecting value: line 1 column 1` 오류 발생. 체결 내역(Transaction)이 없으면 슬리피지/수수료가 반영되지 않은 'Gross Return'만 보고 있는 것임. 실제 수익률은 훨씬 낮을 것.
*   **(b) 리스크:** 로깅 오버헤드 증가(미미함). 기존 백테스트 데이터와의 호환성 문제.
*   **(c) 실험:**
    1.  `fix_logger_format`: JSONL 쓰기 모드(append vs write) 및 인코딩 강제 지정.
    2.  `dry_run_cost_impact`: 강제로 건당 $1 + 10bps 비용을 매기고 백테스트 재구동.
*   **(d) PASS 조건:** `rebalance_pinpoint.py` 툴이 에러 없이 csv/jsonl을 로드하고 Turnover 수치를 출력.

**[P3] Volatility Targeting (변동성 역가중)**
*   **(a) 이유:** Tech/Healthcare는 Beta가 높음. OOS Mean이 높지만 Degenerate가 발생하는 것은 폭락장에서 Solver가 터지기 때문. 변동성 기반 사이즈 조절 필요.
*   **(b) 리스크:** 강세장에서 수익률 제한(Underperformance).
*   **(c) 실험:**
    1.  `vol_target_15`: 포트폴리오 변동성 목표 15% 설정, 초과 시 현금 비중 확대.
    2.  `atr_sizing_filter`: 개별 종목 ATR이 특정 임계치(예: 5%) 초과 시 유니버스 제외.
*   **(d) PASS 조건:** MDD가 -15% 이내로 제어되고, Degenerate Fold가 감소.

**[P4] Regime Filter (XLV/XLK/QQQ 활용)**
*   **(a) 이유:** 섹터 ETF(관측용)의 모멘텀이 꺾였을 때 개별 주식 매매를 멈춰야 함. 현재는 하락장에서도 강제로 8~14종목을 채우려다 망가지는 구조로 추정됨.
*   **(b) 리스크:** 휩소(Whipsaw)로 인한 잦은 진입/청산 손실.
*   **(c) 실험:**
    1.  `regime_ma200_filter`: QQQ가 200일선 아래면 전체 포지션 청산(Cash 100%).
    2.  `regime_adx_filter`: ADX > 40 (과열) 구간에서 비중 50% 축소.
*   **(d) PASS 조건:** OOS Min(최악의 경우) 방어율 개선.

### 2. 48시간 자동 루프 정의

**실험 A: Solver 안정성 확보 (Degenerate Fix)**
*   **(1) 실험 정의:** `constraint_relaxation_v1`
    *   목표 종목 수 8~14 -> "최소 4종목 이상"으로 하한선 완화.
    *   Solver Timeout 2배 연장.
*   **(2) 게이트:** `degenerate_folds == []` (빈 리스트)
*   **(3) 기대 관측치:** OOS Mean은 3.3 -> 2.5 수준으로 하락하더라도, MDD 값 생성 및 전 기간 생존.

**실험 B: 비용 현실화 (Cost Reality)**
*   **(1) 실험 정의:** `cost_inclusion_bps_15`
    *   매매당 15bps 비용 강제 적용 후 백테스트.
    *   Rebalance Log 정상 저장 확인.
*   **(2) 게이트:** `turnover_ann < 12.0` (월 1회 회전 수준 유지)
*   **(3) 기대 관측치:** 기존 대비 수익률 10~20% 하락 예상되나, 이것이 '진짜' 성능임.

**실험 C: 하락장 방어 (Regime Cut)**
*   **(1) 실험 정의:** `sector_trend_following`
    *   XLK(기술), XLV(헬스케어) ETF가 60일 이평선 하회 시 해당 섹터 종목 매수 금지.
*   **(2) 게이트:** `worst_mdd > -0.20`
*   **(3) 기대 관측치:** Degenerate Fold였던 구간(하락장 추정)에서 현금 보유로 손실 방어.

### 3. 성능 정체 시 원인 분해 (Debug Ideas)

성능이 움직이지 않거나 `0.0` 근처에서 맴돌 때 다음 트리거를 확인:

1.  **트리거 부재 (No Signal):**
    *   *현상:* 포트폴리오가 내내 현금(Cash)만 보유.
    *   *체크:* 진입 조건(Threshold)이 너무 높지 않은가? (예: RSI < 20 인데 Tech 대형주가 거기까지 안 내려옴)
2.  **노출 부족 (Under-exposure):**
    *   *현상:* `Exposure Max`가 0.2 미만.
    *   *체크:* 포지션 사이징 로직에서 `volatility_scalar` 등이 너무 작게 잡혀 있는가?
3.  **운영 비용 (Cost Drag):**
    *   *현상:* 승률은 55%인데 계좌는 우하향.
    *   *체크:* 잦은 리밸런싱으로 수수료가 Alpha를 초과. -> `rebalance_pinpoint` 정상화가 시급함.
4.  **레짐 불일치 (Regime Mismatch):**
    *   *현상:* 특정 연도(2022년 등)에만 폭망하고 나머지 해는 좋음.
    *   *체크:* 금리 인상기/인하기에 따른 팩터(Growth vs Value) 로테이션 로직 부재. -> ETF 지표(TNX 등)를 Feature에 추가 고려.
