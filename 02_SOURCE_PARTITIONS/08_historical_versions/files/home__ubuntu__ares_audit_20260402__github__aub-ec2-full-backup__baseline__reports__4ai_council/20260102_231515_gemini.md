[상황 분석 요약]
현재 `worst_mdd: None` 및 `degenerate_folds: [1, 2, 3, 8]` 상태는 시스템이 **'눈을 가리고 절반의 엔진이 꺼진 채 달리는 상태'**임. OOS Mean 3.32는 생존 편향(Survivorship Bias)일 가능성이 매우 높으므로 신뢰 불가. 로깅 시스템(JSON/CSV 파싱 오류) 붕괴로 사후 분석도 차단됨.

---

### 1. 향후 24~48시간 우선순위 TOP 5 (Imperative Checklist)

#### P1. [Risk Engine] MDD 계산 로직 복구 및 Degenerate Fold 원인 규명
*   **(a) Why:** `worst_mdd: None`은 리스크 관리 불가 상태를 의미. 4개 Fold(약 40~50% 데이터)가 학습/검증에 실패했으므로 현재 챔피언 모델은 '반쪽짜리'임.
*   **(b) Risk:** 코드가 수정되면 현재의 높은 OOS Mean(3.32)이 급락할 수 있음(거품 붕괴).
*   **(c) Experiments:**
    1.  `fix_mdd_calc`: NaN/Infinite 값 처리 로직을 추가하여 MDD 강제 계산.
    2.  `debug_degenerate`: Fold 1,2,3,8에서만 발생하는 에러(데이터 결측, 0으로 나누기 등) 로그 상세 출력.
    3.  `fill_data_gaps`: Ticker 데이터의 결측 구간(Null)을 전일 종가(Forward Fill)로 강제 보정.
*   **(d) PASS 조건:** `worst_mdd`가 실수(float)로 출력됨 AND `degenerate_folds` 개수가 0이 됨.

#### P2. [Telemetry] 거래 로그(Rebalance Log) 파서 표준화
*   **(a) Why:** `Expecting value: line 1 column 1` 에러로 인해 어떤 종목을 왜 샀는지 분석 불가. 포트폴리오 구성을 검증할 수 없음.
*   **(b) Risk:** 로깅 오버헤드로 백테스트 속도 저하 가능성(미미함).
*   **(c) Experiments:**
    1.  `format_unify`: 로그 형식을 JSONL(Line-delimited JSON)로 통일하고 헤더 의존성 제거.
    2.  `log_sanitizer`: 특수문자나 인코딩 오류를 필터링하는 전처리 스텝 추가.
*   **(d) PASS 조건:** `aub_rebalance_pinpoint.py` 스크립트가 에러 없이 보고서를 생성함.

#### P3. [Universe] Tech/Healthcare 집중형 유니버스 필터 적용
*   **(a) Why:** 미국주식 Tech+Healthcare 집중 요청에 맞춰, 불필요한 노이즈(금융, 에너지 등)를 제거하여 모델의 학습 효율을 높여야 함.
*   **(b) Risk:** 종목 풀이 좁아져 변동성이 커지고, 특정 섹터 악재에 취약해짐.
*   **(c) Experiments:**
    1.  `sector_filter`: GICS 기준 IT(XLK) 및 Healthcare(XLV) 구성 종목 중 시총 상위 50개로 풀 제한.
    2.  `top_pick_10`: 모델이 예측한 상위 20개 중 Tech/Bio 비중이 80% 이상이 되도록 강제 선택 로직 적용(Target 8~14개).
*   **(d) PASS 조건:** 포트폴리오 내 Tech+Healthcare 비중 > 80% 유지.

#### P4. [Cost Model] 현실적 비용 구조 반영 (Conservative Check)
*   **(a) Why:** OOS Mean 3.32는 비현실적. 슬리피지와 수수료가 반영되지 않았거나 과소평가되었을 가능성.
*   **(b) Risk:** 성과 지표가 대폭 하락하여 기존 전략 폐기 수순으로 갈 수 있음.
*   **(c) Experiments:**
    1.  `cost_stress_10bps`: 편도 수수료+슬리피지를 10bps(0.1%)로 설정.
    2.  `cost_stress_20bps`: 편도 수수료+슬리피지를 20bps(0.2%)로 설정.
    3.  `min_holding_period`: 최소 보유 기간을 3일로 설정하여 과도한 회전율 억제.
*   **(d) PASS 조건:** 20bps 비용 적용 후에도 OOS Sharpe Ratio > 1.0 유지.

#### P5. [Regime Filter] VIX/ETF 기반 변동성 제어 (Hedge Logic)
*   **(a) Why:** 현재 노출도(Exposure) Max 0.83이나 하한선이 0.0임. 시장 급락 시 방어 기제 필요. `hedge_025` 실험의 연장선.
*   **(b) Risk:** 상승장에서 헷지 비용으로 인해 수익률 저하(Underperformance).
*   **(c) Experiments:**
    1.  `dynamic_hedge_vix`: VIX > 25일 때 현금 비중 50% 강제.
    2.  `market_filter_ma`: SPY가 200일 이동평균선 아래일 때, Long 포지션 진입 금지(Cash 100%).
*   **(d) PASS 조건:** MDD가 벤치마크(SPY/QQQ) 대비 30% 이상 개선(감소).

### 2. 48시간 자동 루프 정의

**Loop A: 안정성 확보 (P1, P2)**
1.  **실험 정의:** 데이터 클리닝 + MDD 계산 모듈 핫픽스 배포.
2.  **게이트(Gate):** 모든 Fold 정상 완료 (Degenerate = 0).
3.  **기대 관측치:** OOS Mean이 3.32에서 현실적인 수치(예: 0.5~1.5)로 하락, MDD 수치 확보.

**Loop B: 섹터/비용 최적화 (P3, P4)**
1.  **실험 정의:** Tech/Bio 유니버스 한정 + 슬리피지 15bps 적용.
2.  **게이트(Gate):** Sector Exposure Check (Tech+Bio > 80%).
3.  **기대 관측치:** 승률(Win Rate)은 유지되나 회전율(Turnover) 감소 확인.

### 3. 성능 정체(Stagnation) 시 원인 분해 트리 (Debug Guide)

성능 지표가 움직이지 않을 때 다음 순서로 점검:

1.  **트리거(Trigger) 부재:**
    *   *현상:* 거래 횟수 0 또는 미미함.
    *   *액션:* 진입 임계값(Threshold)을 대폭 낮춰서(예: score > 0.5 -> score > 0.0) 신호가 발생하는지 확인.

2.  **노출(Exposure) 제한:**
    *   *현상:* 신호는 있는데 포지션 사이즈가 0.
    *   *액션:* `exposure_limit` 파라미터나 변동성 타겟팅(Volatility Targeting) 로직이 너무 보수적인지 확인.

3.  **비용(Cost) 잠식:**
    *   *현상:* Gross Return은 우상향이나 Net Return이 횡보/하락.
    *   *액션:* 일일 회전율 체크. 8~14개 종목을 매일 교체하면 비용으로 전멸함. Rebalancing 주기를 주간/월간으로 변경 실험.

4.  **레짐(Regime) 불일치:**
    *   *현상:* 특정 연도(Fold)에서만 박살남.
    *   *액션:* `hedge` 로직(XLK/XLV 인버스 등)이 상승장에서 발목을 잡거나, 하락장에서 작동 안 하는지 점검. ETF를 지표로만 쓰지 말고 Feature로 넣어 상관관계 확인.
