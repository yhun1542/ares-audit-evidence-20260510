1.  **[CRITICAL] Degenerate Folds (1,2,3,8) 원인 규명 및 제거**
    *   절반에 가까운 Fold가 비정상(Degenerate) 상태임. 현재 OOS Mean 3.32는 생존 편향(Survivorship Bias)이거나 특정 구간의 과적합일 확률이 매우 높음. 거래가 전혀 발생하지 않았거나(0 trades), 수익률이 NaN인 구간을 강제로 활성화해야 함.

2.  **[SYSTEM] Rebalance Log 파이프라인 복구**
    *   `Error loading ... Expecting value: line 1 column 1` 오류는 로깅 시스템 붕괴를 의미. 백테스트 상에서 어떤 종목을 샀는지(Tech/Bio 비중) 확인 불가능한 상태. JSONL 포맷 강제 및 Flush 주기 점검 필수.

3.  **[STRATEGY] Tech/Healthcare Sector Constraint 강화 및 검증**
    *   미국주식 Only, Tech+Healthcare 8~14 종목 제한 규칙이 실제로 작동하는지 확인. 현재 Exposure Max 0.83이나 Min 0.0인 점을 보아, 섹터 필터링 후 남는 종목이 없어 현금 보유(Cash hoarding)를 하는지 확인 필요.

4.  **[RISK] MDD 계산 로직 수정 (None 값 처리)**
    *   `worst_mdd: None`은 리스크 관리가 불가능함을 시사. 수익률이 평탄하거나 데이터 포인트 부족으로 계산되지 않는 상황. MDD 산출 기간(Window)을 강제 설정하여 수치 확보.

5.  **[COST] 미체결/슬리피지 비용 스트레스 테스트**
    *   OOS Min이 -0.02로 매우 방어적임. 실제 호가창에서의 슬리피지(Slippage)와 거래 수수료를 반영했을 때, 잦은 진입/청산이 있다면 수익률이 급락할 수 있음.

### 1. Degenerate Folds 긴급 패치 (Patch_Degeneracy_Fix)
*   **(a) 필요성:** Fold 1, 2, 3, 8이 망가진 상태에서 OOS Mean 값은 신뢰 불가. 모델이 특정 시장 국면(Regime)에서 작동을 멈춤.
*   **(b) 위험/부작용:** 거래 횟수를 강제로 늘리면 평균 수익률(Mean)이 하락할 수 있음.
*   **(c) 실험 제안 (48h Loop):**
    1.  **EXP_RELAX_ENTRY:** 진입 임계값(Threshold)을 현재의 70% 수준으로 하향 조정. (거래 강제 유발)
    2.  **EXP_MIN_HOLD:** 최소 보유 기간(Min Holding Period)을 1일에서 3일로 증가시켜 노이즈 필터링 완화.
    3.  **EXP_FILL_NAN:** 데이터 누락 구간에 대해 Forward Fill 대신 거래 금지(Zero Return) 처리 후 Fold 재계산.
*   **(d) PASS 조건:**
    *   `degenerate_folds` 리스트가 비어있을 것 ([]).
    *   모든 Fold의 거래 횟수 > 30회.

### 2. 로깅 시스템 정규화 (Patch_Log_Fix)
*   **(a) 필요성:** `aub_rebalance_pinpoint.py`가 파일을 읽지 못해 매매 내역 분석 불가. 블라인드 상태.
*   **(b) 위험/부작용:** 로깅 오버헤드로 인한 백테스트 속도 저하(미미함).
*   **(c) 실험 제안:**
    1.  **EXP_JSONL_STRICT:** 로그 저장 방식을 CSV에서 Strict JSONL로 변경하고, 매 Step마다 File Flush 강제.
    2.  **EXP_LOG_VALIDATOR:** 시뮬레이션 종료 직후 로그 파일의 무결성(JSON Parsing)을 체크하는 스크립트 실행.
*   **(d) PASS 조건:**
    *   `aub_rebalance_pinpoint.py` 실행 시 에러 없이 리포트 생성.
    *   로그 파일 용량이 0이 아닐 것.

### 3. 섹터 집중도 및 노출 제어 (Patch_Sector_Exposure)
*   **(a) 필요성:** Exposure Min 0.0은 자본 효율성 저하. Tech/Bio 종목 8~14개 유지를 위한 Pool 확보 필요.
*   **(b) 위험/부작용:** 강제 매수로 인한 하락장 손실 확대. 상관계수 1에 가까운 종목(예: NVDA, AMD 동시 보유) 과다 노출.
*   **(c) 실험 제안:**

    2.  **EXP_FORCE_EXPOSURE:** 시장(SPY) 이동평균선 위에 있을 때 최소 Exposure 0.3 강제.
*   **(d) PASS 조건:**

    *   Exposure 0.0인 구간이 전체 기간의 20% 미만일 것.

[성능 정체 시 원인 분해 (Decomposition Logic)]

성능이 움직이지 않거나(3.32에서 고착), 개선되지 않을 때 다음 트리를 따라 점검하라.

1.  **Trigger (신호 발생)**
    *   *문제:* 모델이 매수 신호를 보내지 않음. (Fold 1,2,3,8 문제와 연관)
    *   *확인:* Signal Strength 분포 확인. 0에 수렴하는지? Feature Scaling이 깨졌는지(NaN, Inf) 확인.

2.  **Execution (체결/적용)**
    *   *문제:* 신호는 있는데 현금 부족 or 리스크 한도 초과로 주문 거부.
    *   *확인:* `rebalance` 로그에서 "Order Rejected" 비율 확인. 현재 파일 로딩 에러로 확인 불가하므로 우선순위 #2 해결 선행 필수.

3.  **Exposure (노출)**
    *   *문제:* 8~14 종목을 담으라 했으나 1~2 종목만 담고 있음.
    *   *확인:* 일별 보유 종목 수(Count) 시계열 차트. 평균 보유 종목 수가 8 미만이면 분산 효과 없음.

4.  **Cost (비용)**
    *   *문제:* 수익이 비용으로 다 빠져나감.
    *   *확인:* Gross Return vs Net Return 괴리율. 턴오버(Turnover)가 연 500% 이상인지 확인.

5.  **Regime (시장 국면)**
    *   *문제:* 2022년 하락장 등 특정 구간에서만 손실/이익 집중.
    *   *확인:* 연도별(Yearly) Sharpe Ratio 분해. 특정 연도만 수익이 좋다면 과적합.
