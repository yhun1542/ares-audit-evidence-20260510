### 2) **누수/과최적화 차단(데이터-라벨-피처 시간정렬)**

**(a) 왜 필요한지**
- “No-Delta”는 종종 **누수로 만들어진 허상 성능**이 기준이 되어, 정상적인 개선이 묻히는 패턴에서 발생.

**(b) 위험/부작용**
- 누수 제거 후 OOS 급락 가능(정상적인 정화 과정).
- 데이터 소스가 PIT 미지원이면 피처 대량 폐기될 수 있음.

**(c) 최소 실험 2~3개 (※ 아래 E2 안에서 variant로 처리)**

- (E2-v2) 전 피처에 **최소 lag=1day** 강제(당일 종가/체결 기반 금지).
- (E2-v3) 재무/펀더멘털은 **발표일 기준 + 1영업일 이후**만 유효(lookahead 차단).

**(d) PASS 조건**

- “성능이 안 움직임”은 종종 **알파 개선분이 비용에 상쇄**되는 상황.

**(b) 위험/부작용**
- 비용 모델이 과보수면 전략이 과도하게 둔해져 알파를 놓칠 수 있음.

- (E3-v3) min-hold(예: 5거래일) 또는 리밸런스 주기(예: 주 2회) 비교.

## 48시간 자동 루프용 “실행 가능한 patch/실험” 4개로 고정 (3~5개 제한 준수)

### E1) Rebalance Trace + Metric Integrity Patch
1) **실험 정의**
- 리밸런스 로그(rebalance.csv/jsonl) 강제 생성 + worst_mdd 계산/유닛테스트 추가.
2) **게이트**
- 로그 파일 로딩 성공, schema validation 통과, 지표 재현성 통과.
3) **기대 관측치**
- pinpoint 리포트 생성 가능, MDD가 정상 수치로 출력, “원인 추적 가능성” 급상승.

### E2) Leakage Hardening (purge/embargo + lag + PIT)
1) **실험 정의**
- purge/embargo + 최소 lag + 펀더멘털 발표일 정렬 적용.
2) **게이트**
- 누수 플래그 0건, fold 안정성(분산/극단치) 악화 금지.
3) **기대 관측치**
- 단기 OOS mean이 내려갈 수 있으나, oos_min/분산 개선(=진짜 신호만 남는 패턴).

### E3) Cost-aware Turnover Clamp
1) **실험 정의**
- 비용모델을 PnL에 반영 + turnover cap/min-hold 비교.
2) **게이트**
- 비용 계산 NaN/Inf 0, 평균 turnover 상한 준수.
3) **기대 관측치**
- 총수익은 줄어도 “순수익(비용 차감 후)”의 일관성↑, 과최적화된 고회전 패턴 제거.

### E4) Regime Gating via Indicator ETFs (no trading)
1) **실험 정의**
- ETF는 지표로만 사용해 exposure 스케일링/킬스위치 적용.
2) **게이트**
- ETF 거래 0건(규칙 위반 0), 게이트 조건 충족 시 노출이 실제로 변함.
3) **기대 관측치**
- worst_mdd/oos_min 방어 개선, 레짐 변화 구간에서 손실 꼬리 감소.

## 성능이 “안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐) — 명령형 트리

### A) 트리거(신호 발생) 문제
- 신호 분포(평균/분산/희소도)가 최근 구간에서 붕괴했는지 확인(특징량 drift).
- 상위 피처의 상관/중요도가 fold마다 뒤집히는지 확인(과최적화 징후).
- 이벤트성(헬스케어) 날짜 정렬이 어긋나 신호가 “무력화”됐는지 확인(PIT/lag).

### B) 적용(신호→포지션 변환) 문제
- 신호가 있어도 포지션이 안 바뀌는지 점검(클램프/정규화/라운딩/최소 주문 단위).
- 리밸런스 스케줄/홀딩룰 때문에 신호가 “실행되지 못하는지” 확인(min-hold, turnover cap 상호작용).
- 종목 수(8~14) 제약으로 신호가 포트폴리오에 투영되지 않는지 확인(선택 단계에서 탈락).

### C) 노출(리스크) 문제
- 노출이 0.47~0.84 사이에서 사실상 고정되어 “스케일링 알파”가 없는지 확인.
- 단일 종목/섹터 쏠림으로 분산효과가 깨졌는지 확인(single-name cap 위반 여부).
- 베타(예: QQQ)에 대한 암묵적 노출이 커서 알파가 상쇄되는지 확인(지표 ETF로 베타 추정만).

### D) 비용(슬리피지/수수료/스프레드) 문제
- 총거래비용이 그로스 알파를 상쇄하는지(비용/총PnL 비율) 확인.
- 비용이 특정 종목(유동성 낮은 바이오)에 집중되는지 확인(ADV/스프레드별 비용 기여도).
- 체결 가정(종가/시가/중간가)이 비현실적으로 유리하게 되어 있지 않은지 역점검(누수 유사 효과).

### E) 레짐(시장 환경) 문제
- risk-on/off, 금리 급변, 변동성 급등 구간에서 성능이 구조적으로 꺾이는지 확인(ETF 지표 기반).
- Tech vs Healthcare 상대강도 레짐이 바뀌었는데 섹터 고정 비중 때문에 따라가지 못하는지 확인.
- 동일 레짐에서만 유효한 신호(조건부 알파)인지 확인 → E4 게이팅으로 분리.

## 실행 순서(48시간) — 우선순위 고정
1) **E1부터 즉시 수행**(로그/지표가 서야 나머지 실험이 의미가 생김).  
2) **E2 적용 후 성능 재평가**(누수 제거로 기준선 재설정).

4) **E4로 레짐 방어 추가**(oos_min/MDD 중심으로 개선 확인).

위 4개 실험만으로도, 현재 “No-Delta/리밸런스 로그 부재/MDD 미계산” 상태에서 **원인추적 가능하고 비용·누수·레짐이 분리된** 형태로 48시간 자동 루프를 안정화할 수 있다.
