[분석 요약]
현재 `tuning_min`(-1.349...)과 `lockbox_min`(-0.053...)이 Champion과 Candidate 간에 **정확히 일치**함. 이는 두 모델이 특정 폭락장(Tail Risk)에서 동일한 포트폴리오 구성을 가졌거나, 하드코딩된 손절 로직이 작동했음을 시사함. Candidate가 `worst_mdd`를 개선(-9.02% -> -8.24%)한 것은 긍정적이나, **동일한 하방 경직성**은 시스템적 리스크(상관관계 1.0)를 의미함. Tech+Healthcare 섹터 집중이 하락장에서 방어력을 제공하지 못하고 있음.

### 1. 우선순위 TOP 5 제안 (48시간 내 실행)

1.  **[Risk] 섹터 간 상관관계(Correlation) 기반 비중 캡(Cap) 적용**
    *   **이유:** Tech와 Healthcare가 동반 하락할 때 방어가 안 됨. 두 섹터 ETF(XLV, QQQ) 간 상관계수가 0.7 이상일 때 전체 노출도를 강제 축소해야 함.
    *   **위험:** 상승장에서 추세 추종 시그널을 조기 차단하여 수익률(Mean) 저하 가능성.

2.  **[Alpha] 변동성(VIX/ATR) 레짐에 따른 동적 룩백(Dynamic Lookback)**
    *   **이유:** `tuning_mean`이 Lockbox보다 낮음. 학습 구간의 변동성 변화에 적응하지 못하고 있음. 저변동성 구간에선 긴 룩백, 고변동성 구간에선 짧은 룩백이 필요.
    *   **위험:** 파라미터 과최적화(Overfitting) 위험 증가.

3.  **[Cost] 슬리피지 모델 가중치 2배 적용 스트레스 테스트**
    *   **이유:** Candidate의 개선된 MDD가 거래 빈도 증가로 인한 것인지 확인 필요. 실제 체결 오차를 반영하면 Candidate가 탈락할 수 있음.
    *   **위험:** 유의미한 전략이 비용 과대평가로 인해 기각될 수 있음.

4.  **[Universe] 유동성 하위 20% 종목 제거 및 교체**
    *   **이유:** 8~14개 종목 중 하위 유동성 종목이 `tuning_min`의 원인일 가능성. 대형주(Mega Cap) 위주로 압축하여 방어력 테스트.
    *   **위험:** 유니버스 축소로 인한 분산 효과 감소.

5.  **[Logic] 시장 지표(ETF) 하락 추세 시 Long-Only 진입 금지 (Regime Filter)**
    *   **이유:** 개별 종목 시그널이 살아있어도, SPY/QQQ가 200일선 아래라면 진입을 보류하는 거시적 필터 부재 의심.
    *   **위험:** V자 반등 구간에서 진입 시점 지연(Lag).

### 2. 실행 가능한 Patch/실험 (48시간 루프)

#### 실험 A: 상관관계 기반 노출 제어 (Correlation Constraint)
*   **정의:** 포트폴리오 내 종목 간 평균 상관계수가 0.6을 초과하면, 현금 비중을 최소 30% 강제 확보. (대상: Tech/Healthcare Top 10)
*   **게이트(Gate):**
    1.  `tuning_min`이 기존(-1.349)보다 개선되었는가? (수치 상승)
    2.  `worst_mdd`가 -8.0% 이내로 진입했는가?
*   **기대 관측치:** `tuning_mean` 소폭 하락(-0.05 이내), `worst_mdd` 대폭 개선.

#### 실험 B: 고변동성 구간 룩백 단축 (Regime Adaptive Window)
*   **정의:** VIX > 20 (또는 ATR 상위 20%) 구간에서 모멘텀/평균회귀 지표의 룩백 기간을 절반(0.5x)으로 단축.
*   **게이트(Gate):**
    1.  `lockbox_mean`이 1.34 이상으로 유지되는가?
    2.  거래 횟수(Turnover)가 20% 이상 폭증하지 않는가?
*   **기대 관측치:** 급락장에서 빠른 청산으로 손실 방어, 횡보장에서 휩소(Whipsaw) 일부 증가.

#### 실험 C: 비용 가중치 2x & 유동성 필터 강화 (Reality Check)
*   **정의:** 시뮬레이션 상 거래 비용(bps)을 2배로 설정하고, 일평균 거래대금 하위 2개 종목을 유니버스에서 영구 제외.
*   **게이트(Gate):**
    1.  Candidate 전략이 여전히 Champion보다 우위에 있는가?
    2.  `fold14_mdd`가 악화되지 않는가?
*   **기대 관측치:** `tuning_mean` 하락 예상. 만약 수익이 급감하면 현재 전략은 '비용 과소평가' 상태임.

### 3. 성능 정체 시 원인 분해 (Diagnosis Tree)

성능 지표(Mean/MDD)가 48시간 동안 유의미하게 변하지 않을 경우, 다음 순서로 점검 및 수정.

1.  **트리거(Trigger) 불감증:**
    *   *현상:* 매매 신호 자체가 거의 발생하지 않음.
    *   *조치:* 진입 임계값(Threshold)을 20% 낮추고(완화), 노이즈 필터를 제거.
2.  **포트폴리오 최적화기(Optimizer) 무시:**
    *   *현상:* 신호는 발생하나 실제 비중(Weight)이 0에 수렴.
    *   *조치:* 최소 비중 제약(Minimum Weight Constraint)을 0.05(5%)로 강제 설정하거나, 리스크 허용치(Risk Budget)를 일시적으로 2배 확대.
3.  **레짐(Regime) 불일치:**
    *   *현상:* 전략은 평균회귀(Reversion)를 기대하나 시장은 추세(Trend) 중임.
    *   *조치:* Tech/Healthcare 섹터 ETF의 추세 강도(ADX)를 확인. ADX > 25일 때 추세 추종 로직만 활성화하도록 스위칭.
4.  **손익 상쇄(PnL Wash):**
    *   *현상:* 승률은 높으나 손익비(Reward/Risk)가 낮음 (짧게 먹고 크게 터짐).
    *   *조치:* 익절(Take Profit) 로직을 제거하고, 트레일링 스탑(Trailing Stop)만 남겨서 이익을 길게 가져가는지 테스트.

**즉시 실행:** `experiment_system/tools/aub_autopilot.py` 실행 시 위 실험 A(Correlation Constraint)를 우선 적용할 것.
