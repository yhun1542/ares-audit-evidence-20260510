아래는 **24~48시간 내 우선순위 TOP5**를 “명령형 체크리스트”로 정리한 것입니다.  
단, **실행 실험/patch는 총 5개(E1~E5)만** 정의하고, 각 제안은 그중 **2~3개를 조합**해 돌리도록 구성했습니다(케이스 폭발 방지, 48시간 자동 루프 적합).

---

## 0) 즉시 관측된 레드플래그(먼저 막아야 OOS가 움직임)
- **degenerate_folds = [1,2,3,8]** → CV/워크포워드가 무너져 “OOS 평균”이 의미 없을 수 있음(누수/표본부족/거래없음).
- **worst_mdd: None** → 리스크 계산/로그 누락(운영 리스크 + 게이트 불가).
- **lane_hash/run_hash: None** → 재현성/추적 불가(실험 반복해도 “왜 안 움직였는지” 모름).
- **Rebalance pinpoint 실패**(경로/JSON 파싱) → 전략이 실제로 “언제/무엇을 샀는지” 단서가 끊김(서바이버십/비용/노출 문제 분해 불가).

# 1) TOP5 우선순위 제안(코드/아키텍처/전략)

## P1. 실험 재현성/리스크/리밸런스 로그를 “강제 수집”으로 고정(운영 리스크 최우선)
### (a) 왜 필요한지
- 현재는 **MDD/리밸런스/런 식별자**가 비어 있어, 성능이 안 움직일 때 **원인 분해가 물리적으로 불가능**합니다.
- 48시간 자동 루프에서는 “결과가 나왔는데 설명이 안 됨”이 가장 큰 장애입니다.

### (b) 위험/부작용
- fail-fast 도입 시 **초기에는 런이 자주 실패**(하지만 그게 정상: 조용히 잘못된 결과를 생산하는 것보다 낫습니다).
- 로그/아티팩트 저장으로 **스토리지 비용 증가**.

### (c) 최소 실험(아래 E1~E5 중에서 조합)
- **E1(로깅/메타 강제 + 리밸런스 출력 표준화)**  
- **E2(CV degenerate fold 차단 게이트)**

### (d) PASS 조건
- 모든 런에서 **run_hash/lane_hash 존재**, **worst_mdd 산출**, **rebalance.jsonl(or csv) 생성**.
- degenerate_folds가 **빈 배열**이거나, 최소 기준 미달이면 **OOS 리포트 생성 전에 런 실패 처리**.

---

## P2. 누수/과최적화 방지: Purged Walk-Forward + embargo + “거래 0인 fold” 금지
### (a) 왜 필요한지
- degenerate_folds는 보통 (1) 시계열 분할 오류 (2) 레이블/피처 누수 (3) 해당 fold에서 거래가 0이어서 성과가 계산 불능… 중 하나입니다.  
- 이 상태에서 OOS 평균이 올라가도 **거의 확률적으로 과최적화/우연**입니다.

### (b) 위험/부작용
- 누수 제거 후 **OOS 평균이 단기적으로 하락**할 수 있음(실제 실력 드러나는 과정).
- embargo/purge 적용 시 **학습 데이터 감소 → 분산 증가**.

### (c) 최소 실험
- **E2(CV/누수 차단 패치)**  
- **E5(레짐 게이트로 “학습-검증 분포 괴리” 완화)**

### (d) PASS 조건
- 각 fold에서:
  - 최소 거래 수/리밸런스 이벤트 수 충족(예: fold당 N회 이상)  
  - **train/test 기간 겹침 0**, embargo 적용 확인  
- OOS에서 “평균만”이 아니라 **oos_min 개선** 또는 **하방 꼬리(5% 분위) 악화가 줄어듦**.

---

## P3. 서바이버십/유니버스 고정: 미국주식 Tech+Healthcare 8~14개를 “시점 기준”으로 선택
### (a) 왜 필요한지
- 서바이버십(현재 생존 종목만 사용), 미래 정보(지수 편입/시총 랭크) 혼입은 **가장 흔한 유령 알파**입니다.
- “미국주식 only, Tech+Healthcare, 8~14개” 제약을 코드로 고정하지 않으면 실험마다 우주(universe)가 흔들려 결과가 안 움직일 수 있습니다.

### (b) 위험/부작용
- 유니버스 축소로 **분산효과 감소**, 특정 종목 리스크 증가.
- 데이터 품질(분할/병합/상장폐지) 처리 미흡 시 결측이 늘어 런 실패 가능.

### (c) 최소 실험
- **E3(포인트-인-타임 유니버스/서바이버십 방지 패치)**  
- **E1(리밸런스 로그에 “선정 유니버스/선정 사유/시점” 기록)**

### (d) PASS 조건
- 매 리밸런스 시점에 “선정 가능한 종목 집합”이 **미리 정의된 규칙으로 재현**됨.
- 유니버스가 8~14개를 만족하고, Tech/Healthcare 비중 규칙(예: 둘 중 하나 최소 30%)이 유지됨.
- delist/거래정지 발생 시 **자동 대체/현금화 로직이 로그로 확인**됨.

> 실행 시 기본 후보(예시, 실제 거래는 모델이 선택):  
> Tech: AAPL, MSFT, NVDA, GOOGL, AMZN, META, AVGO  
> Healthcare: LLY, UNH, JNJ, ABBV, MRK, TMO  
> (총 8~14 내에서 시점 기준 필터로 선택/유지)

## P4. 비용/슬리피지/회전율을 성능에 “실제 반영” + 리밸런스 과다를 제어
### (a) 왜 필요한지
- 비용 미반영은 OOS가 “안 움직이거나” “좋아 보이는데 실전에서 붕괴”하는 대표 원인입니다.
- 특히 8~14 종목 집중 포트는 회전율이 높으면 비용 영향이 매우 큼.

### (b) 위험/부작용
- 비용을 넣으면 OOS 평균이 하락할 수 있음(하지만 실전에 가까워짐).
- 회전율 제한/최소 보유기간은 **급변 대응이 느려짐**.

### (c) 최소 실험
- **E4(거래비용/슬리피지/턴오버 페널티 + 최소 보유기간)**  
- **E1(거래별 비용 구성요소를 로그로 출력)**

### (d) PASS 조건
- gross → net 차이가 설명 가능(로그로 분해됨):  
  - spread/slippage/commission/borrow(쇼트 시) 항목이 0이 아님  
- net OOS에서 **oos_min이 덜 나빠지거나**, 동일 oos_mean에서 **turnover 감소**.

---

## P5. 노출/레짐/게이트: ETF는 “관측지표”로만 쓰고, 익스포저 자동 제어
### (a) 왜 필요한지
- 현재 exposure max가 ~0.84인데, 성능이 안 움직일 때는 보통:
  - 게이트가 너무 빡세서 **노출이 안 나감(0 근처로 붙음)** 또는
  - 레짐 불일치로 **좋은 신호도 나쁜 시장에서 강제 집행**되는 경우입니다.
- ETF는 거래 금지 조건이므로 **XLK/XLV/QQQ/IWM, VIX 등은 레짐 지표로만 사용**해 익스포저를 조절합니다.

### (b) 위험/부작용
- 레짐 게이트가 과하면 “기회 상실”로 수익이 줄 수 있음.
- 게이트 설계가 잘못되면 **항상 꺼져있거나 항상 켜져있는** 무용지물이 됨.

### (c) 최소 실험
- **E5(레짐/익스포저 게이트 + 관측 ETF 팩터 로그)**  
- **E2(게이트 때문에 fold가 degenerate 되는지 동시 점검)**

### (d) PASS 조건
- OOS 기간에 노출(exposure) 분포가 극단(항상 0 또는 항상 max)에 붙지 않음.
- 레짐 지표 변화(예: QQQ 추세↓, VIX↑) 시 노출이 예측가능하게 감소하고, 그로 인해 **좌측 꼬리(oos_min) 개선**이 관측됨.

# 2) 48시간 자동 루프용 “실행 실험/patch” 5개 (E1~E5)
아래 5개만 돌리면 됩니다. 각 실험은 **(1) 실험 정의 → (2) 게이트 → (3) 기대 관측치**로 고정합니다.

---

## E1. 아티팩트/메타/리밸런스 표준 로그 강제(운영/추적 패치)
1) **실험 정의**
- 모든 런에 대해:
  - `run_hash`, `lane_hash`, git commit, 데이터 스냅샷 해시 기록
  - `worst_mdd`, turnover, trade_count, rebalance_count 계산/저장
  - `rebalance.jsonl`(각 리밸런스 시점의 universe, target weights, fills 가정, 비용항목) 생성
- 파일 로딩 실패 시 fallback 탐색 금지, **명시적 실패**로 전환

2) **게이트**
- 위 필드/파일 하나라도 누락 시 런 FAIL (리포트 생성 금지)

3) **기대 관측치**
- “성능이 안 움직임”이 발생해도 **언제/무엇을/왜**가 리밸런스 단위로 추적 가능

---

## E2. Purged walk-forward + embargo + degenerate fold 차단(누수/과최적화 패치)
1) **실험 정의**
- 시계열 분할을 “Purged Walk-Forward”로 통일
- 레이블/피처에 lag 강제(예: t 신호는 t-1 데이터까지만)
- fold별 최소 거래수/최소 리밸런스 이벤트 수 미달 시 fold 무효 → 런 FAIL

2) **게이트**
- `degenerate_folds != []` 이면 런 FAIL
- train/test overlap 또는 embargo 미적용 감지 시 런 FAIL

3) **기대 관측치**
- OOS mean이 일시 하락해도, **oos_min/분산/일관성** 지표가 “정상 형태”로 회복

---

## E3. 포인트-인-타임 유니버스 + 서바이버십 방지(유니버스 패치)
1) **실험 정의**
- 미국주식만, 섹터 Tech/Healthcare만
- 리밸런스 시점 기준으로 **선정 가능 종목 집합을 고정 규칙**으로 생성(미래 정보 금지)
- 8~14개 유지(부족 시 현금 또는 사전 정의된 대체 규칙)

2) **게이트**
- 유니버스 크기 8~14 위반 시 런 FAIL
- 섹터 제약 위반 시 런 FAIL
- delist/결측 발생 시 처리 로직이 로그에 없으면 런 FAIL

3) **기대 관측치**
- 실험 간 유니버스 변동이 줄고, 성능 변동이 “신호/게이트” 영향으로 수렴(원인 분해 가능)

---

## E4. 비용/슬리피지/턴오버 제약(비용 미반영 패치)
1) **실험 정의**
- 최소 구성:
  - slippage = k * (spread 또는 ATR 기반) + 고정 bps
  - turnover penalty 또는 최소 보유기간(예: 2~5일) 적용
  - 쇼트가 있다면 borrow/리베이트 단순 모델 포함(없으면 쇼트 금지로 고정)

2) **게이트**
- gross-net 차이가 0에 가깝거나(비용 미적용 의심) 비정상적으로 크면(모델 폭주) 런 FAIL
- turnover 상한(예: 일간 30% 등) 초과 시 런 FAIL

3) **기대 관측치**
- net 성능이 gross 대비 현실적으로 감소
- 회전율이 억제되며 oos_min이 개선되거나, 동일 mean에서 변동성이 감소

---

## E5. 레짐/익스포저 게이트 + ETF 관측지표(노출/레짐 패치)
1) **실험 정의**
- ETF는 매매 금지, 관측만:
  - XLK/XLV 상대강도, QQQ 추세(예: 20/60MA), IWM 위험선호, VIX 수준/변화
- 신호가 켜져도 레짐이 위험이면 익스포저를 0~cap 사이로 축소(연속 스케일링)
- 섹터/종목 집중 제한(8~14개 내에서 단일 종목 cap)

2) **게이트**
- OOS에서 노출이 “항상 0” 또는 “항상 cap”에 붙으면 FAIL(게이트 무용)
- 레짐 지표가 변해도 노출이 반응하지 않으면 FAIL

3) **기대 관측치**
- 리스크 오프 구간에서 손실 꼬리 감소(oos_min 개선)
- 성능이 안 움직이는 경우에도 “게이트가 막았는지/신호가 없었는지”가 로그로 분리

---

# 3) 성능이 안 움직일 때 “원인 분해” 트리(트리거/적용/노출/비용/레짐)
아래를 **질문 없이 그대로 점검 순서로 실행**하세요(로그가 E1로 확보되어 있다는 전제).

## A. Trigger(신호가 발생했나?)
- 신호 발생률(일별/리밸런스별)과 임계값 통과 횟수를 출력하라.
- 신호가 0에 수렴하면:
  - 스케일링/정규화가 깨졌는지(상수열/NaN) 확인하라.
  - 피처 lag가 과도해서 신호가 늦는지 확인하라.

## B. Apply(신호가 포트폴리오로 “적용”됐나?)
- 리밸런스마다 target weights가 생성됐는지 확인하라.
- target weights는 있는데 fill이 0이면:
  - 게이트/제약(섹터/종목 cap, 최소 주문단위)이 막았는지 확인하라.
  - 데이터 결측으로 주문이 스킵됐는지 확인하라.

## C. Exposure(노출이 실제로 나갔나?)
- 일별 gross/net exposure, 상위 3종목 비중, 현금비중을 플롯/로그로 남겨라.
- 노출이 0 근처면:
  - 레짐 게이트(E5)가 상시 OFF인지 확인하라.
  - 거래비용(E4)이 과도하여 최적화가 “아무것도 안 함” 해로 수렴했는지 확인하라.
- 노출이 cap에 고정이면:
  - 리스크 타겟(변동성 타겟, MDD guard)이 비활성인지 확인하라.

## D. Cost(비용이 수익을 먹었나?)
- gross PnL vs cost breakdown(슬리피지/스프레드/커미션/borrow)을 리밸런스 단위로 합산하라.
- “성능이 안 움직임”이 **gross는 움직이는데 net이 죽는** 패턴이면:
  - 회전율을 낮추는 쪽(E4)으로 고정하라.

## E. Regime(레짐 불일치로 죽었나?)
- 레짐 지표(관측 ETF, VIX)와 성과를 같은 타임라인에 겹쳐라.
- 특정 레짐에서만 죽으면:
  - 레짐별 성과 분해(리스크온/오프) 후, E5에서 노출 스케일링을 강화하라.
- 모든 레짐에서 동일하면:
  - 신호 자체가 약하거나(알파 소실), 누수 제거로 사라진 것(E2)일 가능성이 큼 → 신호 재설계가 아니라 **데이터/적용/비용을 먼저 정상화**하라.

# 4) 24~48시간 실행 순서(우선순위대로)
1) **E1을 먼저 머지/적용**하고, 모든 런이 FAIL 없이 아티팩트를 남기는지 확인하라.  
2) **E2 적용 후 degenerate_folds를 0으로 만들라**(이게 안 되면 성능 논의 중단).  
3) **E3로 유니버스/서바이버십을 고정**하고 실험 간 변동 원인을 줄이라.  
4) **E4로 net 기준을 고정**해 “움직이는 성과”가 실제 가능한지 확인하라.  
5) **E5로 레짐/노출을 제어**해 oos_min(하방)을 먼저 개선하라.

이 순서를 지키면 “OOS mean이 안 오른다”를 **원인별로 분리 가능한 상태**로 만들고, 48시간 자동 루프에서 다음 액션이 막히지 않습니다.
