아래는 **24~48시간 자동 루프(실험 정의→게이트→기대 관측치)** 기준으로, 현재 ONE TRUTH에서 바로 드러난 **누수/과최적화/서바이버십/비용 미반영/운영 리스크**를 우선순위로 먼저 막는 **TOP5(코드/아키텍처/전략)** 제안이다.  
단, “케이스 폭발 방지”를 위해 **실행 실험은 총 5개(E1~E5)**로 제한하고, 각 제안에는 **이 5개 중 2~3개를 매핑**한다.

## 0) 즉시 경보(현재 로그가 말해주는 것) — 먼저 막기
- **degenerate_folds: [1,2,3,8]** → OOS 통계가 “의미 없는 폴드”를 포함했을 가능성. 과최적화/데이터 누수/분할 오류 우선 의심.
- **worst_mdd: None** → 리스크 계산이 누락되었거나 파이프라인이 중간에 깨짐(운영 리스크).
- **lane_hash/run_hash: None** → 재현성/추적성 부재(운영 리스크).
- **Rebalance pinpoint가 파일 파싱 실패** → 리밸런스 로그 포맷/경로가 깨져 “성능이 안 움직이는 이유”를 관측 불가.

# TOP5 우선순위 제안 (각 항목별 a~d)

## 1) (아키텍처) “평가 파이프라인”을 정상화: 폴드 퇴화/리밸런스 로그/재현성부터 고치기
### (a) 왜 필요한지
- degenerate_folds가 존재하면 OOS mean이 좋아 보여도 **검증이 무의미**해질 수 있음(과최적화/누수).
- 리밸런스 로그가 없으면 **‘No-Delta(성능 미변화)’ 원인**(트리거 미발동 vs 게이트 과도 vs 노출 0 vs 비용)에 접근 불가.
- run_hash/lane_hash가 없으면 **같은 실험을 다시 돌려도 다른 결과**가 나올 수 있음(운영 리스크).

### (b) 위험/부작용
- 평가를 엄격히 하면 **단기적으로 성능이 떨어져 보일 수 있음**(진짜 성능으로 수렴).
- 로그를 많이 남기면 **I/O 비용 증가** 및 스토리지 증가.

### (c) 최소 실험(2~3개) — 아래 E1/E4/E5 사용
- E1 (폴드/워크포워드 수리)
- E4 (리밸런스 로그+run_hash 강제)
- E5 (No-Delta 원인 분해 메트릭 추가)

### (d) PASS 조건
- degenerate_folds가 **0**이 되거나, 최소 **전체 폴드의 5% 미만**으로 감소.
- rebalance.jsonl(or csv) 생성 성공 + pinpoint 도구가 **에러 없이 리포트 생성**.
- worst_mdd가 None이 아니라 **항상 계산**됨.

## 2) (전략/리스크) 비용(수수료+슬리피지+충격비용) 반영 후에도 생존하는지 먼저 확인
### (a) 왜 필요한지

### (b) 위험/부작용
- 비용을 넣으면 “챔피언이 붕괴”할 수 있음(하지만 그게 정상).

### (c) 최소 실험(2~3개) — 아래 E2/E3/E5 사용
- E2 (비용 모델 ON + 보수적 슬리피지)
- E3 (턴오버/거래금지 게이트 추가)
- E5 (비용 기여도/턴오버 분해 관측)

### (d) PASS 조건
- **Cost-adjusted OOS mean**이 챔피언 대비 **-10% 이내**를 유지하거나,  
  OOS min(최악 구간)이 **악화되지 않음**(예: -0.0257 이하로 더 내려가지 않기).
- 턴오버 상한(예: 2일 누적 turnover) 위반 비율이 **5% 미만**.

### (b) 위험/부작용

- E3 (종목 수/섹터/ETF-거래금지 하드 제약)
- E4 (제약 위반 시 즉시 실패로 로깅)
- E5 (노출/종목수/섹터편중 타임시리즈 관측)

### (d) PASS 조건

- ETF는 **0 거래**(지표로만 사용 로그 확인).

## 5) (코드/실험관리) “No-Delta(성능이 안 움직임)”를 자동으로 원인 분해하는 계측 추가
### (a) 왜 필요한지
- 이미 “No-Delta Diagnoser”가 돌고 있는데, 리밸런스 로그 부재/에러로 핵심 원인이 가려질 수 있음.
- 48시간 자동 루프에서 제일 중요한 건 “실패의 종류를 자동 분류”해서 다음 실험이 헛돌지 않게 하는 것.

### (b) 위험/부작용
- 계측이 과하면 로그 폭증.
- 원인 분해 지표가 잘못 정의되면 잘못된 방향으로 최적화될 수 있음(그래서 게이트를 “성능”이 아니라 “관측 가능성”에도 둠).

### (c) 최소 실험(2~3개) — 아래 E4/E5/E1 사용
- E4 (리밸런스/트리거/게이트 이벤트 로그 표준화)
- E5 (No-Delta 분해 리포트 자동 생성)
- E1 (폴드 정상화 후에도 No-Delta면 진짜 전략 문제로 확정)

### (d) PASS 조건
- 모든 런에서 “No-Delta 분류”가 1개 이상 생성:  
  **Trigger 미발동 / Gate 과도 / Exposure 0 / Cost 지배 / Regime OFF 과다 / Universe 축소** 중 하나로 귀속.
- “rebalance_pinpoint”가 base/cand 모두에서 **파싱 성공**.

# 실행 가능한 Patch/실험 (총 5개만 실행) — 48시간 루프 형태

## E1) Walk-forward 폴드/샘플링 수리 (degenerate fold 제거)
- (1) 실험 정의
  - 폴드 생성 로직에 **최소 표본수/최소 거래일/최소 리밸런스 횟수** 제약을 넣고, 미달 폴드는 **평가에서 제외 + 원인 로그**.
  - 시계열 분할을 **순방향(Anchored/Expanding) walk-forward**로 고정(랜덤 섞기 금지).
- (2) 게이트
  - degenerate_folds > 0이면 **런 FAIL**(또는 점수 0)로 처리해 챔피언 승격 차단.
- (3) 기대 관측치
  - OOS mean이 단기 하락하더라도 **fold별 분산이 감소**하고, oos_min/리스크 지표가 일관되게 산출.

## E2) 비용 모델 ON (수수료+슬리피지+충격비용의 보수적 하한)
- (1) 실험 정의
  - 거래 비용을 최소 3단으로 반영:  
    - 고정 수수료(또는 bps)  
    - 슬리피지(bps, 유동성 기반 하한)  
    - 충격비용(거래대금/ADV 비례 간단 모델)
- (2) 게이트
  - 비용 ON에서 turnover 상위 10% 구간의 PnL이 **음수로 붕괴**하면 FAIL(거래 과다 전략 차단).
- (3) 기대 관측치
  - 총수익↓, 대신 **전략 간 우열이 “현실적”으로 재정렬**되고, No-Delta가 “비용 지배형”으로 분류되면 다음 액션이 명확해짐.

## E3) 제약 하드코딩: 8~14종목 + Tech/Healthcare + ETF 매매 금지 + 턴오버 상한
- (1) 실험 정의
  - 포트 생성 단계에서 다음을 강제:
    - holdings_count ∈ [8,14]
    - 섹터 필터: Tech/Healthcare만
    - ETF 티커는 **거래 리스트에서 제거**(지표만 허용)
    - turnover 상한(예: 1회 리밸런스 35% 또는 2일 누적 60%) 초과 시 리밸런스 축소(부분 실행) 또는 스킵
- (2) 게이트
  - 제약 위반 1회라도 발생 시 런 FAIL(운영 불가능 전략 차단).
- (3) 기대 관측치
  - exposure가 0으로 꺼지는지/과도 집중이 줄어드는지 즉시 확인 가능.
  - “게이트 과도 → No-Delta” 여부가 E5에서 드러남.

## E4) 리밸런스 로그 표준화 + run_hash/lane_hash 강제 + pinpoint 입력 파일 생성
- (1) 실험 정의
  - 매 리밸런스 이벤트를 JSONL로 기록:
    - timestamp, universe_size, target_weights, executed_trades, turnover, 비용, 제약 위반 여부, 게이트 사유, 노출
  - run_hash = (코드커밋, 데이터버전, 설정 해시)로 고정.
  - aub_rebalance_pinpoint 입력 포맷을 “항상 존재”하게 생성(경로 포함).
- (2) 게이트
  - rebalance.jsonl 미생성/파싱 실패 시 런 FAIL.
- (3) 기대 관측치
  - “No rebalance data found” 유형의 블라인드 제거.
  - 챔피언 교체 시 “왜 이겼는지”를 리밸런스 단위로 재현 가능.

## E5) No-Delta 원인 분해 리포트 자동 생성(트리거/적용/노출/비용/레짐)
- (1) 실험 정의
  - 매 런 종료 시 아래를 자동 산출(표/타임시리즈):
    - Trigger firing rate(신호 발생률)
    - Gate hit rate(게이트로 스킵된 비율) + 사유 top-k
    - Exposure distribution(0 근처 체류시간)
    - Turnover, 비용, 비용/총수익 비율
    - Regime indicator 상태(예: QQQ 20/60d 모멘텀, XLV 상대강도 등 “지표만”)
- (2) 게이트
  - 원인 분해 항목 중 1개라도 NaN/None이면 런 FAIL(관측 불능 방지).
- (3) 기대 관측치
  - 성능이 안 움직일 때, 다음 중 하나로 자동 귀속:
    - **Trigger 미발동형**(신호가 거의 0)
    - **Gate 과도형**(제약/레짐 게이트로 실행 0)
    - **Exposure 붕괴형**(노출이 장기간 0)
    - **Cost 지배형**(Gross는 괜찮은데 Net이 붕괴)
    - **Regime 미스매치형**(특정 레짐에서만 붕괴)

# 성능이 “안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐) — 트리 형태 체크리스트

## A. 트리거(신호 생성) 단계
- 신호 분포가 0 근처로 수렴하는지 확인하라(표준편차/상위-하위 스프레드).
- 리밸런스 빈도 대비 신호 갱신이 너무 느린지 확인하라(동일 값 반복 비율).
- (누수 점검) 미래 데이터 참조 가능성이 있는 피처를 전부 “t-1 시점 컷”으로 고정하라.

## B. 적용(게이트/제약) 단계
- 제약 위반으로 “자동 스킵”이 누적되는지 확인하라(게이트 hit rate).
- 8~14 종목 제약 때문에 최적해가 자주 불능이 되는지 확인하라(해결 실패/대체 로직 발동 횟수).
- ETF 매매 금지 필터가 의도치 않게 유니버스를 과도 축소하는지 확인하라(남는 종목 수).

## C. 노출(포지션) 단계
- 노출 0 체류시간을 측정하라(시간의 %).
- exposure_max는 높지만 평균이 낮다면 “게이트/트리거 불일치” 가능성이 크다.
- 종목 수는 맞는데 특정 1~2종목에 과집중되는지(HHI/최대비중) 확인하라.

## D. 비용 단계
- Gross PnL과 Net PnL의 차이를 항상 분리해 기록하라.
- turnover가 같아도 ADV 대비 거래비중이 커지면 충격비용이 튄다 → 거래대금/ADV 비율을 관측하라.
- 비용을 넣은 순간 성능이 평평해지면 “엣지가 비용보다 작다”가 결론이다(전략 신호 개선 또는 거래 감소가 다음 패치).

## E. 레짐 단계(ETF는 지표로만)
- QQQ(성장) vs XLV(헬스케어) 상대강도, QQQ 모멘텀, 금리 민감(IEF 등)을 **상태변수**로만 쓰고,
- 상태별(레짐별)로 성과를 분해하라:
  - 레짐 A에서만 이기고 B에서만 지는지
  - 레짐 게이트가 “너무 늦게/너무 자주” 켜지는지

## 24~48시간 실행 순서(명령형 체크리스트)
1) **E4 먼저 적용**해서 rebalance 로그/해시/핀포인트 입력을 무조건 만들라.  
2) **E1 적용**해서 degenerate_folds를 0으로 만들고 평가를 정상화하라.  
3) **E2 적용**해서 비용 반영 Net 성능이 생존하는지 확인하라.  
4) **E3 적용**해서 운영 제약(8~14, 섹터, ETF 금지, 턴오버 상한)을 하드로 고정하라.  
5) **E5 적용**해서 No-Delta를 자동 분류하고, 다음 루프에서 “한 가지 원인만” 제거하는 방향으로 이어가라.

이 5개를 돌리면, 지금 상태에서 가장 큰 블라인드(폴드 퇴화/리밸런스 미관측/비용 미반영/제약 미강제)를 48시간 내에 제거하면서 “성능이 왜 안 움직이는지”가 자동으로 갈라진다.
