### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### P1. 데이터 파이프라인 무결성 복구
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한가**
- 핸드오프 OOS(3.32) ≠ 진단기 OOS(2.63) → **26% 괴리**
- Rebalance CSV 파싱 실패 → 비용 반영 여부 불명
- 이 상태에서 실험해도 **신뢰 불가**

**(b) 위험/부작용**
- 파이프 수정 시 과거 결과와 비교 불가 (버전 단절)
- 수정 중 48시간 사이클 지연

**(c) 최소 실험**

```
┌─────────────────────────────────────────────────────────────────┐
│ EXP-1A: OOS 계산 경로 일치 검증                                   │
├─────────────────────────────────────────────────────────────────┤
│ 정의: champion_v5를 두 경로(handoff/diagnoser)로 동시 계산        │
│ 게이트: |OOS_handoff - OOS_diag| < 0.01                          │
│ 기대치: 괴리 원인 식별 (fold 선택? 날짜 범위? 수수료?)              │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│ EXP-1B: Rebalance 로더 복구                                      │
├─────────────────────────────────────────────────────────────────┤
│ 정의: CSV/JSONL 파서 에러 핸들링 + 스키마 검증 추가               │
│ 게이트: 파일 로드 성공률 100%, 파싱 row ≥ 1000                    │
│ 기대치: 슬리피지/수수료 컬럼 존재 확인                            │
└─────────────────────────────────────────────────────────────────┘
```

**(d) PASS 조건**
```
□ OOS 괴리 < 1% 
□ Rebalance 파일 정상 로드
□ MDD 계산 파이프 활성화 (None → 숫자)
```

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### P2. Degenerate Fold 원인 분해 및 제거
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한가**
- 4/10 fold가 퇴화 → **서바이버십 바이어스 가능성**
- 퇴화 fold가 특정 레짐(예: 2022 베어마켓)에 집중됐다면 전략이 해당 레짐에서 무력화

**(b) 위험/부작용**
- Fold 제거 시 남은 6개로 과적합 위험 증가
- 퇴화 기준(exposure=0? return<-X%) 정의에 따라 결과 변동

**(c) 최소 실험**

```
┌─────────────────────────────────────────────────────────────────┐
│ EXP-2A: Fold별 레짐 매핑                                         │
├─────────────────────────────────────────────────────────────────┤
│ 정의: 각 fold 기간을 VIX/SPY 레짐과 매핑                         │
│ 게이트: degenerate fold 4개 중 3개 이상이 동일 레짐               │
│ 기대치: "베어마켓에서만 무포지션" 패턴 확인                        │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│ EXP-2B: 퇴화 임계치 민감도                                        │
├─────────────────────────────────────────────────────────────────┤
│ 정의: exposure_min 임계치를 0.01/0.05/0.10으로 변경 후 퇴화 수 측정│
│ 게이트: 임계치 0.05에서 퇴화 fold ≤ 2개                           │
│ 기대치: 현재 0.0 기준이 과도하게 엄격한지 판별                     │
└─────────────────────────────────────────────────────────────────┘
```

**(d) PASS 조건**
```
□ 퇴화 fold 원인 문서화 (레짐/신호부재/데이터이슈)
□ 비퇴화 fold 6개의 OOS 분포 확인 (std < 1.5)
□ 퇴화 fold 레짐에서 대안 전략 식별 (헷지/현금 명시적 처리)
```

### P3. MDD 측정 파이프 활성화 + 리스크 게이트 추가
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한가**
- worst_mdd = None → **드로다운 블라인드 상태**
- OOS 좋아도 MDD -40%면 실운용 불가
- 챔피언 승격 기준에 MDD 게이트 없으면 과최적화 통과

**(b) 위험/부작용**
- MDD 게이트 추가 시 현재 챔피언 탈락 가능
- 계산 비용 증가 (일별 equity curve 필요)

**(c) 최소 실험**

```
┌─────────────────────────────────────────────────────────────────┐
│ EXP-3A: MDD 계산기 구현/활성화                                    │
├─────────────────────────────────────────────────────────────────┤
│ 정의: equity_curve → rolling_max → drawdown 계산 추가            │
│ 게이트: 모든 fold에서 mdd 값 반환 (None 제거)                     │
│ 기대치: worst_mdd 범위 파악 (-15% ~ -35% 예상)                    │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│ EXP-3B: MDD 기반 챔피언 필터                                      │
├─────────────────────────────────────────────────────────────────┤
│ 정의: promote 조건에 worst_mdd > -25% 추가                       │
│ 게이트: 기존 후보 중 MDD 탈락률 < 50%                             │
│ 기대치: 리스크 조정 후 OOS 순위 변동 관찰                          │
└─────────────────────────────────────────────────────────────────┘
```

**(d) PASS 조건**
```
□ worst_mdd 숫자 출력
□ MDD vs OOS 상관관계 문서화
□ 챔피언 promote 게이트에 MDD ≤ -25% 조건 추가
```

### P5. 신호 안정성 점검 (Trigger → Position 경로)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한가**
- exposure 0.0 ~ 0.84 범위 → 신호 on/off가 극단적
- degenerate fold에서 신호가 아예 발생 안 했을 가능성
- 신호 발생률 자체가 낮으면 백테스트 의미 없음

**(b) 위험/부작용**
- 신호 완화 시 노이즈 트레이드 증가
- 신호 강화 시 거래 기회 감소

**(c) 최소 실험**

```
┌─────────────────────────────────────────────────────────────────┐
│ EXP-5A: 신호 발생률 분석                                          │
├─────────────────────────────────────────────────────────────────┤
│ 정의: 각 fold에서 (신호 발생 일수 / 전체 일수) 계산               │
│ 게이트: 모든 fold에서 신호 발생률 > 30%                           │
│ 기대치: 퇴화 fold = 신호 부재 fold 매칭 여부                      │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│ EXP-5B: 신호 임계치 민감도                                        │
├─────────────────────────────────────────────────────────────────┤
│ 정의: 진입 신호 임계치를 ±10% 조정                                │
│ 게이트: OOS 변동 < 20%                                            │
│ 기대치: 임계치 과최적화 여부 판별                                  │
└─────────────────────────────────────────────────────────────────┘
```

**(d) PASS 조건**
```
□ Fold별 신호 발생률 테이블 생성
□ 임계치 ±10%에서 OOS 안정성 확인
□
