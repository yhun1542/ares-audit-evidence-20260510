### 1. 긴급 액션 체크리스트 (24~48h Priority)

#### [PRIORITY 0] 시스템 블라인드 복구 (Logging System Fix)
*   **이유**: `Error loading ... rebalance.csv`로 인해 포트폴리오가 실제 어떤 종목을 잡았는지 확인 불가.
*   **위험**: 로그 없이 모델 수정 시 '운'에 의한 결과인지 판단 불가.
*   **실험 정의**:
    1.  **FIX_LOGGING**: 백테스팅 엔진의 거래 로그 저장 포맷을 JSONL로 강제 통일 및 Flush 주기 단축.
    2.  **VERIFY_PATH**: `run_champion_v5_...` 경로 생성 로직이 날짜/시간 포맷(UTC vs KST) 혼용으로 꼬였는지 확인.
*   **PASS 조건**: `rebalance_pinpoint.py`가 에러 없이 실행되고, 거래 내역이 10건 이상 출력될 것.

#### [PRIORITY 1] Degenerate Folds (1,2,3,8) 소생술
*   **이유**: 특정 시기(Fold 1,2,3,8)에 거래가 '0'이거나 수익률이 Flat함. 이는 해당 시기의 Tech/Healthcare 변동성이 모델의 진입 임계값(Threshold)에 미달했거나, 데이터 누락 가능성 있음.
*   **위험**: 강제 거래 유발 시 MDD 급증 가능성.
*   **실험 (Automated Loop)**:
    1.  **Exp_Relax_Entry**: 진입 Signal Threshold를 기존 대비 50% 하향 조정하여 Fold 1,2,3,8에서 거래 발생 여부 확인.
    2.  **Exp_Force_Universe**: Tech/Healthcare 유니버스 내 상위 시가총액 5개 종목 강제 홀딩(Equal Weight) 시 해당 Fold 수익률 확인 (데이터 문제인지 로직 문제인지 분리).
    3.  **Gate**: Fold 1, 2, 3, 8의 `n_trades > 5`.
    4.  **관측치**: 거래가 발생했으나 손실이라면 '로직 문제', 거래가 여전히 없다면 '데이터 문제'.

#### [PRIORITY 2] 과최적화/누수 킬 스위치 (Cost & Leakage Audit)
*   **이유**: OOS Mean 3.32는 비현실적. 수수료(Cost)가 0으로 설정되었거나, 미래 참조(Look-ahead) 의심.
*   **위험**: 챔피언 모델의 성능이 급락하여 폐기될 수 있음(그러나 가짜 챔피언은 빨리 버려야 함).
*   **실험 (Automated Loop)**:
    1.  **Exp_Cost_Stress**: Transaction Cost 10bps + Slippage 10bps 적용 후 재검증.
    2.  **Exp_Lag_Inputs**: 모든 입력 Feature에 `shift(1)` 강제 적용 후 성능 유지 여부 확인.
    3.  **Gate**: `oos_mean > 1.0` (3.32에서 1.0대로 떨어지면 정상, 음수면 모델 폐기).
    4.  **관측치**: 급격한 샤프지수 하락 폭.

#### [PRIORITY 3] 포트폴리오 집중도 점검 (Tech/Health Focus)
*   **이유**: 8~14개 종목 분산 규정이 있으나, `exposure_max: 0.83`인 상태에서 소수 종목(1~2개)에 몰빵되었을 가능성.
*   **위험**: 섹터 로테이션 실패 시 큰 손실.
*   **실험 (Automated Loop)**:
    1.  **Exp_Cap_Weight**: 개별 종목 비중 상한(Max Weight)을 15%로 강제 설정.
    2.  **Exp_Sector_Balance**: Tech와 Healthcare 비중이 최소 3:7 ~ 7:3 범위 내에 들도록 페널티 부여.
    3.  **Gate**: OOS 성능 하락폭 < 15%.
    4.  **관측치**: 특정 종목 의존도(HHI 지수 등) 감소 확인.

### 2. 성능 정체(Stagnation) 원인 분해 아이디어

성능이 움직이지 않거나(Degenerate), 개선되지 않을 때 다음 트리를 점검하라.

1.  **트리거 부재 (Trigger Check)**
    *   *현상*: 변동성 돌파 등 신호가 발생하지 않음.
    *   *액션*: 변동성 필터(ATR 등)가 Tech/Health 섹터의 고유 변동성보다 너무 높게 설정되어 있는지 확인. (Tech는 높은데 Health는 낮을 수 있음 -> 섹터별 Threshold 분리 적용).

2.  **필터링 과다 (Filter Squeeze)**
    *   *현상*: 신호는 뜨는데 `Liquidity`, `Spread`, `Ma_trend` 필터에서 다 걸러짐.
    *   *액션*: 필터를 하나씩 끄고(Ablation Study) 거래량이 터지는 지점 확인. 특히 Fold 1, 2, 3, 8에서 필터가 모든 종목을 Kill 하고 있는지 확인.

3.  **비용/슬리피지 장벽 (Cost Wall)**
    *   *현상*: 거래는 되는데 계좌가 녹음.
    *   *액션*: 평균 수익(Avg Profit per Trade)이 수수료(예: 0.2%)보다 작은지 확인. Tech/Health ETF를 벤치마크로 삼아 단순 보유 대비 알파가 있는지 확인.

4.  **레짐 불일치 (Regime Mismatch)**
    *   *현상*: 상승장에서는 좋은데 횡보장에서 죽음(현재 2026년 시점의 시장 상황 반영).
    *   *액션*: 2026년 1월 현재가 하락/횡보장이라면, Long-Only 전략이 아닌 현금 비중(Cash Mgmt) 로직이 작동해야 함. `exposure_max`를 동적으로 조절하는 실험 필요.
