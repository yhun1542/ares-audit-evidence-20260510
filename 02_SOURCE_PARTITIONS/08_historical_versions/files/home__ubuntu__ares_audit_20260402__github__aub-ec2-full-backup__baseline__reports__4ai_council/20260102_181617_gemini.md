[진단: 심각한 신뢰성 위기]
OOS Mean 3.32는 비현실적이며, `degenerate_folds: [1, 2, 3, 8]`와 `worst_mdd: None`은 시스템이 하락장이나 특정 구간에서 계산 실패(NaN/Crash)를 일으키고 있음을 의미함. 즉, **생존한 구간의 수익만 집계된 '생존자 편향' 상태**일 가능성 99%.

다음 48시간 내 수행할 TOP 5 액션 아이템:

---

### 1. Degenerate Folds 원인 규명 및 수정 (최우선)
*   **(a) 이유:** 10개 중 4개 폴드가 터짐. 현재 챔피언 모델은 '운 좋게 돌아간 구간'에서만 작동함. 신뢰도 0.
*   **(b) 리스크:** 수정 시 OOS Mean이 급락할 수 있음(현실화).
*   **(c) 실험 (Experiments):**
    1.  **[EXP_FIX_DATA_NAN]**: 입력 데이터(OHLCV)의 결측치 처리 로직을 `drop`에서 `ffill` 혹은 `zero_fill`로 변경.
    2.  **[EXP_SAFE_DIV]**: Alpha 계산식 내 분모가 0이 되거나 로그 음수가 되는 구간에 `epsilon` 추가 및 `clip` 적용.
    3.  **[EXP_STRICT_UNIVERSE]**: 해당 Fold 기간에 상장 폐지/데이터 부족 종목(Tech/Health 중) 강제 제외 로직 강화.
*   **(d) PASS 조건:** `degenerate_folds` 개수가 0이 될 것.

### 2. MDD 및 Risk Metric 계산 모듈 복구
*   **(a) 이유:** `worst_mdd: None`은 리스크 관리가 작동하지 않음을 의미. 하락장에서 포지션이 0이거나 계산 모듈이 깨짐.
*   **(b) 리스크:** 실제 MDD가 -30% 이상으로 드러나며 전략 폐기 압박 발생.
*   **(c) 실험 (Experiments):**
    1.  **[EXP_FORCE_DD_CALC]**: 수익률 배열(returns array)이 비어있거나 NaN일 경우 0.0으로 치환 후 MDD 재계산.
    2.  **[EXP_MIN_VOL_FILTER]**: 변동성이 0인 자산(거래정지 등)을 포트폴리오에서 제외하는 필터 적용.
*   **(d) PASS 조건:** `worst_mdd`가 수치(Float)로 출력되고, OOS Min과 논리적 정합성(-0.02 min인데 MDD가 None일 수 없음) 확보.

### 3. Rebalance Logging 시스템 복구 (Telemetry)
*   **(a) 이유:** `Error loading ... rebalance.csv`. 왜 매매했는지 블랙박스 상태. 과최적화 진단 불가능.
*   **(b) 리스크:** I/O 오버헤드 미미함.
*   **(c) 실험 (Experiments):**
    1.  **[EXP_LOG_FORMAT_JSONL]**: CSV 대신 JSONL 포맷으로 변경하여 쓰기 충돌 방지 및 파싱 에러(Expecting value...) 해결.
    2.  **[EXP_LOG_VERBOSE]**: 매 리밸런싱 시점의 `Target Weight`와 `Actual Weight`, `Slippage Cost`를 명시적 기록.
*   **(d) PASS 조건:** `aub_rebalance_pinpoint.py` 실행 시 에러 없이 리포트 생성.

### 4. 비용 구조 현실화 (Cost/Slippage Stress Test)
*   **(a) 이유:** OOS Mean 3.32는 거래 비용이 0이거나 비현실적으로 낮게 설정되었을 확률 높음. Tech 바이오 종목의 슬리피지 반영 필수.
*   **(b) 리스크:** 샤프지수 대폭 하락 예상.
*   **(c) 실험 (Experiments):**
    1.  **[EXP_COST_BPS_15]**: 거래당 비용 15bps(0.15%) 강제 적용.
    2.  **[EXP_COST_BPS_30]**: 거래당 비용 30bps(0.30%) 강제 적용 (보수적 기준).
*   **(d) PASS 조건:** 15bps 적용 후에도 OOS Sharpe > 1.5 유지.

### 5. Universe 집중도 및 상관성 점검 (Tech/Health Only)
*   **(a) 이유:** 8~14개 종목 제한. 특정 섹터(예: 반도체) 몰빵으로 인한 우연한 수익인지 확인 필요. ETF는 지표로만 사용하되, 개별 종목 간 상관계수 점검.
*   **(b) 리스크:** 분산 효과 감소로 변동성 증가.
*   **(c) 실험 (Experiments):**
    1.  **[EXP_CORR_CAP]**: 포트폴리오 내 종목 간 평균 상관계수가 0.7 이상일 경우, 변동성 낮은 종목 우선 퇴출 로직 추가.
    2.  **[EXP_SECTOR_BAL]**: Tech와 Healthcare 비중을 최소 3:7 ~ 7:3 범위 내로 강제하는 Constraint 추가.
*   **(d) PASS 조건:** `run_hash` 변경 없이 Exposure 분포가 고르게(0.05~0.15) 퍼짐.

**Cycle 1: 안정성 확보 (Stability)**
1.  **실험 정의**: Fold 1, 2, 3, 8 구간의 데이터 무결성 검증 및 Alpha 로직 내 `NaN` 방어 코드 삽입.
2.  **게이트**: `degenerate_folds` == Empty List `[]`.

2.  **게이트**: `worst_mdd` != None AND `worst_mdd` > -25% (허용 한도).
3.  **기대 관측치**: 수익 곡선이 매끄럽지 않더라도 하락 폭이 정량화됨.

### [성능 정체/이상 시 원인 분해 아이디어]

성능 지표가 움직이지 않거나(Flat), 기대와 다를 때 다음 순서로 디버깅:

1.  **트리거 (Signal Trigger)**:
    *   신호가 발생하는가? (Alpha 값이 Threshold를 넘는지 확인)
    *   *Check:* Alpha 분포도(Histogram)가 0에 몰려있지 않은지.
2.  **적용 (Execution Mapping)**:
    *   신호가 포트폴리오 비중으로 변환되는가?
    *   *Check:* `Target Weight`가 계산되는데 `Executed Weight`가 0인지 (현금 부족, 최소 주문 금액 미달).
3.  **노출 (Exposure & Constraints)**:
    *   Exposure Min/Max (0.0 / 0.83) 확인.
    *   *Check:* 시장이 좋을 때도 0.83에 그친 이유가 현금 보유 강제 로직 때문인지, 종목 수 부족 때문인지.
4.  **비용 (Cost Drag)**:
    *   잦은 매매(Churn rate)로 수익이 녹는가?
    *   *Check:* 총 거래 횟수 대비 누적 비용 비율 확인.
5.  **레짐 (Regime Filter)**:
    *   ETF(지표용)가 하락 추세라 매매 자체를 차단하고 있는가?
    *   *Check:* Market Regime Filter(예: SPY MA200 하회 시 매매 중단)가 켜져 있는지 확인.
