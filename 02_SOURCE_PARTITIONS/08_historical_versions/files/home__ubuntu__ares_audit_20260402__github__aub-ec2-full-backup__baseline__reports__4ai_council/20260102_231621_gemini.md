# 우선순위 TOP 5 제안 (48시간 루프용)

현재 상태 진단: **`champion_v5`의 Lockbox 수익률(4.01)이 Tuning(2.32)보다 비정상적으로 높음.** 이는 특정 강세장 구간(Lockbox)에 과적합되었거나, 최근 레짐(Regime)에 운 좋게 편승했을 가능성이 매우 높음(Look-ahead Bias or Lucky Regime). 즉시 **Alpha Decay**에 대비한 방어적 검증이 필요함.

---

### 1. [검증] Slippage & Cost Stress Test (비용 미반영 점검)
*   **이유:** 8~14개 종목의 집중 포트폴리오는 회전율이 높을 경우 슬리피지로 인해 실제 성과가 급락함. 현재의 높은 Lockbox 수익률이 "거래 비용을 과소평가한 단타"인지 확인 필수.
*   **위험:** 챔피언 모델의 기대 수익률이 급격히 하락하여 배포 불가능 판정을 받을 수 있음(그러나 이는 필수적인 고통임).
*   **실험:**
    *   **Exp 1-1:** Transaction Cost를 기존 대비 2.5배(bps) 설정 후 재백테스트.
    *   **Exp 1-2:** 진입/청산 시그널 발생 후 `Open`가가 아닌 `High/Low`의 중간값(또는 불리한 가격) 체결 가정.
*   **PASS 조건:** Cost 2.5배 적용 후에도 Tuning Mean > 1.5 유지 시 통과.

### 2. [로직] Dynamic Sector Cap (과최적화/운영 리스크 방지)
*   **이유:** Tech와 Healthcare가 동시에 무너지는 매크로 환경(예: 고금리 장기화)에서 MDD 방어력이 취약할 수 있음.
*   **위험:** 강력한 모멘텀 장세에서 수익률 상단을 제한하여 `champion_v5`보다 성과가 낮아질 수 있음.
*   **실험:**
    *   **Exp 2-1:** 포트폴리오 내 Tech 비중 Max 60%, Healthcare Min 20% 강제 할당 로직 추가.
    *   **Exp 2-2:** XLK(Tech)와 XLV(Health)의 20일 상관계수가 0.8 이상일 때 현금 비중 30% 강제 확보.
*   **PASS 조건:** `worst_mdd`가 -0.06 (6%) 이내로 개선, Tuning Mean > 1.8 유지.

### 3. [데이터] Strict Lag Implementation (누수 점검)
*   **이유:** `20260102` 시점에서 Lockbox 성과가 너무 좋음. 장 마감 데이터가 다음 날 시초가 매매에 정확히 반영되는지(Look-ahead bias) 확인 필요.
*   **위험:** 데이터 파이프라인 수정 소요 발생.
*   **실험:**
    *   **Exp 3-1:** 모든 Feature 계산 시 `shift(1)` 강제 적용 후 성과 비교.
    *   **Exp 3-2:** PnL 계산 시 진입 가격을 `Next Open`이 아닌 `Next Open + Slippage` 혹은 `VWAP`으로 변경.
*   **PASS 조건:** 기존 Champion 대비 수익률 하락폭이 15% 이내일 것.

### 4. [전략] Volatility Targeting Sizing (서바이버십/운영 리스크)
*   **이유:** 8~14개 종목 중 1~2개 종목의 급락(Bio 임상 실패 등)이 전체 포트폴리오를 망가뜨리는 것 방지.
*   **위험:** 변동성이 낮은 대형주 위주로 포트폴리오가 구성되어 Alpha가 희석될 수 있음.
*   **실험:**
    *   **Exp 4-1:** 개별 종목의 ATR(Average True Range) 역수 비례로 포지션 사이즈 조절 (Equal Weighting 대체).
    *   **Exp 4-2:** 포트폴리오 전체 변동성 타겟(예: 연 20%) 초과 시 전체 노출도 축소.
*   **PASS 조건:** `fold14_mdd` 개선 및 Sharpe Ratio 상승(수익률 하락하더라도 감수).

### 5. [아키텍처] Ensemble with "Shadow" (과최적화 방지)
*   **이유:** 현재 `champion`은 공격적, `candidate_shadow`는 방어적(Min return 방어). 두 모델의 장점을 섞어 안정성 확보.
*   **위험:** 모델 복잡도 증가 및 디버깅 난이도 상승.
*   **실험:**
    *   **Exp 5-1:** `champion_v5`와 `candidate_shadow`의 시그널을 7:3 비율로 혼합(Voting or Avg Weight).
    *   **Exp 5-2:** 시장 변동성 지표(VIX 등)가 특정 임계치 이상일 때 `candidate_shadow` 로직으로 스위칭.
*   **PASS 조건:** Lockbox Min Return > 0.5, Tuning Mean > 2.0 동시 달성.

# 48시간 자동 루프 정의 (Definition / Gate / Expectation)

### Loop 1: Reality Check (비용 및 누수)
1.  **실험 정의:** `champion_v5` 복제본 생성 -> (1) Transaction Fee 20bps 적용, (2) Feature Shift(1) 재검증.
2.  **게이트(Gate):** Tuning Mean > 1.2 (기존 2.3에서 반토막 나도 생존하는가?)
3.  **기대 관측치:** Lockbox 수익률이 4.01에서 2.5 수준으로 하락하되, 마이너스로 전환되지 않아야 함.

### Loop 2: Sector & Volatility Control
1.  **실험 정의:** Universe 필터링 강화 -> Tech/Health Cross-correlation > 0.7 시 현금 비중 50% Rule 적용.
2.  **게이트(Gate):** `worst_mdd` > -0.07 (현재 -0.08보다 개선)
3.  **기대 관측치:** 폭락장(Bear Market) 구간에서의 손실폭 축소 확인.

### Loop 3: Ensemble Stabilization
1.  **실험 정의:** Champion(High Return) + Shadow(High Consistency) 50:50 블렌딩 모델 생성.
2.  **게이트(Gate):** Lockbox Min Return > 1.0 (안정성 확보)
3.  **기대 관측치:** Tuning Mean은 1.9~2.0 수준으로 수렴, 수익 곡선의 변동성 완화.

# 성능 정체 시 원인 분해 (Debugging Tree)

성능 지표가 개선되지 않을 때 다음 순서로 점검하고 `next_fix.md`에 기록할 것.

1.  **Trigger (신호 발생 빈도):**
    *   조건이 너무 까다로워 매매가 거의 없는가? -> *조치: 임계값 완화 (Relax Thresholds)*
2.  **Application (비중):**
    *   좋은 종목을 샀으나 비중이 너무 적은가? (Equal weight의 함정) -> *조치: 확신도 기반 베팅 (Confidence sizing)*
3.  **Exposure (베타 노출):**
    *   시장(QQQ/XLV)이 오를 때 못 따라가고, 내릴 때만 같이 내리는가? -> *조치: 모멘텀 필터 추가 (Relative Strength vs SPY)*
4.  **Cost (비용):**
    *   매매 횟수가 과다하여 수수료가 알파를 잠식하는가? -> *조치: 보유 기간 강제 연장 (Holding Period Constraint)*
5.  **Regime (시장 국면):**
    *   현재 전략이 '횡보장'용인데 '추세장' 데이터를 돌리고 있는가? -> *조치: 레짐 디텍터(Regime Detector) 모듈의 민감도 조정*
