[분석 요약]
현재 `worst_mdd: None` 및 `Degenerate Folds: [1, 2, 3, 8]` 상태는 시스템이 **리스크를 계산하지 못하고 있으며, 특정 구간(Fold)에서 전략이 붕괴(거래 없음 또는 솔버 실패)**했음을 의미합니다. `oos_mean: 3.32`는 4개 Fold가 죽은 상태에서 나온 값이므로 **심각한 과최적화 또는 생존 편향(Survivorship Bias)**이 강력히 의심됩니다. 로그 파싱 에러로 인해 실제 트레이딩 내역 검증이 불가능한 상태입니다.

### 1. 우선순위 TOP 5 제안 (48시간 루프)

#### **Priority 1: `worst_mdd: None` 및 로그 파싱 긴급 수정 (System Integrity)**
*   **(a) 필요성:** 리스크 계측 없이 OOS Mean만 보는 것은 자살행위입니다. MDD가 None인 것은 평가 모듈의 NaN 처리 미비 혹은 데이터 누락입니다. 또한 `rebalance.csv` 포맷 에러로 진단 도구(Diagnoser)가 작동하지 않습니다.
*   **(b) 위험:** 수정 중 평가 파이프라인 일시 중단. 기존 챔피언 점수가 가짜일 가능성 확인 후 멘탈 붕괴.
*   **(c) 실험 (Patch):**
    1.  **Patch_Metric_Sanity:** `worst_mdd` 계산 시 `NaN`이나 거래 없음(Empty)일 경우 `None` 대신 `-1.0` (또는 -999)을 반환하여 해당 설정을 즉시 탈락시키도록 코드 수정.
    2.  **Patch_Log_Format:** `aub_rebalance_pinpoint.py`의 입력 파서가 JSONL과 CSV를 혼동하지 않도록 명시적 핸들러 분리. (Line 1 column 1 에러 해결).
*   **(d) PASS 조건:**
    *   `worst_mdd`가 실수(float) 값으로 출력될 것.
    *   Rebalance 로그가 에러 없이 로드될 것.

#### **Priority 2: Degenerate Folds [1, 2, 3, 8] 솔버 완화 (Optimization Risk)**
*   **(a) 필요성:** 4개의 Fold가 퇴화(Degenerate)했다는 것은 특정 시장 상황에서 포트폴리오 최적화기(Solver)가 해를 찾지 못했거나(Infeasible), 모든 비중을 0으로 둔 것입니다.
*   **(b) 위험:** 제약 조건을 너무 풀면 포트폴리오가 잡주나 과도한 레버리지에 노출될 수 있음.
*   **(c) 실험:**
    1.  **Exp_Relax_Solver:** 최적화 실패 시 `Equal Weight(1/N)` 또는 `Current Hold`를 유지하도록 Fallback 로직 추가.
    2.  **Exp_Min_Weight:** 개별 주식 최소 비중 제약(예: >1%)이 너무 높아 해가 없는지 확인 -> 제약을 0.0으로 완화하거나 Top N(N=5) 강제 선택.
    3.  **Exp_Objective_Change:** 목적 함수를 `Max Return`에서 `Min Volatility`로 변경하여 해 탐색 범위 확장.
*   **(d) PASS 조건:**
    *   `degenerate_folds` 개수가 0~1개로 감소.
    *   `exposure_min`이 0.0이 아닐 것 (시장 참여 유지).

#### **Priority 3: Tech/Healthcare 섹터 편중 및 상관관계 제한 (Concentration Risk)**
*   **(a) 필요성:** Tech/Healthcare 8~14종목 집중 시, 섹터 전체 하락기에 MDD가 급증합니다. 현재 높은 OOS Mean은 섹터 모멘텀 빨일 수 있습니다.
*   **(b) 위험:** 단기 수익률 저하 (베타 플레이 감소).
*   **(c) 실험:**
    1.  **Exp_Sector_Cap:** Tech 비중 Max 60%, Healthcare Max 40% 하드 코딩 제약 추가.
    2.  **Exp_Corr_Filter:** 포트폴리오 내 종목 간 평균 상관계수가 0.7 이상인 종목 조합은 Penalty 부여.
*   **(d) PASS 조건:**
    *   OOS Sharpe Ratio가 유지되면서 MDD가 개선(-15% 이내)될 것.

#### **Priority 4: 고비용 환경 스트레스 테스트 (Cost/Slippage)**
*   **(a) 필요성:** 8~14종목으로 잦은 매매 시 슬리피지와 수수료가 수익을 갉아먹습니다. 현재 3.32 Mean은 비용이 0이거나 낮게 책정되었을 가능성이 큽니다.
*   **(b) 위험:** 거래 횟수가 급감하여 통계적 유의성 상실.
*   **(c) 실험:**
    1.  **Exp_Cost_30bps:** 편도 거래 비용을 15bps(0.15%)에서 30bps로 상향 설정 후 백테스트.
    2.  **Exp_Turnover_Limit:** 일일 회전율(Turnover) 상한을 10% 또는 20%로 제한.
*   **(d) PASS 조건:**
    *   비용 증가 후에도 OOS Mean > 1.0 유지.

#### **Priority 5: 유동성 기반 유니버스 필터링 (Liquidity/Survivorship)**
*   **(a) 필요성:** Tech/Healthcare 소형주가 포함되어 있다면, 백테스트 상으로는 매수 가능하지만 실제로는 불가능한 갭상승/하락이 반영되었을 수 있습니다.
*   **(b) 위험:** 유망한 소형 성장주 배제.
*   **(c) 실험:**
    1.  **Exp_Liquidity_Filter:** 일평균 거래대금(ADV) $50M 미만 종목 배제.
    2.  **Exp_Volatility_Cap:** 30일 변동성이 상위 10%인 초고위험 종목 유니버스에서 제외.
*   **(d) PASS 조건:**
    *   유니버스 축소 후에도 `degenerate_folds`가 증가하지 않음.

### 2. 성능 정체(Stagnation) 시 원인 분해 체크리스트

성능이 움직이지 않거나(3.32 근처 횡보) 떨어지기만 할 때 다음을 점검하십시오.

*   **트리거(Trigger) 불감증:**
    *   시장 변동성(VIX)이나 ETF(QQQ/XLV) 지표가 변해도 개별 종목의 Entry/Exit 신호가 바뀌지 않는가?
    *   *Check:* `Signal_Variance` (신호 분산) 확인. 분산이 0에 가까우면 로직이 죽은 것.
*   **노출(Exposure) 상한:**
    *   `exposure_max`가 0.838로 멈춰 있는가? 현금 비중이 강제되어 더 높은 수익을 낼 기회를 잃고 있는가?
    *   *Check:* 레버리지나 Cash Buffer 제약을 0.95까지 풀어볼 것.
*   **비용(Cost) 장벽:**
    *   알파가 비용보다 작아서(Marginal Alpha < Cost), 최적화기가 "거래 안 함(Do Nothing)"을 선택하는가?
    *   *Check:* 비용을 0으로 설정했을 때 거래가 폭발하는지 확인. 그렇다면 알파가 너무 얇은 것.
*   **레짐(Regime) 불일치:**
    *   학습 데이터(Train)의 시장 성격과 검증 데이터(OOS)의 시장 성격이 정반대(상승장 vs 횡보장)인가?
    *   *Check:* 최근 6개월(OOS) 데이터만으로 재학습(Retrain) 시켜 성능 변화 확인.
