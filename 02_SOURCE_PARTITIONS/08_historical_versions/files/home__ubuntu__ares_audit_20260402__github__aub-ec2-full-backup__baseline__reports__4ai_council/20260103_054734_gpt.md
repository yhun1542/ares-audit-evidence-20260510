아래는 **다음 24~48시간 자동 루프(48h loop)**에서 바로 돌릴 수 있게, **TOP5 우선순위(코드/아키텍처/전략)**를 **“실행 가능한 5개 patch/실험 티켓”**으로 정리한 명령형 체크리스트다.  
우선순위는 **누수/과최적화/서바이버십/비용 미반영/운영 리스크**를 먼저 잡고, 그 다음에 노출/리밸런스/신호를 만진다.  
(미국주식 only, Tech+Healthcare 중심, **8~14종목**, **ETF는 관측지표만**)

## TOP1) [운영 리스크] 리밸런스/아티팩트 로깅 스키마 고정 (현재 rebalance pinpoint가 깨짐)
**(a) 왜 필요한지**
- 현재 상태에서 핵심 디버그가 불능:
  - `aub_rebalance_pinpoint`가 `--base-log` 파일 미존재 + CSV/JSON 파싱 실패로 **리밸런스 비교 자체가 불가**
  - Champion 메타에 `worst_mdd: None`, `lane_hash/run_hash: None` → **재현성/추적성 상실**
- “성능이 안 움직임”이 **진짜 전략 문제인지, 로그/산출 실패인지**부터 분리해야 함.

**(b) 위험/부작용**
- 성능은 안 바뀌는데 코드 변경량만 늘어날 수 있음.
- 스키마 변경으로 기존 리포트/툴이 깨질 수 있음(역호환 레이어 필요).

**(c) 최소 실험(동일 티켓 내 2~3개 변형 = 1개 실험 티켓으로 처리)**
- [변형1] **단일 진실 소스 스키마**: `rebalance.jsonl` + `rebalance.csv`를 **항상** 생성(헤더 고정), 누락 시 파이프라인 fail-fast.
- [변형2] 모든 run에서 `lane_hash/run_hash/seed/git_sha/config_hash` 강제 기록 + `worst_mdd` 계산 실패 시 예외 처리(조용히 None 금지).
- [변형3] `aub_rebalance_pinpoint.py` 입력 자동 탐색: “base-log 경로가 `--base-log` 문자열로 들어오는 케이스”를 즉시 에러로 잡고, 올바른 경로 후보를 탐색/가이드 출력.

**(d) PASS 조건 (게이트)**
- `python3 .../aub_rebalance_pinpoint.py`가 **0 에러**로 리포트 생성.
- 모든 run 아티팩트에 `lane_hash/run_hash/worst_mdd`가 **None 없이** 기록.
- 동일 seed/config 재실행 시 **동일 결과(결정론)** 또는 허용 오차 내 재현.

**48h loop 포맷**
- (1) 실험 정의: “리밸런스/메타 로깅 강제 + fail-fast”
- (2) 게이트: 위 PASS 조건 충족 아니면 다음 실험 진행 금지
- (3) 기대 관측치: 성능 수치 변화보다 **원인 추적 가능성↑**, “왜 노출이 0~0.84에서 멈추는지”를 포지션 단에서 확인 가능

## TOP2) [누수/과최적화] Degenerate folds 제거 + Purged Walk-Forward CV로 교체
현재 `degenerate_folds: [1,2,3,8]`은 **검증 체계가 망가졌거나(표본 부족/신호 미발동), 분할/라벨링/트레이드 생성에 구조적 결함**이 있음을 강하게 시사.

**(a) 왜 필요한지**
- fold가 퇴화(degenerate)하면 OOS mean이 좋아도 **의미가 없음**(서바이버십/누수/표본편향 가능).
- “성능이 안 움직임”이 사실은 **검증이 무력해서 감지 못하는 상태**일 수 있음.

**(b) 위험/부작용**
- 제대로 된 CV로 바꾸면 OOS가 **하락**할 수 있음(하지만 그게 정상).
- embargo/purge 적용 시 데이터 효율이 떨어져 학습이 불안정해질 수 있음(대신 신뢰도↑).

**(c) 최소 실험(= 1개 실험 티켓, 내부 변형 2~3개)**
- [변형1] Walk-forward 분할을 “월 단위/분기 단위”로 고정하고, **purge+embargo(예: 5~20 trading days)** 적용.
- [변형2] fold별 **최소 트레이드 수 / 최소 리밸런스 횟수 / 최소 보유종목수(8~14)**를 하드 게이트로 추가(미달 fold는 “실험 실패” 처리).
- [변형3] 신호 생성~체결 사이 지연(예: 1 bar delay)을 CV에서도 강제(암묵적 미래정보 사용 차단).

**(d) PASS 조건 (게이트)**
- `degenerate_folds == []`
- 각 fold에서:
  - 월평균 트레이드 수/리밸런스 수가 최저 기준 이상
  - 보유 종목 수 8~14 유지율이 기준 이상
- OOS 지표:
  - `oos_min`이 최소 기준(예: 0 이상 또는 -작은값 이하로 제한) 충족
  - OOS 분산/불안정성(폴드간 편차) 감소

**48h loop**
- (1) 실험 정의: “Purged WFV + 퇴화 fold 차단”
- (2) 게이트: 퇴화 fold 발생 시 즉시 중단/원인 로그
- (3) 기대 관측치: OOS mean이 내려가도 **신뢰구간이 좁아지고**, “성능 무반응”이 **검증 무력** 때문인지 분리 가능

## TOP3) [비용 미반영] 거래비용/슬리피지/차입비용(쇼트) 현실화 + turnover 게이트
**(a) 왜 필요한지**
- 비용이 0이거나 너무 낙관적이면, 개선이 실제로는 비용에 먹혀서 “성능이 안 움직이는 것처럼” 보이거나, 반대로 백테스트만 과대평가될 수 있음.
- Tech/Healthcare 8~14개 운용에서 잦은 리밸런스면 turnover가 성과를 잠식.

**(b) 위험/부작용**
- 비용 도입 후 성과 급락 가능(하지만 그게 정상).
- 쇼트 포함 시 차입비용/리콜 리스크를 반영하면 전략 구조를 바꿔야 할 수 있음.

**(c) 최소 실험(= 1개 실험 티켓, 내부 변형 2~3개)**
- [변형1] 슬리피지: `bps = max(spread/2, k * (vol/ADV))` 형태의 보수적 함수로 적용(ADV 기반).
- [변형2] turnover 게이트: 20거래일 rolling turnover가 상한 초과 시 포지션 변경을 감쇠/지연(리밸런스 완화).
- [변형3] 쇼트 차입비용/하드투보로우(HTB) 가정: 헬스케어 바이오 등 HTB 가능군에 보수적 borrow bps 적용(ETF 트레이드 금지, ETF는 관측만).

**(d) PASS 조건 (게이트)**
- **gross→net 하락폭이 합리적**(예: gross가 좋아도 net이 플러스로 유지)
- turnover/거래횟수가 상한 내로 안정
- 비용 반영 후에도 `oos_mean`이 최소 기준 이상 + `oos_min` 악화 폭 제한

**48h loop**
- (1) 실험 정의: “현실적 비용 + turnover 제어”
- (2) 게이트: net 성과/turnover 기준 미달 시 fail
- (3) 기대 관측치: “개선이 비용에 상쇄되는지”가 수치로 드러나고, 리밸런스가 과한지 즉시 확인 가능

## TOP4) [노출/운용] 포트폴리오 구성 레이어 고정: 8~14종목 유지 + 단일종목/섹터/베타 캡
현재 `exposure_max ~0.84`는 “현금 비중/헤지/클리핑”으로 제한되는 것으로 보이는데, **왜 1.0을 못 쓰는지(의도인지 버그인지)**가 리밸런스 로그 없이는 불명확. 동시에 8~14종목 제약을 시스템적으로 강제해야 함.

**(a) 왜 필요한지**
- 종목 수가 흔들리면 성과가 레짐/이벤트에 과민해지고 서바이버십 성향이 생김.
- 노출/단일종목 쏠림이 있으면 OOS min이 깨지기 쉬움.
- ETF는 관측지표로만 쓰되, **QQQ/XLV 같은 지표 베타**는 리스크 캡에 활용 가능(트레이드 금지).

**(b) 위험/부작용**
- 제약이 강해져 수익 상한이 낮아질 수 있음.
- 제약 충돌(신호 종목 부족) 시 현금 비중 증가로 “성능 무반응”처럼 보일 수 있음(그래서 종목수 게이트 필요).

**(c) 최소 실험(= 1개 실험 티켓, 내부 변형 2~3개)**
- [변형1] **종목 수 고정**: 매 리밸런스 시 상위/하위 스코어에서 8~14개만 채택(부족 시 대체 룰 명시).
- [변형2] **단일 종목 캡**(예: 12~15%) + **섹터 밴드**(Tech/Healthcare 중심이되 과쏠림 제한).
- [변형3] **지표 베타 캡**: 관측 ETF(예: QQQ, XLV)로 60~120일 회귀 베타를 추정해, 포트폴리오 베타가 상한을 넘으면 포지션 스케일다운(ETF 매매 없음).

**(d) PASS 조건 (게이트)**
- 보유종목 수가 대부분 시점에서 8~14 유지(유지율 기준)
- 단일종목 최대 비중/섹터 밴드 위반 0
- `worst_mdd` 계산 가능 + 기존 대비 악화 제한, `oos_min` 개선 또는 악화폭 제한

**48h loop**
- (1) 실험 정의: “구성/리스크 레이어로 운용 제약을 코드화”
- (2) 게이트: 8~14 유지 실패 또는 캡 위반 시 fail
- (3) 기대 관측치: OOS min 및 MDD가 안정화되고, 노출이 0~0.84로 갇히는 원인이 규칙/버그 중 무엇인지 분리 가능

## TOP5) [트리거→적용] 신호 스케일/헤지/클리핑 민감도 스모크 테스트(‘거래가 안 나와서 성능이 안 움직임’ 제거)
현재 컨텍스트에 `...fsa_only_scale_090_hedge_025...`가 보이며, 이런 스케일/헤지 계열은 **클리핑/현금화/상쇄**로 이어져 성능을 평평하게 만들기 쉽다.

**(a) 왜 필요한지**
- 성능 무반응의 흔한 원인:
  - 신호가 포지션으로 잘 “적용”되지 않음(클리핑/정규화 버그)
  - 헤지가 알파를 상쇄
  - 임계값 때문에 대부분 0 포지션
- 이건 모델을 바꾸기 전에 **적용 레이어**에서 빠르게 확인 가능.

**(b) 위험/부작용**
- 스케일을 키우면 MDD/변동성이 커질 수 있음.
- 헤지를 줄이면 시장 방향 노출이 커질 수 있음(그래서 베타/노출 게이트 병행).

**(c) 최소 실험(= 1개 실험 티켓, 내부 변형 2~3개)**
- [변형1] scale 3점 스윕: 0.6 / 0.9 / 1.2 (동일 신호, 적용만 변경)
- [변형2] hedge 3점 스윕: 0.0 / 0.25 / 0.5 (ETF 매매가 아니라 내부 헤지계수라면)
- [변형3] 포지션 클리핑/임계값 로깅: “원 신호→정규화→클리핑→최종 주문” 단계별 분포를 jsonl로 저장(포지션이 왜 0이 되는지 계측)

**(d) PASS 조건 (게이트)**
- 월별 평균 노출이 목표 범위(예: 0.2~0.9)에서 움직임
- 트레이드/리밸런스가 최소 기준 이상(너무 적거나 0이면 실패)
- 스윕 간에 성과/리스크가 **단조 혹은 합리적 형태**로 반응(전부 동일하면 적용이 죽어있을 가능성)

**48h loop**
- (1) 실험 정의: “적용 레이어 민감도 + 단계별 로깅”
- (2) 게이트: 노출/거래량이 ‘0에 수렴’이면 즉시 fail(성능 비교 의미 없음)
- (3) 기대 관측치: “성능이 안 움직임”이 모델이 아니라 **적용/상쇄** 때문인지 즉시 판별

# 성능이 안 움직일 때 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래는 **질문 없이** 바로 추가할 수 있는 **자동 진단 트리(체크리스트)**다. (ETF는 관측지표로만)

## 1) Trigger(신호 생성) 레이어
- [ ] 신호 분포가 시간에 따라 변하는지(평균/표준편차/상위1% 값)
- [ ] 신호가 레짐에서만 켜지는지(예: 변동성 급등 구간만)
- [ ] Point-in-time 위반(미래 재무/리비전) 탐지 로그: feature timestamp vs trade timestamp
- [ ] 유니버스(Tech+Healthcare) 구성의 서바이버십 체크: 상장폐지/합병/티커변경 반영 여부

## 2) Apply(신호→포지션) 레이어
- [ ] 정규화/클리핑/임계값 이후 포지션이 “거의 0”인지
- [ ] hedge가 알파를 상쇄하는지(헤지 전후 PnL 분해)
- [ ] 리밸런스 규칙이 주문을 무력화하는지(최소 주문 크기/라운딩/현금 제약)

## 3) Exposure/Portfolio(노출/구성) 레이어
- [ ] 8~14종목 유지율, 단일종목 캡 위반 여부
- [ ] 섹터/팩터 쏠림(Tech/Healthcare 내에서도 mega-cap 쏠림) 진단
- [ ] QQQ/XLV(관측) 베타가 과도하게 고정되어 성과가 평평해지는지

## 4) Costs(비용) 레이어
- [ ] gross vs net 갭이 대부분의 알파를 먹는지(턴오버 구간별)
- [ ] 슬리피지 모델이 ADV 대비 비현실적으로 낮은지
- [ ] 쇼트 차입비용/리콜 리스크를 무시했는지(특히 바이오)

## 5) Regime(시장 국면) 레이어 — ETF는 “지표”로만 사용
- [ ] 관측 지표로 레짐 태깅: QQQ(성장), XLV(헬스케어), XBI(바이오), IWM(리스크), TLT(금리), VIX(변동성)
- [ ] 레짐별 성과표 자동 생성(레짐마다 승률/턴오버/노출/비용)
- [ ] 레짐 전환 시점에만 성과가 생기거나 죽는지(구조적 민감도)

---

## 24~48시간 실행 순서(강제)
1) **TOP1 로깅/리밸런스 스키마** 먼저 통과(미통과 시 나머지 실험 금지)  
2) **TOP2 CV/degenerate fold 제거**로 검증 신뢰도 확보  
3) **TOP3 비용+turnover**로 “가짜 알파” 제거
