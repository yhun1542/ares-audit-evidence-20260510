### 제안 상세 (Actionable Plans)

#### 1. Rebalance 로그 파이프라인 긴급 복구
*   **(a) 필요성:** `Errno 2`, `Expecting value` 에러는 시스템이 실제 거래 내역을 읽지 못함을 의미. 비용 분석 없는 수익률은 허상임.
*   **(b) 위험/부작용:** 로그 포맷 변경 시 기존 데이터와의 호환성 문제 발생 가능(Backfill 필요).
*   **(c) 실험/Patch:**
    *   **Patch 1:** `aub_rebalance_pinpoint.py` 내 CSV/JSONL 파서 로직에 예외 처리 추가 및 강제 `.jsonl` 포맷팅 적용.
    *   **Patch 2:** 실행 경로(Path)를 상대 경로에서 절대 경로로 고정 (`/home/ubuntu/AUB/...`).
    *   **Verify:** 더미(Dummy) 로그 생성 후 로더가 정상적으로 DataFrame을 반환하는지 단위 테스트.
*   **(d) PASS 조건:** `aub_rebalance_pinpoint.py` 실행 시 에러 없이 Rebalance DataFrame이 로드되고, `turnover` 수치가 출력될 것.

#### 2. 챔피언 메트릭 괴리 검증 (Clean Re-run)
*   **(a) 필요성:** OOS Mean 1.88(보수적)과 2.62(낙관적)의 차이는 의사결정 마비 유발. 참조 데이터셋 버전(v5 vs v5_20251231) 불일치 확인 필요.
*   **(b) 위험/부작용:** 2.62가 'Look-ahead Bias(미래참조)'였음이 밝혀질 경우, 전체 기대 수익률 하향 조정 불가피.
*   **(c) 실험:**
    *   **Exp 1 (Base):** 현재 챔피언 코드를 `2025-01-01 ~ 2025-12-31` 구간에 대해 Cold Start로 재실행.
    *   **Exp 2 (Latest Data):** 가장 최근 데이터(2026-01-01 직전)까지 포함하여 OOS 업데이트.
    *   **Exp 3 (Diff Check):** Handoff 리포트 생성 로직과 Diagnoser 로직의 평가 함수(Metric Function) 일치 여부 코드 레벨 대조.
*   **(d) PASS 조건:** 두 평가 도구의 수치 오차가 5% 이내로 수렴하고, 재현된 OOS Mean이 1.5 이상 유지.

#### 3. 슬리피지/수수료 민감도 스트레스 테스트
*   **(a) 필요성:** 집중 포트폴리오(Tech/Bio)는 변동성이 크고 스프레드가 넓을 수 있음. 기본 가정(10bps 등)이 깨질 때의 생존성 확인.
*   **(b) 위험/부작용:** 과도한 비용 설정 시 모든 전략이 기각되어 "Trading Halt" 상태로 빠질 위험.
*   **(c) 실험:**
    *   **Exp 1 (Cost 2x):** 슬리피지/수수료를 현재 설정의 2배(예: 10bps -> 20bps)로 적용 후 시뮬레이션.
    *   **Exp 2 (Cost 5x):** 5배 적용(최악의 상황, 시장 붕괴 시 유동성 증발 가정).
    *   **Exp 3 (Delay):** 체결을 시그널 발생 1분/1시간 후 가격으로 가정하여 시뮬레이션 (Execution Lag 테스트).
*   **(d) PASS 조건:** Cost 2x 상황에서 OOS Sharpe Ratio가 1.0 이상 유지, MDD 증가폭 10%p 이내.

#### 4. 동적 헷지 비율(Hedge Ratio) 최적화
*   **(a) 필요성:** 로그의 `exp_fsa_only_scale_090_hedge_025` 시도 흔적은 노출도(Exposure) 조절 의도. 2026년 초 시장 불확실성 대비.
*   **(b) 위험/부작용:** 과도한 헷지는 상승장(Tech Rally)에서의 수익 기회를 박탈(Underperformance).
*   **(c) 실험:**
    *   **Exp 1 (Fixed Hedge):** 고정 헷지 비율 25% (Long 100 / Short 25) 적용.
    *   **Exp 2 (VIX Dynamic):** VIX 지표 연동형 가변 헷지 (VIX > 20 시 헷지 비율 50%로 상향).
    *   **Exp 3 (Beta Dynamic):** 포트폴리오 베타가 1.2 초과 시 ETF 인버스 비중 확대.
*   **(d) PASS 조건:** 헷지 적용 시 MDD가 기존 대비 15% 이상 개선되고, OOS Mean 감소폭이 10% 미만일 것.

#### 5. 유니버스 필터 완화 (Survivorship Check)
*   **(a) 필요성:** 현재 8~14개 종목은 너무 적음. 2025년 실적 기반 필터링이 이미 상장 폐지되거나 인수된 기업을 배제했는지 확인해야 함.
*   **(b) 위험/부작용:** 부실 기업(Bio Small-cap) 포함 시 변동성 폭발 및 거래 정지 리스크 노출.
*   **(c) 실험:**
    *   **Exp 1 (Relax Cap):** 시가총액 하한선을 현재의 50% 수준으로 하향 조정.
    *   **Exp 2 (Relax Vol):** 거래량(Liquidity) 필터를 완화하여 유니버스 종목 수를 20~30개로 확장 시도.
    *   **Exp 3 (Sector Expansion):** MedTech 등 Tech+Healthcare 교집합 섹터 가중치 부여.
*   **(d) PASS 조건:** 유니버스가 20개 이상으로 확장되었을 때 성능(Sharpe/MDD)이 급격히 붕괴하지 않음 (로바스트성 입증).

### 성능 정체 시 원인 분해 (Diagnosis Tree)

48시간 루프 내 성능 개선이 보이지 않을 경우, 아래 순서로 원인을 트리밍하라.

1.  **Signal Fail (트리거 문제)**
    *   **가설:** 진입/청산 조건이 너무 까다로워 거래 자체가 발생하지 않음 (Low Turnover).
    *   **확인:** 최근 3개월 거래 횟수가 5회 미만인가?
    *   **조치:** 진입 Threshold 10% 완화 실험.

2.  **Execution Drag (비용 문제)**
    *   **가설:** 알파는 있으나 거래 비용(슬리피지)이 수익을 다 갉아먹음.
    *   **확인:** `Gross Return`과 `Net Return`의 괴리가 연환산 5% 이상인가?
    *   **조치:** 회전율(Turnover) 강제 제한 또는 Limit Order(지정가) 로직 도입 검토.

3.  **Regime Mismatch (시장 환경 문제)**
    *   **가설:** Tech/Healthcare 섹터 자체가 하락/횡보장이라 Long-Only 알파가 작동 안 함.
    *   **확인:** 벤치마크(QQQ/XLV) 대비 Alpha가 양수(+)인가? (절대 수익이 마이너스라도 알파가 있으면 정상).
    *   **조치:** 알파가 없다면 전략 폐기 또는 Short 전략 비중(Inverse ETF) 확대.

4.  **Feature Decay (알파 소멸)**
    *   **가설:** 사용 중인 팩터(모멘텀/밸류 등)가 시장에 널리 알려져 우위 상실.
    *   **확인:** 팩터별 IC(Information Coefficient)가 최근 6개월간 0에 수렴하는가?
    *   **조치:** 대체 데이터(News Sentiment 등) 결합 또는 팩터 룩백 기간 변경.
