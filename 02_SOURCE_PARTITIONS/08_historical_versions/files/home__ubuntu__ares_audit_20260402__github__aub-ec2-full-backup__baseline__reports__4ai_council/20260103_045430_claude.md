## 📋 TOP 5 우선순위 액션

### P1. Degenerate Fold 원인 분리 (Gate: 파이프라인 신뢰성)

**왜 필요한가:**
- 4/10 fold가 degenerate → 40% OOS 구간이 무의미
- 이 상태에서 oos_mean 3.32는 **6개 fold만의 평균** = 서바이버십 누수

**위험/부작용:**
- 수정 시 oos_mean 하락 거의 확실
- 진짜 성능 드러나면 champion 교체 필요 가능

**실험 체크리스트:**
```
□ EXP-P1A: degenerate 판정 조건 로깅 추가
  - 파일: experiment_system/walk_forward.py
  - 게이트: 각 fold별 (샘플수, 거래횟수, 평균노출) 출력
  - PASS: 10개 fold 모두 로그 확인

□ EXP-P1B: min_trades_per_fold=5 완화 테스트 (→3)
  - 게이트: degenerate fold 수 < 2
  - 기대: oos_mean 2.0 이상 유지 시 PASS

□ EXP-P1C: fold 기간 확장 (6M→9M IS, 3M→4M OOS)
  - 게이트: degenerate=0, oos_std < 1.5
  - 기대: 안정화되면 기준선 재설정
```

### P2. MDD/리스크 메트릭 복구

**왜 필요한가:**
- worst_mdd=None → 리스크 제약 없이 수익만 추종 중
- 실전에서 -25% DD 발생 시 대응 불가

**위험/부작용:**
- MDD 계산 추가 시 연산 비용 증가 (minor)
- 과거 결과 비교 불가 (버전 분기)

**실험 체크리스트:**
```
□ EXP-P2A: portfolio_value 시계열 → rolling MDD 계산 삽입
  - 파일: backtest_engine/metrics.py
  - 게이트: worst_mdd, avg_mdd, mdd_duration 3개 값 출력
  - PASS: champion 재실행 시 MDD ≥ -0.30 (30% 이내)

□ EXP-P2B: MDD > 25% 시 자동 exposure 반감 로직
  - 게이트: max_exposure 0.85→0.42 전환 확인
  - PASS: 극단 시나리오(2022-Q1)에서 DD 15%p 감소
```

### P3. Rebalance 로그 파이프라인 수리

**왜 필요한가:**
- rebalance.csv 로드 실패 → **비용/슬리피지 미반영 의심**
- 실제 진입/청산 시점 검증 불가

**위험/부작용:**
- 로그 포맷 변경 시 기존 분석 스크립트 호환성 깨짐

**실험 체크리스트:**
```
□ EXP-P3A: rebalance.jsonl 스키마 검증 스크립트
  - CMD: python -c "import json; [json.loads(l) for l in open('rebalance.jsonl')]"
  - PASS: 파싱 에러 0건

□ EXP-P3B: 누락 필드 복구 (timestamp, ticker, shares, price, cost)
  - 게이트: pinpoint.py 정상 실행
  - PASS: 거래당 cost 컬럼 존재, 합산 = 연 -0.5% ~ -2.0% 범위

□ EXP-P3C: 슬리피지 시뮬레이션 (5bps, 10bps, 20bps)
  - 게이트: oos_mean 변화 측정
  - PASS: 10bps 적용 후 oos_mean > 2.5
```

### P4. Exposure Min=0.0 구간 분석

**왜 필요한가:**
- exposure=0 → 시그널이 모든 종목 회피 중
- 정당한 현금 전환 vs 시그널 버그 구분 필요

**위험/부작용:**
- 강제 최소 노출 설정 시 하락장 손실 증가

**실험 체크리스트:**
```
□ EXP-P4A: exposure=0 구간 날짜/레짐 태깅
  - 게이트: 해당 구간 SPY 수익률 로깅
  - PASS: exposure=0 구간이 SPY 하락기와 70%+ 일치

□ EXP-P4B: min_exposure=0.10 강제 후 성능 비교
  - 게이트: oos_mean 변화량
  - PASS: 하락 < 0.3, MDD 개선 시 채택
```

### P5. OOS Mean 3.32 → 2.63 괴리 해명

**왜 필요한가:**
- Handoff(3.32) vs Diagnoser(2.63) = **0.7 차이**
- 동일 champion인데 수치 불일치 → 계산 버그 or 버전 혼선

**위험/부작용:**
- 원인 미파악 시 모든 실험 결과 신뢰 불가

**실험 체크리스트:**
```
□ EXP-P5A: 두 스크립트의 입력 JSON diff
  - CMD: diff <(jq -S . handoff.json) <(jq -S . diagnoser_input.json)
  - PASS: 차이점 명확히 식별

□ EXP-P5B: oos_mean 계산식 단위 테스트
  - 게이트: 수동 계산값 vs 스크립트 출력
  - PASS: 오차 < 0.01

□ EXP-P5C: degenerate fold 포함/제외 분기 확인
  - 게이트: 포함 시 2.63, 제외 시 3.32 재현되는지
  - PASS: 원인 확정 후 단일 계산 방식 고정
```

## 🔍 성능 미동 원인 분해 트리

```
oos_mean 변화 없음
├─ [트리거] 시그널 미발동
│   └─ 확인: signal_count / day 로깅 → <1이면 문제
│
├─ [적용] 필터에서 걸러짐
│   └─ 확인: pre_filter vs post_filter 종목 수 비교
│
├─ [노출] position_size 너무 작음
│   └─ 확인: avg_position_weight < 5%면 의미 없음
│
├─ [비용] 수익 < 거래비용
│   └─ 확인: gross_return vs net_return 차이
│
└─ [레짐] 테스트 기간이 flat market
    └─ 확인: SPY 해당기간 수익률 ±3% 이내면 레짐 탓
```
