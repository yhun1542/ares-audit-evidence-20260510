## 🎯 TOP 5 우선순위 액션

### P1. Degenerate Fold 근본 원인 분리

**(a) 왜 필요한지**
- 4/10 fold 붕괴 = 전략이 특정 레짐에만 작동
- 이 상태로 실험 계속하면 "좋아 보이는 쓰레기"만 양산

**(b) 위험/부작용**
- 원인이 데이터(레짐)면 전략 자체 폐기 필요
- 원인이 코드버그면 과거 실험 전체 재검증 필요

**(c) 실험 체크리스트**
```
□ EXP-1A: Fold별 시계열 구간 + VIX/SPY 레짐 매핑
   → 붕괴 fold가 특정 레짐(예: 2022 금리인상기)에 집중?
   
□ EXP-1B: 동일 fold에서 "랜덤 시그널" 백테스트
   → 랜덤도 붕괴하면 = 레짐 문제 / 랜덤은 OK면 = 전략 문제
   
□ EXP-1C: Feature importance by fold
   → 붕괴 fold에서 특정 피처 가중치 폭발 여부
```

**(d) PASS 조건**
| Gate | Threshold |
|------|-----------|
| 원인 분류 완료 | 레짐/코드/전략 중 1개 확정 |
| 재현 가능 | 동일 조건 재실행 시 같은 fold 붕괴 |

---

### P2. 측정 파이프라인 무결성 복구

**(a) 왜 필요한지**
- `rebalance.csv` 파싱 실패 = 거래비용 미반영 가능
- MDD=None = 리스크 게이트 작동 안 함
- OOS Mean 불일치(3.32 vs 2.63) = 어느 숫자가 진실?

**(b) 위험/부작용**
- 수정 과정에서 과거 champion 기록 오염 가능
- 파이프라인 수정 = 모든 실험 재실행 필요할 수도

**(c) 실험 체크리스트**
```
□ EXP-2A: rebalance 로그 포맷 검증
   → JSON vs CSV 기대값 확인, 파싱 로직 수정
   
□ EXP-2B: MDD 계산 로직 dry-run
   → champion_v5에 수동 MDD 계산 후 비교
   
□ EXP-2C: OOS Mean 계산 경로 2개 비교
   → Handoff(3.32) vs Diagnoser(2.63) 코드 diff
```

**(d) PASS 조건**
| Gate | Threshold |
|------|-----------|
| rebalance 파싱 성공 | 에러 0 |
| MDD 숫자 출력 | None → 실수값 |
| OOS Mean 단일화 | 두 경로 차이 < 0.01 |

---

### P3. 비용 모델 현실화

**(a) 왜 필요한지**
- exposure 0→84% 스윙 = 대량 리밸런스 발생
- 비용 미반영 시 OOS 3.32 → 실제 1.x 가능성

**(b) 위험/부작용**
- 비용 반영 후 전략 수익 음전환 가능
- 과도한 비용 가정 시 실험 과소평가

**(c) 실험 체크리스트**
```
□ EXP-3A: 3-tier 비용 시뮬레이션
   - Conservative: 10bps RT
   - Moderate: 20bps RT  
   - Aggressive: 30bps RT + 0.5% slippage
   
□ EXP-3B: 턴오버 측정
   → 연간 turnover 계산, 비용 impact 정량화
```

**(d) PASS 조건**
| Gate | Threshold |
|------|-----------|
| 비용 반영 OOS | > 1.5 (moderate 기준) |
| 턴오버 | < 400% 연간 |

### P4. Exposure 0% 구간 진단

**(a) 왜 필요한지**
- exposure_min=0 = 시그널 완전 OFF 구간 존재
- 의도적 회피(레짐 필터)인지 버그인지 확인 필요

**(b) 위험/부작용**
- 정상 동작이면 수정 불필요
- 버그면 백테스트 전체 왜곡

**(c) 실험 체크리스트**
```
□ EXP-4A: exposure=0 구간 시계열 추출
   → 해당 날짜의 시장 상황/필터 상태 확인
   
□ EXP-4B: 필터 비활성화 후 해당 구간 성과
   → 필터가 실제로 손실 회피했는지 검증
```

**(d) PASS 조건**
| Gate | Threshold |
|------|-----------|
| 0% 구간 비율 | < 20% of total days |
| 필터 효과 | 해당 구간 buy&hold 대비 손실 회피 확인 |

### P5. Survivorship/Look-ahead 오염 체크

**(a) 왜 필요한지**
- Tech+Healthcare 8~14종목 = 현재 생존자 기준 선정 가능성
- 상장폐지/M&A 종목 누락 시 OOS 과대평가

**(b) 위험/부작용**
- 검증 시 데이터 소스 전환 필요 (비용/시간)
- 심각하면 전체 유니버스 재구축

**(c) 실험 체크리스트**
```
□ EXP-5A: 유니버스 종목의 IPO/상폐 날짜 확인
   → 백테스트 시작일 이전 IPO인지 검증
   
□ EXP-5B: Point-in-time 유니버스 1개 기간 샘플
   → 2020-01-01 기준 S&P500 Tech+Healthcare vs 현재
```

**(d) PASS 조건**
| Gate | Threshold |
|------|-----------|
| 생존자 편향 종목 | 0개 |

```bash

python3 experiment_system/tools/aub_rebalance_pinpoint.py \

  --champion baseline/champion_v5_latest.json \
  --output reports/fold_regime_map.csv

# 3. MDD 수동 계산
python3 -c "
import json
with open('baseline/champion_v5_latest.json') as f:
    d = json.load(f)
    eq = d.get('equity_curve', [])
    if eq:
        peak = eq[0]
        mdd = 0
        for v in eq:
            peak = max(peak, v)
            mdd = min(mdd, (v-peak)/peak)
        print(f'MDD: {mdd:.4f}')
"
```
