### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### PRIORITY #1: Degenerate Fold 근본 원인 제거
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한가**
- 40% 폴드 무효 = OOS 신뢰도 60%로 하락
- 특정 시장구간(아마 2022 bear, 2020 COVID)에서 시그널 완전 실패 의심
- 이 상태로 개선해봤자 과최적화만 심화

**(b) 위험/부작용**
- 원인이 데이터면 해결 가능 / 전략 구조면 대수술 필요
- 폴드 기준 변경 시 모든 실험 재실행 필요

**(c) 실험 체크리스트**

```
┌─────────────────────────────────────────────────────────────────┐
│ EXP-1A: Degenerate Fold 해부                                    │
├─────────────────────────────────────────────────────────────────┤
│ □ 실행: fold별 (시작일, 종료일, 레짐, 평균수익률) 추출          │
│ □ 게이트: degenerate 폴드가 특정 레짐에 집중되는가?             │
│ □ 기대: fold 1,2,3=2020-2022 구간 집중 시 레짐필터 적용 근거    │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│ EXP-1B: Min-Trade Threshold 완화                                │
├─────────────────────────────────────────────────────────────────┤
│ □ 실행: degenerate 판정 기준 (현재값 확인 → 50% 완화 테스트)    │
│ □ 게이트: 완화 시 폴드 생존율 증가 but 노이즈 수익 혼입 확인    │
│ □ 기대: degenerate 2개 이하로 감소                              │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│ EXP-1C: Exposure Floor 강제 적용                                │
├─────────────────────────────────────────────────────────────────┤
│ □ 실행: min_exposure=0.15 강제 (완전현금 금지)                  │
│ □ 게이트: 폴드 생존율 vs 수익률 trade-off 측정                  │
│ □ 기대: exposure_min 0.0→0.15, degenerate -2개                  │
└─────────────────────────────────────────────────────────────────┘
```

**(d) PASS 조건**
```
✓ degenerate_folds ≤ 2 AND oos_mean ≥ 2.0 AND oos_min > -0.05
```

### PRIORITY #2: 측정 인프라 복구 (Rebalance Log)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한가**
- 비용 미반영 상태로 수익률 계산 중일 가능성
- Turnover, 슬리피지, 세금 효과 분석 불가
- "좋아 보이는 숫자"가 실현 불가능할 수 있음

**(b) 위험/부작용**
- 로깅 추가 시 실행 속도 10~20% 저하 가능
- 과거 실험 비교 불가 (기준선 재설정 필요)

**(c) 실험 체크리스트**

```
┌─────────────────────────────────────────────────────────────────┐
│ EXP-2A: Rebalance Logger 복구                                   │
├─────────────────────────────────────────────────────────────────┤
│ □ 실행: backtester.py에서 rebalance 이벤트 로깅 코드 확인/복구  │
│ □ 게이트: champion 1회 실행 후 CSV/JSONL 생성 확인              │
│ □ 기대: 파일 존재 + row count = trading_days * rebal_freq       │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│ EXP-2B: 비용 시뮬레이션 계층 추가                               │
├─────────────────────────────────────────────────────────────────┤
│ □ 실행: rebalance log 기반 (turnover × 0.1% 슬리피지) 차감      │
│ □ 게이트: 비용 반영 전후 oos_mean 차이 계산                     │
│ □ 기대: 비용 반영 후 oos_mean 감소폭 < 0.3 (허용범위)           │
└─────────────────────────────────────────────────────────────────┘
```

**(d) PASS 조건**
```
✓ rebalance.csv 생성 AND row_count > 0 AND cost_adjusted_oos > 2.0
```
