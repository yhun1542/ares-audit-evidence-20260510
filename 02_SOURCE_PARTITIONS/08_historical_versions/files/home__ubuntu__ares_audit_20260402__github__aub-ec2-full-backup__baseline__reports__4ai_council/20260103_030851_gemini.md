### 1. Degenerate Folds(1, 2, 3, 8) 긴급 디버깅 및 Normalization 점검
**(a) 왜 필요한지:**
현재 `degenerate_folds`가 4개(전체의 약 40~50%) 발생. 이는 해당 Fold에서 모델이 거래를 전혀 하지 않거나(Flat), 손실 방지 로직이 시작 즉시 트리거되어 `NaN` 혹은 `0.0` 상수만 뱉고 있음을 의미. 이 상태의 `OOS Mean 3.32`는 통계적 유의성이 전혀 없음(운 좋게 터진 1~2개 Fold의 결과일 확률 99%).

**(b) 위험/부작용:**
- 모델의 실제 성능이 현재보다 대폭 하락할 수 있음(거품 제거).
- 학습 파이프라인이 일시적으로 중단될 수 있음.

**(c) 실험 정의 (48h Loop):**
1.  **EXP_FIX_NORM_CLIPPING:** 입력 데이터 정규화(Z-score) 시 Outlier Clipping을 기존 3.0에서 5.0으로 완화하거나, RobustScaler로 교체. (데이터 스파이크로 인한 학습 붕괴 방지)
2.  **EXP_FORCE_MIN_TRADE:** 각 Fold별 최소 거래 횟수(예: 10회)를 강제하는 Penalty term 추가. (학습 초기 `Action=0` 수렴 방지)
3.  **EXP_NAN_FILL_STRATEGY:** 데이터 전처리 시 `NaN` 처리 방식을 `ffill`에서 `linear_interpolate` 혹은 `0`으로 변경하여 비교.

**(d) PASS 조건:**
- `degenerate_folds` 개수 = 0.
- `oos_min` > 0.0 (최소한 모든 Fold에서 손실은 면할 것).
- `worst_mdd`가 `None`이 아닌 유효한 수치로 계산될 것.

### 2. Tech+Healthcare Universe 강제 및 ETF 배제 로직 삽입
**(a) 왜 필요한지:**
현재 상태 메시지에 종목 구성 정보가 부재하나, `worst_mdd: None`은 포트폴리오 구성 실패 가능성을 시사. ETF 매매 금지 및 Tech/Healthcare 8~14종목 집중이라는 [절대 규칙]을 코드 레벨에서 하드코딩된 필터로 보장해야 함.

**(b) 위험/부작용:**
- 종목 풀 축소로 인한 분산 효과 감소 및 변동성 증가.
- 특정 섹터(Tech) 하락장 시 MDD 급증.

**(c) 실험 정의 (48h Loop):**
1.  **EXP_SECTOR_STRICT_12:** Universe를 `XLK`(Tech), `XLV`(Healthcare) 상위 구성 종목 중 유동성 상위 12개로 고정(ETF 티커 제외).
2.  **EXP_RSI_FILTER_TECH:** Tech/Health 종목 중 RSI(14) < 30 (과매도) 혹은 > 70 (과매수) 구간에서만 진입/청산하도록 게이트 설정.
3.  **EXP_CORRELATION_CAP:** 포트폴리오 내 종목 간 상관계수 평균이 0.7 이상일 경우, 현금 비중을 늘리는 로직 추가.

**(d) PASS 조건:**
- 포트폴리오 구성 종목 수: 8 <= N <= 14.
- ETF 보유 비중 = 0%.
- 섹터 비중: Tech + Healthcare >= 90%.

### 3. 로깅 인프라 복구 (Rebalance Log Fix)
**(a) 왜 필요한지:**
`[Errno 2] No such file` 및 `JSON parsing error` 발생 중. 리밸런싱 로그가 없으면 슬리피지, 수수료, 실제 체결 오차를 추적할 수 없음. 2026년 시점(가상)에서 Blind Trading은 자살행위임.

**(b) 위험/부작용:**
- 로깅 오버헤드로 인한 백테스팅 속도 저하(미미함).

**(c) 실험 정의 (48h Loop):**
1.  **SYS_LOG_JSONL_FORMAT:** `rebalance.csv` 대신 `rebalance.jsonl`로 로깅 포맷을 일원화하고, Atomic Write(파일 잠금 후 쓰기) 구현.
2.  **SYS_BASE_LOG_GENERATOR:** 기준 로그(`--base-log`)가 없을 경우, 빈 템플릿을 생성하여 에러를 우회하고 다음 스텝을 진행시키는 Fallback 로직 추가.
3.  **SYS_METRIC_VALIDATOR:** MDD, Sharpe 계산 시 `ZeroDivisionError` 예외 처리 및 `None` 반환 대신 `-999` 등의 에러 코드 반환으로 디버깅 용이성 확보.

**(d) PASS 조건:**
- `aub_rebalance_pinpoint.py` 실행 시 에러 코드 0 반환.
- 생성된 리포트에 Rebalance Diff(비중 차이)가 시각화될 것.

### [성능 정체 시 원인 분해 아이디어]

성능이 움직이지 않거나(Flat), 개선되지 않을 때 다음 트리를 점검:

1.  **트리거(Trigger) 불발:**
    *   *현상:* 매매 신호 자체가 0으로 수렴.
    *   *진단:* Feature Scaling이 너무 커서 NN의 Activation Function이 Saturation(포화) 상태인지 확인.
    *   *조치:* Input Layer에 Batch Normalization 추가.

2.  **노출(Exposure) 제한:**
    *   *현상:* 신호는 있는데 포지션이 0.01 수준.
    *   *진단:* Volatility Targeting이나 Risk Parity 로직이 현재 시장 변동성(VIX)을 너무 높게 평가하여 사이즈를 강제로 축소시켰는지 확인.
    *   *조치:* 변동성 목표치(Target Vol) 상향 조정(예: 10% -> 15%).

3.  **비용(Cost) 장벽:**
    *   *현상:* Gross Profit은 우상향이나 Net Profit은 횡보/하락.
    *   *진단:* 잦은 리밸런싱으로 인한 수수료 누적.
    *   *조치:* Turnover Constraint 강화 (전일 대비 비중 변화 합계 < 10% 등으로 제약).

4.  **레짐(Regime) 불일치:**
    *   *현상:* 특정 기간(Fold)만 박살남.
    *   *진단:* 2022년 하락장이나 2020년 코로나 같은 특수 구간 데이터가 Validation set에 포함되어 있는지 확인.
    *   *조치:* Regime Filter 도입 (장기 이평선 아래에서는 매수 금지).
