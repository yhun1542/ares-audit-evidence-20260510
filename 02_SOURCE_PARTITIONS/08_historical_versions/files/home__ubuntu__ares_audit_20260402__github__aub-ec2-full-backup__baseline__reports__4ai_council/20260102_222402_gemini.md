[우선순위 TOP 5 제안 - 48시간 내 수행]

### 1. Degenerate Folds(1, 2, 3, 8) 데이터 정합성 긴급 패치
*   **(a) 필요성:** 전체 Fold의 40%가 붕괴(degenerate)된 상태에서 OOS Mean 3.32는 통계적 착시임. 특정 연도/특정 종목의 데이터 누락이 전체 로직을 셧다운시켰을 가능성 높음.
*   **(b) 리스크:** '가짜 알파'가 사라지며 OOS Mean이 급락할 수 있음. (정상화 과정)
*   **(c) 실험:**
    *   `Exp_Data_Valid`: Tech/Healthcare 12개 종목 중, Fold 1,2,3,8 기간(초기 연도 추정)에 상장되지 않았거나 데이터가 비어있는 종목을 유니버스에서 제외.
    *   `Exp_Fill_Forward`: NaN 데이터 발생 시 'Hold' 처리가 아닌, 강제 청산(Cash 100%) 로직 삽입.
*   **(d) PASS 조건:** `degenerate_folds` 리스트가 Empty여야 함. OOS Mean > 1.0 유지.

### 2. `worst_mdd: None` 메트릭 계산기 수정 및 로깅 복구
*   **(a) 필요성:** 리스크 계측 불가능 상태. MDD가 None이라는 것은 Equity Curve가 Monotonic 하거나(버그), 계산 로직이 `NaN`을 뱉고 있다는 뜻. Rebalance Log 파싱 에러도 동시에 해결해야 디버깅 가능.
*   **(b) 리스크:** 시스템 셧다운(코드 에러로 인한).
*   **(c) 실험:**
    *   `Fix_MDD_Calc`: 수익률 배열에 `np.nan_to_num` 적용 후 MDD 재계산 로직 배포.
    *   `Log_Format_Patch`: `rebalance.csv` 생성 시 JSONL 형식이 아닌 표준 CSV 헤더/포맷 강제 적용.
*   **(d) PASS 조건:** `worst_mdd`가 숫자(float)로 출력될 것. `aub_rebalance_pinpoint` 툴이 에러 없이 실행될 것.

### 3. Look-ahead Bias(미래 참조) 스트레스 테스트
*   **(a) 필요성:** OOS Mean 3.32는 현실적이지 않음. 시가/종가 혼용, 혹은 리밸런싱 시점(T)에 T+1 데이터를 참조하는지 확인 필수.
*   **(b) 리스크:** 전략 폐기 수준의 성능 하락 가능성.
*   **(c) 실험:**
    *   `Exp_Lag_1`: 모든 Feature 입력에 `shift(1)` 강제 적용.
    *   `Exp_Open_Execution`: 종가(Close) 매매를 익일 시가(Open) 매매로 변경하고 슬리피지 10bps 추가.
*   **(d) PASS 조건:** `Exp_Lag_1`의 OOS Mean이 `Base` 대비 50% 이상 유지될 것 (완전 붕괴 시 누수 확정).

### 4. 고비용 구조 반영 (Slippage/Transaction Cost 2배 적용)
*   **(a) 필요성:** Tech/Bio 섹터 변동성 고려 시 현재 비용 설정이 과소 평가되었을 가능성. `exposure_max`가 0.83인데 수익이 비정상적으로 높음.
*   **(b) 리스크:** 회전율(Turnover)이 높은 전략일 경우 손익분기점 미달 발생.
*   **(c) 실험:**
    *   `Exp_Cost_Double`: 편도 수수료/슬리피지 합산을 기존 설정의 2배(예: 10bps -> 20bps)로 설정.
    *   `Exp_Min_Holding`: 최소 보유 기간 3일 강제 (과도한 매매 방지).
*   **(d) PASS 조건:** 연율화 수익률(CAGR)이 MDD의 2배 이상 유지.

### 5. ETF 관측 기반 Regime Filter 민감도 조절
*   **(a) 필요성:** `exposure_min`이 0.0임. 하락장에서 현금 비중 100%로 방어했는지, 아니면 시그널이 안 나와서 쉬었는지 확인 필요. QQQ/XLV(Healthcare) 변동성 지표를 Trigger로 사용.
*   **(b) 리스크:** 과도한 필터링으로 인한 기회 비용 발생 (Trade 횟수 급감).
*   **(c) 실험:**
    *   `Exp_Regime_Loose`: 시장 변동성(VIX 등) 임계값을 완화하여 Exposure 빈도를 20% 증가시킴.
    *   `Exp_Sector_Hedge`: QQQ가 20일 이평선 하회 시, 개별 종목 매수 비중 50% 축소 (Stop-loss 강화).
*   **(d) PASS 조건:** `exposure_mean` > 0.4 (현재 너무 낮음), MDD < 15%.

[48시간 자동 루프 정의]

**Cycle 1: 데이터/메트릭 무결성 확보 (Degenerate Fix)**
1.  **실험 정의:** `fold_fix_v1` - Fold 1,2,3,8 기간에 데이터가 없는 Ticker(신규 상장 등)를 유니버스에서 제거하거나 Zero Padding 처리. MDD 계산 함수에 예외처리 추가.
2.  **게이트:** `degenerate_folds == []` AND `worst_mdd is not None`.
3.  **기대 관측치:** OOS Mean은 3.32에서 1.5~2.0 수준으로 하락하더라도, 전 구간에서 매매가 발생하는지 확인.

**Cycle 2: 누수 점검 및 비용 현실화 (Leakage Check)**
1.  **실험 정의:** `lag_test_v1` - Feature Shift(1) 적용 및 슬리피지 15bps 설정.
2.  **게이트:** OOS Mean > 1.2 AND Sharpe > 1.0.
3.  **기대 관측치:** 기존 Champion 대비 성능이 30% 이상 급락한다면, 기존 모델은 폐기하고 이 버전을 Baseline으로 재설정.

**Cycle 3: 포트폴리오 비중 최적화 (Exposure Tune)**
1.  **실험 정의:** `exposure_boost_v1` - Tech/Healthcare 8종목 고정, Cash 비중 최대 30%로 제한 (Min Exposure 0.7).
2.  **게이트:** MDD < 20% (공격적 운영 시 리스크 허용 범위 내인지).
3.  **기대 관측치:** 상승장에서의 Alpha capture 능력 확인 (벤치마크 대비 초과 수익).

    *   *Check:* ETF 지표(QQQ MA 등)가 'Bear Market'으로 오판하여 모든 매수를 막고 있는지 확인.
3.  **Exposure (체결 비중):** 주문은 나갔는데 자금 관리(Position Sizing) 룰에 의해 비중이 0.0xxx로 수렴했는가?

4.  **Cost (비용 잠식):** 잦은 매매로 인한 수수료 누적으로 PnL이 0 근처를 맴도는가?
    *   *Check:* Gross Profit vs Net Profit 괴리율 확인.
5.  **Regime (시장 국면):** 현재 백테스트 구간이 Tech/Bio 섹터가 횡보하는 구간인가?
    *   *Check:* 유니버스 평균 수익률(Equal Weight)과 전략 수익률 비교.
