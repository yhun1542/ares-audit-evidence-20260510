# 1) 우선순위 TOP5 제안 (코드/아키텍처/전략)

### (a) 왜 필요한지
- 현재 rebalance pinpoint가 작동 불가 → **노출/회전율/비용/신호 적용** 중 어디가 문제인지 분해가 안 됨.

### (b) 위험/부작용
- 로깅이 늘어 디스크/IO 증가(비용).  
- 잘못 설계하면 성능 저하(특히 per-bar detail logging).

### (c) 최소 실험(아래 공통 실험에서 선택)
- **[E1] 아티팩트/리밸런스 로깅 표준화**
- **[E4] 비용/회전율 로깅 함께 강제** (비용이 “숫자로” 남도록)

### (d) PASS 조건
- 모든 run에서 다음이 **항상 존재**:  
  `run_hash`, `lane_hash`, `rebalance.jsonl(or csv)`, `metrics.json`(worst_mdd 포함), `positions_timeseries`(요약이라도).
- `aub_rebalance_pinpoint.py`가 **base/cand 모두**에서 에러 없이 리포트 생성.

## TOP2. (누수/과최적화) Degenerate fold 제거 + Purge/Embargo + “폴드 건강도 게이트”
### (a) 왜 필요한지
- `degenerate_folds`가 다수면 OOS_mean이 좋아도 **가짜 성능**일 확률이 큼(분할 오류/라벨 누수/거래 불발로 상수 수익 등).
- “성능이 안 움직임” 현상은 종종 **게이트가 너무 빡세서 트레이드가 거의 없는** 경우에도 발생.

### (b) 위험/부작용
- 폴드/샘플이 줄어 성능 수치가 일시적으로 악화(하지만 “진짜”에 가까워짐).
- purge/embargo 적용으로 학습 데이터 감소.

### (c) 최소 실험
- **[E2] Fold Health Gate + Purge/Embargo 강제**
- **[E5] 노출/트레이드 수 게이트 추가**(“안 움직임”을 거래 빈도로 판정)

### (d) PASS 조건
- `degenerate_folds == []`
- 폴드별: 트레이드 수/일, 분산(returns std), 노출 평균이 **최소 기준 이상**
- OOS_mean이 소폭 하락하더라도 **OOS_min 급락 방지 + 분산 정상화**가 확인되면 통과(“진짜화” 우선)

## TOP3. (서바이버십/유니버스) “미국 Tech+Healthcare 8~14”를 Point-in-time로 고정 (ETF는 관측만)
### (a) 왜 필요한지

- ETF 매매를 막았더라도, ETF가 유니버스에 섞이거나 ADR/비미국이 섞이면 정책 위반+왜곡.

### (b) 위험/부작용
- 종목 수 제약(8~14)으로 분산이 줄어 MDD 악화 가능.
- Point-in-time 데이터가 무거워 빌드/런타임 증가.

### (c) 최소 실험
- **[E3] PIT 유니버스 + 섹터(Tech/Healthcare) 필터 + ETF/ADR/비미국 제거**
- **[E2]와 결합**(폴드 문제와 유니버스 문제를 동시에 배제)

### (d) PASS 조건
- 매일 생성되는 universe 스냅샷에 대해:
  - (1) 미국 상장 보통주 only  
  - (2) Tech/Healthcare 비중 100%(룰 기반)  
  - (3) 종목 수 8~14 고정(부족 시 현금 비중 증가로 처리)  
  - (4) delisted 포함 backtest 가능(서바이버십 방지)
- 섹터 드리프트/룰 위반이 0건.

## TOP4. (비용 미반영) 거래비용/슬리피지/회전율을 “게이트에 포함”
### (a) 왜 필요한지
- “성능이 안 움직임”은 비용이 이익을 잠식해서 **net이 0 근처로 붙는** 전형적 패턴.
- 특히 8~14 종목 집중이면 리밸런스/턴오버가 성능을 결정.

### (b) 위험/부작용
- 비용 모델을 보수적으로 잡으면 성능이 급락(하지만 운영 현실과 일치).
- 과도한 turnover penalty는 신호를 죽임(언더트레이딩).

### (c) 최소 실험
- **[E4] 비용모델(스프레드+임팩트+수수료) + 회전율 로깅 + turnover gate**
- **[E1]**로 비용/체결 관련 아티팩트가 남도록 보장

### (d) PASS 조건
- gross→net 전환 시 손실의 원인이 **비용 항목별로 분해 가능**(spread/impact/fees).
- net OOS_mean이 챔피언 대비 소폭 낮아져도,
  - net OOS_min 악화가 제한되고
  - turnover가 운영 가능한 상한 이하로 내려오면 PASS.

### (c) 최소 실험

### (d) PASS 조건

# 2) 48시간 자동 루프용: 실행 가능한 Patch/실험 (총 5개로 제한)
각 실험은 **(1) 실험 정의 → (2) 게이트 → (3) 기대 관측치** 형식.

---

## [E1] 아티팩트/리밸런스 로깅 표준화 패치
1) **실험 정의**
- 모든 run에 대해 다음을 강제 출력:
  - `run_hash`, `lane_hash`
  - `rebalance.jsonl`(라인당 리밸런스 이벤트: ts, symbol, target_w, exec_w, px, qty, reason)
  - `metrics.json`(oos_mean/oos_min/worst_mdd/exposure_minmax/turnover_gross/net 등)
  - `positions_daily.csv`(date,symbol,weight,notional) 최소 일단위 요약
- `aub_rebalance_pinpoint.py`가 읽는 포맷을 고정(“csv/ jsonl 둘 중 하나로 통일”).

2) **게이트**
- 파일 누락/파싱 실패 시 run을 **자동 FAIL** 처리(챔피언 승격 금지).
- `worst_mdd is None` 이면 FAIL.

3) **기대 관측치**
- pinpoint/diagnoser 리포트가 매번 생성.
- “성능 정체” 케이스에서 **리밸런스 이벤트 수=0** 같은 즉시 원인 발견 가능.

---

## [E2] Fold Health Gate + Purge/Embargo(누수 방지) + degenerate fold 제거
1) **실험 정의**
- 시계열 CV에 purge/embargo 적용(라벨/피처 lookahead 차단).
- 각 fold에 대해 건강도 지표를 계산:
  - fold별 트레이드 수, 평균 노출, 일수익 분산, 결측률, 종목 수 분포(8~14 유지 여부)
- `degenerate` 판정(예: returns std가 매우 작거나 트레이드 수 극저)을 자동 검출하고 해당 fold는 점수 계산에서 제외가 아니라 **run FAIL**로 처리(원인 수정 유도).

2) **게이트**
- `degenerate_folds == []`
- fold별 `trade_count >= N_min`, `returns_std >= s_min`, `avg_exposure >= e_min` (임계값은 코드에 상수로 두고 변경은 PR로만)

3) **기대 관측치**
- OOS_mean이 “덜 화려”해져도 분산/최저치가 정상화.
- 더 이상 폴드 일부가 상수/무거래로 끌어올린 허상이 발생하지 않음.

---

## [E3] Point-in-time 유니버스(미국 Tech+Healthcare, 8~14) + 서바이버십 방지
1) **실험 정의**
- 유니버스 생성 로직을 PIT로 고정:
  - US common stock only(ADR/OTC/ETF 제외)
  - 섹터 Tech+Healthcare만 (GICS/SIC 중 하나를 PIT로)
  - 일별 후보군에서 유동성/가격/거래정지 필터 후 상위 N(8~14) 확정
  - delisted 종목/과거 구성 포함 가능하도록 데이터 소스 연결(가능 범위 내)
- ETF(예: QQQ/XLK/XLV)는 **지표 테이블로만** 별도 유지(거래 대상 포함 금지 테스트 추가).

2) **게이트**
- 매일 universe 스냅샷 검사:
  - ETF 포함 0건, 비미국 0건, ADR 0건
  - 종목 수 8~14 유지(부족 시 현금 처리 기록)
- “과거 날짜의 섹터/상장상태”가 미래정보를 쓰지 않았음을 PIT 검사로 assert.

3) **기대 관측치**
- 성능 변동의 원인이 “유니버스 변조/생존편향”이었는지 즉시 판별 가능.
- 실험 간 비교에서 전략 효과가 더 선명해짐(재현성↑).

---

## [E4] 비용/슬리피지/회전율 모델링 + turnover gate
1) **실험 정의**
- 체결 비용을 net PnL에 반영:
  - 고정 수수료(share 또는 notional)
  - bid-ask spread(일별/종목별 근사)
  - 단순 market impact(예: k * (participation_rate)^alpha 형태, 최소 버전)
- `turnover_gross`, `turnover_net`, 비용 항목별 합계를 로그에 남김.

2) **게이트**
- turnover가 상한 초과 시 FAIL(운영 불가 전략 차단).
- gross→net 감소분이 “비용 로그”로 95% 이상 설명되지 않으면 FAIL(비용 누락 의심).

3) **기대 관측치**
- 성능이 안 움직이면(특히 net이 0 근처) “비용이 원인”인지 즉시 확정.
- 회전율을 낮추는 쪽으로 자동 선택 압력이 생김.

---

## [E5] 레짐 관측(ETF는 지표만) + 노출 타게팅(변동성/드로우다운)
1) **실험 정의**
- ETF를 거래하지 않고 관측 지표로만 사용:
  - 예: QQQ(성장/리스크온), XLK(Tech), XLV(Healthcare), IHI(메드텍) 등
- 레짐별 노출 규칙(최소 버전):
  - risk-off(지표 하락/변동성↑)에는 목표 노출 축소
  - risk-on에는 목표 노출 확대(단, 상한 유지)
- 포지션 수(8~14) 유지하되, 신호 약하면 현금 비중 증가를 “명시적으로 기록”.

2) **게이트**
- “무거래/저노출 정체” 방지:
  - 일정 기간(예: 최근 K일) 평균 노출이 너무 낮거나 트레이드가 0이면 FAIL(전략이 죽었다는 신호)
- worst_mdd 계산 필수(E1과 연동).

3) **기대 관측치**
- 성능 정체가 “신호 약함→현금”인지, “신호는 있으나 비용/상쇄”인지 분리됨.
- OOS_min 또는 worst_mdd 중 최소 하나 개선.

---

# 3) 성능이 안 움직일 때: 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래는 “원인 분해를 자동화”하기 위한 **명령형 체크리스트**(질문 없음).

## A. 트리거(신호 생성) 문제 분해
- [ ] 신호 시계열 분산(표준편차)과 순위 변동률(rank turnover)을 로그로 저장하라.  
- [ ] 예측/스코어가 상수에 가까우면 즉시 FAIL(데이터 결손/정규화 버그/누수 차단 후 붕괴 가능).  
- [ ] 피처-라벨 시차를 강제 assert(lookahead 방지). purge/embargo 적용 후 신호 분산이 0으로 붕괴하면 “누수 제거로 정상화”로 판정하라.

## B. 적용(포트폴리오 구성/리밸런스) 문제 분해
- [ ] “목표 비중(target_w)”과 “실행 비중(exec_w)”을 모두 기록하라(E1).  
- [ ] 리밸런스 이벤트 수가 0이면: 게이트/필터(유니버스 부족, 신호 임계값, 리스크 오버레이) 중 어디서 막혔는지 reason 코드를 남겨라.  
- [ ] 종목 수(8~14) 위반/부족 빈도를 기록하고, 부족 시 현금 처리로 성과 정체가 발생했는지 분리하라.

## C. 노출(현금/레버리지/섹터 편중) 문제 분해
- [ ] 일별 평균 노출, 롱/숏 노출(있다면), 상위 1~3개 종목 기여도를 저장하라.  
- [ ] 노출이 너무 낮아 수익이 안 나는지 vs 노출은 있는데 PnL이 상쇄되는지 구분하라.  
- [ ] “현금 비중 증가 이벤트”를 전략적 선택인지(레짐 필터) 오류인지(유니버스 부족) 태깅하라.

## D. 비용(턴오버/슬리피지) 문제 분해
- [ ] gross PnL과 net PnL 차이를 비용 항목별로 분해해 저장하라(E4).  
- [ ] turnover와 net 성과의 상관을 리포트로 출력하라(고회전에서만 먹는 전략인지 확인).  
- [ ] 비용이 과대/과소추정이면 “민감도 실험(비용 0.5x/1x/2x)”을 자동으로 한 번만 돌려 경계값을 잡아라(케이스 폭발 없이 3점만).

## E. 레짐(시장 상태) 문제 분해
- [ ] ETF(지표) 기반으로 레짐을 2~3개로만 라벨링(risk-on/off/neutral)하고, 레짐별 성과/노출/턴오버를 분리해 출력하라.  
- [ ] 레짐 필터가 성과를 올리는지, 단지 트레이드를 줄여 “정체처럼 보이게” 만드는지(트레이드 수/노출 게이트로) 검증하라(E5).

## 최종 실행 순서(24~48h) — 명령형 체크리스트
1) [ ] **E1** 먼저 머지/적용 → rebalance pinpoint/diagnoser가 항상 돌아가게 고정  
2) [ ] **E2** 적용 → degenerate fold 0 달성(누수/분할 붕괴 제거)  
3) [ ] **E3** 적용 → PIT 유니버스/서바이버십/ETF 제외 준수 증명
