## 즉시 관측된 결함(ONE TRUTH 기반) — 지금 바로 막아야 할 리스크
- **아티팩트(file) 경로가 비어있음** → 재현/롤백 불가(운영 리스크 최상위).
- **worst_mdd=None** → 리스크 지표 미계산(과최적화/테일리스크 은폐 가능).
- **Next Commands 비어있음** → 48시간 자동 루프가 “다음 액션” 없이 정지 상태.
- **exposure 0.47~0.84** → 노출이 구조적으로 높음(비용/레짐 역풍 시 손상 확대).

# 1) 다음 24~48시간 우선순위 TOP5 (코드/아키텍처/전략)
아래는 **각 항목 1개 “필수 실험”**으로 구성(총 5개)하며, 모두 **48시간 자동 루프**로 돌릴 수 있게: **(1) 실험 정의 → (2) 게이트 → (3) 기대 관측치** 형태로 제시.

---

## TOP1) 누수/서바이버십 “타임트래블 차단” 패치 (최우선)
### (a) 왜 필요한지
- OOS가 좋아도 **미세 누수(특히 종가/정정 데이터/기업행사 반영 시점)**면 성능은 허상.
- Tech/Healthcare 대형주라도 **지수편입/상장폐지/심볼 변경**으로 서바이버십 편향 발생 가능.

### (b) 위험/부작용
- 누수 차단 후 **성능 급락** 가능(정상 반응).
- 데이터 로더가 느려져 **실행시간 증가**.

### (c) 최소 실험(필수 1개)
**[실험 #1: “Future-Shift Sanity + Timestamp Guardrail”]**
1) 실험 정의  
- 모든 피처/라벨 생성 단계에 **timestamp(생성시점) 메타**를 붙여, 주문 의사결정 시각(T)에서 **T 이후 정보 접근 시 즉시 실패**시키기(하드 에러).  
- 추가로 백테스트를 1회 더 돌려 **피처를 +1 거래일 미래로 시프트**(미래정보 주입)했을 때 성능이 과도하게 상승하는지 / **-1로 시프트**했을 때 성능이 붕괴하는지 기록.
2) 게이트  
- (필수) **Timestamp 위반 0건**  
- (필수) “-1 shift”에서 oos_mean이 **유의하게 하락**(예: 50% 이상 감소)해야 정상  
- (필수) “+1 shift”에서 oos_mean이 **비정상 급등(예: 2배 이상)**하면 누수 경보로 분류하고 차단 지점 로그 출력
3) 기대 관측치  
- 정상 시스템이면 **-1 shift는 성능 붕괴**, +1 shift는 상승(하지만 그 상승이 “가능”한 정도로만)  
- 현재 챔피언이 누수면: shift 테스트에서 **이상 패턴(shift 무감/반대)**이 나옴

### (d) PASS 조건
- 타임스탬프 위반 0 + shift 진단이 정상 패턴 + 누수 의심 로그 0건.

## TOP2) 과최적화 방지: Purged Walk-Forward + Embargo로 CV 교체
### (a) 왜 필요한지
- 일반 K-fold/랜덤 분할은 **시계열 누수**를 유발(특히 금융).
- “degenerate_folds=[]”가 지금은 깨끗해 보이지만, **분할 설계가 잘못되면 깨끗해도 의미 없음**.

### (b) 위험/부작용
- OOS 성능이 낮아져 보일 수 있음(현실 반영).
- 튜닝 공간이 줄어 “개선” 속도가 느려짐.

### (c) 최소 실험(필수 1개)
**[실험 #2: Purged Walk-Forward CV로 챔피언 재평가]**
1) 실험 정의  
- 학습/검증 구간 사이에 **purge window(예: 5~20 거래일)** + **embargo(예: 5 거래일)** 적용.  
- 모델 선택/하이퍼파라미터는 이 CV 결과만 사용(기존 스킴 결과는 참고 로그로만).
2) 게이트  
- 폴드별 oos_mean 분산이 **기존 대비 증가하더라도** “최악 폴드”가 과도하게 붕괴하지 않을 것(oos_min이 **0.43 → 0.30 미만으로 급락**하면 경고)  
- 폴드 간 성능 편차 상위 10% 절단 평균(Trimmed mean)도 함께 로그.
3) 기대 관측치  
- 과최적화가 있으면: 평균은 비슷해도 **최악 폴드(oos_min)**가 더 나빠지거나, 평균이 의미 있게 하락  
- 견고하면: 평균이 다소 낮아져도 **최악 폴드가 안정**

### (d) PASS 조건
- Purged WF 기준 oos_mean이 **-15% 이내 하락**이며, oos_min이 **0.30 이상 유지**(예시 임계).

## TOP3) 비용 미반영 제거: 슬리피지/스프레드 기반 비용 모델 + 회전율 게이트
### (a) 왜 필요한지
- Tech/Healthcare라도 전략이 빈번히 뒤집히면 **비용이 알파를 삼킴**.
- 비용 미반영은 “좋은 백테스트”의 최다 원인.

### (b) 위험/부작용
- 단기 신호/고회전 전략이 즉시 무력화될 수 있음.
- 비용 파라미터가 과보수면 “과소거래”로 이어짐.

### (c) 최소 실험(필수 1개)
**[실험 #3: ATR·달러거래대금 기반 비용 모델 + Turnover Gate]**
1) 실험 정의  
- 거래비용 = (고정 커미션) + (스프레드 추정) + (임팩트)  
  - 스프레드/임팩트는 **ATR%**와 **$ADV(20일 평균 달러 거래대금)**로 근사(ADV 낮을수록 비용↑).  
- 포트폴리오 **일간/주간 turnover** 계산 후, turnover가 임계 초과 시 신호를 감쇠하거나 리밸런싱 주기 늘리기(예: “주 2회 리밸런스” 강제).
2) 게이트  
- 비용 반영 후 oos_mean이 **-25% 이상 급락**하면: 기존 성능의 비용 의존도가 높다고 판정(전략 구조 수정 트랙으로 이동)  
- 비용 반영 후에도 oos_mean이 버티면서 **turnover가 목표 범위로 내려가야 함**(예: 일간 20%→10% 이하)
3) 기대 관측치  
- 현실적이면: 성능은 내려가도 **더 안정적(테일/최악구간 개선)**인 방향으로 변함  
- 과거가 허상이면: 성능이 크게 붕괴

### (d) PASS 조건
- 비용 반영 후에도 oos_mean이 **유의미(기준선 대비 -25% 이내)** + turnover 목표 달성.

## TOP4) 운영 리스크/리스크 관리: worst_mdd 산출 + 노출/변동성 타게팅(레짐 대응)
### (a) 왜 필요한지
- worst_mdd가 없는 상태는 **리스크 관리가 사실상 0**.
- exposure 상단이 0.84면 레짐 역전(금리/리스크오프)에서 손상이 큼.

### (b) 위험/부작용
- 노출을 줄이면 상승장 수익이 감소할 수 있음.
- 변동성 타게팅이 “후행”이라 급변 구간에서 늦을 수 있음.

### (c) 최소 실험(필수 1개)
**[실험 #4: worst_mdd/TAIL 지표 산출 + Vol Target + Exposure Clamp]**
1) 실험 정의  
- 백테스트 결과에 **worst_mdd, CVaR(또는 95% ES), max daily loss**를 반드시 계산/저장(챔피언 메타 필수 필드).  
- 포트폴리오 변동성(예: 20일 실현 변동성) 기반으로 목표 변동성에 맞춰 레버/노출을 자동 조정 + 노출 상한(예: 0.80→0.60) 클램프.
2) 게이트  
- worst_mdd가 None이면 **실험 실패(파이프라인 오류로 중단)**  
- 노출 클램프 후에도 oos_mean이 **-15% 이내**면 통과  
- worst_mdd가 **의미 있게 개선**(예: 10% 상대 개선)되면 우선 채택
3) 기대 관측치  
- 성능 약간 감소 + MDD/테일 개선이 정상이면 “운영 가능한 전략”으로 가까워짐

### (d) PASS 조건
- worst_mdd/ES가 정상 산출 + worst_mdd 개선 + oos_mean 급락 없음(-15% 이내).

## TOP5) 48시간 자동 루프 복구: 아티팩트/커맨드/재현성(Seed) 고정
### (a) 왜 필요한지
- file 비어있고 Next Commands 없음 → “자동 루프”가 실질적으로 멈춤.
- 동일 run_hash가 나와도 결과 재현이 안 되면 **검증/롤백 불가**.

### (b) 위험/부작용
- 저장/로깅이 늘어 비용(스토리지/실행시간) 증가.
- 규격화 과정에서 기존 코드 일부가 깨질 수 있음.

### (c) 최소 실험(필수 1개)
**[실험 #5: Run Artifact Registry + Next-Command Generator]**
1) 실험 정의  
- 매 런마다 `{lane_hash}/{run_hash}/`에 **데이터 스냅샷 해시, 피처 스키마, 모델 파라미터, 결과 리포트, 주문 시뮬 요약** 저장하고 `file:` 필드에 경로를 기록.  
- Next Commands를 자동 생성(예: “누수 테스트 실패 시 차단 포인트 출력/중단”, “비용 모델 미적용이면 실패”, “worst_mdd 없으면 실패”).
2) 게이트  
- file 경로가 **항상 non-empty**  
- 동일 입력/seed에서 결과 메트릭이 **완전 재현**(허용오차 0 또는 지정 epsilon)  
- Next Commands가 **3줄 이상 자동 생성**(최소: 다음 실험/게이트/알림)
3) 기대 관측치  
- 운영이 “멈추지 않는” 형태로 전환  
- 장애 시 원인 추적 시간이 급감

### (d) PASS 조건
- file 채움 + 재현성 확인 + Next Commands 자동 생성 성공.

# 3) 성능이 안 움직일 때 “원인 분해” 아이디어 (트리거/적용/노출/비용/레짐)
아래 순서로 **분해 리포트(자동 생성)**를 붙여라. 목표는 “어디서 알파가 죽는지”를 한 번에 고정하는 것.

## A. Trigger(신호 발생) 문제
- 신호 발생 빈도(일/주 단위) 추적: **0에 수렴**하면 조건식/데이터 결측/게이트 과도.
- 예측값 분포 추적: 평균/분산이 시간에 따라 **붕괴(=상수화)**하면 피처 스케일/정규화/클리핑 문제.

## B. Apply(주문 적용) 문제
- 신호→포지션 변환에서 감쇠/클램프가 과도한지 분해:  
  - “원신호 수익” vs “포지션 적용 후 수익”을 분리 로깅.
- 리밸런싱 지연(주기/캘린더)로 인해 **시그널이 늦게 반영**되는지 점검.

## C. Exposure(노출) 문제
- 순노출/총노출의 분해: 지금처럼 0.47~0.84이면 **리스크온 베팅**이 강함.  
- 종목별 기여도(PnL contribution)로 **1~2개 종목에 성과가 몰리는지**(서바이버십/우연 가능) 확인.

## D. Cost(비용) 문제
- 총 PnL을 **Gross / Costs / Net**으로 3분할.  
- 비용 기여도를 (스프레드/임팩트/회전율)로 나눠서 **어느 항이 지배적인지** 고정.
- 거래 “실패 조건”을 명확히: ADV 부족/갭/급변동 구간에서 비용이 폭발하는지.

## E. Regime(레짐) 문제
- 레짐 태깅 후 성능을 분리:  
  - 예: QQQ 추세(상/하), VIX(상/하), XLK/XLV 상대강도(Tech 선호 vs Healthcare 방어) — **관측지표로만 사용**  
- “레짐별 oos_mean, oos_min, worst_mdd”를 테이블로 남기고, 특정 레짐에서만 먹히면 **레짐 필터/노출 감쇠**로 운영화.

---

## 48시간 자동 루프에 넣을 “최소 산출물”(모든 실험 공통)
- 누수 진단 결과(shift 테스트/타임스탬프 위반 로그)
- Purged WF 폴드별 성능 테이블(평균/최악/trimmed mean)
- 비용 분해(Gross/Cost/Net + turnover)
- 리스크(worst_mdd, ES, max daily loss) + 노출(min/max)
- 아티팩트 경로(file), 재현성 체크, Next Commands 3줄

위 TOP1~TOP5를 순서대로 실행하면, **누수/과최적화/비용/운영 리스크를 먼저 잠그고** 그 다음에야 “전략 알파 개선”을 의미 있게 할 수 있는 상태로 들어간다.
