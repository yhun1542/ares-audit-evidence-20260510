### 1. [CRITICAL] Degenerate Folds(1,2,3,8) 강제 복구 및 아웃라이어 제거
**현상:** 4개 폴드에서 모델이 붕괴(Degenerate)했음에도 OOS Mean 3.32가 기록됨. 생존 편향(Survivorship Bias)에 의한 '가짜 챔피언' 가능성 99%.
**위험:** 실제 운영 시 계좌 파산(Ruin) 확률 매우 높음.
**Action:**
- **실험 A (Hard Cap):** 개별 종목 최대 비중(Max Position Size)을 12%로 강제 제한 (Tech/Healthcare 8~14개 분산 강제).
- **실험 B (Vol Target):** 포트폴리오 변동성 목표(Target Vol)를 연 20%로 설정하여 레버리지/베팅 크기 동적 축소.

**[48h Loop Spec]**
1. **실험 정의:** `constraint_max_pos: 0.12` OR `target_vol: 0.20` 적용.
2. **게이트:** Degenerate Folds = 0 (모든 폴드 생존 필수).
3. **기대 관측치:** OOS Mean은 3.3 -> 1.5~2.0 수준으로 하락하되, MDD는 계산 가능 범위로 들어와야 함.

### 2. [DATA] `worst_mdd: None` 디버깅 및 Downside Risk 계산 파이프라인 수리
**현상:** 리스크 지표인 MDD가 `None`. 하락장 방어 로직이 작동하는지 검증 불가.
**위험:** 낙관적 수익률만 보고 배포했다가 첫 하락장에서 셧다운.
**Action:**
- **실험 A (Force Log):** 평가 파이프라인에서 MDD 계산 시 `NaN`이나 `Infinite` 발생 시 해당 폴드를 즉시 실패 처리하도록 로직 수정.
- **실험 B (Sanity Check):** 벤치마크(QQQ/XLV) 대비 Beta가 1.5 초과 시 거래 차단 로직 추가.

**[48h Loop Spec]**
1. **실험 정의:** 평가 스크립트 내 `calc_mdd` 함수 예외처리 강화 및 로깅 레벨 격상.
2. **게이트:** `worst_mdd` != None AND `worst_mdd` > -0.30 (30% 이상 손실 방어).
3. **기대 관측치:** 모든 폴드의 MDD 수치가 로그에 명시됨.

### 3. [STRATEGY] Tech/Healthcare Sector Balance 강제 (ETF Indicator 활용)
**현상:** 현재 섹터 쏠림 확인 불가. Tech 몰빵 시 변동성 제어 실패 가능성.
**위험:** 바이오텍 임상 실패 등 섹터 고유 리스크에 과다 노출.
**Action:**
- **실험 A (Sector Constraint):** 유니버스 내 Tech(XLK 구성종목) 최소 4개, Healthcare(XLV 구성종목) 최소 4개 보유 강제.
- **실험 B (Regime Filter):** XLK(기술주 ETF)의 20일 이평선이 하락세일 경우, Tech 비중 50% 축소. (ETF 매매는 안 하되 지표로만 사용).

**[48h Loop Spec]**
1. **실험 정의:** `min_sector_count: {'Tech': 4, 'Health': 4}` 설정.
2. **게이트:** 샤프 지수(Sharpe) > 1.2 유지.
3. **기대 관측치:** 특정 섹터 급락 구간(폴드 2, 3 추정)에서 방어력 개선.

### 4. [COST] 슬리피지/거래비용 민감도 스트레스 테스트
**현상:** OOS Mean이 비정상적으로 높음(3.32). 거래 횟수가 과도하게 많아 비용 반영 시 수익이 소멸될 가능성.
**위험:** 과최적화(Overfitting)된 단타 전략이 실제 체결 오차로 인해 손실 전환.
**Action:**
- **실험 A (Cost Penalty):** 거래 비용(bp)을 현재 설정의 2배(예: 10bp -> 20bp)로 올려서 백테스트 재구동.
- **실험 B (Turnover Limit):** 일일 회전율(Turnover) 10% 이하 제약 추가.

**[48h Loop Spec]**
1. **실험 정의:** `sim_cost_bps: 20` OR `max_daily_turnover: 0.10`.
2. **게이트:** OOS Mean > 1.0 (비용 증가 후에도 수익성 유지).
3. **기대 관측치:** 거래 횟수 감소, OOS Mean 하락폭이 30% 이내여야 함.

### [성능 정체 시 원인 분해 (Debug Tree)]

성능(OOS Mean/Sharpe)이 개선되지 않거나 0에 수렴할 경우 아래 순서로 점검:

1.  **트리거(Trigger) 부재:**
    *   *체크:* XLK/XLV 등 ETF 지표 필터가 너무 타이트해서 진입 신호가 0건인지 확인.
    *   *조치:* 필터 완화 (예: MA > Price -> RSI < 70).
2.  **노출(Exposure) 부족:**
    *   *체크:* `exposure_max`가 0.83인데 실제 평균 노출이 0.2 미만인지 확인.
    *   *조치:* 변동성 타겟팅 목표치 상향 조정.
3.  **비용(Cost) 과다:**
    *   *체크:* 총 수익(Gross Return)은 좋은데 순수익(Net)이 마이너스인지.
    *   *조치:* 매매 빈도 강제 축소 (Holding Period 최소 3일 설정).
4.  **레짐(Regime) 불일치:**
    *   *체크:* Tech/Health 섹터가 동시에 하락하는 금리 인상기(2022년 등)에만 손실이 집중되는지.
    *   *조치:* 현금(Cash) 비중을 늘리거나 인버스 ETF 지표(관측용)를 활용해 매매 중단 로직 추가.
