## 24~48시간 우선순위 TOP5 (명령형 체크리스트)

### 1) **누수/서바이버십/데이터 정합성 우선 차단**
- [ ] **Survivorship-free** 소스/스냅샷 사용 여부를 코드 레벨에서 강제(assert)하고, “현재 유니버스에 있는 종목만 과거에도 존재” 형태를 금지.
- [ ] Feature 생성 시점에 **t 시점 데이터로 t 이후 라벨/리밸런싱 정보 접근**(lookahead) 가능 경로를 전부 차단(특히 리밸런스 캘린더/리턴 집계).
- [ ] Corporate action(분할/배당) 반영 방식(Adj close vs raw) 단일화 + 라벨 계산과 일치시킴.
- [ ] 결측/거래정지/상장폐지 구간 처리 규칙을 고정(삭제/전방채움 등 선택이 성과를 “만드는” 형태 금지).

### 2) **과최적화 신호: degenerate folds(현재 4개) 즉시 해소**
- [ ] CV/워크포워드 분할 로직에서 **fold 길이/표본 수/리밸런스 횟수 최소값**을 강제.
- [ ] Purged/Embargo(시간누수 방지) 적용 + “빈 fold” 발생 시 실험을 FAIL로 처리(현재처럼 성과가 떠도 신뢰 불가).
- [ ] OOS_mean만 보지 말고 fold별 분산/최악 fold를 게이트로 사용.

### 3) **비용 미반영(슬리피지/수수료/충격/리밸런스) 먼저 고정**
- [ ] 거래비용 모델(고정+비례+슬리피지)을 **항상 ON** (지금처럼 net 성과가 “안 움직이는/과대” 원인 1순위).
- [ ] turnover/일별 체결량 대비 비중을 로그로 남기고, 비용 민감도(0.5x/1x/2x)를 48시간 루프에 포함.

### 4) **운영 리스크: 아티팩트/로그/재현성(현재 rebalance pinpoint가 깨짐) 복구**
- [ ] `--base-log`가 파일이 아닌 문자열로 들어가 깨진 상태 → **리밸런스 로그를 “항상 생성/저장”** 하도록 파이프라인 패치.
- [ ] champion 메타(run_hash/lane_hash/file)가 None/빈 값 → **재현 불가**. 실험 단위 식별자/시드/환경을 강제 기록.

### 5) **노출(Exposure)과 유니버스(미국 Tech+Healthcare 8~14) 규격화**
- [ ] 유니버스를 고정(8~14)하고, ETF는 **관측지표만** 사용(매매 제외).
- [ ] 포지션 상한(단일 종목/섹터), 총 익스포저 밴드, 리밸런스 빈도 규칙을 하드게이트로 고정.
- [ ] MDD가 None인 상태는 리스크 계산 경로가 끊긴 것 → **worst_mdd 산출 실패 시 즉시 FAIL**.

## 실행 가능한 Patch/실험(총 5개, 48시간 자동 루프 형태)
아래 5개만 돌리고(케이스 폭발 금지), 각 실험은 **(1) 실험 정의 → (2) 게이트 → (3) 기대 관측치**로 고정.

---

# EXP-1) **Rebalance/Run 아티팩트 스키마 강제 패치 (운영/재현성)**
### (1) 실험 정의
- 리밸런스 발생 시마다 `rebalance.jsonl`(또는 csv) **무조건 생성**
- 각 run에 `run_hash/lane_hash/seed/git_commit/data_snapshot_id` 저장
- `aub_rebalance_pinpoint.py` 입력 포맷을 단일화(“없으면 FAIL”)

### (2) 게이트 (PASS 조건)
- `rebalance_pinpoint`가 **base/cand 모두에서 에러 없이** 리포트 생성
- champion 메타가 **None/빈 문자열 없이 채워짐**
- 동일 seed/run_hash에서 백테스트 결과가 **bit-level 또는 허용오차 내 재현**

### (3) 기대 관측치
- 성과 수치가 좋아지지 않아도 정상: 목표는 **“원인 추적 가능성”** 회복
- 다음 루프부터 “성능 무변화”의 원인이 **리밸런스 미발생/로깅 누락/적용 누락** 중 무엇인지 즉시 분해 가능

**위험/부작용**
- 로그 I/O 증가(디스크/속도) → jsonl append 방식으로 완화
- 스키마 변경으로 기존 도구 호환 깨짐 → 버전 필드 추가로 완화

---

# EXP-2) **Degenerate folds 제거: Purged Walk-Forward + 최소 표본/리밸런스 강제 (과최적화 차단)**
### (1) 실험 정의
- CV를 시간순 walk-forward로 고정
- 각 fold에 대해:
  - 최소 거래일 N, 최소 리밸런스 횟수 K 강제
  - 라벨 산출 구간과 피처 구간 사이 **embargo** 적용
- fold가 비거나 조건 미달이면 해당 실험은 **즉시 FAIL(점수 계산 금지)**

### (2) 게이트 (PASS 조건)
- `degenerate_folds == []`
- OOS_mean 뿐 아니라 **OOS_min(최악 fold)**가 하한 이상(예: 0 이상 또는 -작은값 이하로 제한)
- fold별 성과 분산이 기존 대비 감소(불안정성 완화)

### (3) 기대 관측치
- OOS_mean이 내려가도 정상(과대추정 제거)
- “성능이 안 움직임”이 사실은 **fold 붕괴로 인한 착시**였는지 확인 가능

**위험/부작용**
- 샘플 감소로 성과 하락/변동성 증가 가능
- embargo로 신호가 약해질 수 있음(하지만 누수 차단이 우선)

---

# EXP-3) **거래비용 모델 ON + 비용 민감도 0.5x/1x/2x (비용 미반영 차단)**
### (1) 실험 정의
- 비용 모델(최소 구성):
  - 수수료: bps 고정
  - 슬리피지: 거래대금 비례(또는 ATR/변동성 기반 bps)
- 동일 전략에 대해 비용 배수 0.5/1/2를 자동으로 48시간 내 반복 평가(3-run이지만 “한 실험군”으로 취급)

### (2) 게이트 (PASS 조건)
- 비용 1x에서 **net OOS_mean이 양(또는 목표 하한)** 유지
- turnover가 과도하면(예: 월간/연간 상한) FAIL 처리 또는 자동 페널티 적용
- gross→net 차이가 비정상적으로 크면(비용 모델/리밸런스 계산 오류) FAIL

### (3) 기대 관측치
- “안 움직이는 성능”이 사실상 **거래가 거의 없거나(리밸런스 미적용)** / **거래가 과도해 비용에 잠식** 중 어디인지 즉시 갈림

**위험/부작용**
- 비용 가정이 보수적이면 전략이 전부 죽을 수 있음(하지만 운영 관점에서 필요)
- 슬리피지 모델이 단순하면 종목별 특성 미반영 → 다음 단계에서만 세분화

---

# EXP-4) **유니버스 고정(Tech+Healthcare 8~14) + 노출/리스크 하드게이트 (노출/운영 리스크)**
### (1) 실험 정의
- 매매 유니버스 고정(예시 12종목, 미국주식):
  - Tech: AAPL, MSFT, NVDA, GOOGL, AMZN, META
  - Healthcare: LLY, UNH, JNJ, ABBV, MRK, ISRG  
  (ETF: XLK/XLV/QQQ/VIX 등은 **관측지표만**, 매매 금지)
- 제약:
  - 종목당 |weight| 상한
  - 섹터(Tech/Healthcare) 총합 비중 밴드
  - 총 익스포저(min/max) 밴드
- `worst_mdd` 산출 실패 시 즉시 FAIL

### (2) 게이트 (PASS 조건)
- 노출(min/max)이 설정 밴드 내
- 단일 종목/섹터 쏠림 위반 0건
- worst_mdd가 None이 아니고, 허용 범위 내

### (3) 기대 관측치
- 성과가 “안 움직임”의 원인이 **유니버스 변동/편입편출/비정상 공백 데이터**인지 제거
- 실거래 가능한(8~14) 포트폴리오 형태로 수렴

**위험/부작용**
- 기회 축소로 성과 하락 가능
- 특정 mega-cap 편향이 심해질 수 있음 → 상한으로 제어

---

# EXP-5) **레짐(관측지표 ETF/금리/변동성) 기반 “리스크 스위치”만 추가 (전략 과복잡화 금지)**
### (1) 실험 정의
- 매매는 개별주만, 레짐은 관측지표로만 사용:
  - 예: XLK vs XLV 상대강도, QQQ 모멘텀, VIX/금리(예: 10Y) 변화
- 레짐에 따라 “신호를 바꾸지 말고” **총 익스포저만 스위칭**(예: risk-on 0.8, risk-off 0.3)

### (2) 게이트 (PASS 조건)
- 레짐 스위치가 켜지는 구간에서 **MDD 또는 tail loss**가 개선
- OOS_mean이 동일하거나 소폭 하락해도, **oos_min(최악)** 개선이면 PASS 가능
- 스위치 빈도가 과도(노이즈)하면 FAIL(예: 월 4회 초과 등)

### (3) 기대 관측치
- “성과가 안 움직임”이 **레짐 미적응** 때문인지 확인
- 신호를 건드리지 않고도 리스크 지표가 개선되면 다음 단계(신호 개선)로 진행 가능

**위험/부작용**
- 레짐 지표가 후행이면 수익 기회를 놓침
- 스위치가 잦으면 비용/턴오버 증가 → EXP-3와 함께 게이트

---

## 각 TOP5 제안별 매핑 (왜 필요/위험/최소 실험/패스)
“각 제안별 최소 실험 2~3개”는 **위 5개 실험을 재사용**해서 충족(새 실험 추가 금지).

### TOP1 데이터/누수/서바이버십
- 왜: OOS_mean이 좋아도 누수면 즉시 0점(운영 불가)
- 위험: 정합성 강화로 성과 하락(정상)
- 최소 실험: **EXP-2 + EXP-4 (+ EXP-1로 추적성 확보)**
- PASS: degenerate_folds=0, 유니버스/CA 일관, 누수 의심 경로 0건(assert)

### TOP2 과최적화(CV 붕괴)
- 왜: 현재 degenerate_folds=[1,2,3,8]이면 성과가 “의미 없음”
- 위험: 성과 하락/표본 부족
- 최소 실험: **EXP-2 + EXP-1**
- PASS: 빈 fold 제거 + 최악 fold(oos_min) 바닥 개선/안정화

### TOP3 비용 미반영
- 왜: 실거래에서 성과가 “안 움직이거나” 바로 마이너스 나는 대표 원인
- 위험: 전략이 전부 음수로 바뀔 수 있음(하지만 그게 현실)
- 최소 실험: **EXP-3 + EXP-4**
- PASS: 비용 1x에서 net 성과/턴오버/슬리피지 일관성 OK

### TOP4 운영/로그/재현성
- 왜: rebalance pinpoint가 지금 깨져서 “무변화”의 원인 추적 불가
- 위험: 개발시간 소모
- 최소 실험: **EXP-1 + EXP-3**
- PASS: 리밸런스 로그로 “거래가 있었는지/적용됐는지/비용이 계산됐는지”가 즉시 보임

### TOP5 노출/레짐/리스크
- 왜: exposure가 0~0.84로 넓고 worst_mdd None → 리스크 체계 불완전
- 위험: 지나친 제약으로 수익 둔화
- 최소 실험: **EXP-4 + EXP-5 (+ EXP-3로 비용 동시 확인)**
- PASS: worst_mdd 산출/개선, 최악구간 손실 감소, 노출 위반 0

---

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **순서대로** 보면 대부분 1~2개에서 잡힙니다(질문 없이 바로 체크).

### A) 트리거(리밸런스가 실제로 발생했나?)
- [ ] 리밸런스 이벤트 수(기간당) 0인지 확인 → 0이면 신호가 좋아도 성과 고정
- [ ] 리밸런스 날짜가 캘린더/거래일과 불일치(휴장일)인지 확인
- [ ] 목표 weight 변경량이 대부분 0인지 확인(신호가 변하지 않거나 적용 누락)

**도구화:** EXP-1로 `rebalance.jsonl`에 (date, target_w, prev_w, delta_w, reason)를 남김

### B) 적용(신호가 포지션으로 제대로 반영됐나?)
- [ ] signal → target_weight 매핑에서 클리핑/정규화로 전부 0이 되는지
- [ ] 리스크 제약이 너무 강해 항상 현금/중립으로 수렴하는지
- [ ] long/short 허용 여부(공매도/마진) 플래그가 암묵적으로 꺼져 있는지

**관측치:** 일자별 gross exposure, net exposure, active names(비중≠0 종목 수)

### C) 노출(노출이 움직여야 성과도 움직임)
- [ ] exposure_min=0이 자주 나오면 “대부분 현금”일 수 있음
- [ ] 단일 종목 상한으로 인해 사실상 1~2개만 들고 있는지(분산 부족)
- [ ] 8~14 종목 규격에 맞는지(종목 수가 계속 바뀌면 비교 불가)

**도구화:** EXP-4로 active names, 섹터 비중, 상한 위반을 매일 로그

### D) 비용(성과가 gross 기준으로만 변하고 net은 고정/악화?)
- [ ] turnover가 커서 비용이 수익을 상쇄하는지
- [ ] 비용이 “0으로 계산”되고 있지는 않은지(적용 누락)
- [ ] 슬리피지 단위(bps vs %) 착오로 비용이 비정상인지

**도구화:** EXP-3로 gross/net, turnover, 비용항목별 breakdown 강제

### E) 레짐(신호가 맞는 구간이 따로 있는데 평균에 묻히는지)
- [ ] XLK/XLV 상대강도, VIX 급등, 금리 급변 구간에서 성과가 구조적으로 깨지는지
- [ ] “최악 fold(oos_min)”가 특정 레짐에 집중되는지

**도구화:** EXP-5로 레짐 구간별 성과 분해(평균이 아니라 tail 중심)

---

### 48시간 루프 권장 실행 순서(고정)
- [ ] **Day0~Day1:** EXP-1(로그/재현성) + EXP-2(CV 정상화) 먼저 통과
- [ ] **Day1~Day2:** EXP-3(비용) + EXP-4(유니버스/리스크) 통과
- [ ] **마지막:** EXP-5(레짐 스위치)로 tail 개선 여부만 확인

이 5개 중 하나라도 게이트 FAIL이면, “성능 개선 실험”을 추가로 만들지 말고 해당 FAIL을 먼저 제거하는 쪽이 24~48시간 ROI가 가장 큽니다.
