## 1. 우선순위 TOP 5 실행 항목

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### P1. 파이프라인 복구 (Blocking)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- `rebalance.csv` 로드 실패 → 리밸런싱 비용/슬리피지 검증 불가
- `worst_mdd = None` → 리스크 게이트 작동 안함
- 이 상태로 실험해도 **결과 신뢰 불가**

**(b) 위험/부작용**
- 파이프라인 수정 중 기존 로직 손상 가능
- 시간 소모 (4~8h)

**(c) 최소 실험**

| # | 실험 | 커맨드 |
|---|------|--------|
| 1-1 | rebalance 출력 포맷 확인 | `head -5 baseline/reports/run_champion_v5_*/rebalance.*` |
| 1-2 | JSON→CSV 변환기 삽입 | `python tools/convert_rebalance.py --in .jsonl --out .csv` |
| 1-3 | MDD 계산 로직 추가 | `backtest_engine.py`에 `calc_max_drawdown()` 삽입 |

**(d) PASS 조건**
```
✅ rebalance_pinpoint.py 정상 실행 (exit 0)
✅ worst_mdd ≠ None (숫자 출력)
✅ 최소 1개 fold에서 rebalance 횟수 > 0
```

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### P2. Degenerate Fold 원인 분해
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- Fold 1,2,3,8 = 시계열 초반(2018~2020?) + 중간(2022~2023?)
- 특정 **레짐(금리인상기, COVID)에서 신호 무효화** 가능성
- 이게 "신호 문제"인지 "포지션 사이징 문제"인지 분리 필요

**(b) 위험/부작용**
- Fold별 튜닝 시작하면 **누수 위험** 급증
- 원인 모르고 패치하면 과최적화

**(c) 최소 실험**

| # | 실험 | 목적 |
|---|------|------|
| 2-1 | Fold별 날짜 범위 출력 | 어떤 시장 환경인지 확인 |
| 2-2 | Degenerate 정의 역추적 | `oos_return < 0` vs `exposure = 0` vs `sharpe < 0.1` 중 뭐? |
| 2-3 | Fold 1,2,3,8만 signal histogram | 신호가 아예 안 나오는지, 나오는데 손실인지 |

**(d) PASS 조건**
```
✅ Degenerate 원인 1개로 분류 완료
   - A) 신호 미발생 (exposure ≈ 0)
   - B) 신호 발생 but 손실 (방향성 오류)
   - C) 비용 때문에 손실 (gross > 0, net < 0)
```

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### P3. 레짐 필터 실험 (전략)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- Degenerate fold가 특정 레짐이면, **레짐 감지 → 노출 축소**로 해결 가능
- 현재 신호가 "모든 시장"에 베팅 → 선택적 회피 필요

**(b) 위험/부작용**
- 레짐 정의 자체가 **사후적 피팅** 위험
- VIX 등 외부 지표 추가 시 데이터 누수 확인 필요

**(c) 최소 실험**

| # | 실험 | 설정 |
|---|------|------|
| 3-1 | VIX > 30 시 exposure × 0.3 | `regime_filter: {vix_threshold: 30, scale: 0.3}` |
| 3-2 | SPY 200MA 하회 시 exposure × 0.5 | `regime_filter: {spy_below_ma200: true, scale: 0.5}` |
| 3-3 | 두 조건 AND | 둘 다 충족 시만 축소 |

**(d) PASS 조건**
```
✅ degenerate_folds ≤ 2 (현재 4 → 절반 이하)
✅ oos_mean 하락폭 < 15% (3.32 → 2.82 이상 유지)
✅ oos_min > -0.01 (최악 fold 손실 축소)
```

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**

- 단순 버전이 비슷한 성능이면 → 복잡성 불필요
- 단순 버전이 훨씬 나쁘면 → 복잡성이 "진짜" 알파

**(b) 위험/부작용**
- 단순화가 너무 과격하면 비교 무의미
- 점진적 제거 필요

**(c) 최소 실험**

| # | 실험 | 변경 |

| 5-3 | 종목 수 축소 | 14개 → 8개 (상위 conviction만) |

```
✅ 단순 버전 oos_mean > 2.5 (현재의 75% 이상)
✅ degenerate_folds ≤ 현재 (4개 이하)

```

## 2. 48시간 자동 루프 스펙

```yaml
# autopilot_config.yaml

loop_interval: 6h
max_iterations: 8

experiments:
  - id: p1_pipeline_fix
    priority: BLOCKING
    commands:
      - "python tools/validate_rebalance_output.py"
      - "python tools/add_mdd_calculation.py"
    gate:
      - "worst_mdd != None"
      - "rebalance_pinpoint.py exit 0"
    timeout: 4h

  - id: p2_fold_diagnosis
    priority: HIGH
    depends_on: p1_pipeline_fix
    commands:
      - "python tools/fold_date_range.py --folds 1,2,3,8"
      - "python tools/degenerate_cause.py --threshold exposure<0.01"
    gate:
      - "cause_classification in [A, B, C]"
    expected:
      if_A: "→ 신호 로직 검토"
      if_B: "→ 방향성 반전 실험"
      if_C: "→ 비용 최적화"

  - id: p3_regime_filter
    priority: MEDIUM
    depends_on: p2_fold_diagnosis
    variants:
      - vix_30_scale_03
      - spy_ma200_scale_05
      - combined_filter
    gate:
      - "degenerate_folds <= 2"
      - "oos_mean >= 2.82"

  - id: p4_cost_stress
    priority: MEDIUM
    parallel: true
    variants:
      - slippage_20bps
      - commission_10bps
      - turnover_penalty
    gate:
      - "oos_mean >= 2.3"

  - id: p5_simplify
    priority: LOW
    depends_on: p3_regime_filter
    variants:
      - feature_half
      - lookback_uniform
      - ticker_reduce
    gate:
      - "oos_mean >= 2.5"
      - "degenerate_folds <= 4"

```

│   ├─ 체크: daily_signal_count == 0?
│   ├─ 원인: 임계값 너무 높음 / 데이터 누락
│   └─ 패치: threshold 완화 or 데이터 파이프라인 점검
│

│   ├─ 체크: signal != 0 but position_delta == 0?
│   ├─ 원인: 리밸런싱 로직 버그 / 최소 거래 단위
│   └─ 패치: rebalance 조건 로깅 추가
│
├─[3] 노출 문제: 포지션 있으나 너무 작음
│   ├─ 체크: exposure_mean < 0.1?
│   ├─ 원인: 사이징 로직 과도한 보수성
│   └─ 패치: base_exposure 상향 or 켈리 분율 조정
│
├─[4] 비용 문제: gross 수익 있으나 net 없음
│   ├─ 체크: gross_return > 0, net_return ≈ 0?
│   ├─ 원인: 과다 매매 or 비현실적 비용 가정
│   └─ 패치: 턴오버 제한 or 비용 모델 검증
│
└─[5] 레짐 문제: 특정 기간만 손실
    ├─ 체크: fold별 return 분산 > 임계값?
    ├─ 원인: 신호가 특정 시장 환경에만 유효
    └─ 패치: 레짐 필터 추가 (P3 실험)
