[우선순위 제안 TOP 5]

### 1. Degenerate Folds(1, 2, 3, 8) 긴급 복구 및 로직 완화
- **이유:** 전체 Fold 중 40%가 비정상(거래 없음/에러)임에도 OOS Mean이 3.32라는 것은, 나머지 Fold에서 **과도한 수익(Overfitting/Look-ahead)**이 발생했거나, 특정 시기에만 운 좋게 작동한다는 신호. 생존 편향(Survivorship Bias)의 전형적인 증상.
- **위험:** 완화 시 OOS Mean(3.32)이 급격히 하락할 수 있음. 그러나 현재 수치는 신뢰 불가.
- **실험 제안:**
    1.  **EXP_RELAX_ENTRY:** 진입 임계값(Threshold)을 현행 대비 20% 하향 조정 (거래 빈도 강제 증가).
    2.  **EXP_FORCE_MIN_ASSETS:** 포트폴리오 내 최소 보유 종목 수를 0 -> 3으로 강제 설정 (Tech/Health 각 1개 필수 포함).
    3.  **EXP_DROP_LIQUIDITY_FILTER:** 유동성/변동성 필터 조건을 일시적으로 제거하여 로직이 작동하는지 확인.
- **PASS 조건:** Degenerate Folds가 0개가 되고, OOS Sharpe가 1.5 이상 유지될 것.

### 2. 로깅 파이프라인(Rebalance Log) 포맷 통일 (System Patch)
- **이유:** `Error loading... Expecting value` 에러로 인해 어떤 종목이, 왜 거래되었는지 분석 불가능. 'ONE TRUTH'와 'Diagnoser' 간 지표 불일치(3.32 vs 2.62)의 원인을 파악할 수 없음.
- **위험:** 데이터 파이프라인 중단 리스크 (없음, 코드 수정 사항).
- **실험 제안:**
    1.  **PATCH_LOG_JSONL:** 모든 Rebalance 로그를 `.csv`가 아닌 `.jsonl`로 강제 통일 및 스키마 검증 로직 추가.
    2.  **PATCH_SYNC_METRICS:** 평가 지표 계산식을 `One Truth` 기준으로 통일(라이브러리 버전 고정).
- **PASS 조건:** `aub_rebalance_pinpoint.py`가 에러 없이 실행되고, 거래 로그가 파싱될 것.

### 3. 과최적화 탐지: Universe Restriction & Cost Injection
- **이유:** Tech/Healthcare 8~14개 종목으로 Sharpe 3.32는 비정상적. 소형주나 M&A 이슈 종목이 포함되었거나, 슬리피지(Slippage)가 0으로 설정되었을 가능성 높음.
- **위험:** 성능 지표의 대폭 하락. (그러나 이는 거품이 꺼지는 과정임)
- **실험 제안:**
    1.  **EXP_HIGH_CAP_ONLY:** Universe를 시가총액 상위 50위 내 Tech/Health로 한정 (Small cap 노이즈 제거).
    2.  **EXP_COST_STRESS:** 편도 거래비용(bp)을 현재의 2배로 설정하고 시뮬레이션.
- **PASS 조건:** 비용 2배 적용 후에도 OOS Sharpe > 1.2 유지.

### 4. 레짐 기반 노출(Exposure) 동적 제어
- **이유:** `exposure_min/max: 0.0 / 0.83`는 "모 아니면 도"식 베팅을 의미. 시장 하락기(Degenerate Folds 시기)에 아예 진입을 못하고 있음. ETF(QQQ/XLV)의 변동성을 관측 지표로 삼아 노출도를 조절해야 함.
- **위험:** 급등장에서 수익률 제한(Upside Capping).
- **실험 제안:**
    1.  **EXP_VOL_TARGETING:** 관측된 ETF 변동성이 상위 20%일 때, 최대 Exposure를 0.5로 제한.
    2.  **EXP_LONG_ONLY_FLOOR:** 하락장에서도 최소 Exposure 0.2를 강제하여 "모델이 시장을 떠나는 것"을 방지.
- **PASS 조건:** OOS Min(수익률)이 개선되고, MDD가 15% 이내로 제어될 것.

### 5. Tech/Healthcare 상관관계 디커플링 (Correlation Penalty)
- **이유:** 두 섹터 집중 시, 섹터 전체가 무너질 때 MDD 방어 불가. 종목 간 상관계수가 너무 높은 조합만 선택되었을 가능성.
- **위험:** 기대 수익률(Alpha) 감소.
- **실험 제안:**
    1.  **EXP_CORR_PENALTY:** 목적함수(Objective Function)에 `Portfolio Correlation` 페널티 항 추가.
    2.  **EXP_SECTOR_BALANCE:** Tech와 Healthcare 비중이 각각 최소 30%씩 유지되도록 제약 조건 추가.
- **PASS 조건:** 포트폴리오 평균 상관계수 < 0.7 진입.

[성능 정체 시 원인 분해 아이디어]

1.  **트리거(Signal) 레벨:**
    *   **현상:** 모델이 매수 신호를 아예 생성하지 않음.
    *   **확인:** Feature(입력 데이터)의 정규화(Scaling)가 깨졌는지 확인 (예: 가격이 너무 올라서 과거 모델의 threshold를 넘지 못함).
2.  **필터(Filter) 레벨:**
    *   **현상:** 신호는 있으나 Risk Manager가 차단.
    *   **확인:** `Degenerate Folds` 시기의 변동성(ATR)이나 거래량 확인. 특정 시기 데이터 결측(Null) 여부 점검.
3.  **실행(Execution) 레벨:**
    *   **현상:** 논리적으로는 매수했으나, 비용/슬리피지로 인해 PnL이 0 또는 음수.
    *   **확인:** 거래당 평균 수익(Average Trade Return) vs 거래 비용(Cost) 비교. `Cost > Return`이면 매매 빈도를 강제로 낮춰야 함.
4.  **레짐(Regime) 불일치:**
    *   **현상:** 2026년(One Truth 시점) 시장 환경이 훈련 데이터와 완전히 다름.
    *   **확인:** 훈련 기간 내 '금리 인상기' 또는 '섹터 로테이션' 구간의 성능만 별도로 분리해서 검증(Slicing Evaluation).
