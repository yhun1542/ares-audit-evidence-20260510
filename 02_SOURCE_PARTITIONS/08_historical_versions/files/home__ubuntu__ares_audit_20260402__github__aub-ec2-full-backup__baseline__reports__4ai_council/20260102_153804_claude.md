## 🎯 TOP 5 우선순위 제안

### **P1. Tuning Min 0.05 Fold 해부 (과최적화 차단)**

#### (a) 왜 필요한가
- Candidate의 tuning_min=0.05는 특정 fold에서 거의 전멸 수준
- 이 fold가 lockbox 기간과 다른 regime이면 → 실전 리스크 없음
- 같은 regime이면 → 숨겨진 폭탄

#### (b) 위험/부작용
- 해당 fold 과적합 시 전체 앙상블 신뢰도 하락
- 분석 시간 소요 (실험 아님, 진단)

#### (c) 최소 실험
```yaml
EXP-1A: fold_regime_decomposition
  action: 문제 fold의 날짜/종목/섹터 분포 추출
  script: python3 tools/fold_analyzer.py --candidate candidate_20260102*.json --metric min_cagr
  gate: 자동 리포트 생성
  expect: 특정 섹터(예: Growth Tech) 또는 기간(예: 2022-Q2) 집중 여부 확인

EXP-1B: fold_exclusion_sensitivity  
  action: 문제 fold 제외 후 앙상블 재계산
  script: python3 backtest.py --exclude-fold <문제fold> --config candidate_*.json
  gate: lockbox_mean 변화 < 3%
  expect: 제외해도 lockbox 유지 시 → fold 자체가 outlier regime
```

#### (d) PASS 조건
- 문제 fold가 2022-H1 (금리인상기) 집중 → **regime filter 추가로 해결**
- 그 외 기간 분산 → **전략 자체 재검토 필요**

### **P2. MDD −11% 원인 분해 (Risk Budget 재조정)**

- Champion −9.3% → Candidate −11.2%로 악화
- Lockbox 안정성은 올랐는데 MDD 악화 = **수익 변동성 trade-off**

#### (b) 위험/부작용
- MDD 제약 강화 시 수익률 하락 가능
- 과도한 position sizing 축소 → 기회비용

#### (c) 최소 실험
```yaml

  action: MDD 발생 구간의 종목별/일별 기여도 분해
  script: python3 tools/mdd_decomposer.py --file candidate_*.json --top 5
  gate: 자동
  expect: 단일 종목이 MDD의 50% 이상 기여 여부

EXP-2B: position_cap_test
  action: 종목별 최대 비중 15%→12% 제한 적용

  expect: MDD 개선 with CAGR 손실 < 5%
```

#### (d) PASS 조건

### **P3. Macro Alpha Shadow 모듈 분리 평가**

#### (a) 왜 필요한가
- Candidate 파일명에 `macro_alpha_shadow` 포함
- 이 모듈이 lockbox 개선의 원인인지, 우연인지 분리 필요

- 모듈 기여도 과대평가 시 → 불필요한 복잡성 유지
- 과소평가 시 → 유효 신호 제거

#### (c) 최소 실험
```yaml

  script: python3 backtest.py --disable-module macro_alpha_shadow --config candidate_*.json
  gate: lockbox_mean 차이 > 5% 시 모듈 유효
  expect: 1.79 → 1.70 이하로 하락 시 모듈 기여 확정

EXP-3B: macro_shadow_regime_interact
  action: VIX > 25 구간에서만 모듈 활성화
  script: python3 backtest.py --module-condition "macro_alpha_shadow:vix>25"

  expect: 고변동 구간 집중 시 효율성 증가
```

#### (d) PASS 조건
- EXP-3A에서 모듈 OFF 시 lockbox −5% 이상 하락 → **모듈 유지 확정**

## 🔬 성능 정체 시 원인 분해 프레임워크

```
성능 = 트리거 × 적용률 × 노출크기 × (수익 - 비용) × 레짐적합도

정체 원인 트리:
│
├─ [트리거 문제] 신호가 안 나옴
│   └─ 점검: 일평균 신호 수, 신호 분포 시계열
│   └─ 실험: threshold 완화 테스트
│
├─ [적용률 문제] 신호 나와도 실행 안 됨
│   └─ 점검: 필터(유동성/섹터/이미보유)에서 탈락률
│   └─ 실험: 필터 완화 후 수익률 변화
│
├─ [노출크기 문제] 실행해도 비중이 작음
│   └─ 점검: 평균 position size, Kelly 대비 비율
│   └─ 실험: sizing 공격성 ±20% 테스트
│
├─ [비용 문제] 수익은 있는데 비용이 까먹음
│   └─ 점검: 거래당 평균 수익 vs 비용
│   └─ 실험: holding period 연장 (거래 축소)
│
└─ [레짐 문제] 전략 자체가 현재 시장과 안 맞음
    └─ 점검: 최근 6개월 Sharpe vs 전체 기간
    └─ 실험: regime filter 추가 (VIX, 금리, 모멘텀 팩터)
```
