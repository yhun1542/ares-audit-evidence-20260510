## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — **명령형 체크리스트**
아래 TOP5는 **누수/과최적화/서바이버십/비용 미반영/운영 리스크**를 먼저 막고, **US 주식 only + Tech/Healthcare 8~14종목(ETF 매매 제외, ETF는 관측지표)** 제약 안에서 **48시간 자동 루프**로 돌릴 수 있게 설계했다.  
실험은 케이스 폭발 방지를 위해 **총 5개 패치/실험(E1~E5)**로 고정하고, 각 TOP 항목은 그중 **2~3개를 재사용**한다.

---

# 공통 실험 세트(총 5개) — 48시간 루프용
- **E1. Lookahead/누수 센티넬 + 피처 랙 강제 패치**
- **E2. Purged Walk-Forward(embargo) + 과최적화 진단(퍼뮤테이션/파라미터 프리즈)**
- **E3. 비용/슬리피지/체결 모델 패치 + 비용 민감도 스윕(0.5x/1x/2x)**
- **E4. 8~14종목 강제 + 유동성/턴오버/단일종목 캡 + 리스크 타겟(변동성/베타 클램프)**
- **E5. ETF 기반 레짐 게이트(관측만: QQQ/XLV/VIX/TLT 등) + 노출 스위치(리스크 온/오프)**

각 E는 아래 TOP5에 “최소 실험 2~3개” 요구를 만족하도록 매핑한다.

# TOP1) **데이터 누수/정렬/코퍼레이트액션** 1차 봉쇄
### (a) 왜 필요한지
- 현재 Champion은 lockbox가 좋지만, **후보가 tuning 대비 lockbox에서 흔들리는 패턴**은 “신호 부족”도 가능하지만 **미세 누수/정렬 오류/분할 오염**이 있을 때도 자주 나온다.
- 특히 **Tech/Healthcare 대형주**는 스플릿/배당/리밸런싱 이벤트가 잦아 **조정가격/리턴 정렬**이 조금만 틀어져도 성능이 허수로 올라간다.

### (b) 위험/부작용
- 누수 제거 후 **tuning 성능이 떨어지는 게 정상**(허수 알파 제거).
- 피처 랙 강제 시 신호가 약해져 **거래 빈도/턴오버가 늘거나 줄 수 있음**(전략 형태가 바뀜).

### (c) 최소 실험(2~3개) — 공통 실험 재사용
- **[E1] 누수 센티넬 패치**
  - 모든 피처에 대해 “사용 시점 t에서 이용 가능한 최종 시점”을 메타데이터로 추적하고, `feature_timestamp > decision_timestamp`면 하드 에러.
  - 리턴/가격은 **execution lag(최소 1 bar/day)** 강제.
- **[E2] Purged Walk-Forward + embargo**
  - 학습 윈도우와 평가 윈도우 사이에 embargo(예: 5~20 trading days)를 넣어 **인접 정보 누수**를 차단.
- **[E3] (옵션) 비용 포함 후에도 수익이 남는지 확인**
  - 누수 제거로 알파가 작아지면 비용에 즉시 죽는다. 같이 확인해 “살아남는 알파”만 남김.

### (d) PASS 조건(게이트)
- **Leakage gate:** 누수 센티넬 트립(위반) = **즉시 FAIL**
- **Generalization gate:** Purged WF에서
  - `lockbox_mean`이 Champion 대비 **-10% 이상 악화되면 FAIL**
  - `worst_mdd`가 Champion(-0.0815) 대비 **더 악화(예: < -0.09)면 FAIL**
- **Stability gate:** fold별 성과 분산(표준편차)이 **기존 대비 악화 시 FAIL**(과최적화 가능성)

---

# TOP2) **과최적화/서바이버십(포인트-인-타임 유니버스)** 점검
### (a) 왜 필요한지
- “Tech+Healthcare 8~14”는 유니버스가 좁아 **서바이버십 바이어스**가 성능을 크게 부풀릴 수 있다.
- 후보가 tuning에서만 좋아지고 lockbox에서 약한 경우, **파라미터가 특정 종목/기간에 과적합**했을 가능성이 크다.

### (b) 위험/부작용
- 포인트-인-타임 구성으로 바꾸면 종목 교체/데이터 결측이 늘어 **백테스트 구현 난이도 상승**.
- 과최적화 방지(정규화/모델 단순화)로 **평균 수익이 줄어드는 것이 정상**.

### (c) 최소 실험(2~3개)
- **[E2] Purged WF + 파라미터 프리즈**
  - 하이퍼파라미터 탐색을 줄이고(혹은 고정), **탐색 공간을 절반 이하로 축소**한 “프리즈 버전”을 같이 운용.
- **[E2] 퍼뮤테이션(무작위화) 진단**
  - 타깃 리턴/특정 피처를 기간 블록 단위로 셔플해도 성능이 유지되면 **누수/버그 의심**으로 FAIL.
- **[E1] 포인트-인-타임 유니버스 스냅샷 검증**
  - “오늘 알고 있는 종목 리스트”가 아니라 “그날 존재/거래 가능했던 종목”만 포함하도록 스냅샷을 강제(가능한 범위에서).

### (d) PASS 조건
- **Permutation gate:** 셔플 데이터에서 성능이 원본의 **30% 이상 유지되면 FAIL**(허수 신호 가능성)
- **Freeze gate:** 파라미터 프리즈 버전이 원본 대비
  - `lockbox_mean` **-10% 이내** & `lockbox_min` **악화 없음**이면 PASS(과최적화 민감도 낮음)
- **Survivorship gate:** PIT 유니버스 전환 후에도 전략이 **거래 불능/결측으로 붕괴하지 않을 것**(런타임 에러 0)

---

# TOP3) **비용/슬리피지/체결/차입(숏) 비용 반영 + 민감도 스윕**
### (a) 왜 필요한지
- 8~14개 종목 집중 전략은 리밸런스 때 **턴오버가 높아질 수 있어** 비용에 취약.
- lockbox 성과가 괜찮아도, 비용이 빠지면 실전이 무너지는 케이스가 많다(특히 고빈도 리밸런스).

### (b) 위험/부작용
- 비용 모델을 강화하면 **백테스트 수익 급감** 가능(하지만 그게 현실).
- 슬리피지/임팩트 모델이 과도하면 **진짜 알파까지 제거**할 수 있음(보수성 과다).

### (c) 최소 실험(2~3개)
- **[E3] 비용 모델 패치**
  - 고정 수수료 + bid/ask spread(또는 ATR 기반) + 거래대금 대비 임팩트(단순 파워 모델) 적용
  - 숏이 있다면 borrow cost(보수적으로 상수라도) 반영
- **[E3] 비용 민감도 스윕**
  - 비용 0.5x / 1x / 2x에서 성능이 **단조 감소**하며 “2x에서도 생존”하는지 확인
- **[E4] 턴오버 캡(거래량/리밸런스 제약) 동시 적용**
  - 비용을 넣고도 남는 신호인지 확인하기 위해, “불필요 매매”를 줄이는 강제 장치도 같이 실험

### (d) PASS 조건
- **Cost survival gate:** 비용 1x에서
  - `lockbox_mean`이 Champion 대비 **-10% 이내** 유지
  - `worst_mdd`가 **-0.09 보다 나쁘지 않을 것**
- **Sensitivity gate:** 0.5x → 1x → 2x 비용에서 성능이 **급격히 붕괴(예: mean이 50% 이상 급락)**하면 FAIL(턴오버 의존)

# TOP4) **8~14 종목 제약 준수 + 노출/리스크(베타/변동성/섹터) 통제**
### (a) 왜 필요한지
- “Tech+Healthcare 중심”에서 시장 레짐에 따라 **QQQ/XLV 베타가 과도**해지면, 알파가 아니라 **시장 방향성**으로 벌고 잃는다.
- 종목 수 제약(8~14)을 코드 레벨에서 강제하지 않으면, 최적화 과정에서 **묵시적으로 더 넓은 분산/집중**으로 새는 경우가 있다.

### (b) 위험/부작용
- 리스크 오버레이는 수익률 상단을 깎을 수 있다.
- 종목 수/캡을 강제하면 신호가 약할 때 **현금 비중이 늘거나**(노출 감소) **억지 매수**가 발생할 수 있음.

### (c) 최소 실험(2~3개)
- **[E4] 8~14 강제 + 단일종목/섹터 캡**
  - 예: 단일종목 최대 15~20%, 섹터(Tech/HC 내) 하위그룹 캡(가능하면)
- **[E4] 변동성 타겟 + 베타 클램프**
  - 포트폴리오 ex-ante vol을 일정 범위로 맞추고, QQQ 베타가 임계 초과 시 노출 축소
- **[E5] 레짐 게이트와 결합**
  - 레짐이 위험 오프일 때 포지션 수는 유지하되 gross를 줄이는 식으로 “형태는 유지, 노출만 조절”

### (d) PASS 조건
- **Constraint gate:** 모든 날짜에서 종목 수가 **8~14 유지**(위반=FAIL)
- **Exposure gate:** QQQ 베타/포트 변동성의 상위 5% 꼬리가 Champion 대비 **악화되지 않을 것**
- **Drawdown gate:** `worst_mdd`가 **-0.085보다 나빠지면 FAIL**(Champion과 비슷한 DD 품질 유지)

# TOP5) **레짐(Tech vs Healthcare/금리/VIX) 기반 노출 스위치 — ETF는 “지표만”**
### (a) 왜 필요한지
- Tech/Healthcare는 **금리(장기물)·변동성(VIX) 레짐**에 민감. 같은 알파라도 레짐에 따라 기대값이 바뀐다.
- 후보가 lockbox에서 약해질 때, 종종 “신호는 있는데 레짐이 바뀌어 실패”인 경우가 있다.

### (b) 위험/부작용
- 레짐 게이트는 잘못 설계하면 **타이밍 실패(진입 지연/이탈 지연)**로 성과 악화.
- 지표가 많아지면 과최적화 포인트가 늘어난다(지표는 최소화).

### (c) 최소 실험(2~3개)
- **[E5] 레짐 지표 최소 세트로 고정(매매는 주식만)**
  - 예시(지표): QQQ vs XLV 상대강도, VIX 수준/변화, TLT 모멘텀(금리 방향 프록시)
- **[E5] 레짐별 gross 노출 스위치**
  - Risk-on: gross 100% / Risk-off: gross 30~60% 같은 단순 스위치
- **[E2] 레짐 규칙의 Purged WF 검증**
  - 레짐 규칙은 특히 과최적화되기 쉬우므로 purged로만 통과 인정

### (d) PASS 조건
- **Simplicity gate:** 레짐 피처/규칙 수를 **고정(추가 금지)**하고, 임계값 탐색도 제한(예: 2~3개 후보만)
- **Regime robustness gate:** 레짐 전환 구간(급락/급등)에서
  - `lockbox_min`이 Champion(0.7355) 대비 **유의미하게 악화되지 않을 것**
- **Turnover gate:** 레짐 스위치 도입 후 턴오버가 **유의미하게 증가(예: +30% 이상)**하면 FAIL(비용/운영 부담 증가)

## 48시간 자동 루프 형태(각 실험 공통 템플릿): (1) 실험 정의 (2) 게이트 (3) 기대 관측치
아래를 **E1→E5 순서**로 굴려서 “안전장치 먼저, 알파는 나중”으로 진행.

### E1 (누수 센티넬)
- (1) 실험 정의: 피처 타임스탬프 검증 + execution lag 강제 + 코퍼레이트액션 정렬 테스트
- (2) 게이트: 센티넬 위반 0건, 분할/배당 이벤트 구간 수익률 급점프 탐지 시 FAIL
- (3) 기대 관측치: tuning_mean 하락 가능, 대신 fold/lockbox 변동성 감소

### E2 (Purged WF + 과최적화 진단)
- (1) 실험 정의: embargo 포함 워크포워드 + 파라미터 프리즈 + 퍼뮤테이션 진단
- (2) 게이트: 셔플 성능 붕괴(정상) 확인, 프리즈 버전이 lockbox에서 크게 무너지지 않음
- (3) 기대 관측치: 챔피언 대비 평균은 비슷하거나 소폭 하락, min/MDD 개선이 나오면 “진짜 개선”

### E3 (비용/체결)
- (1) 실험 정의: 비용/슬리피지/임팩트/borrow 반영 + 0.5x/1x/2x 스윕
- (2) 게이트: 2x에서도 완전 붕괴 금지, 비용 포함 후에도 DD 품질 유지
- (3) 기대 관측치: 고턴오버 신호 제거 → 거래 횟수 감소, 수익선이 매끈해질 수 있음

### E4 (제약/리스크 오버레이)
- (1) 실험 정의: 8~14 강제 + 캡 + vol/beta 클램프 + 턴오버 캡
- (2) 게이트: 제약 위반 0, worst_mdd 악화 금지
- (3) 기대 관측치: 평균 일부 희생 대신 최저 성과/꼬리 위험 개선

### E5 (레짐 게이트)
- (1) 실험 정의: QQQ/XLV/VIX/TLT 관측으로 risk-on/off gross 스위치
- (2) 게이트: 규칙 복잡도 고정, 턴오버 급증 금지
- (3) 기대 관측치: 급락 국면 손실 완화(=lockbox_min 및 worst_mdd 개선)

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래 순서대로 보면 “알파가 없는 것”과 “알파가 있는데 구현/운영이 먹는 것”을 분리할 수 있다.

## 1) Trigger(신호 발생) 문제
- **점검:** 신호 발생 빈도(월/분기), 신호가 강한 날의 분포(상위 5% days)
- **트리거:** 신호 빈도가 너무 낮거나 특정 연도에 몰림 → 과최적화/레짐 의존
- **조치:** E2로 purged + 프리즈; 퍼뮤테이션에서 살아남는지 확인

## 2) Apply(적용/체결/딜레이) 문제
- **점검:** decision→execution 지연, 리밸런스 시점(종가/시가), 결측 처리
- **트리거:** “이상하게 좋은 체결” 흔적(슬리피지 0 가정 등)
- **조치:** E1(딜레이 강제) + E3(체결/슬리피지)로 현실화

## 3) Exposure(노출) 문제 — 사실상 베타 전략이 됨
- **점검:** 포트 QQQ 베타, XLV 상대노출, 스타일(모멘텀/퀄리티) 로딩, 상관 구조
- **트리거:** 성과가 QQQ 방향성과 동행, 알파가 아니라 시장 프리미엄
- **조치:** E4(베타/vol 클램프) + E5(레짐 gross 스위치)

## 4) Cost(비용) 문제 — 턴오버가 알파를 먹음
- **점검:** 월간/연간 turnover, 거래당 기대수익(마진) vs 비용, 비용 2x 스트레스
- **트리거:** 비용 1x만 넣어도 샤프 급락/손익 역전
- **조치:** E3(비용 모델) + E4(턴오버 캡)로 “비용 후 알파”만 남김

## 5) Regime(레짐) 문제 — Tech/HC의 금리·변동성 민감도
- **점검:** VIX 상/하위 분위 성과, TLT 모멘텀 국면별 성과, QQQ vs XLV 국면별 성과
- **트리거:** 특정 레짐에서만 벌고 다른 레짐에서 꾸준히 까먹음
- **조치:** E5(레짐 게이트) 단순 규칙으로만, E2(purged)에서만 통과 인정
