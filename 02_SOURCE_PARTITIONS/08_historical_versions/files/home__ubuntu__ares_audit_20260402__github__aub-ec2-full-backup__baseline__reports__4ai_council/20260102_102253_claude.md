## 1. 우선순위 TOP 5 실험

### EXP-1: 비용 현실화 패치
```
[왜 필요]
- 현재 lockbox 결과가 gross return일 가능성
- 실제 운영 시 연 200-400bp 비용 누락 → 샤프 0.3-0.5 하락 예상

[위험/부작용]
- 턴오버 높은 전략 전멸 가능
- 비용 과대 추정 시 저회전 편향 발생

[실험]
EXP-1A: 편도 15bp (보수) 적용 후 lockbox 재실행
EXP-1B: 편도 25bp (공격) 적용 후 lockbox 재실행
EXP-1C: 턴오버 페널티 (연 100% 초과분 × 50bp) 추가

[PASS 조건]
- 비용 반영 후 lockbox_mean ≥ 1.2 AND lockbox_min ≥ 0.5
- Champion/Candidate 순위 역전 시 → 역전된 쪽 채택
```

---

### EXP-2: Champion 과최적화 진단
```
[왜 필요]
- tuning_min 0.43 vs lockbox_min 1.13 → 역전 현상 (비정상)
- 일반적으로 OOS < IS 인데 반대 → 데이터 누수 or 우연

[위험/부작용]
- 누수 확정 시 Champion 폐기 필요
- 검증 과정에서 전체 파이프라인 재점검 필요

[실험]
EXP-2A: Fold 셔플 (시드 3개) → tuning/lockbox 분포 재측정
EXP-2B: Feature importance 상위 3개 제거 후 재학습
EXP-2C: 학습 기간 50% 축소 → 성능 붕괴 여부 확인

[PASS 조건]
- 셔플 후 tuning_mean 변동 < 15% → 안정
- 셔플 후 tuning_mean 변동 > 30% → 누수 확정 → Champion 폐기
```

---

### EXP-3: MDD-수익 트레이드오프 정량화
```
[왜 필요]
- Candidate MDD 4.1% (Champion 9.3% 대비 56% 개선)
- 대가로 lockbox_mean 1.52 vs 1.79 (15% 손실) → 적정 교환인가?

[위험/부작용]
- MDD 최소화 편향 → 저노출/현금 과다 보유 전략화
- 실제 드로다운은 연속 손실에서 발생 (단일 MDD 지표 한계)

[실험]
EXP-3A: 레버리지 1.2x 적용 → MDD 5% 타겟 유지하며 수익 복원 가능?
EXP-3B: 포지션 한도 15%→20% 완화 → lockbox_mean 변화
EXP-3C: MDD 6% 허용 시 최적 파라미터 탐색

[PASS 조건]
- lockbox_mean ≥ 1.65 AND MDD ≤ 6%
- Sharpe/MDD 비율 ≥ 0.25 유지
```

---

### EXP-4: 레짐 필터 점검
```
[왜 필요]
- Candidate lockbox_min 0.33 → 특정 레짐에서 거의 무력화
- 2022-type 하락장 or 2020-type 급등장에서 어떤 쪽이 약한지 확인 필요

[위험/부작용]
- 레짐 필터 추가 → 복잡도 증가 → 과최적화 루프 진입
- 레짐 정의 자체가 사후적 (look-ahead 위험)

[실험]
EXP-4A: VIX 30+ 구간만 별도 백테스트 → 성능 분리
EXP-4B: SPY 200MA 하회 구간 성능 분리
EXP-4C: 월별 수익 분포 → worst 3개월 공통점 추출

[PASS 조건]
- 특정 레짐에서 음수 수익 확인 시 → 해당 레짐 노출 50% 감소 룰 추가
- 레짐 필터 적용 후 lockbox_min ≥ 0.7
```

---

### EXP-5: 종목 집중도 vs 분산 실험
```
[왜 필요]
- 8-14종목 제약 내에서 최적 개수 미정
- 집중 (8개) vs 분산 (14개) → 리스크-수익 프로파일 상이

[위험/부작용]
- 과도한 집중 → 개별 종목 리스크 증폭
- 과도한 분산 → 확신 낮은 종목 포함 → 알파 희석

[실험]
EXP-5A: 상위 8개 고정 → 동일가중
EXP-5B: 상위 12개 → 신뢰도 가중 (랭킹 역순)
EXP-5C: 섹터당 최대 3개 제약 추가

[PASS 조건]
- 최적 개수에서 lockbox Sharpe ≥ 현재 + 0.1
- 단일 종목 기여도 < 전체 수익의 40%
```

## 2. 성능 미변동 시 원인 분해 트리

```
성능 안 움직임
│
├─ [트리거] 시그널 자체가 안 바뀜?
│   └─ 확인: 일별 시그널 변화율 로그 → <5% 변동 시 트리거 사망
│
├─ [적용] 시그널 바뀌어도 포지션 불변?
│   └─ 확인: 리밸런싱 임계값 과대 (예: 20% 변동만 실행)
│
├─ [노출] 포지션 잡아도 비중 미미?
│   └─ 확인: 평균 투자비중 < 70% → 현금 과다
│
├─ [비용] 수익은 있으나 비용이 상쇄?
│   └─ 확인: gross vs net 비교 → 차이 > 100bp/년 시 문제
│
└─ [레짐] 현재 시장이 전략 사각지대?
    └─ 확인: 최근 3개월 vs 전체 기간 성능 비교
```

## 3. 48시간 자동화 루프 정의

```yaml
# experiment_batch_20260102.yaml

experiments:
  - id: EXP-1A
    command: "python3 backtest.py --cost-bp 15 --config candidate_latest"
    gate: "lockbox_mean >= 1.2 AND lockbox_min >= 0.5"
    timeout: 4h
    
  - id: EXP-2A
    command: "python3 cv_shuffle.py --seeds 42,123,456 --config champion_v5"
    gate: "std(tuning_mean) / mean(tuning_mean) < 0.15"
    timeout: 6h
    
  - id: EXP-3B
    command: "python3 backtest.py --position-limit 0.20 --config candidate_latest"
    gate: "lockbox_mean >= 1.65 AND worst_mdd >= -0.06"
    timeout: 4h

auto_rules:
  - if: ALL_PASS → 병합 후 champion_v6 생성
  - if: EXP-2A FAIL → champion_v5 폐기, candidate를 champion으로 승격
  - if: MIXED → 수동 리뷰 플래그
```
