## 1. 우선순위 TOP 5 PATCHES

### PATCH #1: 실험 실효성 검증 (Sanity Check)
```
의심: 실험 코드가 실제 백테스트에 반영 안 됨
```

**(a) 왜 필요한가**
- candidate와 champion의 lockbox 차이 0.0001 = 사실상 동일
- 코드 변경이 실제 weight에 영향 주는지 확인 필요

**(b) 위험/부작용**
- 없음 (진단 작업)

**(c) 최소 실험**
```yaml
EXP-1.1:
  name: "forced_delta_injection"
  action: |
    특정 종목 weight를 강제로 ±5% 변경 후 backtest
    결과가 변하지 않으면 파이프라인 버그
  gate: "lockbox_mean 변화 > 0.01"
  observe: ["weight_diff", "return_diff"]

EXP-1.2:
  name: "param_echo_test"  
  action: |
    config 파라미터 2배로 변경
    로그에서 해당 값이 실제 사용되는지 grep
  gate: "로그에 변경값 출현"
  observe: ["config_loaded", "param_used_in_calc"]
```

**(d) PASS 조건**
- [ ] 강제 delta → lockbox 변화 > 1%
- [ ] 파라미터 변경 → 로그에 반영 확인

### PATCH #2: tuning_min 0.05 Fold 해부
```
의심: 특정 fold가 레짐 붕괴 or 데이터 오염
```

**(a) 왜 필요한가**
- tuning_min 0.05 = 거의 전멸 fold 존재
- 이 fold가 어떤 기간인지, 왜 망했는지 모르면 개선 불가

**(b) 위험/부작용**
- 해당 fold만 과최적화 위험

**(c) 최소 실험**
```yaml
EXP-2.1:
  name: "worst_fold_autopsy"
  action: |
    python3 tools/fold_analyzer.py --find-worst --metric tuning
    출력: fold_id, 기간, 주요 손실 종목, MDD 시점
  gate: "원인 식별 (레짐/종목/버그)"
  observe: ["fold_period", "top3_loss_tickers", "mdd_date"]

EXP-2.2:
  name: "worst_fold_isolation"
  action: |
    해당 fold 제외 후 전체 지표 재계산
    과최적화 여부 판단용 delta 측정
  gate: "제외 시 tuning_mean 변화 < 5%"
  observe: ["mean_with_fold", "mean_without_fold"]

EXP-2.3:
  name: "regime_tag_injection"
  action: |
    worst fold 기간에 VIX > 30 또는 SPY drawdown > 10% 여부 태깅
    레짐 필터 적용 시 성능 변화 측정
  gate: "레짐 필터 적용 후 worst_fold 개선 > 20%"
  observe: ["vix_during_fold", "spy_dd_during_fold"]
```

**(d) PASS 조건**
- [ ] worst fold 원인 1개 이상 식별
- [ ] 레짐 태그 시 해당 fold MDD 개선

### PATCH #3: 시그널→웨이트 전파 효율 점검
```
의심: 시그널 변화 → 웨이트 변화 → 수익 변화 체인 끊김
```

**(a) 왜 필요한가**
- 시그널 모듈 바꿔도 결과 동일 = 웨이트 결정에 시그널 영향 미미
- position sizing이 시그널을 무시하고 있을 가능성

**(b) 위험/부작용**
- 시그널 민감도 높이면 whipsaw 증가

**(c) 최소 실험**
```yaml
EXP-3.1:
  name: "signal_to_weight_correlation"
  action: |
    일별 (signal_score, actual_weight) 상관계수 계산
    corr < 0.3이면 전파 실패
  gate: "correlation > 0.5"
  observe: ["daily_corr", "weight_change_lag"]

EXP-3.2:
  name: "signal_amplification_test"
  action: |
    signal을 2x 증폭 후 weight 변화량 측정
    변화량 < 1%면 sizing 로직이 clipping
  gate: "weight_delta > signal_delta * 0.3"
  observe: ["signal_delta", "weight_delta", "clipping_rate"]
```

**(d) PASS 조건**
- [ ] signal-weight 상관 > 0.5
- [ ] 2x signal → weight 변화 비례 확인

### PATCH #4: 거래비용/슬리피지 현실화
```
의심: 비용 0 가정으로 과대 성능 → 실제 적용 시 정체
```

**(a) 왜 필요한가**
- lockbox 성능이 높지만 실제 운영 시 하락 예상
- 비용 반영 후에도 견딜 수 있어야 진짜 alpha

**(b) 위험/부작용**
- 비용 과다 적용 시 전략 포기 오류

**(c) 최소 실험**
```yaml
EXP-4.1:
  name: "cost_sensitivity_ladder"
  action: |
    슬리피지 [0bp, 5bp, 10bp, 20bp] 적용 후 lockbox 비교
  gate: "10bp에서 lockbox_mean > 1.5"
  observe: ["lockbox@0bp", "lockbox@10bp", "breakeven_bp"]

EXP-4.2:
  name: "turnover_penalty_check"
  action: |
    연간 turnover 계산 후 (turnover × cost)가 return의 몇%인지
  gate: "cost_drag < 15% of gross_return"
  observe: ["annual_turnover", "cost_drag_pct"]
```

**(d) PASS 조건**
- [ ] 10bp 비용에서 lockbox > 1.5
- [ ] cost_drag < 15%
