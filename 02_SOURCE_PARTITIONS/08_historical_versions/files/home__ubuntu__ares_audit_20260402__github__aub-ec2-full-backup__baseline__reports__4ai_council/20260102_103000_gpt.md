(절대규칙 준수: 질문 없음, 누수/과최적화/서바이버십/비용/운영리스크 우선, **미국주식 only + Tech/Healthcare 8~14종목**, ETF는 **관측 지표만**, 제안은 **유니크 실험 5개(E1~E5)**로 제한하고 각 제안은 그 조합으로만 구성)

각 TOP5 제안은 아래 **E1~E5를 2~3개씩 조합**해서 커버한다. (케이스 폭발 방지)

# 1) TOP5 우선순위 제안(코드/아키텍처/전략)

## TOP1. 누수/타임라인 무결성 하드 게이트 추가 (Leakage/Overfit 최우선)
### (a) 왜 필요한지
- 현재 “성능이 안 움직임(no-delta)” 상황에서 **가장 흔한 원인**이 (1) 피처 시프트 불일치 (2) 리밸런스 시점과 체결가 참조 시점 혼재 (3) 미래 데이터 섞임(리비전/기업행사/지표 확정 시점)이다.
- OOS mean이 실험마다 크게 흔들리지 않으면, **진짜 엣지가 없거나** / **누수로 이미 과대평가되었거나** / **게이트가 없어서 실험이 동일 동작** 중 하나일 확률이 높다.

### (b) 위험/부작용
- 누수 제거 후 성능 급락 가능(정상).
- 일부 피처가 “사실상 무력화”되어 모델이 단순화될 수 있음(정상).

### (c) 최소 실험(공유 세트에서 2~3개)
- **E1 + E3** (필수), 보조로 **E4**

### (d) PASS 조건
- (필수) “Leakage sentinel”에서 **수익이 0 근처로 붕괴**(미래정보 차단이 실제로 작동했다는 증거).
- (필수) 리밸런스/피처 타임스탬프가 **단일 규칙으로 로그에 증명**됨(E3 산출물).
- (권장) 누수 차단 후에도 OOS가 완전 붕괴가 아니라면(예: OOS mean 유지율 30~70%) “진짜 엣지” 후보.

---

## TOP2. 거래비용/턴오버/체결가 모델을 “강제”로 넣고, 비용 기반 게이트로 실험을 분리
### (a) 왜 필요한지
- 비용 미반영이면 **테크/헬스케어 대형주라도** 잦은 리밸런스에서 edge가 사라진다.
- “성능이 안 움직임”은 종종 **(gross 기준) 개선이 (net 기준) 상쇄**되기 때문에 발생한다. 지금은 비용/리밸런스 로그도 깨져 있어(리밸런스 pinpoint 실패) 원인 확인이 불가능.

### (b) 위험/부작용
- net 성능 급락 가능(정상).
- 지나치게 보수적인 비용이면 과도하게 거래를 억제해 기회 손실.

### (c) 최소 실험
- **E2 + E3**, 보조로 **E5**(리스크 오버레이가 turnover를 줄일 수 있음)

### (d) PASS 조건
- net 기준으로 **gross 대비 열화폭이 설명 가능**해야 함: “턴오버 × 평균 비용”이 로그로 재현.
- “턴오버 상한”을 줬을 때도 OOS가 유지/개선되면 **엣지가 거래비용에 견디는 구조**.

---

## TOP3. 운영 리스크 제거: 리밸런스/어트리뷰션 로그 포맷 통일 + MDD/노출 산출 자동화
### (a) 왜 필요한지
- 현재 rebalance pinpoint가 **파일 포맷/경로 문제로 완전 실패**했고, champion의 `worst_mdd: None`은 **리스크 산출 파이프라인이 깨져있을 가능성**이 높다.
- 자동 루프에서 “성능이 안 움직임”을 깨려면, 최소한 **무엇이 바뀌었는지(거래/노출/비용/게이트)**가 매회 추적돼야 한다.

### (b) 위험/부작용
- 로그 증가로 저장/비용 증가.
- 파이프라인 변경으로 과거 결과와 1~2회 불일치 발생(정상, 이후 안정화).

### (c) 최소 실험
- **E3 + E2** (리밸런스 로그 없이는 비용도 검증 불가)

### (d) PASS 조건
- 매 run마다 다음이 **자동 산출/저장**:
  - 리밸런스 이벤트(시각, 대상, 목표/실제 수량, 체결가/가정체결가, 비용)
  - 포지션/노출(총익스포저 min/max, 종목별 가중치)
  - 리스크(worst MDD, 1d/5d VaR 대체지표라도)
- pinpoint 스크립트가 **에러 없이 base/cand 비교 리포트 생성**

## TOP4. 서바이버십/유니버스 무결성: 8~14종목(Tech+Healthcare) “가용 시점” 강제 + IPO/상장전 데이터 차단
### (a) 왜 필요한지
- “미국주식 only + 8~14종목”은 설계상 **특정 종목의 생존/대형화 편향**이 전략 전체를 지배한다.
- 특히 상장 전 기간이 데이터에 섞이거나(0 거래량/합성) 또는 현재 구성 종목을 과거로 끌고 가면 **서바이버십 편향**이 생긴다.

### (b) 위험/부작용
- 백테스트 구간 일부에서 종목 수 부족 → 현금/대체 규칙 필요(하지만 ETF 매매 금지이므로 현금 유지).
- 성능 저하 가능(정상).

### (c) 최소 실험
- **E4 + E1** (유니버스 시점 무결성 + 타임라인 무결성)

### (d) PASS 조건
- 각 종목에 대해 “첫 거래일 이후에만 거래/피처 활성”이 로그로 증명.
- 종목 수가 8 미만으로 내려가면 **현금 비중**으로 자동 처리(임의 종목 확장 금지) + 성능/리스크 산출 정상.

## TOP5. 레짐(리스크온/오프) 오버레이로 익스포저/드로우다운 게이트를 추가 (ETF는 관측만)
### (a) 왜 필요한지
- 현재 익스포저가 **0.47~0.84**로 상시 높고, worst_mdd가 None인 상태는 **리스크 제어가 실질적으로 없거나 측정 불능**일 수 있다.
- Tech/Healthcare 집중은 레짐에 따라 상관이 급등한다. 레짐 게이트가 없으면 OOS 개선이 “노출 증가”로만 나타나고, net 성능은 비용/급락에 먹힐 수 있다.

### (b) 위험/부작용
- 레짐 신호가 과민하면 잦은 온/오프 → turnover 증가(그래서 E2와 같이 가야 함)
- 상승장에서 노출을 낮춰 기회비용.

### (c) 최소 실험
- **E5 + E2**, 보조로 **E3**(게이트 발동 로그 필요)

### (d) PASS 조건
- 동일 기간 대비:
  - worst MDD 개선(또는 tail 손실 감소)
  - turnover 감소 또는 유지
  - OOS mean이 약간 낮아져도 **위험조정(예: OOS/MaxDD proxy) 개선**

# 2) 공유 실험 세트(E1~E5): 48시간 자동 루프 형태로 명령형 정의
아래 5개만 “유니크 실험”으로 등록하고, TOP1~TOP5는 이 조합으로만 굴린다.

---

## E1) Leakage Sentinel + Point-in-Time 강제
1) **실험 정의**
- 모든 피처/라벨을 “결정시점 t에서 이용 가능한 정보만” 사용하도록 강제:
  - 가격/거래량 기반 피처: `t-1 close`까지만 사용(리밸런스가 t 오픈이면 t-1 종가 기준)
  - 재무/이벤트/리비전 데이터가 있다면 “발표일/유효일” 기준으로 전진 채움(미래 반영 금지)
- **Leakage sentinel** 추가(의도적으로 누수를 차단하는 확인 장치):
  - 라벨을 +1일 더 뒤로 밀거나,
  - 피처를 +1일 더 과거로 밀어 성능이 붕괴하는지 확인

2) **게이트**
- sentinel 변형에서 OOS가 그대로면 → **누수 의심/실험 무효**로 FAIL
- 데이터 타임스탬프 검증 실패 시 run 중단

3) **기대 관측치**
- sentinel에서는 수익/샤프가 0 근처로 하락
- 본 실험에서는 일부 성능 하락 후에도 구조가 남으면 “실엣지” 가능성 상승

---

## E2) 비용/슬리피지 + Turnover Cap (net 성능 고정)
1) **실험 정의**
- 거래비용 모델을 net PnL에 강제 반영:
  - (최소) 고정 bps + 스프레드 절반 + 슬리피지(거래대금/ADV 기반 간단식)
- 턴오버 상한(예: 일/리밸런스당 총 교체 비중 cap) 적용
- **ETF 매매 금지 유지**, 현금은 허용

2) **게이트**
- 비용 적용 후 net OOS가 기준 대비 급락하더라도 “설명 불가한” 형태(턴오버 낮은데도 net만 급락)면 데이터/로깅 오류로 FAIL
- turnover cap 위반 시 주문을 스케일다운하고 이벤트 로그 기록

3) **기대 관측치**
- gross→net 열화가 “턴오버×비용”과 정합
- turnover를 줄인 변형이 net에서 상대적으로 우수해짐

---

## E3) Rebalance/Attribution 로깅 통일 + worst_mdd 산출 복구
1) **실험 정의**
- 리밸런스 로그를 **단일 JSONL 스키마**로 고정 저장(경로/파일명 규칙 포함)
- base/cand 모두 동일 포맷으로 저장하여 pinpoint가 바로 읽게 함
- worst_mdd를 백테스트 종료 시점에 반드시 계산/저장(없으면 FAIL)

2) **게이트**
- 파일 생성/파싱 실패 시 run FAIL (조용히 넘어가지 않음)
- worst_mdd가 None이면 FAIL

3) **기대 관측치**
- “성능이 안 움직임”일 때도 **변경점(거래/노출/비용/게이트 발동)**이 로그에서 드러남
- pinpoint 리포트가 정상 생성

---

## E4) Universe PIT + 8~14 Tech/Healthcare 강제 + 상장일 필터
1) **실험 정의**
- 유니버스를 8~14로 고정(Tech/Healthcare 중심)하되, 각 종목에 대해:
  - 첫 거래일 이전 구간에서 거래/피처를 0으로 강제(상장 전 데이터 차단)
  - 유동성(ADV) 하한, 가격 하한, 거래정지/이상치 제거 규칙 추가
- 종목 수가 8 미만이면 **현금 비중 증가**로 처리(ETF 대체 금지)

2) **게이트**
- 종목별 “활성 시작일” 이전에 포지션이 생기면 FAIL
- 종목 수 부족 시 강제 확장(룰 위반)하면 FAIL

3) **기대 관측치**
- 과거 구간에서 “비정상적으로 매끈한” 성능이 사라질 수 있음(정상)
- 대신 운영/재현성이 증가

---

## E5) 레짐 오버레이(관측 ETF/지표)로 익스포저 게이트
1) **실험 정의**
- ETF는 **관측만** 사용(매매 금지):
  - 예: QQQ, XLV, IWM, TLT, VIX(또는 VIX 대체 지표)
- 간단한 레짐 분류로 목표 익스포저를 스케일:
  - Risk-off면 목표 익스포저 상한을 낮추고(예: 0.2~0.4), Risk-on이면 기존 유지
- 게이트 발동 시 포지션 스케일만 변경(종목 선택 로직은 그대로 두어 과적합 방지)

2) **게이트**
- 레짐 스위칭 빈도가 과도하면(예: N일 중 스위치 비율 상한) 자동 완화(히스테리시스/쿨다운)
- 익스포저 min/max가 설정 범위를 벗어나면 FAIL

3) **기대 관측치**
- MDD/tail 손실 감소
- net 성능이 동일하거나 약간 낮아도 위험조정 성능 개선

---

# 3) “성능이 안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐) — 명령형 트리
아래를 **매 run마다 자동 리포트**로 찍어 “정체 원인”을 분리한다.

## A. Trigger(신호가 변하나?)
- [ ] 신호 분포(스코어/랭크)의 표준편차가 run 간 거의 동일하면 **실험이 실제로 신호를 못 바꾸는 것** → E3로 파라미터/피처 해시를 로그에 박고 동일성 검사
- [ ] 상위/하위 랭크 종목이 매번 동일하면 **유니버스/필터 고착** → E4 점검

## B. Apply(신호가 주문으로 반영되나?)
- [ ] 목표가중치 대비 실제가중치 괴리가 큰데 조용하면 **주문/제약/스케일링 버그** → E3에 “목표/실제/차이”를 리밸런스 이벤트로 저장
- [ ] turnover cap/리스크 게이트가 항상 발동이면 **항상 축소되어 차이가 안 남** → E2/E5에서 게이트 발동률 리포트

## C. Exposure(노출이 성능을 다 먹나?)
- [ ] OOS가 좋아 보이는데 익스포저가 같이 올라가면 **알파가 아니라 베타** → E5로 베타 억제 후 성능 유지 여부 확인
- [ ] 익스포저 범위가 좁고 고정이면(항상 0.7 근처) 실험 간 차이가 작을 수 있음 → 노출 스케일링이 실험을 덮는지 E3로 확인

## D. Cost(비용이 상쇄하나?)
- [ ] gross는 개선인데 net이 정체면 **거래비용/슬리피지/턴오버 상쇄** → E2에서 turnover×비용 어트리뷰션 자동 출력
- [ ] net이 gross보다 더 좋아지면 비용 부호/적용 시점 버그 가능 → E2/E3 즉시 FAIL 처리

## E. Regime(레짐에서 죽나?)
- [ ] 특정 기간만 성과가 나오면 **레짐 종속** → E5에서 risk-off 회피가 MDD를 줄이는지 확인
- [ ] 레짐 지표 자체가 미래를 보면 누수 → E1로 지표도 동일하게 시프트 검증

## 다음 24~48시간 “명령형 체크리스트(실행 순서)”
