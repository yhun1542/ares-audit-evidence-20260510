### 1. 24~48시간 우선순위 TOP 5 (Action Checklist)

1.  **[CRITICAL] 로깅 시스템 긴급 복구 (`rebalance.csv` Parsing Error 해결)**
    *   현재 상태는 '눈을 감고 운전' 중. `Expecting value` 에러는 파일이 비어있거나 포맷이 깨졌음을 의미. 이것 없이는 Degenerate Fold의 원인(시그널 부재 vs 주문 거절)을 파악 불가.
2.  **[CRITICAL] Degenerate Folds [1, 2, 3, 8] 원인 규명 및 해소**
    *   전체 구간의 40%가 'Degenerate(거래 없음/평가 불가)' 상태임. 이는 전략이 특정 시장 국면(예: 하락장, 횡보장)에서 완전히 셧다운됨을 시사. "생존"이 아닌 "실종" 상태.
3.  **[RISK] Tech/Healthcare 유니버스 및 섹터 밸런스 강제화**
    *   특정 섹터(Tech) 쏠림으로 인한 MDD 심화 가능성. Healthcare 종목이 최소 2~3개 포함되도록 유니버스 선정 로직(Hard Constraint) 점검.
4.  **[PERFORMANCE] 변동성 기반 포지션 사이징(Vol-Targeting) 도입**
    *   OOS Mean(3.32)과 Min(-0.02)의 괴리가 큼. 승률은 낮고 한 방이 큰 구조일 가능성. 변동성을 역수로 취해 포지션 크기를 조절하여 하방 방어.
5.  **[OPS] 슬리피지/거래비용 모델 현실화 (보수적 적용)**
    *   현재 높은 OOS Mean이 잦은 매매와 낮은 비용 가정에서 온 환상인지 검증 필요.

### 2. 실행 가능한 Patch / 실험 제안 (Top 3)

#### 제안 A: `Logger_Fix_and_Trace` (시스템/관측)
*   **(a) 필요성:** `rebalance_pinpoint.py`가 실패함. 진입/청산 로직이 왜 작동 안 하는지(특히 Degenerate Folds에서) 로그를 텍스트로 남겨야 함.
*   **(b) 위험:** 전략 로직 변경 없음. 시스템 오버헤드 미미함.
*   **(c) 실험 (3 items):**
    1.  **[EXP-A1] Force Log Flush:** 매 리밸런싱 스텝마다 `csv/jsonl` 강제 flush 및 포맷 유효성 검증 코드 삽입.
    2.  **[EXP-A2] Zero-Trade Logging:** 거래가 '0'인 날에도 그 이유(예: `Signal < Threshold`, `Vix > 30`, `Liquidity fail`)를 명시적으로 기록하는 필드 추가.
    3.  **[EXP-A3] Fallback Logger:** CSV 파싱 실패 시 Raw Text로 덤프 뜨는 예외 처리 추가.
*   **(d) PASS 조건:**
    *   `AUB Rebalance Pinpoint` 툴이 에러 없이 리포트를 생성.
    *   Degenerate Folds 구간(1,2,3,8)의 'No Trade' 사유가 명확히 식별됨.

#### 제안 B: `Relax_Regime_Filters` (로직/생존)
*   **(a) 필요성:** Degenerate Folds가 많은 것은 시장 필터(Regime Filter)가 너무 엄격(Strict)하다는 뜻. (예: VIX 25 이상 매매 금지 등). 이를 완화하여 일단 '돌아가게' 만들어야 함.
*   **(b) 위험:** 하락장에서 포지션을 잡아 MDD가 증가할 수 있음. (그러나 거래가 없는 것보단 나음).
*   **(c) 실험 (3 items):**
    1.  **[EXP-B1] Remove VIX Cutoff:** VIX 등 시장 변동성 기반 진입 금지 로직을 제거하거나 임계값을 50% 상향.
    2.  **[EXP-B2] Reduce Cash Buffer:** 현금 비중 제약(Min Cash)을 완화하여 유동성이 부족한 구간에서도 강제 진입 시도.
    3.  **[EXP-B3] Wide Stop-Loss:** 손절(Stop-Loss) 폭을 기존 대비 1.5배로 넓혀, 노이즈에 의한 조기 퇴출(Whipsaw)로 인한 포지션 증발 방지.
*   **(d) PASS 조건:**
    *   Degenerate Folds 개수가 4개에서 1개 이하로 감소.
    *   `oos_min`이 양수로 전환되거나 -0.01 이상으로 개선.

#### 제안 C: `Sector_Balance_Hedge` (전략/안정성)
*   **(a) 필요성:** 미국 Tech 주식만으로는 변동성 제어가 어려움. Healthcare(저변동성/방어주 성격)를 강제로 섞어 포트폴리오 안정화.
*   **(b) 위험:** Tech 주도 강세장에서 수익률(Alpha) 희석 가능성.
*   **(c) 실험 (3 items):**
    1.  **[EXP-C1] Sector Floor:** 포트폴리오 내 Healthcare 섹터 비중 최소 20% 강제 할당 (Constraint).
    2.  **[EXP-C2] Correlation Filter:** Tech 대표 ETF(XLK)와 상관계수가 0.7 이하인 종목만 유니버스에 편입.
    3.  **[EXP-C3] Inverse Scaling:** 최근 20일 변동성이 높은 종목(주로 Tech)의 비중을 축소하는 가중치 로직 적용.
*   **(d) PASS 조건:**
    *   `exposure_max`는 유지되면서 `worst_mdd` 개선(데이터 확보 시).
    *   Degenerate Folds 구간에서 방어적 매매가 일어나는지 확인.

### 3. 성능 정체 시 원인 분해 (Root Cause Decomposition)

성능 지표가 움직이지 않거나 0에 수렴할 때 다음 순서로 체크:

1.  **트리거(Trigger) 확인:**
    *   *가설:* 시그널 생성 로직 자체가 너무 보수적임.
    *   *확인:* Raw Signal 값이 진입 임계값(Threshold)을 넘는 횟수 카운트. (로그가 고쳐져야 확인 가능)
2.  **적용(Application) 실패:**
    *   *가설:* 시그널은 떴으나, `Min_Order_Size`나 `Lot_Size` 제한에 걸려 주문이 나가지 않음.
    *   *확인:* 모의 잔고 $10,000 이하 소액 계좌 설정 시 자주 발생. 초기 자본금 설정 확인.
3.  **비용(Cost) 과다:**
    *   *가설:* 잦은 리밸런싱으로 수수료가 알파를 다 까먹음.
    *   *확인:* Turnover(회전율) 지표 확인. 일간 회전율 10% 이상이면 과다. -> 주간 리밸런싱으로 변경 고려.
4.  **레짐(Regime) 불일치:**
    *   *가설:* 현재 전략이 '추세 추종'인데 데이터 구간이 '박스권'임.
    *   *확인:* 벤치마크(SPY/QQQ) 대비 상대 수익률(Relative Strength)이 횡보하는지 확인.
5.  **데이터(Data) 누수/오류:**
    *   *가설:* Look-ahead Bias로 인해 백테스트 엔진이 미래 데이터를 참조하다가, 실제 시뮬레이션 모드에서 차단되어 거래가 멈춤.
    *   *확인:* 피처 생성 시점의 `timestamp`와 거래 실행 시점 대조.
