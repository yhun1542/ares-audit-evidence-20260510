## 24~48시간 TOP5 우선순위(명령형 체크리스트)

### 1) **누수(Leakage) / 시간정렬(Time alignment) “즉시” 봉쇄**
- [ ] **결정시점 t(예: 종가 체결 vs 익일 시가 체결)**을 코드에서 단일하게 정의하고, 모든 feature/label/order 생성이 그 시점 이전 정보만 쓰게 강제하라.
- [ ] **feature 생성 파이프라인에 “shift 규칙”을 강제**(예: `feature_at_t`는 `<=t` 데이터만, `return_label`은 `t+1..`만)하고 unit test로 고정하라.
- [ ] **Adjusted price 사용 시 배당/분할이 미래정보로 스며드는지 점검**(특히 “Adj Close로 신호 생성 + Close로 체결” 조합 금지).

**(a) 왜 필요한지**
- 지금 챔피언이 tuning/lockbox 갭이 크지 않지만(3.47 vs 2.89), 작은 누수도 평균을 인위적으로 끌어올리고 candidate들이 “방향성 없이” 흔들리게 만든다.
- 누수는 이후 어떤 전략 개선도 의미 없게 만들며, 48시간 자동루프에서 “고착(성능이 안 움직임)”의 최상위 원인이다.

**(b) 위험/부작용**
- 누수 제거 후 성능 급락 가능(정상).
- 신호 지연(shift)로 거래 빈도/turnover 패턴 변화.

**(c) 최소 실험 2~3개(=단일 패치 내 변형)**
- (E1-1) **Hard shift 실험**: 모든 feature를 `+1 bar` shift(보수적) vs 기존.
- (E1-2) **Price source 실험**: 신호/체결 모두 `Close` 기반 vs 모두 `Adj Close` 기반(혼용 금지).
- (E1-3) **Label horizon 고정**: label을 `t→t+1`로만 제한 vs 기존(장기 label이면 누수 탐지에 유리).

**(d) PASS 조건(게이트)**
- **게이트(필수)**: “미래 bar 참조” 탐지 테스트 0건(예: pandas shift/merge 후 인덱스 역행, forward-fill이 미래를 끌어오는 케이스 포함).
- **성과 게이트(상대평가)**: 누수 차단 후에도 lockbox_mean이 **챔피언의 85% 이상** 유지 + worst_mdd 악화가 **+0.5%p 이내**면 통과(누수 제거 페널티 감안).

### 2) **거래비용/슬리피지/체결가능성(운영비용) “모델 내장”**
- [ ] **거래비용을 백테스트 코어에 상수로 박아넣지 말고**: (스프레드+슬리피지+수수료) 형태로 분해해 모델링하라.
- [ ] **turnover, 포지션 변경량(Δw) 기반 비용**을 기본으로 하고, 유동성 낮은 종목은 universe에서 제외/감점하라.
- [ ] **챔피언을 비용 반영 버전으로 재산출**해 “비용 포함 챔피언”을 새 기준선으로 만들어라(비용 없이 비교 금지).

**(a) 왜 필요한지**
- Tech/Healthcare 8~14종목은 개별주로도 충분히 turnover가 커질 수 있어, 비용 미반영은 과최적화와 동일한 효과를 낸다.
- 성능이 “안 움직이는” 원인이 사실은 비용 때문에 상쇄되는 구조일 수 있다.

**(b) 위험/부작용**
- 단기 성과 급락(정상).
- 거래가 줄면서 샤프 개선/악화가 혼재할 수 있음(레짐 의존).

**(c) 최소 실험 2~3개(=단일 패치 내 비용 스윕)**
- (E2-1) **비용 3단 스윕**: 5bp / 15bp / 30bp(왕복 기준)로 lockbox 재평가.
- (E2-2) **슬리피지 = k·|Δw|**(선형) vs **k·|Δw|^1.5**(비선형) 비교.
- (E2-3) **거래 제한 실험**: 리밸런스 빈도(매일 vs 주 2회 vs 주 1회)만 바꿔 turnover 민감도 측정.

**(d) PASS 조건(게이트)**
- **게이트(필수)**: 비용 포함 후에도 lockbox_mean이 **비용 포함 챔피언 대비 ≥ 100%**(즉, 비용 기준으로도 개선) 또는
- **대체 게이트(리스크형)**: lockbox_mean이 비용 포함 챔피언의 **≥ 95%**면서 worst_mdd가 **-0.70%p 이상 개선**되면 통과(방어 개선 인정).

### 3) **서바이버십/코퍼레이트 액션/데이터 공백 “락다운”**
- [ ] **유니버스(Tech+Healthcare 8~14) 선정 로직이 “현재 시점 티커 목록”을 참조하는지**(서바이버십)부터 차단하라.
- [ ] **상장폐지/합병/티커 변경 이벤트**를 “그 시점에 존재했던 티커”로 재구성하고, 빠진 구간은 명시적으로 결측 처리하라(자동 forward-fill 금지).
- [ ] **가격 조정(분할/배당)**과 **거래가능성(거래정지/거래량 0)** 필터를 운영 게이트로 넣어라.

**(a) 왜 필요한지**
- 8~14개 집중 포트는 한 종목의 데이터 왜곡이 전체 성과를 좌지우지한다.
- 서바이버십은 tuning/lockbox 모두를 동시에 부풀려 “후보들이 다 거기서 거기”처럼 보이게 만든다.

**(b) 위험/부작용**
- 과거 특정 기간에 “거래 불가능” 판정이 늘어나 수익 기회 감소.
- 유니버스가 줄면 분산효과 감소(단, 규칙상 8~14 유지 필요 → 결측 많은 종목을 교체하는 룰 필요).

**(c) 최소 실험 2~3개(=단일 패치 내 진단/스위치)**
- (E3-1) **Delist-aware 모드 ON/OFF**: delist/merge 처리 켠 버전 vs 기존 비교(성과보다 데이터 integrity를 우선).
- (E3-2) **No forward-fill 모드**: 가격/팩터 결측 발생 시 신호 생성/주문 생성 금지(“거래 중단”) vs 기존.
- (E3-3) **Adj-factor 일관성 테스트**: 조정계수 적용이 신호/체결/평가 전 구간에서 동일한지 강제.

**(d) PASS 조건(게이트)**
- **게이트(필수)**: (i) 유니버스 구성의 “미래 티커 참조” 0건, (ii) 결측 forward-fill로 인한 거래 발생 0건.
- **성과 게이트(완화)**: lockbox_mean이 10% 이내 하락이면 통과(서바이버십 제거 비용 인정), 대신 worst_mdd 악화 금지.

### 4) **레짐(변동성/섹터 리스크) 필터를 “관측지표 ETF”로만 추가**
- [ ] ETF는 매매하지 말고 **관측지표로만** 쓰되, QQQ(Tech), XLV(Health), SPY(시장)로 레짐을 정의하라.
- [ ] 레짐이 불리할 때는 “현금/노트레이드” 또는 “리스크 축소(포지션 스케일다운)”만 허용하라(종목 교체로 케이스 폭발 금지).

**(a) 왜 필요한지**
- Tech/Healthcare는 변동성 레짐에 민감하다. 동일 신호라도 레짐이 바뀌면 기대값이 0으로 수렴한다.
- “성능이 안 움직임”은 신호가 아니라 **적용 구간이 잘못**된 경우가 많다.

**(b) 위험/부작용**
- 기회 상실(강세장 초입에서 필터가 늦게 들어오면 수익 상한 감소).
- 과도한 필터는 overfit 위험(파라미터 늘리면 즉시 과최적화).

**(c) 최소 실험 2~3개(=단일 패치 내 임계치 스윕)**
- (E4-1) **변동성 레짐**: SPY 20D realized vol 상위 30% 구간에서 리스크 0.5배 vs 0배(노트레이드) 비교.
- (E4-2) **섹터 상대강도 레짐**: (QQQ/SPY, XLV/SPY) 60D 모멘텀 음수면 해당 섹터 종목 익스포저 0으로 컷 vs 전체 스케일다운.
- (E4-3) **레짐 유지기간(히스테리시스)**: 레짐 전환 시 최소 5영업일 유지 vs 즉시 전환(턴오버/휩쏘 방지).

**(d) PASS 조건(게이트)**
- lockbox_mean이 **챔피언 대비 ≥ 95%** 유지하면서 worst_mdd가 **-0.5%p 이상 개선**이면 통과.
- turnover(또는 거래일 비중) 급감으로 “거의 거래 안 함”이 되면 실패(예: 거래일 비중 < 30%면 컷).

### 5) **노출/포지션 사이징/턴오버 제약(운영 리스크 포함) 재설계**
- [ ] 단일 종목 최대 비중, 섹터(Tech/Health) 최대 비중, 일별 회전율 상한을 하드 제약으로 넣어라.
- [ ] 변동성 타깃(예: 포트 10~12% ann vol)으로 스케일링해 레짐 변화에 대한 방어를 자동화하라.
- [ ] 운영 리스크(데이터 결측/급등락/거래정지 추정) 발생 시 **주문 생성 금지 게이트**를 넣어라.

**(a) 왜 필요한지**
- 8~14개 집중에서는 “한 번의 큰 손실”이 lockbox_min/worst_mdd를 지배한다.
- 비용/슬리피지 반영 후에는 사이징이 성과의 대부분을 좌우한다.

**(b) 위험/부작용**
- 수익 상한 제한(캡이 강하면 강세장에서 덜 번다).
- 제약이 많아지면 최적화가 제약을 “요령껏” 피해가며 과최적화될 수 있음.

**(c) 최소 실험 2~3개(=단일 패치 내 제약 강도 스윕)**
- (E5-1) **단일 종목 캡**: max 15% / 12% / 10% 비교.
- (E5-2) **턴오버 캡**: 일별 |Δw| 합 30% / 20% 캡 비교(초과 시 비례 축소).
- (E5-3) **Vol targeting**: 포트 realized vol 기준 스케일(ON/OFF) 비교.

**(d) PASS 조건(게이트)**
- worst_mdd가 **챔피언 대비 개선(덜 음수)**되면서 lockbox_min이 **유지 또는 개선**되면 통과.
- 비용 포함 기준에서 net 성과가 개선되거나, net이 2% 이내 감소하더라도 MDD가 유의미하게 개선되면 통과(운영 목적).

## 48시간 자동 루프용 “실행 가능한 Patch/실험” 5개로 고정 (정의→게이트→기대관측치)

1) **E1: Leakage/시간정렬 강제 패치**
- 정의: feature/label/order 생성 시점 규칙 강제 + shift/가격소스 일관성 옵션 스윕(E1-1~1-3)
- 게이트: 미래참조 0건 + lockbox_mean(챔피언 대비) ≥ 85%
- 기대 관측치: (정상이면) tuning 성과 하락, lockbox 갭 축소, fold별 분산 감소

2) **E2: 비용/슬리피지 모델 내장 패치**
- 정의: 비용 3단 + 슬리피지 함수 2종 + 리밸런스 빈도 3단(단일 실험 번들)
- 게이트: 비용 포함 챔피언 대비 개선(또는 MDD 개선형 대체 게이트)
- 기대 관측치: 고턴오버 후보들의 성능이 급락(정상), 저턴오버/레짐형이 상대적으로 부상

3) **E3: 서바이버십/코액션/결측 처리 락다운 패치**
- 정의: delist-aware, no-ffill, adj 일관성 강제 스위치
- 게이트: 미래 티커 참조 0건 + 결측거래 0건
- 기대 관측치: 특정 기간 성과의 “튀는 구간”이 사라지고 fold 안정성 증가

4) **E4: ETF 관측지표 기반 레짐 필터 패치**
- 정의: QQQ/XLV/SPY로 변동성/상대강도 레짐 정의, 노트레이드 또는 리스크 스케일
- 게이트: lockbox_mean ≥ 95% & worst_mdd ≥ (챔피언 worst_mdd + 0.5%p)
- 기대 관측치: 하락장/고변동 구간 손실 압축, 거래일 비중이 과도하게 줄지 않아야 함

5) **E5: 사이징/턴오버/운영 게이트 패치**
- 정의: 종목캡/턴오버캡/볼타깃 번들 적용
- 게이트: 비용 포함 기준에서 net 성과 유지 + worst_mdd 개선
- 기대 관측치: 꼬리손실 감소, lockbox_min 개선 또는 안정화

## 성능이 “안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐)

아래 순서대로 “관측지표”를 찍어서 어디서 죽는지 분해하라(질문 없이 바로 로그/리포트로 뽑는 방식).

### A) Trigger(신호 발생) 문제
- [ ] **신호 발생 빈도**(days with signal, avg #positions)를 fold별로 출력하라.
- [ ] **신호의 방향성(hit rate, avg next-day return conditioned on signal)**을 레이블 구간별로 출력하라.
- 트리거 문제 징후: 신호가 너무 드물거나, 분포가 레짐에 따라 0으로 수렴.

### B) Apply(필터/제약 적용)에서 죽는 문제
- [ ] “원 신호” 대비 **필터 통과율**, **거래 생성율**, **주문 취소율**을 분해해 로그로 남겨라.
- [ ] 레짐/결측/운영 게이트로 인해 **항상 스케일다운/노트레이드**가 되는지 확인하라.
- 적용 문제 징후: 신호는 좋은데 실제 포지션이 거의 안 잡힘(거래일 비중 급락).

### C) Exposure(노출/사이징) 문제
- [ ] 종목별 평균 비중/최대 비중, 섹터별 순노출, 베타(SPY), 팩터 노출(모멘텀/밸류 등) proxy를 출력하라.
- [ ] 손실이 난 기간에 **단일 종목 쏠림**이 있었는지 확인하라.
- 노출 문제 징후: 평균 성과는 비슷한데 worst_mdd/lockbox_min만 계속 나쁨(꼬리 위험).

### D) Cost(비용)에서 상쇄되는 문제
- [ ] gross vs net 성과를 분리하고, **비용이 수익의 몇 %를 먹는지**, **turnover와의 상관**을 찍어라.
- 비용 문제 징후: gross는 개선되는데 net이 정체(또는 후보간 차이가 비용에서 소멸).

### E) Regime(구간 의존) 문제
- [ ] SPY 변동성 상/하, QQQ/SPY 모멘텀 +/-, XLV/SPY 모멘텀 +/-로 **조건부 성과 테이블**을 만들라.
- [ ] “잘 되는 구간”과 “죽는 구간”이 명확하면, 전략 자체가 아니라 **적용 레짐**이 문제다.
- 레짐 문제 징후: 전체 평균은 정체인데 특정 레짐에서만 일관되게 플러스/마이너스.

## 바로 실행 순서(24~48h)
- [ ] **1순위로 E1→E2→E3를 먼저** 돌려 “데이터/평가 신뢰성”을 고정하라(여기서 흔들리면 전략 논의 중단).
- [ ] 그 다음 **E4→E5**로 방어력(MDD/lockbox_min) 개선 실험을 붙여라.
- [ ] 모든 실험은 **비용 포함 챔피언 기준 상대평가**로만 select-best 하라(비용 미반영 결과는 참고값으로 격하).

(현재 제공된 autopilot 커맨드는 유지하되, 위 5개 패치를 실험 레지스트리에 “번들 실험”으로 등록해 48시간 루프에서 자동 반복되게 만드는 쪽이 맞다.)
