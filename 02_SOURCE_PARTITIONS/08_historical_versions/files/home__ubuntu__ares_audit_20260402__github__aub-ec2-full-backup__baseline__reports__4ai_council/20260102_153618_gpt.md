## TOP5 우선순위(24~48h) — “명령형 체크리스트” (미국주식, Tech+Healthcare 8~14종목, ETF는 관측지표만)

### 1) **리밸런스/로그 파이프라인 복구(운영 리스크 1순위)**
- **(a) 왜 필요한지**
  - `aub_rebalance_pinpoint`가 **CSV/JSONL 로드 실패**(경로 `--base-log`/JSON 포맷 깨짐)로 원인 추적 불가.
  - `worst_mdd: None`은 **리스크 메트릭 산출 누락/파이프라인 단절** 가능성이 커서 “성능이 안 움직이는 것처럼 보이는” 착시를 유발.
- **(b) 위험/부작용**
  - 로그 스키마 변경 시 과거 아티팩트 재현성 깨짐(버전 태깅 필요).
  - 핫픽스가 실험 비교의 기준을 흔들 수 있음(“동일 run 재실행” 게이트 필요).
- **(c) 최소 실험 2~3개 (공유 실험 사용: E1, E4)**
  - **E1**(아래 정의)로 로그 스키마/경로 고정 후 **동일 Champion 재실행** → OOS/턴오버/거래내역이 동일하게 재현되는지 확인
  - **E1**로 `rebalance.csv` 또는 `rebalance.jsonl`을 **단일 표준 포맷**으로 저장 후 `pinpoint` 재가동
  - **E4**에서 포지션 제약(8~14) 적용 시 리밸런스 로그가 정상적으로 종목/비중을 기록하는지 확인
- **(d) PASS 조건**
  - `aub_rebalance_pinpoint`가 **에러 없이 리포트 생성**
  - `worst_mdd`가 **숫자로 산출**(None 금지)
  - 동일 입력/seed에서 **Champion 성능 재현 오차 허용범위 내(예: OOS mean ±1~2%)**

---

### 2) **누수(leakage)·서바이버십·가용시점(as-of) 강제(리서치 리스크 1순위)**
- **(a) 왜 필요한지**
  - Tech/Healthcare는 이벤트·실적·가이던스 민감도가 커서 **발표/정정/지연 반영**에 따른 누수 가능성이 높음.
  - “OOS가 안 움직임”은 종종 **데이터가 이미 미래를 알고 있는 상태**에서만 성능이 나오고, 수정하면 급락하면서 드러남.
- **(b) 위험/부작용**
  - 성능이 단기적으로 하락할 수 있음(정상적인 정화).
  - 데이터 레이크/피처 생성 비용 증가(캐시/증분 필요).
- **(c) 최소 실험 2~3개 (공유 실험 사용: E2, E5)**
  - **E2**: 모든 피처에 **as-of timestamp + availability lag(예: T+1, T+2)** 강제하고 OOS 비교
  - **E2**: **생존편향 방지 유니버스 스냅샷**(리밸런스 시점 기준 상장/거래가능 종목만) 적용
  - **E5**: 레짐 게이트를 넣되, 게이트 입력(ETF/지수)은 “관측”만 사용하고 **개별 종목 신호는 동일**하게 둔 채 누수 여부(성능 민감도) 확인
- **(d) PASS 조건**
  - Lag(T+1~T+2) 적용 시 **OOS mean이 급붕괴하지 않음**(예: -20% 이내)
  - 유니버스 스냅샷 적용 시 **거래 불가능 종목/미상장 종목 0건**
  - 실험 간 성능 차이가 “비정상적 급등락”이 아니라 **합리적 범위 내**

### 3) **비용/슬리피지/유동성(ADV) 미반영 제거(실거래 리스크 1순위)**
- **(a) 왜 필요한지**
  - 현재 OOS 수치가 의미 있어도, **거래비용/슬리피지**가 빠지면 8~14 집중 포트에서 턴오버가 성능을 잠식.
  - Tech/Healthcare는 뉴스 갭·프리/애프터 영향으로 **체결 단가 괴리**가 커질 수 있음.
- **(b) 위험/부작용**
  - 비용모델이 과보수면 트레이드가 줄어 성능 둔화.
  - ADV 기반 임팩트는 파라미터 튜닝이 과최적화 포인트가 될 수 있음(스윕으로만 판단).
- **(c) 최소 실험 2~3개 (공유 실험 사용: E3, E4)**
  - **E3**: 비용모델(스프레드+슬리피지+임팩트)을 넣고 **0.5x/1.0x/2.0x 민감도 스윕**
  - **E3**: ADV 대비 주문비율 상한(예: 일 거래대금의 x%) 걸고 체결가능성 체크
  - **E4**: 포지션 수(8~14) 고정 + 최대비중 제한 시 **턴오버/비용이 떨어지는지** 확인
- **(d) PASS 조건**
  - 비용 2.0x에서도 **OOS mean이 0 이하로 붕괴하지 않음**
  - 연간/월간 턴오버가 **상한 내**(프로젝트 기준치로 게이트)
  - 상위 비용 구간에서도 **OOS min/테일이 악화되지 않음**(극단 구간 제거)

---

### 4) **포지션/노출 제약(8~14, 집중/섹터/단일종목 상한) + 리스크 메트릭 정상화**
- **(a) 왜 필요한지**
  - 현재 노출이 `0.47~0.84`로 보이는데, 제약이 느슨하면 **특정 종목/날짜에 과집중** → 테일리스크.
  - `worst_mdd: None`은 제약/메트릭 산출이 엮여 있을 가능성(포지션 이벤트 로그와 함께 점검).
- **(b) 위험/부작용**
  - 제약이 강하면 알파가 희석.
  - 리밸런스 빈도/수수료 구조가 바뀌어 과거 비교가 어려워짐(동일 비용모델로만 비교).
- **(c) 최소 실험 2~3개 (공유 실험 사용: E4, E3)**
  - **E4**: **항상 8~14개** 유지(동률/결측 처리 규칙 포함), 단일종목 max weight(예: 12~15%)
  - **E4**: 섹터 캡(Tech/Healthcare 내 서브산업 과집중 방지) + 현금/노출 상한
  - **E3**: 위 제약이 비용/턴오버를 어떻게 바꾸는지 비용 포함으로 재평가
- **(d) PASS 조건**
  - 모든 리밸런스 시점에 보유 종목 수가 **8~14 범위 100% 준수**
  - 최대비중 위반 **0건**
  - tail(OOS min) 또는 MDD가 **개선 또는 동일**(악화 시 롤백)

---

### 5) **레짐(시장/섹터) 게이트로 “트리거→적용→노출” 분리(성능 정체 해소용)**
- **(a) 왜 필요한지**
  - “성능이 안 움직임”은 종종 **신호는 맞는데 적용 구간(레짐)이 틀려서 상쇄**되는 패턴.
  - ETF는 매매 제외지만 QQQ/XLV 같은 지표로 **리스크 온/오프 관측**은 가능.
- **(b) 위험/부작용**
  - 레짐 게이트가 과최적화되면 OOS에서 무력화(또는 지나친 필터링).
  - 게이트가 트레이드를 줄여 분산이 감소할 수 있음.
- **(c) 최소 실험 2~3개 (공유 실험 사용: E5, E4)**
  - **E5**: (관측지표) QQQ/XLV의 추세/변동성으로 **노출 스케일만 조절**(종목선정 로직은 고정)
  - **E5**: “게이트 ON/OFF”만 바꾸는 A/B로 성능 정체가 **트리거 문제인지/적용 문제인지** 분해
  - **E4**: 게이트 적용 시에도 8~14 유지(게이트는 현금비중/총노출로만 반영)
- **(d) PASS 조건**
  - OOS mean의 큰 상승이 아니라도 **OOS min 개선** 또는 변동성/드로우다운 감소
  - 게이트 ON/OFF 비교에서 **성과 차이가 일관되게** 나타남(폴드/기간별 방향성)

## 48시간 자동 루프용 “실행 가능한 Patch/실험” 5개 (E1~E5)
아래 5개만 돌리고, 위 TOP5는 이 5개를 **재사용**해서 충족시키도록 고정.

### **E1 — Rebalance 로그/아티팩트 표준화 패치**
1) **실험 정의**
   - 리밸런스 결과를 `rebalance.jsonl`(스키마 고정)로 강제 저장 + run_hash/lane_hash/seed/commit 포함
   - `--base-log` 인자에 실제 파일 경로만 허용(문자열 리터럴 차단), 로드 실패 시 즉시 fail-fast
2) **게이트**
   - pinpoint/diagnoser가 모두 리포트 생성, 파서 에러 0건
3) **기대 관측치**
   - “No rebalance data found” 제거
   - `worst_mdd` None 제거, 리밸런스별 종목/비중/거래량이 일관되게 보임

### **E2 — 누수/서바이버십 방지(as-of + lag) 강제 실험**
1) **실험 정의**
   - 피처 입력에 availability lag(T+1, T+2) 적용한 두 변형을 동일 파이프라인으로 OOS 비교
   - 유니버스는 리밸런스 시점 “존재/거래가능” 스냅샷으로 고정
2) **게이트**
   - lag 적용 시에도 백테스트가 정상 완료(결측/종목매핑 오류 0)
3) **기대 관측치**
   - 성능이 하락하더라도 **급붕괴가 아니면 정상**, 급붕괴면 누수 의심을 확정할 근거 확보

### **E3 — 비용/슬리피지/임팩트(ADV) 포함 + 민감도 스윕**
1) **실험 정의**
   - 비용계수 0.5x/1.0x/2.0x 3단 스윕(같은 신호/같은 제약)
2) **게이트**
   - 2.0x에서도 전략이 “거래 과다”로 폭사하지 않음(턴오버 상한)
3) **기대 관측치**
   - 성능이 비용에 선형적으로 반응하면 정상, 특정 구간에서만 붕괴하면 **체결/유동성 병목** 신호

### **E4 — 포지션 제약(8~14) + 최대비중/섹터캡 적용**
1) **실험 정의**
   - 항상 8~14개 보유, 단일종목 max weight, 섹터/서브산업 캡, 총노출 상한
2) **게이트**
   - 제약 위반 0건(보유수/비중/노출), 리밸런스 로그에 제약 사유 기록
3) **기대 관측치**
   - OOS mean이 비슷해도 OOS min/MDD가 개선되면 “리스크 정렬” 성공

### **E5 — 레짐 관측(ETF 지표) 기반 노출 스케일 게이트**
1) **실험 정의**
   - QQQ/XLV/시장 변동성 관측치로 총노출만 0~1 스케일(종목선정 고정), ON/OFF A/B
2) **게이트**
   - 거래 종목(8~14) 유지, 게이트는 현금/총노출로만 반영
3) **기대 관측치**
   - OOS min 개선(테일 리스크 완화) 또는 변동성 감소가 보이면 “레짐 부조화” 가능성 상승

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **순서대로** 고정 점검(케이스 폭발 방지).

1) **트리거(신호 생성)가 실제로 변하고 있는가**
   - 리밸런스 시점별 상위 점수 종목이 바뀌는지(상관/유사도 추적)
   - 신호 분포(평균/분산/극값)가 최근 구간에서 납작해졌는지(스케일/정규화 버그)

2) **적용(필터/게이트/제약)이 신호를 죽이고 있는가**
   - 제약 때문에 “선정은 했는데 매수 불가”가 누적되는지(사유 로그 필요: 현금부족/캡/ADV/가격결측)
   - 게이트/필터 ON/OFF A/B에서 성능 차이가 0이면, 게이트가 무의미하거나 이미 항상 ON 상태

3) **노출(총익스포저/베타)이 원래 의도대로 움직이는가**
   - 현재 노출 min/max(0.47~0.84)가 레짐에 따라 변해야 하는데 고정이면, 스케일 로직 미작동 가능
   - 상위 1~2종목 기여도(수익 기여/리스크 기여)가 과도하면 “집중 리스크로 상쇄” 가능

4) **비용(거래비용/슬리피지)이 알파를 상쇄하고 있는가**
   - 턴오버 급증 구간과 성능 둔화 구간이 겹치는지
   - 비용 0x와 1x의 성능 차이가 비정상적으로 작으면(=비용이 사실상 미적용) 비용 파이프라인 버그 가능

5) **레짐(시장 상태) 미스매치로 알파가 상쇄되는가**
   - 레짐별(고변동/저변동, QQQ 추세↑/↓, XLV 상대강도↑/↓)로 성과를 분해해 “좋은 구간/나쁜 구간”을 분리
   - “좋은 구간에서만 작동”이면 E5처럼 노출 스케일로 먼저 안전하게 대응(종목선정 로직은 그대로 두고)

### 실행 순서(48h 내)
1) **E1 먼저 고정**(로그/메트릭/리밸런스 데이터 없으면 이후 실험은 전부 해석 불가)
2) **E2로 누수/서바이버십 리스크 제거**
3) **E3로 비용 현실화**
4) **E4로 8~14/집중/리스크 제약 고정**
5) **E5로 레짐 게이트 A/B로 성능 정체 원인 분해**

이 5개만 자동 루프에 올리면, “성능 정체”가 **(데이터 문제인지 / 비용 문제인지 / 제약-적용 문제인지 / 레짐 문제인지)** 48시간 안에 최소 1~2개 축으로 확실히 좁혀집니다.
