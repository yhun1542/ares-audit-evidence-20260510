## 다음 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — 명령형 체크리스트

### 1) **누수(lookahead)·서바이버십·데이터 정합성 게이트를 “실행 전 강제”로 승격**
**(a) 왜 필요한지**  
- 현재 champion/candidate 격차가 “평균 수익”보다 “MDD/최저 fold”에서 크게 갈리는 형태라, 미세한 누수/정렬 오류가 있으면 튜닝 평균만 과대평가되고 lockbox에서 둔화되는 전형 패턴이 나옴.  
- Tech/Healthcare 8~14 종목 집중은 작은 데이터 오류도 성능을 크게 왜곡함.

**(b) 위험/부작용**  
- 과거 성능(튜닝/폴드)이 단기적으로 하락할 수 있음(진짜 성능만 남음).  
- 데이터 로딩/전처리 시간이 증가.

**(c) 최소 실험 2~3개**  *(아래 실험들은 48시간 루프에서 자동 반복 가능하도록 “게이트” 포함)*  
- **실험 L1: “as-of(시점 고정)” 강제 + 피처/라벨 정렬 단위 테스트 삽입(패치)**  
  - (1) 실험 정의: 모든 피처를 `t` 시점 종가/공시 이후에만 사용하도록 as-of timestamp를 강제하고, `label(t+1..)`과의 정렬을 테스트로 고정(미래 인덱스 접근 시 실패).  
  - (2) 게이트: 테스트 실패 시 백테스트/튜닝 실행 자체를 중단(하드 fail).  
  - (3) 기대 관측치: tuning_mean 하락 가능, 대신 lockbox_mean 하락폭이 줄거나 lockbox_min 개선(“불량 알파 제거” 신호).
- **실험 L2: 서바이버십/코퍼레이트액션(분할·상장폐지) 처리 체크(패치)**  
  - (1) 실험 정의: (i) delist return 처리(가능하면 CRSP 스타일), (ii) split/dividend 조정 가격과 거래량 동기화, (iii) 유니버스 산출이 “당시점 존재 종목”만 포함하도록 점검.  
  - (2) 게이트: 임의 50일 샘플에서 `universe(t)`가 미래 상장 종목을 포함하면 fail.  
  - (3) 기대 관측치: worst_mdd가 완화되거나 fold 간 분산 감소.
- **실험 L3: 과최적화 탐지(“튜닝-락박스 괴리” 자동 리포트) 추가(패치)**  
  - (1) 실험 정의: 각 후보에 대해 `gap = tuning_mean - lockbox_mean`, `min_gap = tuning_min - lockbox_min`을 자동 기록/랭킹에 패널티 반영.  
  - (2) 게이트: gap이 임계치 초과면 자동 “reject(soft)”로 분류.  
  - (3) 기대 관측치: 선택되는 후보 수는 줄지만, lockbox에서 안정성 개선.

**(d) PASS 조건**  
- (필수) 누수/서바이버십 게이트 테스트 100% 통과.  
- (성과) `lockbox_min`이 현 champion(1.5367) 대비 **동일 이상**이거나, `worst_mdd`가 **-0.0704 → -0.060 이하로 개선**(둘 중 하나 충족).  
- (안정성) fold14_mdd 악화 폭이 -0.01 이내.

### 2) **비용(슬리피지·스프레드·수수료·리밸런싱) 미반영을 “현실 모델”로 상향**
**(a) 왜 필요한지**  
- 8~14종목 집중 + 잦은 회전은 비용에 매우 민감. 비용 모델이 약하면 tuning에서는 좋아 보이고 lockbox/실전에서 죽음.  
- Tech/Healthcare 대형주라도 이벤트/갭 구간에서 체결비용이 커짐.

**(b) 위험/부작용**  
- 단기적으로 평균 수익이 감소.  
- 지나치게 보수적인 비용이면 거래가 거의 멈춰 성능이 평평해질 수 있음(“미동 없음”의 한 원인).

**(c) 최소 실험 2~3개**  
- **실험 C1: 체결비용 모델 업그레이드(패치)**  
  - (1) 실험 정의: 고정 bps + (스프레드/유동성 프록시) 혼합. 예: `cost = max(fixed_bps, k * (dollar_volume^-0.5)) + half_spread_proxy`. (데이터 없으면 ATR/가격 기반 대체 프록시).  
  - (2) 게이트: 회전율(turnover)이 높을수록 net 성과가 단조 감소하는지 sanity 체크(상식 위배 시 fail).  
  - (3) 기대 관측치: gross는 하락하나 net의 worst_mdd/lockbox_min이 개선되면 “현실 적합” 신호.
- **실험 C2: “거래 임계값(no-trade band)” 도입(패치)**  
  - (1) 실험 정의: 목표 비중 변경이 `Δw < threshold`면 주문 생략(예: 1~2%p).  
  - (2) 게이트: 거래 횟수 N이 일정 수준 이하로 급감하면(예: -60% 이상) threshold 자동 축소.  
  - (3) 기대 관측치: turnover 감소, 비용 감소, lockbox_min 개선.
- **실험 C3: 리밸런싱 캘린더 고정(패치)**  
  - (1) 실험 정의: 일간 신호라도 거래는 주 2~3회(예: Tue/Thu)만 실행, 나머지는 홀드.  
  - (2) 게이트: 익스포저 추적오차(목표 vs 실제)가 임계 초과 시(예: L1 norm > X)만 예외적 리밸런스 허용.  
  - (3) 기대 관측치: MDD/변동성 완화, 성능이 “비용에 견딜 수 있는지” 드러남.

**(d) PASS 조건**  
- 비용 포함 net 기준으로 `lockbox_mean`이 현 champion(2.8855) 대비 **-10% 이내로 유지**하면서, `worst_mdd`가 **동일 또는 개선**.  
- turnover(연율/월율) 상한을 설정했다면 상한 준수(운영 리스크 게이트).

### 3) **운영 리스크 우선: 포지션 사이징·리스크 제한(단일종목/섹터/갭) 하드룰 추가**
**(a) 왜 필요한지**  
- 8~14종목은 단일 종목 갭/임상/규제(Healthcare) 이벤트에 취약.  
- MDD가 -7% 수준이면 “리스크 룰 추가로 더 줄일 여지”가 큼.

**(b) 위험/부작용**  
- 수익 상단(상승장)에서 알파가 일부 깎일 수 있음.  
- 룰이 과하면 “항상 비슷한 포트폴리오”로 수렴(미동 없음).

**(c) 최소 실험 2~3개**  
- **실험 R1: 단일종목 최대비중 + 변동성 타깃(패치)**  
  - (1) 실험 정의: `w_i <= 12~15%` 하드캡 + 최근 20~60일 변동성으로 포지션 스케일링(간단한 vol targeting).  
  - (2) 게이트: 캡 때문에 종목 수가 8 미만으로 떨어지면(현금 과다) 다음 종목으로 자동 확장.  
  - (3) 기대 관측치: worst_mdd 개선, lockbox_min 개선.
- **실험 R2: 이벤트/갭 리스크 완화 룰(패치)**  
  - (1) 실험 정의: (i) 전일 대비 갭이 큰 종목(예: |gap|>X%) 신규 진입 금지, (ii) 실적발표일(가능하면 캘린더) 주변 포지션 축소.  
  - (2) 게이트: 필터로 거래 기회가 과소(월 거래일의 <Y%)면 X를 완화.  
  - (3) 기대 관측치: tail loss 감소(최악 일간 손실, worst_mdd 개선).
- **실험 R3: 섹터(Tech/Healthcare) 내부 편중 제어(패치)**  
  - (1) 실험 정의: GICS/서브산업(가능한 범위) 기준으로 동일 서브섹터 최대 N종목 또는 비중 상한.  
  - (2) 게이트: 제약으로 기대수익이 급락하면(튜닝_mean 급락) 제약 강도를 자동 완화.  
  - (3) 기대 관측치: 특정 팩터/테마 쏠림 완화 → fold 분산 감소.

**(d) PASS 조건**  
- `worst_mdd` **-0.0704 대비 개선(예: -0.060 이하)** 또는 `lockbox_min` **+0.10 이상 개선** 중 하나.  
- 포트폴리오 제약 위반 0건(운영 게이트).

### 4) **ETF는 매매하지 말고 “레짐(위험온/오프) 관측지표”로만 사용해 노출 스위치 추가**
**(a) 왜 필요한지**  
- Tech/Healthcare는 레짐 민감(금리/리스크온)에 의해 알파가 “켜졌다 꺼졌다” 함.  
- ETF(예: QQQ/XLK/XLV/SPY/TLT/IEF/VIX proxy)를 **게이팅 신호**로만 쓰면 전략 복잡도 대비 효과가 큼.

**(b) 위험/부작용**  
- 레짐 필터가 늦으면 상승 구간을 놓칠 수 있음.  
- 과한 필터는 “항상 노출 낮음”으로 미동이 줄어듦.

**(c) 최소 실험 2~3개**  
- **실험 G1: 위험오프 게이트(패치)**  
  - (1) 실험 정의: 예) `SPY < MA200` 또는 `QQQ 상대강도 하락` 또는 `TLT 강세 + 주식 약세` 조건에서 목표 총노출을 30~60%로 축소(현금 보유).  
  - (2) 게이트: 게이트 발동일 비중이 과도(예: 전체 기간의 >70%)면 조건을 완화.  
  - (3) 기대 관측치: worst_mdd 하락, 특히 급락 구간 손실 완화.
- **실험 G2: 섹터 로테이션 힌트(Tech vs Health 상대강도)로 내부 비중만 재배분(패치)**  
  - (1) 실험 정의: XLK/XLV 상대강도가 상승이면 Tech 선택/비중 상향, 하락이면 Healthcare 쪽 상향(총 종목수 8~14 유지).  
  - (2) 게이트: 특정 섹터 쏠림이 상한 초과 시(예: 한 섹터 >75%) clamp.  
  - (3) 기대 관측치: 레짐별 성과 분산 감소, lockbox_mean 유지하며 min 개선.

**(d) PASS 조건**  
- 레짐 구간(하락장/변동성 확장)에서 `maxDD` 또는 `worst_mdd`가 유의미하게 개선.  
- 전체 lockbox_mean이 champion 대비 **-10% 이내**로 유지(“방어만 하고 수익 소멸” 방지).

### 5) **“성능이 안 움직임”을 막는 실험 설계/선발(Selection) 로직 개선: 탐색 폭은 좁게, 검증은 강하게**
**(a) 왜 필요한지**  
- 현재 candidate는 MDD는 개선했지만 평균이 크게 하락. 즉, 탐색이 “수익 vs 리스크”를 동시에 못 잡고 있음.  
- 자동 루프에서는 “안전한 개선(락박스/최저 fold)”을 우선하는 선발 규칙이 필요.

**(b) 위험/부작용**  
- 탐색이 지나치게 보수적으로 변해 새로운 알파를 놓칠 수 있음.  
- 리포팅 지표가 늘어 운영 복잡도 증가.

**(c) 최소 실험 2~3개**  
- **실험 S1: 멀티오브젝티브 선발(패치)**  
  - (1) 실험 정의: `score = lockbox_mean - α*|gap(tuning-lockbox)| - β*|worst_mdd| - γ*turnover` 같은 단일 점수로 선발(αβγ는 소수의 고정값만).  
  - (2) 게이트: 새로운 score 상위가 기존 champion 대비 lockbox_mean이 너무 낮으면 자동 보류.  
  - (3) 기대 관측치: “튜닝만 높은 후보”가 사라지고 lockbox 안정성이 올라감.
- **실험 S2: 워크포워드/최근구간 가중(패치)**  
  - (1) 실험 정의: lockbox를 최근 구간 가중(예: 최근 2~3년 가중)한 보조 점수 추가.  
  - (2) 게이트: 최근 가중으로만 최적화되어 전체 성과가 무너지면(전기간 lockbox_min 급락) fail.  
  - (3) 기대 관측치: 최신 레짐 적응성 향상(운영 적합).

**(d) PASS 조건**  
- 자동 선발 결과가 “튜닝 고점 후보”가 아니라 “락박스 안정 후보”로 바뀌는지 확인:  
  - `gap(tuning-lockbox)` 평균/상위값 감소  
  - 동시에 lockbox_min 유지 또는 개선

## 48시간 자동 루프용 “실행 가능한 Patch/실험(3~5개)만” 최종 묶음
아래 5개만 실제 브랜치/플래그로 만들어 루프에 태우고, 위 TOP5 항목들은 이 5개 안에서 커버하도록 고정.

1. **PATCH-L (LeakageGatePack)**: as-of 강제 + 정렬 유닛테스트 + 서바이버십 체크  
2. **PATCH-C (CostModelPack)**: 비용모델 업그레이드 + no-trade band + 리밸런스 캘린더  
3. **PATCH-R (RiskPack)**: 단일종목 캡 + vol targeting + 갭/이벤트 필터(가능한 범위)  
4. **PATCH-G (RegimeGatePack)**: SPY/QQQ/XLK/XLV/TLT 관측 기반 총노출 게이트 + Tech/Health 내부 재배분  
5. **PATCH-S (SelectionPack)**: 선발 점수에 gap/mdd/turnover 패널티 + 최근가중 보조점수

각 패치는 “ON/OFF 플래그 1개 + 내부 파라미터 1~2개”로만 운용해 케이스 폭발을 방지.

## 성능이 안 움직일 때(plateau) 원인 분해 아이디어 — 트리거/적용/노출/비용/레짐 순서로 고정 점검
아래는 **질문 없이 바로 실행**하는 진단 체크리스트.

### A) Trigger(신호 발생) 문제
- **신호 발생 빈도/엔트로피 기록**: 일별로 선택 스코어 상위 종목이 얼마나 바뀌는지(Top-K turnover) 로그.  
- **상관/중복 점검**: 선택된 8~14 종목의 팩터/수익률 상관이 너무 높으면(테마 1개) 실질 베팅이 1개뿐.

### B) Apply(적용/체결) 문제
- **주문이 실제로 나갔는지**: no-trade band, 캡, 레짐 게이트가 동시에 발동되어 “항상 홀드”가 되는지 플래그별 발동률을 집계.  
- **리밸런스 캘린더로 인한 지연 손실**: 신호 변경일과 실제 거래일 간 지연 PnL(슬리피지 포함) 분해.

### C) Exposure(노출) 문제
- **총노출/순노출/섹터노출 시계열**을 저장하고, 성과가 나는 구간에 노출이 실제로 올라갔는지 확인.  
- **단일종목 기여도 분해**: PnL 기여 상위 1~2개가 대부분이면, 나머지는 노이즈 → 캡/대체 규칙 필요.

### D) Cost(비용) 문제
- **Gross vs Net PnL 분해**: 비용이 알파를 전부 먹는지(특히 회전 급증 구간) 확인.  
- **체결비용 민감도 스윕(작게)**: fixed_bps만 2~3단계로 바꿔 net이 얼마나 출렁이는지(전략이 비용-취약인지 즉시 판별).

### E) Regime(레짐) 문제
- **레짐별 성과 테이블**:  
  - SPY 추세(>MA200 / <MA200), 금리 프록시(TLT 추세), 변동성 프록시(고/저)로 4~6개 버킷만 나눠 bucket 성과를 기록.  
- **레짐 불일치**: champion이 특정 레짐에서만 먹히면, “게이트로 피할지 / 그 레짐에 맞는 노출로 바꿀지” 둘 중 하나로 고정.

이 분해 로그는 다음 자동 루프에서 **“왜 후보가 안 좋아졌는지”를 숫자로 설명**해 주므로, 무작정 파라미터를 더 돌리는 과최적화를 막는 효과가 큼.
