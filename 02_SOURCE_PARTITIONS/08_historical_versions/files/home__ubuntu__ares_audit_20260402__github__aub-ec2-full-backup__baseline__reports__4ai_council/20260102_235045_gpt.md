아래는 **향후 24~48시간**에 “성능 정체(=No-Delta)”를 먼저 깨기 위해, **누수/과최적화/서바이버십/비용 미반영/운영 리스크**를 우선으로 잡는 **TOP5 우선순위**와, 각 항목별 **(a) 필요 이유 (b) 위험/부작용 (c) 최소 실험(공유 5개 실험 세트에서 2~3개만 참조) (d) PASS 조건**입니다.  
또한 48시간 자동 루프에서 바로 돌릴 수 있도록 각 실험은 **(1) 실험 정의 (2) 게이트 (3) 기대 관측치**로 고정했습니다.

## 0) 즉시 관찰된 “레드 플래그”(ONE TRUTH 기반)

- `worst_mdd: None` → 리포팅/집계가 누락되어 **리스크 개선이 성능에 반영되는지 검증 불가**(운영 리스크).
- `rebalance` 로그 로딩 실패 → **거래/리밸런스/비용 모델 검증이 막힌 상태**(비용 미반영 + 운영 리스크).

# TOP5 우선순위

## 1) (운영/코드) 리밸런스·비용·MDD “관측 가능성” 복구가 최우선
### (a) 왜 필요한지
- 지금은 `rebalance.csv/jsonl`이 깨져 있어 **회전율/체결/슬리피지/비용이 실제로 어떻게 적용되는지**가 보이지 않음.
- `worst_mdd: None`이면 **리스크 악화/개선이 성능에 미치는 영향**을 루프에서 자동 게이트로 못 씀 → 실험이 전부 “감”으로 바뀜.

### (b) 위험/부작용
- 로깅/지표 추가로 **실험 속도 저하**(I/O 증가) 가능.
- 지표 정의 변경으로 과거 결과와 **비교 불연속** 발생 가능(버전 태깅 필요).

### (c) 최소 실험(아래 “공유 실험 5개”에서 선택)
- **E1(무결성/누수 감사)**: 리밸런스 이벤트와 포지션 변화가 시간적으로 정합한지 체크
- **E2(비용/슬리피지 모델 도입)**: 비용이 성능을 어떻게 깎는지 관측 가능화
- **E4(노출/제약 + 8~14 종목 강제)**: 포지션 개수/노출이 로그로 남는지 확인

### (d) PASS 조건
- 모든 백테스트 run에서 자동 산출:
  - `rebalance_events`(날짜/종목/수량/가격/비용) 로그 생성
  - `turnover`, `gross/net exposure`, `worst_mdd`가 **None 없이** 기록
  - 비용 적용 전/후 PnL이 분리 기록되고, 비용이 0이 아닌 값으로 안정적으로 반영

---

## 2) (전략 신뢰성) **누수/시간정렬/타겟 생성** “즉시 봉쇄”
### (a) 왜 필요한지
- degenerate folds는 흔히
  - 라벨이 미래를 봄(look-ahead),
  - feature가 리밸런스 이후 가격을 참조,
  - `asof join` 오류,
  - 결측을 미래값으로 채움
  같은 **구조적 누수**에서 터짐.
- 누수는 OOS 평균을 “좋게” 만들 수도 있지만, “No-Delta” 상황에서는 **개선 실험이 전부 무의미**해지는 가장 큰 원인.

### (b) 위험/부작용
- 누수 제거 후 단기적으로 성능 급락 가능(진짜 실력만 남음).
- 피처 수가 줄거나 지연되어 신호가 약해질 수 있음.

### (c) 최소 실험
- **E1(무결성/누수 감사)**  ← 핵심
- **E3(스플릿/폴드 복구: purged/embargo CV)**  ← degenerate fold 직접 타격
- **E2(비용 모델)**: 누수 제거 후에도 “거래 가능한 성능”인지 동시 확인

### (d) PASS 조건
- 누수 감사지표:
  - feature timestamp ≤ decision timestamp(리밸런스 컷오프) 위반이 0
  - 라벨 구간과 피처 구간이 **purge/embargo**로 겹치지 않음
- degenerate folds가 0으로 수렴(또는 허용치 이하) + OOS 분산이 정상화(폴드별 표준편차 과도 폭발 제거)

---

## 3) (과최적화 방지) 폴드 퇴행/불안정성 제거: “Purged Walk-Forward + 최소 표본 게이트”
### (a) 왜 필요한지
- 현재 `degenerate_folds`는 “모델이 좋아서”가 아니라 **검증체계가 깨져서** 생겼을 가능성이 큼.
- 이 상태에서 하이퍼파라미터/신호 실험은 과최적화만 가속.

### (b) 위험/부작용
- purge/embargo 적용 시 학습 데이터가 줄어 **성능 하락** 가능.
- 과거 결과와 직접 비교가 어려움(하지만 신뢰성은 증가).

### (c) 최소 실험
- **E3(폴드/스플릿 패치)**  ← 핵심
- **E1(누수 감사)**: fold가 정상화되었는지 동시 검증
- **E4(노출/종목수 제약)**: 폴드별 포트폴리오 붕괴(종목수 1~2개로 쏠림)를 방지

### (d) PASS 조건
- 폴드별:
  - 샘플 수/거래 횟수/리밸런스 횟수가 최소치 이상(예: fold당 rebalance ≥ N)
  - fold별 OOS가 “전부 0 근처”로 붕괴하거나 “한 폴드만 폭발”하는 현상 감소
- 자동 루프에서 “degenerate fold 발생 시 run 즉시 폐기” 게이트가 동작

---

## 4) (전략/리스크) 8~14 종목(Tech+Healthcare) 강제 + 노출/회전율 상한으로 “거래 가능성” 확보
### (a) 왜 필요한지
- 요구사항: **미국주식 only**, **Tech+Healthcare 중심**, **8~14 종목**, **ETF 매매 제외**.
- 지금 `exposure_max ~0.84`, `exposure_min 0` → 리스크가 “현금 대기 ↔ 높은 노출”로 출렁일 수 있음.  
  No-Delta에서는 작은 규칙 변경이 성능이 아니라 “운”을 만들기 쉬움.
- 종목 수/섹터 제약이 없으면 결과가 특정 빅테크 1~2개에 “서바이버십/편향”으로 고정될 위험.

### (b) 위험/부작용
- 강제 분산으로 신호가 희석되어 단기 Sharpe 하락 가능.
- 거래 횟수가 늘어 비용 부담 증가(그래서 E2와 세트로 봐야 함).

### (c) 최소 실험
- **E4(포트폴리오 제약/포지션 사이징 패치)**  ← 핵심
- **E2(비용 모델)**: 제약으로 증가한 매매가 성능을 갉아먹는지 확인
- **E5(레짐 필터/헤지 스위치)**: 위험 구간에서 노출만 줄이는 방식이 유효한지

### (d) PASS 조건
- 모든 리밸런스 시점에:
  - 보유 종목 수가 8~14를 만족(미달/초과 0회)
  - Tech+Healthcare 비중(예: 합산 ≥ X%) 준수(룰 기반)
  - turnover 상한(예: 일/주 리밸런스당 최대 %) 위반 시 신호를 “스킵/완만화”하여 비용 폭발 방지
- net performance가 비용 포함 기준으로 유지(최소 기준: 비용 적용 후 OOS_mean이 비용 적용 전 대비 급붕괴하지 않음)

---

## 5) (레짐/헤지) ETF는 “관측지표”로만: 위험 레짐에서 노출 스케일링/헤지 비율 고정 실험
### (a) 왜 필요한지
- ETF는 거래하지 않되, **레짐 관측(QQQ/XLV/SMH, VIX 대용 지표 등)**으로 “언제 위험을 줄일지”만 결정하면, 전략의 베타 노출이 안정화됨.
- No-Delta 상태에서 신호 자체를 더 복잡하게 하기보다, **적용(노출)** 계층에서 성능을 움직이는 게 비용 대비 효율적.

### (b) 위험/부작용
- 레짐 필터가 과하게 작동하면 기회 손실(상승장에서 덜 탐).
- 레짐 지표가 가격 기반이면 지연(늦게 줄이고 늦게 늘림).

### (c) 최소 실험
- **E5(레짐 기반 노출 스케일링)**  ← 핵심
- **E2(비용 모델)**: 스위칭이 잦아져 비용이 증가하는지 확인
- **E3(폴드 패치)**: 레짐 효과가 폴드마다 일관적인지(과최적화 징후) 검증

### (d) PASS 조건
- 레짐 On/Off에 따른:
  - 최대낙폭(worst_mdd) 유의미 개선(예: 상대 기준 X% 이상 감소)
  - 비용 포함 OOS_mean이 유지되거나 소폭 개선
  - 레짐 전환 횟수 과다 시 자동 게이트로 비활성(운영 안정성)

# 48시간 자동 루프용 “공유 실험 5개”(3~5개 제한 준수)
아래 5개만 생성/실행하고, TOP5 우선순위는 이 5개를 조합해 검증한다(케이스 폭발 방지).

---

## E1) Data/Label 무결성 + 누수 감사 패치
1) **실험 정의(패치)**
- 모든 feature/label/price/decision timestamp를 **단일 “as-of 컷오프”**로 정렬
- 결측 처리 시 미래 참조 금지(Forward fill 금지/제한, 또는 “마지막 관측치 ≤ 컷오프”만 허용)
- 리밸런스 시점에 사용된 피처 스냅샷을 로그로 남김(해시/샘플링)

2) **게이트**
- `leakage_violations == 0`
- “피처 생성 시각 > 의사결정 시각” 발생 시 run 폐기
- label horizon 구간이 학습 피처 구간과 겹치면 run 폐기

3) **기대 관측치**
- degenerate fold 감소
- OOS 변동성이 “정상 범위”로 복귀(너무 매끈하거나 폭발적이지 않음)

---

## E2) 거래비용/슬리피지/회전율 모델 최소 도입 (관측 + 적용)
1) **실험 정의**
- 종목별 고정 bps + 변동(ATR 또는 일평균 거래대금 기반) 슬리피지 모델
- 리밸런스 로그를 표준 포맷(jsonl)로 강제 출력
- 비용 “전/후” PnL 분리 기록

2) **게이트**
- 비용 적용 후에도 `oos_mean`이 허용 하한 이상(내부 기준)
- turnover가 상한 초과하면 신호를 스무딩/클리핑하고, 그 비율이 로그에 남아야 함

3) **기대 관측치**
- 과거에는 좋아 보이던 조합이 비용 포함에서 무너지는지 즉시 판별
- “No-Delta”가 사실은 비용 미반영 때문인지 분리 가능

---

## E3) Purged Walk-Forward CV + degenerate fold 방지(최소 표본/거래수 게이트)
1) **실험 정의**
- label horizon만큼 purge + embargo를 넣은 walk-forward split로 교체
- 폴드별 최소 거래수/리밸런스 수 미달 시 폴드 폐기(그리고 전체 run도 폐기)

2) **게이트**
- `degenerate_folds == []`
- fold별 리밸런스/거래 횟수 최소치 충족
- 폴드별 성능이 “단일 폴드 폭발” 패턴이면 경고/폐기(과최적화 신호)

3) **기대 관측치**
- 개선 실험이 “폴드 운빨”이 아니라 구조적 개선인지 보임

---

## E4) 포트폴리오 제약 레이어: 8~14 종목, Tech+Healthcare 중심, 노출/포지션 상한
1) **실험 정의**
- 유니버스: US 주식, 섹터(Tech/Healthcare) 우선. (ETF는 신호/지표만)
- 매 리밸런스 시 보유종목 8~14 강제(부족하면 상위 신호로 채움, 초과면 하위 제거)
- 포지션 상한(단일 종목 비중), net/gross exposure 상한 도입

2) **게이트**
- 8~14 위반 0회
- 섹터 비중 규칙 위반 0회
- 노출 상한 위반 시 자동 클리핑이 로그로 남음

3) **기대 관측치**
- 성능이 특정 1~2 종목/특정 기간에만 의존하는 현상 완화
- 실거래 가능한 형태로 수렴

---

## E5) 레짐 관측(ETF 지표) 기반 노출 스케일링(거래는 주식만)
1) **실험 정의**
- 관측 지표(예: QQQ, XLV, SMH, IWM 중 일부 + 금리/신용 대용 가능)를 사용해 Risk-On/Off 점수 생성
- Risk-Off에서 **주식 포지션 사이징만** 축소(또는 고정 헤지 비율 적용하되 헤지는 주식/현금으로만 처리; ETF 매매는 금지)
- 스위칭 빈도 제한(최소 유지기간/히스테리시스)

2) **게이트**
- worst_mdd 개선(최소 개선폭 기준)
- 스위칭 횟수 상한 준수
- 비용 포함 성능 유지

3) **기대 관측치**
- 레짐 나쁠 때 손실 줄고, 좋아질 때 다시 참여하는지(“노출 계층”의 개선 확인)

# 성능이 안 움직일 때(=No-Delta) 원인 분해 아이디어: 트리 형태의 자동 진단 루틴
아래를 **자동 리포트 섹션**으로 고정해서 매 run마다 원인 후보를 깎아나가라.

## A. Trigger(신호가 실제로 변하나?)
- **신호 분포 드리프트**: 예측값/스코어의 분산이 0에 수렴하는지(=신호 죽음)
- **상위 랭크 안정성**: 매 리밸런스마다 상위 14종목 교체율(너무 낮으면 신호 고착/너무 높으면 노이즈)
- **섹터 편향**: Tech/Healthcare 내부에서 특정 산업군만 반복되는지

## B. Apply(신호가 포지션으로 제대로 번역되나?)
- **제약에 의한 무력화**: 상한/하한/8~14 강제 때문에 실제 목표 포트가 매번 비슷해지는지
- **클리핑 빈도**: 노출 클리핑이 자주 발생하면 신호 개선이 성과로 연결 안 됨
- **리밸런스 실패**: 데이터 누락/가격 결측으로 주문이 스킵되는 비율

## C. Exposure(노출이 성능을 잠식하나?)
- **gross/net 노출의 시간적 패턴**: 노출이 0↔0.8로 출렁이면 레짐/비용에 취약
- **단일 종목 비중**: “8~14”를 지켜도 상위 1~2개에 과집중이면 사실상 단일 베팅

## D. Cost(비용이 알파를 상쇄하나?)
- **turnover vs net PnL 분해**: (총수익 - 비용)에서 비용 비중이 커지는 구간
- **슬리피지 민감도**: bps를 ±50%로 흔들어도 성능이 유지되는지(유지 안 되면 신호가 너무 얇음)
- **체결가 모델**: 종가 체결 가정이 과도하게 낙관적인지(가능하면 VWAP/다음날 시가 등 보수적 대체)

## E. Regime(레짐에 따라 이길 때/질 때가 분명한가?)
- 레짐 지표별 조건부 성능:
  - Risk-On 구간 성능, Risk-Off 구간 성능
  - 변동성 상/하위 구간 성능
- “개선 실험이 특정 레짐에서만 작동”하면, 그 레짐에서만 켜는 게이트가 맞음(전략 복잡화 금지)

# 실행 체크리스트(명령형, 24~48h)
1) **리밸런스 로그/비용/MDD 산출 파이프라인을 먼저 복구**하고, 모든 run에 강제 적용하라(E2 포함).
2) **E1 누수 감사**를 넣고, 위반 시 run을 즉시 폐기하도록 게이트를 걸어라.
3) **E3 purged walk-forward + degenerate fold 차단 게이트**로 검증 체계를 정상화하라.
4) **E4 포트폴리오 제약(8~14, Tech+Healthcare, 노출 상한)**을 “모델 바깥 레이어”로 고정하고, 신호 실험은 그 안에서만 하라.
5) **E5 레짐 기반 노출 스케일링**을 추가하되, 스위칭 빈도/비용 게이트를 함께 걸어 “리스크만 줄이고 복잡도는 늘리지” 마라.

이 5개가 돌아가면, “성능이 안 움직이는 이유”가 **(신호가 안 변함 / 변하지만 적용이 안 됨 / 비용이 먹음 / 레짐에서만 됨 / 검증이 깨짐)** 중 어디인지 48시간 루프에서 자동으로 갈라진다.
