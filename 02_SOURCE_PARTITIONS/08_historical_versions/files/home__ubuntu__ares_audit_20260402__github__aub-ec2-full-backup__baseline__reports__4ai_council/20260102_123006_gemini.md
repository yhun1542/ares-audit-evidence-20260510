### 2. 제안별 실행 계획 (Actionable Patch)

#### A. 거래 로그 정규화 및 무결성 확보
*   **(a) 필요성:** 현재 `rebalance_pinpoint` 도구가 실패하여, 챔피언 모델이 '왜' 매매했는지 사후 분석 불가.
*   **(b) 리스크:** 로깅 로직 수정 중 메인 트레이딩 루프의 I/O 병목 발생 가능성.
*   **(c) 실험 제안:**
    1.  `EXP_LOG_FIX_JSONL`: 모든 거래 로그를 `ndjson`(Newlines Delimited JSON)으로 통일하고 타임스탬프 키(Key) 표준화.
    2.  `EXP_LOG_PATH_ABS`: 상대 경로 대신 절대 경로(`/home/ubuntu/AUB/...`)를 config에 하드코딩하여 경로 에러 방지.
    3.  `EXP_DUMMY_WRITE`: 1 epoch 더미 런을 돌려 로그 파일 생성 및 `rebalance_pinpoint.py` 파싱 성공 여부 확인.
*   **(d) PASS 조건:** `rebalance_pinpoint.py` 실행 시 에러 코드 0 반환 및 파싱된 행(Row) 개수 > 0.

#### B. MDD 계산 로직 복구 (The "None" Bug)
*   **(a) 필요성:** MDD가 None인 전략은 서바이버십 편향이거나 데이터 누락 상태임. 리스크 평가 불가.
*   **(b) 리스크:** 실제 MDD가 매우 높게 나와 챔피언 모델이 즉시 폐기될 가능성(그러나 이는 필요한 조치임).
*   **(c) 실험 제안:**
    1.  `EXP_MDD_FORCE_CALC`: 성과 평가 모듈에서 `np.nan_to_num` 처리 및 초기 자산 대비 하락폭 계산식 재점검.
    2.  `EXP_STRESS_2022`: 2022년 하락장 구간만 별도 백테스트 수행하여 MDD가 음수(-)로 찍히는지 확인.
*   **(d) PASS 조건:** `worst_mdd` 값이 `None`이 아니며, `-0.01` 이하의 유효한 음수 값 출력.

#### C. Tech+Healthcare 유니버스 압축
*   **(a) 필요성:** 요구사항(Tech/Healthcare 8~14종목) 대비 현재 Universe가 모호함. 잡주 거래로 인한 우연한 수익 배제.
*   **(b) 리스크:** 분산 효과 감소로 인한 개별 종목 리스크 증가.
*   **(c) 실험 제안:**
    1.  `EXP_UNIV_SECTOR_STRICT`: GICS 섹터 코드로 Tech, Healthcare 외 전량 매수 금지(Allowlist 적용).
    2.  `EXP_UNIV_LIQ_TOP20`: 해당 섹터 내 거래대금 상위 20개 중 변동성 낮은 순 12개 선정 로직.
*   **(d) PASS 조건:** 포트폴리오 내 Tech+Health 비중 100% 유지, OOS Sharpe > 1.5 유지.

#### D. 비용 민감도 스트레스 테스트
*   **(a) 필요성:** 높은 OOS Mean(1.88~2.62)이 잦은 매매와 낮은 비용 가정 덕분인지 확인.
*   **(b) 리스크:** 수익률 급감으로 인한 모델 폐기.
*   **(c) 실험 제안:**
    1.  `EXP_COST_BPS_10`: 슬리피지+수수료 합산을 기존(예: 5bps)에서 10bps~15bps로 상향.
    2.  `EXP_TURNOVER_CAP`: 일일 회전율(Turnover) 10% 초과 시 페널티 부여.
*   **(d) PASS 조건:** 비용 2배 적용 시에도 OOS Mean > 1.2 방어.
