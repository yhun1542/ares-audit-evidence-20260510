## 1. 우선순위 TOP 5 Patch 제안

### P1. 시그널 노출률(Exposure) 점검 — "불 안 붙는 트리거"

**(a) 왜 필요한가**
- lockbox 동일 = 실제 포지션 변경이 거의 없었을 가능성
- MRD/ARS/FSA 모듈 추가해도 트리거 조건이 너무 tight하면 발동 0회

**(b) 위험/부작용**
- 노출 늘리면 false positive 증가 → 거래비용·whipsaw 폭증
- 과최적화 위험: "발동시키려고" 임계값 조정 시 tuning set 오버핏

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| E1.1 | `trigger_rate` 로깅 추가: 각 모듈별 일간 발동 횟수 기록 | N/A (관측 전용) | 모듈당 발동률 0.5%↑ 이상인지 확인 |
| E1.2 | MRD 임계값 −10% 완화 (`mrd_threshold *= 0.9`) | lockbox_mean ≥ 1.79, fold14_mdd ≥ −10.5% | 발동률 +20% 이상 |
| E1.3 | FSA lookback 20→15일 단축 | lockbox_mean ≥ 1.79 | 더 민첩한 반응, 거래횟수 +15% 내외 |

**(d) PASS 조건**
```
trigger_rate_delta ≥ +10% AND lockbox_mean ≥ 1.79 AND worst_mdd ≥ −12%
```

**(c) 최소 실험**

## 2. 성능 안 움직일 때 원인 분해 트리

```
성능 정체
├─ 1) 트리거 문제
│   ├─ 조건 너무 tight → 발동 0회
│   └─ 조건 너무 loose → 노이즈만 진입
│
├─ 2) 적용 문제
│   ├─ 시그널 → 포지션 변환 로직 버그
│   └─ 기존 로직과 충돌 (override 안 됨)
│
├─ 3) 노출 문제
│   ├─ 해당 레짐 구간이 테스트셋에 없음
│   └─ 포지션 크기 제한으로 임팩트 0
│
├─ 4) 비용 문제
│   ├─ 개선분 < 거래비용 → 넷 제로
│   └─ 슬리피지 과소 가정 → 환상적 개선
│
└─ 5) 레짐 미스매치
    ├─ 튜닝셋 = 상승장, 락박스 = 횡보/하락
    └─ 모듈이 특정 레짐에서만 작동
```
