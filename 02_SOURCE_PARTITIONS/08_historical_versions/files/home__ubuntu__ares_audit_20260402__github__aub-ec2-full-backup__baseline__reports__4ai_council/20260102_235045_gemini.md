[진단 요약]
현재 챔피언 모델은 **심각한 데이터/로직 결함** 상태입니다.
1. `degenerate_folds: [1, 2, 3, 8]` → 전체 기간의 40%에서 모델이 작동하지 않거나(거래 없음), 파산했거나, NaN을 반환 중입니다.
2. `worst_mdd: None` → MDD 계산 로직이 깨졌거나, 거래가 아예 없는 구간이 존재합니다.
3. `rebalance.csv` 로드 실패 → 거래 비용/슬리피지가 반영된 실제 PnL을 검증할 수 없습니다.

OOS Mean(3.32)은 생존한 일부 Fold의 과적합 결과일 가능성이 매우 높습니다. 따라서 '성능 향상'이 아니라 **'정상화(Normalization)'**가 최우선입니다.

### 1) 향후 24~48시간 우선순위 TOP 5

1.  **[FIX] Degenerate Folds 디버깅**: Fold 1, 2, 3, 8에서 거래가 0건인지, 데이터가 없는지, 로직이 터지는지 확인. (유니버스 생존 편향 의심)
2.  **[INFRA] 로깅 파이프라인 복구**: `rebalance.csv` 포맷 에러 수정. 거래 내역 없이는 백테스트 신뢰도 0.
3.  **[RISK] MDD 계산 로직 수정**: `None`이 뜨는 예외 상황(무거래, NaN) 처리.
4.  **[STRAT] 동적 유니버스 할당**: 고정된 8~14개 종목이 과거(Fold 1~3)에 존재하지 않았을 가능성 검증 및 수정.
5.  **[MECH] 최소 노출(Min Exposure) 강제 실험**: Exposure 0.0인 구간이 너무 길어 Degenerate로 분류되는지 확인.

### 2) 제안별 상세 실행 계획 (48시간 루프)

#### 실험 A: 유니버스 가용성 검증 (Universe Availability Check)
*   **(a) 필요성**: Tech/Healthcare 8~14개 종목이 Fold 1, 2, 3 기간(과거)에 상장되지 않았거나 데이터가 비어있어 'Degenerate' 발생 가능성 99%.
*   **(b) 위험**: 오래된 대형주(Legacy)만 남겨 최근 트렌드(AI/Bio)를 놓칠 위험.
*   **(c) 실행 실험**:
    1.  `EXP_UNIV_01`: 유니버스를 동적 풀(Dynamic Pool)로 변경. 매 리밸런싱 시점 기준 시총 상위 Tech/Health 20개 중 10개 선택.
    2.  `EXP_UNIV_02`: 고정 유니버스 사용 시, 데이터 시작일이 가장 늦은 종목의 상장일 이후로 백테스트 기간 단축 (Fold 제외).
    3.  `EXP_UNIV_03`: 결측치(NaN) 발생 시 0으로 채우지 말고, 해당 종목 제외하고 리밸런싱 로직 수정.
*   **(d) PASS 조건**:
    *   `degenerate_folds` 개수 0개.
    *   `worst_mdd`가 수치로 산출됨 (Not None).

#### 실험 B: 로깅 및 비용 강제 주입 (Force Cost Logging)
*   **(a) 필요성**: `rebalance.csv` 로드 에러는 현재 시스템이 비용(Cost)을 무시하고 있음을 시사. 실제 수익률은 훨씬 낮을 것.
*   **(b) 위험**: 로깅 오버헤드로 인한 속도 저하(미미함), 충격적인 성능 하락 확인.
*   **(c) 실행 실험**:
    1.  `EXP_LOG_01`: JSONL 대신 표준 CSV로 로깅 포맷 단순화 및 `flush()` 강제 호출.
    2.  `EXP_COST_01`: 매수/매도 시 10bps 슬리피지 + 고정 수수료 강제 적용 후 OOS 측정.
*   **(d) PASS 조건**:
    *   진단 스크립트(`aub_rebalance_pinpoint.py`)가 에러 없이 로그 파일을 파싱.
    *   Net Profit < Gross Profit 확인.

#### 실험 C: 최소 활동성 보장 (Active Exposure Floor)
*   **(a) 필요성**: `Exposure Min: 0.0`. 시장이 안 좋을 때 현금 100%는 좋지만, 신호가 너무 보수적이라 거래를 안 해서(Fold 8) Degenerate 되었을 수 있음.
*   **(b) 위험**: 하락장에서 억지 매수로 인한 MDD 증가.
*   **(c) 실행 실험**:
    1.  `EXP_ACT_01`: `min_exposure = 0.1` 설정 (최소 10%는 항상 시장 참여).
    2.  `EXP_ACT_02`: 변동성 타겟팅(Vol Targeting) 로직 도입. 변동성 낮을 때 레버리지 대신 노출도 증가.
*   **(d) PASS 조건**:
    *   OOS Min > -0.15 (MDD가 생기더라도 거래가 일어나는지 확인).
    *   Trade Count > 50 (전 기간).

2.  **게이트(Gate)**: `Worst MDD < -0.05` (MDD가 0이 아니어야 함), `Exposure Max > 0.5`
3.  **기대 관측치**: 정상적인 Drawdown 곡선과 우상향 Equity Curve의 상관관계 확인.

### 4) 성능 정체 원인 분해 아이디어

만약 위 조치 후에도 성능이 제자리라면 다음 트리를 점검:

*   **트리거(Trigger) 불량**:
    *   진입 시그널 임계값(Threshold)이 너무 높아 1년에 1번만 거래하는가? -> *Threshold 50% 낮춰서 실험.*
*   **노출(Exposure) 왜곡**:
    *   특정 종목(예: NVDA, LLY) 하나가 수익의 90%를 차지하는가? -> *종목당 Max Weight 20% 제한 걸고 재실행.*
*   **비용(Cost) 과소평가**:
    *   회전율(Turnover)이 너무 높아 비용이 알파를 다 까먹는가? -> *Turnover 기반 페널티 term 추가.*
*   **레짐(Regime) 불일치**:
    *   금리 인상기(2022년)에만 깨지는가? -> *TLT(채권 ETF)를 관측 지표(Feature)로 넣어 하락장 감지 로직 강화.*
