### 3. 성능 정체 시 원인 분해 아이디어 (Debugging Framework)

성능 지표(Sharpe/Return)가 개선되지 않을 경우, 다음 순서로 원인을 제거하십시오.

1.  **Trigger (진입 시그널) 문제인가?**
    *   *Check:* 거래 횟수(Number of Trades) 확인. 
    *   *Action:* 거래가 너무 적으면(연 10회 미만) 진입 장벽(Threshold)을 낮추고, 너무 많으면(연 200회 이상) 수수료가 알파를 잠식 중. RSL(상대강도) 기간값 변경(e.g., 20일 -> 60일).

2.  **Execution (실행/청산) 문제인가?**
    *   *Check:* 승률(Win Rate) vs 손익비(P/L Ratio).
    *   *Action:* 승률은 높은데 손익비가 낮다면 **"이익 실현이 너무 빠름"**. -> Trailing Stop 폭을 넓힘.
    *   *Action:* 승률이 낮은데 손익비도 낮다면 **"손절이 너무 늦음"**. -> Time-based Exit(n일 후 강제 청산) 도입.

3.  **Exposure (종목 선정군) 문제인가?**
    *   *Check:* 8~14개 종목의 구성 확인. 잡주(Small cap)나 유동성 부족 종목이 포함되는지.
    *   *Action:* Universe 필터 강화 (일평균 거래대금 $50M 이상만 허용). Tech/Bio 대장주 위주로 유니버스 압축.

4.  **Regime (시장 국면) 불일치인가?**
    *   *Check:* 특정 연도(e.g., 2022년)에만 MDD가 집중되는지.
    *   *Action:* 금리 상승기(2022)와 하락기(2020/2023)를 구분하는 거시 지표(TNX 등)를 Filter로 추가. (단, 과최적화 주의).
