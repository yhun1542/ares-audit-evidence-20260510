## 48시간 자동 루프용 “실행 가능한 실험/패치” 5개 (3~5개 제한 준수)

아래 E1~E5만 돌리면, 위 TOP5 전부를 커버하도록 설계(각 우선순위는 이 실험들을 “참조”하는 방식).

---

### E1) **지표/로그 스키마 통일 + rebalance 아티팩트 강제 생성**
1) **실험 정의**
- 백테스트 결과 아티팩트에 다음을 **항상** 포함시키는 패치:
  - `metrics.json`(oos_mean/oos_min/worst_mdd/exposure/turnover/gross/net)
  - `rebalance.jsonl`(각 리밸런스 시점의 target/current/filled/cost)
- `aub_rebalance_pinpoint.py`가 `rebalance.jsonl`만 읽도록 단일화(없으면 Hard fail)
- OOS 집계 함수를 단일 모듈로 고정(진단툴/메인파이프라인 동일 호출)

2) **게이트**
- pinpoint 리포트 생성 **성공**
- `worst_mdd != None`
- HANDOFF 출력 oos_mean과 diagnoser oos_mean의 상대오차 < 1% (또는 “비용 포함/제외” 메타데이터로 차이를 설명)

3) **기대 관측치**
- “성능이 안 움직임”의 상당 부분이 **측정/로그 누락**이었는지 즉시 판별 가능
- 이후 실험(E2~E5)에서 “변화가 어디서 생겼는지”가 자동으로 분해됨


---

### E2) **누수 센티널: 1D feature lag + Purged/Embargo CV 스위치**
1) **실험 정의**
- 모든 특징량/라벨 정렬에 대해 “최소 1영업일 lag” 강제 옵션 추가
- CV/워크포워드에서 purge+embargo(예: purge=5D, embargo=5D) 옵션 추가
- 동일 데이터로 (A)기존 (B)lag (C)purge+embargo 를 같은 러너로 비교

2) **게이트**
- (B)/(C)에서 OOS가 “붕괴”하면 실패로 간주(누수 의심):
  - 예: `oos_mean_lag < 0.7 * oos_mean_base` **이면 FAIL**
- degenerate fold 발생 시 FAIL

3) **기대 관측치**
- 누수가 있으면 lag/purge에서 성능이 급락
- 누수가 없으면 성능 하락은 제한적이며, 변동성만 증가하는 패턴이 일반적


---

### E3) **비용+턴오버 게이트: net-of-cost가 운영 가능 수준인지 확인**
1) **실험 정의**
- 보수적 하한 비용모델을 강제(예시):
  - 수수료/세금 제외 최소치로도 됨: `5 bps (slippage) + 1 bps (fees)` 등
  - 주당 고정비용을 쓰는 시스템이면 `$0.005/share` 같은 하한 추가
- 턴오버 패널티 또는 상한(예: 일간 turnover 0.25 캡 / 주간 1.0 캡) 옵션 추가

2) **게이트**
- `oos_mean_net >= 0.9 * oos_mean_gross` (비용에 다 삼켜지면 FAIL)
- `turnover_p95`가 상한 이내(예: 일간 0.25 또는 시스템 기준치)
- 비용 반영 후에도 worst_mdd가 계산/보고될 것(E1과 결합)

3) **기대 관측치**
- OOS 정체 원인이 “비용/회전”인지 즉시 분리
- 전략이 유지되면 리밸런싱이 줄면서 oos_min이 개선되는 경우가 흔함


---

### E4) **유니버스 고정(8~14, Tech+Healthcare only) + 비교 가능성 확보**
1) **실험 정의**
- 다음 12개 티커로 유니버스 고정(미국, Tech+Healthcare 중심, 8~14 준수):
  - Tech: AAPL, MSFT, NVDA, AMZN, GOOGL, META, AMD, AVGO
  - Healthcare: LLY, UNH, ABBV, ISRG
- 해당 유니버스 외 종목이 포트폴리오/피처 로딩 단계에서 들어오면 Hard fail

2) **게이트**
- 전 기간 동안 포트폴리오 보유 종목이 위 리스트를 벗어나면 FAIL
- 종목수 8~14 유지(결측으로 8 미만이면 FAIL)

3) **기대 관측치**
- 서바이버십/유니버스 드리프트 제거로 실험 변동성이 줄고,
- “전략 로직 자체 문제” vs “유니버스 문제”가 분리됨


---

### E5) **레짐 기반 노출 캡(ETF는 관측만): MDD 개선이 목표**
1) **실험 정의**
- 관측 ETF(매매 금지): QQQ, XLK, XLV, IBB
- 레짐 스코어 예시(단순/견고):
  - `risk_on = (QQQ 20D return > 0) AND (QQQ 20D vol < 60D vol)`
  - `sector_confirm = (XLK-XLV 20D 상대강도)`로 Tech 과열/약세 판단
- 노출 캡:
  - risk_on: gross exposure cap 0.8~0.9
  - risk_off: cap 0.3~0.5
- 기존 알파 스코어/랭킹은 유지하고 “스케일만” 바꿈

2) **게이트**
- `worst_mdd`가 기준 대비 **10% 이상 개선**
- `oos_mean` 하락은 **5% 이내**
- exposure_min/max가 캡 범위 안에 들어옴

3) **기대 관측치**
- 성능이 “안 움직이는” 구간에서 손익곡선의 바닥이 올라가고(oos_min 개선),
- 알파가 약한 레짐에서 비용/변동성 낭비가 줄어듦

## 성능이 안 움직일 때 “원인 분해 아이디어(트리거/적용/노출/비용/레짐)” — 질문 없이 바로 실행 체크리스트

### A) Trigger(신호 발생) 문제 분해
- [ ] 신호 분산(variance) 추적: 일별/주별 알파 스코어 분산이 0에 수렴하면 “신호가 죽음”
- [ ] 상위/하위 랭크 스프레드(Top-K vs Bottom-K 기대수익) 로그화
- [ ] 피처 결측/클리핑/정규화로 인한 상수화 여부 점검(특히 최근 구간)

### B) Apply(적용/리밸런싱) 문제 분해
- [ ] 리밸런싱 트리거 발생 횟수 vs 실제 포지션 변화 횟수 비교(“신호는 나왔는데 적용이 안 됨” 탐지)
- [ ] 최소 주문단위/포지션 라운딩으로 인해 미세신호가 전부 0 처리되는지 점검
- [ ] 쿨다운/임계값 때문에 포지션이 고착되는지(hold drift) 점검

### C) Exposure(노출) 문제 분해
- [ ] gross/net 노출 타임시리즈 + 캡 히트율(상한에 계속 붙어 있으면 베타 장사 가능성)
- [ ] 섹터 내 편향(Tech 과쏠림) vs Healthcare 헤지 역할 확인
- [ ] 단일 종목 기여도(특정 NVDA 같은 1종목이 PnL 대부분이면 정체가 “집중 리스크”일 수 있음)

### D) Cost(비용) 문제 분해
- [ ] gross PnL과 net PnL의 갭(비용)이 레짐별로 커지는지 확인
- [ ] turnover 상위 5% 구간에서 PnL이 음수로 바뀌는지(“거래할수록 손해”)
- [ ] 리밸런싱 크기 분포(작은 거래가 너무 많으면 스프레드에 먹힘)

### E) Regime(레짐) 문제 분해
- [ ] QQQ/XLK/XLV/IBB 상태별(상승/하락/고변동)로 성능을 조건부 집계
- [ ] “레짐 필터 ON/OFF”의 차이를 **노출만 바꿔** 비교(E5 방식)
- [ ] 레짐 전환 직후(1~2주) 성능이 급락하는 패턴이면 “지연 반응” 문제 → 노출 캡을 더 빠르게/보수적으로
