## 24~48시간 TOP5 우선순위(코드/아키텍처/전략) — **명령형 체크리스트**
(우선순위 기준: **누수/과최적화/서바이버십/비용 미반영/운영 리스크**)

---

# 1) **Lockbox 평가 무결성/누수 방지(가장 우선)**
### (a) 왜 필요한지
- **Champion과 Last PASS Candidate의 lockbox_mean/min, MDD가 “완전히 동일”**합니다. 이는 정상적인 후보 탐색에서 매우 드문 패턴이며, 아래 가능성을 최우선 의심해야 합니다.  
  - lockbox 재평가가 **캐시/스킵**됨  
  - 후보가 바뀌어도 **동일한 신호/포지션**이 재사용됨  
  - split/정렬/라벨 생성에서 **시간 누수(look-ahead)**가 잠복  
  - lockbox 구간이 실수로 **tuning과 겹치거나** 인덱싱이 고정됨

### (b) 위험/부작용
- 이 단계에서 잘못 고치면 “진짜 성능”이 급락(기존 성능이 누수였던 경우)할 수 있음
- 캐시 강제 무효화로 런타임/비용 증가

### (c) 최소 실험 2~3개 (48시간 자동 루프에 넣을 형태)
**실험 1 — Lockbox 강제 재계산/캐시 무효화**
- (1) 실험 정의: lockbox 산출 단계에 `no_cache=true` 또는 **입력/코드 해시 기반 캐시 키**를 강제. 결과 리포트에 `data_hash`, `feature_hash`, `pred_hash`, `position_hash`를 반드시 기록.
- (2) 게이트: 같은 후보를 2회 실행 시 **hash가 동일**하고, 다른 후보 실행 시 **pred/position hash가 달라야 함**
- (3) 기대 관측치: 후보가 바뀌면 lockbox 지표가 **미세하게라도 변동**해야 정상

**실험 2 — “의도적 신호 오염” 센티널 테스트**
- (1) 실험 정의: 예측값/시그널에 작은 랜덤 노이즈(또는 10% 확률로 sign flip)를 주입한 “센티널 후보”를 1개만 생성
- (2) 게이트: lockbox 성과가 **유의미하게 악화**(예: lockbox_mean -10%p 이상 또는 MDD 악화)해야 함  
- (3) 기대 관측치: 악화가 없다면 **평가 파이프라인/포지션 적용이 실제로 반영되지 않는 버그** 가능성 큼

**실험 3 — 시간 쉬프트 누수 탐지(anti-leakage)**
- (1) 실험 정의: feature를 `t+1`(미래)로 쉬프트한 “치팅 모델”과 `t-1`(지연) 모델을 각각 1개씩 생성
- (2) 게이트:  
  - 치팅 모델이 비정상적으로 좋아지면 → **누수 감지**  
  - 지연 모델이 과도하게 나빠지면 → 실제 운영 지연/체결 지연에 취약
- (3) 기대 관측치: 치팅은 좋아지더라도(정상), 그 정도가 **과도**하면 누수 강함. 지연은 **완만한 하락**이 정상

### (d) PASS 조건
- 후보 변경 시 lockbox 결과가 “항상 동일” 현상이 사라질 것
- 센티널(오염) 테스트에서 성과가 확실히 악화될 것
- 모든 리포트에 `hash 4종(data/feature/pred/position)`이 남고, **재현성(동일 입력 동일 결과)** 보장

# 2) **비용/체결/슬리피지 미반영 패치(성과 정체의 흔한 원인)**
### (a) 왜 필요한지
- Tech/Healthcare 8~14종목은 유동성은 대체로 좋지만, **회전율이 높으면** “샤프 정체/실전 붕괴”로 직결됩니다.
- tuning 성과가 잘 나오는데 lockbox가 안 움직이면, 실제로는 **거래비용이 성과를 상쇄**하는 경우가 많습니다(특히 일간/고빈도 리밸런싱).

### (b) 위험/부작용
- 비용을 넣으면 성과가 하락(정상)
- 지나치게 보수적 비용 모델은 연구 속도를 늦춤

### (c) 최소 실험 2~3개
**실험 1 — 비용 스윕(단 3점)**
- (1) 실험 정의: `fee+slippage`를 (낮음/기준/높음) 3점만 고정 스윕
- (2) 게이트: 비용 증가에 따라 PnL이 **단조 감소**해야 정상(비단조면 비용 적용 버그 의심)
- (3) 기대 관측치: turnover 높은 전략은 비용 민감도가 크게 나타남

**실험 2 — 체결 1바 지연(운영 현실화)**
- (1) 실험 정의: 신호 생성 시점과 체결 시점을 1 bar(1일) 지연
- (2) 게이트: lockbox_mean 하락폭이 과도(예: -15%p 이상)면 “타이밍/체결 민감” 경고
- (3) 기대 관측치: 견고한 전략은 하락하더라도 **완만**

**실험 3 — Turnover cap / 리밸런싱 빈도 감소**
- (1) 실험 정의: (A) turnover 상한, 또는 (B) 주 1~2회 리밸런싱으로 제한
- (2) 게이트: 비용 포함 후 성과가 개선되거나 MDD가 개선되면 채택
- (3) 기대 관측치: lockbox에서 “샤프 정체”가 비용/회전율 문제였으면 개선 신호가 나옴

### (d) PASS 조건(Champion 대비)
- 비용 포함 기준으로  
  - `lockbox_mean >= 1.7927 * 1.01` (약 +1% 상대) **또는**  
  - `worst_mdd >= -0.1118`(덜 나빠짐) + `turnover` 유의미 감소  
- 비용 스윕에서 단조성 확인

# 3) **서바이버십/상장폐지/코퍼레이트 액션/유니버스 고정(US Tech+Healthcare 8~14)**
### (a) 왜 필요한지
- “현재 살아남은 종목”으로만 백테스트하면 **서바이버십 편향**이 즉시 성과를 과대평가합니다.
- 8~14개 집중 포트폴리오는 **단일 이벤트(인수/상폐/거래정지/스플릿)**가 성과를 좌우합니다.
- 유니버스가 시점별로 바뀌는 로직은 누수/과최적화의 온상입니다.

### (b) 위험/부작용
- 데이터 공급원의 delisting return/배당/분할 처리 품질에 따라 성과가 출렁일 수 있음
- 유니버스 고정 시 기회 감소

### (c) 최소 실험 2~3개
**실험 1 — 유니버스 “PIT 고정” vs “현재시점 고정” 비교**
- (1) 실험 정의: 동일 전략을 (A) point-in-time 가능 유니버스, (B) 현재 구성 고정 유니버스로 각각 1회씩만 실행
- (2) 게이트: (B)가 (A)보다 과도하게 좋으면 서바이버십/누수 의심
- (3) 기대 관측치: PIT 적용 시 성과는 보수적으로 내려가되, 형태는 유지

**실험 2 — 코퍼레이트 액션 무결성 체크(스플릿/배당/병합)**
- (1) 실험 정의: 조정주가/비조정주가 두 경로로 산출해 리턴 분포/극단값 비교
- (2) 게이트: 극단 갭(예: 단일일 ±50% 이상)이 빈번하면 액션 처리 오류 가능
- (3) 기대 관측치: 분포가 합리적으로 수렴

**실험 3 — 결측/거래정지 스트레스**
- (1) 실험 정의: 랜덤하게 일부 종목의 특정 구간 가격을 마스킹하고(또는 실제 결측 구간만) 포지션 로직이 안전하게 작동하는지 확인
- (2) 게이트: 포지션 NaN/무한대/레버리지 폭발이 0건이어야 함
- (3) 기대 관측치: 결측 시 현금/대체 규칙이 안정적으로 발동

### (d) PASS 조건
- PIT 유니버스에서도 lockbox 성능의 “형태”가 유지(샤프/드로우다운이 과도 붕괴하지 않음)
- 코퍼레이트 액션/결측에서 포지션 산출 안정성 100% 통과

# 4) **노출(베타/섹터/단일종목) 제어 + ETF는 “관측지표”로만 사용**
(매매는 US 개별주 8~14, Tech+Healthcare 유지. ETF는 **레짐/리스크 지표로만**)

### (a) 왜 필요한지
- 성능 정체는 종종 “시그널이 좋아도” **노출이 잘못**되어 발생합니다:  
  - QQQ/SPY 베타 과다, 단일 종목 쏠림, Tech 과집중, 변동성 급등 구간에서 레버리지 유지 등
- 레짐(리스크온/오프) 전환에서 MDD가 커지면 lockbox 개선이 막힙니다.

### (b) 위험/부작용
- 제약이 과하면 알파를 깎아먹음(과도한 중립화)
- 레짐 필터는 잘못 만들면 “타이밍 미스”로 손실

### (c) 최소 실험 2~3개
**실험 1 — 베타 캡(또는 부분 중립화)**
- (1) 실험 정의: 포트폴리오 beta(SPY 또는 QQQ 기준)를 목표 범위로 클리핑(예: 0.3~0.8)
- (2) 게이트: beta가 범위를 벗어나는 날이 1% 미만
- (3) 기대 관측치: worst_mdd 개선, 성과 변동성 감소

**실험 2 — 섹터 밸런스 강제(Tech/Healthcare 최소 보유 수)**
- (1) 실험 정의: 8~14개 중 Tech/Healthcare 각각 최소 n개 보유(예: 각 3개 이상) + 단일 종목 max weight 제한
- (2) 게이트: 제약 위반 0건
- (3) 기대 관측치: 특정 빅테크/바이오 단일 이벤트 리스크 감소

**실험 3 — ETF 레짐 관측(QQQ, XLV, IBB 등) 기반 리스크 오프 스위치**
- (1) 실험 정의: ETF는 매매하지 않고, (예) QQQ 20d 모멘텀<0 또는 변동성 급등 시 총 익스포저/turnover 축소
- (2) 게이트: 레짐 신호가 미래 데이터를 참조하지 않음(정렬/시차 해시로 검증)
- (3) 기대 관측치: 하락장 구간에서 드로우다운 완화

### (d) PASS 조건
- `worst_mdd`가 Champion(-0.1118) 대비 개선(예: **-0.105 이상**)  
- lockbox_mean이 소폭 손해를 보더라도(예: -0.5%p 이내) **min/드로우다운 개선**이면 채택 가능

# 5) **과최적화 억제(튜닝-락박스 갭/분산 축소) + 48시간 루프 안정화**
### (a) 왜 필요한지
- tuning_mean이 높아도 lockbox가 안 움직이면, **모델/피처/하이퍼파라미터가 과적합**일 확률이 큽니다.
- 자동 루프(48h)에서는 “승자”가 우연히 뽑히는 것을 막는 **보수적 게이트**가 필요합니다.

### (b) 위험/부작용
- 단기 최고 성과 후보를 버리고 “덜 화려하지만 견고한” 후보로 이동 → 숫자가 잠깐 밋밋해질 수 있음

### (c) 최소 실험 2~3개
**실험 1 — 피처/모델 단순화(코어 피처만)**
- (1) 실험 정의: 피처 셋을 상위 기여 코어로 축소(예: 30~50%로), 나머지 제거
- (2) 게이트: tuning_mean은 조금 내려가도, fold 분산/최저값이 개선되면 통과
- (3) 기대 관측치: lockbox의 변동성/최저 성과 개선

**실험 2 — Purge/Embargo(시간 누수형 과적합 방지)**
- (1) 실험 정의: CV split에 purge/embargo를 적용(이벤트/기간 겹침 제거)
- (2) 게이트: 적용 전/후 tuning 성과가 크게 무너지면 기존에 누수형 구조였던 것
- (3) 기대 관측치: tuning이 내려가도 lockbox는 상대적으로 유지

**실험 3 — “게이트 우선순위”를 샤프 단일지표 → 최저/드로우다운 중심으로 변경**
- (1) 실험 정의: 자동 선택 기준을 `mean` 우선이 아니라 `lockbox_min`, `worst_mdd` 가중으로 변경(소수 후보만)
- (2) 게이트: 선택된 후보의 worst_mdd가 꾸준히 개선되는지 확인
- (3) 기대 관측치: 성과 정체가 “꼬리 리스크” 때문이면 개선

### (d) PASS 조건
- `tuning_mean - lockbox_mean` 갭 축소(예: 20% 이상 감소)  
- fold 최저값/lockbox_min 하방 안정(Champion lockbox_min=1.3469 이상 유지 목표)  
- worst_mdd 악화 금지(≤ -0.1118로 더 나빠지면 FAIL)

## 48시간 자동 루프에 바로 넣는 “실행 순서” (명령형)
1) **Lockbox 무결성 센티널 3종을 먼저 1회씩 돌려**(캐시무효/오염/시간쉬프트) → 평가 파이프라인이 실제로 변화를 반영하는지 확인  
2) **비용/체결 패치(비용 스윕 + 1일 지연 + turnover cap)**를 고정된 Champion에서 먼저 검증 → “정체 원인이 비용인지” 선판별  
3) PIT 유니버스/코퍼레이트 액션 체크를 통과한 뒤에만 → 노출제어/레짐 관측 실험을 진행  
4) 마지막으로 과최적화 억제(CV purge/embargo + 단순화 + 선택게이트 변경)를 적용해 후보 탐색 재개  
5) 모든 리포트에 `data/feature/pred/position hash`와 turnover/beta/섹터비중/비용을 표준 출력으로 고정

# 성능이 안 움직일 때 “원인 분해” 아이디어(트리거/적용/노출/비용/레짐)
아래는 **한 번에 원인을 특정**하기 위한 분해 트리(질문 없이 바로 측정 항목 제시).

## A) Trigger(신호 자체가 맞나?)
- **IC/RankIC**(예측 vs 다음기간 수익) + 기간별 안정성(rolling)
- **Hit rate**(상위 n개가 시장/섹터 대비 이겼는지)
- “치팅 쉬프트(+1)”와 “지연 쉬프트(-1)” 민감도(누수/타이밍 의존성)

## B) Apply(신호가 포지션으로 제대로 반영되나?)
- 예측→가중치 매핑이 **포화/클리핑**되어 대부분 동일 비중인지 확인
- 리밸런싱 시점에 **포지션 갱신이 실제로 일어나는지**: `pred_hash != position_hash` 빈도 측정
- 결측/거래불가 시 fallback 규칙이 **몰래 현금화/몰빵**을 만드는지 점검

## C) Exposure(원치 않는 위험을 먹고 있나?)
- SPY/QQQ 베타, 섹터(Tech/Health) 내부 편향, 단일종목 max weight
- 스타일 팩터(대형/가치/모멘텀/퀄리티) 간접노출(단순 회귀로도 충분)
- 변동성 타겟 위반일수(레버리지/익스포저가 급등하는 구간)

## D) Cost(거래비용이 알파를 삼키나?)
- **Turnover(일/주/월)**, 평균 리밸런싱 거래량, 비용 민감도(3점 스윕)
- “비용 전 알파” vs “비용 후 알파” 분해(슬리피지/수수료 각각 기여)

## E) Regime(레짐에서만 죽나?)
- 변동성 상/하위 구간, 금리 급등 구간(간단히 TLT/IEF/2Y proxy를 **지표로만**), QQQ 모멘텀 음/양 구간에서 성과 분리
- 레짐별 MDD/승률/턴오버 비교 → 특정 구간에서만 붕괴하면 레짐 게이트가 해법
