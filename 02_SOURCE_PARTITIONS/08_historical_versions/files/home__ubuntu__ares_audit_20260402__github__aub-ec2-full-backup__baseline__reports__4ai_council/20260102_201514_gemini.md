3.  **[COST/REALITY] 슬리피지/수수료 페널티 강제 주입 실험**: 현재 높은 OOS Mean이 거래 비용을 무시한 단타 매매 결과인지 확인. 편도 15bps(0.15%) 강제 적용 후 수익률 방어력 테스트.
4.  **[UNIVERSE/FILTER] Tech/Healthcare 섹터 편중 리스크 헷지**: 기술주/헬스케어(High Beta) 집중 시 하락장에서 전멸 가능. 변동성(ATR) 기반 포지션 사이징(Position Sizing) 로직 도입으로 MDD 산출 유도.
5.  **[EXECUTION] Exposure Gap 필터링**: Exposure Min이 0.0임. 시장 관망이 너무 잦음. 최소 노출 비중(예: 0.2)을 강제하거나, Cash 보유 시 패널티를 부여해 '안전지향 편향' 제거.

### 실험 1: Rebalance Logger Patch & Format Unification
*   **(a) 필요성**: 현재 `rebalance.csv` 로딩 실패로 턴오버 및 거래 비용 분석 불가. 맹목적 비행 상태.
*   **(b) 위험**: 로그 포맷 변경 시 기존 백테스트 기록과의 호환성 일시 단절.
*   **(c) 실험 정의 (3개)**:
    1.  `fix_log_jsonl`: 로거 출력을 강제로 JSONL 포맷으로 통일하고, CSV 헤더 유효성 검사 로직 추가.
    2.  `force_flush`: 매 리밸런싱 스텝마다 I/O Flush 강제 수행 (빈 파일 생성 방지).
    3.  `verify_log_content`: 더미(Dummy) 거래 10회를 수행하고 로그 파싱이 성공하는지 단위 테스트.
*   **(d) PASS 조건**: `aub_rebalance_pinpoint.py` 실행 시 에러 없이 통계(Turnover, Cost) 출력.

### 실험 2: Degenerate Folds Resurrection (Entry Threshold Relax)
*   **(a) 필요성**: 폴드 1, 2, 3, 8의 붕괴는 해당 시기 시장 데이터 노이즈로 인해 신호가 전무했거나, 손절이 너무 타이트하여 깡통을 찼음을 의미.
*   **(b) 위험**: 진입 장벽을 낮추면 False Positive(가짜 신호) 증가로 평균 수익률 하락 가능성.
*   **(c) 실험 정의 (3개)**:
    1.  `relax_entry_05`: 진입 신호(Signal Strength) 임계값을 기존 대비 50% 하향 조정.
    2.  `widen_stop_2x`: 손절(Stop-loss) 폭을 2배로 확장 (노이즈에 의한 조기 퇴출 방지).
    3.  `fill_na_neutral`: 데이터 결측 구간에 대해 '보류(Hold)' 또는 '시장수익률'로 대체하여 폴드 계산 강제 수행.
*   **(d) PASS 조건**: `degenerate_folds` 리스트가 빈 배열 `[]`이 되고, OOS Mean > 1.5 유지.

### 실험 3: Cost Reality Check (Slippage Injection)
*   **(a) 필요성**: OOS Mean 3.32는 비현실적. 비용 반영 시 마이너스로 전환될 가능성 점검.
*   **(b) 위험**: 전략 폐기 수순으로 이어질 수 있음(그러나 빨리 폐기하는 것이 리소스 절약).
*   **(c) 실험 정의 (3개)**:
    1.  `cost_10bps`: 거래당 비용 10bps(0.1%) 적용.
    2.  `cost_20bps`: 거래당 비용 20bps(0.2%) 적용 (보수적 기준).
    3.  `cost_variable_vol`: 변동성(ATR)이 높을 때 비용 가중치 증가 모델 적용.
*   **(d) PASS 조건**: 20bps 적용 시에도 Sharpe Ratio > 1.0 (또는 OOS Mean > 1.0) 유지.

### 실험 4: Volatility-based Exposure Cap (Anti-MDD)
*   **(a) 필요성**: `worst_mdd: None`은 MDD 계산 로직 오류거나 데이터 부족. Tech/Bio는 변동성이 크므로 변동성 역가중(Inverse Volatility) 배분이 필수.
*   **(b) 위험**: 강세장에서 수익률 제한(Underperformance).
*   **(c) 실험 정의 (3개)**:
    1.  `calc_mdd_force`: MDD 계산 기간 및 로직 재설정 (Daily -> Hourly or Tick data check).
    2.  `cap_exposure_atr`: 개별 종목의 ATR이 상위 20%일 경우 비중 50% 축소.
    3.  `sector_hedge_tech`: 기술주 비중이 60% 초과 시 현금 비중 강제 20% 확보.
*   **(d) PASS 조건**: `worst_mdd` 수치가 정상 산출되고, -20% 이내로 방어.

[성능 정체 시 원인 분해 아이디어]

만약 위 실험 후에도 성능(수익률)이 제자리거나 개선되지 않는다면 다음 단계로 분해:

1.  **트리거(Trigger) 실패**:
    *   *가설*: 예측 모델의 신호가 실제 매매 임계값(Threshold)을 넘지 못함.
    *   *확인*: `pred_score` 분포 확인 (대부분 0.4~0.6 사이의 애매한 값인지).
2.  **적용(Execution) 누수**:
    *   *가설*: 신호는 떴으나 유동성 부족이나 호가 갭으로 체결 실패 가정.
    *   *확인*: 시뮬레이터의 `fill_rate` 확인. (특히 개장 직후/장 마감 직전).
3.  **노출(Exposure) 회피**:
    *   *가설*: 시장 하락을 예측하고 지속적으로 Cash(Exposure 0) 상태 유지.
    *   *확인*: 전체 기간 중 `Cash Ratio`가 50% 이상인지 확인. (너무 겁쟁이 모델).
4.  **레짐(Regime) 불일치**:
    *   *가설*: 현재 훈련 데이터가 2020-2021년(상승장)에 편중되어, 횡보/하락장에서 작동 안 함.
    *   *확인*: 폴드별 수익률과 SPY/QQQ 벤치마크 상관관계(Correlation) 분석. 상관계수가 너무 높으면 알파가 없는 것.
