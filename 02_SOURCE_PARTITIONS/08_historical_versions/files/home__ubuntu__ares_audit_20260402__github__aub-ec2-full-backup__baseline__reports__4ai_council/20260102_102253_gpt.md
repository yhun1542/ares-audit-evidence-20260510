## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — **명령형 체크리스트**
(우선 점검: **누수 → 과최적화 → 서바이버십 → 비용 미반영 → 운영 리스크** / US 주식 only / Tech+Healthcare 8~14종목 / ETF는 관측지표만)

---

# 1) **시간축 누수(특히 corporate action/지표 publish lag) “하드-게이트” 추가**
### (a) 왜 필요한지
- 현재 챔피언이 tuning/lockbox 모두 높은데, 이런 형태는 **미세 누수(정렬/시차/수정주가 사용)**만 있어도 “안정적으로 좋아 보이는” 착시가 자주 발생.
- 48시간 자동 루프에서 **누수 검증이 gate로 고정**되지 않으면, 이후 모든 개선이 무의미해짐.

### (b) 위험/부작용
- 누수 제거 후 성능 급락 가능(정상).  
- 라벨/피처 시차를 보수적으로 잡으면 신호가 약해져 수익률 감소.

### (c) 최소 실험 (Micro-test 2개 + Full-run 1개)
**Micro-test (빠르게, 백테스트 전)**
- [ ] **시차 강제 테스트**: 모든 피처에 +1 trading day 지연 강제 적용(또는 라벨을 -1로 당김) 시 성능이 “비정상적으로 유지”되는지 확인.
- [ ] **셔플 테스트**: 날짜 블록 단위로 피처/라벨 관계를 깨는(block shuffle) 테스트에서 성능이 0 근처로 붕괴하는지 확인.

**Full-run (이번 48h에 포함: 1개)**
- [ ] `exp_leakage_hardgate_v1`: (i) publish-lag 적용(가능한 피처는 공시/발표 지연 반영), (ii) close→next open/close 실행가정 정합성 강제, (iii) split/dividend 처리 경로 단일화 후 tuning+lockbox 재평가.

### (d) PASS 조건(게이트)
- [ ] 셔플/시차 테스트 성능이 **무의미(예: SR≈0, 평균수익≈0)로 붕괴**할 것(“유의미하게 남으면 FAIL”).
- [ ] Full-run에서 **lockbox_mean ≥ 챔피언 lockbox_mean의 95%**(≈ 1.7925 * 0.95) 이상 유지 **또는** 유지 실패 시에도 “누수 제거 증거”가 명확하면 다음 패치로 진행(챔피언 교체는 보류).

---

# 2) **거래비용/슬리피지/체결지연을 ‘상한선(보수적)’으로 고정하고 성능 재측정**
### (a) 왜 필요한지
- 비용 미반영은 Tech/Healthcare(특히 변동성 큰 성장주)에서 **가짜 알파**를 가장 많이 만듦.
- 현재 lockbox_mean이 좋을수록 “비용 5~30bp만 얹어도” 급격히 무너질 수 있음.

### (b) 위험/부작용
- 비용 상향으로 단기 성능이 크게 낮아져 “개선이 안 움직인다”로 오해 가능.
- 너무 보수적이면 유의미 신호까지 죽일 수 있음(하지만 **게이트 목적**에선 보수적이 맞음).

### (c) 최소 실험 (Micro-test 2개 + Full-run 1개)
**Micro-test**
- [ ] **회전율(turnover) 분해 리포트**: 일별/주별 turnover, 상위 10 이벤트일(리밸런싱 폭발일) 추출.
- [ ] **비용 민감도 곡선**: 비용 0/5/10/20/40bp에서 PnL 기울기(대충이라도) 산출.

**Full-run (이번 48h에 포함: 1개)**
- [ ] `exp_cost_model_cap_v1`: (i) 고정비용 + (ii) 변동 스프레드(예: ADV/vol 기반 간단 모델) + (iii) 체결 1 bar 지연(가능하면 next open) 가정으로 tuning+lockbox 재평가.

### (d) PASS 조건(게이트)
- [ ] 비용 20bp(또는 내부 기준 상한)에서 **lockbox_mean이 챔피언 대비 90% 이상 유지**.
- [ ] 비용을 올릴수록 성능이 “완만하게” 감소해야 함(비용 0과 20bp 결과가 비슷하면 오히려 체결/비용 모델 누락 의심 → FAIL).

# 3) **서바이버십/상장폐지/심볼변경(merger) 처리: “리턴 체인” 완전성 게이트**
### (a) 왜 필요한지
- 8~14 종목 집중 포트폴리오는 **단일 상장폐지/인수합병 이벤트**가 성능을 완전히 바꿈.
- survivorship가 있으면 Healthcare 바이오 쪽에서 특히 과대평가됨.

### (b) 위험/부작용
- 데이터 소스/매핑 수정이 커지면 파이프라인이 흔들릴 수 있음(운영 리스크).
- delist return을 보수적으로 넣으면 성능 하락 가능(정상).

### (c) 최소 실험 (Micro-test 2개 + Full-run 1개)
**Micro-test**
- [ ] 백테스트 기간 중 **delist/merge/symbol change 발생 티커 목록**과 해당 기간 포지션 보유 여부 리포트 생성.
- [ ] “가격 시계열 단절(0, NaN, 점프)” 이벤트 탐지 후, 해당 날짜의 포지션/리밸런싱 로그 매칭.

**Full-run (이번 48h에 포함: 1개)**
- [ ] `exp_survivorship_fix_v1`: (i) delisting return 반영(가능한 범위), (ii) 심볼 체인 매핑 고정, (iii) 결측 처리 규칙 단일화 후 lockbox 재평가.

### (d) PASS 조건(게이트)
- [ ] delist/merge 이벤트일에 포트폴리오 가치가 “비현실적 점프”를 보이지 않을 것(탐지 규칙 기반).
- [ ] fix 전후 결과 차이가 큰 경우(>X%)라도 원인이 이벤트로 설명 가능하면 PASS(게이트는 “정합성” 우선).

# 4) **과최적화 억제: “모델 복잡도/자유도 상한” + 단순 노출 제어(베타/섹터/볼)**
### (a) 왜 필요한지
- 챔피언은 좋지만, 후보가 tuning_min이 -1.41처럼 크게 깨진 이력이 있음 → **설정/모듈 조합에 따라 tail이 쉽게 깨지는 구조** 가능.
- Tech+Healthcare 집중은 시장 베타/금리 레짐에 휩쓸리기 쉬움 → 알파인지 베타인지 분해가 필요.

### (b) 위험/부작용
- 노출 제어(예: beta neutral, vol targeting)가 알파를 같이 깎을 수 있음.
- 지나친 단순화는 기회 손실.

### (c) 최소 실험 (Micro-test 2개 + Full-run 1개)
**Micro-test**
- [ ] 포트의 **SPY/QQQ/XLV(관측용 ETF)** 회귀로 beta/섹터 노출 추정(월별 롤링).
- [ ] 신호의 “자유도” 지표: 피처 수/룰 수/리밸런싱 빈도/turnover 상관을 대시보드화.

**Full-run (이번 48h에 포함: 1개)**
- [ ] `exp_exposure_cap_v1`: (i) beta cap(예: |beta|<0.3) 또는 (ii) 변동성 타게팅(포트 vol 목표) 중 하나만 추가해 lockbox에서 tail 개선 여부 확인.

### (d) PASS 조건(게이트)
- [ ] **worst_mdd가 챔피언(-0.0931) 대비 개선(절대값 감소)**하거나 최소 동일 수준 유지.
- [ ] lockbox_mean이 챔피언의 **93~95% 이상 유지**하면서 tail(최악구간/드로우다운)이 개선되면 강한 PASS.

# 5) **운영 리스크: 48시간 자동 루프 “재현성/데이터 스냅샷/게이트 실패 시 롤백” 강제**
### (a) 왜 필요한지
- 실험이 “안 움직이는” 가장 흔한 이유 중 하나가 **데이터/시드/캐시 흔들림**으로 신호 대비 잡음이 커지는 것.
- 자동 루프에서 챔피언을 보호하려면 **게이트 실패 시 자동 중단 + 리포트 생성**이 필수.

### (b) 위험/부작용
- 초기엔 속도 저하(스냅샷/로그 증가).
- 게이트가 빡세면 PASS가 안 나와 정체처럼 보일 수 있음(하지만 장기적으론 필수).

### (c) 최소 실험 (Micro-test 2개 + Full-run 0개: 운영 패치)
**Micro-test**
- [ ] 동일 커밋/동일 데이터 스냅샷/동일 시드로 **2회 연속 실행 결과가 byte-level(또는 지표 수준)로 동일**한지 확인.
- [ ] 데이터 갱신 시각 기준으로 **스냅샷 해시**를 기록하고, 실험 결과 메타데이터에 강제 첨부.

**운영 패치**
- [ ] `gate_fail_stop`: 누수/비용/서바이버십 게이트 중 하나라도 FAIL이면 `--select-best`에서 자동 제외 + `next_fix.md`에 원인/로그 링크 자동 출력.

### (d) PASS 조건(게이트)
- [ ] 재현성 테스트 2회 결과가 지표 오차 허용범위 내(예: SR diff < 0.01, MDD diff < 0.1%p)로 일치.
- [ ] gate fail 시 챔피언 파일이 절대 덮어써지지 않음(원자적 저장/락).

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래 순서대로 “깨지는 지점”을 고정적으로 찾는 분해 루틴을 추가(질문 없이 실행):

## A) Trigger(신호 발생) 문제
- [ ] 신호 발생 빈도(일별 non-zero weight 변화, 진입/청산 횟수)가 너무 낮거나 너무 높지 않은지 확인.
- [ ] 상위 기여 피처/룰이 특정 기간에만 작동하는지(기간별 IC/Hit-rate) 확인.

## B) Apply(체결/리밸런싱 적용) 문제
- [ ] 리밸런싱 스케줄이 price bar와 정렬되는지(예: close 기준 신호를 same close에 체결하는 오류) 점검.
- [ ] 포지션 업데이트가 “부분 적용”되거나 결측일에 강제 청산/강제 유지되는 버그 탐지.

## C) Exposure(시장/섹터/팩터 노출) 문제
- [ ] SPY/QQQ/XLV에 대한 롤링 beta 및 섹터 노출이 알파를 압도하는지 확인.
- [ ] 상관구조 붕괴 시(예: 금리 급변) 포트가 한 방향으로 쏠리는지 점검(8~14 집중은 특히 중요).

## D) Cost(비용/슬리피지) 문제
- [ ] 성능 기여가 “리밸런싱 직후 초단기 구간”에만 존재하면 비용에 취약한 신호일 확률 큼 → 비용 상향 민감도 곡선으로 즉시 확인.
- [ ] turnover 폭발일이 성능의 대부분을 만들면(몇 일에 PnL 집중) 과최적화/체결착시 가능성 ↑.

## E) Regime(레짐) 문제
- [ ] 금리/인플레/리스크온오프 대용 지표로 기간을 쪼개고(관측용: TLT/IEF, VIX proxy, QQQ/XLV 상대강도) 레짐별 성능을 분해.
- [ ] 레짐 전환 구간에서 MDD가 집중되면 “노출 cap/vol targeting”이 효과적인지 확인.
