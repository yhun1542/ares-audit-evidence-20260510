## 0) 24~48시간 “먼저 깨질 것부터” 점검 순서 (명령형 체크리스트)
1) **누수(lookahead/as-of) 차단**: 모든 피처/펀더멘털/코퍼액션/리밸런싱 타임스탬프를 “체결 가능 시점” 기준으로 강제 정렬하라.  
2) **서바이버십 제거**: Tech+Healthcare **8~14 종목 유니버스**를 “현재 구성”이 아니라 **과거 시점에 실제로 존재/거래 가능**한 규칙으로 재정의하라(IPO/상폐/거래정지 반영).  
3) **비용/마켓임팩트 반영**: 스프레드·ADV·변동성 기반 슬리피지 + 커미션 + (숏이면) borrow/HTB 비용을 **학습/평가/게이트 전 구간에 동일 적용**하라.  
4) **과최적화(튜닝-락박스 갭) 축소**: purged CV + embargo + 단순화(파라미터/피처/룰 수 축소)로 “우연히 맞춘” 구조를 걷어내라.  
5) **운영 리스크(48h 자동루프) 봉합**: 데이터 누락/분할·배당 조정/주문 실패/리밸런싱 타이밍 불일치가 나도 포지션이 폭주하지 않게 “안전모드”를 넣어라.

## 1) 우선순위 TOP5 제안 (코드/아키텍처/전략)  
아래 5개 제안은 **서로 다른 이름**이지만, 실제 실행은 **공유되는 5개 패치/실험(E1~E5)**로 돌리게 구성했다(케이스 폭발 방지).

---

# 제안 1) “비용-현실화”를 챔피언 게이트에 승격
### (a) 왜 필요한지
- 현재 챔피언/후보 비교에서 **튜닝 성능은 높지만(챔피언 tuning_mean 1.90)** 실제 운용에서 제일 먼저 무너지는 건 대개 **회전율·슬리피지·숏 비용**이다.
- 비용을 사후에만 빼면, 최적화가 “비용 0” 세계에 과적합될 확률이 높다.

### (b) 위험/부작용
- 비용 모델이 과보수면 좋은 전략을 조기에 죽일 수 있다(특히 8~14 종목이면 개별 종목 스프레드 민감).
- 숏 borrow/HTB를 잘못 추정하면 특정 종목에 불필요한 페널티가 걸린다.

### (c) 최소 실험 2~3개 (공유 실험 참조)
- **E1** 비용/임팩트 모델을 백테스트 PnL에 “항상” 적용 + 목적함수에 turnover 페널티 추가  
- **E4** 포지션 사이징에 “거래 임계값(Δposition < x면 미체결)” 또는 최소 보유기간 적용(회전율 강제 하락)  
- **E3** 고변동 레짐에서 거래량/슬리피지 확대를 반영하거나, 아예 위험회피 게이트로 트레이드 차단

### (d) PASS 조건(게이트)
- **락박스(net-of-cost) mean ≥ 1.70** AND **락박스 min ≥ 0.90**  
- **턴오버 20% 이상 감소**(챔피언 대비) AND **성능 하락폭 ≤ 5~8%**(mean 기준)  
- 비용 적용 전/후 성능 괴리가 “비정상적으로” 커지지 않을 것(= 비용 모델이 과도하지 않음): **(gross_mean - net_mean) 안정적**

---

# 제안 2) “서바이버십/유니버스”를 고정 규칙으로 재구성(Tech+Healthcare 8~14)
### (a) 왜 필요한지
- 8~14 종목 소수 포트는 **유니버스 정의가 곧 알파**다.  
- “현재 알고 있는 대표 종목”으로 과거를 돌리면 서바이버십으로 락박스가 뻥 튈 수 있다.

### (b) 위험/부작용
- 유니버스를 고정하면 기회가 줄어 mean이 떨어질 수 있다.
- 과거 구성까지 완벽히 하려다 데이터 비용/복잡도가 급증할 수 있다(운영 리스크 증가).

### (c) 최소 실험 2~3개
- **E2** “유니버스 생성기”를 과거시점 기준으로 재정의:  
  - (예) *상장 후 N일 경과*, *평균 달러거래대금 하한*, *거래정지/상폐 제거*, *Tech/Healthcare 분류 as-of 적용*  
- **E2** “현재 목록을 과거에 투사”하는 코드 경로를 강제로 차단(테스트 실패 처리)  
- **E5** 유니버스 변경 빈도를 제한(월 1회/분기 1회)해 과최적화 및 운영 복잡도 축소

### (d) PASS 조건
- 유니버스 관련 누수 테스트(아래 E2 게이트) **100% 통과**  
- 락박스 성능이 낮아지더라도 **worst_mdd 악화 없이 유지(≤ -0.10)** 또는 개선  
- 종목 수가 항상 **8~14**로 유지되고, 단일 종목 비중 폭주가 없을 것(= E4와 결합)

---

# 제안 3) “누수/타임스탬프” 하드 게이트 + Purged CV로 과최적화 억제
### (a) 왜 필요한지
- 지금 수치만 보면 챔피언이 튜닝에서 강함(1.90) → **튜닝-락박스 갭 관리**가 최우선.  
- 펀더멘털/리비전/공시/코퍼액션이 들어가면 as-of 누수는 거의 필연적으로 발생한다.

### (b) 위험/부작용
- 엄격한 embargo/purge는 성능을 “진짜로” 깎는다(하지만 그게 현실).
- 피처 파이프라인이 복잡하면 개발 시간이 늘어난다.

### (c) 최소 실험 2~3개
- **E2** “as-of join” 강제(모든 피처에 `available_ts`를 부여하고, 예측 시점 < available_ts면 NaN 처리)  
- **E5** Purged K-fold + embargo(예: 5~20일)로 재평가하고, 튜닝 최적화를 간소화(파라미터 수/피처 수 상한)  
- **E5** “라벨-실행” 정렬: 예측 horizon과 실제 보유/리밸런싱 주기를 1:1로 고정(불일치 제거)

### (d) PASS 조건
- **튜닝_mean - 락박스_mean ≤ 0.25** (갭이 커지면 과최적화로 FAIL)  
- 락박스 mean이 소폭 내려가도 **락박스 min ≥ 1.0 근처 유지**(바닥 붕괴 금지)  
- 누수 탐지 테스트(E2 게이트)에서 단 1건이라도 적발 시 즉시 FAIL

---

# 제안 4) “노출(베타/섹터/단일종목) + MDD”를 시스템 레벨에서 강제
### (a) 왜 필요한지
- 8~14 종목은 **단일 종목/섹터/시장 베타**가 실적을 지배한다.  
- 후보가 MDD는 개선(-0.041)했는데 mean이 낮음 → **리스크 예산/노출 제어로 mean을 덜 해치며 MDD를 유지**하는 쪽이 현실적이다.

### (b) 위험/부작용
- 제약이 과하면 알파를 잘라먹는다(특히 Tech 편향 알파가 많음).
- 베타 중립이 “원치 않는 역노출(예: 품질주/성장주)”을 만들 수 있다.

### (c) 최소 실험 2~3개
- **E4** 시스템 제약 추가:  
  - 단일 종목 max weight(예: 15~20%)  
  - Tech/Healthcare 비중 밴드(예: 30~70% 범위)  
  - QQQ(관측지표 ETF) 대비 베타/상관 상한  
- **E3** 레짐(리스크-온/오프)에서 net exposure/레버리지 축소(변동성 타겟팅)  
- **E1** 회전율 페널티와 결합해 “리스크 줄이려고 괜히 자주 갈아타는” 현상 방지

### (d) PASS 조건
- **worst_mdd ≤ -0.10 방어**(현재 챔피언 worst_mdd -0.093 수준 유지/개선)  
- 락박스 mean **유지(≥ 1.70)** 또는 min **개선(≥ 1.10)** 중 하나는 달성  
- 단일 종목 기여도/리스크 기여가 특정 1~2종목에 과집중되지 않을 것(기여도 상한 체크)

---

# 제안 5) 48시간 자동루프 운영 리스크 봉합(데이터/주문/코퍼액션)
### (a) 왜 필요한지
- 자동 루프에서 진짜 손실은 성능이 아니라 **“잘못된 데이터/주문”**에서 나온다.
- 분할/배당/티커 변경/거래정지에서 포지션 계산이 꼬이면 MDD가 아닌 “단발성 폭발”이 생긴다.

### (b) 위험/부작용
- 방어 코드가 많아지면 실험 속도가 느려질 수 있다.
- 너무 보수적인 안전모드는 거래 기회를 줄인다.

### (c) 최소 실험 2~3개
- **E2** 코퍼액션/가격 조정 무결성 테스트(분할일 전후 수익률 이상치 탐지, 조정 전/후 연속성)  
- **E4** “안전모드” 포지션 클램프: 데이터 결측/가격 급변/체결 실패 시 목표 포지션을 0 또는 축소로 강제  
- **E1** 비용/슬리피지가 특정일 비정상 급등하면 트레이드 스킵(운영 게이트)

### (d) PASS 조건
- 데이터 무결성 테스트에서 **치명(critical) 0건**  
- 주문/포지션 산출에서 NaN/inf/초과 레버리지 **0건**  
- 안전모드 발동이 있어도 락박스 성능이 “완전 붕괴”하지 않을 것(락박스 min 방어)

## 2) 48시간 자동루프에 바로 넣는 “실행 패치/실험” 5개 (E1~E5)
각 실험은 (1)정의 (2)게이트 (3)기대 관측치로 고정.

---

### E1) Cost/Impact-aware PnL + Turnover penalty (비용-현실화)
1) **실험 정의**  
- 백테스트 체결가를 mid가 아니라 `mid ± k*spread` 또는 `vol, ADV` 기반 슬리피지로 모델링  
- 커미션 고정 + (숏이면) borrow 비용(보수적 상수라도) 반영  
- 목적함수/스코어에 turnover 페널티(또는 거래 임계값) 추가
2) **게이트**  
- net-of-cost 락박스 mean ≥ 1.70, min ≥ 0.90  
- turnover 20%+ 감소  
3) **기대 관측치**  
- gross 성능은 유지 또는 소폭 하락, **net 성능의 안정성↑**, min/꼬리 손실↓  

---

### E2) Leakage/Survivorship hardening (as-of + 유니버스 과거화)
1) **실험 정의**  
- 모든 피처/펀더멘털에 `available_ts` 부여 후 as-of join 강제  
- 유니버스는 “과거 시점에서 생성 가능한 규칙”으로만 구성(Tech+Healthcare, 8~14 유지)
2) **게이트**  
- lookahead 탐지(미래 데이터 사용) 0건  
- “현재 종목 리스트로 과거 백테스트” 경로 감지 시 즉시 FAIL
3) **기대 관측치**  
- 튜닝 성능 하락 가능, 대신 **튜닝-락박스 갭 축소**, 락박스 신뢰도↑  

---

### E3) Regime gate using ETF indicators (관측지표로만)
1) **실험 정의**  
- QQQ/XLK/XLV(및 VIX 등)로 레짐 스코어 산출(예: 추세/변동/크레딧 스트레스 대용)  
- 레짐이 위험오프면: (a) 노출 축소 (b) 리밸런싱 빈도 축소 (c) 거래 스킵
2) **게이트**  
- worst_mdd 개선 또는 유지(≤ -0.10)  
- 레짐 OFF 구간에서 거래 수/회전율 유의미 감소
3) **기대 관측치**  
- 급락/변동성 확대 구간 손실↓, 후보가 보인 “낮은 MDD” 성질을 시스템화  

---

### E4) Exposure constraints + safety clamps (노출/운영 동시 제어)
1) **실험 정의**  
- 단일 종목 max weight, 섹터 밴드, 베타 상한, 레버리지 상한  
- 데이터 결측/가격 이상치/체결 실패 시 목표 포지션 클램프(축소 또는 0)
2) **게이트**  
- 포지션/레버리지 초과 0건, NaN 0건  
- 락박스 min ≥ 1.0 근처 유지(바닥 붕괴 금지)
3) **기대 관측치**  
- tail risk↓, 운영사고성 손실↓, 소수 종목 포트의 “폭주” 방지  

---

### E5) Purged CV + horizon alignment + complexity cap (과최적화 억제)
1) **실험 정의**  
- Purged K-fold + embargo로 재튜닝  
- 예측 horizon = 보유기간/리밸런싱과 강제 정렬  
- 피처/하이퍼파라미터 수 상한(복잡도 캡)
2) **게이트**  
- tuning_mean - lockbox_mean ≤ 0.25  
- 락박스 mean ≥ 1.70 또는 락박스 min ≥ 1.10 중 1개 만족
3) **기대 관측치**  
- 튜닝 스코어는 덜 화려하지만, **락박스의 재현성↑**, “성능이 안 움직이는” 구간에서 원인 분해 가능해짐  

---

## 3) 성능이 안 움직일 때 “원인 분해” 체크리스트 (트리거/적용/노출/비용/레짐)
아래는 48시간 루프에서 바로 로그/리포트로 분해할 항목들이다.

### A. Trigger(신호가 실제로 생기나?)
- 신호 분포가 **0 근처로 수렴**했는지 확인(표준편차/상위분위수)  
- 예측 상위/하위 분위 포트의 **ex-ante 기대수익(또는 다음기간 평균수익)** 스프레드가 있는지 측정  
- 이벤트(실적/뉴스) 기반이면, 이벤트 캘린더가 누락되어 “트리거 부재”인지 확인

### B. Apply(신호가 주문으로 반영되나?)
- 목표 포지션 vs 실제 포지션 괴리(체결 실패/거래 임계값/클램프 발동) 로그화  
- 리밸런싱 타이밍(장중/종가/익일 시가)이 **라벨 산출 시점과 일치**하는지 검증  
- 포지션 변경이 대부분 임계값 아래에서 잘려 “아무것도 안 함”이 되었는지 확인

### C. Exposure(노출이 알파를 덮나?)
- QQQ/XLK/XLV에 대한 베타(롤링)와 성과 상관을 분해  
- 종목별/섹터별 기여도(Contribution to PnL, Contribution to Risk)가 1~2개에 과집중인지 확인  
- 롱/숏(또는 net/gross) 노출이 레짐에 맞게 변했는지 확인

### D. Cost(비용이 알파를 먹나?)
- gross→net 손익 차이를 **거래일/종목별**로 분해(스프레드 확대일이 원인인지)  
- 회전율 급증 구간이 성능 정체 구간과 겹치는지 확인  
- 숏이 있다면 borrow 비용/리콜(가정) 민감도 분석(±50%로 net 변화)

### E. Regime(레짐이 바뀌어 알파가 역전되나?)
- 변동성/추세/금리(관측 ETF로 대체) 상태별로 성과를 **조건부 평균**으로 쪼개라  
- “위험오프에서만 깨지는지 / 위험온에서만 안 먹는지”를 표로 고정 출력  
- 레짐 분류가 불안정하면(자주 토글) → E3에서 히스테리시스(전환 임계값 간격) 추가

## 4) 24~48시간 실행 우선순위(작업 순서)
1) **E2 먼저**(누수/서바이버십은 발견 즉시 전부 무효)  
2) **E1 적용**(비용 현실화 없이는 수치 비교가 무의미)  
3) **E5로 갭 축소**(purged CV + 복잡도 캡)  
4) **E4로 폭주 방지**(소수 종목 포트 안정화)  
5) **E3는 마지막에**(레짐은 강력하지만 과도하면 수익 기회를 잘라먹음)

위 5개를 현재 자동 커맨드 루프에 그대로 태우고, 게이트 실패 시 즉시 롤백/중단하는 구조로 고정하라.
