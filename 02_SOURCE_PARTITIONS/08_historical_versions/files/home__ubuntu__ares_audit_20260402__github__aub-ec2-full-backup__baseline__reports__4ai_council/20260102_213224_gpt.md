## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — **명령형 체크리스트**
> 최우선 점검 순서: **누수 → 과최적화 → 서바이버십 → 비용 미반영 → 운영 리스크**  
> 실행은 **48시간 자동 루프**에 맞춰 “(1) 실험 정의 (2) 게이트 (3) 기대 관측치”로 고정.

---

# 1) **데이터 누수/서바이버십/포인트-인-타임(PTI) 감사 패치**
### (a) 왜 필요한지
- 현재 Champion은 lockbox_mean이 높고(w/ 낮은 worst_mdd) 형태가 “**숨은 누수/서바이버십**이 있으면 가장 먼저 과대평가”되는 패턴.
- 특히 Tech/Healthcare는 **분할·M&A·지수편입·대형 이벤트**가 많아 **종목 리스트/재무데이터/리밸런싱 기준일**이 PTI가 아니면 쉽게 새어 나감.

### (b) 위험/부작용
- 누수 제거 즉시 성능이 “정상화(하락)”될 수 있음(단, 이 하락은 좋은 신호).
- 데이터 로더/피처 생성이 느려질 수 있음(캐시/스냅샷 필요).

### (c) 최소 실험(번들 1개, 내부 3-arm ablation)  
**[실험 E1: PTI+서바이버십 하드닝 번들]**
- Arm A: 현행 그대로(대조)
- Arm B: **종목 유니버스 스냅샷(당시점 상장/거래가능 기준) + delist 포함** 강제
- Arm C: **피처/라벨 “as-of timestamp” 검증**(t 이후 데이터 접근 시 런타임 에러/드롭)

### (d) PASS 조건 (Champion 대비 “정상화 후에도 유지”)
- Gate-1(무결성): **룩어헤드 접근 0건**(로그/카운터로 강제)
- Gate-2(성능):  
  - lockbox_mean ≥ **Champion의 0.90배** (≈ 3.61 이상)  
  - worst_mdd ≥ **Champion - 0.01 이내** (즉, -0.091보다 크면 통과)
- Gate-3(안정성): tuning_mean/lockbox_mean 괴리 확대 금지(과최적화 신호):  
  - (tuning_mean - lockbox_mean) 악화가 Champion 대비 **+0.3 이상 증가**하면 FAIL

### (48h) 기대 관측치
- 성능이 떨어져도 **분산/드로우다운이 더 현실적으로 정렬**, 후보 간 순위 변동이 “설명 가능”해짐.
- 이후 비용/노출 제어 패치가 제대로 먹기 시작함.

---

# 2) **거래비용/슬리피지/시장충격(미반영 비용) 내재화**
### (a) 왜 필요한지
- Tech 대형주는 스프레드가 낮아 보여도 **턴오버/리밸런싱 빈도**가 성능을 잠식.
- Healthcare(특히 바이오/중형)는 이벤트 시 **갭/슬리피지**가 커서 “백테스트 상 이득”이 실거래에서 사라지기 쉬움.

### (b) 위험/부작용
- 비용을 넣으면 당연히 성능 하락. 대신 **실현 가능성**이 올라감.
- 비용 모델이 과보수적이면 전략이 “거의 안 움직이는” 쪽으로 수렴.

### (c) 최소 실험(번들 1개, 내부 3-arm ablation)
**[실험 E2: 비용모델+턴오버 페널티 번들]**
- Arm A: 현행 비용(또는 0에 가까운 비용)
- Arm B: **고정 bps + 스프레드 근사 + 변동성 기반 슬리피지**(간단 모델)
- Arm C: Arm B + **턴오버 상한/페널티(예: 일/주 turnover cap)**

### (d) PASS 조건
- Gate-1(실현가능성): 비용 차감 후에도  
  - lockbox_mean ≥ **Champion의 0.85배** (≈ 3.41 이상)
- Gate-2(과매매 방지):  
  - turnover가 Champion 대비 **+25% 이상 증가**하면 FAIL
- Gate-3(리스크):  
  - worst_mdd가 Champion 대비 **-0.015 이상 악화**하면 FAIL (즉 -0.096 이하로 커지면 FAIL)

### (48h) 기대 관측치
- “좋아 보이던 후보”가 비용에서 무너지는지 즉시 분리됨.  
- 남는 후보는 이후 운영(실거래) 이행 가능.

---

# 3) **노출(Exposure) 제어: Tech+Healthcare 8~14종목 집중 + 베타/섹터/단일종목 리스크 게이트**
### (a) 왜 필요한지
- “성능이 안 움직임”은 종종 **신호는 있는데 포지션 매핑/리스크 제약이 엉켜** 알파가 죽는 케이스.
- 8~14개 집중 포트는 **단일 종목 리스크/섹터 베타**가 성과를 좌우하므로, 노출 게이트가 없으면 fold별 편차가 커짐.

### (b) 위험/부작용
- 제약이 강하면 수익 기회가 줄어 성능이 낮아질 수 있음.
- 섹터 뉴트럴을 과하게 강제하면 “의도한 Tech 편향 알파”가 사라질 수 있음.

### (c) 최소 실험(번들 1개, 내부 3-arm ablation)
**[실험 E3: 노출 게이트 번들(ETF는 관측지표만)]**
- 관측 ETF(매매 금지): **QQQ(성장/나스닥), XLK(Tech), XLV(Healthcare), IBB/XBI(바이오 리스크)**  
- Arm A: 현행 포지션 산출
- Arm B: **단일 종목 최대 비중 cap(예: 15~20%) + 섹터(Tech/HC) 합산 비중 범위**
- Arm C: Arm B + **베타(대 QQQ) 범위 게이트**(예: |beta-1| 제한 또는 저베타 모드)

### (d) PASS 조건
- Gate-1(집중도): 종목 수 **8~14 유지**, 단일 종목 비중 cap 준수 100%
- Gate-2(리스크): worst_mdd **개선 또는 동일**(Champion 대비 +0.0~+0.005p 이내 악화만 허용)
- Gate-3(효율): lockbox_mean이 Champion 대비 **0.95배 이상**이면 PASS(≈ 3.81 이상)  
  - 만약 mean이 소폭 하락해도 **min(최저 성과) 상승** 시(Champion lockbox_min 0.735 대비 +0.1 이상) 조건부 PASS

### (48h) 기대 관측치
- 레짐별(성장/가치, 리스크온/오프) 성과가 “베타”로 설명되는지/알파가 있는지 분리됨.
- fold14_mdd 급락 같은 **특정 구간 붕괴**가 줄어드는지 확인 가능.

# 4) **과최적화(Overfitting) 억제: 단순화/피처 정리/검증 강도 상향**
### (a) 왜 필요한지
- Champion이 너무 강하면(특히 lockbox_mean이 튀는 경우) “검증이 약한 부분”이 있을 확률이 큼.
- 후보가 lockbox에서 눌리면(최근 PASS 후보도 lockbox_mean이 낮음) **특정 모듈이 튜닝셋에만 맞는 구조**일 수 있음.

### (b) 위험/부작용
- 단순화하면 단기 성능은 내려갈 수 있음(대신 재현성과 안정성이 상승).
- 피처 제거가 잘못되면 알파 소실.

### (c) 최소 실험(번들 1개, 내부 3-arm ablation)
**[실험 E4: 단순화/정규화 번들]**
- Arm A: 현행 복잡도
- Arm B: **피처 수/룰 수 상한**(상위 N개만, 또는 L1/그룹 라쏘 등)  
- Arm C: Arm B + **워크포워드 고정(튜닝 윈도우 축소/고정) + seed 고정**(재현성 체크)

### (d) PASS 조건
- Gate-1(일반화): tuning_mean 하락폭 대비 lockbox_mean 하락폭이 작아야 함  
  - (lockbox_mean / tuning_mean) 비율이 Champion 대비 **개선**이면 PASS
- Gate-2(최악 구간): worst_mdd **개선** 또는 Champion 대비 **-0.01p 이내 악화**
- Gate-3(재현성): 동일 seed에서 결과 분산(핵심 지표)이 **허용 범위 내**(예: lockbox_mean 표준편차 임계)

### (48h) 기대 관측치
- “모델이 진짜 세냐 vs 튜닝에만 세냐”가 분리됨.  
- 이후 패치(비용/노출)가 성능에 미치는 방향성이 일관되게 바뀜.

---

# 5) **운영 리스크(48h 자동루프) 하드닝: 실패 모드 차단 + 리포트 강제**
### (a) 왜 필요한지
- 자동 루프에서 제일 큰 리스크는 “조용한 실패”:  
  - 데이터 갱신 누락, 캐시 오래됨, 룩어헤드 재발, 비용모델 비활성화, 종목 수가 8~14를 이탈.
- 성능이 안 움직일 때도 원인을 “관측” 못하면 같은 자리에 머뭄.

### (b) 위험/부작용
- 실패 시 즉시 중단이 많아져 실험 throughput이 줄 수 있음(그러나 잘못된 승자 선택 방지).

### (c) 최소 실험(번들 1개, 내부 2~3 체크)
**[실험 E5: 파이프라인 가드레일/리포트 의무화 번들]**
- Arm A: 현행 autopilot
- Arm B: **Pre-flight 체크(데이터 as-of, 종목 수, 비용 on, 룩어헤드 카운터)** 통과 못하면 run 자체 FAIL
- Arm C: Arm B + **아티팩트 고정 저장(스냅샷/설정/seed/리포트)** + “diff 리포트” 자동 생성

### (d) PASS 조건
- Gate-1: 실패는 “조용히” 지나가면 안 됨 → **체크 실패 시 종료/알림/리포트 생성 100%**
- Gate-2: 동일 config 재실행 시 핵심 지표 재현(허용오차 내)
- Gate-3: next_fix.md에 “원인→조치”가 최소 1개 이상 자동 기재(운영 가시성)

### (48h) 기대 관측치
- 성능 정체의 원인이 “전략”인지 “파이프라인”인지 바로 갈라짐.
- 실험 비교가 쉬워져 select-best의 품질이 올라감.

## 48시간 루프 실행 형태(권장 실행 순서 — 명령형)
1) **E1(누수/서바이버십) 먼저 실행** → 결과가 정상화되면 그 위에 비용/노출을 올리기  
2) 다음으로 **E2(비용) + E3(노출)**  
3) 성능 흔들리면 **E4(과최적화 억제)**  
4) 항상 병행으로 **E5(운영 가드레일)**

# 성능이 안 움직일 때 “원인 분해” 아이디어 (트리거/적용/노출/비용/레짐) — 명령형 체크리스트

## A. 트리거(신호 발생) 단계
- 신호 발생 빈도(일/주)와 강도 분포를 로그로 고정 저장하라  
- 상위 5% 신호일의 다음날/다다음날 수익 분포를 뽑아 “예측력이 있는 날”이 존재하는지 확인하라  
- 신호가 특정 이벤트(실적, CPI/FOMC, FDA, M&A)에만 반응한다면 이벤트 캘린더 기반으로 분리 집계하라(의존성 확인)

## B. 적용(신호→포지션 매핑) 단계
- “신호는 좋은데 성과가 없다”면 아래를 먼저 의심하고 지표화하라  
  - 포지션 캡/리밸런싱 지연으로 신호가 희석되는지  
  - 신호 방향과 포지션 부호가 뒤집히는 케이스가 있는지(부호 오류 카운터)  
  - 포지션 변경이 너무 잦아 비용에 먹히는지(턴오버 히스토그램)

## C. 노출(Exposure) 단계
- 성과를 **QQQ/XLK/XLV**에 회귀해 “알파 vs 베타”를 분리하라(ETF는 관측만)  
- Tech/HC 내에서 특정 메가캡 1~2개가 성과를 지배하면:  
  - 단일 종목 제외 시 성과(leave-one-out)를 48h 루프 리포트에 자동 추가하라(서바이버/집중 리스크 탐지)

## D. 비용(Cost) 단계
- 비용 차감 전/후 샤프·평균·최소 성과를 나란히 저장하라  
- 슬리피지가 커지는 날(갭/고변동성)을 태그하고 해당 구간만 성과를 따로 보라  
- “턴오버 상한”을 걸었을 때 성과가 거의 동일하면 → 기존 성과는 비용에 취약했음을 의미(구조 변경 필요)

## E. 레짐(Regime) 단계
- 레짐을 단 2~3개로만 쪼개라(케이스 폭발 금지):  
  1) QQQ 추세상/하, 2) 변동성 상/하(예: VIX 또는 QQQ realized vol), 3) XLV 상대강도(방어장)  
- 레짐별로 **신호 빈도/평균수익/최대낙폭**을 고정 테이블로 출력하라  
- 특정 레짐에서만 망가지면 → 그 레짐에서 “포지션 0 또는 베타 축소” 게이트를 E3에 편입하라

## 마지막으로: PASS 판정의 “우선순위”
- 성능(mean)보다 먼저 **(1) 누수 0 (2) 비용 반영 후 생존 (3) worst_mdd 안정**을 통과시켜라.  
- Champion 갱신은 **lockbox_mean 근소 열위라도 lockbox_min/worst_mdd 개선**이면 “운영 관점 조건부 승격” 트랙을 허용하라(단, E1~E2 통과 전엔 금지).

위 5개(E1~E5)는 48시간 루프에 그대로 얹을 수 있는 “실행 가능한 번들 실험”으로 설계했고, 각 번들은 내부 ablation(2~3-arm)으로만 변주해 케이스 폭발을 막았다.
