### **P1. Degenerate Fold 근본 원인 진단**

**(a) 왜 필요한지**
- 10개 fold 중 4개 실패 = 전략이 특정 regime에서만 작동
- 남은 6개 fold가 전체 OOS를 끌어올리는 서바이버십 bias

**(b) 위험/부작용**
- 진단만 하면 성능 변화 없음 → 시간 투자
- Fold 구조 변경 시 기존 결과와 비교 불가

**(c) 실험 체크리스트**

```yaml
EXP-P1-A: fold_failure_profiler
  - 정의: 각 degenerate fold (1,2,3,8)의 기간/regime 특성 추출
  - 실행:
    □ python3 tools/fold_analyzer.py --folds 1,2,3,8 --output fold_failure_report.json
    □ 각 fold의 시작-종료일, VIX 평균, 섹터 수익률 분포 기록
  - 게이트: 리포트 생성 완료
  - 기대 관측치: "공통 regime 패턴 발견" 또는 "랜덤 실패"

EXP-P1-B: fold_exclusion_sensitivity
  - 정의: degenerate fold 제외 시 vs 포함 시 OOS 비교
  - 실행:
    □ --exclude-folds 1,2,3,8 로 백테스트 재실행
    □ 전체 10fold와 delta 계산
  - 게이트: |delta OOS| > 0.5 → 서바이버십 확정
  - 기대 관측치: OOS 6-fold only = 4.5+ (과최적화), 10-fold = 2.0- (실제 성능)

EXP-P1-C: walk_forward_purge_extension  
  - 정의: train-test 간 purge gap 7일→21일 확대
  - 실행:
    □ config.yaml에 purge_days: 21 설정
    □ 전체 fold 재실행
  - 게이트: degenerate fold 수 ≤ 2
  - 기대 관측치: OOS mean 2.0~2.5 (누수 제거 시 하락 예상)
```

**PASS 조건**: Degenerate fold ≤ 2개 AND OOS mean > 1.5

### **P2. OOS Mean 급등 누수 검증**

**(a) 왜 필요한지**
- 2.63 → 3.32 (26% 급등)은 실제 개선이 아닌 look-ahead bias 가능성
- Champion 파일 경로 비어있음 → 어떤 변경이 적용됐는지 불명확

**(b) 위험/부작용**
- 누수 확정 시 전체 파이프라인 재검토 필요 (48h 초과 가능)
- False positive → 유효한 개선을 버릴 위험

**(c) 실험 체크리스트**

```yaml
EXP-P2-A: future_feature_audit
  - 정의: 모든 feature의 계산 시점 검증
  - 실행:
    □ python3 tools/feature_timestamp_audit.py --config champion_latest
    □ 각 feature별 "data available at t" vs "used at t" 체크
  - 게이트: 0개 violation
  - 기대 관측치: violation 발견 시 해당 feature 명시

EXP-P2-B: shuffle_target_test
  - 정의: target(수익률)을 랜덤 셔플 후 동일 파이프라인 실행
  - 실행:
    □ --shuffle-target 플래그로 백테스트
    □ OOS mean 측정
  - 게이트: shuffled OOS < 0.3 (랜덤 수준)
  - 기대 관측치: shuffled OOS > 1.0 → 심각한 누수

EXP-P2-C: t-1_strict_mode
  - 정의: 모든 시그널을 t-1 close 기준으로 강제
  - 실행:
    □ config에 strict_lag: true 설정
    □ OOS 재측정
  - 게이트: OOS delta < 0.5 (누수 없음 확인)
  - 기대 관측치: OOS 2.8~3.0 유지 시 clean, 2.0 이하 급락 시 누수 확정
```

**PASS 조건**: shuffle OOS < 0.3 AND t-1 strict OOS > 2.5

### **P3. MDD 계산 파이프라인 복구**

**(a) 왜 필요한지**
- worst_mdd: None = 리스크 측정 완전 실패
- 실제 운영 시 drawdown 제어 불가

**(b) 위험/부작용**
- 계산 로직 버그 vs 데이터 부재 구분 필요
- MDD 계산 추가 시 백테스트 속도 저하

**(c) 실험 체크리스트**

```yaml
EXP-P3-A: mdd_pipeline_debug
  - 정의: MDD 계산 실패 지점 특정
  - 실행:
    □ python3 tools/mdd_debugger.py --champion champion_latest.json
    □ equity curve 존재 여부, NaN 비율 체크
  - 게이트: 실패 원인 명확화
  - 기대 관측치: "equity curve missing" 또는 "division by zero at fold X"

EXP-P3-B: mdd_fallback_calculation
  - 정의: 독립적 MDD 계산 스크립트로 검증
  - 실행:
    □ daily_returns.csv에서 직접 rolling MDD 계산
    □ 결과를 champion.json에 수동 패치
  - 게이트: MDD 값 산출 (예상 범위: -15% ~ -35%)
  - 기대 관측치: MDD > -20% → 양호, MDD < -40% → 전략 재검토
```

**PASS 조건**: worst_mdd 값 산출 AND -40% < MDD < -10%

### **P4. Rebalance 비용 데이터 복구 및 검증**

**(a) 왜 필요한지**
- rebalance.csv 로드 실패 → 거래비용 미반영
- 실제 운영 시 연 1~3% 비용 누락 가능

**(b) 위험/부작용**
- 비용 모델이 과도하면 전략 자체가 무효화
- 슬리피지 가정에 따라 결과 크게 변동

**(c) 실험 체크리스트**

```yaml
EXP-P4-A: rebalance_data_recovery
  - 정의: 누락된 rebalance 데이터 재생성
  - 실행:
    □ 백테스트 재실행 with --export-rebalance
    □ rebalance.csv 또는 .jsonl 생성 확인
  - 게이트: 파일 생성 + row count > 100
  - 기대 관측치: 연간 turnover 200~400%

EXP-P4-B: cost_sensitivity_test
  - 정의: 거래비용 0bp / 5bp / 10bp / 20bp 시나리오
  - 실행:
    □ --cost-bps 0,5,10,20 각각 실행
    □ OOS mean 변화 기록
  - 게이트: 10bp에서 OOS > 2.0
  - 기대 관측치:
    - 0bp: 3.32 (현재)
    - 10bp: 2.8~3.0
    - 20bp: 2.3~2.7
```

**PASS 조건**: rebalance 데이터 복구 AND 10bp 비용 시 OOS > 2.0

### **P5. Hash/재현성 인프라 복구**

**(a) 왜 필요한지**
- lane_hash, run_hash = None → 어떤 코드/데이터로 생성됐는지 추적 불가
- 실험 비교, 롤백 불가능

**(b) 위험/부작용**
- 인프라 작업 = 직접 성능 개선 아님
- 과투자 시 본질 분석 지연

**(c) 실험 체크리스트**

```yaml
EXP-P5-A: hash_injection_fix
  - 정의: 백테스트 출력에 자동 hash 삽입
  - 실행:
    □ git rev-parse HEAD → lane_hash
    □ md5(config.yaml) → run_hash
    □ champion.json 스키마에 필수 필드 추가
  - 게이트: 다음 실행 시 hash 값 존재
  - 기대 관측치: lane_hash = 40char hex, run_hash = 32char hex

EXP-P5-B: artifact_lineage_check
  - 정의: 현재 champion의 생성 경로 역추적
  - 실행:
    □ artifacts/ 폴더에서 timestamp 기반 매칭
    □ autopilot_20260102_084021 로그 분석
  - 게이트: champion 생성 실험 특정
  - 기대 관측치: "exp_fsa_only_scale_090_hedge_025" 확인
```

**PASS 조건**: 모든 신규 실행에 hash 자동 기록
