## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — “명령형 체크리스트”
우선순위는 **누수 → 과최적화 → 서바이버십 → 비용 미반영 → 운영 리스크** 순으로 배치. (미국주식 only, Tech+Healthcare 중심, 8~14종목, ETF는 관측지표만)

---

# TOP1) **누수(lookahead/label leakage) 0화 + 검증 게이트를 파이프라인에 강제 삽입**
### (a) 왜 필요한지
- 최근 PASS 후보가 lockbox에서 매우 좋음(특히 min이 양수) → **진짜 개선일 수도 있지만**, 누수가 섞이면 가장 그럴듯한 “가짜 개선”이 됨.
- 48시간 자동 루프에서 “한 번 새면 계속 새는” 구조가 되기 쉬워서, **실험 전에 자동 차단 게이트**가 필요.

### (b) 위험/부작용
- 누수 차단 후 성능 하락 가능(정상).
- 데이터 정렬/지연(shift) 수정이 들어가면 신호 타이밍이 바뀌어 회전율/비용이 변함.

### (c) 최소 실험 2~3개 (각 실험은 48시간 루프 형태로)
**실험 1: Purge/Embargo Walk-Forward 게이트 추가**
- (1) 실험 정의: 학습/검증 분할에 **purge window + embargo**를 넣어 동일 이벤트/인접 구간 누수를 차단.
- (2) 게이트:  
  - “purge/embargo 미적용 실험 결과”가 아무리 좋아도 **채택 금지**  
  - tuning_mean 상승이 아니라도, lockbox_mean/min의 과장 개선이 사라지는지 확인
- (3) 기대 관측치:  
  - tuning 성능은 내려가도 괜찮음  
  - lockbox_mean/min이 **급락**하면 기존 개선은 누수 가능성↑

**실험 2: Feature Timestamp Assert(시점 단언) 자동 테스트**
- (1) 실험 정의: 각 feature에 “사용 가능한 timestamp”를 기록하고, 리밸런스 시점에 미래 timestamp 접근 시 바로 실패.
- (2) 게이트: timestamp assert 위반 시 실험 전체 FAIL.
- (3) 기대 관측치: 일부 feature/리포트가 즉시 깨지며 누수 지점을 좁힘.

**실험 3: 라벨/목표 정의 재검증(특히 close-to-close vs next open)**
- (1) 실험 정의: 목표수익을 `t+1 open` 또는 `t+1 VWAP` 기준으로 재정의(실행가능성 반영)하고 동일 feature로 재학습.
- (2) 게이트: “close 체결 가정” 결과는 리더보드에서 제외(참고만).
- (3) 기대 관측치: 성능이 다소 내려가도 **lockbox min이 과도하게 흔들리지 않으면** 진짜 신호 가능성↑

### (d) PASS 조건(추천)
- 누수 게이트 통과(Assert 0건) + purge/embargo 적용 후에도  
  - `lockbox_mean`이 챔피언 대비 **동일 이상**(≥ 1.33) 유지 또는  
  - `lockbox_min`이 **음수로 급전환하지 않음**(예: ≥ -0.10)  
- worst_mdd가 현재 수준(≈ -0.09)보다 악화되지 않을 것

# TOP2) **비용/슬리피지/실행지연(운영 가능한 체결) 모델을 “강제”로 통합**
### (a) 왜 필요한지
- Tech+Healthcare 8~14종목 전략은 집중도가 높아 **턴오버/슬리피지**가 성과를 좌우.
- 비용 미반영은 “락박스가 좋게 보이는” 대표 원인.

### (b) 위험/부작용
- 성능 하락(정상). 다만 **실거래 가능 전략만 남게 됨**.
- 비용 모델이 과보수적이면 신호가 죽을 수 있음.

### (c) 최소 실험 2~3개
**실험 1: 1-bar execution lag 강제(신호 생성 t, 체결 t+1)**
- (1) 실험 정의: 리밸런스 결정 후 다음 바에서만 체결되도록 고정.
- (2) 게이트: lag 없는 결과는 채택 금지.
- (3) 기대 관측치: 성능 감소 폭이 제한적이면 신호가 견고.

**실험 2: 슬리피지 = f(ADV, 변동성, 스프레드 proxy)**
- (1) 실험 정의: 종목별 ADV/일중변동성 기반 슬리피지(예: bps) 적용 + 고정 수수료.
- (2) 게이트: 비용 반영 후에도 `lockbox_mean`이 기준선의 X% 이상 유지(예: ≥ 80%).
- (3) 기대 관측치: 턴오버가 높은 설정이 자연스럽게 밀려남.

**실험 3: Turnover cap + 거래 최소단위(리밸런스 완화)**
- (1) 실험 정의: 일/주간 turnover 상한(예: 30~60%) + 너무 작은 비중 변화는 무시.
- (2) 게이트: turnover cap 위반 시 FAIL.
- (3) 기대 관측치: 비용 후 성과가 안정화(특히 lockbox_min 개선 기대).

### (d) PASS 조건
- 비용+lag 포함 성과로 리더보드 재정렬 시에도 상위 유지  
- `lockbox_min` 악화가 제한적(예: ≥ -0.10) + worst_mdd 악화 제한(예: ≥ -0.10)

# TOP3) **서바이버십/포인트-인-타임(PIT) 데이터 가드레일 + 상장폐지 처리**
### (a) 왜 필요한지
- 미국주식 백테스트에서 서바이버십(현재 생존 종목만) + PIT 미적용은 **가장 흔한 구조적 과대평가**.
- Tech/Healthcare는 M&A/상장폐지/티커 변경 이벤트가 상대적으로 잦아 왜곡 가능.

### (b) 위험/부작용
- 데이터 소스/전처리 변경으로 과거 성능 급락 가능(정상).
- 유니버스가 줄면 신호 공간 축소.

### (c) 최소 실험 2~3개
**실험 1: “유니버스 스냅샷(일자별 상장 가능 종목)” 강제**
- (1) 실험 정의: 각 거래일에 거래 가능했던 종목만 후보에 포함(거래정지/상폐/티커 변경 반영).
- (2) 게이트: 유니버스 생성이 “현재 시점 종목 목록”을 참조하면 FAIL.
- (3) 기대 관측치: 성과가 다소 낮아져도 분포가 더 현실적.

**실험 2: PIT Fundamentals/Estimates 사용 여부 점검 + 지연 적용**
- (1) 실험 정의: 실적/가이던스/추정치 기반 feature는 공시 지연(예: 1~5영업일) 강제.
- (2) 게이트: 공시일 이후에만 값이 등장하도록 assert.
- (3) 기대 관측치: 누수성 alpha가 사라지고 재현성↑.

**실험 3: Delisting return/마지막 거래 처리**
- (1) 실험 정의: 상폐 종목 보유 시 상폐수익(또는 합리적 패널티) 반영.
- (2) 게이트: 상폐 발생 시 “0으로 소거” 처리 금지.
- (3) 기대 관측치: tail risk가 현실화되어 MDD/최저치가 보수적으로 변함.

### (d) PASS 조건
- PIT/서바이버십 가드 통과 후에도 전략이 “완전히 붕괴”하지 않을 것  
  - 예: lockbox_mean이 챔피언의 70~90% 범위라도 **일관성**이 있으면 PASS 후보 유지
- 상폐 이벤트 포함 후 worst_mdd가 비정상적으로 커지지 않을 것(구조적 취약성 제거)

# TOP4) **과최적화(모듈 조합/하이퍼파라미터) 억제: “단순성 우선” 선택 규칙 추가**
### (a) 왜 필요한지
- 현재 PASS 후보가 좋을수록, 다음 자동 루프에서 조합 탐색이 커지면 **과최적화로 되돌아가기 쉬움**.
- 48시간 루프는 “조금씩 좋아 보이는 복잡도”가 누적되는 구조적 위험이 큼.

### (b) 위험/부작용
- 단기적으로 최고 성능 후보를 버릴 수 있음.
- 너무 강하게 걸면 혁신적인 개선을 막음.

### (c) 최소 실험 2~3개
**실험 1: 선택 기준을 “lockbox 최저치 + MDD 우선”으로 변경**
- (1) 실험 정의: 평균보다 `lockbox_min`, `worst_mdd` 가중치를 높인 스코어로 --select-best.
- (2) 게이트: 평균만 좋은 후보(분산 큼)는 자동 탈락.
- (3) 기대 관측치: 꾸준한 후보가 챔피언/차기 챔피언이 됨.

**실험 2: 파라미터 자유도 패널티(Occam penalty)**
- (1) 실험 정의: 파라미터 수/모듈 수 증가 시 스코어에서 패널티.
- (2) 게이트: 복잡도 상한 초과 시 실험 자체 FAIL.
- (3) 기대 관측치: 성능이 약간 낮아도 재현성↑.

**실험 3: Seed/기간 교란 안정성 테스트(미니)**
- (1) 실험 정의: 학습 seed 3개 + 시작일/종료일 소폭 이동으로 성능 분산 측정.
- (2) 게이트: 분산이 기준 이상이면 FAIL(“우연 적합”).
- (3) 기대 관측치: 진짜 신호는 분산이 상대적으로 작음.

### (d) PASS 조건
- lockbox_mean이 최고가 아니어도,  
  - `lockbox_min` 개선(또는 유지) + `worst_mdd` 악화 없음 + 복잡도 제한 충족

# TOP5) **운영 리스크(집중/유동성/체결/리밸런스 규율) 게이트를 전략 레이어에 내장**
### (a) 왜 필요한지
- 8~14종목 집중 포트는 “한 종목 이벤트/갭”에 취약.  
- 실전에서는 유동성/스프레드/서킷/거래정지/급등락이 백테스트보다 더 빈번.

### (b) 위험/부작용
- 제약이 늘어 수익 기회가 감소 가능.
- 제약 설계가 잘못되면 포트가 “계속 현금”이 될 수 있음.

### (c) 최소 실험 2~3개
**실험 1: 유동성 게이트(ADV/가격/스프레드 proxy)로 유니버스 컷**
- (1) 실험 정의: ADV 하한, 가격 하한, 변동성/스프레드 proxy 상한을 만족하는 종목만 매수.
- (2) 게이트: 보유 종목이 조건 이탈 시 다음 리밸런스에서 강제 축소.
- (3) 기대 관측치: 극단 tail 손실 감소, turnover 안정.

**실험 2: 종목당 최대 비중 + 섹터(Tech/Healthcare) 범위 강제**
- (1) 실험 정의: 단일 종목 max weight(예: 12~18%) + Tech/Healthcare 합 70~100% 범위.
- (2) 게이트: 위반 시 포트 구성 단계에서 재정규화.
- (3) 기대 관측치: MDD/최저치 개선, 평균은 소폭 감소 가능.

**실험 3: 리밸런스 실패/데이터 결측 시 안전 동작(failsafe)**
- (1) 실험 정의: 가격 결측/체결 불가 시 “유지/축소/현금화” 정책을 명시하고 백테스트에 동일 반영.
- (2) 게이트: 결측 발생 시 조용히 스킵하는 코드 경로 금지(assert).
- (3) 기대 관측치: 운영 이벤트에서 성능이 급왜곡되는 현상 제거.

### (d) PASS 조건
- 제약 적용 후에도 **항상 8~14종목 유지**(현금 비중이 과도해지지 않음)  
- worst_mdd, lockbox_min이 개선되거나 최소한 악화하지 않음

## “성능이 안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래는 **질문 없이 바로 넣을 수 있는 진단 분해 트리**(로그/리포트 지표로 남기기).

### 1) Trigger(신호가 나오는가?)
- **Signal sparsity**: 리밸런스 시점에 상위 랭크 점수가 거의 동일/0 근처인지 로그로 기록
- **Feature drift**: 최근 구간에서 feature 분포(평균/표준편차)가 학습구간 대비 붕괴했는지 체크
- **Label alignment**: 예측 대상 수익률 정의가 바뀌며 상관이 깨졌는지(IC, rankIC 추적)

### 2) Apply(적용이 실제 주문으로 변환되는가?)
- **게이트/제약 과다**: 유동성/섹터/비중/턴오버 캡 때문에 “결정은 했지만 주문이 0” 되는 비율 기록
- **재정규화 누락**: 제약 후 weight 합이 1이 아닌 케이스/NaN 발생 케이스 assert

### 3) Exposure(노출이 원하는 베타/팩터로 나가나?)
- **섹터/스타일 노출**: Tech/Healthcare 내에서도 Mega-cap 편향, 단일 팩터(모멘텀/퀄리티) 쏠림을 주간 리포트
- **상관 구조**: 8~14종목이면 종목 간 상관 급등 시 사실상 2~3개 포지션과 동일 → 유효 분산 수(Effective N) 기록

### 4) Cost(비용이 수익을 먹는가?)
- **Turnover attribution**: 총 수익을 “그로스 알파 / 비용 / 슬리피지”로 분해
- **체결 지연 민감도**: lag 0 vs lag 1 비교로 “실행 가능 알파”만 분리

### 5) Regime(레짐 변화로 신호가 죽었나?)
- **변동성 레짐**: VIX(관측 ETF/지표만 사용 가능) 또는 시장 변동성 지표로 구간 나누고 구간별 성과 테이블
- **금리/헬스케어 이벤트**: 금리 급변 구간에서 성장주/바이오가 동시에 흔들리는지(관측지표로만 분류)

## 바로 실행 순서(48시간 자동 루프에 맞춘 최소 운영)
1) **TOP1 누수 게이트부터 코드에 “실패 시 중단”으로 박아라.**  
2) **TOP2 비용+lag를 기본값으로 승격하고, 비용 없는 결과는 리더보드에서 제외하라.**  
3) **TOP3 PIT/서바이버십 체크를 통과하지 못하면 어떤 후보도 챔피언 승격 금지하라.**  
4) **TOP4 선택 규칙을 평균 중심 → 최저치/MDD/복잡도 패널티 중심으로 바꿔라.**  
5) **TOP5 운영 제약(유동성/비중/결측 failsafe)을 포트 생성 단계의 필수 게이트로 넣어라.**

원하면(질문은 하지 않음), 위 5개를 `aub_autopilot.py / system_autopilot.py` 흐름에 끼워 넣는 형태로 **게이트 항목(FAIL 조건) 템플릿**을 다음 메시지에 “체크리스트+의사코드”로 정리해 줄 수 있음.
