## 0. 현황 진단 요약

| 항목 | 상태 | 판정 |
|------|------|------|
| **Degenerate Folds** | 4/10 (Fold 1,2,3,8) | 🔴 CRITICAL — 40% fold 실패 |
| **OOS Mean** | 3.32 (handoff) vs 2.63 (diagnosis) | 🟡 불일치 — 측정 기준 확인 필요 |
| **Worst MDD** | None | 🔴 미측정 — 리스크 게이트 무력화 |
| **Rebalance Log** | 파일 미존재/파싱 실패 | 🔴 비용 검증 불가 |
| **Exposure** | 0.0 ~ 0.84 | 🟡 0-exposure 구간 존재 |

**핵심 누수점**: Degenerate fold 다수 + MDD 미측정 + 거래비용 로그 부재 → **백테스트 신뢰도 자체가 의심됨**

## 1. 우선순위 TOP-5 실행 패치

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### P1. Degenerate Fold 원인 분해 및 수정
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- 4/10 fold가 degenerate = OOS 평가 표본 60%만 유효
- 생존편향: "작동하는 fold만" 평균내면 과최적화

**(b) 위험/부작용**
- 수정 시 OOS mean 급락 가능 (실제 성능 드러남)
- Fold 정의 변경 시 과거 실험과 비교 불가

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P1-A | Fold 1,2,3,8 구간 데이터 덤프 → 종목수/거래일수/시그널 유효율 확인 | 각 fold ≥ 50 거래일, ≥ 5 종목 | degenerate 원인 특정 |
| P1-B | `min_samples_per_fold=50` 파라미터 추가, 미달 fold 제외 후 재계산 | 유효 fold ≥ 6/10 | OOS mean 재산출 |
| P1-C | Purged K-Fold gap을 30일→15일로 축소 (데이터 활용↑) | degenerate fold ≤ 2 | fold별 샘플수 균등화 |

**(d) PASS 조건**
```
✅ degenerate_folds ≤ 2 AND 전체 fold OOS 분산 < 1.5
```

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### P2. MDD 측정 파이프라인 복구
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- `worst_mdd: None` = 리스크 게이트가 작동 안 함
- MDD 없이 Sharpe만 보면 tail risk 무시

**(b) 위험/부작용**
- MDD 계산 추가 시 루프 시간 증가 (≈ +10%)
- 과거 champion 비교 시 기준 불일치

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P2-A | `backtest_engine.py`에 rolling MDD 계산 추가, JSON 출력 | MDD 필드 non-null | worst_mdd 값 확인 |
| P2-B | MDD > 25% 시 자동 FAIL 플래그 추가 | champion MDD ≤ 25% | 위험 실험 자동 제거 |

**(d) PASS 조건**
```
✅ worst_mdd 필드 존재 AND worst_mdd ≤ 0.25
```

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### P3. Rebalance 로그 파이프라인 수리
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- 파일 미존재 + JSON 파싱 실패 = 거래비용 검증 불가
- 슬리피지/수수료 미반영 시 OOS mean 30-50% 과대추정 가능

**(b) 위험/부작용**
- 로그 포맷 변경 시 기존 분석 스크립트 호환성 문제

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P3-A | `run_champion_v5` 실행 후 `rebalance.jsonl` 생성 확인 | 파일 존재 & 파싱 성공 | 거래 횟수, 평균 turnover |
| P3-B | 비용 10bps/20bps/30bps 시뮬레이션 후 OOS mean 재계산 | OOS mean 변화율 기록 | 비용 민감도 파악 |

**(d) PASS 조건**
```
✅ rebalance.jsonl 파싱 성공 AND 비용 반영 후 OOS mean ≥ 1.5
```

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### P4. Exposure 0-구간 원인 분석
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- `exposure_min: 0.0` = 특정 구간 100% 현금
- 의도된 헷지인지, 시그널 버그인지 불명확

**(b) 위험/부작용**
- 강제 최소 노출 시 나쁜 시장에서 손실 증가

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P4-A | exposure=0 발생 일자 추출 → 해당 일 시그널/유니버스 덤프 | 원인 분류 (no signal / filter 과잉 / 버그) | 0-exposure 일수 |
| P4-B | `min_exposure=0.2` 강제 후 OOS 재측정 | OOS mean 변화 ≤ 15% | 노출 하한 효과 |

**(d) PASS 조건**
```
✅ 0-exposure 원인 특정 AND (버그 시 수정 / 의도 시 문서화)
```

### P5. OOS Mean 불일치 조사 (3.32 vs 2.63)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(b) 위험/부작용**
- 기준 통일 시 과거 모든 실험 재평가 필요

**(c) 최소 실험**

## 2. 성능 미변동 원인 분해 트리

```
OOS Mean 변화 없음
│
├─[1] 트리거 미작동
│   ├─ 시그널이 threshold 미달 → 진입 안 함
│   └─ 검증: 일별 signal count 히스토그램
│
├─[2] 적용 오류
│   ├─ 코드 변경이 실제 백테스트에 반영 안 됨
│   └─ 검증: config hash 비교, dry-run 로그
│
├─[3] 노출 상쇄
│   ├─ Long/Short 동시 진입 → net exposure ≈ 0
│   └─ 검증: gross vs net exposure 비교
│
├─[4] 비용 상쇄
│   ├─ alpha < transaction cost → 실질 수익 0
│   └─ 검증: turnover × cost vs gross return
│
└─[5] 레짐 불일치
    ├─ 실험 기간이 특정 레짐에 편중
    └─ 검증: 연도별/분기별 OOS 분해
```

## 3. 48h 자동 루프 실행 순서

```bash
# ===== HOUR 0-8: 인프라 수리 =====
□ P3-A: rebalance.jsonl 생성 확인
□ P2-A: MDD 계산 파이프라인 추가
□ P5-A: OOS 계산 로직 diff

# ===== HOUR 8-24: 데이터 무결성 =====
□ P1-A: Degenerate fold 원인 덤프
□ P4-A: Exposure=0 일자 추출
□ P5-B: OOS 재현성 테스트

# ===== HOUR 24-40: 수정 적용 =====
□ P1-B: min_samples_per_fold 적용
□ P2-B: MDD 게이트 추가
□ P3-B: 비용 민감도 분석

# ===== HOUR 40-48: 검증 =====
□ P1-C: Purged gap 축소 실험
□ P4-B: min_exposure 실험
□ 전체 PASS 조건 체크 → 다음 사이클 핸드오프
```
