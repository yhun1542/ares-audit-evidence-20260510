## 24~48시간 TOP5 우선순위(명령형 체크리스트)

### 1) **누수/서바이버십/코퍼레이트액션 무결성부터 “차단”**
- **왜 필요한지**
  - OOS가 “조금씩만” 움직이거나, 챔피언이 교체돼도 분포가 비슷하면 **미세 누수(특히 타임스탬프/조정주가/편입종목)** 또는 **서바이버십(상폐/합병 누락)** 이 가장 흔한 원인.
  - Tech+Healthcare 8~14 종목 고정/준고정이면, **과거 특정 승자만 남는 편향**이 수익률을 “보기 좋게 고정”시키는 경향이 큼.
- **위험/부작용**
  - 진짜 알파가 사라진 것처럼 보이며 성능 급락 가능(정상).
  - 데이터 소스/조정방식 변경으로 과거 실험과 직접 비교가 어려워질 수 있음(메타데이터로 해결).
- **연결 실험(아래 공통 실험 ID 참조, 2~3개)**
  - **E1(데이터 누수/서바이버십 스모크 테스트)**
  - **E3(시간분할 Purge/Embargo + degenerate fold 제거)**
- **PASS 조건**
  - (필수) **미래정보 차단 테스트에서 성능이 “의도대로” 붕괴**하고, 정상 파이프에서는 OOS가 재현됨.
  - (필수) **상폐/합병/티커변경 이벤트 포함 여부가 로그로 증명**되고, “조정주가/배당/스플릿” 기준이 단일화됨.

---

### 2) **비용/체결/회전율 모델을 먼저 “하드닝” (비용 미반영 최우선 차단)**
- **왜 필요한지**
  - OOS mean이 양호해도 **턴오버/슬리피지/스프레드**가 실제를 먹으면 “성능이 안 움직이는” 게 아니라 **실제로는 이미 0 근처**일 수 있음.
  - 특히 8~14개 집중 포트폴리오에서 리밸런스가 잦으면 비용 민감도가 매우 큼.
- **위험/부작용**
  - 백테스트 성능 급락(정상).
  - 과도한 비용 가정으로 알파를 과소평가할 수 있음(민감도 실험으로 제어).
- **연결 실험(2~3개)**
  - **E2(비용 민감도 그리드 + 턴오버 캡)**
  - **E5(노출 게이트/변동성 타게팅으로 거래 빈도 감소)**
- **PASS 조건**
  - (필수) **비용 2배/0.5배 민감도**에서 성능이 단조롭게 반응(모델이 “비용에 무감각”하면 체결/거래가 백테스트에 제대로 반영 안 된 신호).
  - (권장) 비용 반영 후에도 **OOS mean이 0 이상 유지 + 최악구간 손실이 비용 미반영 대비 과도하게 악화되지 않음**.

---

### 3) **과최적화/폴드 퇴행(degenerate_folds) 즉시 수리 (검증 구조를 바꾸지 않으면 어떤 실험도 의미 없음)**
- **왜 필요한지**
  - 현재 `degenerate_folds: [1,2,3,8]`는 **검증셋/훈련셋이 사실상 비정상(표본 부족/결측/동일구간 중복)** 가능성이 큼.
  - degenerate가 있으면 OOS mean이 “정지”하거나 랜덤하게 변동하며, 챔피언 비교가 무의미해짐.
- **위험/부작용**
  - 기존 챔피언의 성능이 “재평가”되며 랭킹이 바뀜.
- **연결 실험(2~3개)**
  - **E3(워크포워드 + Purge/Embargo + 최소 표본 게이트)**
  - **E4(실험 메타데이터/재현성/로그 수리: run_hash/lane_hash/worst_mdd)**  
- **PASS 조건**
  - (필수) **degenerate_folds=0**.
  - (필수) 동일 코드/시드로 **OOS 통계 재현**(run_hash 단위로 동일 결과).

---

### 4) **운영 리스크: 리밸런스/로그 파이프라인 복구 (지금은 “고장난 계기판” 상태)**
- **왜 필요한지**
  - `aub_rebalance_pinpoint`가 base-log/cand-log 모두 로딩 실패 → **리밸런스 원인 분석 불가**.
  - `worst_mdd: None`, `lane_hash/run_hash: None` → **실험 추적/비교/재현 불가**(운영 리스크 최상위).
- **위험/부작용**
  - 로그 포맷 변경 시 이전 리포트 도구가 깨질 수 있음(버전 필드로 해결).
- **연결 실험(2~3개)**
  - **E4(로그/메타데이터/리밸런스 이벤트 JSONL 표준화 + 도구 자동 탐지)**
  - **E2(비용/체결 로그에 turnover/slippage 항목 강제 기록)**  
- **PASS 조건**
  - (필수) `rebalance_pinpoint`가 **base/cand 모두**에서 리밸런스 이벤트를 읽고, “차이 상위 N건”이 출력됨.
  - (필수) 모든 런에서 **run_hash/lane_hash/worst_mdd**가 채워지고, 리포트에서 링크 가능.

---

### 5) **전략 제약 준수(미국주식 only, Tech+Healthcare, 8~14, ETF 매매 제외) + 노출(Exposure) 게이트를 “명시적”으로**
- **왜 필요한지**
  - 현재 exposure max가 0.838…이고 min 0 → 신호 약할 때 현금 비중이 큰 구조로 보이는데, 이게 의도인지/버그인지 불명확.  
  - ETF는 “관측지표로만” 써야 하는데, 실험명에 hedge가 존재 → **ETF 거래/헤지 혼입 위험**을 즉시 차단해야 함.
- **위험/부작용**
  - 헤지 제거 시 변동성/드로우다운 악화 가능(대신 노출 타게팅으로 완화).
  - 종목 수 제한으로 기회가 줄어 OOS mean 하락 가능.
- **연결 실험(2~3개)**
  - **E5(유니버스/포지션 수/섹터 제약 + 노출 게이트 + ETF “읽기전용” 강제)**
  - **E2(거래비용 포함 시, 노출 게이트가 turnover를 줄이는지 확인)**  
- **PASS 조건**
  - (필수) 실제 주문/포지션 로그에서 **ETF 거래 0건**.
  - (필수) 포트폴리오가 매 리밸런스마다 **8~14개 종목** 유지(예외는 데이터 결측/거래정지 등만 허용, 로그에 사유 기록).
  - (권장) 노출 타게팅 후 **턴오버 감소** + 비용 반영 성능 유지.

## 공통 “실행 가능한 Patch/실험” 5개 (48시간 자동 루프 형태)

아래 5개만 **유니크 실험**으로 돌리고, 위 TOP5는 이 실험들을 재사용해서 검증하세요(케이스 폭발 방지).

---

### **E1) 데이터 누수/서바이버십 스모크 테스트 (Patch + 실험)**
1) **실험 정의**
   - (Patch) 피처 생성 시점/라벨 시점 강제 검증: 모든 feature에 `asof_timestamp`를 붙이고, 학습에서 `feature_time <= decision_time` 불만족 샘플 제거.
   - (실험) “미래 참조” 탐지:
     - (a) 라벨을 +k일 시프트했을 때 성능이 비정상적으로 유지되는지
     - (b) 의도적으로 feature를 -1bar 지연/선행시켜 성능 반응이 정상인지
   - (Patch) 상폐/합병/티커변경/스플릿/배당 처리 파이프라인에 “이벤트 존재 여부”를 메타로 기록.
2) **게이트(실패 시 즉시 중단)**
   - 미래참조 위반 샘플이 전체의 일정 비율(예: 0.1%+)이면 FAIL.
   - 상폐/코퍼레이트액션 이벤트가 존재하는데도 “처리 0건”이면 FAIL.
3) **기대 관측치**
   - 미래 시프트/선행에서 성능이 **의도대로 붕괴**(정상).
   - 정상 세팅에서만 OOS가 살아남고, 분해 지표(종목별 기여/기간별 기여)가 현실적으로 변함.

---

### **E2) 비용/체결 민감도 그리드 + 턴오버 캡 (실험)**
1) **실험 정의**
   - (Patch) 비용 모델을 “고정 스프레드 + 슬리피지(bps) + 수수료”로 단순 표준화하고, 모든 리밸런스에 `turnover`, `est_cost`, `net_pnl`를 기록.
   - (실험) 비용 파라미터를 0.5x/1x/2x로 스윕 + 턴오버 상한(예: 일/주 기준) 도입 비교.
2) **게이트**
   - 비용을 2x로 올렸는데 net 성능이 거의 변하지 않으면(민감도 0) → 비용이 적용 안 된 것으로 간주 FAIL.
3) **기대 관측치**
   - 비용↑ → OOS mean↓, turnover↑일수록 하락폭↑ (단조 반응).
   - 턴오버 캡이 비용을 줄이며 net 성능이 상대적으로 개선.

---

### **E3) 워크포워드 CV 재설계 (Purge/Embargo + 표본 게이트)**
1) **실험 정의**
   - (Patch) 시간분할을 purge/embargo 포함 워크포워드로 변경.
   - (Patch) 각 fold에 최소 샘플/거래일/리밸런스 횟수 기준을 두고, 미달 fold는 생성 자체를 막음.
2) **게이트**
   - `degenerate_folds != 0`이면 FAIL.
   - fold별 거래일/리밸런스 수가 최소 기준 미달이면 FAIL.
3) **기대 관측치**
   - OOS 분산이 커질 수 있으나(정상), fold별 성능/노출이 “설명 가능”해지고 챔피언 교체가 의미를 갖게 됨.

---

### **E4) 리밸런스/메타데이터 로깅 표준화 + 도구 자동탐지 (운영 Patch)**
1) **실험 정의**
   - (Patch) 모든 런에서 아래를 강제 기록:
     - `run_hash`, `lane_hash`, git commit, 데이터 스냅샷 ID
     - `worst_mdd` 계산 및 저장
     - 리밸런스 이벤트를 **JSONL 단일 포맷**으로 저장(기존 CSV/JSON 혼재 제거)
   - (Patch) `aub_rebalance_pinpoint`가 입력을 자동탐지(파일 경로가 CSV/JSONL/JSON 어떤 형태든)하도록 수정.
2) **게이트**
   - 리포트 생성 단계에서 위 메타가 하나라도 None이면 FAIL.
   - pinpoint 도구가 base/cand를 둘 다 못 읽으면 FAIL.
3) **기대 관측치**
   - “왜 리밸런스가 달라졌는지(신호/가격/비용/제약)”가 상위 N건으로 출력되어, 다음 전략 실험의 원인-결과 연결이 가능해짐.

---

### **E5) 유니버스/포지션 수/ETF 매매 금지 + 노출 게이트(변동성 타게팅)**
1) **실험 정의**
   - (Patch) 트레이딩 유니버스 강제: 미국 상장, 섹터 Tech+Healthcare, 보유 종목 수 8~14, 단일 종목 상한, 현금 허용.
   - (Patch) ETF는 **관측 전용**: 주문 라우팅에서 ETF 티커는 reject(하드 차단).
   - (실험) 노출 게이트:
     - (a) 신호 약할 때 현금 비중 확대 기준
     - (b) realized vol 타게팅으로 gross exposure를 자동 조절
2) **게이트**
   - 주문/체결 로그에서 ETF 거래가 1건이라도 나오면 FAIL.
   - 보유 종목 수가 8~14 범위를 반복적으로 벗어나면 FAIL(예외 사유 로그 없으면 즉시 FAIL).
3) **기대 관측치**
   - exposure가 구간별 레짐에 따라 합리적으로 변하고, turnover가 감소하며 비용 반영 성능이 안정화.

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)

아래는 **질문 없이 바로 추가 로그/리포트로 쪼개는** 트리거 트리입니다.

### A) Trigger(신호 발생) 문제
- **증상**: 리밸런스 빈도/종목 교체가 거의 없음, 또는 항상 비슷한 종목.
- **조치**
  - 신호 분포(평균/분산/꼬리), 상위 랭크 종목의 점유율, “신호가 0 근처로 눌리는 날 비율”을 일별로 로그.
  - 신호-수익 상관(동일일/1일후/5일후) heatmap을 레짐별로 출력.

### B) Apply(제약/정규화/클리핑)에서 알파가 소실
- **증상**: raw 신호는 변하는데 포지션이 비슷하거나, 포지션이 지나치게 작음.
- **조치**
  - `raw_signal -> normalized -> clipped -> target_weight -> executed_weight` 단계별로 상관/분산을 기록.
  - 각 단계에서 “정보량 감소율(분산 감소, 순위 상관)”을 지표화.

### C) Exposure(노출) 구조 문제
- **증상**: exposure min=0이 자주 발생(현금 과다), 혹은 max가 항상 상한에 붙음(리스크 과다).
- **조치**
  - gross/net exposure, sector exposure, single-name concentration, vol contribution을 리밸런스마다 저장.
  - exposure와 성과의 조건부 관계(고노출/저노출 구간별 성과)를 분해.

### D) Cost(비용) 누락/과소/적용 지점 오류
- **증상**: 비용 파라미터를 바꿔도 성과가 거의 동일, 또는 turnover가 높아도 성과가 과도하게 좋음.
- **조치**
  - 리밸런스마다 `turnover`, `est_spread_cost`, `est_slippage`, `fee`, `net`를 반드시 저장(E2).
  - “체결가격 vs 기준가격(종가/시가/VWAP)” 차이를 모델링하고, 성과가 어떤 기준가격에 민감한지 비교.

### E) Regime(시장 레짐) 편향/착시
- **증상**: 특정 기간만 기여(예: 2020~2021)하고 최근/다른 구간에서 0에 수렴.
- **조치(ETF는 관측지표로만)**
  - QQQ(Tech), XLV(Healthcare), VIX proxy 등을 **레짐 라벨**로만 사용해 구간별 성과/노출을 조건부로 리포트.
  - 레짐별로 “신호 유효성(정보계수/승률/손익비)” 테이블 생성.

---

### 실행 순서(48시간 내)
1) **E4 먼저 적용**(로그/메타/리밸런스 도구 복구 없으면 이후 실험 해석 불가)  
2) **E3로 degenerate_folds 제거**(검증구조 정상화)  
3) **E1로 누수/서바이버십 차단 확인**
