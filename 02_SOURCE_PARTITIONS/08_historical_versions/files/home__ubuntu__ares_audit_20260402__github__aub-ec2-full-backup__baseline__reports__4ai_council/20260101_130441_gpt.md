## 다음 24~48시간 TOP5 우선순위(명령형 체크리스트)

### 1) 누수(lookahead) + corporate action 정합성 최우선 감사
- **해야 할 일**
  - 모든 feature/label을 `asof_timestamp` 기준으로 강제 정렬(거래 의사결정 시점 이전 데이터만 허용)하라.
  - split/dividend/earnings timestamp(발표 시각) 처리 방식을 “실거래 가능 시점” 기준으로 통일하라.
  - 학습/검증/락박스에 동일한 “데이터 가용성 규칙”을 적용하라(한 구간만 느슨하면 누수 재발).
- **(a) 왜 필요한지**
  - 지금처럼 lockbox가 잘 나오고 MDD가 낮을수록, “미세 누수”가 있으면 성능이 부자연스럽게 고정/과대평가되기 쉽다.
  - Tech/Healthcare는 earnings·guidance 이벤트가 많아 timestamp 누수 빈도가 높다.
- **(b) 위험/부작용**
  - 누수 제거 후 tuning/lockbox 평균이 단기적으로 하락할 수 있다(정상).
  - 데이터 가용성 제한으로 트레이드 수가 감소할 수 있다.
- **(c) 최소 실험(아래 Experiment E1로 통합)**
  - (E1-1) feature 1-bar/1-day 강제 시프트 후 성능 붕괴 여부 확인
  - (E1-2) earnings 변수를 “발표 다음 거래일 반영”으로 강제 후 재평가
  - (E1-3) adjusted/unadjusted price 혼용 여부 탐지 및 단일화
- **(d) PASS 조건**
  - 누수 방지 패치 적용 후에도 **lockbox_mean이 챔피언 대비 -0.5%p 이내**로 유지(또는 개선)되고,
  - **worst_mdd가 악화되지 않을 것(≤ +0.5%p)**  
  - “시프트 테스트(E1-1)”에서 성능이 *유사하게 유지*되면(=누수 의심), 해당 feature를 즉시 격리/제거.

### 2) 비용(슬리피지/스프레드/체결) 미반영 리스크를 “강제 내재화”
- **해야 할 일**
  - 거래비용 모델을 보수적으로 고정하고(스프레드+슬리피지+충격) 모든 리포트에 **gross/net** 동시 출력하라.
  - turnover 상한(일/주)과 포지션당 최소 홀딩을 옵션으로 두고, 비용 민감도를 스윕하라.
- **(a) 왜 필요한지**
  - Tech 대형주는 비용이 낮아 보이지만, 8~14종목 집중+리밸런스가 잦으면 비용이 성과를 “고정적으로” 갉아먹어 개선이 안 보인다.
- **(b) 위험/부작용**
  - net 성능 하락으로 후보가 대거 탈락할 수 있다(정상).
  - 비용 모델이 과도하면 유효전략을 죽일 수 있다(스트레스/베이스 2단 운영 필요).
- **(c) 최소 실험(아래 Experiment E2로 통합)**
  - (E2-1) 슬리피지 1x/2x 스트레스에서 lockbox 유지 여부
  - (E2-2) turnover cap 적용 전/후 비교(성과 vs MDD vs 거래수)
- **(d) PASS 조건**
  - **net lockbox_mean이 챔피언(net 기준) 대비 +0.3%p 이상** 또는
  - **worst_mdd가 -0.5%p 이상 개선**되면서 net mean이 유지(≥ -0.2%p).

### 3) 서바이버십(종목 생존 편향) + 유니버스 고정(Tech+Healthcare 8~14) 규격화
- **해야 할 일**
  - “오늘 살아남은 종목”이 아니라 **과거 시점에서 접근 가능했던 종목**만 포함되도록 유니버스를 역사적으로 재구성하라.
  - 최소 유동성(달러거래대금), 최소 상장기간(예: 180거래일) 필터를 “시점별로” 적용하라.
  - 종목 수 8~14를 강제하고, Tech/Healthcare 비중 상한을 함께 걸어 쏠림을 통제하라.
- **(a) 왜 필요한지**
  - 종목 수가 적을수록 서바이버십/데이터결손/상폐(또는 인수합병) 처리에 따라 성능이 쉽게 왜곡된다.
- **(b) 위험/부작용**
  - 유니버스가 바뀌면 과거 성과와 단절되어 “좋았던 구간”이 사라질 수 있다.
  - 필터가 과도하면 트레이드 기회가 줄어든다.
- **(c) 최소 실험(아래 Experiment E3로 통합)**
  - (E3-1) historical constituent(또는 point-in-time membership) 기반 유니버스 재런
  - (E3-2) liquidity/age 필터 on/off로 성과-안정성 비교
- **(d) PASS 조건**
  - **worst_mdd가 -0.5%p 이상 개선** 또는
  - **lockbox_min(최악) 개선**(더 덜 음수) + 평균 유지(≥ -0.3%p).

### 4) 과최적화 방지 게이트 강화(튜닝 성능이 움직여도 락박스가 고정되는 문제 차단)
- **해야 할 일**
  - 튜닝에서 올라간 개선폭이 락박스로 전달되는지 “전달률”을 지표화하라.
  - 후보 선택 기준에 **복잡도 패널티**(feature 수/모델 자유도/리밸런스 빈도)를 포함하라.
  - fold별 분산과 최악 fold 성능을 1차 게이트로 올려라(평균보다 tail 우선).
- **(a) 왜 필요한지**
  - 현재 tuning_mean이 후보에서 약간 개선되어도 lockbox가 비슷하게 잘 나오는 구조는, (i) 우연 (ii) 누수 (iii) 과최적화가 섞였을 확률이 높다.
- **(b) 위험/부작용**
  - 단기적으로 “눈에 띄는 평균 상승” 후보가 줄어든다.
- **(c) 최소 실험**
  - (E4와 공유) 리스크/레짐 오버레이 적용 시 “전달률”이 개선되는지 확인
  - (정적 패치) 후보 셀렉터에 complexity penalty 추가(실험은 E4 결과로 간접 검증)
- **(d) PASS 조건**
  - tuning→lockbox 전달률(Δlockbox/Δtuning)이 **0.3 이상**이거나,
  - 평균이 비슷해도 **worst_mdd/lockbox_min이 일관되게 개선**될 것.

### 5) 운영 리스크(체결/결측/재시작/중복주문) + 48시간 자동루프 안전장치
- **해야 할 일**
  - 결측 데이터 시 “거래 중단(hold)”을 기본값으로 하고, 대체값(FFill 등) 사용 시 로그/카운트하라.
  - 주문 중복 방지 키(idempotency key), 리밸런스 캘린더, 장휴일 캘린더를 강제하라.
  - 리포트에 “실행 가능 주문 수/실패 수/데이터 결측률/코스트 비중”을 매 런마다 남겨라.
- **(a) 왜 필요한지**
  - 성능이 잘 나오는 백테스트보다, 자동 루프에서 **조용히 성능을 죽이는 요인**은 운영 결함(결측, 재시작, 중복체결)이다.
- **(b) 위험/부작용**
  - hold가 늘면서 수익 기회가 줄 수 있다(대신 tail 리스크 감소).
- **(c) 최소 실험**
  - 운영 패치는 “실험”보단 게이트(아래 공통 Gate)에 편입하고, 실패 시 즉시 롤백하도록 구성하라.
- **(d) PASS 조건**
  - 결측률/실패주문/재시도 횟수 0에 수렴, 또는 사전에 정한 임계치 이하 유지.
  - 비용 비중(총 PnL 대비 비용)이 보고서에 항상 출력될 것(미출력 시 FAIL).

## 48시간 자동 루프용 “실행 가능한 Patch/Experiment” 4개 (케이스 폭발 방지)

아래 4개만 돌려라. 각 실험은 (1)정의 (2)게이트 (3)기대 관측치로 고정한다.

---

### Experiment E1 — Time Integrity/Leakage Kill-Switch
1) **실험 정의**
- feature/label 생성 파이프라인에 `asof` 강제 + (옵션) 1-day shift 스위치 추가
- earnings/뉴스성 지표는 “발표 다음 거래일”부터 반영
- adjusted/unadjusted 혼용 제거(단일 소스 강제)

2) **게이트**
- `shift=+1`에서 성능이 거의 유지되면(예: lockbox_mean 변화가 ±0.2%p 이내) → **누수 의심으로 FAIL**(해당 feature set 격리)
- 누수 방지 적용 후:
  - lockbox_mean ≥ (챔피언 lockbox_mean - 0.5%p)
  - worst_mdd 악화 ≤ +0.5%p

3) **기대 관측치**
- 정상이라면: tuning_mean은 약간 하락/비슷, lockbox는 큰 변화 없이 유지(또는 소폭 하락)
- 누수가 있었다면: tuning이 크게 무너지고 shift 테스트에서 급변(또는 반대로 shift에도 유지되는 이상징후)

---

### Experiment E2 — 비용 내재화 + Turnover Cap
1) **실험 정의**
- 거래비용 모델을 “베이스/스트레스(2x)” 두 모드로 고정
- turnover cap(일/주) 또는 최소 홀딩(예: 2~3일) 옵션을 추가해 비용 민감도 확인

2) **게이트**
- net 기준으로:
  - lockbox_mean 개선(+0.3%p) **또는**
  - worst_mdd 개선(-0.5%p) + mean 유지(≥ -0.2%p)
- 비용 비중(총 PnL 대비)이 보고서에 반드시 출력(미출력=FAIL)

3) **기대 관측치**
- gross는 비슷, net은 현실화로 하락하되 turnover cap이 tail/MDD를 줄이며 “개선 여지”를 드러냄

---

### Experiment E3 — Survivorship-safe Universe (Tech+Healthcare 8~14)
1) **실험 정의**
- 유니버스를 point-in-time로 재구성(가능한 소스로 고정)
- 필터(최소 달러거래대금/최소 상장기간)를 시점별 적용
- 종목 수 8~14 유지, Tech/Healthcare 쏠림 상한 설정

2) **게이트**
- worst_mdd -0.5%p 이상 개선 **또는** lockbox_min 개선
- 거래 가능 종목 수가 임계치 미만으로 자주 떨어지면 FAIL(운영 불가)

3) **기대 관측치**
- 평균은 비슷하거나 소폭 하락해도, 최악 구간/꼬리 손실이 줄어드는 방향이 정상

---

### Experiment E4 — Regime/Risk Overlay (ETF는 “관측 지표”로만)
1) **실험 정의**
- ETF/매크로 관측지표로만 레짐을 정의하고(매매 금지):
  - 예: QQQ 모멘텀, XLV 상대강도(관측), VIX, 10Y(예: ^TNX)
- 레짐에 따라:
  - 포지션 사이즈(볼 타겟) 조정 또는 신규 진입 게이트(리스크-오프 시 진입 축소)
  - 드로우다운 기반 서킷 브레이커(예: 최근 N일 DD 초과 시 노출 축소)

2) **게이트**
- worst_mdd -0.7%p 이상 개선 **또는** fold14_mdd 개선(-0.5%p)하면서 lockbox_mean ≥ -0.3%p
- 레짐 스위치가 과도하게 빈번하면 FAIL(운영 리스크/비용 증가 신호)

3) **기대 관측치**
- 평균 수익은 크게 안 오를 수 있으나, tail/MDD가 줄고 lockbox_min이 개선되는 패턴이 정상

## 성능이 안 움직일 때 원인 분해 아이디어(트리거/적용/노출/비용/레짐)

아래를 “매 런 리포트에 숫자로” 쪼개서, 어디가 막혔는지 즉시 판단하라.

### A) Trigger(신호 발생) 문제
- **진단 지표**
  - 종목당 신호 발생 빈도(일/주), 0에 수렴하는지
  - 신호 강도 분포(상위 5%/중앙값), 분포가 납작해졌는지
- **대표 원인**
  - 필터 과도(유동성/결측/레짐 게이트가 지나치게 막음)
  - 피처 스케일링/정규화 오류로 신호가 죽음

### B) Apply(적용/체결 시점) 문제
- **진단 지표**
  - “결정 시점 가격” vs “체결 가격” 괴리(슬리피지 추정치)
  - 신호→주문 지연(다음 바 체결 강제 여부)
- **대표 원인**
  - asof misalignment(사실상 lookahead 또는 반대로 지나친 지연)
  - 장중/장마감 기준 혼재

### C) Exposure(노출) 문제
- **진단 지표**
  - 순노출/총노출, 섹터별 노출(Tech/Healthcare), 상위 1~2종목 비중
  - 포지션 변화율(리밸런스 시 포트 회전)
- **대표 원인**
  - 8~14 소수 종목에서 단일 종목이 성과를 “고정”시킴(좋든 나쁘든)
  - 리스크 제약이 사실상 알파를 상쇄

### D) Cost(비용) 문제
- **진단 지표**
  - 비용 / gross PnL 비중, 거래당 평균 비용
  - turnover와 성과의 상관(높을수록 성과가 악화되는지)
- **대표 원인**
  - 비용 모델 미반영/과소추정(백테스트 착시)
  - turnover cap 부재로 미세 신호를 과다 매매

### E) Regime(시장 국면) 문제
- **진단 지표**
  - 레짐별 성과 테이블(리스크온/오프 구간별 mean, mdd, hit rate)
  - 관측지표(QQQ/XLV/VIX/TNX) 구간별 성과 분해
- **대표 원인**
  - 단일 국면에만 강한 신호(특히 2020~2021류) → 최근엔 평평
  - Tech/Healthcare 상호 레짐이 달라 “섞었더니 중화”되는 경우

---

### 최종 정렬(핵심)
- **먼저 누수(E1) 제거 → 그 다음 비용(E2) → 그 다음 유니버스/서바이버십(E3) → 마지막으로 레짐/리스크(E4)**  
이 순서를 깨면, 좋아진 것처럼 보이는 개선이 대부분 “착시”로 남는다.
