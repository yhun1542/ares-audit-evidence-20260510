## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — 명령형 체크리스트

### 1) **누수/폴드 퇴화(degenerate_folds) 즉시 차단**
- **왜 필요**: `degenerate_folds: [1,2,3,8]`는 (a) 시계열 분할 오류 (b) 라벨/피처 lookahead (c) 동일 날짜 중복/정렬 문제 중 하나일 확률이 높고, OOS가 “안 움직이거나” 비정상적으로 튀는 1순위 원인.
- **위험/부작용**: 누수 제거 후 성능 급락 가능(그게 정상). 학습 데이터 유효 샘플 감소로 변동성 증가.
- **최소 실험(아래 공용 실험 ID 참조)**: **E1 + E4** (2개)
- **PASS 조건**:
  - degenerate_folds가 **0개**로 감소
  - OOS min이 “우연한 -0.02” 수준이 아니라 **일관된 분포**로 재형성(극단치 원인 설명 가능)
  - 동일 설정 재실행 시 결과가 **재현 가능(분산 축소)**

---

### 2) **재현성/추적성(해시/로그) 복구 + 리밸런스 로그 표준화**
- **왜 필요**: `lane_hash/run_hash: None`, `worst_mdd: None`, rebalance pinpoint가 입력을 못 읽는 상태는 “성능 정체 원인분해” 자체를 막음. 48시간 자동 루프에서 가장 먼저 깨지는 운영 리스크.
- **위험/부작용**: 로깅 추가로 I/O 비용 증가, 저장 공간 증가(하지만 디버깅 비용 대비 저렴).
- **최소 실험**: **E2 + E3** (2개)
- **PASS 조건**:
  - 모든 런에 `run_hash/lane_hash/dataset_hash/cost_model_hash`가 채워짐
  - `rebalance.jsonl(or parquet)`이 항상 생성되고 pinpoint가 **에러 없이** diff 생성
  - `worst_mdd`가 항상 계산/기록됨(NA 금지)

---

### 3) **비용/턴오버 미반영(또는 과소반영) 우선 교정**
- **왜 필요**: “OOS가 안 움직이는” 케이스에서, 실은 gross는 움직이는데 net에서 비용이 다 먹거나, 반대로 비용을 0에 가깝게 둬서 과최적화된 경우가 흔함.
- **위험/부작용**: 비용 도입 즉시 성능 하락 가능. 대신 실거래 근접.
- **최소 실험**: **E3 + E5** (2개)
- **PASS 조건**:
  - gross→net 성능 차이가 합리적 범위로 안정화(과도한 턴오버가 사라짐)
  - turnover, 거래횟수, 평균 보유기간이 “전략 설명 가능한 수준”으로 수렴
  - 비용 민감도(스프레드/슬리피지 2배)에서도 완전 붕괴하지 않음

---

### 4) **서바이버십/유니버스 드리프트 고정 (미국 Tech+Healthcare 8~14 종목 준수)**
- **왜 필요**: 유니버스가 백테스트 중간에 “미래 기준으로 정리”되면, 성능이 좋게 고정되거나 반대로 갑자기 무의미해질 수 있음. 또한 현재 요구사항(US only, Tech+Healthcare 8~14) 준수 강제 필요.
- **위험/부작용**: 유니버스 축소로 샤프 하락 가능. 하지만 운영/재현성 향상.
- **최소 실험**: **E4 + E1** (2개)
- **PASS 조건**:
  - 유니버스가 날짜별로 “당시 존재” 기준(as-of)으로 고정됨(상장폐지/티커변경 처리)
  - 8~14 종목 제약을 강제해도 모델이 퇴화하지 않음(항상 현금만 들고 있는 상태 방지)
  - 종목별 기여도/노출이 상식 범위(단일 종목 쏠림 감지 가능)

---

### 5) **레짐/노출(Exposure) 게이트 추가(ETF는 지표로만) + 드로우다운 운영 스위치**
- **왜 필요**: `exposure max ~0.84`로 보이는데, 레짐에 따라 노출이 “의미 없이 고정”되면 성능이 정체. QQQ/XLV/XBI/SPY, VIX/TLT 같은 지표로 “거래는 하지 않고” 환경 인지→노출 스케일링을 걸어야 함.
- **위험/부작용**: 과도한 게이팅은 기회 손실(under-trading). 레짐 규칙 과최적화 위험.
- **최소 실험**: **E5 + E2** (2개)
- **PASS 조건**:
  - 레짐별(리스크온/오프) 노출 분포가 분리되어 설명 가능
  - 최악 구간에서 MDD/손실꼬리가 개선(특히 oos_min 방어)
  - 규칙이 단순하고 재현 가능(파라미터 1~2개 수준)

---

# 48시간 자동 루프용 “공용 실험(3~5개)” 패치/실험 정의 (총 5개만)

아래 **E1~E5**만 돌리고, TOP5 우선순위는 이 5개를 **공유 참조**해서 케이스 폭발을 막아라.

---

## E1) Purged TimeSeries Split + Lookahead 방지 패치
1) **실험 정의(패치)**  
   - 시계열 CV를 **purge+embargo**로 교체(예: purge = N bars, embargo = M bars).  
   - feature/label 생성에 `t+1` 이상 데이터 접근 차단(특히 리밸런스 가격/체결가/종가 기준 혼용 금지).  
   - 인덱스 정렬 강제: (symbol, date) unique 보장 + timezone 통일 + 중복 제거 로그 출력.
2) **게이트(실행 차단 조건)**  
   - 폴드별 train/test 날짜가 겹치면 즉시 FAIL.  
   - fold별 샘플 수가 임계치 미만이면 FAIL(폴드 퇴화 감지).  
   - “동일 timestamp 중복 row” 1건이라도 있으면 FAIL.
3) **기대 관측치**  
   - degenerate_folds → 0  
   - OOS 분산이 정상화(“몇 폴드만 미친 듯이 좋음/나쁨” 현상 감소)  
   - 재실행 결과의 변동 축소

---

## E2) 런 메타데이터/해시 + 리밸런스 로그 표준화(운영 리스크 제거)
1) **실험 정의(패치)**  
   - `run_hash = hash(code_commit, config, universe_spec, dataset_hash, cost_model_hash)` 강제 기록.  
   - `lane_hash`도 동일 규격으로 생성.  
   - 리밸런스 로그를 **단일 포맷(jsonl/parquet)**로 고정: 날짜별 target, filled, price, fees, slippage, turnover, exposure 기록.  
   - `worst_mdd`를 항상 산출해 summary에 포함(NA 금지).
2) **게이트**  
   - run_hash/lane_hash None이면 FAIL.  
   - rebalance 로그 파일이 없으면 FAIL.  
   - pinpoint 도구가 로그 로드 실패 시 FAIL(즉시 파이프라인 중단).
3) **기대 관측치**  
   - “성능 정체”가 발생해도 **어디서 정체인지(트리거/노출/비용)** 즉시 분해 가능  
   - 재현 가능한 비교(Champion vs Candidate)가 가능해짐

---

## E3) 비용/슬리피지/턴오버 캡 실험(넷 성능 실거래화)
1) **실험 정의(패치)**  
   - 비용 모델을 명시적으로 분리: `commission + spread + impact(볼륨/ADV 기반)` 최소형으로.  
   - turnover cap(예: 일/주 단위) + 최소 보유기간(예: 2~5 trading days) 중 **하나만** 먼저 적용(단순 유지).
2) **게이트**  
   - 평균 일 turnover가 임계치 초과 시 FAIL(전략이 비용에 먹히는 구조 차단).  
   - 비용 0 설정이면 FAIL(실험 금지).
3) **기대 관측치**  
   - gross는 유지/소폭 하락, net의 꼬리 손실 감소  
   - 거래 빈도 감소 + 성능 변동성 감소

---

## E4) 서바이버십/유니버스 고정(US Tech+Healthcare 8~14) 실험
1) **실험 정의(패치)**  
   - 유니버스를 “현재 구성”이 아니라 **as-of date**로 고정(상장폐지/티커변경 매핑 포함).  
   - 종목 수 8~14 강제(Tech+Healthcare로만), 단일 종목 최대 비중 상한 설정.  
   - (예시 종목군) Mega/large 중심으로 고정 리스트를 만들고, 실험 동안은 변경 금지.
2) **게이트**  
   - 날짜별 유니버스가 미래정보로 재구성되면 FAIL(예: 전체 기간을 보고 상위 시총 선정).  
   - 8~14 제약 위반 시 FAIL.
3) **기대 관측치**  
   - 성능이 “덜 좋아질 수 있으나” 결과의 신뢰도가 상승  
   - 종목별 성과 기여/리스크가 설명 가능해짐(서바이버 편향 감소)

---

## E5) 레짐(ETF 지표) 기반 노출 스케일링 + DD Kill-switch
1) **실험 정의(패치)**  
   - **ETF는 매매 금지**, 지표로만 사용: QQQ(Tech), XLV(Healthcare), XBI(Biotech), SPY(시장), VIX(변동성) 등에서 1~2개 신호만 채택.  
   - 노출 스케일링 규칙을 단순화: `exposure *= f(regime)` (예: risk-off면 0.3~0.6).  
   - 운영 스위치: rolling MDD/vol 임계치 초과 시 노출 자동 축소(하드 리밸런스 대신 점진 축소).
2) **게이트**  
   - 레짐 규칙 파라미터가 2개 초과하면 FAIL(과최적화 방지).  
   - 레짐 판단에 미래 데이터 사용 시 FAIL.
3) **기대 관측치**  
   - oos_min 개선(최악 구간 방어)  
   - 레짐별 노출/턴오버가 구조적으로 달라짐(“항상 0.8 노출” 같은 정체 해소)

---

# 성능이 “안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐) — 실행 체크리스트

## A) 트리거(신호) 자체가 안 바뀌는지
- 신호가 0 또는 상수로 붙는 구간 비율을 로그로 출력하라(종목×날짜).
- 신호 분포(평균/표준편차/상위 1% 절대값)를 폴드별로 저장하라.
- 신호와 다음날 수익률 상관(단순 IC)을 “학습/검증/OOS”로 분리해 찍어라.  
  - **IC가 전 구간 0 근처**면: 피처 누락/정렬/라벨 시프트 오류 가능.

## B) 적용(포지션 사이징/리밸런싱)이 신호를 무시하는지
- target position과 filled position 괴리(체결 실패/캡/라운딩)를 로그로 분해하라.
- 제약(최대 비중, 종목 수, 현금 하한, 노출 캡) 때문에 **항상 같은 포트폴리오**가 나오는지 확인하라.
- 리밸런스 빈도 vs 신호 갱신 빈도 불일치(예: 신호는 매일, 거래는 주간으로 강제) 여부를 점검하라.

## C) 노출(Exposure)이 정체인지
- 날짜별 gross exposure / net exposure / sector exposure를 저장하고, 분산이 너무 낮으면(거의 상수) “전략이 사실상 고정 베타”인지 의심하라.
- 상관 구조: 포트 수익률 vs QQQ/XLV/SPY 회귀 베타를 롤링으로 계산하라(ETF는 지표만).

## D) 비용/슬리피지가 성능을 눌러서 정체처럼 보이는지
- gross PnL, cost, net PnL을 분리해 누적 곡선을 3개로 고정 출력하라.
- turnover×(spread proxy)로 “예상 비용”을 먼저 산정하고, 실현 비용과 괴리를 비교하라.
- 비용을 0/기본/2배로 스윕해서 민감도 곡선을 남겨라(과최적화/취약성 탐지).

## E) 레짐 미스매치로 구간별 상쇄가 발생하는지
- 레짐 라벨(예: risk-on/off)을 단순 정의하고, 레짐별 성과/턴오버/노출을 테이블로 저장하라.
- 레짐별로 “신호는 유효한데 노출이 과도” 혹은 “신호가 죽음”을 분리하라.
- OOS min이 발생한 날짜 주변 20~60 trading days를 자동으로 잘라 **원인 리포트(노출/비용/신호/베타)**를 생성하라.

---

## 실행 순서(48시간 루프, 우선순위)
1) **E2 먼저**(로그/해시/리밸런스 표준화 없으면 이후 실험이 전부 비교 불가)  
2) **E1**(degenerate_folds 제거)  
3) **E3**(넷 성능 현실화)  
4) **E4**(서바이버십/유니버스 고정)  
5) **E5**(레짐/노출 게이트로 oos_min 방어)

이 5개만 고정 루프로 돌려서, “성능이 왜 안 움직이는지”를 **로그로 증명 가능한 상태**로 만든 뒤에만 추가 전략 실험을 허용하라.
