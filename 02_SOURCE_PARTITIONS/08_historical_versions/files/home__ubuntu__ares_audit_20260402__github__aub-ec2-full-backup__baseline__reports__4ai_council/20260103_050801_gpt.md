## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — 명령형 체크리스트

### 1) **관측/아티팩트 무결성 복구(“왜 안 움직였는지”부터 보이게)**
**(a) 왜 필요한지**
- 현재 `rebalance_pinpoint`가 **입력 로그 부재/JSON 파손**으로 실패했고, Champion에 `worst_mdd: None`, `lane_hash/run_hash: None` 등 **핵심 메타데이터 누락**이 보임.  
- “성능이 안 움직임(no-delta)” 상황에서 **리밸런스 이벤트/포지션 변동/비용/제약 발동 여부**가 관측되지 않으면 원인분해가 불가능함.

**(b) 위험/부작용**
- 로그/저장량 증가, I/O 병목, 런타임 증가(경미).  
- 로깅 포맷 변경 시 기존 리포트 파서 깨질 수 있음(버전 태깅으로 완화).

**(c) 최소 실험(공유 실험 ID 사용)**
- **E1**, **E2** 사용

**(d) PASS 조건**
- 모든 런에서 아래 파일이 **항상 생성 + 파싱 성공**:
  - `rebalance.jsonl`(이벤트 단위), `rebalance.csv`(요약), `positions.parquet`, `costs.parquet`, `metrics.json`
- `worst_mdd`, `lane_hash`, `run_hash`가 **항상 non-null**
- “no-delta” 발생 시, 최소 1개 리포트에 **(신호 변화량, 거래 임계치, 제약 발동, 반올림/최소주문) 중 무엇이 0-delta를 유발했는지**가 문자열로 명시

---

### 2) **누수/과최적화/폴드 붕괴(degenerate_folds) 우선 차단**
**(a) 왜 필요한지**
- `degenerate_folds: [1,2,3,8]`는 **검증 구조가 깨졌거나(표본 부족/라벨 누출/분할 오류)** OOS가 과대평가될 가능성이 큼.
- “OOS mean은 있는데 min이 거의 0 근처 / MDD None” 조합은 **평가 파이프라인 자체 이상**을 강하게 시사.

**(b) 위험/부작용**
- Purged/embargo 적용 시 과거 대비 성능 하락 가능(정상).  
- Fold 재정의로 결과가 흔들릴 수 있음(정상). 안정성이 오히려 개선돼야 함.

**(c) 최소 실험**
- **E2**, **E3** 사용

**(d) PASS 조건**
- degenerate_folds가 **빈 배열**  
- OOS 평가에서 최소 다음이 항상 산출:
  - fold별 샘플수/수익률 분포, 거래횟수, 평균 보유기간
- 누수 방지 후에도 **OOS_mean이 기존 대비 -20% 이내로 유지**되거나(방어), 혹은 **OOS_min/드로우다운 지표가 개선**되면(공격) 통과  
  - (예: `oos_min` 상승, worst_MDD 산출 및 제한 내)

---

### 3) **서바이버십/Point-in-time(편입/상폐/스플릿) + 유니버스 강제(미국 Tech+Healthcare 8~14)**
**(a) 왜 필요한지**
- “US 주식 only + Tech/Healthcare 중심(8~14)”은 **전략 정의의 일부**인데, 유니버스가 느슨하면 **서바이버십/편입 시점 오류**가 성능을 가짜로 끌어올리거나(또는 거래 불가 종목 포함) 실거래에서 붕괴함.
- 상폐/정지/합병 이벤트 미반영은 **백테스트-실거래 괴리 1순위**.

**(b) 위험/부작용**
- 데이터 소스/조인 변경으로 과거 수익률 급락 가능(정상).  
- 종목 수가 8 미만으로 떨어지는 구간이 생길 수 있음(현금/대체 규칙 필요).

**(c) 최소 실험**
- **E3**, **E5** 사용

**(d) PASS 조건**
- 모든 시점에 포트폴리오 보유종목 수가 **8~14 유지** (불가 시 현금 처리 규칙이 로그로 명시)
- 산업 분류 기준(예: GICS)으로 **Tech+Healthcare 외 보유 0%** (예외는 운영상 금지)
- 상폐/거래정지 발생 종목 처리(마지막 거래가, 상폐 반환 등)가 **비용/손익에 반영**되고 재현 가능

---

### 4) **비용(슬리피지/스프레드/임팩트) 미반영을 OOS에서 바로 반영 + 과도 회전율 차단**
**(a) 왜 필요한지**
- “성능이 안 움직임”의 원인이 실제로는 **거래는 활발한데 비용으로 다 깎이는** 구조일 수 있음.  
- 반대로 “거래가 안 일어남(no-delta)”이면 비용을 넣어도 변화가 없는 것이 정상 → 이 구분이 필요.

**(b) 위험/부작용**
- 비용 모델이 과하면 거래가 0으로 수렴(과도 보수) 가능.  
- 임팩트 모델 파라미터 미스 시 특정 종목이 영구 배제될 수 있음(게이트로 확인).

**(c) 최소 실험**
- **E4**, **E1** 사용

**(d) PASS 조건**
- `gross_return`, `net_return`, `cost_breakdown(spread/slippage/fees)`가 리밸런스 이벤트와 함께 저장
- Net 기준으로도 **OOS_mean 유지(예: gross 대비 70% 이상 유지)** 또는 회전율 감소로 **OOS_min/MDD 개선**
- “거래 0”이 되면 FAIL(단, E5의 의도적 게이트로 거래 억제한 경우는 로그로 사유가 명시돼야 함)

---

### 5) **운영 리스크(48시간 자동루프) 제어: 노출/리밸런스/현금화 규칙을 게이트로 고정**
**(a) 왜 필요한지**
- 현재 `exposure_max ~0.84`로 보이는데, “언제/왜 0~0.84로 바뀌는지”, “0-delta의 원인이 제약인지”가 불명확.  
- 48시간 자동 루프에서는 **게이트 없는 전략 변경**이 운영 사고로 직결(거래 폭주/미거래/섹터 이탈).

**(b) 위험/부작용**
- 게이트가 너무 강하면 기회 손실 + 성능 둔화.  
- 현금 비중이 늘어 벤치 대비 언더퍼폼 가능(하지만 운영 안정성 우선).

**(c) 최소 실험**
- **E5**, **E4** 사용

**(d) PASS 조건**
- 매 런에서 다음 게이트 결과가 “PASS/FAIL + 수치”로 출력:
  - 목표 종목수(8~14), 섹터 위반(0%), 최대 단일종목 비중, 최대 회전율, 최대 총노출, 최소 거래금액/수량
- FAIL 시 **주문 생성이 0**이고, 원인이 로그 1줄로 요약되어야 함

## 공용 “실행 가능한 patch/실험” 5개 (48시간 자동 루프용)
아래 **E1~E5만** 돌려도 위 TOP5 요구를 모두 커버하도록 설계(실험 폭발 방지).

### E1) Rebalance/Order “진실 로그” 패치
1) **실험 정의**
- 리밸런스 결정 전/후를 이벤트로 기록:  
  - 입력 신호 요약(상위 20개 스코어), 목표비중, 제약에 의해 잘린 비중, 반올림/최소주문으로 삭제된 주문, 최종 체결가정, 비용.
- 산출물 강제 저장: `rebalance.jsonl`, `rebalance.csv`, `positions.parquet`, `costs.parquet`, `run_meta.json`.

2) **게이트**
- 파일 파싱 실패 시 런 전체 FAIL 처리(조용히 넘어가지 않기).
- `run_hash/lane_hash` 미기록 시 FAIL.

3) **기대 관측치**
- no-delta 런에서 “거래가 0인 이유”가 아래 중 하나로 분류되어 찍힘:
  - (a) 신호 변화 없음 (b) 임계치/밴드에 걸림 (c) 제약(종목수/섹터/노출/회전) (d) 최소주문/반올림 (e) 데이터 결측

---

### E2) Fold 붕괴 제거 + Purged Walk-Forward/Embargo 적용
1) **실험 정의**
- 현재 CV/분할 로직에 다음을 추가:
  - Purge 기간(lookback/holding 기간 기반) + Embargo(예: 1~5영업일)
  - fold별 최소 표본/거래횟수 기준 미달 시 fold 제외가 아니라 **실험 FAIL** 처리
- degenerate_folds 원인(표본 0/거래 0/라벨 누출 가능)을 리포트에 명시.

2) **게이트**
- `degenerate_folds`가 1개라도 발생하면 FAIL.
- fold별 거래횟수 < N(예: 10)면 FAIL.

3) **기대 관측치**
- OOS_mean이 일시 하락할 수 있으나, fold 분산/최저 성과(oos_min) 및 MDD가 정상적으로 산출되고 안정화.

---

### E3) Point-in-time 유니버스 + 상폐/편입 시점 정합성 테스트
1) **실험 정의**
- 유니버스를 “그 날짜에 실제로 거래 가능했던 미국 Tech+Healthcare”로 강제:
  - 편입 시점 이전 데이터로 미래 구성 종목이 들어오지 않게 차단
  - 상폐/합병/거래정지 처리(최종가/현금정산 규칙) 반영
- 결과를 기존 유니버스 대비 A/B 리포트로 출력.

2) **게이트**
- 섹터 외 종목 보유 발생 시 FAIL.
- 보유 종목 수 8~14 위반 시: 현금 대체 로직이 발동되어야 PASS(미정의면 FAIL).

3) **기대 관측치**
- 과거 성능이 “덜 좋아지더라도” 현실성이 증가.  
- 특정 기간에 거래 불능 이벤트가 로그로 관측됨(운영 리스크가 보이기 시작).

---

### E4) 비용 모델 v2 + 회전율 캡(운영비용 반영)
1) **실험 정의**
- 비용을 최소 2층으로 분해하여 기록:
  - (1) 스프레드/슬리피지(유동성 기반, 예: ADV/price/vol proxy)
  - (2) 고정 수수료(주당/거래당)
- 회전율 캡(예: 일/리밸런스당 max turnover %)을 걸고, 캡으로 잘린 주문을 로그로 남김.

2) **게이트**
- net 성과 산출이 없으면 FAIL.
- turnover 캡이 발동될 때 “잘린 주문 리스트/규모”가 기록되지 않으면 FAIL.

3) **기대 관측치**
- 거래가 많은 전략은 net이 급락하고, 회전율 캡으로 거래가 줄며 MDD/최저 성과가 개선되는 패턴이 나타남(또는 반대로, 거래가 거의 없어서 비용 영향이 미미함이 확인됨).

---

### E5) 노출/거래 게이트(48시간 자동루프 안정장치)
1) **실험 정의**
- 아래를 “정책”으로 고정하고, 매 런 PASS/FAIL을 출력:
  - 총노출 상한(예: 0.85), 단일종목 상한(예: 0.15), 종목수 8~14, 섹터 2개(Tech/HC)만, 최소 거래 임계치, 현금 대체 규칙
- 신호 강도 부족 시 “의도적 no-trade” 허용(단, 사유를 로그로 남김).

2) **게이트**
- 정책 위반 주문 생성 시 FAIL(주문 0으로 강제).
- 정책 준수 여부가 리포트에 없으면 FAIL.

3) **기대 관측치**
- “성능이 안 움직임”이 신호 문제인지 정책 게이트 문제인지 즉시 분리됨.
- 자동 루프에서 폭주/이탈 방지.

## 성능이 안 움직일 때(“No-Delta”) 원인 분해 아이디어 — 트리(질문 없이 실행 순서)
아래는 **관측 → 원인 → 조치** 순으로 1회 루프에서 끝내는 분해 절차.

### A) 트리거(신호 변화) 레이어
- [ ] **신호 분포 변화량**(전일 대비 각 종목 스코어 Δ, 랭크 Δ)을 `rebalance.jsonl`에 기록(E1)
- [ ] Δ가 거의 0이면:  
  - 원인 후보: 피처가 고정(캐시/스냅샷/업데이트 실패), 리밸런스 주기 불일치, 데이터 결측 후 전방채움  
  - 조치: 피처 생성 타임스탬프/소스 row count를 로그에 남기고, 결측률 상위 피처를 리포트에 출력(E1)

### B) 적용(목표비중 생성) 레이어
- [ ] 목표비중이 생성되었는지(비중 벡터 합, 상위 종목 리스트) 기록(E1)
- [ ] 목표비중은 변하는데 주문이 0이면:
  - 원인 후보: 임계치(band), 반올림/최소주문, turnover 캡, 종목수 제약  
  - 조치: “주문 삭제 사유”를 카운트로 집계(E1, E4, E5)

### C) 노출(제약/리스크) 레이어
- [ ] 총노출/순노출/섹터/단일종목/종목수 제약이 발동했는지 기록(E5)
- [ ] exposure가 0~0.84 사이에서만 움직이면:
  - 원인 후보: 스케일링 버그, 리스크 타깃 계산 오류, cash 대체 규칙 미정의  
  - 조치: 정책 수치와 실제 수치 비교 테이블을 리포트에 고정 출력(E5)

### D) 비용(거래비용이 신호를 압살) 레이어
- [ ] gross vs net의 괴리, 비용 항목별 기여를 기록(E4)
- [ ] gross는 좋은데 net이 평평하면:
  - 원인 후보: 회전율 과다, 유동성 낮은 종목 비중 과다  
  - 조치: turnover 캡 + 유동성 패널티(비용모델)로 재평가(E4)

### E) 레짐(시장 국면/섹터 국면) 레이어 — “ETF는 관측지표로만”
- [ ] 거래는 정상인데 성능이 특정 기간만 죽으면:
  - 원인 후보: Tech/HC 내부 레짐(변동성 급등/금리 민감 구간)  
  - 조치(관측): XLK/XLV(ETF **매매 금지**, 지표만), VIX/UST10Y 변화율을 리포트에 붙이고 성과를 구간별로 슬라이스
  - 조치(정책): 레짐에 따라 **현금 비중(노출)만** 조절(E5) — ETF 헤지 매매는 하지 않음

## 48시간 자동 루프 운영 순서(명령형)
- [ ] **0~6시간:** E1 구현/적용 → `rebalance_pinpoint`가 실패 없이 돌아가게 만들기(파일 경로/포맷 버저닝 포함)
- [ ] **6~18시간:** E2 적용 후 전체 백테스트 1회(폴드 붕괴 제거가 최우선 게이트)
- [ ] **18~30시간:** E3 적용(유니버스 PIT/상폐) + 섹터/종목수 강제
