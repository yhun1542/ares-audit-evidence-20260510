(미국주식 only, **Tech+Healthcare 8~14개** 고정 유니버스, **ETF는 관측지표(레짐/필터)로만 사용**, 매매 제외)

# TOP5 우선순위 제안(각 항목: 왜/리스크/최소 실험/ PASS)

아래 5개 우선순위는 **실험 5개(E1~E5)**를 공유해서 “케이스 폭발”을 막는다.  
각 우선순위별 “최소 실험 2~3개”는 **E1~E5 중 해당되는 것만 실행**하도록 구성했다(총 유니크 실험은 5개).

---

## 1) 운영/관측 불능 상태 제거 (로그/리밸런스/해시/리포트 무결성)
### (a) 왜 필요한지
- `aub_rebalance_pinpoint`가 **base-log/cand-log 로딩 실패** → “왜 성능이 안 움직이는지”를 **분해할 근거 데이터가 없음**
- Champion이 `lane_hash/run_hash=None`, `worst_mdd=None` → **재현성/리스크 관리 붕괴**
- 48시간 루프에서는 **관측 파이프라인이 전략보다 우선**

### (b) 위험/부작용
- 로그 포맷 변경 시 과거 결과와 비교가 어려워질 수 있음(마이그레이션 필요)
- 리밸런스 로그 기록으로 저장공간/IO 비용 증가

### (c) 최소 실험(2~3개)  → **E1, E5 사용**
- **(E1)** *리밸런스 로그 표준화 패치 + 핀포인트 도구 호환*
- **(E5)** *리포트 필수 필드 강제(worst_mdd, run_hash/lane_hash, exposure stats, turnover, cost)*

### (d) PASS 조건(게이트)
- [ ] `aub_rebalance_pinpoint.py`가 **base/cand 둘 다**에서 리밸런스 이벤트를 읽고 **차이 리포트 생성 성공**
- [ ] 모든 런 산출물에 `run_hash/lane_hash`가 채워짐
- [ ] `worst_mdd`가 None이 아니고 값이 정상 범위(예: 0~1)로 기록됨

---

## 2) 누수/과최적화/폴드 붕괴(현재 degenerate_folds) 해결
### (a) 왜 필요한지
- Champion에 `degenerate_folds: [1,2,3,8]` → **OOS Mean(3.32)이 “진짜 OOS”가 아닐 가능성**(데이터 부족/정렬 오류/누수/타깃 시프트)
- “No-Delta Diagnoser”에서 실험은 9개인데 개선이 안 보임 → **모델이 아니라 평가 체계가 막고 있을 확률** 큼

### (b) 위험/부작용
- 정제 후 성능이 “갑자기” 떨어질 수 있음(그게 정상일 수 있음)
- Purged/Embargo CV 적용 시 학습 데이터 감소 → 분산 증가

### (c) 최소 실험(2~3개)  → **E2, E4 사용**
- **(E2)** *Purged Walk-Forward CV + Embargo + 폴드 최소 샘플/거래일 수 게이트*
- **(E4)** *피처 생성 시점 강제(라그/클로즈-오픈 정렬), 타깃 시프트/리샘플링 누수 체크*

### (d) PASS 조건(게이트)
- [ ] `degenerate_folds`가 **빈 배열**(또는 0개)로 수렴
- [ ] 동일 코드 재실행 시 OOS 지표가 **작은 오차 범위 내 재현**(해시 기반)
- [ ] 누수 가드 실패 시 **즉시 FAIL**(런 중단): “피처 timestamp > 의사결정 timestamp” 탐지 시 종료

---

## 3) 비용/슬리피지/턴오버 미반영 제거 (현실성 게이트)
### (a) 왜 필요한지
- 비용 미반영은 OOS 평균을 “움직이게” 만들지만 실전에서 바로 붕괴
- Tech/Healthcare 대형주라도 48시간 루프에서 리밸런스가 잦으면 **턴오버가 성과를 삼킴**
- 현재 exposure max가 0.84까지 가는데, 비용/충격 없으면 과감한 포지션이 과대평가됨

### (b) 위험/부작용
- 비용 모델이 과하게 보수적이면 전략이 “아무것도 안 함”으로 수렴 가능
- ADV/스프레드 데이터 품질 낮으면 노이즈 유입

### (c) 최소 실험(2~3개)  → **E3, E5 사용**
- **(E3)** *거래비용 모델 추가(스프레드+임팩트) + cost-adjusted OOS 생성*
- **(E5)** *턴오버 상한/거래 빈도 제한 게이트(예: 일별 리밸런스 시 변경량 cap)*

### (d) PASS 조건(게이트)
- [ ] **비용 반영 후** OOS mean이 “완전히 사라지지” 않음(예: 비용 후 OOS mean > 0, oos_min 심각 악화 없음)
- [ ] turnover(연환산 또는 월평균)가 상한 이내(예: 월 200~400% 같은 내부 기준)
- [ ] 리밸런스 로그에서 “미세한 왔다갔다” 매매(초소형 포지션 flip)가 감소

---

## 4) 서바이버십/데이터 무결성(분할·배당·티커변경·상장폐지) 점검
### (a) 왜 필요한지
- 고정 8~14개라도, **adj price/배당/스플릿 처리**가 잘못되면 신호가 구조적으로 틀어짐
- 성능이 안 움직일 때 실제 원인은 “전략”이 아니라 **데이터 정렬/조정 실패**인 경우가 많음

### (b) 위험/부작용
- 데이터 소스 변경/조정 방식 변경으로 과거 성능이 크게 바뀔 수 있음(정상)
- PIT(포인트-인-타임) 적용은 구현 비용 증가

### (c) 최소 실험(2~3개)  → **E4, E2 사용**
- **(E4)** *Adj Close 기반 통일 + 배당/스플릿 이벤트 발생일 검증(가격 점프 탐지)*
- **(E2)** *폴드별 결측률/거래정지일/이상치 비율 리포트 → 임계 초과 시 FAIL*

### (d) PASS 조건(게이트)
- [ ] 유니버스 전 종목에 대해 조정 전/후 점프 탐지 리포트가 “설명 가능한 수준”
- [ ] 폴드별 결측률/정지일 비율이 임계 이하(예: 결측 > X%면 FAIL)
- [ ] 이벤트(스플릿/배당) 전후로 피처/리턴이 비정상 폭주하지 않음

---

## 5) 노출/레짐/리스크 레이어 추가(“안 움직임”을 깨는 최소한의 구조 변경)
### (a) 왜 필요한지
- 현재 노출이 `0.0 ~ 0.84`로 넓고, `oos_min`이 작게라도 음수로 내려감 → **리스크 레이어 부재 가능성**
- “No-Delta” 상황은 신호가 약한 게 아니라 **노출/적용이 레짐에 둔감**해서 평균이 상쇄될 때 발생

### (b) 위험/부작용
- 레짐 필터가 과하면 거래 기회가 줄어 수익이 눌릴 수 있음
- 지나친 변동성 타게팅은 추세구간에서 수익 상한을 낮출 수 있음

### (c) 최소 실험(2~3개)  → **E5, E3 사용**
- **(E5)** *ETF 관측지표로 레짐 스케일링만 적용*  
  - 예: `XLK/VHT 상대강도`, `QQQ 50/200`, `VIX(가능하면)`로 **exposure multiplier**만 조절(ETF 매매 금지)
- **(E3)** *포지션 변경량/리밸런스 비용과 함께 최적 exposure cap 탐색(단 2~3개 설정값)*

### (d) PASS 조건(게이트)
- [ ] oos_min(최저 구간 성과) 또는 MDD가 유의미하게 개선(예: MDD 감소)하면서
- [ ] OOS mean이 크게 훼손되지 않음(내부 기준: -X% 이내)
- [ ] 노출 히스토그램이 “항상 0 또는 항상 max” 같은 극단이 줄어듦

# 공용 실험 5개(E1~E5) — 48시간 루프용 포맷(정의/게이트/기대 관측치)

## E1) 리밸런스/실행 로그 표준화 + pinpoint 호환 패치
- **실험 정의**:  
  - 리밸런스 이벤트를 `rebalance.jsonl`(한 줄=한 이벤트)로 고정 저장  
  - `aub_rebalance_pinpoint.py`가 `csv/jsonl` 모두 ingest 가능하게 패치(또는 변환기 추가)  
  - base-log 경로 누락 시 “자동 탐색 + 명시적 FAIL”로 변경
- **게이트**: 리밸런스 로그 0건이면 FAIL(전략이 진짜 무거래인 경우만 예외로 명시)
- **기대 관측치**:  
  - “언제/왜/무엇을” 샀는지 diff가 찍힘  
  - 성능 무변동 시 “리밸런스가 없어서”인지 “리밸런스는 있는데 효과가 없어서”인지 분리 가능

## E2) Purged Walk-Forward CV + 폴드 붕괴 방지
- **실험 정의**:  
  - 시간순 워크포워드, 학습/검증 사이 embargo  
  - 폴드별 최소 거래일/표본수 미달 시 폴드 생성 자체를 막고 FAIL
- **게이트**: `degenerate_folds` 발생 시 FAIL(=릴리즈 금지)
- **기대 관측치**:  
  - OOS mean이 낮아질 수 있으나, 지표가 “일관되게” 나오고 분산이 설명 가능해짐

## E3) 비용/슬리피지 모델 + turnover 제약(현실 게이트)
- **실험 정의**:  
  - 비용 = `half_spread + impact * sqrt(order_notional / ADV)` 같은 단순 모델로 시작  
  - turnover cap(일별 포지션 변경량 합 상한) 1개만 도입해 비교
- **게이트**: cost-adjusted OOS가 음수로 붕괴하거나 turnover 폭발 시 FAIL
- **기대 관측치**:  
  - 작은 알파가 비용에 먹히는 구간이 드러남  
  - “성능이 안 움직임”의 원인이 비용인지 아닌지 즉시 분리

## E4) 데이터 무결성/누수 가드(Adj/타임스탬프/리샘플링)
- **실험 정의**:  
  - 피처는 의사결정 시점 이전 데이터만 사용(라그 강제)  
  - Adj Close 통일, corporate action 점프 리포트 생성  
  - 이상치/결측률을 폴드별로 출력
- **게이트**: 타임스탬프 위반/결측 임계 초과 시 FAIL
- **기대 관측치**:  
  - 누수성 알파가 제거되며 “진짜 전략 문제 vs 데이터 문제”가 분리됨

## E5) 리스크/노출 레이어 + 필수 리포트 필드 강제
- **실험 정의**:  
  - 레짐(ETF 관측지표)로 **노출만 스케일**(종목 선택 로직은 그대로)  
  - vol targeting 또는 max exposure cap을 2~3개 값만 시험  
  - 리포트에 `worst_mdd, run_hash/lane_hash, turnover, cost, exposure stats` 필수화
- **게이트**: worst_mdd None / hash None 발생 시 FAIL
- **기대 관측치**:  
  - oos_min/MDD가 개선되는지 확인 가능  
  - 성능이 그대로면 “신호 자체가 약함” 쪽으로 결론을 좁힐 수 있음

# 성능이 안 움직일 때: 원인 분해 아이디어(트리거/적용/노출/비용/레짐) 체크 트리

아래는 “No-Delta” 상황에서 **원인을 1~2시간 내로 좁히는** 분해 순서(질문 없이 실행형).

## A) 트리거(신호가 발생하나?)
- [ ] 종목별 신호값 분포(평균/표준편차/0 비율) 출력  
- [ ] 신호의 **부호 일관성**(최근 1~3개월) 확인: 계속 뒤집히면 신호가 노이즈
- [ ] 신호가 거의 0이면 → **피처 라그/정렬 버그** 또는 과도한 정규화/클리핑 의심(E4)

## B) 적용(신호가 포지션으로 반영되나?)
- [ ] 신호→목표비중 변환 단계에서 **클리핑/라운딩**으로 0이 되는지 확인  
- [ ] 리밸런스 임계치(threshold) 때문에 “거의 무거래”인지 확인(E1 로그로 즉시 확인)

## C) 노출(포지션이 성과를 낼 만큼 노출되나?)
- [ ] net/gross exposure 타임시리즈 출력  
- [ ] “항상 0 근처”면: 리밸런스 제한/레짐 필터 과도(E5)  
- [ ] “항상 max”면: 레짐/리스크 부재로 하방에서 상쇄(E5로 개선)

## D) 비용(알파가 비용에 잠식되나?)
- [ ] 비용 전/후 PnL 브릿지(=gross PnL, cost, net PnL) 출력(E3)  
- [ ] turnover 상위 날짜 TOP10 확인: 그날 신호가 뒤집혔는지/데이터 점프인지(E4)

## E) 레짐(특정 구간에서만 먹히는데 평균에서 상쇄되나?)
- [ ] 관측 ETF 지표로 시장을 2~3 레짐으로 나누고 레짐별 성과를 분해(E5)  
  - 예: `XLK/VHT 상승 레짐 vs 하락 레짐`, `QQQ above/below 200DMA`
- [ ] 레짐별로 플러스/마이너스가 강하게 갈리면 → 노출 스케일링이 해법(E5)

---

## 24~48시간 실행 순서(중요도/의존성 기준)
- [ ] **(0~6h)** E1+E5부터 적용: 로그/해시/MDD/필수 리포트 강제 → 관측 파이프라인 복구
- [ ] **(6~18h)** E2 적용: degenerate_folds 제거(FAIL-fast) → OOS의 “진짜 의미” 확보
- [ ] **(18~30h)** E4 적용: 누수/조정/정렬 가드로 데이터 신뢰성 확보
- [ ] **(30~48h)** E3/E5 적용: 비용/턴오버/레짐 노출 스케일링 → 실전형 성과로 수렴

이 순서로 돌리면, “성능이 안 움직임”이 **(1) 관측불능**, **(2) 폴드 붕괴**, **(3) 누수/정렬**, **(4) 비용 잠식**, **(5) 레짐 상쇄** 중 어디에 있는지 48시간 내에 강제로 갈라진다.
