## 1. 우선순위 TOP 5 패치/실험

### PATCH-1: Drawdown Floor Guard 강화
**왜 필요한가**
- Champion의 lockbox_min(0.74) vs Candidate(1.35) → 0.6 gap
- 특정 fold에서 수익이 급락하는 regime 존재 추정
- worst_mdd -8.1%도 목표(-5%) 대비 초과

**위험/부작용**
- 과도한 방어 시 upside 훼손 (tuning_mean 하락 우려)
- 현금비중 증가로 exposure 부족 가능

**최소 실험**
| ID | 실험 | 변경점 |
|----|------|--------|
| 1a | mdd_threshold 조정 | `-0.05` → `-0.04` 트리거 |
| 1b | recovery_period 확장 | 5일 → 8일 대기 |
| 1c | volatility_scalar 추가 | VIX>25 시 position×0.7 |

**PASS 조건**
```yaml
gate:
  lockbox_min: ">= 1.0"
  tuning_mean: ">= 2.0"  # 10% 하락까지 허용
  worst_mdd: ">= -0.06"
```

### PATCH-2: Sector Concentration Cap 검증
**왜 필요한가**
- Tech+Healthcare 중심 → 단일 섹터 쏠림 시 동반 하락
- 2022년 Tech drawdown 시나리오 미반영 가능성

**위험/부작용**
- 분산 과도 시 alpha 희석
- 종목 수 증가로 transaction cost 상승

**최소 실험**
| ID | 실험 | 변경점 |
|----|------|--------|
| 2a | sector_cap 도입 | 단일섹터 max 60% → 50% |
| 2b | correlation_filter | 상위 3종목 corr>0.8 시 1개 제외 |
| 2c | regime별 cap | VIX>30 시 sector_cap 40% |

**PASS 조건**
```yaml
gate:
  lockbox_mean: ">= 3.5"
  max_sector_exposure: "<= 0.55"
  turnover_increase: "<= 20%"
```

### PATCH-3: Cost Model 현실화 점검
**왜 필요한가**
- 현재 비용 모델 미확인 → 슬리피지/스프레드 과소 추정 위험
- 실전에서 backtest 대비 30-50% 성능 저하 일반적

**위험/부작용**
- 비용 과대 추정 시 불필요한 전략 폐기
- 실험 복잡도 증가

**최소 실험**
| ID | 실험 | 변경점 |
|----|------|--------|
| 3a | slippage 상향 | 0.05% → 0.10% |
| 3b | spread_model 추가 | 소형주 0.15%, 대형주 0.05% |
| 3c | turnover_penalty | 월간 회전율 100% 초과 시 -0.5% 패널티 |

**PASS 조건**
```yaml
gate:
  tuning_mean_with_cost: ">= 1.8"
  lockbox_mean_with_cost: ">= 3.0"
  cost_delta: "< 30% of gross return"
```

### PATCH-4: Signal Decay 분석 (누수 점검)
**왜 필요한가**
- tuning vs lockbox 성능 gap 존재 (2.32 vs 4.01)
- **역전 현상** → lockbox가 더 좋음 = 과거 데이터에 underfit 또는 regime shift

**위험/부작용**
- False positive: 단순 분산일 수 있음
- 과도한 수정 시 overfitting 유발

**최소 실험**
| ID | 실험 | 변경점 |
|----|------|--------|
| 4a | rolling_sharpe 분석 | 6개월 rolling으로 signal 유효성 확인 |
| 4b | decay_halflife 측정 | signal 발생 후 1/3/5/10일 수익률 |
| 4c | forward_purge 확대 | embargo 5일 → 10일 |

**PASS 조건**
```yaml
gate:
  tuning_lockbox_gap: "< 1.0 (absolute)"
  signal_decay_5d: "> 50% of day1"
  no_negative_contribution: "day3+"
```

### PATCH-5: Position Sizing Robustness
**왜 필요한가**
- fold14_mdd(-9.97%) 급락 → 특정 종목 과집중 의심
- 8~14 종목 중 1개가 -30% 시 포트 영향 과대

**위험/부작용**
- Equal weight 전환 시 alpha 희석
- 변동성 기반 sizing은 추가 파라미터 (overfitting 위험)

**최소 실험**

| 5b | vol_parity 도입 | 20일 vol inverse weighting |
| 5c | loss_cut 추가 | 종목 -15% 시 강제 청산 |

**PASS 조건**
```yaml
gate:
  single_stock_max_loss_contribution: "< 3%"
  fold14_mdd: ">= -0.07"
  sharpe_ratio: ">= 0.9 * champion"
```

## 3. 성능 미변동 시 원인 분해 트리

```
성능 안 움직임
│
├─[1] TRIGGER 미발동
│   ├─ signal 발생 빈도 확인 (trades_per_month < 2?)
│   ├─ threshold 너무 높음 → 조건 완화 실험
│   └─ 체크: `grep -c "SIGNAL_FIRED" logs/*.log`
│
├─[2] APPLY 적용 오류
│   ├─ 코드 버그: signal→order 변환 확인
│   ├─ position already maxed out
│   └─ 체크: `diff intended_orders.csv executed_orders.csv`
│
├─[3] EXPOSURE 부족
│   ├─ 현금비중 과다 (cash > 30%?)
│   ├─ position size 너무 작음
│   └─ 체크: `mean(daily_exposure)` / `max(daily_exposure)`
│
├─[4] COST 상쇄
│   ├─ gross return은 있으나 net ≈ 0
│   ├─ turnover 과다 (월 200%+)
│   └─ 체크: `gross_return - net_return` / `turnover_ratio`
│
└─[5] REGIME 불일치
    ├─ 현재 regime이 signal 무효 구간
    ├─ VIX/금리/달러 regime 태깅 확인
    └─ 체크: `performance_by_regime.groupby('vix_bucket').mean()`
```
