## TOP5 우선순위(24~48h) — 명령형 체크리스트(코드/아키텍처/전략)

### 1) **누수/서바이버십/데이터 타임라인 무결성부터 “게이트로 고정”**
**(a) 왜 필요한지**
- OOS가 “안 움직이는” 케이스에서 가장 흔한 원인이 **실험이 실제로 신호를 바꾼 게 아니라**(no-delta) 데이터/피처가 **같은 정보**를 계속 주거나, **미세 누수**로 인해 검증이 무감각해지는 것.
- Tech+Healthcare 8~14 종목은 표본이 작아 **서바이버십/리밸런스 타이밍 오차**가 성능을 통째로 왜곡.

**(b) 위험/부작용**
- 누수 게이트가 과격하면 실험이 대량 FAIL → 탐색 속도 저하.
- PIT(시점고정) 데이터 미구비 시 “완벽한” 해결이 아니라 **탐지/완화** 수준으로 제한.

**(c) 최소 실험(공용 실험 참조, 총 실험 수는 하단 5개로 제한)**
- **[E1] Leakage/Survivorship Audit Gate** 적용
- **[E3] Walk-forward + Purged split**로 재평가(시간 누수 차단)

**(d) PASS 조건**
- (게이트) 누수 의심 신호: `feature_time_shift_test`에서 성능이 **t+0 > t+1**로 유의미하게 우세하면 FAIL(누수 가능성).
- (성과) E3 기준 OOS mean이 챔피언 대비 **+0.15 이상** 또는 OOS min이 **개선(덜 음수)**.

---

### 2) **비용/체결/리밸런스 로그 “실제로 돌아가게” 복구 (현재 rebalance pinpoint가 깨짐)**
**(a) 왜 필요한지**
- 현재 상태에서 `aub_rebalance_pinpoint`가 **파일 경로/포맷 오류로 로그를 못 읽음** → 비용/턴오버/리밸런스 영향 분석이 사실상 불가.
- 비용 미반영은 Tech 대형주에서도 리밸런스 잦으면 **백테스트-실거래 괴리**가 커짐.

**(b) 위험/부작용**
- 비용 모델을 넣는 즉시 과거 성능이 “급락”할 수 있음(정상).
- 로그 스키마 변경이 파이프라인 호환성을 깨뜨릴 수 있음 → 버전필드 필요.

**(c) 최소 실험**
- **[E2] Rebalance log 스키마 고정 + 비용모델 on/off A/B**
- **[E4] Turnover cap(턴오버 상한) + 단일종목 캡**으로 비용 민감도 테스트

**(d) PASS 조건**
- (운영) 48h 루프 내 모든 런에서 `rebalance.jsonl`(또는 csv) 생성 및 파서 통과(에러 0).
- (성과) 비용 ON에서 OOS mean이 비용 OFF 대비 **-20% 이내**로만 감소(=전략이 비용에 과도하게 취약하지 않음) + turnover 상한 적용 시 OOS min 악화 없음.

---

### 3) **과최적화/검증 붕괴(현재 degenerate_folds 다수)부터 차단**
**(a) 왜 필요한지**
- `degenerate_folds: [1,2,3,8]`는 교차검증 일부 폴드가 **무거래/동일포지션/상수예측** 등으로 붕괴했다는 신호일 확률이 큼 → 평균 OOS가 의미 없어짐.
- “no-delta”가 떠도 실제론 **평가가 둔감**해서 실험 차이를 못 보는 상황 가능.

**(b) 위험/부작용**
- 폴드 기준 강화(최소 거래수/변동성/노출)하면 데이터가 줄어 성능 변동 커질 수 있음.
- Purged split은 학습 데이터 감소로 단기 성능 하락 가능.

**(c) 최소 실험**
- **[E3] Purged walk-forward + 폴드 유효성 게이트(최소 거래수/노출/변동성)**
- **[E1] “라벨/피처 시프트” 리그레션 테스트**를 CV 앞단에 배치(누수·과최적화 동시 탐지)

**(d) PASS 조건**
- degenerate_folds **0** 달성(또는 전체 폴드의 90% 이상 유효).
- worst_mdd가 **None이 아닌 값**으로 산출(리포트 완결성).
- OOS 분산(폴드 간)이 기존 대비 **감소**(불안정 과최적화 완화).

---

### 4) **운영 리스크(재현성/해시/설정 적용) 해결: “실험이 적용됐는지”를 증명**
**(a) 왜 필요한지**
- 현재 `lane_hash/run_hash: None` → **동일 설정 재현/추적 불가**.
- no-delta가 반복될 때 가장 먼저 확인할 것: **실험 파라미터가 실제로 런타임에 반영됐는지**.

**(b) 위험/부작용**
- 해시/매니페스트 강제는 “귀찮은 엄격함”을 유발하지만, 자동루프에는 필수.
- 설정 호환성 문제로 초기 FAIL 증가 가능.

**(c) 최소 실험**
- **[E2] 로그 스키마에 config_digest / code_commit / data_snapshot_id 강제 기록**
- **[E1] 입력 데이터/피처셋 체크섬 + 예측분포 체크섬**을 런마다 저장(변화 없으면 즉시 FAIL)

**(d) PASS 조건**
- 모든 런에서 `run_hash != None`, `lane_hash != None`, `config_digest` 존재.
- “변경 실험”에서 예측분포 체크섬/포지션 시계열 체크섬이 **기준 대비 변화**(완전 동일이면 FAIL).

---

### 5) **전략 레짐/노출(ETF는 지표로만)로 8~14 종목 포트의 ‘급락 구간’ 방어**
**(a) 왜 필요한지**
- Tech+Healthcare 소수 종목은 레짐(리스크온/오프)에 민감 → OOS min이 음수로 찍히는 구간을 **노출 스케일링**으로 완화해야 함.
- ETF는 매매 금지지만 **관측지표**로는 강력(예: QQQ, XLV, IWM, TLT, VIX 대용지표).

**(b) 위험/부작용**
- 레짐 게이트는 타이밍 실패 시 수익 상단을 깎음.
- 지표가 많아지면 룰이 복잡해져 과최적화 위험 → 1~2개 지표로 제한.

**(c) 최소 실험**
- **[E5] ETF 관측지표 기반 노출 스케일링(매매 없음)**  
- **[E4] 포트 제약(섹터 균형/단일종목 캡/최소 8종목 유지) + 노출 상한** 결합

**(d) PASS 조건**
- OOS min(최악 구간 수익)이 챔피언 대비 **개선**(덜 음수) + OOS mean 손실이 **-0.10 이내**.
- max exposure가 0.84 수준에서 **규정 상한(예: 0.70~0.80)**으로 안정화되며 성과 크게 훼손 없음.

---

## 48시간 자동 루프용 “실행 가능한” 공용 Patch/Experiment 5개 (총 3~5개 제한 준수)

아래 5개만 돌리고, 위 TOP5 제안은 이 5개를 조합해 검증하도록 고정.

### [E1] Leakage/Survivorship Audit Gate (패치 + 자동 실패)
1) **실험 정의**
- 모든 피처에 대해 `t` vs `t-1` 시프트 성능 비교(간이 누수탐지)
- 종목 유니버스(Tech+Healthcare 8~14) 고정 시점 리스트 + 상장폐지/합병 처리 룰 점검(가능 범위에서)
- 런 산출물: `feature_checksum`, `pred_checksum`, `position_checksum`

2) **게이트(FAIL 조건)**
- 시프트 테스트에서 `t`가 `t-1` 대비 유의미하게 우월(임계값 설정: OOS mean +0.20 이상)하면 FAIL
- 체크섬이 “실험 변경인데도” 동일하면 FAIL(=no-delta 확정)

3) **기대 관측치**
- 누수/실험 미적용 케이스를 조기에 컷 → “성능이 안 움직이는 이유”를 즉시 분류 가능

---

### [E2] Rebalance 로그 복구 + 비용 모델 A/B
1) **실험 정의**
- `rebalance.jsonl` 표준 스키마 고정: timestamp, symbol, target_w, prev_w, delta_w, price, shares, notional, est_spread, est_slippage, fee, realized_cost
- 비용 모델 토글: OFF / ON(고정 스프레드+슬리피지 간단모델)

2) **게이트**
- 리밸런스 로그 파싱 실패 1회라도 발생 시 FAIL
- 비용 ON에서 turnover가 비정상 급증(기준 대비 +50% 이상) 시 FAIL(로깅/계산 버그 가능성)

3) **기대 관측치**
- pinpoint 리포트가 정상 생성되고, “성과 변화가 비용인지/신호인지” 분해 가능

---

### [E3] Purged Walk-forward + 폴드 유효성(degenerate 제거)
1) **실험 정의**
- purged walk-forward(룩어헤드 차단) + embargo 적용
- 폴드 유효성 기준: 최소 거래수, 평균 노출, 포지션 변화율, 수익률 분산 하한

2) **게이트**
- degenerate_folds > 0 이면 FAIL
- worst_mdd 산출 불가(None)면 FAIL

3) **기대 관측치**
- “검증이 무너져서 차이를 못 보는” 상태를 제거 → 실험 간 델타가 살아남

---

### [E4] 포트폴리오 제약(운영/비용/리스크 동시 완화)
1) **실험 정의**
- 종목 수 8~14 강제
- 단일종목 최대 비중(예: 12~15%), 섹터(Tech/Healthcare) 편중 상한
- 턴오버 상한(리밸런스 델타 총합 제한), 노출 상한

2) **게이트**
- 제약 위반 0건(리밸런스 로그 기준)
- turnover 상한 적용 후 거래가 “0에 수렴”하면 FAIL(전략 사망)

3) **기대 관측치**
- 비용과 급락 리스크 동시 감소, 실거래 가능성 상승

---

### [E5] 레짐(ETF는 지표로만) 기반 노출 스케일링
1) **실험 정의**
- 관측지표: QQQ(테크), XLV(헬스케어) 상대강도 + 변동성 대용(예: VIX proxy 또는 SPY 단기 변동)
- 조건 충족 시 총 노출을 1.0 → 0.5/0.0로 스케일(현금 비중 증가), ETF 매매는 금지

2) **게이트**
- 레짐 신호가 지나치게 잦은 토글(예: 10영업일 내 4회 이상) 발생 시 FAIL(노이즈 과민)

3) **기대 관측치**
- OOS min 및 MDD 개선(특히 테크 급락 구간), 평균 수익은 소폭 희생

---

## 성능이 “안 움직일 때” 원인 분해 아이디어 (Trigger → 적용 → 노출 → 비용 → 레짐)

아래 순서대로 로그/지표를 강제 산출하고, 해당 단계에서 **증거가 없으면 다음 단계로 진행**하도록 고정.

1) **Trigger(실험 변화가 생겼나?)**
- `config_digest`, `feature_checksum`, `pred_checksum`, `position_checksum` 비교
- **변화 없음** → (A) 설정 미적용 (B) 코드 경로 미사용 (C) 캐시 재사용/고정시드 오류

2) **적용(신호가 실제 포지션으로 갔나?)**
- 예측분포(평균/분산), 랭크, 임계값 통과 건수
- 타깃 웨이트 분포(상위/하위), “0 비중 비율”
- **예측은 변했는데 포지션이 동일** → 포트 제약/클립/정규화에서 소거되는 중

3) **노출(리스크 예산이 달라졌나?)**
- gross/net exposure, single-name max, sector exposure(Tech/Healthcare), cash %
- **노출이 항상 0 또는 상한에 붙음** → 전략이 사실상 “스위치”로만 동작(중간영역 부재)

4) **비용(성과가 비용에 잠식되나?)**
- turnover, 거래 횟수, 평균 스프레드/슬리피지 추정, 비용/총수익 비율
- **비용 비중이 높으면** → (a) 리밸런스 주기 완화 (b) turnover cap (c) 신호 스무딩/히스테리시스

5) **레짐(언제 죽는가?)**
- 레짐 라벨(리스크온/오프)과 성과의 조건부 평균
- Tech vs Healthcare 상대강도 구간에서의 성능 분해
- **특정 레짐에서만 음수** → E5 같은 노출 스케일링이 1순위 처방

---

## 즉시 처리(운영 핫픽스) — 오늘 안에 끝내기
- `aub_rebalance_pinpoint.py` 입력 경로를 “실제 생성되는 리밸런스 로그”로 단일화하고, 생성 포맷을 jsonl로 고정하라.
- 챔피언/후보 아티팩트에 `run_hash/lane_hash/config_digest/code_commit/data_snapshot_id`를 필수 필드로 넣고, 누락 시 런을 FAIL 처리하라.
- 리포트에서 `worst_mdd=None`이 발생하면 평가 파이프라인을 FAIL 처리하고, MDD 계산 경로를 우선 복구하라.

위 5개(E1~E5)만 48시간 자동 루프로 고정 실행하면, “안 움직임”의 80%는 **(1) 실험 미적용/no-delta**, **(2) 검증 붕괴(degenerate folds)**, **(3) 비용/리밸런스 로그 부재** 중 하나로 빠르게 분류되고, 그 다음에야 신호/전략 개선이 의미 있게 진행된다.
