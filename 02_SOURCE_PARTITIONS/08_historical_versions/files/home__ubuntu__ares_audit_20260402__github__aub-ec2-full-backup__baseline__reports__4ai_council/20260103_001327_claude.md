## 0. 즉시 수정 필요 (Blocking Issues)

```
[CRITICAL] 현재 상태 분석
├─ degenerate_folds: [1,2,3,8] → 4/10 폴드 퇴화 = 40% 실패율
├─ oos_min: -0.0257 → 음수 폴드 존재 (과최적화 시그널)
├─ worst_mdd: None → MDD 계산 누락 (위험 모니터링 불가)
├─ rebalance.csv 로드 실패 → 리밸런싱 검증 불가
└─ lane_hash/run_hash: None → 실험 추적 불가능
```

## 1. 우선순위 TOP 5 액션

### ▶ P1. 퇴화 폴드 근본 원인 격리

| 항목 | 내용 |
|------|------|
| **(a) 필요성** | 4개 폴드 퇴화 = 신호 자체가 특정 레짐에서만 작동. 이대로 배포 시 40% 확률로 손실 |
| **(b) 위험** | 폴드별 튜닝 시 과최적화 심화 가능 |
| **(c) 실험** | 아래 참조 |
| **(d) PASS** | `degenerate_folds ≤ 1` AND `oos_min > 0` |

```yaml
EXP-P1-A:
  name: "fold_regime_tag"
  action: |
    각 폴드 기간에 VIX_level, SPY_trend, sector_rotation 태그 부여
    퇴화폴드 공통점 추출 (예: VIX>25, Tech underperform 구간?)
  gate: 공통 패턴 1개 이상 식별
  observe: fold_{1,2,3,8}_regime_overlap_ratio

EXP-P1-B:
  name: "min_signal_threshold"
  action: |
    alpha_signal < threshold 일 때 포지션 스킵
    threshold = [0.01, 0.02, 0.03] 그리드
  gate: degenerate_folds <= 2
  observe: oos_mean, oos_min, skip_rate_per_fold

EXP-P1-C:
  name: "adaptive_exposure_cap"
  action: |
    퇴화폴드 기간의 exposure_max 분석
    exposure > 0.5 구간에서 손실 집중 여부 확인
  gate: exposure-return 상관 < -0.3 이면 cap 0.5 적용
  observe: per_fold_exposure_return_corr
```

### ▶ P5. OOS Min 음수 원인 격리

| 항목 | 내용 |
|------|------|
| **(a) 필요성** | `oos_min: -0.0257` → 최소 1개 폴드 손실. 전략 robustness 의문 |
| **(b) 위험** | 해당 폴드 제거 시 서바이버십 바이어스 |
| **(c) 실험** | 아래 참조 |
| **(d) PASS** | `oos_min > 0` OR 음수 원인 문서화 + 헷지 로직 |

```yaml
EXP-P5-A:
  name: "negative_fold_decompose"
  action: |
    oos_min 폴드 식별 → 해당 기간 trade log 추출
    - 어떤 종목에서 손실?
    - 진입 시점 신호 강도?
    - 섹터 집중도?
  gate: 손실 원인 1개 이상 특정
  observe: worst_trades_top5, sector_concentration, signal_strength_at_entry

EXP-P5-B:
  name: "volatility_filter"
  action: |
    개별 종목 ATR > 상위 20% 시 position size 50% 축소

  observe: oos_min, oos_mean, filtered_trade_count
```

## 3. 48h 자동 루프 YAML

```yaml
# autopilot_48h.yaml
schedule: "0 */12 * * *"  # 12시간마다
timeout_hours: 48

stages:
  - name: blocking_fix
    run:
      - EXP-P2-A  # MDD 복구
      - EXP-P3-A  # 로그 포맷
      - EXP-P4-A  # 해시 복구
    gate: all_pass
    on_fail: alert + halt

  - name: robustness
    run:
      - EXP-P1-A
      - EXP-P1-B
      - EXP-P5-A
    gate: degenerate_folds <= 2 AND oos_min > -0.01
    on_fail: continue + log

  - name: cost_validation
    run:
      - EXP-P3-B
    gate: cost_adjusted_oos > 2.0
    on_fail: reduce_turnover_experiment

promotion_rule:
  require:
    - degenerate_folds <= 1
    - oos_min > 0
    - worst_mdd < 15%
    - cost_adjusted_oos > 2.5
    - lane_hash != None
```
