## 0) 24~48시간 운영 원칙(고정 체크리스트)
- **누수(lookahead/label leakage) → 과최적화(CV/선정편향) → 서바이버십 → 비용(슬리피지/수수료/체결) → 운영 리스크(로깅/재현성)** 순서로 먼저 막아라.
- **미국주식 only**, **Tech+Healthcare 중심 8~14 종목**으로 유니버스/리밸런스/노출을 강제하라. (ETF는 **관측지표**로만 사용)

- “성능이 안 움직임”은 대부분 **(a) 실험이 실제로 적용 안 됨 (b) 노출/턴오버가 게이트에 막힘 (c) 비용 반영으로 알파가 상쇄 (d) 누수 제거로 정상화 (e) 레짐 변화** 중 하나다.

# [E1] Rebalance/Trade 로그 표준화 패치 (TOP1 중심, TOP2~4 지원)
## (1) 실험 정의
- 백테스트/실거래 공통으로 **리밸런스 단위 이벤트를 JSONL로 강제 기록**:
  - timestamp, universe(티커리스트), target_weight, pre_weight, order_qty, fill_price(또는 bar close), realized_slippage, fees, turnover, exposure, cash, reason_code(게이트/리밸런스 트리거)
- `aub_rebalance_pinpoint` 입력을 **단일 스키마로 고정**하고, 현재처럼 `--base-log`가 파일 경로가 아닌 문자열로 들어가 실패하는 케이스를 차단(인자 검증).

## (2) 게이트
- 리포트 생성 시 **rebalance 로그 로드 성공률 100%**.
- 각 런(run_hash)마다 리밸런스 이벤트 수, 평균턴오버, 비용 합계가 **NaN/빈값 없이** 채워질 것.

## (3) 기대 관측치
- “성능 무변화” 케이스에서 실제로는 **리밸런스가 0회**였거나, 반대로 **과도한 턴오버**였는지 즉시 분해 가능.

### TOP1에 대한 (c) 최소 실험 2~3개 매핑
- E1-1: `rebalance.csv/jsonl` **동시 출력** + 스키마 검증(파싱 테스트 포함)
- E1-2: `--base-log/--cand-log` **인자 유효성 검사**(파일 없으면 즉시 FAIL)
- E1-3: 리밸런스 이벤트에 **reason_code(게이트/리스크/유니버스 변경)** 기록

### TOP1 PASS 조건
- `rebalance_pinpoint.md`가 **빈 리포트 없이 생성**되고,
- base/cand 모두 **리밸런스 요약(횟수/턴오버/비용/노출)** 테이블이 채워질 것.

# [E2] 거래비용/턴오버 “강제 반영 + 게이트” (TOP2 중심, TOP1/5 지원)
## (1) 실험 정의
- 비용 모델 최소 버전(보수적)부터 고정:
  - 슬리피지 = k1 * 일중변동(예: ATR%) + k2 * 스프레드(프록시) + k3 * 체결지연(1 bar)
  - 수수료 고정(브로커 수수료/SEC fee 단순화)
- 최적화/평가 지표를 **gross→net으로 전환**하고,
- 턴오버/거래횟수에 상한을 두는 **운영 게이트**를 추가.

## (2) 게이트
- Net 성과가 Gross 대비 과도하게 붕괴하면(예: net/gross < 임계치) 자동 FAIL.
- 평균 턴오버(예: 일/주 단위) 상한 초과 시 FAIL.

## (3) 기대 관측치
- “OOS mean 개선이 안 보임”이 **비용으로 상쇄**인지, **알파가 원래 없었는지** 분리된다.
- Tech/HC 소수종목에서 특히 **턴오버 억제 → MDD/성능 안정화**가 관측될 가능성.

### TOP2에 대한 (c) 최소 실험 2~3개 매핑
- E2-1: **1-bar execution delay** 강제(lookahead/체결 환상 제거도 겸함)
- E2-2: 보수적 슬리피지(ATR% 기반) 2단계 스윕(낮음/높음)
- E2-3: 턴오버 상한 게이트(예: 리밸런스당 총 거래비중 상한)

### TOP2 PASS 조건
- Net OOS mean이 기존 대비 **유의미하게 유지/개선**(최소: net이 gross 대비 “붕괴하지 않음”),
- worst-case 구간에서 **턴오버/비용이 감당 가능한 범위**로 기록될 것(로그로 증명).

# [E3] 누수/서바이버십 자동 감사 하네스 (TOP3 중심, TOP2/4 지원)
## (1) 실험 정의
- 아래 3종 “파괴 테스트”를 자동으로 돌려 누수/선정편향을 탐지:
  1) **Feature lag 강제(+1 bar, +2 bar)**: 성능이 비정상적으로 유지되면 누수 의심
  2) **Label/타임 셔플 테스트**: 성능이 남아있으면 데이터 누수/파이프라인 버그
  3) **Point-in-time 유니버스 스냅샷**: “현재 생존 종목”만 쓰는지 차단(Tech/HC 8~14 고정 룰 포함)

## (2) 게이트
- 셔플 테스트 성과는 **랜덤 수준으로 붕괴**해야 PASS.
- lag(+1/+2)에서 성과가 **단조 감소**하는 방향성이 나와야 PASS.
- 유니버스가 항상 **8~14**, Tech/HC 비중 규칙 위반 시 즉시 FAIL.

## (3) 기대 관측치
- “Champion이 갑자기 좋아졌다/안 좋아졌다”가 **누수 제거/유니버스 변경** 때문인지 빠르게 판별 가능.

### TOP3에 대한 (c) 최소 실험 2~3개 매핑
- E3-1: lag +1 bar 강제 런
- E3-2: 날짜 셔플(또는 라벨 셔플) 런
- E3-3: point-in-time 유니버스 강제 + 8~14 종목 제약 위반 감지

### TOP3 PASS 조건
- 셔플 성과 붕괴(랜덤 수준),
- lag 증가 시 성과 저하,
- 유니버스/섹터 제약 100% 준수(로그로 증명).

# [E4] Purged/Embargo WFA + 안정성 게이트 (TOP4 중심, TOP3 지원)
## (1) 실험 정의
- 시간누수 방지용 **purged walk-forward CV + embargo**로 평가를 고정.
- fold별 성과 분산/최악폴드/드로우다운을 “승자폴드만 보고 채택”하지 못하도록 게이트화.
- degenerate fold(데이터 부족/거래 0회 등) 발생 시 즉시 FAIL.

## (2) 게이트
- fold 최솟값(oos_min)이 바닥을 치면 FAIL(최소 성과 하한).
- fold 간 분산이 과도하면 FAIL(안정성).
- degenerate_folds 발생 시 FAIL.

## (3) 기대 관측치
- “개선이 안 보임”은 정상일 수 있음(과최적화 제거로 수렴).
- 대신 **최악폴드 개선/분산 축소**가 관측되면 ‘실전성’이 올라간다.

### TOP4에 대한 (c) 최소 실험 2~3개 매핑
- E4-1: purged+embargo WFA로 재평가
- E4-2: “최악폴드/분산” 안정성 게이트 추가
- E4-3: 거래 0회/리밸런스 0회 fold를 degenerate로 정의하고 자동 FAIL

### TOP4 PASS 조건
- 평균만이 아니라 **oos_min(최악폴드)**이 악화되지 않거나 개선,
- degenerate_folds = [] 유지,
- 분산(폴드 표준편차) 감소.

# [E5] ETF 지표 기반 레짐 노출 스케일(관측만) (TOP5 중심, TOP2/4 지원)
## (1) 실험 정의
- ETF는 매매하지 않고 **상태변수로만 사용**:
  - 예: QQQ 모멘텀/변동성, XLV 상대강도(Tech vs HC), IEF(금리 리스크) 모멘텀, VIX proxy(변동성)
- 상태에 따라 **주식 포트 노출(총 익스포저)만 스케일**:
  - risk-off이면 exposure를 낮추고, risk-on이면 올림
  - 단, 8~14 종목 구성은 유지(현금 비중으로 조절)

## (2) 게이트
- 노출 스케일로 인해 턴오버가 급증하면 FAIL(E2 게이트와 연동).
- 노출이 특정 구간에서 0/1로 붙는 이산화가 심하면 FAIL(운영 안정성).

## (3) 기대 관측치
- 레짐 전환 구간에서 **MDD 감소 / 최악폴드 개선**이 먼저 나타나고,
- 평균 성과는 천천히 반응(“no-delta”라도 리스크 지표가 개선되면 전진).

### TOP5에 대한 (c) 최소 실험 2~3개 매핑
- E5-1: QQQ 모멘텀/변동성 기반 exposure 2단계(예: 0.5 / 0.8)
- E5-2: XLV/QQQ 상대강도로 Tech/HC 내부 비중이 아니라 **총 노출만** 스케일(구성종목 수는 유지)
- E5-3: VIX proxy 급등 시 “리밸런스 빈도 제한 + 노출 하향” 결합

### TOP5 PASS 조건
- worst-case MDD 또는 oos_min이 개선(평균이 그대로여도 PASS 가능),
- 비용/턴오버 게이트(E2)를 깨지 않음,
- 노출 분포가 “너무 극단적”으로 쏠리지 않음.

## 3) “성능이 안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래를 **트리 형태로 순서대로 자르기**(명령형).

### A. 트리거(리밸런스가 실제로 발생했나?)
- **리밸런스 이벤트 수**를 base vs cand로 비교하라.
- 이벤트가 0에 가깝다면:  
  - (원인) 게이트가 너무 빡빡 / 트리거 조건이 안 맞음 / 데이터 결측으로 신호가 NaN  
  - (조치) E1 로그에 reason_code로 “왜 안 했는지”를 남겨라.

### B. 적용(패치가 실험에 반영됐나? / 설정이 먹었나?)
- run_hash 단위로 **config diff + checksum(피처 리스트/유니버스/비용모델)**를 저장하라.
- 성능이 동일하면 먼저 “코드가 안 돌아간 것”을 의심하고, E1로 증거를 남겨라.

### C. 노출(포지션/익스포저가 바뀌었나?)
- (핵심 지표) 평균 노출, 노출 min/max, 현금비중, 종목 수(항상 8~14), 상위 3종목 집중도
- 성능이 안 움직이는데 노출도 안 변하면:  
  - (원인) 신호는 변했지만 포트폴리오 최적화/제약에서 눌림  
  - (조치) E5(노출 스케일) 또는 제약 로그(왜 클리핑됐는지) 추가

### D. 비용(알파가 비용으로 상쇄됐나?)
- gross→net 브리지 지표를 항상 찍어라:
  - gross pnl, slippage, fees, net pnl, turnover
- gross 개선인데 net 동일이면:  
  - (원인) 턴오버/슬리피지 폭증  
  - (조치) E2 턴오버 게이트 + 실행지연(1 bar)로 현실화

### E. 레짐(시장이 바뀌어 신호가 무력화됐나?)
- ETF 관측 지표로 레짐 태깅:
  - QQQ 추세/변동, XLV 상대강도, 금리(IEF) 추세, 변동성 급등 구간
- 개선안이 특정 레짐에서만 먹으면:  
  - (조치) E5로 레짐별 노출만 조절(매매대상은 주식 8~14 유지)

## 4) 24~48시간 실행 순서(명령형)
1) **E1 먼저**: 리밸런스/거래 로그를 JSONL로 표준화하고 `rebalance_pinpoint`가 100% 돌아가게 고쳐라.  
2) **E2 즉시 결합**: 1-bar 지연 + 보수적 슬리피지 2단계 + 턴오버 상한 게이트를 걸어 net 기준으로 재평가하라.  
3) **E3로 누수/서바이버십 파괴 테스트**를 자동 루프에 넣고, FAIL이면 그 어떤 성능 개선도 채택하지 마라.  
4) **E4로 과최적화 방지 평가체계**를 고정하고, 평균이 아니라 최악폴드/분산을 채택 기준에 올려라.  
5) **E5는 마지막에**: 레짐 지표 기반 노출 스케일만 추가해 MDD/oos_min 개선을 먼저 노려라.

이렇게 하면 “no-delta” 상태가 나와도, **(적용 실패 / 리밸런스 부재 / 비용 상쇄 / 누수 제거로 정상화 / 레짐 미스매치)** 중 어디에 있는지 48시간 내에 로그로 갈라진다.
