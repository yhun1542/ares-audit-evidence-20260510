## 24~48시간 TOP5 우선순위(명령형 체크리스트)
> **원칙:** 누수/과최적화/서바이버십/비용 미반영/운영 리스크를 먼저 부숴서 “락박스가 안 움직이는 이유”를 제거한 뒤, **Tech+Healthcare 8~14개** 집중 포트폴리오가 **비용 포함**으로도 버티는지 확인하라.  
> 아래는 **유니크 실험 5개(E1~E5)**만 만들고, 각 우선순위는 그중 **2~3개를 재사용**해서 조건을 만족시킨다(케이스 폭발 방지).

# 공통 PASS 조건(모든 실험에 동일 적용)
- **락박스 평균(lockbox_mean)**: 현 챔피언(1.7927) 대비 **+0.03 이상**(≥ **1.8227**)  
- **락박스 최저(lockbox_min)**: 현 챔피언(1.3469) 대비 **-0.03 이내**(≥ **1.3169**)  
- **최악 MDD(worst_mdd)**: 현 챔피언(-0.1118) 대비 **악화 -0.01 이내**(≥ **-0.1218**)  
- **운영 게이트:** 재현성(동일 seed/동일 데이터 스냅샷에서 결과 동일) + 실패 시 원인 로그가 남을 것

# TOP1) 데이터 누수/시점오류(lookahead) “0으로” 만들기
### (a) 왜 필요한지
- 현재 **락박스가 고정적으로 비슷**하게 나오는데, 이 패턴은 (1) 정보가 이미 정제돼 과하게 보수적이거나 (2) 반대로 **시점 누수로 튜닝이 의미 없게** 되는 경우에 자주 나타난다.
- 특히 Tech/Healthcare는 이벤트(실적, 임상, 가이던스) 영향이 커서 **EOD에서 다음날 체결을 가정할 때 shift 누수**가 흔하다.

### (b) 위험/부작용
- 누수 제거 후 성능이 떨어질 수 있음(“진짜 성능”이 드러남).
- 피처/라벨 시프트를 바꾸면 기존 최적화 파라미터가 무의미해져 단기 혼란.

### (c) 최소 실험(2~3개) — 아래 유니크 실험 재사용
- **E3(누수 유닛테스트+강제 lag)**  
- **E1(서바이버십/상장폐지/코퍼레잇액션 PIT 검증)**

### (d) PASS 조건
- 공통 PASS 조건 + **누수 테스트 100% 통과(실패 0건)**  
- 튜닝↔락박스 괴리가 줄어드는 방향(과최적화 완화 신호)

---

# TOP2) 서바이버십/상폐/병합/IPO 처리(포인트-인-타임) 고정
### (a) 왜 필요한지
- 8~14개 집중 포트폴리오는 **상폐/거래정지/인수합병**이 손익과 운영에 치명적.
- Tech/Healthcare(특히 바이오)는 상폐/급락/거래중단이 잦아 **서바이버십 편향**이 성능을 과대평가하기 쉽다.

### (b) 위험/부작용
- PIT 유니버스가 좁아져 트레이드 수 감소 → 성능 하락처럼 보일 수 있음.
- 데이터 소스/정합성 이슈가 드러나면 파이프라인이 일시적으로 깨질 수 있음.

### (c) 최소 실험(2~3개)
- **E1(PIT 유니버스 + 상폐 수익률/현금정산 규칙 적용 비교)**  
- **E2(비용/유동성까지 포함해 상폐 근처 구간의 현실성 점검)**

### (d) PASS 조건
- 공통 PASS 조건 + **상폐/병합 케이스에서 포트폴리오가 “중단 없이” 끝까지 시뮬 완료**(운영 게이트)
- 상폐 이벤트가 있는 기간에서 비정상 체결(무한 슬리피지/0 유동성 체결)이 0건

---

# TOP3) 비용/유동성/회전율을 “락박스에 반영” (현재 정체의 최우선 원인 후보)
### (a) 왜 필요한지
- 락박스가 안 움직이는 가장 흔한 이유: 알파가 미세한데 **비용이 미반영/과소반영**되어 후보 간 차이가 사라지거나, 실제로는 비용이 다 깎아먹는다.
- 8~14개 집중 + Tech 변동성 → **회전율**이 조금만 늘어도 성능이 급감.

### (b) 위험/부작용
- 거래 비용을 현실화하면 백테스트 지표가 즉시 나빠질 수 있음(그러나 필수).
- 유동성 제한으로 트레이드가 줄면서 샤프류가 흔들릴 수 있음.

### (c) 최소 실험(2~3개)
- **E2(거래비용+슬리피지+유동성 캡+턴오버 패널티 on/off A/B)**  
- **E4(포지션/리스크 제약으로 회전율을 구조적으로 제한)**

### (d) PASS 조건
- 공통 PASS 조건 + **턴오버 상한을 걸었을 때도 성능이 유지**(알파가 “거래로만” 나오는 게 아님을 확인)
- 비용 민감도: 비용 파라미터를 보수적으로 올려도(예: 슬리피지 2배) lockbox_mean 급락이 제한적

---

# TOP4) 과최적화(튜닝 민감도) 완화: “단순하지만 강한 제약”으로 고정
### (a) 왜 필요한지
- 후보 성능이 튜닝에서 흔들리고 락박스가 비슷하면, 파라미터가 알파가 아니라 **노이즈에 맞춰진** 가능성이 큼.
- 집중 포트폴리오는 제약이 없으면 특정 팩터/종목에 과도하게 쏠려 “한두 번 맞고 끝” 패턴이 난다.

### (b) 위험/부작용
- 제약이 과하면 알파 자체를 눌러버릴 수 있음(너무 낮은 자유도).
- “좋아 보이던” 전략이 사라질 수 있음(정상).

### (c) 최소 실험(2~3개)
- **E4(8~14개 강제 + 섹터(Tech/Healthcare) 내 캡 + 단일종목 max + 변동성 타깃/리밸런스 캡)**  
- **E3(피처 lag 강제 후에도 동일 제약에서 유지되는지 확인)**

### (d) PASS 조건
- 공통 PASS 조건 + **파라미터 스윕에서 성능 곡면이 평탄해짐**(best-2nd gap 축소, fold 간 분산 감소)
- worst_mdd 악화 없이 fold14_mdd가 개선 또는 동일 수준 유지

---

# TOP5) 레짐/노출(Tech vs Healthcare) “관측지표(ETF)로만” 분리하고, 신호 적용을 게이트로 묶기
### (a) 왜 필요한지
- Tech와 Healthcare는 **레짐이 다르게** 움직이며(금리/리스크온/리스크오프), 단일 알파로 같이 굴리면 성능이 상쇄되기 쉽다.
- ETF는 매매 금지지만, **레짐 관측 지표**로는 매우 유용(예: QQQ, XLV, VIX).

### (b) 위험/부작용
- 레짐 필터가 과하면 거래 기회가 줄어 “기대수익 감소”.
- 레짐 신호 자체가 누수/지연 처리 잘못되면 역효과.

### (c) 최소 실험(2~3개)
- **E5(ETF 관측지표 기반 레짐 스코어 → gross/섹터비중 게이트)**  
- **E2(레짐 전환 구간에서 비용/슬리피지 확대를 같이 반영해 현실성 확보)**

### (d) PASS 조건
- 공통 PASS 조건 + **레짐별 성능 분해에서 최악 레짐 성능 개선**(락박스 min/최악 MDD 방어)
- 레짐 필터 on/off 비교에서 “비용 포함” 기준으로 우위

---

## 유니크 실험 5개(E1~E5): 48시간 자동 루프 형태(정의 → 게이트 → 기대 관측치)

### E1) PIT 유니버스 + 상폐/CA 처리 패치
1) **실험 정의**
- 백테스트 입력 유니버스를 **포인트-인-타임**으로 고정(당시 존재 종목만).
- 상폐/병합/거래정지 시 **정산 규칙**(현금정산/마지막 거래가/상폐 수익률 데이터) 명시.
2) **게이트**
- 상폐 케이스 포함 기간에서 **시뮬 중단 0건**
- 상장폐지일 이후 가격 사용(lookahead) **탐지 시 즉시 FAIL**
3) **기대 관측치**
- 성능이 떨어지더라도 **MDD/꼬리위험이 현실화**되어 후보 간 변별력이 생김(락박스가 “움직이기” 시작)

---

### E2) 비용/유동성/턴오버 현실화 패치
1) **실험 정의**
- 비용 모델: 커미션+슬리피지(스프레드/ATR 기반 중 택1) + **ADV 대비 참여율 캡** + 리밸런스 빈도/턴오버 패널티.
2) **게이트**
- 주문 크기 > ADV 참여율 상한이면 **체결 축소/분할 규칙** 강제(무제한 체결 금지)
- 비용 파라미터 2배 스트레스에서도 **결과 NaN/폭주 0건**
3) **기대 관측치**
- 후보 간 차이가 비용에서 갈리며, “락박스 정체”가 비용 미반영 때문인지 바로 드러남

---

### E3) 누수 방지 유닛테스트 + 피처 lag 강제 패치
1) **실험 정의**
- 모든 피처를 `t`에서 계산 시 **최소 t-1 데이터만 사용** 강제(룰 기반).
- 라벨/체결 가정(예: next open/close)을 코드 레벨에서 명시하고 일관화.
2) **게이트**
- (a) 피처-타겟 상관이 비정상적으로 높아지는 케이스 탐지 (b) shift 검사 (c) 미래 인덱스 참조 탐지 → 하나라도 걸리면 FAIL
3) **기대 관측치**
- 튜닝 점수는 하락 가능, 대신 락박스 신뢰도 상승 + 과최적화 신호 감소

---

### E4) 8~14개 집중 포트폴리오 제약 + 리스크 오버레이 패치
1) **실험 정의**
- 보유 종목 수 8~14 강제, 단일 종목 max, 섹터(Tech/Healthcare) 내 비중 캡, 변동성 타깃(또는 beta 타깃), 리밸런스/포지션 변경 캡.
2) **게이트**
- 제약 위반 0건(테스트에서 자동 검증)
- 회전율 상한 초과 시 주문 축소/스킵(운영 규칙 일관)
3) **기대 관측치**
- worst_mdd가 개선되거나 최소한 악화하지 않으면서 lockbox_mean이 안정화

---

### E5) 레짐 게이트(ETF는 관측만) 패치
1) **실험 정의**
- 관측지표(매매 금지): QQQ, XLV, (가능하면 VIX 또는 금리 ETF)로 레짐 스코어 산출  
  → 레짐에 따라 **총 익스포저(gross) 또는 Tech/Healthcare 비중**만 조절(개별 종목 선택 로직은 유지).
2) **게이트**
- ETF 데이터도 **t-1까지**만 사용(누수 금지)
- 레짐 on/off A/B가 동일 비용 모델(E2) 하에서 비교되도록 고정
3) **기대 관측치**
- 특정 레짐에서 망가지는 구간이 줄어 lockbox_min/최악 MDD가 개선

# 성능이 안 움직일 때 “원인 분해” 아이디어(트리거/적용/노출/비용/레짐)
아래 분해를 **항상 같은 포맷의 리포트로 자동 생성**해 “왜 락박스가 고정인지”를 수치로 못 박아라.

## 1) Trigger(신호 발생) 문제
- **신호 발생 빈도/분포**: 종목별 월간 신호 발생 횟수, 상위 10% 종목 편중 여부
- **신호-수익률 조건부 기대값**: 신호 구간(상위/하위 분위)에서 다음날~5일 기대수익이 실제로 양(+)인지

## 2) Apply(적용/체결) 문제
- 신호는 있는데 **제약/체결 규칙 때문에 못 타는지** 분해:
  - 목표 포지션 vs 실제 체결 포지션 괴리(슬리피지/ADV캡 때문에 축소됐는지)
  - 리밸런스 캡/턴오버 캡으로 주문이 잘렸는지 비율로 보고

## 3) Exposure(노출) 문제
- 8~14개 집중에서 흔한 함정:
  - 섹터는 Tech/Healthcare인데도 실제로는 **1~2개 서브테마(예: 반도체, 바이오)로 쏠림**
  - 팩터 노출(모멘텀/밸류/퀄리티/저변동) 추정해서 “의도치 않은 베팅” 확인
- 결과 리포트: 기간별 상위 기여 종목/하위 기여 종목, 포지션 사이즈가 손익을 좌우하는지

## 4) Cost(비용) 문제
- 총 PnL을 **Gross PnL / Cost / Net PnL**로 쪼개고,
  - 비용이 알파의 몇 %를 먹는지
  - 비용 기여 상위 구간(고변동/레짐 전환/실적 시즌)에 집중되는지
- “후보들이 락박스에서 비슷”하면, 대개 **Net이 비용에 의해 평탄화**되는지부터 확인

## 5) Regime(레짐) 문제
- 레짐별(예: QQQ 강세/약세, XLV 상대강세, VIX 고/저)로 성능을 **동일 포맷**으로 쪼개라:
  - 레짐별 lockbox_mean, lockbox_min, MDD
  - 최악 레짐이 전체 성능을 깎는지(대부분 여기서 정체가 발생)

---

## 결론: 48시간 동안 “이 5개(E1~E5)만” 돌려서 락박스 정체 원인을 제거하라
