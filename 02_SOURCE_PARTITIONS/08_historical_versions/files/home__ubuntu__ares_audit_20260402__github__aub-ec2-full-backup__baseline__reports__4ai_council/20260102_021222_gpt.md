## 다음 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — **명령형 체크리스트**
우선순위는 **누수 → 과최적화 → 서바이버십 → 비용 미반영 → 운영 리스크** 순으로 배치.

1) **(누수 차단) 피처/라벨 시간정렬 강제 + Purge/Embargo CV 적용**
2) **(비용 반영) 거래비용/슬리피지/스프레드 + 회전율(턴오버) 페널티를 백테스트에 ‘하드’로 주입**
3) **(서바이버십/데이터 무결성) 상장폐지/결측/액션 처리 규칙 고정 + “거래 가능성” 게이트 추가**
4) **(과최적화 완화) 하이퍼파라미터 탐색 폭 축소 + 안정성(분산/최저치) 목적함수로 전환**
5) **(운영 리스크) 48시간 자동 루프에서 실패 모드(데이터 지연/부분 업데이트/주문 불가) 시나리오 테스트 게이트 추가**

## TOP5 제안별 상세 (a)왜 (b)위험 (c)최소 실험 (d)PASS 조건
아래는 **48시간 자동 루프에서 바로 도는 형태**로, 각 항목당 **실행 1개 패치/실험**만 제시(케이스 폭발 방지).  
(추가 실험은 “보류 후보”로만 두고 이번 48시간엔 실행 금지)

# 1) 누수 차단: 시간정렬 강제 + Purge/Embargo CV
### (a) 왜 필요한지
- Champion은 성능이 높은데, 이런 경우 **미세한 누수(특히 리샘플/리밸런스 경계, corporate action 반영 시점, “당일 종가로 다음날 체결 가정” 같은 암묵적 룩어헤드)**가 숨어 있으면 lockbox에서만 무너지거나, 후보들이 불안정해짐.
- 현재 후보 성능이 tuning 대비 lockbox/min이 약한 패턴(예: candidate lockbox_min 0.33)은 **경계 조건/미세 누수/비용 미반영**에서 자주 발생.

### (b) 위험/부작용
- 누수를 막으면 단기 성능이 내려갈 수 있음(“가짜 알파” 제거).
- Purge/Embargo로 학습 샘플이 줄어 분산 증가.

### (c) 최소 실험 1개 (48h 실행)
**실험 E1 — “Strict As-Of + Purged Walkforward” 패치**
- **실험 정의**
  - 모든 피처/라벨에 `asof_timestamp`를 강제하고,
  - 리밸런스 시점 기준으로 **피처는 t-1(또는 t close 이후 확정된 값만)** 사용,
  - CV는 **Purged K-Fold + Embargo(예: 5~10 trading days)** 적용.
- **게이트(실행 전/중단 조건)**
  - (누수 감지 게이트) “당일 체결 가정” 또는 “피처 생성에 t 가격 포함” 패턴 발견 시 즉시 FAIL로 처리하고 패치 고정.
  - (학습 안정성 게이트) 유효 샘플 수가 기존 대비 과도하게 감소(예: -30% 초과)하면 embargo 축소만 허용(다른 변경 금지).
- **기대 관측치**
  - tuning_mean은 하락할 수 있으나, **lockbox_min 개선/안정화**가 나타나야 정상.
  - 후보들의 tuning↔lockbox 갭이 줄어듦.

### (d) PASS 조건(Champion 대비 “누수 제거” 성공 판정)
- `lockbox_min >= 1.2` (Champion 1.447 근방을 크게 훼손하지 않는 수준)
- `worst_mdd >= -0.10` 유지(Champion worst_mdd -0.095 근처 방어)
- tuning_mean 하락은 허용하되, **tuning_mean - lockbox_mean 격차가 축소**되는 방향이면 PASS

# 2) 비용 반영: 슬리피지/스프레드/커미션 + 턴오버 페널티 “하드” 적용
### (a) 왜 필요한지
- Tech+Healthcare 8~14종목 집중은 **회전율/체결비용**에 민감.
- 비용 미반영은 **tuning에서는 좋아 보이는데 lockbox나 실거래에서 급락**하는 대표 원인.

### (b) 위험/부작용
- 순성과 급락 가능(특히 단타형 시그널).
- 비용 파라미터가 너무 보수적이면 알파가 묻힘.

### (c) 최소 실험 1개 (48h 실행)
**실험 E2 — “Cost Model + Turnover Cap” 패치**
- **실험 정의**
  - 체결가격에 슬리피지(예: bps), 스프레드(고정 또는 ATR/가격 기반), 커미션을 포함.
  - 포트폴리오 리밸런스 시 **턴오버 상한(예: 일 30~50% 또는 리밸런스당 X%)** 적용(초과 주문은 비례 축소).
  - 성과 지표는 “비용 차감 후”만 기록.
- **게이트**
  - (비용 일관성 게이트) gross→net 차이가 비정상적으로 작으면(예: 평균 턴오버가 높은데 비용 영향이 미미) 비용 적용 경로를 버그로 간주하고 FAIL.
  - (현실성 게이트) 체결가능성(거래대금/호가스프레드 근사)이 일정 기준 이하인 종목은 주문 0 처리.
- **기대 관측치**
  - gross 성과는 유지/상승, net 성과는 하락하더라도 **net의 lockbox 안정성 증가**가 목표.
  - “좋은데 실현 불가능한” 후보가 자동 탈락.

### (d) PASS 조건
- `lockbox_mean >= 2.7` 유지(Champion 2.84 대비 과도 훼손 방지)
- `lockbox_min >= 1.0`
- 추가 운영지표: **평균 턴오버 감소 + net Sharpe/Calmar가 gross 대비 과도하게 붕괴하지 않음**

# 3) 서바이버십/데이터 무결성: 상폐/결측/액션 처리 고정 + 거래가능 게이트
### (a) 왜 필요한지
- 서바이버십/액션 반영 시점 오류는 **장기 백테스트 과대평가**의 최빈 원인.
- 8~14 종목 집중은 결측 1~2개가 **포트폴리오 전체를 왜곡**.

### (b) 위험/부작용
- “깔끔한 데이터만 남기는” 방식은 또 다른 편향을 만들 수 있음(샘플 선택 편향).
- 상폐 처리(0 처리 vs 마지막 가격 유지 vs delisting return 반영) 정책에 따라 성과가 크게 변동.

### (c) 최소 실험 1개 (48h 실행)
**실험 E3 — “Tradability Gate + Missing/Delist Policy” 패치**
- **실험 정의**
  - 종목별로 매일 `tradable=true/false`를 산출:
    - 가격/거래대금 결측, 비정상 스프레드 추정, 급격한 단일 캔들 점프(데이터 오류 의심) 시 **거래 금지**
  - 결측 발생 시 포지션 처리 규칙 고정:
    - (권장) 해당 일자 리밸런스에서 주문 0 + 기존 포지션은 **리스크 한도 내에서 축소/청산** 우선
  - delist 추정 이벤트(연속 결측/거래정지 패턴) 발생 시 **보수적 손실(예: -30%~-100% 스트레스)** 중 하나를 정책으로 고정(“마지막 가격 유지” 금지).
- **게이트**
  - (정책 일관성 게이트) 결측/상폐 처리 로직이 종목/기간에 따라 달라지면 FAIL(단일 규칙만 허용).
- **기대 관측치**
  - 극단적 드로우다운/이상치 기여가 감소.
  - lockbox_min 개선 가능.

### (d) PASS 조건
- `worst_mdd`가 개선되거나 최소 유지(`>= -0.10`)
- fold별 성능 분산(최저치)이 완화: `tuning_min`이 과도하게 음수로 내려가는 패턴 감소

# 4) 과최적화 완화: 탐색 폭 축소 + “안정성 목적함수”로 전환
### (a) 왜 필요한지
- Champion 대비 후보가 tuning에서 흔들리고 min이 심하게 음수로 내려가는 패턴은 **탐색 공간 과대/불안정 목적함수** 신호.
- 현재 운영은 48시간 자동 루프이므로, “더 많은 실험”보다 **나쁜 후보를 빠르게 버리는 규칙**이 ROI가 큼.

### (b) 위험/부작용
- 진짜 알파를 놓칠 수 있음(탐색 폭 축소의 비용).
- 단기적으로 “개선이 없어 보이는” 구간 발생.

### (c) 최소 실험 1개 (48h 실행)
**실험 E4 — “Objective = mean + min + MDD”로 고정 (안정성 우선)**
- **실험 정의**
  - 선택 기준을 `lockbox_mean` 단일 극대화가 아니라,
  - 예: `score = lockbox_mean + 0.5*lockbox_min - 2.0*abs(worst_mdd)` 같은 **안정성 가중 스코어**로 통일
  - 하이퍼파라미터 범위 축소(현재 champion 주변 ±작게)만 허용.
- **게이트**
  - (과탐색 게이트) 후보 수/탐색 파라미터 수가 증가하면 FAIL(이번 사이클은 “축소만”).
- **기대 관측치**
  - 평균 성능이 큰 폭으로 오르지 않아도, **min과 MDD가 안정**되는 후보가 꾸준히 상위에 옴.
  - “PASS 후보의 lockbox_min 바닥”이 올라감.

### (d) PASS 조건
- `lockbox_min >= 1.2` 달성 후보 출현(Champion급 바닥 회복)
- `worst_mdd >= -0.09` 수준으로 개선 또는 유지

# 5) 운영 리스크: 자동 루프 실패 모드 테스트 게이트(데이터 지연/주문 불가/부분 체결)
### (a) 왜 필요한지
- 실거래에서 성능이 안 움직이는 가장 흔한 이유는 “전략이 아니라 운영”:  
  **데이터 지연, 리밸런스 타이밍 미스, 주문 거부/부분 체결, 종목 거래정지** 등.
- 8~14종목 집중은 부분 체결 1~2개가 노출을 바꿔 성과를 크게 좌우.

### (b) 위험/부작용
- 백테스트 결과가 더 보수적으로 변해 “보기 좋은 숫자”가 감소.
- 구현 복잡도 증가(단, 이번은 최소 게이트만).

### (c) 최소 실험 1개 (48h 실행)
**실험 E5 — “Execution Failure Simulation Gate”**
- **실험 정의**
  - 백테스트에 확률적/규칙적 실패를 주입:
    - 리밸런스 당 주문의 X%는 다음 날로 이월(데이터/주문 지연)
    - 유동성 부족이면 목표 수량의 Y%만 체결(부분 체결)
  - 성과 평가는 이 실패 시뮬레이션 포함 버전으로만 PASS 인정.
- **게이트**
  - (운영 견고성 게이트) 실패 주입 후 `worst_mdd`가 특정 임계(-0.11 등) 아래로 급락하면 FAIL.
- **기대 관측치**
  - “운영에 강한” 신호/리밸런스 빈도가 선택됨(회전율 감소 쪽으로 압력).

### (d) PASS 조건
- 실패 주입 후에도 `lockbox_mean >= 2.6` 유지
- `worst_mdd >= -0.10` 유지

## 48시간 자동 루프에 바로 붙이는 실행 순서(명령형)

2) **E2(비용/턴오버)** 적용 → gross/net 성과 동시 기록, net만 모델 선택에 사용
3) **E3(거래가능 게이트)** 적용 → 결측/상폐 처리 단일 규칙 확정

5) **E5(운영 실패 주입)** 적용 → PASS 판정은 실패 주입 포함 성과로만

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래 트리는 **관측 지표(ETF는 관측만)**를 이용해 어디서 막히는지 기계적으로 쪼개는 용도.

### A. Trigger(시그널이 발생하나?)
- 체크: 일/주 단위 **신호 발생 빈도**, 상위 스코어 종목 교체율
- 이상 패턴
  - 신호가 거의 안 뜸 → 임계값/필터 과도, 결측/거래가능 게이트가 너무 빡셈
  - 신호는 뜨는데 성과 무 → 아래 B~E로 이동

### B. Apply(신호가 포지션으로 “적용”되나?)
- 체크: 목표 포지션 vs 실제 포지션(체결 후) 괴리, 리밸런스 지연률
- 이상 패턴
  - 목표는 잘 바뀌는데 실제는 거의 안 바뀜 → 주문 제한/턴오버 캡/부분 체결/거래불가 종목 증가

### C. Exposure(노출이 의도대로 나오나?)
- (미국주식 Tech+Healthcare 8~14 고정 전제) 체크:
  - 순/총 익스포저, 단일 종목 최대 비중, 섹터 비중(Tech/HC)
  - 시장 베타(관측: SPY), 성장/나스닥 민감도(관측: QQQ), 헬스케어 레짐(관측: XLV)
- 이상 패턴
  - 베타가 올라가며 성과가 시장과 동일 → 사실상 “위험 프리미엄”만 먹는 중
  - 특정 1~2종목 편중 → idiosyncratic 리스크가 성과를 잠식

### D. Cost(비용이 알파를 먹나?)
- 체크:
  - gross vs net 격차(턴오버와 함께), 슬리피지 민감도(비용 bps를 2배로 했을 때 성과 변화)
- 이상 패턴
  - gross는 좋은데 net이 평평 → 회전율/체결비용이 원인, 리밸런스 빈도 줄이거나 턴오버 캡 강화

### E. Regime(레짐에서만 죽나?)
- 레짐 관측(매매 X): SPY/QQQ/XLV 추세, 변동성(VIX), 금리(관측용 지표)
- 분해:
  - “QQQ 강세” 구간에서만 성과, 횡보/급락에서 손실 → 모멘텀 편향
  - XLV 상대강세 구간에서만 성과 → 섹터 레짐 의존
- 대응은 “케이스 확장”이 아니라:
