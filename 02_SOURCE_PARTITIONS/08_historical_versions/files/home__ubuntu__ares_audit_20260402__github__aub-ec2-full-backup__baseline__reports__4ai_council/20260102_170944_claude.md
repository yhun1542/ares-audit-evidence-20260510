## 1. 48H TOP-5 PATCH BACKLOG

### PATCH-1: Degenerate Fold 근본 원인 격리
**왜 필요한가**
- 40% fold 퇴화 = 신호가 특정 시장 레짐에서만 작동 (서바이버십/과최적화 징후)
- 이 상태로 라이브 전환 시 실제 손실 구간에서 무방비

**위험/부작용**
- 퇴화 fold 제거 시 OOS mean 인플레이션 (가짜 개선)
- 과도한 필터링 → 거래 기회 소멸

**실험 체크리스트**
| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P1-A | `fold_analysis.py --per-fold-sharpe` 실행, 퇴화 fold 시계열 특성 추출 | 완료 | 퇴화 fold 공통 레짐 식별 (ex: 2022Q1 금리인상, 2020Q1 COVID) |
| P1-B | 퇴화 fold에서 exposure=0 구간 비율 측정 | 0-exposure > 60%면 신호 자체 문제 | 수치 리포트 |
| P1-C | 퇴화 fold 제외 vs 포함 OOS 비교 (둘 다 기록, 제외 버전 채택 금지) | OOS gap < 1.5%p | 편향 크기 정량화 |

**PASS 조건**: 퇴화 원인 1개 이상 명시 + 해당 레짐 태그 부여

- 라이브 운영 시 드로다운 한도 초과 감지 불가

**위험/부작용**
- MDD 계산 로직 버그 시 false-negative (허용해선 안 될 전략 통과)

**실험 체크리스트**
| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P2-A | `backtest_core.py` 내 MDD 계산 함수 단위테스트 (known drawdown 시계열 투입) | 오차 < 0.1%p | MDD 계산 정상 여부 |
| P2-B | Champion JSON에 `worst_mdd` 필드 강제 기록 로직 추가 | 필드 존재 확인 | 스키마 검증 통과 |

**PASS 조건**: `worst_mdd` 값 존재 + 값 ≤ -15% 시 자동 REJECT 플래그
