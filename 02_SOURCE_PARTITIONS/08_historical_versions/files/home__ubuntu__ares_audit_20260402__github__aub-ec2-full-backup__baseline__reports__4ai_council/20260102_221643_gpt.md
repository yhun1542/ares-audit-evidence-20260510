- `aub_rebalance_pinpoint`가 깨진 원인(파일 경로 `--base-log` 문자열, JSON decode 실패)을 제거하라:

**(b) 위험/부작용**: 게이트 강화로 실패 런이 늘어 속도 저하. 하지만 48시간 루프에서는 이게 이득.

### 2) **누수/과최적화(특히 degenerate_folds) 즉시 차단**
- `degenerate_folds: [1,2,3,8]` 원인을 **게이트로 격리**하라: 해당 폴드에서 “트레이드 0 / 시그널 상수 / 라벨 분산 0”이면 런 실패.
- 시계열 CV에 **purge/embargo**(예: 5~20 거래일) 적용하고, 피처 생성에서 **미래 참조 가능성(리샘플/정규화/랭크)**을 전부 “과거만”으로 제한하라.
- 테크+헬스케어 8~14종목 구성에서 종목선정 로직이 있다면, 선정 기준 입력이 **리밸런스 시점에 존재하던 데이터만** 쓰는지(발표일/리비전) 강제하라.

**(a) 왜 필요한지**: degenerate fold는 OOS 평균이 그럴듯해도 *실전에서 깨지는 전형적 신호*이며, 누수/정렬 버그/선정 버그의 가장 빠른 지표.  
**(b) 위험/부작용**: 모델이 “덜 똑똑해 보이게” 떨어질 수 있음(정상).  
**(c) 최소 실험(공유 실험 사용)**: 아래 **실험 E1**로 48시간 내 2회 반복.  
**(d) PASS 조건**: `degenerate_folds == []` + OOS 성능이 “상승”이 아니라도 **oos_min 악화 방지**(예: 기존 대비 하락폭 제한) + 폴드별 트레이드 수/시그널 분산 최소치 충족.

### 3) **서바이버십/코퍼레이트 액션/유니버스 고정**
- 유니버스를 “현재 살아있는 종목” 기준으로 만들지 말고, **백테스트 시점 기준 point-in-time**로 고정하라(최소한 delisting/merged 처리).
- 가격데이터는 **분할/배당 조정(Adjusted)**을 사용하고, 리턴 계산은 일관된 방식으로 통일하라.

**(a) 왜 필요한지**: 8~14 소수 종목 전략은 서바이버십/분할 처리 오류 하나로 성과가 “움직이지 않거나” “가짜로 좋아지는” 현상이 잦음.  
**(b) 위험/부작용**: 진짜 성능이 내려갈 수 있음(정상). 데이터 소스에 따라 구현 비용 증가.  
**(c) 최소 실험(공유 실험 사용)**: 아래 **실험 E2**로 “유니버스 고정 vs 기존” 1:1 A/B.  
**(d) PASS 조건**: (1) 일자별 종목 수 8~14 유지 (2) delisting/merge 이벤트가 있어도 런이 중단되지 않음 (3) 동일 시드에서 재현성 확보 (성과가 내려가도 PASS 가능: 데이터 정합성 확보가 목적).

### 4) **비용 미반영(턴오버/슬리피지) 즉시 포함 + 리밸런스 로그로 검증**
- 거래비용을 “고정 bps”로라도 즉시 넣고(예: 5~20bps + 슬리피지), 성과 리포트에 **Gross/Net**을 분리 표기하라.
- 48시간 루프에서 매 런마다 **턴오버(일/월), 평균 보유기간, 체결 단가 추정**을 의무 로그로 남겨라.
- 리밸런스 산출물이 없으면(현재처럼) 비용 검증이 불가하니, **리밸런스 로그 생성 실패 = 런 실패**로 바꿔라.

**(a) 왜 필요한지**: “성능이 안 움직임”의 상당수가 사실은 비용/턴오버 변화로 상쇄되거나, 아예 주문이 적용되지 않는 상태에서 발생.  
**(b) 위험/부작용**: Net 성과 급락 가능. 하지만 실전 정합성 확보.  
**(c) 최소 실험(공유 실험 사용)**: 아래 **실험 E3**에서 비용 스윕(2포인트만) + 로그 검증.  
**(d) PASS 조건**: Net 성과 산출 성공 + 리밸런스 로그로 “주문 수/턴오버/비용”이 숫자로 일치 + oos_mean이 떨어져도 **oos_min, drawdown, turnover**가 개선되면 PASS.

### 5) **전략 리스크(노출·레짐) — ETF는 “관측지표”로만 사용**
- QQQ/XLV(Tech/Healthcare), VIX(또는 VIX proxy), TLT 같은 ETF/지표를 **매매하지 말고**, 노출 게이트로만 써라:  
  - 예: VIX 상승/QQQ 모멘텀 음수 구간에는 **총 익스포저 상한 축소**, 리밸런스 빈도 축소
- 단일 종목 최대비중/섹터 균형(Tech vs Healthcare)을 **하드 캡**으로 걸어 tail-risk를 줄여라.
- 익스포저(min/max 0~0.838)처럼 낮은 편이면 “적용이 안 되는 문제”도 가능하니, **노출 타임시리즈를 의무 플롯/로그**로 고정하라.

**(a) 왜 필요한지**: 소수 종목 + 섹터 집중은 레짐에 따라 성과가 잠기며, 그때 “아무리 튜닝해도 No-Delta”가 반복됨.  
**(b) 위험/부작용**: 상단 성과(상승장) 일부 희생. 게이트가 과하면 거래가 거의 사라질 수 있음.  
**(c) 최소 실험(공유 실험 사용)**: 아래 **실험 E4**(레짐 게이트 1개 + 캡 1개만)로 최소 구성.  
**(d) PASS 조건**: (1) 하락 레짐에서 MDD/왼쪽 꼬리(oos_min) 개선 (2) 익스포저/턴오버가 목표 범위로 수렴 (3) 트레이드 수가 0으로 붕괴하지 않음.

# 성능이 안 움직일 때(“No-Delta”) 원인 분해 아이디어 — 트리거/적용/노출/비용/레짐 순서

## 1) 트리거(신호 생성) 레벨
- **시그널 분포 드리프트 체크**: 날짜별 시그널 평균/표준편차/상위-하위 스프레드가 거의 동일하면 “실험이 사실상 같은 전략”.
- **랭크/선정 안정성**: 리밸런스 시점 Top-K(8~14) 종목 리스트의 Jaccard 유사도 추적. 유사도 0.9+가 지속되면 파라미터 변경이 효력을 못 냄.
- **피처/라벨 정렬 검사**: purge/embargo 없이도 “어제 정보가 오늘 라벨에 섞이는”지, 샘플 인덱스 단위로 자동 점검.

## 2) 적용(주문/리밸런스) 레벨
- **리밸런스 이벤트 수**가 실험 간 동일한지 비교(지금은 rebalance 로그가 깨져 있어 최우선 복구 대상).
- 목표비중 → 주문수량 변환에서 **라운딩/최소주문/현금부족**으로 주문이 0이 되는 케이스 탐지.
- “신호는 바뀌는데 포지션이 안 바뀜”을 잡기 위해, 리밸런스마다  
  - 목표 포트 vs 실제 포트의 L1 distance  
  - 주문 전/후 익스포저 변화량  
  을 기록.

## 3) 노출(익스포저/리스크) 레벨
- 현재 `exposure_max ~ 0.84`는 “의도된 상한”인지 “적용 실패로 낮아진 것”인지 분리하라.  
  - 일자별 총/섹터별 익스포저, 종목별 최대비중, 현금비중을 필수 로그.
- Tech/Healthcare 내 쏠림(예: NVDA/MSFT/LLY 같은 초대형) 때문에 실질적으로 “거의 지수”가 되는지 상관/베타(관측 ETF 대비)로 확인.

## 4) 비용(슬리피지/턴오버) 레벨
- Gross는 움직이는데 Net이 안 움직이면 비용/턴오버 상쇄.  
- Gross도 안 움직이면 “적용/노출/트리거” 중 하나가 실제로 고정되어 있을 가능성이 큼.
- 비용 민감도(5bps vs 15bps)에서 성과 순위가 뒤집히면, 전략이 미세 알파에 과의존.

## 5) 레짐(시장 상태) 레벨
- 레짐별 성과를 조건부로 쪼개라(ETF는 지표):  
  - QQQ 상승/하락, XLV 상대강도, VIX 상/하 분위  
- No-Delta가 특정 레짐에서만 반복되면, 그 레짐에서 신호가 작동하지 않거나 노출 게이트가 과도한 것.

## 즉시 실행 순서(48시간 내)
1) **E0 먼저 머지**(로그/해시/MDD/리밸런스 산출물 없으면 전부 무의미).
