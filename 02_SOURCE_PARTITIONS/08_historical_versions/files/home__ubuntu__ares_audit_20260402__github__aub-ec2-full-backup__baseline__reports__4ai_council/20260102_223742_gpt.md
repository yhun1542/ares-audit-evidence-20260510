## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — 명령형 체크리스트

### 1) **리밸런스/로그 파이프라인 복구(운영 리스크 최우선)**
**(a) 왜 필요한지**
- `aub_rebalance_pinpoint`가 **입력 파일 부재/파싱 실패**로 완전 무력화됨 → “언제/왜 성능이 변했는지”를 48시간 루프에서 추적 불가.
- `file: (blank)`, `lane_hash/run_hash: None`, `worst_mdd: None`은 **재현성/감사 가능성**이 깨졌다는 신호.

**(b) 위험/부작용**
- 로그를 늘리면 I/O 비용 증가, 디스크 누수 가능.
- 포맷 변경 시 기존 리포트 도구가 깨질 수 있음(버전 태깅 필요).

**(c) 최소 실험 2~3개 (아래 공통 실험 ID 재사용)**
- **E1**(필수): Rebalance 로그 표준화 + deterministic replay
- **E3**: Fold/평가 파이프라인 재현성 점검(로그로 fold별 거래수/노출 기록)
- **E4**: 비용/슬리피지 로그 항목 추가(순성과 변동 원인 추적)

**(d) PASS 조건**
- `rebalance.csv` 또는 `rebalance.jsonl`이 **매 런 생성**되고, `aub_rebalance_pinpoint`가 **에러 없이 리포트 생성**.
- 모든 런에서 `run_hash/lane_hash`가 채워지고, 동일 seed/데이터로 **완전 재현**.
- `worst_mdd`가 누락 없이 산출.

---

### 2) **누수(Leakage) + 생존자편향(Survivorship) 1차 봉합**
**(a) 왜 필요한지**
- OOS가 “안 움직이는” 상태에서 가장 흔한 원인이 **미세 누수(특히 시그널 적용 시점/리밸런스 체결 시점 mismatch)** 또는 **생존자편향으로 인한 과대추정**.
- Tech+Healthcare는 이벤트(승인/임상/가이던스)로 급변 → **PIT(시점일치)** 깨지면 성능이 허상화.

**(b) 위험/부작용**
- 누수 제거 후 OOS가 하락할 수 있음(정상).
- PIT 강제 시 결측 증가로 거래 빈도/노출이 감소할 수 있음.

**(c) 최소 실험 2~3개**
- **E2**: 시그널 1바(1D) 강제 지연 + as-of 체크(룩어헤드 센티넬)
- **E3**: 시간 연속 OOS split에서 누수 흔적 재검출(“랜덤 CV” 금지)
- **E1**: 리밸런스 타임스탬프/체결가격 소스가 시점 일치인지 로그로 검증

**(d) PASS 조건**
- “의도적 지연(shift)” 후에도 **성능이 급락하지 않거나(예: OOS mean 30% 이내 하락)**, 급락한다면 누수 가능성을 명확히 로그로 특정(어떤 피처/어떤 시점).
- delist/휴지(거래정지) 케이스가 포트폴리오에서 **자동 처리**되고, 백테스트에서 **0원 청산/무한 수익** 같은 이상치 제거.

---

### 3) **Degenerate folds(현재 [1,2,3,8]) 제거 + 평가 체계 안정화(과최적화/허상 방지)**
**(a) 왜 필요한지**
- degenerate fold는 보통 “거래가 거의 없거나/노출이 0이거나/라벨이 비정상” → OOS 평균이 의미 없어지고 “안 움직이는” 상황을 만듦.
- `exposure_min=0.0`도 같은 계열(폴드/구간에선 아예 포지션이 안 잡힘).

**(b) 위험/부작용**
- 폴드 재구성 시 과거 챔피언과 직접 비교가 어려워질 수 있음(메트릭 버전 고정 필요).
- 최소 거래수 강제하면 특정 전략이 자동 탈락할 수 있음(정상).

**(c) 최소 실험 2~3개**
- **E3**(필수): 시간 연속 walk-forward + 폴드별 최소 거래/최소 노출 게이트
- **E1**: 폴드별 “주문수/체결수/턴오버/노출시간” 로그 남기기
- **E4**: 비용 포함 시 degenerate가 더 심해지는지(거래가 사라지는지) 확인

**(d) PASS 조건**
- degenerate_folds가 **빈 리스트**(또는 0개)로 수렴.
- 모든 OOS 폴드에서 `exposure_min > 0` (예: 최소 0.05 이상) + 최소 거래수 충족.
- 메트릭 산출 누락(worst_mdd 등) 0건.

---

### 4) **비용(수수료/슬리피지/스프레드/borrow) 미반영 리스크 즉시 반영**
**(a) 왜 필요한지**
- Tech/Healthcare 단일종목 8~14개 운용은 리밸런스 시 **턴오버가 수익을 잡아먹는 구조**가 되기 쉬움.
- 비용을 안 넣으면 “좋아 보이는데 실전에서 0”이 되며, 성능이 안 움직이는 이유가 **사실상 비용에 눌린 것**인지 분리 불가.

**(b) 위험/부작용**
- 비용 모델이 과보수적이면 좋은 전략이 과소평가될 수 있음.
- borrow 가정이 비현실적이면 헷지/숏 관련 성능이 왜곡될 수 있음.

**(c) 최소 실험 2~3개**
- **E4**(필수): net performance(비용 포함)로 챔피언 평가를 강제
- **E1**: 리밸런스 로그에 “예상비용/체결슬리피지/스프레드 대용치” 기록
- **E5**: 포트폴리오 제약(8~14, turnover cap)으로 비용 민감도 완화

**(d) PASS 조건**
- gross→net 전환 후에도 OOS mean이 **치명적으로 붕괴하지 않음**(예: 50% 이상 증발하면 전략/턴오버 구조 문제로 판정).
- 평균/최악 구간에서 **net MDD/턴오버/거래비용**이 허용 범위 내(게이트로 자동 차단).

---

### 5) **전략/포트폴리오 제약: “미국주식 only + Tech/Healthcare + 8~14 종목”을 엔진 레벨에서 강제**
**(a) 왜 필요한지**
- 현재 상태에서 “노출 0” 구간이 존재 → 유니버스/필터/신호가 너무 빡세거나 반대로 **우회 경로(다른 섹터/ADR/비미국)**가 섞일 수 있음.
- 8~14개 강제는 “모델이 좋아서가 아니라 우연히 분산된 덕”을 줄이고, 운영 가능한 형태로 수렴.

**(b) 위험/부작용**
- 강제 제약으로 백테스트 수익이 내려갈 수 있음(정상).
- 섹터 분류(GICS 등) 데이터 품질 문제 시 종목 누락/오분류 발생.

**(c) 최소 실험 2~3개**
- **E5**(필수): 포트 구성 모듈에 (US listing + Tech/Healthcare + 8~14) 하드 게이트
- **E2**: 제약 적용 시 누수 의심(미래 섹터 분류/리밸런스일 분류 변경) 방지
- **E4**: 제약으로 turnover가 줄어 비용이 개선되는지 확인

**(d) PASS 조건**
- 모든 리밸런스 스냅샷에서 **보유 종목 수 8~14 준수**, 섹터 비중이 Tech/Healthcare 범위 내(0 이탈).
- 비미국/ETF/ETN/펀드/ADR 혼입 0건(룰 기반 차단 + 로그).

---

## 48시간 자동 루프용 “실행 가능한 Patch/실험” (3~5개로 제한)

아래 **E1~E5만** 돌리고, 각 실험은 (1)정의 (2)게이트 (3)기대 관측치로 자동 판정해 승격/폐기하라.

### E1) **Rebalance 로그 표준화 + run 재현성 패치**
1) **실험 정의**
- 리밸런스 출력 포맷을 단일 표준으로 고정(`rebalance.jsonl` 권장: timestamp, universe_hash, holdings, trades, px_source, costs_est, exposure, turnover).
- `run_hash/lane_hash`를 데이터스냅샷+코드버전+seed로 강제 생성/기록.
- `aub_rebalance_pinpoint` 입력 경로를 **실제 산출물**로 연결(“--base-log” 같은 더미 인자 제거).

2) **게이트**
- 매 런에 리밸런스 로그 파일 존재 + JSON 파싱 성공.
- pinpoint 리포트 생성 성공(에러 0).
- 동일 seed로 2회 실행 시 holdings/trades가 byte-level 동일.

3) **기대 관측치**
- “성능이 안 움직임”이 **로그 부재 때문인지/전략 자체 때문인지** 분리 가능.
- `worst_mdd`/fold별 노출/턴오버가 자동으로 리포트에 뜸.

---

### E2) **누수 센티넬: 시그널 1D 지연 + as-of 검증**
1) **실험 정의**
- 모든 피처/시그널을 **거래 적용일 기준 최소 1 trading day 지연**(t 정보로 t 체결 금지).
- 데이터 로더에 “as-of timestamp ≤ decision time” assert를 추가(위반 시 해당 피처/종목을 drop하고 로그).

2) **게이트**
- 누수 위반 카운트가 0 또는 명시적으로 로그에 집계(피처별/소스별).
- shift 적용 버전이 baseline 대비 OOS가 극단 붕괴하면(예: -50% 이상) **누수 후보로 강제 플래그**.

3) **기대 관측치**
- 진짜 알파면 shift 후에도 성능이 일정 부분 유지.
- 붕괴 시 “어느 피처/어느 시점”에서 미래 참조가 있었는지 목록이 나온다.

---

### E3) **Degenerate folds 제거: 시간연속 walk-forward + 최소거래/최소노출 게이트**
1) **실험 정의**
- 랜덤 CV 금지, 시간 연속 walk-forward로 재구성.
- 각 폴드에 대해 `min_trades`, `min_exposure_time`, `min_positions`를 하드 게이트로 둬서 degenerate를 사전에 차단.

2) **게이트**
- degenerate_folds = 0
- 모든 폴드에서 `exposure_min ≥ 0.05`(예시) + `trades ≥ N`(예시)

3) **기대 관측치**
- OOS mean이 “평균만 좋고 일부 폴드가 비는” 현상이 사라짐.
- 성능이 안 움직이던 원인이 “폴드/노출 붕괴”였는지 판명.

---

### E4) **비용 포함(Net) 평가 강제 + 비용 로그**
1) **실험 정의**
- 거래비용(수수료+슬리피지+스프레드 대용치)을 net 성과에 반영하고, 챔피언 승격 기준을 net으로 강제.
- 리밸런스 로그에 `gross_pnl`, `cost`, `net_pnl`, `turnover` 저장.

2) **게이트**
- gross/net이 모두 산출되고, net이 NaN/누락 없이 기록.
- net 기준으로도 OOS 최소치(oos_min)가 임계값 이상(예: -X 이하로 붕괴 시 FAIL).

3) **기대 관측치**
- 성능 정체가 “사실상 거래비용에 의해 상쇄”인지 바로 보인다.
- turnover 높은 실험이 자동으로 도태되기 시작.

---

### E5) **포트폴리오 제약 패치(US only + Tech/Healthcare + 8~14)**
1) **실험 정의**
- 유니버스 필터를 엔진 레벨에서 강제(US listing, common stock, ETF 제외, 섹터=Tech/Healthcare).
- 포트 구성 시 항상 8~14 종목 유지(스코어 상위 N + 결측/거래불가 시 대체 규칙).

2) **게이트**
- 모든 리밸런스 스냅샷에서 holdings count 8~14 준수.
- 섹터 이탈 0, ETF 혼입 0, 비미국 0.

3) **기대 관측치**
- 노출 0 구간 감소(또는 원인 명확화: 필터가 과도하게 빡셈).
- 운영 가능 형태로 수렴(실전 제약과 백테스트가 일치).

---

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐) — 질문 없이 바로 실행

### A) 트리거(신호 발생) 문제
- **신호 발생률/분포를 폴드별로 로그**하라: `signal_nonzero_rate`, `topk_score_gap`, `rank_stability`.
- 0에 수렴하면 “전략이 조용”한 게 아니라 **필터/결측/PIT 드랍**으로 죽은 것일 수 있음.

### B) 적용(리밸런스/체결) 문제
- “의사결정 시점”과 “체결 가격/시간”이 섞이면 누수/허상이 발생.
- 리밸런스마다 `decision_ts`, `execution_ts`, `price_source`를 남기고, **decision_ts < execution_ts** 강제.

### C) 노출(포지션이 실제로 잡히는가) 문제
- `exposure_min=0`은 곧 “일부 구간 무포지션” 가능성.
- 폴드/월별로 **exposure histogram**, **현금비중**, **종목수**를 표준 리포트로 고정(E1+E3+E5로 해결).

### D) 비용(거래비용이 알파를 덮는가) 문제
- gross는 오르는데 net이 제자리면, 해결책은 모델이 아니라 **턴오버/리밸런스 규칙**이다.
- `net_pnl / gross_pnl` 비율을 기간별로 보고, 특정 변동성 레짐에서만 악화되는지 확인(E4).

### E) 레짐(시장 국면) 문제
- QQQ/XLV 같은 ETF는 **매매하지 말고 관측지표**로만 쓰되, 다음을 자동 태깅하라:
  - (i) 금리/성장: QQQ 수익률/변동성 구간
  - (ii) 헬스케어 방어 레짐: XLV 상대강도
- 레짐별로 `hit_rate`, `avg_trade_pnl`, `turnover`, `mdd`를 분해해서 “알파가 있는 구간/없는 구간”을 분리하라(단, 레짐을 학습에 과다 투입해 과최적화하지 말고 **리포팅/게이팅**에만 사용).

---

### 최종 실행 순서(48시간 내)
1) **E1 먼저 머지**(로그/재현성 없으면 나머지 실험이 무의미).
2) E2/E3를 병렬로 돌려 **누수 vs 폴드 붕괴**를 먼저 분리.
3) E4로 net 기준 승격으로 전환(비용 미반영 리스크 제거).
4) E5로 운영 제약(US+Tech/Health+8~14)을 엔진 레벨 고정.

위 5개(E1~E5)만으로도 현재 관측된 에러(리밸런스 로그 부재), 구조적 이상( degenerate folds, worst_mdd None, exposure_min 0), 그리고 “성능 정체”의 1차 원인(누수/폴드/비용/제약 불일치)을 48시간 루프에서 자동으로 갈라낼 수 있다.
