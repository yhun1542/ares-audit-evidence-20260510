## 📋 TOP 5 우선순위 액션

### PRIORITY 1: 파이프라인 복구 & 측정 신뢰성 확보
**왜 필요한지:**
- rebalance.csv 로드 실패 → 비용/슬리피지 미반영 상태로 OOS 계산 중일 가능성
- MDD=None → 리스크 게이트 작동 불가, 위험한 전략 통과 가능
- 측정이 틀리면 모든 실험이 무의미

**위험/부작용:**
- 복구 후 OOS가 급락할 수 있음 (진짜 성능 노출)
- 기존 champion이 무효화될 수 있음

**실험:**
| ID | 정의 | 게이트 | 기대 관측치 |
|----|------|--------|-------------|
| P1-A | rebalance.jsonl 파서 수정 (JSON 포맷 검증) | 파일 로드 성공 | 리밸런스 횟수, 평균 턴오버 출력 |
| P1-B | MDD 계산 로직 추가 (equity curve 기반) | worst_mdd ≠ None | 각 폴드별 MDD 분포 |
| P1-C | OOS 계산에 비용(10bps RT) 강제 적용 확인 | cost_applied=True 플래그 | OOS 변화량 기록 |

**PASS 조건:** 3개 모두 실행 완료 + MDD, 턴오버, 비용 반영 OOS 리포트 생성

---

### PRIORITY 2: 퇴화 폴드 원인 분해
**왜 필요한지:**
- Fold 1,2,3,8 = 아마도 특정 시기 (예: 2022 하락장, 2020 코로나)
- 퇴화 = exposure→0 또는 시그널 자체가 없음
- 이걸 모르면 레짐 필터나 시그널 수정 방향을 못 잡음

**위험/부작용:**
- 퇴화 폴드를 억지로 살리면 과최적화 심화
- 폴드별 튜닝은 누수 위험

**실험:**
| ID | 정의 | 게이트 | 기대 관측치 |
|----|------|--------|-------------|
| P2-A | 퇴화 폴드 시계열 구간 맵핑 (fold→date range) | 출력 테이블 | 각 폴드의 시장 레짐(VIX, SPY 수익률) |
| P2-B | 퇴화 폴드에서 시그널 발화율 측정 | signal_fire_rate < 5% 확인 | 폴드별 시그널 통계 |
| P2-C | 퇴화 폴드 제외 시 OOS 재계산 (참고용) | 6폴드 OOS mean | 과최적화 상한선 파악 |

**PASS 조건:** 퇴화 원인 1개 이상 특정 (레짐/시그널/노출)

---

### PRIORITY 3: 노출(Exposure) 0 구간 원인 파악
**왜 필요한지:**
- exposure_min=0.0 = 완전 현금 구간 존재
- 시그널이 발화했는데 노출 0이면 → 리스크 필터 과도
- 시그널 자체가 0이면 → 유니버스/팩터 문제

**위험/부작용:**
- 노출 강제 상향 시 MDD 악화
- 레버리지 착각 가능

**실험:**
| ID | 정의 | 게이트 | 기대 관측치 |
|----|------|--------|-------------|
| P3-A | exposure=0 구간 추출 및 시장 상태 태깅 | 리스트 출력 | VIX>30 비율, SPY drawdown 비율 |
| P3-B | 해당 구간에서 시그널 상위 5종목 확인 | 종목 리스트 | 실제 매수 가능했던 종목 존재 여부 |

**PASS 조건:** 노출 0의 원인이 (a) 의도적 리스크오프 vs (b) 시그널 사망 중 어느 쪽인지 판정

### PRIORITY 4: FSA/Hedge 파라미터 민감도 (이전 실험 계승)
**왜 필요한지:**
- `exp_fsa_only_scale_090_hedge_025.json` 실험 존재 → 결과 미확인
- FSA scale, hedge 비율이 퇴화 폴드와 연관 가능성

**위험/부작용:**
- 파라미터 그리드 확장 시 케이스 폭발
- 이미 과최적화된 상태에서 추가 튜닝은 위험

**실험:**
| ID | 정의 | 게이트 | 기대 관측치 |
|----|------|--------|-------------|
| P4-A | 기존 FSA 실험 결과 로드 및 폴드별 성능 분해 | 로드 성공 | 퇴화 폴드 개선 여부 |
| P4-B | FSA off (baseline) vs FSA on 비교 (A/B) | Δ OOS, Δ degenerate_folds | FSA가 퇴화 유발인지 확인 |

**PASS 조건:** FSA가 퇴화의 원인인지 아닌지 이진 판정

### PRIORITY 5: 유니버스/섹터 집중도 점검
**왜 필요한지:**
- Tech+Healthcare 집중 → 2022 금리 상승기에 동반 하락
- 특정 폴드 퇴화가 섹터 레짐과 일치하면 분산 부족

**위험/부작용:**
- 섹터 확장 시 유니버스 품질 저하 가능
- 당장은 실험 범위 제한 권장

**실험:**
| ID | 정의 | 게이트 | 기대 관측치 |
|----|------|--------|-------------|
| P5-A | 퇴화 폴드 구간에서 Tech/HC 섹터 성과 | 섹터 지수 수익률 | 시장 대비 언더퍼폼 확인 |
| P5-B | 현재 포트폴리오 HHI(집중도) 시계열 | HHI > 0.3 빈도 | 과집중 구간 특정 |

**PASS 조건:** 섹터 집중이 퇴화 원인의 50% 이상 설명 여부

## 🔬 성능 무변동 시 원인 분해 트리

```
성능이 안 움직인다
│
├─ [트리거] 시그널이 발화했나?
│   ├─ No → 팩터 임계값 너무 높음 / 유니버스 필터 과도
│   └─ Yes ↓
│
├─ [적용] 시그널이 포지션으로 전환됐나?
│   ├─ No → 리스크 필터(변동성, 상관관계)가 차단
│   └─ Yes ↓
│
├─ [노출] 포지션 크기가 유의미한가?
│   ├─ No → 사이징 로직이 exposure 압축 (vol target 과소)
│   └─ Yes ↓
│
├─ [비용] 실현 수익이 비용에 먹혔나?
│   ├─ Yes → 턴오버 과다 / 스프레드 미반영
│   └─ No ↓
│
└─ [레짐] 해당 구간이 전략과 미스매치인가?
    ├─ Yes → 레짐 필터 또는 동적 가중치 필요
    └─ No → 측정 오류 / 코드 버그 점검
```
