## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — 명령형 체크리스트

### 1) **누수(Leakage)·타임얼라인·룩어헤드 제거를 “강제”하는 실행 경로로 고정**
- **(a) 왜 필요한지**
  - 현재 tuning/lockbox가 모두 양호해 보이지만, *미세한 타임스탬프/리밸런싱 시점 누수*는 락박스에서도 “그럴듯한” 성능을 만들고 실거래에서 붕괴하는 1순위 원인.
  - Tech+Healthcare 8~14 종목은 개별 이벤트(실적/가이던스/임상) 영향이 커서, 하루 단위 정렬 오류가 성능을 과대평가하기 쉬움.
- **(b) 위험/부작용**
  - 성능이 단기적으로 하락할 수 있음(진짜 성능으로 수렴).
  - 실험 간 결과 변동성이 커져 “개선이 안 보이는” 구간이 늘 수 있음.
- **(c) 최소 실험(아래 공용 실험 중 선택)**
  - **E1, E2** 적용
- **(d) PASS 조건**
  - `lockbox_mean`이 챔피언 대비 **+0.3%p 이상** 유지/상승 *또는* `worst_mdd`가 **개선(절대값 감소)** 하면서 `lockbox_mean` **동일 이상**.
  - 누수 점검 테스트(아래 E1/E2 게이트) **전부 통과**.

---

### 2) **비용/슬리피지/체결 불확실성(운영 리스크 포함)을 “성능 지표”에 강제 반영**
- **(a) 왜 필요한지**
  - 현재 지표는 좋아도 *비용 미반영*이면 “락박스에서만 좋은 전략”이 됨.
  - 8~14 종목 집중은 회전율이 조금만 높아도 비용이 PnL을 먹음(특히 변동성 구간).
- **(b) 위험/부작용**
  - 비용을 보수적으로 넣으면 단기 성능이 크게 떨어져 “개선이 없어 보이는” 상태로 보일 수 있음.
  - 너무 강한 비용 패널티는 과도한 홀딩(기회 손실)로 이어질 수 있음.
- **(c) 최소 실험**
  - **E3 + (E4 또는 E5 중 1개)**  
- **(d) PASS 조건**
  - 비용 포함 후 `lockbox_mean` **챔피언 대비 동일 이상**(0 이상) + `worst_mdd` **악화 없음(±0.5%p 이내)**.
  - 거래 건수/회전율 지표가 목표 범위(아래 E3 기대 관측치)로 내려갈 것.

---

### 3) **서바이버십(종목 생존/데이터 가용성)·코퍼레이트액션 점검을 “락박스급 게이트”로 승격**
- **(a) 왜 필요한지**
  - US 개별 종목은 스플릿/머지/티커 변경/상장폐지/거래정지 등으로 *체계적 데이터 오류*가 누수처럼 작동.
  - Tech+Healthcare는 M&A/임상 실패로 갭이 커서, 조정가격/거래정지 처리 오류가 치명적.
- **(b) 위험/부작용**
  - 데이터 정제가 강화되면 사용 가능한 샘플이 줄어 성능이 일시 하락 가능.
- **(c) 최소 실험**
  - **E2 + E3** (특히 E2의 PIT/이벤트 정합성 게이트 활용)
- **(d) PASS 조건**
  - 이벤트/조정가격 검증 실패율 0(게이트 통과).
  - 특정 종목 1~2개가 성능을 “독식”하는 집중 현상이 완화(아래 관측치 참조).

---

### 4) **과최적화(하이퍼파라미터/폴드 튜닝 드리프트) 차단: “단순화 + 제약”으로 재현성 강화**
- **(a) 왜 필요한지**
  - tuning_mean이 lockbox_mean과 함께 올라가는 모습은 좋지만, *후속 실험이 더 안 움직이는* 상황은 흔히 “튜닝이 이미 잡음 최적화”에 걸린 신호.
- **(b) 위험/부작용**
  - 단순화하면 평균 성능이 떨어질 수 있음(대신 분산/리스크가 줄어드는지 확인 필요).
- **(c) 최소 실험**
  - **E4, E5**
- **(d) PASS 조건**
  - `tuning_mean - lockbox_mean` 갭이 **축소**(과최적화 완화)하면서 `lockbox_mean` **유지 이상**.
  - 폴드 간 성능 분산(표준편차) 감소.

---

### 5) **운영 리스크(48시간 자동 루프) 하드닝: 실패해도 “안전하게 멈추고 기록”**
- **(a) 왜 필요한지**
  - 자동 루프는 *실험 자체의 신뢰도*가 핵심. 로깅/재현/아티팩트 관리가 약하면 개선 방향이 왜곡됨.
- **(b) 위험/부작용**
  - 즉시 성능 개선은 없고, 개발 시간이 소모됨.
- **(c) 최소 실험**
  - **E1 + E5**(실험 재현성/결과 안정성 관측)
- **(d) PASS 조건**
  - 동일 커밋/동일 시드에서 결과가 허용 오차 내 재현.
  - “실패 케이스(데이터 결측/주문 불가/급락)”에서 강제 리스크오프가 동작.

## 공용 “실행 가능한 patch/실험” (총 5개만 운용) — 48시간 자동 루프용
아래 **E1~E5**만 돌리고, TOP5 항목은 이 조합으로 커버하라(케이스 폭발 금지).

### E1) **타임얼라인/룩어헤드 방지 패치**
1) **실험 정의**
   - 피처/라벨 생성 시점, 리밸런싱 시점, 체결 가격 시점을 명시적으로 분리(예: 신호는 T 종가 기준, 주문은 T+1 시가/중간가 등).
   - “미래 데이터 접근” 가능 경로를 코드 레벨에서 차단(assert/스키마).
2) **게이트**
   - 신호 생성 함수가 `t+1` 이후 데이터 참조 시 즉시 실패하도록 단위 테스트 추가.
   - 리밸런싱 캘린더와 가격 캘린더 불일치 시 run 중단.
3) **기대 관측치**
   - 성능이 소폭 하락할 수 있으나, 폴드/락박스 간 괴리 감소.
   - 특정 이벤트 데이(실적 발표) 주변의 비정상 수익 급등이 완화.

---

### E2) **PIT(포인트-인-타임)·코퍼레이트액션·결측 처리 검증**
1) **실험 정의**
   - 조정주가/거래정지/티커 변경/스플릿 구간에서 수익률 계산과 포지션 유지 규칙을 고정.
   - 결측 바/거래정지 시 “보수적 체결 불가/포지션 유지/강제 축소” 중 하나로 통일.
2) **게이트**
   - split/merger/티커변경 구간에서 비정상 수익률(예: 일간 ±80% 이상) 탐지 시 원인 로그 없으면 실패.
   - 종목별 유효 관측치 비율이 임계치 미만이면(예: 99% 미만) 실험 제외 또는 페널티.
3) **기대 관측치**
   - “한 종목이 전체 PnL을 끌어올리는” 현상이 줄고, 성능이 더 균질해짐.
   - 락박스 최저 성능 구간(worst_mdd) 안정화.

---

### E3) **거래비용/슬리피지/유동성 페널티를 목적함수에 삽입**
1) **실험 정의**
   - 비용 모델 2단(최소 고정수수료 + 스프레드/슬리피지)로 단순 시작.
   - 유동성 페널티(예: ADV 대비 주문비율, 당일 변동성 기반)를 “점수 차감”으로 반영.
2) **게이트**
   - 비용 포함 PnL을 **기본 리포트에서 1급 지표로 승격**(비용 미포함 결과만 좋으면 무조건 FAIL).
   - 평균 일간 turnover, 거래 횟수가 상한을 넘으면 FAIL(운영가능성).
3) **기대 관측치**
   - turnover 감소, 평균 보유기간 증가.
   - `lockbox_mean`은 유지, `worst_mdd`는 개선 또는 동일.

---

### E4) **노출 제약(Tech+Healthcare 내) + 포지션 집중/섹터 편향 제어**
1) **실험 정의**
   - “8~14개 종목” 유지하되, 단일 종목 최대 비중/동일 이벤트 리스크(상관) 제한.
   - 섹터는 Tech/Healthcare 중심을 유지하면서도 **서브산업 과집중(예: 바이오테크 only)** 방지.
2) **게이트**
   - 단일 종목 기여도(총 PnL/리스크 기여)가 임계치 초과 시 FAIL.
   - 상관 클러스터(동일 팩터/동일 테마) 편중이 일정 수준 넘으면 FAIL.
3) **기대 관측치**
   - 꼬리 손실 감소(worst_mdd 완화), fold14_mdd 안정화.
   - 성능이 크게 안 오르더라도 “망가질 확률”이 줄어듦.

---

### E5) **레짐 게이팅(관측 ETF는 지표로만) + 리스크오프 규칙 최소 도입**
1) **실험 정의**
   - 매매는 개별주만, **ETF(예: QQQ/XLV)는 관측 지표**로만 사용.
   - 레짐 신호(예: 변동성 급등, 지수 추세 붕괴)에서 포지션 총노출을 단계적으로 축소(현금 비중 증가).
2) **게이트**
   - 레짐 신호가 발동했는데도 총노출이 줄지 않으면 FAIL.
   - 레짐 신호가 과도하게 자주 발동(예: 월 8회 이상)하면 FAIL(과보수).
3) **기대 관측치**
   - 극단 구간 손실 감소(worst_mdd 개선).
   - 평시 성능 소폭 하락 가능하나 락박스 최저점이 올라가야 함.

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **로그/리포트의 고정 섹션**으로 만들어, 매 실험마다 자동 출력하라.

1) **Trigger(신호 트리거)**
- 신호 발생 빈도, 신호 강도 분포(상/하위 5%).
- 이벤트 데이(실적/임상/가이던스) 전후 신호의 일관성(급증이면 누수/정렬 의심).

2) **Apply(적용/체결)**
- 신호→주문→체결까지 단계별 “드랍률”(주문 불가, 거래정지, 결측, 리밸런싱 미스).
- 체결 가정(시가/종가/VWAP 근사) 변경에 대한 민감도(작게 바꿔도 성능이 크게 바뀌면 과최적화/비용 취약).

3) **Exposure(노출/집중)**
- 단일 종목/서브산업/팩터(모멘텀·퀄리티·저변동 등) 기여도 분해.
- 상관 클러스터별 노출(사실상 “한 베팅”인지 확인).

4) **Cost(비용)**
- 일간 turnover, 거래 횟수, 비용 총액/수익 대비 비중.
- “비용 0 vs 비용 on” 성능 격차: 격차가 크면 전략 알파가 비용보다 작다는 뜻.

5) **Regime(레짐)**
- 변동성/추세 국면별 성능 표(예: 고변동/저변동, 상승/하락 추세).
- 레짐별 MDD와 회복기간: 레짐 게이트(E5)가 필요한지/과한지 판단.

---

## 실행 순서(48시간 루프에 바로 넣기)
- **[1] E1 → E2**로 “데이터/정렬 신뢰성”을 먼저 고정하라(누수 가능성 제거가 우선).
- **[2] E3**로 비용 포함 성능을 챔피언 선정 기준에 강제 반영하라.
- **[3] E4 또는 E5**를 1개만 추가해 tail-risk를 줄이는 방향으로 마무리하라(케이스 폭발 방지).
- **[4] 결과가 정체되면** 위 원인 분해 5종 로그를 기준으로 “어디가 안 움직이는지(Trigger/Apply/Exposure/Cost/Regime)”부터 고정하라.

(위는 질문 없이 즉시 실행 가능한 형태로만 구성했으며, 실험 수는 E1~E5로 제한했다.)
