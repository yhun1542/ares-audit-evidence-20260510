3.  **[ARCH] 섹터 간 상관관계 제어**: Tech와 Healthcare가 동반 하락하는 구간 방어. XLK(Tech) 변동성 확대 시 XLV(Health) 비중을 늘리거나 현금화하는 동적 비중 조절(Dynamic Allocation) 도입.

5.  **[OPS] 단일 종목 리스크 캡(Cap) 설정**: 8~14개 종목 중 특정 종목(예: NVDA, LLY)에 몰빵되어 나온 수익인지 확인. 단일 종목 최대 비중 15~20% 하드 코딩 제한.

### [제안: 실행 가능한 Patch/실험 (48시간 루프)]

#### 1. 실험 ID: `EXP_001_LEAKAGE_PURGE` (데이터 누수 점검)
*   **왜 필요한가**: Tuning Min(0.05) 대 Lockbox Min(1.34)의 격차는 비현실적임. Feature 생성 시 미래 참조(Open/High/Low/Close의 시점 혼동)가 의심됨.
*   **위험/부작용**: 실제 성능이 대폭 하락할 수 있음(그러나 그것이 진실임).
*   **실행 내용**: 모든 입력 Feature(기술적 지표)를 `shift(1)` 처리하여 강제로 하루 지연시킴.
*   **PASS 조건**:
    *   (1) 실험 정의: `features = features.shift(1)` 적용 후 백테스트.
    *   (2) 게이트: Tuning Mean > 1.0 (손익분기점 유지).
    *   (3) 기대 관측치: Lockbox 성능이 하락하더라도 Tuning Min이 0.05에서 상승하거나, 전체적인 일관성이 확보되어야 함. 만약 수익률이 음수로 전환되면 기존 로직 폐기.

#### 2. 실험 ID: `EXP_002_REGIME_FILTER_SPY` (하락장 차단)
*   **왜 필요한가**: Tuning Min 0.05는 생존 불가능한 전략임. 대세 하락장에서 매매를 멈춰야 함.
*   **위험/부작용**: 급반등 구간(V자 반등)에서 진입이 늦어 수익 기회 박탈(Opportunity Cost).
*   **실행 내용**: ETF 지표(SPY)가 200일 이동평균(MA200) 아래일 때, 주식 포지션을 0% 또는 50% 이하로 강제 축소.
*   **PASS 조건**:
    *   (1) 실험 정의: `if SPY_Close < SPY_MA200: target_weight = 0.0`
    *   (2) 게이트: Tuning Min > 0.5 (MDD 방어 확인), Fold14 MDD > -0.15 유지.
    *   (3) 기대 관측치: Tuning Mean은 소폭 감소하더라도, Worst Case(Tuning Min)가 획기적으로 개선되어야 함.

#### 3. 실험 ID: `EXP_003_INVERSE_VOL_ALLOC` (섹터 밸런싱)
*   **왜 필요한가**: Tech 몰빵으로 인한 변동성 제어. Healthcare(저변동성)로의 자금 이동 자동화.
*   **위험/부작용**: 강세장에서 Tech 수익률을 일부 희생.
*   **실행 내용**: 포트폴리오 내 종목 비중 산정 시 `1 / (Rolling_Volatility_20d)` 비례 배분 적용 (Equal Weight 대신).
*   **PASS 조건**:
    *   (1) 실험 정의: Weighting Scheme을 `Inverse Volatility`로 변경.
    *   (2) 게이트: Sharpe Ratio > Champion_v5 대비 +0.2 개선.
    *   (3) 기대 관측치: 포트폴리오의 일일 변동성 감소 및 Tuning Min의 바닥 상승.

#### 4. 실험 ID: `EXP_004_STRICT_STOPLOSS` (개별 종목 손절)
*   **왜 필요한가**: 특정 종목의 급락이 전체 포트폴리오를 훼손하는 것을 방지(Tuning Min 0.05 방어).
*   **위험/부작용**: 잦은 손절(Whipsaw)로 인한 누적 손실 및 거래 비용 증가.
*   **실행 내용**: 개별 종목 진입가 대비 -7% 도달 시 즉시 청산 및 3일간 재진입 금지.
*   **PASS 조건**:
    *   (1) 실험 정의: `StopLoss = -7%`, `Cooldown = 3 days` 로직 추가.
    *   (2) 게이트: Win Rate(승률) 변화폭 -5%p 이내, Profit Factor 개선.
    *   (3) 기대 관측치: MDD(최대 낙폭)의 유의미한 감소(-11% -> -8% 수준).

### [성능 정체 시 원인 분해 (Debugging Tree)]

성능 지표(Sharpe/MDD)가 48시간 내 개선되지 않을 경우, 다음 순서로 원인을 제거할 것.

1.  **트리거(Trigger) 실패**: 매수 신호가 너무 적거나(과최적화된 필터), 너무 많음(변별력 없음).
    *   *Check*: 연간 거래 횟수가 종목당 10회 미만인가? -> 진입 장벽 완화 필요.
2.  **적용(Allocation) 실패**: 좋은 종목을 샀으나 비중이 너무 적음.
    *   *Check*: 수익 상위 3개 종목의 평균 비중이 5% 미만인가? -> 확신 있는 종목 비중 확대(Concentration).
3.  **비용(Cost) 과다**: 잦은 리밸런싱으로 수익 잠식.
    *   *Check*: `Gross Profit`과 `Net Profit` 차이가 30% 이상인가? -> 리밸런싱 주기 완화(Daily -> Weekly) 또는 Turnover Penalty 도입.
4.  **레짐(Regime) 불일치**: 현재 로직이 '저금리/상승장'에만 특화됨.
    *   *Check*: 2022년(금리인상기) 성과가 다른 해 대비 -50% 이하인가? -> 금리(TNX) 또는 달러지수(DXY)를 Feature로 추가하여 매매 강도 조절.
