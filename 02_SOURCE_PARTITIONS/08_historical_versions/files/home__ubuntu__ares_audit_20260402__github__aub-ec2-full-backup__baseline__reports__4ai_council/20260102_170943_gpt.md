## 다음 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — 명령형 체크리스트

### 1) **누수(lookahead / asof 정렬) 최우선 차단**
- **왜 필요한지**
  - tuning/lockbox 괴리, fold별 MDD 급락은 “미세 누수/정렬 실수/리밸런싱 시점 착오”에서 가장 자주 발생.
  - 특히 재무/가이던스/서프라이즈/리비전류가 있으면 공시 시점(as-of) 누수 가능성이 높음.
- **위험/부작용**
  - 단기적으로 성능 하락(“진짜 알파”가 아닌 누수 성분 제거).
  - 데이터 로더/피처 캐시 무효화로 실행시간 증가.
- **최소 실험(2~3개)**
  - **[A] 시간무결성(Temporal Integrity) 강제 패치** 실행
  - **[E] Purged/Embargo CV로 재평가** 실행
  - (선택) **[C] 코퍼레이트액션/심볼이력 정합** 일부 포함(스플릿/배당/리네임)
- **PASS 조건**
  - (필수) **누수 의심 테스트에서 0건**(아래 실험 A의 게이트 통과)
  - (성능) lockbox_mean **하락 허용폭 ≤ 10%** 이내에서 **worst_mdd 개선 또는 유지**(현재 worst_mdd -0.0815 기준, **-0.0815보다 악화 금지**)

---

### 2) **비용(슬리피지/스프레드/턴오버) 미반영 리스크 제거**
- **왜 필요한지**
  - Tech+Healthcare 8~14개 집중 포트는 회전율이 조금만 올라가도 “백테스트-실거래” 괴리 급증.
  - 후보(candidate)가 fold14_mdd, worst_mdd가 크게 악화된 건 “스트레스 구간에서 잦은 리밸런스” 가능성.
- **위험/부작용**
  - 비용 모델을 넣으면 과거 성능이 크게 떨어져 전략 폐기처럼 보일 수 있음(하지만 현실 적합도는 상승).
  - 비용 가정이 과도하면 알파를 과소평가.
- **최소 실험(2~3개)**
  - **[B] 거래비용+슬리피지 모델 추가** 실행
  - **[D] 레짐(리스크오프)에서 노출 축소 게이트** 실행(비용/드로우다운 동시 감소 목적)
- **PASS 조건**
  - (필수) 비용 포함 후에도 **lockbox_min > 0 유지**(현재 챔피언 lockbox_min 0.7355 수준; 절대치 목표는 시스템 기준에 맞추되 **음수 금지**)
  - (리스크) **턴오버 상한 도입 후 worst_mdd 악화 금지**

---

### 3) **서바이버십/상장폐지/심볼 변경(운영 데이터 리스크) 제거**
- **왜 필요한지**
  - “US 주식 only” + 섹터 집중에서, 심볼 변경/인수/상폐/분할 이벤트가 누적되면 백테스트가 조용히 왜곡됨.
  - 운영 자동루프(48시간)에서 데이터 이상이 한번만 터져도 챔피언 교체가 오염될 수 있음.
- **위험/부작용**
  - 데이터 소스에 따라 상폐수익률/과거 심볼 매핑이 불완전 → 구현 난이도 상승.
- **최소 실험(2~3개)**
  - **[C] 심볼 히스토리/상폐/코퍼레이트액션 정합 패치** 실행
  - **[A] 시간무결성 패치**와 함께 재검증(“정합+시간” 동시 통과가 중요)
- **PASS 조건**
  - (필수) 유니버스 재구성 후 **백테스트 가능 종목 수/기간 결손 0**(결손 발생 시 FAIL)
  - (성능) 챔피언 대비 **fold14_mdd 개선 또는 동일**, worst_mdd 악화 금지

---

### 4) **과최적화 방지: 검증 체계(Purged/Embargo + 안정성 지표) 강화**
- **왜 필요한지**
  - 후보가 tuning 대비 lockbox가 낮거나, 특정 fold(MDD)에서 무너지는 패턴은 “특정 구간 맞춤” 신호.
  - 챔피언의 lockbox_mean이 tuning_mean보다 큰 구조(2.32 vs 4.01)는 “검증 분포가 다르거나 누수/편향/표본 차” 가능성도 함께 점검 필요.
- **위험/부작용**
  - 더 엄격한 검증을 적용하면 통과 후보가 줄어 탐색 속도 저하.
- **최소 실험(2~3개)**
  - **[E] Purged/Embargo CV + 부트스트랩 안정성 지표** 실행
  - **[A] 누수차단** 후 재측정(“검증 강화”는 “시간무결성” 전제)
- **PASS 조건**
  - (필수) **tuning↔lockbox 성능 괴리 축소**(예: mean 기준 |tuning-lockbox|가 기존 대비 감소)
  - (리스크) **worst_mdd 개선 또는 동일**

---

### 5) **레짐(ETF 관측지표) 기반 노출 게이트로 ‘드로우다운 바닥’ 올리기**
- **왜 필요한지**
  - Tech+Healthcare는 금리/리스크오프 레짐에서 동시 하락(상관↑)이 잦음.
  - ETF는 “매매 제외” 조건이므로 **관측 지표로만** 사용해 자동 루프에서 리스크를 낮추는 게 효율적.
- **위험/부작용**
  - 레짐 게이트가 과하게 작동하면 수익 기회를 놓쳐 lockbox_mean 하락 가능.
  - 지표 선택이 잘못되면 “추세추종/평균회귀” 충돌.
- **최소 실험(2~3개)**
  - **[D] ETF 관측지표 기반 리스크오프 게이트(노출 축소/현금 비중 증가)** 실행
  - **[B] 비용 모델**과 함께 평가(게이트가 거래를 줄여 비용 감소 효과)
- **PASS 조건**
  - (필수) **worst_mdd 개선**(현 -0.0815보다 덜 음수)
  - (성능) lockbox_mean 하락 시에도 **하락폭 ≤ 10%** 이내

## 48시간 자동 루프용 “실행 가능한 Patch/실험” (총 5개로 제한)
아래 **A~E 5개만** 돌리고, TOP5 항목은 이 5개를 조합해 커버하라(케이스 폭발 금지).

---

### [A] Temporal Integrity(시간무결성) 강제 + 누수 감지 패치
1) **실험 정의**
- 모든 피처에 대해 `asof` 머지 강제(공시/지표 timestamp를 “알 수 있었던 시점”으로 스냅).
- 리밸런싱 시점 기준으로 **피처 1-bar(또는 1-day) lag 강제 옵션** 토글 추가.
- “미래값 참조” 자동 탐지 테스트 추가:
  - `feature_time > decision_time` 건수 집계
  - 종가 기반 라벨이면 체결/결정 시점과 가격 사용 시점 분리(예: decision at t close면 사용 가능 데이터는 t close까지)
2) **게이트(실패 시 즉시 중단)**
- `future_ref_count == 0`
- `asof_merge_missing_rate < 0.1%` (과도 결손이면 데이터 파이프 문제로 FAIL)
3) **기대 관측치**
- tuning 성능 소폭 하락 가능
- 대신 fold별 성능 분산 감소, 특정 fold(MDD 급락) 완화
- tuning-lockbox 괴리 구조가 “더 설명 가능”해짐

---

### [B] 거래비용/슬리피지/턴오버 상한 패치
1) **실험 정의**
- 종목별 비용 모델(최소 구성):
  - `cost = spread_bps + k * (|trade_value| / ADV) + fee_bps`
  - 변동성 높을수록 슬리피지 가중(옵션: `k *= (1 + vol_z)`).
- 포트폴리오 레벨 턴오버 상한 또는 거래 페널티(라그랑지/soft penalty) 추가.
2) **게이트**
- 비용 포함 후 `lockbox_min > 0`
- 평균 턴오버가 기준 대비 감소(예: -20% 이상) **또는** 비용총합/수익 비율이 개선
3) **기대 관측치**
- gross 성능 하락하나 net 안정성↑
- worst_mdd가 유지되거나 개선되면 “현실 적합도” 상승 신호

---

### [C] 서바이버십/심볼 히스토리/코퍼레이트액션 정합 패치
1) **실험 정의**
- 심볼 변경/리네임/머지 이력 테이블을 별도 ID로 정규화(가능하면 PERMNO류 surrogate key).
- split/dividend 조정의 일관성 검사(조정가격/원가격 혼용 방지).
- (가능하면) delisting return 반영 또는 상폐 종목 제거 규칙을 명시적으로 동일 적용.
2) **게이트**
- 유니버스 생성 시점별 종목 수 급변(outlier) 탐지: z-score로 이상치면 FAIL
- 조정가격/원가격 혼용 탐지 테스트 PASS
3) **기대 관측치**
- 과거 특정 구간 성능이 “재현 불가하게 좋던 부분”이 정상화될 수 있음
- 운영 안정성(데이터 결손/에러)이 눈에 띄게 감소

---

### [D] ETF 관측지표 기반 레짐 게이트(매매 금지, 지표로만)
1) **실험 정의**
- ETF는 지표로만 사용: 예) **QQQ(tech risk), XLV(healthcare), IWM(리스크 선행), TLT(금리/리스크오프)**  
- 간단한 게이트(한 가지 형태만 선택해 과최적화 방지):
  - risk-off: `QQQ < MA(50)` 또는 `IWM/QQQ 약세` 또는 `TLT 급등(리스크오프)` 시
  - 동작: **총 노출(gross) 30~60%로 축소** 또는 현금 비중 증가, 리밸런스 빈도 감소
2) **게이트**
- 게이트 발동 비율이 과도하지 않음(예: 전체 기간의 10~40% 범위; 밖이면 FAIL로 간주하고 파라미터 고정/폐기)
- worst_mdd 개선 확인(최소 1개 fold에서라도 개선 없으면 보류)
3) **기대 관측치**
- 수익률 상단은 약간 깎여도, 하단(lockbox_min)과 worst_mdd가 개선되는 형태 기대

---

### [E] Purged/Embargo CV + 안정성(분산/민감도) 리포트 자동화
1) **실험 정의**
- Purged CV(라벨 누수 방지) + embargo window 적용.
- 결과 리포트에 아래를 자동 출력:
  - fold별 mean/min, worst_mdd, turnover, 비용총합(실험 B와 결합 시)
  - 하이퍼파라미터 민감도(상위 3개 설정의 성능 분산)
2) **게이트**
- “선정 기준”을 단일 평균이 아니라 **하방/드로우다운 포함**으로 고정:
  - 예: `lockbox_mean` + `lockbox_min` + `worst_mdd` 3요소 중 2개 이상이 챔피언 대비 개선/동일 아니면 FAIL
3) **기대 관측치**
- 후보가 잘 바뀌지 않더라도 “왜 안 바뀌는지”가 수치로 분해됨(과최적화/레짐/비용/누수)

---

## 성능이 안 움직일 때: 원인 분해(트리거/적용/노출/비용/레짐) 체크리스트
아래를 **로그/리포트에 강제 출력**해서 “어디서 죽는지”를 48시간 루프에서 자동 분해하라.

1) **트리거(신호 발생)**
- 신호 발생 빈도(일/주당 엔트리 수), 신호 강도 분포(상위 5%/하위 5%)
- 예측력(IC/RankIC)과 실현수익의 연결(신호 분위수별 다음기간 수익)
- 신호가 특정 1~2 종목에만 과집중되는지(8~14 종목 제약 내에서 편중 체크)

2) **적용(포트 구성/리밸런싱 구현)**
- 결정 시점 vs 체결 시점 분리 로그(결정가격/체결가격/다음날 시가 등)
- 리밸런싱 주기 변경 시 성능 민감도(일간↔주간): 지나치게 민감하면 구현/비용/누수 의심
- 포지션 캡/섹터 캡/종목수(8~14) 제약이 실제로 지켜졌는지(위반 횟수 0이어야 함)

3) **노출(팩터/베타)**
- QQQ/XLV/TLT에 대한 회귀 베타(롤링 60일)와 성과의 상관
- “알파”가 아니라 “나스닥 베타”로 먹는 구간인지 확인(베타 제거 후 성과도 유지되는지)
- drawdown 구간에서 상관이 1로 수렴하는지(집중 포트의 구조적 취약점)

4) **비용(현실 수익 잠식)**
- 총거래비용/총수익 비율, 비용이 큰 상위 10% 거래 추적(어떤 종목/어떤 상황인지)
- turnover가 성과에 미치는 기여(턴오버 높은 구간의 샤프/손익 악화 여부)
- 슬리피지 모델 민감도(비용 0.5x/1x/2x에서 전략 순위가 뒤집히면 취약)

5) **레짐(시장 상태)**
- 레짐별 성과 테이블:
  - QQQ 추세 상/하, 금리(TLT) 급변, 변동성 급등 구간 등에서 성과/최대낙폭 분리
- 레짐 필터(D 실험) 적용 전/후의 **하방(min)과 worst_mdd** 비교가 핵심(평균만 보면 착시)

## 24~48시간 실행 순서(권장) — 명령형
1) **[A] 누수/시간무결성 패치 적용 후 전체 리런**(게이트 미통과 시 즉시 중단)
2) **[E] Purged/Embargo CV 리포트 자동생성으로 “움직이지 않는 이유”를 수치화**
3) **[B] 비용/턴오버 모델 적용**(net 기준으로만 후보 비교)
4) **[D] ETF 관측지표 레짐 게이트 1종만 고정해 테스트**(파라미터 스윕 금지)
5) **[C] 심볼/코퍼레이트액션 정합을 운영 리스크 관점에서 마감**(데이터 결손/혼용 0건)

위 5개를 돌린 다음에만 챔피언 교체를 시도하라. (누수/비용/서바이버십/운영 리스크가 정리되지 않은 상태의 성능 개선은 대부분 재현되지 않는다.)
