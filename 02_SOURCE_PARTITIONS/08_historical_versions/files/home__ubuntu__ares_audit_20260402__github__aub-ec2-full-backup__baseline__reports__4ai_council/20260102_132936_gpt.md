# TOP5 우선순위 제안 (코드/아키텍처/전략)

## 1) (최우선) 누수/룩어헤드/발표지연 강제: “as-of 강제 + 단위테스트”
**왜 필요한지**
- 지금 후보는 `tuning_min`이 극단적으로 낮고(0.05), lockbox는 나쁘지 않은데 최악 MDD가 악화(-0.1118). 이런 패턴은 **(1) 신호의 시간정렬 미세 누수**, **(2) 리밸런스 시점 대비 데이터 가용성 미반영**, **(3) corporate action 처리 불일치**에서 자주 발생.
- 누수는 성능을 “가짜로” 올리거나, 반대로 특정 fold에서만 급락(불안정)시키기도 함.

**위험/부작용**
- 누수를 제거하면 **평균 성능이 단기 하락**할 수 있음(정상).
- 발표지연을 보수적으로 잡으면 신호가 둔해져 **턴오버 감소/알파 감소** 가능.

**최소 실험(2~3개) — E1/E5 재사용**
- **[E1] As-of join + 가용성 캘린더 강제 패치**
  - (1) 실험 정의: 모든 피처/라벨 생성 시 **“리밸런스 시점에 이용 가능했던 데이터만”** 남기도록 `asof` 머지/shift를 일괄 적용(특히 fundamentals, macro, 이벤트성 지표). corporate action(분할/배당) 반영 시점도 동일 룰로 통일.
  - (2) 게이트: leakage unit test 0 fail + “피처 timestamp ≤ decision timestamp” 위반 0건
  - (3) 기대 관측치:  
    - tuning_mean 소폭 하락 가능  
    - 대신 fold 간 분산 감소, `tuning_min`/`lockbox_min` 개선 또는 안정화
- **[E5] 관측지표(ETF 등)로 ‘미래정보 탐지’ 리포트 추가**
  - (1) 실험 정의: QQQ/XLV/IEF/TLT/VIX 등은 **거래 금지**, 단 **(a) 리밸런스 시점에 관측 가능한 값만** 사용해 “성능이 특정 구간에서만 폭발하는지” 레짐 리포트 생성
  - (2) 게이트: 레짐 리포트 생성이 backtest 파이프라인을 깨지 않음(자동 루프 통과)
  - (3) 기대 관측치: 누수/정렬 문제 시 “특정 이벤트/레짐에서만 비정상 초과성과” 패턴이 잡힘

**PASS 조건**
- E1 적용 후 **lockbox_min 개선**(>= +0.05) 또는 **worst_mdd 악화 방지**(>= -0.095) 달성  
- `tuning_min` 극단값(0.05급)이 **구조적으로 사라지거나 완화**(예: >0.3 수준)

## 2) 서바이버십/유니버스 편향 제거: “point-in-time 유니버스 + 상장폐지/합병 처리”
**왜 필요한지**
- 8~14종목 소수 포트는 **유니버스 편향이 성과를 거의 결정**할 수 있음.
- “현재 살아남은 대형 Tech/Healthcare”만으로 과거를 테스트하면 **서바이버십 편향**으로 tuning은 좋아 보이는데 lockbox/실거래에서 깨짐.

**위험/부작용**
- point-in-time 구현은 데이터 요구가 커서, 완전한 PIT가 어려우면 **근사치(보수적 룰)**로 가야 함 → 성능 하락 가능.
- 상폐/인수 이벤트 처리가 추가되며 운영 복잡도 증가.

**최소 실험(2~3개) — E2/E1 재사용**
- **[E2] “유니버스 빌더”를 리밸런스 시점 동결 + 상폐 리턴/가격 공백 처리**
  - (1) 실험 정의: 매 리밸런스에서 유니버스를 **그 시점 기준**으로 동결(시총/유동성 필터도 그 시점 값). 상장폐지/합병으로 가격이 끊기면 **delisting return 처리(보수적)** 또는 강제 청산 룰 명시.
  - (2) 게이트: 과거 기간에 “현재 존재 종목만 남는” 현상(커버리지 급감/급증)이 사라지는지 체크
  - (3) 기대 관측치: 평균은 떨어져도 **최악구간(MDD/최저 성과)이 개선**되거나 분산 축소
- **[E1] corporate action 정합(분할/배당) 재검증**
  - (1) 실험 정의: split/dividend adjust 방식 단일화(가격/수량/리턴 중복반영 방지)
  - (2) 게이트: 조정 전후 수익률 점프(비정상 스파이크) 탐지 0건
  - (3) 기대 관측치: 특정 하루/주에 발생하던 비정상 손익 스파이크 제거

**PASS 조건**
- 유니버스 편향 제거 후에도 `lockbox_mean`이 **champion 대비 -0.03 이내**로 유지되면서 `lockbox_min` 또는 `worst_mdd`가 개선(= 더 “진짜” 성능)

## 3) 비용/슬리피지/회전율 미반영 제거: “거래비용 모델 + 비용 스윕”
**왜 필요한지**
- 소수 종목 전략은 신호가 조금만 흔들려도 **회전율이 성과를 잡아먹음**.
- 비용을 넣지 않으면 lockbox가 좋아 보여도 운영에서 “안 움직이는” 것처럼 보이거나 실제론 마이너스가 되기 쉽다.

**위험/부작용**
- 비용을 현실화하면 대부분 성능이 하락(정상).
- 비용 페널티가 과하면 신호가 둔화되어 기회 손실.

**최소 실험(2~3개) — E3/E4 재사용**
- **[E3] 거래비용 모델 업그레이드 + 비용 스윕(고정/스프레드/임팩트)**
  - (1) 실험 정의:  
    - 커미션(고정) + bid-ask spread(유동성 기반) + 간단 임팩트(거래대금 대비) 포함  
    - 비용 파라미터를 3단(낮음/기준/높음)으로 스윕해 강건성 측정
  - (2) 게이트: 비용 “기준”에서 성능이 유지되는 후보만 통과(낮음에서만 좋은 건 컷)
  - (3) 기대 관측치:  
    - turnover가 높았던 후보가 급격히 약화 → 그게 정상 신호  
    - 비용 하에서 살아남는 신호는 운영 적합
- **[E4] 회전율 상한/거래 빈도 제약(리밸런스 캘린더 고정)**
  - (1) 실험 정의: 리밸런스 빈도(예: 주/격주/월) 고정 + 턴오버 상한 페널티(포지션 변화량에 L1 페널티)
  - (2) 게이트: 비용 포함 PnL에서 성능 개선 또는 MDD 개선
  - (3) 기대 관측치: gross 알파는 줄어도 net 알파/최악구간 개선

**PASS 조건**
- 비용 “기준”에서 `lockbox_mean`이 champion 대비 **동일 이상** 또는 `lockbox_min` 유의 개선  
- 비용 “높음”에서도 성능이 **완전 붕괴하지 않을 것**(lockbox_mean이 1.6 아래로 급락하면 운영 부적합 신호)

## 4) 운영 리스크/포지션 리스크: “단일종목/섹터/베타/갭 리스크 캡”
**왜 필요한지**
- 8~14종목은 **단일종목 이벤트(임상/규제/실적 갭)**에 취약.
- 지금 worst_mdd가 후보에서 -0.1118까지 튀는 건 “리스크 오버레이 부재” 가능성이 큼.

**위험/부작용**
- 리스크 캡은 수익 상단도 제한.
- 과도한 캡은 포트가 “시장중립 흉내만” 내며 알파가 사라질 수 있음.

**최소 실험(2~3개) — E4/E5 재사용**
- **[E4] 리스크 오버레이(포지션 상한 + 섹터 캡 + 변동성 타깃)**
  - (1) 실험 정의:  
    - 단일 종목 최대 비중(예: 15~20%)  
    - Tech/Healthcare 내부에서도 서브산업 캡(가능하면)  
    - 포트 변동성 타깃(예: 10~12% ann)으로 레버리지/노출 자동 스케일
  - (2) 게이트: `worst_mdd` 개선 + lockbox_min 개선 우선
  - (3) 기대 관측치: tail 손실 감소, 성과 분산 감소
- **[E5] 레짐별 손실 기여(갭/이벤트 주간, VIX 상위구간) 리포트**
  - (1) 실험 정의: 큰 손실이 “언제/왜” 생겼는지 레짐 태깅(고VIX, 금리급등, QQQ underperform 등)으로 손실 원인 파악
  - (2) 게이트: 리포트 생성이 자동루프에 포함(아웃풋 파일 고정)
  - (3) 기대 관측치: 손실이 특정 레짐에 집중되면 “레짐 기반 노출 제한” 근거 확보

**PASS 조건**
- `worst_mdd >= -0.095` 달성(최소 악화 방지) + `lockbox_min` 개선(>= +0.03)

## 5) “성능이 안 움직이는” 원인 해결용: 모델-노출-비용-레짐 분해(측정 체계)
**왜 필요한지**
- 현재 champion과 candidate가 lockbox_mean이 비슷한데, tuning 안정성/최악 MDD에서 흔들림. 이 구간은 **‘더 똑똑한 알파’보다 ‘측정/분해’가 먼저**다.
- 성능 정체는 보통 (a) 트리거가 작동 안 함 (b) 적용(리밸런스/딜레이)에서 죽음 (c) 노출이 엉뚱함 (d) 비용으로 상쇄 (e) 레짐 드리프트 중 하나.

**위험/부작용**
- 분해 로깅/리포트가 늘면서 계산량 증가.
- 메트릭을 잘못 잡으면 잘못된 최적화로 유도.

**최소 실험(2~3개) — E5/E3 재사용**
- **[E5] “원인 분해 대시보드” 자동 산출(48h 루프 산출물)**
  - (1) 실험 정의: 아래 분해 항목을 **매 실행마다 고정 포맷으로 저장**(csv/json/markdown)
  - (2) 게이트: 리포트 누락 0회 + 지표가 NaN/빈값이면 실패 처리
  - (3) 기대 관측치: “안 움직이는 이유”가 수치로 드러남(턴오버/비용/노출/레짐 중 어디가 병목인지)
- **[E3] 비용/슬리피지 민감도와 성과 민감도를 한 화면에 연결**
  - (1) 실험 정의: 비용 스윕 결과와 turnover, trade count, avg holding period를 같이 출력
  - (2) 게이트: 비용 증가에 대해 성과가 단조롭게 나빠지는지(비정상적인 경우 모델/비용 버그 의심)
  - (3) 기대 관측치: 비용에 극단 민감하면 “회전율 제약(E4)”이 우선임이 확정

**PASS 조건**
- 성능 개선이 아니라도, **원인 분해 리포트가 자동 루프에서 안정적으로 생성**되고, 다음 1~2회 사이클에서 “어디를 고치면 개선될지”가 숫자로 확정되면 통과(측정 인프라 PASS)

# 실험 정의 요약 (48시간 자동 루프에 넣는 형태: 정의/게이트/기대 관측치)

### E1) As-of / 발표지연 / corporate action 정합 패치
- 정의: 피처/라벨 생성 시점 엄수, as-of merge 강제, shift 규칙 통일
- 게이트: timestamp 위반 0, 조정 스파이크 탐지 0
- 기대: tuning 과대/불안정 감소, min 계열 안정화

### E2) PIT 유니버스 + 상폐/합병 처리
- 정의: 리밸런스 시점 유니버스 동결, 유동성/시총 필터 PIT 적용, 상폐 리턴 룰
- 게이트: 현재종목-only 편향 신호 제거, 커버리지 급변 제거
- 기대: 평균 하락 가능, tail 개선/분산 감소

### E3) 비용 모델 + 비용 스윕
- 정의: 커미션+스프레드+임팩트, 3단 스윕
- 게이트: “기준 비용”에서만 평가, 낮은 비용에서만 좋은 후보 컷
- 기대: turnover 높은 후보 탈락, net 기준 강건 후보 선별

### E4) 리스크 오버레이(캡/볼 타깃/턴오버 페널티)
- 정의: 종목 최대비중, 섹터 캡, 변동성 타깃, 턴오버 페널티
- 게이트: worst_mdd/lockbox_min 우선 개선
- 기대: tail 감소, 운영 내구성↑

### E5) 레짐/원인분해 리포트(ETF는 관측만)
- 정의: QQQ/XLV/IEF/TLT/VIX 등 관측지표로 레짐 태깅, 손실 기여/노출/비용/턴오버 리포트 자동 저장
- 게이트: 리포트 누락/NaN=실패
- 기대: 정체 원인(트리거/적용/노출/비용/레짐) 확정

# 성능이 안 움직일 때 “원인 분해” 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **명령형 체크리스트**로 1회 실행마다 자동 산출(E5로 고정)하라.

## A) 트리거(신호) 문제
- 신호 분포(평균/표준편차/꼬리)와 과거 대비 드리프트를 로그로 남겨라
- 예측값 상위/하위 분위 포트의 **ex-ante 스프레드(다음기간 리턴 차)**를 출력하라
- “신호가 0 근처로 붕괴”하면: 스케일링/정규화 윈도/결측 처리 변화를 의심하라

## B) 적용(리밸런스/딜레이/실행) 문제
- decision timestamp → order timestamp → fill timestamp를 분리해라(백테스트에서는 최소 1-bar 딜레이 강제)
- 리밸런스 캘린더 변경(주/월) 시 성과가 갑자기 좋아지면: 원래는 **미세 룩어헤드/체결 가정** 가능성을 의심하라
- 체결가(종가/시가/VWAP) 가정별 성과 민감도를 출력하라

## C) 노출(팩터/베타/섹터/단일종목) 문제
- 포트의 beta(대략 QQQ), duration proxy(IEF/TLT 관측), healthcare/tech 내부 비중을 매 리밸런스마다 기록하라
- 성과가 QQQ 방향성과 거의 동일하면: 알파가 아니라 **베타**다 → E4로 베타/변동성 타깃을 먼저 걸어라
- 손실 상위 5거래(또는 5일)의 종목 기여도를 출력하라(단일종목 리스크 확인)

## D) 비용(턴오버/슬리피지) 문제
- turnover, 거래횟수, 평균 보유기간, 비용/총손익 비율을 고정 포맷으로 저장하라
- 비용 스윕(E3)에서 성과가 비정상적으로 “비용↑인데 성과↑”면 비용/체결 로직 버그를 의심하라
- net 성과가 0 근처면: 회전율 제약(E4) 또는 신호 홀딩기간 연장부터 적용하라

## E) 레짐(시장상태) 문제
- VIX 상/하위 구간, 금리 급등락 구간, QQQ vs XLV 상대강도 구간별 성과를 조건부로 분해하라(ETF는 관측만)
- 특정 레짐에서만 붕괴하면: 레짐-조건부 포지션 스케일(노출 축소)만 먼저 적용하라(E4/E5 연결)

---

## 24~48시간 실행 순서(명령형)
1) **E1 먼저 머지**: as-of/가용성/unit test 추가 → 자동 루프에서 “누수 0” 확인  
2) **E3 동시 착수**: 비용 모델 + 비용 스윕 결과를 lockbox와 함께 저장  
3) **E4 적용**: 포지션 캡/볼 타깃/턴오버 페널티로 tail 우선 안정화  
4) **E2는 2순위로 병렬**: PIT 유니버스/상폐 처리(가능한 범위에서 보수적으로)  
5) **E5는 상시**: 레짐/원인분해 리포트가 매 실행 산출되도록 고정(다음 사이클 의사결정 자동화)

이 5개(E1~E5)만으로도 “성능이 안 움직이는 이유”를 48시간 내에 **측정 가능한 형태로 고정**하고, 동시에 lockbox의 **min/MDD 안정화**를 우선 달성하는 방향으로 다음 후보들을 빠르게 걸러낼 수 있다.
