아래 TOP5는 **누수/과최적화/서바이버십/비용 미반영/운영 리스크**를 최우선으로 먼저 잠그고, 그 다음에 **Tech+Healthcare 8~14개 종목(미국주식 only, ETF 매매 제외)** 조건에서 48시간 자동 루프에 바로 얹을 수 있는 **실행형 patch/실험**으로 제한함.

## TOP1) (누수/평가 버그) Lockbox 평가 “동일값 재사용/캐시/데이터 공유” 차단 패치
### (a) 왜 필요한지
- 현재 로그에서 **Champion과 최근 Candidate의 lockbox_mean/min, mdd가 동일하게 찍히는 패턴**은 정상적인 개선/악화가 반영되지 않았을 가능성을 강하게 시사.
- 이 케이스는 성능 정체의 “진짜 원인”이 아니라 **측정/평가 파이프라인 문제**일 수 있어, 최우선으로 제거해야 함.

### (b) 위험/부작용
- 캐시를 끊고 재평가하면 런타임/비용 증가.
- 기존 “좋아 보이던” 성능이 하향 재평가될 수 있음(그러나 이게 맞는 방향).

### (c) 최소 실험 2~3개 (48시간 루프형)
**실험 1: Lockbox 평가 강제 재계산(캐시 무효화)**
- (1) 실험 정의: lockbox 산출 단계에 `run_id` 기반 캐시 키를 강제 주입 + 기존 결과 파일 재사용 금지 옵션 추가  
- (2) 게이트: 동일 candidate를 2회 연속 실행 시 lockbox 리포트의 `hash/signature`가 달라지지 않고, 지표는 동일(재현성)이어야 함. 단, “이전 run 결과 파일을 재사용한 흔적”이 없어야 함.  
- (3) 기대 관측치: 재현 가능한 동일 결과 + “캐시 히트 없이” 동일값 산출

**실험 2: 데이터 스플릿 누수 체크(시간/심볼/피처)**
- (1) 실험 정의: lockbox 기간의 원천 데이터/피처 생성 로그에 “최신일자 참조 여부(lookahead)” 검증 훅 추가(예: rolling window가 미래를 참조하는지, 리밸런싱 시점 이후 종가를 쓰는지)  
- (2) 게이트: lockbox 구간에서 피처 생성 시 사용된 최대 timestamp ≤ 의사결정 timestamp  
- (3) 기대 관측치: 위반 케이스 0건 (발견 시 즉시 차단)

**실험 3: “동일지표” 원인 트레이싱(artifact fingerprint)**
- (1) 실험 정의: tuning/lockbox 산출물에 (모델 파라미터, 데이터 버전, 유니버스, 비용 설정)의 fingerprint를 의무 기록  
- (2) 게이트: champion vs candidate의 fingerprint가 다르면 lockbox 지표도 달라져야 정상. 다름에도 동일 지표면 버그로 판정  
- (3) 기대 관측치: 지표-아티팩트 일관성 확보

### (d) PASS 조건
- lockbox 평가가 **캐시/재사용 없이** 재현 가능하게 고정되고,
- fingerprint가 다른데 지표가 동일하게 찍히는 케이스가 0,
- lookahead 위반 0.

## TOP2) (비용 미반영) 슬리피지/수수료/스프레드/리밸런싱 충격 “보수적 비용 모델” 도입
### (a) 왜 필요한지
- Tech/Healthcare 개별주 8~14개 운용은 회전율/스프레드/체결충격에 민감.
- 비용 모델이 낙관적이면 튜닝 성능은 높고 실전은 붕괴 → **과최적화의 대표 형태**.

### (b) 위험/부작용
- 백테스트 성과가 즉시 하락(현실 반영).
- 회전율 낮추는 방향으로 수익 기회가 일부 희생.

### (c) 최소 실험 2~3개
**실험 1: 비용 스트레스 테스트(3단계)**
- (1) 실험 정의: (기본 비용) / (2배) / (4배) 3단계로 lockbox 재평가  
- (2) 게이트: 비용 2배에서도 lockbox_mean이 챔피언 대비 급락(예: -0.15 이상)하면 “비용 민감 과다”로 실패  
- (3) 기대 관측치: 비용 증가에 따른 성능 기울기(민감도) 정량화

**실험 2: 회전율 캡 + 재진입 쿨다운**
- (1) 실험 정의: 48시간 루프 내 리밸런싱에서 (i) 포트폴리오 turnover cap, (ii) 동일 종목 재진입 최소 대기일(쿨다운) 추가  
- (2) 게이트: turnover 20~40% 감소 + lockbox_mean 손실이 제한적(예: -0.03 이내)  
- (3) 기대 관측치: 비용 반영 후 성능의 안정화(순성과 개선)

**실험 3: 체결가격 보수화(종가→VWAP/다음날 시초 가정)**
- (1) 실험 정의: 신호는 t에 생성, 체결은 t+1 시초 혹은 VWAP로 이동(lookahead 방지 겸)  
- (2) 게이트: lockbox_mean 급락 없이(예: -0.05 이내) 유지되면 신호가 “체결지연 내구성” 보유  
- (3) 기대 관측치: 실전 근접 성능 추정치 확보

### (d) PASS 조건
- 비용 2배 환경에서도 lockbox_mean이 챔피언 대비 **유의미 붕괴 없이** 유지(민감도 완만),
- turnover 감소 패치가 mdd를 악화시키지 않음(worst_mdd 챔피언 대비 -0.01 이내).

## TOP3) (서바이버십/유니버스 리스크) 8~14 Tech+Healthcare 종목 선정의 “생존편향/사후선정” 차단
### (a) 왜 필요한지
- “현재 잘 아는/살아남은” 대형주 위주로 과거를 돌리면 생존편향이 생기고, lockbox에서만 좋아 보이는 착시 발생.
- 특히 Tech/Healthcare는 상장폐지/합병/티커 변경/스핀오프가 잦아 데이터 정합성이 성과에 직접 영향.

### (b) 위험/부작용
- 데이터 소스/매핑 작업 증가.
- 유니버스가 현실적으로 축소될 수 있음(거래가능성 필터 강화).

### (c) 최소 실험 2~3개
**실험 1: “시점-정합 유니버스” 고정(룰 기반)**
- (1) 실험 정의: 매 리밸런스 시점 t에서만 알 수 있는 정보로 유니버스 구성(예: 시가총액/유동성 필터를 t시점 데이터로), Tech/Healthcare 섹터는 GICS 시점 데이터 사용  
- (2) 게이트: 유니버스 구성에 미래 데이터 접근 로그 0건  
- (3) 기대 관측치: 성과가 다소 내려가도(정직해져도) 변동이 설명 가능해짐

**실험 2: 기업행동(스플릿/합병/상폐) 이벤트 강제 시나리오**
- (1) 실험 정의: 과거 구간에서 티커 변경/상폐 발생 종목이 포함되면 해당 구간 거래/가격 처리 규칙을 명시(거래중지/최종가격/현금화 등)  
- (2) 게이트: 이벤트 발생일 전후 PnL 점프/비정상 가격 0건  
- (3) 기대 관측치: “깨끗한” equity curve, 꼬리위험 감소

**실험 3: 유동성/스프레드 기반 거래가능 필터**
- (1) 실험 정의: ADV(평균거래대금) / 가격 / 스프레드 대용치로 거래가능 종목만 편입  
- (2) 게이트: lockbox에서 체결불가(거래량 부족) 시뮬레이션 비율 0  
- (3) 기대 관측치: 비용모델과 일관된 실전성 상승

### (d) PASS 조건
- 유니버스/기업행동 처리 변경 후에도 lockbox_mean이 **과도 붕괴 없이**(예: -0.05 이내) 유지되거나,
- worst_mdd 개선 또는 동일 수준 유지.

## TOP4) (과최적화) CV 구조 강화: Purge/Embargo + 하이퍼파라미터 “안정성 기준”으로 선택
### (a) 왜 필요한지
- tuning_mean이 높아도 실전/lockbox에서 안 움직이는 전형적 원인은 **시간의존 데이터에서의 정보누수 + 튜닝 과적합**.
- Purged K-Fold/Embargo, 안정성 기반 선택(평균이 아니라 하위 분위수/일관성)으로 완화.

### (b) 위험/부작용
- 튜닝 성능 하락(정상).
- 탐색 공간 축소로 “가끔 대박” 설정을 버리게 됨.

### (c) 최소 실험 2~3개
**실험 1: Purge/Embargo 적용한 워크포워드 재튜닝**
- (1) 실험 정의: 각 fold 경계에 purge window + embargo 기간 추가  
- (2) 게이트: tuning_mean 하락은 허용하되, tuning_min(최악 fold) 개선 또는 변동성 감소(분산 감소) 확인  
- (3) 기대 관측치: “평균은 낮아도 견고한” 후보가 상위로 올라옴

**실험 2: 선택 기준을 mean→(p25, worst-fold, mean-λ*std)로 변경**
- (1) 실험 정의: 후보 선택을 평균 수익률이 아니라 하방 안정성 기준으로  
- (2) 게이트: lockbox_min이 챔피언 대비 악화되지 않음(예: -0.05 이내)  
- (3) 기대 관측치: lockbox에서의 실망(평균은 좋은데 최소가 깨짐) 감소

**실험 3: 파라미터 민감도 스윕(국소)**
- (1) 실험 정의: 챔피언 주변 파라미터를 작은 격자로 흔들어 성능면을 측정(국소 3x3 혹은 5점)  
- (2) 게이트: 국소 변화에 성능이 급격히 무너지는 “needle”이면 폐기  
- (3) 기대 관측치: 평탄한 성능면(robust basin) 확보

### (d) PASS 조건
- lockbox_mean이 소폭 개선(+0.02 이상)하거나,
- 개선이 없더라도 lockbox_min 및 worst_mdd가 **동일/개선**되면서(안정성↑) 추후 개선의 기반 확보.

## TOP5) (레짐/노출 관리) ETF는 “관측지표”로만: Risk-on/off 게이트 + 섹터 상대강도 기반 포지션 스케일링
*(ETF 매매는 금지, 신호용 지표만 사용)*

### (a) 왜 필요한지
- Tech/Healthcare는 레짐(금리/변동성/성장주 선호)에 따라 동일 신호의 기대값이 바뀜.
- “신호는 좋은데 안 움직임”은 종종 **레짐 미스매치로 알파가 상쇄**되는 현상.

### (b) 위험/부작용
- 게이트가 과도하면 기회 손실(undertrading).
- 지표 자체가 누수(미래 데이터)로 연결되면 위험 → 반드시 시점 정합.

### (c) 최소 실험 2~3개
**실험 1: 변동성 레짐 게이트(VIX/vol proxy)**
- (1) 실험 정의: VIX(또는 시장 변동성 지표) 상승/고변동 구간에서 포지션 총노출(총베타/총익스포저)을 축소  
- (2) 게이트: lockbox에서 worst_mdd 개선(챔피언 대비 +0.01 이상 개선) 없으면 폐기  
- (3) 기대 관측치: 꼬리구간 손실 완화, 성과가 동일해도 생존성↑

**실험 2: QQQ vs XLV 상대강도(Tech 선호/Defensive 선호) 기반 스케일**
- (1) 실험 정의: QQQ/XLV 상대 모멘텀으로 Tech 바스켓과 Healthcare 바스켓 비중을 60/40↔40/60 범위로 조절(종목 매매만)  
- (2) 게이트: 회전율 증가가 비용 모델 하에서 손해를 상쇄해야 함(순성과 기준으로 평가)  
- (3) 기대 관측치: 레짐별 기여도가 분리되어 성능 정체 원인(섹터 믹스) 해소

**실험 3: 금리 민감 레짐(10Y yield 변화율) 관측 후 duration-sensitive growth 노출 조절**
- (1) 실험 정의: 10Y 급등 구간에서 고밸류 성장주(Tech 내 특정 그룹) 스케일다운, Healthcare 비중 유지  
- (2) 게이트: lockbox에서 drawdown 구간의 손실 기여도 감소가 관측되어야 함  
- (3) 기대 관측치: 동일 신호라도 레짐에 따라 알파 소멸 구간을 피함

### (d) PASS 조건
- lockbox_mean +0.02 이상 **또는** worst_mdd 개선(+0.01 이상) + lockbox_mean 악화가 -0.03 이내.

# 24~48시간 실행 순서(명령형 체크리스트)
1) **Lockbox 캐시/재사용 차단 + fingerprint 로깅**을 최우선으로 적용하고, 동일 candidate 2회 재평가로 재현성/독립성 확인  
2) **비용 모델 3단계 스트레스**를 즉시 돌려 비용 민감도 곡선을 확보하고, turnover cap/체결지연 가정을 함께 비교  
3) **유니버스 시점정합(서바이버십 차단)** 패치를 넣고 기업행동 이벤트가 있는 구간을 강제 통과시키며 이상치 점프 제거  
4) Purge/Embargo + 안정성 기반 선택 기준으로 튜닝/선정 규칙을 교체하고, 국소 민감도 스윕으로 needle 파라미터 제거  
5) ETF 지표(관측치)로 레짐 게이트 1~2개만 추가해(케이스 폭발 금지) drawdown 완화 여부를 lockbox에서 확인

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래는 **원인 규명용 계측/분해 항목**이며, 질문 없이 바로 로깅/리포트로 붙여서 48시간 루프에 태울 수 있는 형태로 정리.

## 1) Trigger(신호 발생) 문제
- 신호 발생 빈도(일/주당), 상위/하위 신호의 분포(스코어 히스토그램), 신호의 자기상관(신호가 거의 상수면 무효)
- 관측: “신호는 변하는데 포지션이 안 바뀜” vs “신호 자체가 안 변함”을 분리

## 2) Apply(적용/제약/리밸런싱) 문제
- 제약 바인딩 비율: 상한/하한/현금비중/섹터 캡이 실제로 얼마나 자주 걸리는지
- 주문 생성 후 필터(유동성/리스크/쿨다운)로 컷되는 비율
- 관측: 알파가 “제약에 의해 눌려” 실현되지 않는지 확인

## 3) Exposure(노출/상쇄) 문제
- 포트폴리오 베타, 섹터/팩터(성장/가치/퀄리티/모멘텀) 노출을 일별로 추정해 “의도한 알파 vs 시장요인” 분리
- 롱/숏(또는 고위험/저위험) 쏠림, 상관 높은 종목만 모이는지(8~14개에서 치명적)
- 관측: 개별 알파가 서로 상쇄되는 구성인지(다중공선) 확인

## 4) Cost(비용/회전율) 문제
- 총거래대금, turnover, 평균 보유기간, 체결지연 가정별 PnL 차이(종가 체결 vs t+1 시초)
- 비용의 PnL 기여(총수익-비용=순수익) 분해: “총은 괜찮은데 비용이 다 먹는지” 즉시 판별

## 5) Regime(레짐) 문제
- VIX 고/저, 금리 급등/급락, QQQ/XLV 상대강도 구간별로 성과를 슬라이스
- 관측: 특정 레짐에서만 먹히는 전략인지(레짐 의존) → 게이트/스케일링의 근거 확보

## 6) 운영/데이터 파이프라인 문제(가장 흔한 “정체 원인”)
- 데이터 결측/스플릿 조정/심볼 매핑 오류 건수, 이상치 캔들(0 거래량, 급점프) 탐지 카운트
- 결과 파일 재사용/캐시 히트율, run_id별 artifact 불일치
- 관측: “성능이 안 움직임”이 사실은 “평가가 안 바뀜/데이터가 깨짐”인지 제거

---

원칙적으로 **TOP1(평가/누수) → TOP2(비용) → TOP3(서바이버십) 순서**로 먼저 잠가야, 이후 전략/레짐 패치(TOP4~5)가 의미 있는 성능 신호로 관측됨.
