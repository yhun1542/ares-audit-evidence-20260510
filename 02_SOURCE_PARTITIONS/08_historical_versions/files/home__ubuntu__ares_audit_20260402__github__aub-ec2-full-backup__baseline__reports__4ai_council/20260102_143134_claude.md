## 1. 우선순위 TOP 5 제안

### 🔴 P1. MDD 개선 (Fold14 -9.3% → -7% 목표)

**(a) 왜 필요한지**
- worst_mdd가 fold14에서 발생 → 최근 레짐(2024-2025 금리 변동기)에 취약
- Champion/Candidate 모두 -9~11% MDD → 실운용 시 -15% 이상 가능

**(b) 위험/부작용**
- 드로다운 회피 강화 → CAGR 10-20% 하락 가능
- 과거 MDD 최적화 ≠ 미래 MDD 방어

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P1-A | `vol_target` 15% → 12% 하향 | fold14_mdd > -8% AND lockbox_mean > 1.6 | CAGR -10%, MDD -25% 개선 |
| P1-B | `trailing_stop` 모듈 추가 (개별종목 -12% 청산) | worst_mdd > -8% | 종목당 손실 제한, 턴오버 +20% |
| P1-C | `regime_filter`: VIX>25 시 현금 50% | fold14_mdd > -7% | 2022년 구간 보호, 상승장 노출 감소 |

**(d) PASS 조건**
```
fold14_mdd > -0.08 AND lockbox_mean > 1.65 AND tuning_min > 0.3
```

---

### 🟠 P2. Lockbox 분산 개선 (min 1.13 → 1.25 목표)

**(a) 왜 필요한지**
- lockbox_min=1.13 → 특정 fold(레짐)에서 거의 무성과
- 실전 투입 시 해당 레짐 재현되면 1년간 횡보/손실

**(b) 위험/부작용**
- 분산 추구 → 평균 수익 희석
- 추가 팩터 = 추가 파라미터 = 과적합 리스크

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P2-A | `sector_cap` Tech 40% 상한 (현재 무제한?) | lockbox_min > 1.2 | Healthcare 노출↑, Tech 하락기 방어 |
| P2-B | `quality_score` 추가 (ROE>15%, D/E<1) | lockbox_min > 1.2 | 저품질 종목 필터, 턴오버 유사 |
| P2-C | `momentum_decay` 12M→6M 단축 | lockbox_std 감소 | 레짐 전환 반응 속도 개선 |

**(d) PASS 조건**
```
lockbox_min > 1.20 AND lockbox_mean > 1.75 AND fold14_mdd > -0.10
```

---

### 🟡 P3. 시그널 강건성 (Tuning Min 0.05 → 0.25 목표)

**(a) 왜 필요한지**
- Candidate의 tuning_min=0.05 → 특정 fold에서 사실상 실패
- 이게 lockbox에선 1.35로 역전 → **noise fitting 또는 fold 특성 의존**

**(b) 위험/부작용**
- 시그널 단순화 → 엣지 감소
- 앙상블 추가 → 복잡도/비용 증가

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P3-A | `signal_smooth`: 5일 MA 적용 | tuning_min > 0.20 | 노이즈 감소, 지연 +2일 |
| P3-B | `min_holding` 5일→10일 연장 | tuning_min > 0.20 | whipsaw 감소, 기회비용↑ |

**(d) PASS 조건**
```
tuning_min > 0.20 AND tuning_mean > 1.80 AND lockbox_mean > 1.70
```

### 🟢 P4. 운영 리스크 감소 (종목 수/턴오버)

**(a) 왜 필요한지**
- 현재 유니버스 크기/턴오버 미명시 → 실행 비용 불확실
- 8-14종목 규칙 준수 확인 필요

**(b) 위험/부작용**
- 집중 → 변동성 증가
- 분산 → 엣지 희석

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P4-A | `max_positions` = 12 하드코딩 | 평균 보유 10-12 유지 | 관리 가능성 확보 |
| P4-B | `turnover_penalty` 연 400% 상한 | 월 턴오버 < 35% | 비용 -0.5%p/년 |

**(d) PASS 조건**
```
avg_positions ∈ [8,14] AND annual_turnover < 400% AND lockbox_mean > 1.70
```

### 🔵 P5. 레짐 적응 (Macro Shadow 후속)

**(a) 왜 필요한지**

- 레짐 필터 방향은 유효, 파라미터 조정 필요

**(b) 위험/부작용**
- 매크로 지표 지연 (발표 lag 2-4주)
- 레짐 정의 과적합

**(c) 최소 실험**

lockbox_min > 1.25 AND fold14_mdd > -0.085 AND tuning_mean > 1.85

## 2. 48시간 자동 루프 스펙

```yaml
# experiment_system/config/48h_batch.yaml
experiments:
  - id: P1-A
    module: vol_target
    params: {target: 0.12}
    gate: "fold14_mdd > -0.08 and lockbox_mean > 1.6"
    
  - id: P1-C
    module: regime_filter
    params: {vix_threshold: 25, cash_pct: 0.5}
    gate: "fold14_mdd > -0.07"
    
  - id: P2-A
    module: sector_cap
    params: {tech_max: 0.40}
    gate: "lockbox_min > 1.2"
    
  - id: P3-A
    module: signal_smooth
    params: {window: 5}
    gate: "tuning_min > 0.2"
    
  - id: P5-A
    module: yield_curve_filter
    params: {threshold: 0, defense_mode: true}
    gate: "fold14_mdd > -0.085"

promotion_rule: |
  IF gate_pass AND lockbox_mean > champion.lockbox_mean * 0.98
  THEN promote_to_candidate
  
champion_rule: |
  IF lockbox_mean > champion.lockbox_mean 
  AND lockbox_min > champion.lockbox_min * 0.95
  AND fold14_mdd > champion.fold14_mdd
  THEN promote_to_champion
```

## 3. 성능 불변 시 원인 분해 트리

```
성능 안 움직임
│
├─► [1] 트리거 발생 안함
│   └─ 확인: 시그널 ON 횟수, 평균 포지션 변화율
│   └─ 조치: threshold 완화, lookback 단축
│
├─► [2] 트리거 → 적용 실패
│   └─ 확인: 시그널 vs 실제 포지션 일치율
│   └─ 조치: execution delay 확인, min_holding 충돌
│
├─► [3] 적용 → 노출 불충분
│   └─ 확인: 변경 종목의 포트폴리오 비중
│   └─ 조치: position_size 로직 점검
│
├─► [4] 노출 → 비용 상쇄
│   └─ 확인: gross return vs net return 차이
│   └─ 조치: 턴오버 감소, 슬리피지 모델 현실화
│
└─► [5] 레짐 미스매치
    └─ 확인: 해당 fold의 시장 특성 (bull/bear/sideways)
    └─ 조치: 레짐별 분리 분석, 조건부 전략
```

## 4. 즉시 실행 커맨드

```bash
# Step 1: 현재 Champion 재검증 (누수/비용 체크)
python3 experiment_system/tools/leak_check.py --config baseline/champion_v5_latest.json

# Step 2: 48시간 배치 실행
python3 experiment_system/tools/batch_runner.py \
  --spec experiment_system/config/48h_batch.yaml \
  --parallel 3 \
  --output baseline/reports/48h_results.json

# Step 3: 자동 프로모션 판정
python3 experiment_system/tools/auto_promote.py \
  --results baseline/reports/48h_results.json \
  --champion baseline/champion_v5_latest.json
```
