# TOP5 우선순위 제안 (각 제안별: 필요성/위험/검증실험/PASS)

## 1) (운영+재현성) 아티팩트/로그 스키마 고정 + 리밸런스 로그 “항상 생성”
### (a) 왜 필요한지
- 현재 `lane_hash/run_hash None`, 리밸런스 로그 파싱 실패로 **원인-결과 연결이 끊김** → 성능이 안 움직일 때 “전략이 문제인지/실행이 문제인지” 분해 불가.
- 자동 루프(48h)에서 **실험 비교의 기본 전제(재현성)**가 없음.

### (b) 위험/부작용
- 로깅/스키마 변경으로 **기존 리포트 파서가 깨질 수 있음**.
- 성능 개선이 아니라 “관측 가능성” 개선이라 단기적으로 답답하게 느껴질 수 있음.

### (c) 최소 실험(공유 실험 사용)
- **E3(리밸런스/런 로그 강제 + 리플레이)**, **E1(폴드/데이터 무결성 감사)** 적용
- (필수 패치 체크리스트)
  - `run_hash`, `lane_hash`, `git_commit`, `data_snapshot_id`, `universe_version`, `cost_model_version`를 **모든 결과 JSON에 강제 기록**
  - 리밸런스 이벤트를 **JSONL로 항상 출력**: timestamp, symbol, side, target_w, exec_w, price, shares, est_cost, realized_cost(가능시), reason_code
  - `aub_rebalance_pinpoint`가 읽는 입력을 **단일 규격**으로 통일(`rebalance.jsonl`)

### (d) PASS 조건
- (필수) 다음 48h 루프에서 **모든 실험이 동일한 스키마로 아티팩트 생성**, pinpoint/diagnoser가 **에러 없이 실행**
- (필수) 임의의 1개 런을 **리플레이(동일 seed/스냅샷)했을 때 핵심 메트릭 오차 < 1e-6** 또는 허용범위 내(결정적 재현)

---

## 2) (누수/과최적화) degenerate folds 원인 제거 + “시간/유니버스/피처” 누수 차단 게이트
### (a) 왜 필요한지
- `degenerate_folds`는 보통 아래 중 하나:
  - 특정 폴드에 **표본이 거의 없음/NaN 폭발/필터로 전부 제거**
  - **lookahead/label leakage**로 학습이 비정상적으로 쉬워짐
  - 유니버스 생존자 편향(상장폐지/합병/티커 변경)으로 폴드별 종목 수 급감
- 이 상태에서 OOS 평균이 좋아도 **실거래로 안 이어지는 “허상”** 가능성이 큼.

### (b) 위험/부작용
- 누수 차단/폴드 정상화 후 **성능이 급락**할 수 있음(하지만 그게 정상).
- 데이터 필터/결측 처리 강화로 **거래 신호 빈도 감소** 가능.

### (c) 최소 실험(공유 실험 사용)
- **E1(폴드 퇴화/누수 감사 & 자동 게이트)** + **E4(종목수/섹터 강제 제약 실험)**

### (d) PASS 조건
- (필수) 퇴화 폴드 0개(또는 정의한 허용치 이하) + 폴드별 샘플/종목 수가 **최소 기준 충족**
- (필수) “피처 timestamp ≤ 의사결정 timestamp” 규칙 위반 0건(자동 검사)

---

## 3) (비용 미반영) 거래비용/슬리피지/턴오버를 “게이트”로 승격 + 비용 민감도 테스트
### (a) 왜 필요한지
- Tech/Healthcare 8~14종목 집중 포트는 리밸런스가 잦으면 **실현 성과가 비용에 의해 쉽게 상쇄**됨.
- 현재 rebalance 데이터 추적이 깨져 있어 **비용이 사실상 미반영**일 가능성이 큼.

### (b) 위험/부작용
- 비용을 제대로 넣으면 백테스트 성능이 하락하고, 기존 champion이 무너질 수 있음.
- 과도한 비용 패널티는 과하게 “거래 안 하는” 전략으로 굳을 수 있음(노출/기회 상실).

### (c) 최소 실험(공유 실험 사용)
- **E2(비용 민감도: base/2x/4x cost 모델 스윕)** + **E3(리밸런스 로그로 turnover/cost 실측)**

### (d) PASS 조건
- (필수) 비용 2x에서도 **OOS mean이 기준치 이상 유지**(현재 champion 대비 하락폭 제한)
- (필수) 연환산 turnover, 평균 리밸런스 횟수, 거래당 비용이 **사전 정의한 상한 내**
- (필수) 성과의 대부분이 “거래 전 알파”가 아니라 “거래 후(net) 알파”로 남아있음

---

## 4) (운영 리스크+제약 준수) “8~14 Tech/Healthcare” 강제 + 포지션/노출 상한·하한 규칙화
### (a) 왜 필요한지
- `exposure max 0.8388`이며 min 0.0 → 현금 비중이 들쭉날쭉할 수 있음.  
- 종목 수/섹터 제약이 느슨하면, 최적화가 **우연히 특정 메가캡/테마로 몰빵**하거나 **종목 수가 붕괴**할 수 있음(운영/리스크 정책 위반).
- “ETF 매매 제외”를 시스템적으로 강제해야 실수 방지.

### (b) 위험/부작용
- 강제 제약으로 백테스트 상 성능이 일부 감소할 수 있음.
- 종목 수를 맞추기 위해 신호가 약한 종목을 “억지 편입”하면 알파 희석 가능.

### (c) 최소 실험(공유 실험 사용)
- **E4(종목수 8~14 + 섹터 Tech/Healthcare 하드필터 + 리스크 캡)**  
- **E2(비용 민감도)** 함께 적용해 “제약 준수로 인한 거래 증가/감소” 영향 확인

### (d) PASS 조건
- (필수) 모든 리밸런스 시점에 **보유 종목 수 8~14 유지**
- (필수) 섹터 노출: Tech+Healthcare 합계가 **정책 하한 이상**(예: ≥ 90% 등 내부 기준)이며, ETF 보유 0
- (필수) 단일 종목 최대 비중, 총 익스포저 상한 준수(예: gross/net cap)

---

## 5) (레짐/트리거 안정성) “거래 트리거→적용→노출” 파이프라인 분해 로깅 + 레짐 게이트(관측지표로만)
### (a) 왜 필요한지
- “성능이 안 움직임”은 종종 전략이 나빠서가 아니라
  - 트리거가 거의 안 뜸(히트레이트 0)
  - 떴는데 필터에서 다 죽음(적용률 0)
  - 포지션 사이징/익스포저 캡 때문에 실제 노출이 안 실림(노출 0)
  - 비용으로 상쇄(net 0)
  로 발생함.
- 레짐(변동성/금리/리스크온오프)에 따라 Tech/Healthcare의 승률/손익비가 달라질 수 있어, **관측지표로 ‘거래 강도’를 조절**하는 게 필요.

### (b) 위험/부작용
- 레짐 게이트가 과하면 “시장 좋은 구간”을 놓칠 수 있음(기회비용).
- 레짐 지표를 잘못 잡으면 또 다른 과최적화 축이 됨(규모 제한 필요).

### (c) 최소 실험(공유 실험 사용)
- **E5(레짐 관측지표 기반 게이트: VIX/금리/XLK·XLV 상대강도 ‘관측만’ 사용)**  
- **E3(트리거/적용/노출 단계별 카운터 로깅)**

### (d) PASS 조건
- (필수) 단계별 지표가 “0에 붙는 병목”을 제거:  
  - trigger_hit_rate, apply_rate, avg_exposure가 모두 **최소 기준 이상**
- (필수) 레짐별(고변동/저변동 등) 성과 분해에서 **최악 레짐의 MDD 또는 손실 기여가 완화**
- (필수) 레짐 추가 후에도 모델 복잡도 증가가 제한(파라미터 수/규칙 수 상한)

# 실험(총 5개) — 48시간 자동 루프 형태: (1) 실험 정의 (2) 게이트 (3) 기대 관측치

## E1) Fold 퇴화/누수/서바이버십 자동 감사 실험
1) **실험 정의**
- 모든 폴드에 대해: 샘플 수, 종목 수, 결측률, 라벨 분포, 피처-라벨 타임스탬프 정합성, 상장폐지/티커변경 반영 여부를 리포트.
- “미국 주식 only” 및 유니버스 스냅샷 고정(서바이버십 방지).

2) **게이트**
- degenerate fold 발생 시 해당 런은 **실격(Score=NaN 처리)**.
- 피처 타임스탬프 > 결정 시점(lookahead) 1건이라도 발견 시 **실격**.

3) **기대 관측치**
- degenerate_folds가 0으로 감소, OOS mean이 하락할 수 있으나 분산/재현성이 개선.

---

## E2) 비용 민감도(슬리피지/수수료/스프레드) 1x/2x/4x 스윕
1) **실험 정의**
- 동일 신호/리밸런스 규칙에서 cost_model만 3수준으로 스윕.
- 출력: gross return, net return, turnover, 거래횟수, 평균 거래비용, 비용으로 깎인 bps.

2) **게이트**
- 2x 비용에서 OOS mean이 **기준 하한 미달**이면 전략은 비용 취약으로 분류 → 다음 루프에서 리밸런스 완화/홀딩 강화로만 탐색.

3) **기대 관측치**
- 진짜 알파면 2x에서도 일부 유지, 가짜 알파면 급격히 0에 수렴.

---

## E3) 리밸런스 로그/이벤트 스키마 고정 + 리플레이 재현성 실험
1) **실험 정의**
- 모든 주문/체결(또는 가정체결) 이벤트를 JSONL로 기록.
- 동일 입력 스냅샷+seed로 2회 실행해 결과 hash 비교.

2) **게이트**
- pinpoint/diagnoser 파서가 에러 없이 통과.
- 재현성 실패 시(결과 hash 불일치) 해당 커밋은 **자동 롤백 후보**로 지정.

3) **기대 관측치**
- “성능 무변화”의 원인이 로깅/파이프라인이었는지 즉시 판별 가능.
- turnover 급증 구간/특정 날짜의 리밸런스 폭증을 pinpoint 가능.

---

## E4) 8~14 종목 + Tech/Healthcare 하드 제약 + 포지션 캡 실험
1) **실험 정의**
- 유니버스: US equities 중 Tech+Healthcare(섹터 분류 공급원 고정).
- 포트폴리오: 항상 8~14개, 단일 종목 최대 비중/최소 비중, 총 익스포저 범위 강제.
- ETF 티커는 매수 금지(관측용으로만 허용).

2) **게이트**
- 제약 위반(종목수/섹터/ETF 보유/비중캡) 단 1회라도 발생 시 실격.

3) **기대 관측치**
- 노출/종목수 붕괴가 사라지고, 성과가 다소 줄어도 운용 가능성이 확보.

---

## E5) 레짐 관측지표 기반 “거래 강도” 게이트(ETF 매매 없이)
1) **실험 정의**
- 관측지표(매매 금지): 예) VIX, UST 10Y, XLK/XLV 상대강도(가격 시계열은 신호 입력에만 사용).
- 규칙은 단순하게: 레짐이 불리하면 (a) 목표 익스포저 축소 또는 (b) 리밸런스 빈도 축소.

2) **게이트**
- 레짐 규칙 추가 후 파라미터/규칙 수가 상한 초과 시 실격(과최적화 방지).
- 레짐별 샘플 수가 너무 적으면(희소) 레짐 분기 사용 금지.

3) **기대 관측치**
- 고변동 구간에서 손실 기여 감소, MDD 관련 지표가 개선(또는 tail 손실 완화).

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **반드시 로그로 쪼개서** “어디에서 0이 되는지”를 찾는 구조로 고정하세요.

## A) Trigger(신호 발생) 문제
- 지표: `trigger_hit_rate`(일/주당 신호 발생 횟수), 신호 강도 분포, 종목별 신호 커버리지
- 트리거: 특정 기간 0에 수렴하면  
  - 데이터 결측/리샘플링/타임존 정렬 문제  
  - 과도한 필터/임계값  
  - 유니버스 축소(섹터 필터 과도) 가능

## B) Apply(필터/정책 적용)에서 죽는 문제
- 지표: `apply_rate = executed_candidates / triggered_candidates`
- 흔한 원인: 유동성/가격/거래가능 플래그/ETF 차단/종목수 8~14 강제 중 충돌
- 해결: 이유코드(`reason_code`)를 주문 거절/미편입에 붙여 집계

## C) Exposure(실제 노출) 문제
- 지표: 평균/분산 `net_exposure`, 현금비중, 종목수 분포, 단일 종목 상한에 걸린 빈도
- “신호는 있는데 성과가 안 움직임”이면 보통 **익스포저가 너무 낮거나**, 캡에 막혀 **엣지가 포지션에 반영되지 않음**

## D) Cost(비용) 문제
- 지표: gross vs net, `cost_drag_bps`, turnover, 평균 보유기간, 리밸런스 당 종목 교체 비율

## E) Regime(시장 국면) 문제
