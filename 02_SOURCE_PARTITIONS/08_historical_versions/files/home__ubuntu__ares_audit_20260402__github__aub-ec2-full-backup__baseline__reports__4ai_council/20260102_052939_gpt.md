## 24~48시간 우선순위 TOP5 (명령형 체크리스트)

### 1) **누수(lookahead)·정렬(as-of)·리밸런스 타이밍** 우선 감리
- [ ] feature/label 생성 단계에서 “발표/공시 시각” 기준 as-of join 강제
- [ ] 종가 기반 신호면 **T+1 체결(다음날 시가/종가)**로만 백테스트되도록 강제
- [ ] 기업행사(분할/배당) 반영 시점이 신호에 선행하지 않도록 검증

**왜 필요한지**
- 챔피언 성능(튜닝 1.90 / 락박스 1.79)이 “고정밀”인 경우, 미세한 lookahead만 있어도 락박스에서 유지되는 듯 보이는 착시가 생김(특히 Tech/HC에서 이벤트 기반 특징치가 누수 유발).

**위험/부작용**
- [ ] 정렬을 바로잡으면 단기적으로 성능이 “확” 빠질 수 있음(정상화).
- [ ] 체결 지연(T+1) 적용 시 회전율/체결 가정이 바뀌어 기존 결과와 비연속 발생.

**최소 실험(아래 공통 실험 E1, E5 사용)**
- E1, E5 적용

**PASS 조건**
- [ ] 락박스 mean 하락폭이 과도하지 않을 것(예: -0.15~-0.20 이내)
- [ ] 신호 지연(T+1)에도 성능이 “형태”를 유지(수익일 분포/턴오버 급변 없음)
- [ ] 누수 검출 로그(미래 timestamp 참조)가 0건


---

### 2) **서바이버십·유니버스 고정(8~14 종목 Tech+Healthcare)** 강제
- [ ] 유니버스를 “현재 구성”이 아니라 **해당 시점 기준 상장/거래 가능 종목**으로 고정
- [ ] 8~14 종목 제약이 룰 기반으로 강제되며, 종목 수 변동 시 원인 로그 기록
- [ ] Tech/HC 섹터 분류도 시점 고정(현시점 GICS를 과거에 투사 금지)

**왜 필요한지**
- 소수(8~14) 집중 포트는 서바이버십 편향에 특히 취약(망한 종목이 과거 유니버스에서 빠지면 성능이 과대평가).

**위험/부작용**
- [ ] 과거 구간에서 “가능 종목 수 부족”으로 신호/리밸런스가 빈번히 무효 처리될 수 있음(공백 증가).
- [ ] 섹터 분류 시점 고정 데이터가 없으면 구현 비용 상승.

**최소 실험(아래 공통 실험 E2, E4 사용)**
- E2, E4 적용

**PASS 조건**
- [ ] 락박스 mean의 구조적 붕괴(예: -0.30 이상 하락) 없이 유지
- [ ] 월별 평균 보유 종목 수가 8~14 범위를 안정적으로 만족(결측/공백률 임계 이하)
- [ ] “유니버스 변경 이벤트” 로그가 재현 가능(동일 시드/동일 데이터면 동일)


---

### 3) **비용(슬리피지/스프레드/충격)·회전율·체결 실패**를 성능지표에 1순위로 반영
- [ ] 고정 bps가 아니라 **유동성(ADV), 변동성, 스프레드 proxy** 기반 비용 모델로 하방 스트레스
- [ ] 회전율 상한/리밸런스 빈도 상한(48시간 루프에 맞춰) 게이트 추가
- [ ] 체결 불가능(거래정지/극저유동성/갭) 시 정책을 명시(다음 바 이월/주문 취소)

**왜 필요한지**
- Tech/HC 8~14 집중 + 잦은 교체는 비용에 매우 민감. 락박스가 좋을수록 “비용 미반영” 가능성을 먼저 제거해야 함.

**위험/부작용**
- [ ] 비용을 현실화하면 수익률이 하락(정상).
- [ ] 회전율 제한이 신호를 “무디게” 만들어 MDD가 늘 수도 있음.

**최소 실험(아래 공통 실험 E3, E4 사용)**
- E3, E4 적용

**PASS 조건**
- [ ] 락박스 mean이 비용 스트레스에서도 의미 있게 유지(예: base 대비 -0.20 이내)
- [ ] 연환산 turnover/거래횟수 상한을 안정적으로 준수
- [ ] MDD가 악화되지 않거나(±0.02p 이내) 대신 변동성이 유의하게 감소


---

### 4) **과최적화(튜닝 과민) 완화: 신호-포트폴리오 분리 + 단순 게이트**
- [ ] 하이퍼파라미터를 줄이고 “학습된 것”보다 “규칙 게이트”로 손실 방지
- [ ] 8~14 종목 선정 로직을 단순화(스코어 상위 N + 최소 유동성/가격/이벤트 제외 규칙)
- [ ] fold 간 성능 분산(분산/최악 fold)을 1차 목표로 두고 평균은 2차로 둠

**왜 필요한지**
- 챔피언이 튜닝 대비 락박스가 근접한 건 장점이지만, 다음 후보들이 튜닝/락박스 괴리(튜닝 min 급락 등)가 커 보임 → 파라미터 민감도가 높을 수 있음.

**위험/부작용**
- [ ] 평균 성능(특히 튜닝 mean)이 떨어질 수 있음(대신 최악 케이스 개선).
- [ ] 너무 보수적이면 알파가 사라짐.

**최소 실험(아래 공통 실험 E4, E5 사용)**
- E4, E5 적용

**PASS 조건**
- [ ] tuning_min / lockbox_min이 유의미하게 개선(“최악 케이스” 우선)
- [ ] fold 간 성능 분산 감소(표준편차/최악 fold 개선)
- [ ] 종목 교체율(일/주 단위)이 감소하면서도 수익원(히트레이트/평균 이익)이 유지


---

### 5) **운영 리스크(48시간 자동 루프): 재현성/데이터 결측/롤백** 고정
- [ ] 실행마다 결과가 바뀌는 비결정성 제거(seed, 데이터 스냅샷, 의존성 버전 고정)
- [ ] 데이터 결측/지연/부분 업데이트 시 “중단 vs degrade” 정책을 명시하고 게이트로 강제
- [ ] 자동 선택-best가 잘못된 후보를 채택하지 않도록 “락박스 최소 조건”을 하드코딩

**왜 필요한지**
- 48시간 루프는 성능보다 먼저 “망가질 확률”을 줄여야 함. 한 번의 데이터 이상치가 챔피언 교체를 유발하면 누적 손실.

**위험/부작용**
- [ ] 게이트가 너무 강하면 탐색이 느려짐.
- [ ] 스냅샷 보관으로 스토리지/시간 비용 증가.

**최소 실험(아래 공통 실험 E1, E3 사용)**
- E1, E3 적용

**PASS 조건**
- [ ] 동일 입력 스냅샷에서 결과 해시가 동일(결정성)
- [ ] 결측/지연 상황에서 “안전 실패(safe-fail)”로 종료/유지
- [ ] 자동 채택이 락박스 min 조건을 위반하지 않음


---

## 공통으로 돌릴 “유니크 실험/패치” 5개만 정의 (48시간 루프 형태: 실험 정의 → 게이트 → 기대 관측치)

### E1) **Time-travel(누수) 감사 패치**
- **실험 정의**
  - [ ] 모든 feature 테이블 join을 `asof_timestamp <= decision_timestamp`로 강제
  - [ ] 신호 산출 시점과 체결 시점을 분리(T+1 체결 모드)
  - [ ] 위반 건수/테이블명을 로그로 기록
- **게이트**
  - [ ] 누수 위반 로그 0건 아니면 즉시 FAIL
  - [ ] 체결 지연 모드에서 락박스 min < (기준 - 0.25)면 FAIL
- **기대 관측치**
  - [ ] 성능이 소폭 하락하되 형태 유지
  - [ ] “특정 이벤트 주간”에서만 과대 수익이 줄어드는 패턴이면 누수 의심 해소/확인 가능

---

### E2) **서바이버십/유니버스 시점고정 패치 (Tech+Healthcare, 8~14)**
- **실험 정의**
  - [ ] 각 날짜별 거래 가능(상장/거래정지 제외) 종목만 유니버스 포함
  - [ ] 섹터 분류/산업코드도 날짜 기준 스냅샷(없으면 최소한 “현재 섹터 투사” 플래그로 실험 분리)
  - [ ] 포트폴리오 구성은 상위 N(8~14) + 유동성 컷으로 단순화
- **게이트**
  - [ ] 평균 보유 종목 수가 8~14 범위 밖으로 벗어난 일수가 전체의 2% 초과 시 FAIL
  - [ ] 유니버스 공백률(선정 불가) 1% 초과 시 FAIL
- **기대 관측치**
  - [ ] 과거 특정 구간에서 성능이 더 현실적으로 낮아질 수 있음
  - [ ] 대신 fold 간 일관성이 개선되면 “편향 제거 효과”로 해석

---

### E3) **비용/슬리피지 스트레스 + 회전율 상한 패치**
- **실험 정의**
  - [ ] 비용을 3단(기본/스트레스1/스트레스2)으로 백테스트에 동시 적용
  - [ ] turnover cap(예: 일/주 단위) 및 주문 크기/ADV 비율 상한 적용
- **게이트**
  - [ ] 스트레스2에서 락박스 mean이 기준 대비 -0.25 초과 하락이면 FAIL
  - [ ] turnover cap 위반 발생 시 FAIL
- **기대 관측치**
  - [ ] 거래가 많은 구간에서 성능이 더 깎이면서 “진짜 알파 vs 비용 착시” 분리
  - [ ] MDD가 개선되거나(혹은 유지) 변동성이 낮아지는 쪽이 정상

---

### E4) **노출(Exposure) 제어 패치: 베타/섹터/단일종목 편중 제한**
- **실험 정의**
  - [ ] 포트폴리오 최적화/리밸런스 시 다음 제약 추가:
    - 단일 종목 최대 비중
    - 섹터(Tech/HC 내부) 편중 상한
    - 시장 베타(예: SPY) 범위
  - [ ] 8~14 종목 유지하면서 가중치만 조정
- **게이트**
  - [ ] 베타/섹터 편중 제약 위반 0건
  - [ ] 락박스 min이 기준 대비 -0.20 이내
- **기대 관측치**
  - [ ] 수익률 평균은 조금 낮아져도 최악 fold/MDD 개선이 관측되면 성공
  - [ ] 특정 메가캡 쏠림이 줄어들며 성능 분산 감소

---

### E5) **레짐(국면) 게이트: ETF는 “관측지표만” 사용**
- **실험 정의**
  - [ ] 매매는 개별주(미국 Tech+HC)만 유지
  - [ ] 관측지표로만 사용: SPY/QQQ, XLK(Tech), XLV(Health) 등의
    - 추세(예: 50/200), 변동성(예: 20일 realized), 리스크오프 프록시
  - [ ] 레짐이 나쁘면 **노출 축소(현금 비중 증가) 또는 리밸런스 중지** 규칙 적용
- **게이트**
  - [ ] 레짐 필터 ON에서 MDD가 개선되지 않으면 FAIL(예: worst_mdd가 기준보다 0.02p 이상 악화 시)
  - [ ] 거래 횟수 급감으로 공백률 증가 시 FAIL(예: 공백률 2% 초과)
- **기대 관측치**
  - [ ] 큰 하락 국면에서 드로다운 억제
  - [ ] 평균 수익률이 일부 희생되더라도 “꼬리 손실”이 줄어드는지 확인 가능


---

## 성능이 안 움직일 때: 원인 분해 아이디어 (트리거/적용/노출/비용/레짐) — 명령형 트리

### A) 트리거(신호 자체가 알파를 못 내는가?)
- [ ] 종목별 예측 스코어의 **순위 상관(IC)**, 상위/하위 스프레드(다음 기간 수익률 차)를 로그로 고정 저장
- [ ] 상위 N(8~14) 선택 전/후 성능을 분리(“스코어는 맞는데 포트에서 망가짐” 여부)

### B) 적용(신호는 맞는데 적용 시점/리밸런스가 깨지는가?)
- [ ] decision_timestamp vs execution_timestamp 수익률을 분리 측정(T+0 가정 성과가 높고 T+1에서 붕괴면 적용 문제)
- [ ] 리밸런스 캘린더(48시간 루프) 변경 전/후를 A/B로 고정

### C) 노출(원래는 팩터/베타로 먹는 건가, 진짜 종목선정인가?)
- [ ] 포트의 베타(SPY/QQQ), 섹터 비중(Tech/HC 내부), 메가캡 편중을 시계열로 저장
- [ ] 수익을 (i) 시장상승 구간 (ii) 하락 구간 (iii) 횡보 구간으로 분해해서 “언제만 먹는지” 확인

### D) 비용(수익은 비용으로 소멸되는가?)
- [ ] 매 거래별 예상비용(스프레드/충격)과 실현수익 기여를 함께 로그
- [ ] turnover와 성능의 관계(턴오버 구간별 성과)를 리포트로 자동 생성
- [ ] 스트레스 비용에서만 붕괴하면 “알파<비용” 문제로 판정

### E) 레짐(국면이 바뀌어 전략이 꺼져야 하는데 계속 켜져 있는가?)
- [ ] ETF 관측지표(추세/변동성) 상태별 성과를 2x2 테이블로 저장(예: 추세↑/↓ × 변동성↑/↓)
- [ ] 레짐별로 “노출 축소/중지” 규칙이 실제로 발동했는지(발동률/평균 지속시간) 로그로 검증

## 48시간 루프에 바로 끼워 넣는 실행 순서(권장)
- [ ] **E1 → E3 → E2 → E4 → E5** 순으로 돌려서, 먼저 “착시 제거(누수/비용/편향)” 후 “안정화(노출/레짐)”로 이동
