## 1. 우선순위 TOP 5 패치

### PATCH-1: 파이프라인 복구 (Blocker)

**(a) 왜 필요**
- rebalance.csv/jsonl 로드 실패 → delta 분석 불가
- 실험 비교 없이 진행하면 blind optimization

**(b) 위험/부작용**
- 낮음 (인프라 수정만)
- 잘못 수정 시 기존 로그 덮어쓰기 주의

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P1-A | `rebalance_logger.py`에 JSON Lines 출력 추가 | 파일 생성 확인 | `wc -l rebalance.jsonl > 0` |
| P1-B | diagnoser 경로 인자 하드코딩 제거, `--cand` 자동탐색 | exit code 0 | diagnosis.md 정상 생성 |

**(d) PASS 조건**
```
✅ aub_rebalance_pinpoint.py 실행 시 "No rebalance data" 미출력
✅ pinpoint.md에 종목별 delta 테이블 존재
```

---

### PATCH-2: Degenerate Fold 근인 분석

**(a) 왜 필요**
- 4/10 폴드가 퇴화 = 신호가 특정 기간에만 작동
- Survivorship bias 또는 레짐 과적합 가능성

**(b) 위험/부작용**
- 분석 전용 (프로덕션 영향 없음)
- 폴드별 종목 구성이 다르면 해석 복잡

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P2-A | 폴드 1,2,3,8의 기간/종목/VIX 분포 추출 | 리포트 생성 | 공통 패턴 식별 (예: 모두 2022 포함) |
| P2-B | 정상 폴드(4,5,6,7,9,10)만으로 OOS 재계산 | OOS mean 산출 | 3.32 → 1.5~2.5 예상 시 과최적화 확정 |
| P2-C | 퇴화 폴드에서 exposure=0인 날짜 비율 체크 | 비율 산출 | >50%면 시그널 자체 문제 |

**(d) PASS 조건**
```
✅ 퇴화 원인 1개 이상 식별 (레짐/종목/신호)
✅ 정상 폴드 OOS mean < 2.0 확인 시 → Champion 교체 트리거
```

### PATCH-3: MDD 측정 복구 + 하드캡

**(a) 왜 필요**
- `worst_mdd: None` = 리스크 blind
- OOS 좋아도 MDD -40%면 운용 불가

**(b) 위험/부작용**
- MDD 캡 너무 타이트 → 신호 대부분 필터링
- 계산 로직 버그 시 false positive

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P3-A | `backtest_engine.py`에 rolling MDD 계산 추가 | 값 출력 | MDD ∈ [-0.5, 0] |
| P3-B | Gate 추가: `worst_mdd > -0.25` 미충족 시 실험 FAIL | 필터 작동 | 일부 실험 자동 제외 |

**(d) PASS 조건**
```
✅ handoff.json에 worst_mdd 필드 != None
✅ MDD > -25% 위반 실험 자동 REJECT 로그 확인
```

### PATCH-4: OOS 급등 과최적화 검증

**(a) 왜 필요**
- 2.63 → 3.32 (26% 급등)은 red flag
- 실제 알파 vs 노이즈 피팅 구분 필요

**(b) 위험/부작용**
- 검증 통과해도 미래 레짐에서 실패 가능
- 과도한 보수주의 → 유효 신호 폐기

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P4-A | 2024.01~2024.06 구간만 holdout으로 분리, 재테스트 | Sharpe 산출 | Sharpe > 1.0 유지 |
| P4-B | 종목 절반 랜덤 제거 후 OOS 재계산 (robustness) | OOS mean 비교 | 하락폭 < 30% |
| P4-C | 거래비용 2x (20bp→40bp) 적용 | OOS mean 비교 | 양수 유지 |

**(d) PASS 조건**
```
✅ 3개 중 2개 이상 통과 시 Champion 유지
✅ 2개 이상 실패 시 이전 버전(2.63)으로 롤백
```

### PATCH-5: Exposure 상한 정규화

**(a) 왜 필요**

**(b) 위험/부작용**
- 캡 너무 낮추면 수익률 희석
- 섹터 집중도도 함께 봐야 함

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P5-A | 종목별 exposure cap 0.15 (현재 추정 0.25+) | OOS 비교 | 하락 < 15% |

```
✅ exposure_max < 0.65 달성
✅ OOS mean > 2.5 유지
```

├─ [비용] 수익 = 비용으로 상쇄
│   └─ 체크: gross_return vs net_return 갭
│   └─ 조치: 회전율 (turnover) 제한
│

    └─ 체크: VIX/금리 구간별 성과 분해
    └─ 조치: 레짐 필터 추가 or 인정(no action)
