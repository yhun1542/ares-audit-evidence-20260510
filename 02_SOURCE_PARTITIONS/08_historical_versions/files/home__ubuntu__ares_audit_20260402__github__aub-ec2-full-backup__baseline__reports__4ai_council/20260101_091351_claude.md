## 1. 우선순위 TOP 5 제안

### P1. Tuning Fold 전손 원인 분해
| 항목 | 내용 |
|------|------|
| **왜 필요** | tuning_min 0.05 = 특정 fold에서 -95% 손실. 이 레짐이 lockbox 기간에 재현되면 실전 파산 |
| **위험/부작용** | 해당 fold 제거 유혹 → 과최적화 악화 |
| **실험** | |
| (a) | fold별 CAGR/MDD 히트맵 생성 → 전손 fold 식별 |
| (b) | 해당 fold 기간 VIX/금리 레짐 태깅 → 레짐 필터 후보 도출 |
| (c) | 해당 fold만 별도 백테스트, position sizing 0.5x 적용 시 MDD 변화 |
| **PASS 게이트** | 전손 fold 원인 문서화 + 해당 레짐 탐지 로직 명세 완료 |

### P2. MDD 방어 레이어 (Drawdown Circuit Breaker)

|------|------|

| **실험** | |
| (a) | trailing stop -7% 적용 → MDD/CAGR 변화 측정 |

| **PASS 게이트** | worst_mdd ≤ -0.10 AND tuning_mean ≥ 1.70 유지 |

## 2. 48h 자동 루프 명세

```yaml
# experiment_queue_20260101.yaml

experiments:
  - id: exp_fold_autopsy
    script: tools/fold_analysis.py --champion baseline/champion_v5_20251231.json
    gate: worst_fold_cagr >= 0.5  # 최소 50% 생존
    observe: [fold_id, period, vix_mean, cagr, mdd]

  - id: exp_mdd_breaker_7pct

    gate: worst_mdd >= -0.10 AND tuning_mean >= 1.70
    observe: [tuning_mean, lockbox_mean, worst_mdd, turnover]

  - id: exp_cost_sensitivity
    script: backtest.py --cost-sweep 5,10,15,20
    gate: breakeven_bps >= 12

  - id: exp_vix_filter

    gate: vix30_mdd_improvement >= 0.20
    observe: [regime, mdd_in_regime, cagr_drag]

  - id: exp_n_stocks

    gate: sharpe_lockbox >= 1.0
    observe: [n_stocks, sharpe, mdd, concentration_hhi]
```

## 3. 성능 안 움직일 때 원인 분해 트리

```
성능 정체
├─ 트리거 미발동
│   └─ 시그널 빈도 측정 → 연간 트리거 횟수 < 10이면 신호 자체 문제
├─ 적용 안 됨
│   └─ 리밸런스 실행 로그 확인 → 주문 생성 vs 실제 체결 괴리
├─ 노출 부족
│   └─ 평균 포지션 크기 / 현금 비중 → 현금 > 30%면 under-invested
├─ 비용 흡수
│   └─ 회전율 × 비용 vs gross alpha → drag > alpha면 전략 무효
└─ 레짐 미스매치
    └─ 최근 N개월 레짐 vs 튜닝 기간 레짐 분포 → OOD(out-of-distribution) 탐지
```
