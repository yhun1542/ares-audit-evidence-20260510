## 0) 즉시 우선 점검(누수/과최적화/서바이버십/비용/운영 리스크) — 명령형 체크리스트
- **(누수)** `t` 시점 feature가 **반드시 `t-1`(또는 더 이전) 데이터만** 사용하도록 강제(특히 종가/체결가/지표 리샘플링/리밸런스 캘린더).
- **(누수)** 학습/튜닝에서 **Purged+Embargo CV** 적용(리밸런스 주기만큼 purge, 최소 1~5 bar embargo).
- **(서바이버십)** 유니버스(Tech+Healthcare 8~14종목)가 **과거 시점에 실제 존재/거래 가능**했는지(상장폐지/티커변경/합병) PIT로 검증.
- **(비용 미반영)** 슬리피지/스프레드/수수료 + 체결 지연 + 부분체결을 **백테스트에 강제 반영**(특히 회전율 높을수록).
- **(운영 리스크)** 48시간 루프에서 **결정론(deterministic) 재현**(seed, 데이터 스냅샷, 버전) + 실패 시 롤백(Champion 유지) 자동화.

## 1) 다음 24~48시간 우선순위 TOP5(코드/아키텍처/전략)
아래 TOP5 중 **실행 실험은 5개로 제한**(규칙 준수). 각 제안은 “왜/위험/PASS 조건”을 주고, **실험은 공용 5개로 매핑**합니다.

### P1) 누수 차단(시간 정렬/리밸런스 캘린더/리턴 라벨링)
**(a) 왜 필요한지**
- 현재 Candidate가 lockbox에서 강함(특히 lockbox_min이 +) → “진짜 개선”일 수도 있지만, **미세 누수**도 가장 흔한 원인.
- Tech/Healthcare는 이벤트(실적/승인/가이던스) 갭이 커서 **종가-익일 시가 정렬 오류**가 성능을 과대평가하기 쉽습니다.

**(b) 위험/부작용**
- 누수 차단 후 성능 급락 가능(그게 정상일 수 있음).
- 거래지연/리밸런스 시점 변경으로 turnover/노출이 바뀜.

**(c) 최소 실험(공용 실험 사용)**
- **E1**(아래) Purged+Embargo + “주문→다음 바 체결” 강제
- **E2**(아래) Corporate action/PIT 스냅샷 검증(가격/분할/배당/티커)

**(d) PASS 조건**
- lockbox_mean이 Champion 대비 **+0.10 이상 유지**하면서,
- lockbox_min이 **0 이상 유지**(현재 Candidate가 이미 만족) 또는 Champion 대비 개선,
- worst_mdd가 **-0.10 이내** 유지(현재 Worst -0.048 수준이면 여유).

---

### P2) 비용/슬리피지/회전율 모델 강화(“실전 PnL”로 수렴)
**(a) 왜 필요한지**
- Tech/Healthcare 8~14종목은 종목 집중이라 **비용/슬리피지 한 방에 알파가 소거**됩니다.
- 백테스트가 “평균”만 좋아도 **min/테일**이 무너지면 운영 불가.

**(b) 위험/부작용**
- 비용 모델 강화는 성능을 떨어뜨릴 가능성이 큼(그러나 실전 적합성 상승).
- 너무 보수적으로 잡으면 신호가 죽어 탐색이 멈춤.

**(c) 최소 실험**
- **E3**(아래) 비용 모델(스프레드+충격비용) + turnover cap 실험

**(d) PASS 조건**
- 비용 포함 후 lockbox_mean이 Champion 대비 **동등 이상(≥)** 이거나,
- lockbox_mean이 소폭 하락해도 **worst_mdd 또는 lockbox_min 개선**이 명확할 것(테일 리스크 감소).

---

### P3) 서바이버십/데이터 무결성(PIT 유니버스, delist 처리)
**(a) 왜 필요한지**
- “미국주식 only + Tech/Healthcare 8~14”는 보통 **사후적으로 고른 생존자**가 섞이기 쉬움.
- delist 리턴 누락/티커 변경 미반영은 백테스트를 구조적으로 부풀립니다.

**(b) 위험/부작용**
- 과거 데이터가 빠지면 학습 샘플이 줄어 분산 증가.
- 유니버스가 바뀌면 전략 특성이 변함.

**(c) 최소 실험**
- **E2**(아래) PIT/Corporate action/티커체인지/상폐 처리 검증 + 결측 처리 규칙 고정

**(d) PASS 조건**
- PIT 정합성 통과 후에도 Candidate의 lockbox 성능이 **유의미하게 유지**(mean 급락/테일 붕괴 없을 것).
- “유니버스 변동/결측”으로 인한 신호 공백률(아래 관측치) **임계 이하**.

---

### P4) 레짐/리스크 스케일링(ETF는 관측지표로만)
**(a) 왜 필요한지**
- Tech/Healthcare는 레짐 민감(금리/리스크온오프).  
- ETF(QQQ/XLV/SPY/IWM 등)는 매매하지 않되 **위험 스케일링/게이트**에 쓰면 테일을 줄이는 데 효과적.

**(b) 위험/부작용**
- 레짐 필터는 오버필터링으로 기회 손실 가능.
- “뒤늦게 꺼지는” 게이트는 오히려 손실 확정.

**(c) 최소 실험**
- **E4**(아래) ETF 관측 기반 리스크 스케일/게이트(거래는 개별주만)

**(d) PASS 조건**
- worst_mdd **추가 개선**(예: -0.05 → -0.04 이하) 또는 lockbox_min 개선.
- 평균 성능이 소폭 감소해도 **테일 개선이 명확**하면 PASS.

---

### P5) 운영 안정성(48시간 자동 루프에서 “깨지지 않게”)
**(a) 왜 필요한지**
- 지금은 성능도 중요하지만, 48시간 무인 루프에서 **재현성/롤백/드리프트 감지**가 없으면 운영 리스크가 손익을 압도.

**(b) 위험/부작용**
- 로깅/검증 추가로 실행 시간이 늘 수 있음.
- 게이트를 과하게 두면 실험이 “항상 FAIL”로 정체.

**(c) 최소 실험**
- **E5**(아래) Shadow live-sim(운영 리스크/결정론) + 자동 롤백 게이트

**(d) PASS 조건**
- 동일 입력에서 결과 해시(포지션/트레이드 로그)가 **완전 일치**(결정론).
- 데이터 결측/지연 시에도 **Champion 유지 + 안전 종료**.

## 2) 48시간 자동 루프용 “실행 가능한 patch/실험” 5개(정의/게이트/기대 관측치)
아래 5개만 돌리면 위 TOP5가 커버됩니다(케이스 폭발 방지).

### E1) Purged+Embargo CV + 체결 지연(누수 차단 패치)
- **(1) 실험 정의**
  - 모든 학습/튜닝 평가를 **Purged K-fold time series CV**로 교체.
  - 리밸런스 시점 `t`에 생성한 신호는 **`t+1` 바(익일 시가 or 다음 캔들)**에 체결되도록 강제.
  - Purge 길이 = 리밸런스 주기, Embargo = 1~5 bar(데이터 주기에 맞춤).
- **(2) 게이트**
  - lockbox_min < 0이면 즉시 FAIL(테일 악화 방지) **또는** Champion 대비 lockbox_min 개선 요구.
  - fold 간 성능 분산이 급증하면 FAIL(과최적화 징후).
- **(3) 기대 관측치**
  - 평균은 다소 하락 가능, 대신 **min/테일이 더 “현실적”**으로 재배치.
  - “성능 유지”면 누수 가능성 낮아지고 Candidate 승격 근거 강화.

---

### E2) Corporate action/PIT 무결성 + 서바이버십 스캔(데이터 패치)
- **(1) 실험 정의**
  - 가격: split/dividend 조정의 일관성(Adj vs Raw) 선택을 하나로 고정하고 전 구간 재생성.
  - 티커 변경/상폐(가능하면 CRSP/상폐리턴) 처리 규칙 적용, 결측 발생 시 신호 생성 금지(강제 NaN 전파).
  - 유니버스 8~14종목의 “각 날짜 거래 가능 여부” 플래그 생성.
- **(2) 게이트**
  - 거래 가능 플래그가 false인데 포지션이 잡히면 FAIL.
  - 결측으로 인해 **신호 공백률 > X%**(프로젝트 내부 임계치)면 FAIL.
- **(3) 기대 관측치**
  - 과거 특정 구간에서 “비정상 수익”이 사라지면 원인이 데이터였음을 확증.
  - 살아남으면 전략 신뢰도 상승.

---

### E3) 비용 모델 강화 + 회전율 캡(실전 비용 반영)
- **(1) 실험 정의**
  - 비용 = 고정 수수료 + (스프레드/2) + 충격비용(`k * |Δposition| * volatility`류 단순 모델).
  - **turnover cap**(일/주 기준)을 두고, 초과 시 주문을 스케일 다운(부분 집행).
- **(2) 게이트**
  - 비용 포함 후 lockbox_mean이 Champion 대비 **크게 붕괴(예: -0.15 이상)**면 FAIL.
  - turnover가 캡에 의해 상시 눌리면 FAIL(신호 설계가 비용 비현실적).
- **(3) 기대 관측치**
  - 평균은 내려가도 **분산/테일이 개선**되면 운영 적합성 상승.
  - “비용에 취약한 알파”를 조기에 제거.

---

### E4) ETF 관측지표 기반 레짐 게이트/리스크 스케일(매매는 개별주만)
- **(1) 실험 정의**
  - ETF(예: QQQ=Tech, XLV=Healthcare, SPY=시장)에서
    - 모멘텀/변동성/드로우다운 지표를 계산해 **포지션 총 노출(레버리지/현금비중)**만 스케일.
  - 예: QQQ 추세 하락+변동성 급등이면 총 익스포저 0.5x, 평시 1.0x.
- **(2) 게이트**
  - 게이트로 인해 연속적으로 “거의 무포지션” 상태가 장기간이면 FAIL.
  - worst_mdd 개선이 없고 mean만 감소하면 FAIL.
- **(3) 기대 관측치**
  - **worst_mdd/lockbox_min 개선**이 가장 먼저 관측될 것.
  - 평균은 약간 희생될 수 있으나 운영 안정성 상승.

---

### E5) Shadow live-sim(운영/결정론/롤백) + 자동 승격 규칙
- **(1) 실험 정의**
  - 백테스트 외에 “실시간과 동일한 파이프라인”으로 **shadow run** 수행:
    - 데이터 스냅샷 버전 고정
    - 시드/환경 해시 기록
    - 생성 포지션/주문/체결 로그 해시 저장
  - Candidate 승격은 “다중 게이트 통과” 시에만 자동 적용, 아니면 Champion 유지.
- **(2) 게이트**
  - 동일 입력 재실행 시 로그 해시 불일치면 FAIL(비결정론).
  - 데이터 지연/결측 발생 시 안전 종료 + Champion 유지가 안 되면 FAIL.
- **(3) 기대 관측치**
  - 성능 이전에 **운영 리스크(재현성/데이터 문제/중단)**가 수치로 드러남.
  - 48시간 무인 루프의 실패율이 급감.

## 3) 성능이 안 움직일 때: 원인 분해 아이디어(트리거/적용/노출/비용/레짐) — 명령형 트러블슈팅 트리
아래를 “로그 지표”로 쪼개서, **어디서 PnL이 죽는지**를 1~2회 루프로 특정하세요.

### A) Trigger(신호가 실제로 발생하나?)
- 신호 발생률(일/주당) 로그 → **0에 수렴**하면 feature 결측/게이트 과도/스케줄 오류.
- 상위 스코어 종목의 점수 분포 → **항상 비슷**하면 모델이 무감각(스케일링/정규화 문제).

### B) Apply(신호가 주문으로 변환되나?)
- 목표 포지션 vs 실제 포지션 괴리(|target-actual|) → 항상 크면 제약/라운딩/현금부족.
- 리밸런스 캘린더가 실제 거래일과 맞는지(미국 휴장/half-day) 점검.

### C) Exposure(노출이 의도대로인가?)
- 종목별 비중 상한, 섹터(Tech/Healthcare) 비중, 시장베타(대략 SPY 회귀) 로그.
- 8~14종목 유지 규칙 때문에 **강제 분산**이 알파를 희석하는지 체크(동일가중 강제 여부).

### D) Cost(비용이 알파를 먹나?)
- 총 비용 / 총 거래대금 / turnover / 평균 보유기간 로그.
- “비용 제외 수익”과 “비용 포함 수익”의 차이를 구간별로 분해 → 특정 변동성 구간에서만 깨지면 충격비용 모델/레짐 문제.

### E) Regime(구간 의존으로 접히나?)
- 성과를 QQQ/XLV 추세, SPY 변동성(ATR류), 금리 급등 구간(대체 지표)으로 버킷팅.
- 어떤 버킷에서만 성능이 나오면:  
  - **게이트/스케일링(E4)**로 테일을 줄이거나  
  - 아예 해당 레짐에서 “no-trade”를 허용하는 대신 평균 하락을 감수.

## 4) 실행 순서(24~48h) — 명령형 체크리스트
1. **E1 → E2를 먼저**(누수/데이터 무결성 없으면 나머지 최적화가 전부 무의미).
2. 그 다음 **E3(비용/turnover cap)**로 실전성 확인.
3. 테일이 남으면 **E4(레짐 스케일링)**로 mdd/min을 먼저 정리.
4. 전 과정은 **E5(shadow+결정론+롤백)**를 항상 켠 상태로 고정.

(현재 상태 기준으로는 Candidate가 lockbox 성능이 강하므로, 위 게이트를 통과하면 “승격 근거”는 충분하지만, **E1/E2 통과 전 승격은 보류**가 운영적으로 안전합니다.)
