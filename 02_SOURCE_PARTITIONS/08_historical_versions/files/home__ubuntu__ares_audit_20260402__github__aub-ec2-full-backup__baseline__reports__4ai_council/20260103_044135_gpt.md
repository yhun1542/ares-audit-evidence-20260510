(누수/과최적화/서바이버십/비용 미반영/운영 리스크를 최우선으로 점검, **미국주식 only / Tech+Healthcare 8~14종목 / ETF는 지표로만**)

## 0) 48시간 자동 루프 공통 규격(모든 실험에 동일 적용)
- **(1) 실험 정의**: 패치 → 백테스트/워크포워드 → 리포트 생성(단일 JSON + rebalance JSONL 포함)
- **(2) 게이트**: (a) 누수 테스트 통과 (b) degenerate_folds=0 (c) 비용 포함 성과 리포트 존재 (d) worst_mdd 숫자 생성
- **(3) 기대 관측치**: “지표가 움직여야 하는 포인트”를 명시(노출/턴오버/비용/레짐별)

이하 TOP5는 **총 5개의 고유 실험(E1~E5)**만 돌리도록 구성했고, 각 TOP 항목은 그중 **2~3개 실험을 재사용**해서 충족시킴(케이스 폭발 방지).

# TOP1) 누수(Leakage) + 시간정렬(As-Of) 우선 봉합
### (a) 왜 필요한지
- OOS가 “안 움직임(no-delta)”일 때 가장 흔한 원인이 **미세 누수(특히 close/return 정렬 1칸 오류, split/dividend 반영 시점 오류, 지표 계산에 t+0 가격 포함)**.
- 현재 `degenerate_folds` 존재는 **학습/검증 구간에서 신호가 무의미해지거나(전부 0), 트레이드가 막히거나, 데이터 정렬이 깨졌을 가능성**을 함께 시사.

### (b) 위험/부작용
- 누수 제거 후 성능 급락 가능(“가짜 알파” 제거).
- lag 적용으로 반응이 둔해져 단기 성과 감소 가능.

### (c) 최소 실험(2~3개) — 아래 고유 실험 ID 사용
- **E1: As-Of/lag 강제 + 누수 유닛테스트 추가**
- **E4: 워크포워드/폴드 게이트 강화(=degenerate 제거) + 지표 산출 정상화**

### (d) PASS 조건
- (필수) **누수 테스트 0건**, lookahead 의심 join 0건(“t 시점 feature에 t+1 가격/리턴 포함” 검출 0)
- (필수) `degenerate_folds == 0`
- (성능) 비용 포함 OOS_mean이 **baseline 대비 비슷하거나(+0.00 이상)**, OOS_min이 **악화되지 않음(동일 또는 개선)**

# TOP2) 서바이버십(종목 생존편향) + 유니버스 고정(8~14) 확정
### (a) 왜 필요한지
- Tech/Healthcare를 “현재 기준으로” 뽑아 과거로 백테스트하면 **서바이버십 편향**이 들어가 OOS가 왜곡됨.
- 또한 유니버스가 변동하면 **실험 간 차이가 신호가 아니라 유니버스 변화**로 흡수되어 “성능이 안 움직이는 것처럼” 보일 수 있음.

### (b) 위험/부작용
- 유니버스 고정 시 분산효과 감소(특정 기간 취약).
- 너무 소수 종목 고정은 idiosyncratic 리스크 증가.

### (c) 최소 실험(2~3개)
- **E2: 유니버스 “고정 12종목(Tech+Healthcare)”로 잠금 + 재현성 해시 기록**
- **E4: 폴드별 최소 트레이드/최소 변동성 게이트로 ‘유령 폴드’ 제거**

> 권장 고정 유니버스(예시, 12종목 / US / Tech+Healthcare):  
> Tech: AAPL, MSFT, NVDA, AMZN, GOOGL, META  
> Healthcare: UNH, JNJ, LLY, ABBV, MRK, PFE  
> (8~14 범위 내에서만 운용, ETF 매매 금지)

### (d) PASS 조건
- (필수) 매 런마다 **동일 유니버스 해시**가 리포트에 남음(재현성)
- (필수) `degenerate_folds == 0`
- (성능) OOS_mean이 baseline 대비 **-0.10 이상 악화하지 않을 것**, 대신 OOS_min(꼬리)이 **개선 또는 유지**되면 통과(서바이버십 제거의 정상적 trade-off 허용)

# TOP3) 비용(수수료/슬리피지/스프레드/차입) 미반영 즉시 반영 + 턴오버 제어
### (a) 왜 필요한지
- “성능이 안 움직임”은 실제로는 **비용이 성과를 상쇄**하거나, 반대로 **비용을 안 넣어서 과최적화가 발생**해 OOS가 무의미해지는 경우가 많음.
- 현재 rebalance 로그가 깨져 비용/턴오버 진단이 불가한 상태(운영 리스크).

### (b) 위험/부작용
- 비용 반영 즉시 성과 하락 가능.
- 턴오버 억제는 기회 손실을 만들 수 있음.

### (c) 최소 실험(2~3개)
- **E3: 비용모델(고정 bps + 스프레드 + 임팩트 단순모형) + 턴오버 패널티 도입**
- **E4: 리밸런스 로그 포맷 통일(JSONL) + 비용 리포트 강제 생성**

### (d) PASS 조건
- (필수) after-cost 리포트가 항상 생성되고, **turnover/거래횟수/평균슬리피지**가 출력됨
- (성능) after-cost OOS_mean이 baseline 대비 **+0.05 이상**이거나, 최소한 OOS_min이 **유의미하게 개선**(tail 개선)되면 통과
- (리스크) 평균 턴오버가 **baseline 대비 감소**(또는 상한선 이하)해야 통과

---

# TOP4) 과최적화/폴드 퇴화(degenerate_folds) 제거: 평가 파이프라인을 “고장나지 않게” 만들기
### (a) 왜 필요한지
- 현재 `degenerate_folds: [1,2,3,8]`은 **평가 자체가 신뢰 불가** 신호.
- `worst_mdd: None`은 **MDD 계산/로깅 파이프라인이 깨졌거나 트레이드 시계열이 비어있는 경우**가 많음.
- 진단 도구가 `rebalance.csv/jsonl`을 못 읽고 있어 운영 관측성이 붕괴 상태.

### (b) 위험/부작용
- 게이트 강화로 “통과하는 실험 수”가 줄어 탐색 속도 저하.
- 단기적으로는 성능 개선보다 “정상화”가 목표가 됨.

### (c) 최소 실험(2~3개)
- **E4: 폴드 게이트(최소 거래수/최소 노출/최소 변동) + MDD 산출 강제 + rebalance 로그 강제**
- **E1: 누수/정렬 테스트와 함께, 폴드별 feature 분포가 0으로 붕괴하는지 체크 추가**

### (d) PASS 조건
- (필수) `degenerate_folds == 0`
- (필수) `worst_mdd`가 **항상 숫자**로 채워짐(None 금지)
- (필수) rebalance 로그가 도구에서 파싱 가능(빈 파일/JSON 파손 0건)

---

# TOP5) 레짐/리스크(운영 포함): ETF는 “지표”로만 써서 노출 스케일러 도입
### (a) 왜 필요한지
- Tech/Healthcare 8~14 종목은 **레짐 의존**이 커서, 레짐별로 노출을 조절하지 않으면 OOS_min(꼬리)이 깨짐.
- ETF는 매매하지 않고도 **시장 상태(추세/변동성/리스크온오프)** 관측 지표로 강력함.

### (b) 위험/부작용
- 노출 스케일러가 과도하면 알파를 “죽이는” 결과(항상 현금화) 가능.
- 지표가 지나치게 단순하면 거짓 신호로 성과 저하 가능.

### (c) 최소 실험(2~3개)
- **E5: ETF 관측지표 기반 노출 스케일러(매매 금지)**
- **E3: 턴오버 패널티와 결합(리스크오프 구간 과매매 방지)**

> ETF 관측지표 예시(매매 금지, 신호만): QQQ(Tech 베타), XLV(헬스케어), VIX 대체로는 VIX 지수 직접 또는 VXX 같은 ETF 가격을 “지표로만” 사용

### (d) PASS 조건
- (리스크) worst_mdd 또는 OOS_min이 **개선(꼬리 완화)**  
- (성능) OOS_mean이 baseline 대비 **-0.10 이상 악화하지 않을 것**(tail 개선이면 약간의 mean 희생 허용)
- (운영) 노출이 0으로 고정되는 구간이 과도하지 않음(“항상 현금” 방지 게이트)

# 고유 실험 정의(E1~E5): 48시간 자동 루프 형태로 바로 실행 가능하게

## E1) Leakage/As-Of 강제 패치
1) **실험 정의**
- feature 생성 시점에 **항상 t-1까지의 가격/리턴만 사용**(예: 신호는 t-1 close 기준, 포지션은 t open/close에 적용 중 하나로 고정)
- corporate actions(분할/배당) 반영 시점 명시(Adjusted vs Unadjusted 혼용 금지)
- “미래 데이터 사용 탐지” 유닛테스트 추가(랜덤 날짜 샘플로 feature가 미래 캔들 참조하면 실패)

2) **게이트**
- 누수 테스트 0건
- 폴드별 feature 분포가 상수(분산=0)로 붕괴한 구간이 임계치 이내

3) **기대 관측치**
- degenerate_folds 감소
- “실험 간 성능이 동일(no-delta)” 현상이 완화(신호 변경이 성과로 반영되기 시작)

---

## E2) Survivorship 방지: 고정 유니버스(8~14) 잠금
1) **실험 정의**
- 위 12종목 같은 **고정 리스트**로 유니버스 생성(과거 상장폐지 종목까지 커버가 필요하면 별도 데이터 없이는 완전 해결 불가하므로, 우선 “유니버스 변동”을 제거해 실험 재현성을 확보)
- 매 런에 universe_hash 저장

2) **게이트**
- universe_hash 변동 0
- 섹터 비중이 Tech/Healthcare 내에서만 유지(다른 섹터 종목 0)

3) **기대 관측치**
- 실험 간 분산 감소(“유니버스가 달라서 생긴 가짜 차이” 제거)
- OOS_min 안정화 가능

---

## E3) 비용모델 + 턴오버 패널티(현실화)
1) **실험 정의**
- 비용: commission + spread(고정 bps) + impact(턴오버 비례 단순) + (short 시) borrow bps
- 목적함수 또는 스코어에 turnover penalty 추가(리밸런스 빈도/규모 억제)

2) **게이트**
- after-cost 성과 리포트 필수 생성
- turnover 상한선 초과 시 실패

3) **기대 관측치**
- “전에는 좋았는데 실제 운용은 나쁨” 갭 축소
- 과매매 전략 성과 하락, 대신 tail/안정성 개선

---

## E4) 평가/운영 파이프라인 정상화(폴드 퇴화 제거 + 로그/리포트 통일)
1) **실험 정의**
- 폴드 게이트: 각 폴드별 최소 거래 수/최소 평균 노출/최소 수익률 분산 조건 미달 시 “실험 실패”로 처리
- `worst_mdd` 계산을 강제(시계열 비면 실패)
- rebalance 로그를 **JSONL로 고정 출력**하고, 진단 도구 입력 포맷도 그에 맞춰 단일화(현재 `--base-log` 파일 부재/CSV 파손을 근절)

2) **게이트**
- degenerate_folds=0
- worst_mdd != None
- 로그 파서가 에러 없이 끝까지 읽음

3) **기대 관측치**
- “성능이 안 움직이는 이유”를 수치로 분해 가능(턴오버/비용/노출/리밸런스 빈도)
- 장애(파일 없음/JSON 파손)로 진단 불능 상태 제거

---

## E5) 레짐 기반 노출 스케일러(ETF는 관측만)
1) **실험 정의**
- 지표: QQQ/XLV의 추세(예: 20/60MA), 변동성(예: 20일 realized vol), 리스크오프 신호(예: 급락/변동성 급등)
- 결과: 포트폴리오 gross/net exposure를 0~1 범위에서 스케일(매매 종목은 US Tech+Healthcare만)

2) **게이트**
- 스케일러로 인해 “항상 0 노출” 상태가 일정 비율 이상이면 실패
- drawdown/꼬리 지표가 개선되지 않으면 실패

3) **기대 관측치**
- OOS_min 개선(왼쪽 꼬리 완화)
- max exposure가 레짐에 따라 내려가며 tail 안정화

---

# 성능이 안 움직일 때: 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래 순서대로 “관측 → 결론”이 나도록 강제 점검하라(질문 금지, 체크리스트로 실행).

## 1) Trigger(신호가 실제로 변하나?)
- [ ] 동일 기간에서 **feature/score 시계열**을 실험 A/B로 덤프하고 상관/동일값 비율 계산  
- [ ] (관측) A/B score가 거의 동일 → **상류(데이터/피처)에서 no-delta**
- [ ] (관측) score는 다른데 성과 동일 → **하류(매핑/게이트/제약)에서 막힘**

## 2) Apply(신호가 포지션으로 변환되나?)
- [ ] score→target_weight 매핑 로직에서 **클리핑/라운딩/최소주문수량** 때문에 0이 되는지 확인  
- [ ] (관측) target이 계속 0 또는 동일 → **제약/임계치가 신호를 죽임**

## 3) Exposure(노출이 폴드에서 살아있나?)
- [ ] 폴드별 평균 gross/net, 최대 포지션, 현금비중 덤프  
- [ ] (관측) 특정 폴드에서 노출≈0 → **degenerate_folds 원인(게이트/데이터 누락/거래불가)**

## 4) Cost(비용이 알파를 상쇄하나?)
- [ ] before/after cost PnL을 분리, turnover 대비 비용 기여도를 분해  
- [ ] (관측) after-cost에서만 붕괴 → **턴오버/슬리피지 과다** (E3로 해결)

## 5) Regime(특정 레짐에서만 죽나?)
- [ ] QQQ/XLV 추세, realized vol 구간을 태깅해서 OOS를 레짐별로 분해  
- [ ] (관측) 고변동/하락 레짐에서만 tail 붕괴 → **노출 스케일러(E5) 필요**

## 6) 운영 리스크(진단 불능 상태 자체가 문제)
- [ ] rebalance 로그/리포트 포맷 단일화(JSONL) 및 “없으면 실패” 규칙 적용  
- [ ] (관측) 파일 없음/파손이 사라져야 원인 추적이 가능(E4가 최우선)

---

## 실행 순서(24~48h)
