## 0) 즉시(오늘) 운영 리스크 차단 체크리스트 (실험 전 필수)
1) **artifact 메타데이터 강제 기록**
- `lane_hash`, `run_hash`, git SHA, 데이터 스냅샷 ID(최소: 가격데이터 파일 해시) 를 **실험 산출물 JSON에 필수 필드로 강제**하라.
- `worst_mdd: None` 이면 **리포트 단계에서 실패로 처리**하라(결측이면 “좋음”으로 오판 가능).

2) **리밸런스 로그 포맷을 단일화**
- `aub_rebalance_pinpoint`가 `csv/jsonl`을 찾는데 현재 파일/포맷이 깨져 있음 → **리밸런스 이벤트를 JSONL로 표준화**하고 경로를 “실험 산출물 내 상대경로”로 고정하라.
- “없으면 스킵”이 아니라 **없으면 FAIL**로 바꿔라(운영에서 원인분해 불가능).

3) **degenerate fold 방지 가드레일**
- `degenerate_folds: [1,2,3,8]`은 평가가 무의미해질 수 있음 → **fold별 최소 트레이드 수/포지션 변화 수 미달 시 FAIL**로 처리하라.

## TOP1) 운영/재현성 패치: 리밸런스/비용/노출 로그를 “항상 남기게” 고정
**(a) 왜 필요한지**
- 현재 `rebalance_pinpoint`가 입력을 못 읽고 있고, `run_hash/lane_hash/worst_mdd`도 비어 있음. 이 상태면 **성능이 안 움직이는 원인이 “전략”인지 “로깅/평가 결측”인지 분리가 불가**.

**(b) 위험/부작용**
- 로그가 늘어 IO/저장소 비용 증가.
- FAIL-fast로 인해 실험이 더 자주 중단될 수 있음(하지만 이게 정상).

**(c) 최소 실험(게이트로 1개만 진행)**
- **E1-1 (필수)**: `rebalance_events.jsonl` 표준 스키마로 저장(타임스탬프, ticker, target_w, prev_w, trade_qty, est_cost, realized_fill(옵션), reason) + 경로를 artifact에 기록.
- **E1-2 (옵션, E1-1 통과 시만)**: 평가 리포트에서 `worst_mdd`, turnover, gross/net exposure, trade count를 “필수 필드”로 강제(결측이면 FAIL).
- **E1-3 (옵션, E1-2 통과 시만)**: `degenerate fold` 감지 시 해당 실험을 “무효”로 마킹하고, 원인(표본 부족/리밸런스 없음/노출 0)까지 자동 출력.

**(d) PASS 조건**
- 100% 실험에서 `rebalance_events.jsonl` 생성 + `worst_mdd` 산출 + fold별 trade/event 카운트가 리포트에 표시.
- `aub_rebalance_pinpoint`가 base/cand 모두에서 **에러 없이 비교 리포트 생성**.

**48시간 루프 기대 관측치**
- “성능 무변화”가 발생해도 **(1) 트리거 발생 여부 (2) 실제 주문 발생 여부 (3) 비용/노출로 상쇄 여부**가 숫자로 갈라짐.

## TOP2) 누수/과최적화 패치: Purged Walk-Forward + fold 퇴화 제거(embargo 포함)
**(a) 왜 필요한지**
- degenerate fold가 여러 개면, OOS mean이 좋아도 **실제로는 일부 구간이 평가에서 빠지거나(거래 0), 누수로 부풀었을 가능성**이 큼.

**(b) 위험/부작용**
- 성능(평균 수익)이 단기적으로 떨어질 수 있음(정상: 과대추정이 제거됨).
- 데이터/시간 분할이 빡세져 표본이 줄어듦.

**(c) 최소 실험(게이트로 1개만 진행)**
- **E2-1 (필수)**: Purged Walk-Forward CV 적용  
  - purge window = 신호 lookback + 실행 지연(예: 1~2일)  
  - embargo = 1~5 거래일 중 1개로 고정(스윕 금지, 48시간엔 1개만)
- **E2-2 (옵션, E2-1 통과 시만)**: fold별 최소 조건 가드  
  - 각 fold에 “리밸런스 이벤트 ≥ N(예: 30)” 또는 “평균 노출 > 0.1” 미달 시 FAIL
- **E2-3 (옵션, E2-2 통과 시만)**: feature leakage 스캔(라벨/미래값 참조 패턴 탐지)  
  - 예: forward return/미래 고가/종가 shift 오류, 리밸런스 시점 이후 가격 사용 여부 검사

**(d) PASS 조건**
- degenerate fold = 0
- OOS mean이 “의미 있게” 유지: 기존 대비 **급락(-30% 이상) 시 원인 리포트에 누수/표본 이슈가 명시**되어야 PASS(숫자만으로 PASS/FAIL 하지 말고, 진단이 나와야 함).
- OOS min이 지나치게 0 근처로 “인위적 안정화”되면(거래가 안 나가서) FAIL.

**48시간 루프 기대 관측치**
- 성능이 내려가면: 과대추정 제거 시그널.
- 성능이 유지되면: “전략 개선” 실험으로 넘어갈 자격 확보.

## TOP3) 비용 미반영 패치: 슬리피지/수수료/스프레드 기반 비용모델을 “하드-게이트”로 넣기
**(a) 왜 필요한지**
- 미국 대형 Tech/Healthcare라도 리밸런스/턴오버가 크면 **OOS 개선이 비용에 즉시 소거**됨. 현재 리밸런스 로그도 깨져 있어 비용 상쇄 여부가 안 보임.

**(b) 위험/부작용**
- 단기 성과 하락(정상).
- 비용모델이 과보수면 좋은 전략까지 죽일 수 있음.

**(c) 최소 실험(게이트로 1개만 진행)**
- **E3-1 (필수)**: 단일 비용모델 고정(스윕 금지)  
  - 예: `cost = max(1bp, 0.5*spread_bp) + k*volatility_proxy + fixed_commission_bp`  
  - spread는 (가능하면) 일별 bid-ask 또는 대체 proxy(예: ATR 기반)로 추정
- **E3-2 (옵션, E3-1 통과 시만)**: “비용 차감 후에도” 신호가 남는지 확인하는 진단 출력  
  - gross pnl / cost / net pnl을 fold별로 출력
- **E3-3 (옵션, E3-2 통과 시만)**: short가 있으면 borrow cost(간단히 연 0.5~2% 고정) 추가

**(d) PASS 조건**
- Net OOS mean이 **양수 유지 + gross-to-net ratio가 비정상(예: 비용이 gross의 70% 이상)일 경우 FAIL**.
- turnover 상위 10% 구간에서 net이 일관되게 음수면 FAIL(턴오버 억제 패치로 이동).

**48시간 루프 기대 관측치**
- “성능 무변화”의 상당수가 **비용으로 상쇄되는지** 바로 드러남.

## TOP4) 노출/턴오버 패치: 8~14 종목 고정 + 변동성 타깃 + turnover penalty(단일 형태)
**(a) 왜 필요한지**
- `exposure_max 0.84`는 좋을 수도 있지만, fold 퇴화/리밸런스 결측 상황에선 “어떤 구간은 0, 어떤 구간은 과도”일 가능성이 큼.  
- 턴오버가 높으면 비용/슬리피지로 성능이 멈춘다.

**(b) 위험/부작용**
- 너무 강한 노출/턴오버 제한은 알파를 죽일 수 있음.
- 포트가 “항상 비슷”해져서 레짐 변화에 둔감해질 수 있음.

**(c) 최소 실험(게이트로 1개만 진행)**
- **E4-1 (필수)**: 포지션 업데이트에 turnover penalty 단일 도입  
  - 목적함수: `score_adj = score - λ * |Δw|` (λ 하나만, 스윕 금지)
- **E4-2 (옵션, E4-1 통과 시만)**: 변동성 타깃(예: 10~12% 연환산 고정)으로 스케일링  
  - 단, ETF 매매 금지. ETF는 관측(레짐)만.
- **E4-3 (옵션, E4-2 통과 시만)**: gross/net cap 고정(예: gross ≤ 1.0, net ≤ 0.6)

**(d) PASS 조건**
- turnover가 의미 있게 감소(예: -20% 이상)하면서 Net OOS mean이 악화되지 않거나(±작은 범위), OOS min 개선(왼쪽 꼬리 완화).
- 노출이 “0에 붙는 구간”이 사라지고(coverage 증가), 리밸런스 이벤트가 fold별로 고르게 분포.

**48시간 루프 기대 관측치**
- 성능이 안 움직일 때 “신호는 있는데 비용/턴오버로 죽는지”를 분리.

# 2) 48시간 자동 루프 실행 순서(강제)
1) **E1(로깅/재현성) 먼저 통과** → 실패하면 다른 실험 금지  
2) **E2(누수/분할) 통과** → degenerate fold가 남으면 전략 실험 금지  
3) **E3(비용모델) 적용 후 성능 확인**  
4) **E4(턴오버/노출)로 net 개선 시도**  
5) **E5(유니버스 고정)로 안정성 확인**

# 3) 성능이 안 움직일 때 “원인 분해” 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **리포트에 강제로 출력**해서, “신호가 없나 / 적용이 안 되나 / 비용이 먹나 / 레짐이 다르나”를 1회 실행으로 분해하라.

## A. Trigger(신호 발생) 문제
- 각 ticker별, 각 fold별:
  - `signal_nonzero_rate`(신호가 0이 아닌 비율)
  - `signal_strength_mean/std`
  - 상위/하위 분위수에서 다음날(또는 보유기간) 수익의 방향성(간단한 hit-rate)

**관측 패턴**
- 신호가 대부분 0 → 피처/임계값/게이트가 너무 빡셈.
- 신호는 강한데 성과 0 → 아래 “적용/노출/비용” 문제 가능.

## B. Apply(리밸런스/주문 적용) 문제
- `rebalance_event_count`와 `|Δw|` 분포를 fold별 출력.
- “신호는 있는데 주문이 안 나감” 케이스를 자동 태깅:
  - 제한조건(gross/net cap)으로 컷
  - 최소 주문단위/라운딩으로 소멸
  - 데이터 결측으로 스킵

**관측 패턴**
- 이벤트 수가 매우 적음 → “전략이 안 도는” 운영 문제(혹은 게이트 과도).

## C. Exposure(노출) 문제
- 시간별 `gross`, `net`, `HHI(집중도)`, top1 종목 비중을 출력.
- 포지션이 “0 근처에 붙는 기간”의 비율(coverage) 출력.

**관측 패턴**
- coverage가 낮으면 성과가 안 움직이는 게 정상 → 게이트/스케일 수정.

## D. Cost(비용) 문제
- fold별 `gross pnl`, `cost`, `net pnl`, `cost/gross`를 고정 출력.
- turnover 상위 구간에서 net이 음수로 고정되는지 확인.

**관측 패턴**
- gross는 플러스인데 net이 0 근처 → 비용/슬리피지가 원인.

## E. Regime(레짐) 문제 — ETF는 관측만
- QQQ/XLK/XLV의 추세(예: 50/200MA), 변동성(예: 20d realized vol)로 레짐 라벨링:
  - Risk-on(상승/저변동), Risk-off(하락/고변동) 등 4분면
- 레짐별 성과를 분해해서 “특정 레짐에서만 알파”인지 확인.

**관측 패턴**
- 특정 레짐에서만 성과 → 게이트를 레짐 조건으로 제한(매매가 아니라 **포지션 스케일/리스크만** 조절).

---

## 최종 출력 형태(각 실험 공통, 자동 리포트에 강제)
- OOS mean/min, worst MDD, turnover, gross/net exposure, cost(gross/net), trade/rebalance count
- degenerate fold 여부 및 사유
- 기여도: ticker별 PnL/리스크 기여 상위 3개
- 레짐별 성과 테이블(ETF는 관측 지표로만)

이 5개 Patch/실험을 위 순서로 돌리면, “성능이 안 움직인다”를 **전략 문제로 결론내리기 전에** 운영/평가/누수/비용/노출/레짐 중 어디서 막히는지 48시간 내에 숫자로 갈라낼 수 있다.
