### 1. 24~48시간 우선순위 TOP 5 제안 (코드/아키텍처/전략)

#### P1. [아키텍처] Degenerate Folds(1, 2, 3, 8) 긴급 디버깅 및 로깅 복구
*   **왜 필요한가:** 전체 폴드 중 4개가 '퇴화(Degenerate)'했다는 것은 해당 구간에서 거래가 전무하거나, 수익률이 0으로 수렴했음을 의미. 이는 과도한 리스크 제약(Risk Constraint)이나 데이터 결측으로 인한 Silent Failure임. 또한 `rebalance.csv` 로드 실패는 비용 분석을 불가능하게 함.
*   **위험/부작용:** 로깅 로직 수정 시 오버헤드 증가 가능성.
*   **실험 (Patch):**
    1.  **EXP_LOG_FIX:** `rebalance` 로그 포맷을 JSONL로 강제 통일 및 경로 절대경로화 (`tools/aub_rebalance_pinpoint.py` 수정).
    2.  **EXP_NO_STOP:** Folds 1, 2, 3 구간에서 'Stop Loss' 또는 'Min Volatility' 제약 해제 후 백테스트 실행.
*   **PASS 조건:**
    *   `rebalance_pinpoint.md`가 정상 생성됨.
    *   Degenerate Folds 개수가 0개로 감소.

#### P2. [전략] 변동성 타겟팅(Volatility Targeting) 완화 실험
*   **왜 필요한가:** 현재 Exposure Max가 0.83이고 Degenerate Folds가 다수 존재함. 이는 시스템이 시장 변동성을 과대평가하여 현금(Cash) 비중을 100%로 유지하는 '쫄보(Cowardly) 구간'이 길다는 반증.
*   **위험/부작용:** MDD(최대 낙폭) 증가 가능성.
*   **실험 (Experiments):**
    1.  **EXP_VOL_RELAX_10:** 목표 변동성(Target Vol)을 기존 대비 10% 상향.
    2.  **EXP_MIN_EXPOSURE:** 포트폴리오 최소 노출(Exposure Min)을 강제로 0.3으로 설정 (Cash 비중 최대 0.7 제한).
    3.  **EXP_ETF_VIX_FILTER:** VIX ETF(VIXY 등)의 모멘텀이 양수일 때만 Cash 전환 로직 적용 (단순 변동성 수치 기반 제외).
*   **PASS 조건:**
    *   Exposure Max > 0.9.
    *   OOS Mean > 2.0 유지하면서 Degenerate Folds 해소.

#### P3. [전략] Tech/Healthcare 섹터 밸런싱 강제 (Universe Constraint)
*   **왜 필요한가:** 현재 8~14개 종목 제한에서, 특정 섹터(예: Tech)로만 쏠림 현상이 발생하여 특정 구간(Healthcare 강세장 등)에서 성과가 퇴화했을 가능성. ETF는 매매 제외이나 지표로 활용 필요.
*   **위험/부작용:** 강제 분산으로 인한 샤프지수 하락.
*   **실험 (Experiments):**
    1.  **EXP_SECTOR_HARD_LOCK:** 유니버스 내 Tech 4종목, Healthcare 4종목 최소 보유 강제 (Signal Top N 선정 시 섹터 쿼터제 도입).
    2.  **EXP_XLV_XLK_REL:** (XLK/XLV) 상대강도 지표를 통해, 우위 섹터에 가중치 1.5배 부여.
*   **PASS 조건:**
    *   종목 집중도(HHI) 감소.
    *   특정 섹터 하락 구간(Fold 1, 2 등)에서 방어력 입증 (Drawdown < -10%).

#### P4. [비용] 슬리피지/수수료 가혹 테스트 (Reality Check)
*   **왜 필요한가:** OOS Mean 3.32는 비현실적임. 거래 비용이 0이거나 과소계상되었을 확률 99%. 실제 운영 시 '운영 리스크'로 직결.
*   **위험/부작용:** 챔피언 모델 폐기 수순 (심리적 타격).
*   **실험 (Experiments):**
    1.  **EXP_COST_STRESS_BP:** 슬리피지 10bps + 수수료 5bps 적용 후 재평가.
    2.  **EXP_TO_CAP:** 회전율(Turnover) 일일 20% 초과 시 패널티 부여 로직 추가.
*   **PASS 조건:**
    *   OOS Mean > 1.5 (생존 확인).
    *   일일 회전율 < 15% 수준 안착.

#### P5. [데이터] 서바이버십 바이어스(Survivorship Bias) 점검
*   **왜 필요한가:** 2026년 시점(현재 상태)에서 과거 2020~2024 데이터를 볼 때, 현재 상장 폐지된 Tech/Bio 종목이 유니버스에 포함되어 있는지 확인 불가. 생존한 승자만 가지고 백테스트했을 가능성.
*   **위험/부작용:** 데이터셋 재구축 비용 발생.
*   **실험 (Experiments):**
    1.  **EXP_DELIST_INJECT:** 과거 상장 폐지된 주요 Tech/Bio 종목(예: SVB 등)을 유니버스에 강제 주입하여 로직이 어떻게 처리하는지 확인.
*   **PASS 조건:**
    *   상폐 종목 보유 시 손실 처리가 정상적으로 반영됨 (MDD 악화 확인).

### 2. 48시간 자동 루프 정의 (Execution Loop)

각 실험은 다음 포맷으로 `experiment_system`에 큐잉(Queueing)할 것.

#### 실험 A: [EXP_FIX_DEGENERATE] 변동성 제약 완화 및 최소 노출 설정
*   **실험 정의:** `config.constraints.min_exposure = 0.2` (기존 0.0), `config.risk.vol_target_multiplier = 1.2`
*   **게이트(Gate):**
    *   `degenerate_folds_count` <= 1
    *   `oos_mean` >= 2.5
*   **기대 관측치:**
    *   Folds 1, 2, 3의 수익률 곡선이 Flat(0)에서 변동하기 시작함.
    *   전체 Exposure Mean이 0.4~0.6 수준으로 상승.

#### 실험 B: [EXP_REALITY_CHECK] 고비용 구조 적용
*   **실험 정의:** `config.cost_model.slippage = 0.0015` (15bps), `config.cost_model.commission = 0.0005`
*   **게이트(Gate):**
    *   `oos_mean` >= 1.2 (3.32에서 급락하더라도 1.2 이상이면 양호)
    *   `oos_sharpe` >= 1.0
*   **기대 관측치:**
    *   고빈도 매매가 줄어들고 보유 기간(Holding Period)이 증가함.

#### 실험 C: [EXP_SECTOR_BALANCE] 쿼터제 적용
*   **실험 정의:** `algo.selection.force_sector_min = {"Technology": 4, "Healthcare": 4}`
*   **게이트(Gate):**
    *   `oos_min` > -0.05 (MDD 방어력 개선)
*   **기대 관측치:**
    *   XLV(헬스케어) 방어주 성격으로 인해 하락장(Fold 1, 2 예상 구간) 손실폭 축소.

### 3. 성능 정체 시 원인 분해 (Debug Checklist)

성능지표가 움직이지 않거나(Flat), 3.32 같은 비정상 수치에 고착화될 경우 체크리스트.

1.  **트리거(Trigger) 불감증:**
    *   *체크:* 매수/매도 시그널의 Threshold가 너무 높아(예: 예측확률 > 0.95) 거래가 거의 안 일어나는가?
    *   *액션:* Threshold를 0.6 수준으로 낮춰서 노이즈 거래를 유발해 볼 것.

2.  **적용(Application) 실패:**
    *   *체크:* 유니버스 필터링(유동성, 가격)에서 Tech/Healthcare 우량주가 다 걸러지고 잡주만 남았는가?
    *   *액션:* `universe_filter.log` 확인. $200 이상 고가주(High Price)가 제외되는지 확인.

3.  **노출(Exposure) 제로:**
    *   *체크:* 시장 변동성 지표(VIX 등)가 데이터 파이프라인에서 `NaN`이나 `Infinity`로 들어와 시스템이 Defensive Mode(Cash 100%)로 잠겼는가?
    *   *액션:* Feature Data의 `Null` 비율 점검.

4.  **레짐(Regime) 불일치:**
    *   *체크:* 학습 데이터는 '저금리 상승장'인데, 테스트 데이터(Fold 1~3)는 '고금리 하락장'인가?
    *   *액션:* ETF(SPY, IEF)의 200일 이동평균선을 Feature로 강제 주입하여 레짐 정보를 모델에 제공.
