### 1. 우선순위 TOP 5 제안 (48시간 내 실행)

**P1. [INFRA] 로그 파이프라인 정합성 긴급 패치**
*   **(a) 이유:** `Error loading --base-log`, `worst_mdd: None`, `rebalance.csv` 파싱 에러 발생. 측정 도구가 고장 난 상태에서 모델 개선은 불가능. 데이터 누락 상태임.
*   **(b) 위험:** 로깅 수정 중 기존 벤치마크 데이터와의 포맷 불일치로 이력 단절 가능성.
*   **(c) 실험:**
    1.  `fix_logger_format`: rebalance 로그를 JSONL로 통일하고 `NaN` 값을 `null`로 변환하여 저장.
    2.  `recalc_metrics`: 기존 챔피언 모델을 재실행하여 `worst_mdd`가 `None`이 아닌 실수(float)로 찍히는지 확인.
*   **(d) PASS 조건:** `worst_mdd` ≠ None AND 파싱 에러 0건.

**P2. [MODEL] Degenerate Folds(1,2,3,8) 해결을 위한 진입 장벽 완화**
*   **(a) 이유:** 전체 Fold의 절반 가까이가 거래가 없거나 무의미함(Degenerate). 이는 과도한 필터링(Over-filtering)으로 인한 과최적화 신호. 특정 시기(초기 데이터 등)에 서바이버십 편향 가능성 높음.
*   **(b) 위험:** 진입 장벽을 낮추면 MDD가 급격히 증가하고 승률이 떨어질 수 있음.
*   **(c) 실험:**
    1.  `relax_entry_thresh`: 진입 임계값(score)을 기존 대비 10~15% 하향 조정.
    2.  `min_universe_check`: 해당 Fold 기간에 거래 가능한 Tech/Healthcare 유니버스가 최소 8개 이상 존재하는지 검증하는 로직 추가.
*   **(d) PASS 조건:** Degenerate Folds 개수 < 2 (기존 4개).

**P3. [COST] 슬리피지/수수료 현실화 (Stress Test)**
*   **(a) 이유:** OOS Mean 3.32는 비현실적으로 높음. 비용이 `0`이거나 과소 계상되었을 확률 99%. 실제 운영 시 계좌가 녹아내릴 위험.
*   **(b) 위험:** 벤치마크 성능이 급락하여 챔피언 모델이 폐기될 수 있음(그러나 이는 필요한 고통임).
*   **(c) 실험:**
    1.  `apply_cost_model_v1`: 매매당 수수료 0.1% + 슬리피지 5bps 강제 적용 후 OOS 측정.
    2.  `force_market_impact`: 유동성이 낮은 소형 바이오주(Healthcare) 비중 제한(Max 5%).
*   **(d) PASS 조건:** 비용 적용 후에도 OOS Mean > 1.0 유지.

**P4. [STRATEGY] Tech/Health 섹터 밸런싱 강제**
*   **(a) 이유:** "Tech+Healthcare 중심" 요구사항. 현재 특정 섹터(예: Tech)에만 몰빵되어 수익률이 왜곡되었을 수 있음.
*   **(b) 위험:** 강제 배분으로 인한 수익률 저하(Momentum 킬링).
*   **(c) 실험:**
    1.  `sector_cap_60`: 단일 섹터(Tech or Health) 비중 합계 Max 60% 제한.
    2.  `pair_selection`: 상위 랭킹에서 Tech 1개 선택 시 Health 1개 의무 선택 (Pairing).
*   **(d) PASS 조건:** 포트폴리오 내 섹터 비중이 한쪽으로 80% 이상 쏠리지 않음.

**P5. [RISK] 변동성(VIX) 기반 노출 제어 (Regime Filter)**
*   **(a) 이유:** `exposure_max`가 0.83인데 `oos_min`이 -0.02로 극도로 낮음. 이는 하락장에서 현금 보유가 잘 되었다는 뜻이나, 운(Luck)일 수 있음. 명시적 규칙 필요.
*   **(b) 위험:** 잦은 마켓 타이밍 시도로 인한 휩소(Whipsaw) 손실.
*   **(c) 실험:**
    1.  `vix_filter_25`: VIX > 25 구간에서 신규 진입 금지 및 기존 포지션 50% 청산.
    2.  `tnx_filter`: 10년물 국채금리(TNX) 급등 구간(WoW +5% 이상) 매매 중단.
*   **(d) PASS 조건:** 2022년(하락장) 구간 MDD 개선 확인.

### 3. 성능 정체 시 원인 분해 (Debug Tree)

성능 지표가 움직이지 않거나(Flat), 기대와 다를 때 다음 순서로 체크:

1.  **TRIGGER (신호 발생 여부)**
    *   *원인:* `entry_threshold`가 너무 높거나, `liquidity_filter`가 모든 Tech/Health 종목을 걸러내고 있음.
    *   *확인:* 일별 `candidate_count` 로그 확인. 0이면 필터 완화 필요.
2.  **EXPOSURE (비중 할당)**
    *   *원인:* 신호는 떴으나 최적화기(Optimizer)가 리스크(공분산) 과대평가로 비중을 0.01% 수준으로 줌.
    *   *확인:* `weights.csv`에서 0.0 이상인 종목들의 평균 비중 확인.
3.  **EXECUTION (체결 및 비용)**
    *   *원인:* 시가(Open) vs 종가(Close) 괴리, 혹은 슬리피지로 인해 이론 수익이 삭제됨.
    *   *확인:* `gross_return` vs `net_return` 격차 분석.
4.  **REGIME (시장 국면)**
    *   *원인:* 현재 테스트 구간이 Tech/Health 섹터 전체가 횡보하는 구간임 (Beta가 0에 수렴).
    *   *확인:* 벤치마크(XLK, XLV) 대비 Alpha가 있는지 확인. Alpha가 0이면 전략 무용지물.
