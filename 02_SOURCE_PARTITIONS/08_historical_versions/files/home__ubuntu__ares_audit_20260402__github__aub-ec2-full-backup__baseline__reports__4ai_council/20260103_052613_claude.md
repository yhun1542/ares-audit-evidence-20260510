### #1. Lockbox-Tuning 갭 원인 분해 (과적합/누수 점검)

| 항목 | 내용 |
|------|------|
| **왜 필요** | Champion lockbox 4.01 vs tuning 2.32 → 72% 갭은 feature leakage 또는 fold 분포 편향 시사 |
| **위험/부작용** | 진짜 alpha가 lockbox 구간에만 존재할 수 있음 (false negative) |
| **PASS 조건** | gap < 0.5σ 또는 leak 경로 명시적 식별 |

**최소 실험:**
```
EXP-1a: feature timestamp audit
  - 정의: 모든 feature의 t-1 완결성 검증 (earnings, macro 특히)
  - 게이트: leak 발견 시 즉시 FAIL, 수정 후 재실행
  - 기대치: gap 감소 or 원인 코드라인 특정

EXP-1b: fold boundary shuffle
  - 정의: lockbox 기간을 3개 다른 구간으로 rotate
  - 게이트: 3구간 모두 tuning 대비 +50% 이상이면 레짐 의존 확정
  - 기대치: 구간별 분산 측정 → α 안정성 판단

EXP-1c: purged k-fold gap 재계산
  - 정의: embargo=5일 적용 후 gap 재측정
  - 게이트: gap < 0.8σ면 PASS
  - 기대치: 기존 embargo 부족 여부 확인
```
