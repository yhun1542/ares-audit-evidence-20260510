## 24~48시간 TOP5 우선순위(명령형 체크리스트)

### P1) **누수/과최적화(Temporal Integrity) 최우선 차단**
- **왜 필요한지**: Champion은 tuning/lockbox가 비슷해 보이지만, *숨은 누수(라벨 정렬/미래 가격/리밸런싱 시점 오류)*가 있으면 “성능이 안 움직이거나” 특정 구간에서만 비정상적으로 강해집니다.
- **위험/부작용**: 누수 제거 시 단기적으로 성능 하락(정상), 데이터/피처가 대거 무효화될 수 있음.
- **최소 실험(공유 실험 ID 참조)**: **E1, E3**
- **PASS 조건**:
  - (필수) tuning↔lockbox 갭 축소: `abs(tuning_mean - lockbox_mean) <= 0.10`
  - (필수) 최악 구간 MDD 악화 금지: `worst_mdd >= -0.10` 유지(Champion 근처)
  - (권장) “의심 피처” 제거 후에도 lockbox_mean 급락(>0.15p) 없으면 통과

---

### P2) **비용/슬리피지/턴오버를 성능함수에 “강제 반영”**
- **왜 필요한지**: 비용 미반영은 실전에서 가장 흔한 실패 원인입니다(특히 8~14종목 집중 포트에서 리밸런스 잦으면 체감 손익 급변).
- **위험/부작용**: 비용 넣으면 평균 수익 급락 가능, 모델이 거래를 지나치게 안 하게 될 수 있음(신호 무력화).
- **최소 실험**: **E2, E4**
- **PASS 조건**:
  - (필수) 비용 포함 lockbox_mean이 Champion 대비 **-0.05p 이내** 방어
  - (필수) 연환산 턴오버/거래횟수 **30% 이상 감소** 또는 비용/매매대금 비율 안정화
  - (권장) “비용 충격 구간”에서 drawdown 개선(최악 MDD 개선 폭 ≥ +0.01)

---

### P3) **서바이버십/유니버스 고정(Tech+Healthcare 8~14) + PIT 검증**
- **왜 필요한지**: 유니버스가 학습/평가 기간에 따라 바뀌면(현재 존재 종목만 포함 등) 서바이버십 편향이 생기고, 개선이 멈춘 듯 보이는 “가짜 상한”이 나타납니다.
- **위험/부작용**: 고정 유니버스는 기회 감소, 특정 종목 이벤트에 민감(집중 리스크).
- **최소 실험**: **E3, E1**
- **PASS 조건**:
  - (필수) 유니버스 고정 후에도 lockbox_mean 급락(>0.10p) 없을 것
  - (필수) 종목별 기여도 상위 1종목 의존도 완화(Top1 PnL 기여 < 35% 권장)

> 유니버스(예시, **미국주식 only / Tech+Healthcare / 12종목**):  
Tech: AAPL, MSFT, NVDA, AMZN, GOOGL, META, AVGO, AMD  
Healthcare: LLY, UNH, JNJ, MRK  
(ETF는 매매 제외, 관측지표로만 사용)

---

### P4) **운영 리스크(재현성/데이터 결측/코퍼릿액션) 하드닝**
- **왜 필요한지**: 자동 루프 48시간에서 가장 치명적인 건 “조용한 데이터 이상”과 “재현 불가”입니다. 성능이 안 움직이면 먼저 운영층에서 병목이 생겼을 확률이 큽니다.
- **위험/부작용**: 초기엔 실패(FAIL fast) 빈도가 증가, 개발 속도 체감 저하.
- **최소 실험**: **E1, E2**
- **PASS 조건**:
  - (필수) 동일 커밋/동일 데이터 스냅샷에서 결과 완전 재현(주요 지표 오차 허용폭 1e-6~1e-4)
  - (필수) 결측/분할/배당 처리 오류 시 “즉시 중단 + 롤백” 동작 확인

---

### P5) **레짐(변동성/추세) 기반 메타-게이트로 MDD 개선**
- **왜 필요한지**: Champion은 수익은 좋지만 MDD가 약 -9.6% 수준. Candidate는 수익이 떨어졌지만 MDD가 -4%대로 개선. 즉 “수익-리스크 트레이드”가 핵심 병목일 가능성 큼.
- **위험/부작용**: 레짐 신호가 과최적화되면 오히려 성능 흔들림(게이트가 노이즈 증폭).
- **최소 실험**: **E5, E4**
- **PASS 조건**:
  - (필수) worst_mdd를 **-0.08 이상**으로 개선(Champion 대비 개선)
  - (필수) lockbox_mean **1.63 이상** 유지(수익 급락 방지)

---

## 48시간 자동 루프용 “공유 실험(3~5개)” 정의 (총 5개만 실행)

아래 **E1~E5**를 autopilot이 48시간 동안 반복 실행하도록 고정하고, TOP5 제안은 이 실험들을 **공유 참조**합니다.

---

### E1) **Purged Walk-Forward + Embargo + 라벨/피처 시점 감사(Leakage Kill Switch)**
1) **실험 정의(패치)**  
- 학습/검증 분할을 “purged”로 변경(리밸런스 주기 기준으로 lookahead 구간 제거)  
- embargo 적용(검증 시작 직전 N일 학습 데이터 제거)  
- 피처 생성 시점 강제 `t-1`(당일 종가 기반이면 다음날 체결로 강제)  
- 라벨(수익률) 정렬을 “체결 가능 시점 이후”로 이동
2) **게이트(자동 FAIL 조건)**  
- (하드) 검증 구간에 학습 샘플이 시간적으로 겹치면 즉시 FAIL  
- (하드) 피처에 당일 종가/고가/저가가 “체결 전에” 반영되면 FAIL  
- (소프트) tuning_mean 급락은 허용, 단 tuning-lockbox 갭이 커지면 FAIL
3) **기대 관측치**  
- tuning이 내려가도 lockbox 안정도 상승(갭 축소)  
- fold별 성능 분산 감소(“잘 되는 폴드만” 살아남는 현상 완화)

---

### E2) **거래비용/슬리피지 모델 + 턴오버 페널티(현실 손익 고정)**
1) **실험 정의(패치)**  
- 비용 모델 최소 구성:  
  - 고정 수수료(또는 bps) + 슬리피지(bps) + 스프레드 가정  
- 목적함수에 turnover penalty 추가(예: 비용추정치 기반)  
- 결과 리포트에 “gross vs net”를 항상 분리 표기
2) **게이트**  
- (하드) net 성능 미산출이면 FAIL  
- (소프트) net lockbox_mean이 Champion 대비 -0.05p 이상 하락하면 FAIL
3) **기대 관측치**  
- 거래횟수/턴오버 감소  
- gross는 비슷해도 net이 덜 흔들리는 구조로 이동

---

### E3) **유니버스 고정(8~14 Tech+Healthcare) + PIT 가격/액션 정합성**
1) **실험 정의(패치)**  
- 백테스트 전체 기간 동안 유니버스 고정(12종목 추천 리스트 사용)  
- 조정주가/분할/배당 처리 파이프라인을 “PIT 일관성”으로 통일  
- 상장폐지/거래정지 같은 이벤트는 “데이터 부재=현금화 규칙”으로 단순화(운영 리스크 감소)
2) **게이트**  
- (하드) 종목별 거래 가능일 캘린더 불일치/가격 점프(코퍼릿액션 미처리) 감지 시 FAIL  
- (소프트) 특정 1종목 PnL 기여가 과도(>35~40%)면 FAIL
3) **기대 관측치**  
- 서바이버십 편향 제거로 폴드간 성능이 더 “비슷”해짐  
- 개선이 “안 되는 이유”를 유니버스 변동성에서 분리 가능

---

### E4) **리스크 오버레이: 변동성 타게팅 + 포지션 상한 + 리밸런스 완화**
1) **실험 정의(패치)**  
- 포트 변동성 타게팅(예: 최근 20~60일 실현변동성 기반)  
- 단일 종목 최대 비중 상한(예: 12~15%)  
- 리밸런스 완화(목표비중 변화가 임계치 이하이면 거래 생략)
2) **게이트**  
- (하드) 포지션 상한 위반 시 FAIL  
- (소프트) lockbox_mean < 1.63이면 FAIL(수익 급락 방지)
3) **기대 관측치**  
- worst_mdd 개선, tail 리스크 완화  
- 비용도 동반 감소(불필요 리밸런스 제거)

---

### E5) **레짐 메타-게이트(관측용 ETF/지수 사용 가능, 매매는 개별주만)**
1) **실험 정의(패치)**  
- 관측지표로만 사용(매매 금지): SPY(시장), XLK(Tech), XLV(Healthcare) 또는 VIX 대용 지표  
- 레짐 조건 예:  
  - 고변동/급락 레짐: 노출 축소(현금 비중↑ 또는 종목 수↓)  
  - 저변동/추세 레짐: 기본 전략 유지/확대  
- 메타-게이트는 “단순 규칙 1~2개”로 제한(과최적화 방지)
2) **게이트**  
- (하드) 레짐 규칙이 fold별로 다르게 튜닝되면 FAIL(규칙 고정)  
- (소프트) worst_mdd 개선이 없으면 FAIL
3) **기대 관측치**  
- Candidate가 보여준 MDD 개선(-4%대)을 일부 재현  
- 수익률은 소폭 희생하더라도 tail 손실 감소

---

## 성능이 “안 움직일 때” 원인 분해(트리거/적용/노출/비용/레짐) 체크리스트

### 1) Trigger(신호) 문제
- **증상**: 예측력/랭킹이 폴드마다 들쭉날쭉, 튜닝만 높고 락박스 정체
- **즉시 점검**:
  - IC(정보계수), hit-rate, top-bottom spread를 **폴드별**로 로그
  - 피처 1~3개가 성능 대부분을 설명하는지(과의존) 확인
- **즉시 조치**: E1로 누수 제거 + “당일정보” 제거 + 피처 라그 강제

### 2) Apply(적용: 리밸런스/체결/포지셔닝) 문제
- **증상**: gross는 개선인데 net은 정체 / 거래가 너무 잦음
- **즉시 점검**:
  - 턴오버, 거래횟수, 평균 보유기간, 리밸런스 임계치
  - 신호 변화 대비 포지션 변화가 과도한지(포지션 탄성)
- **즉시 조치**: E2(비용) + E4(리밸 완화/상한)

### 3) Exposure(노출: 단일종목/섹터/팩터) 문제
- **증상**: 특정 1~2종목이 거의 모든 손익을 좌우(서바이버십/집중 리스크)
- **즉시 점검**:
  - 종목별 PnL 기여, 최대 비중, 상관 구조(동일 방향 쏠림)
- **즉시 조치**: E3(유니버스 고정) + E4(상한/볼타게팅)

### 4) Cost(비용) 문제
- **증상**: 개선 실험들이 전부 “실전 가정”에서 사라짐
- **즉시 점검**:
  - gross→net 감소폭, 거래가 몰리는 시간대/이벤트(실적발표 등)
- **즉시 조치**: E2 비용 강제 + 거래 생략 규칙(E4)

### 5) Regime(시장 레짐) 문제
- **증상**: 특정 변동성 구간에서만 성능 발현, 최악 MDD 구간이 고정
- **즉시 점검**:
  - 최악 MDD가 발생한 날짜 주변의 변동성/추세/섹터 회전
  - 레짐별 성능(고/저 변동, 상승/하락 국면)
- **즉시 조치**: E5(관측 ETF/지수로 레짐 게이트) + E4로 tail 방어

---

## 실행 순서(48시간 내, 질문 없이 그대로 수행)
1) **E1 먼저 실행**: 누수 의심 제거 없이는 어떤 개선도 신뢰 불가  
2) **E2 병행**: 비용 포함 net을 “기본 스코어”로 고정  
3) **E3로 유니버스 고정**: 서바이버십/가변 유니버스 요인 제거  
4) **E4 적용**: MDD/운영 안정성 개선(리밸런스 절제)  
5) **E5는 마지막**: 레짐은 과최적화 위험이 커서 위 1~4 통과 후 투입

위 5개(E1~E5)만으로 48시간 자동 루프에서 “누수/비용/서바이버십/운영/레짐” 병목을 순서대로 분리해 낼 수 있게 구성했습니다.
