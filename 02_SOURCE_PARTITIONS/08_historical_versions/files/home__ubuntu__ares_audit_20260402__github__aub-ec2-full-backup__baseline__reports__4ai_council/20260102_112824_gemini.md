### 2) 실행 가능한 Patch / 실험 제안 (3건)

    *   로그 파일 정상 생성 확인.

#### 실험 B: `Exp_Smooth_Exposure_0.1`

    *   Exposure Min/Max 범위가 0.6 ~ 0.8 수준으로 축소.

### 3) 성능 정체 원인 분해 (Debugging Tree)

현재 성능(OOS 1.88)이 정체되어 있다면, 다음 5가지 관점에서 원인을 파악하라.

1.  **트리거(Trigger) 지연:**
    *   *가설:* 지표(Indicator)가 너무 후행적(Lagging)이라 이미 가격이 오른 뒤 매수하고 내린 뒤 매도함.
    *   *확인:* 진입 시점의 `Entry Price`와 `Next Day Open` 간의 괴리(Slippage)가 아닌, 진입 후 3일간 수익률 분포 확인.

2.  **적용(Execution) 누수:**
    *   *가설:* 시뮬레이터는 종가(Close) 배정을 가정하나, 실제 로직은 익일 시가(Open) 배정일 때 갭(Gap)으로 인한 손실.
    *   *확인:* 백테스트 설정을 `Execution=NextOpen`으로 변경 후 성과 급락 여부 체크.

3.  **노출(Exposure) 과잉/부족:**
    *   *가설:* 상승장에서 현금을 너무 많이 들고 있거나(Cash Drag), 하락장에서 레버리지가 걸려있음.
    *   *확인:* `Exposure` 시계열과 `SPY` 수익률 간의 상관계수(Correlation) 측정. 양의 상관관계가 강해야 함.

4.  **비용(Cost) 잠식:**
    *   *가설:* 잦은 리밸런싱으로 인한 수수료가 알파를 갉아먹음.
    *   *확인:* `Gross Return`과 `Net Return`의 차이(Spread)가 연 2% 이상인지 확인. (Rebalance 로그 복구 후 최우선 확인)

5.  **레짐(Regime) 불일치:**
    *   *가설:* 현재 전략이 '추세 추종'인데 시장이 '박스권'임.
    *   *확인:* 최근 3개월 시장 변동성(VIX)과 전략 수익률 대조. VIX가 낮을 때 수익이 나지 않는다면 변동성 돌파 전략이 필요.
