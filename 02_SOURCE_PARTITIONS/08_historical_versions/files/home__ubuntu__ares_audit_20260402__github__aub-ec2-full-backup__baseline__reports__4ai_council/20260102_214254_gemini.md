## 1. 향후 24~48시간 우선순위 TOP 5 제안

### [P1] `worst_mdd: None` 및 로그 파싱 오류 수정 (Critical)
*   **(a) 필요성**: MDD가 계산되지 않는다는 것은 리스크 계측이 불가능한 상태(Blind Spot)임. `Rebalance Pinpoint`의 파일 포맷 불일치(JSON vs CSV)는 분석 파이프라인을 마비시킴.
*   **(b) 위험**: 잘못된 지표(High OOS Mean)에 속아 치명적인 Drawdown이 숨겨진 전략을 배포할 위험.
*   **(c) 실험 (Experiments)**:
    1.  `fix_metric_calc`: MDD 계산 로직에 0 나누기 방지 및 NaN 처리 강화, 결과가 `None`일 경우 강제 Fail 처리.
    2.  `standardize_logs`: Rebalance 로그를 `jsonl` 포맷으로 통일하고, 기존 CSV 파서 제거 또는 호환 레이어 추가.
*   **(d) PASS 조건**: `worst_mdd`가 유효한 `float` 값으로 산출됨 + 파이프라인 에러 0건.

### [P2] Degenerate Folds (1, 2, 3, 8) 안정화 (Robustness)
*   **(a) 필요성**: 전체 Fold 중 약 40%가 실패(Degenerate)함. 특정 시장 국면(Regime)에서 전략이 파산하거나 거래를 멈추는 과최적화 증상.
*   **(b) 위험**: OOS Mean이 높아도, 라이브 트레이딩 시 해당 국면을 만나면 즉시 계좌가 망가짐.
*   **(c) 실험 (Experiments)**:
    1.  `regime_filter_vix`: VIX(또는 ETF 변동성) 상위 10% 구간에서 Cash 비중 100% 강제 (Fold 1,2,3,8 방어 확인).
    2.  `clip_outliers`: 수익률 분포 상/하위 1% 윈저라이징(Winsorizing) 후 학습 재진행.
*   **(d) PASS 조건**: Degenerate Folds 개수가 1개 이하로 감소 + OOS Mean > 1.5 유지.

### [P3] 유니버스 강제 및 섹터 집중 (Universe/Constraint)
*   **(a) 필요성**: Tech+Healthcare, 8~14 종목 제한 준수. 현재 0.0~0.83 Exposure는 현금 비중이 높거나 종목 수가 부족할 수 있음.
*   **(b) 위험**: 서바이버십 편향(상폐 종목 제외된 데이터 사용) 또는 유동성 부족 종목 선택.
*   **(c) 실험 (Experiments)**:
    1.  `universe_tech_health_top20`: XLK, XLV 구성 종목 중 시총 상위 20개씩만 유니버스로 고정.
    2.  `force_min_assets`: 포트폴리오 내 최소 보유 종목 수 8개 미만 시 진입 금지(또는 현금 보유).
*   **(d) PASS 조건**: 보유 종목 수(Median) 8~14 구간 안착 + Tech/Health 비중 100%.

### [P4] 비용 민감도 테스트 (Cost Reality)
*   **(a) 필요성**: OOS Mean 3.32는 비현실적임. 슬리피지와 수수료가 과소평가되었을 가능성 99%.
*   **(b) 위험**: 백테스트 수익이 실제 매매 비용으로 전액 상쇄됨.
*   **(c) 실험 (Experiments)**:
    1.  `stress_test_bps_10`: 편도 거래 비용을 10bps(0.1%)로 설정하여 백테스트.
    2.  `stress_test_bps_20`: 편도 거래 비용을 20bps(0.2%)로 설정하여 백테스트.
*   **(d) PASS 조건**: 20bps 비용 적용 시에도 OOS Sharpe > 1.0 유지.

### [P5] Lookback Window 다양화 (Parameter Stability)
*   **(a) 필요성**: 특정 윈도우(예: 20일)에만 최적화되었을 가능성. Fold 붕괴의 원인일 수 있음.
*   **(b) 위험**: 시장 속도가 변할 때(빠른 하락/느린 상승) 대응 실패.
*   **(c) 실험 (Experiments)**:
    1.  `multi_window_ensemble`: 5일, 20일, 60일 신호의 가중 평균 사용.
    2.  `adaptive_window`: 변동성(ATR)에 따라 룩백 윈도우 동적 조절.
*   **(d) PASS 조건**: 기존 단일 윈도우 대비 OOS Volatility 감소.

## 2. 48시간 자동 루프 실행 계획

### Experiment 1: Metrics & Logging Fix (P1)
1.  **실험 정의**: MDD 계산 모듈의 예외 처리 추가 및 로깅 포맷을 JSONL로 통일.
2.  **게이트 (Gate)**: `analysis_pipeline` 실행 시 Exit Code 0 반환 && `worst_mdd` != None.
3.  **기대 관측치**: `rebalance_pinpoint.md` 리포트가 정상 생성됨.

### Experiment 2: Heavy Cost Stress Test (P4)
1.  **실험 정의**: `config.transaction_cost`를 0.0005(5bps)에서 0.0020(20bps)까지 5bps 단위로 증액하여 4회 백테스트.
2.  **게이트 (Gate)**: 모든 케이스에서 연환산 수익률(CAGR) > 0.
3.  **기대 관측치**: 비용 증가에 따라 OOS Mean이 급격히 1.0 이하로 꺾이지 않는지 확인 (선형적 감소는 OK, 절벽형 감소는 NG).

### Experiment 3: Anti-Fragile Filtering (P2)
1.  **실험 정의**: Fold 1, 2, 3, 8 구간의 데이터를 분석하여 공통적 특징(예: VIX > 25, SPY < MA200) 추출 후 필터 적용.
2.  **게이트 (Gate)**: `degenerate_folds` 리스트가 비어 있거나 `[1]` 등 1개 이하.
3.  **기대 관측치**: OOS Mean은 다소 하락(3.3 -> 2.0 수준)하더라도 `oos_min`이 -0.02에서 크게 개선되지 않거나 악화되지 않음(안정성 확보).

## 3. 성능 정체 시 원인 분해 (Debugging Checklist)

성능 지표가 움직이지 않을 경우 아래 순서로 병목을 점검하고 **코드 레벨**에서 수정하라.

1.  **트리거 (Trigger)**
    *   *Check*: 신호 생성 로직(`alpha_model`)의 임계값(Threshold)이 너무 높아 거래가 아예 발생하지 않는지?
    *   *Action*: 임계값 0으로 낮추고 Raw Signal 분포 확인.

2.  **노출 (Exposure)**
    *   *Check*: `exposure_max`가 0.83인데, 실제로는 특정 1-2 종목에 몰방되어 있고 나머지는 현금인지?
    *   *Action*: 종목별 가중치(`weights`) 로그 덤프 확인.

3.  **비용 (Cost)**
    *   *Check*: 잦은 리밸런싱으로 인해 수익이 수수료로 삭제되고 있는지? (Turnover Rate 확인)
    *   *Action*: `rebalance_frequency`를 주간/월간으로 변경 테스트.

4.  **레짐 (Regime)**
    *   *Check*: 학습 데이터가 강세장에 편향되어 있어, 횡보/하락장에서 신호를 못 만드는지?
    *   *Action*: 2022년(하락장) 데이터에 대해서만 별도 OOS 테스트 수행.

5.  **데이터 (Data Integrity)**
    *   *Check*: 가격 데이터에 `NaN`이나 `0`이 포함되어 신호가 Drop 되고 있는지?
    *   *Action*: 전처리 단계에서 결측치 보간(`ffill`) 로직 강제 적용.
