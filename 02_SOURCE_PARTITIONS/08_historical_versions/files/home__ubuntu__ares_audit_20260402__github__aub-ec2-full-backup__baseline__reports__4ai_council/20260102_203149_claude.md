## 1. 우선순위 TOP 5 액션

### P1. 인프라/데이터 무결성 복구 (BLOCKER)

**(a) 왜 필요한지**
- rebalance.csv 파싱 실패 → 실험 비교 불가
- OOS Mean 불일치 (3.32 vs 2.63) → 어느 숫자가 진실인지 불명
- MDD=None → 리스크 게이트 작동 불가

**(b) 위험/부작용**
- 복구 중 48h 윈도우 소모
- 잘못된 복구 시 히스토리 손상

**(c) 최소 실험**

| # | 실험 | 게이트 | 기대 관측치 |
|---|------|--------|-------------|
| 1-1 | `aub_validate_champion.py --check-integrity` | 파일 해시 일치 | JSON/CSV 포맷 일관성 100% |
| 1-2 | `rebalance_parser.py --fix-format` | 파싱 성공률 | 10/10 fold 로드 성공 |
| 1-3 | `mdd_calculator.py --backfill` | worst_mdd 값 산출 | MDD ∈ [-0.40, 0] 범위 확인 |

**(d) PASS 조건**
```
□ rebalance.csv 정상 로드
□ OOS Mean 단일값 확정 (±0.01 오차 내)
□ worst_mdd 숫자 반환
```

### P2. Degenerate Fold 원인 분리

**(a) 왜 필요한지**
- 4/10 폴드 퇴화 = 전략이 특정 레짐에서만 작동
- 레짐: 금리인상기(Fold1~3) + 변동성급등(Fold8) 가능성
- 수정 없이 진행 시 OOS 붕괴 확률 높음

**(b) 위험/부작용**
- 폴드별 맞춤 수정 → 과최적화 위험 ↑
- 폴드 제거 시 데이터 손실

**(c) 최소 실험**

| # | 실험 | 게이트 | 기대 관측치 |
|---|------|--------|-------------|
| 2-1 | `fold_regime_tagger.py` (VIX>25, 10Y>4% 태깅) | 태그 분포 확인 | Fold1,2,3,8 = 고VIX or 고금리 >60% |
| 2-2 | `run_backtest.py --exclude-folds 1,2,3,8` | OOS Mean 변화 | 남은 6폴드 OOS Mean > 4.0 예상 |
| 2-3 | `strategy_stress.py --regime=high_vol` | 손익 분해 | 퇴화폴드 손실 원인 (Tech 집중? 타이밍?) |

**(d) PASS 조건**
```
□ 퇴화 원인 레짐 식별 완료
□ 건전 폴드 OOS Mean ≥ 3.5 유지
□ 레짐별 전략 분기 설계안 도출
```

### P5. 레짐 적응형 파라미터 탐색

**(a) 왜 필요한지**
- 단일 파라미터셋 → 특정 레짐 과적합
- Degenerate 폴드가 레짐 문제라면, 레짐별 분기 필요

**(b) 위험/부작용**
- 파라미터 ↑ = 과적합 경로 ↑
- 복잡도 증가 → 운영 에러 확률 ↑

**(c) 최소 실험**

| # | 실험 | 게이트 | 기대 관측치 |
|---|------|--------|-------------|
| 5-1 | `regime_detector.py --method vix_20ma` | 레짐 라벨 | Bull/Bear/Volatile 3분류 |
| 5-2 | `run_backtest.py --regime-switch simple` | 폴드별 OOS | Degenerate 폴드 개선 (≥2개 복구) |
| 5-3 | `param_sensitivity.py --regime=volatile` | 민감도 맵 | 변동성 레짐 최적 파라미터 범위 |

**(d) PASS 조건**
```
□ Degenerate 폴드 ≤ 2개로 감소
□ 전체 OOS Mean ≥ 2.5 유지
□ 레짐 전환 지연 ≤ 3일
```

## 2. 48h 자동 루프 체크리스트

```yaml
# autopilot_48h.yaml
loop_interval: 6h
max_iterations: 8

sequence:
  - phase: INFRA_FIX
    run:
      - aub_validate_champion.py --check-integrity
      - rebalance_parser.py --fix-format
      - mdd_calculator.py --backfill
    gate: all_pass
    
  - phase: FOLD_DIAGNOSIS  
    depends: INFRA_FIX
    run:
      - fold_regime_tagger.py
      - run_backtest.py --exclude-folds 1,2,3,8
    gate: regime_identified
    
  - phase: EXPOSURE_CAP
    depends: FOLD_DIAGNOSIS
    run:
      - run_backtest.py --max-exposure 0.60
      - cost_model.py --slippage 10bp
    gate: oos_mean >= 2.0
    
  - phase: LEAKAGE_AUDIT
    depends: EXPOSURE_CAP
    run:
      - lookahead_detector.py
      - survivorship_audit.py
    gate: violations == 0

abort_conditions:
  - oos_mean < 1.5
  - mdd < -0.35
  - degenerate_folds > 5
```

## 3. 성능 미동 시 원인 분해 트리

```
성능 변화 없음
├─ [트리거] 신호 미발생?
│   ├─ 조건 너무 엄격 → 발생 빈도 체크
│   └─ 데이터 지연/누락 → 피드 상태 확인
│
├─ [적용] 신호 발생 but 미실행?
│   ├─ 포지션 한도 도달 → exposure 로그
│   └─ 리스크 게이트 차단 → gate 로그
│
├─ [노출] 실행됐으나 영향 미미?
│   ├─ 포지션 사이즈 너무 작음 → sizing 분포
│   └─ 상쇄 포지션 존재 → net exposure
│
├─ [비용] 수익 = 비용?
│   ├─ 슬리피지 과다 → 실행가 vs 신호가
│   └─ 빈번한 회전 → turnover 측정
│
└─ [레짐] 전략 무효 구간?
    ├─ VIX 레벨 체크 → 현재 vs 학습 분포
    └─ 금리/달러 환경 → 매크로 레짐 태그
```

**디버깅 명령어:**
```bash

python3 tools/cost_attribution.py --breakdown        # 비용
```
