## 24~48시간 TOP5 우선순위(코드/아키텍처/전략) — **명령형 체크리스트**

### 1) **리밸런스/로그/메타데이터 파이프라인을 먼저 “정상화”**
- [ ] `aub_rebalance_pinpoint`가 **현재 파일을 못 읽는 상태**를 즉시 해소(CSV/JSONL 포맷, 경로, 인코딩).
- [ ] `lane_hash / run_hash / worst_mdd`가 `None`으로 남지 않도록 **단일 소스(artifact JSON)에서 강제 산출**.
- [ ] “챔피언 비교(베이스 vs 캔디데이트)”가 항상 동일 포맷으로 재현되도록 **로그 스키마 고정**.

**(a) 왜 필요한지**
- 지금 상태는 “성능이 안 움직이는 것” 이전에 **측정/추적이 불가능**(rebalance 데이터 로딩 실패, run/lane hash 누락, MDD 미계산).
- 48시간 자동 루프에서 “왜 안 움직였는지”를 남길 수 없는 구조면, 실험이 누적될수록 디버깅 비용만 커짐.

**(b) 위험/부작용**
- 로그 산출을 강화하면 I/O 증가로 실행시간이 늘 수 있음.
- 스키마 변경 시 과거 리포트 호환성 깨질 수 있음(마이그레이션 필요).

**(c) 최소 실험(여기서는 E1로 통합, 변형 2~3개는 내부 토글로 처리)**
- (E1-A) rebalance 로그를 **JSONL(행 단위)**로 고정 + “필수 필드” 누락 시 실패 처리
- (E1-B) 기존 CSV도 병행 생성(사람 눈 검증용), 단 파서는 JSONL 우선
- (E1-C) `worst_mdd` 계산을 리포트 단계가 아니라 **백테스트 종료 시점에 강제 기록**

**(d) PASS 조건**
- `aub_rebalance_pinpoint.py`가 **에러 없이** base/cand 둘 다 로드하고 비교 리포트 생성
- artifact JSON에 `lane_hash/run_hash/worst_mdd`가 **항상 non-null**
- 최소 1회 리밸런스가 있는 실험에서 `rebalance.jsonl`이 **0바이트가 아님**

### 2) **누수/과최적화/폴드 붕괴(degenerate_folds) 우선 차단**
- [ ] `degenerate_folds: [1,2,3,8]` 원인 제거: 데이터 split/라벨/피처 생성의 시간축 정합 검증.
- [ ] Purged/Embargo walk-forward로 “미래 정보” 유입을 구조적으로 막기.

**(a) 왜 필요한지**
- 폴드가 붕괴하면 OOS 평균이 좋아도 **의미 없는 승리**(누수/데이터 부족/선정 편향)일 확률이 큼.
- Tech+Healthcare 8~14종목은 표본이 작아서, 누수/경계조건 버그가 성능을 “고정된 것처럼” 보이게 만들기도 함.

**(b) 위험/부작용**
- 누수 차단하면 당장 OOS 수치가 떨어질 수 있음(정상 반응).
- 샘플이 더 줄어 과소학습이 드러날 수 있음.

**(c) 최소 실험 (E2로 통합)**
- (E2-A) Purged K-Fold + embargo(예: 5~10거래일) 적용
- (E2-B) 모든 피처에 대해 “asof(시점 고정)” 강제(리밸런스 시점 이후 데이터 접근 시 fail-fast)
- (E2-C) 폴드별 유효 샘플/유효 리밸런스 횟수 최소치 미달 시 폴드 자체를 **실험 실패로 처리**

**(d) PASS 조건**
- `degenerate_folds == []`
- OOS 지표가 “좋아짐”이 아니라 **폴드 간 분산이 감소**(stability 개선)
- 최소 조건: OOS mean이 챔피언 대비 -X 이내(예: -0.15 이내)로 유지되면서 OOS min/최악 구간이 개선되면 합격

### 3) **거래비용/슬리피지/유동성(운영 리스크 포함) 모델을 ‘의도적으로’ 강하게 넣기**
- [ ] 비용 미반영 상태에서의 개선은 실전에서 무의미할 가능성이 큼 → 먼저 비용을 넣어 “환상 수익” 제거.
- [ ] 8~14 종목 집중은 회전율이 조금만 커져도 비용에 취약.

**(a) 왜 필요한지**
- 지금 “성능이 안 움직임”은 (1) 신호가 약함이 아니라 (2) 비용/회전율이 수익을 상쇄하는데 로그가 없어서 못 보는 상황일 수 있음.
- Tech 대형주는 괜찮아도 일부 헬스케어(바이오/메디컬디바이스)는 스프레드/갭이 커서 체감 비용이 큼.

**(b) 위험/부작용**
- 성능 수치가 단기적으로 내려가며 “개선이 사라진 것처럼” 보일 수 있음(정상).
- 과도한 비용 가정은 신호를 죽일 수 있음(보수적 편향).

**(c) 최소 실험 (E3로 통합)**
- (E3-A) 슬리피지 = `k * (spread + sqrt(order/ADV))` 형태의 보수적 모델(고정 k로 시작)
- (E3-B) 회전율 상한(예: 리밸런스당 notional 20~30%) + 초과분은 다음 회차로 이월
- (E3-C) 공매도/대차/하드투보로우는 **금지(롱온리)**로 고정(운영 리스크 제거)

**(d) PASS 조건**
- turnover 상한을 걸어도 OOS mean이 “붕괴”하지 않을 것(예: 챔피언 대비 -0.20 이내 유지)
- 비용 반영 후에도 OOS min(최악)이 개선되거나, worst_mdd가 유의미하게 감소

### 4) **서바이버십/코퍼레이트액션(분할·합병·상폐) ‘점검을 테스트로 강제’**
- [ ] “현재 구성 종목만”으로 과거를 돌리는 서바이버십 편향 차단.
- [ ] split/dividend 조정 및 상폐 처리 누락 시, 특정 구간에서 성능이 “이상하게 고정/왜곡”됨.

**(a) 왜 필요한지**
- Tech+Healthcare라도 장기간이면 구성 변화가 생김.
- 표본이 작은 8~14 종목 바스켓은 **단 1개 종목의 데이터 오류가 전체 성능을 고정**시킬 수 있음.

**(b) 위험/부작용**
- 데이터 소스 교체/정정으로 과거 결과가 크게 변동(재현성 이슈).
- 구현 비용이 들 수 있음(하지만 48시간 루프에선 “검증 테스트”라도 먼저 넣는 게 이득).

**(c) 최소 실험 (E4로 통합)**
- (E4-A) “포인트인타임 유니버스” 테스트: 리밸런스 날짜에 존재하지 않는 티커가 잡히면 즉시 실패
- (E4-B) 조정주가 vs 비조정주가 혼용 탐지(분할일 전후 급변율 이상치로 자동 감지)
- (E4-C) 상폐/거래정지 바 처리 규칙 고정(마지막 유효가로 청산 등)

**(d) PASS 조건**
- 미래 티커/미래 재무지표 접근 시 **fail-fast**
- 분할/배당 이벤트 구간에서 비정상 수익률 스파이크가 감소
- 동일 기간 재실행 시 성능 재현(결과 drift 허용범위 내)

### 5) **노출/레짐(Tech vs Healthcare 상대강도) 기반 게이트를 “지표로만” 추가**
- [ ] ETF는 매매 금지(요구사항) → **관측 지표로만 사용**(QQQ, XLV 등).
- [ ] 8~14종목 집중 전략에서 레짐 게이트는 MDD/최악구간 개선에 직결.

**(a) 왜 필요한지**
- 성능이 안 움직일 때 흔한 원인: 신호는 있는데 레짐이 반대라서 **노출이 계속 상쇄**됨.
- Tech/Healthcare는 금리/리스크온오프에 민감 → 레짐 필터가 “나쁜 시기만 피하는” 효과가 큼.

**(b) 위험/부작용**
- 게이트가 과하면 거래가 줄어 “기회 상실”.
- 지표가 느리면 반응이 늦어질 수 있음.

**(c) 최소 실험 (E5로 통합)**
- (E5-A) 레짐 스코어 = 20일 모멘텀(또는 60일) 기반: `QQQ vs XLV 상대강도`가 음수면 Tech 비중 축소, 양수면 정상
- (E5-B) 변동성 게이트: VIX(또는 SPY 변동성 대체지표) 급등 구간에 **총 노출 캡**(exposure_max를 자동 낮춤)
- (E5-C) 금리 민감도(10Y 수익률: ^TNX 등) 급등 시 고밸류 Tech 노출 감산(단, 지표로만)

**(d) PASS 조건**
- OOS min(최악)이 개선(예: 더 이상 -0.025 이하로 악화되지 않음)
- exposure_max가 레짐에 따라 “의도한 대로” 움직이며, worst_mdd가 감소

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)

아래는 **질문 없이** 바로 추가할 수 있는 “분해 로그/리포트 항목” 체크리스트임.

### A) Trigger(신호 생성) 문제
- [ ] 리밸런스 시점마다 **신호 분포(평균/표준편차/상위-하위 스프레드)** 기록  
  - 관측: 분포가 거의 일정(평평)하면 신호가 죽었거나 스케일링/클리핑으로 소실
- [ ] 신호가 변해도 **랭킹 상관(전일 vs 당일 Spearman)** 기록  
  - 관측: 상관이 항상 0.9+면 “변화 없는 신호” → 성능이 안 움직이는 게 정상

### B) Apply(선정/리밸런스 로직) 문제
- [ ] “선정 종목 8~14개” 제약 때문에 **항상 같은 종목만 뽑히는지**(선정 다양성) 기록  
  - 관측: 상위 N이 고정이면 전략이 사실상 buy-and-hold에 가까워짐
- [ ] 목표비중→실행비중 괴리(리밸런스 실패/캡 적용) 로그  
  - 관측: cap/rounding 때문에 실제 포트가 거의 변하지 않으면 성능 변화가 작음

### C) Exposure(노출) 문제
- [ ] 총 노출(gross/net), 섹터(Tech/Healthcare) 비중, 상위 1~3종목 기여도(contribution) 기록  
  - 관측: 상위 1종목이 대부분을 설명하면 “전략”이 아니라 “단일 종목 베팅” 상태
- [ ] exposure가 0~0.84로 널뛰는 원인을 규명(게이트/현금화 조건)  
  - 관측: 현금 비중이 커지면 평균수익이 “정체”처럼 보일 수 있음(리스크는 줄었는지 함께 봐야 함)

### D) Cost(비용) 문제
- [ ] 리밸런스별 비용 기여도(수수료/슬리피지/스프레드)를 PnL과 함께 저장  
  - 관측: 총 PnL이 미세하게 움직이는 이유가 “비용이 알파를 상쇄”인지 즉시 확인
- [ ] ADV 대비 주문비율(특히 헬스케어 일부) 기록  
  - 관측: 주문/ADV가 일정 임계치(예: 1~3%)를 넘으면 슬리피지로 성능이 고정되기 쉬움

### E) Regime(시장 국면) 문제 — ETF는 “지표로만”
- [ ] 국면 태그를 붙여 성과를 분해:  
  - `QQQ 모멘텀(+/-)`, `XLV 모멘텀(+/-)`, `QQQ-XLV 상대강도(+/-)`, `VIX 상/하`, `10Y 상승/하락`
- [ ] 각 태그별 hit-rate, avg return, worst drawdown 기록  
  - 관측: 특정 국면에서만 유효하면 “평균이 안 움직이는” 건 레짐 믹스 문제 → 게이트가 해법

---

### 요약(실행 순서 고정)
1) **E1**로 “측정 가능 상태” 만들기 → 지금 rebalance pinpoint가 깨져 있어서 최우선  
2) **E2**로 누수/폴드 붕괴 제거(신뢰도 확보)  
3) **E3**로 비용/회전율/롱온리(운영 가능성 확보)  
4) **E4**로 서바이버십/CA 테스트 강제(데이터 리스크 제거)  
5) **E5**로 레짐 기반 노출 제어(최악구간 개선)

이 5개만 48시간 루프에 태우면, “성능이 왜 안 움직였는지”가 **신호 문제인지 / 적용 문제인지 / 노출·비용·레짐 문제인지** 최소 1~2회전 안에 분해 가능해짐.
