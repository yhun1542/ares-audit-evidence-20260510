## 0. 선행 점검 (누수/과최적화/비용/리스크)

| 체크 항목 | 현재 상태 | 액션 |
|-----------|-----------|------|
| **Tuning-Lockbox 갭** | tuning 1.76 vs lockbox 1.79 → **역전(lockbox > tuning)** | ✅ 과적합 아님, 정상 |
| **Tuning min 이상치** | 0.0508 (거의 0) → **특정 fold 붕괴 의심** | ⚠️ fold별 분해 필요 |
| **MDD 수준** | worst -11.2% → 허용범위 | ✅ |

## 1. 우선순위 TOP 5 제안

### PATCH-1: Tuning Min 0.05 Fold 격리 및 원인 분해

**(a) 왜 필요한가**
- tuning_min 0.0508은 사실상 해당 fold에서 전략 붕괴
- 이 fold가 lockbox에 영향 안 줬을 뿐, 향후 레짐에서 재발 가능
- **숨겨진 리스크 노출 전 식별 필수**

**(b) 위험/부작용**
- 해당 fold 제거 시 survivorship bias 발생
- fold 특성에 과적합된 fix 적용 위험

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| 1A | `--debug-fold` 플래그로 min fold 식별 및 거래 로그 덤프 | 완료 | fold 번호, 해당 기간, 종목별 손익 |
| 1B | 해당 fold 기간의 VIX/금리 레짐 태깅 | 레짐 라벨 생성 | 고변동/금리급등 등 특이 레짐 여부 |
| 1C | 해당 fold에서 position sizing만 50% 축소 백테스트 | tuning_min > 0.3 | MDD 개선, 평균 수익 감소폭 < 10% |

**(d) PASS 조건**
- tuning_min ≥ 0.30 AND tuning_mean 감소 < 5%

---

### PATCH-2: Candidate 무차별 원인 분해 (실험 다양성 부족)

**(a) 왜 필요한가**
- Champion vs Candidate 차이 0.0001 → **탐색 공간 소진 또는 local optima**
- 현재 실험이 동일 축(파라미터 미세조정)만 탐색 중일 가능성

**(b) 위험/부작용**
- 새로운 축 탐색 시 variance 증가
- 과도한 구조 변경은 검증 비용 폭발

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| 2A | module_registry.yaml 내 미사용 모듈 1개 활성화 (예: alternative_exit) | 빌드 성공 | lockbox 분산 변화 관측 |
| 2B | 현재 signal generator의 lookback을 ±30% 변형한 2개 candidate 생성 | 실행 완료 | tuning 분포 이동 여부 |
| 2C | Healthcare 비중 상한 +5%p 실험 | 섹터 cap 수정 | 섹터 집중 리스크 vs 수익 트레이드오프 |

**(d) PASS 조건**
- 최소 1개 candidate에서 lockbox_mean > 1.80 OR tuning_min > 0.30

---

### PATCH-3: 비용 모델 현실화 점검

**(a) 왜 필요한가**
- 현재 백테스트 비용 가정 미명시 → 실거래 괴리 리스크
- slippage/commission 과소 추정 시 lockbox 성능 과대평가

**(b) 위험/부작용**
- 비용 상향 시 전략 수익성 급락 가능
- 과도한 비용 가정은 실행 가능 전략 제거

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| 3A | slippage 0.05% → 0.10% 상향 백테스트 | 실행 완료 | lockbox_mean 변화량 (Δ < -0.05 시 경고) |
| 3B | 연간 회전율(turnover) 계산 및 로깅 | 메트릭 추가 | 회전율 > 500% 시 비용 민감도 높음 |

**(d) PASS 조건**
- slippage 0.10%에서 lockbox_mean > 1.70

---

### PATCH-4: 레짐 필터 ON/OFF A/B 테스트

**(a) 왜 필요한가**
- 레짐 필터가 과거 특정 구간에만 유효했을 가능성
- 필터가 오히려 기회비용 발생 중인지 검증 필요

**(b) 위험/부작용**
- 필터 제거 시 MDD 급증 가능
- 레짐 정의 자체가 look-ahead bias 포함 가능성

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| 4A | 레짐 필터 비활성화 candidate 생성 | 빌드 성공 | worst_mdd 변화, tuning_mean 변화 |
| 4B | 레짐 필터 lookback 절반으로 축소 | 실행 완료 | 반응속도 vs 노이즈 트레이드오프 |

**(d) PASS 조건**
- 필터 OFF 시 worst_mdd < -0.15 AND tuning_mean > 1.70 → 필터 유효성 재검토
- 필터 OFF 시 worst_mdd > -0.20 → 필터 유지 확정

---

### PATCH-5: 종목 수 확장 실험 (현재 8-14 → 10-16)

**(a) 왜 필요한가**
- 집중 포트폴리오의 idiosyncratic risk 노출
- tuning_min 붕괴가 특정 종목 집중 때문일 가능성

**(b) 위험/부작용**
- 종목 증가 시 alpha 희석
- 거래 비용 증가

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| 5A | max_positions 14 → 16 변경 | 실행 완료 | tuning_min 개선, MDD 개선 여부 |
| 5B | min_positions 8 → 10 변경 | 실행 완료 | 현금 비중 감소 vs 리스크 변화 |

**(d) PASS 조건**
- tuning_min > 0.20 AND worst_mdd 악화 < 1%p

## 2. 48시간 자동 루프 스펙

```yaml
# experiment_system/config/48h_loop_spec.yaml
loop_interval: 6h
max_iterations: 8

experiments:
  - id: PATCH-1C
    cmd: "python3 tools/backtest.py --config candidate_fold_fix.json --size-mult 0.5"
    gate: "tuning_min > 0.30"
    
  - id: PATCH-2B
    cmd: "python3 tools/aub_autopilot.py --lookback-variants 0.7,1.3"
    gate: "any(lockbox_mean) > 1.80"
    
  - id: PATCH-3A
    cmd: "python3 tools/backtest.py --slippage 0.001"
    gate: "lockbox_mean > 1.70"
    
  - id: PATCH-4A
    cmd: "python3 tools/backtest.py --regime-filter off"
    gate: "worst_mdd < -0.15"
    
  - id: PATCH-5A
    cmd: "python3 tools/backtest.py --max-positions 16"
    gate: "tuning_min > 0.20"

promotion_rule: |
  IF any(PASS) → promote to candidate_*.json
  IF all(FAIL) → log to baseline/reports/failed_experiments.md
  IF INCONCLUSIVE → retry with extended data
```

## 3. 성능 정체 원인 분해 트리 (5-Why 구조)

```
성능이 안 움직임
│
├─[1] 트리거 미발동
│   ├─ 시그널 임계값이 현재 시장에 과도하게 보수적
│   ├─ 점검: 일별 시그널 발동 횟수 로깅 → 월 평균 < 5회면 문제
│   └─ 실험: 임계값 -10% 완화 candidate
│
├─[2] 적용 오류
│   ├─ 시그널은 발동하나 position sizing에서 0으로 수렴
│   ├─ 점검: sizing 단계 로그에서 target_size 분포 확인
│   └─ 실험: sizing 로직 bypass하여 고정 비중 테스트
│
├─[3] 노출 부족
│   ├─ 레짐 필터가 대부분 구간 OFF 처리
│   ├─ 점검: 레짐 ON 비율 < 30%면 과잉 필터링
│   └─ 실험: PATCH-4A/4B
│
├─[4] 비용 잠식
│   ├─ 높은 회전율로 gross alpha를 비용이 소진
│   ├─ 점검: gross return vs net return 갭 > 0.3이면 문제
│   └─ 실험: PATCH-3A/3B
│
└─[5] 레짐 불일치
    ├─ 훈련 구간 레짐 ≠ 검증 구간 레짐
    ├─ 점검: 각 fold별 VIX 평균/분산 비교
    └─ 실험: PATCH-1B 결과로 레짐 태깅 후 stratified fold 재구성
```

## 4. 즉시 실행 명령어 (복사-붙여넣기)

```bash
# Step 1: 문제 fold 식별
python3 experiment_system/tools/fold_analyzer.py \
  --config baseline/champion_v5_20251231.json \
  --output baseline/reports/fold_breakdown.csv

# Step 2: 비용 민감도 테스트
python3 experiment_system/tools/backtest.py \
  --config baseline/champion_v5_20251231.json \
  --slippage 0.001 \
  --output baseline/candidate_cost_stress.json

# Step 3: 포지션 확장 테스트  
python3 experiment_system/tools/backtest.py \
  --config baseline/champion_v5_20251231.json \
  --max-positions 16 \
  --output baseline/candidate_pos16.json

# Step 4: 자동 루프 시작
python3 experiment_system/tools/aub_autopilot.py \
  --registry experiment_system/config/module_registry.yaml \
  --loop-spec experiment_system/config/48h_loop_spec.yaml \
  --run
```
