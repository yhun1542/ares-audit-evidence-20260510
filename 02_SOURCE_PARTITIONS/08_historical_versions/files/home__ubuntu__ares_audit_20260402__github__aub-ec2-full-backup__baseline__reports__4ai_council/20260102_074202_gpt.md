## 1) 우선순위 TOP5 제안 (코드/아키텍처/전략)  
※ 아래 5개 제안은 **실행 실험을 E1~E5(총 5개)**로 제한하고, 각 제안은 그중 **2~3개 실험을 참조**하는 방식으로 케이스 폭발을 방지.

---

### P1) **누수(look-ahead) + Point-in-time 강제 (최우선)**
**(a) 왜 필요한지**
- Champion이 tuning/lockbox 괴리가 크지 않아 보여도, 지금 단계에서 가장 위험한 건 **“평균은 좋아 보이는데 실전에서 무너지는 누수/정렬 오류”**임.
- 특히 Tech/Healthcare는 **실적/가이던스/리비전/기업행사**가 많아 “발표 시점”이 어긋나면 알파가 가짜가 됨.

**(b) 위험/부작용**
- 누수 제거 시 성능이 **즉시 하락**할 수 있음(하지만 이 하락이 “진짜 바닥”).
- 데이터 공급원에 따라 point-in-time를 완벽히 못 맞추면 신호 자체가 약화될 수 있음.

**(c) 최소 실험(2~3개, E-세트 참조)**
- [ ] **E1** 누수 차단(피처/라벨/캘린더 정렬 강제)
- [ ] **E4** 퍼지드 워크포워드로 “CV 갭” 재측정
- [ ] **E5** 데이터 지연/결측 주입 시 신호/포지션이 비정상 점프하는지 점검

**(d) PASS 조건**
- [ ] tuning_mean - lockbox_mean **갭이 확대되지 않을 것**(과최적화/누수 신호)
- [ ] lockbox_min이 **0 아래로 과도하게 꼬리(-) 확장**되지 않을 것(누수 제거 후 급락 방지)
- [ ] “피처 타임스탬프 감사 로그”에서 **t 시점에 t+1 정보 접근 0건**

---

### P2) **거래비용/슬리피지/대차(쇼트) 비용 반영 강화 (net 성능 고정)**
**(a) 왜 필요한지**
- 8~14종목 집중 포트는 turnover가 커지면 **비용 민감도가 극단적으로 커짐**.
- Tech/Healthcare는 이벤트 드리븐 구간에서 스프레드/임팩트가 커져 **백테스트 gross 알파를 net이 잡아먹는** 형태가 자주 발생.

**(b) 위험/부작용**
- 비용 모델이 과도하면 전략이 **거의 거래를 안 하는 형태**로 붕괴할 수 있음.
- 비용 가정 하나로 순위가 바뀌어 “챔피언 불안정”이 증가할 수 있음.

**(c) 최소 실험**
- [ ] **E2** 비용 모델 패치(스프레드+임팩트+ADV 기반 슬리피지 + borrow fee 옵션)
- [ ] **E4** 비용 포함 상태에서만 모델 선택(“net-only selection”)
- [ ] **E3** 고변동 레짐에서 거래 중지(비용 폭증 구간 회피)

**(d) PASS 조건**
- [ ] lockbox에서 **net 기준** 성능이 챔피언 대비 열화되지 않거나(=동급) 개선
- [ ] turnover 상한을 둔 뒤에도 **수익 기여 상위 종목/상위 신호가 유지**(신호 붕괴 방지)
- [ ] “gross→net 드로다운 확대폭”이 줄어들 것(비용 모델이 실제 리스크를 흡수)

---

### P3) **서바이버십 바이어스 제거 + 유니버스(US Tech+Healthcare 8~14) 규칙 고정**
**(a) 왜 필요한지**
- “오늘 살아남은 대형 Tech/Healthcare”로 과거를 테스트하면 **서바이버십이 알파로 오인**될 수 있음.
- 유니버스가 실험마다 흔들리면, 개선이 **전략 개선인지 종목 선택 우연인지** 분리가 안 됨.

**(b) 위험/부작용**
- point-in-time 유니버스가 준비 안 되어 있으면 구현 비용이 증가.
- 유니버스를 고정하면 특정 레짐에서 성능이 떨어질 수 있음.

**(c) 최소 실험**
- [ ] **E1** point-in-time 유니버스 스냅샷(가능한 소스 기준) + 리밸런스 날짜 동기화
- [ ] **E4** “유니버스 고정/변동” 두 조건을 동일 평가 파이프라인에서 비교(단, 실행은 1회만: 고정안 우선)
- [ ] **E5** 종목 상장폐지/거래정지/티커변경 이벤트 주입 테스트

**(d) PASS 조건**
- [ ] 각 리밸런스 시점의 종목 리스트가 **미래 정보를 포함하지 않는 로그**로 재현 가능
- [ ] 8~14종목 제약이 항상 유지되며, Tech+Healthcare 비중 규칙이 깨지지 않을 것
- [ ] “유니버스 변경”이 성능 변동의 주원인이라는 증거가 줄어들 것(변동성 감소)

---

### P4) **과최적화(특히 튜닝_mean 과대) 억제: 퍼지/중첩 CV + 단순성(복잡도) 게이트**
**(a) 왜 필요한지**
- 현재 챔피언은 tuning_mean이 높고 lockbox도 높지만, 다음 후보들이 tuning에서 흔들리는 걸 보면 **탐색 공간이 과적합을 유도** 중일 가능성.
- “평균 상승”보다 중요한 건 **최저치(min)와 MDD의 안정성**.

**(b) 위험/부작용**
- 복잡도 제한 시 절대수익이 약간 감소할 수 있음.
- 탐색이 느려져 48시간 내 탐색 폭이 줄 수 있음(대신 질이 올라감).

**(c) 최소 실험**
- [ ] **E4** 퍼지드 워크포워드/중첩 검증 + 선택 기준을 “lockbox 우선”으로 변경
- [ ] **E2** 비용 포함 net에서만 선택(튜닝 단계부터 비용을 보게 함)
- [ ] **E1** (보조) 피처 지연 강제 시 성능이 급락하면 “누수-유사” 과최적화로 판정

**(d) PASS 조건**
- [ ] 후보 간 성능 순위가 튜닝에서 자주 뒤집히지 않을 것(선택 안정화)
- [ ] worst_mdd가 챔피언(-0.093) 대비 **더 나빠지지 않거나 개선**
- [ ] lockbox_min이 **유의미하게 개선**(꼬리 리스크 감소)

---

### P5) **운영 리스크(48h 자동 루프) 내재화: 데이터/주문/재시도/안전장치**
**(a) 왜 필요한지**
- 자동 루프에서 가장 흔한 실전 실패는 알파가 아니라 **데이터 결측, 캘린더 불일치, 주문 실패 후 재시도 폭주, 포지션 리밸런스 꼬임**.
- 8~14 집중 포트는 1종목 오류가 포트 전체를 흔듦.

**(b) 위험/부작용**
- 안전장치가 과하면 트레이딩이 멈춰 “기회 손실”이 생김.
- 장애 주입 테스트는 초기엔 실패를 많이 만들어 디버깅 부담이 큼.

**(c) 최소 실험**
- [ ] **E5** 장애 주입(결측/지연/심볼 변경/거래정지) + 포지션 무결성 검사
- [ ] **E2** 비용/슬리피지 파라미터 민감도 최소 점검(극단 비용에서도 주문량이 폭주하지 않게)
- [ ] **E3** 레짐 OFF 시 “주문 0”이 아니라 “리스크 축소”로 안전하게 전환되는지 확인

**(d) PASS 조건**
- [ ] 데이터 결측/지연 시에도 포지션이 **NaN/무한대/비정상 레버리지**로 가지 않음
- [ ] 주문 실패 시 재시도가 **상한/백오프**를 지키고, 포지션이 중복 집행되지 않음
- [ ] 48시간 루프에서 “수동 개입 0회”로 정상 완료(리포트 생성 포함)

## 2) 48시간 내 실행할 “실험/패치” 5개 (각: 실험 정의 / 게이트 / 기대 관측치)

### E1) Point-in-time/누수 차단 패치
**(1) 실험 정의**
- 모든 피처에 대해 `feature_timestamp <= decision_time - 1bar(또는 1day)` 강제(최소 1스텝 시프트)
- 실적/펀더멘털/리비전류는 **발표 시각 기준**으로 거래 가능 시점 재정의
- corporate action(분할/배당) 반영 시 **price/volume 정렬 로그** 생성

**(2) 게이트**
- [ ] “라벨 생성 시점”과 “피처 접근 시점” 감사 로그에서 위반 0건
- [ ] 동일 날짜 종가로 신호 계산 후 동일 날짜 종가로 체결하는 구조 금지(동봉 체결 금지)

**(3) 기대 관측치**
- tuning 성능 일부 하락 가능
- 대신 lockbox_min / worst_mdd가 **비정상적으로 악화되지 않으면** 신뢰도 상승

---

### E2) 비용/슬리피지/대차 비용 패치(net 기준 선택)
**(1) 실험 정의**
- 슬리피지: `spread_component + impact_component(ATR, ADV, participation)` 형태로 단순 모델 추가
- short 가능 시 borrow fee(고정 or 구간별 상한) 옵션
- 선택/랭킹은 **net 성능만** 사용

**(2) 게이트**
- [ ] turnover 상한(예: 일/리밸런스당) 초과 시 자동 FAIL
- [ ] net이 gross 대비 과도하게 붕괴하는 후보는 자동 제외

**(3) 기대 관측치**
- gross 대비 net 성능이 내려가도, 후보 간 순위가 “실전형”으로 재정렬
- MDD/꼬리 손실이 줄어드는 방향 기대

---

### E3) ETF는 “관측지표”로만 쓰는 레짐 게이트(거래 ON/OFF or risk scalar)
**(1) 실험 정의**
- 거래 대상은 **US Tech+Healthcare 개별주 8~14개 only**
- 레짐 관측: QQQ/XLK/XLV/SPY, VIX(가능하면)로
  - risk-on: 추세 양호 + 변동 낮음 → 정상 운용
  - risk-off: 변동 급증/추세 붕괴 → 신규 진입 제한 또는 리스크 스칼라 축소

**(2) 게이트**
- [ ] 레짐 입력은 반드시 **t-1까지 데이터**만 사용
- [ ] 레짐이 바뀌어도 포지션이 급격히 뒤집히지 않게(거래량 상한 유지)

**(3) 기대 관측치**
- 대형 급락 국면에서 worst_mdd 및 lockbox_min 개선 기대
- 수익이 줄더라도 “생존성” 개선이 목적

---

### E4) 과최적화 억제: 퍼지드 워크포워드 + 복잡도 상한 + 안정성 선택
**(1) 실험 정의**
- 퍼지 구간(lookahead contamination 방지) 포함한 워크포워드 고정
- 하이퍼파라미터/피처 수/모델 복잡도 상한
- 선택 기준: tuning_mean 중심 → **lockbox_mean & lockbox_min & worst_mdd** 가중

**(2) 게이트**
- [ ] 후보가 tuning에서만 좋고 lockbox에서 무너지는 경우 즉시 제외
- [ ] fold별 성능 분산이 임계치 초과 시 제외(안정성 게이트)

**(3) 기대 관측치**
- 평균은 정체될 수 있으나 “최악 케이스”가 개선되면 성공
- 챔피언 교체가 느려져도 장기적으로 자동 루프 품질 상승

---

### E5) 운영/데이터 장애 주입 + 포지션 무결성 테스트
**(1) 실험 정의**
- 입력 데이터에 결측/지연/중복/티커 변경/거래정지 이벤트를 주입
- 주문 모듈에 실패/부분체결/재시도 상황을 시뮬레이션
- 포지션 불변식 체크: 레버리지, 현금, 종목수(8~14), 섹터(Tech+HC), US only

**(2) 게이트**
- [ ] 어떤 장애에서도 종목수가 0 또는 과다로 폭주하지 않음
- [ ] 재시도 루프 상한/백오프 준수 + 중복주문 방지

**(3) 기대 관측치**
- 성능 숫자보다 “루프 완주율/에러율 0”이 1차 목표
- 실전 이행 가능성이 올라감

---

## 3) 성능이 안 움직일 때 “원인 분해” 아이디어(트리거/적용/노출/비용/레짐)

아래 순서로 **원인 위치를 고정**해서 디버깅(명령형 체크리스트).

### A. Trigger(신호 생성) 문제
- [ ] 신호가 특정 이벤트(실적/급락)에서만 발생하는지 “발생 빈도/조건부 기대수익” 로그화
- [ ] 피처 1개씩 ablation(상위 5개만)으로 **성과 기여/불안정 피처** 식별
- [ ] 신호가 레짐별로 방향이 바뀌는지(예: risk-off에서 모멘텀 역전) 확인

**관측치**
- 신호 발생 횟수, 신호 강도 분포, 상위/하위 분위 수익, 레짐 조건부 hit-rate

### B. Application(적용/리밸런스/체결 시점) 문제
- [ ] 신호 계산 시점과 주문 시점(장중/종가/익일 시가) 불일치 여부 점검
- [ ] 리밸런스 캘린더(휴장/반일장)로 인한 “하루 밀림”이 있는지 검사
- [ ] 동일 바에서 “신호-체결”이 같이 일어나는지(누수 유사) 강제 차단

**관측치**
- 결정시각/체결시각 차이, 캘린더 미스매치 카운트, 슬리피지 분포

### C. Exposure(노출/포지션 구성) 문제
- [ ] 8~14종목 제약 하에서 **상관 높은 종목**만 뽑혀 사실상 1베팅이 되는지 점검
- [ ] Tech/Healthcare 내에서도 하위 산업(반도체/소프트웨어/바이오)의 편중 확인
- [ ] 베타/듀레이션(금리 민감)/퀄리티 팩터에 무의식적으로 과노출인지 확인

**관측치**
- 포트 상관/유효 종목수(Effective N), 섹터/산업 비중, 베타/팩터 노출 시계열

### D. Cost(비용) 문제
- [ ] gross에서는 이기는데 net에서만 죽는지(“비용이 알파를 전부 먹음”) 분해
- [ ] turnover가 특정 레짐에서 폭증하는지 확인(급락장에서 리밸런스 과다)
- [ ] 슬리피지 모델을 0.5x~2x로 흔들었을 때 순위가 뒤집히면 “비용 민감 과다”로 판정

**관측치**
- 거래비용 기여도(총손익 대비 %), turnover-성과 상관, 비용 민감도 곡선

### E. Regime(레짐) 문제
- [ ] 알파가 risk-on에서만 유효한지 / risk-off에서 음(-)인지 조건부 성과로 분해
- [ ] 변동성 급등(VIX/realized vol)에서 체결/슬리피지 악화가 동반되는지 확인
- [ ] 레짐 전환 구간에서 포지션이 뒤집혀 “추세 추종의 역효과”가 나는지 점검

**관측치**
- 레짐별 평균/최저/드로다운, 레짐 전환일 전후 손익, 변동성-슬리피지 상관
