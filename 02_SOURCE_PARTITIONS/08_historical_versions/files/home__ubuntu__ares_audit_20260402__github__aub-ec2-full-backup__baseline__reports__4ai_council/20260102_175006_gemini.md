### 2. 제안별 실행 계획 (Executable Patches)

#### A. Fallback Allocator Injection (Stability)
*   **필요성:** Degenerate Folds는 최적화 솔버(Solver)가 해를 못 찾거나, 데이터 결측으로 인해 발생함. 해당 구간의 성과가 0이거나 NaN 처리되어 전체 `oos_mean`을 왜곡 중.
*   **위험:** 단순 로직(Equal Weight 등)이 복잡한 알파를 희석할 수 있음.
*   **실험 정의:**
    1.  `Exp_Fallback_EW`: 최적화 실패 시, 선정된 상위 N개 종목에 대해 동일 비중(Equal Weight) 배분.
    2.  `Exp_Fallback_Cash`: 최적화 실패 시, 전액 현금 보유(Cash 100%) 처리하여 MDD 방어 여부 확인.
    3.  `Exp_Loose_Constraint`: 최적화 제약조건(Turnover, Min Weight)을 50% 완화하여 솔버 성공률 테스트.
*   **PASS 조건:** `degenerate_folds` 개수 0개 달성 AND `oos_min` > -0.05

#### B. Data Pipeline Repair (Observability)
*   **필요성:** 현재 `rebalance.csv` 파싱 에러로 인해 실제 회전율과 비용을 추적 불가. '눈 가리고 운전'하는 상태.
*   **위험:** 코드 수정 중 로깅 오버헤드 발생 가능성 (미미함).
*   **실험 정의:**
    1.  `Fix_Log_Format`: JSONL 포맷 강제 및 UTF-8 인코딩 명시 코드 배포.
    2.  `Verify_Cost_Impact`: 수리된 로그를 기반으로, 회전율(Turnover) > 500% 구간 식별.
*   **PASS 조건:** `Rebalance Pinpoint` 툴 정상 실행 AND 로그 파일 생성 확인.

#### C. Sector Exposure Capping (Risk/Regime)
*   **필요성:** Tech/Healthcare 중심 포트폴리오(8~14종목)는 섹터 로테이션 시 MDD가 급격히 확대됨. 특정 섹터 몰빵 방지.
*   **위험:** 주도주 장세(예: AI 랠리)에서 수익률 제한(Capping)으로 인한 Underperformance.
*   **실험 정의:**
    1.  `Exp_Sector_Cap_60`: 단일 섹터(Tech or Health) 비중 합계 최대 60% 제한.
    2.  `Exp_Min_Div_3`: 최소 3개 하위 산업군(Semis, Software, BioPharma, Devices 등) 분산 강제.
*   **PASS 조건:** `worst_mdd` 개선(절댓값 감소) AND `oos_mean` 유지(90% 수준).

### 3. 성능 정체(Stagnation) 시 원인 분해 & 아이디어

성능 지표가 움직이지 않을 경우, 다음 트리를 따라 디버깅하십시오.

*   **[트리거(Trigger) 점검]**
    *   *현상:* 매매 신호 자체가 발생하지 않음.
    *   *확인:* `buy_signal` 조건이 너무 엄격한지(예: RSI < 20 AND Z-score < -3) 확인.
    *   *액션:* 시그널 임계값(Threshold)을 완화하여 거래 횟수(Trade Count) 증가 유도.

*   **[적용(Application) 점검]**
    *   *현상:* 시그널은 있는데 포지션 변경이 미미함.
    *   *확인:* 최적화 함수에서 `turnover_penalty`가 너무 높게 설정되어 기존 포지션을 고수하는지 확인.
    *   *액션:* `turnover_penalty`를 0으로 설정한 실험(`Exp_Zero_Penalty`) 실행.

*   **[노출(Exposure) 점검]**
    *   *현상:* `exposure_max`가 0.83임에도 수익 변동성이 낮음.
    *   *확인:* 선택된 종목들이 저변동성(Low Vol) 종목 위주인지, 혹은 현금 비중이 강제로 높게 유지되는지.
    *   *액션:* `target_exposure`를 1.0(레버리지 없는 Full Investment)으로 강제 설정.

*   **[비용(Cost) 점검]**
    *   *현상:* Gross Return은 좋은데 Net Return이 나쁨.
    *   *확인:* Tech/Bio 소형주의 슬리피지가 과대평가 되었거나 실제 잦은 매매 발생.
    *   *액션:* 거래당 비용(bps) 민감도 테스트 수행 (10bps vs 30bps 차이 확인).

*   **[레짐(Regime) 불일치]**
    *   *현상:* 백테스트 전체 평균은 좋으나 최근 6개월(OOS)이 박살남.
    *   *확인:* 금리 인상기 vs 인하기 로직이 정반대인지 확인.
    *   *액션:* 최근 3년 데이터에 가중치를 두는 `Decay_Window` 방식 적용.
