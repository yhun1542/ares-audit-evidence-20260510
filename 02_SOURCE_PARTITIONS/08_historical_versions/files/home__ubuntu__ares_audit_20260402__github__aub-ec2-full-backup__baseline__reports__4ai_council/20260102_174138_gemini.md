[분석 요약]
현재 시스템은 **신뢰성 위기** 상태임. OOS Mean 3.32는 비정상적으로 높으나, **`worst_mdd: None`**과 **`degenerate_folds: [1, 2, 3, 8]`**는 특정 기간 데이터가 누락되었거나 거래가 전혀 발생하지 않았음을 시사함. 40%의 구간(Fold)이 검증되지 않은 채 평균값이 왜곡되었을 가능성이 매우 높음. 로그 파일 로딩 실패(`Errno 2`)로 인해 실행 내역 확인 불가. 전략 수정보다 **시스템 무결성 복구**가 최우선.

---

### 1. 향후 24~48시간 우선순위 TOP 5

#### P1. 무결성 복구: Degenerate Folds & NaN MDD 해결 (최우선)
- **이유:** 전체 구간의 40%(Fold 1,2,3,8)가 `degenerate`(거래 없음/에러) 상태임. 이 구간을 제외한 나머지 구간의 과적합(Lucky regime)일 확률 99%. `MDD: None`은 리스크 계산 로직 붕괴를 의미.
- **위험:** 복구 시 OOS Mean이 대폭 하락할 수 있음(현실화).
- **실험 계획:**
    1.  **EXP_FIX_DATA_INTEGRITY:** 데이터 로더에서 `NaN`이나 `Zero volume` 캔들 필터링 로직 완화 또는 데이터 소스 재검증.
    2.  **EXP_FORCE_ENTRY:** Degenerate Fold 구간에서 강제 진입 로직(Random Entry)을 구동하여 백테스트 엔진이 도는지 확인.
- **PASS 조건:** `degenerate_folds` 리스트가 빈 배열(`[]`)이 되고, `worst_mdd`가 유효한 음수 값으로 산출될 것.

#### P2. 관측 복구: Rebalance Logger 경로 및 JSON 파싱 수정
- **이유:** `[Errno 2] No such file` 및 JSON 파싱 에러로 실제 매매 내역(Turnover, Cost) 확인 불가. 블라인드 상태.
- **위험:** 로깅 오버헤드로 인한 미세한 속도 저하(무시 가능).
- **실험 계획:**
    1.  **EXP_LOG_FORMAT_FIX:** `aub_rebalance_pinpoint.py`의 JSONL 파싱 로직을 `strict=False`로 변경 및 경로 절대 경로화.
    2.  **EXP_VERBOSE_LOGGING:** 매 리밸런싱 시점의 Target Weight와 Actual Weight의 Delta를 CSV로 별도 저장.
- **PASS 조건:** `rebalance.csv` 파일이 정상 생성되고 `aub_rebalance_pinpoint` 툴이 에러 없이 리포트를 생성할 것.

#### P3. 유니버스 확정: Tech/Healthcare Top-Tier 고정 (US Only)
- **이유:** 현재 전략이 어떤 종목을 거래하는지 명시되지 않음. 유동성이 낮은 잡주가 섞여 수익률이 뻥튀기되었을 가능성 차단.
- **위험:** 유니버스 축소로 인한 분산 효과 감소.
- **실험 계획:**
    1.  **EXP_UNIVERSE_TECH_HEALTH_10:** NVDA, MSFT, AAPL, LLY, UNH, JNJ 등 시총 상위 10-14개 종목으로 유니버스 하드코딩(ETF 제외).
    2.  **EXP_SECTOR_BALANCE:** Tech 50% / Healthcare 50% 비중 제약(Constraint) 추가.
- **PASS 조건:** Exposure Max > 0.6 유지, OOS Mean > 1.0 방어.

#### P4. 비용 현실화: Slippage/Commission Stress Test
- **이유:** OOS Mean 3.32는 비용 미반영일 가능성 농후.
- **위험:** 성과 지표 급락. 그러나 이는 '버그'가 아니라 '현실'임.
- **실험 계획:**
    1.  **EXP_COST_BP_10:** 편도 거래비용 10bp(0.1%) 강제 적용.
    2.  **EXP_COST_BP_20:** 편도 거래비용 20bp(0.2%) 강제 적용.
- **PASS 조건:** OOS Mean > 1.5 유지 시 실전 투입 가능성 높음.

#### P5. 과최적화 방지: Parameter Stability Check
- **이유:** 현재 챔피언 모델이 특정 파라미터(예: Lookback window)에 너무 민감한지 확인.
- **위험:** 최적 파라미터 이탈 시 성능 저하 확인.
- **실험 계획:**
    1.  **EXP_PARAM_NOISE:** 주요 파라미터(윈도우 사이즈 등)에 ±10% 노이즈 추가 후 5회 반복 실행.
- **PASS 조건:** 5회 실행의 OOS Mean 표준편차가 평균의 20% 이내일 것.

### 2. 48시간 자동 루프 정의 (실행 가능한 Patch)

#### Loop 1: 시스템 정상화 (Debug Mode)
1.  **실험 정의:** `Patch_Fix_Degenerate_Folds`
    - Fold 1,2,3,8 기간의 데이터 무결성 체크 루틴 추가.
    - 최소 거래 대금(min_dollar_volume) 필터 일시적 해제.
2.  **게이트(Gate):**
    - `len(degenerate_folds) == 0`
    - `worst_mdd is not None`
3.  **기대 관측치:**
    - OOS Mean은 3.32에서 1.5~2.0 수준으로 하락 예상(정상화 과정).
    - MDD는 -0.1 ~ -0.3 수준으로 잡혀야 함.

#### Loop 2: 섹터 집중 및 로깅 (Strategy Alignment)
1.  **실험 정의:** `Patch_Universe_TechHealth_Only`
    - 유니버스 필터: `Sector in ['Technology', 'Healthcare']` AND `MarketCap > 50B` (ETF 제외).
    - 종목 수: 10개 내외 유지.
    - Logger Fix 적용.
2.  **게이트(Gate):**
    - `exposure_max <= 0.95` (레버리지 금지)
    - `rebalance_log_exists == True`
3.  **기대 관측치:**
    - 변동성 감소(대형주 위주).
    - 샤프 비율(Sharpe) 유지 여부 관측.

#### Loop 3: 비용 스트레스 테스트 (Robustness)
1.  **실험 정의:** `Patch_Cost_20bp`
    - `sim_params['commission'] = 0.001` (10bp)
    - `sim_params['slippage'] = 0.001` (10bp)
2.  **게이트(Gate):**
    - `OOS_Mean > 1.0` (비용 차감 후에도 수익이 나는가?)
3.  **기대 관측치:**
    - 회전율(Turnover)이 높은 로직이라면 성능 급락 예상 -> 회전율 제어 로직 필요성 도출.

### 3. 성능 정체 시 원인 분해 아이디어 (Debug Checklist)

성능이 움직이지 않거나(Flat), 개선되지 않을 때 다음 순서로 점검:

1.  **트리거(Trigger) 부재:**
    - *현상:* 시그널이 0으로 유지됨.
    - *점검:* 지표(Indicator) 값이 `NaN`인지, 임계값(Threshold)이 너무 높아 도달하지 않는지 확인. (예: RSI > 99 조건 등)
2.  **노출(Exposure) 제한:**
    - *현상:* 시그널은 뜨는데 포지션이 안 잡힘.
    - *점검:* `risk_budget`이나 `max_position_size` 제약이 너무 타이트한지, 혹은 현금 보유 성향(Risk-free rate 선호)이 강하게 설정되었는지 확인.
3.  **실행(Execution) 비용:**
    - *현상:* Gross Profit은 좋은데 Net Profit이 나쁨.
    - *점검:* 잦은 리밸런싱(Whipsaw). `turnover` 수치를 확인하고 진입/청산 밴드(Hysteresis) 도입 필요.
4.  **레짐(Regime) 불일치:**
    - *현상:* 특정 연도만 수익이 좋고 나머지는 손실.
    - *점검:* 현재 `degenerate_folds` 문제와 직결. 특정 시장 상황(Bull/Bear)에서만 작동하는 로직인지 확인 (베타 의존도 체크).
5.  **데이터(Data) 오류:**
    - *현상:* 가격 데이터 스파이크나 분할(Split) 미반영.
    - *점검:* 수익률이 비정상적으로 튀는 날짜의 Raw Data 전수 조사.
