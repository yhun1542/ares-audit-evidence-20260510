## 📋 PRIORITY #1: Degenerate Folds 복구

### 왜 필요한가
- 10개 fold 중 4개(40%) 실패 → OOS 신뢰도 붕괴
- oos_min=-2.57% 음수 존재 → 특정 fold에서 손실 발생
- 서바이버십 바이어스: 성공 fold만으로 평균 계산 시 과최적화

### 위험/부작용
- 제약 완화 시 과적합 위험 증가
- 반대로 제약 강화 시 전체 exposure 급감

### 실험 체크리스트

```yaml
EXP-1A: fold_constraint_relax
  정의: degenerate 판정 기준을 exposure_min=0.05 → 0.02로 완화
  게이트: 
    - degenerate_folds ≤ 2
    - oos_mean ≥ 2.5
  기대치: fold 1,2,3,8 중 최소 2개 복구
  
EXP-1B: universe_filter_regime
  정의: 2020-2022 기간(fold 1-3) regime 필터 추가 (VIX>30 시 50% exposure cap)
  게이트:
    - fold [1,2,3] 중 ≥2개 non-degenerate
    - 전체 oos_mean 하락폭 < 15%
  기대치: 코로나 급등락 구간 생존율 개선

EXP-1C: min_holding_period_extend  
  정의: 최소 보유기간 3일 → 5일 (초단기 whipsaw 방지)
  게이트:
    - 거래비용 20% 이상 감소
    - oos_min > -1.5%
  기대치: fold 8(최근 구간) 안정화
```

## 📋 PRIORITY #3: MDD 계산 및 리스크 게이트 추가

### 왜 필요한가
- `worst_mdd = None` → 리스크 미측정 상태로 실전 배포 불가
- 과최적화 탐지 불가능

### 위험/부작용
- MDD 게이트 추가 시 후보 탈락률 증가

### 실험 체크리스트

```yaml
EXP-3A: mdd_calculator_inject
  정의: fold별 MDD 계산 로직 추가, worst_mdd 필드 채움
  게이트:
    - worst_mdd 필드 non-null
    - worst_mdd < 15% (절대값)
  기대치: 리스크 정량화

EXP-3B: mdd_gate_enforcement
  정의: champion 승격 조건에 mdd < 12% 추가
  게이트:
    - 과거 champion 중 MDD>15% 탈락률 확인
  기대치: 테일 리스크 필터링
```

## 📋 PRIORITY #4: Exposure 분포 정규화

### 왜 필요한가
- exposure_min=0.0 / max=0.84 → 극단적 변동
- 0% 구간 = 시장 참여 안 함 → 기회비용 미반영

### 위험/부작용
- floor 강제 시 불리한 시장에서도 포지션 유지 → 손실 증가 가능

### 실험 체크리스트

```yaml
EXP-4A: exposure_floor_10pct
  정의: 최소 exposure 10% 강제 (현금비중 cap 90%)
  게이트:
    - exposure_min ≥ 0.10
    - oos_mean 하락폭 < 20%
  기대치: degenerate fold 감소

EXP-4B: exposure_smoothing
  정의: 일일 exposure 변동폭 ±15% 제한
  게이트:
    - exposure 일변동 표준편차 50% 감소
  기대치: 거래비용 절감 + 안정성
```

EXP-5A: explicit_cost_model

EXP-5B: turnover_penalty

    - 고회전 전략 자동 탈락
