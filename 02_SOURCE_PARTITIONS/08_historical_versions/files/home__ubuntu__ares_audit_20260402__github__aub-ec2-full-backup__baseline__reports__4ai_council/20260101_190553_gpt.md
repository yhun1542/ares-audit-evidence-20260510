## 0) 최우선 리스크 점검(누수/과최적화/서바이버십/비용/운영) — 즉시 실행 체크리스트
- [ ] **(Leakage)** 피처/라벨/체결시점 정렬을 “as-of(시점고정)”로 강제하고, `t` 정보로 `t` 체결이 불가능하도록 전 구간 검증
- [ ] **(Overfit)** 튜닝 성능 개선이 lockbox에 동행하는지, “하이퍼파라미터/특징 수 증가 → lockbox 악화” 패턴 차단
- [ ] **(Survivorship)** 유니버스(Tech+Healthcare 8~14) 구성에 **상장폐지/합병/티커 변경**이 반영되는지(포인트-인-타임) 확인
- [ ] **(Costs)** 수수료/슬리피지/스프레드/부분체결/거래가능성(유동성) 비용을 net에 반영하고, turnover 폭주 방지
- [ ] **(Ops)** 48시간 무인 루프에서 데이터 신선도/장시간/장전/휴장/주문실패/리밸 실패 시 “안전모드”로 자동 전환

## 1) 다음 24~48시간 TOP5 우선순위(코드/아키텍처/전략)
아래 5개 “제안”은 **서로 다른 5개의 신규 실험을 만들지 않도록**, **공유되는 5개 Patch/실험(=E1~E5)** 안에서만 반복 검증하도록 설계함.

### TOP1) 누수(Leakage)·시점정렬(As-of) 하드닝
- 목적: lockbox가 좋아도 실제 운용에서 붕괴하는 1순위 원인 제거

### TOP2) 비용/슬리피지/회전율(turnover) net 성능 강제
- 목적: gross 알파를 net에서 실현 가능한 알파로 바꾸기

### TOP3) 서바이버십/상폐/코퍼레이트액션 포함한 포인트-인-타임 유니버스
- 목적: “백테스트만 이기는” 환상 제거, 진짜 재현성 확보

### TOP4) 레짐(시장 국면) 게이팅: ETF는 관측지표로만 사용
- 목적: worst MDD/하방 꼬리 리스크를 줄이되, 과최적화는 피하기

### TOP5) 운영 리스크(데이터/주문/실패복구) 자동 안전장치
- 목적: 무인 48시간 루프에서 “한 번의 장애로 계좌가 죽는” 사건 방지

## 2) 실행 가능한 Patch/실험(총 5개, 48시간 자동 루프용)  
각 제안별 (a)(b)(c)(d)는 **아래 E1~E5를 재사용**해서 충족함(케이스 폭발 방지).

---

# E1) Leakage/정렬 감사 패치 (TOP1 중심)
### (1) 실험 정의
- [PATCH] 모든 피처 생성/머지에 **as-of merge** 규칙 적용(“미래 값이 과거로 들어오면 즉시 에러”)
- [PATCH] 매매 의사결정 시점과 체결 시점을 분리(예: `t`에서 신호 → `t+1` 오픈/혹은 `t+1` VWAP에 체결)
- [TEST] “의도적 지연(shift +1bar/+1day)” A/B backtest로 누수 민감도 측정

### (2) 게이트(실패 시 즉시 중단)
- [GATE] shift(+1) 적용 시 성능이 **비정상적으로 붕괴**하거나, 반대로 **거의 동일**하면(둘 다 의심) 원인 로그를 남기고 해당 모듈 FAIL
- [GATE] 데이터 머지에서 **미래 타임스탬프 유입 0건**(검출 시 즉시 FAIL)

### (3) 기대 관측치
- 정상이라면: shift(+1)에서 성능 **일부 하락**은 있으나, lockbox가 “0 근처로 붕괴”하지는 않음  
- 비정상이라면: shift(+1)에서 lockbox_mean 급락 / 트레이드 타이밍이 현실적으로 불가능한 패턴 노출

### (d) PASS 조건(현 상태 기준, 실무형)
- [PASS] 누수 검출 0건 + shift(+1)에서도 **lockbox_mean이 극단적으로 붕괴하지 않음**(예: 기존 대비 -30% 이내 하락 수준을 목표; 더 나쁘면 원인 규명 전까지 병합 금지)
- [PASS] worst_mdd가 “누수 제거 후” 비정상적으로 악화되지 않을 것(악화 시, 기존 알파가 누수였을 가능성 높음)

### 제안별 매핑
- TOP1: E1의 직접 대상  
- TOP2~TOP4도 **E1 통과 전까지 의미 없음**(선행 게이트)

---

# E2) 비용/슬리피지/회전율 net 강제 패치 (TOP2 중심)
### (1) 실험 정의
- [PATCH] 거래비용 모델 고정(최소 구성):  
  - 수수료(브로커 기준) + 고정 슬리피지(bps) + 스프레드(일중 대용치)  
  - 부분체결/유동성 제한(일 거래대금 대비 포지션 상한)
- [PATCH] 목적함수/선택 기준을 **gross → net** 중심으로 변경 + turnover 패널티(혹은 리밸 빈도 제한)
- [TEST] “비용 0 / 기본 / 2배” 3단 스트레스

### (2) 게이트
- [GATE] 비용 2배에서도 성능이 완전히 붕괴하면(특히 lockbox) **거래가 너무 잦거나 마진이 얇은 구조** → FAIL
- [GATE] 평균 turnover/일 거래횟수 상한 초과 시 FAIL(운영/슬리피지 리스크로 간주)

### (3) 기대 관측치
- net-gross 간 격차가 줄고, worst_mdd가 완만해지며, lockbox의 min이 개선되는 방향 기대

### (d) PASS 조건
- [PASS] net 기준 lockbox_mean이 champion 대비 **유의미 개선**(예: +0.05 이상) 또는 최소한 lockbox_min이 더 안정적(꼬리 개선)
- [PASS] worst_mdd가 악화되지 않음(목표: 현 worst_mdd -0.09 대비 개선 방향 유지)

### 제안별 매핑
- TOP2: E2 직접 대상  
- TOP4(레짐 게이팅)도 E2 비용 하에서만 “진짜 개선”으로 인정

---

# E3) 포인트-인-타임 유니버스/서바이버십 제거 패치 (TOP3 중심)
### (1) 실험 정의
- [PATCH] 유니버스 생성 로직을 “현재 티커 목록”이 아니라 **당시 존재했던 종목만** 포함하도록 변경  
  - 상폐/합병/티커변경/거래정지 이벤트 처리  
  - 조정주가/배당/분할 코퍼레이트액션 일관성 검증
- [TEST] “상폐 포함/제외” A/B + “랜덤 종목 드랍(결측)” 내성 테스트

### (2) 게이트
- [GATE] 상폐 포함 시 성능이 급락하면 기존 성능이 서바이버십 의존일 가능성 → FAIL(원인 리포트 생성 전까지 채택 금지)
- [GATE] 결측/티커변경 이벤트에서 포지션이 비정상 점프하면 FAIL

### (3) 기대 관측치
- 성능은 일부 내려갈 수 있으나, lockbox와 worst_mdd가 더 “진짜”에 가까워지고 운영 안정성이 증가

### (d) PASS 조건
- [PASS] 포인트-인-타임 적용 후에도 lockbox_mean이 **0 이상을 안정적으로 유지** + worst_mdd가 통제 범위 내  
- [PASS] 이벤트(상폐/변경) 처리 로그 “미처리 0건”

### 제안별 매핑
- TOP3: E3 직접 대상  
- TOP5(운영)에도 강하게 연결(실데이터에서 가장 자주 터지는 부분)

---

# E4) 레짐 게이팅(ETF 관측지표만) 패치 (TOP4 중심)
> **ETF는 매매 제외**, 관측 지표로만 사용. (예: XLK, XLV, IBB, VGT, VHT 등)

### (1) 실험 정의
- [PATCH] 레짐 스코어 생성(단순·저자유도):  
  - 예: (XLK/XLV 추세) + (SPY 변동성 대용) + (장단기 금리 대용)  
- [PATCH] 레짐에 따라 **노출만 조절**:  
  - risk-off에서 포지션 수 축소/현금 비중 증가/리밸 빈도 완화
- [TEST] “게이팅 OFF/ON” + “임계값 2~3개” 소수만 비교(과최적화 방지)

### (2) 게이트
- [GATE] 게이팅 ON이 tuning만 개선하고 lockbox에서 악화되면 FAIL(레짐 과최적화로 간주)
- [GATE] 노출 급변(하루에 0→100%) 빈번하면 FAIL(운영/비용 리스크)

### (3) 기대 관측치
- fold14_mdd 및 worst_mdd 개선, lockbox_min이 올라가는 방향(꼬리 리스크 완화)

### (d) PASS 조건
- [PASS] worst_mdd가 의미 있게 개선(예: -0.09 → -0.07 이하 방향)하면서 lockbox_mean 유지/개선
- [PASS] 레짐 분기별 성과 편차가 줄어듦(특정 국면 “몰빵” 감소)

### 제안별 매핑
- TOP4: E4 직접 대상  
- TOP2 비용 모델(E2) 하에서만 최종 판단

---

# E5) 48시간 무인 운용 안전장치/실패복구 패치 (TOP5 중심)
### (1) 실험 정의
- [PATCH] 데이터 신선도/완결성 체크(장 시작 전/중/후): stale이면 **거래 금지**
- [PATCH] 주문 라우팅 실패/부분체결/거래정지 시 **안전모드**(포지션 동결, 다음 사이클로 이월)
- [TEST] “장애 주입(fault injection)” 48시간 페이퍼런:  
  - 데이터 1회 누락, API 타임아웃, 가격 0/NaN, 휴장일, 심볼 변경 등

### (2) 게이트
- [GATE] 거래 전 검증 실패인데도 주문이 나가면 FAIL
- [GATE] 장애 후 재시도 루프가 무한 반복/중복주문이면 FAIL

### (3) 기대 관측치
- 실패가 나도 계좌/포지션이 보수적으로 유지되고, 다음 사이클에서 정상 복구

### (d) PASS 조건
- [PASS] 48시간 페이퍼런에서 “주문 전 검증 위반 0건”, “중복주문 0건”, “stale 데이터 거래 0건”
- [PASS] 장애 발생 시에도 프로세스가 자동 복구하고 다음 사이클 정상 수행

### 제안별 매핑
- TOP5 직접 대상(성능이 아니라 “생존성” PASS가 목표)

## 3) TOP5 제안별 (a)(b)(c)(d) 요약 매핑(명령형)
### 제안 TOP1 누수/정렬
- (a) 필요: lockbox 개선이 “실거래 불가능한 정보”일 수 있음  
- (b) 위험: 누수 제거 후 성능 하락(진짜 성능으로 수렴)  
- (c) 실험: **E1**(shift A/B, as-of 강제, 체결시점 분리)  
- (d) PASS: **E1 PASS**

### 제안 TOP2 비용/turnover net 강제
- (a) 필요: Tech/Healthcare 8~14 종목은 회전이 높으면 슬리피지가 전부 먹음  
- (b) 위험: 과도한 패널티로 알파 자체 소거  
- (c) 실험: **E2**(비용 0/1/2배), + 결과는 **E1 통과 후**만 인정  
- (d) PASS: **E2 PASS**

### 제안 TOP3 서바이버십 제거
- (a) 필요: “살아남은 대형주만”이면 백테스트 착시  
- (b) 위험: 데이터 소스/정합성 비용 증가, 성능 하락  
- (c) 실험: **E3**(상폐 포함 A/B, 결측 내성)  
- (d) PASS: **E3 PASS**

### 제안 TOP4 레짐 게이팅(ETF 관측)
- (a) 필요: worst_mdd 꼬리 리스크를 구조적으로 줄이는 레버  
- (b) 위험: 임계값 튜닝으로 lockbox 훼손(과최적화)  
- (c) 실험: **E4**(게이팅 OFF/ON, 임계값 소수), 단 **E2 비용 포함**에서 평가  
- (d) PASS: **E4 PASS**

### 제안 TOP5 운영 안전장치
- (a) 필요: 48시간 무인 루프에서 단 1회 장애가 치명상  
- (b) 위험: 보수적 안전모드로 거래 기회 일부 상실  
- (c) 실험: **E5**(fault injection 48h 페이퍼런)  
- (d) PASS: **E5 PASS**

## 4) “성능이 안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐) — 트리 형태 체크리스트
아래는 **한 번에 하나씩만** 고장 지점을 찾도록 분해한 진단 루틴.

### A. 트리거(신호 생성) 문제
- [ ] 신호 발생 빈도(트리거 수)가 과도하게 낮아졌는지(시장 변화/필터 과도)
- [ ] 피처 분포 드리프트(특히 변동성/거래대금/갭)로 모델 입력이 “학습범위 밖”인지
- [ ] 레이블 정의(예: 다음날 수익)와 체결 방식(오픈/클로즈/VWAP)이 불일치하는지

### B. 적용(포지션 구성/리밸) 문제
- [ ] 포지션 상한/하한/정규화 로직이 노출을 눌러서 “항상 비슷한 포트”가 되는지
- [ ] 리밸 빈도가 너무 잦아 net이 죽는지(특히 8~14 집중 포트)
- [ ] 결측/정지/티커변경 시 대체 로직이 의도와 다르게 작동하는지

### C. 노출(Exposure) 문제
- [ ] 섹터 내부 상관 급등 시(Tech 동조화 등) 실질 분산이 사라져 MDD가 커지는지
- [ ] 베타/금리민감/퀄리티 팩터 노출이 특정 방향으로 고정됐는지(원치 않는 팩터 베팅)

### D. 비용(Cost) 문제
- [ ] gross는 좋은데 net이 안 움직이면: **turnover/체결단가/스프레드**가 원인  
- [ ] 거래대금 대비 주문 크기 과대(시장충격) 여부
- [ ] 리밋/마켓 주문 가정이 백테스트와 불일치(실거래에서 미체결 누적)

### E. 레짐(Regime) 문제
- [ ] risk-on에서는 잘 되나 risk-off에서만 깨지는지(국면별 성과 분해)
- [ ] 변동성 급등 구간에서만 손실이 집중되는지(꼬리 구간 태깅)
- [ ] XLK/XLV 같은 관측지표와 성과의 조건부 상관이 있는지(단, ETF 매매 금지)

## 5) 48시간 자동 루프에 바로 얹는 실행 순서(명령형)
- [ ] **Step 1 (선행 게이트): E1 누수/정렬**부터 통과시켜 “성능 숫자의 의미”를 확정
- [ ] **Step 2: E2 비용/turnover**로 net을 고정(이후 실험은 전부 net 기준)
- [ ] **Step 3: E3 서바이버십**으로 재현성 확보(여기서 흔들리면 전략/데이터 재설계)
- [ ] **Step 4: E4 레짐 게이팅**은 소수 설정만 비교(과최적화 방지)
- [ ] **Step 5: E5 운영 안전장치**는 성능과 무관하게 병행(“살아남는 시스템” 우선)

(사용 중인 오토파일럿 커맨드는 현재 HANDOFF의 3줄을 유지하되, 위 E1~E5 패치를 브랜치로 분리해 **각각 하나의 후보(candidate)로만** 올려서 `--select-best`가 lockbox 기준으로 고르도록 제한하는 방식이 48시간 루프에 맞음.)
