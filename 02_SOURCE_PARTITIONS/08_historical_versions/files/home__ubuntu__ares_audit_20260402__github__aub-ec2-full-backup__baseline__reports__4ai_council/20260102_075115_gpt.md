아래는 **다음 24~48시간 자동 루프(48h loop)**에 바로 넣을 수 있는 **TOP5 우선순위(코드/아키텍처/전략)**와, 이를 **총 5개 실험(E1~E5)**로 커버하는 형태의 **명령형 체크리스트**다. (미국주식 only, **Tech+Healthcare 중심 8~14종목**, ETF는 **관측지표만** 사용)

## 0) 48h 루프에 넣을 “공통 실험 세트” (E1~E5, 총 5개만 실행)

### E1. 누수(lookahead) 차단: Purged/Embargoed Walk-forward + Feature As-Of 강제
1) **실험 정의**
- 모든 피처/라벨을 “as-of timestamp” 기준으로 재정렬하고, **거래 의사결정 시점 T에서 접근 가능한 정보만** 남기도록 강제.
- CV를 **purge(라벨 윈도우만큼 gap 제거) + embargo(추가 완충 구간)** 적용한 walk-forward로 교체.
- 간이 누수 탐지로 **feature 1-bar shift(+1일 지연)** 버전을 함께 돌려 성능 급락 여부 확인.
2) **게이트(실행 차단/보류 조건)**
- shift(+1)에서 성능이 **비정상적으로 유지/상승**하면 누수 의심 → 즉시 병합 금지.
- purge/embargo 적용 후 fold 중 **degenerate fold** 발생 시(학습 불가/표본 부족) → 윈도우 재설계 전까지 stop.
3) **기대 관측치**
- 정상이라면: 평균은 소폭 하락 가능하나 **oos_min 개선** 또는 fold 분산 감소.
- 누수였다면: purge/shift에서 **oos_mean 급락** + 특정 피처 기여도 붕괴.

---

### E2. 서바이버십/유니버스 편향 제거: “As-Of Universe” 리플레이
1) **실험 정의**
- 현재 시점 종목 리스트가 아니라, 각 시점에 실제 존재/상장/거래 가능했던 **historical universe(포인트-인-타임)**로 리플레이.
- Tech+Healthcare 중심 유지하되, “현재 살아남은 대형주만” 편향이 없도록 **당시 시가총액/거래대금 필터**로 구성.
2) **게이트**
- 유니버스 생성에 미래 정보가 섞이면(예: 현재 S&P 구성 사용) → 즉시 중단.
- delisting/merger 처리 미정이면 → 해당 기간 제외 or 이벤트 처리 로직 없이는 배포 금지.
3) **기대 관측치**
- 정상이라면: 평균은 약간 하락할 수 있으나 **oos_min/안정성**이 더 현실적으로 변함.
- 편향이 컸다면: 성능이 크게 꺾이고, 특정 메가캡 의존도가 드러남.

---

### E3. 비용/슬리피지/유동성 현실화: Cost Stress Test (bps/ADV 기반)
1) **실험 정의**
- 거래비용을 “0bps / 10bps / 25bps” 3단 스트레스 레벨로 고정 비교.
- 슬리피지는 최소 **half-spread + impact(포지션/ADV 비율, 변동성 기반)** 근사치를 넣고, 리밸런싱 회전율(turnover)도 기록.
2) **게이트**
- 비용 10bps만 넣어도 oos가 붕괴하면(예: oos_mean 급락 + oos_min 바닥) → **모델이 엣지보다 회전율**로 먹고 있었던 것 → 구조 수정 없이는 stop.
- 체결 가능한 유동성 제약(예: 일 거래대금 대비 주문비율 상한) 위반 시 → 해당 종목/사이징 규칙 없이는 배포 금지.
3) **기대 관측치**
- 정상이라면: 비용 증가에 따라 성능이 **단조 감소**하지만, 10bps에서는 여전히 플러스/안정.
- 문제라면: “거래가 늘수록 좋아지는” 비현실 패턴(사실상 누수/과최적화/비용 미반영) 노출.

---

### E4. 노출(Exposure)/집중/레짐 리스크 제어: 8~14종목, 섹터 바스켓 + ETF 관측 게이트
1) **실험 정의**
- 포트폴리오 규칙을 하드하게 고정:
  - 종목수: **8~14**
  - 섹터: **Tech+Healthcare 합산 비중 하한**(예: ≥70%) + 단일종목 상한(예: ≤15%)
  - 총 노출(exposure): 목표 밴드(예: 0.35~0.80)로 클램프
- ETF는 매매 금지, **관측지표만**:
  - 예: **QQQ 추세(200D 위/아래)**, **XLV 상대강도(XLV/QQQ)**, **SPY 변동성/드로우다운 상태**
- 관측지표가 risk-off면 **사이징 감축/현금 비중 증가**만 수행(종목선정 로직 자체는 유지).
2) **게이트**
- 게이트가 “항상 risk-on” 또는 “항상 risk-off”로 고착되면 → 지표 설계 실패 → stop.
- 노출 클램프 후에도 oos_min이 악화되면 → 엣지가 “고베타 레버리지”였을 가능성 → stop.
3) **기대 관측치**
- 정상이라면: oos_mean은 비슷하거나 소폭 하락해도 **oos_min 개선**, tail risk 감소, 노출 안정화.

---

### E5. 운영 리스크 차단: 재현성/데이터 드리프트/자동 롤백 canary
1) **실험 정의**
- 매 48h 루프에 “canary run” 포함:
  - 동일 데이터 스냅샷으로 **두 번 실행 시 결과 해시/지표 동일**(완전 결정성) 확인
  - 결측/이상치 급증, 수정주가 갱신 폭발, 분할/합병 이벤트 급증을 **드리프트 지표**로 감시
  - 성능/리스크 지표가 기준 이탈 시 **자동으로 이전 champion 유지(롤백)** + 신규는 격리
2) **게이트**
- 재현성 실패(동일 입력인데 결과 다름) → 그 어떤 신규 전략도 승격 금지.
- 데이터 결측/수정주가 재작성(리라이트) 감지 시 → 해당 날짜 재학습/재평가 전까지 배포 금지.
3) **기대 관측치**
- 정상이라면: run_hash는 달라도 결과 지표가 동일(또는 허용 오차 내), 드리프트 알람은 낮음.
- 문제라면: “어느 날 갑자기 좋아짐/나빠짐”이 데이터/파이프라인 변경 탓으로 분해됨.

## 1) TOP5 우선순위 제안 (각 항목별: 왜/위험/최소 실험/ PASS)

### P1) **누수/과최적화 최우선 제거(가장 먼저)**
- (a) 왜 필요한지  
  현재 champion의 oos_mean이 높은 편(1.88)일수록, **시간정렬/라벨 윈도우/리밸런스 타이밍 누수**가 있으면 “가짜 엣지”일 확률이 커짐. 48h 자동 루프에서는 누수가 있으면 계속 잘못된 방향으로 강화됨.
- (b) 위험/부작용  
  purge/embargo/shift로 인해 성능이 떨어져 보일 수 있음(정상). 단기적으로 “퇴보”처럼 보이는 게 가장 큰 함정.
- (c) 최소 실험(공통 실험 참조, 2~3개만)  
  - **E1**(purge/embargo + feature as-of + 1-bar shift)  
  - **E2**(as-of universe 리플레이)
- (d) PASS 조건(명령형)  
  - purge/embargo 적용 후에도 **oos_min이 악화되지 않거나 개선**될 것  
  - 1-bar shift에서 성능이 **유의미하게 하락**할 것(정상)  
  - 특정 fold만 과도하게 좋지 않을 것(fold 분산 제한)

---

### P2) **비용 미반영 제거(실거래 가능성 확보)**
- (a) 왜 필요한지  
  Tech/Healthcare라도 8~14종목을 자주 갈아타면, **슬리피지/스프레드/임팩트**가 엣지를 먹어버림. 비용을 나중에 넣으면 “운영 들어가서만 죽는 전략”이 됨.
- (b) 위험/부작용  
  비용 모델이 과보수면 좋은 전략까지 죽일 수 있음. 하지만 48h 루프에서는 “낙관 비용”이 더 치명적.
- (c) 최소 실험  
  - **E3**(0/10/25bps + ADV impact)  
  - **E5**(비용/체결 관련 로그/지표 재현성 포함)
- (d) PASS 조건  
  - 10bps 비용에서 **oos_mean이 플러스 유지** + 성능이 비용 증가에 따라 **단조 감소**할 것  
  - turnover 상한(예: 일평균 30~60% 등 내부 기준) 위반 시 자동 fail

---

### P3) **서바이버십/유니버스 편향 제거(특정 메가캡 의존도 제거)**
- (a) 왜 필요한지  
  Tech/Healthcare는 장기 승자(메가캡) 편향이 크고, 현재 구성 종목으로만 백테스트하면 **서바이버십 바이어스**로 oos가 과대평가됨.
- (b) 위험/부작용  
  historical universe 구축 비용/복잡도가 늘고, 단기 성능 지표가 꺾일 수 있음.
- (c) 최소 실험  
  - **E2**(as-of universe)  
  - **E1**(purge/embargo로 함께 안정성 확인)
- (d) PASS 조건  
  - as-of universe에서도 전략이 “완전 붕괴”하지 않을 것(예: oos_min이 바닥으로 가지 않을 것)  
  - 성과가 특정 1~2종목 기여에 과도하게 집중되지 않을 것(기여도 상한)

---

### P4) **노출/레짐/테일리스크를 규칙으로 고정(운영 안정성)**
- (a) 왜 필요한지  
  현재 노출이 0.47~0.84로 상단이 높고, worst_mdd가 None인 상태는 **계산/기록 누락 가능성**도 시사. 48h 자동에서는 “한 번의 레짐 전환”이 계좌를 훼손할 수 있음.
- (b) 위험/부작용  
  게이트/클램프가 성능 상단을 깎을 수 있음. 하지만 oos_min을 끌어올리는 게 우선.
- (c) 최소 실험  
  - **E4**(8~14종목, 섹터/단일종목/총노출 클램프 + ETF 관측 게이트)  
  - **E3**(클램프 후 turnover/비용 재평가)
- (d) PASS 조건  
  - worst_mdd가 **항상 계산/로깅**될 것(None 금지)  
  - oos_min이 현 수준(0.43) 대비 **상향/안정**  
  - 노출 밴드 위반 “0회” 또는 자동 클램프 적용 기록이 남을 것

---

### P5) **운영 리스크(재현성/드리프트/롤백) 먼저 잠그기**
- (a) 왜 필요한지  
  자동 루프에서 가장 흔한 실패는 “전략이 나빠서”가 아니라 **데이터 갱신/수정주가 리라이트/결측/랜덤성**이다. 한 번의 비결정성은 모든 비교를 무의미하게 만든다.
- (b) 위험/부작용  
  초기에는 fail이 자주 떠서 배포가 느려질 수 있음(정상). 대신 장기적으로 디버깅 비용이 급감.
- (c) 최소 실험  
  - **E5**(canary + 재현성 + 드리프트 + 자동 롤백)  
  - **E2**(corporate action/delisting 이벤트 감지 강화에 도움)
- (d) PASS 조건  
  - 동일 스냅샷 재실행 결과 지표 **동일(허용오차 내)**  
  - 데이터 드리프트 알람 시 **자동으로 champion 유지**  
  - 결측/수정주가 급변 시 거래/학습 자동 중지(킬스위치)

## 2) 성능이 안 움직일 때: 원인 분해 아이디어(트리거/적용/노출/비용/레짐) “명령형 트리”

아래 순서대로 **한 단계씩만** 고정/검증해서 원인을 격리하라(동시에 여러 개 바꾸지 말 것).

### A. 트리거(신호) 자체 문제인지
- **신호 분포 드리프트**를 기록하라(평균/표준편차/상관/상위-하위 스프레드).
- 상위/하위 디사일(또는 랭크) **다음기간 수익 스프레드**가 0에 수렴했는지 확인하라.
- 특정 피처/모델이 최근 구간에서만 먹는지(기간별 IC/스프레드) 분해하라.  
→ 트리거가 죽었으면: 레짐/시장 구조 변화 또는 누수 제거 후 “진짜 엣지 없음”.

### B. 적용(리밸런싱/지연/체결) 문제인지
- 신호 시점 T, 주문 생성 T, 체결 T+? 를 명시하고 **지연(latency) 시뮬레이션**을 붙여라.
- 리밸런싱 주기를 고정한 뒤(예: 1D vs 5D) 성능 변화를 보라.  
→ 적용이 문제면: 신호는 좋은데 체결/지연/리밸 주기에서 엣지가 소실.

### C. 노출(사이징/집중) 문제인지
- 성과를 **베타/섹터/단일종목 기여도**로 분해하라.
- “상위 1~2종목 제거 후” 성능을 다시 계산하라(leave-one-out).  
→ 노출이 문제면: 엣지가 아니라 **집중/레버리지**가 수익의 대부분.

### D. 비용(슬리피지/스프레드/임팩트) 문제인지
- 총 수익을 **gross → cost 분해**로 매일 기록하라.
- turnover가 성능과 양(+)의 상관이면 비용 미반영/과최적화 가능성을 우선 의심하라.  
→ 비용이 문제면: 10bps에서도 급락, 또는 임팩트 모델에서만 붕괴.

### E. 레짐(시장 국면) 문제인지
- 관측지표(ETF)로 상태를 나누고(예: QQQ 추세 상/하, XLV/QQQ 상대강도 상/하) 각 레짐별 성과를 표로 쪼개라.
- 레짐별로 “같은 신호가 반대로 작동”하는지 확인하라.  
→ 레짐이 문제면: 전체 평균은 비슷한데 **oos_min이 레짐 전환에서 깨짐**.

## 3) 지금 당장 실행 순서(24~48h) — 명령형 체크리스트
1) **E5부터 넣어라**: 재현성/스냅샷/롤백 canary 없으면 이후 모든 비교를 중단하라.  
2) **E1 수행하라**: purge/embargo + as-of + 1-bar shift로 누수부터 제거하라.  
3) **E3 수행하라**: 0/10/25bps 비용 스트레스에서 무너지는지 확인하라.  
4) **E2 수행하라**: as-of universe로 서바이버십 편향을 제거하라.  
5) **E4 수행하라**: 8~14종목/노출 밴드/ETF 관측 게이트로 oos_min을 끌어올려라.

이 5개(E1~E5)만으로, 요청한 우선순위 5개를 **케이스 폭발 없이** 48시간 자동 루프에 태울 수 있다.
