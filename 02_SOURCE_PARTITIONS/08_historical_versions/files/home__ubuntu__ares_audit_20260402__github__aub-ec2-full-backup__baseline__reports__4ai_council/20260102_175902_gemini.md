[우선순위 제안 요약]
현재 `oos_mean`이 3.32로 비정상적으로 높으나, `degenerate_folds`가 4개(약 40%) 발생했습니다. 이는 **특정 구간 과최적화(Overfitting)** 또는 **미래 참조(Look-ahead Bias)** 가능성이 매우 높으며, 나머지 구간에서는 거래가 아예 안 일어나는(Cash 100%) **'All or Nothing'** 상태입니다. 또한 `rebalance.csv` 로드 에러는 실험 피드백 루프가 끊겨 있음을 의미합니다.

---

### Priority 1. 퇴화 폴드(Degenerate Folds) 강제 활성화 및 제약 완화
**a) 필요성:** 1, 2, 3, 8번 폴드에서 거래가 없거나 모델이 붕괴됨. 이를 해결하지 않으면 OOS Mean 3.32는 허수임.
**b) 위험/부작용:** 강제로 거래하게 만들면 수익률(Mean)이 급락하고 MDD가 증가할 수 있음(현실화 과정).
**c) 실험 제안:**
1.  **[EXP_FORCE_EXP]**: 최소 노출도(min_exposure)를 0.0 → 0.2로 강제 상향. (현금 비중 최대 80% 제한)
    *   *Gate:* `degenerate_folds` 개수 < 2
    *   *Obs:* OOS Mean이 1.5 수준으로 하락하더라도 Sharpe가 유지되는지 확인.
2.  **[EXP_LOOSE_THRESH]**: 매수 진입 임계값(Threshold)을 현재보다 20% 낮춤.
    *   *Gate:* 거래 횟수(Trade Count) > 폴드당 10회
    *   *Obs:* 4개 퇴화 폴드에서 거래 발생 여부.
3.  **[EXP_OBJ_SORTINO]**: 최적화 목적함수를 Mean Return에서 Sortino Ratio로 변경 (하방 변동성만 벌칙 부여).
    *   *Gate:* `oos_min` > -0.05
    *   *Obs:* 변동성이 큰 Tech/Bio 섹터 특성상 수익률 보존 여부.
**d) PASS 조건:** Degenerate Folds가 0~1개로 줄어들고, 전체 폴드에서 양의 기대값이 관측됨.

### Priority 2. 데이터 누수(Leakage) 점검 및 Feature Lag
**a) 필요성:** OOS Mean 3.32는 일반적인 Tech/Healthcare 전략에서 나오기 힘든 수치. 종가(Close)가 피처 계산 시 당일 데이터로 포함되었는지 의심.
**b) 위험/부작용:** 누수를 제거하면 성능이 0에 수렴하거나 마이너스로 전환될 수 있음(거품 붕괴).
**c) 실험 제안:**
1.  **[EXP_LAG_1]**: 모든 기술적 지표(RSI, MA 등) 입력에 `shift(1)` 강제 적용.
    *   *Gate:* 코드 컴파일 및 실행 성공
    *   *Obs:* OOS Mean이 0.5~1.0 구간으로 '정상화' 되는지 확인.
2.  **[EXP_NO_NEXT_RETURN]**: 학습 타겟(Y) 생성 시 `shift(-1)`이 정확히 적용되었는지, 당일 수익률이 Y에 섞이지 않았는지 검증하는 더미 피처 실험.
    *   *Gate:* 피처 중요도(Feature Importance) 확인
    *   *Obs:* 특정 피처의 중요도가 0.9 이상이면 누수 확정.
**d) PASS 조건:** Lag 적용 후에도 OOS Sharpe > 1.0 유지.

### Priority 3. 유니버스 압축 및 섹터 밸런싱 (Tech/Health Focus)
**a) 필요성:** 8~14개 종목 운영 시, 한 섹터(예: Tech)가 무너질 때 방어가 안 됨. Healthcare는 Tech와 상관계수가 낮아 헷지 수단으로 필수.
**b) 위험/부작용:** 종목 풀이 너무 작으면 분산 효과 감소, 개별 종목 악재(FDA 승인 거절 등)에 취약.
**c) 실험 제안:**
1.  **[EXP_SECTOR_LOCK]**: 포트폴리오 내 Tech:Health 비중을 60:40 ~ 70:30 범위로 강제 할당.
    *   *Gate:* 할당 최적화 솔버(Solver) 성공
    *   *Obs:* `oos_min` 개선 여부 (하락장 방어력).
2.  **[EXP_TOP_CAP_ONLY]**: 유니버스를 각 섹터 시가총액 상위 7개(총 14개)로 고정하여 잡주(Micro-cap) 제거.
    *   *Gate:* 대상 종목 리스트 생성 (NVDA, MSFT, LLY, UNH 등)
    *   *Obs:* 슬리피지 비용 반영 후 성능 차이 미미함 확인.
**d) PASS 조건:** 특정 연도(2022년 등) MDD가 -20% 이내로 방어됨.

### Priority 4. 로깅 시스템 복구 (System Patch)
**a) 필요성:** `rebalance.csv` 로드 실패(`Errno 2`, `Expecting value`)는 현재 시스템이 '깜깜이' 상태임을 의미. 진단 도구(`aub_rebalance_pinpoint.py`)가 작동 불가.
**b) 위험/부작용:** 없음 (필수 인프라 작업).
**c) 실험 제안:**
1.  **[PATCH_JSONL_DUMP]**: 리밸런싱 로그를 CSV가 아닌 `jsonl` 포맷으로 변경하고, 파일 쓰기 시 `flush()` 강제 호출.
    *   *Gate:* `rebalance_pinpoint.py` 실행 시 에러 없음.
    *   *Obs:* 로그 파일 용량 증가 확인.
2.  **[PATCH_PATH_FIX]**: `--base-log` 경로 인자 처리 로직 수정 (상대 경로/절대 경로 매핑).
**d) PASS 조건:** 백테스트 종료 후 리밸런싱 로그가 정상 파싱됨.

### Priority 5. 비용 구조 현실화 (Cost & Friction)
**a) 필요성:** 8~14개 종목으로 빈번한 교체 매매 시 수수료와 슬리피지가 수익을 잠식함. 현재의 고수익이 비용 '0' 가정 때문인지 확인 필요.
**b) 위험/부작용:** 거래 횟수가 급감하여 통계적 유의성 확보가 어려울 수 있음.
**c) 실험 제안:**
1.  **[EXP_COST_BPS_20]**: 매매 건당 편도 20bps(0.2%) 비용 강제 적용.
    *   *Gate:* 실행 완료
    *   *Obs:* OOS Mean 하락폭 확인. 3.32 -> 2.0 이상이면 양호.
2.  **[EXP_HOLD_DAYS]**: 최소 보유 기간 3일 제약 추가 (잦은 매매 방지).
    *   *Gate:* 평균 보유 기간(Avg Hold Days) > 3
    *   *Obs:* 비용 차감 후 Net Profit 변화.
**d) PASS 조건:** 비용 적용 후에도 연환산 수익률(CAGR) > 20%.

### [성능 정체(Stagnation) 원인 분해 아이디어]

성능이 움직이지 않거나(0 근처), 극단값(3.32)에서 고착화된 경우 다음 5단계를 체크하십시오.

1.  **트리거(Trigger) 불발:**
    *   시장 변동성(VIX)이나 ETF(QQQ) 모멘텀 지표가 너무 보수적으로 설정되어 진입 자체를 차단하고 있는가?
    *   *Action:* 필터 조건(AND 조건)을 OR 조건으로 완화.

2.  **적용(Allocation) 실패:**
    *   Optimizer가 해를 찾지 못해(Infeasible) 이전 포트폴리오를 유지하거나 현금(0)으로 회귀하는가?
    *   *Action:* `solver` 에러 로그 확인 및 제약조건(Constraint) 완화.

3.  **노출(Exposure) 왜곡:**
    *   특정 1~2개 종목(예: NVDA)이 전체 수익의 90%를 차지하는가? (Survivorship Bias 유사)
    *   *Action:* 종목당 최대 비중 15% 제한(Hard Cap) 적용 후 재실험.

4.  **비용(Cost) 과소:**
    *   수익은 나지만 실제 거래 비용을 넣으면 마이너스인가?
    *   *Action:* BPS 10~30 적용 후 손익분기점(BEP) 확인.

5.  **레짐(Regime) 불일치:**
    *   학습 데이터(과거)와 검증 데이터(OOS)의 시장 성격(금리 인상기 vs 인하기)이 정반대인가?
    *   *Action:* 훈련 기간(Window size)을 줄여(예: 2년 -> 6개월) 최근 트렌드 반영 속도 높임.
