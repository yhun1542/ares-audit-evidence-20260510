## 다음 24~48시간 TOP5 우선순위(명령형 체크리스트)

### 1) **누수(Leakage)/정렬(Alignment) 하드닝을 1순위로 고정**

- [ ] **OHLCV 사용 시점 명시**(예: 신호는 t 종가 기준이면 체결은 t+1 시가/중간가 등) 및 그에 맞는 shift 강제
- [ ] **이벤트(실적발표, FDA, 분할/병합) 주변 purge**로 “사후 반영 데이터” 혼입 차단
- (a) 왜 필요한지: lockbox가 좋더라도 **미세 누수는 후보 간 상대비교를 왜곡**하고, 특히 MDD/분산이 커지는 후보에서 “운 좋게 통과”가 발생 가능
- (b) 위험/부작용: 성능 하락(정상), 신호 반응 지연, 거래 빈도 변화
- (c) 최소 실험(아래 공용 실험 ID 참조): **E1, E5**
- (d) PASS 조건(요약):
  - **Leak canary**에서 “불가능한 성능”이 재현되지 않을 것
  - shift 강화 후에도 **Champion의 lockbox 성능이 ‘급락(예: -30% 이상)’하지 않을 것**(정상 하락 범위 내 유지)

### 2) **서바이버십/상장폐지/Corporate action 반영 + 유니버스(Tech+Healthcare 8~14) 강제**

- [ ] **상장폐지 수익률/거래정지 처리**(0으로 두지 말고 규칙화)
- [ ] **Tech+Healthcare만**(GICS/NAICS 등) + **보유 종목 수 8~14 강제**
- (a) 왜 필요한지: 서바이버십은 평균수익을 가장 쉽게 부풀리고, 운영 전환 시 실현 손실/공백을 만든다
- (b) 위험/부작용: 백테스트 수익 하락, 거래 불가 종목 처리로 turnover 증가 가능
- (c) 최소 실험: **E2, E5**
- (d) PASS 조건:
  - 유니버스 강제 후에도 **최악 MDD(worst_mdd)가 악화폭 제한(예: +2%p 이내)** 또는 수익/리스크가 동반 개선
  - **보유 종목 수가 전 기간 8~14 범위**를 벗어나지 않음(예외는 명시적으로 로그)

### 3) **비용(수수료/슬리피지/스프레드/임팩트) 미반영을 즉시 제거 + turnover 제어**
- [ ] 거래비용 모델을 **상수 bps가 아니라 “유동성/변동성 기반”으로 상향식 반영**
- [ ] **turnover 상한/패널티**를 목적함수에 반영(과최적화 방지 + 실현가능성 증가)
- (a) 왜 필요한지: Tech/HC는 이벤트 드리븐 변동이 커서 **슬리피지/갭 비용이 전략 성패를 좌우**
- (b) 위험/부작용: 수익 하락(정상), 신호가 “자주 바뀌는 알파”일 경우 전략 붕괴 가능(오히려 조기 발견이 이득)
- (c) 최소 실험: **E3, E5**
- (d) PASS 조건:
  - 비용 반영 후에도 **lockbox_mean이 의미 있게 양수 유지**(예: 0 이상 + 하방 꼬리 개선)
  - **turnover(일/주/리밸런스 기준)가 목표 범위 내**로 들어오고, MDD가 악화되지 않음

### 4) **레짐(리스크-온/오프) 관측을 “ETF로만” 추가하고, 운영 게이트로 연결**
- [ ] ETF는 매매 금지(관측 전용): **QQQ/XLK/XLV/IBB 등**을 레짐 지표로만 사용
- [ ] 레짐에 따라 **포지션 사이즈/진입 게이트(예: risk-off 시 신규 진입 제한, 현금비중 증가 등)** 적용
- (a) 왜 필요한지: 최근 후보가 MDD가 커진 것은 **레짐 취약(특정 장세에서만 먹힘)** 가능성이 크다
- (b) 위험/부작용: 과도한 게이트는 수익 상단을 깎고, 레짐 스위치가 늦으면 whipsaw
- (c) 최소 실험: **E4, E5**
- (d) PASS 조건:
  - 레짐 구간 분해 시 **최악 구간 MDD 또는 손실 꼬리가 유의미하게 감소**
  - 전체 수익은 소폭 감소해도 **샤프/소르티노/드로다운 측면 개선**이 확인될 것

## 48시간 자동 루프용 “실행 가능한 Patch/실험” 5개(공용 ID)
아래 5개만 구현/가동하고, TOP5 항목은 이 5개 조합으로만 검증.

---

### **E1) Leak Canary Suite (정렬/누수 탐지 패치)**
1) **실험 정의**
- feature/label 생성 단계에 다음 “카나리”를 추가:
  - (i) **label을 t+0로 당겨서**(불가능한 설정) 성능이 비정상적으로 급등하는지 확인
  - (ii) feature를 **+1 bar 미래로 shift**했을 때 성능이 급등하면 누수 의심
  - (iii) 신호 생성 시점과 체결 시점을 강제 분리(예: signal@Close(t) → fill@Open(t+1))
2) **게이트**
- 카나리(i)(ii)에서 성능이 “의미 있게 개선”되면(예: lockbox_mean +X%p 이상) **즉시 FAIL**로 표시하고 해당 모듈/피처 블록을 블랙리스트
3) **기대 관측치**
- 정상 시스템이면 카나리에서 성능은 **악화**해야 한다(개선되면 누수 가능성↑)

---

### **E2) Point-in-time Universe + Tech/HC 8~14 강제 패치**
1) **실험 정의**
- 매 시점 유니버스를 “당시 상장/거래 가능” 종목으로 제한
- 섹터를 Tech+Healthcare로 제한
- 포트폴리오 보유 수를 **항상 8~14**로 강제(부족 시 현금)
2) **게이트**
- 보유 수 범위 위반, 미래 섹터 정보 사용, 상장폐지 처리 누락 로그가 있으면 **FAIL**
3) **기대 관측치**
- 평균수익은 일부 하락할 수 있으나, **리얼라이저블(현실성) 지표**(turnover/갭손실/MDD 꼬리)가 개선되는 패턴이 나와야 함

---

### **E3) 비용/슬리피지 + Turnover 패널티 패치**
1) **실험 정의**
- 비용 모델 최소 구성:
  - 커미션(고정 bps) + 스프레드(가격/유동성 proxy) + 슬리피지(ATR/일중변동 proxy)
- 목적함수에 turnover 패널티 또는 제약(예: 리밸런스당 교체 상한)
2) **게이트**
- 비용 반영 후 성능이 0 근처로 붕괴하면서 turnover가 높게 유지되면 **알파 품질 FAIL**로 분류
3) **기대 관측치**
- “진짜 알파”면 비용 반영 후에도 **수익이 남고**, turnover가 내려가면서 MDD가 완만해짐

---

### **E4) ETF 관측 레짐 모니터 + 진입/사이징 게이트 패치(ETF 매매 없음)**
1) **실험 정의**
- 관측 ETF(예: QQQ/XLK/XLV/IBB)로 레짐 스코어 생성(추세/변동성/드로다운)
- 레짐이 risk-off면:
  - 신규 진입 제한, 또는
  - 포지션 사이즈 스케일 다운(현금 비중 증가)
2) **게이트**
- 레짐 게이트 적용 후에도 최악 구간 손실이 줄지 않으면(꼬리/MDD 개선 없음) **FAIL**
3) **기대 관측치**
- 전체 수익이 소폭 감소해도 **worst_mdd, tail loss, fold14_mdd**가 개선되는 방향

---

### **E5) Robustness Gate Pack (과최적화/운영/재현성 통합)**
1) **실험 정의**
- Purged/embargo 교차검증(이벤트/근접기간 누수 완화)
- 시드/스냅샷 고정, 파라미터 민감도(±10~20%) 흔들어도 성능 유지 확인
- “선발 규칙” 하드코딩: lockbox 중심 + MDD/꼬리 제약 + turnover 제약
2) **게이트**
- 파라미터/시드 변화에 성능이 크게 요동하면 **FAIL**
- lockbox_mean은 좋은데 worst_mdd/turnover가 기준 위반이면 **FAIL**
3) **기대 관측치**
- PASS 후보 수는 줄어들지만, **운영 전환 시 성능 붕괴 확률**이 내려감

---

## PASS 조건(시스템 레벨로 고정 권장)
- [ ] **누수 카나리(E1) 무사 통과**
- [ ] **서바이버십/유니버스(E2) 통과 + 보유 8~14 유지**
- [ ] **비용/turnover(E3) 반영 후에도 lockbox_mean 양수 & worst_mdd 악화 제한**
- [ ] **레짐 취약 꼬리(E4) 개선**
- [ ] **강건성(E5)에서 시드/파라미터 흔들림에 안정**

## 성능이 “안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래 순서대로 “고장 위치”를 좁히는 체크리스트로 고정.

### A) Trigger(신호 발생) 문제
- [ ] 신호 발생 빈도(주당/월당)가 과거 대비 급감/급증했는지 확인
- [ ] 신호 분포가 한쪽으로 쏠렸는지(항상 매수/항상 현금) 확인
- [ ] 이벤트 캘린더(실적/FDA) 주변에서만 작동하는 “조건부 알파”인지 분해

### B) Apply(적용/체결) 문제
- [ ] 시그널 시점 vs 체결 시점이 뒤섞여 “좋아 보이던 엣지”가 사라졌는지 점검(E1)
- [ ] 리밸런스 규칙이 현실 체결(갭/유동성)에서 과도한 손실을 만드는지(E3로 확인)

### C) Exposure(노출) 문제
- [ ] 8~14 종목 강제에서 특정 초대형 1~2개로 쏠림이 생겼는지(단일종목 기여도/리스크 기여도)
- [ ] Tech vs Healthcare 비중이 한쪽으로 고착되어 “섹터 베팅”이 되었는지
- [ ] 팩터 노출(모멘텀/퀄리티/저변동 등)이 사실상 동일하게 변했는지(성능 정체의 흔한 원인)

### D) Cost(비용) 문제
- [ ] 성과 정체가 “gross는 괜찮은데 net에서 죽는지” 확인(거래당 기대수익 vs 비용)
- [ ] turnover가 엣지 대비 과도한지(엣지/회전 비율) 확인 → E3로 즉시 판별

### E) Regime(레짐) 문제
- [ ] 성과가 특정 변동성/추세 구간에서만 나는지(구간별 PnL)
- [ ] QQQ/XLK/XLV/IBB 관측 레짐으로 “죽는 구간”을 라벨링하고, 그 구간에서만 손실이 집중되는지(E4)

---

## 즉시 실행 순서(48시간 루프에 맞춘 명령형)
- [ ] **E1 → E2 → E3 → E4 → E5** 순으로 패치 브랜치 생성 및 각각 독립 실행
- [ ] 기존 자동 명령 3개는 그대로 돌리되, 리포트에 **E1~E5 게이트 결과를 1페이지 요약**으로 강제 출력
- [ ] PASS 후보가 나오면 성능 수치보다 먼저 **(누수/서바이버십/비용/운영 게이트) 통과 여부**로 선발 고정

위 구성은 “케이스 폭발” 없이, 현재 Champion을 훼손하지 않으면서도(락박스 성과 유지) 후보들의 **MDD 악화/레짐 취약/비용 미반영/누수 가능성**을 48시간 내에 가장 빨리 걸러내는 방향으로 정리돼 있다.
