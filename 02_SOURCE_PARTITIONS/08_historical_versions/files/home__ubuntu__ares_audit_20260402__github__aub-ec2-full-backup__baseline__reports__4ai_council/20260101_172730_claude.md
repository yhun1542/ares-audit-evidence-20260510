## Priority 1: Tuning Fold 참사 원인 분리

### (a) 필요성
- tuning_min = -1.35 → 특정 fold에서 극단적 손실
- 이 fold가 2022 금리쇼크/2020 COVID 등 특수 regime이면 수용 가능
- 일반 구간이면 전략 결함

### (b) 위험/부작용
- 해당 fold만 맞추면 → 다른 fold 성능 훼손 (시소효과)
- Regime 필터 과도 적용 → 거래일 급감 → 수익 기회 상실

### (c) 최소 실험

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| **P1-A** | 최악 fold 식별 → 해당 구간 regime label 확인 | regime=crisis면 PASS | fold별 return 분포 출력 |
| **P1-B** | 최악 fold 제외 후 나머지 fold 안정성 확인 | std < 0.3 | 13fold mean ± std |
| **P1-C** | 최악 fold 내 개별 종목 기여도 분해 | 단일종목 > 50% 기여면 FAIL | 종목별 PnL attribution |

### (d) PASS 조건
```
tuning_min > -0.8 OR (tuning_min ≤ -0.8 AND regime=documented_crisis)
```

## Priority 2: Lockbox 과신 검증 (Survivorship 재점검)

### (a) 필요성
- Lockbox mean 1.33 >> Tuning mean 1.07
- 보통 반대가 정상 (tuning 과적합 → lockbox 하락)
- Lockbox 구간이 bull market 편중 가능성

### (b) 위험/부작용
- Lockbox가 2023-24 AI버블 구간이면 → 실전 성능 과대추정
- Survivorship: 현재 종목풀이 lockbox 시점에 상장되어 있었는지

### (c) 최소 실험

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| **P2-A** | Lockbox 구간 SPY 수익률 대비 alpha 계산 | alpha > 0.1 | excess return % |
| **P2-B** | Lockbox 구간 내 regime 분포 확인 | bull < 70% | regime % breakdown |
| **P2-C** | 종목별 상장일 vs lockbox 시작일 교차검증 | 전종목 상장일 < lockbox 시작 | 위반 종목 리스트 |

### (d) PASS 조건
```
lockbox_alpha > 0.05 AND bull_regime_ratio < 0.75 AND survivorship_violation = 0
```

## Priority 3: MDD 구조 개선 (Worst -9% → -7% 목표)

### (a) 필요성
- fold14_mdd=-5% vs worst_mdd=-9% → 특정 fold에 MDD 집중
- 실전에서 해당 regime 재발 시 동일 손실 예상

### (b) 위험/부작용
- MDD 축소 = position sizing 축소 → CAGR 동반 하락
- 과도한 방어 → Sharpe 하락

### (c) 최소 실험

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| **P3-A** | Worst MDD fold에서 vol scaling 1.5x → 1.0x | MDD < -7% | worst_mdd 변화 |
| **P3-B** | Drawdown > 5% 시 position 50% 청산 rule 추가 | tuning_mean > 1.0 유지 | mean/mdd tradeoff |
| **P3-C** | Sector concentration cap 30% → 20% | worst_mdd 개선 | sector_max % |

### (d) PASS 조건
```
worst_mdd > -0.07 AND tuning_mean > 1.05
```

## Priority 4: Signal 유효성 (Alpha Decay 점검)

### (a) 필요성
- 성능 정체 시 signal 자체가 decay 했을 가능성
- 최근 fold에서 signal IC 하락 여부 확인 필요

### (b) 위험/부작용
- Signal 교체 → 전체 파이프라인 재검증 필요
- 새 signal 과적합 위험

### (c) 최소 실험

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| **P4-A** | Fold별 signal IC (정보계수) 계산 | 최근 3fold IC > 0.03 | IC timeseries |
| **P4-B** | Signal holding period 분석 (1d/3d/5d) | 최적 period 식별 | return by holding |
| **P4-C** | Signal ensemble weight 재조정 (equal → IC-weighted) | tuning_mean 개선 | weight 변화량 |

### (d) PASS 조건
```
recent_3fold_IC > 0.03 AND IC_trend ≠ declining
```

## Priority 5: 운영 비용 현실화

### (a) 필요성
- 현재 backtest에 slippage/commission 수준 미확인
- 과소 반영 시 실전 수익률 20-40% 하락 가능

### (b) 위험/부작용
- 비용 상향 → 거의 모든 metric 하락
- 현실적이지만 심리적 저항 발생

### (c) 최소 실험

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| **P5-A** | 현재 cost assumption 문서화 | 존재 확인 | bps 수치 |
| **P5-B** | Slippage 5bps → 10bps 스트레스 테스트 | tuning_mean > 0.9 | 성능 하락폭 |
| **P5-C** | Turnover 계산 → 연간 비용 총액 산출 | 비용 < 수익의 15% | cost/return ratio |

### (d) PASS 조건
```
cost_ratio < 0.15 AND tuning_mean_after_cost > 0.95
```

## 성능 미변동 시 원인 분해 트리

```
성능 정체
├── [1] 트리거 미작동
│   └── Signal이 발생했으나 조건 미충족 → entry 빈도 확인
│
├── [2] 적용 실패  
│   └── Signal 발생 + 조건 충족, but 체결 실패 → execution log 확인
│
├── [3] 노출 부족
│   └── Position size가 너무 작음 → avg exposure % 확인
│
├── [4] 비용 상쇄
│   └── 수익 발생했으나 비용에 잠식 → gross vs net return 비교
│
└── [5] 레짐 미스매치
    └── 전략이 특정 regime only → 현재 regime 식별
```
