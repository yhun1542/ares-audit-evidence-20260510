## 24~48시간 TOP5 우선순위 (코드/아키텍처/전략) — **명령형 체크리스트**
1) **누수/폴드 붕괴(degenerate_folds)부터 즉시 차단하라**  
2) **서바이버십/Corporate Actions(분할·배당·티커변경) 포인트-인-타임 정합성을 강제하라**  
3) **비용·체결·리밸런스 로그를 “ONE TRUTH”로 복구하라(현재 rebalance 데이터 로딩 실패)**  
4) **“성능이 안 움직임(No-Delta)”을 신호→게이트→포지션→수익 기여까지 분해 로깅하라**  
5) **운영 리스크(해시/아티팩트/재현성) 제거 + 노출(8~14종, Tech+Healthcare) 제약을 코드로 고정하라**

## 실행 가능한 Patch/실험 (48시간 자동 루프용) — **총 5개만**
아래 5개 실험을 돌리면, 위 TOP5를 전부 커버하도록 설계했다(각 TOP 항목에서 **같은 실험을 재사용**).

# 제안 1) 누수/과최적화/폴드 붕괴(최우선)
### (a) 왜 필요한지
- 현재 `degenerate_folds: [1,2,3,8]` → 워크포워드/스플릿에서 **학습-평가 분리가 깨졌거나**, 특정 구간에서 거래/라벨이 비어 **검증이 무의미**할 가능성.
- `worst_mdd: None`, `lane_hash/run_hash: None`도 같이 보이는 점상, **실험 산출물/평가 파이프라인 자체가 불완전**할 수 있음(누수만큼 위험).

### (b) 위험/부작용
- 누수 차단 후 성능 급락 가능(이게 정상).
- 폴드 규칙 강화로 유효 샘플 감소 → 분산 증가.

### (c) 최소 실험(아래 5개 중 재사용) 2~3개
- **[E1] 폴드/누수 감사 하네스**
- **[E4] No-Delta 분해 로깅(신호→포지션)**
- **[E5] 노출/보유종목 제약 고정(폴드별 공통 제약 강제)**

### (d) PASS 조건
- `degenerate_folds == []` (또는 원인 로그로 “왜 비었는지”가 폴드별로 1줄 요약 생성)
- “시간 셔플/라벨 리드(lead) 테스트”에서 성능이 **의미 있게 붕괴**(누수 없다는 증거)
- 폴드별 거래 수/리밸런스 수가 0이 아닌 구간이 대부분(비정상 폴드 제거)

---

# 제안 2) 서바이버십/포인트-인-타임(Tech+Healthcare 유니버스) 점검
### (a) 왜 필요한지
- 미국 개별주에서 서바이버십은 성능을 가장 크게 부풀리는 축.  
- Tech+Healthcare 8~14종 운용이면, 유니버스/상장폐지/인수합병 처리 누락 시 **선택 편향**이 즉시 발생.

### (b) 위험/부작용
- 포인트-인-타임 유니버스 적용 시 과거에 가능했던 종목 접근이 막혀 성능 저하.
- 데이터 소스 변경으로 리턴 시계열이 미세하게 달라져 리그레션 필요.

### (c) 최소 실험 2~3개
- **[E2] 포인트-인-타임 유니버스 + Corporate Actions 재구성 A/B**
- **[E1] 폴드/누수 감사 하네스(유니버스 교체 후 재검증)**

### (d) PASS 조건
- “유니버스 재구성 전/후”에 대해  
  - 종목 수, 섹터(Tech/Healthcare) 비중, 생존/퇴출 이벤트 카운트가 리포트로 출력
  - OOS 성능이 **동일 방향으로 크게 괴리**하면(특히 개선) → 기존이 오염 가능성 경고를 자동 raise
- 상장폐지/티커변경/합병 이벤트가 있었던 샘플 구간에서 **데이터 공백/미정렬 0건**(또는 예외 목록이 파일로 남음)

---

# 제안 3) 비용 미반영 + 리밸런스 로그 실패(현재 최우선 운영 장애)
### (a) 왜 필요한지
- 현재 `aub_rebalance_pinpoint`가  
  - `--base-log` 파일 미존재  
  - `rebalance.csv` JSON 파싱 실패  
  → **리밸런스/체결 단위의 검증이 불가능** = 비용·회전율·슬리피지·체결불능(운영 리스크) 전부 블라인드.
- 비용 미반영은 OOS 평균을 가장 쉽게 “가짜로” 올림.

### (b) 위험/부작용
- 비용 모델 도입 후 성능 급락 가능(정상).
- 로깅 증가로 실행시간/스토리지 증가(48시간 루프에서는 크기 제한 필요).

### (c) 최소 실험 2~3개
- **[E3] 리밸런스 로그 포맷/경로 표준화 + 비용 모델 0/기본/스트레스 3단 비교**
- **[E4] No-Delta 분해 로깅(거래가 실제로 나가는지 확인)**

### (d) PASS 조건
- 매 런마다 `rebalance.jsonl`(권장) 또는 단일 포맷이 **항상 생성**되고, 핀포인트 툴이 **무에러 로드**
- 비용 스윕 결과가 단조적이어야 함: `0비용 성능 ≥ 기본비용 성능 ≥ 스트레스비용 성능`
- 회전율/거래대금/슬리피지 추정치가 **폴드별·기간별**로 출력(최소: mean/95%/max)

---

# 제안 4) “성능이 안 움직임(No-Delta)” 원인: 게이트/스케일링/라운딩/노출 한계
### (a) 왜 필요한지
- No-Delta 진단이 이미 돌았고, “실험을 했는데 성능 변화가 없음” 상태는 보통:
  - (i) 신호가 포지션으로 전달되기 전에 **게이트에서 잘림**
  - (ii) 가중치가 **라운딩/클리핑**으로 동일 포트폴리오가 반복
  - (iii) 리밸런스가 안 일어남(로그가 없어서 확인 불가)
  - (iv) 노출 상한(현재 max 0.84)과 결합해 **대부분 동일 노출**로 수렴  
  중 하나다.

### (b) 위험/부작용
- 로깅/디버그 추가로 성능 저하(시간) 가능.
- “진짜 신호가 약함”이 드러날 수 있음.

### (c) 최소 실험 2~3개
- **[E4] 신호→게이트→타깃가중치→실행가중치 단계별 델타 로깅 + 미세 스케일링 교란 테스트**
- **[E3] 리밸런스 로그 복구(거래 발생 여부를 객관화)**

### (d) PASS 조건
- 같은 날짜에서 `signal_weight`와 `executed_weight`의 상관/차이 통계가 출력되고,
  - 교란(예: 신호 스케일 ×0.9/×1.1) 시 **executed_weight 또는 turnover가 유의미하게 변화**
- “게이트로 인해 0이 된 비율”, “클리핑으로 동일해진 비율”이 0이 아니면 원인으로 자동 태깅

---

# 제안 5) 운영 리스크 제거 + 운용 제약(8~14개, Tech+Healthcare) 코드로 강제
### (a) 왜 필요한지
- `lane_hash/run_hash: None`은 재현성/추적성 붕괴 신호. 48시간 자동 루프에서 가장 위험.
- “8~14개 미국 개별주(Tech+Healthcare)”가 전략 정의라면, 제약이 느슨하면 실험 간 비교 자체가 무의미.

### (b) 위험/부작용
- 제약 도입으로 성능 저하 가능(정상).
- 과도한 제약은 다각화/알파 표현을 제한(그래도 운영 요구사항이면 강제해야 함).

### (c) 최소 실험 2~3개
- **[E5] 보유종목 수(8~14) + 섹터(Tech/Healthcare) + 단일종목 max weight + 현금/노출 한도 고정**
- **[E1] 폴드/누수 감사(제약이 폴드마다 다르게 적용되지 않는지 확인)**

### (d) PASS 조건
- 모든 날짜에서 `holdings_count`가 8~14 범위 유지(예외 발생 시 원인 로그 1줄)
- 섹터 외 종목이 편입되면 즉시 fail(또는 관측용으로 별도 레인에 격리)
- 모든 런에 `run_hash/lane_hash`가 채워지고, 동일 입력이면 해시/결과가 재현

## 48시간 자동 루프용 “실험 정의/게이트/기대 관측치” (E1~E5)

### [E1] 폴드/누수 감사 하네스
- (1) **실험 정의**:  
  - 워크포워드 각 폴드에 대해 (a) 학습/검증 기간 겹침 검사 (b) feature timestamp ≤ trade decision timestamp 강제 (c) 라벨 lead(+1일) 테스트 (d) 시간 셔플 테스트를 자동 실행
- (2) **게이트**:  
  - 겹침 0건, lead/셔플 성능이 기준 대비 큰 폭 하락, `degenerate_folds` 빈 리스트
- (3) **기대 관측치**:  
  - 누수 있으면 lead/셔플에서 성능 유지/개선 같은 비정상 패턴이 뜸 → 즉시 차단 포인트 확보

### [E2] 포인트-인-타임 유니버스 + Corporate Actions A/B
- (1) **실험 정의**:  
  - 현재 유니버스 vs PIT 유니버스(상장/상폐 포함)로 동일 전략 백테스트 A/B, 분할/배당 조정 리턴 정합성 검사 포함
- (2) **게이트**:  
  - 종목 접근 가능 여부가 과거 시점 기준으로 일관, 데이터 공백/미정렬 0(또는 목록화)
- (3) **기대 관측치**:  
  - 기존 성능이 과대평가였다면 PIT 적용 시 성능 하락 + 변동성 구조 변화가 관측

### [E3] 리밸런스 로그 복구 + 비용 3단 스윕
- (1) **실험 정의**:  
  - 출력 포맷을 `rebalance.jsonl`로 단일화(날짜, pre/post weights, trades, est_slippage, fees)  
  - 비용: 0 / 기본 / 스트레스(슬리피지×2, 수수료×2 등) 3회전 비교
- (2) **게이트**:  
  - 핀포인트 도구가 무에러 로드, 비용 단조성 만족
- (3) **기대 관측치**:  
  - 거래가 실제로 발생하면 비용 증가에 따라 성능이 계단식으로 감소  
  - 감소가 없으면 “거래가 안 나감/거래량 0/로그 불일치” 쪽으로 원인 좁힘

### [E4] No-Delta 분해 로깅 + 스케일 교란
- (1) **실험 정의**:  
  - 매 리밸런스 시점에 `signal`→`gated_signal`→`target_weight`→`clipped_weight`→`executed_weight`를 저장  
  - 신호 스케일을 ±10% 교란한 2개 런을 추가
- (2) **게이트**:  
  - 교란 시 `executed_weight`/turnover/리밸런스 횟수 중 최소 1개가 유의미하게 변화
- (3) **기대 관측치**:  
  - 변화가 없으면 “게이트/클리핑/라운딩/리밸런스 미발생”이 자동으로 좁혀짐

### [E5] 운용 제약(8~14, Tech+Healthcare) + 노출 상한 고정
- (1) **실험 정의**:  
  - 보유종목 수 8~14 강제, 섹터 필터(Tech/Healthcare), 단일종목 max weight, gross/net 노출 상한을 config로 고정  
- (2) **게이트**:  
  - 전 기간 제약 위반 0(또는 위반 시 즉시 fail-fast)
- (3) **기대 관측치**:  
  - 기존 결과가 제약 밖에서 나온 착시라면 성능이 재배치되고, 회전율/노출 프로파일이 안정화

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래 순서로 **원인을 하나씩 제거**하라(각 단계는 위 E3~E4 로깅으로 관측 가능해야 함).

1) **트리거(리밸런스가 실제로 도는가?)**
- 관측: 리밸런스 이벤트 수, 거래 건수, turnover가 0 또는 비정상적으로 낮음  
- 조치: 스케줄/캘린더/휴장/데이터 결측으로 트리거가 막혔는지 확인(E3)

2) **적용(신호가 포지션으로 전달되는가?)**
- 관측: `signal`은 변하지만 `executed_weight`가 거의 동일  
- 원인 후보: 게이트(임계값), 클리핑, 라운딩, 최소주문단위, 현금/노출 상한  
- 조치: 단계별 델타 로깅 + 스케일 교란(E4)

3) **노출(포트폴리오가 실제로 달라지는가?)**
- 관측: holdings overlap가 너무 높음, 섹터/종목 구성 고정  
- 원인 후보: 유니버스가 지나치게 좁거나, 제약이 사실상 단일해를 강제  
- 조치: 제약의 “활성화 비율(clip 비율)”을 로그로 수집(E5+E4)

4) **비용(알파가 비용에 먹히는가?)**
- 관측: 0비용에서만 성능이 좋고 기본/스트레스에서 급락  
- 조치: 비용 민감도를 기본 리포트로 상시 출력(E3)

5) **레짐(시장 국면별로만 먹히는가?)**
- 관측: 특정 변동성/금리/섹터 리더십 구간에서만 성능이 발생  
- 조치(관측지표로만, ETF 매매 제외):  
  - QQQ/XLK/XLV, VIX, 10Y(예: TNX) 등을 레짐 태그로 저장하고, 폴드별 성능을 레짐별로 분해(추가 전략 확장 금지, “진단”만)

---

### 즉시 실행 순서(24~48h)
1) **E3부터**: 리밸런스 로그/비용 스윕 복구(지금은 검증 자체가 막혀 있음)  
2) **E1**: degenerate_folds 제거 + 누수 테스트 통과  
3) **E4**: No-Delta 분해로 “안 움직임”의 위치를 특정  
4) **E2**: PIT 유니버스/Corporate Actions A/B로 서바이버십 제거  
5) **E5**: 8~14, Tech+Healthcare 제약을 코드로 고정(운영 정의를 실험마다 일관화)

이 5개가 통과되면 그 다음부터야 비로소 “알파 아이디어”를 늘릴 자격이 생긴다. 지금은 **정합성/비용/적용 경로**가 최우선이다.
