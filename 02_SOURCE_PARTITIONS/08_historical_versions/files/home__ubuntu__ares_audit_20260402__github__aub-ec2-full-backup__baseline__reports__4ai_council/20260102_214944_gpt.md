## 다음 24~48시간 TOP5 우선순위(명령형 체크리스트)

### P0) **리포팅/리밸런스 로그/해시 “단일 진실” 복구 (재현성·운영 리스크 최우선)**
- **왜 필요?**
  - 현재 `lane_hash/run_hash=None`, `worst_mdd=None`, 리밸런스 로그 로드 실패(`rebalance.csv`/`jsonl` 파싱 실패) → **성과가 “움직였는지/안 움직였는지” 자체가 불명확**.
  - `oos_mean`이 3.32 vs 2.63으로 상충 → **평가 파이프라인/스코어 집계 불일치** 가능성.
- **위험/부작용**
  - 로깅/스키마 강제 시 과거 아티팩트 일부 폐기, 기존 리포트 호환 깨짐.
- **최소 실험(공통 실험 ID 재사용)**
  - **E1(관측/로그 스키마 강제)** + **E4(폴드 유효성 게이트)** 를 즉시 적용해 “측정 가능한 상태”로 고정.
- **PASS 조건**
  - 모든 런에서 `run_hash/lane_hash` 생성, `rebalance.jsonl` 100% 파싱, `worst_mdd` 산출.
  - OOS 집계(평균/최소/분포)가 리포트·아티팩트·콘솔 출력에서 **완전 일치**.

---

### P1) **누수/과최적화 차단: Purged Walk-Forward + Embargo + 피처 타임스탬프 검증**
- **왜 필요?**
  - `degenerate_folds: [1,2,3,8]` → 폴드에서 트레이드 0/극소, 신호가 미래정보/리밸런스 타이밍과 충돌하거나 트리거 조건이 학습/검증 분리와 엇갈릴 가능성.
  - Tech/Healthcare 단일주(8~14) 집중은 **과최적화/누수에 취약**.
- **위험/부작용**
  - OOS 평균이 단기적으로 하락(“정상화”), 신호가 줄어 수익 기회 감소.
- **최소 실험**
  - **E2(누수 방지 CV/임바고 + 피처 지연 검증)** + **E4(폴드 유효성/최소 트레이드 수 게이트)**.
- **PASS 조건**
  - 폴드별 트레이드 수/노출이 최소 기준 충족(아래 E4 게이트), degenerate fold 0.
  - “피처 timestamp > bar close” 같은 누수 플래그 0건.

---

### P2) **비용 미반영 제거: 슬리피지/스프레드/임팩트/수수료를 학습·평가에 강제 삽입**
- **왜 필요?**
  - 현재 리밸런스 데이터 부재 + 비용모델 누락 가능성이 큼 → **표면 성과는 좋은데 실전에서 0 델타/역전**의 대표 원인.
- **위험/부작용**
  - 전략이 급격히 보수적으로 변해 노출 감소, 샤프 하락 가능.
- **최소 실험**
  - **E3(비용모델 on: 보수/중간 2단계)** + **E1(체결단가/슬리피지 로그 의무화)**.
- **PASS 조건**
  - 비용 적용 전후 성과가 “예상 가능한” 방향으로만 변화(턴오버 높은 설정에서 성과가 과도하게 유지되면 누수 의심).
  - 비용 포함 OOS에서 **턴오버-성과 상관**이 정상화(턴오버↓ 시 성과 유지/개선 또는 MDD↓).

---

### P3) **운영 리스크/노출 리스크: 유니버스 고정 + 리스크 예산(턴오버/섹터/단일종목) 하드 캡**
- **왜 필요?**
  - `exposure_max ~0.84`는 나쁘지 않지만, degenerate fold 존재 시 “어떤 구간은 0, 어떤 구간은 과노출” 가능.
  - US 단일주(ETF 매매 제외)에서 비용/슬리피지/리밸런스 실패는 즉시 성과 훼손.
- **위험/부작용**
  - 상한 규제 때문에 극단적 알파 구간을 못 먹음(단, 실전 안정성↑).
- **최소 실험**
  - **E4(리스크 하드캡: 노출/턴오버/단일종목/섹터)** + **E3(비용모델)**.
- **PASS 조건**
  - 48시간 루프에서 **실현 턴오버, 단일종목 비중, 총노출**이 상한을 한 번도 위반하지 않음.
  - OOS min(최악 구간) 개선 또는 MDD 산출/개선(최소한 “None” 제거).

---

### P4) **“안 움직임(=No-Delta)” 대응: 레짐/드리프트 기반 게이트 + 관측 ETF(지표)로만 필터링**
- **왜 필요?**
  - `No-Delta Diagnoser`가 돌아갔다는 건 “성능 변화가 안 나오는 패턴”이 반복된다는 뜻.
  - 레짐(리스크온/오프)에서 신호가 무효화되면 트리거는 발생해도 적용이 상쇄되거나, 반대로 아예 트레이드가 사라짐.
- **위험/부작용**
  - 필터가 과하면 기회 상실(노출이 0으로 수렴).
- **최소 실험**
  - **E5(레짐 게이트: QQQ/XLV/TLT/VIX는 관측만)** + **E4(최소 노출/최소 트레이드 게이트)**.
- **PASS 조건**
  - 레짐별(예: 고변동/저변동) 성과 분해에서 **한쪽 레짐이 지속적으로 발목 잡는 패턴**이 약화.
  - “신호는 있는데 포지션 반영이 안 됨” 유형의 No-Delta 케이스 감소(아래 분해 체크로 계량).

## 48시간 자동 루프용 “실행 가능한 Patch/실험” 5개 (3~5개 제한 준수)

아래 E1~E5만 돌리도록 고정(케이스 폭발 방지). 각 실험은 **(1)정의 → (2)게이트 → (3)기대 관측치** 형태로 설계.

### E1) 관측/로그 스키마 강제 + 재현성 해시 고정
1) **실험 정의**
   - `run_hash/lane_hash`를 입력(코드 커밋+데이터 버전+파라미터)로 결정론적으로 생성.
   - `rebalance.jsonl`를 “단일 포맷”으로 강제(한 줄당: ts, symbol, target_w, exec_w, price, slippage_bps, fees, reason).
   - `worst_mdd`, turnover, trade_count, exposure stats를 리포트에 필수 필드로 추가(없으면 런 실패).
2) **게이트**
   - 리포트 생성 단계에서 **필수 필드 누락 시 즉시 FAIL**.
   - 리밸런스 로그 파서 100% 통과(0 에러) 아니면 FAIL.
3) **기대 관측치**
   - OOS mean/min이 리포트/콘솔/아티팩트에서 일치.
   - “No rebalance data found” 제거, degenerate fold 원인이 “측정 불가”가 아닌 “전략 구조”로 좁혀짐.

---

### E2) 누수 차단 CV: Purged Walk-Forward + Embargo + 피처 지연(availability lag) 검증
1) **실험 정의**
   - 폴드 분할을 Purged WF로 변경(학습/검증 경계 주변 N일 임바고).
   - 각 피처에 **가용 시점(available_at)** 을 부여하고, 의사결정 시점 이전 피처만 사용하도록 강제.
2) **게이트**
   - 누수 감지 규칙(예: feature_time > bar_close, future earnings/fundamental) 1건이라도 발견 시 FAIL.
   - 폴드별 최소 트레이드 수(예: fold당 N회) 미달 시 FAIL(E4와 연동).
3) **기대 관측치**
   - OOS 평균이 하락하더라도 분산/최악값이 안정화.
   - degenerate fold가 “누수/타이밍 충돌” 기인이라면 폴드가 정상화되거나, 반대로 트레이드가 줄며 원인이 명확해짐.

---

### E3) 비용모델 강제(2단계): 보수/중간 시나리오
1) **실험 정의**
   - 비용 = 수수료 + 스프레드/2 + 슬리피지(ATR 또는 dollar volume 기반) + (옵션/공매도 없으면 borrow 제외).
   - **중간/보수 2개 설정**만 허용(과다 분기 금지).
2) **게이트**
   - 비용 적용 후에도 “거래가 많은데 성과가 거의 동일”이면 누수/체결모델 오류로 FAIL.
   - 비용 로그(각 트레이드별 cost_bps)가 누락되면 FAIL(E1 연동).
3) **기대 관측치**
   - 턴오버 높은 구간의 성과가 더 깎이고, 안정 구간이 상대적으로 부각.
   - 전략 개선 방향이 “턴오버 낮추기/리밸런스 빈도 조절”로 수렴.

---

### E4) 리스크/운영 하드캡 + 폴드 유효성(퇴화 방지) 게이트
1) **실험 정의**
   - **유니버스 고정(미국주식, Tech+Healthcare 8~14)**: 예시(고정 리스트)
     - Tech: AAPL, MSFT, NVDA, GOOGL, AMZN, META, AMD, ORCL
     - Healthcare: LLY, UNH, JNJ, MRK, ABBV, TMO  
     (총 10~14 내에서 선택 고정; ETF 매매 금지)
   - 하드캡(예):
     - 총노출 max 0.85, min 0.05(상시 0 회피가 목적이면 min=0 허용하되 사유 로그 필수)
     - 단일종목 |w| max 0.20~0.25
     - 일/주간 turnover cap
     - 섹터 비중 상한(Tech/HC 편중 허용하되 단일 섹터 80% 초과 시 경고/게이트)
2) **게이트**
   - degenerate fold(트레이드 0 또는 노출 0 지속) 발생 시 FAIL(또는 “현금전략”이면 명시 태그 없으면 FAIL).
   - 상한 위반 1회라도 FAIL(운영 리스크 우선).
3) **기대 관측치**
   - 성과가 좋아도 “실전 불가능” 케이스가 조기 차단.
   - 노출/턴오버 분포가 안정화되어 No-Delta 원인(미반영/미체결/미노출)을 분리 가능.

---

### E5) 레짐 게이트(관측 ETF만): QQQ/XLV/TLT + VIX로 거래 ON/OFF 또는 스케일링
1) **실험 정의**
   - ETF는 **매매 금지**, 관측 지표로만 사용:
     - QQQ 모멘텀/드로우다운, XLV 상대강도(Healthcare 레짐), TLT 금리 레짐, VIX 변동성 레짐
   - 레짐별로 포지션 스케일(예: VIX 상단에서 gross ↓, QQQ 하락 레짐에서 베타 노출 ↓).
2) **게이트**
   - 필터 적용 후 트레이드 수가 급감하면 FAIL(E4의 최소 트레이드와 동시 충족).
   - 레짐별 성과가 특정 레짐에만 과도하게 의존하면 FAIL(서바이버십/우연 적합 경고).
3) **기대 관측치**
   - “변동성 급등/리스크오프” 구간에서 oos_min 개선 또는 MDD 개선.
   - No-Delta 중 “신호 상쇄(시장 레짐에 눌림)” 비중 감소.

## 성능이 “안 움직일 때(No-Delta)” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)

아래를 **순서대로** 깎아나가면, 48시간 안에 원인 범위를 급격히 줄일 수 있음.

### 1) Trigger(신호 생성) 문제
- **체크**
  - 신호가 실제로 변하는가? (시점별 alpha score 분산이 0에 수렴하는지)
  - 상위/하위 랭크가 매일 동일한지(피처 정지/결측 대체로 평탄화)
- **관측치**
  - `signal_std`, `rank_turnover`, 결측률, forward-fill 비율
- **결론 패턴**
  - 신호가 평탄 → 데이터/피처 파이프라인 고장(E1/E2로 잡힘)

### 2) Apply(포지션 반영) 문제
- **체크**
  - 신호는 변하는데 target weights가 0 또는 동일한가?
  - 리밸런스가 “계획”만 있고 “체결/적용”이 없는가? (현재 rebalance 로그 부재가 강한 의심)
- **관측치**
  - target_w vs exec_w 괴리, 리밸런스 이벤트 수, order reject/skip reason
- **결론 패턴**
  - 계획≠체결 → 로깅/체결모델/게이트 문제(E1)

### 3) Exposure(노출) 문제
- **체크**
  - gross/net/beta가 레짐과 무관하게 0 근처로 고정되는가?
  - degenerate folds가 특정 구간(예: 고변동)에서만 반복되는가?
- **관측치**
  - gross exposure 시계열, 포지션 수, 단일종목 상한에 자주 걸리는지
- **결론 패턴**
  - 제약이 과도해 포지션이 사라짐 → E4 조정
  - 레짐에서만 노출 0 → E5 필요

### 4) Cost(비용) 문제
- **체크**
  - 비용을 넣는 순간 성과가 “0 델타” 또는 급락하는가?
  - 비용이 0으로 기록되거나 비정상적으로 작게 기록되는가?
- **관측치**
  - cost_bps 분포, turnover-성과 상관, 슬리피지 vs dollar volume
- **결론 패턴**
  - 비용모델/로그 부재 → E3/E1 우선
  - 비용이 본질이라면 전략 구조(리밸런스 빈도/포지션 수) 변경 필요(E4)

### 5) Regime(시장 국면) 문제
- **체크**
  - 동일 전략이 레짐별로 +/−가 극단적으로 갈리는가?
  - Tech vs Healthcare 상대강도 국면에서만 작동하는가?
- **관측치**
  - 레짐별 OOS mean/min, 레짐 전환 시 성과 급변 여부
- **결론 패턴**
  - 국면 의존 심함 → 레짐 게이트(E5)로 “나쁜 레짐을 덜 먹는” 쪽이 현실적

## 24~48시간 실행 순서(강제)
1) **E1 먼저 적용**: 로깅/해시/필수 지표 없으면 전부 FAIL 처리.
2) **E4 동시 적용**: degenerate fold를 게이트로 막아 “측정 가능한 런”만 남김.
3) **E2 적용**: 누수/과최적화 제거 후 기준선 재확립.
4) **E3 적용**: 비용 포함 성과로만 판단하도록 전환.
5) **E5 적용**: No-Delta가 레짐 기인일 때만 마지막으로 안정화.

이 순서로 돌리면, “성능이 안 움직이는” 상태가 **(a) 측정 불가/로그 문제인지 (b) 누수 제거로 정상화된 것인지 (c) 비용/제약/레짐의 구조적 한계인지** 48시간 내에 분리된다.
