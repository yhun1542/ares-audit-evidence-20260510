*   **(b) 위험/부작용:** 코드 수정 중 파이프라인 일시 중단 가능성. 기존 백테스트 기록과의 정합성 깨짐(재계산 필요).

#### **Priority 2: 개별 종목 변동성 기반 컷오프 (Risk/Logic)**
*   **(a) 필요성:** `oos_min`이 0.43까지 떨어지는 것은 특정 종목/기간에 깊은 손실을 입었다는 뜻. Tech/Bio는 개별 종목 리스크가 큼. 포트폴리오 전체 헷지보다 개별 종목의 '꼬리 자르기'가 시급.
*   **(b) 위험/부작용:** 잦은 손절(Whipsaw)로 인한 슬리피지/수수료 증가. 상승 추세 초입에서 매도될 위험.
*   **(c) 실행 실험 (Experiments):**
    1.  **[Exp_ATR_Cut_2.5]**: 개별 종목 진입 후 `Entry_Price - 2.5 * ATR(14)` 하회 시 즉시 청산 (일봉 기준).
    2.  **[Exp_Hard_Stop_8pct]**: 진입가 대비 -8% 도달 시 조건 없이 청산 (손절매).
    3.  **[Exp_Trailing_Stop_5pct]**: 고점 대비 -5% 하락 시 청산 (이익 보전).
*   **(d) PASS 조건:**

#### **Priority 3: ETF 지표 기반 동적 익스포저 (Regime/Filter)**
*   **(a) 필요성:** 현재 `exposure`가 0.47~0.84로 움직이나, `oos_min` 방어가 안 됨. 단순히 비중을 줄이는 게 아니라, "위험할 때 아예 쉬는" 로직 필요. (ETF 매매는 안 하지만 지표로 활용).
*   **(b) 위험/부작용:** 시장이 V자 반등할 때 진입 시점을 놓침(Lagging). 과최적화(Overfitting) 위험 존재.
*   **(c) 실행 실험 (Experiments):**

### 3. 성능 정체 원인 분해 (Diagnosis Checklist)

성능 지표가 움직이지 않을 때 다음 순서로 점검:

1.  **트리거 불일치 (Trigger mismatch):**
    *   *체크:* 로직상 매수 시그널이 발생했으나, `Cash < Min_Order_Value` 제한으로 주문이 기각되고 있지 않은가?
    *   *액션:* `rebalance` 로그에서 `rejected` 사유 확인.

2.  **비용 과다 반영 (Cost Drag):**
    *   *체크:* 잦은 리밸런싱으로 슬리피지(0.1% 가정 등)가 알파를 모두 잠식하는가?
    *   *액션:* 회전율(Turnover) 확인. 연간 회전율 1000% 초과 시 매매 빈도 제한(Holding Period 강제).

3.  **데이터/생존 편향 (Survivorship Bias):**
    *   *체크:* 현재 유니버스(8~14개)가 "현재 시점 우량주"로만 구성되어 과거에 상장폐지된 종목이 없는가?
    *   *액션:* 과거 시점 기준 시총 상위 리스트(Point-in-Time) 사용 여부 재검증.

4.  **레짐 불일치 (Regime Disconnect):**
    *   *체크:* 학습 기간(Train)과 검증 기간(OOS)의 시장 성격(Trend vs Mean-Reversion)이 정반대인가?
    *   *액션:* OOS 구간을 쪼개서(Rolling Window) 성능 일관성 확인.
