[분석 요약]
현재 `oos_mean: 3.32`라는 비정상적으로 높은 수치와 `degenerate_folds: [1, 2, 3, 8]`(전체 구간 중 절반 가까이 실패)가 공존함. 이는 특정 구간에 과적합(Overfitting)되었거나, 거래 비용/슬리피지가 0으로 설정된 '환상'일 가능성이 높음. 또한 로그 파일 오류로 인해 트랜잭션 분석이 불가능한 상태임.

다음 48시간 목표: **"환상 제거 및 시스템 정상화"**

### 1. 우선순위 TOP 5 (실행 체크리스트)

1.  **[Infra] Rebalance Logger 포맷 수정**: 빈 파일/JSON 에러(`Expecting value`) 해결. 거래 내역 없이는 과최적화 진단 불가.
2.  **[Sanity] 거래 비용 스트레스 테스트**: 현재 3.32라는 수치가 비용 반영 후에도 유지되는지 확인.
3.  **[Logic] Degenerate Folds(1,2,3,8) 해제**: 거래가 전혀 일어나지 않거나 터진 구간의 진입 장벽(Threshold) 완화.
4.  **[Universe] Tech/Bio 유동성 필터 강화**: 8~14개 종목 제한 시, 비주류 바이오 종목의 갭락(Gap-down) 리스크 점검.
5.  **[Risk] ETF 기반 레짐 필터(Regime Filter)**: 하락장에서 매매를 강제 중단시키는 게이트 추가.

### 2. 제안별 실행 계획 (Actionable Patches)

#### 실험 A: "Reality Check" (비용 현실화)
*   **왜 필요한가**: `oos_mean` 3.32는 현실적이지 않음. 슬리피지와 수수료가 누락되었거나, Lookahead Bias(미래 참조) 가능성 농후.
*   **위험/부작용**: 성능 지표가 급락하여 현재 챔피언 모델이 폐기될 수 있음(그러나 이는 필요한 과정임).
*   **실험 정의**:
    1.  `fee_bps`: 0 -> 10bp (0.1%) 설정.
    2.  `slippage`: 0 -> 5bp (0.05%) 설정.
    3.  Entry/Exit 시가(Open) 대신 `vwap` 혹은 `worst_case_price` 사용.
*   **게이트 (Gate)**: `oos_mean > 1.0` (3.32에서 1.0 이상으로 방어하면 성공).
*   **기대 관측치**: 거래 횟수가 급감하고, 승률이 50~55%대로 수렴하며 Degenerate Fold가 명확해짐.

#### 실험 B: "Unlock Constraints" (폴드 복구)
*   **왜 필요한가**: 폴드 1, 2, 3, 8이 죽었다는 것은 해당 기간(약세장 또는 횡보장 추정)에 시그널이 전혀 안 떴거나 손절만 나갔다는 뜻.
*   **위험/부작용**: 약한 시그널에 진입하여 MDD가 증가할 수 있음.
*   **실험 정의**:
    1.  Tech/Healthcare 유니버스 내 상위 14개 종목 강제 할당(Empty Slot 방지).
    2.  매수 시그널 임계값(Threshold)을 기존 대비 20% 하향 조정 (예: 0.7 -> 0.56).
    3.  `min_holding_days`를 1일로 단축하여 빠른 손절 허용.
*   **게이트 (Gate)**: `len(degenerate_folds) <= 1`.
*   **기대 관측치**: `oos_min`은 다소 악화되더라도, `exposure`가 전 구간에서 0.3 이상 유지되어야 함.

#### 실험 C: "Regime Cut" (시장 지표 활용)
*   **왜 필요한가**: 개별 주식(Tech/Bio)은 시장 전체 하락에 취약함. ETF(QQQ, XLV)를 매매하진 않더라도 관측 지표로 써야 함.
*   **위험/부작용**: 반응이 느려(Lagging) 반등 초입을 놓칠 수 있음(Whipsaw).
*   **실험 정의**:
    1.  Condition: `QQQ` 20일 이동평균선 아래일 때 Long 포지션 진입 금지.
    2.  Condition: `XLV` RSI(14) < 30 (과매도) 일 때만 헬스케어 비중 확대.
    3.  Target: 위 조건 미달 시 `cash` 비중 100%.
*   **게이트 (Gate)**: `worst_mdd` 계산 값 생성(None 탈출) 및 -15% 이내 방어.
*   **기대 관측치**: 하락장 구간(Degenerate folds 중 일부)에서 거래 횟수 0이 되더라도, 이는 '의도된 0'이어야 함(Log에 기록).

### 3. 성능 정체 원인 분해 (Diagnosis Logic)

성능이 움직이지 않거나 이상할 때 다음 순서로 점검하라:

1.  **트리거 오류 (Trigger Failure)**:
    *   진입 조건이 너무 까다로워(Strict) Tech/Healthcare 변동성을 담지 못함.
    *   *Check*: 일평균 거래 횟수가 8~14개 종목 대비 0.5회 미만인가?

2.  **적용 실패 (Execution Failure)**:
    *   시그널은 발생했으나 `rebalance.csv` 로그 오류처럼 시스템이 주문을 생성하지 못함.
    *   *Check*: 백테스트 로그에 "Order rejected" 또는 "Cash limit" 경고가 있는가?

3.  **노출 부족 (Exposure Gap)**:
    *   보유 현금 비중이 지나치게 높음 (Active Share 낮음).
    *   *Check*: `exposure_max`가 0.84이나, 평균 exposure가 0.2 미만인지 확인.

4.  **레짐 불일치 (Regime Mismatch)**:
    *   현재 전략이 '모멘텀'인데 시장이 '평균 회귀' 중임.
    *   *Check*: Tech(XLK)와 Healthcare(XLV)가 횡보할 때 손실이 누적되는가?

5.  **비용 누락 (Invisible Costs)**:
    *   현재 가장 유력한 원인. 수수료 0 가정 하에 초단타(Scalping)로 수익을 낸 척하고 있음.
    *   *Check*: 평균 보유 기간(Holding Period)이 3일 미만인가? (그렇다면 수수료 반영 시 필패).
