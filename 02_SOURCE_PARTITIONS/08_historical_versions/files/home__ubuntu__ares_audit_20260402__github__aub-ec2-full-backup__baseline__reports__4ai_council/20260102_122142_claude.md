## 1. 우선순위 TOP 5 패치 (48h 자동 루프용)

---

### PATCH-1: 인프라 버그 수정 (Rebalance 로그 파싱)

**(a) 왜 필요한지**
- `rebalance.csv` 로드 실패 → 성능 하락 원인 추적 불가
- No-Delta Diagnoser가 작동해도 trade-level 분해 불가능

**(b) 위험/부작용**
- 낮음. 로깅만 수정, 전략 로직 무관

**(c) 실험 체크리스트**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|----------|--------|-------------|
| P1-A | `rebalance.csv` 출력 포맷 검증 (JSON vs CSV 헤더) | 파일 10줄 head 정상 | trade_date, ticker, weight 컬럼 존재 |
| P1-B | `aub_rebalance_pinpoint.py` 경로 인자 하드코딩 제거 | `--base-log` 파싱 성공 | Error 0건 |
| P1-C | Champion run 재실행 + CSV 출력 확인 | CSV rows > 100 | 빈 파일 아님 |

**(d) PASS 조건**
```
rebalance_pinpoint.md 생성 AND diff_rows > 0
```

### PATCH-2: OOS Mean 하락 원인 분해 (Fold-level Attribution)

**(a) 왜 필요한지**
- 2.63 → 1.88 (28% 하락)의 원인이 특정 폴드/기간/섹터인지 규명 필요
- 서바이버십 또는 과최적화 누수 가능성 점검

**(b) 위험/부작용**
- 분석 only, 전략 변경 없음

**(c) 실험 체크리스트**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|----------|--------|-------------|
| P2-A | Fold별 OOS 분포 출력 (`fold_id`, `oos_sharpe`, `period`) | 전체 폴드 출력 | Worst fold 식별 |
| P2-B | Worst fold 기간 + VIX/QQQ drawdown 상관분석 | corr 계산 완료 | 레짐 의존성 수치 |
| P2-C | Tech vs Healthcare 섹터별 기여도 분리 | 섹터 attribution 출력 | 한쪽 섹터가 drag인지 확인 |

**(d) PASS 조건**
```
worst_fold_sharpe > 0.3 AND 원인 태그 1개 이상 식별 (regime/sector/overfitting)
```

---

### PATCH-3: Lookahead/Leakage 누수 점검

**(a) 왜 필요한지**
- IS vs OOS gap이 클 경우 feature leakage 의심
- 현재 IS 성능 미보고 → 반드시 비교 필요

**(b) 위험/부작용**
- 누수 발견 시 전면 재설계 필요 (높은 영향)

**(c) 실험 체크리스트**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|----------|--------|-------------|
| P3-A | IS Mean Sharpe 출력 추가 | 로그에 IS/OOS 둘 다 출력 | IS_mean, OOS_mean 쌍 |
| P3-B | IS/OOS gap 비율 계산 | gap_ratio = IS/OOS | gap_ratio < 1.5 정상 |
| P3-C | Feature timestamp audit (가격 데이터 t+1 사용 여부) | assert문 삽입 | AssertionError 0건 |

**(d) PASS 조건**
```
IS/OOS gap_ratio < 1.5 AND timestamp_audit_error == 0
```

---

### PATCH-4: 비용 민감도 스트레스 테스트

**(a) 왜 필요한지**
- 현재 비용 모델이 OOS에 미반영 가능성
- 높은 turnover가 실제로 penalty 받는지 확인

**(b) 위험/부작용**
- 비용 2x 적용 시 전략 폐기 가능성

**(c) 실험 체크리스트**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|----------|--------|-------------|
| P4-A | 현재 turnover 연간화 출력 | turnover_annual 계산 | 값 존재 |
| P4-B | 비용 1.5x 적용 재실행 | OOS_mean 출력 | 하락폭 < 20% |
| P4-C | 비용 2.0x 적용 재실행 | OOS_mean > 1.0 | 전략 생존 확인 |

**(d) PASS 조건**
```
cost_2x_oos_mean > 1.0 AND turnover_annual < 400%
```

---

### PATCH-5: Exposure 동적 범위 최적화 실험

**(a) 왜 필요한지**
- 현재 47%~84% → 하한이 낮으면 레짐 회피 과잉 의심
- Exposure floor 올려서 안정성 vs 수익 trade-off 확인

**(b) 위험/부작용**
- Exposure floor 과도 상향 시 MDD 증가

**(c) 실험 체크리스트**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|----------|--------|-------------|
| P5-A | exposure_floor=0.55 적용 | 실행 완료 | OOS_mean 비교 |
| P5-B | exposure_floor=0.60 적용 | 실행 완료 | OOS_mean 비교 |
| P5-C | 두 실험 vs champion MDD 비교 | MDD 계산 | MDD 증가 < 5%p |

**(d) PASS 조건**
```
exp_floor_60_oos >= champion_oos * 0.95 AND mdd_delta < 5%p
```

## 3. 성능 불변 시 원인 분해 트리 (Δ≈0 디버깅)

```
성능 안 움직임 (Δ OOS < 0.05)
│
├─ [트리거 미작동]
│   ├─ 신호 생성됐으나 threshold 미달
│   └─ 검증: signal_count_before vs signal_count_after
│
├─ [적용 누락]
│   ├─ 리밸런스 로직이 신호 무시
│   └─ 검증: rebalance_diff_rows == 0 이면 버그
│
├─ [노출 상쇄]
│   ├─ 롱/숏 또는 섹터 간 상쇄로 net exposure 불변
│   └─ 검증: gross_exposure 변화 vs net_exposure 변화
│
├─ [비용 상쇄]
│   ├─ 수익 증가분 = 거래비용 증가분
│   └─ 검증: gross_return vs net_return gap 비교
│
└─ [레짐 비활성]
    ├─ 실험 기간에 해당 레짐 미출현
    └─ 검증: regime_flag 분포 (실험기간 내 True 비율)
```
