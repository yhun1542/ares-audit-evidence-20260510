아래는 **다음 24~48시간** 동안 “성능이 안 움직이는(no-delta)” 상태에서 **먼저 터뜨려야 하는 리스크(누수/과최적화/서바이버십/비용 미반영/운영 리스크)** 순으로 정리한 **명령형 체크리스트 TOP5**입니다.  
(현재 로그상: `degenerate_folds=[1,2,3,8]`, `worst_mdd=None`, `lane_hash/run_hash=None`, 리밸런스 로그 로딩 실패 → **검증/진단 파이프라인이 무너져 OOS가 ‘진짜 개선/악화’를 반영 못할 가능성**이 큼)

---

## TOP5 우선순위 (24~48h)

### 1) **데이터 누수(lookahead/as-of) 즉시 차단**
**(a) 왜 필요한지**
- 누수는 OOS 평균이 “그럴듯하게” 나오면서도 **실거래/진짜 OOS에서 갑자기 붕괴**하는 1순위 원인.
- “성능이 안 움직임”의 흔한 형태가 **누수 방지 패치 후 전부 비슷해지는 현상**(기존 개선이 사실상 누수였던 것)이라, 먼저 확정해야 함.

**(b) 위험/부작용**
- 누수 제거 후 성능 급락 가능(하지만 이는 ‘악화’가 아니라 ‘정상화’).
- 데이터 정렬/머지 비용 증가(ETL 느려짐).

**(c) 최소 실험 2~3개 (아래 공용 실험 ID 재사용)**
- **[E1] As-of Hardening + Lookahead Unit Tests**
- **[E4] Purged/Embargo Walk-forward CV(과최적화/누수 동시 방어)**
- (옵션) **[E5] 리밸런스 로그/피처 타임스탬프 로깅**으로 위반 샘플 즉시 추적

**(d) PASS 조건**
- 누수 테스트 0건(“t 시점 결정이 t+1 이후 데이터를 참조” 케이스 0).
- OOS mean이 하락하더라도 **fold 간 분산↓ + 재현성↑**(동일 seed/동일 구간에서 결과 흔들림 감소).
- `degenerate_folds`가 0에 수렴(= 실제로 트레이드가 발생하고 통계가 서는 구조).

---

### 2) **서바이버십/코퍼레이트액션(상장폐지/합병/심볼변경) 바이어스 제거**
**(a) 왜 필요한지**
- US 개별주(특히 성장주)에서 **delist/merge** 미반영 시 백테스트가 “살아남은 승자만”으로 구성됨.
- Tech+Healthcare 8~14종목 소수 바스켓은 **한두 종목의 생존 편향이 성능을 지배**함.

**(b) 위험/부작용**
- 구현 난이도 상승(심볼 히스토리, delist return 처리).
- 거래 가능 종목 수가 줄어들어 포트폴리오가 더 집중될 수 있음(→ 노출/리스크 제어 필요).

**(c) 최소 실험 2~3개**
- **[E2] Survivorship-safe Universe Builder** (delist/merge/symbol mapping 포함)
- **[E1] As-of Hardening** (기업행사 반영 시점도 as-of로 고정)
- **[E5] 리밸런스/유니버스 스냅샷 로깅**(각 리밸런스 시점 구성종목/제외 사유 기록)

**(d) PASS 조건**
- 백테스트 기간 내 “존재했던 종목”이 유니버스에 포함되는지 샘플 검증 통과(특정 연도/월 임의 샘플).
- delist 발생 구간에서 수익률이 “0으로 사라지지 않고” 합리적으로 반영(갭/NaN 제거).
- 유니버스 변화 로그가 재구성 가능(리밸런스 시점별 구성 100% 재현).

---

### 3) **비용(슬리피지/스프레드/임팩트) + 회전율 미반영을 즉시 교정**
**(a) 왜 필요한지**
- 8~14종목 집중 전략은 리밸런스 한 번이 포트 전체를 크게 흔들어 **비용 민감도**가 매우 큼.
- “OOS가 안 움직임”은 사실 **비용을 넣으면 모두 비슷하게 깎여서 차이가 사라지는 현상**으로도 나타남.

**(b) 위험/부작용**
- 비용 모델을 넣으면 성능 하락 가능(정상).
- 너무 강한 비용/제약은 트레이드를 거의 안 하게 만들어 `degenerate_folds`를 악화시킬 수 있음(게이트 필요).

**(c) 최소 실험 2~3개**
- **[E3] Cost-aware Execution Model + Turnover/ADV Cap**
- **[E5] 체결가정/비용/턴오버 로깅**(리밸런스 pinpoint가 현재 실패 중이라 필수)
- **[E4] Walk-forward에서 비용 포함 성능 안정성 확인**

**(d) PASS 조건**
- 거래당/일별 총비용, turnover, 평균 보유기간이 자동 리포트로 출력되고 공백/NaN 없음.
- 비용 포함 OOS에서 **Sharpe/mean이 의미 있게 남고**, 비용을 2배로 올려도 전략이 “즉시 음수로 붕괴”하지 않음(민감도 테스트 통과).
- ADV 캡/턴오버 캡 적용 후에도 **리밸런스가 ‘0회’로 수렴하지 않음**(최소 트레이드 수 게이트 통과).

---

### 4) **과최적화/검증 붕괴(퇴화 fold, MDD 미계산)를 먼저 복구**
**(a) 왜 필요한지**
- 현재 `degenerate_folds`가 다수이고 `worst_mdd=None`이면, **평가 지표 자체가 유효하지 않거나 트레이드가 안 난 구간이 많다**는 뜻.
- no-delta(실험 9개가 있어도 챔피언이 안 바뀌는) 상황에서 가장 흔한 원인은 **평가가 고장**난 것.

**(b) 위험/부작용**
- 엄격한 게이트를 걸면 많은 실험이 “실패”로 끝나 진행이 느려짐(하지만 자동 루프에서는 오히려 필요).
- purged CV는 성능이 낮아 보일 수 있음(정상).

**(c) 최소 실험 2~3개**
- **[E4] PurgedKFold/Embargo Walk-forward + Fold Health Gate**
- **[E5] 지표 산출 강제(최소 트레이드/최소 변동/최소 리밸런스 수 미달 시 실험 FAIL로 종료)**  
- (연계) **[E3] 제약이 fold 퇴화를 유발하는지 동시 점검**

**(d) PASS 조건**
- `degenerate_folds == []` 또는 전체 fold의 90% 이상이 “정상 fold”(트레이드 수/분산/리밸런스 수 임계치 충족).
- `worst_mdd`가 항상 계산되고 None이 사라짐.
- 동일 실험을 2회 돌렸을 때 핵심 지표 변동이 허용범위 내(재현성 게이트).

---

### 5) **운영 리스크(로그/메타데이터/리밸런스 데이터 포맷) 복구**
**(a) 왜 필요한지**
- 현재 `--base-log` 경로 오류 + `rebalance.csv/jsonl` 로딩 실패 → **리밸런스 pinpoint/비용/턴오버 원인분해가 막힘**.
- `lane_hash/run_hash=None`이면 **실험 추적/회귀 분석 불가** → 자동 루프에서 no-delta가 반복됨.

**(b) 위험/부작용**
- 로깅 추가로 디스크/IO 증가.
- 포맷 변경 시 과거 실험과 비교가 끊길 수 있음(버전 필드 필요).

**(c) 최소 실험 2~3개**
- **[E5] Rebalance/Attribution Logging Schema v2 + lane_hash/run_hash 강제**
- **[E4] 게이트 결과(왜 FAIL인지) 표준화 출력**
- **[E3] 비용 항목 로깅(commission/spread/slippage/borrow) 강제**

**(d) PASS 조건**
- `aub_rebalance_pinpoint.py`가 base/cand 모두에서 **에러 없이 실행**되고 리포트가 생성됨.
- 모든 artifact JSON에 `lane_hash/run_hash/git_sha/data_snapshot_id` 존재.
- 각 리밸런스에 대해 “신호→타깃웨이트→체결→비용→사후 수익” 체인이 최소 필드로 재구성 가능.

# 공용 “실행 가능한 Patch/실험” 5개 (48시간 자동 루프용)
아래 **5개만 실제로 돌리고**, 위 TOP5는 이 5개를 조합해서 커버하도록 제한합니다(케이스 폭발 방지).

## [E1] As-of Hardening + Lookahead Unit Tests
1) **실험 정의**
- 모든 피처/라벨/유니버스 생성에 `as_of_timestamp`를 강제하고, 조인/리샘플링 시 미래 데이터 접근을 금지.
- “결정시점 t”에 사용된 모든 입력의 최대 timestamp ≤ t 인지 자동 검증.

2) **게이트**
- lookahead 위반 1건이라도 발견 시 실험 FAIL.
- 위반 샘플 top-N을 파일로 저장(심볼/필드/타임스탬프/경로).

3) **기대 관측치**
- 기존 고성능 구간이 약화되거나 평탄화될 수 있음(정상).
- 대신 fold 간 성능 편차 감소, 재현성 증가.

---

## [E2] Survivorship-safe Universe Builder (US Tech+Healthcare, 8~14 names constraint-ready)
1) **실험 정의**
- 종목 마스터를 “현재 생존 종목”이 아니라 “당시 존재했던 종목” 기준으로 구성.
- 심볼 변경/합병/상폐를 연결하고 delist return(또는 최종가 처리 규칙)을 명시.

2) **게이트**
- 임의의 과거 날짜들에 대해 유니버스 스냅샷 재생성 가능해야 함.
- NaN price로 인해 포트 가치가 끊기는 구간이 있으면 FAIL.

3) **기대 관측치**
- 백테스트 성능 소폭~큰 폭 하락 가능(정상).
- 특정 연도/섹터에서 tail event가 더 현실적으로 반영.

---

## [E3] Cost-aware Execution Model + Turnover/ADV Cap
1) **실험 정의**
- 비용 = commission + spread(예: half-spread) + slippage(ADV/vol 기반 간단 모델) + (필요 시) borrow.
- 제약: 일별 turnover 상한, 포지션별 ADV 대비 체결비율 상한, 8~14종목 유지(Tech+Healthcare).

2) **게이트**
- 비용/턴오버 리포트 필수 필드 누락 시 FAIL.
- 제약 때문에 리밸런스가 “거의 0”이 되면 FAIL(최소 트레이드 수).

3) **기대 관측치**
- 거래 잦은 전략이 크게 깎이고, 거래 적은 전략이 상대적으로 개선.
- “개선이 안 움직이던” 실험들 사이에 차이가 다시 생김(비용 민감도가 달라서).

---

## [E4] Purged/Embargo Walk-forward CV + Fold Health Gate
1) **실험 정의**
- PurgedKFold(또는 walk-forward) + embargo로 시계열 누수/정보 재사용 차단.
- Fold health metric: 각 fold 최소 리밸런스 수/트레이드 수/수익률 분산/최소 기간.

2) **게이트**
- `degenerate_folds` 발생 시 실험 FAIL 또는 해당 fold 제외가 아니라 “원인 로그”를 남기고 FAIL(숨기지 않기).
- `worst_mdd` 미계산 시 FAIL.

3) **기대 관측치**
- 과최적화된 설정이 자동으로 걸러지고, 남는 설정의 성능이 낮아 보이지만 일관성 증가.

---

## [E5] Logging/Metadata v2 (rebalance + attribution + hashes)
1) **실험 정의**
- 리밸런스 로그를 **단일 표준 포맷(JSONL 권장)**으로 고정:  
  `timestamp, universe, scores, target_weights, prev_weights, fills, costs, realized_pnl, constraints_binding_flags`
- 모든 run에 `lane_hash/run_hash/git_sha/data_snapshot_id/config_hash` 강제.

2) **게이트**
- `aub_rebalance_pinpoint.py`가 base/cand 모두 정상 실행되어 리포트 생성 못 하면 FAIL.
- hash 누락 시 FAIL.

3) **기대 관측치**
- “왜 no-delta인지”가 비용/노출/트레이드 변화로 바로 분해됨.
- 장애 시 원인 위치(데이터/전략/실행/로깅)가 즉시 특정됨.

---

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래는 **질문 없이 바로 자동 리포트/체크로 박을 수 있는 분해 트리**입니다.

## A) Trigger(신호 발생) 문제
- **체크**: 리밸런스마다 “스코어 분포(평균/표준편차/상하위 스프레드)” 로그 출력
- **증상**: 스코어 분산이 0에 수렴 → 모델이 상수 출력/피처 NaN 대체로 평탄화
- **조치**: E5로 스코어 히스토그램 저장 + E1로 as-of 위반 시점 확인

## B) Apply(포트 적용) 문제
- **체크**: `target_weights` 대비 실제 `fills/weights` 괴리(제약/라운딩/최소주문/현금 처리)
- **증상**: 신호는 변하는데 포지션이 안 바뀜 → 제약이 항상 바인딩, 또는 8~14종목 규칙 때문에 교체가 막힘
- **조치**: E3의 constraint binding flag 로깅 + 최소 교체율(예: rebalance당 1종목 이상 교체 가능성) 게이트

## C) Exposure(노출) 문제
- **체크**: (i) gross/net exposure, (ii) 섹터 노출(Tech/Healthcare 내에서도 mega-cap 편중), (iii) single-name max weight
- **증상**: 결과가 다 비슷 → 사실상 동일 종목/동일 베타(예: AAPL/MSFT/NVDA)로 수렴
- **조치**: 리밸런스마다 상위 보유종목/기여도(attribution) 출력(E5)

## D) Cost(비용) 문제
- **체크**: turnover vs pnl, 비용이 pnl의 몇 %인지, 비용 상정 1x/2x 민감도
- **증상**: 비용 포함하면 전부 비슷한 낮은 값 → 알파가 비용에 묻힘
- **조치**: E3로 비용 모델+민감도 리포트 자동 생성

## E) Regime(레짐) 문제
- **체크(관측지표로만 ETF 사용)**: QQQ(Tech), XLV(Healthcare), IWM(리스크온/오프), TLT(금리) 구간별 성과 슬라이스
- **증상**: 특정 레짐에서만 통하고 나머지에서 상쇄 → 전체 OOS 평균이 “안 움직임”
- **조치**: E4 walk-forward 결과를 레짐별로 분해해서 출력(구간 성과 테이블)

---

## 48시간 루프에 바로 넣을 “게이트 우선순위”(실패 시 즉시 중단)
1) **E5 로깅/메타데이터 게이트**(pinpoint 리포트 생성 불가면 그 실험은 의미 없음)  
2) **E1 누수 게이트**(위반 1건이라도 있으면 전부 무효)  
3) **E4 fold health 게이트**(degenerate fold / MDD None 제거)  
4) **E2 서바이버십 게이트**(유니버스 재현 불가/NaN 단절 제거)  
5) **E3 비용/턴오버 게이트**(비용 리포트 누락/트레이드 0 수렴 방지)
