아래는 **다음 24~48시간** 안에 “48시간 자동 루프”로 바로 돌릴 수 있는 **우선순위 TOP5**입니다.  
(누수→과최적화→서바이버십→비용→운영리스크 순으로 먼저 잠그고, 그 다음 성능을 움직이게 만듭니다. **미국주식 only / Tech+Healthcare 중심 / 8~14종목 / ETF는 관측지표만**)

## TOP5 우선순위 제안 (24~48h)

### 1) (Leakage/Overfit) **Fold 퇴행(degenerate) 원인 차단 + Purged Walk-Forward/Embargo 적용**
**(a) 왜 필요한지**
- 현재 `degenerate_folds: [1,2,3,8]`는 “해당 폴드에서 학습/검증이 사실상 무의미”하다는 강한 신호입니다. 보통:
  - 타깃/리턴이 거의 상수(표본 부족, 리밸런싱 이벤트 부족)
  - 시간 누수(lookahead)로 인해 일부 폴드가 깨짐
  - 특정 구간에 포지션이 거의 없어서 평가가 퇴행
- 이 상태에서 OOS mean이 좋아도 **재현성과 안정성이 무너져** 다음 실험이 “안 움직이는 것처럼” 보이거나, 우연히 좋은 챔피언이 남는 **서바이버십 편향**이 생깁니다.

**(b) 위험/부작용**
- Purge/embargo로 학습 데이터가 줄어 **단기적으로 OOS mean 하락** 가능.
- “좋아 보이던” 누수 성능이 제거되며 챔피언이 흔들릴 수 있음(정상).

**(c) 최소 실험 2~3개 (아래 ‘실험#1’로 묶어서 수행)**
- (1) **Purged Walk-Forward + Embargo**(예: 리밸런싱 주기/특징 윈도우 길이에 맞춰 embargo)
- (2) **Fold Health Gate** 추가: 폴드별 최소 거래/리밸런스 횟수, 타깃 분산, 유효 샘플 수 체크 → 미달 시 폴드 제외가 아니라 **런 자체 FAIL**
- (3) **Leakage Unit Test**: feature timestamp ≤ decision timestamp 강제(미세한 tz/close-time 이슈 포함)

**(d) PASS 조건**
- `degenerate_folds == []`
- 각 폴드에서:
  - 유효 리밸런스(또는 트레이드) 횟수 ≥ 최소치(예: 20)
  - 타깃/리턴 표준편차 ≥ ε
- OOS min이 더 악화되지 않을 것(예: 현재 `oos_min=-0.0257` 대비 **동일 또는 개선**)

---

### 2) (Survivorship) **유니버스 Point-in-Time 고정 + 상장/상폐/티커변경 처리**
**(a) 왜 필요한지**
- Tech+Healthcare 8~14종목 전략은 **유니버스의 “당시 알 수 있었는가”**가 성능을 크게 좌우합니다.
- 상폐/합병/티커변경이 빠지면 결과가 “좋게만” 나오는 서바이버십 편향이 생기고, OOS가 둔감해져 “실험이 안 움직이는” 현상이 강화됩니다.

**(b) 위험/부작용**
- PIT 유니버스로 바꾸면 과거 선택 가능 종목이 줄어 **성과 하락** 가능(정상).
- 데이터 소스/매핑 로직이 추가되어 운영 복잡도 증가.

**(c) 최소 실험 2~3개 (아래 ‘실험#2’로 묶어서 수행)**
- (1) 유니버스 생성 시점에 **PIT membership** 강제(해당 일자에 존재/거래 가능/섹터 분류 존재)
- (2) 상폐 종목 가격(마지막 거래일) 이후 처리 규칙 고정(0으로 두지 말고 **현금화/청산 규칙**)
- (3) 섹터 분류(PIT) 누락 종목은 제외(Tech/Healthcare 중심 유지)

**(d) PASS 조건**
- 백테스트 로그에 “일자별 유니버스 크기/신규편입/상폐청산 이벤트”가 남고 재현 가능
- PIT 적용 후에도:
  - 일자별 보유 종목 수(비현금) **대부분 구간에서 8~14 유지**
  - 특정 이벤트(상폐/합병) 구간에서 PnL/포지션이 비정상(가격 0, 무한 수익률 등) 발생하지 않음

---

### 3) (Cost) **거래비용/슬리피지/회전율 페널티를 목적함수에 “반드시” 반영**
**(a) 왜 필요한지**
- 현재 챔피언 메타에 `worst_mdd: None` 같은 누락이 있고, rebalance 로그도 깨져 있어 비용이 **평가에서 사실상 빠졌을 가능성**이 큽니다.
- Tech/Healthcare 8~14종목은 집중 포트폴리오라 **턴오버/슬리피지**에 매우 민감합니다. 비용을 안 넣으면 “성능이 안 움직이거나” “실전에서만 무너지는” 전형적 패턴이 납니다.

**(b) 위험/부작용**
- 비용 반영 즉시 성과 하락 가능(정상).
- 지나친 페널티는 신호가 있어도 거래를 못 하게 만들어 과도한 현금 비중을 유발.

**(c) 최소 실험 2~3개 (아래 ‘실험#3’로 묶어서 수행)**
- (1) **고정+비례 비용 모델**(수수료+스프레드) + 최소 슬리피지
- (2) **턴오버 페널티**를 objective에 추가(예: 월 회전율 목표 범위)
- (3) 리밸런싱 빈도/임계값(“trade only if |Δw|>x”)을 1개 축으로만 스윕(케이스 폭발 금지)

**(d) PASS 조건**
- 비용 차감 후 지표가 산출되고(누락 없음):
  - 비용이 총 수익의 과도 비중(예: >30%)을 차지하지 않음
  - 회전율이 상한 내(예: 월 200% 이하 등 시스템 기준)
- 비용 반영 후에도 OOS mean이 “0 근처로 붕괴”하지 않을 것(신호가 실재하면 유지되어야 함)

---

### 4) (Ops Risk) **리밸런스 로그/아티팩트 경로 정상화 + run_hash/lane_hash/메트릭 누락 제거**
**(a) 왜 필요한지**
- 현재 상태에서:
  - `file:` 비어 있음
  - `lane_hash/run_hash: None`
  - `aub_rebalance_pinpoint`가 `--base-log`를 파일로 오인 + CSV/JSON 파싱 실패
- 즉, “전략이 안 움직이는” 이전에 **관측/재현/원인분해가 불가능**합니다. 자동 루프에서 가장 치명적인 운영 리스크입니다.

**(b) 위험/부작용**
- 로깅이 늘어 디스크/IO 증가.
- 파이프라인 단계 간 경로 규약 변경 시 일시적으로 실패 가능(하지만 지금도 실패 중).

**(c) 최소 실험 2~3개 (아래 ‘실험#4’로 묶어서 수행)**
- (1) **아티팩트 규약 강제**: (champion.json, rebalance.jsonl, metrics.json) 필수 생성 + 상대/절대경로 표준화
- (2) `aub_rebalance_pinpoint.py` 입력을 “파일 경로”로만 받도록 방어(문자열 `--base-log` 같은 값 차단) + JSONL/CSV 자동 감지
- (3) 모든 런에 `run_hash/lane_hash/git_sha/config_hash` 주입, `worst_mdd` 등 필수 메트릭 누락 시 FAIL

**(d) PASS 조건**
- 아래 커맨드가 **에러 없이** 결과 파일 생성:
  - `aub_no_delta_diagnoser.py ...`
  - `aub_rebalance_pinpoint.py ...`
- 챔피언 상태에서 `file/run_hash/lane_hash/worst_mdd`가 None이 아님
- 동일 config 재실행 시 결과/로그가 재현 가능(해시 동일)

---

### 5) (Strategy/Exposure) **8~14종목 바스켓 제약 + ETF(관측) 기반 레짐 익스포저 스케일링**
**(a) 왜 필요한지**
- 현재 `exposure_min/max: 0.0 / 0.8388`로 보아 **현금 구간이 길거나**, 혹은 신호 약화 시 익스포저가 급감하는 구조일 수 있습니다. 이러면 성능 변화가 둔감해져 “안 움직이는” 것처럼 보입니다.
- 8~14종목 집중 포트폴리오는 **종목 수/최대 비중/섹터 편중** 제약이 없으면 폴드별 결과 변동이 커져 과최적화가 강화됩니다.
- ETF는 매매 금지이므로 **QQQ/XLV(또는 VHT/XLK 등) 관측지표**로만 레짐을 잡아 익스포저를 조절합니다.

**(b) 위험/부작용**
- 제약을 걸면 알파가 줄어들 수 있음(정상).
- 레짐 스케일링이 잘못되면 “좋은 구간에서 덜 타는” 언더익스포저 발생.

**(c) 최소 실험 2~3개 (실험은 #1~#4 안정화 후에만 수행; 추가 케이스 폭발 금지)**
- (1) **보유 종목 수 하드 제약(8~14)** + 단일 종목 최대 비중(예: 15%)
- (2) 섹터 비중 하드/소프트 제약(Tech+Healthcare 합 ≥ 예: 80%)
- (3) ETF 관측지표(예: QQQ 추세, XLV 상대강도)로 gross exposure를 2단(1.0 / 0.5)만 스케일

**(d) PASS 조건**
- 일자 기준:
  - 보유 종목 수 8~14 유지율 ≥ 95%
  - max single-name weight ≤ 설정치
- 레짐 구간 분해 시(상승/하락):
  - 하락 레짐에서 MDD 또는 OOS min 개선(최소 한 지표라도 유의미하게)

# 48시간 자동 루프용 “실행 가능한 Patch/Experiment” 4개 (3~5개 제한 준수)

아래 4개만 돌리면 위 TOP5를 커버합니다. 각 실험은 **(1)정의 (2)게이트 (3)기대 관측치** 형태로 자동 루프에 바로 넣을 수 있습니다.

## 실험 #1 — Purged Walk-Forward + Fold Health + Leakage Test
1) **실험 정의**
- 시간분할을 purged walk-forward로 교체 + embargo 추가
- 폴드별 최소 리밸런스/타깃 분산/유효샘플 게이트
- feature timestamp 검증(lookahead 차단)

2) **게이트(실패 시 롤백)**
- degenerate_folds 발생 시 FAIL
- 폴드 health 미달 시 FAIL
- leakage unit test 실패 시 FAIL

3) **기대 관측치**
- OOS mean이 단기 하락할 수 있으나, 폴드 분포가 정상화되고 OOS min이 안정화
- “실험이 안 움직임” → “어디가 문제인지 보임”으로 전환

## 실험 #2 — PIT Universe + 상장/상폐 이벤트 처리
1) **실험 정의**
- 유니버스 PIT 고정(일자별 존재/거래가능/섹터)
- 상폐/합병/티커변경 이벤트를 포지션 청산 규칙으로 일관 처리

2) **게이트**
- 유니버스/이벤트 로그 누락 시 FAIL
- 가격 0/무한수익률/NaN 포지션 평가 발생 시 FAIL

3) **기대 관측치**
- 성능이 “조금 덜 좋아 보일” 수 있지만, OOS가 현실적으로 변하고 실전 괴리가 줄어듦

## 실험 #3 — 비용+슬리피지+턴오버 페널티 목적함수 반영
1) **실험 정의**
- 비용 모델(고정+비례) + 슬리피지
- turnover penalty 또는 Δw 임계값 도입(스윕은 1축만)

2) **게이트**
- 비용 차감 후 메트릭 누락 시 FAIL
- 회전율/거래횟수 상한 위반 시 FAIL

3) **기대 관측치**
- gross 성과는 유지되더라도 net 성과가 안정화
- “리밸런싱이 잦아서 생긴 착시 알파” 제거

## 실험 #4 — 아티팩트/리밸런스 로그 규약 + 해시/메트릭 강제

2) **게이트**

- champion에서 file/run_hash/lane_hash/worst_mdd None이면 FAIL

3) **기대 관측치**
- “성능이 안 움직임”이 아니라 “변화가 어디서 발생했는지” 즉시 추적 가능
- 48시간 루프에서 운영 사고율 급감

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)

아래는 질문 없이 바로 적용 가능한 **분해 트리(체크리스트)** 입니다. 핵심은 “알파가 없는 것”과 “알파가 있는데 포트폴리오/비용/게이트에서 죽는 것”을 분리하는 것입니다.

## A. Trigger(신호 생성) 단계
- [ ] 일자별 신호 분산(표준편차/엔트로피)이 일정 수준 이하로 떨어지는 구간 표시  
- [ ] 신호 상위/하위 종목의 교집합이 과도하게 고정되는지(=과최적화/데이터 누수 의심)
- [ ] IC(Information Coefficient) / Rank IC를 월별로 찍어 **0 근처로 평평한지** 확인

## B. Apply(의사결정/리밸런싱 적용) 단계
- [ ] “신호 변화가 있어도 거래가 안 나는” 구간(Δw 임계값/제약/현금화 규칙) 탐지  
- [ ] 리밸런싱 이벤트 수가 폴드별로 충분한지(=degenerate fold의 직접 원인)

## C. Exposure(노출/포트 구성) 단계
- [ ] 보유 종목 수(8~14) 유지율, 단일 종목 최대 비중, 섹터 비중(Tech/HC) 시계열 로깅  
- [ ] 베타 분해: SPY/QQQ/XLV에 대한 회귀 베타로 “시장 따라간 수익” vs “초과수익” 분리(ETF는 관측만)
- [ ] 현금 비중이 높아서 성능이 둔감한지(exposure_min=0 구간 길이 확인)

## D. Cost(비용/슬리피지) 단계
- [ ] 총 수익 중 비용 비중(commission+spread+slippage) 시계열로 표시  
- [ ] turnover가 성과를 잠식하는지: turnover ↔ net pnl 상관 확인  
- [ ] 비용 모델을 2개(보수적/낙관적)만 두고 민감도 비교(케이스 폭발 금지)

## E. Regime(레짐) 단계
- [ ] QQQ 추세(상승/하락) × XLV 상대강도(방어/공격)로 4분면만 나눠 성과 테이블  
- [ ] 레짐별로 “신호는 맞는데 익스포저가 낮아 못 먹는지” vs “신호 자체가 무력한지” 분리  
- [ ] 하락 레짐에서 OOS min/MDD가 악화되면: 익스포저 스케일링(2단) 또는 리스크 컷 규칙만 최소 추가
