## 1. 우선순위 TOP 5 액션

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### P1. Degenerate Fold 근본 원인 수정
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- 40% 폴드 실패 = 특정 시장 레짐에서 신호 0 또는 position 0
- 이 상태로 OOS 평균 계산 → survivorship bias 내재
- 실전 배포 시 해당 레짐 진입하면 전략 무력화

**(b) 위험/부작용**
- 과도한 신호 완화 → 과최적화 위험 증가
- 폴드별 튜닝 시작하면 look-ahead 오염

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P1-A | `signal_floor=0.05` 추가 (신호 최소 임계값) | degenerate_folds ≤ 1 | 8+ 폴드 active |
| P1-B | Fold 1,2,3,8 날짜 범위 추출 → 레짐 태그 분석 | 레짐 라벨 확보 | VIX>25 or 특정 섹터 크래시 여부 |
| P1-C | `min_position_per_fold=2` 강제 | OOS mean ≥ 2.0 유지 | exposure_min > 0.1 |

**(d) PASS 조건**
```
degenerate_folds ≤ 1 AND oos_mean ≥ 2.5 AND oos_min > -0.05
```

### P2. MDD 측정 파이프라인 복구
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- `worst_mdd: None` = 리스크 게이트 무력화
- MDD 없이 샤프만 보면 tail risk 누수

**(b) 위험/부작용**
- 계산 추가로 백테스트 시간 10-15% 증가 예상
- 일별 PnL 로그 필수 → 저장 용량 증가

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P2-A | `metrics.py`에 `calc_mdd()` 함수 존재 확인 → 호출 누락이면 패치 | worst_mdd ≠ None | -0.05 ~ -0.25 범위 예상 |
| P2-B | 일별 equity curve JSON 출력 추가 | 파일 생성 확인 | 250+ 데이터포인트/폴드 |

**(d) PASS 조건**
```
worst_mdd != None AND worst_mdd > -0.30
```

## 3. 성능 미변동 시 원인 분해 트리

```
OOS 안 움직임
│
├─[1] 트리거 문제
│   └─ 신호가 threshold 못 넘음 → signal histogram 확인
│   └─ 확인: signal_count_per_day < 1 이면 트리거 사망
│
├─[2] 적용 문제  
│   └─ 신호 발생했으나 position sizing에서 0으로 절삭
│   └─ 확인: signal>0 but position=0 케이스 카운트
│
├─[3] 노출 문제
│   └─ position 잡았으나 exposure cap에 막힘
│   └─ 확인: exposure_max 도달 빈도
│
├─[4] 비용 문제
│   └─ gross return은 있으나 비용 차감 후 0
│   └─ 확인: gross_return vs net_return diff
│
└─[5] 레짐 문제
    └─ 특정 시장 상황에서만 전략 작동
    └─ 확인: 폴드별 OOS 분포 (std/range)
```
