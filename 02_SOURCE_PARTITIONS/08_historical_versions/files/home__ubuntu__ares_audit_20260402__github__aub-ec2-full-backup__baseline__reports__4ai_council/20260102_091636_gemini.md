### 1. 우선순위 TOP 3 제안 (Actionable Patches)

다음 액션을 48시간 루프 내에 순차적으로 실행하십시오. 최우선 과제는 Champion 모델의 '비용 민감도' 검증과 Candidate 모델의 '방어 로직' 이식입니다.

#### A. [검증] Friction Stress Test (비용/슬리피지 가혹 조건 테스트)
*   **이유:** Champion의 `Lockbox Min > 1.13`은 비현실적으로 높음. 낮은 슬리피지나 수수료 설정으로 인한 과최적화 가능성 높음. Tech/Bio 섹터는 변동성이 커 실제 체결 오차(Slippage)가 큼.
*   **위험:** 모델 폐기(Champion 탈락) 가능성. 그러나 이는 운영 리스크를 막기 위해 필수적임.
*   **실험 정의:**
    1.  `Exp_HighFriction`: 매매 수수료(TC) 10bps -> 20bps, 슬리피지 0 -> 5bps 상향 조정 후 백테스트.
    2.  `Exp_LaggedExecution`: 시그널 발생 후 'Next Open' 체결이 아닌 'Next Close' 또는 'VWAP' 가정 테스트 (Look-ahead bias 제거).
*   **게이트 (Pass Condition):**
    *   TC 상향 후 `Lockbox Mean` > 1.2 유지.
    *   `Worst MDD` 변화폭이 기존 대비 15% 이내일 것.
*   **기대 관측치:**
    *   거래 횟수가 많은 전략일수록 성능 급락 예상. (급락 시 Turnover 제한 로직 추가 필요)

#### B. [전략] Hybrid Champion (Candidate의 MRD/FSA 이식)
*   **이유:** Champion은 수익이 좋으나 MDD(-9%)가 큼. Candidate는 MDD(-4%)가 훌륭함. Candidate의 `mrd`(시장 국면 탐지)와 `fsa`(유한 상태 머신) 모듈을 Champion의 알파 로직에 결합하여 '방어형 챔피언' 생성 필요.
*   **위험:** 로직 복잡도 증가로 인한 오버피팅, 시그널 희석(수익률 저하).
*   **실험 정의:**
    1.  `Exp_Hybrid_VolSwitch`: ETF(QQQ)의 변동성이 상위 20% 구간일 때, Champion의 진입 비중을 50% 축소(Cash 비중 확대).
    2.  `Exp_Hybrid_FSA_Exit`: Champion의 청산 로직을 Candidate의 FSA 기반 Trailing Stop으로 대체.
    3.  `Exp_TechBio_Balance`: 포트폴리오 내 Tech:Healthcare 비중이 7:3을 초과하지 않도록 Hard Limit 설정.
*   **게이트 (Pass Condition):**
    *   `Lockbox Mean` > 1.6 (Champion 대비 10% 감소 허용).
    *   `Worst MDD` < -0.06 (기존 -0.09 대비 30% 개선).
*   **기대 관측치:**
    *   상승장 수익률은 다소 꺾이나, 하락 구간 방어력 급상승 기대.

#### C. [유니버스] Survivor Bias Scrubbing (생존 편향 제거)
*   **이유:** Tech/Healthcare 8~14 종목이 현재 시점의 우량주(NVDA, LLY 등)로만 고정되어 있다면 과거 데이터 백테스트는 무의미함.
*   **위험:** 유니버스 품질 저하로 인한 전체 성능 하락.
*   **실험 정의:**
    1.  `Exp_Universe_Dynamic`: 매 월말 시가총액/거래대금 기준 상위 30개 중 모멘텀 스코어로 10개 동적 재선정(Rebalancing).
    2.  `Exp_WorstCase_Drop`: 현재 유니버스에서 수익 기여도 1위, 2위 종목을 강제 제외하고 백테스트.
*   **게이트 (Pass Condition):**
    *   상위 2개 종목 제외 시에도 `Tuning Mean` > 1.0 유지.
*   **기대 관측치:**
    *   특정 종목 의존도가 높은 경우 성능 붕괴 -> 로직이 아닌 '운'이었음을 증명.

### 2. 성능 정체 시 원인 분해 (Debug Tree)

성능 지표(Mean/MDD)가 개선되지 않거나 횡보할 경우, 다음 순서로 원인을 파악하고 조치하십시오.

1.  **Trigger (시그널 발생 빈도)**
    *   *현상:* 거래 횟수가 너무 적거나(과소), 너무 많음(노이즈).
    *   *조치:* 필터 조건(Threshold) 완화 또는 강화. 최근 3개월 거래 횟수 0건이면 '죽은 로직'.

2.  **Application (주문 집행)**
    *   *현상:* 시그널은 매수인데 포지션이 0.
    *   *조치:* 자금 관리(Money Management) 모듈 확인. 한 종목당 최대 비중 제한에 걸려 매수 실패했는지 로그 확인.

3.  **Exposure (시장 노출)**
    *   *현상:* MDD는 낮은데 수익도 낮음.
    *   *조치:* 현금 보유 비중(Cash Ratio) 확인. 두려움에 의한 과도한 현금 보유가 수익을 갉아먹는지 점검. 레버리지 1.0 -> 1.2 실험 고려 (단, MDD 감수).

4.  **Regime (시장 국면 불일치)**
    *   *현상:* 특정 연도(예: 2022)에만 박살남.
    *   *조치:* Tech/Healthcare는 금리 민감도가 다름. 거시 지표(금리 ETF: TLT 등)를 Feature로 추가하여 Regime Filter 강화.

5.  **Cost (비용 누적)**
    *   *현상:* Gross Return은 좋은데 Net Return이 나쁨.
    *   *조치:* 잦은 손절매(Whipsaw) 발생 여부 확인. 진입 후 최소 보유 기간(Holding Period) 강제 설정 실험.
