## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — **명령형 체크리스트**
아래는 **누수/과최적화/서바이버십/비용 미반영/운영 리스크**부터 먼저 잠그는 순서로 정렬함. (미국주식 only, Tech+Healthcare 8~14종목, ETF 매매 금지/지표용만)

---

# 1) **리밸런스/실험 아티팩트 표준화 + 재현성 고정** (운영 리스크 1순위)
### (a) 왜 필요한지
- 현재 로그에서 **rebalance pinpoint가 “No rebalance data found”**로 실패(파일 포맷/경로/JSON 깨짐). → “성과가 안 움직임”이 **실제 전략 문제인지, 리밸런스가 기록/적용이 안 된 건지** 구분 불가.
- Champion에 **lane_hash/run_hash가 None**, worst_mdd도 None → **실험 식별/추적/회귀검증 불가능**.
- 이런 상태에서 OOS mean이 좋아도 **서바이버십/운영 실패**로 실전 불가.

### (b) 위험/부작용
- 로깅/직렬화 변경으로 과거 리포트 파이프라인이 깨질 수 있음.
- “지표가 바뀌지 않았는데 성과만 바뀌는” 회귀가 발생할 수 있음(랜덤시드/캘린더/데이터정렬 영향 노출).

### (c) 최소 실험(공용 실험 ID로 제한)
- **[E1] 아티팩트 강제 생성/파싱 통과 실험**
- **[E2] (간접) 재현성/해시 고정으로 fold 퇴행 탐지**

### (d) PASS 조건
- **rebalance.csv 또는 rebalance.jsonl**이 매 런마다 생성되고, `aub_rebalance_pinpoint.py`가 **에러 없이 끝날 것**
- champion JSON에 **run_hash/lane_hash/worst_mdd**가 채워질 것
- 동일 입력에서 **메트릭 재현 오차가 허용범위(예: oos_mean ±0.5%p 이내)**로 유지될 것

---

# 2) **degenerate_folds 제거 + 누수/시간정렬(shift) 감사** (누수/과최적화 1순위)
### (a) 왜 필요한지
- champion에 **degenerate_folds: [1,2,3,8]** → OOS 추정이 깨졌거나(표본 0/상수예측/결측 대량), 데이터 split이 잘못되었을 가능성 큼.
- degenerate가 있으면 “개선 실험”이 실제로는 **평가가 안 돌아가서 변화가 0**으로 보일 수 있음(= no-delta의 가짜 원인).

### (b) 위험/부작용
- 누수 제거/퍼지드 스플릿 적용 시 **성과가 하락**할 수 있음(하지만 그게 정상).
- 샘플 수 감소로 분산이 증가할 수 있음.

### (c) 최소 실험
- **[E2] Purged walk-forward(embargo 포함) + fold 건강도 게이트**
- **[E3] (간접) 비용/턴오버 추가 시 fold 안정성 변화 관측**

### (d) PASS 조건
- degenerate_folds가 **빈 배열**이 될 것
- 각 fold에서 **거래일 수/리밸런스 이벤트 수 최소 기준**(예: 거래일 ≥ 120, 리밸런스 ≥ 8)을 만족할 것
- OOS 분포에서 **특정 fold만 과도하게 튀는 현상(극단값)**이 완화될 것(예: fold별 oos_mean 분산 감소)

---

# 3) **비용(슬리피지/스프레드/수수료) + 턴오버 패널티를 목표함수에 반영** (비용 미반영 1순위)
### (a) 왜 필요한지
- 현재 “rebalance 데이터 미확보” 상황과 결합하면, 실제로는 **리밸런스가 잦아 비용으로 상쇄**되는데 백테스트가 못 잡았을 수 있음.
- “성과가 안 움직임”이 **알파가 없어서**가 아니라 **비용이 알파를 전부 깎아서**일 수 있음.

### (b) 위험/부작용
- 비용 모델이 과도하면 전략이 **거의 거래하지 않는 방향**(또 다른 no-delta)으로 수렴 가능.
- 현실적인 비용을 넣으면 OOS mean이 떨어질 수 있음(정상).

### (c) 최소 실험
- **[E3] 비용 ON/OFF A/B + 턴오버 캡 실험**
- **[E4] (간접) 포트폴리오 제약(8~14, 집중도 제한)과 결합 시 비용 민감도 관측**

### (d) PASS 조건
- 비용 ON에서도 **순수익(net) OOS mean이 의미 있게 양수**로 유지(예: net oos_mean ≥ gross의 60% 이상 유지 또는 net oos_mean ≥ 내부 최소치)
- 연환산 턴오버가 **상한 이하**(예: 300~500%/yr 같은 시스템 기준)로 통제될 것
- 리밸런스 이벤트별 비용 기여도가 리포트로 출력될 것

# 4) **포트폴리오 구성/노출 제약을 “운영 가능한 형태”로 고정 (8~14 Tech+Healthcare)** (노출/운영 리스크)
### (a) 왜 필요한지
- 현재 노출이 `0.0 ~ 0.8388`로 흔들림 → 타이밍/스케일 문제로 **거의 캐시** 또는 **과노출**로 갈 수 있음.
- “성과가 안 움직임”은 모델이 아니라 **포트폴리오 레이어에서 클리핑/라운딩/최소주문단위**로 변화가 죽어서 발생하는 경우가 흔함.

### (b) 위험/부작용
- 제약을 강화하면 단기 성과는 악화될 수 있음(대신 재현성/실전성 증가).
- Tech+Healthcare로 제한하면 레짐에 따라 **상관/집중 리스크**가 커질 수 있음(그래서 변동성 타게팅이 필요).

### (c) 최소 실험
- **[E4] 8~14 종목 강제 + 섹터 필터(Tech/Healthcare) + 단일종목 상한 + 변동성 타게팅**
- **[E5] (간접) 레짐 게이트 적용 시 노출이 자연스럽게 줄어드는지 관측**

### (d) PASS 조건
- 항상 **보유 종목 수 8~14 유지**
- 단일 종목 비중 상한(예: 15% 또는 12.5%) 준수
- 총 노출이 목표 밴드(예: 30~80%)를 벗어나지 않음
- 리밸런스 시 “목표→실행” 차이(라운딩/클립) 리포팅이 남을 것(= no-delta 원인 추적 가능)

# 5) **레짐(위험선호/변동성/금리) 기반 게이트로 꼬리손실 통제** (레짐/트리거)
*(ETF는 매매 금지, 지표로만 사용: SPY/QQQ/XLK/XLV, 그리고 금리/변동성 프록시)*

### (a) 왜 필요한지
- Tech/Healthcare 중심 포트는 레짐 민감(성장주/금리/리스크오프).
- OOS min이 이미 음수로 찍힘(`oos_min: -0.0257`) → “평균은 괜찮은데 특정 구간에서 깨짐” 패턴 가능.

### (b) 위험/부작용
- 레짐 게이트가 잘못되면 **기회 구간을 놓쳐** 평균수익이 하락.
- 레짐 신호가 과최적화되면 미래에 무력화.

### (c) 최소 실험
- **[E5] 레짐 게이트 ON/OFF (SPY 추세 + SPY realized vol + (XLK/XLV 상대강도) 기반)**
- **[E3] (간접) 비용 포함 시 레짐 게이트가 거래를 줄여 net 개선되는지 확인**

### (d) PASS 조건
- tail 구간에서 방어: **oos_min 개선**(예: -2.6% → -1.5% 이상으로 완화 같은 내부 기준)
- 레짐 OFF 대비 **MDD 또는 CVaR 지표가 유의 개선**
- 게이트가 “항상 OFF/항상 ON”으로 고정되지 않고, 48시간 루프에서 **전환 이벤트가 관측**될 것

## 48시간 자동 루프용 “실행 가능한 실험/패치” 5개 (3~5개 제한 준수)
각 실험은 (1) 정의 (2) 게이트 (3) 기대 관측치로 고정.

---

## [E1] **리밸런스/아티팩트 강제 생성 + 파서 통과**
1) **실험 정의**
- 백테스트 종료 시 반드시 아래 산출:
  - `rebalance.csv`(또는 `rebalance.jsonl`) : 날짜, 타겟웨이트, 체결웨이트, 델타, 추정비용, 체결가정
  - champion JSON: `run_hash`, `lane_hash`, `worst_mdd`, `turnover`, `num_rebalances`
- `aub_rebalance_pinpoint.py` 입력 경로를 “--base-log=--base-log” 같은 더미가 아니라 **실제 파일 경로**로 강제.

2) **게이트**
- 파일 존재/파싱 성공/스키마 검사 통과
- rebalance 이벤트 수가 0이 아니거나(전략 의도상 0이면) “0인 이유(게이트/제약/시그널 0)”가 리포트에 기록

3) **기대 관측치**
- pinpoint 리포트가 생성되고, “no-delta”가 **신호/제약/라운딩/게이트** 중 어디서 발생하는지 라벨링 가능

---

## [E2] **Purged Walk-Forward + Fold 건강도 게이트(누수/degenerate 제거)**
1) **실험 정의**
- split을 **시간 순서 고정 + purge/embargo**로 교체
- 각 fold에 대해:
  - 결측률 상한
  - 샘플 수/거래일 수/리밸런스 수 하한
  - 예측값 분산(상수 예측 감지)
- 위반 시 fold를 “degenerate”로 표기하는 대신 **실험 자체 FAIL** 처리(자동루프에서 조기 중단).

2) **게이트**
- degenerate_folds = []
- fold별 리밸런스/거래일 하한 충족

3) **기대 관측치**
- oos_mean이 내려갈 수 있으나, fold별 편차가 줄고 결과가 신뢰 가능해짐
- “성과가 안 움직임”이 평가 오류였는지 즉시 판별 가능

---

## [E3] **비용 모델 ON/OFF + 턴오버 캡**
1) **실험 정의**
- 비용 구성요소 최소셋:
  - 고정 커미션(0으로 두더라도 명시)
  - 스프레드/슬리피지(bps, 유동성 기반 간단 모델)
  - 리밸런스 시 거래대금 기반 비용 산출
- 목표함수에 turnover penalty 추가(또는 사후 게이트로 turnover cap)

2) **게이트**
- net 성과 리포트(비용 전/후) 반드시 출력
- 턴오버 상한 준수 (초과 시 FAIL)

3) **기대 관측치**
- gross→net 갭이 커지면 “알파는 있는데 비용이 잡아먹음”으로 원인 확정
- 거래가 지나치게 줄면(또 다른 no-delta) 비용 패널티 강도 재조정 근거 확보

---

## [E4] **포트폴리오 제약 레이어 고정 (8~14, Tech+Healthcare, 집중도/노출/변동성)**
1) **실험 정의**
- 유니버스: 미국주식, 섹터 Tech+Healthcare로 필터(분류 소스 고정)
- 포트폴리오:
  - 보유 8~14 강제
  - 단일 종목 상한
  - 총 노출 30~80% 밴드
  - 변동성 타게팅(예: 목표 연환산 vol)
- 주문 라운딩/클리핑 이후 “실제 체결 웨이트 변화량”을 로깅

2) **게이트**
- 보유 수/섹터/노출/집중도 제약 위반 = FAIL
- 리밸런스 델타가 장기간 0이면 FAIL(원인코드와 함께)

3) **기대 관측치**
- “전략은 변하는데 포트가 안 변한다” 문제(라운딩/제약) 즉시 드러남
- 노출 안정화로 oos_min/MDD 쪽이 개선될 가능성

---

## [E5] **레짐 게이트(지표용 ETF 활용)로 리스크 스케일링**
1) **실험 정의**
- ETF는 **매매 금지**, 지표만 사용:
  - SPY 추세(예: 50/200)
  - SPY 실현변동성(20~60d)
  - XLK/XLV 상대강도(Tech vs Defensive proxy)
- 레짐에 따라:
  - 총 노출 스케일(예: risk-off면 0.3배)
  - 또는 리밸런스 빈도 축소(쿨다운)

2) **게이트**
- 게이트 전환 이벤트가 일정 빈도로 발생(항상 ON/OFF면 FAIL)
- risk-off 구간에서 tail metric 개선(최소 oos_min 또는 CVaR 개선)

3) **기대 관측치**
- 평균 수익은 소폭 감소할 수 있으나, 꼬리 손실/최저점이 개선되어 실전 적합성 상승

# 성능이 안 움직일 때 “원인 분해” 트리 (트리거/적용/노출/비용/레짐)
아래 순서대로 로그/리포트에서 **증거를 붙이며** 원인을 확정하라. (각 단계는 “관측 지표”를 반드시 남겨 자동루프에서 회귀탐지)

## A. Trigger(신호가 변하나?)
- **관측:** 예측값 분산, 상위랭크 종목 교체율, 시그널 히스토그램(클리핑/표준화 후)
- **고장 패턴:**  
  - 예측값이 거의 상수(스케일링/정규화 버그, feature 전부 NaN/0)  
  - 상위랭크가 고정(데이터 스냅샷 고정/서바이버십/룩어헤드)

## B. Apply(신호가 포트로 반영되나?)
- **관측:** 타겟웨이트 vs 체결웨이트, 델타(Δw) 분포, 최소주문단위/라운딩 후 변화량
- **고장 패턴:**  
  - 제약(8~14, 상한/하한, 노출밴드) 때문에 항상 같은 해  
  - rebal gate(쿨다운/threshold)가 너무 커서 변화 0

## C. Exposure(노출이 죽었나/과해졌나?)
- **관측:** 총 노출, 섹터 노출(Tech/Healthcare), 단일종목 최대비중, 베타(대 SPY)
- **고장 패턴:**  
  - 노출이 0 근처로 붙음(리스크 타게팅/게이트 과도)  
  - 노출이 상한에 붙어 더 개선 여지 없음(항상 풀리스크)

## D. Cost(비용이 알파를 상쇄하나?)
- **관측:** gross→net 갭, 리밸런스별 비용 기여도, 턴오버, 거래대금/유동성 대비 임팩트
- **고장 패턴:**  
  - gross는 움직이는데 net이 평평(비용 민감)  
  - 비용 모델이 너무 강해 거래가 사라짐(= no-delta)

## E. Regime(특정 레짐에서만 깨지나?)
- **관측:** 레짐별 성과 분해(추세/변동성/금리 민감 구간), oos_min 발생 구간 태깅
- **고장 패턴:**  
  - 특정 국면에서만 손실 집중(Tech 성장주 리스크오프/금리 급등)  
  - 레짐 신호가 미래에선 무력(과최적화)

## 즉시 실행 순서(48시간 내)
1) **E1 먼저 실행**해서 “리밸런스/로그/해시/파서”를 정상화하라. (지금은 진단 도구가 제대로 못 돎)
2) 다음으로 **E2 실행**해 degenerate_folds를 0으로 만들고, 누수/평가 붕괴를 제거하라.
3) 그 다음 **E3→E4→E5** 순으로 비용/운영 제약/레짐을 얹어 “실전 가능한 형태”에서 성능이 움직이는지 관측하라.

이 5개만 돌려도 “안 움직임”이 **(1) 평가/로그 결함 (2) 신호 무변화 (3) 포트 반영 실패 (4) 비용 상쇄 (5) 레짐 붕괴** 중 어디인지 48시간 내에 대부분 확정된다.
