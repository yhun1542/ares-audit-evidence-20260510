## 24~48시간 TOP5 우선순위(코드/아키텍처/전략) — “명령형 체크리스트”
(현재 ONE TRUTH 기준: `file` 비어있음, `lane_hash/run_hash None`, `worst_mdd None`, `degenerate_folds [1,2,3,8]`, 리밸런스 로그 로딩 실패 → **성능 논의 이전에 파이프라인/검증이 먼저**)

### 1) **프로비넌스/로깅/아티팩트 무결성 복구 (운영 리스크 최우선)**
- [ ] Champion JSON에 `file`, `run_hash`, `lane_hash`, `data_hash`, `config_hash`, `code_git_sha`, `cost_model_version` 강제 기록
- [ ] 리밸런스 로그를 **단일 포맷(jsonl)로 강제**하고, CSV/JSON 혼용 제거
- [ ] 리포트 생성기가 읽는 입력 경로를 “옵션 문자열”이 아닌 “실제 파일 경로”로만 받게 스키마 검증
- [ ] OOS Mean이 서로 다르게 찍히는(3.32 vs 2.63) 케이스를 **동일 base/cand 참조 여부**로 자동 검출 후 실패 처리

**(a) 왜 필요한지**
- 지금 상태는 “전략 개선”이 아니라 **측정 시스템이 깨져서 no-delta/리밸런스 부재**가 발생할 확률이 큼.  
- `degenerate_folds`와 결합되면, 실험이 돌아도 **의미 있는 OOS 비교 자체가 불능**.

**(b) 위험/부작용**
- 단기적으로 실험 실패율 증가(의도된 fail-fast).
- 과거 결과와 숫자가 달라질 수 있음(기존이 잘못 측정됐을 가능성 포함).

**(c) 최소 실험(아래 실험팩에서 선택)**
- E1(로깅/스키마 강제) + E2(폴드/누수 게이트) **필수**
- + E3(비용모델) 권장

**(d) PASS 조건**
- (필수) 모든 런에서 `run_hash/lane_hash/file` non-null, 리밸런스 로그가 1개 이상 생성
- (필수) `aub_rebalance_pinpoint`가 base/cand 모두 로딩 성공
- (필수) 동일 run_hash에 대해 OOS Mean이 리포트/요약 간 불일치 0건


---

### 2) **누수/과최적화/폴드 퇴화(degenerate folds) 제거 (품질 리스크 최우선)**
- [ ] Walk-forward time split에 **purge/embargo** 적용(신호 lookahead 방지)
- [ ] 폴드별 최소 거래일/샘플 수 미달 시 “스킵”이 아니라 **런 실패 처리**
- [ ] 생존편향 방지: 유니버스가 “현재 구성 종목”만 쓰지 않도록(상장폐지/합병 반영) 데이터 레이어 검증
- [ ] corporate action(분할/배당) 반영 시점 테스트(가격/리턴 정합성) 추가

**(a) 왜 필요한지**
- `degenerate_folds [1,2,3,8]`은 “OOS 평균이 좋아도” **실제 일반화가 불가능**한 전형적 신호.
- 누수/폴드 퇴화가 있으면, 24~48시간 실험이 전부 “가짜 개선”으로 귀결.

**(b) 위험/부작용**
- 성능 수치 하락 가능(정상).
- 거래 횟수/노출이 줄어 OOS mean이 낮아질 수 있음.

**(c) 최소 실험**
- E2(시간분할+purge/embargo+폴드 게이트) + E1(검증/아티팩트)  
- + E4(포트폴리오 제약)로 과최적화 완화

**(d) PASS 조건**
- degenerate_folds = 0
- 폴드별 샤프/수익이 “한 폴드만 압도”하지 않고 분산(예: 최상/최하 폴드 성과 비율 상한)
- OOS min이 음수라도, **폴드별 분포**가 설명 가능한 수준으로 안정(극단값 감소)


---

### 3) **비용(슬리피지/스프레드/회전율) 미반영 제거 (수익 착시 방지)**
- [ ] 체결비용(스프레드+슬리피지)을 **거래대금 비례**로 기본 탑재
- [ ] 회전율(turnover) 패널티 혹은 상한(리밸런스 빈도 폭주 방지)
- [ ] 공매도 사용 시 borrow fee/HTB 가드(불가능하면 short 금지)

**(a) 왜 필요한지**
- Tech/Healthcare 8~14종목 집중전략은 리밸런스가 잦으면 **비용이 PnL을 삼킴**.
- “OOS mean 2~3대”가 비용 포함 후 0 근처로 수렴하는 케이스가 가장 흔함.

**(b) 위험/부작용**
- 기대수익 감소, 전략이 “거의 거래 안 하는 형태”로 붕괴 가능.
- 비용 파라미터 과대 설정 시 과도한 보수성.

**(c) 최소 실험**
- E3(비용모델+회전율 캡) + E4(리밸런스/보유종목 제약)  
- + E5(레짐 스케일링)으로 위험구간 거래 감소

**(d) PASS 조건**
- 비용 차감 후에도 OOS mean이 유의미하게 양수 유지(그리고 turnover가 상한 내)
- 거래 횟수/거래대금이 “설명 가능한 수준”으로 감소하며, OOS min 악화가 완화

### 4) **포트폴리오 구성/노출(8~14, Tech+Healthcare) 강제 + 리밸런스 규율화**
- [ ] **미국주식 only**, 유니버스는 Tech+Healthcare에서 8~14 종목으로 강제(ETF 매매 제외)
- [ ] 단일 종목 최대 비중/섹터 편중 상한 설정(집중 폭주 방지)
- [ ] 노출 0~0.84로 들쭉날쭉이면, 변동성 타게팅/포지션 스무딩으로 “급격한 on/off” 완화

**(a) 왜 필요한지**
- 현재 exposure max 0.84 / min 0.0은 레짐에 따라 “완전 캐시 ↔ 거의 풀”로 튀는 패턴 가능 → OOS min/드로우다운 악화 요인.
- “종목 수/섹터” 제약이 없으면 백테스트가 우연 종목에 과최적화됨.

**(b) 위험/부작용**
- 알파가 줄어드는 대신 안정화(의도).
- 종목 제약이 강하면 기회 손실.

**(c) 최소 실험**
- E4(8~14 강제+비중/섹터/리밸런스 규율) + E3(비용)  
- + E2(누수/폴드)로 과최적화 방지

**(d) PASS 조건**
- 보유종목 수가 항상 8~14 유지, 단일종목 비중 상한 준수
- 리밸런스 간격/회전율이 목표 범위 내
- OOS 변동(폴드별/기간별)이 감소하고, 최악 구간 성과가 개선(“tail” 완화)

### 5) **레짐(Tech/HC 국면) 관측지표 기반 노출 스케일링(ETF는 지표로만)**
- [ ] ETF(예: QQQ, XLV)를 **매매하지 말고**, 추세/변동성 지표로만 사용
- [ ] risk-on일 때만 총노출 상향, risk-off일 때는 노출 하향(또는 신규 진입 금지)
- [ ] 48시간 루프에서 “지표 계산 → 게이트 통과 시만 트레이드”로 연결

**(a) 왜 필요한지**
- 성능이 “안 움직이는” 원인 중 하나가 레짐 무시로 인한 **신호 무력화/손실 회피 실패**.
- Tech/Healthcare는 리스크-온/오프 민감도가 커서 노출 스케일링 효과가 큼.

**(b) 위험/부작용**
- 너무 보수적이면 기회를 놓쳐 OOS mean 하락.
- 지표가 느리면 진입이 늦어질 수 있음.

**(c) 최소 실험**
- E5(레짐 스케일링) + E4(포트폴리오 제약)  
- + E3(비용)으로 “거래 줄이기” 효과 검증

**(d) PASS 조건**
- risk-off 구간의 드로우다운/최악 손실 개선
- 노출 on/off가 덜 급격해지고, OOS min이 완화(극단 손실 감소)
- 거래가 줄면서도 수익/리스크 비가 개선

## 48시간 자동 루프용 “실행 가능한 실험팩(3~5개)”  
아래 **5개만** 돌려서 TOP5 우선순위에 매핑되도록 구성(케이스 폭발 방지). 각 실험은 (1)정의 (2)게이트 (3)기대 관측치 형태.

### E1) 아티팩트/로깅 스키마 강제 패치
1) **실험 정의**
- 런 시작 시 `run_hash = hash(code_sha, data_hash, config_hash)` 생성
- 결과 JSON에 필수 필드 강제(non-null), 리밸런스 로그는 `rebalance.jsonl`로 통일 저장
- 리포트/도구가 파일 경로를 못 읽으면 즉시 실패(fail-fast)

2) **게이트**
- 필수 필드 누락/NULL → 런 실패
- 리밸런스 로그 0건 → 런 실패
- 요약 OOS mean과 리포트 OOS mean 불일치 → 런 실패

3) **기대 관측치**
- “No rebalance data found”류 에러 0건
- champion/diagnoser 숫자 불일치 해소
- 이후 실험(E2~E5)에서 “변화가 없는 이유”가 측정 문제인지 전략 문제인지 분리 가능


### E2) 시간분할+purge/embargo + 폴드 퇴화 제거 게이트
1) **실험 정의**
- Walk-forward split에 purge/embargo 적용
- 폴드별 최소 샘플/거래일 조건 미달 시 실패 처리
- 생존편향 방지 체크(가능하면 delisted 포함 데이터셋 사용/검증)

2) **게이트**
- degenerate_folds 발생 시 런 실패
- train/test 기간 겹침(lookahead 가능성) 검출 시 실패

3) **기대 관측치**
- OOS mean이 다소 내려가도 분포가 안정화
- 폴드 간 편차 감소(한 폴드 “대박” 패턴 완화)


### E3) 비용/슬리피지/회전율 반영(net PnL) 패치
1) **실험 정의**
- 거래대금 기반 슬리피지 + 고정 커미션(또는 bps) 적용
- turnover 상한 또는 패널티 추가(예: 목표 이하로 유도)
- 공매도면 borrow 비용/불가 처리(가능하지 않으면 short 차단)

2) **게이트**
- 비용 차감 후 OOS mean이 임계값 미만이면 fail(“착시 전략” 컷)
- turnover가 상한 초과 시 fail

3) **기대 관측치**
- gross→net 격차가 수치화되어 “개선 방향(신호 vs 비용)”이 명확
- 불필요한 잦은 매매가 줄어듦


### E4) 포트폴리오 제약(8~14) + 섹터/비중/리밸런스 규율
1) **실험 정의**
- 유니버스: 미국 Tech+Healthcare에서만, 보유 8~14 강제(ETF 매매 금지)
- 단일 종목 max weight(예: 12~15%), 섹터 편중 상한
- 리밸런스 주기 고정(예: 주 2회) 또는 신호 변화 임계값 기반

2) **게이트**
- 보유종목 수/비중/섹터 제약 위반 시 fail
- 리밸런스 과다(회전율 상한 초과) 시 fail

3) **기대 관측치**
- 노출/성과 변동성 완화
- 특정 종목 원툴 과최적화 감소, OOS tail 개선


### E5) 레짐 관측(ETF는 지표) 기반 노출 스케일링
1) **실험 정의**
- QQQ(Tech), XLV(Healthcare)로 추세/변동성 지표 계산(매매 없음)
- risk-on에서만 총노출 상향, risk-off에서 신규 진입 제한/노출 감산

2) **게이트**
- 지표 계산 실패/결측치 발생 시 fail
- 노출 변화가 과도(급격한 0↔max)하면 스무딩 없이는 fail

3) **기대 관측치**
- risk-off 구간 손실 완화, OOS min 개선
- 거래 빈도 감소 + 비용 절감과 결합 시 net 개선 가능

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **순서대로** 확인(위 실험팩의 관측치로 자동 판정되게 만드는 게 목적).

### A) 트리거(신호 생성) 문제
- 신호가 상수/클리핑으로 죽었는지: 신호 분산(표준편차), 상위/하위 분위 스프레드 모니터링
- 지표 업데이트 주기 불일치(예: 일봉인데 주봉처럼 고정): feature timestamp/라벨 timestamp 감사 로그
- 결측치 처리로 전부 동일값 대체됐는지: 결측률/대체 비율 로그

### B) 적용(주문/리밸런스) 문제
- 신호는 변하는데 거래가 0건:  
  - 포지션 제한이 과도한지(8~14 강제/비중 상한/섹터 상한 충돌)  
  - 리밸런스 조건이 너무 빡센지(임계값 과대)
- 리밸런스 로그 부재면 **전략 문제가 아니라 운영/로깅 문제(E1)**

### C) 노출(포지션 사이징) 문제
- exposure min=0이 자주 나오면: 레짐 게이트가 상시 risk-off로 잠겼는지, 혹은 변동성 타게팅이 과도한지
- max가 0.84에서 멈추면: 레버리지/현금 규칙, 포지션 수 제약, 잔고 계산 버그 점검

### D) 비용(슬리피지/스프레드/회전율) 문제
- gross는 괜찮은데 net이 0 근처: 회전율 과다/스프레드 민감 종목 편중
- 비용모델이 “0”으로 사실상 꺼져 있으면: 성능이 움직여도 실전 무의미(우선 E3)

### E) 레짐(시장 국면) 문제
- 특정 구간(금리 급등/리스크오프)에서만 깨지면: 레짐 스케일링(E5)로 tail 관리
- Tech/HC 상대강도 국면이 바뀌면: QQQ vs XLV 상대 추세를 지표로 노출 비중을 이동(단, 종목은 Tech+HC 내에서만)

## 24~48시간 실행 순서(권장) — 실패를 빨리 내서 시간 절약
- [ ] **T+0~6h:** E1 적용 → 로깅/리밸런스/해시/불일치 게이트로 파이프라인 고정
- [ ] **T+6~18h:** E2 적용 → degenerate_folds 0 만들 때까지(실패하면 수정 반복)
- [ ] **T+18~30h:** E3 적용 → net 기준으로 “살아있는지” 판정
- [ ] **T+30~42h:** E4 적용 → 8~14, Tech+HC 강제 + 리밸런스 규율로 과최적화 절단
- [ ] **T+42~48h:** E5 적용 → tail 개선 확인(특히 OOS min/최악구간)

이 순서대로면, “성능이 안 움직이는 이유”를 **측정/누수/비용/제약/레짐** 중 어디에서 막히는지 48시간 내에 자동으로 분리해낼 수 있게 된다.
