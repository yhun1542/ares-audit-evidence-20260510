### PATCH 1: tuning_min 0.05 원인 규명 (최우선)
### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- tuning_min=0.05 vs tuning_mean=1.76 → 33배 차이
- 특정 fold에서 전략 완전 실패 or 데이터 오염 가능성
- 이 문제 미해결 시 모든 개선 실험 무의미

**(b) 위험/부작용**
- 해당 fold 제거 시 survivorship bias 발생 가능
- 실제 레짐 취약점일 수 있음 (제거하면 안 됨)

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P1-E1 | 전체 fold별 return 분포 덤프, min fold 식별 | 완료 | fold_id, 해당 기간 |
| P1-E2 | 해당 fold 기간 종목별 PnL 분해 | 완료 | 단일 종목 > 90% 손실 여부 |
| P1-E3 | 해당 fold look-ahead bias 체크 (시그널 생성일 vs 가격 참조일) | PASS: 누수 無 | 시그널 t, 가격 t+1 확인 |

**(d) PASS 조건**
```
✅ PASS: 누수 無 & 특정 레짐(예: 2022-Q1) 확인 → 레짐 필터 실험으로 전환
❌ FAIL: 누수 발견 → 파이프라인 수정 후 전체 재실행
```

## 2. 48H 자동 루프 실행 순서

```bash
# ===== HOUR 0-6: PATCH 1 (tuning_min 진단) =====

  --output baseline/reports/cost_impact.json

  --champion baseline/champion_v5_20251231.json \
  --output baseline/reports/attribution.json

# GATE: top3_contribution < 0.70

# ===== HOUR 18-30: PATCH 4 (레짐) =====

  --champion baseline/champion_v5_20251231.json \

# ===== HOUR 30-42: PATCH 5 (시그널 decay) =====
python3 experiment_system/tools/temporal_split.py \
  --champion baseline/champion_v5_20251231.json \
  --periods "2023-H2" \
  --output baseline/reports/temporal_performance.json

# ===== HOUR 42-48: 종합 판정 & HANDOFF 생성 =====

  --registry experiment_system/config/module_registry.yaml \
  --output baseline/reports/next_fix.md
```

## 3. 성능 불변 시 원인 분해 트리

```
성능이 안 움직임
│
├─[1] 트리거 실패
│   └─ 시그널이 발생하지 않음 (임계값 과다)
│   └─ 점검: signal_count per fold
│
├─[2] 적용 실패  
│   └─ 시그널 → 포지션 변환 로직 버그
│   └─ 점검: position_change_count vs signal_count
│
├─[3] 노출 부족
│   └─ 포지션 크기가 너무 작음 (max_weight cap)
│   └─ 점검: avg_position_size, capital_utilization
│
├─[4] 비용 상쇄
│   └─ 거래 비용이 alpha 잠식
│   └─ 점검: gross_return vs net_return gap
│
└─[5] 레짐 상쇄
    └─ 특정 구간 이익 / 다른 구간 손실 = 제로섬
    └─ 점검: regime별 return 분해
```
