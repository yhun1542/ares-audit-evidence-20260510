### P1. 파이프라인 신뢰성 복구 (BLOCKER)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한가**
- rebalance.csv 로딩 실패 → 비용/슬리피지 미반영 가능성
- MDD=None → 리스크 게이트 작동 안 함
- OOS 값 불일치 (3.32 vs 2.63) → 어떤 값이 진짜인지 불명

**(b) 위험/부작용**
- 수정 중 기존 로직 회귀 가능
- 시간 소모 (전략 개선 지연)

**(c) 실험 체크리스트**

```
□ EXP-P1-A: rebalance 출력 형식 통일
  - 정의: JSON→CSV 변환 레이어 추가 또는 jsonl 파서 수정
  - 게이트: 파일 로딩 성공 + row count > 0
  - 기대치: pinpoint 도구 정상 실행

□ EXP-P1-B: MDD 계산 로직 디버그
  - 정의: backtest_engine에서 equity_curve → MDD 계산 경로 추적
  - 게이트: worst_mdd 값 출력 (예상: -15% ~ -40% 범위)
  - 기대치: 모든 fold에서 MDD 수치 존재

□ EXP-P1-C: OOS metric 소스 통일
  - 정의: champion JSON vs diagnoser 출력 비교, 계산식 일치 확인
  - 게이트: |JSON_oos - diagnoser_oos| < 0.01
  - 기대치: single source of truth 확립
```

**(d) PASS 조건**
- [ ] `aub_rebalance_pinpoint.py` 에러 없이 완료
- [ ] `worst_mdd` ≠ None, 값 범위 합리적 (-5% ~ -50%)
- [ ] OOS Mean 단일 값 확정

### P2. Degenerate Fold 원인 분석 및 수정
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한가**
- Fold 1,2,3,8 = 초기/특정 구간 실패 → **레짐 의존성** 또는 **데이터 부족**
- 40% degenerate = 실전 배포 시 동일 확률로 실패 가능

**(b) 위험/부작용**
- 문제 fold 강제 포함 시 전체 성능 하락
- 과도한 제약 추가 시 alpha 손실

**(c) 실험 체크리스트**

```
□ EXP-P2-A: Fold별 시장 레짐 태깅
  - 정의: 각 fold 기간의 VIX 평균, SPY 수익률, 섹터 로테이션 측정
  - 게이트: degenerate fold 공통 특성 1개 이상 발견
  - 기대치: "고VIX 구간 실패" 또는 "횡보장 실패" 등 패턴

□ EXP-P2-B: Min-exposure 제약 실험
  - 정의: exposure_min ≥ 0.15 강제 (현재 0.0 허용)
  - 게이트: degenerate fold ≤ 2개
  - 기대치: 전체 OOS Mean ≥ 2.0 유지하며 안정성 확보

□ EXP-P2-C: Fold 가중치 재조정
  - 정의: degenerate fold OOS=0 대신 페널티 (-0.5) 부여
  - 게이트: 최종 스코어 계산식 변경 후 ranking 재정렬
  - 기대치: 과최적화 전략 순위 하락
```

**(d) PASS 조건**
- [ ] Degenerate fold ≤ 2개 (현재 4개)
- [ ] OOS Mean ≥ 2.0 (하락 허용 범위 내)
- [ ] Exposure Min ≥ 0.10
