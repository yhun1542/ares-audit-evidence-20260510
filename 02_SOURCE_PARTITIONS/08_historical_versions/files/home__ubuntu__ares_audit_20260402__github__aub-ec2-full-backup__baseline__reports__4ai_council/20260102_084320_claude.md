# 48시간 자동 루프용 액션 체크리스트

## 0. 현재 상태 진단

| 항목 | 값 | 판정 |
|------|-----|------|
| OOS Mean | 1.88 | ⚠️ 양호하나 1.5 미만 폴드 존재 가능 |
| OOS Min | 0.43 | 🔴 **위험**: 1.0 미만 = 음수 수익 폴드 |
| Worst MDD | None | 🔴 **누락**: MDD 미측정 = 운영 리스크 블라인드 |
| Exposure 범위 | 47%~84% | ⚠️ 변동폭 37%p = 레짐 민감도 과다 |

**핵심 문제**: OOS Min 0.43은 특정 시장 구간에서 전략이 완전 실패함을 의미. MDD 미측정 상태로 실전 불가.

## 1. 우선순위 TOP 5 패치

### PATCH-1: MDD 게이트 구현 (CRITICAL)
```
[실험 정의]
- worst_mdd 계산 로직 추가
- 게이트: worst_mdd > -25% 시 FAIL
```

| 항목 | 내용 |
|------|------|
| **(a) 필요성** | MDD=None은 drawdown blind. 실전 배포 시 -40% 낙폭 발생해도 감지 불가 |
| **(b) 위험** | 게이트 추가로 현 Champion이 FAIL될 수 있음 (정보 손실 아님, 진실 노출) |
| **(c) 실험** | ① 전체 폴드 MDD 히스토그램 생성 → ② 최악 폴드 날짜/종목 특정 → ③ -20%/-25%/-30% 게이트별 통과율 |
| **(d) PASS** | MDD 계산 완료 + worst_mdd ≥ -25% + 최소 4/5 폴드 통과 |

---

### PATCH-2: OOS Min 폴드 부검 (HIGH)
```
[실험 정의]
- oos_min=0.43 발생 폴드 isolate
- 해당 기간 레짐/종목/시그널 분해
```

| 항목 | 내용 |
|------|------|
| **(a) 필요성** | 0.43 폴드가 2022 금리인상기인지 2020 코로나인지에 따라 처방 상이 |
| **(b) 위험** | 특정 레짐 제거 시 데이터 스누핑 → 반드시 레짐 라벨은 사전 정의된 것만 사용 |
| **(c) 실험** | ① 해당 폴드 날짜 범위 추출 → ② VIX/금리 레짐 태깅 → ③ 해당 기간 상위 손실 종목 3개 특정 |
| **(d) PASS** | 원인 1개 이상 특정 + 해당 레짐 발생 확률 <15% 확인 OR 레짐 필터 추가 |

---

### PATCH-3: Exposure 안정화 (MEDIUM-HIGH)
```
[실험 정의]
- exposure 변동폭 47%~84% → 목표 55%~75%
- 급변 구간 시그널 스무딩 또는 캡 적용
```

| 항목 | 내용 |
|------|------|
| **(a) 필요성** | 37%p 변동 = 레버리지 급변 = 슬리피지/실행 비용 과다 + 심리적 운영 부담 |
| **(b) 위험** | 스무딩 과도 시 시그널 지연 → 수익 저하. 캡 설정 시 과최적화 위험 |
| **(c) 실험** | ① EMA(5) 스무딩 적용 → ② hard cap [0.5, 0.8] 적용 → ③ 두 방식 OOS 비교 |
| **(d) PASS** | exposure 범위 ≤25%p + OOS mean ≥1.7 유지 + OOS min ≥0.7 |

---

### PATCH-4: 거래비용 현실화 (MEDIUM)
```
[실험 정의]
- 현재 비용 가정 점검 (슬리피지 + 커미션)
- 10bps / 20bps / 30bps 시나리오 비교
```

| 항목 | 내용 |
|------|------|
| **(a) 필요성** | exposure 변동 크면 회전율 ↑ → 비용 미반영 시 실전 괴리 |
| **(b) 위험** | 과도한 비용 가정 시 전략 자체 폐기 위험 (실제보다 비관적) |
| **(c) 실험** | ① 연간 회전율 계산 → ② 10/20/30bps별 OOS 재계산 → ③ 손익분기 비용 역산 |
| **(d) PASS** | 20bps 적용 시에도 OOS mean ≥1.5 + OOS min ≥0.6 |

---

### PATCH-5: 종목 수 적정성 검토 (MEDIUM)
```
[실험 정의]
- 현재 포트폴리오 종목 수 확인 (8~14 범위 준수?)
- 집중도 상위 3종목 비중 점검
```

| 항목 | 내용 |
|------|------|
| **(a) 필요성** | 단일 종목 비중 >20% 시 개별 이벤트 리스크 과다 (NVDA 실적발표 등) |
| **(b) 위험** | 분산 강제 시 시그널 희석 → 수익 저하 |
| **(c) 실험** | ① 시점별 종목 수 분포 → ② 상위 3종목 비중 합 추적 → ③ max_weight=15% 캡 실험 |
| **(d) PASS** | 상위 3종목 합 ≤45% + 종목 수 상시 8~14 유지 |

## 2. 48시간 자동 루프 명세

```yaml
LOOP_CYCLE:
  - hour_00: PATCH-1 실행 (MDD 계산)
  - hour_06: GATE_1 → worst_mdd ≥ -25% ? continue : ALERT
  - hour_08: PATCH-2 실행 (OOS min 부검)
  - hour_16: PATCH-3 실행 (exposure 스무딩)
  - hour_24: PATCH-4 실행 (비용 시나리오)
  - hour_32: PATCH-5 실행 (종목 집중도)
  - hour_40: 전체 결과 집계
  - hour_48: NEW_CHAMPION 판정 또는 HOLD

GATE_CONDITIONS:
  PROMOTE_NEW_CHAMPION:
    - oos_mean ≥ 1.7
    - oos_min ≥ 0.7
    - worst_mdd ≥ -25%
    - exposure_range ≤ 25%p
    - cost_20bps_oos_mean ≥ 1.5
  
  ALERT_HUMAN:
    - 모든 패치 실패 시
    - worst_mdd < -35% 발견 시
    - degenerate_folds ≥ 2 발생 시
```
