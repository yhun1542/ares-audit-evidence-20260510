## 24~48시간 TOP5 우선순위 (코드/아키텍처/전략) — **명령형 체크리스트**
우선순위는 **누수/과최적화/서바이버십/비용 미반영/운영 리스크**를 먼저 끊는 순서로 정렬.

---

# 1) (운영 리스크) **리밸런스/체결/비용 로그 파이프라인 복구 + 하드 게이트**
### (a) 왜 필요한지
- 현재 `aub_rebalance_pinpoint`가 **로그 파일/포맷 오류로 무력화**됨 → “성능이 안 움직이는” 원인이 **전략이 아니라 로깅/산출 실패**일 수 있음.
- `worst_mdd: None`도 **리스크 산출 파이프라인 결함** 가능성이 큼 (게이트가 없으니 챔피언이 “불완전 메트릭” 상태로 통과).

### (b) 위험/부작용
- 로그 강제/게이트 추가로 인해 **기존 실험의 대량 FAIL** 발생(정상).
- 비용/체결 기록이 추가되면 **OOS 성능이 하락**할 수 있음(현실 반영).

### (c) 최소 실험 세트(2~3 variants, 48h 루프용)
**실험세트 P1: “Rebalance Trace Contract v1”**
1. **Variant A (Strict JSONL)**: 모든 주문/체결/포지션 스냅샷을 `rebalance.jsonl`로 강제(한 줄=한 이벤트, 스키마 고정)
2. **Variant B (CSV fallback)**: JSONL 실패 시 동일 내용을 `rebalance.csv`로 이중 기록
3. **Variant C (Pinpoint self-test)**: 런 종료 후 `aub_rebalance_pinpoint.py` 자동 실행 + 리포트 경로 존재 체크

### (d) PASS 조건 (게이트)
- 런 종료 시 아래 **전부 만족 아니면 FAIL**
  - `rebalance.jsonl` 또는 `rebalance.csv` **파일 존재 + 0바이트 아님**
  - 마지막 포지션 스냅샷 존재(종가 평가 가능)
  - `worst_mdd` 값이 None이 아닌 실수로 산출됨
  - `rebalance_pinpoint.md` 생성 성공

**(1) 실험 정의 / (2) 게이트 / (3) 기대 관측치**
- (1) 정의: 리밸런스 이벤트 스키마 고정 + 자동 사후진단
- (2) 게이트: 위 PASS 조건
- (3) 기대 관측치: “성능 무변화”의 원인이 전략인지 파이프라인인지 즉시 분리(로그 부재 원인 제거)

# 2) (비용 미반영) **거래비용/슬리피지/턴오버를 OOS 스코어에 강제 포함**
### (a) 왜 필요한지
- Tech/Healthcare 8~14종목 집중 전략은 리밸런스 빈도에 따라 **턴오버가 성과를 전부 먹는 케이스**가 잦음.
- 비용을 OOS에 포함하지 않으면 **과최적화가 가장 먼저 발생**하는 지점이 거래비용.

### (b) 위험/부작용
- 성과가 급락할 수 있음(정상적인 “현실화”).
- 너무 보수적인 비용 모델은 우량 전략까지 제거할 수 있음 → “모델 강도”를 2~3단으로 비교해야 함.

### (c) 최소 실험 세트(2~3 variants)
**실험세트 P2: “Cost Model Clamp v1”**
1. **Variant A (기본 수수료+슬리피지)**: `commission_bps + slippage_bps`를 체결대금 기준으로 차감
2. **Variant B (유동성 페널티)**: `slippage_bps = base + k * (order_dollar / ADV_dollar)` 형태로 ADV 기반 페널티
3. **Variant C (턴오버 하드리밋)**: 일/주간 turnover가 임계치 초과 시 주문을 스케일 다운(또는 다음 캔들로 지연)

### (d) PASS 조건
- 비용 포함 OOS에서:
  - **oos_mean 하락폭이 합리적**(예: gross 대비 net이 비정상적으로 무너지면 전략이 턴오버 의존)
  - turnover/비용 항목이 리포트에 **명시적으로 수치화**
  - “비용 0”과 “비용 on”의 차이가 재현 가능(로그로 설명 가능)

**(1)/(2)/(3)**
- (1) 정의: 체결 기반 비용 차감 + ADV 기반 슬리피지 + turnover 제한
- (2) 게이트: 비용/턴오버 리포트 누락 시 FAIL
- (3) 기대 관측치: 성능 정체의 원인이 “알파 부족”인지 “비용 상쇄”인지 즉시 분리

# 3) (누수/서바이버십) **유니버스/데이터 타임라인 ‘불변 계약’ + 누수 자동탐지**
### (a) 왜 필요한지
- Tech+Healthcare 8~14 종목은 종목 선정 자체가 성과에 큰 영향 → **서바이버십/룩어헤드**가 들어가면 OOS가 “잘 나오는 척”하기 쉬움.
- 현재 챔피언 메트릭이 서로 다른 값으로 보이는 정황(2.62 vs 1.88)도 **데이터 스냅샷/버전 불일치** 가능성.

### (b) 위험/부작용
- “지금까지 잘 나오던 설정”이 대거 붕괴 가능(정상: 누수 제거).
- 데이터 준비 시간이 증가(캐시/스냅샷 관리 필요).

### (c) 최소 실험 세트(2~3 variants)
**실험세트 P3: “Timeline & Universe Contract v1”**
1. **Variant A (as-of 스냅샷 고정)**: 피처/가격/펀더멘털 모두 `as_of_timestamp` 강제(학습/예측 시점 이후 데이터 접근 차단)
2. **Variant B (서바이버십 방지 유니버스)**: 날짜별 상장/거래정지/합병 반영된 membership 테이블 사용(“현재 구성 종목” 금지)
3. **Variant C (Leak Canary tests)**: 무작위로 미래 데이터를 1개 피처에 섞었을 때 성과가 급등하면 FAIL(누수 민감도 테스트)

### (d) PASS 조건
- 아래 중 하나라도 위반 시 FAIL
  - 피처 생성/로딩 단계에서 `t+1` 이상 데이터 접근 흔적 탐지
  - 유니버스 membership이 “백테스트 전체 기간 단일 리스트”로 고정
  - Leak Canary에서 성과가 비정상적으로 크게 개선(누수 취약)

**(1)/(2)/(3)**
- (1) 정의: as-of 강제 + membership 시계열 + 누수 카나리
- (2) 게이트: 누수 탐지 트립 시 FAIL
- (3) 기대 관측치: 성과 정체/변동의 원인이 모델이 아니라 “데이터 계약” 문제인지 제거

# 4) (과최적화/노출) **노출(Exposure)·집중도·드로다운 기반 리스크 게이트 + 캐시 허용**
### (a) 왜 필요한지
- 현재 노출이 `min 0.47 / max 0.84`로 보이며, 사실상 “항상 꽤 투자” 상태 → 레짐 악화 구간에서 **방어가 약해 MDD가 커질 위험**.
- `worst_mdd: None` 상태 자체도 리스크 관리가 붕 떠있을 가능성.

### (b) 위험/부작용
- 캐시 허용/노출 제한은 상승장에서는 **수익을 깎을 수 있음**.
- 너무 빡빡한 제한은 신호를 죽여 “성능 무변화”처럼 보이게 할 수 있음(게이트 튜닝 필요).

### (c) 최소 실험 세트(2~3 variants)
**실험세트 P4: “Exposure & Concentration Guard v1”**
1. **Variant A (cash-on 규칙)**: 신호 약화/레짐 악화 시 목표 노출을 0~100%로 가변(현 노출 바닥 0.47을 0까지 허용)
2. **Variant B (HHI/Top-weight 제한)**: 8~14종목 내에서도 단일 종목 비중 상한(예: 15~20%) + HHI 상한
3. **Variant C (DD circuit breaker)**: 롤링 DD가 임계 초과 시 포지션 스케일다운(예: 0.5x) 후 쿨다운 N일

### (d) PASS 조건
- OOS에서:
  - `worst_mdd` 산출 및 리포트 반영(필수)
  - 노출 분포가 “상시 고정”이 아니라 레짐에 따라 움직임(통계로 확인)
  - 동일 수익 대비 MDD 또는 tail loss가 개선(방어 효과 확인)

**(1)/(2)/(3)**
- (1) 정의: 캐시 허용 + 집중도 제한 + DD 브레이커
- (2) 게이트: MDD/노출/집중도 지표 누락 시 FAIL
- (3) 기대 관측치: 성과 정체가 “알파 부재”인지 “리스크로 상쇄”인지 분리, 운영 리스크(급락) 완화

# 5) (레짐) **ETF는 ‘관측지표’로만 사용한 레짐 게이팅(Tech/Health 전용)**
> 매매는 **개별 미국주식(Tech+Healthcare 8~14)**만. ETF는 **신호 입력/관측 지표**로만.

### (a) 왜 필요한지
- Tech/Healthcare는 금리/리스크온오프 레짐 민감 → 신호가 맞아도 레짐이 틀리면 **전략이 눌리는 구간**이 발생.
- “성능이 안 움직임”은 종종 레짐 미스매치로 신호가 상쇄되는 현상.

### (b) 위험/부작용
- 레짐 필터가 잘못되면 거래 기회가 줄어 **수익 기회 상실**.
- 필터 파라미터가 새로운 과최적화 포인트가 될 수 있음 → 단순/저차원으로 제한.

### (c) 최소 실험 세트(2~3 variants)
**실험세트 P5: “Regime Gate (observe-only ETFs) v1”**
1. **Variant A (XLK/XLV 모멘텀 게이트)**: XLK, XLV의 중기 모멘텀/추세가 악화면 Tech/Health 노출 상한 축소
2. **Variant B (QQQ + IEF 스프레드 위험지표)**: 성장주 vs 금리 민감도를 단일 스칼라로 만들어 노출 조절
3. **Variant C (VIX proxy 간이 게이트)**: 변동성 급등 구간에 turnover/레버(있다면) 제한

### (d) PASS 조건
- 레짐 지표가:
  - **미래 데이터 없이** 계산(as-of 준수)
  - 신호/노출 변화가 로그로 설명 가능(언제 게이트가 걸렸는지)
  - OOS에서 MDD/변동성/테일 손실이 감소하거나, 동일 MDD에서 수익 개선

**(1)/(2)/(3)**
- (1) 정의: ETF 관측 지표로만 레짐 스칼라 생성 → 노출/턴오버 조절
- (2) 게이트: 레짐 계산에 lookahead 흔적 있으면 FAIL
- (3) 기대 관측치: 성능 정체가 레짐 상쇄인지 확인, 방어력 개선

## 24~48시간 실행 순서 (루프에 바로 넣기)
1. **P1 먼저 적용**: 로그/메트릭/게이트 복구(안 되면 그 다음 실험이 전부 의미 없음)
2. **P2 적용**: 비용/턴오버를 OOS 스코어에 강제(현실성 확보)
3. **P3 적용**: 타임라인/유니버스 계약 고정(누수/서바이버십 제거)
4. **P4 적용**: 노출/집중/드로다운 게이트(리스크 바닥 다지기)
5. **P5 적용**: 레짐 관측지표로 노출을 “움직이게” 만들기(정체 원인 분해)

# 성능이 안 움직일 때 “원인 분해” 아이디어 (트리거/적용/노출/비용/레짐)
아래는 **질문 없이 바로 태깅/로그로 분해**하는 체크리스트.

## A) 트리거(신호 생성) 문제
- **신호 발생 빈도**가 OOS에서 급감/급증했는지(분포 비교)
- 상위/하위 점수 종목의 **순위 상관(일관성)**이 기간별로 붕괴했는지
- 피처 드리프트: 주요 피처의 평균/분산/결측률이 학습 구간 대비 변했는지

## B) 적용(주문 변환/리밸런스) 문제
- 신호→목표비중 변환에서 **클리핑/정규화로 모두 비슷해지는 현상**(“스코어는 다른데 포지션은 같다”)
- 리밸런스가 실제로 실행되었는지(로그 부재/0주문/전량 거절)
- 리밸런스 주기/캘린더가 틀어져 **같은 날만 계속 거래**하거나 반대로 거의 거래 안 하는지

## C) 노출(Exposure) 문제
- 노출이 상한에 고정되어 신호가 변해도 **베타만 먹는 상태**인지
- 8~14 종목인데 상위 1~2개에 쏠려 **사실상 단일종목 베팅**이 되었는지(HHI/Top weight)
- 섹터 내 상관이 높아 **분산효과가 거의 0**인지(동일 팩터에 몰림)

## D) 비용(거래비용/슬리피지/턴오버) 문제
- gross는 좋은데 net이 죽는지(비용이 원인)
- turnover가 특정 레짐/특정 요일에만 폭발하는지(체결/리밸런스 로직 결함 가능)
- ADV 대비 주문 크기가 과해 슬리피지가 비선형으로 커지는지

## E) 레짐(시장 국면) 문제
- 레짐별(리스크온/오프, 금리상승/하락)로 성과를 쪼개면 **특정 국면에서만 죽는지**
- Tech vs Health 간 상대강도(예: XLK/XLV) 변화에 전략 노출이 따라가고 있는지
- 변동성 상승 구간에서 신호가 “맞아도” 손실이 커지는 구조인지(리스크 게이트 부재)

## 핵심: “성능 무변화”를 48시간 내에 끝내는 방법
- **P1~P3로 ‘측정 가능 + 현실 반영 + 누수 제거’**를 먼저 완료하면, 성능이 안 움직이는 이유가 최소한 **(전략 알파 vs 비용/체결 vs 레짐)** 중 어디인지 자동으로 갈라짐.
- 그 다음에만 **P4~P5로 노출/레짐을 움직이는 실험**이 의미를 가짐.
