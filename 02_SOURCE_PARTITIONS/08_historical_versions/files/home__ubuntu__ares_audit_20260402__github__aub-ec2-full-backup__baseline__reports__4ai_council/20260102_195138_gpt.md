아래는 **다음 24~48시간**에 바로 돌릴 수 있게, 누수/과최적화/서바이버십/비용/운영리스크를 **우선 점검**하는 순서로 정리한 **명령형 체크리스트 TOP5**입니다. (미국주식 only, Tech+Healthcare 8~14종목, ETF는 관측지표만)

---

## TOP5 우선순위 (24~48h)

1) **누수(lookahead)·정렬(asof)·코퍼레이트액션 정합성 하드게이트 추가**  
2) **거래비용(슬리피지/스프레드/임팩트)+턴오버 페널티를 “학습/선정 게이트”에 강제 반영**  
3) **서바이버십/유니버스 정의를 “고정 바스켓(8~14)” 중심으로 잠그고, 동적선정은 지연·검증 후만 허용**  
4) **과최적화 방지: purged/embargo CV + 단순화(피처/파라미터 자유도 축소)로 재튜닝**  
5) **레짐/리스크 오버레이(관측 ETF 사용): Tech vs Healthcare 로테이션 + 시장 스트레스 시 익스포저 축소**

# 1) 누수·정렬·코퍼레이트액션 하드게이트

### (a) 왜 필요한지
- 현재 champion 대비 candidate에서 **MDD 악화**가 뚜렷합니다. 이런 형태는 “신호가 좋아졌다”기보다 **누수/정렬 오류/리밸런싱 타이밍 착시**로 성능이 흔들릴 때 자주 나타납니다.
- 특히 **펀더멘털/이벤트/리포트성 데이터**가 1일만 앞서 들어가도 lockbox에서 미묘하게 수익률이 왜곡됩니다.

### (b) 위험/부작용
- 엄격한 lag/embargo 적용 시 단기적으로 성능 하락 가능(“진짜 알파”가 아니라 “타이밍 착시”였던 부분이 제거됨).
- 데이터 결측이 늘어 신호 빈도가 줄 수 있음.

### (c) 최소 실험(번들 2~3개 변형)
**실험 E1: “PIT(시점정합) 강제 + 누수 유닛테스트” 패치**
- 변형 A: 모든 비가격 피처 **+1 trading day lag** 강제
- 변형 B: **+2 trading day lag** 강제(보수적 상한)
- 변형 C: 리밸런싱/체결 타이밍을 “신호 t → 주문 t+1 open(or vwap)”로 고정

### (d) PASS 조건 (게이트)
- **Leakage gate**: 미래참조 탐지 테스트 0건(피처 timestamp ≤ decision timestamp 엄수)
- **성능 gate(비열화 최소)**:  
  - `worst_mdd >= -0.085` (champion -0.081 근처 유지)  
  - `lockbox_min >= 0.70`  
  - `lockbox_mean >= 3.8` (champion 4.01 대비 비열화 제한)

### 48시간 자동 루프 형식
- (1) 실험 정의: E1(A/B/C) 적용 → 동일 seed/동일 구간 재평가
- (2) 게이트: leakage 테스트 통과 + 위 성능 gate
- (3) 기대 관측치: tuning_mean은 소폭↓ 가능, **MDD/lockbox 안정성은↑**(특히 min 개선/급락 완화)

---

# 2) 비용·슬리피지·턴오버를 선정 게이트에 강제 반영

### (a) 왜 필요한지
- 현재 리포트는 “모델 성과” 중심으로 보이는데, **비용 미반영**이면 Tech 대형주라도 잦은 리밸런싱에서 성과가 쉽게 붕괴합니다.
- candidate에서 MDD가 커진 건 **턴오버 증가 → 비용·슬리피지 누적** 시나리오도 유력합니다.

### (b) 위험/부작용
- 비용 모델이 과도하면 진짜 알파를 과소평가(거래를 과도하게 억제).
- 비용 파라미터 튜닝이 또 다른 과최적화 축이 될 수 있음(그래서 “범위 테스트”만 하고 고정해야 함).

### (c) 최소 실험(번들 2~3개 변형)
**실험 E2: “3-레벨 비용 스트레스 + turnover cap” 패치**
- 변형 A(기본): 고정 bps(예: 5~10bps) + 스프레드 절반
- 변형 B(보수): 변형 A의 **2배 비용**
- 변형 C(ADV/vol 기반): `cost = base + k * (order/ADV) + vol_adjust` 형태(단순 1식 고정)
- 공통: **턴오버 상한(예: 일/주 단위)** 또는 **포지션 변화량 L1 페널티**를 objective에 추가

### (d) PASS 조건
- **비용 스트레스 내구성 gate**: A/B/C 중 **최소 2개**에서
  - `lockbox_mean >= 3.6`
  - `worst_mdd >= -0.09`
- **운영 gate**: 평균 turnover가 상한 이내(상한 초과 시 FAIL)

### 48시간 자동 루프
- (1) 정의: 비용 모델 3레벨 동시 평가 + turnover cap on/off 비교(단, 결과 보고 cap은 고정)
- (2) 게이트: 내구성 2/3 통과 + turnover 상한
- (3) 기대 관측치: “좋아 보이던” 후보들이 탈락, 남는 모델은 **실현가능 성과**로 수렴

---

# 3) 서바이버십/유니버스 잠금 (Tech+Healthcare 8~14 고정 바스켓 우선)

### (a) 왜 필요한지
- 동적 유니버스(예: 시총/성과 상위 N)는 PIT 처리 미흡 시 **서바이버십 + 룩어헤드**가 섞일 확률이 큽니다.
- 또한 운영 관점에서 48시간 루프 자동화는 **종목 변경이 잦을수록 장애·예외케이스**가 폭발합니다(티커 변경, 합병, 거래정지 등).

### (b) 위험/부작용
- 고정 바스켓은 알파 기회 일부 포기(특히 중형주 모멘텀).
- 특정 메가캡 쏠림으로 팩터 노출이 커질 수 있음(그래서 5번 레짐/리스크와 함께 봐야 함).

### (c) 최소 실험(번들 2~3개 변형)
**실험 E3: “고정 12종목 바스켓 + (제한적) 동적 대체 규칙” 패치**
- 변형 A(완전 고정 12): 예시(Tech) AAPL/MSFT/NVDA/AMZN/GOOGL/META/AVGO/CRM + (HC) UNH/LLY/JNJ/ABBV  
- 변형 B(고정 10 + 대체 2): 결측/거래불가 시에만 대체(대체 리스트 사전 고정)
- 변형 C(동적 허용하되 지연): 분기 1회만 재선정 + 모든 선정 입력을 **t-5영업일** 기준으로 고정

### (d) PASS 조건
- **서바이버십 gate**: delist/티커변경/결측 발생 시에도 백테스트가 “fail open”이 아니라 **fail closed(거래 중지/대체)**로 동작
- **성능 gate**: `worst_mdd` 악화 없이(`>= -0.085 ~ -0.09`) lockbox_mean 유지(>= 3.7)

### 48시간 자동 루프
- (1) 정의: A/B/C 백테스트 + 데이터 품질 로그(결측, corporate action 처리 로그) 출력
- (2) 게이트: 데이터 예외 0-crash + fail-closed 확인 + 성능 gate
- (3) 기대 관측치: 성능은 약간 줄어도 **분산/안정성/운영 신뢰도**가 올라감

---

# 4) 과최적화 방지: purged/embargo CV + 단순화(자유도 축소)

### (a) 왜 필요한지
- champion이 튜닝 성과 대비 lockbox가 더 좋게 나오는 형태는 “우연히” 가능하지만, 후보들이 흔들리는 상황에서는 **CV 설계 미흡/자유도 과다**가 흔한 원인입니다.
- 시계열에서는 일반 KFold가 누수 유발(인접 구간 정보가 새는 문제) → **purged + embargo**가 우선입니다.

### (b) 위험/부작용
- 성능이 단기적으로 내려갈 수 있음(대신 재현성↑).
- 탐색 공간 축소로 “좋아 보이는” 후보가 덜 나올 수 있음(정상).

### (c) 최소 실험(번들 2~3개 변형)
**실험 E4: “Purged CV + embargo 확장 + 피처/파라미터 다이어트” 패치**
- 변형 A: embargo 5일
- 변형 B: embargo 10일
- 변형 C: 피처 상위 K개만(또는 L1/elasticnet 규제 강화) + 파라미터 고정폭 확대(튜닝 자유도 축소)

### (d) PASS 조건
- **일관성 gate**: fold 간 분산 감소(예: fold 성과 표준편차가 기존 대비 ↓)
- **성능 gate**: lockbox_mean 비열화 제한(>= 3.7) + worst_mdd 비악화(>= -0.09)

### 48시간 자동 루프
- (1) 정의: A/B/C를 동일 데이터로 반복 + 분산/민감도 리포트 출력
- (2) 게이트: 분산 감소 + 성능 하한 유지
- (3) 기대 관측치: 평균 수익률보다 **최악구간/분산 개선**이 먼저 나타남(“안 흔들리는” 쪽으로 수렴)

---

# 5) 레짐/리스크 오버레이 (ETF는 관측지표만)

### (a) 왜 필요한지
- Tech/Healthcare는 레짐(금리/리스크온오프)에 따라 상대강도가 크게 바뀝니다. 신호가 “맞아도” 레짐에서 **노출이 반대로 걸리면** 성능이 안 움직입니다.
- 후보에서 MDD가 커진 경우, 레짐 필터가 없으면 손실 구간을 그대로 맞습니다.

### (b) 위험/부작용
- 필터가 과도하면 거래 기회를 놓쳐 수익률이 감소.
- 레짐 정의가 복잡해지면 과최적화 위험(그래서 **지표 1~2개로 단순화**).

### (c) 최소 실험(번들 2~3개 변형)
**실험 E5: “관측 ETF 기반 2-상태 레짐 + 익스포저 스케일” 패치** (매매는 개별주만)
- 관측지표 후보(택1~2로 고정):
  - 시장 추세: QQQ 또는 SPY의 50/200MA 상태
  - 섹터 상대강도: XLK/XLV 비율의 추세
- 변형 A: 리스크오프(추세↓) 시 총 익스포저 50%로 축소
- 변형 B: 리스크오프 시 Tech 비중↓, Healthcare 비중↑(로테이션 스케일)
- 변형 C: 변동성 타게팅(실현 변동성↑ 시 레버리지/익스포저 축소)

### (d) PASS 조건
- **드로우다운 gate**: `worst_mdd` 개선(예: champion 대비 최소 10% 상대개선 또는 절대 -0.075 이상)
- **비용 gate**: turnover가 증가하지 않거나(혹은) 비용 차감 후 성능 유지(>= 3.7)

### 48시간 자동 루프
- (1) 정의: 레짐 2-상태 + 스케일 규칙만 추가(신호 자체는 그대로)
- (2) 게이트: MDD 개선 + 비용 후 성능 하한
- (3) 기대 관측치: 평균 수익률보다 **tail 손실 감소**, lockbox_min 개선

# 성능이 “안 움직일 때” 원인 분해 체크리스트 (트리거/적용/노출/비용/레짐)

아래는 질문 없이 바로 로그/리포트에 추가해서 원인 위치를 좁히는 **분해 프레임**입니다.

## A. Trigger(신호 발생) 문제
- **신호 발생 빈도**: 기간별 신호 발생 횟수/비율이 급감했는지 확인
- **신호 품질(IC/Hit rate)**:  
  - 예측/랭킹이면: IC(mean/IR)  
  - 트레이드면: 방향 적중률, 평균 승/패, payoff ratio
- **지연/체결 타이밍**: 신호 t와 체결 t+1 규칙이 실제로 적용되었는지(로그로 강제)

## B. Apply(포지션 적용) 문제
- **포지션 클리핑/리밸런싱 충돌**: max weight, sector cap, turnover cap이 신호를 “눌러버리는지”
- **리밸런싱 캘린더**: 월말/주말 편향, 휴장일 처리, 리밸런싱이 비정상적으로 몰리는지

## C. Exposure(노출) 문제
- **팩터 노출**(간단 버전): 시장베타(대략 SPY/QQQ 회귀), 테크 쏠림, 헬스케어 쏠림
- **단일종목 기여도**: 상위 1~2개 종목이 전체 PnL/DD를 지배하는지(기여도 리포트)
- **포지션 상관**: 보유 종목 간 상관이 올라가 “분산이 사라진” 상태인지

## D. Cost(비용) 문제
- **턴오버 vs PnL**: gross PnL은 괜찮은데 net이 죽는지(비용 차감 전/후 분해)
- **슬리피지 민감도**: 비용 1배/2배에서 성과가 급격히 무너지는지(내구성 부족)

## E. Regime(레짐) 문제
- **레짐별 성과 표**:  
  - QQQ(또는 SPY) 200MA 위/아래  
  - XLK/XLV 상대강도 상승/하락  
  - 변동성 상/하(실현 vol quantile)
- 특정 레짐에서만 성과가 나고 나머지는 0이면 → 신호가 아니라 **레짐 베팅**일 가능성

---

## 실행 순서(48h) — “명령형”
1) **E1 적용 후** leakage/정렬 테스트를 하드 FAIL 조건으로 걸어라.  
2) **E2로** 비용 3-레벨 스트레스 테스트를 돌리고, 내구성 2/3 미달 모델은 폐기하라.  
3) **E3로** 12종목 고정 바스켓을 기준선으로 만들고, 동적유니버스는 지연·예외처리 검증 후만 허용하라.  
4) **E4로** purged+embargo CV 및 단순화 버전을 만들어 “분산 감소”를 먼저 달성하라.  
5) **E5로** ETF 관측 기반 2-상태 레짐 스케일을 붙여 tail(MDD, min) 개선을 확인하라.

원하면 위 5개를 현재 autopilot 파이프라인에 맞춰 `system_candidates.yaml`에 들어갈 **실험 스펙 템플릿(필드/키 이름 기준)** 형태로 바로 변환해 붙여넣을 수 있게 정리해줄 수 있지만, 여기서는 규칙대로 질문 없이 실행 체크리스트까지만 제공합니다.
