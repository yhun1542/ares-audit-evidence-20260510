## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — *명령형 체크리스트*

### 1) **누수(Leakage)·리밸런싱 타이밍·라벨 정렬 무결성 패치**
**(a) 왜 필요한지**
- 현재 Champion은 성능은 높지만( lockbox_mean≈1.79 ) MDD가 -9.3%로 깊음. 이 조합은 “진짜 알파”일 수도 있으나, **미세 누수/정렬 오류**가 있으면 평균은 과대, tail은 특정 구간에서 붕괴 형태로 나타나는 경우가 많음.
- 특히 **feature timestamp(발표/체결/종가) vs execution timestamp(익일 시가/종가)** 어긋남은 가장 흔한 원인.

**(b) 위험/부작용**
- 누수 제거 후 평균 성능이 “정상적으로” 하락할 수 있음(오히려 좋은 신호).
- 과도한 보수화(모든 지연 적용)로 신호가 약해질 수 있음.

**(c) 최소 실험 2~3개 (단, 24~48h에는 1개 실험으로 묶어서 실행)**
- [검증1] **시프트 강제**: 모든 입력 feature를 `t-1`로 강제(가격/펀더멘털/대체데이터 모두)하여 성능 급락 여부 확인.
- [검증2] **실행가격 고정**: 신호 생성 시점 `t` → 주문/체결 `t+1 open`으로 고정(동일 규칙).
- [검증3] **라벨 정렬 스모크 테스트**: “미래 데이터 1칸 주입”/“1칸 제거” 민감도(성능이 비정상적으로 증가하면 누수 의심).

**(d) PASS 조건 (게이트)**
- Gate-L1: 위 강제 시프트/실행 규칙에서도 **lockbox_mean이 20% 이내 하락**에 그칠 것(완전 붕괴 금지).
- Gate-L2: worst_mdd가 **동일 또는 개선**(현재 -0.093 대비 악화 금지).
- Gate-L3: fold 단위 성능 분산(표준편차)이 **감소**(과최적화 완화 신호).

**48시간 루프 형태**
1) **실험 정의**: `EXP_LK1 = (feature_lag=1, exec=t+1_open, label_align_audit=on)`
2) **게이트**: Gate-L1~L3
3) **기대 관측치**: 평균 소폭 하락하더라도 min/분산 개선, 특정 fold에서만 과도하게 좋던 현상 완화

### 2) **거래비용/슬리피지/체결 제약(운영 리스크) 반영 패치**
**(a) 왜 필요한지**
- Tech/Healthcare 8~14종 단일주 운용에서 비용은 “부차적”이 아니라 **성능의 핵심**. 특히 리밸런싱이 잦으면 lockbox_mean이 허상일 수 있음.
- 비용 미반영은 “과최적화”와 함께 가장 먼저 터지는 실전 리스크.

**(b) 위험/부작용**
- 비용을 현실화하면 평균이 크게 떨어질 수 있음(특히 turnover 높은 전략).
- 너무 보수적인 슬리피지로 기회가 과소평가될 수 있음(하지만 운영 관점에서는 안전).

**(c) 최소 실험 2~3개 (24~48h에는 1개 실험으로 묶어서 실행)**
- [검증1] **기본 비용 모델 추가**: `commission + spread/2 + impact(k * ADV^-α * |qty|^β)` 형태(단순 파라미터로 시작).
- [검증2] **체결 한도**: 1일 거래량 대비 참여율 cap(예: 1~3%) + 갭 발생 시 슬리피지 확대.
- [검증3] **턴오버 패널티**: 목적함수/스코어에 turnover 항 추가(“비용 최적화”가 아니라 “비용 민감도” 확인용).

**(d) PASS 조건 (게이트)**
- Gate-C1: 비용 포함 후에도 **lockbox_mean이 1.65 이상**(Champion 1.79 대비 과도 붕괴 방지; 현실 감안).
- Gate-C2: 평균 대비 비용 드래그(총비용/총수익)가 **설명 가능한 수준**으로 로깅될 것(“비용이 어디서 나는지” 분해 가능).
- Gate-C3: worst_mdd **-0.10 이하로 악화 금지**(비용으로 tail이 더 나빠지면 구조 문제).

**48시간 루프**
1) **실험 정의**: `EXP_COST1 = (slippage_model=v1, participation_cap=2%, turnover_penalty=on)`
2) **게이트**: Gate-C1~C3
3) **기대 관측치**: 평균 하락 대신, “실전형 후보”만 살아남고 성능 변동 원인이 비용/턴오버로 분해됨

### 3) **서바이버십/유니버스 구성 규칙(미국 Tech+Healthcare, 8~14) 고정 및 재현성 패치**
**(a) 왜 필요한지**
- “미국주식 only, Tech+Healthcare 중심 8~14종”은 유니버스 선정이 곧 전략임. 여기서 서바이버십이 섞이면 lockbox가 아니라도 **전체가 낙관 편향**됨.
- 상장폐지/인수/티커변경 처리 미흡은 운영에서 즉시 터짐.

**(b) 위험/부작용**
- 과거 시점 유니버스 재구성(당시 존재 종목만)으로 성능이 떨어질 수 있음.
- 유니버스가 너무 자주 바뀌면 turnover/비용이 증가.

**(c) 최소 실험 2~3개 (24~48h에는 1개 실험으로 묶어서 실행)**
- [검증1] **시점 기반 유니버스 스냅샷**: 매 리밸런스일에 “그날 시점에 존재 + 유동성/시총 조건”을 만족하는 종목만 후보.
- [검증2] **섹터 필터 고정**: GICS(또는 동등 분류)로 Tech/Healthcare만, 단 **과거 분류 변경**이 있으면 당시 분류로.
- [검증3] **8~14개 강제**: 점수 상위 N 선택 + 동일 가중/리스크패리티 중 하나로 단순화(ETF 매매는 금지, 단 XLK/XLV/QQQ는 관측지표로만 사용).

**(d) PASS 조건 (게이트)**
- Gate-U1: 유니버스가 바뀌어도 lockbox_mean **1.60 이상 유지**(유니버스 편향 제거 감안).
- Gate-U2: “유니버스 변경 횟수/턴오버/비용” 로깅이 완비되고, 성능 변화가 그 변수들로 설명 가능.
- Gate-U3: 상장폐지/결측 처리로 인한 거래 불능(주문 불가)이 0에 수렴(운영 리스크 제거).

**48시간 루프**
1) **실험 정의**: `EXP_UNIV1 = (point_in_time_universe=on, sector_filter=PIT, N=8~14_enforced)`
2) **게이트**: Gate-U1~U3
3) **기대 관측치**: 평균 일부 하락 대신, “살아남는 성능”과 운영 가능성 확보

### 4) **리스크 오버레이(드로우다운/레짐)로 tail(-9.3% MDD) 우선 제어**
**(a) 왜 필요한지**
- Champion의 worst_mdd=-0.093은 “실전에서 중단/강제청산/투자자 이탈”을 유발하는 수준일 수 있음.
- Candidate는 MDD가 -0.042로 좋아졌지만 mean이 낮음. 즉, **리스크 제어가 성능 자체를 망치지 않는 형태로 결합**해야 함.

**(b) 위험/부작용**
- 오버레이가 과하면 알파를 깎아 평균이 크게 내려감(“안전하지만 못 버는” 상태).
- 레짐 신호가 늦으면 최악 구간 방어 실패.

**(c) 최소 실험 2~3개 (24~48h에는 1개 실험으로 묶어서 실행)**
- [검증1] **변동성 타게팅**: 포트폴리오 ex-ante vol 목표(예: 10~12%)로 레버리지/노출 조절.
- [검증2] **드로우다운 브레이크**: rolling peak 대비 DD가 임계치(예: -4%/-6%) 넘으면 포지션 축소/현금(현금은 허용) 전환.
- [검증3] **레짐 관측지표(ETF는 지표만)**: `QQQ, XLK, XLV` 모멘텀/추세 + `VIX` 상승 시 위험 노출 상한 낮춤(매매는 개별주만).

**(d) PASS 조건 (게이트)**
- Gate-R1: worst_mdd **-0.06 이상(절대값 축소)** 달성.
- Gate-R2: lockbox_mean **1.70 이상 유지**(리스크 줄이되 수익성 유지).
- Gate-R3: tail 구간(최악 fold14 등)에서 손실의 “원인 분해”가 가능(노출 축소가 실제로 작동했는지 로그로 확인).

**48시간 루프**
1) **실험 정의**: `EXP_RISK1 = (vol_target=on, dd_brake=on, regime_indicators=on)`
2) **게이트**: Gate-R1~R3
3) **기대 관측치**: MDD 개선 + 성능 하락 최소화(Champion vs Candidate의 “중간 지점” 목표)

### 5) **과최적화(모듈/하이퍼) 억제: “단순화 + 안정성 지표”를 1등 기준으로 승격**
**(a) 왜 필요한지**
- Champion tuning_mean(1.90) 대비 lockbox_mean(1.79)로 나쁘진 않지만, 최악 구간 MDD가 깊음. 이는 “평균은 좋은데 특정 구간에서 깨짐” → 복잡도/조건 분기/피처 과다의 신호일 수 있음.
- 48시간 자동 루프에서는 “가끔 대박”보다 **지속적으로 통과하는 후보**가 더 중요.

**(b) 위험/부작용**
- 단순화로 평균이 내려갈 수 있음.
- 너무 강한 규제가 알파 소스를 제거할 수 있음.

**(c) 최소 실험 2~3개 (24~48h에는 1개 실험으로 묶어서 실행)**
- [검증1] **피처/모듈 어블레이션(하나만 제거)**: 성능 기여도 상위/하위 피처를 1개씩 제거해 민감도 확인(“필수/독” 구분).
- [검증2] **파라미터 범위 축소**: 하이퍼 서치 공간을 반으로 줄이고(또는 priors 도입) lockbox 재현성 체크.
- [검증3] **선발 기준 변경**: 평균 최대화 대신 `min / worst_fold / MDD`에 가중치를 준 스코어로 champion 선정(서바이버십/운영 리스크 반영).

**(d) PASS 조건 (게이트)**
- Gate-O1: lockbox_mean **유지(±0.10 이내)** 하면서 worst_mdd 개선.
- Gate-O2: fold 간 성능 분산 감소(“일관성 증가”).
- Gate-O3: 동일 설정 재실행 시 결과 변동(랜덤/샘플링 노이즈) 감소.

**48시간 루프**
1) **실험 정의**: `EXP_OH1 = (feature_ablate=1, search_space=shrunk, selection_score=stability_weighted)`
2) **게이트**: Gate-O1~O3
3) **기대 관측치**: 평균 약간 손해 보더라도 “락박스에서 자꾸 통과하는” 형태로 수렴

## 24~48시간 실행 순서(최대 5개 실험으로 제한, 48h 자동 루프 친화)
1) `EXP_LK1` (누수/정렬) → PASS 시
2) `EXP_COST1` (비용/체결) → PASS 시
3) `EXP_UNIV1` (서바이버십/유니버스) → PASS 시
4) `EXP_RISK1` (리스크 오버레이) → PASS 시
5) `EXP_OH1` (과최적화 억제/선발기준)

각 단계 FAIL이면: **즉시 롤백 + FAIL 원인 로그(아래 분해 프레임) 출력**을 “필수 산출물”로 남기고 다음 단계로 넘어가지 말 것(오염된 기반 위 최적화 방지).

## 성능이 안 움직일 때(또는 챔피언이 교체되지 않을 때) 원인 분해 아이디어 — 트리거/적용/노출/비용/레짐

아래를 **항상 로그/리포트로 강제 출력**하도록 패치(“성능 정체”를 숫자로 해체):

### A) Trigger(신호 발생) 분해
- 기간별 **신호 발생 횟수**, 롱/숏 비율(숏이 있다면), 종목별 발생 빈도
- “상위 스코어와 하위 스코어 간” 실제 다음날 수익 스프레드(예측력이 있는지)
- 신호 임계값 주변(컷오프)에서의 민감도: 컷오프 ±5%에서 turnover와 PnL이 어떻게 변하는지

### B) Apply(적용/체결) 분해
- 주문이 “언제 생성되고 언제 체결되는지” 타임라인 고정 로그
- 체결 실패/거래불가(결측/정지/상폐) 카운트
- 가격 사용(종가/시가/VWAP 등)별 PnL 차이: 실행 가정이 성능을 만들고 있는지 점검

### C) Exposure(노출) 분해
- 포트폴리오 **유효 종목 수(실제 보유 8~14 유지 여부)**, 집중도(HHI), 최대 비중
- 섹터(Tech/Healthcare 내 서브산업)·팩터(대형/성장/퀄리티/모멘텀) 노출
- “특정 1~2개 종목이 PnL 대부분을 설명”하면 과최적화/서바이버십 가능성↑

### D) Cost(비용) 분해
- 총비용을 **커미션/스프레드/임팩트**로 쪼개고, 종목별 기여도 출력
- turnover가 높은 구간에서만 성능이 죽는지(전략 문제 vs 비용 문제 분리)
- 비용 포함/미포함 성능 격차를 기간별로 플롯(비용이 레짐 의존인지 확인)

### E) Regime(레짐) 분해 (ETF는 지표로만)
- 관측지표: `QQQ(Tech beta), XLV(Healthcare), VIX(리스크), TLT(금리 민감), IWM(리스크온)` 등을 **구간 라벨**로만 사용
- 레짐별(예: QQQ 상승/하락, VIX 상/하) 성능 테이블:
  - hit rate, avg win/loss, MDD, turnover, 비용
- “정체”가 레짐 미스매치면: **레짐 게이트(노출 상한/하한)**가 효과적이고, “항상 정체”면: 신호 자체/누수/비용 가능성이 큼

## 즉시 적용(코드/리포트) 최소 패치 산출물(운영 리스크 우선)
- 백테스트 산출물에 아래를 **필수 컬럼**으로 강제:
  - `signal_time, exec_time, exec_price_type, feature_max_timestamp`
  - `turnover, cost_total, cost_breakdown(spread/impact/commission)`
  - `positions_count, max_weight, HHI, sector_exposure`
  - `regime_labels(qqq_trend, vix_bucket, rates_bucket)`
- champion 선정 스코어를 “mean 단독”이 아니라:
  - `Score = lockbox_mean - λ1*abs(worst_mdd) + λ2*lockbox_min - λ3*turnover`
  - λ는 작게 시작(정체 원인 분해가 목적)

이대로면 48시간 자동 루프에서 **(1) 누수 제거 → (2) 비용 현실화 → (3) 서바이버십 제거**의 “3대 착시”를 먼저 제거하고, 그 위에서 **리스크 오버레이/단순화**로 Champion의 -9.3% MDD를 구조적으로 줄이는 방향으로 수렴시킬 수 있음.
