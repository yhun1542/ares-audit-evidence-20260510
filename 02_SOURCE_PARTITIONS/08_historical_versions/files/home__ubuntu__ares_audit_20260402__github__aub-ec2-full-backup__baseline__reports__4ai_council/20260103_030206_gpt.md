## 0) 지금 ONE TRUTH에서 “먼저 의심할 것” (우선 점검 순서)
- **리밸런스 로그가 깨짐/부재**: `aub_rebalance_pinpoint`가 CSV/JSONL 모두 로딩 실패 → “전략이 안 움직인다/변경이 반영 안 된다”의 최상위 원인 후보.
- **degenerate_folds = [1,2,3,8]**: CV가 무너져 OOS mean이 의미 없거나, 특정 구간에서 신호가 상수/결측으로 붕괴했을 가능성.
- **worst_mdd = None**: 리스크/테일 메트릭이 계산 누락 → 과최적화/운영 리스크를 가릴 수 있음.
- **lane_hash/run_hash = None**: 재현성 결여(동일 입력이 동일 결과를 보장 못함) → 48시간 자동 루프에서 “원인 추적 불가”.
- **oos_min < 0 & exposure 0~0.84**: 구간 손실 + 현금 비중 변동/미투자 구간 존재 → 레짐/게이트/제약/비용 때문에 “진입 자체가 막히는” 케이스 점검 필요.

# P1) “리밸런스/거래/비용” 관측가능성 복구 (가장 먼저)
### (a) 왜 필요한지
- 지금은 **리밸런스 데이터가 로딩 실패** → 성능이 안 움직일 때 “신호가 안 나옴 vs 신호는 있는데 체결/제약/비용으로 못 삼” 분해가 불가능.
- 48시간 루프에서 필수인 **원인-결과 연결고리(포지션/주문/체결/비용)**가 끊김.

### (b) 위험/부작용
- 로깅/메트릭 추가로 런타임/디스크 증가.
- 로깅이 “사후 계산”이면 다시 왜곡(체결가/슬리피지 시뮬레이션 일관성 깨짐).

### (c) 최소 실험(공유 실험 참조)
- **E1(관측성 패치)** + **E5(비용모델 목적함수 반영)** 를 함께 수행(아래 실험 섹션 참조).  
  - *E1*: `rebalance.jsonl`(또는 parquet)로 **주문 전/후 목표비중, 실제비중, 트레이드 수량, 슬리피지/스프레드, 수수료** 기록
  - *E5*: 비용을 “사후 차감”이 아니라 **최적화/선정 단계에 포함**

### (d) PASS 조건
- `aub_rebalance_pinpoint.py`가 **base/cand 모두 정상 로딩**하고, 종목별 트레이드 원인이 추적 가능.
- 매일(또는 각 리밸런스 이벤트마다) 다음이 **non-null**로 출력:
  - turnover, cost_breakdown(commission/spread/slippage/borrow), realized vs intended weights
- “성능이 안 움직임” 발생 시, **신호→목표→제약→주문→비용** 중 어디서 막혔는지 10분 내 역추적 가능.

# P2) 누수/시간정렬/서바이버십 바이어스 하드닝
### (a) 왜 필요한지
- degenerate folds + no-delta diagnoser 결과(“성능 변화 없음”)는 흔히 **(1) 피처가 미래를 본다(누수)** 또는 **(2) 반대로 피처가 모두 NaN/상수(파이프라인 붕괴)**에서 같이 나타남.
- 미국주식(Tech/Healthcare)에서는 **실적/가이던스/리비전 타이밍** 누수가 매우 치명적.

### (b) 위험/부작용
- 누수 제거(시프트/엠바고) 후 단기적으로 성능 하락 가능(“진짜 성능”으로 내려앉음).
- 데이터 제공자별 timestamp 해석이 달라 “과도한 지연”이 생기면 알파 약화.

### (c) 최소 실험
- **E2(누수 차단 패치)** 1개로 2~3개 변형을 한 번에 커버:
  - 변형 A: 모든 비가격 데이터(펀더멘털/리비전/뉴스성)를 **+1 trading day asof shift**
  - 변형 B: 이벤트성 데이터는 **+5 trading day lag**
  - 변형 C: 학습/검증 사이 **purge/embargo(예: 5~10일)** 강제

### (d) PASS 조건
- 변형 A/B/C에서 **OOS mean이 “비정상적으로 과도하게 높아지지 않음”**(누수 제거 후 급락은 허용, 급등은 경고).
- 피처 결측률/상수 피처 비율이 임계치 이하:
  - 결측률 상위 피처/종목 리스트가 로깅되고, 폴드별 동일 패턴이 반복되지 않음.
- 서바이버십 방지: 백테스트 시점별 universe가 “그 시점에 존재한 티커”로 고정(상폐/합병 포함).

# P3) CV/폴드 붕괴(degenerate_folds) 제거 + 과최적화 방지 게이트
### (a) 왜 필요한지
- degenerate folds는 **선정/학습이 특정 구간에서 무의미**해졌다는 뜻(상수 예측, 데이터 없음, 분산 0, 라벨 누락 등).
- 이 상태에서 OOS mean은 우연/샘플링 아티팩트가 되기 쉬움(과최적화·서바이버십 착시).

### (b) 위험/부작용
- 폴드 정리 후 학습 데이터가 줄어 성능 하락 가능.
- “좋아 보이던” 챔피언이 사라질 수 있음(정상).

### (c) 최소 실험
- **E3(CV 안정화 패치)**:
  - Purged Walk-Forward(시간순), 최소 폴드 길이, 폴드당 최소 거래횟수/종목수 제약
  - degenerate fold 자동 fail-fast + 원인 리포트(라벨 분산/피처 결측/예측 상수 여부)

### (d) PASS 조건
- degenerate_folds가 **빈 리스트**.
- 폴드별 성과 분산이 “정상 범위”로 수렴(최소한 특정 폴드만 폭발적으로 좋지 않음).
- 동일 seed/config에서 결과 재현(아래 P4의 해시/시드 포함).

# P4) 재현성(해시/시드/아티팩트)과 자동 루프 “가드레일”
### (a) 왜 필요한지
- lane_hash/run_hash=None이면, 48시간 루프에서 **원인 규명이 불가능**(같은 설정인데 결과가 달라짐).
- 운영 리스크: 배포된 챔피언이 어떤 코드/데이터로 만들어졌는지 추적 불가.

### (b) 위험/부작용
- 초기에는 개발 속도 저하(해시/아티팩트 강제).
- 데이터 버전 고정이 없으면 오히려 혼란(그래서 고정해야 함).

### (c) 최소 실험
- **E1(관측성 패치)**에 포함해서 같이 처리(실험을 늘리지 않음):
  - git commit hash, 데이터 스냅샷 버전, config hash, seed, python pkg freeze를 아티팩트에 강제 저장
  - run_hash/lane_hash를 결과 JSON에 강제 기록

### (d) PASS 조건
- 동일 커밋+동일 데이터 스냅샷+동일 시드 → **완전 동일**한 백테스트 결과(허용오차 0 또는 매우 미소).
- 챔피언 파일에 run_hash/lane_hash가 항상 채워짐.

# P5) “미국 Tech+Healthcare 8~14 종목” 운영 제약 + 레짐 게이트(ETF는 관측지표만)
### (a) 왜 필요한지
- exposure가 0~0.84로 흔들리는 건 레짐/게이트/제약이 의도치 않게 포지션을 막거나, 비용 반영으로 거래가 취소되는 신호.
- Tech/Healthcare는 레짐(금리/리스크온오프)에 따라 상관이 급변 → **레짐 관측**을 넣되 ETF는 “매매”가 아니라 **게이트/리스크 지표**로만 사용.

### (b) 위험/부작용
- 레짐 게이트가 과하면 “항상 현금” → OOS mean 정체.
- 8~14 종목 강제는 집중 리스크↑(단, 이건 의도된 제약이므로 리스크 메트릭 필수).

### (c) 최소 실험
- **E4(레짐+노출 제어 패치)**:
  - Universe: 미국 상장, 섹터=Tech/Healthcare에서 8~14개만 보유(ETF 매매 제외)
  - 레짐 관측지표(예시): QQQ/XLK(테크), XLV/VHT(헬스케어), IWM(리스크), HYG(크레딧) **가격/변동성/추세만 사용**
  - 게이트 예: “리스크오프”면 net exposure 상한 하향, 또는 Tech 비중 캡/Healthcare 쪽으로 틸트(개별주 내에서)

### (d) PASS 조건
- net exposure 분포가 의도대로(예: 중앙값/상한선 준수), “0 노출” 구간이 레짐 신호와 일치.
- oos_min(최저 성과) 또는 tail 지표가 개선(최소한 악화하지 않음).
- 종목 수 8~14 준수 + 섹터 제약 준수.

## 2) 48시간 자동 루프용 “실행 가능한 Patch/실험” 5개 (3~5개 제한 준수)
아래는 **실험 정의 → 게이트 → 기대 관측치** 형태로 바로 루프에 넣을 수 있게 작성.

---

### E1) 관측성(리밸런스/비용/해시) 패치
- **실험 정의**
  - 리밸런스 이벤트마다 `rebalance.jsonl` 생성(또는 parquet)
  - 필드: timestamp, universe, target_weights, pre_weights, post_weights, trades, prices_used, slippage_model_inputs/outputs, fees, borrow_cost, turnover
  - 결과 JSON에 `run_hash/lane_hash/git_sha/data_version/seed` 강제 기록
  - `worst_mdd` 포함 주요 리스크 메트릭 non-null 강제
- **게이트(FAIL FAST)**
  - rebalance 로그 파일 파싱 실패 시 실험 즉시 FAIL
  - worst_mdd/turnover/cost_breakdown가 None이면 FAIL
  - run_hash/lane_hash 비어있으면 FAIL
- **기대 관측치**
  - “안 움직임”이 발생하면 (i) 신호 0 (ii) 제약 클리핑 (iii) 비용으로 trade 0 (iv) 최소주문단위/쿨다운 중 하나로 분류 가능

---

### E2) 누수 차단(시간정렬/엠바고) 패치
- **실험 정의**
  - 모든 비가격 피처 asof join을 강제하고 +1D shift 기본 적용
  - 옵션 플래그로 +5D lag 변형 가능
  - Purge/Embargo(예 5~10거래일) 적용
- **게이트**
  - 피처 결측률/상수 비율이 임계치 초과 시 FAIL(폴드별 리포트 출력)
  - “미래 timestamp” 감지(피처 timestamp > 의사결정 timestamp) 시 즉시 FAIL
- **기대 관측치**
  - 누수가 있었다면 성과가 의미 있게 변동(대개 하락) + 폴드 성과가 현실적으로 변함
  - 파이프라인 붕괴였다면 결측/상수 경고가 폭발적으로 드러남

---

### E3) CV 안정화 + degenerate fold 제거
- **실험 정의**
  - Purged Walk-Forward로 고정
  - 폴드당 최소 표본/거래/종목 수 제약
  - degenerate fold(라벨 분산 0, 예측 상수, 유효표본 부족) 자동 FAIL + 원인 출력
- **게이트**
  - degenerate_folds가 1개라도 생기면 FAIL(챔피언 승격 금지)
- **기대 관측치**
  - OOS mean이 과장된 경우 정상화
  - “특정 구간만 성과가 좋던” 과최적화 패턴이 사라짐

---

### E4) 레짐 관측(ETF는 지표만) + 노출 제어 + 8~14 종목 제약
- **실험 정의**
  - 보유 종목 수 8~14 강제, 섹터 Tech/Healthcare만
  - 레짐 지표: QQQ/XLK/XLV(VHT)/HYG/IWM의 추세·변동성으로 risk-on/off 스코어 산출
  - 스코어에 따라 net exposure 상한/섹터 캡/리밸런스 빈도 조절(주식만 매매)
- **게이트**
  - 종목 수/섹터 제약 위반 시 FAIL
  - 노출 상한 위반 시 FAIL
- **기대 관측치**
  - 급락 구간에서 oos_min 개선 또는 MDD 개선
  - 현금 비중 급증이 “레짐 때문에 의도적으로 줄인 것”인지 로그로 설명 가능

---

### E5) 비용을 목적함수/선정에 “내재화” (비용 미반영 제거)
- **실험 정의**
  - 단순 사후 차감이 아니라, 종목 선정/가중치 최적화 단계에서
    - 예상 거래비용(스프레드/슬리피지/수수료/borrow)을 페널티로 포함
    - turnover 상한 또는 L1 거래 페널티 적용
- **게이트**
  - 비용=0 시나리오 대비 비용 포함 시나리오에서 turnover가 의미 있게 감소하지 않으면 FAIL(비용이 의사결정에 반영 안 된 것)
- **기대 관측치**
  - “좋아 보이는데 실거래에서 죽는” 전략을 조기에 제거
  - 리밸런스가 잦아 생기던 과최적화/노이즈 트레이딩 감소

## 3) “성능이 안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래는 **로그/지표로 즉시 분기**할 수 있는 분해 트리입니다(질문 없이 바로 적용 가능한 체크 항목).

### A) Trigger(신호 생성) 단계
- [ ] 신호 분산(종목간 std)이 일정 임계치 이하인가? → **상수 신호** 의심
- [ ] 유효 피처 수/결측률이 폴드/날짜별로 급변하는가? → **데이터 파이프라인 붕괴/스냅샷 변경**
- [ ] 이벤트(실적/가이던스) 직후 성과 급등이 있나? → **누수 가능성**(E2로 차단)

### B) Apply(제약/가중치/리밸런스 적용) 단계
- [ ] target_weights는 변하는데 post_weights가 거의 고정인가? → **클리핑/캡/최소거래단위/쿨다운**
- [ ] 리밸런스가 “계산상 발생”했는데 트레이드가 0인가? → **비용/슬리피지로 trade 무효화** 또는 **거래가능성(유동성/borrow) 제약**
- [ ] degenerate folds가 특정 기간에 집중되는가? → **해당 기간 라벨/피처/유니버스 불연속**

### C) Exposure(노출) 단계
- [ ] net exposure가 0 근처로 오래 머무는가? → 레짐 게이트가 과도하거나, 신호가 약해 threshold 통과 못함
- [ ] gross exposure가 상한에 계속 걸리는가? → 종목 수(8~14) 제약 하에서 리스크 캡이 지나치게 타이트

### D) Cost(비용) 단계
- [ ] 비용 차감 전 성과와 차감 후 성과 괴리가 큰가? → **비용 미반영 과최적화**
- [ ] 특정 티커에서 비용/슬리피지가 비정상적으로 큰가? → 유동성 부족/스프레드 확대(헬스케어 바이오 소형주에서 흔함)
- [ ] borrow_cost/short availability가 원인인가? (숏이 있다면) → 숏 제약으로 실행 불가

### E) Regime(시장 국면) 단계 — ETF는 “관측지표”
- [ ] QQQ/XLK 추세 하락 + 변동성 상승 구간에서만 성과 악화인가? → 테크 베타 노출 문제
- [ ] XLV/VHT 상대강도 상승 국면에서 헬스케어 쏠림이 방어적으로 작동하는가?
- [ ] HYG 스프레드성 하락(리스크오프)에서 신호가 계속 롱을 강요하는가? → 레짐 게이트 필요(E4)

## 4) 24~48시간 “명령형 체크리스트”(질문 없이 실행)
1) **E1부터 적용**: 리밸런스 로그/비용/해시/worst_mdd를 non-null 강제 → pinpoint 도구가 정상 동작할 때까지 FAIL FAST.
2) **E3 적용**: degenerate fold 자동 FAIL + 원인 리포트 생성 → 현재 [1,2,3,8] 원인(상수예측/결측/라벨분산0)을 로그로 확정.
3) **E2 적용**: asof join + shift/lag + embargo → 누수/시간정렬 문제를 강제 차단하고 성능 변화를 확인.
4) **E5 적용**: 비용을 목적함수에 내재화 + turnover 페널티 → “실거래 불가능 알파” 제거.
5) **E4 적용**: Tech+Healthcare 8~14 종목 제약 + ETF 레짐 관측 기반 노출상한/틸트 → oos_min(최저구간)과 MDD를 우선 방어.

이 순서대로 돌리면, “성능이 안 움직임”을 **(로그 부재)→(CV 붕괴)→(누수/파이프라인)→(비용)→(레짐/노출)**로 단계적으로 고립시킬 수 있습니다.
