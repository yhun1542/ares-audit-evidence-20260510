### 1) TOP 5 실행 제안 (향후 48시간)

#### P1. [INFRA] 로그/메트릭 무결성 긴급 패치
*   **(a) 필요성:** `rebalance.csv` 파싱 에러 및 `worst_mdd: None`은 시스템이 '손실'을 제대로 기록하지 못하고 있음을 의미. 맹목적 비행 상태.
*   **(b) 리스크:** 전략 로직이 아닌 코드 버그 수정이므로 성능 수치가 급락할 수 있음(현실화).
*   **(c) 실험 (48hr Loop):**
    1.  **실험 정의:** `calc_metrics` 함수 내 `NaN`/`Inf` 처리 로직 강제 디버깅 및 거래 기록이 0인 Fold에 대해 강제 MDD 할당. JSONL 포맷터 강제 적용.
    2.  **게이트:** `rebalance_pinpoint.py`가 에러 없이 실행되고, 모든 Fold의 MDD가 `Float`으로 산출될 것.
    3.  **기대 관측치:** OOS Mean의 하락, degenerate_folds의 원인(Zero Trade vs Blow up) 식별.
*   **(d) PASS 조건:** `worst_mdd`가 유효 숫자(Valid Float)로 표출됨.

#### P2. [STRATEGY] Degenerate Fold 강제 노출 주입 (Unlock Frozen Folds)
*   **(a) 필요성:** Fold 1, 2, 3, 8의 침묵은 과도한 Risk Gate(변동성 필터)가 작동했거나 시그널 생성 실패를 의미. 최소한의 거래를 강제하여 문제 구간을 시각화해야 함.
*   **(b) 리스크:** 하락장 방어 기제가 해제되어 MDD가 급격히 증가할 수 있음.
*   **(c) 실험 (48hr Loop):**
    1.  **실험 정의:** `min_exposure`를 0.0에서 **0.15**로 상향 조정 (현금 비중 최대 85% 제한).
    2.  **게이트:** Degenerate Fold 목록에서 최소 2개 Fold가 제외될 것.
    3.  **기대 관측치:** 침묵하던 Fold의 수익률이 음수(-)로 찍히더라도 거래 로그가 생성되어야 함.
*   **(d) PASS 조건:** `degenerate_folds` 개수 감소 (4개 -> 2개 이하).

#### P3. [UNIVERSE] Tech/Healthcare 섹터 집중도 및 상관성 점검
*   **(a) 필요성:** 현재 8~14개 종목이 특정 단일 팩터(예: AI 모멘텀)에만 쏠려있어, 해당 팩터가 죽은 구간(Fold 1,2,3)에서 전멸했을 가능성.
*   **(b) 리스크:** 유니버스 교체 시 기존 학습 가중치 무효화.
*   **(c) 실험 (48hr Loop):**
    1.  **실험 정의:** 유니버스 내 Tech:Healthcare 비율을 **6:4**로 강제 리밸런싱. (Low Correlation 페어링 강제).
    2.  **게이트:** 포트폴리오 전체 변동성(Portfolio Volatility) 감소 확인.
    3.  **기대 관측치:** 특정 섹터 급락 구간에서 OOS Min 방어력 상승.
*   **(d) PASS 조건:** `oos_min` > -0.02 유지하면서 `oos_mean` > 2.0 유지.

#### P4. [COST] 슬리피지/비용 스트레스 테스트
*   **(a) 필요성:** OOS Mean 3.32는 비현실적. 비용 모델이 누락되었거나 너무 낮게 책정되었을 가능성. 과최적화 거품 제거 필요.
*   **(b) 리스크:** 성과 지표 대폭 하락으로 챔피언 모델 폐기 가능성.
*   **(c) 실험 (48hr Loop):**
    1.  **실험 정의:** 거래 비용(Transaction Cost)을 현재 설정의 **2배(예: 10bps -> 20bps)**로 설정 후 백테스트.
    2.  **게이트:** OOS Mean이 1.5 이상 유지될 것.
    3.  **기대 관측치:** 회전율(Turnover)이 높은 전략일수록 성능 급감 확인.
*   **(d) PASS 조건:** 비용 2배 적용 후에도 Sharpe Ratio > 1.0 유지.

#### P5. [LOGIC] 변동성 기반 진입 게이트 완화 (Vix Filter Relax)
*   **(a) 필요성:** 시장 변동성(VIX 등)이 높을 때 진입을 아예 막는 로직이 있다면, 기회를 놓치고 있을 수 있음(특히 회복장 초입).
*   **(b) 리스크:** 하락장 칼날 잡기(Catching falling knife)로 인한 손실 확대.
*   **(c) 실험 (48hr Loop):**
    1.  **실험 정의:** 진입 금지(Veto) 조건인 `Market_Vol_Threshold`를 기존 대비 **20% 상향** (더 높은 변동성 허용).
    2.  **게이트:** 승률(Win Rate) 45% 이상 유지.
    3.  **기대 관측치:** 거래 횟수 증가, Drawdown 회복 속도 단축.
*   **(d) PASS 조건:** 총 거래 횟수(Trade Count) 15% 이상 증가.

### 2) 성능 정체 원인 분해 (Debug Checklist)

성능 지표가 움직이지 않거나(Flatline), Degenerate Fold가 해결되지 않을 때 다음을 순차적으로 점검하십시오.

1.  **트리거(Trigger) 불발:**
    *   *현상:* 시그널이 생성되지만 주문이 나가지 않음.
    *   *점검:* `alpha_score`가 `entry_threshold`를 넘지 못하는지 확인. Threshold를 0으로 낮춰 모든 시그널 강제 실행 테스트.

2.  **노출(Exposure) 차단:**
    *   *현상:* `exposure_max`가 0.84인데 실제 포지션은 0에 수렴.
    *   *점검:* 리스크 매니저(Stop-loss, Vol-target)가 진입 즉시 청산(Close)을 날리는지 확인. `stop_loss_pct`를 일시적으로 `None` 처리.

3.  **비용(Cost) 장벽:**
    *   *현상:* Gross Return은 우상향이나 Net Return이 0 또는 음수.
    *   *점검:* `slippage_model`이 유동성이 적은 종목(Small cap bio)에 대해 과도한 페널티를 부과하는지 확인.

4.  **레짐(Regime) 불일치:**
    *   *현상:* 특정 연도(Fold)에서만 성능이 0.
    *   *점검:* 해당 연도의 ETF(XLK, XLV) 트렌드와 전략의 Long/Short 성향 비교. Long Only 전략이 하락장(2022년 등)을 만나면 Degenerate(0 거래)가 최선일 수 있음 -> 이 경우 **Short 전략 추가** 혹은 **Inverse ETF 지표 활용** 고려.

5.  **데이터(Data) 누락:**
    *   *현상:* 특정 기간 캔들 데이터 Missing.
    *   *점검:* 데이터 로더 로그에서 `ffill` 혹은 `drop` 비율 확인.
