## 1. 우선순위 TOP 5 실행 체크리스트

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### P1. Degenerate Fold 원인 분해 (신뢰성 최우선)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- 4/10 폴드가 퇴화 → OOS 수치 자체가 무의미할 수 있음
- 누수/레짐편향/표본부족 중 원인 미분리 상태

**(b) 위험/부작용**
- 폴드 제거 시 survivorship bias 발생
- 원인 오진 시 잘못된 방향으로 최적화

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 조건 | 기대 관측치 |
|----|-----------|-------------|-------------|
| P1-A | 퇴화 폴드(1,2,3,8) 기간 추출 → 해당 기간 시장 레짐 라벨링 (VIX>25, SPY DD>10%) | 자동완료 | 4폴드 중 3개 이상 고변동 레짐이면 "레짐 문제" |
| P1-B | 퇴화 폴드에서 feature importance 상위 3개 추출 → train/test 분포 KS-test | KS p-value < 0.05 개수 | 2개 이상이면 "데이터 시프트" |
| P1-C | 퇴화 폴드 제외 후 OOS 재계산 (6-fold) | OOS Mean 변화율 | >20% 상승이면 "폴드 품질 문제 확정" |

**(d) PASS 조건**
```
IF P1-A="레짐문제" → 레짐 필터 추가 (P3로)
IF P1-B="데이터시프트" → feature 재검토 (P2로)  
IF P1-C > 20% 상승 → 폴드 구조 자체 재설계
```

- Feature 생성 시 look-ahead bias 가능성

**(b) 위험/부작용**
- 누수 발견 시 전체 재실험 필요 (시간 손실)
- 과민 진단 시 정상 feature 제거

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 조건 | 기대 관측치 |
|----|-----------|-------------|-------------|
| P2-A | Feature 생성 timestamp vs 예측 대상 timestamp 전수 검사 스크립트 | 위반 건수 | 0건이면 PASS |
| P2-B | Random shuffle target → 동일 파이프라인 OOS | OOS Mean | < 0.5 (무작위 수준)이면 PASS |
| P2-C | Purged K-Fold (embargo 5일) 적용 → OOS 재측정 | OOS 하락율 | < 15% 하락이면 PASS |

**(d) PASS 조건**
```
P2-A = 0 AND P2-B < 0.5 AND P2-C 하락 < 15% → 누수 없음 확정
ANY FAIL → 해당 지점 수정 후 전체 재실험
```
