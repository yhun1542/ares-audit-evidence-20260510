### #1. Tuning Fold 취약점 격리 및 원인 분해
### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- tuning_min이 -1.497로 champion보다 악화
- Lockbox는 개선됐으나 OOS 일반화 불확실
- 특정 fold에서 과최적화 누수 가능성

**(b) 위험/부작용**
- 해당 fold 제거 시 샘플 손실 (유효 데이터 ~7% 감소/fold당)
- 과도한 fold 필터링 → 서바이버십 바이어스 유발

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 조건 |
|----|----------|------------|
| 1-A | 각 fold별 return 분포 출력 → worst fold 식별 | worst_fold_return < -1.0 인 fold 수 ≤ 2 |
| 1-B | worst fold 제외 후 candidate 재평가 | lockbox_mean 유지 (≥1.50) AND tuning_min > -1.0 |
| 1-C | worst fold 기간 vs VIX/금리 레짐 매핑 | 레짐 태그 일치율 > 70% |

**(d) PASS 조건**
```
tuning_min > -1.2 AND lockbox_mean ≥ 1.50 AND worst_mdd < -5.5%
```
