### P1. 🔴 MDD 집중 공략 (worst_mdd = -11.18% → 목표 -9% 이하)

**(a) 왜 필요한지**
- lockbox_mean은 1.79로 충분 → 추가 수익 추구는 과최적화 위험
- MDD -11%는 실운용시 심리적/자본 리스크
- MDD 개선이 Sharpe 대비 로버스트한 신호

**(b) 위험/부작용**
- 수익률 감소 가능 (mean 1.6대로 하락 용인)
- 포지션 축소로 거래비용 효율 저하

**(c) 최소 실험**

```yaml
EXP-P1-A: # Drawdown-triggered deleveraging
  변경: peak 대비 -5% 도달시 exposure 50% 축소
  gate: worst_mdd < -0.10 AND lockbox_mean > 1.65
  관측치: MDD 분포, 회복 기간(days)

EXP-P1-B: # Sector concentration cap
  변경: 단일 섹터 노출 40% → 30% 하드캡
  gate: worst_mdd < -0.10 AND lockbox_min > 1.30
  관측치: Tech 집중도 피크, sector별 MDD 기여도

EXP-P1-C: # Volatility regime filter
  변경: VIX 25+ 시 신규진입 중단, 기존포지션 유지만
  gate: worst_mdd < -0.10 AND 연간 거래횟수 -20% 이내
  관측치: 레짐별 승률, 기회비용 추정
```

**(d) PASS 조건**
- `worst_mdd < -0.10 (= -10%)` **AND** `lockbox_mean ≥ 1.65`

### P2. 🟠 Min Fold 안정성 (tuning_min = 0.05 → 위험)

**(a) 왜 필요한지**
- tuning_min = 0.05 = 특정 fold에서 거의 손익분기
- 이건 **과최적화 or 레짐 취약성** 신호
- lockbox에서 숨겨진 시한폭탄

**(b) 위험/부작용**
- 해당 fold가 outlier인지 구조적인지 판별 필요
- 수정 시 다른 fold 성능 저하 가능

**(c) 최소 실험**

```yaml
EXP-P2-A: # Worst fold 분석
  변경: 코드 수정 없음, 분석만
  출력: worst_fold 기간, 주요 종목, 손실 원인 breakdown
  gate: N/A (분석)
  관측치: 어떤 섹터/종목/레짐에서 손실 집중?

EXP-P2-B: # Minimum exposure floor
  변경: 어떤 시점에도 최소 20% cash 유지
  gate: tuning_min > 0.30 AND lockbox_mean > 1.60
  관측치: fold별 min 분포 변화

EXP-P2-C: # Tail risk scaling
  변경: 개별종목 loss -15% 시 즉시 청산
  gate: tuning_min > 0.20 AND worst_mdd 개선
  관측치: 조기청산 횟수, 기회비용
```

**(d) PASS 조건**
- `tuning_min > 0.25` **AND** `lockbox_mean ≥ 1.70`

### P3. 🟡 비용 현실화 점검

**(a) 왜 필요한지**
- 현재 백테스트 비용 모델 검증 필요
- slippage, 실제 spread가 반영 안 됐으면 lockbox 수치 무의미
- 특히 Healthcare 소형주는 spread 클 수 있음

**(b) 위험/부작용**
- 비용 올리면 수익률 하락 (하지만 현실 반영)
- 거래빈도 축소 압박

**(c) 최소 실험**

```yaml
EXP-P3-A: # Slippage stress test
  변경: slippage 10bp → 25bp로 증가
  gate: lockbox_mean > 1.50 (생존 여부 확인)
  관측치: 수익률 민감도, breakeven slippage

EXP-P3-B: # Turnover penalty
  변경: 연간 turnover 200% 초과 시 페널티 적용
  gate: turnover < 250% AND lockbox_mean > 1.60
  관측치: 거래빈도 vs 수익 trade-off
```

**(d) PASS 조건**
- slippage 25bp에서 `lockbox_mean ≥ 1.50` (stress survival)

## 3. 성능 plateau 원인 분해 트리

```
성능이 안 움직일 때
│
├─ (1) 트리거 문제
│   ├─ 신호가 이미 포화 (alpha decay)
│   ├─ 임계값이 너무 tight → 발동 안 함
│   └─ 체크: 신호 발동 횟수 / 월 추적
│
├─ (2) 적용 문제
│   ├─ 코드 버그 (변경이 실제 반영 안 됨)
│   ├─ 모듈 간 충돌
│   └─ 체크: 변경 전후 거래로그 diff
│
├─ (3) 노출 문제
│   ├─ 포지션 사이즈가 너무 작음
│   ├─ 동시 반대 신호로 상쇄
│   └─ 체크: 일별 net exposure 분포
│
├─ (4) 비용 문제
│   ├─ 개선분이 거래비용에 먹힘
│   ├─ turnover 증가 > 수익 증가
│   └─ 체크: gross return vs net return gap
│
└─ (5) 레짐 문제
    ├─ 테스트 기간에 유리한 레짐 부재
    ├─ 새 전략이 특정 레짐에서만 작동
    └─ 체크: 레짐별 수익 breakdown (bull/bear/sideways)
```
