### 1. 24~48시간 우선순위 TOP 3 제안 (Action Plan)

현재 `candidate_..._exp_mrd_fsa` (Mean Reversion / Feature Selection Adaptation 추정)가 Champion 대비 **Lockbox(OOS) 성능이 급격히 향상(Mean 1.32 -> 1.55)**되었으나, **Training Min 값은 악화(-1.34 -> -1.49)**되었습니다. 이는 과적합보다는 "고위험 고수익" 구조로의 변질 가능성을 시사합니다. 따라서 다음 단계는 **'하방 경직성 강화'**와 **'비용 민감도 테스트'**입니다.

#### [Priority 1] Candidate 스트레스 테스트 및 비용 가중치 상향
*   **(a) 이유:** Lockbox 성능이 급등한 경우, 낮은 유동성 종목이나 비현실적인 체결 가격을 가정했을 가능성(Slippage 누락)이 큼. Tech/Bio 섹터의 변동성을 고려할 때 비용 구조를 가혹하게 적용해야 함.
*   **(b) 위험:** 테스트 통과 기준이 너무 높아져 유효한 시그널까지 폐기될 수 있음.
*   **(c) 실험 정의:**
    *   **EXP-01-COST:** 현재 슬리피지 모델(예: 5bps)을 2배(10bps)로 설정하고 `candidate_..._exp_mrd_fsa` 재검증.
    *   **EXP-02-DELAY:** 시그널 발생 후 체결까지 1-bar delay(지연) 강제 적용 후 성능 하락폭 측정.
*   **(d) PASS 조건:**
    *   Lockbox Mean > 1.4 (기존 1.55에서 하락 허용)
    *   Lockbox Min > 0 (손실 전환 금지)

#### [Priority 2] 변동성 역가중(Inverse Volatility) 포지션 사이징 적용
*   **(a) 이유:** Tuning Min 값 악화(-1.49)는 특정 종목(바이오/테크 급락)에 과도한 비중이 실렸음을 의미. 8~14개 종목 포트폴리오에서 개별 종목 리스크를 제어해야 함.
*   **(b) 위험:** 강한 추세장(Momentum)에서 수익률이 둔화될 수 있음 (Under-betting).
*   **(c) 실험 정의:**
    *   **EXP-03-VOL-SIZE:** 매수 시그널 발생 시, 고정 비중(1/N) 대신 `Target_Risk / Rolling_ATR(14)`로 개별 비중 산출. (최대 비중 Cap 15% 설정).
    *   **EXP-04-BETA-NEUTRAL:** (ETF 관측 활용) QQQ 또는 XLV와의 Beta가 1.5 이상인 종목의 진입 비중 50% 축소.
*   **(d) PASS 조건:**
    *   Tuning Min > -1.2 (하방 리스크 개선)
    *   Worst MDD < -0.06 (기존 Champion 수준 유지)

#### [Priority 3] 섹터 내 상관관계 페널티 (Correlation Penalty)
*   **(a) 이유:** Tech와 Healthcare는 내부 하위 섹터(반도체 vs SW, 제약 vs 의료기기) 간 디커플링이 존재함. 단순히 상위 랭킹만 매수하면 상관계수 1에 가까운 종목만 담을 위험(Cluster Risk).
*   **(b) 위험:** 연산 비용 증가 (Covariance Matrix 계산), 포트폴리오 회전율 감소.
*   **(c) 실험 정의:**
    *   **EXP-05-CORR-FILTER:** 진입 후보군(Top 20) 중 기존 보유 종목과 상관계수(60일)가 0.8 이상인 신규 종목 진입 차단.
*   **(d) PASS 조건:**
    *   Fold14 MDD 개선 (현재 -0.041 유지 혹은 개선)
    *   Sharpe Ratio 상승 (변동성 감소 효과 확인)

### 2. 48시간 자동 루프 정의 (Automated Loop Spec)

시스템에 다음 설정을 주입하여 48시간 동안 무인 검증을 수행하십시오.

#### (1) 실험 정의 (Experiment Definition)
```yaml
experiment_batch:
  base_candidate: "baseline/candidate_20260102_001102_exp_mrd_fsa.json"
  variations:
    - name: "STRESS_TEST_COST"
      params:
        transaction_cost_bps: 10  # Double the standard
        slippage_model: "quadratic"
    - name: "VOL_TARGETING"
      params:
        position_sizing: "inverse_volatility"
        vol_lookback: 20
        max_position_weight: 0.15
    - name: "CORRELATION_CAP"
      params:
        max_correlation_threshold: 0.85
        lookback_window: 60
```

#### (2) 게이트 (Gates - Hard Constraints)
*   **Gate 1 (Survivorship):** 최근 12개월 내 상장 폐지된 종목이 유니버스에 포함되어 있는가? (필수 포함되어야 함)
*   **Gate 2 (Overfitting):** `Lockbox Sharpe` / `Tuning Sharpe` 비율이 0.7 ~ 1.3 사이인가? (비율이 너무 높거나 낮으면 기각)
*   **Gate 3 (Drawdown):** Worst Case MDD가 -10%를 초과하는가? (초과 시 즉시 Kill)

#### (3) 기대 관측치 (Expected Observations)
*   **성공 시나리오:** `VOL_TARGETING` 적용 시 Tuning Min이 -1.49에서 -1.1 수준으로 회복되고, Lockbox Mean은 1.45 수준에서 방어됨.
*   **실패 시나리오:** `STRESS_TEST_COST` 적용 시 Lockbox Mean이 1.0 이하로 급락 -> 현재 Candidate의 수익성이 거래 비용에 지나치게 의존적임(Scalping 성향)을 의미. 이 경우 진입 로직의 `Threshold`를 높여야 함.

### 3. 성능 정체 시 원인 분해 프로토콜 (Debug Protocol)

성능 지표(Sharpe, MDD)가 개선되지 않거나 횡보할 경우, 다음 5가지 차원에서 원인을 진단하십시오.

1.  **트리거(Trigger):** 시그널이 너무 늦게 뜨는가?
    *   *Check:* 진입 시점의 `Next Open` 수익률과 `Next Close` 수익률 간의 괴리 확인. (시초가 갭으로 알파 소멸 여부)
2.  **적용(Execution):** 목표 비중을 채우지 못하는가?
    *   *Check:* `Fill Rate`(체결률) 지표 확인. 유동성 부족으로 인한 미체결 발생 빈도.
3.  **노출(Exposure):** 시장 베타에만 의존하는가?
    *   *Check:* 전략 수익률과 QQQ 수익률의 상관계수가 0.9 이상이면 알고리즘 무의미. (Alpha 부재)
4.  **비용(Cost):** 잦은 매매가 이익을 갉아먹는가?
    *   *Check:* 총 손익 대비 수수료/슬리피지 비율이 20%를 넘는지 확인.
5.  **레짐(Regime):** 전략과 시장 상황이 불일치하는가?
    *   *Check:* Mean Reversion 전략인데 VIX가 낮고 일방적 상승장(Trend)인지 확인. (이 경우 Trend Following 로직 비중 확대 필요)
