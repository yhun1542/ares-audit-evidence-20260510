## TOP 5 우선순위 제안

### #1. Lockbox 괴리 원인 분해 (누수/과최적화 점검)

#### (a) 왜 필요한지
- Champion tuning 2.32 vs lockbox 4.01 = **1.7배 괴리** → 역방향 괴리가 비정상
- 가능성: (1) lockbox 데이터 누수 (2) lockbox가 특이 레짐 (3) 튜닝 fold 불충분

#### (b) 위험/부작용
- 누수 발견 시 lockbox 재정의 필요 → 전체 실험 기준 리셋
- 과최적화 아닐 경우 시간 낭비 (2-4h)

#### (c) 최소 실험
```yaml
EXP-1.1: lockbox_leakage_audit
  action: |
    python3 -c "
    from utils.data_audit import check_temporal_leakage
    check_temporal_leakage(
      training_end='tuning_fold_max_date',
      lockbox_start='lockbox_min_date',
      feature_files=['features/*.parquet']
    )"
  gate: 누수 발견 여부
  expect: gap_days >= 21 (3주 버퍼)

EXP-1.2: lockbox_regime_decompose
  action: |
    python3 experiment_system/tools/regime_analyzer.py \
      --lockbox-period \
      --output baseline/reports/lockbox_regime.json
  gate: VIX/금리/섹터 분포가 tuning과 유사한지
  expect: regime_overlap_score >= 0.6

EXP-1.3: champion_oos_variance
  action: |
    # Champion을 tuning folds 중 held-out 3개에 적용
    python3 backtest_runner.py \
      --config baseline/champion_v5_latest.json \
      --folds 12,13,14 --mode pure_oos
  gate: OOS 성능 분산
  expect: std(fold_returns) < 0.5
```

#### (d) PASS 조건
- [ ] 누수 없음 (gap ≥ 21일)
- [ ] lockbox regime이 특이하지 않음 (overlap ≥ 0.6)
- [ ] OOS 분산 정상 (std < 0.5)

## 성능 안 움직일 때 원인 분해 트리

```
성능 정체 원인 분해
│
├─ (1) 트리거 실패
│   ├─ 시그널이 발생 안 함 → 조건 너무 엄격
│   ├─ 시그널 지연 → lookback 너무 김
│   └─ 검증: signal_firing_rate < 5% 이면 문제
│
├─ (2) 적용 실패
│   ├─ 시그널 있지만 포지션 안 잡힘 → 필터/제약 충돌
│   ├─ 포지션 잡히지만 너무 작음 → sizing 로직
│   └─ 검증: signal_to_trade_conversion_rate
│
├─ (3) 노출 부족
│   ├─ 평균 투자비중 < 50% → 현금 과다
│   ├─ 보유 기간 너무 짧음 → alpha 실현 전 청산
│   └─ 검증: avg_exposure, avg_holding_days
│
├─ (4) 비용 상쇄
│   ├─ gross return은 있으나 net ≈ 0
│   ├─ 회전율 과다
│   └─ 검증: gross_vs_net_return_gap
│
└─ (5) 레짐 미스매치
    ├─ 특정 레짐에서만 작동 → 현재 레짐과 불일치
    ├─ 레짐 전환기에 손실
    └─ 검증: return_by_regime_bucket
```
