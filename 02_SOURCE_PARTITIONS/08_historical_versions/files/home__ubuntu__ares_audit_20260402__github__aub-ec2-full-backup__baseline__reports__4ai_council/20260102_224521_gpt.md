## 다음 24~48시간 TOP5 우선순위 (코드/아키텍처/전략) — 명령형 체크리스트

### 1) **누수/서바이버십 + Fold 퇴행(degenerate_folds) 즉시 봉합**
- (a) 왜 필요한지  
  - `degenerate_folds: [1,2,3,8]`는 OOS가 “학습/검증 분리가 깨졌거나(누수), 표본이 비거나, 라벨/피처 정렬이 깨진” 전형 신호다. 이 상태의 OOS mean은 신뢰 불가(과최적화·우연성) 가능성이 높다.
- (b) 위험/부작용  
  - 봉합 후 성능 급락 가능(“진짜” 성능으로 수렴).  
  - 데이터 필터 강화로 트레이드 수/노출 급감 가능.
- (c) 최소 실험(공용 실험 ID 사용, 전체 4개 실험만 운용)  
  - **[E1] Point-in-time/정렬/서바이버십 감사 + Fold 복구** (아래 “48h 자동 루프” 섹션 참조)  
  - **[E4] 과최적화 억제(Seed/Fold bagging + 안정성 게이트)**로 fold 퇴행 재발 방지
- (d) PASS 조건  
  - `degenerate_folds == []`  
  - OOS 분포가 “소수 fold에만 의존”하지 않음(최소 80% fold에서 유의미 샘플 수/거래 수 확보)  
  - OOS mean이 다소 하락하더라도 OOS min/분산이 안정화(꼬리 리스크 축소)

---

### 2) **비용/슬리피지 미반영(또는 과소반영) 우선 차단**
- (a) 왜 필요한지  
  - Tech+Healthcare 8~14 종목은 개별주 거래비용(스프레드/임팩트/리밸 빈도)에 성능이 크게 흔들린다. “OOS가 안 움직이는” 경우도 실제론 비용이 신호 개선분을 상쇄하는 케이스가 많다.
- (b) 위험/부작용  
  - 비용 모델이 과보수적이면 노출이 과도하게 줄어 성능이 죽을 수 있음.  
  - 반대로 과소추정 시 라이브에서 성능 붕괴.
- (c) 최소 실험  
  - **[E2] 비용/임팩트 모델 추가 + turnover 예산 게이트**  
  - **[E3] 리밸/체결 제약(ADV/스프레드 기반)으로 비용 민감도 완화**
- (d) PASS 조건  
  - Net(비용 차감) 기준 OOS mean 개선 또는 최소 유지 + OOS min 개선  
  - Turnover가 명시 예산 이하로 수렴(예: 주당/월당 상한)  
  - 비용(슬리피지 포함) 기여도가 PnL의 상수항으로 안정(특정 구간에서만 폭발하지 않음)

---

### 3) **운영 리스크(재현성/로깅/리밸 로그 누락) 복구**
- (a) 왜 필요한지  
  - `lane_hash/run_hash: None`, 리밸 pinpoint가 `--base-log`/CSV/JSONL 로딩 실패 → “무엇이 언제 왜 바뀌었는지” 역추적 불가. 48시간 자동 루프의 최대 적이다.
- (b) 위험/부작용  
  - 로깅/아티팩트 강제는 디스크/IO 비용 증가.  
  - 구성 강제(고정 seed 등)로 탐색 다양성 일부 감소.
- (c) 최소 실험(전략 실험이 아니라 **패치 + 검증 실험**)  
  - **[E1]**에 “데이터 스냅샷 해시 + 피처/유니버스 해시 + 리밸 로그 포맷 강제”를 포함  
  - **[E3]**에서 리밸 이벤트 단위(JSONL) 로깅을 강제(주문/체결/비용 분해)
- (d) PASS 조건  
  - 모든 런에 `run_hash/lane_hash` 생성 및 보고서에 자동 삽입  
  - `rebalance_pinpoint`가 base/cand 모두에서 정상 로딩, 리밸 이벤트 100% 재현  
  - 동일 config 재실행 시 핵심 지표(oos_mean, turnover, exposure)가 허용 오차 내 재현

---

### 4) **노출/리밸 규율(8~14개, Tech+Healthcare) 강제 + 퇴행 방지**
- (a) 왜 필요한지  
  - `exposure_max ~0.84`는 “가끔 과도 노출”이 발생한다는 뜻이고, 8~14개 소수종목은 단일 종목/단일 이벤트에 꼬리위험이 커진다.  
  - 노출 규율이 없으면 OOS가 좋아 보여도 운영에서 MDD/갭리스크로 죽는다.
- (b) 위험/부작용  
  - 규율이 과도하면 기회 손실(특히 강한 트렌드 국면).  
  - 리밸 완화는 반응 지연(신호가 빨리 죽는 전략이면 손해).
- (c) 최소 실험  
  - **[E3] 노출/포지션/회전율/유동성 제약 포함 리밸 엔진 패치**  
  - **[E2] 비용 포함 후에도 규율이 성능을 유지하는지 동시 검증**
- (d) PASS 조건  
  - 종목별/총 노출 상한 준수(예: 1종목 max, 총 gross/net 범위)  
  - “거래 수는 줄어도” OOS min(최악 케이스) 개선  
  - 리밸 빈도·회전율이 예산 내로 수렴하며 PnL이 특정 리밸 타이밍에만 의존하지 않음

### 5) **성능 정체(“No-Delta”)의 원인을 ‘신호 vs 실행 vs 레짐’으로 분해하는 관측계 추가**
- (a) 왜 필요한지  
  - 이미 `no_delta_diagnoser`가 돌고 있는데, 결과를 “어디가 막혔는지” 자동으로 쪼개서 다음 액션을 고정해야 48시간 루프가 산다.
- (b) 위험/부작용  
  - 지표가 많아지면 오히려 의사결정이 느려질 수 있음 → 게이트(합격/불합격)만 남기고 나머지는 로그로만 저장.
- (c) 최소 실험  
  - **[E4] 신호-포트-비용-레짐 분해 리포트 자동 생성 + 게이트 연동**  
  - (필요 시) **[E1]**에 “누수 스캐너 결과를 게이트에 직접 반영”
- (d) PASS 조건  
  - “성능 불변”이 발생하면 자동으로 1) 신호 약화 2) 적용/리밸 실패 3) 노출 상쇄 4) 비용 상쇄 5) 레짐 미적합 중 최소 1개로 귀결(UNKNOWN 비율 축소)  
  - 다음 런의 실험 선택이 자동으로 1~2개로 좁혀짐(케이스 폭발 금지)

## 48시간 자동 루프용 “실행 가능한 Patch/실험” 4개만 운용 (정의/게이트/기대 관측치)

### [E1] 데이터/유니버스 누수-서바이버십 감사 + Fold 복구 + 아티팩트 해시/로그 강제
1) 실험 정의(패치)
- **Point-in-time 강제**:  
  - 라벨 생성 시점 이후 데이터(재무/리비전/분류/지표)가 피처에 섞이는지 스캔(lookahead scanner).  
  - 유니버스(Tech+Healthcare 8~14) 구성 로직에 “당시점(as-of) 분류”만 사용하도록 고정.
- **Fold 복구**:  
  - fold별 최소 표본/거래수 하한 설정(미달 fold는 자동 병합 또는 제외)  
  - 시간순 워크포워드로 고정하고, 라벨 기간과 겹침 방지(embargo) 적용
- **운영 로깅**: run_hash/lane_hash 생성, 데이터 스냅샷 해시, 피처 해시, 유니버스 해시 저장

2) 게이트
- `degenerate_folds == []`  
- 누수 스캐너 FAIL=0 (또는 허용된 예외 목록만)  
- 동일 config 재실행 시 핵심 지표 재현(허용 오차 내)

3) 기대 관측치
- OOS mean은 변동 가능(대개 하락)하나 OOS 분산/최악값이 안정화  
- fold별 성능 편차 감소, 특정 fold “잭팟” 현상 감소  
- 리밸/포지션 로그가 항상 생성되어 pinpoint가 동작

---

### [E2] 비용/슬리피지/임팩트 모델 도입 + Net 기준 게이트로 전환
1) 실험 정의(패치)
- 거래비용 = (고정 커미션) + (스프레드 기반) + (ADV 대비 체결량 기반 임팩트)  
- 비용 파라미터는 보수/기본/낙관 3단(단, **전략 제안은 1개 실험으로 묶고** 리포트에서 3단 민감도만 출력)

2) 게이트
- Net OOS mean이 Gross 대비 과도하게 붕괴하지 않을 것(붕괴 시 원인=turnover/체결량/리밸 빈도로 자동 분류)  
- Turnover 예산 초과 시 FAIL

3) 기대 관측치
- “성능 정체”의 상당수가 비용 상쇄로 분류되며, 리밸/노출 규율(E3)로 이동할 트리거가 생김  
- 비용 민감도가 큰 구간(고변동/저유동) 자동 표기

---

### [E3] 리밸 엔진/노출/유동성 제약 패치 (8~14개, Tech+Healthcare 유지)
1) 실험 정의(패치)
- 8~14개 유지(ETF 매매 없음), 종목별 max weight, 총 gross/net, 일일 거래량(ADV) 대비 참여율 상한  
- 리밸을 “전량 교체”가 아닌 **부분 리밸(목표 대비 갭만큼)**로 변경  
- 리밸 이벤트를 JSONL로 표준 로깅(주문수량/체결가/비용/슬리피지/사유코드)

2) 게이트
- 제약 위반 0건(상한/ADV/참여율)  
- turnover 예산 준수  
- 노출 max가 상한 내로 수렴(현재 0.84 피크를 관리)

3) 기대 관측치
- MDD/꼬리 손실 완화(특히 갭/급락 구간)  
- 비용(E2)과 결합 시 Net 성능의 “실제” 안정성 상승  
- 리밸 pinpoint가 “어느 규칙 때문에 거래가 줄었는지”까지 역추적 가능

---

### [E4] 과최적화 억제 + 신호/적용/노출/비용/레짐 분해 리포트 자동화
1) 실험 정의(패치)
- seed/fold bagging(동일 전략을 여러 seed로 학습 후 앙상블)로 fold 잭팟 제거  
- 리포트에 다음 분해를 고정 출력:
  - Signal: 예측 분포/IC/Hit rate  
  - Apply: 신호→주문 변환 실패율(제약으로 컷된 비율)  
  - Exposure: 섹터/종목/베타/변동성 노출  
  - Cost: 비용 항목별 PnL 상쇄 기여  
  - Regime: 변동성/금리/나스닥 레짐(ETF는 **관측 지표**로만: QQQ/XLV 등 레짐 태깅)

2) 게이트
- 앙상블 후 OOS min(최악값) 개선 또는 분산 감소가 확인될 것  
- “No-Delta” 발생 시 자동 분류 결과가 UNKNOWN이 아니어야 함(UNKNOWN 비율 상한)

3) 기대 관측치
- 성능이 안 움직일 때도 “원인 라벨”이 붙어서 다음 48시간 액션이 자동으로 수렴  
- 과최적화로 인한 fold 편차/급격한 성능 변동 감소

---

## 성능이 안 움직일 때(“No-Delta”) 원인 분해 아이디어 — 트리거/적용/노출/비용/레짐 순서

아래 순서대로 **자동 판정 규칙(트리거)**를 걸어 “어디가 막혔는지”를 한 번에 좁혀라.

1) **트리거(신호 발생) 문제**
- 증상: 예측 분포가 0 근처로 붕괴, 신호 분산 급감, IC≈0  
- 체크: 피처 스케일/결측 처리 변경, 라벨 기간 변경, 데이터 컷오프 오프바이원  
- 액션: E1(정렬/누수) 로그로 “피처 해시 변화” 탐지, E4에서 신호 분포 경보

2) **적용(신호→주문) 문제**
- 증상: 신호는 있는데 실제 포지션 변화가 없음(거래수 0 또는 급감), 리밸 로그 부재/오류  
- 체크: 제약이 너무 타이트, 리밸 스케줄/캘린더 버그, 포지션 라운딩(수량 0)  
- 액션: E3 리밸 이벤트 로그로 “컷 사유코드(ADV/상한/턴오버)” 집계

3) **노출 상쇄/집중 문제**
- 증상: 종목 몇 개에 쏠려 베타/섹터 노출이 결과를 지배, 특정 이벤트에 성능이 고정  
- 체크: 8~14개 소수 종목 특성상 단일 종목 리스크 관리 부재  
- 액션: E3 상한/분산 규율, E4에서 종목별 PnL/리스크 기여도 출력

4) **비용 상쇄 문제**
- 증상: Gross는 미세 개선인데 Net이 정체/악화, turnover가 높거나 특정 레짐에서 비용 폭발  
- 체크: 스프레드/임팩트 과소추정, 잦은 리밸, 유동성 낮은 종목 편중  
- 액션: E2 비용 민감도 리포트 + E3 참여율/부분리밸로 완화

5) **레짐 미적합 문제(관측 ETF로 태깅만)**
- 증상: 특정 레짐(고변동/금리 급등/나스닥 급락)에서만 지속 손실  
- 체크: Tech/Healthcare 내에서도 레짐 따라 팩터가 반전  
- 액션: E4 레짐 태그로 구간 성능 분해 → “레짐별 실패 원인”이 비용인지/노출인지/신호인지로 다시 귀결

---

## 즉시 실행 순서(48시간 내) — 명령형
1) **E1 먼저 실행**: degenerate_folds 제거 + 누수/정렬/서바이버십 스캔 + run_hash/lane_hash/리밸 로그 강제.  
2) **E2 실행**: Net 기준으로만 평가 전환, turnover 예산 게이트 추가.  
3) **E3 실행**: 부분 리밸 + ADV/참여율/노출 상한 + 리밸 JSONL 표준 로그.  
4) **E4 실행**: seed/fold bagging + 신호/적용/노출/비용/레짐 자동 분해 리포트 및 UNKNOWN 축소 게이트.  
5) 위 4개 중 하나라도 FAIL이면 다음 루프에서 “전략 변경” 금지하고 FAIL 원인 패치만 재실행(과최적화 방지).
