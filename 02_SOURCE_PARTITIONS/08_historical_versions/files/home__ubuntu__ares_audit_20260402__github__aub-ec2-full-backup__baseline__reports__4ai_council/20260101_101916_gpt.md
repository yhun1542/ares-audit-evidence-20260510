아래 TOP5는 **누수/과최적화/서바이버십/비용 미반영/운영 리스크**를 우선으로, **미국주식 only + Tech/Healthcare 중심 + 8~14종목 + ETF는 관측지표만**을 강제하는 방향으로, **48시간 자동 루프에 바로 얹을 수 있는 “패치/실험”** 형태로 정리했다. (질문 없음, 실행 체크리스트만)

## TOP1) 데이터 누수(look-ahead) / PIT(Point-in-time) 무결성 하드 게이트 추가
### (a) 왜 필요한지
- lockbox가 튜닝 대비 과도하게 잘 나오거나(또는 반대로 전혀 움직이지 않거나) 하는 가장 흔한 원인이 **PIT 위반(재무/분류/액션), split/dividend 처리 시점 오류, 바-클로즈 사용 시점 혼선**이다.
- 이게 깨져 있으면 이후 어떤 전략 개선도 “가짜 개선”이 되거나, 반대로 진짜 개선이 잠긴다.

### (b) 위험/부작용
- PIT를 제대로 강제하면 **성능이 즉시 하락**할 수 있음(정상).
- 데이터 준비(특히 GICS/재무 PIT)가 비용/시간을 먹을 수 있음.

### (c) 최소 실험 2~3개 (48h 루프형: 실험 정의 → 게이트 → 기대 관측치)
**실험 1: “Lag-ablation(지연 강제)” 누수 탐지**
- (정의) 모든 특징/리밸런스 입력을 **+1일, +2일 강제 지연**한 변형을 각각 백테스트(동일 로직).
- (게이트)  
  - +1일 지연에서 lockbox_mean이 **-10% 이상 붕괴**하면 누수 가능성 경고(FAIL 플래그).  
  - +2일에서 추가 붕괴가 크면(> -5%p 추가) 더 강한 경고.
- (기대 관측치) 정상 전략은 지연 시 완만한 하락(예: -1~5% 수준) 또는 유사.

**실험 2: “Split/Dividend 타임스탬프 점검”**
- (정의) 가격 series를 (i) raw (ii) split-adjusted (iii) total-return(배당 포함) 3버전으로 동일 전략 실행(가능 범위 내).
- (게이트)  
  - 성능/포지션 변동이 특정 종목/구간에서 비정상적으로 튀면(기여도 상위 1개 종목이 전체 PnL의 과도 비중, 예: >40%) 누수/조정 오류 의심(FAIL 플래그).
- (기대 관측치) 조정 방식에 따라 레벨은 달라도 “상대적 일관성” 유지.

**실험 3: “Feature time-travel 유닛테스트(하드 에러)”**
- (정의) 피처 테이블에 `feature_timestamp <= decision_timestamp - lag`를 위반하면 즉시 예외를 내는 검증 레이어 추가.
- (게이트) 위반 1건이라도 발견 시 실험 전체 FAIL(코드 상 종료).
- (기대 관측치) 위반 0건. 발견되면 해당 피처/데이터 소스가 원인.

### (d) PASS 조건
- 지연 강제(+1일)에서도 lockbox가 **과도 붕괴 없이**(예: -5% 이내) 유지되고,
- split/dividend/total-return 변형에서 **PnL 집중이 완화**되며,
- time-travel 검증 **0 위반**.

## TOP2) 서바이버십/유니버스 규칙을 “8~14 Tech+Healthcare”로 고정 + PIT 섹터 분류
### (a) 왜 필요한지
- “종목풀이 계속 바뀌는 것” 자체가 알파처럼 보이게 만드는 **서바이버십/선정편향**의 주요 통로다.
- 운영 관점에서도 8~14 종목 고정형이 리스크/실행/모니터링이 단순해진다.

### (b) 위험/부작용
- 유니버스가 좁아지면 샤프가 떨어질 수 있음(정상). 대신 **재현성/운영성**이 좋아진다.
- PIT 섹터 분류를 못 구하면 구현 난이도 상승(대체로 “룰 기반 분류”로 임시 가능).

### (c) 최소 실험 2~3개
**실험 1: “PIT 섹터 게이트 + 8~14 강제” 유니버스 빌더**
- (정의) 매 리밸런스 시점에 (Tech, Healthcare)만 필터 → 유동성/시총 기준 상위에서 8~14 선택(룰 고정).  
  - ETF(QQQ/XLK/XLV)는 **지표만** 사용.
- (게이트)  
  - 모든 날짜에서 종목 수가 8~14를 벗어나면 FAIL.  
  - 거래정지/상폐 등으로 결측이 생기면 대체 규칙(다음 순위) 적용 여부 로그 확인.
- (기대 관측치) 종목 수 안정, 극단적 종목 교체 감소.

**실험 2: “서바이버십 스트레스”**
- (정의) 유니버스 선정에서 **현재 시점 티커 목록**을 절대 참조하지 않도록(=백테스트 기간 내 존재한 종목만 그 시점 데이터로) 강제. 가능하면 CRSP/Refinitiv PIT, 아니면 “상폐 티커 포함”된 공급원 사용.
- (게이트) 상폐/합병 종목 이벤트가 있는 구간에서 백테스트가 비정상 종료하거나, 해당 구간 수익이 비현실적으로 좋아지면 FAIL 플래그.
- (기대 관측치) 성능은 다소 하락 가능하지만, **구간별 변동이 더 현실화**.

**실험 3: “유니버스 고정 vs 동적” A/B**
- (정의) (A) 연 1회/분기 1회만 유니버스 교체(준-고정) vs (B) 매 리밸런스 교체(동적) 비교.
- (게이트) 동적이 고정보다 성능이 좋더라도 turnover/비용을 함께 비교해 **순성과(net)**로 판단.
- (기대 관측치) 고정형이 운영/비용 면에서 우위, 동적형은 과최적화 가능성 높음.

### (d) PASS 조건
- lockbox_mean이 챔피언 대비 **-1%p 이내**로 유지되면서,
- turnover(회전율)/종목 교체율이 의미 있게 감소(예: -20% 이상)하고,
- 종목수 8~14 강제가 전 기간 만족.

## TOP3) 비용/슬리피지/스프레드/차입(숏) 현실화 + “비용 게이트”를 PASS 조건에 포함
### (a) 왜 필요한지
- 성능이 “안 움직이는” 원인이 실제로는 개선이 **비용에서 상쇄**되기 때문인 경우가 많다.
- 특히 8~14 집중 포트에서 리밸런스가 잦으면 비용 민감도가 급증.

### (b) 위험/부작용
- 비용을 현실화하면 백테스트 성능이 하락(정상).
- 너무 보수적으로 잡으면 좋은 전략도 다 죽일 수 있음(그래서 **범위 실험**이 필요).

### (c) 최소 실험 2~3개
**실험 1: “3단계 비용 스윕”**
- (정의) 거래비용을 (Low / Base / High) 3단계로 스윕해서 동일 전략 재실행.  
  - 예: 고정 bps + 변동(거래대금 대비) 조합.
- (게이트) High 비용에서 lockbox_mean이 **Base 대비 과도 붕괴(예: -15% 이상)**면 비용 취약(FAIL 플래그).
- (기대 관측치) robust한 전략은 비용 스윕에도 성능 기울기가 완만.

**실험 2: “턴오버 캡(soft/hard) + 재최적화”**
- (정의) 리밸런스 시 거래량/턴오버 상한을 두고, 초과분은 다음 캔들로 이월하거나 목표 비중을 shrink.
- (게이트)  
  - 평균 turnover가 목표 대비 감소(예: -25% 이상)하면서 lockbox_mean 손실이 제한적(예: -2%p 이내)이면 PASS 후보.
- (기대 관측치) 순성과(net) 개선 또는 MDD 개선.

**실험 3: “숏 제약(차입비용/불가) 시나리오”**
- (정의) (A) 롱온리 (B) 롱+숏(차입비용 반영) (C) 숏 금지 종목 발생(랜덤/규칙 기반) 시나리오 비교.
- (게이트) (B)에서만 성능이 급증하면 실행 리스크 큼(FAIL 플래그).
- (기대 관측치) 롱온리에서도 기본 방어력이 있어야 운영 가능.

### (d) PASS 조건
- **net 성능 기준**으로 lockbox_mean이 챔피언 대비 **동급 이상(≥ -0.5%p)** 또는
- worst_mdd가 **개선(예: 1%p 이상 감소)**되면서 turnover가 감소.

## TOP4) 노출(베타/섹터/팩터) 제어 + 레짐(ETF 지표) 기반 리스크 게이트
### (a) 왜 필요한지
- Tech/Healthcare라도 시장 베타/금리 민감도/변동성 레짐에 의해 성과가 좌우된다.
- 성능이 “안 움직임”은 실제로는 **알파가 아니라 베타가 지배**하거나, 레짐에서 리스크 컷이 없어 손실 구간이 커서 평균이 깎이는 경우가 많다.

### (b) 위험/부작용
- 노출 제약을 걸면 수익도 줄 수 있음.
- 레짐 게이트는 잘못 만들면 “알파 구간을 꺼버리는” 역효과 가능.

### (c) 최소 실험 2~3개
**실험 1: “베타 중립(또는 상한) 캡”**
- (정의) SPY(지표만)로 rolling beta 추정 후 포트폴리오 beta를 상한(예: |beta| ≤ 0.3~0.5)으로 shrink.
- (게이트) lockbox에서 MDD가 개선되고(예: worst_mdd 1%p 이상 완화) 수익 감소가 과하지 않으면 PASS 후보.
- (기대 관측치) 급락 구간 방어력 증가.

**실험 2: “변동성 타게팅(포지션 스케일)”**
- (정의) 포트 변동성이 목표치(예: 연 10~12%)를 넘으면 비중을 선형 축소.
- (게이트) 레버리지/현금 비중 변동 로그가 정상이며, drawdown 구간의 일간 손실 꼬리가 줄어야 함.
- (기대 관측치) tail risk 감소, MDD 완화.

**실험 3: “레짐 필터(ETF 관측지표: QQQ/XLK/XLV + VIX)”**
- (정의) QQQ 추세/모멘텀, XLK-XLV 상대강도, VIX 레벨로 레짐을 2~3구간으로 나누고, 특정 레짐에서 리밸런스 빈도/위험만 축소(=완전 off가 아니라 scale-down).
- (게이트) 레짐별 성과 분해 시 “특정 레짐의 대형 손실”이 줄어야 함.
- (기대 관측치) 평균은 비슷해도 최악구간 개선.

### (d) PASS 조건
- lockbox_mean이 챔피언 대비 **유지(≥ -1%p)**되면서,
- worst_mdd가 **유의 개선(≥ +1%p 완화)** 또는 fold별 성과 분산 감소.

## TOP5) 과최적화/평가체계 강화(퍼지드 CV/엠바고/랜덤 테스트) + 운영 리스크(결정론/재현성) 고정
### (a) 왜 필요한지
- 지금처럼 챔피언이 안정적인데 후보가 잘 안 이기면, 실제로는 **평가 체계가 둔감**하거나 후보가 **과적합**일 가능성이 높다.
- 자동 루프 운영에서는 “재현 가능한 결과(결정론)”가 1순위다.

### (b) 위험/부작용
- 평가를 엄격히 하면 PASS가 더 어려워져 “진도”가 느려질 수 있음(정상).
- 퍼지드/엠바고 적용은 표본 수 감소로 분산 증가.

### (c) 최소 실험 2~3개
**실험 1: “Purged CV + Embargo”로 교체**
- (정의) 학습/검증 분할에서 인접 기간 누수를 방지(엠바고), 이벤트 윈도우를 purge.
- (게이트) 기존 챔피언이 새 체계에서도 “큰 붕괴 없이” 유지되면 체계 교체 PASS.
- (기대 관측치) 과거에 좋던 과적합 후보들이 더 많이 탈락.

**실험 2: “라벨/피처 랜덤화(무력화) 테스트”**
- (정의) (A) 신호를 날짜 내 랜덤 셔플 (B) 종목 라벨 셔플 후 성능이 유지되는지 확인.
- (게이트) 랜덤화에서 성능이 의미 있게 남으면(예: 샤프가 0.5 이상 유지) 누수/버그 의심(FAIL).
- (기대 관측치) 랜덤화 성과는 0 근처로 수렴.

**실험 3: “결정론(시드/정렬) + 스냅샷 아티팩트”**
- (정의) 데이터 스냅샷 해시, 정렬 키, RNG seed를 고정하고 동일 커밋에서 결과가 완전 재현되는지 CI로 확인.
- (게이트) 동일 입력에서 metric 변동 발생 시 FAIL(운영 리스크).
- (기대 관측치) 결과 완전 동일(또는 허용오차 내).

### (d) PASS 조건
- 챔피언이 새 평가체계에서도 성능 유지(예: lockbox_mean **-1%p 이내**),
- 랜덤화 테스트에서 성능이 소거되고,
- 동일 실행 재현성 확보.

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래는 **원인-증상-검증 로그**를 한 번에 뽑아 “어디서 막혔는지”를 가르는 체크리스트다. (질문 없이 실행 항목만)

## 1) 트리거(신호 자체) 문제
- [ ] **신호 분포 드리프트**: 신호 값의 평균/분산/상위 분위가 튜닝 vs 최근/락박스에서 변했는지(PSI/KS-test).
- [ ] **예측력 분해**: 종목별/레짐별 IC, hit-rate, 평균 보유기간별 기여(1~3일/1~2주/1~3개월).
- [ ] **정보 지연 민감도**: +1일 lag에서 성능이 비정상 붕괴하면 누수/즉시성 의존.

## 2) 적용(포트폴리오 구성/리밸런스)에서 막힘
- [ ] “신호는 변하는데 포지션이 안 변함” 확인: **목표비중 vs 체결비중 차이**(제약/턴오버 캡 때문인지).
- [ ] 8~14 종목 강제 시 **동률/경계 종목**에서 불안정 교체가 발생하는지(타이브레이커 규칙 필요).
- [ ] 리밸런스 빈도 변경(A/B)으로 **알파 수명** 추정.

## 3) 노출(베타/섹터/팩터)로 알파가 가려짐
