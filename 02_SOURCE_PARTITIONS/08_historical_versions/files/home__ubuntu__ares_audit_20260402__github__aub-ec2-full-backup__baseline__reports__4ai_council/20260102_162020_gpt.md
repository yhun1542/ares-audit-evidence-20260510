## “성능이 안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **자동 리포트 섹션**으로 넣고, 각 항목이 FAIL이면 즉시 “개선 실험”이 아니라 “버그/측정기 수리”로 분기한다.

### A) Trigger(신호 생성) 계층
- [ ] 신호 분포가 학습/검증/OOS에서 동일한지(평균/분산/상위% 비중)  
- [ ] 신호가 항상 0 근처로 붕괴(정규화/스케일 오류, 결측 처리로 0 채움)  
- [ ] label/feature time alignment(lookahead) 체크: **t 시점 의사결정에 t+1 정보가 섞이는지**

### B) Apply(리밸런스 적용/주문 생성) 계층
- [ ] target weights 생성되는데 fills가 0(주문 생성/체결 모델 버그)  
- [ ] 가중치 클리핑/라운딩/현금 처리로 신호가 죽는지(특히 소수점/최소 주문 단위)  
- [ ] 리밸런스 주기가 실제로 실행되는지(스케줄러/캘린더/휴장일 처리)

### C) Exposure(노출/포지션) 계층
- [ ] exposure=0 구간이 길어 “수익이 안 나는” 구조인지  
- [ ] 종목별 cap 때문에 알파가 큰 종목이 항상 잘리는지  
- [ ] 상관 높은 종목만 과다 보유→ 실질적으로 단일 베팅이 되는지(리스크 패리티/분산 체크)

### D) Cost(비용) 계층
- [ ] 턴오버가 성과를 상쇄(“gross 알파”는 있는데 “net”이 0)  
- [ ] 슬리피지 모델이 너무 낙관적/비관적인지(Arm 실험으로 민감도 곡선 확보)  
- [ ] 스프레드 확장(변동성 구간)에서 체결 가정이 깨지는지

### E) Regime(레짐) 계층
- [ ] 전체 기간 평균 성과는 0이지만, 레짐별(Tech 우위/Healthcare 우위/고변동)로는 유의미한지  
- [ ] 레짐 전환이 잦아 비용만 증가시키는지  
- [ ] 레짐 지표가 매매자산과 동형(lookahead나 동시성 문제)인지: **지표 timestamp 동기화 필수**

- [ ] **EXP1(스플릿/누수 감사)** → degenerate_folds 제거  
- [ ] **EXP2(비용 현실화)** → net 성과 기준으로 재정렬  
- [ ] **EXP4(노출/리스크 가드레일)** → MDD None 제거, 노출 안정화  
- [ ] **EXP5(레짐 게이트)** → 개선이 아니라 “기여 분해”가 목적(과최적화 방지)

이 5개 패키지는 “케이스 폭발” 없이, 48시간 자동 루프에서 **(정의→게이트→관측치)**로 바로 돌릴 수 있는 형태로 제한했다.
