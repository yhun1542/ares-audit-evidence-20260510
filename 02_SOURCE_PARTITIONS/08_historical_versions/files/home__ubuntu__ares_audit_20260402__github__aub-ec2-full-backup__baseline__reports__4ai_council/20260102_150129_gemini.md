[진단 요약]
현재 시스템은 **"실행 로그 누락(Rebalance Log Fail)"**과 **"성능 지표 불일치(Diagnoser 2.6 vs Handoff 1.8)"**라는 치명적 결함을 안고 있음. 거래 비용과 회전율을 검증할 수 없는 상태에서의 OOS 수치는 신뢰 불가. 즉시 파이프라인 수리가 1순위.

---

### 1. 24~48시간 우선순위 TOP 5 제안

1.  **[CRITICAL] 거래 로그 파이프라인 복구**: `rebalance.csv/jsonl` 로딩 에러(Argument Parsing 오류 포함) 즉시 수정. 비용 분석 없는 최적화 중단.
2.  **[RISK] 노출도(Exposure) 하한선 강제 테스트**: 현재 Min Exposure 0.47은 상승장에서 치명적일 수 있음. 0.60~0.70으로 강제 상향 시 성능 변화 관측.
3.  **[UNIVERSE] 헬스케어 방어 로직 검증**: Tech 하락 시 Healthcare 비중이 실제로 늘어나는지, 아니면 단순히 전체 현금 비중만 늘리는지 확인.
4.  **[COST] 슬리피지(Slippage) 스트레스 테스트**: Tech/Bio 종목 특성상 변동성이 큼. 슬리피지를 5bp -> 15bp로 가정했을 때 수익 곡선 붕괴 여부 확인.
5.  **[METRIC] 평가 지표 통일**: Diagnoser와 Handoff 간의 Metric 계산 로직(연율화 방식, 무위험 수익률 반영 여부) 일치화.

### 2. 실행 가능한 Patch / 실험 (3 items)

#### 실험 A: [SYS_FIX] 거래 로그 포맷 정규화 및 인자 수정
*   **이유**: `[Errno 2] No such file or directory: '--base-log'` 에러는 파이썬 스크립트 호출 시 인자 전달 실수임. 거래 내역이 없으면 과최적화(Overfitting) 여부를 판단할 수 없음(회전율 0 or 무한대 가능성).
*   **위험**: 없음(시스템 정상화).
*   **실험 정의**:
    *   `aub_rebalance_pinpoint.py` 호출부의 `argparse` 로직 수정.
    *   Output 포맷을 CSV 대신 JSONL로 강제 통일하여 파싱 오류 제거.
*   **PASS 조건**: `rebalance_pinpoint.md` 리포트가 정상 생성되고, 일평균 회전율(Daily Turnover)이 0 < T < 50% 사이로 집계될 것.

#### 실험 B: [STRATEGY] Exposure Floor Clamping (0.47 → 0.65)
*   **이유**: 현재 Min Exposure 0.47은 과도한 마켓 타이밍(Market Timing) 시도로 보임. Tech/Health 섹터 펀드라면 65% 이상은 시장에 노출되어야 Beta 손실을 방지함.
*   **위험**: 하락장에서 MDD(최대 낙폭) 증가 가능성.
*   **실험 정의**:
    *   Control: 기존 Min Exposure (Open)
    *   Test 1: Min Exposure = 0.65 (강제)
    *   Test 2: Min Exposure = 0.80 (강제)
*   **게이트**: Test 그룹의 Sharpe Ratio가 Control 대비 -10% 이내이면서, 상방 포획률(Upside Capture)이 증가해야 함.
*   **기대 관측치**: 상승 구간에서 Benchmark(SPY/QQQ) 대비 언더퍼폼 폭 축소.

#### 실험 C: [ALPHA] 헬스케어 'Safe Haven' 트리거 강화
*   **이유**: Tech와 Healthcare는 상관계수가 낮아야 효용이 있음. Tech 변동성 확대 시 Healthcare 비중을 **현금 대신** 늘리는지 확인 필요.
*   **위험**: 두 섹터 동반 하락 시(Systematic Risk) 손실 가중.
*   **실험 정의**:
    *   로직 추가: `if Tech_Vol(20d) > Threshold: Min_Healthcare_Weight += 20%`
    *   Universe: Tech(XLK 구성종목 상위) + Health(XLV 구성종목 상위) 로 고정.
*   **게이트**: Tech 급락 구간(예: 2022년형 시나리오)에서 MDD가 현금 보유 전략 대비 5%p 이내 차이 유지.
*   **기대 관측치**: 회전율은 다소 증가하더라도, Exposure 급락(0.47) 없이 포트폴리오 밸런스 유지.

### 3. 성능 정체 시 원인 분해 (Decomposition Logic)

성능(OOS Score)이 48시간 동안 유의미하게 변하지 않을 경우, 다음 순서로 원인을 제거하시오.

1.  **트리거 불발 (Signal Dead)**:
    *   *Check*: 생성된 포트폴리오의 일별 Weight 변화량(Delta)이 0에 수렴하는가?
    *   *Action*: 거래 임계값(Threshold)을 강제로 낮춰 거래를 유발(Forced Trading)해본다.

2.  **비용 잠식 (Cost Decay)**:
    *   *Check*: Gross Return은 우상향이나 Net Return이 횡보하는가?
    *   *Action*: 회전율 제한(Turnover Cap)을 걸거나, 유동성이 낮은 헬스케어 소형주를 유니버스에서 배제.

3.  **레짐 불일치 (Regime Mismatch)**:
    *   *Check*: 특정 연도(예: 2022, 2025)에만 성능이 좋고 나머지는 Flat한가?
    *   *Action*: 2026년 시점 기준, 최근 6개월 데이터의 가중치를 높이는 `Decay Factor` 적용 실험.

4.  **운영 리스크(Pipeline Broken)**:
    *   *Check*: 위 로그 에러처럼, 평가 스크립트가 엉뚱한 파일(Empty JSON)을 읽고 '성능 변화 없음'으로 오판하는지 확인.
    *   *Action*: 수동으로 백테스트 로그 파일(`*.jsonl`)을 열어 데이터 존재 여부 육안 확인.
