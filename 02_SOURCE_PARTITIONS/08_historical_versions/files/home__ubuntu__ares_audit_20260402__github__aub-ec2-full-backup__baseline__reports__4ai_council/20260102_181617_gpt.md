## 0) 지금 당장 보이는 “우선 차단 대상”(ONE TRUTH 기반)
- **degenerate_folds = [1,2,3,8]**: OOS 평균이 좋아도 **검증이 무의미해질 위험(누수/데이터 부족/분할 오류/리샘플링 오류)**이 최우선.
- **worst_mdd = None**: 리스크/운영 게이트가 작동하지 않음(서바이버십/과최적화가 숨기기 쉬운 상태).
- **lane_hash/run_hash = None**: 재현성/추적 불가 → 48시간 자동 루프에서 “좋았던 설정”이 증발.
- **rebalance pinpoint 실패(로그/포맷 깨짐)**: 비용/턴오버/리밸런스 품질을 못 봄 → “성능 안 움직임” 원인 분해 불가.

아래는 **다음 24~48시간 TOP5 우선순위**이며, 제안 실행은 **총 5개(패치/실험)로 제한**했습니다. 각 우선순위마다 “최소 실험 2~3개”는 **동일 5개 항목을 조합**해서 충족합니다(케이스 폭발 방지).

# 1) TOP5 우선순위 제안 (코드/아키텍처/전략)

## P1. (최우선) 검증 무결성: 누수/degenerate fold 제거 + 시간정렬 강제
**(a) 왜 필요한지**
- degenerate folds가 있으면 OOS 평균이 올라가도 **실제로는 분할이 깨졌거나 표본이 거의 없는 구간**일 수 있음.
- 누수(특히 리밸런스 시점 이후 데이터, 종가 확정 전 특징, survivorship 포함)가 있으면 “No-Delta”처럼 **실험을 아무리 해도 방향성이 왜곡**됨.

**(b) 위험/부작용**
- 제대로 고치면 **OOS가 단기적으로 하락**할 수 있음(그게 정상).
- 분할/정렬 강화로 학습 데이터가 줄어 **분산 증가** 가능.

**(c) 최소 실험 2~3개 (아래 5개 항목 중 조합)**
- [E1] Fold Integrity + Leakage Sentinel 실험
- [E3] 리밸런스/노출 로깅 패치(정렬 점검 포함)
- [E5] 유니버스(Tech+Healthcare 8~14) 강제 실험(검증 구간에서 표본 안정성 확인)

**(d) PASS 조건(게이트)**
- degenerate_folds = **[]**
- 모든 fold에서 OOS 표본 수/리밸런스 횟수 최소치 충족(예: 각 fold 리밸런스 **>= 30회** 같은 내부 기준)
- “리밸런스 시점 t에서 사용하는 feature/label이 t 이후를 참조하지 않음” 자동 테스트 통과

## P2. 비용 미반영 차단: 거래비용/슬리피지/턴오버 게이트를 ‘강제’로
**(a) 왜 필요한지**
- 비용 미반영은 **과최적화의 1순위 원인**. 특히 8~14개 종목이라도 리밸런스가 잦으면 OOS가 “움직이지 않거나” 허상으로 좋아짐.
- rebalance 로그가 지금 깨져 있어 **턴오버가 원인인지**조차 분해가 안 됨.

**(b) 위험/부작용**
- net 성능이 급락할 수 있음(정상). 그 경우 전략의 “엣지”가 비용에 잠식된 것.
- 비용 모델 파라미터가 보수적이면 과도한 억제 가능.

**(c) 최소 실험 2~3개**
- [E2] Cost Model On (commission+spread+slippage) 실험
- [E3] 리밸런스 로그/턴오버 산출 패치
- [E4] 노출 스케일링(레짐 기반)로 **턴오버/드로우다운 감소** 유도

**(d) PASS 조건**
- net(OOS) 기준으로 champion 대비 **oos_mean -2% 이내 유지** 또는 개선(비용 넣었는데도 유지되면 강함)
- turnover 상한 게이트 통과(예: **일/주간 turnover 상위 95%가 내부 한도 이하**)
- 비용이 반영된 상태에서 oos_min(최악 구간 수익)이 **더 악화되지 않음**(현재 oos_min ≈ -0.0257 → 예: -0.03 이하로 내려가면 FAIL)

## P3. 운영 리스크 제거: 재현성(run_hash) + 리스크 지표(worst_mdd) + 로그 포맷 통일
**(a) 왜 필요한지**
- lane_hash/run_hash None이면 “좋았던 결과를 다시 못 만드는 상태” → 자동 루프의 최대 적.
- worst_mdd None이면 리스크 게이트가 비활성 → **서바이버십/운영 리스크**가 그대로 통과.

**(b) 위험/부작용**
- 단기 성능 개선은 없고, “보이는 지표”가 늘어나며 실패가 더 자주 드러남(정상).
- 로깅 추가로 런타임/디스크 비용 소폭 증가.

**(c) 최소 실험 2~3개**
- [E3] 로깅/해시/리스크지표 산출 패치(필수)
- [E1] fold 무결성 실험(재현성 있는 split hash 포함)
- [E2] 비용 포함 시 리밸런스 로그로 상호검증

**(d) PASS 조건**
- 모든 artifact에 run_hash/lane_hash가 **항상 채워짐**
- worst_mdd가 **항상 수치로 산출**되고, fold별/전체 기준 일관
- rebalance pinpoint가 base/cand 모두에서 **정상 로드**(csv/jsonl 포맷 고정)

## P4. 노출(Exposure)·헤지 해석가능화: “헷지=ETF매매” 금지, 대신 노출 스케일링으로
**(a) 왜 필요한지**
- 현재 exp 이름에 hedge가 보이는데, 요구사항상 **ETF 매매는 금지**. 대신 ETF는 관측지표로만 쓰고, 포지션은 **Tech+HC 개별주 8~14개**로 유지하면서 **총노출만 조절**해야 함.
- exposure max 0.838…은 괜찮지만, **레짐 악화 시 줄이는 규칙**이 없으면 oos_min이 계속 끌려 내려갈 수 있음.

**(b) 위험/부작용**
- 노출 스케일링이 과하면 수익 기회를 놓침.
- 레짐 신호가 늦으면 “늦게 줄이고 늦게 늘리는” 문제.

**(c) 최소 실험 2~3개**
- [E4] 레짐 기반 노출 스케일링(ETF는 관측지표) 실험
- [E2] 비용 포함 상태에서 스케일링이 turnover를 얼마나 줄이는지 확인
- [E5] 8~14 종목 고정 + 섹터 바운드로 분산 유지하며 스케일만 변화

**(d) PASS 조건**
- oos_min 개선(예: -0.0257 → **-0.020 이상**)
- worst_mdd가 기준 이하(내부 한도)로 감소
- 평균 노출이 과도하게 줄지 않음(예: mean exposure가 기존 대비 **-20% 이상 감소**하면 FAIL로 간주 같은 운영 룰)

## P5. 유니버스/포트폴리오 규율: Tech+Healthcare 8~14개 “항상 유지” + 집중/상관 리스크 캡
**(a) 왜 필요한지**
- 요구사항: 미국주식 only, Tech+Healthcare 중심, 8~14개, ETF 매매 제외.
- 유니버스가 흔들리면 실험 비교가 불가능하고, 상관 높은 종목(메가캡) 쏠림으로 **표면 수익은 좋지만 최악구간(oos_min) 악화** 가능.

**(b) 위험/부작용**
- 종목 제한으로 알파가 줄 수 있음.
- 섹터 고정이 레짐 전환 때 불리할 수 있음 → 그래서 P4(노출 스케일링)와 같이 가야 함.

**(c) 최소 실험 2~3개**
- [E5] 유니버스/종목수(8~14)/섹터 바운드 강제 실험
- [E2] 비용 포함 상태에서 종목수 변화가 turnover에 미치는 영향 확인
- [E3] 리밸런스 로그로 “종목수 위반/섹터 위반” 자동 적발

**(d) PASS 조건**
- 모든 리밸런스에서 포지션 수 **8~14 준수**
- Tech+Healthcare 비중(종목수 또는 시총가중/동일가중 기준) **규칙 준수**
- 단일 종목 비중 상한(예: 15~20%) 위반 0건

# 2) 48시간 자동 루프용 “실행 가능한 Patch/실험” 5개 (총량 제한 준수)

아래 5개만 돌리면 위 TOP5의 (c)를 모두 커버합니다. 각 항목은 **(1) 실험 정의 (2) 게이트 (3) 기대 관측치**로 작성.

---

## [E1] Fold Integrity + Leakage Sentinel
**(1) 실험 정의**
- 시간 분할을 완전 고정(lookback/label horizon 포함)하고,
- 각 fold에 대해:
  - 표본 수, 리밸런스 이벤트 수, 결측률,
  - feature timestamp <= decision timestamp 검증,
  - survivorship 방지(가능하면 point-in-time 구성 여부 플래그)
- degenerate fold 발생 시 학습/평가를 실패 처리(soft pass 금지).

**(2) 게이트**
- degenerate_folds == []
- fold별 리밸런스 수/표본 수 하한 통과
- leakage unit test 100% 통과

**(3) 기대 관측치**
- oos_mean이 단기 하락 가능(정상)
- 대신 oos_min, 분산, fold 간 편차가 “설명 가능한 수준”으로 안정

---

## [E2] Cost Model On (거래비용/슬리피지/턴오버 게이트)
**(1) 실험 정의**
- 거래비용 구성요소를 net PnL에 반영:
  - 커미션(고정/주당),
  - bid-ask spread의 절반,
  - 슬리피지(유동성/변동성 기반 단순 모델이라도 고정)
- turnover 상한을 게이트로 추가(초과 시 FAIL 또는 페널티).

**(2) 게이트**
- net oos_mean이 gross 대비 “합리적” 감소폭(예: 비용이 0이 아니게 반영됨을 확인)
- turnover 95% 분위수 < 내부 한도
- 비용 반영 후에도 oos_min 급락 방지

**(3) 기대 관측치**
- “성능 안 움직임”의 주범이 비용이면: gross는 유사하나 net이 크게 흔들림
- 비용이 주범이 아니면: net에서도 실험 간 순위가 유지

---

## [E3] Rebalance/Exposure Observability Patch (로그/해시/리스크지표)
**(1) 실험 정의**
- 산출물 스키마를 강제:
  - run_hash/lane_hash 기록,
  - rebalance.csv 또는 jsonl을 **항상 생성**(포맷 고정),
  - exposure(min/max/mean), 포지션 수, 섹터 비중,
  - worst_mdd를 fold별/전체로 계산해 저장
- aub_rebalance_pinpoint가 기본적으로 이 파일을 읽도록 경로/인자 정리.

**(2) 게이트**
- pinpoint 도구가 base/cand 모두 **에러 없이 로드**
- worst_mdd != None
- run_hash/lane_hash 누락 0건

**(3) 기대 관측치**
- 다음부터 “왜 성능이 안 움직였는지”가 리밸런스 단위로 분해 가능
- 운영 장애(파일 없음/JSON 깨짐)로 실험이 무효화되는 빈도 급감

---

## [E4] Regime-aware Exposure Scaling (ETF는 관측지표만)
**(1) 실험 정의**
- ETF(예: XLK/XLV) 및 VIX/금리 같은 지표는 **매매하지 않고**,
- 관측지표로 레짐(리스크온/오프)을 추정하여,
- 개별주 포트폴리오의 **총노출(0~1)**만 스케일링:
  - 변동성 상승/리스크오프 시 노출 축소
  - 리스크온 시 정상 노출 복귀
- 종목 선택 로직 자체는 건드리지 않거나 최소 변경.

**(2) 게이트**
- oos_min 개선(최악구간 완화)
- worst_mdd 감소
- mean exposure 과도 감소 방지(내부 하한)

**(3) 기대 관측치**
- 평균 수익(oos_mean)은 소폭 감소할 수 있으나,
- 최악구간/드로우다운이 개선되면 “운영 가능한 전략”으로 진입

---

## [E5] Universe/Portfolio Constraints Hardening (US Tech+Healthcare, 8~14)
**(1) 실험 정의**
- 유니버스를 “미국 상장 + Tech/Healthcare”로 하드 필터.
- 보유 종목 수 8~14 하드 제약(미달/초과 시 리밸런스에서 보정).
- 단일종목/상관(또는 동일 팩터) 쏠림 캡(간단히 비중 상한으로 시작).

**(2) 게이트**
- 전 리밸런스에서 종목 수 8~14 준수
- 섹터 바운드 위반 0건
- 상위 1~2개 종목 비중 상한 위반 0건

**(3) 기대 관측치**
- 성능이 “덜 화려해져도” 재현성과 리스크가 개선
- 비용/턴오버도 함께 안정화되는 경우가 많음

# 3) 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래는 **질문 없이 바로 돌릴 수 있는 분해 체크리스트**입니다. (E3 로그가 전제)

## A. Trigger(신호 발생) 단계
- [ ] 리밸런스 시점마다 **signal 분포(평균/표준편차/상위-하위 스프레드)** 로그 저장
- [ ] 상위/하위 그룹 간 예측 스프레드가 0에 수렴하면: **특징량 붕괴/정규화 버그/스케일 클리핑** 의심
- [ ] fold별로 신호 분포가 다르면: **데이터 누락/분할 불균형** 의심(E1로 회귀)

## B. Apply(주문/체결/리밸런스 적용) 단계
- [ ] 목표비중 → 실제비중 변환에서 “라운딩/최소 주문 단위/거래불가”로 **알파가 소실**되는지 확인
- [ ] 리밸런스 빈도 대비 “변경된 종목 수”가 과도하면: **노이즈 추종/과최적화** 가능
- [ ] 리밸런스 로그가 없으면 무조건 E3부터

## C. Exposure(노출) 단계
- [ ] exposure(min/max/mean)과 성과의 상관을 fold별로 계산
- [ ] oos_min이 나쁠 때 노출이 높았다면: **E4(레짐 스케일링)** 우선
- [ ] 노출이 낮은데도 성과가 정체면: 신호 자체가 약하거나 비용/슬리피지 영향 가능(E2)

## D. Cost(비용) 단계
- [ ] gross vs net 성과 차이를 리밸런스 단위로 분해(비용이 특정 구간에 몰리는지)
- [ ] turnover 급증 구간이 oos_min과 겹치면: **전략이 레짐 전환에 취약**(E4) 또는 리밸런스 규칙 문제(E3/E2)
- [ ] 비용 넣었더니 실험 간 순위가 뒤집히면: 기존 평가는 비용 누락 최적화였음(E2 고정)
