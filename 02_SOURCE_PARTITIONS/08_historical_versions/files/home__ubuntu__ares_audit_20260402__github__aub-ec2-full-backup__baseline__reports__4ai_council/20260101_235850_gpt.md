아래 TOP5는 **24~48시간 내 “바로 코드로 패치/실험 가능한 것”만** 추렸고, 우선순위는 **누수 → 과최적화 → 서바이버십/비용 미반영 → 운영 리스크** 순으로 잡았습니다. (미국주식 only, **Tech+Healthcare 중심 8~14종목**, ETF는 **관측지표**로만)

## TOP1) 데이터 누수/시간정렬 “하드 게이트” 패치 (가장 먼저)
### (a) 왜 필요한지
- 지금 결과(특히 lockbox 개선)가 좋아도, **미세한 누수(리밸런스 시점의 종가/수정주가/지표 확정시각)** 하나로 튜닝·락박스가 동시에 상승하는 “가짜 개선”이 자주 발생.
- 48시간 루프에서 가장 싼 비용으로 **신뢰도**를 올리는 작업.

### (b) 위험/부작용
- 단기 성능 하락 가능(누수 제거로 현실 성능으로 “정상화”).
- 일부 feature/label 생성 로직이 깨지며 실험 실패가 늘 수 있음(하지만 그게 목적).

### (c) 최소 실험 2~3개 (명령형 체크리스트)
1) **E1: “시점 잠금(Time-lock)” 강제**
   - 모든 feature를 `t`에서 계산하고, 매매는 **t+1 시가(or VWAP)** 로만 체결되게 강제.
   - corporate action(분할/배당) 반영은 **t 시점까지 공지된 정보만** 사용하도록 분리(가능하면 point-in-time).
2) **E2: “가격/지표 스냅샷 단위테스트” 추가**
   - 리밸런스 직전/직후 바뀌면 안 되는 값(예: 과거 캔들, 과거 이동평균)이 재계산으로 변하지 않는지 테스트.
   - lookahead 탐지: `feature[t]`가 `price[t+1..]` 변화에 반응하면 실패 처리.
3) **E3: “gap walk-forward”**
   - 학습구간과 평가구간 사이에 **gap(예: 5~20 trading days)** 를 삽입한 백테스트도 병렬로 돌려 성능 붕괴 여부 확인.

### (d) PASS 조건 (게이트)
- **누수 테스트 0건 통과(=위반 없음)** 가 1순위 PASS.
- 성능 게이트(둘 중 하나 만족):
  - lockbox_mean **±3% 이내 유지** + worst_mdd 악화 **≤ 1%p**, 또는
  - lockbox_mean 하락이 있더라도 gap walk-forward에서 **MDD 악화가 줄면 PASS**(현실화로 간주).

### 48시간 자동 루프 형태
- (1) 실험 정의: `time_lock + unit_test + gapWF`
- (2) 게이트: `누수=0`, `MDD 악화 제한`, `lockbox_mean 급락 방지`
- (3) 기대 관측치: “좋아 보이던 후보가 떨어지면 정상”, 살아남는 후보는 향후 개선이 진짜일 확률↑

## TOP2) 거래비용/슬리피지/체결가 모델 “현실화 패치”
### (a) 왜 필요한지
- Tech/Healthcare는 갭·이벤트(실적, FDA)로 **슬리피지 비대칭**이 커서, 비용 미반영은 전략 랭킹을 뒤집음.
- 특히 8~14종목 집중 포트는 **턴오버/호가충격** 영향이 큼.

### (b) 위험/부작용
- 과거 성능 큰 폭 하락 가능.
- 비용 모델을 과도하게 잡으면 “아무것도 못 사는 전략”이 될 수 있음.

### (c) 최소 실험 2~3개
1) **E1: 체결가를 “다음날 시가 + 슬리피지(기본 bp + 변동성/유동성 가중)”로 통일**
   - 예: `slip_bp = base(3~10bp) + k * (ATR/price) + m*(1/ADV)` 형태(단순해도 됨).
2) **E2: 턴오버 패널티를 목적함수에 삽입**
   - 리밸런스 당 목표: “예상 샤프 - λ*turnover”.
   - λ는 48시간 동안 2~3개 그리드만(케이스 폭발 금지).
3) **E3: 이벤트 갭 리스크 비용**
   - 실적발표일(earnings)·FDA 일정 주변은 슬리피지/갭 비용을 상향(일정 데이터가 없으면, 고변동 구간 대체 규칙).

### (d) PASS 조건
- lockbox_mean **하락 ≤ 10%** 이면서 worst_mdd **동일 또는 개선**, 또는
- lockbox_mean 하락이 더 크더라도, **턴오버가 ≥ 20% 감소**하며 MDD가 개선되면 PASS(운영가능성↑).

### 48시간 자동 루프
- (1) 실험 정의: `execution_model_v1 + turnover_penalty`
- (2) 게이트: `turnover`, `net returns after costs`, `MDD`
- (3) 기대 관측치: “후보 간 순위가 바뀌면 정상”, 비용 견디는 후보만 남음

## TOP3) 서바이버십/액션/상장폐지/심볼변경 “데이터 생존성 패치”
### (a) 왜 필요한지
- US 개별주 백테스트에서 **상장폐지/합병/심볼 변경** 누락은 서바이버십 바이어스를 만들고, 특히 헬스케어(바이오)에서 치명적.
- “종목 유니버스”가 시간이 지나면서 조용히 정제되면 성능이 과대평가됨.

### (b) 위험/부작용
- 데이터 소스에 따라 구현 난이도/공백 발생.
- 유니버스가 커지면 계산비용 증가(하지만 8~14 보유면 선별단만 정확하면 됨).

### (c) 최소 실험 2~3개
1) **E1: 유니버스를 ‘당시 시총/거래대금 조건’으로 매일 재구성(시점별)**
   - “현재 살아있는 종목 목록” 금지.
2) **E2: delisting return 처리**
   - 상장폐지 시점 수익률(가능하면 CRSP/동등 로직), 불가하면 보수적으로 **강제 손실 처리 규칙**(예: -100% 또는 -50% 등) 2안만 비교.
3) **E3: corporate action 일관성 체크**
   - split/dividend 반영이 가격·거래량에 동시에 일관되게 적용되는지 검사(과거 캔들 재작성 여부 포함).

### (d) PASS 조건
- “유니버스/심볼 이벤트가 있는 기간”에서 전략이 **완전히 붕괴하지 않음**
  - worst_mdd 악화 **≤ 2%p**
  - lockbox_mean **±10% 이내 유지**
- 그리고 **상장폐지/심볼 변경 케이스가 로그로 추적 가능**하면 운영 PASS.

### 48시간 자동 루프
- (1) 실험 정의: `point_in_time_universe + delisting_model`
- (2) 게이트: `event windows stability`, `logging completeness`
- (3) 기대 관측치: “헬스케어 구간 성능이 더 현실적으로 변동”, 생존편향 제거

## TOP4) 과최적화 방지: “검증게이트 강화 + 선택 편향 차단” 패치
### (a) 왜 필요한지
- 지금처럼 후보가 lockbox까지 개선되면 오히려 의심해야 하는 구간(선택 편향/리트라이 편향).
- 48시간 자동 루프에서 **선정 규칙 자체**가 과최적화를 만들기 쉬움(“좋은 것만 남기는 자동화”).

### (b) 위험/부작용
- PASS가 거의 안 나올 수 있음(정상).
- 개발 속도 체감.

### (c) 최소 실험 2~3개
1) **E1: “다중비교 보정 게이트”**
   - 후보 수가 많을수록 PASS 문턱을 상향(예: lockbox_mean 개선 요구치를 후보 개수의 log에 비례).
2) **E2: “단일 지표 최적화 금지”**
   - 목적함수/선정 기준을 2축 이상으로 고정: `net_return` + `worst_mdd` + `turnover` (가중치는 고정, 튜닝 금지).
3) **E3: “pre-commit split”**
   - lockbox 외에 **추가 holdout(초소형) 1개**를 만들어 최종 선정 때 1회만 확인(누수 방지 목적).

### (d) PASS 조건
- 후보가 tuning만 좋아지고 lockbox가 흔들리는 패턴이 줄어야 함:
  - 최근 N회 실험에서 **tuning_mean 대비 lockbox_mean 하락폭의 분산 감소**
- 선정된 챔피언의 worst_mdd가 **현 챔피언(-0.0902) 대비 악화되지 않을 것**(동일/개선).

### 48시간 자동 루프
- (1) 실험 정의: `selection_gate_v2`
- (2) 게이트: `multiple-comparison penalty`, `2-axis criteria`
- (3) 기대 관측치: PASS 수 감소, 대신 “진짜 PASS”의 재현성↑

## TOP5) 운영 리스크 패치: “48시간 자동 루프 안전장치(롤백/서킷브레이커/로그 표준화)”
### (a) 왜 필요한지
- 자동루프는 성능보다 먼저 **망가지는 방식**이 대부분 “조용한 실패(데이터 결측, API 지연, 주문 실패, 재학습 폭주)”로 옴.
- 운영 안전장치가 없으면 좋은 챔피언도 실전에서 깨짐.

### (b) 위험/부작용
- 초기 구현 시간 소요.
- 지나치게 보수적이면 거래가 거의 안 나갈 수 있음(하지만 안전장치가 먼저).

### (c) 최소 실험 2~3개
1) **E1: 서킷브레이커**
   - 조건: (i) 데이터 결측률 임계 초과 (ii) 비용/턴오버 급증 (iii) 최근 K일 손실 급증 시 → **현금화 또는 포지션 동결**.
2) **E2: 챔피언 롤백**
   - “신규 후보가 PASS해도 1사이클(48h) 관찰 후” 적용.
   - 적용 후 성능/리스크 지표가 악화되면 자동으로 이전 챔피언으로 복귀.
3) **E3: 실험/실행 로그 표준**
   - run마다: git hash, 데이터 스냅샷 id, 유니버스 크기, 턴오버, 비용, 체결가 규칙, 실패 사유를 단일 JSON으로 적재.

### (d) PASS 조건
- 48시간 동안 무중단:
  - 실험/백테스트/선정/리포트 생성 **실패율 < 5%**
  - 실패 시에도 “자동 롤백/동결”이 정상 동작(사후 재현 가능 로그 남음)

### 48시간 자동 루프
- (1) 실험 정의: `circuit_breaker + rollback + logging`
- (2) 게이트: `job success rate`, `rollback correctness`
- (3) 기대 관측치: 성능이 아니라 **운영 안정성 지표**가 개선

# 성능이 안 움직일 때 “원인 분해” 아이디어 (트리거/적용/노출/비용/레짐)
아래는 **질문 없이 바로 실행 가능한 진단 트리**입니다.

## 1) Trigger(신호 발생) 문제인지
- [ ] 신호 분포 점검: 예측/스코어의 **분산이 급감**했는지(=아무 신호도 안 나옴)
- [ ] 상관 붕괴: 과거에 먹던 alpha feature와 수익의 상관이 **구간별로 0 근처**로 수렴했는지
- [ ] 이벤트 민감도: 실적/FDA 주간에 신호가 **역방향**이 되는지

## 2) Apply(적용/리밸런스/체결) 문제인지
- [ ] 리밸런스 타이밍을 바꿔 비교: D+1 open vs D+1 VWAP에서 성능이 급변하면 **체결가 민감**
- [ ] 주문 제약으로 “원하는 포지션을 못 가짐” 발생 여부(최대 비중/최소 거래대금) 로그화
- [ ] turnover가 늘었는데 gross는 그대로면 **적용 단계에서 마찰**이 증가한 것

## 3) Exposure(노출/팩터) 문제인지
- [ ] 포트의 베타/섹터 편향: Tech/Healthcare 내에서도 **대형주/고밸류/저퀄리티**로 쏠리는지
- [ ] 상위 2~3종목 기여도: PnL이 특정 종목에 과도 집중(“8~14 보유”라도 사실상 2종목 베팅)
- [ ] 공통 팩터(금리/달러/리스크온) 노출이 커져 알파가 아니라 **매크로 베팅**이 됐는지

## 4) Cost(비용/슬리피지) 문제인지
- [ ] gross는 괜찮은데 net이 정체면 비용 탓
- [ ] 변동성 확대 구간에서 slip이 과소추정되어 “이론상 수익”만 남는지
- [ ] 체결 실패/부분체결을 0으로 가정하고 있지 않은지(운영 리스크 포함)

## 5) Regime(레짐) 문제인지
- [ ] 관측지표(ETF는 트레이드 금지, **지표로만**): QQQ(성장), XLV(헬스케어), IHI(의료기기), XBI(바이오), IWM(소형), TLT(금리), VIX 지표화
- [ ] 레짐별 성과 테이블: (Risk-on/off, 고금리/저금리, 변동성 상/하)로 나눠 **어느 레짐에서만 죽는지**를 먼저 고정
- [ ] 레짐 감지 후 “포지션 축소/현금 비중 증가”가 효과적인지(ETF 매매 없이도 가능)
