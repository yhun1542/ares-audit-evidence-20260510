# TOP1) (최우선) 누수 방지: “시점 정렬 + PIT(point-in-time) 강제”
### (a) 왜 필요한지
- 지금처럼 lockbox가 양호해도, **미세한 시점 누수(리밸런스 시각/종가 사용/리비전 반영/기업행사 반영 시점 오류)**가 있으면 성능이 “움직이지 않거나” 특정 구간만 과대평가된다.
- Tech/Healthcare는 실적/가이던스/임상 이벤트로 갭이 커서, **의사결정 시점과 체결/가격 기준**이 틀리면 체감상 “알파가 증발”한다.

### (b) 위험/부작용
- PIT 강제 후 성능 하락 가능(정상적인 현상).  
- 데이터 파이프라인 복잡도 증가(조인/스냅샷/캘린더).

### (c) 최소 실험(단일 실험에 arm 2~3개)
**실험 정의: `exp_pit_time_alignment_v1`**
- Arm A(기준): 현행(챔피언 파이프라인 그대로)
- Arm B: **signal 생성 시점 T의 입력은 “T-1 close까지”로 고정**, 주문은 T open(or VWAP) 체결로 고정(룰 고정)
- Arm C(가능하면): **기업행사/분할/배당 처리 “as-of” 검증 모드**(가격/수량 조정 타이밍을 하루 지연/당김 비교)

### (d) PASS 조건(게이트)
- [ ] **Leakage unit check**: 각 feature의 timestamp ≤ decision_time을 100% 만족(위반 0건)
- [ ] lockbox_mean **유지 또는 +0.5%p 이상 개선**, 동시에 lockbox_min 악화 폭이 **-0.5%p 이내**
- [ ] worst_mdd **현행(-0.0902) 대비 악화 금지**(동일 또는 개선)

### (48h) 기대 관측치
- PIT 강제 후 tuning_mean은 떨어질 수 있으나, **lockbox 안정성(worst_mdd, lockbox_min)**이 개선/유지되면 정상.
- 성능이 크게 붕괴하면: 기존 성능이 누수 의존 가능성 신호.

# TOP2) 서바이버십/유니버스 편향 제거: “8~14 종목 우주 고정 + 상장폐지/합병 처리”
### (a) 왜 필요한지
- “현재 살아남은 종목 기준”으로만 백테스트하면 Tech에서 특히 **서바이버십 편향**이 강하다.
- 유니버스가 실험마다 미세하게 달라지면, 모델 개선이 아니라 **표본 변화**로 성능이 안 움직이거나 흔들린다.

### (b) 위험/부작용
- 상폐/합병 데이터 처리 미흡 시 NaN/가격 점프 이슈.
- 유니버스 고정으로 단기 성능 하락 가능(대신 재현성↑).

### (c) 최소 실험(단일 실험에 arm 2~3개)
**실험 정의: `exp_universe_survivorship_v1`**
- Arm A: 현행 유니버스 로직
- Arm B: **유니버스 “사전 고정 리스트(Tech+Healthcare 8~14)”**로 고정(리밸런스 시 구성 변경 금지)
- Arm C(가능하면): 상폐/인수 시 **마지막 거래일 이후 현금화 규칙**(다음 거래일 시가 청산 등) 명시 적용

### (d) PASS 조건
- [ ] 각 fold에서 유니버스 구성 변화 로그가 **결정론적(동일 입력→동일 구성)**일 것
- [ ] lockbox_min이 **현행(-0.0534)보다 악화되지 않거나**, 악화 시 worst_mdd가 **동일 이상 개선**으로 보상
- [ ] 운영 관점: 상폐/거래정지 이벤트에서 포트폴리오가 **중단 없이** 다음 스텝으로 진행(에러 0)

### (48h) 기대 관측치
- 평균 성능보다 **분산/꼬리(worst_mdd, min)**가 먼저 변한다. 꼬리 안정화가 관측되면 정답 방향.

# TOP3) 과최적화 차단: “튜닝 자유도 축소 + 잠금 파라미터(Freeze)”
### (a) 왜 필요한지
- 현재 챔피언/후보 간 tuning_mean 개선폭이 작고, lockbox도 비슷하게 움직인다. 이런 국면에서 “더 많은 하이퍼파라미터”는 대부분 **과최적화**로 이어진다.
- 성능이 안 움직일 때는 **탐색공간을 줄여** 신호의 실재 여부를 확인하는 게 더 빠르다.

### (b) 위험/부작용
- 단기 성능이 정체/하락할 수 있음.
- “개선이 안 보이는” 결과가 나오지만, 그게 바로 과최적화 제거의 증거일 수 있음.

### (c) 최소 실험(단일 실험에 arm 2~3개)
**실험 정의: `exp_overfit_controls_v1`**
- Arm A: 현행 튜닝/선택(best-of)
- Arm B: **튜닝 파라미터 50% 축소 + 상위 2~3개만 고정(freeze)**
- Arm C(가능하면): **walk-forward형 선택 규칙**(tuning best가 아니라 “fold별 일관성 점수”로 선택)

### (d) PASS 조건
- [ ] lockbox_mean이 Arm A 대비 **-0.5%p 이내**로 유지되면서, fold 간 성능 분산(표준편차) **감소**
- [ ] worst_mdd 악화 금지(동일 또는 개선)
- [ ] 선택된 설정이 다음 루프에서도 **재선정 확률↑(안정성)**

### (48h) 기대 관측치
- 평균이 크게 안 오르더라도, **재현성(선정 안정성/분산 감소)**이 개선되면 다음 단계(알파 추가/리스크 모델링) 준비 완료.

# TOP4) 비용/슬리피지 미반영 제거: “턴오버 게이트 + 간단 임팩트 모델”
### (a) 왜 필요한지
- Tech/Healthcare 8~14종목은 포지션이 집중되기 쉬워 **리밸런스 비용/스프레드 영향**이 커진다.
- 비용을 모델에 넣지 않으면, 개선이 lockbox에서 “안 움직이는” 형태로 나타나기 쉽다(실현 알파가 비용에 상쇄).

### (b) 위험/부작용
- 비용 모델이 과보수적이면 거래가 사라져 성능이 평평해질 수 있음.
- 비용 파라미터를 또 튜닝하면 과최적화 포인트가 됨(고정 상수로 시작).

### (c) 최소 실험(단일 실험에 arm 2~3개)
**실험 정의: `exp_cost_slippage_v1`**
- Arm A: 현행 비용(또는 비용 없음/단순)
- Arm B: **bid-ask 스프레드 기반 고정 슬리피지 + 체결가(T open/VWAP) 일관화**
- Arm C(가능하면): **거래량 대비 임팩트(간단한 sqrt model) + turnover cap**(예: 일별/리밸런스당 최대 회전율)

### (d) PASS 조건
- [ ] **net(after cost) lockbox_mean** 기준으로 평가(총수익이 아니라 순수익)
- [ ] turnover가 목표 상한 이내로 떨어지면서 lockbox_mean **-0.5%p 이내 유지** 또는 개선
- [ ] worst_mdd 악화 금지(동일 또는 개선)

### (48h) 기대 관측치
- gross는 떨어져도 **net이 유지/개선**되면 실거래 가능성이 올라간다.
- net이 크게 붕괴하면: 기존 알파가 비용에 취약(=턴오버/체결가/시점 문제) 신호.

# TOP5) 운영 리스크/레짐 내성: “관측지표(ETF/VIX) 기반 위험 스케일링(매매는 개별주만)”
### (a) 왜 필요한지
- Tech/Healthcare는 레짐(금리/리스크오프/변동성 급등)에 따라 공통요인 노출이 커서, 알파가 있어도 **레짐 한 번에 MDD가 커질 수 있음**.
- ETF는 매매하지 않고 **관측지표로만** 써서, 포지션 사이징/리스크 오프 게이트로만 활용하면 운영 안정성이 올라간다.

### (b) 위험/부작용
- 레짐 게이트가 과도하면 “현금 비중↑ → 성능 둔화”.
- 레짐 신호가 늦으면 보호 효과 제한.

### (c) 최소 실험(단일 실험에 arm 2~3개)
**실험 정의: `exp_regime_risk_scaler_v1`**  *(ETF 매매 금지, 관측만)*
- Arm A: 현행(리스크 스케일링 없음 또는 기존)
- Arm B: 관측지표(예: **VIX, QQQ/XLV/SPY 수익률/변동성**)로 **포지션 노출 스케일링**(변동성 높으면 총 익스포저 축소)
- Arm C(가능하면): **드로우다운 기반 디레버리지 룰**(최근 N일 DD가 임계 초과 시 익스포저 단계적 축소)

### (d) PASS 조건
- [ ] worst_mdd **개선(현행 -0.0902 → -0.085 이하 목표)** 또는 최소 동일 유지
- [ ] lockbox_mean **-0.5%p 이내 유지**(MDD 개선과 트레이드오프 허용)
- [ ] “레짐 급변 구간”에서 손실 꼬리(lockbox_min, fold별 최저) 악화 금지

### (48h) 기대 관측치
- 평균 수익보다 먼저 **MDD/최저 성과 꼬리**가 개선되는지 본다.
- 개선이 없으면: 현재 전략이 레짐 민감도가 낮거나, 관측지표/임계가 부적절.

# 성능이 “안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래를 **로그/리포트 항목으로 강제 출력**해서, “어디서 죽는지”를 분해한다(질문 없이 바로 추가).

## 1) Trigger(신호 발생) 문제
- [ ] 일별/리밸런스 시점마다 **signal 분포(평균/표준편차/상위·하위 퍼센타일)** 로그
- [ ] “거래가 발생한 날 비율(%)” 및 **신호가 0/클리핑되는 비율** 로그
- 해석
  - 신호 분산이 너무 작으면: 알파가 거의 없거나 스케일링/정규화로 눌림
  - 거래일 비율이 낮으면: 임계치/필터가 과도

## 2) Apply(주문/체결/리밸런스) 문제
- [ ] 목표 포지션 vs 실제 포지션(체결 후) 괴리, 체결 실패/거래정지 처리 로그
- [ ] 리밸런스 주기별 **turnover, 포지션 변경량** 로그
- 해석
  - 목표 대비 괴리가 크면: 체결가/슬리피지/거래가능성 제약이 원인
  - 턴오버가 과하면: 비용이 알파를 상쇄

## 3) Exposure(노출) 문제
- [ ] 포트폴리오 **단일종목 최대 비중**, 섹터(Tech/HC) 내 편중, 베타(시장) 추정치 로그
- [ ] 공통요인(시장/나스닥/금리 민감) 대략 프록시로 상관(예: QQQ, XLV 관측) 로그
- 해석
  - 알파가 아니라 “QQQ 롱”이면: 레짐에서 성능이 안 움직이거나 역풍 시 급락
  - 집중도가 높으면: 몇 종목 이벤트에 성과가 종속

## 4) Cost(비용) 문제
- [ ] gross PnL vs cost vs net PnL 분해 로그(비용이 몇 bp 먹는지)
- [ ] 종목별 스프레드/거래대금 대비 체결비용 추정 로그
- 해석
  - gross는 좋아도 net이 평평하면: 비용/턴오버/체결가 문제
  - 특정 종목만 비용이 과도하면: 유니버스 교체/비중 상한 필요

## 5) Regime(레짐) 문제
- [ ] VIX 구간(저/중/고), QQQ 추세(상승/횡보/하락)별 성과 테이블
- [ ] “레짐별 히트레이트/평균손익/최대손실” 로그
- 해석
  - 특정 레짐에서만 성과가 나면: 레짐 스위치/스케일러가 해결책
  - 모든 레짐에서 평평하면: 신호 자체가 약하거나 누수 제거 후 알파가 사라진 것
