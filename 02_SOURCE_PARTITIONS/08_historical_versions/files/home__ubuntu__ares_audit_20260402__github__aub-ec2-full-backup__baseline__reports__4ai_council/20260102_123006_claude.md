## 1. Priority #1: Rebalance Pipeline 복구 및 검증

### (a) 왜 필요한가
- `rebalance.csv` 로딩 에러 = **실험 결과 자체가 신뢰 불가**
- Delta가 0인 이유가 "전략 문제"인지 "파이프 파손"인지 구분 불가

### (b) 위험/부작용
- 파이프만 고치고 전략 문제를 놓칠 수 있음
- 로그 포맷 변경 시 하위 호환성 깨짐

### (c) 최소 실험

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P1-1 | `rebalance.csv` 출력 로직 점검 — JSON→CSV 변환 누락 여부 | 파일 존재 & row > 0 | ≥50 rows/fold |
| P1-2 | pinpoint 도구에 `--format auto` 추가, JSON/CSV 자동 감지 | 에러 0 | 정상 diff 출력 |
| P1-3 | 강제 리밸런스 1회 삽입 후 로그 확인 (`--force-rebal`) | 로그에 trade 기록 | position delta ≠ 0 |

### (d) PASS 조건
```
✅ rebalance_pinpoint.py 정상 실행
✅ 최소 1개 fold에서 trade_count ≥ 10
```

### (a) 왜 필요한가

- 신호가 0이면 어떤 파라미터를 바꿔도 무의미

### (b) 위험/부작용
- 계측 오버헤드로 백테스트 속도 저하
- 과잉 로깅 시 디스크 문제

### (c) 최소 실험

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P2-1 | `signal_firing_rate.py` 추가 — 일별 FSA buy/sell 카운트 | 스크립트 정상 완료 | daily_fire_rate 출력 |
| P2-2 | threshold 완화 (scale 0.7 → 0.5) 후 발화율 비교 | fire_rate 증가 | Δfire ≥ +30% |
| P2-3 | 무신호 구간 식별 → 해당 구간 레짐 태깅 | 레짐별 fire_rate | bear 구간 < bull 구간 예상 |

### (d) PASS 조건

