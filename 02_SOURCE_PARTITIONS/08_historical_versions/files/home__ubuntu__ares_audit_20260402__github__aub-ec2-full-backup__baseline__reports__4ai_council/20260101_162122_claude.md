## 1. 우선순위 TOP 5 패치

### ⬛ PATCH-1: Tuning Fold 이상치 격리 및 원인 분해

**(a) 필요성**
- tuning_min = -1.35는 단일 종목 또는 특정 기간에서 발생한 극단 손실
- 이것이 과거 데이터 오류인지, 실제 regime인지, 누수인지 분리 필요
- lockbox에 이 패턴이 없다 = **미래에 발생 시 대응 불가**

**(b) 위험/부작용**
- 해당 fold를 "이상치"로 제거하면 서바이버십 편향 증가
- 과도하게 보수적 조치 시 전체 수익률 희생

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| 1a | tuning_min 발생 fold/ticker 식별 → 해당 종목 데이터 integrity 검증 | 데이터 오류 발견 시 PASS | 오류 ticker 목록 또는 "clean" 확정 |
| 1b | 해당 fold 기간(YYYY-MM) regime 분석: VIX spike, sector crash 여부 | regime 매칭 시 PASS | regime_label 태깅 |
| 1c | worst fold를 lockbox에 강제 포함 후 전체 재평가 | lockbox_min > -0.3 유지 시 PASS | lockbox_min 변화량 |

**(d) PASS 조건**
```
IF 1a에서 데이터 오류 → 수정 후 재실행
ELIF 1b에서 regime 매칭 → regime filter 후보 생성
ELIF 1c에서 lockbox_min < -0.5 → 전략 근본 수정 필요 (FAIL → escalate)
```

### ⬛ PATCH-2: Position Sizing에 MDD Guard 추가

**(a) 필요성**
- worst_mdd -9%는 수용 가능하나, tuning에서 -135%는 레버리지 또는 concentration 문제
- 현재 sizing 로직에 drawdown-based throttle 부재 추정

**(b) 위험/부작용**
- 과도한 throttle → 상승장에서 underperformance
- lookback 기간 설정 오류 시 whipsaw

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| 2a | `max_position = min(base_size, 1 / (1 + trailing_dd_5d))` 적용 | tuning_min > -0.5 | tuning_min 개선폭 |
| 2b | Per-ticker MDD cap (단일 종목 -20% 도달 시 1주 hold 금지) | 해당 ticker 이후 손실 축소 | ticker별 손실 분포 |

**(d) PASS 조건**
```
tuning_min > -0.8 AND lockbox_mean 하락 < 3%
```

### ⬛ PATCH-3: 비용 모델 현실화 (슬리피지 + 스프레드)

**(a) 필요성**

**(b) 위험/부작용**
- 과도한 비용 가정 시 신호가 모두 PASS 실패
- 과소 가정 시 라이브 성과 괴리

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |

### ⬛ PATCH-4: Signal Decay / Holding Period 최적화

**(a) 필요성**
- 현재 holding period 고정(추정) → 신호 decay에 따른 exit timing 미조정
- 수익의 대부분이 진입 후 1~3일에 집중되면 longer hold는 노이즈

**(b) 위험/부작용**
- 과최적화 위험 (holding period를 fold별로 맞추면 누수)
- 거래 빈도 증가 → 비용 증가

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| 4a | 진입 후 D+1,2,3,5,10 수익 곡선 분해 (전 fold 평균) | D+3 이후 flat 확인 시 PASS | 수익 decay 곡선 |
| 4b | Holding period를 현행 대비 -30% 축소 후 테스트 | tuning_mean 유지 + worst_mdd 개선 | 변화량 |

**(d) PASS 조건**
```
holding 축소 시 lockbox_mean 하락 < 2% AND worst_mdd 개선 > 0.5%
```
