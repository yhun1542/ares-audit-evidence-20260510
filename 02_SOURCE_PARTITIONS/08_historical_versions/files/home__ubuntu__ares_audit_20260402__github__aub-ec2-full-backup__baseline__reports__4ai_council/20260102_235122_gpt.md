## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — 명령형 체크리스트

### 1) **누수(lookahead) / 타이밍 정합성 최우선 감사**
- [ ] **feature/label 생성 시각을 “거래 의사결정 시각” 기준으로 강제 고정**(예: t일 종가로 계산한 지표는 t+1에만 사용)
- [ ] **asof-merge(시계열 조인) 규칙을 단일화**: `<= decision_time`만 허용
- [ ] **기업행사(earnings/분할/배당) 반영 시각**: “발표일/효력일” 구분, 가격/재무 데이터의 적용 시점 분리
- [ ] **모델/피처 캐시 재사용 시 “시점 키(timestamp key)” 포함**(캐시가 누수를 만들기 쉬움)

**(a) 왜 필요한지**
- Champion이 lockbox_mean이 tuning_mean보다 큰 구조(4.01 vs 2.32)는 **우연/레짐 편차**일 수도 있지만, 동시에 **타이밍/조인 누수**가 섞여도 이런 비정상 패턴이 나올 수 있어 1순위로 제거해야 함.

**(b) 위험/부작용**
- 누수 제거 후 성능이 “일시적으로” 하락할 수 있음(정상화).
- 데이터 정합성 강화로 계산 비용 증가/런타임 증가.

**(c) 최소 실험(아래 공통 실험 E1, E4 재사용)**
- E1, E4 실행

**(d) PASS 조건**
- [ ] **누수 탐지 테스트 전부 PASS**
- [ ] lockbox_mean 하락이 있더라도 **worst_mdd가 악화되지 않음(현재 -0.0815 이하로 악화 금지)**  
- [ ] tuning↔lockbox 성능 괴리가 “설명 가능” 수준으로 축소(과대 괴리 지속 시 추가 조사)

---

### 2) **서바이버십 바이어스/상장폐지/유니버스 고정(Tech+Healthcare 8~14종목)**
- [ ] **유니버스 생성 모듈을 “과거 시점 기준”으로 재구축**(현재 알고 있는 생존 종목만 쓰는지 차단)
- [ ] **delisting return(상장폐지 수익률) 또는 대체 로직**을 명시적으로 처리
- [ ] **Corporate action(분할/합병) 심볼 변경 맵**을 백테스트에 일관 적용
- [ ] “8~14 종목” 제약을 **항상 강제**(리밸런스 시점마다 동일 규칙)

**(a) 왜 필요한지**
- Tech/Healthcare는 상장/합병/심볼 변경이 잦아 **서바이버십 누수**가 성능을 허위로 끌어올리기 쉬움.
- 8~14종목 집중 포트는 **단 1~2개 종목의 데이터 결함**이 결과를 왜곡할 수 있음.

**(b) 위험/부작용**
- 데이터 소스/정합성 이슈로 결측이 늘어 백테스트 가능 구간이 줄어들 수 있음.
- “진짜” 성능이 낮아 보일 수 있음(정상).

**(c) 최소 실험(공통 실험 E2, E1 재사용)**
- E2, E1 실행

**(d) PASS 조건**
- [ ] 서바이버십 방지 유니버스로 재실행해도 **lockbox_mean 급락 방지(예: -25% 이상 급락 시 FAIL)**  
- [ ] **worst_mdd 악화 금지**, fold14_mdd가 현재(-0.0395) 대비 과도 악화 시 롤백

---

### 3) **비용(스프레드/슬리피지/임팩트)/회전율 미반영 제거**
- [ ] **거래비용 모델을 강제 적용**(고정 bps + 스프레드 + 거래대금 기반 임팩트)
- [ ] **턴오버 상한** 또는 **턴오버 패널티**를 목적함수에 포함
- [ ] 리밸런스 주기를 최소 2개 비교(예: daily vs weekly)해서 비용 민감도 확인  
- [ ] “ETF는 매매 금지” 유지, 단 **관측지표(레짐/리스크)**로만 사용

**(a) 왜 필요한지**
- 8~14종목 집중전략은 회전율이 조금만 올라가도 실현 성과가 급락.
- 비용을 안 넣으면 lockbox에서 “좋아 보이는” 모델이 실거래에서 붕괴.

**(b) 위험/부작용**
- 비용 적용 후 평균 수익이 낮아질 수 있음(정상).
- 과도한 비용 가정은 유효 신호까지 제거할 수 있음(보수성 과다).

**(c) 최소 실험(공통 실험 E3, E4 재사용)**
- E3, E4 실행

**(d) PASS 조건**
- [ ] 비용 포함 후에도 **lockbox_mean이 0 이상 유지 + lockbox_min(현재 0.7355) 크게 훼손 금지**  
- [ ] turnover가 목표 범위로 감소(예: -20% 이상)하면서 **worst_mdd 악화 금지**

---

### 4) **과최적화(탐색 폭발) 차단 + 게이트/고정 규칙 강화**
- [ ] 후보군 탐색을 “파라미터 1~2개 축소”로 제한(서치 공간 축소)
- [ ] 튜닝 성능 기준이 아니라 **락박스/워크포워드 게이트 우선**으로 승격 규칙 변경
- [ ] “개별 종목 알파”보다 **공통 구조(리스크/레짐/비용)**를 먼저 고정한 뒤 알파 실험

**(a) 왜 필요한지**
- 지금 상태에서 candidate는 tuning/lockbox가 비슷하지만 MDD가 악화(-0.1118) → **“좋아 보이는 평균”이 DD에서 깨지는 전형적 과최적화/리스크 미통제** 패턴.

**(b) 위험/부작용**
- 단기적으로 “새로운 후보”가 덜 나오고 성능 상승 속도가 느려질 수 있음.
- 게이트 강화로 승격이 거의 없을 수 있음(정상적인 보수화).

**(c) 최소 실험(공통 실험 E4, E3 재사용)**
- E4, E3 실행

**(d) PASS 조건**
- [ ] 승격 후보의 **worst_mdd가 현재 champion(-0.0815) 대비 개선 또는 최소 비열화 금지**
- [ ] lockbox_mean이 champion 대비 열세여도 **MDD/변동성 개선이 명확하면 조건부 PASS(“보수형 챔피언”)** 룰 추가

---

### 5) **운영 리스크(48시간 자동 루프) — 재현성/드리프트/실패 격리**
- [ ] 매 실행마다 **데이터 스냅샷 해시 + 코드 커밋 해시 + 설정 해시** 저장
- [ ] 실패 격리: 데이터 업데이트 실패/일부 심볼 결측 시 **중단 vs 대체 규칙**을 명시
- [ ] “관측 ETF 지표”가 결측이면 레짐 판단을 **보수적 기본값**으로 폴백
- [ ] 리포트에 **(노출/비용/턴오버/레짐) 분해 지표**를 기본 출력으로 추가

**(a) 왜 필요한지**
- 자동 루프에서 가장 흔한 손실 원인은 “전략 자체”보다 **데이터/실행/폴백의 숨은 변화**.
- 실험이 안 움직일 때 원인 파악이 안 되면 48시간 루프가 무의미해짐.

**(b) 위험/부작용**
- 저장/로그로 디스크 사용량 증가.
- 폴백 규칙이 보수적으로 바뀌어 단기 성능 감소 가능.

**(c) 최소 실험(공통 실험 E1, E2 재사용)**
- E1, E2 실행(재현성/데이터결측 케이스 포함)

**(d) PASS 조건**
- [ ] 동일 스냅샷 재실행 시 결과가 **완전 재현(허용 오차 0 또는 매우 작은 수치 오차)**  
- [ ] 결측/실패 시나리오에서 **비정상 포지션(종목 수>14, 현금<0 등) 발생 0건**

## 공통 “실행 가능한 patch/실험” 4개만 운용 (48시간 자동 루프형)
아래 4개(E1~E4)만 돌리고, TOP5는 이 4개를 재사용해서 커버한다.

---

### E1) **Leakage/Timestamp Sanitizer + 단위테스트 패치**
1) 실험 정의
- 모든 feature를 `decision_time` 기준으로 **최소 1바(1일) 시프트** 강제 옵션 추가
- 시계열 조인 함수 1개로 통일(`asof <= decision_time`)
- “발표일 vs 효력일” 필드가 있는 데이터는 **발표일 이전 사용 금지**

2) 게이트
- 누수 테스트(랜덤 시프트/미래값 삽입 감지) 전부 PASS
- lockbox_min 급락(예: 0 이하로 추락) 시 FAIL
- worst_mdd가 -0.0815보다 악화 시 FAIL

3) 기대 관측치
- tuning_mean 감소 가능(정상), 대신 **tuning↔lockbox 괴리 축소**
- 특정 피처 기여도가 급락하면 그 피처가 누수 후보로 식별됨

---

### E2) **Survivorship-free Universe Builder (Tech+Healthcare 8~14)**
1) 실험 정의
- 유니버스를 “현재 구성”이 아니라 **각 시점에 존재했던 티커 집합**으로 생성
- 상장폐지/합병/심볼변경을 이벤트로 처리(대체 티커 매핑 또는 delisting return 반영)
- 섹터 분류(Tech/Healthcare)도 **과거 시점 기준** 캐시/스냅샷화

2) 게이트
- 백테스트 가능 구간/샘플 수가 기준 이하로 감소하면 FAIL(예: 거래일 -20% 초과 감소)
- 종목 수 제약(8~14) 위반 0회
- worst_mdd 악화 시 FAIL

3) 기대 관측치
- 과거 특정 구간 성과가 낮아지면 서바이버십 영향 가능성 증가
- 유니버스 교체가 잦은 구간에서 turnover/비용 민감도가 드러남

---

### E3) **비용/회전율 패치 + 리밸런스 주기 A/B**
1) 실험 정의
- 거래비용 모델: `commission_bps + spread_bps + k * (trade_value/ADV)^alpha`
- 목적함수에 turnover penalty 추가 또는 turnover hard cap
- 리밸런스 주기 2안만 비교: daily vs weekly(케이스 폭발 방지)

2) 게이트
- 비용 포함 후 lockbox_mean이 0 미만이면 FAIL
- turnover가 줄었는데 MDD가 커지면 FAIL(리스크 전이 의심)
- 포지션 종목 수/섹터 비중 제약 위반 0회

3) 기대 관측치
- weekly가 daily 대비 성과는 비슷하거나 조금 낮아도 **MDD/실현 성과 안정**이 개선될 수 있음
- 비용 민감도가 큰 신호(단기 모멘텀 등)는 자동으로 불리해짐

---

### E4) **노출/레짐 게이트(ETF는 지표만) + 리스크 제약**
1) 실험 정의
- ETF는 매매 금지, **관측 지표로만 사용**: 예) QQQ(Tech 위험선호), XLV(헬스케어 방어), SPY(시장), VIX(변동성)
- 레짐 게이트: 고변동/리스크오프에서 **총 익스포저 축소(현금비중 증가)**
- 베타/변동성 타겟 또는 최대 섹터/단일종목 비중 제한 강화

2) 게이트
- worst_mdd 개선(또는 최소 비열화 금지)
- lockbox_mean이 champion 대비 크게 떨어지면 FAIL(예: -20% 초과 열화)
- 종목 수(8~14) 유지, ETF 매매 0건

3) 기대 관측치
- 평균 수익이 약간 줄어도 **하방(min, MDD) 개선**이 나타나야 정상
- 특정 레짐(고VIX)에서 손실이 줄면 게이트가 유효

## 성능이 안 움직일 때 “원인 분해” 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **리포트 기본 섹션**으로 고정 출력하게 패치해 원인 규명을 자동화한다.

### A) Trigger(신호 발생) 문제
- 신호 발생 빈도(일/주), 신호 강도 분포가 과거 대비 드리프트하는지 출력
- 상위 기여 피처 TOP-N의 **시계열 안정성**(갑자기 0/결측/클리핑 여부) 체크
- “신호는 나오는데 수익이 없음” vs “신호 자체가 안 나옴” 분리

### B) Apply(체결/리밸런스 적용) 문제
- 목표 포지션 → 실제 포지션 변환 과정에서
  - 제약(8~14, 섹터, 단일종목 상한) 때문에 신호가 잘려 나가는 비율
  - 리밸런스 주기/컷오프 때문에 신호가 지연되는 정도(평균 지연바) 출력

### C) Exposure(노출) 문제
- 포트폴리오 베타/섹터/상관 구조(Tech 내부 상관 급등 등)로 성과가 잠기는지
- “종목선정 알파”와 “시장 방향성”을 분리:
  - 동일 포지션을 시장중립(가상)으로 만든 성과도 함께 출력(진짜 알파 존재 여부)

### D) Cost(비용) 문제
- 총 PnL을 `gross_pnl - costs = net_pnl`로 강제 분해
- turnover와 비용의 탄력(턴오버 10%p 증가 시 비용 증가량)을 구간별로 출력
- “비용이 성과를 잡아먹는 레짐”이 특정 월/분기에 집중되는지 확인

### E) Regime(시장 국면) 문제
- VIX/시장 추세(예: SPY 50/200), 금리(가능하면) 등 관측지표로 구간을 나누고:
  - 각 레짐별 hit-rate, avg return, MDD를 테이블로 출력
- 레짐별로 **전략이 해야 할 행동(노출 축소/유지)**이 실제로 작동했는지(게이트 히스토리) 출력

---

## 48시간 실행 순서(명령형)
- [ ] E1 → E2 → E3 → E4 순으로 **단일 루프**로 실행(중간에 후보 탐색 확장 금지)
- [ ] 각 E* 실행 후 **게이트 FAIL이면 즉시 롤백**하고 다음 실험으로 진행(케이스 폭발 방지)
- [ ] 최종적으로 “승격 후보 0개”여도 정상 종료: **원인 분해 리포트(A~E) 자동 생성**을 PASS로 간주(운영 안정화 우선)

원하는 형태로 바로 얹을 수 있게, 위 E1~E4를 `aub_autopilot`/`system_autopilot`의 후보 스펙에 “4개 실험만” 등록해서 48시간 자동 루프에 고정시키면 된다.
