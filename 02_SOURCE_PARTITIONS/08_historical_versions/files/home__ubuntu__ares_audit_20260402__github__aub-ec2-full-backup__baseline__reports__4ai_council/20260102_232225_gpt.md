## 다음 24~48시간 TOP5 우선순위(코드/아키텍처/전략)
아래 5개는 “성능 개선”보다 **누수/과최적화/서바이버십/비용 미반영/운영 리스크**를 먼저 잡는 순서로 정렬. (미국주식 only, Tech+Healthcare 8~14종목 유지, ETF는 지표로만 사용)

---

# 1) **리밸런스/체결/노출 로그를 “ONE TRUTH”로 고정 (관측 불능 제거)**
### (a) 왜 필요한지
- 현재 상태에서 **rebalance pinpoint가 실패**(CSV/JSON 파싱 실패, base-log 경로 오류) → **“언제/왜 리밸런스가 일어났는지” 관측 불가**.
- `lane_hash/run_hash=None`, `worst_mdd=None` 등 **산출물 스키마/아티팩트가 불완전** → 성능이 안 움직일 때 원인 규명이 막힘(운영 리스크 1순위).

### (b) 위험/부작용
- 로그/스키마 변경이 **기존 리포트/도구 호환성**을 깨뜨릴 수 있음.
- 저장량 증가(비용). 다만 48시간 루프에선 “필수 지표만” 남기면 제어 가능.

### (c) 최소 실험(2~3개)  ← 아래 EXP 공용 사용
- **[EXP-A] 아티팩트 스키마 하드닝 + 파서 고정**
- **[EXP-D] 비용/턴오버 모델 도입 후, 리밸런스 로그에 비용 항목 강제 포함**
- **[EXP-E] 노출/리스크 지표(베타/섹터/그로스/넷/현금) 로그 강제 포함**

### (d) PASS 조건(게이트)
- (필수) `rebalance.csv or rebalance.jsonl`이 **항상 생성**되고, pinpoint 도구가 **에러 없이 실행**.
- `run_hash/lane_hash/worst_mdd`가 **NULL 없이 채워짐**.
- 각 리밸런스 이벤트에 대해 최소 다음 필드가 존재: `ts, universe_size, selected_names(8~14), weights_pre/post, turnover, est_cost, realized_slippage(가능 시), gross/net, cash`.

---

# 2) **Degenerate folds 제거 + 누수 테스트(시간축/라벨축)**
### (a) 왜 필요한지
- `degenerate_folds: [1,2,3,8]`는 **CV 분할이 깨졌거나(표본 0/상수), 라벨/피처 alignment 문제** 가능성이 큼.
- 이 상태에서 OOS mean이 좋아도 **과최적화/누수**일 확률이 급상승.

### (b) 위험/부작용
- 분할을 정상화하면 **OOS가 떨어질 수 있음**(하지만 “진짜 성능”에 수렴).
- 학습 데이터가 줄어들어 신호가 약해질 수 있음.

### (c) 최소 실험(2~3개)
- **[EXP-B] Walk-forward 분할 sanitizer + 누수 유닛테스트**
- **[EXP-A] 폴드별 요약 아티팩트 강제 저장(폴드별 표본수/타깃 분포/피처 결측률)**
- **[EXP-E] 노출/포지션 수가 폴드별로 붕괴되는지(0노출/과대노출) 체크 로그**

### (d) PASS 조건
- 모든 fold에 대해 `n_train>0, n_valid>0`, 타깃 분산>0, 피처 결측률이 임계 이하.
- “시간 누수” 테스트 통과: `max(feature_ts) < min(label_ts)`(정의한 예측시점 기준).
- 폴드별 노출이 안정: `gross`/`net`/종목수(8~14)가 폴드마다 비정상(0 또는 급등) 패턴이 없음.

---

# 3) **서바이버십/유동성/상장폐지 수익 반영(미국주식 백테스트 신뢰성)**
### (a) 왜 필요한지
- Tech+Healthcare는 종목 교체가 잦고, 상장폐지/인수합병 이벤트가 빈번 → **서바이버십 바이어스**에 매우 취약.
- “좋은 종목만 남는” 우주면 OOS가 멀쩡해 보여도 실거래에서 붕괴.

### (b) 위험/부작용
- 데이터 소스/우주 구축이 바뀌면 과거 성능이 크게 변동(대개 하락).
- 유동성 필터 강화 시 기회가 줄어 성능 상한이 낮아질 수 있음.

### (c) 최소 실험(2~3개)
- **[EXP-C] Survivorship-free universe builder + 상장폐지 리턴 반영**
- **[EXP-D] 유동성 기반 슬리피지(ADV, 스프레드) 비용화**
- **[EXP-A] “일자별 우주 스냅샷(종목 리스트)” 아티팩트 저장**

### (d) PASS 조건
- 임의 날짜 t에 대해 “당시 존재하던 종목”만 우주에 포함됨(현재 생존 종목만으로 구성되는 현상 금지).
- delist 이벤트가 포트폴리오에 들어오면 **리턴/가격 시계열이 끊기지 않고** 규칙대로 처리됨(0 처리/최종가 고정 금지).
- 유동성 필터 후에도 **항상 8~14개 선택 가능**(선택 불가일 땐 현금 비중으로 처리 로그 명시).

---

# 4) **비용(수수료/스프레드/슬리피지/턴오버) 미반영 제거**
### (a) 왜 필요한지
- 현재 챔피언 노출 max 0.84인데, 리밸런스/턴오버 데이터가 “관측 불능” → **비용에 의한 성능 붕괴를 숨길 위험**.
- 특히 48시간 자동 루프에서는 “성능이 안 움직임”의 원인이 사실 **비용이 다 먹는 것**인 경우가 잦음.

### (b) 위험/부작용
- 비용을 넣으면 전략이 “갑자기 죽어 보일” 수 있음(하지만 그게 정상).
- 과한 비용 가정은 신호를 과도하게 죽일 수 있음(보수적으로 시작 후 보정).

### (c) 최소 실험(2~3개)
- **[EXP-D] 거래비용 모델(고정+스프레드+ADV 기반) + 턴오버 패널티**
- **[EXP-A] 리밸런스 로그에 turnover/est_cost 강제**
- **[EXP-E] 노출 타겟팅(변동성 타겟/현금 버퍼)으로 불필요한 매매 감소**

### (d) PASS 조건
- 비용 ON/OFF 두 리포트에서 다음이 항상 산출: `avg_turnover, cost_bps, net_return`.
- 비용 ON 상태에서 **턴오버가 비정상적으로 높으면**(예: 일간 50%+) 자동 게이트로 FAIL 처리(아래 EXP-D 게이트 참고).

# 5) **운영 가능한 리스크 오버레이(노출/레짐/섹터)로 “붕괴 모드” 차단**
### (a) 왜 필요한지
- `exposure_max ~0.84`면 레짐 급변(금리/리스크오프)에서 손실이 급격히 확대 가능.
- Tech+Healthcare는 레짐(금리/리스크선호)에 민감 → **지표 기반(ETF는 지표만) 레짐 게이트**가 운영 리스크를 줄임.

### (b) 위험/부작용
- 오버레이가 과하면 수익 상한을 깎고, “성능이 안 움직이는” 구간이 늘 수 있음.
- 레짐 신호가 지연되면 오히려 손실을 키울 수 있음(게이트는 보수적으로).

### (c) 최소 실험(2~3개)
- **[EXP-E] 리스크 오버레이: (1) 그로스/넷 캡 (2) 현금 버퍼 (3) 베타/변동성 타겟**
  - 베타 추정은 **SPY/XLK/XLV를 ‘지표’로만** 사용(매매는 종목만)
- **[EXP-D] 턴오버 패널티로 오버레이가 불필요한 리밸런스 유발하는지 점검**
- **[EXP-A] 일별 위험지표(베타, VaR proxy, DD, 섹터 익스포저) 로그 강제**

### (d) PASS 조건
- 노출 제약 준수: `gross<=G_cap`, `net` 범위 준수, 현금 최소 비중 준수.
- 급락 구간에서 `worst_mdd`가 기존 대비 개선(또는 최소 악화 제한) + OOS mean 급락이 제한적.

## 48시간 자동 루프용 “실행 가능한” 공용 실험 5개 (정의/게이트/기대 관측치)
아래 5개만 돌려도 위 TOP5를 커버하도록 구성(케이스 폭발 방지).

### [EXP-A] Artifact/Log 스키마 하드닝(리밸런스 포함)
- **(1) 실험 정의**: 백테스트 러너가 항상 동일 스키마(JSON)로 `run_hash/lane_hash/worst_mdd/rebalance_log/universe_snapshot/fold_summary`를 저장. 파서는 한 포맷만 읽게 고정.
- **(2) 게이트**: 도구 2개(`no_delta_diagnoser`, `rebalance_pinpoint`)가 exit code 0.
- **(3) 기대 관측치**: “성능 변화 없음”이어도 리밸런스/노출/비용이 어디서 멈추는지 즉시 보임.

### [EXP-B] Walk-forward 분할 sanitizer + 누수 유닛테스트
- **(1) 실험 정의**: 시간순 분할 고정, 각 폴드에 대해 표본수/타깃분산/결측률/미래정보 참조 여부 검사.
- **(2) 게이트**: degenerate_folds=0, 시간누수 테스트 통과.
- **(3) 기대 관측치**: OOS mean이 떨어질 수 있으나 변동 원인이 “데이터/분할”로 확정됨.

### [EXP-C] Survivorship-free 우주 + delist 처리 + Tech/Health 제약(8~14)
- **(1) 실험 정의**: 날짜 t 기준 상장 종목만 포함, delist 리턴 반영, 섹터(Tech+Healthcare) 필터 + 최종 선택 8~14 강제.
- **(2) 게이트**: 임의 기간에서 우주 스냅샷이 “현재 구성종목 쏠림”을 보이지 않음(서바이버십 징후 제거), 선택 종목수 규칙 준수(불가 시 현금 처리 로그).
- **(3) 기대 관측치**: 백테스트가 더 “현실적으로 나빠질” 수 있으나 신뢰도 상승.

### [EXP-D] 비용/슬리피지/턴오버 모델 + 턴오버 패널티
- **(1) 실험 정의**: (고정 수수료 + 스프레드/ADV 기반 슬리피지) 비용 차감, 목적함수에 turnover 패널티(또는 리밸런스 밴드) 추가.
- **(2) 게이트**: 평균 일간 turnover 임계 이하(예: 20% 같은 내부 기준), 비용 bps 출력 필수.
- **(3) 기대 관측치**: 성능이 “비용 전/후”로 분해되어, 정체 원인이 비용인지 신호인지 분리됨.

### [EXP-E] 리스크 오버레이(노출/베타/변동성/현금) + 레짐 게이트(지표 only)
- **(1) 실험 정의**: 종목 포지션은 유지하되, (1) gross/net cap (2) vol targeting (3) 현금 버퍼. 레짐은 SPY/XLK/XLV의 추세/변동 지표로 “리스크 축소/확대”만 결정.
- **(2) 게이트**: 노출 제약 위반 0회, worst_mdd 산출 및 악화 제한.
- **(3) 기대 관측치**: 급변 구간에서 DD 완화, 평시엔 수익 소폭 감소 가능(트레이드오프가 로그로 명확).

## 성능이 안 움직일 때(“No-Delta”) 원인 분해 아이디어: 트리거/적용/노출/비용/레짐
아래를 **질문 없이** 바로 돌려서 어디가 막혔는지 확정하는 체크리스트.

### A) Trigger(신호 생성) 레벨
- [ ] **신호 분산 체크**: 일자별/종목별 alpha(score)의 표준편차가 0에 수렴하면 “신호가 죽음”.
- [ ] **피처 타임스탬프 검사**: feature_ts, label_ts alignment 로그로 “미래 참조” 또는 “전부 NaN→0 대체” 여부 확인.
- [ ] **폴드별 분포 비교**: 폴드마다 alpha 분포가 급변하면 과최적화/분할 문제.

**트리거가 막혔을 때 기대 관측치**: 종목 선택이 항상 동일/랜덤, 포지션이 현금으로 고정, degenerate fold 증가.

### B) Apply(포지션 변환/랭킹/제약) 레벨
- [ ] **8~14 종목 제약이 실제로 작동하는지**(선택 실패 시 현금 처리되는지) 확인.
- [ ] **타이브레이크/랭크 안정성**: 점수 동일값이 많으면 매일 구성 흔들림(턴오버 폭발) 또는 반대로 고정.
- [ ] **리밸런스 밴드/홀드 규칙**이 의도대로 비용을 줄이는지(턴오버 감소 확인).

**적용이 막혔을 때 기대 관측치**: 신호는 변하는데 포트폴리오는 거의 동일(또는 반대로 과도한 교체).

### C) Exposure(노출/리스크) 레벨
- [ ] `gross/net/cash`가 목표 범위를 지키는지 + 특정 시점에 0 또는 상한에 붙는지 확인.
- [ ] **섹터/팩터 쏠림**(Tech 내부 메가캡 편중 등)으로 실질적으로 “단일 베팅”이 되는지 확인.
- [ ] 베타(대 SPY) 추정치가 지속적으로 한쪽으로 치우치면 레짐에 의해 성능이 “멈춘 것처럼” 보일 수 있음.

**노출이 문제일 때 기대 관측치**: 성능 변동이 시장 지표(SPY/XLK/XLV)와 거의 동일, DD가 레짐에 종속.

### D) Cost(비용) 레벨
- [ ] 비용 OFF/ON 성능 차이를 매일 출력(“gross alpha는 있는데 비용이 다 먹음” 즉시 확인).
- [ ] turnover 상위 날짜 TOP-N을 뽑아 “왜 그날 갈렸는지” 리밸런스 로그로 추적.
- [ ] ADV/스프레드 기반 슬리피지가 특정 종목에 과도하게 붙는지(유동성 부족) 확인.

**비용이 문제일 때 기대 관측치**: 비용 차감 전은 양호, 차감 후만 붕괴 / turnover 스파이크가 성능을 압살.

### E) Regime(레짐) 레벨
- [ ] 레짐 구간을 “지표 only”로 라벨링: 예) SPY 추세↓ & 변동↑이면 위험축소.
- [ ] 레짐별 성능 분해: 같은 전략이 레짐별로만 성능이 갈리는지 확인.
- [ ] 레짐 전환 시점에 노출이 줄어드는지(오버레이 작동) 확인.

**레짐이 문제일 때 기대 관측치**: 전체 평균은 정체인데, 레짐별로는 +/−가 극단적으로 갈림(상쇄).

- [ ] **EXP-B 실행**: degenerate_folds=0 만들고 시간누수 유닛테스트를 게이트로 승격.
- [ ] **EXP-C 실행**: survivorship-free 우주 + delist 처리 + Tech/Health + 8~14 강제(선택 실패는 현금).
- [ ] **EXP-D 실행**: 비용 ON/OFF 리포트 + turnover 게이트(턴오버 폭발 시 자동 FAIL).
- [ ] **EXP-E 실행**: gross/net/현금/변동성 타겟 오버레이 + SPY/XLK/XLV 지표 기반 위험축소(매매는 종목만).

이 5개가 돌아가면, 48시간 루프에서 “성능이 안 움직이는 이유”가 **신호/적용/노출/비용/레짐 중 어디인지** 로그만으로 즉시 갈라지고, 그 다음에야 진짜 알파 실험(피처/모델)을 안전하게 붙일 수 있음.
