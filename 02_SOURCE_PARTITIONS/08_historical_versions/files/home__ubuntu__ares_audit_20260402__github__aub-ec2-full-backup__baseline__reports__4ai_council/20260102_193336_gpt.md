## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — **명령형 체크리스트**

### 1) **아티팩트/로깅/재현성(Ops)부터 즉시 복구**
- `lane_hash/run_hash=None`, `file:` 비어있음 상태를 **실패로 간주**하고 파이프라인을 멈추도록 바꿔라.
- `aub_rebalance_pinpoint`가 **CSV/JSONL 파싱에 실패**했으니, 리밸런스 로그를 “항상 생성/검증”하도록 강제하라.
- “OOS가 움직이지 않는” 문제는 성능 문제가 아니라 **관측 불능(telemetry gap)** 일 가능성이 매우 높으니, 먼저 관측가능 상태로 만들라.

**(a) 왜 필요한지**
- 지금은 후보/챔피언 비교에서 핵심인 **리밸런스/체결/비용** 로그가 비어 있어, 성능 정체가 “전략 문제”인지 “실험이 실제로 다르게 실행되지 않은 문제”인지 분해가 안 된다.

**(b) 위험/부작용**
- 로깅/검증 추가로 실행 시간이 늘고, 과거 실험 일부가 “실패”로 재분류될 수 있다(그러나 그게 정상이자 필요).

**(c) 최소 실험(공유 실험 ID 사용, 총 5개로 제한)**
- (E1), (E2) 적용

**(d) PASS 조건**
- `rebalance.jsonl` + `rebalance.csv`가 **항상 생성**되고 도구가 파싱 성공해야 한다.
- 모든 런에 `lane_hash/run_hash/model_hash/data_hash`가 채워지고, 누락 시 런을 FAIL 처리해야 한다.
- “No rebalance data found” 문구가 **0건**이 되어야 한다.



### 2) **누수/폴드 퇴화(degenerate_folds) 최우선 차단**
- `degenerate_folds: [1,2,3,8]`는 **누수/데이터 정렬 오류/트레이드 0건 폴드** 가능성이 높으니, 성능 논의 전에 구조적 결함을 제거하라.
- “폴드 내 거래 수/노출/리턴 분포”를 폴드별로 강제 로깅하고, 기준 미달 시 FAIL 처리하라.

**(a) 왜 필요한지**
- 폴드가 퇴화하면 OOS mean이 “우연히” 좋아 보이거나, 반대로 “아무 변화 없음”으로 보일 수 있다(실험이 실제로 적용되지 않았거나, 포지션이 0에 가까움).

**(b) 위험/부작용**
- 누수 제거 후 OOS가 하락할 수 있다(하지만 그게 현실 성능).
- 게이트 강화로 통과 실험 수가 줄어 개발 체감 속도가 느려질 수 있다.

**(c) 최소 실험**
- (E2), (E1) 적용

**(d) PASS 조건**
- `degenerate_folds=[]` 달성.
- 각 폴드에서 `#trades >= N`, `avg_gross_exposure >= X` 같은 **최소 활동성 게이트** 통과(폴드별 0거래 금지).
- OOS 분포에서 극단치(한 폴드만 기여)가 줄고, `oos_min`이 악화되지 않아야 한다(현재 `oos_min`이 이미 음수).



### 3) **서바이버십/상장폐지/기업행동(스플릿·M&A) 반영**
- “미국주식 only, Tech+Healthcare 8~14종목” 제약에서 **서바이버십 바이어스**가 성능을 가장 쉽게 부풀린다.
- 상장폐지/티커 변경/합병을 반영하지 않으면 OOS가 “안 움직이거나” “과도하게 좋게” 보일 수 있다.

**(a) 왜 필요한지**
- Tech/Healthcare는 구성 변화가 잦고, 실패 기업의 데이터 누락이 성능을 왜곡한다.
- 8~14개 집중 포트는 한 종목의 결측/행동 오류가 성능을 지배한다.

**(b) 위험/부작용**
- 과거 성능 하락(정상).
- 데이터 소스/파이프라인 변경으로 과거 결과 재현이 깨질 수 있으니 해시/버전 고정이 필요(1번과 연결).

**(c) 최소 실험**
- (E3), (E2) 적용

**(d) PASS 조건**
- “상장폐지 포함 유니버스(PIT)”로 재계산했을 때도 챔피언이 **유사한 방향성**을 유지해야 한다(완전 붕괴 시 과거 성능은 허상 가능성 큼).
- 기업행동 반영 후에도 **가격 점프(스플릿 미반영)** 같은 비정상 수익률 스파이크가 제거되어야 한다.



### 4) **비용(스프레드/슬리피지/임팩트/차입) 미반영 제거 + 턴오버 제어**
- 지금 상태는 `worst_mdd: None` 같은 핵심 리스크 메트릭도 비어 있고, 비용 로그도 불명확하다.
- 48시간 루프에서는 “gross 개선”보다 **net 안정화**가 우선이다.

**(a) 왜 필요한지**
- Tech 대형주라도 잦은 리밸런싱은 슬리피지/스프레드로 깎인다.
- 헬스케어(바이오 등)는 이벤트로 갭이 커 비용/체결 리스크가 커진다.

**(b) 위험/부작용**
- 비용 모델이 과도하면 전략이 과도하게 보수화되어 기회 손실.
- 차입비/공매도 제약을 넣으면 전략 설계 자체가 바뀔 수 있음.

**(c) 최소 실험**
- (E4), (E1) 적용

**(d) PASS 조건**
- `OOS_net_mean`(또는 비용 차감 후 메트릭)이 **개선**되거나, 최소한 `OOS_gross - OOS_net` 갭이 설명 가능한 수준으로 안정화.
- 턴오버 상한 도입 후에도 `oos_min`이 악화되지 않아야 한다(꼬리 리스크 악화 금지).



### 5) **노출/리스크/레짐 게이팅(ETF는 관측지표만) + 8~14종목 강제**
- 현재 `exposure_max ~0.84`이고 최소 노출은 0이라 “때로는 거의 안 들어감/때로는 크게 들어감” 형태일 수 있다.
- Tech/Healthcare 집중(8~14)에서 레짐(리스크온/오프) 미반영은 `oos_min` 악화로 이어진다.

**(a) 왜 필요한지**
- 성능이 “안 움직이는” 가장 흔한 이유 중 하나가 **노출이 다 비슷하게 고정**되거나, 반대로 **게이트로 인해 거의 0노출**이어서 변화가 리턴에 반영되지 않는 것이다.
- ETF는 매매하지 말고, QQQ/XLK/XLV/SPY/IEF/VIX류(지표로만)로 레짐을 관측해 **진입 강도/총노출**을 조절하라.

**(b) 위험/부작용**
- 레짐 게이트가 과최적화되면(특히 최근 1~2년) OOS가 악화.
- 8~14 강제는 분산을 제한하여 단기 변동성을 키울 수 있음.

**(c) 최소 실험**
- (E5), (E2) 적용

**(d) PASS 조건**
- **항상 8~14종목** 보유(현금 비중이 정책상 필요하면 그 규칙을 명시하고 로깅).
- `oos_min`(최저 OOS 구간 성과) 개선 또는 최소한 악화 금지.
- `worst_mdd`가 계산 가능하고, 상한을 넘지 않아야 한다(계산 불가 상태는 FAIL).

## 48시간 자동 루프용 “실행 가능한 Patch/실험” 5개 (총 5개로 제한)
아래 5개를 **공유 실험 세트(E1~E5)** 로 돌리고, 위 TOP5 제안은 이 실험들을 조합해 평가하라.

### (E1) **Rebalance/Cost/Exposure 텔레메트리 강제 패치**
1) **실험 정의**
- 리밸런스 이벤트를 `rebalance.jsonl`(원자 이벤트) + `rebalance.csv`(요약)로 항상 기록하라.
- 각 이벤트에 `timestamp, universe_size, holdings_count, target_w, filled_w, gross/net, turnover, est_cost, realized_cost(가능 시)`를 포함하라.
- `lane_hash/run_hash/data_hash/code_hash`를 산출해 아티팩트에 박아라(누락 시 런 FAIL).

2) **게이트**
- 로그 파일 존재/파싱 성공 필수.
- `holdings_count`/`gross_exposure`가 전 기간 0에 수렴하면 FAIL(“전략 미적용” 탐지).

3) **기대 관측치**
- `aub_rebalance_pinpoint`가 정상 리포트를 생성.
- “성능 무변화”가 **(a) 신호 변화 없음 (b) 적용 안 됨 (c) 비용으로 상쇄** 중 어디인지 분해 가능해짐.


### (E2) **누수/폴드 퇴화 차단 게이트(Embargo + PIT shift + 활동성 하한)**
1) **실험 정의**
- 모든 feature/라벨에 대해 **PIT 시간 정렬(shift)** 를 강제하라(미래 데이터 참조 방지).
- 폴드 분할에 **embargo(완충 구간)** 를 추가하라(특히 일봉/이벤트 기반이면 필수).
- 폴드별 최소 거래 수/최소 평균 노출/최소 리밸런스 횟수 게이트를 추가하라.

2) **게이트**
- `degenerate_folds`가 하나라도 있으면 FAIL.
- 폴드별 `#rebalance >= N`, `#trades >= N`, `avg_gross_exposure >= X` 미달 시 FAIL.

3) **기대 관측치**
- OOS mean이 단기 하락할 수 있으나, 폴드 간 분산이 줄고 재현성이 상승.
- “No-Delta(변화 없음)” 케이스가 **실제 전략 무변화인지** 빠르게 판정 가능.


### (E3) **서바이버십/상장폐지/기업행동 반영 유니버스 패치**
1) **실험 정의**
- 종목 마스터를 PIT 스냅샷으로 구성하고, delist/merge/rename를 추적하라.
- 스플릿/배당 조정 가격(조정종가)과 “실제 체결 가능한 가격” 정의를 분리해 로깅하라.
- “Tech+Healthcare” 분류도 PIT로 고정(사후 분류 금지).

2) **게이트**
- 특정 시점에 존재하던 종목이 미래 시점 데이터만으로 선별되지 않았음을 검증(샘플링 검사 자동화).
- 비정상 수익률 스파이크(스플릿 미반영 등) 탐지 시 FAIL.

3) **기대 관측치**
- 과대평가된 성능이 정상화(대개 하락).
- 8~14 집중 포트에서 데이터 오류로 인한 가짜 알파가 사라짐.


### (E4) **비용/차입/슬리피지 모델 온 + 턴오버 패널티**
1) **실험 정의**
- 최소 비용 모델: `half-spread + k*vol*sqrt(size/adv)` 같은 임팩트 근사 + 커미션.
- 공매도 사용 시 차입비(보수적으로 상수라도) 반영, 또는 공매도 금지/제한 실험을 별도 토글로 두되 여기선 “반영”을 우선.
- 목적함수/선정 규칙에 turnover 패널티 또는 리밸런스 빈도 하향을 포함하라.

2) **게이트**
- `OOS_net` 메트릭을 기본 출력으로 강제(없으면 FAIL).
- 턴오버 상한 초과 구간이 일정 비율 이상이면 FAIL(운영 불능 탐지).

3) **기대 관측치**
- gross 성능은 줄어도 net이 안정화.
- “움직이지 않음”이 비용 상쇄 때문인지 즉시 확인 가능(거래는 많지만 net이 0에 수렴하는 패턴).


### (E5) **노출/종목수(8~14) 강제 + 레짐 관측 기반 위험 게이트**
1) **실험 정의**
- 포트폴리오 보유 종목 수를 **항상 8~14**로 강제하라(동률 처리 규칙 고정).
- 총노출(gross), 순노출(net) 상한/하한을 정책으로 고정하고 로그로 남겨라.
- ETF는 매매 금지 유지, 대신 관측지표로만 사용:
  - 예: `QQQ/XLK/XLV/SPY` 20~60일 모멘텀, `VIX` 또는 변동성 대용(가능한 내부 추정치).
  - 레짐에 따라 **포지션 스케일(0.6~1.0)** 또는 **리스크 컷(총노출 상한)** 만 조정하라(규칙 단순 유지).

2) **게이트**
- holdings_count가 범위를 벗어나면 FAIL.
- 노출 상한 위반/현금 과다(정책 위반) 시 FAIL.
- 레짐 신호가 특정 구간에만 과도하게 작동(희소 트리거)하면 경고/FAIL(과최적화 냄새).

3) **기대 관측치**
- `oos_min` 개선(꼬리 구간 방어) 또는 최소 악화 방지.
- 성과가 “안 움직이면” 그 원인이 **노출 고정/게이트로 인한 무포지션**인지 로그로 즉시 드러남.

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐) — 체크리스트 트리
아래를 **위에서 아래 순서로** 자동 진단 리포트로 만들라. (누수/운영 리스크 우선)

### A. 트리거(신호 생성) 레벨
- 신호 시계열의 분산/엔트로피를 기록하라: `std(signal)`, `pct_nonzero`, `rank_dispersion`.
- 신호가 바뀌었는데도 동일하면 “실험 미적용(코드 경로 동일)” 의심 → (E1) 해시로 확인하라.
- 신호 자체가 거의 상수면 “데이터 정렬/결측 처리/정규화 버그” 의심 → (E2) PIT/shift 점검하라.

### B. 적용(포트 구성/리밸런스) 레벨
- 리밸런스 횟수/거래 수가 폴드별로 0 또는 극단적으로 적으면 “degenerate fold” → (E2) 게이트로 차단하라.
- 목표비중(target)과 체결비중(filled)의 차이를 기록하라: 지속적으로 괴리면 체결/제약(종목수, 상한) 문제다 → (E5) 정책/게이트 조정.

### C. 노출(포지션 사이징) 레벨
- 기간별 `gross/net exposure` 히스토그램을 출력하라.
- 성능이 안 움직이고 노출도 거의 일정하면 “사이징이 신호를 죽임” → 스케일링이 0.9 고정 같은 구조를 의심.
- 노출이 자주 0이면 “게이트/레짐 필터가 과도” → (E5) 트리거 희소성 경고.

### D. 비용(실현/추정) 레벨
- `gross_return - cost_est - borrow - slippage` 브릿지를 리밸런스 단위로 쪼개라.
- 거래는 많은데 net이 0 근처면 “비용 상쇄/턴오버 과다” → (E4)로 턴오버 패널티/빈도 조정.
- 비용 모델을 넣었는데 결과가 거의 동일하면 “비용이 로그에 반영 안 됨/계산 경로 미연결” → (E1) 텔레메트리로 검증.

### E. 레짐(시장 상태) 레벨
- ETF(관측지표) 기반으로 구간을 나눠 성과를 분해하라(매매 금지 유지):
  - 예: QQQ 모멘텀 상/하, 변동성 상/하, 금리(IEF proxy) 상/하
- 특정 레짐에서만 성능이 나오면 “레짐 민감 + 샘플 편향” → (E5)로 노출 컷만 단순 적용하고, 복잡한 조건 분기는 금지하라(과최적화 방지).

## 실행 순서(48시간 루프에서 바로 돌아가게)
1. **E1 먼저 병합** → 로그/해시/리밸런스 파싱이 “항상 성공”하게 만들어라.  
2. **E2 병합** → degenerate_folds를 0으로 만들고, 누수 가능성을 구조적으로 제거하라.  
3. 그 다음 **E4 → E3 → E5** 순으로 1개씩 켜서, “성능 정체”가 비용/데이터편향/노출정책 중 어디서 오는지 순차적으로 분리하라.  

이 순서를 지키면, 24~48시간 안에 “왜 안 움직였는지”가 최소한 **관측 가능** 상태로 바뀌고, 이후에야 전략 성능 개선 실험이 의미를 갖는다.
