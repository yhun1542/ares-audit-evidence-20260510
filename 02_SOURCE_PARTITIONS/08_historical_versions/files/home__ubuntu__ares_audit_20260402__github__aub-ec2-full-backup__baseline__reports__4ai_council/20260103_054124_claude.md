## 📋 TOP 5 Priority Patches (48H)

### **P1. Degenerate Fold 원인 분리 (Infra)**

**(a) 왜 필요한가**
- 4/10 fold가 degenerate = 40% 구간에서 전략이 "아무것도 안 함"
- 원인 후보: (1) 시그널 임계값 과잉 (2) 유니버스 필터 과잉 (3) 특정 레짐 회피
- 이걸 모르면 OOS 개선이 운인지 실력인지 판별 불가

**(b) 위험/부작용**
- 잘못 완화 시 noise trade 증가 → 비용 폭증
- 과거 degenerate 구간이 실제로 "거래 안 하는 게 맞았던" 레짐일 수 있음

**(c) 실험 정의**

```yaml
EXP-P1a:
  name: "signal_threshold_sweep"
  change: signal_threshold ∈ [0.3, 0.5, 0.7] (현재 추정 0.6+)
  gate: degenerate_folds ≤ 2 AND oos_mean ≥ 2.0
  observe: [fold별 exposure_mean, trade_count_per_fold]

EXP-P1b:
  name: "universe_filter_relax"  
  change: min_adv 20M→15M, min_mcap 10B→5B
  gate: universe_size +20% AND degenerate_folds ≤ 3
  observe: [avg_daily_positions, sector_concentration]

EXP-P1c:
  name: "regime_tag_audit"
  change: fold별 VIX/SPY-trend 태깅 후 degenerate 상관분석
  gate: report_only (no param change)
  observe: [correlation(degenerate, high_vix), correlation(degenerate, bear_market)]
```

**(d) PASS 조건**
```
degenerate_folds ≤ 2 
AND oos_mean ≥ 2.5 
AND oos_min > -1.5%
```

### **P2. MDD 계산 파이프라인 복구 (Infra)**

**(a) 왜 필요한가**
- `worst_mdd = None` = 리스크 게이트 작동 불가
- MDD 없이 champion 선정 = drawdown 폭탄 내재 가능성

**(b) 위험/부작용**
- 계산 버그 수정 시 과거 champion이 실격될 수 있음 (좋은 일)
- 연산 비용 증가 (미미)

**(c) 실험 정의**

```yaml
EXP-P2a:
  name: "mdd_calc_debug"
  change: |
    # champion_v5_latest.json에서 equity curve 추출
    # peak-to-trough 계산 로직 단위테스트
  gate: worst_mdd ≠ None
  observe: [mdd_per_fold, mdd_recovery_days]

EXP-P2b:
  name: "mdd_gate_activation"
  change: gate 조건에 worst_mdd < 15% 추가
  gate: 기존 champion 재평가 시 PASS/FAIL 분류
  observe: [filtered_experiments_count]
```

**(d) PASS 조건**
```
worst_mdd ≠ None 
AND worst_mdd < 20%
```

### **P3. Rebalance 로그 정규화 (Infra)**

**(a) 왜 필요한가**
- 현재 CSV/JSONL 파싱 실패 → 실제 거래 비용 검증 불가
- "OOS 3.3% → 비용 반영 후 1.5%" 같은 함정 탐지 불가

**(b) 위험/부작용**
- 로그 포맷 변경 시 기존 분석 도구 호환성 깨짐
- 저장 용량 증가

**(c) 실험 정의**

```yaml
EXP-P3a:
  name: "rebalance_schema_fix"
  change: |
    # 출력 포맷 통일: JSONL with schema
    # {"ts", "action", "ticker", "shares", "price", "cost_bps"}
  gate: aub_rebalance_pinpoint.py 정상 실행
  observe: [total_cost_bps, turnover_annual]

EXP-P3b:
  name: "cost_model_validation"
  change: 실제 거래 기록 vs 백테스트 가정 비용 비교
  gate: |cost_gap| < 5bps
  observe: [slippage_realized, spread_cost]
```

**(d) PASS 조건**
```
로그 파싱 성공 
AND 연간 turnover < 300%
AND total_cost < 80bps/year
```

### **P4. OOS Min 방어 (Strategy)**

**(a) 왜 필요한가**
- `oos_min = -2.57%` = 최악 fold에서 손실
- 단일 fold 손실이 전체 신뢰도 훼손

**(b) 위험/부작용**
- 방어 과잉 시 수익 기회 상실
- Tail hedge 비용 증가

**(c) 실험 정의**

```yaml
EXP-P4a:
  name: "position_cap_tighten"
  change: max_position_weight 8%→5%
  gate: oos_min > -1.5% AND oos_mean > 2.0
  observe: [concentration_ratio, worst_single_stock_contrib]

EXP-P4b:
  name: "sector_cap_add"
  change: max_sector_weight 35%→25%
  gate: oos_min > -2.0%
  observe: [sector_drawdown_contrib]

EXP-P4c:
  name: "vol_scaling_dynamic"
  change: position_size *= (target_vol / realized_vol_20d)
  gate: oos_min > -1.5% AND oos_std < 1.5%
  observe: [vol_ratio_distribution, exposure_stability]
```

**(d) PASS 조건**
```
oos_min > -1.5%
AND oos_mean > 2.5
AND oos_std < 2.0
```

### **P5. Exposure 안정화 (Strategy)**

**(a) 왜 필요한가**
- `exposure_min=0.0, max=0.84` = 0~84% 진폭
- 0% 노출 = 기회비용, 급변동 = 거래비용 폭증

**(b) 위험/부작용**
- 강제 노출 시 불리한 레짐에서 손실 확대
- 유동성 제약 위반 가능

**(c) 실험 정의**

```yaml
EXP-P5a:
  name: "min_exposure_floor"
  change: exposure_min = 0.3 (현금 최대 70%)
  gate: oos_mean > 2.0 AND exposure_std < 0.15
  observe: [cash_drag_cost, forced_entry_return]

EXP-P5b:
  name: "exposure_smooth"
  change: target_exposure = 0.7 * prev + 0.3 * signal
  gate: turnover -20% AND oos_mean > 2.0
  observe: [daily_exposure_change, rebalance_frequency]
```

**(d) PASS 조건**
```
exposure_min > 0.2
AND exposure_max < 0.85
AND exposure_std < 0.12
```
