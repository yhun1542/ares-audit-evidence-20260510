## 1. 우선순위 TOP 5 제안

### P1. 비용 모델 현실화 (가장 높은 누수 리스크)

**(a) 왜 필요한지**
- Lockbox mean 1.55 vs Tuning mean 1.40 → 역전 현상 = 비용 미반영 또는 리밸런싱 빈도 과다 의심
- 실거래 시 연 20~40% 성과 차감 가능

**(b) 위험/부작용**
- 비용 반영 후 전략 대부분 FAIL 가능 (과최적화 노출)
- 리밸런싱 빈도 강제 축소 시 신호 지연

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P1-a | `cost_model: {slippage_bps: 5, commission_bps: 2}` 추가 후 전체 재계산 | lockbox_mean ≥ 1.0 | 0.8~1.2 예상 |
| P1-b | 리밸런싱 주기 weekly → monthly 변경 | turnover ↓50% 이상 | MDD 악화 ≤ 2%p |
| P1-c | 거래비용 10bps로 스트레스 테스트 | lockbox_mean > 0 | 전략 생존 여부 확인 |

**(d) PASS 조건**
```
lockbox_mean(cost-adjusted) ≥ 1.0 AND worst_mdd ≤ -0.10
```

### P2. Survivorship Bias 점검

**(a) 왜 필요한지**
- Tech+Healthcare 집중 → 2020-2025 생존 기업만 백테스트 위험
- 상폐/인수 종목 누락 시 연 3~8% 상향 편향

**(b) 위험/부작용**
- 과거 데이터 재구축 필요 (시간 소요)
- 종목 수 증가 시 신호 희석

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P2-a | 2020-2023 상폐 종목 5개 수동 추가 (예: LUMN, VIAC 등) | tuning_mean 변화율 | ≤ -5% 시 편향 확정 |
| P2-b | S&P500 at-the-time 구성으로 유니버스 재정의 | 종목 수 변화 | +20~50개 예상 |

**(d) PASS 조건**
```
at-the-time 유니버스 tuning_mean ≥ 현재값 × 0.90
```

### P3. 레짐 필터 도입 (Worst MDD 개선 타겟)

**(a) 왜 필요한지**
- worst_mdd -9% → 실전 운용 시 -15% 이상 가능 (슬리피지+패닉)
- VIX > 30 구간 노출 축소로 테일 리스크 제어

**(b) 위험/부작용**
- 레짐 판단 지연 → 반등 초기 미탑승
- 과적합된 VIX 임계값 위험

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P3-a | VIX > 28 시 포지션 50% 현금화 | worst_mdd 개선 | -9% → -6% 타겟 |
| P3-b | SPY 20일 이평 하회 시 신규 진입 중단 | 수익률 영향 | ≤ -10% 허용 |
| P3-c | P3-a + P3-b 결합 | MDD + 수익률 균형 | Sharpe 유지 |

**(d) PASS 조건**
```
worst_mdd ≥ -0.07 AND lockbox_mean ≥ 1.20
```

### P4. 종목 집중도 최적화 (8~14 범위 내 탐색)

**(a) 왜 필요한지**
- 현재 종목 수 미확인 → 과집중(< 8) 또는 희석(> 14) 리스크
- Kelly 기준 최적 종목 수 재계산 필요

**(b) 위험/부작용**
- 종목 수 증가 → 관리 복잡도 상승
- 감소 → 개별 종목 리스크 증폭

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P4-a | 종목 수 고정 8개 (Top conviction만) | 변동성 변화 | vol +20% 허용 |
| P4-b | 종목 수 고정 14개 (분산 최대화) | 수익률 변화 | -15% 허용 |

**(d) PASS 조건**
```
Sharpe(new) ≥ Sharpe(champion) × 0.95
```

### P5. 신호 지연 테스트 (운영 리스크 시뮬레이션)

**(a) 왜 필요한지**
- 실전에서 신호 발생 → 체결까지 4~24시간 지연
- 백테스트는 즉시 체결 가정 → 3~10% 성과 괴리

**(b) 위험/부작용**
- 지연 반영 시 모든 수치 하락
- 너무 보수적 설정 시 전략 무력화

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P5-a | 신호 1일 지연 체결 (T+1 close) | 전체 수익률 변화 | -5~15% 예상 |
| P5-b | 신호 2일 지연 (T+2) | 전략 생존 여부 | lockbox_mean > 0 |

**(d) PASS 조건**
```
T+1 lockbox_mean ≥ 1.0
```

## 3. 성능 미변화 시 원인 분해 트리

```
성능 변화 없음
│
├─ [트리거] 신호가 발생했는가?
│   ├─ NO → 조건 너무 엄격 / 데이터 문제
│   └─ YES ↓
│
├─ [적용] 신호가 포지션 변경으로 이어졌는가?
│   ├─ NO → 필터/제약조건 차단 (레짐, 집중도 등)
│   └─ YES ↓
│
├─ [노출] 포지션이 충분히 오래 유지되었는가?
│   ├─ NO → 휩소 (whipsaw) / 너무 빈번한 리밸런싱
│   └─ YES ↓
│
├─ [비용] 거래비용이 수익을 상쇄했는가?
│   ├─ YES → 비용 모델 또는 회전율 문제
│   └─ NO ↓
│
└─ [레짐] 테스트 기간이 불리한 시장 환경이었는가?
    ├─ YES → 레짐 분리 테스트 필요
    └─ NO → 전략 자체 알파 부재 (폐기 검토)
```
