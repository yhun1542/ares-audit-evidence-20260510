## TOP5 우선순위(24~48h) — “명령형 체크리스트” (Tech+Healthcare, 8~14종목, ETF는 관측만)

### 1) **누수/평가 무결성: time alignment + MDD/리포팅 결손 먼저 고쳐라**
- (a) 왜 필요한지  
  - 현재 Champion에 `file:` 비어있고 `worst_mdd: None`은 **평가 파이프라인 결손/예외** 가능성이 큼.  
  - 누수/평가 오류는 어떤 전략 개선보다 우선(잘못된 OOS가 “개선”처럼 보임).
- (b) 위험/부작용  
  - 정정 후 성능(oos_mean)이 급락할 수 있음(그게 정상).  
  - 기존 챔피언 갱신/비교 기준이 바뀌어 과거 결과와 단절.
- (c) 최소 실험(아래 공용 실험 ID 재사용)  
  - **[E1] 시간정렬/누수 감사 + Purge/Embargo CV 적용**  
  - **[E4] 리포팅/아티팩트(파일/해시/메트릭) 강제 저장 + MDD 산출 강제**
- (d) PASS 조건  
  - `worst_mdd`가 **항상 유한값**으로 산출되고, 예외 발생 시 run이 **FAIL로 종료**.  
  - Purge/Embargo 적용 후에도 OOS가 **극단적 붕괴(-50% 이상 등)**가 아니고, fold별 성능 분산이 “설명 가능한 범위”로 안정(최소/평균 갭 축소 관측).  
  - `file`(모델/설정 스냅샷)이 run_hash와 함께 100% 남음.

### 2) **비용/슬리피지/턴오버 미반영부터 제거해라 (가장 흔한 ‘가짜 샤프’ 원인)**
- (a) 왜 필요한지  
  - Tech/Healthcare 단일주 8~14종목은 리밸런싱 빈도/체결 가정에 따라 성능이 크게 흔들림.  
  - 비용을 뒤늦게 넣으면 전략 구조 자체가 무너질 수 있어 조기 반영이 필수.
- (b) 위험/부작용  
  - 비용 모델이 과도하면 “좋은 전략”도 죽일 수 있음(보수적/현실적 범위 스윕 필요).  
  - 턴오버 제한이 시그널 반응성을 감소시킬 수 있음.
- (c) 최소 실험  
  - **[E2] 비용+슬리피지 민감도 스윕 + 턴오버 캡 패치**  
  - **[E3] 레짐 게이트 도입 시 비용/턴오버가 실제로 줄어드는지 동시 관측**
- (d) PASS 조건  
  - 비용/슬리피지 “중간값” 가정에서 OOS 성능이 **기준 대비 과도 붕괴 없이(예: oos_mean 80~90% 이상 유지)** 남고,  
  - 연환산 턴오버/거래횟수가 **명시한 운영 상한** 아래로 들어옴(그리고 그 상한이 코드로 강제됨).

### 3) **서바이버십/기업행위(스플릿·머지·상폐)·데이터 품질을 ‘테스트로’ 잠가라**
- (a) 왜 필요한지  
  - 단일주 기반은 corporate action 처리/상장폐지 처리에서 한 번만 틀려도 백테스트가 미화됨.  
  - 특히 “8~14종목 고정 바스켓”일수록 과거 생존 종목만 남기는 편향이 생기기 쉬움.
- (b) 위험/부작용  
  - 데이터 소스/정정 로직 추가로 파이프라인이 복잡해지고 속도가 느려질 수 있음.  
  - 상폐/티커 변경 처리에서 예외케이스가 늘어 운영 부담 증가.
- (c) 최소 실험  
  - **[E4] 데이터 무결성 테스트(스플릿/가격점프/결측/상폐) + 실패 시 자동 중단**  
  - **[E1] 시계열 누수 검사에 “기업행위 이벤트 당일/익일 정렬” 포함**
- (d) PASS 조건  
  - 결측/가격점프/거래정지/상폐 이벤트가 있는 구간에서 **룰 기반 처리(제외/홀드/현금화)가 일관**되고,  
  - 동일 기간을 재실행해도 성능이 **완전 재현**(run_hash 동일 설정이면 메트릭 변동 허용범위 내).

### 4) **노출(Exposure) 제어: 항상 0.47~0.84 박스권이면 ‘리스크 오프’가 없다**
- (a) 왜 필요한지  
  - 현재 노출이 거의 항상 높음 → 레짐이 꺾일 때 손실을 그대로 맞기 쉬움.  
  - ETF(매매 X)를 관측지표로 쓰면 “시장/섹터 레짐”을 싸게 추적 가능.
- (b) 위험/부작용  
  - 게이트가 잦으면 기회손실(상승장 수익 감소).  
  - 게이트가 시그널과 상충하면 전략이 “항상 안 들어가는” 상태가 될 수 있음.
- (c) 최소 실험  
  - **[E3] ETF 기반 레짐 게이트(관측만): QQQ, XLV, SPY (필요시 IWM)로 Risk-on/off 스위치**  
  - **[E2] 게이트 도입 후 비용/턴오버 감소가 동반되는지 확인**
- (d) PASS 조건  
  - 노출 분포에 **의미 있는 저노출 구간(예: <0.20)**이 생기고,  
  - 비용 포함 기준으로도 OOS 성능이 **개선 또는 MDD 유의미 감소**(최소한 `worst_mdd`가 계산되고 하방이 줄어드는 방향).

### 5) **과최적화(특히 폴드/하이퍼) 억제: “안 움직이는 개선”은 대부분 안정성 문제다**
- (a) 왜 필요한지  
  - oos_mean이 좋아도 degenerate fold/특정 구간 편중이면 실전에서 재현 불가.  
  - 48시간 루프는 “조금씩 나아지는 척” 하는 과최적화를 만들기 쉬움.
- (b) 위험/부작용  
  - 제약을 걸면 단기 성능이 낮아 보일 수 있음(대신 지속가능성↑).  
  - 탐색공간 축소로 “진짜 개선”도 늦게 발견될 수 있음.
- (c) 최소 실험  
  - **[E1] Purge/Embargo + Walk-forward 고정**으로 검증을 더 보수적으로  
  - **[E4] 챔피언 승급 게이트를 메트릭+안정성(분산/턴오버/노출)로 묶어 자동화**
- (d) PASS 조건  
  - 폴드별 성능 편차 감소(최소치 oos_min 개선 또는 min/mean 괴리 축소).  
  - 승급 규칙을 만족하는 런만 챔피언이 되며, 승급 후에도 재실행/재학습에서 메트릭이 크게 흔들리지 않음.

## 48시간 자동 루프용 “공용 패치/실험” 4개 (TOP5 전부를 이 4개로 커버)

### [E1] **Leakage/Overfit 방지 패치**
1) **실험 정의(Implement)**  
   - 모든 피처/라벨 생성에 대해 `t` 시점에서 **t 이후 데이터 접근 금지**(shift/merge_asof 강제).  
   - CV를 **Purged K-Fold + Embargo**로 교체(리밸런스 주기만큼 embargo).  
   - Walk-forward 고정(훈련창/검증창을 시간 순으로 고정) + seed 고정.
2) **게이트(Gate)**  
   - 누수 탐지 테스트(미래 timestamp 조인/forward-fill/리밸런스 직후 체결가 참조)를 **단위테스트로 강제**.  
   - 폴드 중 하나라도 degenerate(표본 0, 동일날짜 중복, lookahead 의심)면 런 FAIL.
3) **기대 관측치(Expected)**  
   - 누수가 있었다면 OOS 성능이 하락하고 대신 폴드 안정성/재현성이 증가.  
   - 노이즈 피처 제거 시 oos_min이 개선되거나 극단값이 줄어듦.

---

### [E2] **비용/슬리피지/턴오버 모델 패치**
1) **실험 정의**  
   - 거래비용 = (고정 수수료/주 + bid-ask half-spread + 충격함수)로 단순 모델부터 적용.  
   - 비용 파라미터를 3점 스윕(낙관/중간/보수)하고 결과를 동일 리포트에 저장.  
   - 턴오버 캡(일/주 단위) + 포지션 변화율 제한(Δw cap) 추가.
2) **게이트**  
   - 비용 포함 성과가 무비용 대비 **비정상적으로 거의 동일**하면(차이 < 임계치) 비용이 실제로 적용 안 된 것으로 간주하고 FAIL.  
   - 연환산 턴오버가 상한 초과 시 FAIL.
3) **기대 관측치**  
   - 무비용 대비 성능 하락(정상) + 대신 전략 간 “현실적 순위”가 바뀜.  
   - 턴오버 캡으로 슬리피지 민감도가 낮아짐.

---

### [E3] **ETF 관측 기반 레짐 게이트(매매 금지) + 노출 제어 패치**
1) **실험 정의**  
   - 관측지표: QQQ(테크), XLV(헬스케어), SPY(시장)로 **risk-on/off 스코어** 산출(예: 추세/변동성/드로다운 기반).  
   - risk-off면 목표 노출을 0~20%로 낮추거나 “현금 유지”(단, ETF 매매 없음).  
   - risk-on이면 기존 시그널 정상 작동.
2) **게이트**  
   - 노출 분포가 여전히 0.4 이상에 갇히면(저노출 구간 부재) FAIL.  
   - 게이트가 지나치게 잦아 거래비용/턴오버가 오히려 증가하면 FAIL.
3) **기대 관측치**  
   - 하락 레짐에서 MDD 감소(특히 `worst_mdd`가 유의미하게 개선).  
   - 거래 빈도 감소로 비용 민감도 완화.

---

### [E4] **서바이버십/데이터 무결성 + 운영 리스크(아티팩트/리포팅) 패치**
1) **실험 정의**  
   - corporate action(스플릿/역스플릿) 구간 가격/수익률 점프 탐지 후 자동 조정/제외 규칙 적용.  
   - 상폐/거래정지/결측 처리 룰을 명시(예: 결측 n일 초과 시 포지션 0으로).  
   - `file`, 설정 JSON, 데이터 스냅샷 해시, 메트릭(`worst_mdd` 포함) 저장을 **필수**로 하고 누락 시 런 FAIL.
2) **게이트**  
   - 데이터 품질 테스트 실패(결측률/점프/중복 timestamp/비단조 인덱스) 시 즉시 FAIL.  
   - 아티팩트 미저장/메트릭 None 발생 시 FAIL.
3) **기대 관측치**  
   - 결과 재현성↑(동일 run_hash면 동일 출력).  
   - “좋아 보이던” 특정 구간 성과가 정상화(서바이버십/데이터 오류 제거).

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **순서대로 고정 로그/리포트**로 남겨서, 어디서 막히는지 한 번에 쪼개라.

1) **Trigger(시그널 생성) 문제인지**
- 신호의 예측력 자체:  
  - (A) 시그널-미래수익률 IC/RankIC (기간별)  
  - (B) 히트레이트(방향 적중) vs payoff(손익비) 분리  
- 증상 패턴: IC는 있는데 수익이 없음 → 적용/비용/노출 문제 가능성 큼.

2) **Apply(체결/리밸런스/포트 구성) 문제인지**
- “신호가 포지션으로 제대로 반영되는지” 체크:  
  - 목표가중치 w* vs 실제가중치 w의 괴리(슬리피지/캡/라운딩)  
  - 리밸런스 타이밍(종가 신호면 다음날 시가 체결 등) 일관성  
- 증상: 신호는 좋지만 w가 거의 변하지 않음 → 턴오버 캡/게이트/버그 의심.

3) **Exposure(시장 베타/섹터 베타) 문제인지**
- 노출 분해:  
  - SPY/QQQ/XLV에 대한 회귀 베타, 순노출/총노출, 현금비중  
- 증상: 성과 변동이 대부분 QQQ 방향과 동일 → 종목 선택 알파가 아니라 베타 장사.

4) **Cost(거래비용) 문제인지**
- 비용 기여도 분해:  
  - 총 PnL = 그로스 PnL – (스프레드+충격+수수료)  
  - 거래당 평균 비용, 비용/수익 비율, 턴오버 구간별 성과
- 증상: 그로스는 괜찮은데 넷이 죽음 → 리밸런스 빈도/캡/종목 유동성 재설계.

5) **Regime(국면) 문제인지**
- 레짐별 성과 테이블:  
  - (A) QQQ 추세 상/하, (B) 변동성 상/하, (C) 시장 드로다운 구간  
- 증상: 특정 레짐에서만 수익 → 게이트/노출 스케일링이 해법.

---

## 실행 순서(24~48h) — 강제 진행 플로우
1) **E4 먼저 적용**: `worst_mdd None`, `file` 누락 같은 “평가/운영 결손”을 0으로 만들어라.  
2) **E1 적용**: Purge/Embargo + time alignment 테스트로 누수 가능성을 닫아라.  
3) **E2 적용**: 비용/슬리피지/턴오버를 넷 성과로 강제하고, 비용이 적용 안 되면 FAIL 처리하라.  
4) **E3 적용**: ETF 관측 레짐 게이트로 노출 박스권(0.47~0.84)을 깨고, MDD 감소 여부를 확인하라.  

이 4개만 48시간 루프로 돌려도, “성능이 진짜인지/어디서 새는지/왜 안 오르는지”가 대부분 분해된다.
