### 1) 향후 48시간 우선순위 TOP 3 제안 (실행 가능한 Patch)

#### **Proposal A. 로깅 파이프라인 긴급 복구 및 강제 구조화**
*   **이유**: 현재 `rebalance_pinpoint`가 실패하여 전략의 의사결정 과정을 볼 수 없음. 블랙박스 상태에서의 튜닝은 도박임.
*   **위험**: 로깅 오버헤드로 인한 백테스트 속도 저하(미미함).
*   **실험 정의**:
    1.  **[Patch 1] JSONL Enforce**: 리밸런싱 로그를 `csv`가 아닌 `jsonl`(Line-delimited JSON)로 강제 저장. Trade Decision, Target Weight, Current Price, Signal Score 포함.
    2.  **[Patch 2] Path Validation**: 로그 저장 경로가 없을 경우 `mkdir -p` 수행 로직 추가.
*   **GATE (Pass 조건)**:
    - 백테스트 완료 후 `rebalance.jsonl` 파일 용량이 1KB 이상일 것.
    - `aub_rebalance_pinpoint.py`가 에러 없이 파싱 완료할 것.
*   **기대 관측치**: Degenerate Fold 구간에서 로그가 'Empty'인지, 'Constraint Violation'인지 확인 가능.

#### **Proposal B. 변동성 스케일링 하한선(Clamping) 설정 (Degeneracy 해결)**
*   **이유**: Degenerate Folds(1,2,3,8)의 주원인은 특정 구간의 낮은 변동성으로 인한 레버리지 폭발(Inf/NaN) 혹은 높은 변동성으로 인한 포지션 0 수렴임.
*   **위험**: 저변동성 구간에서 수익 기회 감소.
*   **실험 정의**:
    1.  **[Exp 1] Vol-Floor**: 변동성 역가중(Inverse Volatility) 계산 시, 변동성(std)의 최솟값을 `max(current_vol, 0.01)`로 강제(Clamp).
    2.  **[Exp 2] Max-Leverage Cap**: 개별 종목 가중치 상한을 `0.20` -> `0.15`로 축소, 전체 레버리지 `1.0` 초과 금지.
    3.  **[Exp 3] Fallback Logic**: 최적화 실패(Solver Error) 시, `Equal Weight` 또는 `Previous Portfolio` 유지 로직 삽입.
*   **GATE (Pass 조건)**:
    - `degenerate_folds` 리스트가 빈 배열(`[]`)이 되거나 개수가 1개 이하로 감소.
    - `oos_mean`이 2.5 이하로 떨어지더라도 `oos_min`이 -0.05 이상으로 방어될 것.
*   **기대 관측치**: 폴드 1,2,3,8이 정상적인 수익 곡선을 그리며 복구됨.

#### **Proposal C. 비용 스트레스 테스트 (과최적화 필터링)**
*   **이유**: `oos_mean: 3.32`는 Tech/Bio 섹터의 고변동성을 고려해도 비정상적으로 높음. 슬리피지/수수료 과소평가 가능성.
*   **위험**: 현재 챔피언 모델 폐기 가능성(Mental Stop).
*   **실험 정의**:
    1.  **[Exp 1] Cost x2**: 거래 수수료(bps)와 슬리피지를 현재 설정의 2배로 적용.
    2.  **[Exp 2] Liquidity Filter**: 일일 거래대금 하위 20% 종목 강제 제외(유동성 부족 종목의 틱 튀기기 방지).
*   **GATE (Pass 조건)**:
    - Cost x2 적용 후에도 `oos_mean` > 1.5 유지.
    - `turnover`(회전율)이 20% 이상 급감하지 않을 것(비용 때문에 거래를 포기하는지 확인).
*   **기대 관측치**: 수익률은 하락하겠으나, 우상향 추세가 유지되어야 함. 급락 시 현재 전략은 '노이즈 마이닝'임.

### 2) 성능 정체 시 원인 분해 (Debug Tree)

성능 지표가 움직이지 않거나(No-Delta), 개선되지 않을 때 다음 순서로 점검하십시오.

1.  **Trigger (신호 발생 여부)**
    *   *체크*: 지표(RSI, MA, Alpha Model) 값이 `Threshold`를 넘었는가?
    *   *액션*: Threshold를 극단적으로 낮춰(예: RSI < 90) 강제 매매 유발 실험.

2.  **Application (주문 생성 여부)**
    *   *체크*: 신호는 떴는데 `Target Weight`가 0인가?
    *   *원인*: 리스크 관리 모듈(변동성 할당)이나 현금 비중(Cash Buffer) 로직이 신호를 상쇄 중.
    *   *액션*: `Allow_Short=False`인 경우, Long 신호만 발생하는지 확인.

3.  **Exposure (체결/노출 여부)**
    *   *체크*: 주문은 나갔는데 잔고가 그대로인가?
    *   *원인*: 
        - **유동성 필터**: 설정된 `min_volume` 미달.
        - **개장일 데이터 누락**: 미국 휴장일 처리 로직 오류.
    *   *액션*: 유동성 필터를 `0`으로 설정 후 백테스트.

4.  **Cost (비용 잠식)**
    *   *체크*: Gross Return은 좋은데 Net Return이 0인가?
    *   *원인*: 잦은 리밸런싱. Tech/Bio는 변동성이 커서 잦은 손절매(Whipsaw) 발생 가능.
    *   *액션*: 리밸런싱 주기를 주간(Weekly) -> 월간(Monthly)로 변경 혹은 `BufferZone`(목표 비중 ±5% 내 유지) 도입.

5.  **Regime (시장 국면)**
    *   *체크*: ETF(QQQ/XLV) 지표가 'Bear'로 인식되어 현금 보유만 하는가?
    *   *액션*: ETF 기반 `Market Regime Filter`를 끄고(Bypass) 전략만으로 돌려볼 것.
