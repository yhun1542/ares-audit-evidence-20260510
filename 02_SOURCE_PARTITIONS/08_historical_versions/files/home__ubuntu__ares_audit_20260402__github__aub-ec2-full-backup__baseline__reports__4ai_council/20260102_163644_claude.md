### PRIORITY 2: Degenerate Fold 원인 분해
```
WHY: 4/10 fold 실패 = 신호 자체가 없거나 threshold 과잉 → OOS 일반화 불가능
```

**체크리스트:**
- [ ] 각 fold별 신호 생성 횟수 카운트
- [ ] Fold 1,2,3,8의 공통점 파악 (기간? 레짐? 섹터 부재?)
- [ ] Threshold/filter 조건 중 어디서 신호 소멸하는지 추적

**실험:**
| ID | 정의 | 게이트 | 기대 관측치 |
|----|------|--------|-------------|
| P2-A | `--debug-signals` 플래그로 fold별 raw 신호 수 출력 | 모든 fold > 10 signals | 1,2,3,8에서 0이면 데이터 문제 |
| P2-B | Threshold 50% 완화 (0.7→0.35) 후 재실행 | degenerate fold ≤ 1 | 과필터링 확인 |
| P2-C | Fold 1,2,3,8 기간의 시장 레짐 태깅 | 레짐 클러스터 확인 | 특정 레짐에서만 실패 시 레짐 필터 추가 |

## 2. 성능 불변 시 원인 분해 트리

```
OOS Mean 변화 없음
│
├─ [트리거] 신호 자체가 안 바뀜?
│   └─ 확인: 실험 전후 signal_count 비교
│
├─ [적용] 신호는 바뀌었는데 포지션 안 바뀜?
│   └─ 확인: rebalance 횟수/규모 비교
│
├─ [노출] 포지션 바뀌었는데 exposure 동일?
│   └─ 확인: avg_exposure 비교
│
├─ [비용] 수익은 바뀌었는데 비용이 상쇄?
│   └─ 확인: gross_return vs net_return 차이
│
└─ [레짐] 특정 기간에만 효과 있고 평균 희석?
    └─ 확인: fold별 수익 분포 (std 확인)
```
