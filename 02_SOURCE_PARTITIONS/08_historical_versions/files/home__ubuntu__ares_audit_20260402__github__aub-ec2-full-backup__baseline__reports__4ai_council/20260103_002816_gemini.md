### 1. Metric Validity & Cost Injection (MDD=None 해결)
*   **(a) 필요성:** `worst_mdd: None`과 `oos_mean: 3.32`는 비정상적. 리스크 계산 모듈이 작동하지 않거나, 비용(Slippage/Commission)이 0으로 설정되어 수익률이 과대평가(Overfitting/Look-ahead)되었을 가능성 99%. 즉시 현실화 필요.
*   **(b) 위험/부작용:** 수익률(OOS Mean)이 급락할 수 있음. 그러나 이는 '성능 하락'이 아니라 '진실 확인'임.
*   **(c) 실험 (Experiments):**
    1.  `FIX_MDD_CALC`: MDD 계산 로직 강제 디버깅 (Drawdown Array가 비어있는지 확인).
    2.  `COST_INJECT_10BPS`: 매매당 거래비용 10bps + 슬리피지 모델 적용.
    3.  `MIN_CASH_BUFFER`: 현금 비중 최소 5% 강제 (Full Invest 방지).
*   **(d) PASS 조건:** `worst_mdd` != None AND `oos_mean` > 1.5 (비용 반영 후에도 생존).

### 2. Degenerate Folds (1, 2, 3, 8) 안정화
*   **(a) 필요성:** 10개 내외의 Fold 중 4개가 실패(Degenerate)했다는 것은 특정 시기(하락장 혹은 횡보장)에 **거래가 아예 없거나(Zero Trades)** 로직이 터졌음을 의미. 생존 편향(Survivorship Bias)의 전형적인 징후.
*   **(b) 위험/부작용:** 필터를 완화하면 '쓰레기 주식'이 포트폴리오에 편입될 리스크 증가.
*   **(c) 실험 (Experiments):**
    1.  `RELAX_LIQUIDITY`: 거래대금/시가총액 하위 필터 20% 완화.
    2.  `FORCE_MIN_TRADES`: 특정 기간 내 거래가 0이면 강제로 2순위 시그널 매수 로직 추가.
    3.  `EXPAND_UNIVERSE_TEMP`: 해당 Fold 기간에만 Universe를 Tech/Health 외 대형주로 일시 확장하여 데이터 부재 확인.
*   **(d) PASS 조건:** Degenerate Folds 개수 < 2.

### 3. Rebalance Log Logging Pipeline 복구
*   **(a) 필요성:** `Error loading --base-log` 발생. 왜 매수/매도했는지(Why)에 대한 로그가 없으면 튜닝 불가. Blind Optimization 상태.
*   **(b) 위험/부작용:** I/O 오버헤드 약간 증가 (무시 가능 수준).
*   **(c) 실험 (Experiments):**
    1.  `LOG_FORMAT_FIX`: JSONL 형식을 강제하고 경로를 절대 경로로 고정.
    2.  `VERBOSE_REBALANCE`: 리밸런싱 시점의 Target Weight와 실제 Order 간의 차이(Delta) 기록.
*   **(d) PASS 조건:** `aub_rebalance_pinpoint.py` 실행 시 에러 없이 Report 생성.

### 4. Tech+Healthcare Concentration (Universe 정제)
*   **(a) 필요성:** 현재 `exposure_max: 0.83`. 남은 현금이 비효율적임. Tech/Health 섹터의 모멘텀을 확실히 타기 위해 8~14개 종목으로 압축 필요.
*   **(b) 위험/부작용:** 분산 효과 감소로 MDD 증가 가능성.
*   **(c) 실험 (Experiments):**
    1.  `SECTOR_FILTER_STRICT`: XLK(Tech), XLV(Health) 구성 종목 중 시총 상위 30개로 유니버스 제한.
    2.  `ALLOCATION_BOOST`: 종목당 최대 비중을 10% -> 15%로 상향 (종목 수 8~10개 타겟).
*   **(d) PASS 조건:** Exposure Max > 0.95 AND Sharpe Ratio 유지/상승.

### 5. Execution Lag & Look-ahead Check
*   **(a) 필요성:** `oos_min`이 -0.02로 지나치게 방어적임. 미래 데이터를 참조(Look-ahead)하여 하락을 완벽히 피했거나, 장 마감 후 데이터로 시초가 매매를 하는 오류 가능성.
*   **(b) 위험/부작용:** 시뮬레이션 성능 대폭 하락 가능.
*   **(c) 실험 (Experiments):**
    1.  `EXECUTION_DELAY`: 시그널 발생 다음 날 Open이 아닌 Close 혹은 VWAP으로 체결 가격 변경.
    2.  `SIGNAL_SHIFT`: 입력 데이터(Feature)를 1일 강제 Shift하여 미래 참조 원천 차단.
*   **(d) PASS 조건:** `oos_mean` 급락 폭이 30% 이내일 것 (로직의 견고함 증명).
