### 1. [CRITICAL] 매매 로그 파이프라인 복구
*   **(a) 이유:** `aub_rebalance_pinpoint` 실행 실패(FileNotFound/JSON Error) 확인. 실제 체결 내역과 시뮬레이션 간 괴리(Slippage/Cost)를 추적 불가능한 상태. 운영 리스크 최상.
*   **(b) 위험:** 로그 포맷 변경 시 백테스트 엔진과 호환성 깨질 우려.
*   **(c) 실험 (48h Loop):**
    1.  **[Fix_Log_Format]**: `rebalance.csv`를 `jsonl` 포맷으로 통일하고, 누락된 `execution_price`, `slippage_cost` 필드 강제 기록.
    2.  **[Dry_Run_Verify]**: 모의 매매 1회 실행 후 파서(Parser)가 에러 없이 로드하는지 단위 테스트.
    3.  **[Sync_Check]**: 백테스트 상의 `target_weight`와 실제 `executed_weight` 차이(Delta)가 0.01% 미만인지 검증.
*   **(d) PASS 조건:** `aub_rebalance_pinpoint`가 에러 없이 리포트를 생성하고, Delta > 0.5%인 건이 0건일 것.

### 2. 변동성 기반 노출도(Exposure) 최적화
*   **(a) 이유:** 현재 Exposure Min 0.47 / Max 0.84는 강세장(2026 Context)에서 기회비용 발생, 약세장에서 방어력 부족 가능성. Tech/Health는 변동성이 크므로 VIX나 섹터 IV(Implied Volatility)에 연동 필요.
*   **(b) 위험:** 과최적화(Overfitting)로 인한 휩소(Whipsaw) 손실.
*   **(c) 실험 (48h Loop):**
    1.  **[Exp_Inv_Vol]**: 최근 20일 섹터 변동성 역가중(Inverse Volatility)으로 총 노출도(0.3~1.0) 결정.
    2.  **[Exp_Regime_Step]**: VIX < 20이면 Max 0.95, 20 < VIX < 30이면 0.7, VIX > 30이면 0.4로 계단식 적용.
    3.  **[Exp_Floor_Lift]**: 최소 노출도를 0.47 -> 0.60으로 상향 조정 (상승장 바이어스).
*   **(d) PASS 조건:** OOS Sharpe 비율 유지 하에 MDD 5% 이상 개선 or 수익률 10% 이상 증가.

### 3. 거래 비용 절감을 위한 'Lazy Trading'
*   **(a) 이유:** 잦은 리밸런싱은 슬리피지와 수수료 누적으로 성능 정체(Stagnation)의 주원인. Tech 종목 특성상 변동성이 커 불필요한 트레이딩 발생 가능성 높음.
*   **(b) 위험:** 포트폴리오 드리프트(Drift)로 인해 리스크 한도 초과 가능성.
*   **(c) 실험 (48h Loop):**
    1.  **[Buffer_02]**: 목표 비중과 현재 비중 차이가 2%(`0.02`) 미만이면 리밸런싱 스킵.
    2.  **[Hold_Winner]**: 수익 구간(Profit > 5%)인 종목은 매도 시그널 강도를 0.8배로 낮춤 (Momentum 유지).
    3.  **[Turnover_Cap]**: 일일 최대 회전율(Turnover)을 10%로 제한.
*   **(d) PASS 조건:** 연간 회전율 20% 이상 감소하면서 OOS Mean 하락폭 2% 미만 방어.

### 4. 섹터 상관관계 하드 캡 (Tech vs Healthcare)
*   **(a) 이유:** Tech와 Healthcare가 동시에 무너지는 'Risk-off' 구간 방어. 현재 포트폴리오(8~14종목) 내 종목 간 공분산이 높으면 분산 효과 없음.
*   **(b) 위험:** 유효한 종목을 강제로 제외하여 알파 기회 상실.
*   **(c) 실험 (48h Loop):**
    1.  **[Corr_Filter]**: 포트폴리오 내 평균 상관계수 > 0.7인 종목 조합 발견 시, 변동성 높은 종목 제외.
    2.  **[Sector_Balance]**: Tech:Health 비중을 최소 4:6 ~ 6:4 범위로 강제.
    3.  **[Beta_Hedge]**: 포트폴리오 베타가 1.2 초과 시, Beta가 낮은 Healthcare 종목 비중 확대.
*   **(d) PASS 조건:** 최악의 달(Worst Month) 수익률 개선 및 OOS Min > 0.5 달성.

### 5. 슬리피지 페널티 강화 스트레스 테스트
*   **(a) 이유:** 백테스트 성능(1.88)과 실제(진입 전) 간의 괴리를 좁히기 위함. Tech 소형주는 호가 갭으로 예상보다 비용이 클 수 있음.
*   **(b) 위험:** 지나친 보수적 설정으로 인해 실제 수익 가능한 시그널까지 폐기.
*   **(c) 실험 (48h Loop):**
    1.  **[Cost_Double]**: 슬리피지 설정을 현재의 2배(예: 5bps -> 10bps)로 적용 후 생존하는 로직만 선별.
    2.  **[Liquidity_Cut]**: 일평균 거래대금 하위 20% 종목 매매 시 페널티 3배 적용.
    3.  **[Entry_Delay]**: 시그널 발생 후 '다음 날 시가(Open)'가 아닌 '다음 날 VWAP' 체결 가정.
*   **(d) PASS 조건:** 강화된 비용 구조에서도 OOS Sharpe > 1.5 유지.

### [성능 정체(Flat) 원인 분해 아이디어]

성능 지표가 움직이지 않을 때, 다음 순서로 디버깅을 수행하라.

1.  **트리거(Trigger) 확인:**
    *   *가설:* 시장 변동성이 낮아 시그널 임계값(Threshold)을 넘는 종목이 없음.
    *   *진단:* 시그널 생성 단계에서 `raw_score`의 분포(Histogram) 확인. 0 근처에 몰려있다면 Feature Scaling 재점검.

2.  **적용(Execution) 확인:**
    *   *가설:* 시그널은 발생했으나, 리스크 관리 모듈(Exposure limit, Position limit)이 주문을 차단함.
    *   *진단:* `target_weight`가 0이 아닌데 `order_size`가 0인 케이스 필터링.

3.  **노출(Exposure) 확인:**
    *   *가설:* 현금 비중이 너무 높아(Low Exposure) 알파가 희석됨.
    *   *진단:* 일별 현금 비중 시계열 플롯 확인. 지속적으로 50% 이상이면 공격적 사이징(Sizing) 필요.

4.  **비용(Cost) 확인:**
    *   *가설:* 잦은 매매로 인한 비용이 수익을 정확히 상쇄 중(Burn Rate).
    *   *진단:* `Gross Return` vs `Net Return` 차트 비교. 갭이 벌어지는 기울기 확인.

5.  **레짐(Regime) 불일치:**
    *   *가설:* 현재 전략(예: 모멘텀)이 현재 시장(예: 횡보장)과 맞지 않음.
    *   *진단:* 벤치마크(QQQ/XLV) 대비 상대 수익률(Relative Strength)이 0에 수렴하는지 확인.
