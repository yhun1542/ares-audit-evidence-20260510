## 24~48시간 우선순위 TOP5 (명령형 체크리스트)

### 1) **누수(Leakage) / 시점정렬(Time alignment) / CV 오염(purge/embargo) 최우선 하드닝**
- (a) 왜 필요한지  
  - 현재 후보들이 lockbox에서 잘 나오더라도 **시점 누수/폴드 간 정보누설**이 있으면 “가짜 개선”이 발생하고, 48시간 루프에서 재현성이 무너짐.
- (b) 위험/부작용  
  - 성능이 단기적으로 하락(“진짜 성능”만 남음). 실행 시간이 증가.
- (c) 최소 실험(아래 E1 재사용) 2~3개  
  - E1-a: 모든 feature/label **t-1 강제 시프트 + 어서션**(future timestamp 탐지 시 fail-fast)  
  - E1-b: **purged k-fold + embargo**(이벤트/리밸런스 윈도우 겹침 제거)  
  - E1-c: 데이터 파이프라인에 **“asof join only”** 강제(리포팅 날짜/공시 날짜 분리)
- (d) PASS 조건(게이트)  
  - **누수 탐지 0건**, fold별 metric 분포가 급격히 비정상(특정 fold만 과대)인 현상 완화  
  - lockbox_mean이 **Champion 대비 -3% 이내** 유지 + worst_mdd 악화 없음(±0.5%p 이내)

---

### 2) **비용 미반영(거래비용/슬리피지/임팩트) + 과최적화(턴오버) 억제**
- (a) 왜 필요한지  
  - Tech/Healthcare 8~14종목 집중이면 회전율이 커지기 쉽고, 비용이 빠지면 **튜닝 성능만 상승**하는 패턴이 흔함.
- (b) 위험/부작용  
  - “좋아 보이던” 전략이 비용 반영 후 무너질 수 있음. 지나친 패널티로 기회 손실.
- (c) 최소 실험(아래 E2 재사용) 2~3개  
  - E2-a: 거래비용 모델 3단(낮음/기준/높음) 스윕(고정 커미션 + half-spread + 간단 임팩트)  
  - E2-b: 목적함수에 **turnover penalty**(또는 rebalancing threshold) 추가  
  - E2-c: 슬리피지 민감도: 리밸런스 시점(종가/익일 시가 가정) 2안 비교
- (d) PASS 조건  
  - 기준 비용에서 lockbox_mean이 Champion 대비 **+2% 이상** 또는 worst_mdd가 **0.5%p 이상 개선**  
  - “높은 비용” 시나리오에서 lockbox_mean **0 이하로 붕괴하지 않음**(전략 생존성 게이트)

---

### 3) **서바이버십/기업행동(스플릿/상폐/인수) 처리 + Point-in-time 유니버스 고정**
- (a) 왜 필요한지  
  - US 개별주에서 가장 흔한 함정이 **상폐 수익률 누락, 분할/배당 조정 오류, 후행 유니버스**로 인한 서바이버십 바이어스.
- (b) 위험/부작용  
  - 데이터 소스/정합성 이슈가 드러나며 성능이 하락할 수 있음(하지만 “정답에 가까워짐”).
- (c) 최소 실험(아래 E3 재사용) 2~3개  
  - E3-a: **delisting return**(상폐/인수/거래정지 처리) 반영 체크 및 누락 시 fail  
  - E3-b: **split/dividend adjusted vs raw** 이중계산 후 수익률 갭 감시(허용오차 초과 시 경고/차단)  
  - E3-c: 8~14 종목 **Tech+Healthcare only** 유니버스를 “당시점 기준(point-in-time)”으로 고정(리밸런스 시점에만 편입/편출)
- (d) PASS 조건  
  - 데이터 무결성 체크 모두 통과(상폐/분할/배당)  
  - lockbox_min이 **비정상적으로 좋아지거나 나빠지는 단일 이벤트**(특정 티커/구간) 원인이 제거되어 분포가 안정화  
  - worst_mdd 악화 없음(±0.5%p 이내)

---

### 4) **운영 리스크(실행/리밸런싱/데이터 지연) + 실패 안전장치(중지/감액)**
- (a) 왜 필요한지  
  - 48시간 자동 루프는 “백테스트 성능”보다 **운영 실패(데이터 결측, 주문 실패, 급등락, 거래정지)**가 더 자주 문제를 만듦.
- (b) 위험/부작용  
  - 보수적 안전장치로 수익이 줄 수 있음. 로직 복잡도 증가.
- (c) 최소 실험(아래 E4 일부 재사용) 2~3개  
  - E4-a: 데이터 결측/지연 시 **hold/flat** 규칙과 알람(실패 시 포지션 변경 금지)  
  - E4-b: 주문 가능성 체크(거래정지/가격 0/스프레드 급확대) 시 **리스크 감액**  
  - E4-c: 리밸런스 빈도/시간 고정(예: 익일 시가 체결 가정) + 재현성 로그
- (d) PASS 조건  
  - “결측/지연/거래정지” 시뮬레이션에서 **크래시 없이 종료**, 포지션 규칙 위반 0건  
  - 비용/슬리피지 민감도에서 성능 급락(knife-edge) 완화

---

### 5) **레짐(Regime) 리스크: ETF는 ‘관측지표’로만 사용해 노출을 조절**
- (a) 왜 필요한지  
  - Tech/Healthcare 집중은 특정 레짐(금리 급등, 리스크오프)에서 동반 하락이 큼.  
  - ETF(예: QQQ/XLK/XLV/VIX proxy)는 매매하지 않고도 **환경지표**로 유효.
- (b) 위험/부작용  
  - 레짐 필터가 과최적화되면 기회 손실/신호 지연 발생.
- (c) 최소 실험(아래 E4 재사용) 2~3개  
  - E4-d: QQQ/XLK/XLV 모멘텀·변동성 지표로 **노출 스케일링(0~100%)**만 수행(ETF 거래 금지)  
  - E4-e: 레짐 게이트는 단순 규칙 1~2개만(예: 20d 추세 음수 & 변동성 상위 분위면 50% 감액)
- (d) PASS 조건  
  - worst_mdd가 **0.5%p 이상 개선** 또는 fold14_mdd 개선 유지  
  - lockbox_mean이 Champion 대비 **-2% 이내**로 유지(방어 개선이 목적)

## 실행 가능한 Patch/실험(총 4개로 제한) — 48시간 자동 루프 형태
아래 4개(E1~E4)만 “유일한 실험”으로 생성하고, TOP5 요구사항을 이 안에 매핑해 과폭발을 방지.

### E1) Leakage Hardening Pack
1) **실험 정의**
   - 모든 피처/라벨 생성부에 `t-1` 시프트 강제, future timestamp 검출 어서션 추가
   - purged CV + embargo 적용(리밸런스/이벤트 윈도우 겹침 제거)
2) **게이트**
   - 누수/정렬 어서션 0건
   - lockbox_mean ≥ Champion * 0.97, worst_mdd 악화 ≤ 0.5%p
3) **기대 관측치**
   - tuning 대비 lockbox 과대갭 감소  
   - fold별 성능 분산 감소(특정 fold만 과대 성능 패턴 완화)

---

### E2) Cost & Turnover Realism Pack
1) **실험 정의**
   - 비용모델 3단 스윕(낮음/기준/높음): commission + half-spread + 단순 임팩트
   - turnover penalty 또는 rebal threshold 도입(“미세 신호로 잦은 매매” 억제)
2) **게이트**
   - 기준 비용에서 lockbox_mean ≥ Champion * 1.02 **또는** worst_mdd 0.5%p 개선
   - 높은 비용에서도 lockbox_mean이 0 이하로 붕괴 금지
3) **기대 관측치**
   - 회전율 하락, 성능-비용 민감도 완화  
   - “튜닝만 상승/락박스 정체” 패턴 감소

---

### E3) Survivorship & Corporate Actions Integrity Pack
1) **실험 정의**
   - delisting return 포함 여부 검증(누락 시 실험 실패)
   - split/dividend adjusted vs raw 갭 모니터링
   - 유니버스 point-in-time 고정(Tech+Healthcare 8~14 유지)
2) **게이트**
   - 무결성 체크 전부 통과(상폐/분할/배당)
   - worst_mdd 악화 ≤ 0.5%p, lockbox_min 급변 이벤트 원인 제거
3) **기대 관측치**
   - 특정 티커/기간의 비정상 기여 제거  
   - 성능이 “덜 좋아 보여도” 재현성과 신뢰도 상승

---

### E4) Exposure + Ops + Regime Gate Pack (ETF는 관측만)
1) **실험 정의**
   - 단일 종목 최대비중/일일 거래량 기반 포지션 상한, 결측 시 hold 규칙
   - QQQ/XLK/XLV 기반 간단 레짐 신호로 **노출 스케일링만**(ETF 거래 금지)
2) **게이트**
   - 운영 시뮬(결측/거래정지/스프레드 급확대)에서 규칙 위반 0건
   - worst_mdd 0.5%p 개선 또는 lockbox_mean -2% 이내 유지
3) **기대 관측치**
   - tail 구간 손실 축소(특히 tech risk-off)  
   - 운영 실패로 인한 “실전 불가능” 케이스 제거

---

## 24~48시간 명령형 실행 순서(루프 친화)
1) `E1 → E3` 순으로 먼저 돌려 **데이터/누수 리스크를 선제 제거**  
2) 그 다음 `E2`로 비용/턴오버를 현실화  
3) 마지막으로 `E4`로 운영/노출/레짐 방어 추가  
4) 각 단계마다 `--select-best`가 “성능”이 아니라 **게이트 통과**를 우선하도록 점수함수(패널티) 반영

---

## 성능이 안 움직일 때: 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래는 “질문 없이” 바로 로그/리포트에 추가할 분해 관측치 목록.

### A) Trigger(신호 발생) 문제
- 신호 발생 빈도(일/주당)와 분포(상위/하위 분위) 추적: **너무 드물거나 너무 잦으면** 정체
- 피처 중요도/기여도가 특정 피처 1~2개에 쏠리는지: 과최적화 신호

### B) Apply(체결/반영) 문제
- 신호→포지션 반영 지연(오늘 신호가 언제 체결 가정인지) 변경 시 성능 민감도 측정
- 리밸런스 룰(임계값, 최소 주문 단위)로 인해 **실제로 포지션이 거의 안 바뀌는지** 확인

### C) Exposure(노출) 문제
- 8~14 종목 내에서 단일 종목 기여도(top contributor)와 손실 기여도(worst detractor) 분해  
- 요인 노출(간이): 시장베타, 금리 민감(대형 성장주 비중), 변동성 노출  
- 상관이 급등하는 구간(리스크오프)에서 포트 분산이 실질적으로 사라지는지 확인

### D) Cost(비용/마찰) 문제
- 회전율(일/월), 거래대금 대비 포지션 크기, 스프레드 프록시로 **비용 탄력성 곡선** 생성  
- “비용 0일 때만 개선”이면 신호가 얇다는 뜻 → turnover penalty/threshold가 정답

### E) Regime(국면) 문제
- ETF(관측지표) 기반으로 국면을 2~3개로만 나눠 성능 테이블 작성:  
  - 예: QQQ 추세(+/-) × 변동성(상/하)  
- 성능이 특정 레짐에서만 나오면: 레짐별 노출 스케일링(E4)로 “살아남는” 전략으로 변환

---

원칙적으로 **E1/E3(신뢰성) → E2(현실 비용) → E4(운영+방어)** 순서로 게이트를 통과시키면, lockbox가 “정체”하더라도 원인이 (누수/비용/레짐/노출) 중 어디인지 자동으로 분해되는 형태로 48시간 루프를 안정화할 수 있음.
