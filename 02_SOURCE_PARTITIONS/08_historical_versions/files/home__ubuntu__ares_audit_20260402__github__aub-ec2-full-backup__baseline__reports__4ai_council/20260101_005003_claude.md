## 1. 우선순위 TOP 5 패치/실험

---

### PATCH-1: 포지션 사이즈 스케일링 로직 검증 (노출 누수 점검)

#### (a) 왜 필요한가
- lockbox 0.006% 차이 = 시그널이 있어도 **실제 포지션에 반영 안 됨** 의심
- `position_sizer` 모듈에서 min_weight floor나 max_concentration cap이 변경을 흡수했을 가능성

#### (b) 위험/부작용
- 사이저 로직 수정 시 기존 리스크 한도 이탈 가능
- 과거 폴드 재현성 깨질 수 있음 (버저닝 필수)

#### (c) 최소 실험
| ID | 정의 | 게이트 | 기대 관측치 |
|----|------|--------|-------------|
| P1-A | `position_sizer.py`에 debug_log 삽입 → 시그널 → 최종 weight 매핑 덤프 | 로그 생성 | 시그널 변화 vs weight 변화 상관 >0.5 |
| P1-B | min_weight=0 테스트 (lockbox fold14만) | fold14 MDD <-15% 이내 | mean 변화 >2% |

#### (d) PASS 조건
- **P1-A**: weight 변화율 / 시그널 변화율 ratio가 1:1±30% 이내면 PASS → 누수 아님 확인
- **P1-B**: mean 변화 >2%면 PASS → 사이저가 bottleneck임을 확인

---

### PATCH-2: 트리거 빈도/분포 프로파일링

#### (a) 왜 필요한가
- 시그널 생성 → 트레이드 실행 사이 **트리거 자체가 희소**할 수 있음
- 최근 6개월 lockbox 구간에서 트리거 횟수 미확인 상태

#### (b) 위험/부작용
- 트리거 빈도 높이면 거래비용 급증 (비용 미반영 덫)
- 과최적화 신호 (특정 구간만 트리거 몰림)

#### (c) 최소 실험
| ID | 정의 | 게이트 | 기대 관측치 |
|----|------|--------|-------------|
| P2-A | lockbox 구간 트리거 히스토그램 (월별) 생성 | 출력 파일 생성 | 월평균 트리거 ≥4회 |
| P2-B | 트리거 임계값 -20% 완화 (lockbox fold14) | MDD <-13% | 트리거 +50% 이상 증가 |

#### (d) PASS 조건
- **P2-A**: 월평균 <2회면 **FAIL** → 트리거 희소가 원인
- **P2-B**: 트리거 +50% & mean 상승 >1%면 PASS

---

### PATCH-3: 비용 모델 현실화 (숨은 드래그 점검)

#### (a) 왜 필요한가
- 현재 비용 상수 0.1% 가정 → 실제 슬리피지+스프레드 0.15~0.25% 가능
- lockbox mean 1.79 → 비용 2배 시 1.65 수준으로 하락 가능성

#### (b) 위험/부작용
- 비용 과대 적용 시 보수적 편향 → 실제 수익률과 괴리
- 백테스트 재실행 필요 (연산 비용)

#### (c) 최소 실험
| ID | 정의 | 게이트 | 기대 관측치 |
|----|------|--------|-------------|
| P3-A | cost=0.2% 로 lockbox 전체 재실행 | 완료 | mean Δ 기록 |
| P3-B | cost=0.3% 로 lockbox 전체 재실행 | 완료 | mean Δ 기록 |

#### (d) PASS 조건
- mean 변화 <5%면 PASS → 비용 민감도 낮음, 전략 견고
- mean 변화 >10%면 **ALERT** → 비용 모델 우선 수정 필요

### PATCH-4: 레짐 필터 on/off 민감도 테스트

#### (a) 왜 필요한가
- 레짐 필터가 **과도하게 보수적**이면 좋은 시그널도 차단
- Champion=Candidate 동일 원인이 "레짐 OFF 구간"일 수 있음

#### (b) 위험/부작용
- 레짐 필터 제거 시 드로다운 구간 노출 급증
- 서바이버십 편향 (상승장만 살아남은 종목)

#### (c) 최소 실험
| ID | 정의 | 게이트 | 기대 관측치 |
|----|------|--------|-------------|
| P4-A | 레짐 필터 완전 OFF (lockbox fold14) | MDD <-18% | mean 변화 >5% |
| P4-B | 레짐 임계값 +1σ 완화 (lockbox fold14) | MDD <-15% | mean 변화 2~5% |

#### (d) PASS 조건
- **P4-A**: mean +10% 이상 & MDD <-18%면 → 레짐 과필터링 확인
- **P4-B**: mean +3% & MDD 유지면 PASS → 임계값 조정 채택

## 3. 성능 정체 원인 분해 트리

```
lockbox_mean 변화 없음 (Δ < 0.1%)
│
├─[A] 트리거 미발생
│   ├─ 시그널 자체 flat → 팩터 검토 필요
│   └─ 임계값 과도 → P2-B 실험
│
├─[B] 트리거 → 포지션 미반영
│   ├─ min_weight floor 흡수 → P1-B 실험
│   └─ max_concentration cap 흡수 → 사이저 로그 확인
│
├─[C] 포지션 반영 → 수익 상쇄
│   ├─ 비용 과소계상 → P3-A/B 실험
│   └─ 레짐 필터가 수익구간 차단 → P4-A 실험
│
└─[D] 수익 발생 → 측정 오류
    ├─ 폴드 경계 데이터 누락 점검
    └─ 배당/스플릿 미반영 점검
```
