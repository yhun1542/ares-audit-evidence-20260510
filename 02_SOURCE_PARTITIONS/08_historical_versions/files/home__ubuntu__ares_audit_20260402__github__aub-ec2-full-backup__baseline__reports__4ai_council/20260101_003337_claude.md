## 1. 우선순위 TOP 5 실험

### PRIORITY 1: Tuning 구간 Blow-up Fold 격리 및 원인 분해

#### (a) 왜 필요한가
- `tuning_min=0.05`는 특정 fold에서 -95% 손실 발생 의미
- Lockbox에 해당 레짐이 없어서 통과했을 뿐, **실전 배치 시 동일 레짐 재현되면 파산**
- 이 문제 해결 전 다른 최적화는 무의미

#### (b) 위험/부작용
- 해당 fold 제거 시 survivorship bias 발생
- 과도한 방어 로직 추가 시 정상 구간 수익 희생

#### (c) 최소 실험

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| **P1-E1** | blow-up fold 식별 → 해당 구간 종목별 손익 분해 | 완료 | 원인 종목/섹터/날짜 리스트 |
| **P1-E2** | 해당 fold에 `max_position_loss=-30%` stop 적용 | tuning_min ≥ 0.50 | min 10배 개선 |
| **P1-E3** | 해당 fold 레짐(VIX>35 등) 탐지 → 전체 fold에 방어 적용 | lockbox_mean 유지 ±2% | 일반화 검증 |

#### (d) PASS 조건
```
tuning_min ≥ 0.50 AND lockbox_mean ≥ 1.78 AND lockbox_min ≥ 1.30
```

### PRIORITY 3: Holding Period / Turnover 최적화

#### (a) 왜 필요한가
- Champion과 Candidate가 0.007% 차이 → **변화량 자체가 너무 작음**
- 현재 전략의 turnover가 과도하거나 과소할 가능성
- Turnover 조정 없이 다른 alpha 실험은 noise에 묻힘

#### (b) 위험/부작용
- Holding 늘리면 단기 momentum 포착 실패
- Holding 줄이면 비용 증가 + whipsaw

#### (c) 최소 실험

| ID | 실험 정의 | 게이트 | 기대 관측치 |

| **P3-E2** | holding 1.5배로 늘린 variant | lockbox_mean ↑ 또는 turnover ↓30% | 비용 절감 효과 |
| **P3-E3** | min_holding=5일 강제 | tuning_min 유지 | whipsaw 방지 |

#### (d) PASS 조건
```
turnover ↓20% AND lockbox_mean ≥ 1.78
```

## 2. 성능 정체 원인 분해 트리

```
성능 안 움직임
│
├─ [트리거 문제] 신호가 안 바뀜
│   ├─ threshold 너무 보수적 → 진입 자체가 희소
│   └─ 신호 decay → 더 이상 유효하지 않음
│
├─ [적용 문제] 신호는 발생하나 실행 안 됨
│   ├─ position sizing이 너무 작음
│   └─ max_positions 이미 full → 신규 진입 불가
│
├─ [노출 문제] 실행되나 효과 안 보임
│   ├─ holding이 너무 짧아 alpha 실현 전 청산
│   └─ 동시다발 진입 후 상쇄 (롱/숏 balance 문제)
│
├─ [비용 문제] 효과가 비용에 잠식
│   ├─ turnover 과다
│   └─ 슬리피지 미반영
│
└─ [레짐 문제] 특정 구간만 극단적 결과
    ├─ tuning에 극단 fold 포함 → min 급락
    └─ lockbox에 해당 레짐 미포함 → false pass
```
