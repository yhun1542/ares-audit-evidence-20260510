## 0) 즉시 확인해야 할 “빨간불”(운영/신뢰성)
- **Rebalance 로그가 깨져 pinpoint 불가**: `--base-log` 파일 미존재 + `rebalance.csv`/`jsonl` 파싱 실패 → **성과가 안 움직이는 원인이 “전략”이 아니라 “측정 불능”일 수 있음**
- **Champion 지표 불일치**: 현재 핸드오프 OOS mean `1.88` vs Diagnoser의 Champion OOS mean `2.6276` → **베이스 파일/스코어 산출 경로가 2개로 갈라진 상태(누수·과최적화 이전에 재현성 리스크)**  
- **worst_mdd: None**: 리스크 핵심 지표가 누락 → **게이트(중단/보류) 조건이 작동 불가**

아래 TOP5는 24~48시간 내 **자동 루프(48h)에서 바로 돌아갈 “패치+실험”**만 제시.

# 1) TOP5 우선순위 제안 (코드/아키텍처/전략)

## TOP1. (운영) 리밸런스/오더 로그 스키마 고정 + 재현성(ONE TRUTH) 단일화
### (a) 왜 필요한지
- 현재 **rebalance pinpoint가 데이터 부재/파싱 실패로 무력화** → 비용/턴오버/노출 변화가 성능에 미치는 영향 추적 불가
- Champion 점수 불일치 → **같은 run_hash라도 다른 입력/스코어러를 타면 “개선/악화”가 착시**로 남음

### (b) 위험/부작용
- 로그/스키마 변경으로 과거 리포트 호환성 깨짐(단, 48h 루프 안정성이 더 중요)
- “진짜 성능”이 아니라 “측정 체계”가 먼저 바뀌어 단기 성능 변동이 커 보일 수 있음

### (c) 최소 실험(공유 실험 사용)
- **E4 (Logging/Schema Fix)**, **E1 (Score Path Unify & Repro)**

### (d) PASS 조건
- `rebalance.csv` 또는 `rebalance.jsonl` **항상 생성 + 스키마 검증 통과**
- 동일 seed/데이터 스냅샷에서 **oos_mean 재현 오차 ≤ 0.5%**
- worst_mdd가 None이 아닌 값으로 산출되고 리포트에 노출

---

## TOP2. (누수 우선) Point-in-time 정합 + Purged/Embargo CV로 누수/과최적화 차단
### (a) 왜 필요한지
- Tech/Healthcare 단일 섹터 집중 전략은 **미세 누수에도 OOS가 “좋게” 나오는 경우가 잦음**
- “No-Delta” 상태는 종종 **(1) 이미 누수 제거 후 알파 소진** 또는 **(2) 누수 의심을 못하고 실험만 반복**에서 발생

### (b) 위험/부작용
- 누수 제거 시 OOS 급락 가능(하지만 이게 정상)
- 데이터 지연(리포트/펀더멘털 업데이트) 반영하면 신호가 희석될 수 있음

### (c) 최소 실험
- **E1 (Purged/Embargo Walk-forward + 스코어 경로 단일화)**  
- **E2 (Survivorship/Delist 처리 포함한 Universe 재구성 A/B)**

### (d) PASS 조건
- Purged/Embargo 적용 후에도 **oos_mean 하락폭이 제한적**(예: -15% 이내)이고
- oos_min(최악 구간)이 **악화되지 않거나 개선**
- fold별 성능 분산이 줄고(degenerate_folds가 새로 생기지 않음) 재현성 OK

---

## TOP3. (비용/현실성) 거래비용·슬리피지·턴오버 캡을 “학습/선정”에 강제 반영
### (a) 왜 필요한지
- 8~14개 집중 포트는 리밸런스 빈도/체결 비용에 민감  
- 비용이 백테스트에 “사후 차감”으로만 있으면 **선정 과정에서 과잉 회전(과최적화)**이 유지됨

### (b) 위험/부작용
- 단기적으로 oos_mean 감소 가능(현실화)
- 턴오버 캡이 신호 반응성을 떨어뜨릴 수 있음(단, 안정성 상승)

### (c) 최소 실험
- **E3 (Cost Stress + Turnover Cap A/B)**  
- **E5 (Exposure/Gross cap + 포지션 제약 동시 적용)**

### (d) PASS 조건
- 비용 2~3배 스트레스에서도 **oos_mean이 “양(+)” 유지**(또는 목표 하한 초과)
- 연환산 turnover가 캡 이하로 안정화, 리밸런스 당 평균 체결비용 추정이 리포트에 노출
- worst_mdd가 계산되고 특정 임계(예: -25% 등 내부 기준) 이내

---

## TOP4. (전략/구성) 8~14개 강제 + Tech/Healthcare 섹터 바스켓 고정 + 노출(베타/볼) 게이트
### (a) 왜 필요한지
- 현재 exposure min/max가 `0.47~0.84`로 보이며, 변동성 레짐에서 **“노출이 성능을 집어삼키는”** 구간이 생김
- 섹터 집중 전략에서 **종목 수/섹터 순수도**가 흔들리면 알파가 아니라 베타를 사고팔게 됨

### (b) 위험/부작용
- 기회 상실(섹터 외 종목/현금 비중이 제한됨)
- 섹터 내 상관이 높아 tail risk가 커질 수 있음 → 그래서 **노출/볼 게이트가 같이 필요**

### (c) 최소 실험
- **E5 (8~14명/섹터필터/포지션리밋/노출캡 패치)**  
- **E3 (비용 포함 상태에서 동일 제약의 성능 확인)**

### (d) PASS 조건
- 항상 보유 종목 수가 8~14에 들어오고(예외=데이터 결측 시 현금)
- gross/net 노출이 목표 밴드 내(예: gross ≤ 0.85 고정)
- oos_min 개선 또는 worst_mdd 완화

---

## TOP5. (원인분해/No-Delta 대응) “신호→적용→노출→비용→레짐” 분해 리포트 자동 생성
### (a) 왜 필요한지
- 성능이 안 움직일 때 대부분은 “알파가 없음”이 아니라  
  **(1) 신호는 있으나 적용(리밸런스/지연/필터)에서 소실**  
  **(2) 노출/레짐이 손익을 덮음**  
  **(3) 비용/턴오버가 다 먹음**  
  중 하나임. 분해 없이는 실험이 랜덤워크가 됨.

### (b) 위험/부작용
- 리포트 지표가 늘어나면서 “지표 최적화” 유혹 증가 → PASS 게이트를 단순화해야 함
- 레짐 분해(예: 금리/변동성)에서 과도한 사후해석 위험

### (c) 최소 실험
- **E1 (Fold별/시점별 성능 분해 포함)**  
- **E3 (비용 전/후 PnL 분해 자동 저장)**  
- **E5 (노출/섹터/포지션 제약 변경 전후 비교 리포트)**

### (d) PASS 조건
- 매 48h 루프마다 아래 5개가 자동으로 떨어짐:  
  1) Signal IC/RankIC(또는 내부 score 상관)  
  2) 적용 손실(리밸런스 지연/필터 전후 성능 차)  
  3) 노출 기여(시장/섹터 베타 기여)  
  4) 비용 기여(슬리피지/스프레드/회전)  
  5) 레짐 슬라이스(저변동/고변동, 금리상승/하락 proxy)  
- “성능 무변화” 케이스에서 **어느 단계가 병목인지 1개로 수렴**(모호하면 FAIL)

# 2) 48시간 자동 루프용 “공유 실험(3~5개)” 정의
아래 5개 실험만 돌리고, TOP5 제안은 이 실험들을 **공유**해서 검증.

## E1) Repro & Purged/Embargo Walk-forward (누수/과최적화 1차 게이트)
- **실험 정의(명령형)**  
  - 데이터 스냅샷 해시 고정(날짜/소스/전처리 버전)  
  - 스코어 산출 경로 단일화(Champion OOS mean 불일치 제거)  
  - Purged K-fold + embargo(예: 5~20 거래일)로 워크포워드 평가
- **게이트**  
  - 동일 seed에서 oos_mean 재현 오차 ≤ 0.5%  
  - fold별 성능 분산이 기존 대비 증가하면 FAIL(누수 제거 후 불안정 가능성)
- **기대 관측치**  
  - 누수 있었다면 oos_mean 하락 + 분산 감소(“좋던 성능”이 깎이며 안정화)  
  - 진짜 알파면 oos_mean 방어 + oos_min 개선/유지

## E2) Survivorship/Delist/Corporate Action A/B (서바이버십/정합성 게이트)
- **실험 정의(명령형)**  
  - as-of date 기준으로 “그 시점에 존재했던” 유니버스 재구성  
  - delist 종목 처리(가격 0/거래정지 구간) 명시  
  - 스플릿/배당 조정 로직을 단일 파이프라인으로 고정
- **게이트**  
  - A/B 결과가 비정상적으로 크게 갈리면(예: oos_mean ±30% 이상) → 기존 결과 신뢰 FAIL
- **기대 관측치**  
  - 정상이라면 성능이 소폭 변하고 리스크 지표(worst_mdd)가 더 보수적으로 변함

## E3) Cost Stress + Turnover Cap (비용 미반영/운영 가능성 게이트)
- **실험 정의(명령형)**  
  - 비용 모델 3단: baseline / 2x / 3x(스프레드+슬리피지)  
  - turnover cap(주/월 기준)과 “리밸런스 미실행(hold)” 규칙을 포트 생성에 내장
- **게이트**  
  - 2x 비용에서도 oos_mean이 목표 하한 미만이면 FAIL  
  - turnover가 캡을 지속 초과하면 FAIL
- **기대 관측치**  
  - 거래가 과했던 전략은 성능 급락 + turnover 감소가 곧바로 관측됨  
  - 견고하면 비용 증가에도 성능 완만 감소

## E4) Rebalance 로그/스키마 패치 (측정 불능 제거 게이트)
- **실험 정의(명령형)**  
  - 리밸런스 이벤트마다: timestamp, ticker, target_w, prev_w, trade_w, price, est_cost, reason 저장  
  - CSV/JSONL 둘 중 하나는 반드시 생성 + JSON schema validation
- **게이트**  
  - pinpoint 도구가 에러 없이 리포트 생성 못 하면 FAIL
- **기대 관측치**  
  - “성능 무변화” 구간에서 실제로는 리밸런스가 거의 없었는지/너무 잦았는지 즉시 드러남

## E5) Portfolio Constraints Patch (8~14명 + Tech/Healthcare + 노출캡)
- **실험 정의(명령형)**  
  - 보유 종목 수: 8~14 강제(부족 시 현금)  
  - 섹터 필터: Tech+Healthcare only(ETF 매매 없음, XLK/XLV는 관측만)  
  - max position, max gross exposure(예: 0.85), 볼 타겟(또는 변동성 기반 스케일링)
- **게이트**  
  - 종목 수/섹터 위반 1회라도 발생 시 FAIL(운영 규율)  
  - gross exposure가 상한을 넘으면 FAIL
- **기대 관측치**  
  - oos_min 및 worst_mdd 개선(“잘 안 깨지는” 구조)  
  - oos_mean이 약간 줄어도 비용·리스크 조정 후 성능이 개선될 가능성

# 3) 성능이 안 움직일 때 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래를 **자동 리포트/로그로 강제**해서 “어디서 죽는지”를 한 번에 고정.

## A. Trigger(신호 생성) 문제
- **점검 지표(명령형)**  
  - 신호 분산(표준편차)·유효 표본수(매일 신호 있는 종목 수)  
  - RankIC/Hit-rate(상위 버킷이 다음 기간 수익 상위로 가는지)
- **트리거**  
  - 신호 분산이 0에 수렴하거나, 항상 같은 종목만 선택 → feature freeze/데이터 결측 가능성

## B. Apply(적용/리밸런스/지연)에서 알파 소실
- **점검 지표(명령형)**  
  - “가상(ideal) 리밸런스” vs “제약 적용 후(real)” 성능 차  
  - 리밸런스가 실제로 발생한 횟수/평균 변경폭(Δw)
- **트리거**  
  - ideal은 좋은데 real이 평평하면 → 턴오버 캡/섹터/포지션 제약이 과도하거나, 리밸런스 일정/캘린더 버그

## C. Exposure(베타/섹터)로 수익이 덮임
- **점검 지표(명령형)**  
  - QQQ(관측), XLK/XLV(관측) 대비 포트 베타/상관  
  - gross/net exposure 시계열, tail 구간(급락일) 손실 기여
- **트리거**  
  - 성과가 QQQ/XLK 방향성과 거의 동일 → “알파”가 아니라 “섹터 베타”만 거래 중

## D. Cost(비용)로 PnL이 소멸
- **점검 지표(명령형)**  
  - 비용 전/후 PnL 분해(거래비용 기여율 %)  
  - turnover 대비 성과 탄력(회전 10%p 증가 시 성과 변화)
- **트리거**  
  - 비용 전 성능은 괜찮은데 비용 후가 평평 → 전략이 구조적으로 고회전/박한 알파

## E. Regime(레짐) 미스매치
- **점검 지표(명령형)**  
  - VIX(관측), 10Y 금리(관측), XLK/XLV 상대강도(관측)로 구간 슬라이스 성과  
- **트리거**  
  - 특정 레짐에서만 성과가 나고 나머지는 0 근처 → 레짐 게이트(현금 비중 확대/노출 축소) 필요

---

## 실행 순서(24~48h) — 명령형 체크리스트
1) **E4 먼저**: rebalance 로그 생성/파싱/스키마 검증 통과시키고 pinpoint 리포트가 나오게 고정  
2) **E1 실행**: 스코어 경로 단일화 + purged/embargo WF로 “누수/재현성” 1차 판정  
3) **E3 실행**: 비용 1x/2x/3x + turnover cap으로 “현실성” 판정  
4) **E5 실행**: 8~14명 + Tech/Healthcare + 노출캡으로 “운영 가능한 포트 형태” 고정  
5) **E2는 병렬**: 유니버스/서바이버십 A/B로 백테스트 신뢰도 확정

이 5개가 통과(PASS)하면 그 다음에야 “신호 개선(피처/모델)”로 넘어가고, 하나라도 FAIL이면 **전략 실험을 늘리지 말고 FAIL 원인부터 제거**가 맞습니다.
