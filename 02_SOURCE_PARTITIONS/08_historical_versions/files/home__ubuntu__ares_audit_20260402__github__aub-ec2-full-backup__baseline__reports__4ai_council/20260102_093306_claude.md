## TOP 5 우선순위 (24~48h)

---

### P1. MDD 계산 파이프라인 복구
**왜 필요한가**: `worst_mdd: None` → drawdown 기반 position sizing, 레짐 필터 모두 작동 불가. 과최적화 감지 게이트 무력화.

**위험/부작용**: 계산 로직 변경 시 과거 결과와 비교 불가 (버전 태깅 필수)

| 실험 ID | 정의 | 게이트 | 기대 관측치 |
|---------|------|--------|-------------|
| P1-a | `backtest_engine.py`에서 `equity_curve` → `max_drawdown()` 호출 확인 | MDD ≠ None | -15% ~ -35% 범위 |
| P1-b | None 반환 시 fallback = `-999` 삽입 후 로그 grep | 로그에 `-999` 0건 | 정상 계산 확인 |
| P1-c | 5-fold 중 1개 fold에서 MDD 수동 계산 vs 시스템 값 비교 | 오차 < 0.5% | 로직 정합성 |

**PASS 조건**: 다음 핸드오프에서 `worst_mdd: -XX.X%` 숫자 출력

---

### P2. Rebalance 로그 경로/포맷 수리
**왜 필요한가**: 거래 비용(슬리피지, 수수료) 미반영 시 OOS 1.88 → 실제 1.2 이하 가능. Survivorship bias 외에 가장 큰 누수 원인.

**위험/부작용**: 로그 포맷 변경 시 기존 분석 스크립트 호환성 깨짐

| 실험 ID | 정의 | 게이트 | 기대 관측치 |
|---------|------|--------|-------------|
| P2-a | `rebalance.csv` 생성 코드 추적 → 경로 하드코딩 수정 | 파일 존재 & row > 0 | 최소 50+ 거래 기록 |
| P2-b | JSON vs CSV 이중 출력 활성화 | 둘 다 로드 성공 | 동일 row count |
| P2-c | 1회 리밸런스당 평균 턴오버 계산 | 턴오버 < 30%/월 | 과다 매매 아님 확인 |

**PASS 조건**: `aub_rebalance_pinpoint.py` 에러 0건 + 턴오버 리포트 출력

---

### P3. OOS Mean 0.75 Gap 원인 분해
**왜 필요한가**: 핸드오프(1.88) ≠ Diagnoser(2.63) → 둘 중 하나는 틀림. 의사결정 기반 자체가 흔들림.

**위험/부작용**: 잘못된 쪽을 기준으로 삼으면 이후 모든 실험 무효

| 실험 ID | 정의 | 게이트 | 기대 관측치 |
|---------|------|--------|-------------|
| P3-a | 두 스크립트의 `oos_mean` 계산 함수 diff | 수식 동일 | 둘 다 geometric mean 또는 arithmetic |
| P3-b | 동일 JSON 입력 → 두 스크립트 출력 비교 | 차이 < 0.01 | 입력 문제면 gap 유지 |
| P3-c | Diagnoser의 "9 experiments" 중 champion과 동일 config 식별 | 1개 매칭 | 해당 exp의 oos = 1.88 |

**PASS 조건**: Gap 원인 1줄 문장으로 설명 가능 (예: "Diagnoser는 9개 평균, 핸드오프는 champion 단일값")

---

### P4. 비용 모델 현실화 (슬리피지 + 수수료)
**왜 필요한가**: 현재 비용 = 0 가정이면, Tech 소형주 실제 슬리피지 0.3~0.8%가 OOS를 직접 깎음.

**위험/부작용**: 과도한 비용 가정 → 실험 전체 reject → 전략 탐색 정체

| 실험 ID | 정의 | 게이트 | 기대 관측치 |
|---------|------|--------|-------------|
| P4-a | 현재 `transaction_cost` 파라미터 값 확인 | 값 ≥ 0.001 (10bp) | 0이면 즉시 수정 |
| P4-b | 비용 0bp vs 15bp vs 30bp 3단계 백테스트 | OOS 차이 기록 | 15bp당 OOS -0.1~0.2 예상 |
| P4-c | 유니버스 내 평균 bid-ask spread 샘플링 (10종목) | spread < 0.1% | 대형주 위주 확인 |

**PASS 조건**: `cost_sensitivity_report.md` 생성 + 권장 비용 파라미터 제시

---

### P5. 레짐 필터 유효성 검증 (FSA/Hedge 영향도)
**왜 필요한가**: `exp_fsa_only_scale_090_hedge_025.json` 실험 존재 → FSA 파라미터 변경이 OOS에 미치는 영향 미측정 상태.

**위험/부작용**: 레짐 필터가 과거 데이터에만 피팅되면 실시간 악화

| 실험 ID | 정의 | 게이트 | 기대 관측치 |
|---------|------|--------|-------------|
| P5-a | FSA on vs off 단일 변수 실험 | OOS diff > 0.1 | 필터 유효 |
| P5-b | Hedge 0% vs 25% vs 50% 그리드 | MDD 개선 vs OOS 손실 트레이드오프 | Sharpe 유지 범위 |
| P5-c | 2022년 bear market fold만 분리 성과 | OOS > 1.0 | 방어력 확인 |

**PASS 조건**: FSA 기여도 정량화 (예: "FSA on = OOS +0.3, MDD -5%")

## 성능 미변동 시 원인 분해 트리

```
OOS 변화 없음
├─ [트리거] 시그널 자체가 안 바뀜
│   └─ 체크: signal diff count = 0? → 파라미터가 threshold 밖
├─ [적용] 시그널은 바뀌나 포지션 동일
│   └─ 체크: position diff = 0? → 리밸런스 로직 또는 min_weight 제한
├─ [노출] 포지션 바뀌나 수익 기여 없음
│   └─ 체크: 변경 종목의 개별 return 분포 → 노이즈 상쇄
├─ [비용] 수익 있으나 비용이 상쇄
│   └─ 체크: gross return vs net return diff
└─ [레짐] 특정 기간만 효과 있음 (평균에 묻힘)
    └─ 체크: fold별 OOS 분산 → 1개 fold가 outlier
```
