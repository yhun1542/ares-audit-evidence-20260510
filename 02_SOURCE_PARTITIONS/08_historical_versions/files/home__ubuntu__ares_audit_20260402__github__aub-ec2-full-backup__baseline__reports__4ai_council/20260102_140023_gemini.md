## 1. 48시간 내 실행할 TOP 3 우선순위 제안 (Code/Strategy)

현재 Champion(`v5`)과 Candidate(`shadow`) 간 `tuning_min`(0.05 vs 0.43)과 `lockbox_min`(1.34 vs 1.13)의 괴리가 심각함. 이는 특정 구간 과최적화(Overfitting) 혹은 레짐 운(Luck)일 가능성이 높으므로, 이를 검증하고 보정하는 실험에 집중하라.

### P1. [검증] 슬리피지/지연 비용 스트레스 테스트 (Cost/Lag Injection)
*   **이유:** `tuning_min`이 0.05로 낮은데 `lockbox_min`이 1.34로 튀는 현상은, 거래 비용이 과소평가되었거나 체결 가능성을 낙관했을 때 발생함. Tech/Bio 변동성 고려 시 필수.
*   **위험/부작용:** 모든 후보 모델이 탈락(Fail)하여 Baseline이 후퇴할 수 있음. 그러나 이는 '가짜 수익'을 걷어내는 과정임.
*   **실험 정의:**
    1.  **Exp_HighCost:** 매매 수수료(Bps)를 기존 대비 2배(예: 10bps → 20bps) 설정.
    2.  **Exp_ExecutionLag:** 시그널 발생 후 `t+1` 시가(Open)가 아닌 `t+1` 종가(Close) 혹은 `t+1` VWAP 체결로 가정.
    3.  **Exp_LiquidityFilter:** 일평균 거래대금 하위 20% 종목 강제 제외 후 백테스트.
*   **PASS 조건 (Gate):**
    *   `lockbox_mean` > 1.2 유지.
    *   `worst_mdd` > -15% 방어.
*   **기대 관측치:** 기존 Champion 수익률의 20~30% 하락 예상. 만약 50% 이상 하락 시, 현재 전략은 유동성 공급자에게 비용을 헌납 중인 것임.

### P2. [로직] Tech/Healthcare 섹터 동적 캡 (Dynamic Sector Capping)
*   **이유:** 8~14개 종목 제한 시, 모멘텀에 따라 Tech 100% 또는 HC 100% 쏠림 현상 발생 가능. 두 섹터 동반 하락 시 MDD 방어 불가.
*   **위험/부작용:** 강세장에서 주도 섹터 비중이 제한되어 Upside가 깎일 수 있음(Underperformance).
*   **실험 정의:**
    1.  **Exp_HardCap:** Tech Max 60%, Healthcare Max 60% 비중 강제 제한 (Rebalancing 시).
    2.  **Exp_InverseWeight:** 두 섹터 ETF(XLK, XLV)의 20일 변동성 역가중 비율로 섹터 예산 할당.
*   **PASS 조건 (Gate):**
    *   `fold14_mdd` (검증 데이터 MDD)가 Champion 대비 10% 이상 개선 (예: -9% → -8.1%).
*   **기대 관측치:** 수익률(Mean)은 소폭 감소하나, Sharpe Ratio 및 MDD 안정성이 유의미하게 증가.

### P3. [전략] Champion + Shadow 앙상블 (Linear Blending)
*   **이유:** Champion은 `tuning`에서 안정적이고, Candidate(`shadow`)는 `lockbox`에서 강함. 두 모델의 상관관계가 낮다면 혼합 시 변동성 상쇄 가능.
*   **위험/부작용:** 코드 복잡도 증가, 연산 비용 2배 증가.
*   **실험 정의:**
    1.  **Exp_Blend_50_50:** Champion 시그널 50% + Candidate 시그널 50% 단순 혼합.
    2.  **Exp_Regime_Switch:** VIX > 20 이면 Champion(보수적 가정), VIX < 20 이면 Candidate(공격적) 사용.
*   **PASS 조건 (Gate):**
    *   `tuning_min` > 0.3 (Candidate의 약점 보완).
    *   `lockbox_min` > 1.2 (Candidate의 강점 유지).
*   **기대 관측치:** 개별 모델보다 낮은 MDD와 평활화된 수익 곡선(Equity Curve).

## 2. 성능 정체 원인 분해 (Decomposition Framework)

성능이 움직이지 않거나(Plateau), `tuning`과 `lockbox` 괴리가 좁혀지지 않을 때 다음 순서로 점검하라.

1.  **트리거(Trigger) 실패:**
    *   *체크:* 진입 신호가 너무 드물게 발생하는가? (연간 매매 횟수 < 10회면 과최적화)
    *   *액션:* 진입 임계값(Threshold)을 완화하고, 포지션 사이즈를 줄여라.

2.  **노출(Exposure) 왜곡:**
    *   *체크:* 특정 1~2개 "슈퍼 주식"(예: NVDA, LLY)이 전체 수익의 80%를 차지하는가?
    *   *액션:* 개별 종목 Max 비중을 15% 이하로 강제하고 재실험.

3.  **레짐(Regime) 불일치:**
    *   *체크:* `tuning` 구간은 저변동성 상승장, `lockbox` 구간은 고변동성 횡보장인가?
    *   *액션:* 훈련 데이터(Fold)를 시계열 순서가 아닌, 시장 국면(변동성/추세)별로 샘플링하여 재학습.

4.  **비용(Cost) 민감도:**
    *   *체크:* 평균 수익(Average Trade Return)이 편도 수수료의 5배 미만인가?
    *   *액션:* 5배 미만이면, 예측력이 없는 모델임. 알파 팩터를 전면 교체하라.
