## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — 명령형 체크리스트

### 1) **재현성/아티팩트/리밸런스 로그 파이프라인 복구 (운영 리스크 최우선)**
**왜 필요한지**
- 현재 상태에서 `file: (empty)`, `lane_hash/run_hash: None`, `worst_mdd: None` → “챔피언이 무엇인지/어떻게 나왔는지”가 재현 불가.
- `aub_rebalance_pinpoint`가 `--base-log` 경로 오류 및 `rebalance.csv/jsonl` 파싱 실패 → 비용/턴오버/체결 가정 문제를 추적할 수 없음(전략 개선이 멈춤).

**위험/부작용**
- 로그/아티팩트 스키마 변경 시 기존 리포트/도구가 깨질 수 있음(호환성 이슈).
- 재현성 강화로 실험 속도 일시 저하(추적 정보/검증 단계 추가).

**최소 실험(공유 실험 중 2~3개 사용)**
- **[E1] Run Manifest & Atomic Artifact Patch**
- **[E4] Cost/Turnover/Exposure Sensitivity (로그 기반)**
- **[E3] Fold 재생성 후 재실행(재현성 검증 포함)**

**PASS 조건**
- `champion.json`에 `file, lane_hash, run_hash, git_sha, data_version, universe_hash`가 항상 채워짐(빈 값 0건).
- `rebalance.csv` 또는 `rebalance.jsonl`이 매 런 생성되고, `aub_rebalance_pinpoint`가 에러 없이 report 생성.
- `worst_mdd`가 None이 아닌 수치로 산출(계산 파이프 누락 제거).
- 동일 seed/동일 데이터에서 핵심 KPI(oos_mean 등) 변동이 사전 정의 허용오차 이내(예: ±1~2%).

---

### 2) **누수(lookahead)/서바이버십/코퍼레이트 액션 PIT(시점정합) 우선 감사**
**왜 필요한지**
- OOS가 “안 움직이거나 비정상적으로 안정적/불안정”할 때 가장 흔한 원인이 **시점정합 실패(lookahead)** 또는 **서바이버십 편향**.
- 특히 Tech/Healthcare 단일종목(8~14) 집중 구조는 한두 이벤트(상폐/인수/분할/급락)가 백테스트를 왜곡하기 쉬움.

**위험/부작용**
- PIT/서바이버십 보정 후 성능 급락 가능(“진짜 성능”이 드러남).
- 데이터 소스/조정 방식 변경 시 과거 결과와 불연속(리그레션 비교 필요).

**최소 실험**
- **[E2] PIT/서바이버십 스트레스 테스트(토글/대체 데이터/이벤트 삽입)**
- **[E3] Purge/Embargo 포함 CV로 재검증(누수 의심 경로 차단)**
- **[E5] 이벤트(실적/급변) 회피 게이트 추가 후 성능 변화 관측**

**PASS 조건**
- PIT on/off(또는 서바이버십 on/off) 간 성능 격차가 “설명 가능한 범위”로 축소(예: oos_mean 급변/부호전환 같은 비정상 패턴 제거).
- delist/인수/거래정지에 대한 가격/수익률 시계열이 NaN/0으로 뭉개지지 않고, 포지션 정리 규칙이 일관되게 적용됨.
- 누수 의심 지표: (1) 리밸런스 직후 과도한 즉시 수익 (2) 특정 리포트 날짜 전후로만 알파 발생 (3) 폴드 간 성능 괴리 → 완화.

---

### 3) **폴드 degeneracy 제거 + Purged Walk-Forward로 과최적화 차단**
**왜 필요한지**
- `degenerate_folds: [1,2,3,8]` → 일부 폴드가 학습/평가로서 의미가 없거나(표본 부족/편향) 분할 로직이 깨진 상태.
- 폴드가 깨지면 OOS mean은 “그럴듯해 보이지만” 개선이 안 되거나 랜덤하게 흔들림(최적화가 먹히지 않음).

**위험/부작용**
- 더 엄격한 CV는 단기적으로 점수 하락(허수 알파 제거).
- split/embargo 적용으로 학습 데이터가 줄어 모델이 단순해질 수 있음.

**최소 실험**
- **[E3] Purged Walk-Forward 재정의(최소 표본/embargo 강제)**
- **[E1] split 메타데이터 로그(각 폴드 샘플 수/기간/유니버스) 강제 기록**
- **[E4] 비용 포함 시 폴드별 성능 분해(턴오버-알파 상관 확인)**

**PASS 조건**
- degenerate_folds가 0으로 수렴(모든 폴드가 최소 표본/최소 기간/최소 거래 수 충족).
- 폴드별 oos 분산이 감소(“한 폴드만 잘됨” 현상 완화).
- 폴드별 turnover/cost 대비 net 성과가 일관(특정 폴드에서만 비용 무시로 이익이 나는 패턴 제거).

---

### 4) **비용/슬리피지/임팩트 반영 + 노출/턴오버 게이트(현실화)**
**왜 필요한지**
- 단일종목 8~14 + 리밸런스가 잦으면, **스프레드/슬리피지/임팩트**가 알파를 쉽게 삼킴.
- 현재 `exposure_max ~0.84`만 보이고, 비용/체결/리밸런스 로그가 불완전 → “순수익(net)”이 아닌 “총수익(gross)” 최적화로 흐를 위험.

**위험/부작용**
- 비용을 현실화하면 전략이 무의미해질 수 있음(그러나 이게 정상적인 필터).
- 과도한 게이트는 거래를 못 하게 만들어 성능이 정체될 수 있음(게이트 튜닝 필요).

**최소 실험**
- **[E4] 비용 배수(예: 0.5x/1x/2x) + turnover cap grid**  
- **[E1] 리밸런스 단위 로그로 ‘거래수/체결가정/비용’ 추적**  
- **[E5] 포지션 사이징(변동성 타겟/리스크 패리티 유사) 추가**

**PASS 조건**
- 비용 1x~2x에서도 oos_mean의 급격한 붕괴가 완화(민감도 완화).
- turnover 상한 적용 후에도 net 성과가 유지되거나 MDD가 개선.
- 리밸런스/거래 로그에서 “거래가 너무 자주/너무 크게” 발생하는 날이 감소(운영 리스크↓).

### 5) **Tech+Healthcare(미국주식) 8~14종목 전용 포트폴리오 규칙 + 레짐 게이트(ETF는 지표만)**
**왜 필요한지**
- 섹터/레짐에 따라 알파가 “켜졌다 꺼지는” 구조면, 단순 최적화로는 OOS가 잘 안 움직임.
- ETF는 매매 금지이므로 **레짐 지표(관측용)**로만 사용해, 신호 적용/노출을 자동으로 조절해야 함.

**위험/부작용**
- 레짐 게이트가 과도하면 거래 기회 상실(알파 희석).
- 지표 설계가 과최적화되면 또 다른 누수/오버핏이 됨(간단하게 유지).

**최소 실험**
- **[E5] 레짐 게이트 2단(ON/OFF) + 노출 스케일링**  
  - 관측지표(예): `XLK/XLV 상대강도`, `QQQ 모멘텀`, `VIX(또는 VIX proxy)`  
- **[E3] 레짐별 폴드 성능 분해(레짐 태깅 후 oos_mean 분해)**  
- **[E4] 레짐별 비용/턴오버 민감도 분해(고변동 구간 비용 폭증 체크)**

**PASS 조건**
- 레짐별 성과 편차가 줄고(특정 레짐에서만 폭망/폭등 감소), oos_min(최악 구간)이 개선.
- 레짐 OFF 구간에서 불필요 거래(턴오버)가 유의미하게 감소.
- 8~14 종목 제한 하에서도 단일종목 쏠림(상위 1~2종목 기여도 과대)이 완화.

## 48시간 자동 루프용 “공유 실험(3~5개)” 정의 (각 실험: 정의/게이트/기대 관측치)

### [E1] **Run Manifest & Rebalance Logging Patch (재현성/운영 안정화)**
1) **실험 정의**
- 모든 런에 대해 `manifest.json` 저장(필수 키: git_sha, data_version, universe_hash, lane_hash, run_hash, config_hash, seed).
- `rebalance.jsonl`(또는 csv) 표준 스키마로 생성: timestamp, symbol, target_w, prev_w, trade_qty, est_spread, est_slip, fee, notional.
- 파일 기록은 atomic write(임시파일→rename)로 중간 실패 방지.

2) **게이트**
- manifest 필드 누락/None 발생 시 런 FAIL.
- rebalance 로그 0바이트/파싱 실패 시 런 FAIL.
- `worst_mdd is None`이면 FAIL.

3) **기대 관측치**
- pinpoint 리포트 생성 성공률 100%.
- “성능이 안 움직임”의 1차 원인(파이프라인/로그 부재) 제거.

---

### [E2] **PIT/서바이버십/코퍼레이트액션 스트레스 테스트**
1) **실험 정의**
- 데이터 파이프에 PIT 토글(가능하면) + delist/merge/split 처리 검증.
- “상폐/거래정지/급락” 이벤트 구간에서 포지션/리밸런스가 어떻게 처리되는지 리플레이 리포트 생성.

2) **게이트**
- 조정 전/후에 동일 날짜의 feature가 미래 데이터를 참조하는 흔적 발견 시 FAIL(예: 발표일 이전에 실적 반영).
- 상폐/병합 심볼에서 가격이 0/고정값으로 이어지면 FAIL(현실 부정합).

3) **기대 관측치**
- PIT 적용 후에도 전략이 “완전 붕괴”하지 않고, 성능 변화가 설명 가능한 형태로 정리됨(누수 제거의 증거).

---

### [E3] **Purged Walk-Forward CV + Fold Degeneracy Zero**
1) **실험 정의**
- walk-forward split 재정의: 학습/검증 사이 embargo, 신호 산출 창 길이만큼 purge 적용.
- 폴드별 최소 거래 수/최소 일수/최소 유니버스 커버리지 강제.

2) **게이트**
- degenerate_folds 발생 시 FAIL.
- 폴드별 샘플 수가 임계치 미만이면 FAIL.

3) **기대 관측치**
- 폴드별 성능 분산 감소, oos_min 개선(특정 구간 폭망 완화).

---

### [E4] **Cost/Turnover/Exposure Sensitivity Grid (현실 비용 반영)**
1) **실험 정의**
- 비용 배수 0.5/1/2 + turnover cap(예: 일/주 단위 상한) + exposure cap(예: 0.6/0.8) 간단 그리드.
- 결과는 net 성과 기준으로만 랭킹.

2) **게이트**
- 비용 2x에서 net이 급락(예: oos_mean이 기준 대비 -X% 이상)하면서 발생 원인이 “턴오버 폭증”으로 추적되면 FAIL(전략 구조 문제로 간주).
- 거래 로그 없이 비용 민감도 계산이 불가하면 FAIL.

3) **기대 관측치**
- 비용/턴오버에 둔감한 구조가 상위로 올라오고, 개선 방향이 “신호”가 아닌 “거래 구조”로 명확해짐.

---

### [E5] **Regime Gate (ETF는 관측만) + 포지션 사이징**
1) **실험 정의**
- 관측지표만 사용: 예) `XLK/XLV 상대강도`, `QQQ 추세`, `VIX 수준/변화`.
- 게이트 출력: {Risk-ON, Neutral, Risk-OFF} → 노출 스케일(1.0/0.5/0.0) 또는 리밸런스 빈도 축소.
- 포지션 사이징: 변동성 타겟(단순 20D realized vol 기반)으로 단일종목 쏠림 완화.

2) **게이트**
- 게이트가 전체 기간의 과반을 OFF로 만들면 FAIL(과도한 필터).
- 레짐별 성과가 한 레짐에만 과도하게 의존하면 FAIL(오버핏 의심).

3) **기대 관측치**
- drawdown 구간에서 거래/노출이 줄고 oos_min 개선.
- 레짐별 성과 분해 시 “망하는 레짐”이 줄어듦.

---

## 성능이 “안 움직일 때” 원인 분해 아이디어 — 트리거/적용/노출/비용/레짐 순서로 강제 점검

### A) Trigger(리밸런스 트리거가 실제로 발동하나)
- **명령형 체크**
  - “리밸런스 발생 횟수/간격/조건 충족률”을 일자별로 로그화하라.
  - 트리거가 거의 0이면: 임계값 과도/데이터 결측/스케줄러 오류로 분기하라.
- **관측 지표**
  - rebalance_count/day, avg_days_between_rebalances, signal_update_count/day.

### B) Apply(신호가 포지션으로 반영되나)
- **명령형 체크**
  - 목표비중(target_w)과 실제 체결 후 비중(realized_w)의 괴리를 기록하라.
  - 괴리가 크면: 체결 모델/최소 주문 단위/리밸런스 캡/노출 캡이 신호를 눌러버리는지 확인하라.
- **관측 지표**
  - tracking_error_to_target, clipped_weight_ratio, orders_rejected_ratio.

### C) Exposure(노출이 의도대로 나오나: 8~14 종목 집중 리스크)
- **명령형 체크**
  - 상위 1~2종목 기여도, 섹터 내 편향(Mega-cap 쏠림), 현금 비중을 항상 출력하라.
  - 노출이 항상 0 근처면: 게이트 과도/리스크 모델 과잉 방어로 분기하라.
- **관측 지표**
  - top1_contrib, effective_n, gross/net exposure, cash_ratio.

### D) Cost(비용이 알파를 상쇄하나)
- **명령형 체크**
  - gross→net 브리지 리포트(수익 - 슬리피지 - 스프레드 - 수수료)를 매 폴드/매 레짐으로 쪼개라.
  - net이 움직이지 않으면: “턴오버가 원인인지, 스프레드가 원인인지”를 분리하라.
- **관측 지표**
  - cost_pct_of_gross, slippage_per_trade, turnover, avg_spread_est.

### E) Regime(레짐 의존으로 OOS가 고정/정체되나)
- **명령형 체크**
  - 레짐 태그(Risk-ON/OFF)를 붙이고 성과를 분해하라(ETF는 관측만).
  - 특정 레짐에서만 이기면: 그 레짐에서만 노출, 나머지는 방어(또는 전략 2개 lane 분리)로 구조화하라.
- **관측 지표**
  - pnl_by_regime, drawdown_by_regime, trade_freq_by_regime.

## 실행 순서(24~48h) — 실패 확률을 먼저 줄이는 순
1) **E1 먼저 적용/통과** → 로그/아티팩트가 없으면 나머지 실험이 “해석 불가”.
2) **E3로 폴드 정상화** → degenerate_folds=0 만들기(과최적화/누수 차단의 기반).
3) **E2로 PIT/서바이버십 감사** → “진짜 성능 바닥” 확정.
