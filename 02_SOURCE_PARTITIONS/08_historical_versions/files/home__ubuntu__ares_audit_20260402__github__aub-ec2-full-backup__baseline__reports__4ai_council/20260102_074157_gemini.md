### 2. 제안별 상세 실행 계획

#### (1) MDD 계산 로직 디버깅 및 NaN 데이터 정제
*   **(a) 필요성:** `worst_mdd: None`은 리스크 관리 모듈이 작동하지 않음을 시사. 현재 OOS Mean 1.88이 실제로는 막대한 MDD를 감춘 수치일 가능성 높음.
*   **(b) 위험:** 수정 후 성과 지표가 급락하여 전략 폐기 수순으로 갈 수 있음(그러나 필수적임).
*   **(c) 실험:**
    *   `EXP-01-A`: 수익률 배열(Returns array)에 `NaN` 또는 `Inf` 존재 여부 전수 검사.
    *   `EXP-01-B`: MDD 계산 함수에 강제로 -10% 하락 더미 데이터 주입하여 `None`이 아닌 값이 나오는지 단위 테스트.
    *   `EXP-01-C`: 자산이 0이거나 거래가 없는 구간(Flat line) 처리 로직 확인.
*   **(d) PASS 조건:** `worst_mdd`가 유효한 `float` 값(예: -0.15 등)으로 출력되고, 로그에 에러 없음.

#### (2) 섹터 집중도(Tech/Health) 동적 유니버스 필터
*   **(a) 필요성:** 8~14개 종목 제한 상황에서 특정 하위 섹터(예: 반도체 또는 바이오)에만 쏠리면 분산 효과 소멸. Tech와 Healthcare 간 상관계수 스파이크 방어 필요.
*   **(b) 위험:** 과도한 필터링으로 인해 수익성 높은 종목(Alpha source)이 제외될 수 있음.
*   **(c) 실험:**
    *   `EXP-02-A`: 유니버스 구성 시 Tech(XLK 구성종목)와 Health(XLV 구성종목) 비중을 강제로 40:60 ~ 60:40 범위로 제한.
    *   `EXP-02-B`: 개별 종목 선정 시 20일 평균 거래대금 하위 20% 자동 탈락 (유동성 리스크 제거).
    *   `EXP-02-C`: ETF(XLK, XLV)를 매매 대상에서 제외하고, 피처(Feature)로만 사용하여 상대강도(RS) 계산.
*   **(d) PASS 조건:** 포트폴리오 내 단일 섹터 비중 < 70%, Exposure Min > 0.5 유지, OOS Mean > 1.5.

#### (3) 변동성 기반 포지션 사이즈 축소 (De-leveraging)
*   **(a) 필요성:** Exposure Max가 0.84이나, Tech/Bio 종목은 개별 변동성이 큼. 시장 급락 시 노출도를 빠르게 0.47(Min) 이하로 낮출 수 있어야 함.
*   **(b) 위험:** 추세 추종 구간에서 너무 빨리 내려서 Upside를 놓칠(Under-betting) 가능성.
*   **(c) 실험:**
    *   `EXP-03-A`: 포트폴리오 가중 평균 변동성(ATR 등)이 임계치 초과 시, 현금 비중 10%p 강제 상향.
    *   `EXP-03-B`: 개별 종목 MDD -5% 발생 시 해당 종목 비중 50% 즉시 청산(Cut-loss 강화).
*   **(d) PASS 조건:** `worst_mdd`가 -15% 이내로 제어, Exposure 변동폭이 시장 변동성과 역의 상관관계 확인.

#### (4) 슬리피지/수수료 가중 스트레스 테스트
*   **(a) 필요성:** 8~14개 종목의 잦은 리밸런싱은 비용 민감도가 높음. 현재 성과가 과최적화된 비용 모델 덕분일 수 있음.
*   **(b) 위험:** 전략의 기대 수익률(Sharpe)이 급격히 낮아져 '실패'로 판정될 수 있음.
*   **(c) 실험:**
    *   `EXP-04-A`: 기존 슬리피지 모델 대비 비용 2배 적용 시뮬레이션.
    *   `EXP-04-B`: 매수/매도 시 호가 공백(Market Impact) 모델 적용 (유동성 낮은 바이오주 타겟).
*   **(d) PASS 조건:** 비용 2배 적용 시에도 OOS Mean > 1.2 유지.

#### (5) 최근 3개월(Simulated) 윈도우 데이터 무결성 검증
*   **(a) 필요성:** 2026-01-02 시점에서 과거 데이터(현재 시점 기준 미래)를 사용할 때 Look-ahead Bias(미래 참조) 발생 가능성 점검.

*   **(c) 실험:**

### 3. 성능 정체 시 원인 분해 (Debugging Tree)

성능(OOS Mean)이 개선되지 않거나 1.8대에서 횡보할 경우 다음 순서로 점검:

1.  **트리거(Trigger) 불발:**
    *   *현상:* 매매 횟수가 극도로 적거나(주당 1회 미만), 특정 종목만 반복 매매.
    *   *액션:* 진입 장벽(Threshold)을 낮추고(예: Signal > 0.7 -> 0.5), 노이즈가 아닌 신호가 들어오는지 확인.

2.  **적용(Execution) 지연:**
    *   *현상:* 신호 발생 시점(Close)과 체결 시점(Next Open)의 괴리(Gap)로 인한 손실.
    *   *액션:* Tech/Bio 특성상 갭락/갭상 빈번. TWAP(시간가중평균) 매매 도입 시뮬레이션.

3.  **노출(Exposure) 과소:**
    *   *현상:* 예측 정확도(Hit Ratio)는 높은데 계좌 수익률이 낮음.
    *   *액션:* 켈리 베팅(Kelly Criterion) 비율 점검. 확신도가 높을 때 비중을 충분히 싣고 있는지(0.84 Max가 충분한지) 확인.

4.  **비용(Cost) 과다:**
    *   *현상:* Gross Return은 우상향이나 Net Return이 횡보.
    *   *액션:* 회전율(Turnover) 강제 제한 (일일 리밸런싱 -> 주간 리밸런싱 변경 고려).

5.  **레짐(Regime) 불일치:**
    *   *현상:* Tech/Health 섹터 전체가 횡보/하락장인데 Long Only 전략 고수.
    *   *액션:* 시장 지표(S&P500 MA200 등) 하회 시 현금 비중 100%로 전환하는 'Regime Filter' 작동 여부 확인.
