## TOP5 우선순위(24~48h) — “명령형 체크리스트”
(누수/과최적화/서바이버십/비용/운영리스크 순으로 선점)

---

### 1) **리밸런스/메트릭 로깅 파이프라인 복구(운영 리스크 최우선)**
**왜 필요?**  
현재 `worst_mdd: None`, 리밸런스 핀포인트가 `--base-log` 경로 오류/CSV 파싱 실패로 “관측 불능” 상태입니다. 자동루프에서 “성능이 안 움직이는 이유”를 분해할 수 없습니다(= 운영 리스크 + 디버깅 불가).

**위험/부작용**  
- 로깅 추가로 실행시간/디스크 증가  
- 로그 포맷 변경 시 기존 리포트 도구가 깨질 수 있음(버전 태깅 필요)

**최소 실험(공유 실험: E5)**  
- (E5-a) 리밸런스 로그를 **단일 소스(예: JSONL)** 로 강제 저장 + 리포트 도구 입력을 그 포맷으로 고정  
- (E5-b) 백테스트 종료 시 `worst_mdd`, turnover, 비용 포함 PnL 분해를 **필수 산출**로 gate  
- (E5-c) 실패 시 “원인+재현 커맨드+해시”를 next_commands 3줄에 자동 기록

**PASS 조건**  
- 모든 런에서 `worst_mdd != None`  
- `rebalance.jsonl(or csv)`가 생성되고 pinpoint 도구가 **에러 없이** diff를 출력  
- next_commands가 공백이 아니라 **재현 가능한 3줄 커맨드**로 채워짐

---

### 2) **누수(lookahead) 센티넬 실험을 ‘항상’ 돌리기(과최적화/누수 우선 차단)**
**왜 필요?**  
OOS가 “안 움직이거나” 갑자기 좋아질 때 1순위 원인은 누수/미세 lookahead 입니다. 특히 리밸런스/피처 조인/시가-종가 사용 혼합에서 자주 발생합니다.

**위험/부작용**  
- 센티넬 실험이 추가되어 48h 예산의 일부를 소모  
- 너무 엄격한 gate로 정상 개선도 차단할 수 있음(임계치 조정 필요)

**최소 실험(공유 실험: E1)**  
- (E1-a) **피처/레이블 타임시프트 테스트**: 모든 입력 피처를 +1 bar(미래)로 민 뒤 성능이 유지되면 누수 의심  
- (E1-b) **거래가능 시점 제약 테스트**: 신호 생성 시점(T)과 체결 시점(T+1 open 등)을 강제 분리  
- (E1-c) **랜덤 날짜/퍼뮤테이션**: 날짜 셔플에서 성능이 의미있게 남으면 누수/평가버그 의심

**PASS 조건**  
- (E1-a) 미래 시프트에서 성능이 **유의미하게 붕괴**(예: OOS mean이 20~30% 이하로 하락)  
- (E1-b) 체결 시점 분리 후에도 OOS가 “비정상 급락”하지 않음(현실 제약에 견딤)  
- (E1-c) 퍼뮤테이션에서 성능이 0 근처(또는 음수 근처)로 수렴

---

### 3) **비용/슬리피지/차입(숏) 비용을 강제 반영(“거짓 알파” 제거)**
**왜 필요?**  
현재 리밸런스 로그도 없고 비용 분해도 불명확합니다. 노출(min/max 0.47~0.84)이면 회전이 조금만 커도 비용에 취약합니다. “성능이 안 움직임”도 사실상 비용이 알파를 상쇄하는 경우가 많습니다.

**위험/부작용**  
- 단기적으로 성능 수치가 악화되어 실험이 모두 FAIL로 보일 수 있음(하지만 현실성 확보가 우선)  
- 비용 파라미터 과대 적용 시 지나친 보수화

**최소 실험(공유 실험: E2)**  
- (E2-a) **bps 슬리피지 + 커미션 + half-spread** 기본 비용모델 on/off 비교  
- (E2-b) **turnover cap**(예: 일/주당 최대 회전율) 도입 전/후 비교  
- (E2-c) 숏 사용 시 **borrow fee/locate 실패 확률(보수적)** 시나리오 추가(없으면 “숏 금지” 시나리오로 대체)

**PASS 조건**  
- 비용 ON에서도 OOS mean이 **0 근처로 붕괴하지 않음**(전략이 비용 내성 보유)  
- turnover cap 적용 후 OOS min(바닥 성과)이 개선되거나, 동일 성과 대비 turnover가 하락  
- 비용 분해 리포트에서 “총 PnL – 비용 = 순 PnL” 일관성 확보

---

### 4) **서바이버십/유니버스 고정(Tech+Healthcare 8~14) + 운영 가능성 검증**
**왜 필요?**  
“현재 존재하는 종목만으로 과거를 돌리는” 서바이버십 편향을 제거해야 합니다. 또한 미국주식 only, Tech+Healthcare 중심(8~14) 제약을 **명시적 유니버스 레이어**로 고정해야 실험 간 비교가 깨끗해집니다(ETF 매매는 제외).

**위험/부작용**  
- 너무 메가캡 위주로 고정하면 알파가 줄어들 수 있음(대신 견고성↑)  
- 종목 수가 적어지면 분산↓, MDD↑ 가능

**최소 실험(공유 실험: E3)**  
- (E3-a) **정적 유니버스(12종)** 고정: Tech/Healthcare 메가캡 중심(예: AAPL MSFT NVDA GOOGL AMZN META AVGO ORCL / UNH LLY JNJ MRK)  
- (E3-b) **동일 전략 + 동일 비용모델**로 유니버스만 교체하여 성능/회전/드로다운 비교  
- (E3-c) 종목별 기여도(Top contributor)와 집중도(HHI 등) 리포트 추가

**PASS 조건**  
- 유니버스 고정 후에도 성과가 “완전 소멸”하지 않음(서바이버십 의존이 아님)  
- 단일 종목 기여도가 과도(예: 총 PnL의 40%+)하면 FAIL → 포지션 상한 강화 필요  
- 8~14 제약을 위반하는 거래가 0건

---

### 5) **노출/헤지/리밸런스 게이트를 ‘고정 규칙’으로 넣어 OOS 바닥(oos_min) 방어**
**왜 필요?**  
현재 노출이 0.47~0.84로 비교적 높고, `oos_min`이 0.43 수준이면 “레짐 한 번”에 전략이 깨질 수 있습니다. 성능이 안 움직이는 것도 헤지/스케일이 신호를 상쇄하거나, 반대로 노출이 과해 비용+변동성에 먹히는 구조일 수 있습니다.

**위험/부작용**  
- 과도한 헤지/볼타겟은 알파를 죽일 수 있음  
- 게이트가 많아지면 트레이드 빈도 급감(신호 미적용)

**최소 실험(공유 실험: E4)**  
- (E4-a) **gross/net exposure 하드밴드**(예: gross 0.6~0.9, net -0.2~0.2 또는 전략 목적에 맞게) 강제  
- (E4-b) **vol targeting**(실현변동성 기반) on/off  
- (E4-c) 리밸런스 빈도(48h 루프 내에서) 2수준만 테스트: “기본” vs “turnover cap과 연동된 느린 리밸런스”

**PASS 조건**  
- `oos_min` 개선(최저 성과 방어) 또는 worst_mdd 감소  
- 노출 게이트 위반 0건  
- 헤지/볼타겟 적용 후에도 순성과가 비용 대비 의미있게 유지

## 48시간 자동 루프용 “실행 가능한 Patch/실험” 5개(3~5 제한 준수)
아래 5개만 돌리고, 나머지는 이 5개 결과로 분기하세요.

### E1) Leakage Sentinel Pack
1) **실험 정의**: 피처 +1 시프트 / 체결시점 T+1 강제 / 날짜 퍼뮤테이션 3종 세트  
2) **게이트**: 미래시프트 성능 붕괴 + 퍼뮤테이션 성능 0 근처 + 체결 분리 후 비정상 급락 없음  
3) **기대 관측치**: “정상 전략”이면 센티넬에서 성능이 무너지고(=누수 없음), 원래 설정에서만 성능이 남음

### E2) Cost Reality Pack
1) **실험 정의**: 비용모델 on/off + turnover cap + (가능시) borrow/숏 제약 시나리오  
2) **게이트**: 비용 ON 순성과가 0으로 붕괴하지 않음 + turnover cap이 효율 개선  
3) **기대 관측치**: 성능이 안 움직이던 이유가 “비용 상쇄”인지 즉시 판별(총PnL vs 비용)

### E3) Universe Survivorship-Control Pack (US Tech+HC 8~14 고정)
1) **실험 정의**: 정적 12종 유니버스에서 동일 전략 재평가 + 기여도/집중도 리포트  
2) **게이트**: 8~14 준수 + 단일 종목 과집중 경보 시 FAIL  
3) **기대 관측치**: 성능이 특정 생존 종목/편향에 의존하는지 제거 후 확인

### E4) Exposure/Hedge Guard Pack
1) **실험 정의**: gross/net 밴드 + vol targeting + 리밸런스 속도 2수준  
2) **게이트**: 밴드 위반 0 + worst_mdd 감소 또는 oos_min 개선  
3) **기대 관측치**: “안 움직임”이 헤지 과다/노출 과다 중 무엇인지 노출-성과 탄력으로 드러남

### E5) Rebalance+Metrics Logging Patch
1) **실험 정의**: 리밸런스 로그 단일 포맷 저장 + worst_mdd/turnover/cost/PnL분해를 강제 산출 + 도구 입력 경로 자동 주입  
2) **게이트**: pinpoint 리포트가 에러 없이 생성 + worst_mdd 계산 완료  
3) **기대 관측치**: “성능 정체”의 원인을 트레이드 단위로 추적 가능(언제/무엇이/왜)

## “성능이 안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래를 **로그로 수치화**해서, 원인 트리를 자동으로 태우세요(질문 없이 바로 추가 가능).

### A) Trigger(신호 발생) 문제
- 관측치: 신호 발생 횟수/일, 신호 강도 분포(상위 5% 빈도), 신호가 0으로 클리핑되는 비율  
- 트리거: “신호 발생률 급락”이면 → 게이트/필터가 과도하거나 데이터 결측/정렬 오류

### B) Apply(실행/체결) 문제
- 관측치: 목표 포지션 vs 실제 포지션 괴리(L1), 주문 불발률, 리밸런스 시점 지연  
- 트리거: 괴리↑면 → 노출 밴드/리밸런스 규칙이 신호를 상쇄(“신호는 있는데 못 삼/못 팜”)

### C) Exposure(노출/집중) 문제
- 관측치: gross/net, 종목별 비중 상위 N, HHI, 섹터(Tech/HC) 비중 이탈  
- 트리거: 상위 1~2종목 기여 과대 또는 gross 과다 → 성능이 레짐에 종속, oos_min 악화

### D) Cost(비용) 문제
- 관측치: turnover, 비용(bps) 분해(슬리피지/스프레드/커미션/차입), “총PnL 대비 비용 비율”  
- 트리거: 총PnL은 있는데 순PnL이 평평 → 비용이 알파를 상쇄(리밸런스 느리게/캡/신호 임계 강화로 대응)

### E) Regime(레짐/시장 국면) 문제
- ETF는 **매매 금지**, 단 **관측지표**로만 사용: QQQ/XLK/XLV, VIX(또는 VVIX), UST10Y 같은 레짐 태그  
- 관측치: 레짐별 성과 테이블(상승장/하락장/고변동/저변동), 레짐 전환 시 성과 붕괴 시점  
- 트리거: 특정 레짐에서만 수익 → 헤지/노출을 레짐 태그로 스위칭하거나(단순 2상태), 최소한 “레짐 감지 시 리스크 축소” 게이트 추가

---

### 즉시 실행 순서(권장)
1) **E5 먼저**: 로깅/메트릭 복구 없으면 나머지 실험이 의미 없음  
2) **E1 동시**: 누수 의심을 24h 내에 종결  
3) **E2 → E4**: 비용이냐 노출이냐를 먼저 가르고  
4) **E3**: 유니버스 고정으로 서바이버십/집중 리스크를 정리

이 5개만 48시간 자동 루프에 태우면, “성능 정체”가 **(1) 누수/평가버그 (2) 비용 상쇄 (3) 실행/노출 게이트 상충 (4) 유니버스 편향 (5) 레짐 취약** 중 어디인지 강제로 갈라집니다.
