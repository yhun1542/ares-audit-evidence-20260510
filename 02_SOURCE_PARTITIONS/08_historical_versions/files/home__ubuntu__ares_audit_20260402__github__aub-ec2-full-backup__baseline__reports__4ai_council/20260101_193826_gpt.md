# TOP5 우선순위 제안 (각 항목: 왜/위험/연결 실험/패스 조건)

## 1) **누수(temporal leakage)·as-of 무결성·purge/embargo 강화**
### (a) 왜 필요한지
- candidate 성능이 lockbox에서 크게 개선된 상태이므로, **피처 생성/정규화/리밸런싱 타이밍** 중 하나라도 미래정보가 섞이면 “가짜 개선”이 가장 흔한 원인.
- 특히 **기업행사(earnings/분할) 반영 시점**, **리턴 라벨과 피처의 인덱스 정렬**, **전체기간 통계(스케일러/윈저라이즈)**가 대표 누수 포인트.

### (b) 위험/부작용
- 엄격한 as-of/purge 적용 시 단기적으로 성능이 떨어질 수 있음(정상).
- 학습 데이터가 줄어 분산↑ → 과최적화 방지에는 유리하나 “좋아 보이던 알파”가 사라질 수 있음.

### (c) 최소 실험(공유 실험에서 선택)
- **E1**, **E5** (아래 정의 참조)

### (d) PASS 조건
- **E1 통과(누수 의심 시그널 0개)** + lockbox 성능이 “유의미하게 붕괴하지 않을 것”
  - 예: lockbox_mean **≥ champion 대비 -5% 이내 유지** AND lockbox_min **≥ 0.0**(현재 candidate 수준 유지가 최선)
- E5(기업행사/데이터품질) 통과 시 “운영 가능한 알파”로 승격 가능

## 2) **비용 미반영/슬리피지·유동성·(가능하면)차입비용까지 포함한 현실화**
### (a) 왜 필요한지
- Tech/Healthcare는 대형주도 많지만, 8~14종목 집중 포트는 **회전율/체결비용**이 곧 성과를 갉아먹음.
- lockbox_min이 양수로 바뀐 상태에서도 비용 스트레스에서 무너지면 “실전 불가”.

### (b) 위험/부작용
- 비용 모델이 과도하게 보수적이면 알파가 과소평가될 수 있음.
- 반대로 비용을 너무 낙관하면 락박스에서 “좋은데 실전에서 망하는” 형태로 이어짐.

### (c) 최소 실험
- **E2**, **E3**  
  - (E3의 포지션/턴오버 제약이 비용과 직결)

### (d) PASS 조건
- 비용(슬리피지/수수료) 포함 후에도:
  - lockbox_mean **≥ champion**(또는 최소 candidate의 90% 유지)
  - lockbox_min **≥ 0**
  - turnover 상한(예: 일간 30~50% 등 시스템 기준)에 **안정적으로 수렴**(제약 걸었을 때 성능 붕괴 X)

---

## 3) **서바이버십/기업행사/데이터갭 운영 리스크 차단(재현성 확보)**
### (a) 왜 필요한지
- 백테스트에서 잘 나오는데 라이브에서 깨지는 1순위: **심볼 변경, 상장폐지, 분할/병합, earnings 캘린더, 결측치**.
- Tech/Healthcare는 이벤트 드리븐(특히 HC) 변동이 커서 **결측 처리/이벤트 처리**가 곧 리스크 관리.

### (b) 위험/부작용
- 엄격한 데이터 품질 필터링 시 거래 가능 종목이 줄어 집중도↑(리스크↑) 또는 기회 손실.

### (c) 최소 실험
- **E5**, **E1**

### (d) PASS 조건
- 데이터 품질 센티넬이 “차단/대체/스킵”을 일관되게 수행하고,
- 동일 기간 재실행 시 결과가 **결정론적으로 재현**(seed/데이터 스냅샷/룰 기반)

## 4) **포트폴리오 구성(8~14종목·Tech+HC 중심)에서 의도치 않은 노출(베타/팩터/단일종목) 억제**
### (a) 왜 필요한지
- “전략 알파”가 아니라 **단순 QQQ 베타** 또는 **M7 집중**으로 성과가 난 경우, 레짐 전환에서 급격히 무너짐.
- 8~14종목 집중은 **단일 종목 이벤트 리스크**가 매우 커서, 구성 규칙이 핵심.

### (b) 위험/부작용
- 노출 제약(섹터/베타/포지션 상한) 걸면 백테스트 성과가 내려갈 수 있음(정상).  
- 하지만 drawdown/최저성과가 개선되면 실전에 더 적합.

### (c) 최소 실험
- **E3**, **E4** (레짐 게이트와 결합 시 drawdown 안정화 확인)

### (d) PASS 조건
- worst_mdd가 개선되거나 최소한 악화되지 않을 것(예: 현재 candidate worst_mdd≈-0.048 대비 **-0.06 이내 유지**)
- 최대 단일 종목 기여/리스크가 상한 이하(예: 기여도/비중 상한 준수)
- Tech+HC 비중 규칙 준수(ETF 매매 없이)

---

## 5) **레짐(변동성/금리/리스크온오프)에서 “트레이드 게이트”를 둬서 락박스 최저 성능 방어**
### (a) 왜 필요한지
- lockbox_min이 개선된 전략을 “안전하게” 만들려면 평균보다 **꼬리(min) 방어**가 중요.
- ETF는 거래하지 않더라도 **시장 레짐 관측 지표**로는 매우 유용(예: QQQ/XLK/XLV, VIX proxy 등).

### (b) 위험/부작용
- 게이트가 많아지면 룰이 레짐에 과최적화될 수 있음(특히 데이터 짧을 때).
- 게이트 오작동 시 기회비용(수익 구간을 놓침) 발생.

### (c) 최소 실험
- **E4**, **E2**(비용+레짐 결합 시 “쉬는 구간”의 비용/턴오버 감소 확인)

### (d) PASS 조건
- lockbox_min(또는 하위 5% 성과) 개선이 명확할 것  
  - 예: lockbox_min **≥ 0 유지** 또는 하방 꼬리(최악 구간) 손실 폭 감소
- 거래 빈도/턴오버가 감소하거나 동일 수준 유지

# 48시간 자동 루프 투입용 “공유 실험 5개” (E1~E5)
각 실험은 **(1) 실험 정의 (2) 게이트 (3) 기대 관측치**로 작성.  
(이 5개만 돌리면 TOP5 우선순위 모두 커버)

---

## E1) Temporal as-of + Purge/Embargo 누수 차단 실험
1) **실험 정의**
- 피처/라벨 생성 전 구간에 대해:
  - [ ] 모든 피처를 **as-of 타임스탬프**로 강제(미래 값 접근 불가)
  - [ ] 학습/검증 분할에 **purge k일 + embargo k일** 적용(예: 5~20 trading days sweep는 “옵션”이 아니라 기본값 1개로 고정)
  - [ ] 스케일링/윈저라이징을 **train-fold 내부에서만 fit**
- 결과를 champion vs candidate에 동일 적용하여 비교

2) **게이트**
- [ ] “피처 타임 인덱스가 라벨보다 늦지 않음” 자동 검사 100% 통과
- [ ] lockbox_min ≥ 0.0 (또는 candidate 대비 과도한 붕괴 없음)
- [ ] fold별 성과 분산이 비정상적으로 줄지/늘지(누수 시 특정 폴드만 폭발하는 경향)

3) **기대 관측치**
- 누수 있으면 성능이 **뚜렷하게 하락**하거나 특정 폴드만 붕괴
- 누수 없으면 평균은 소폭 감소 가능하나 **min/드로우다운 안정** 유지

---

## E2) 비용/슬리피지/유동성 스트레스(현실성) 실험
1) **실험 정의**
- [ ] 고정된 비용 모델을 “보수적으로” 1세트로 적용(스윕 폭발 금지):
  - per-trade bps + spread/impact 간단 모델
  - ADV 기반 체결 상한(예: 일 거래량의 x% 이내)
- [ ] 비용 포함 성과를 lockbox 중심으로 재평가

2) **게이트**
- [ ] 비용 포함 lockbox_mean이 champion 이상(또는 최소 악화폭 제한)
- [ ] turnover가 상한 이내로 자동 수렴(제약 위반 시 FAIL)
- [ ] lockbox_min ≥ 0.0 (특히 candidate의 강점 유지 여부 확인)

3) **기대 관측치**
- 과도한 회전이 알파였으면 성과가 크게 훼손
- 진짜 알파면 비용 반영 후에도 min 방어가 유지

---

## E3) 포트폴리오 구성 패치(8~14종목, Tech+HC, 포지션 상한, 간단 중립화) 실험
1) **실험 정의**
- [ ] 종목 수 **항상 8~14** 유지(미달/초과 시 리밸런싱 규칙 명시)
- [ ] 섹터: **Tech+Healthcare 중심**(예: 두 섹터 합 최소 비중/나머지 상한)
- [ ] 단일 종목 비중 상한(예: 12~15%) + 리밸런싱 시 과도한 매매 억제
- [ ] (옵션) 간단한 베타/시장중립을 “완전 중립”이 아니라 **노출 상한**으로만 적용

2) **게이트**
- [ ] 제약 위반 0회(락박스 포함)
- [ ] worst_mdd가 candidate 대비 악화 제한(예: -0.06 이내)
- [ ] lockbox_min ≥ 0.0 유지 시 PASS 강함

3) **기대 관측치**
- 평균 수익은 소폭 감소 가능
- 대신 min/드로우다운/단일 이벤트 리스크가 개선

---

## E4) 레짐 관측(ETF는 지표만) 기반 트레이드 게이트 실험
1) **실험 정의**
- [ ] ETF를 매매하지 않고, 지표로만 사용:
  - QQQ/XLK/XLV의 추세/변동성/상대강도 등 1~2개 신호로 “리스크 온/오프”
- [ ] 오프 레짐에서는 (a) 익스포저 축소 또는 (b) 신규 진입 금지 (c) 리밸런싱 빈도 감소 중 1개로 단순화

2) **게이트**
- [ ] lockbox_min 개선(또는 하위 꼬리 손실 축소)
- [ ] turnover 감소 또는 동일 수준 유지
- [ ] 규칙 복잡도 증가 없이 재현 가능(룰 1~2개로 제한)

3) **기대 관측치**
- 평균은 비슷하거나 약간 감소
- min/최악 구간에서 성과가 안정화되면 성공

---

## E5) 운영 리스크 패치(기업행사/결측/이벤트 캘린더) 실험
1) **실험 정의**
- [ ] split/dividend/심볼변경 조정의 as-of 적용 검증(가격/거래량 연속성)
- [ ] 결측치 처리 규칙 고정(드랍/전진채움/대체 중 1개, 로그로 남김)
- [ ] (Healthcare 특히) earnings 전후 N일 “신규 진입 제한” 같은 **블랙아웃 룰**을 옵션으로 1개만 추가

2) **게이트**
- [ ] 데이터 품질 경고율/스킵율이 기준 이내(너무 높으면 실전 불가)
- [ ] 재실행 결과 동일(결정론)
- [ ] lockbox_min과 worst_mdd가 유의미하게 악화되지 않을 것

3) **기대 관측치**
- 성능 자체보다 “터지지 않음/재현성”이 개선
- 블랙아웃이 유효하면 tail-risk가 줄어듦

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래 트리는 **각 노드별로 로그/리포트에 반드시 찍을 관측치**를 명령형으로 정리했습니다.

## A) Trigger(신호가 생성되는가?)
- [ ] **신호 발생 빈도**(일별/주별)와 **상위/하위 신호 분포**를 lockbox 기간에 출력
- [ ] 상위 신호 종목이 **항상 동일(M7 고정)**인지 점검(서바이버/베타 의심)
- [ ] 신호가 “0에 수렴/클리핑”되는지(스케일러, 결측 처리 후) 확인

## B) Apply(신호가 포지션으로 전환되는가?)
- [ ] 신호→주문→체결(가정)까지 **전환율**(trade rate) 출력
- [ ] 8~14 종목 제약 때문에 **신호가 버려지는 비율**(drop due to constraints) 출력
- [ ] 리밸런싱 타이밍(장중/종가/익일 시가) 변경에 따른 성과 민감도(누수/슬리피지 단서)

## C) Exposure(의도한 노출인가?)
- [ ] 섹터 비중(Tech/HC)과 상위 종목 편중도를 lockbox에서 시계열로 기록
- [ ] 시장 베타/QQQ 상관을 롤링으로 출력(알파 vs 베타 구분)
- [ ] 단일 종목 손익 기여도(Top contributor)로 “한두 종목이 다 먹임” 여부 확인

## D) Cost(비용이 알파를 잠식하는가?)
- [ ] gross→net 브리지 리포트(거래비용/슬리피지/턴오버로 성과가 얼마나 깎였는지) 자동 출력
- [ ] 성과가 좋은 구간에서 turnover가 과도하게 튀는지 확인(과최적화 단서)

## E) Regime(레짐이 바뀌었는가?)
- [ ] VIX proxy/금리 proxy/QQQ 추세 상태별로 성과를 bucketting(ETF는 지표만)
- [ ] 레짐별로 **승률/손익비/최악일** 비교 → 게이트(E4) 필요성 판단

---

## 24~48시간 운영 순서(권장)
