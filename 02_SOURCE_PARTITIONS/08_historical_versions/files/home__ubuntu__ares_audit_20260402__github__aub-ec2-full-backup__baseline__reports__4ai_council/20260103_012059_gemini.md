### [우선순위 TOP 5 제안: 24~48시간 루프]

#### 1. Degenerate Folds (죽은 구간) 소생 패치
*   **(a) 이유:** 현재 `degenerate_folds: [1, 2, 3, 8]` 상태는 전체 백테스트/검증 기간의 40%에서 거래가 없거나 로직이 붕괴됨을 의미. 이 상태의 `oos_mean: 3.32`는 신뢰할 수 없는 데이터임. 특정 레짐(예: 하락장, 횡보장)에서 포트폴리오 구성을 포기하는 버그일 가능성 높음.
*   **(b) 위험:** 죽은 구간을 살려낼 때 막대한 MDD가 드러나 `oos_mean`이 급락할 수 있음.
*   **(c) 실행 실험:**
    *   `EXP_01_RELAX_LIQUIDITY`: 거래량/변동성 필터(Filter) 조건을 20% 완화하여 강제 진입 유도.
    *   `EXP_02_FORCED_MIN_EXPOSURE`: 시그널 강도와 무관하게 Top 3 종목에 최소 10% Exposure 강제 할당.
    *   `EXP_03_DATA_ALIGN_CHECK`: Fold 1,2,3,8 기간의 Tech/Healthcare 섹터 데이터 누락(Null) 여부 검증 코드 삽입.
*   **(d) PASS 조건:** Degenerate Folds 개수가 0개 또는 1개로 감소.

#### 2. `worst_mdd: None` 및 로깅 시스템 복구
*   **(a) 이유:** MDD가 `None`이라는 것은 손실 계산 로직이 작동하지 않았거나, 거래가 아예 없었음을 시사. 또한 `rebalance.csv` 파싱 에러는 비용/턴오버 분석을 불가능하게 함.
*   **(b) 위험:** 시스템 수정 중 과거 로그 데이터 덮어쓰기 위험.
*   **(c) 실행 실험:**
    *   `EXP_04_FIX_METRIC_CALC`: 수익률 배열(Returns Array)이 비어있을 경우 0으로 채우는 예외 처리 및 MDD 계산식 재검증.
    *   `EXP_05_JSONL_LOGGER`: `rebalance` 로그 형식을 CSV에서 JSONL로 변경하고, Flush 빈도를 매 틱(tick)으로 설정.
*   **(d) PASS 조건:** `worst_mdd`가 실수(Float) 값으로 산출됨 + 리밸런싱 로그 파일 용량이 0보다 큼.

#### 3. Tech/Healthcare 섹터 편중 리스크 제어 (Sector Cap)
*   **(a) 이유:** 40%의 Fold가 죽은 이유가 특정 섹터(Tech)가 무너질 때 Healthcare로 로테이션되지 않았기 때문일 가능성.
*   **(b) 위험:** 강제 분산으로 인해 상승장에서의 Alpha(Tech 모멘텀) 삭감.
*   **(c) 실행 실험:**
    *   `EXP_06_SECTOR_HARD_CAP`: 단일 섹터(Tech) 비중 Max 60% 제한, 나머지는 현금 또는 타 섹터(Healthcare) 강제.
    *   `EXP_07_HC_DEFENSIVE`: VIX(ETF 관측지표) > 25 구간에서 Healthcare 상위 3종목 가중치 1.5배 적용.
*   **(d) PASS 조건:** Exposure Max는 유지하되 `oos_min`이 -0.05 이하로 떨어지지 않음.

#### 4. 과최적화 방지: 파라미터 민감도 테스트
*   **(a) 이유:** 현재 OOS Mean 3.32는 비정상적으로 높음. 특정 파라미터(예: 룩백 윈도우)에 과적합되었을 확률 99%.
*   **(b) 위험:** 성능 지표가 '현실적인 수준(예: 0.5~1.0)'으로 급락하여 챔피언 모델 폐기 가능성.
*   **(c) 실행 실험:**
    *   `EXP_08_WINDOW_NOISE`: Lookback Window에 ±10% 랜덤 노이즈 추가 후 성능 유지력 테스트.
    *   `EXP_09_STOP_LOSS_TIGHT`: 손절(Stop Loss) 라인을 현재 설정의 0.5배로 타이트하게 적용해 '운 좋게 버틴' 수익 제거.
*   **(d) PASS 조건:** 파라미터 변경에도 Sharpe Ratio 변동폭이 15% 이내.

#### 5. 비용 구조 현실화 (Slippage/Fee Stress)
*   **(a) 이유:** `rebalance.csv` 오류로 보아 비용 반영이 누락되었을 가능성 큼. 고빈도 매매가 숨어있다면 실제 수익은 마이너스일 수 있음.
*   **(b) 위험:** 전략의 기대 수익률(Edge) 완전 소멸.
*   **(c) 실행 실험:**
    *   `EXP_10_HIGH_COST_SIM`: 슬리피지(bps)를 현재의 3배로 설정하고 백테스트 수행.
*   **(d) PASS 조건:** OOS Mean > 1.0 유지.

### [48시간 자동 루프 정의]

**1. 실험 정의 (Experiment Definition)**
```json
{
  "target": "Fold_Repair_And_Risk_Calc",
  "experiments": ["EXP_01", "EXP_04", "EXP_06"],
  "constraints": {
    "asset_class": "US_Equity_Tech_HC",
    "max_tickers": 14,
    "allow_short": false
  }
}
```

**2. 게이트 (Gate - 진입/기각 조건)**
*   **Gate 1 (Validity):** `degenerate_folds` 리스트 길이가 2 이하인가? (YES -> GO / NO -> DROP)
*   **Gate 2 (Reality):** `worst_mdd` is not None AND `worst_mdd` < 0 (MDD는 음수여야 함).
*   **Gate 3 (Efficiency):** `rebalance_log` 크기 > 1KB (로그 정상 작동 확인).

**3. 기대 관측치 (Expected Observations)**
*   **Case A (성공):** Fold 1,2,3,8이 살아나며 거래 횟수 증가, OOS Mean은 3.3 -> 1.5 수준으로 하락하나 신뢰도 상승.
*   **Case B (실패):** 여전히 특정 Fold에서 거래 없음 -> 데이터 피드(Data Ingestion) 파이프라인 자체 점검 필요.

### [성능 정체 원인 분해 (Debug Logic)]

성능(Score)이 움직이지 않을 때, 다음 순서로 원인을 트리거할 것.

1.  **Trigger Dead (신호 불발):**
    *   *Check:* 시그널 생성 로직의 Threshold가 너무 높아 진입조차 안 하는가?
    *   *Action:* Threshold 강제 0 설정 후 모든 캔들에서 진입 시도해봄.
2.  **Exposure Mismatch (비중 오류):**
    *   *Check:* 시그널은 떴으나 포트폴리오 최적화기(Optimizer)가 `weight=0`을 할당했는가?
    *   *Action:* `EqualWeight`로 강제 고정 후 성과 비교.
3.  **Cost Filtering (비용 삭제):**
    *   *Check:* 예상 수익이 거래 비용(Fee+Slippage)보다 작아 주문이 취소되었는가?
    *   *Action:* 비용 파라미터를 0으로 두고 백테스트.
4.  **Regime Lock (시장 상황):**
    *   *Check:* Tech 섹터 전체가 횡보하여 모멘텀이 없는 구간인가?
    *   *Action:* 지수(QQQ, XLV) 대비 상대 강도(RS) 지표가 작동하는지 확인.
