아래 5개만 24~48시간 루프의 “우선순위 patch/실험”으로 고정하고, 나머지는 보류하라. (누수/과최적화/서바이버십/비용/운영 리스크를 먼저 잠그는 순서)

## TOP5 (24~48h) 명령형 체크리스트

### 1) **Lockbox 무결성/누수(Leakage) 1차 봉쇄 패치**
**(a) 왜 필요한지**
- 현재 Champion과 Candidate가 **lockbox_mean/min이 완전히 동일**하게 찍힌다. 정상이라면 후보 변경 시 lockbox가 미세라도 흔들리는 게 자연스럽다.
- “lockbox 결과 캐시 재사용/데이터 스플릿 고정 오류/피처 산출에 미래값 혼입” 가능성을 최우선으로 제거해야 한다. (이거 미해결이면 이후 개선이 전부 허상일 수 있음)

**(b) 위험/부작용**
- 누수 차단 후 성능이 급락할 수 있다(그게 정상 신호).
- 실험 시간이 늘고, 기존 챔피언이 “가짜로 좋았던” 것으로 판명될 수 있다.

**(c) 최소 실험 2~3개 (48h 루프 형태로)**
1. **[실험 정의] Lockbox 재계산 강제(캐시 무효화) + 해시 로그 추가**
   - 학습/평가 산출물에 `data_hash`, `split_hash`, `feature_hash`, `model_hash`를 로그로 남기고, lockbox는 항상 재실행 옵션을 강제.
   - **[게이트]** 동일 후보를 2회 돌렸을 때 lockbox 결과가 “완전 동일 + 동일 해시”일 때만 통과(비결정성 제거/고정).
   - **[기대 관측치]** 후보가 바뀌면 최소한 lockbox 해시/결과가 변동해야 정상.

2. **[실험 정의] Purged/Embargo TimeSeries CV로 튜닝 재실행(누수 내성 확인)**
   - 이벤트/리밸런스 구간 기준으로 purge(겹침 제거) + embargo(완충 구간) 적용.
   - **[게이트]** 튜닝_mean이 하락해도 좋으나, **lockbox_mean이 챔피언 대비 -0.02 이내** 유지하거나(보수적), MDD/변동이 개선될 것.
   - **[기대 관측치]** 누수 신호가 있으면 튜닝↔락박스 괴리가 줄거나 전체 하향 조정.

3. **[실험 정의] 피처 시점 강제(모든 피처에 “asof timestamp” 강제)**
   - OHLCV/펀더멘털/리비전 데이터가 섞이면 특히 위험.
   - **[게이트]** 미래 참조가 의심되는 피처가 탐지되면 해당 피처 자동 disable.
   - **[기대 관측치]** 성능이 약간 줄더라도 안정성(락박스 재현성/드리프트)이 개선.

**(d) PASS 조건**
- (필수) lockbox가 후보 변화에 따라 **해시/값이 합리적으로 변동**하며, 캐시/고정 오류가 없음이 로그로 입증.
- (성과) cost 반영 전 기준이라도 **lockbox_mean ≥ 1.79 유지**(챔피언 1.7927 근처), 또는 **worst_mdd ≤ -0.11 개선** 중 하나 달성.

---

### 2) **서바이버십/코퍼레이트 액션/델리스팅 리턴 패치**
**(a) 왜 필요한지**
- 미국 주식 백테스트에서 **상장폐지(Delisting) 리턴 누락**, 액면분할/배당/스핀오프 처리 오류는 성과를 “조용히” 부풀린다.
- Tech+Healthcare 중심 8~14종목 운영이면 개별 종목 이벤트 영향이 커서, 데이터 정합성 문제가 바로 실전 손실로 직결.

**(b) 위험/부작용**
- 정합성 강화 후 과거 성과가 하락할 수 있음(정상).
- 데이터 공급원/정정 로직에 따라 backfill 이슈가 생길 수 있음 → 운영 복잡도 증가.

**(c) 최소 실험 2~3개**
1. **[실험 정의] Delisting return/거래정지 처리 규칙 추가**
   - “거래불능 시 0수익” 같은 단순 처리 금지. 가능한 범위에서 delisting return 반영(또는 보수적 상각 규칙).
   - **[게이트]** 델리스팅/정지 이벤트 발생 종목에 대해 리턴이 비정상(0 고정/NaN 연쇄)인 케이스 0건.
   - **[기대 관측치]** 일부 구간 손익/드로우다운이 더 현실적으로 변함.

2. **[실험 정의] Adjusted/Unadjusted 가격 일관성 테스트(배당/분할)**
   - 신호는 unadjusted 기준, 체결/평가는 adjusted 기준 등 혼용되면 치명적.
   - **[게이트]** 가격 체계(Adj/Raw)가 전 파이프라인에서 1가지로 고정되며, 분할일에 비정상 갭/리턴 폭주 0건.
   - **[기대 관측치]** 특정 이벤트 구간의 이상수익이 제거됨.

3. **[실험 정의] Point-in-time 유니버스(최소한 “당시 거래가능” 필터)**
   - 완벽한 PIT가 어렵다면, 최소한 “미래에 생존한 종목만 포함”을 피하도록 상장일/거래가능 여부로 필터.
   - **[게이트]** 백테스트 시작 시점에 아직 상장 전인 종목이 유니버스에 포함되는 케이스 0건.
   - **[기대 관측치]** 과거 초반 성과 과대평가가 줄어듦.

**(d) PASS 조건**
- 데이터 정합성 테스트(델리스팅/분할/배당/거래정지)에서 **하드 에러 0건**.
- lockbox_mean **-0.03 이내 방어** + worst_mdd **-0.115 이하로 악화 금지**(안정성 목표).

---

### 3) **거래비용/슬리피지/회전율(턴오버) 반영 패치 (과최적화/현실성 봉쇄)**
**(a) 왜 필요한지**
- 8~14개 종목 집중 전략은 리밸런스가 잦으면 성과가 비용에 잠식될 확률이 높다.
- 지금 성능 지표가 비용 미반영이면, 최적화가 “턴오버 최대” 쪽으로 기울 수 있다.

**(b) 위험/부작용**
- 비용을 넣으면 성능이 떨어질 수 있음(정상).
- 비용 모델이 과도하게 보수적이면 유효 신호까지 죽일 수 있음.

**(c) 최소 실험 2~3개**
1. **[실험 정의] 2단 비용 모델 도입(커미션+슬리피지)**
   - 슬리피지: `k * ATR` 또는 `k * spread proxy` 같은 단순 모델로 시작(보수적/낙관적 2버전).
   - **[게이트]** 비용 반영 후에도 포트폴리오 수익 곡선이 논리적으로 유지(거래 급증 구간에서 성과 급락이 관측되는지 확인).
   - **[기대 관측치]** “좋아 보이던” 고회전 구간의 성과가 눌림.

2. **[실험 정의] 목적함수에 턴오버 페널티 추가**
   - 예: score = return_metric − λ * turnover.
   - **[게이트]** 평균 턴오버가 X% 이상 감소(예: -20%)하면서 lockbox_mean이 -0.02 이내 방어.
   - **[기대 관측치]** 신호가 약하면 성능 거의 동일 + 비용 개선, 신호가 강하면 성능 방어.

3. **[실험 정의] 리밸런스 빈도/임계값 실험(거래 발생 임계치)**
   - 목표비중 변화가 일정 threshold 이하이면 거래 스킵.
   - **[게이트]** 거래 횟수 감소 + MDD 비악화.
   - **[기대 관측치]** 성과는 비슷하고 실현가능성이 올라감.

**(d) PASS 조건**
- **비용 반영 lockbox_mean ≥ (챔피언 lockbox_mean - 0.02)** 이면서,
- worst_mdd **-0.112 보다 악화 금지**, 그리고
- 평균 턴오버 **최소 15~25% 감소**(운영현실성 개선).

---

### 4) **유니버스/섹터 제약(Tech+Healthcare, 8~14종목) 하드코딩 패치 + ETF는 “관측지표”만**
**(a) 왜 필요한지**
- “미국주식 only + Tech/Healthcare 중심 + 8~14종목” 제약을 **백테스트/실행에서 동일하게** 강제해야 운영 리스크가 줄고, 성과 원인도 명확해진다.
- ETF 매매 금지이므로, ETF는 “레짐/리스크 지표”로만 사용(예: QQQ, XLK, VHT, SPY).

**(b) 위험/부작용**
- 제약 강화로 기회가 줄어 성과 하락 가능.
- 섹터 분류(GICS 등) 데이터 품질 이슈가 있으면 종목 누락/오분류 가능.

**(c) 최소 실험 2~3개**
1. **[실험 정의] 유니버스 생성기를 단일 모듈로 고정 + 8~14 강제**
   - Tech/Healthcare 외 종목은 원천 차단(혹은 최대 1~2개 예외 허용 정책을 명시).
   - **[게이트]** 모든 백테스트 날짜에서 보유종목 수 8~14 유지(예외 로그 0건).
   - **[기대 관측치]** 포트폴리오가 의도대로 단순해지고 설명가능성이 증가.

2. **[실험 정의] 섹터 중립/상한(Tech vs Healthcare 비중 상한)**
   - 예: 한 섹터 70% 상한, 또는 50/50 타깃 범위.
   - **[게이트]** 섹터 편중 완화 + worst_mdd 개선 또는 비악화.
   - **[기대 관측치]** 특정 섹터 급락 레짐에서 방어력 증가.

3. **[실험 정의] ETF 관측지표 기반 “위험온/오프” 포지션 스케일링(매매는 주식만)**
   - 예: QQQ/SPY 모멘텀↓ 또는 VHT/XLK 상대강도 변화 시 총 익스포저 0.5배.
   - **[게이트]** 드로우다운 테일(-10%~-12%) 구간 빈도 감소.
   - **[기대 관측치]** 레짐 전환 구간에서 MDD가 줄고 수익은 약간 희생.

**(d) PASS 조건**
- 제약 위반(종목 수/섹터/미국 외) **0건**.
- lockbox_mean **-0.02 이내 방어** + worst_mdd **-0.11 근처 유지 또는 개선**.

### 5) **운영 리스크(48시간 자동루프) 안정화 패치: 재현성/중단복구/모니터링**
**(a) 왜 필요한지**
- 자동 루프는 “좋은 전략”보다 “깨지지 않는 파이프라인”이 먼저다.
- 재현성/중단복구가 없으면 성능이 안 움직일 때 원인분해 자체가 불가능해진다.

**(b) 위험/부작용**
- 초기엔 성능 개선이 아니라 “운영 부채 상환”이라 지표 변화가 없을 수 있음.
- 로깅/아티팩트 저장으로 디스크/비용 증가.

**(c) 최소 실험 2~3개**
1. **[실험 정의] run_id 기준 아티팩트 고정 저장(데이터 스냅샷/피처/모델/결과)**
   - **[게이트]** 동일 run_id 재실행 시 결과가 완전 동일(또는 난수 seed가 다르면 그 차이가 로그로 설명됨).
   - **[기대 관측치]** “성능이 안 움직임”이 진짜인지(변화 없음) vs 파이프라인이 멈춰있는지 구분 가능.

2. **[실험 정의] 실패 내성: 부분 실패 시 다음 단계 스킵/롤백 규칙**
   - 예: lockbox 실패 시 champion 유지 + 알림 + 다음 실험 진행.
   - **[게이트]** 48시간 동안 무인 실행에서 전체 파이프라인이 멈추는 케이스 0회.
   - **[기대 관측치]** 운영 중단 리스크 감소.

3. **[실험 정의] 핵심 KPI 모니터(성능/노출/비용/턴오버/제약 위반)**
   - **[게이트]** KPI 리포트가 매 실행 생성되고, 이상치(턴오버 급증/제약 위반) 시 즉시 Fail 처리.
   - **[기대 관측치]** “성능 정체”가 신호 문제인지 비용/노출 문제인지 즉시 보임.

**(d) PASS 조건**
- 48시간 동안 자동 루프에서 **중단 없이 2회 이상 완주**.
- 각 실행에서 KPI 리포트 생성 + 제약 위반 0건.

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래를 “진단 트리”로 고정하고 매 실행마다 자동 출력하라.

### A. Trigger(신호 발생) 문제
- **체크**: 알파 스코어 분산/엔트로피가 너무 낮아 “매번 비슷한 랭킹”인지
- **체크**: 상위/하위 신호 스프레드(예: top-bottom 예측 수익) 자체가 0에 수렴하는지
- **결론 패턴**
  - 스프레드가 0 근처 → 피처가 죽었거나(데이터 지연/결측), 과도한 정규화/클리핑으로 신호가 사라짐

### B. Application(적용/실행) 문제
- **체크**: 신호→포지션 변환에서 제약(8~14, 섹터 상한, 리밸런스 임계값)이 신호를 거의 다 상쇄하는지
- **체크**: 포지션이 실제로 바뀌는지(일별/리밸런스별 포지션 변화량)
- **결론 패턴**
  - 신호는 있는데 포지션 변화가 거의 없음 → 매핑/제약/버그(캐시된 포지션) 가능

### C. Exposure(노출) 문제
- **체크**: 팩터 노출(시장 베타, 섹터 베타, 사이즈/밸류/모멘텀 대략 프록시)을 단순 회귀로 분해
- **체크**: Tech/Healthcare 내에서도 “사실상 1~2개 대형주에 편중”되는지
- **결론 패턴**
  - 성과가 시장/QQQ 베타로 대부분 설명 → 진짜 알파가 아니라 레버드 베타일 가능성

### D. Cost(비용) 문제
- **체크**: 총수익 vs 비용 차감 후 수익의 갭(거래가 많은 달/주에 갭이 커지는지)
- **체크**: 턴오버 급증 구간이 성과 둔화 구간과 일치하는지
- **결론 패턴**
  - 비용 차감 후만 성능이 죽음 → 리밸런스/임계값/턴오버 페널티 우선

### E. Regime(레짐) 문제
- **체크**: ETF 관측지표(예: QQQ 추세, SPY 변동성, XLK vs VHT 상대강도)로 구간을 2~4개로 나눠 성과 테이블 출력
- **체크**: 챔피언이 “특정 레짐에서만” 강하고 나머지는 0인지
- **결론 패턴**
  - 레짐 의존이 크면 → 레짐 스케일링(익스포저 조절) 또는 레짐별 모델/룰 분기 실험만 제한적으로 허용

---

## 실행 순서(48h 자동루프에 바로 꽂기)
1. **Leakage/Lockbox 무결성 패치(1번)**를 먼저 넣고, lockbox 재계산/해시 로그를 강제하라.
2. 그 다음 **서바이버십+코퍼레이트 액션(2번)** 테스트를 “하드 게이트”로 올려라(실패 시 후보 자동 폐기).
3. 이후 **비용+턴오버(3번)**를 목적함수/리포트에 강제 반영하라.
4. 그 다음에만 **유니버스/제약/ETF 관측지표(4번)**와 **운영 안정화(5번)**를 붙여라.

이 5개가 통과되면, 그때부터 성능 개선(알파 확장) 실험을 해도 “진짜 개선”만 남는다.
