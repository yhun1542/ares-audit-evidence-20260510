## 1. TOP 5 우선순위 제안

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### P1. 시그널 트리거 분포 감사 (Signal Fire Rate Audit)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- 시그널이 너무 드물면(fire rate <5%) → 대부분 시간 idle → 변화 체감 불가
- 시그널이 너무 잦으면(>40%) → 노이즈 트레이딩 → 비용에 잠식

**(b) 위험/부작용**
- 측정 오버헤드 낮음
- 부작용: 없음 (읽기 전용 진단)

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|---|---|---|---|
| P1-A | 전 모듈별 fire_rate 히스토그램 출력 | 완료 시 리포트 생성 | fire_rate 분포 시각화 |
| P1-B | fire_rate <3% 모듈 리스트 추출 | 리스트 비어있지 않음 | 죽은 시그널 후보 식별 |
| P1-C | fire_rate >50% 모듈 리스트 추출 | 리스트 비어있지 않음 | 과잉 시그널 후보 식별 |

**(d) PASS 조건**
```
fire_rate 분포 확보 + 이상치(상위/하위 10%) 모듈 최소 2개 식별
```

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### P2. Position Sizing 민감도 검증
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- 현재 sizing이 고정(equal-weight) 또는 극보수적이면 → 시그널 품질과 무관하게 수익 평탄화
- tuning/lockbox 결과가 거의 동일 = sizing이 변동을 흡수 중일 가능성

**(b) 위험/부작용**
- aggressive sizing → MDD 급증 위험
- 실험은 tuning set only로 격리

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|---|---|---|---|
| P2-A | base_weight ×1.5 (aggro) | tuning only, fold14_mdd < -15% | mean 변화율 >5% 또는 MDD 악화 관측 |
| P2-B | base_weight ×0.7 (conserv) | tuning only | mean 변화율 확인 (방향 반대?) |
| P2-C | conviction-weighted (시그널 강도 비례) | 코드 존재 시 | Sharpe 개선 여부 |

**(d) PASS 조건**
```
sizing 변경 시 tuning_mean Δ > ±3% 관측 → sizing이 유효 레버라고 확인
sizing 변경 시 Δ ≈ 0% → sizing 아닌 다른 레버 탐색 필요
```

### P3. 거래비용 현실화 (Cost Injection)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- 비용=0 백테스트는 환상 → lockbox가 live에서 붕괴 원인
- 슬리피지 10bp + 커미션 5bp 적용 시 전략 생존 여부 확인

**(b) 위험/부작용**
- 수익률 전반적 하락 예상 (이게 현실)
- 모든 후보가 비용 후 음수면 전략 자체 재검토 필요

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|---|---|---|---|
| P3-A | cost=10bp (one-way) 적용 | lockbox_mean > 1.2 (생존) | 비용 후 수익률 분포 |
| P3-B | cost=20bp (보수적) 적용 | lockbox_mean > 1.0 | 전략 생존 한계선 |
| P3-C | turnover 측정 (연간 회전율) | 리포트 출력 | 회전율 × 비용 = 연간 마찰 |

**(d) PASS 조건**
```
cost=10bp 적용 후 lockbox_mean ≥ 1.3 유지 → 운영 가능
cost=10bp 적용 후 lockbox_mean < 1.1 → 회전율 감소 또는 전략 폐기 검토
```

### P4. 레짐 다양성 검증 (Out-of-Regime Stress)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- tuning/lockbox 모두 2020-2024 QE→긴축 전환기
- 단일 레짐 과적합 시 2025 레짐 전환에 붕괴

**(b) 위험/부작용**
- 과거 데이터 부족 시 검증 불가
- 합성 스트레스 시나리오는 현실과 괴리 가능

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|---|---|---|---|
| P4-A | 2022-Q4 단독 fold (베어마켓) | mdd < -20% | 하락장 생존력 |
| P4-B | 2020-Q1 단독 fold (코로나 크래시) | 데이터 존재 시 | 급락 대응력 |
| P4-C | VIX>30 구간만 필터 후 성과 | 리포트 출력 | 고변동성 레짐 성과 분리 |

**(d) PASS 조건**
```
P4-A/B에서 mdd < -25% 유지 + 회복 관측 → 레짐 다양성 OK
모든 스트레스 구간 mdd > -30% → 레짐 취약, 헤지 모듈 필요
```

### P5. 모듈 상관관계 감사 (Correlation Audit)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한지**
- 8~14개 모듈이 동일 팩터(모멘텀?) 변형이면 → 분산 효과 환상
- 고상관 모듈 제거 → 복잡도↓, 과적합↓, 비용↓

**(b) 위험/부작용**
- 잘못 제거 시 엣지 손실
- 상관관계 ≠ 인과관계

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|---|---|---|---|
| P5-A | 모듈간 일별 시그널 상관행렬 | corr > 0.8 쌍 식별 | 중복 모듈 후보 |
| P5-B | corr > 0.85 쌍 중 1개 제거 후 성과 | tuning_mean 하락 < 3% | 복잡도 감소 + 성과 유지 |
| P5-C | PCA로 실질 팩터 수 추정 | 리포트 출력 | 유효 팩터 << 모듈 수 시 정리 대상 |

**(d) PASS 조건**
```
corr > 0.8 쌍 제거 후 tuning_mean Δ < 3% → 모듈 정리 실행
유효 팩터 수 < 모듈 수/2 → 앙상블 구조 재설계 필요
```

## 3. 성능 정체 시 원인 분해 의사결정 트리

```
[진단 결과 분기]

IF fire_rate 분포 이상(P1):
  ├─ <3% 모듈 다수 → 임계값 완화 실험
  └─ >50% 모듈 다수 → 임계값 강화 또는 신호 필터 추가

IF sizing 민감도 0%(P2):
  └─ sizing 아닌 entry/exit 타이밍이 진짜 문제 → 타이밍 모듈 점검

IF cost 적용 후 붕괴(P3):
  ├─ turnover > 300%/yr → 회전율 제한 또는 holding period 연장
  └─ turnover < 100%/yr but 여전히 붕괴 → 엣지 자체 부족

IF 스트레스 레짐 붕괴(P4):
  └─ 단일 레짐 과적합 확정 → 레짐 탐지 + 조건부 전략 분기 필요
