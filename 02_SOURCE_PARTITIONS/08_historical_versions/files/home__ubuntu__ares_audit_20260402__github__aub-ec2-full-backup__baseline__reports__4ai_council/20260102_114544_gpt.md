## TOP5 우선순위(24~48h) — **명령형 체크리스트**
> 원칙: **누수/과최적화/서바이버십/비용 미반영/운영 리스크**를 먼저 제거하고, **미국주식(Tech+Healthcare) 8~14종목**만 거래(ETF는 관측지표만)하도록 고정.

### 1) **리밸런스 로그/리스크 지표 파이프라인 복구(운영 리스크 최우선)**
- [ ] `aub_rebalance_pinpoint`가 읽을 **rebalance.csv/jsonl**을 “항상 생성”하도록 백테스트 출력 포맷을 고정
- [ ] `worst_mdd: None`가 나오지 않게 **MDD/턴오버/거래수/슬리피지**를 강제 계산(없으면 FAIL)
- [ ] `Champion OOS Mean`이 서로 다르게 찍히는 상황(1.88 vs 2.63)을 **단일 계산 경로**로 통일(메트릭 소스 1개)

**왜 필요?**
- 현재 로그가 깨져 있어(파일 경로/JSON 파싱 에러) “성능이 안 움직이는 이유”를 관측으로 분해할 수 없음 → 자동 루프가 **눈이 먼 상태**.

**위험/부작용**
- 지표 계산/로그 IO 증가로 런타임 상승(하지만 48h 루프에서 감당 가능한 수준으로 샘플링/압축하면 됨).

---

### 2) **거래비용(슬리피지/스프레드/임팩트) 모델을 PnL에 강제 반영**
- [ ] 수수료(고정) + 스프레드(유동적) + 임팩트(ADV 기반)로 **단일 비용 함수**를 만들고 “항상 net PnL”로 비교
- [ ] 비용 반영 전/후의 **turnover 대비 성과 민감도**를 자동 리포트(“비용이 알파를 먹는지” 즉시 확인)

**왜 필요?**
- 비용 미반영이면 OOS가 “움직이지 않는 것처럼” 보이거나, 반대로 과대평가되어 챔피언이 굳어짐.

**위험/부작용**
- 비용을 넣으면 단기 성능 급락 가능(정상). 이후엔 turnover 억제/홀딩 연장 실험으로 수습해야 함.

---

### 3) **누수/서바이버십/정렬(lookahead) 자동 감사(Audit) 게이트 추가**
- [ ] 가격/리턴/팩터/재무/이벤트가 **t시점에 이용 가능했는지** “포인트-인-타임”으로 강제
- [ ] 모든 feature를 **1 trading-day 지연**시킨 버전(anti-leak)과 원본을 같이 돌려 **성능 급변 여부**를 감시
- [ ] 종목 유니버스를 “현재 성분”이 아니라 **당시 거래 가능 우주**로 고정(서바이버십 차단)

**왜 필요?**
- OOS가 정체/비정상적으로 높게 유지될 때 1순위 의심이 누수/서바이버십.
- “진짜 알파가 없다” vs “알파가 있는데 비용/노출/레짐에서 눌린다”를 구분하려면 감사가 먼저.

**위험/부작용**
- 감사 통과 후 성능이 내려갈 수 있음(정상). 내려간 폭이 크면 기존 챔피언은 폐기 후보.

---

### 4) **노출(Exposure)·레짐 기반 게이트로 ‘안 좋은 구간’에서 베팅 축소**
- [ ] 현재 노출 min/max(0.47~0.84)가 의미하는 바를 분해: “시그널 부족”인지 “제약”인지 로깅
- [ ] 변동성/스트레스 레짐(VIX, MOVE, SPX drawdown 등 ETF는 **지표로만**)에서 **타겟 노출**을 자동 축소
- [ ] MDD 계산이 살아난 뒤 **DD 기반 리스크 컷**(감산형) 1개만 추가

**왜 필요?**
- OOS 평균은 괜찮은데 `oos_min`이 낮으면(0.43) 보통 레짐/노출 제어가 부족.
- “성능이 안 움직임”은 사실상 **나쁜 구간 손실이 좋은 구간 이익을 상쇄**하는 형태가 많음.

**위험/부작용**
- 레짐 게이트가 과도하면 기회 손실(언더인베스트)로 평균 수익률 감소 가능 → 게이트 임계값을 최소화해야 함.

---

### 5) **전략/우주 제약을 명문화: Tech+Healthcare 8~14종목, ETF 거래 금지(컴플라이언스/안정성)**
- [ ] 거래 우주를 **미국 Tech+Healthcare**로만 구성하고 “동시에 보유 종목 수 8~14” 하드 제약
- [ ] 종목당 비중 상한(예: 15~20%)과 일간 회전율 상한을 추가해 과최적화·비용 폭발 방지
- [ ] ETF는 **관측 지표(레짐/헤지 강도 추정)**로만 쓰고 주문 엔진에서 차단

**왜 필요?**
- 우주/제약이 흔들리면 백테스트가 매번 다른 게임이 되어 “48h 자동 루프 학습”이 무의미해짐.
- 종목 수 고정은 과최적화/서바이버십 효과를 줄이고 운영 난이도를 낮춤.

**위험/부작용**
- 종목 제한으로 분산 감소 → 리스크 지표(MDD/변동성)를 같이 게이트해야 함.

# 48시간 자동 루프용 **실행 Patch/실험 5개(상한 준수)**
> 아래 5개만 돌리고, 나머지는 “관측/리포트”로 해결(케이스 폭발 방지).  
> 각 실험은 **(1)정의 (2)게이트 (3)기대 관측치**로 구성.

---

## 실험 E1) 리밸런스/메트릭 로깅 표준화 패치
1) **정의**
- [ ] 백테스트 종료 시 `rebalance.jsonl`(주문/체결/비용/슬리피지/포지션) + `metrics.json`(oos_mean/min, worst_mdd, turnover, cost%)를 **항상 출력**
- [ ] `aub_rebalance_pinpoint` 입력 경로를 “존재하는 파일”로만 지정(현재 `--base-log`가 문자열로 남아 실패)

2) **게이트**
- [ ] `worst_mdd != None`
- [ ] `rebalance_pinpoint.md`가 “No rebalance data found” 없이 생성
- [ ] oos_mean이 리포트 간 ±1% 이내로 일치(단일 계산 경로)

3) **기대 관측치**
- [ ] “성능 정체”가 실제인지(알파 없음) vs 관측 불능인지(로그 불량) 즉시 분리

**PASS 조건**
- [ ] 위 게이트 3개 모두 만족 + 재현 실행 2회에서 동일 결과(해시만 달라지고 지표 동일)

---

## 실험 E2) 비용 모델 ON(슬리피지/스프레드/임팩트) + 비용 분해 리포트
1) **정의**
- [ ] 비용 함수: `cost = commission + spread(bps) + k * (order_notional / ADV)` 형태로 단순 시작
- [ ] 출력: gross PnL, net PnL, cost%, turnover, ADV 대비 주문비율

2) **게이트**
- [ ] net PnL이 gross PnL보다 항상 낮음(역전 발생 시 FAIL)
- [ ] cost%가 turnover와 양(+)의 상관을 가짐(0.3 이상 같은 단순 기준)

3) **기대 관측치**
- [ ] 성능 정체의 원인이 “비용 상쇄”인지 바로 드러남
- [ ] 이후 최적화 방향이 “시그널”이 아니라 “회전율/홀딩”으로 좁혀질 수 있음

**PASS 조건**
- [ ] net 성과가 합리적 범위로 하락(과도한 플러스 유지 시 누수 의심 트리거) + 비용분해 리포트 생성

---

## 실험 E3) Anti-leak 스모크 테스트(피처 1일 지연 + PIT 우주)
1) **정의**
- [ ] 모든 feature를 1일 지연한 모델을 동일 조건으로 재실행
- [ ] 유니버스를 “당시 거래 가능(상장/거래정지/합병 반영)” 형태로 재구성(서바이버십 제거)

2) **게이트**
- [ ] 원본 대비 성능 변화가 “급락/급등”하면 FAIL로 표시하고 누수 조사 워크플로우로 자동 전환
  - 예: oos_mean이 30~50%+ 급변, 승률/턴오버 패턴이 비정상 변화

3) **기대 관측치**
- [ ] 누수/서바이버십이면 성능이 크게 붕괴하거나 매매 패턴이 달라짐
- [ ] 정상 알파면 완만한 하락(또는 유사) + 비용/레짐 문제가 더 중요해짐

**PASS 조건**
- [ ] anti-leak 버전이 “완전 붕괴”하지 않고, 핵심 패턴(노출/턴오버/섹터 기여)이 유사

---

## 실험 E4) 레짐-노출 게이트(관측지표 기반) 최소 1개만 추가
1) **정의**
- [ ] VIX/금리변동/시장 DD 같은 지표로 레짐 스코어 산출(ETF는 거래 금지, 관측만)
- [ ] 레짐 나쁠 때 목표 총노출을 0.3~0.5로 낮추고, 좋을 때 0.7~0.9 유지

2) **게이트**
- [ ] `oos_min` 개선(최저 성과/최악 구간이 완화)
- [ ] `worst_mdd` 감소(계산 가능해진 상태에서)

3) **기대 관측치**
- [ ] 평균 수익률이 약간 깎이더라도 최악 구간이 개선되면 “정체”가 풀릴 확률 증가

**PASS 조건**
- [ ] worst_mdd 10~20% 상대 개선(혹은 사전 설정 임계) + oos_min 상승

---

## 실험 E5) 우주/포트폴리오 제약 고정(Tech+Healthcare 8~14, 비중 상한, ETF 주문 차단)
1) **정의**
- [ ] 주문 엔진에서 ETF 티커 주문을 하드 블락(관측만 허용)
- [ ] 보유 종목 수 8~14 강제 + 종목당 비중 상한 + 회전율 상한(단순)

2) **게이트**
- [ ] 모든 리밸런스 스텝에서 제약 위반 0건(위반 시 FAIL)
- [ ] 섹터 분류 기준으로 Tech/HC 외 편입 0건

3) **기대 관측치**
- [ ] 과최적화 완화(특정 소수 종목에 쏠림 감소), 비용/운영 리스크 감소
- [ ] 성과가 “덜 출렁”이며 레짐 게이트와 결합 시 최악 구간 방어

**PASS 조건**
- [ ] 제약 위반 0 + turnover 감소 또는 비용% 감소 + oos_min 악화 없음

# 성능이 “안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래를 **리포트 한 장**으로 고정 생성하도록 만들어 “정체 원인”을 자동 판정하라.

## A) Trigger(신호 발생) 문제
- [ ] 신호 발생률(% days with signal), 종목당 신호 빈도, 신호 강도 분포를 출력
- [ ] 상위 k% 신호만 거래했을 때 성과(스파스화 민감도) 출력  
**해석:** 신호가 너무 드물면 노출이 떨어져 정체 / 너무 잦으면 비용으로 정체.

## B) Apply(실행/리밸런스) 문제
- [ ] 목표 포지션 vs 실제 체결 포지션 괴리(슬리피지/체결 실패) 출력
- [ ] 리밸런스 주기별 성과(일/주/격주) 비교  
**해석:** 실행이 기대와 다르면 시그널이 좋아도 PnL이 안 움직임.

## C) Exposure(노출) 문제
- [ ] 총노출 시계열 + 노출이 낮았던 구간의 “신호 부족 vs 제약” 원인 태깅
- [ ] 상/하방 베타(시장 민감도)와 알파를 분리(간단 회귀)  
**해석:** 알파는 있는데 베타/노출이 잘못되어 상쇄될 수 있음.

## D) Cost(비용) 문제
- [ ] gross→net 브리지(수익에서 비용이 몇 bps를 깎는지)와 turnover 기여도 출력
- [ ] “비용/ADV 비율” 상위 거래 TOP20을 출력(어떤 종목이 비용을 태우는지)  
**해석:** 특정 종목/구간에서 비용이 알파를 먹으면 전체가 정체.

## E) Regime(레짐) 문제
- [ ] 레짐 버킷별 성과(저변동/고변동, 상승/하락, 금리상승/하락) 테이블 출력
- [ ] 레짐 전환 시점에서 손실이 집중되는지(transition loss) 출력  
**해석:** 평균은 괜찮아도 레짐 전환 손실이 반복되면 “계속 제자리”처럼 보임.

---

## 실행 순서(48h 내)
- [ ] **E1 → E2 → E3**를 먼저 돌려 “관측 신뢰성/비용/누수”를 확정
- [ ] 그 다음에만 **E4/E5**로 전략 제어(레짐/제약) 최적화로 들어가라  
- [ ] 모든 실험은 “PASS 조건 미충족 시 즉시 중단 + 원인 리포트”로 자동 루프에 연결하라
