    1.  유니버스(Tech+Healthcare)의 지난 60일 상관관계 행렬 계산.

    3.  각 클러스터에서 상위 2~3개 종목만 선택하여 최종 8~14개 구성.

### 2. 성능 정체 시 원인 분해 (Debugging Checklist)

성능 지표(Mean/Min/MDD)가 개선되지 않거나 0에 수렴할 경우 다음 순서로 점검.

1.  **Trigger (신호 발생 여부)**
    *   *Check*: 선택된 Tech/Healthcare 유니버스 8~14개가 너무 좁거나, 필터(조건)가 너무 엄격하여 `No Trade` 구간이 길어지는가?
    *   *Action*: 진입 조건 완화 (예: RSI < 30 -> RSI < 40).

2.  **Regime (시장 국면 불일치)**
    *   *Check*: 테스트 구간(Fold)이 Tech/Bio 섹터가 횡보하거나 하락하는 구간에 집중되어 있는가? (Long-only 전략의 한계)
    *   *Action*: 상대 모멘텀(Relative Strength vs SPY) 필터 적용하여 시장보다 강할 때만 진입.

3.  **Survivorship (생존 편향)**
    *   *Check*: 현재 유니버스에 상장 폐지된 종목이 포함되어 있는가? 혹은 현재 잘나가는 종목(NVDA, LLY 등)만 과거 데이터에 소급 적용했는가?
    *   *Action*: Point-in-Time 데이터셋으로 유니버스 재구성 (과거 특정 시점 시가총액 상위 종목 리스트 사용).

4.  **Cost Impact (비용 잠식)**
    *   *Check*: 평균 건당 이익(Average Profit per Trade)이 수수료(약 0.1~0.2%)보다 근소하게 높은 수준인가?
    *   *Action*: 보유 기간(Holding Period) 강제 연장 (최소 3일 -> 5일) 또는 변동성 돌파 컷오프 상향.
