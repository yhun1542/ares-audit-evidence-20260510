[분석 요약]
현재 `Champion` 모델은 **심각한 과최적화 및 데이터 파이프라인 붕괴** 상태입니다.
1. `oos_mean: 3.32`는 비현실적으로 높으며, `degenerate_folds: [1, 2, 3, 8]` (전체 폴드의 약 40% 실패)가 이를 증명합니다. 실패한 폴드를 제외하고 계산된 수치(서바이버십 바이어스)일 확률이 99%입니다.
2. `Worst MDD: None`은 MDD 계산 로직이 깨졌거나, 거래가 체결되지 않은 구간이 존재함을 의미합니다.
3. 로깅 시스템(`rebalance.csv` vs `jsonl`) 불일치로 인해 진단 도구(`AUB Rebalance Pinpoint`)가 작동하지 않고 있습니다.

다음 48시간의 목표는 **"수익률 개선"이 아니라 "시스템 정상화 및 리스크 측정 복구"**입니다.

### 2. 제안별 상세 실행 계획

#### (1) 로그 포맷 통일 및 파이프라인 복구
*   **Why:** `Expecting value: line 1 column 1` 에러로 인해 리밸런싱 내역을 분석할 수 없음. 챔피언 모델의 실제 매매 내용을 모르는 상태.
*   **Risk:** 기존 로그 데이터 유실 가능성 (백업 필수).
*   **Patch/Experiment:**
    *   **P1-Fix-Logger:** 모든 리포트 출력을 `JSONL`로 통일하고, 빈 파일 생성 시 예외 처리 추가.
    *   **P1-Verify-Parser:** `aub_rebalance_pinpoint.py`가 빈 파일이나 헤더만 있는 CSV를 읽을 때 Skip하도록 수정.
*   **PASS 조건:** `aub_rebalance_pinpoint.py`가 에러 없이 실행되고, 최소 100개 이상의 트랜잭션 로그가 파싱될 것.

#### (2) Degenerate Folds 패널티 적용
*   **Why:** 폴드 1, 2, 3, 8이 실패(아마도 거래 없음 or 에러)했음에도 OOS Mean이 높게 나오는 착시 제거.
*   **Risk:** 겉보기 성능(Mean) 급락 (-50% 이상 예상). 멘탈 흔들리지 말 것.
*   **Patch/Experiment:**
    *   **E2-Penalty-NaN:** 폴드 수행 실패 시 해당 폴드의 수익률을 `0`이 아닌 `-100%` (또는 `-2.0` Sharpe)로 강제 할당.
    *   **E2-Data-Fill:** 폴드 1~3(과거 데이터일 가능성 높음)의 Tech/Healthcare 티커 데이터 누락(Gap) 여부 전수 조사.
*   **PASS 조건:** `degenerate_folds` 리스트가 빈 배열(`[]`)이 되거나, 실패 시 OOS Mean이 마이너스로 떨어져서 해당 모델이 Champion에서 탈락할 것.

#### (3) MDD 계산 로직 수정
*   **Why:** `Worst MDD: None`은 투자 불가능한 상태. 리스크 제어가 작동하지 않음.
*   **Risk:** 숨겨져 있던 거대한 MDD가 드러나며 전략 폐기 가능성.
*   **Patch/Experiment:**
    *   **P3-Calc-Repair:** MDD 계산 모듈에서 `np.nan` 처리 로직 및 `div by zero` 예외 처리 점검. Equity Curve가 Flat할 때 0.0 반환하도록 수정.
*   **PASS 조건:** `worst_mdd`가 `None`이 아닌 `float` 값(0.0 ~ 1.0)으로 출력될 것.

#### (4) Tech/Healthcare 섹터 밸런싱 (ETF 관측)
*   **Why:** 현재 8-14개 종목 선정 시 특정 섹터(예: Tech)에 100% 쏠림 현상이 발생하여 변동성이 폭발할 가능성 차단.
*   **Risk:** 강세장에서 수익률 제한 (Upside Capping).
*   **Patch/Experiment:**
    *   **E4-Sector-Cap:** XLK(Tech)와 XLV(Healthcare)의 20일 모멘텀을 비교하여, 약세 섹터의 비중을 최소 20%로 강제하거나 아예 제외하는 필터.
    *   **E4-Universe-Split:** 포트폴리오 슬롯(8~14) 중 최소 3개는 Healthcare, 최소 3개는 Tech로 강제 배분.
*   **PASS 조건:** 백테스트 기간 내 Tech/HC 비중이 9:1 ~ 1:9 사이에서 동적으로 움직이며, MDD가 0.25 이하로 제어될 것.

#### (5) 비용 및 슬리피지 강화
*   **Why:** OOS Mean 3.32는 거래 비용이 '0'일 때만 가능한 수치일 수 있음.
*   **Risk:** 샤프 지수 급락.
*   **Patch/Experiment:**
    *   **E5-Cost-Injection:** 매매당 10bps 슬리피지 + 수수료 적용 후 재평가.
*   **PASS 조건:** 비용 적용 후에도 OOS Mean > 0.5 유지.
