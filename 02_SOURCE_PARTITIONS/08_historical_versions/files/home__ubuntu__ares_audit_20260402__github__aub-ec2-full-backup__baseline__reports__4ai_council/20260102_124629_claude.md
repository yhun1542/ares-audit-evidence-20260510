## 0. 긴급 진단: 왜 Delta가 없는가?

| 관측 | 분석 |
|------|------|
| OOS Mean **1.88 → 2.63** (진단 리포트) | 진단기가 읽은 Champion이 다름 (버전 불일치 의심) |
| `rebalance.csv` 로딩 실패 | 리밸런스 로그 자체가 JSON 형식 미지원 or 빈 파일 |
| `worst_mdd: None` | MDD 계산 코드 미실행 or 데이터 누락 |
| **9개 실험 → 승격 0** | Gate 조건 또는 비교 기준 오류 가능성 |

**→ 성능 미변동의 1차 원인: 인프라/데이터 파이프라인 장애 가능성 高**

## 1. 우선순위 TOP 5 패치

### P1. 파이프라인 무결성 복구
```
WHY: rebalance 로그 파싱 실패 → 모든 비교 분석 무효화
RISK: 잘못된 수정 시 기존 로그 덮어쓰기
```

| 실험 ID | 정의 | Gate | 기대 관측 |
|---------|------|------|-----------|
| `PIPE-01` | `rebalance_pinpoint.py`에 JSONL 파서 추가 | 로그 100개 행 파싱 성공 | diff 리포트 정상 출력 |
| `PIPE-02` | Champion 파일 경로 하드코딩 제거 → `ONE_TRUTH.yaml` 참조 | 버전 불일치 0건 | `oos_mean` 값 일관성 확인 |
| `PIPE-03` | MDD 계산 null-check 삽입 | `worst_mdd != None` | 수치 출력 확인 |

**PASS 조건**: 3개 모두 통과 시 P2 진행

---

### P2. 실험 비교 기준 정규화
```
WHY: 9개 실험 중 승격 0 → Gate 기준 또는 baseline 불일치
RISK: Gate 완화 시 과최적화 통과 위험
```

| 실험 ID | 정의 | Gate | 기대 관측 |
|---------|------|------|-----------|
| `GATE-01` | 진단기 baseline hash vs ONE_TRUTH hash 일치 검증 로직 | hash mismatch 시 abort | 로그에 hash 출력 |
| `GATE-02` | OOS Mean 비교 시 소수점 6자리 반올림 통일 | diff > 0.01 시만 유의미 판정 | false-positive 감소 |

**PASS 조건**: GATE-01 통과 + GATE-02에서 재현성 확인

---

### P3. Exposure 하한 리스크 점검
```
WHY: exposure_min=0.47 → 절반 가까이 현금, 기회비용 과다 의심
RISK: 노출 강제 증가 시 MDD 악화
```

| 실험 ID | 정의 | Gate | 기대 관측 |
|---------|------|------|-----------|
| `EXP-01` | `min_exposure=0.55` 제약 추가 | OOS Mean ≥ 1.85 **AND** MDD ≤ 25% | Sharpe 유지 + 노출 증가 |
| `EXP-02` | Low-exposure 구간 레짐 태깅 (VIX>25 등) | 해당 구간 승률 별도 집계 | 방어적 현금이 정당한지 확인 |

**PASS 조건**: EXP-02 선행 → 정당성 없으면 EXP-01 적용

---

### P4. Degenerate Fold 모니터 강화
```
WHY: degenerate_folds=[] 이지만 None MDD와 결합 시 집계 오류 의심
RISK: 실제 degenerate fold 누락 시 과최적화 미탐지
```

| 실험 ID | 정의 | Gate | 기대 관측 |
|---------|------|------|-----------|
| `DEG-01` | fold별 `trade_count < 10` 시 degenerate 플래그 | 플래그 발생 시 해당 fold OOS 제외 | 리포트에 경고 출력 |
| `DEG-02` | fold별 Sharpe < 0.3 시 soft-degenerate 태깅 | 태깅 fold 2개 이상 시 실험 reject | 품질 게이트 강화 |

**PASS 조건**: DEG-01 구현 후 과거 9개 실험 재평가

---

### P5. 비용/슬리피지 현실화 점검
```
WHY: OOS 성능 좋아도 실전 괴리 → 비용 미반영 가능성
RISK: 비용 과대 적용 시 전략 전체 음수 전환
```

| 실험 ID | 정의 | Gate | 기대 관측 |
|---------|------|------|-----------|
| `COST-01` | 현재 cost 파라미터 값 로깅 (bp 단위) | 로그 출력 | 10bp 이상인지 확인 |
| `COST-02` | cost=15bp로 강제 재시뮬 | OOS Mean ≥ 1.5 | 비용 민감도 파악 |

**PASS 조건**: COST-01 기록 후 COST-02 delta 분석

## 2. 성능 미변동 원인 분해 트리

```
성능 Delta = 0
│
├─ [트리거 미발동]
│   ├─ 신호 생성 로직 동일 (코드 변경 無)
│   └─ 입력 데이터 동일 (날짜 범위 고정)
│
├─ [적용 실패]
│   ├─ Gate 조건이 모든 실험 reject
│   └─ Baseline 파일 경로 오류 → 비교 무효
│
├─ [노출 불변]
│   ├─ 리밸런스 실제 미실행 (dry-run 상태)
│   └─ 포지션 사이즈 cap에 걸림
│
├─ [비용 상쇄]
│   ├─ 개선분이 슬리피지로 소멸
│   └─ 거래 횟수 증가 → net 동일
│
└─ [레짐 불일치]
    ├─ 학습 기간 ≠ OOS 기간 레짐
    └─ OOS 기간 자체가 너무 짧음 (노이즈 지배)
```

## 3. 48h 자동루프 실행 순서

```bash
# Phase 1: 인프라 복구 (0-8h)
□ PIPE-01 → PIPE-02 → PIPE-03 순차 실행
□ 각 단계 PASS 시 다음 진행, FAIL 시 alert + 중단

# Phase 2: 실험 품질 게이트 (8-24h)
□ GATE-01 실행 → hash 일치 확인
□ DEG-01 구현 후 과거 9개 실험 재스캔
□ 승격 후보 1개 이상 발생 시 Phase 3 진행

# Phase 3: 전략 실험 (24-48h)
□ EXP-02 (레짐 태깅) → 결과 기반 EXP-01 판단
□ COST-01 → COST-02 순차 실행
□ 최종 Champion 갱신 여부 결정
```
