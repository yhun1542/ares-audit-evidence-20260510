아래 5개를 24~48시간 TOP5 우선순위로 “명령형 체크리스트” 형태로 제시한다. (누수/과최적화/서바이버십/비용/운영리스크 순으로 먼저 잠금)  
전제: **미국주식 only**, **Tech+Healthcare 8~14종목**, **ETF 매매 금지(관측지표만)**, 48시간 자동 루프에 바로 얹을 수 있게 (1)실험 정의 (2)게이트 (3)기대 관측치 포함.

## TOP1) 누수/서바이버십 “하드락” (데이터·검증 체계 패치)
### (a) 왜 필요한지
- Champion은 lockbox_mean이 높지만(≈4.01) **candidate가 tuning에서만 형태가 바뀌고 lockbox/드로다운이 악화**(worst_mdd -0.11대) → 전형적인 **검증 누수/분할 오염/과최적화 신호**를 먼저 제거해야 다음 개선이 의미가 생김.
- Tech+Healthcare 8~14 종목 운용에서 **유니버스 선정(생존편향)과 point-in-time** 실수는 성능을 “가짜로 고정”시키거나 “가짜로 튀게” 만드는 1순위 원인.

### (b) 위험/부작용
- 성능 수치가 단기적으로 하락할 수 있음(‘진짜’ 성능으로 재기준).  
- 데이터 요구사항 증가(포인트인타임 펀더멘털/기업행동/상장폐지 처리)로 파이프라인 복잡도 상승.

### (c) 최소 실험(2~3개, 단일 실험 안에 서브체크로 묶기)
**[실험 E1: Leak/Survivorship Audit Harness]**
- 서브체크1) **Purged/Embargoed CV** 적용(이벤트/룩백 겹침 제거): 학습-검증 간 최소 embargo(예: 5~20 trading days) 강제.
- 서브체크2) **Point-in-time 유니버스 스냅샷**: “당시 시점에 존재/거래 가능했던 Tech+Healthcare 8~14”만 구성(상장폐지/인수합병 포함), 티커 변경/기업행동 반영.
- 서브체크3) **Feature timestamp lint**: 모든 피처가 `t` 시점에서 사용 가능한 데이터만 참조하는지 자동 검출(리포트/지표 업데이트 지연 반영).

### (d) PASS 조건(게이트)
- **Leakage Gate**: embargo/purge 적용 후에도
  - lockbox_mean이 **Champion 대비 ≥ 0.95 유지**(≈3.81 이상)하면서  
  - worst_mdd가 **현 Champion(-0.081)보다 악화되지 않음**(≤ -0.085 같은 완화 기준)  
  - tuning→lockbox 성능 갭(일관성 지표)이 **축소**(예: tuning_mean - lockbox_mean 절대값 감소).
  
### 48시간 루프 형태
1) **실험 정의**: `E1`을 “항상-on” 회귀테스트로 추가(모든 후보가 이 하네스를 통과해야만 다음 단계 진입).  
2) **게이트**: 위 PASS 조건 + “데이터 린트 0건(critical)”.  
3) **기대 관측치**: tuning 성능이 일부 내려가더라도 lockbox/드로다운 안정화, 후보들 간 변동성이 줄어듦(가짜 알파 제거).

## TOP2) 비용/회전율/유동성 “실거래 반영” (비용 미반영 제거)
### (a) 왜 필요한지
- Tech+Healthcare 8~14 단일종목 조합은 **리밸런스 빈도/턴오버**에 따라 비용 민감도가 매우 큼.  
- 비용을 안 넣으면, “좋아 보이는 후보”가 실제로는 비용에 깎여 lockbox에서 움직이지 않거나 MDD만 커짐.

### (b) 위험/부작용
- 단기 성능(평균)이 떨어질 수 있음(비용 차감으로 현실화).  
- 과도한 비용 페널티는 알파까지 죽여 “아무 것도 안 함”으로 수렴 가능.

### (c) 최소 실험(2~3개)
**[실험 E2: Cost & Turnover Reality Patch]**
- 서브체크1) **슬리피지+스프레드+수수료** 비용모델을 백테스트 PnL에 강제 주입(최소: bps 고정 + 거래대금 비례).
- 서브체크2) **턴오버 상한 + 거래량 기반 참여율 cap**(예: 일평균거래대금 대비 X% 제한)으로 실행 가능성 확보.
- 서브체크3) **리밸런스 빈도 스윕(예: daily vs 2~3day vs weekly)**을 같은 신호에서만 비교해 “알파/비용 탄력성” 측정.

### (d) PASS 조건(게이트)
- 비용 포함 후 lockbox_mean이 **Champion 대비 ≥ 0.98 유지(≈3.93 이상)** 또는  
- lockbox_mean이 소폭 하락하더라도 **worst_mdd 개선(예: -0.081 → -0.075 이하로 완화)** + **턴오버 20~40% 감소** 같이 “현실 이득”이 명확할 것.  
- “비용 차감 전후” 성능 갭이 과도하면(예: Sharpe 30%+ 급락) 해당 전략/신호는 폐기.

### 48시간 루프 형태
1) **실험 정의**: 모든 후보에 cost-aware 스코어를 병기(“gross”, “net” 동시 출력).  
2) **게이트**: net 기준 PASS 없으면 select-best에서 제외.  
3) **기대 관측치**: 후보 간 랭킹이 “gross”와 달라짐(비용에 강한 신호가 살아남음).

## TOP3) 운영 리스크/드로다운 제어 오버레이 (전략은 유지, 리스크만 패치)
### (a) 왜 필요한지
- Candidate에서 fold14_mdd / worst_mdd가 크게 악화(-0.10~-0.11) → 신호 자체보다 **포지션 사이징/리스크 브레이크 부재**가 문제일 수 있음.
- 8~14 종목 집중 포트는 단일 이벤트(실적, FDA, 규제)로 tail risk가 큼.

### (b) 위험/부작용
- 상방을 일부 포기(수익 상한).  
- 과도한 브레이크는 “잦은 risk-off”로 비용/슬리피지 증가 가능.

### (c) 최소 실험(2~3개)
**[실험 E3: Risk Overlay Patch (Vol/Drawdown/Beta Caps)]**
- 서브체크1) **Vol targeting**: 포트폴리오 목표 변동성(예: 연 10~12%)으로 레버리지/노출 자동 조절.
- 서브체크2) **Drawdown brake**: 최근 N일 DD가 임계치 초과 시 노출 단계적 축소(예: 100%→50%→0%).
- 서브체크3) **Market beta cap**: SPY(관측용)로 회귀 베타를 추정해 베타 상한(예: |β|≤0.6) 유지.

### (d) PASS 조건(게이트)
- lockbox_mean이 **Champion 대비 ≥ 0.95 유지(≈3.81 이상)** 하면서  
- worst_mdd가 **-0.081 대비 개선**(예: ≤ -0.075), 또는 최소한 **candidate 수준(-0.11대) 재발 방지**.  
- “리스크 오버레이 on/off” 비교에서 **tail(하위 5% 수익률) 개선**이 확인될 것.

### 48시간 루프 형태
1) **실험 정의**: 전략 본체는 고정하고 오버레이만 토글(A/B).  
2) **게이트**: net 성능 + MDD + tail 지표 3종 합격.  
3) **기대 관측치**: 평균은 비슷/소폭↓, MDD와 하방 꼬리 개선으로 lockbox 안정화.

## TOP4) 레짐(시장 국면) 게이트 추가 (ETF는 “센서”로만)
### (a) 왜 필요한지
- Tech+Healthcare는 금리/리스크온오프/퀄리티-그로스 스타일에 민감.  
- 성능이 “안 움직이는” 기간은 대개 **레짐 미스매치**(신호가 먹히지 않는 국면 지속)일 확률이 큼.

### (b) 위험/부작용
- 레짐 분류가 틀리면 오히려 성능 악화(잘못된 risk-off).  
- 게이트가 늘어 과최적화 포인트가 증가(= 규칙 단순화 필요).

### (c) 최소 실험(2~3개)
**[실험 E4: Regime Gate (Observable ETFs as Indicators)]**  *(ETF 매매 금지, 관측만)*
- 서브체크1) **Risk-on/off 지표**: (SPY 추세, QQQ/SPY 상대강도, HYG/LQD 크레딧 스프레드 proxy, TLT 추세)로 2~3상태 레짐 분류.
- 서브체크2) **섹터 센서**: XLK, XLV 상대강도(Tech vs Health 리더십)에 따라 동일 신호라도 **포지션 총노출(또는 리밸런스 강도)**만 조절.
- 서브체크3) 레짐별 성능 리포트 자동 생성(“레짐별 승률/턴오버/비용/드로다운”).

### (d) PASS 조건(게이트)
- 전체 lockbox_mean이 **Champion 대비 ≥ 0.98 유지** 또는  
- 전체 평균이 비슷하더라도 **레짐별 최악 구간의 worst_mdd가 유의미하게 완화**(예: 레짐-불리 구간에서 DD 20%+ 감소).  
- 레짐 상태 수를 3개 초과로 늘리지 말 것(과최적화 방지 게이트).

### 48시간 루프 형태
1) **실험 정의**: “레짐 분류→노출 스케일링”만 추가(종목 선택 로직은 고정).  
2) **게이트**: 레짐별 리포트에서 불리 레짐 손실 감소 확인.  
3) **기대 관측치**: 성능이 안 나오던 구간에서 손실이 줄어 lockbox 최저치/최악DD 개선.

## TOP5) 과최적화 감지 + 단순화(안정성) 패치 (신호/모델의 “움직임” 확보)
### (a) 왜 필요한지
- Champion 대비 candidate가 tuning에서만 형태가 바뀌는 상황은 **자유도(피처/룰) 과다** 또는 **파라미터 민감도 과도**일 가능성이 큼.
- 성능이 “안 움직이는” 것도, 사실은 모델이 너무 복잡해 **바뀐 게 일반화되지 않고 상쇄**되는 경우가 많음.

### (b) 위험/부작용
- 알파 일부를 잃을 수 있음(특히 특정 구간에서만 먹던 패턴).  
- 지나친 단순화는 시장 변화 대응력 저하.

### (c) 최소 실험(2~3개)
**[실험 E5: Robustness & Simplification Patch]**
- 서브체크1) **파라미터 민감도 맵**(주요 하이퍼파라미터 2~3개만): 성능이 “뾰족”하면 폐기, “plateau”면 채택.
- 서브체크2) **피처 그룹 드롭 테스트**(macro/price/quality 등 큰 그룹 단위로만): 특정 그룹 제거 시 성능 폭락하면 과의존 경고.
- 서브체크3) **신호 안정성 지표**: 포지션 변화율(턴오버), 예측/스코어의 자기상관, 랭크 안정성(스피어만) 출력.

### (d) PASS 조건(게이트)
- lockbox_mean이 **Champion 대비 ≥ 0.95 유지**하면서  
- 성능이 상위 10% 파라미터 좁은 영역에만 존재하지 않을 것(plateau 확인).  
- 안정성 지표가 개선(예: turnover 10~30%↓ 또는 랭크 안정성↑)되면 가산점.

### 48시간 루프 형태
1) **실험 정의**: 후보 생성 시 “민감도/드롭/안정성” 리포트를 자동 첨부.  
2) **게이트**: plateau 미확보/그룹 과의존이면 자동 탈락.  
3) **기대 관측치**: 후보 간 성능 분산이 줄고, lockbox 재현성이 올라 “진짜로 움직이는 개선”이 생김.

# 24~48시간 실행 순서(명령형)
1) **E1을 최우선으로 always-on**으로 올려라(누수/서바이버십/타임스탬프 린트).  
2) **E2를 모든 backtest에 기본 비용모델로 주입**하고 gross/net을 분리 출력해라.  
3) **E3를 A/B로 붙여 worst_mdd를 먼저 잡아라**(전략 본체는 고정).  
4) **E4 레짐 게이트는 상태 2~3개로만 최소 구현**하고 레짐별 손실 완화만 노려라.  
5) **E5로 과최적화 자동 탈락 룰**(plateau/드롭/안정성) 추가해 후보 품질을 올려라.

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **한 번에 대시보드/리포트로 고정 출력**해 “어디서 막히는지”를 즉시 분해해라.

## 1) Trigger(신호 생성) 문제
- 신호 분포가 죽었는지 확인: 스코어 분산(표준편차), 상/하위 분위수 간 스프레드, 예측 자기상관.
- 특정 피처/그룹에 과의존인지 확인: 그룹 드롭 시 성능 변화(E5-서브체크2).
- 이벤트 지연/리포팅 랙 반영 누락 점검: 타임스탬프 린트(E1).

## 2) Apply(적용/리밸런스) 문제
- 리밸런스 타이밍이 알파를 갉아먹는지: daily vs weekly에서 알파/비용 분해(E2-서브체크3).
- 신호→포지션 변환이 과도하게 비선형인지: 클리핑/정규화/랭킹 규칙 점검(포지션 변화율, 랭크 안정성).

## 3) Exposure(노출/집중) 문제
- 시장/금리/스타일 노출이 원인인지: SPY 베타, QQQ/SPY, TLT 상관, 섹터 편향(Tech vs Health) 추적(E3/E4).
- 8~14종목 집중에서 단일 종목 기여도(수익/리스크 기여) 상시 출력: 상위 1~2종목이 성과를 좌우하면 “집중 리스크”가 정체 원인.

## 4) Cost(비용) 문제
- gross는 괜찮은데 net이 안 움직이면 비용 문제다: 거래비용 기여도(슬리피지/스프레드/수수료) 항목별 분해(E2).
- 턴오버-성과 탄력성 곡선 출력: “턴오버를 줄이면 성과가 유지되는지/급락하는지”로 신호 품질 판단.

## 5) Regime(국면) 문제
- 레짐별로 성능을 쪼개서 “먹히는 구간/안 먹히는 구간”을 확정해라(E4-서브체크3).  
- 안 먹히는 레짐에서의 손실이 크면: 신호를 바꾸기 전에 **노출 스케일링/브레이크(E3/E4)**로 먼저 방어해라.

---

위 5개(E1~E5)는 케이스 폭발을 막으면서도, 현재 로그(Champion 양호 vs Candidate MDD 악화)가 시사하는 **가장 가능성 큰 실패 원인(누수·비용·리스크·레짐·과최적화)**을 48시간 자동 루프에 바로 넣는 패치/실험 세트다.
