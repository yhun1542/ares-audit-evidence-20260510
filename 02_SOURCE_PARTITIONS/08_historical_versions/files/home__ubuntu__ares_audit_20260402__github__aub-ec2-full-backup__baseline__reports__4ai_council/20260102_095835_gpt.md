## 24~48시간 TOP5 우선순위(코드/아키텍처/전략) — **명령형 체크리스트**

### 1) **리밸런스/로그 파이프라인 무결성 복구(운영 리스크 1순위)**
- `aub_rebalance_pinpoint`가 **파일 미존재 + JSON 파싱 실패**로 리밸런스 근거를 못 찍고 있음 → 비용/회전/슬리피지/체결 가정 점검 불가(=성능 정체 원인 분해 불가).
- `worst_mdd: None`도 같이 떠서 **리스크 지표 산출 누락** 가능성 큼(운영/리스크 통제 붕괴).

**(a) 왜 필요한지**
- “성능이 안 움직임”의 1차 원인은 대개 **신호가 아니라 파이프라인/산출물 누락**(리밸런스 내역, 비용, MDD, 포지션 변화)이어서, 먼저 관측 가능하게 만들어야 함.

**(b) 위험/부작용**
- 로그 스키마 변경 시 기존 리포트/도구 호환 깨짐.
- 리플레이(재현) 고정이 안 되면 결과 변동이 “전략 개선”으로 오인될 위험.

**(c) 최소 실험(공유 실험 사용)**
- **[E1] 리밸런스 로그 스키마 고정 + 결정적 리플레이** (아래 실험 정의 참조)
- **[E5] 메트릭 정합성/산출 누락 감지**(MDD/턴오버/비용/노출 일관성 체크)

**(d) PASS 조건**
- `rebalance.csv` 또는 `rebalance.jsonl`이 **항상 생성**되고(실험/챔피언 모두) `pinpoint`가 **에러 없이 diff**를 출력.
- `worst_mdd`가 None이 아니라 **수치로 산출**되고, OOS 평가 리포트에 **턴오버/비용/노출 타임라인**이 포함.


---

### 2) **비용(수수료/슬리피지/임팩트) 미반영/과소반영 차단(가장 흔한 착시)**
- 현재 로그 상태상 비용 근거가 비어 있을 확률이 높고, 이러면 OOS mean이 “잘 나오는 척”하거나 “개선이 안 되는 척” 둘 다 가능.

**(a) 왜 필요한지**
- 8~14개 종목(Tech+Healthcare) 집중 포트는 리밸런스 빈도/회전에 따라 **비용 민감도가 급격히 커짐**.
- “No-Delta(개선 없음)”는 실제로는 **비용이 알파를 먹는 상태**일 때 자주 발생.

**(b) 위험/부작용**
- 비용을 현실화하면 단기 성능 급락 가능(그러나 그게 진짜 상태).
- 비용 모델 파라미터를 잘못 잡으면 과도 보수적이 되어 거래를 못 함(언더트레이딩).

**(c) 최소 실험**
- **[E2] 비용 모델 토글(0 vs 현실) + 턴오버 패널티**  
- **[E1] 리밸런스/체결단가 로그 기반으로 비용이 “실제로 적용됐는지” 검증**

**(d) PASS 조건**
- “비용=0” 대비 “현실 비용”에서 성능이 하락하더라도, **OOS Mean이 0 이상 유지 + MDD 악화 폭이 통제**.
- 비용 적용 후에도 포지션 변화/체결가/비용이 **로그로 재구성 가능**(감사 가능성).


---

### 3) **누수/서바이버십/포인트-인-타임(universe) 감사(데이터 리스크)**
- US 주식 only + Tech/Healthcare 중심이라도, 유니버스가 현재 구성/현재 섹터 분류를 과거에 “소급 적용”하면 **서바이버십/룩어헤드**로 OOS가 왜곡됨.

**(a) 왜 필요한지**
- “정체”의 또 다른 원인은 **모델이 개선돼도 누수 제거로 성능이 상쇄**되거나, 반대로 누수 때문에 이미 과대평가되어 더 이상 올라갈 공간이 없는 경우.

**(b) 위험/부작용**
- 포인트-인-타임 구성으로 바꾸면 성능이 떨어질 수 있음(정상).
- 데이터 소스/매핑(섹터, 상장폐지 수익률) 처리 비용 상승.

**(c) 최소 실험**
- **[E3] 포인트-인-타임 유니버스 + 상장폐지/기업행위 반영 리플레이**  
- **[E5] 폴드별/기간별 “유니버스 크기·교체율·결측률” 리포트 추가**

**(d) PASS 조건**
- PIT 적용 후에도 **OOS가 붕괴하지 않고**, 폴드별 성능 편차가 과도하게 커지지 않음(과최적화 징후 완화).
- 유니버스/섹터 필터가 과거 시점에서 **재현 가능**(같은 날짜 재실행 시 동일 종목 풀).


---

### 4) **노출/레짐/리스크 게이트를 48시간 루프에 강제(전략 운영 안정화)**
- 현재 노출 min/max가 `~0.47~0.84`로 **상시 롱 바이어스**. 레짐 전환(금리 급등/리스크오프)에서 성능이 멈추거나 역전될 수 있음.
- MDD 산출 누락이면 더 위험(리스크 브레이크 없음).

**(a) 왜 필요한지**
- “성능이 안 움직임”을 **레짐 적합 실패** vs **신호 적용 실패**로 분리하려면, 노출/변동성/드로우다운 게이트가 로그로 남아야 함.

**(b) 위험/부작용**
- 게이트가 과도하면 수익 기회 상실.
- 변동성 타게팅이 신호를 눌러 과소투자될 수 있음.

**(c) 최소 실험**
- **[E4] 변동성 타게팅 + 드로우다운/리스크오프 게이트(관측 ETF는 지표로만)**  
- **[E2] 턴오버 패널티와 결합 시 과도한 매매 억제 확인**

**(d) PASS 조건**
- 리스크오프 구간에서 **노출이 자동 축소**되고, MDD가 기준 대비 개선.
- 정상 구간에서 수익률 손상이 과도하지 않음(예: OOS Mean 하락이 제한적).


---

### 5) **평가 메트릭/워크플로 정합성(“챔피언 OOS” 수치 불일치 제거)**
- 현재 출력에 `Current Champion oos_mean: 1.8815`인데, Diagnoser는 `Champion OOS Mean: 2.6276`로 표기 → **평가 파이프라인/스케일/기간/비용 적용** 중 하나가 서로 다름.
- 이 상태면 “개선이 안 된다”는 판단 자체가 흔들림.

**(a) 왜 필요한지**
- 실험이 실제로 개선돼도, 메트릭 산출이 다르면 **No-Delta로 오판**.
- degenerate_folds가 비어 있어도, 폴드 스플릿/기간 정의가 다르면 “겉보기 정상”이 될 수 있음.

**(b) 위험/부작용**
- 메트릭을 통일하는 과정에서 과거 챔피언 재현이 깨질 수 있음(하지만 그게 정상적인 정리).

**(c) 최소 실험**
- **[E5] 단일 소스 메트릭 계산기(리포트/Diagnoser/선정 로직 통합) + 회귀 테스트**  
- **[E1] 동일 입력에서 완전 재현(시드/데이터 스냅샷) 확인**

**(d) PASS 조건**
- 챔피언 OOS mean이 모든 도구에서 **동일 값(허용 오차 내)**으로 재현.
- 메트릭 산출에 사용된 기간/비용/노출/리밸런스 규칙이 **리포트에 자동 명시**.

## 48시간 자동 루프용 “실행 가능한” Patch/실험 5개(케이스 폭발 방지)
아래 5개만 돌리고, 위 TOP5 항목은 이 실험들을 **공유**해서 검증/통과 처리.

### [E1] 리밸런스 로그 스키마 고정 + 결정적 리플레이(운영 무결성)
1) **실험 정의**
   - 백테스트 실행 시 `rebalance.jsonl`을 표준 스키마로 강제 생성:  
     `ts, symbol, target_w, prev_w, trade_qty, est_fill_px, est_slip_bps, fee, notional, reason(signal/risk/cost)`
   - `--base-log` 같은 플래그는 **실제 파일 경로만 허용**(문자열 `'--base-log'`가 경로로 들어가면 즉시 실패시키는 가드 추가).
   - 동일 데이터 스냅샷+시드로 2회 실행 시 포지션/리밸런스가 동일하게 나오는 “리플레이 모드” 추가.
2) **게이트**
   - `pinpoint`가 에러 없이 diff 생성.
   - 동일 조건 2회 실행 결과 해시가 일치(포지션 타임라인/리밸런스 이벤트).
3) **기대 관측치**
   - “성능 정체” 케이스에서 **실제로 리밸런스가 거의 없었는지**, 혹은 **과도 회전이었는지**가 즉시 드러남.

---

### [E2] 비용 모델 현실화(슬리피지/임팩트) + 턴오버 패널티
1) **실험 정의**
   - 비용 2레벨만 비교(케이스 최소화):
     - A: 비용=0 (진단용)
     - B: 현실 비용(예: 고정 bps + 거래대금 기반 임팩트)
   - 목적함수에 **턴오버 패널티**(예: 일/주간 turnover 상한 또는 페널티 항) 추가.
2) **게이트**
   - B에서 성능이 A 대비 하락하되, **수익/리스크가 합리적으로 유지**(붕괴 금지).
   - 리밸런스 로그에서 비용이 **실제 차감**된 흔적(현금/수익률 브리지)이 확인됨.
3) **기대 관측치**
   - No-Delta의 원인이 “알파 부족”인지 “비용 잠식”인지 분리됨.
   - 과회전이면 turnover 패널티 적용 후 **거래 횟수 감소 + OOS 안정화**가 관측됨.

---

### [E3] PIT 유니버스(Tech+Healthcare) + 상장폐지/기업행위 반영 리플레이
1) **실험 정의**
   - 유니버스 생성은 “해당 시점에 존재” 기준(PIT)으로 고정.
   - Tech/Healthcare 분류도 PIT(가능한 데이터 소스 기준)로 적용.
   - 상장폐지 수익률/스플릿 등 기업행위 반영을 강제.
2) **게이트**
   - 유니버스 크기/교체율/결측률 리포트가 자동 생성.
   - PIT 적용 후에도 OOS가 완전히 무너지지 않음.
3) **기대 관측치**
   - 성능 정체가 누수 제거에 의한 착시인지(과대평가 제거) 확인 가능.
   - 특정 기간에만 성능이 좋았던 경우(서바이버십) 패턴이 드러남.

---

### [E4] 노출/레짐 리스크 게이트(변동성 타게팅 + 드로우다운 브레이크)
1) **실험 정의**
   - ETF는 매매 금지, **관측 지표로만** 사용: 예) QQQ(Tech), XLV(Healthcare), IWM(리스크), TLT(금리), VIX proxy(가능 시).
   - 규칙 예:
     - 포트 변동성 타게팅(목표 vol)으로 레버리지/노출 조정
     - 드로우다운이 임계치 초과 시 노출 단계적 축소
2) **게이트**
   - 리스크오프 구간에서 노출 축소가 로그로 확인.
   - MDD 개선(또는 악화 방지) + OOS 평균의 과도한 손상 없음.
3) **기대 관측치**
   - “레짐 불일치”로 성능이 멈춘 경우, 방어 구간 성과가 개선되며 곡선이 매끈해짐.

---

### [E5] 메트릭/스플릿 단일화(챔피언 OOS 불일치 제거) + 회귀 테스트
1) **실험 정의**
   - OOS mean, min, MDD, turnover, 비용, 노출을 계산하는 함수를 **단일 모듈로 통합**하고 모든 도구가 이를 호출.
   - Diagnoser/선정로직/리포트가 참조하는 기간 정의(학습/검증/테스트)와 비용 on/off를 **메타데이터로 강제 표기**.
2) **게이트**
   - 동일 run_hash에서 모든 리포트의 OOS mean이 일치.
   - `worst_mdd` 등 필수 리스크 지표가 항상 채워짐.
3) **기대 관측치**
   - “개선이 안 된다”가 진짜인지, 단지 평가 기준이 달라서 그렇게 보였는지 즉시 판별됨.

## 성능이 안 움직일 때 “원인 분해” 아이디어(트리거/적용/노출/비용/레짐)
아래 순서대로 **관측 가능성(로그) → 경제적 원인**으로 내려가며 절단해라.

### A. 트리거(신호 생성) 문제
- 체크: 신호 분포가 기간별로 **평평해짐/클리핑됨/상수화됨**(특히 스케일링/정규화 이후).
- 체크: 상위 랭크 종목이 **항상 동일**(8~14개가 고정) → 모델이 새 정보를 못 읽음.
- 트리거: 데이터 결측/정렬 오류로 feature가 0/NaN 대체되어 신호가 죽는 케이스.

### B. 적용(포트 구성/리밸런스) 문제
- 체크: 신호가 변해도 타깃 웨이트가 안 바뀜(리밸런스 조건/임계치/라운딩).
- 체크: 리밸런스가 발생해도 체결 수량이 0(최소 주문단위/현금/리스크 제한).
- 필요 로그: `[E1]` 스키마로 `reason`과 `prev_w→target_w` 변화를 반드시 남김.

### C. 노출(리스크/제약) 문제
- 체크: net/gross exposure가 거의 고정(현재 min/max가 좁으면 특히 의심).
- 체크: 리스크 게이트가 항상 “ON”이라 신호가 눌림(사실상 캐시 전략).
- 해결: `[E4]`로 레짐별 노출 변화가 실제로 발생하는지 확인.

### D. 비용(회전/슬리피지) 문제
- 체크: 거래 수는 많지 않은데 성과가 안 나옴 → **임팩트/슬리피지 가정 누락**이거나 반대로 과대.
- 체크: turnover가 높고 OOS가 정체 → 알파보다 비용이 큼.
- 해결: `[E2]` A(0비용) vs B(현실비용) 스프레드로 “비용 잠식”을 수치화.

### E. 레짐(시장 국면) 문제
- 체크: 특정 국면(금리 급등/리스크오프/대형 성장주 언더퍼폼)에서만 성능이 멈춤.
- 체크: Tech/Healthcare 내에서도 하위 섹터(반도체/소프트웨어/바이오) 순환에 취약.
- 해결: `[E4]`에서 관측 지표(ETF)는 “거래”가 아니라 **게이트/타게팅 신호로만** 사용해 레짐 대응 여부를 검증.

---

### 실행 순서(48시간 내)
1. **E1 → E5** 먼저 돌려서 “관측/평가/리스크 산출”을 정상화.
2. 그 다음 **E2**로 비용 잠식 여부를 확인.
3. 마지막으로 **E3/E4**로 데이터 리스크(누수)와 레짐/노출 통제를 분리 검증.

이 루프가 돌아가면, “정체”를 감정이 아니라 **(신호 생존)→(리밸런스 적용)→(노출)→(비용)→(레짐)**의 순서로 매번 자동 판정할 수 있게 된다.
