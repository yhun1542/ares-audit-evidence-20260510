아래는 **다음 24~48시간**에 바로 넣어 돌릴 수 있는 **우선순위 TOP5(코드/아키텍처/전략)**입니다.  
절대 우선 점검 순서(누수→과최적화→서바이버십→비용→운영리스크)를 그대로 반영했고, **실행 가능한 patch/실험은 총 5개(E1~E5)로만 제한**합니다. 각 제안의 (c) “최소 실험 2~3개”는 **E1~E5를 조합 참조**하는 방식으로 충족합니다(새 실험 폭증 방지).

- 48시간 자동 루프 형태: 모든 실험은 (1) 실험 정의 → (2) 게이트 → (3) 기대 관측치 포함

# TOP5 우선순위 제안

## 1) (최우선) 데이터 누수(lookahead/asof) 차단: “시간정합 강제 + 누수 유닛테스트”
### (a) 왜 필요한지
- 현재 Champion이 lockbox 평균이 높아도(4.01) **누수/시간정합 결함**이 있으면 다음 데이터/레짐에서 급사합니다.
- 특히 **기업행사(분할/배당), 지표 업데이트 시각, EOD 가격 vs 신호 생성 시점**에서 빈번히 누수 발생.

### (b) 위험/부작용
- 누수를 제거하면 **성능이 내려갈 가능성**(하지만 그게 “진짜 성능”).
- 시간정합 강제(asof merge, lag 적용)로 **거래 타이밍이 느려져 turnover/수익 구조가 바뀜**.

### (c) 최소 실험(2~3개) — *E1, E5 참조*
- **E1**: 시간정합 강제 패치 + 누수 테스트(필수)
- **E5**: 실험 재현성/로그(시점, lag, asof key) 강제 저장으로 “누수 재발” 방지

### (d) PASS 조건
- (필수) **누수 테스트 0 fail** (아래 E1 Gate 참조)
- (성능) lockbox_mean이 Champion 대비 **-10% 이내 유지**(≥ 3.61)하면서  
  worst_mdd가 **개선 또는 동일**(≥ -0.0815) 이면 PASS  
  *(누수 제거로 평균이 조금 빠져도, MDD 안정성이 유지/개선되면 통과시키는 게 맞음)*

---

## 2) 과최적화/불안정(튜닝-락박스 괴리, fold 민감도) 완화: “단순화+정규화+워크포워드 일관성”
### (a) 왜 필요한지
- Candidate에서 **fold14_mdd/worst_mdd 악화(-0.099/-0.112)**는 “특정 구간/레짐에만 맞춘 신호” 가능성이 큼.
- Tech/Healthcare는 레짐 의존(금리/리스크온/AI 사이클/헬스케어 규제)이 커서 **정규화/레짐 게이트** 없으면 흔들림.

### (b) 위험/부작용
- 단순화/정규화는 **피크 수익을 깎는 대신** 분산을 줄입니다.
- 레짐 게이트는 **거래 기회를 줄여** 평균 수익이 감소할 수 있음.

### (c) 최소 실험(2~3개) — *E4, E1 참조*
- **E4**: “정규화+레짐 관측(ETF는 지표만)” 기반의 단순 게이트 실험
- **E1**: 누수 제거 이후에만 의미가 있으므로 E1 통과가 선행 조건

### (d) PASS 조건
- tuning_mean 대비 lockbox_mean의 괴리가 **축소**(예: |tuning-lockbox|가 기존 대비 -20% 이상) 또는
- worst_mdd가 **-0.0815 이상(개선/동일)**이고 lockbox_mean **≥ 3.6** 유지

---

## 3) 서바이버십/유니버스 드리프트 차단: “8~14 종목을 ‘시점 고정’ 구성으로”
### (a) 왜 필요한지
- “오늘 살아남은 종목(mega-cap 승자)”로 유니버스를 구성/업데이트하면 **서바이버십 편향**이 생깁니다.
- 운영 중 유니버스가 바뀌면 성능이 “전략 변화”인지 “구성 변화”인지 분리가 안 됩니다.

### (b) 위험/부작용
- 과거에 부진/변동 큰 종목이 포함되면 평균 수익이 떨어질 수 있음(하지만 현실 반영).
- 8~14로 제한하면 분산이 부족해 MDD가 커질 수 있어 **포지션/리스크 제한과 함께** 가야 함.

### (c) 최소 실험(2~3개) — *E3, E2 참조*
- **E3**: 유니버스 “고정 파일” + 심볼 변경/상장/거래정지 처리 규칙 적용
- **E2**: 유니버스가 좁을수록 비용/슬리피지 영향이 커지므로 비용 모델을 동시에 현실화

### (d) PASS 조건
- (데이터) 과거 전 구간에서 **유니버스 크기 8~14 유지** + 결측/중단 처리 로직이 “강제 규칙”대로 동작(아래 E3 Gate)
- (성능) lockbox_mean **≥ 3.6** 유지, worst_mdd **악화 금지**

---

## 4) 비용(스프레드/슬리피지/임팩트) 미반영 제거: “현실적 체결 + turnover 상한”
### (a) 왜 필요한지
- Tech/Healthcare 대형주라도 **고회전**이면 스프레드/체결 미끄러짐으로 성능이 쉽게 사라집니다.
- Candidate의 MDD 악화는 비용 반영 시 더 나빠질 수 있어, **비용 모델을 먼저 고정**해야 “진짜 개선”이 나옵니다.

### (b) 위험/부작용
- 비용을 올리면 당연히 성과가 낮아짐.
- 지나치게 보수적인 비용은 “좋은 전략”도 죽일 수 있어 **보수/기본/낙관 3단계 스트레스**가 필요.

### (c) 최소 실험(2~3개) — *E2, E4 참조*
- **E2**: 비용 모델 3단계(기본/보수/극단) + turnover cap 패치
- **E4**: 레짐 게이트로 거래 빈도 감소가 실제로 비용 민감도를 낮추는지 확인

### (d) PASS 조건
- 비용 “기본”에서 lockbox_mean **≥ 3.6**
- 비용 “보수”에서 lockbox_mean **≥ 3.0** 유지(완전 붕괴 방지)
- turnover가 상한을 준수(예: 일평균 turnover ≤ 설정값)

---

## 5) 운영 리스크(자동루프 실패/재현성/원인불명) 제거: “원클릭 재현 + 아티팩트/로그 강제”
### (a) 왜 필요한지
- 48시간 루프에서 가장 큰 리스크는 “좋아 보였는데 다시 안 나오는 결과”, “어느 커밋/데이터/설정인지 모름”입니다.
- 누수/비용/유니버스 변경이 섞이면 **원인 추적 불가능**.

### (b) 위험/부작용
- 로그/아티팩트 저장으로 디스크/시간 비용 증가.
- 실험 속도가 소폭 느려질 수 있음.

### (c) 최소 실험(2~3개) — *E5, E1 참조*
- **E5**: 실행마다 (데이터 스냅샷 hash, 유니버스, 비용 파라미터, 시드, 커밋) 저장 강제
- **E1**: 누수 테스트/시간정합 체크를 CI처럼 “게이트”로 격상

### (d) PASS 조건
- 동일 커밋/동일 시드/동일 데이터 hash에서 결과가 **허용 오차 내 재현**(예: lockbox_mean ±1%p 이내)
- 실패 시에도 “어느 단계에서 실패했는지” 로그로 즉시 식별 가능

# 48시간 자동 루프용: 실행 가능한 Patch/실험 5개(E1~E5)

아래 5개만 만들고, TOP5 제안은 이 5개를 조합해서 굴립니다.

---

## E1) 누수/시간정합 강제 패치 + 누수 게이트
### (1) 실험 정의(패치)
- 데이터 로더/피처 생성에서 **asof merge**(시점키 기반) 강제
- 신호 생성 시 **최소 1 bar lag**(EOD 기반이면 다음 거래일 오픈/또는 다음 종가 체결로 통일)
- corporate actions(분할/배당) 처리 시 **가격/볼륨 조정이 미래정보를 쓰지 않도록** “발표/적용 시점” 분리
- “라벨/리턴 계산”은 항상 **t+1 이후**만 사용

### (2) 게이트(실패 시 즉시 중단)
- 랜덤 날짜 k개 샘플에 대해:
  - 피처 timestamp ≤ 주문 timestamp 조건 위반 0건
  - 라벨/리턴 창에 현재/미래 바 포함 0건
- 데이터 hash + asof key + lag 정책을 아티팩트로 저장(E5와 연동)

### (3) 기대 관측치
- tuning 성능 하락 가능(정상)
- 대신 lockbox에서 **MDD 악화가 줄거나**, tuning-lockbox 괴리 감소

---

## E2) 비용/체결 모델 현실화 + turnover cap
### (1) 실험 정의(패치)
- 체결가 = mid ± (half-spread) + slippage(ATR/가격 기반) + 임팩트(거래대금 대비)
- 비용 3단계:
  - 기본: 보통 스프레드/슬리피지
  - 보수: 기본의 1.5~2배
  - 극단: 기본의 3배(스트레스)
- 일/주 단위 **turnover 상한** 및 리밸런싱 최소 변경폭(threshold) 적용

### (2) 게이트
- 비용=0 대비 비용=기본에서 성과가 “기이하게” 거의 동일하면(차이가 너무 작으면) 비용이 적용 안 된 버그로 FAIL
- turnover 상한 위반 시 FAIL

### (3) 기대 관측치
- 평균 수익 하락(정상)
- 비용 보수/극단에서 “완전 붕괴”하는 전략은 실전 부적합 → 조기 폐기 가능

---

## E3) 유니버스 고정(8~14) + 심볼/상장 이벤트 규칙
### (1) 실험 정의(패치)
- 유니버스를 코드에서 “동적 선정”하지 말고 **고정 구성 파일**로 분리
- 심볼 변경/거래정지/결측 시 규칙:
  - 결측이 일정 기간 초과 시 거래 중단(현금/대체규칙)
  - 신규 상장/편입은 금지(고정 유지)
- Tech+Healthcare만 포함, 8~14 강제

### (2) 게이트
- 전체 백테스트 기간 동안 매일 유니버스 크기 8~14 유지(예외는 규칙 로그로 남겨야만 허용)
- “오늘 기준으로만 존재하는 티커” 참조 발견 시 FAIL(서바이버십 의심)

### (3) 기대 관측치
- 특정 구간 성과가 낮아질 수 있으나, 대신 결과가 더 신뢰 가능
- 리스크/분산 특성이 바뀌므로 E2(비용)와 함께 해석

---

## E4) 레짐 관측(ETF 지표만) 기반의 “단순 게이트” + 정규화
### (1) 실험 정의(패치)
- ETF는 **관측지표로만** 사용(매매 금지)
- 예시(단순):
  - QQQ, XLV의 추세/변동성, (옵션) TLT/IEF로 금리 민감도, (옵션) HYG로 크레딧 리스크
- 레짐이 불리할 때:
  - 포지션 크기 축소(노출 감축) 또는 시그널 임계값 상향(거래 횟수 감소)
- 신호 정규화:
  - cross-sectional z-score, clipping(winsorize), 포지션 상한

### (2) 게이트
- 레짐 게이트가 “항상 on/항상 off”면 FAIL(효과 없는 스위치)
- 레짐별 성과 리포트에서 특정 레짐에만 극단적으로 의존하면 FAIL(과최적화 의심)

### (3) 기대 관측치
- 평균 수익은 소폭 감소할 수 있으나 worst_mdd/fold mdd가 개선
- 거래 횟수↓ → 비용 민감도↓ (E2와 연결)

---

## E5) 운영/재현성 게이트(아티팩트/로그/원인추적)
### (1) 실험 정의(패치)
- 매 실행마다 아래를 “필수 저장”:
  - git commit hash / 브랜치
  - 데이터 스냅샷 hash(또는 파일 목록+mtime hash)
  - 유니버스 파일 checksum
  - 비용 모델 파라미터
  - 랜덤 시드
  - 누수 테스트 결과(E1)
- 결과 리포트에 “실행 ID → 설정/데이터/결과”를 1:1로 링크

### (2) 게이트
- 동일 실행 ID 재실행 시 주요 메트릭이 허용 오차 밖이면 FAIL(비결정성/데이터 드리프트)
- 필수 아티팩트 누락 시 FAIL

### (3) 기대 관측치
- 성능 변화 자체는 없지만, “왜 안 움직이는지/왜 움직였는지”를 1~2회전 안에 설명 가능해짐

# 성능이 “안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐)

아래는 **원인-증상 매핑**으로 바로 로그/리포트에 추가 가능한 분해 축입니다(질문 없이 적용).

## A) Trigger(신호 발생) 문제
- **증상**: 거래 수가 급감/급증, 특정 날짜에만 신호 폭발
- **체크**:
  - 일별 신호 발생률(종목별/전체) 시계열
  - 신호 분포(z-score, clipping 전/후)
- **트리거**:
  - 임계값이 레짐/변동성에 비해 고정되어 “항상/절대”가 됨

## B) Application(주문/체결 적용) 문제
- **증상**: 신호는 좋은데 PnL이 반대로 감, 체결가가 비현실적
- **체크**:
  - 신호 시점 vs 주문 시점 vs 체결 시점(타임라인 로그)
  - next-bar 적용/lag 규칙이 일관적인지
- **트리거**:
  - lookahead 제거 후 실제로는 “다음날”에 못 타는 구조였던 것

## C) Exposure(노출/리스크) 문제
- **증상**: 평균은 괜찮은데 MDD만 커짐, 특정 종목이 손실 대부분
- **체크**:
  - 종목별 기여도(PnL contribution), 최대 비중, 상위 1~2종목 의존도
  - 섹터(Tech/Healthcare) 내부 편향, 단일 팩터(모멘텀/베타) 쏠림
- **트리거**:
  - 8~14 압축 유니버스에서 포지션 상한이 느슨하면 단일종목 리스크 폭발

## D) Cost(비용) 문제
- **증상**: 비용=0에서는 좋고 비용 반영만 하면 사라짐
- **체크**:
  - gross vs net PnL 분리, turnover와 비용의 상관
  - 비용 3단계 스트레스(E2)에서 민감도 곡선
- **트리거**:
  - 고회전 알파(미세 신호)가 비용에 취약

## E) Regime(레짐) 문제
- **증상**: 특정 기간(금리 급등/리스크오프/헬스케어 이슈)에서만 붕괴
- **체크**:
  - 레짐별 성과 테이블(예: QQQ 추세 상/하, XLV 상대강도, 변동성 구간)
  - 레짐 전환 시점에서 포지션/turnover가 어떻게 변했는지
- **트리거**:
  - 하나의 알파가 레짐 의존인데, 레짐 감지/노출 축소가 없음(E4로 완화)

## 결론: 48시간 내 “가장 값싼” 성공 경로
- **E5(재현/로그) → E1(누수 게이트) → E3(유니버스 고정) + E2(비용/turnover) → E4(레짐 게이트)** 순으로 넣고,  
- PASS는 “평균 수익 극대화”가 아니라 **누수/서바이버십/비용/운영 리스크를 제거한 상태에서 lockbox_mean 유지 + worst_mdd 악화 방지/개선**으로 잡으세요.
