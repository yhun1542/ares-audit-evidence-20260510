### 🥇 P1: MDD 방어 강화 — Drawdown-Triggered Deleveraging

#### (a) 왜 필요한가
- worst_mdd -11.18%가 개선되지 않음 → 테일 리스크 고정
- lockbox_min 1.35 정체 = 최악 fold에서 손실 방어 부재
- **현재 시스템은 MDD 발생 후 대응 없음 (패시브 리밸런싱만)**

#### (b) 위험/부작용
- 과최적화: 특정 drawdown threshold가 과거에만 최적
- 휩쏘: 빈번한 deleverage→releverage로 비용 폭발
- 레짐 의존: 2022 스타일 급락에만 맞춰질 수 있음

#### (c) 최소 실험 3개
```yaml
exp_p1_mdd_delev:
  variants:
    - name: "mdd_5pct_half"
      trigger: portfolio_dd >= 5%
      action: reduce_exposure_to 50%
      recovery: dd < 3% → restore 100%
    
    - name: "mdd_7pct_third"  
      trigger: portfolio_dd >= 7%
      action: reduce_exposure_to 33%
      recovery: dd < 4% → restore 100%
    
    - name: "vol_scaled_delev"
      trigger: realized_vol_20d > 1.5 * median_vol
      action: exposure = baseline / vol_ratio
      recovery: vol normalizes → restore
```

#### (d) PASS 조건
```
GATE:
  - worst_mdd >= -10.5% (0.68%p 개선)
  - lockbox_min >= 1.38 (2.2% 개선)
  - lockbox_mean >= 1.78 (degradation < 1%)
  - turnover_increase < 20%
```

### 🥈 P2: 종목 품질 필터 — Earnings Stability Gate

#### (a) 왜 필요한가
- 현재 모멘텀/퀄리티 지표만 사용 추정
- 실적 발표 후 급락 종목이 MDD 주범일 가능성
- Healthcare 특히 FDA/임상 이벤트에 취약

#### (b) 위험/부작용
- Universe 축소 → 분산 감소
- Survivorship bias: 과거 데이터에서 "좋은 실적" 기업만 남음
- 실적 데이터 지연(8-K lag) 미반영 시 누수

#### (c) 최소 실험 2개
```yaml
exp_p2_earnings_gate:
  variants:
    - name: "eps_beat_streak"
      filter: last 4Q EPS beat >= 3회
      apply_to: entry only (exit 무관)
    
    - name: "revenue_stability"
      filter: revenue_yoy_std(4Q) < 15%
      exclude: biotech (GICS 352010)
```

#### (d) PASS 조건
```
GATE:
  - lockbox_mean >= 1.79 (no degradation)
  - worst_mdd >= -10.8% (개선 또는 유지)
  - avg_holding_count >= 8 (과도한 축소 방지)
```

### 🥉 P3: 섹터 동적 틸트 — Tech/HC Regime Rotation

#### (a) 왜 필요한가
- Tech+HC 고정 비중 → 금리 상승기(2022) 동반 급락
- 섹터 간 상관관계 변동 미반영
- lockbox 일부 fold에서 두 섹터 동시 하락 관측 가능성

#### (b) 위험/부작용
- 섹터 타이밍 = 어려움, 과최적화 1순위
- 백테스트에서 완벽해 보여도 실전 레짐 전환 인식 지연
- 거래 비용 증가

#### (c) 최소 실험 2개
```yaml
exp_p3_sector_tilt:
  variants:
    - name: "rate_sensitive_tilt"
      signal: US10Y_3m_change > 50bp
      action: HC weight += 10%, Tech weight -= 10%
      revert: US10Y stable 2 months
    
    - name: "relative_strength_tilt"
      signal: XLK/XLV 20d ratio < 0.95
      action: overweight laggard sector by 15%
```

#### (d) PASS 조건
```
GATE:
  - fold별 sharpe 표준편차 < current (안정성)
  - lockbox_min >= 1.35 (최소 유지)
  - 섹터별 max_weight <= 70% (집중 방지)
```

### P4: 거래비용 현실화 — Slippage Model Upgrade

#### (a) 왜 필요한가
- 현재 비용 모델 불명확 → 실제 수익률 누수 가능
- 소형주/저유동성 종목에서 슬리피지 과소 추정 위험
- **이건 "성능 개선"이 아니라 "진짜 성능 확인"**

#### (b) 위험/부작용
- 비용 올리면 백테스트 성능 하락 (진실이지만 painful)
- 과도한 비용 가정 시 실행 가능 전략 범위 축소

#### (c) 최소 실험 2개
```yaml
exp_p4_cost_model:
  variants:
    - name: "tiered_slippage"
      cost: |
        market_cap > 50B: 5bp
        market_cap 10-50B: 10bp
        market_cap < 10B: 20bp
    
    - name: "volume_impact"
      cost: 0.1 * (trade_size / avg_volume_20d)^0.5
```

#### (d) PASS 조건
```
GATE (다름 — 하락 허용):
  - lockbox_mean >= 1.65 (10% 하락까지 수용)
  - 하락분이 "비용 차이"로 설명 가능해야 함
  - 비용 반영 후에도 sharpe > 1.0 유지
```

---

### P5: 홀딩 기간 최적화 — Rebalancing Frequency Test

#### (a) 왜 필요한가
- 현재 리밸런싱 주기 불명 → 암묵적 turnover
- 너무 잦으면 비용, 너무 드물면 시그널 decay
- MDD 방어와 상호작용 있음

#### (b) 위험/부작용
- 주기 자체를 파라미터화하면 과최적화
- 짧은 주기 = 더 많은 데이터 필요 (fold당 샘플 감소)

#### (c) 최소 실험 2개
```yaml
exp_p5_rebal_freq:
  variants:
    - name: "weekly_rebal"
      frequency: 5 trading days
      
    - name: "monthly_rebal"  
      frequency: 21 trading days
      
    - name: "signal_triggered"
      frequency: rebal when top_rank changes > 30%
```

#### (d) PASS 조건
```
GATE:
  - lockbox_mean >= 1.78
  - turnover_annual < 400% (과도한 회전 방지)
  - 거래비용 반영 후 순수익 개선
```

## 2. 성능이 안 움직일 때 — 원인 분해 트리

```
[성능 정체]
    │
    ├─[1] 트리거 문제: 시그널이 발생 안 함
    │   └─ 체크: signal_fired_rate by fold
    │   └─ 원인: threshold 너무 엄격 / 데이터 부재
    │
    ├─[2] 적용 문제: 시그널 → 포지션 전환 안 됨
    │   └─ 체크: position_change_when_signal
    │   └─ 원인: 기존 포지션 유지 로직 / 버퍼 과다
    │
    ├─[3] 노출 문제: 포지션은 바뀌는데 PnL 무반응
    │   └─ 체크: 변경된 종목의 return 분포
    │   └─ 원인: 신규 종목도 비슷한 성과 / 상관관계 높음
    │
    ├─[4] 비용 문제: gross는 개선, net은 동일
    │   └─ 체크: gross_return - net_return by fold
    │   └─ 원인: turnover 증가분 = 수익 증가분
    │
    └─[5] 레짐 문제: 특정 fold만 개선, 다른 fold 악화
        └─ 체크: fold별 delta 분포
        └─ 원인: 과최적화 / 레짐 특화
```
