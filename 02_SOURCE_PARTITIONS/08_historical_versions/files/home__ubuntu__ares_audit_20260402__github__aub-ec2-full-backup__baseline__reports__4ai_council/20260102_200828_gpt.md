아래는 **24~48시간 안에 자동 루프(48h)로 돌릴 수 있는 “우선순위 TOP5”**와, 이를 검증하기 위한 **유니크 실험 5개(E1~E5)**만 제시합니다(각 제안은 이 5개 실험을 조합해 2~3개씩 참조).  
우선 점검 순서는 **누수/과최적화 → 서바이버십 → 비용 → 운영 리스크**를 최우선으로 둡니다. (미국주식 only, Tech+Healthcare 8~14종목, ETF는 관측지표만)

---

## 0) 48시간 자동 루프 실행 순서(명령형 체크리스트)
1. **E1 먼저 적용(운영/로그 복구)** → 도구들이 깨져 있으면 이후 개선이 “안 움직이는 것처럼” 보임.
2. **E2(누수/폴드 degeneracy) + E3(비용/턴오버)**를 1차로 돌려 “진짜 수익원”인지 확인.
3. **E4(서바이버십/유니버스/8~14종목 강제) + E5(노출/리스크/레짐)**로 운영 가능한 형태로 수렴.
4. 각 실험은 반드시 **(정의 → 게이트 → 기대 관측치)** 형태로 기록하고, 48시간 내 **최소 2회 재현(run 2 seeds or 2 time windows)**.

# TOP5 제안 (코드/아키텍처/전략)

## 1) (운영 리스크) 리밸런스/트레이드 로그 및 run 메타데이터를 “도구 친화 포맷”으로 고정
현재 `aub_rebalance_pinpoint`가 **base-log/cand-log 로드 실패**(파일 경로/JSON 포맷 문제)로 “왜 성능이 안 움직였는지” 추적이 막혀 있습니다. 또한 champion에 `lane_hash/run_hash=None`, `worst_mdd=None`는 **재현/비교/리스크 산출 체인 누락** 신호입니다.

- (a) 왜 필요?
  - 성능 정체의 1순위 원인은 종종 **전략이 아니라 관측/로깅 파이프라인 결손**입니다.
  - 리밸런스/체결/포지션 변화를 못 보면 “트리거는 변했는데 적용이 안 됨” 같은 버그를 못 잡습니다.

- (b) 위험/부작용
  - 로그 스키마 변경이 기존 리포트/대시보드와 충돌 가능.
  - 저장량 증가(단, 48h 루프에서는 감수할 가치가 큼).

- (c) 최소 실험(2~3개, 아래 E1~E5 참조)
  - **E1(필수)** + E3(비용 항목도 로그에 포함) + E5(노출/리스크 지표까지 메타로 고정)

- (d) PASS 조건
  - `aub_rebalance_pinpoint.py`가 **입력 2개(base/cand) 모두에서 무오류 실행**
  - 각 run에 `run_hash`, `lane_hash`, `worst_mdd`, `exposure_min/max`, `turnover`, `cost_breakdown`가 **항상 채워짐**
  - “리밸런스 이벤트 수 / 거래 수 / 포지션 수”가 0이 아닌데도 성능이 0변화면 **원인 추적 가능(로그로 설명 가능)**

---

## 2) (누수/과최적화) degenerate_folds 제거 + 시간 정렬/엠바고로 누수 가능성 차단
현재 `degenerate_folds: [1,2,3,8]`은 **CV 분할이 사실상 깨졌거나(데이터 부족/동일 값), 누수/정렬 문제**로 성능이 “고정”되는 전형적 징후입니다.

- (a) 왜 필요?
  - 폴드가 퇴화하면 OOS mean이 의미가 없어지고, 실험 간 차이가 “안 움직이는 것처럼” 보일 수 있습니다.
  - 특히 퀀트 파이프라인에서 **라벨/피처 시점 불일치(t vs t+1)**는 가장 흔한 잠복 누수입니다.

- (b) 위험/부작용
  - 누수 제거 시 단기 성능 하락 가능(“진짜” 성능이 드러나는 과정).
  - 엠바고/시프트로 거래 신호가 하루 늦어져 회전이 느려질 수 있음.

- (c) 최소 실험(2~3개)
  - **E2(필수)** + E1(폴드별 요약 로그 강화) + E4(유니버스/상장폐지 처리로 폴드 데이터 안정화)

- (d) PASS 조건
  - degenerate_folds가 **0개** 또는 “원인(데이터 공백/분할 기간 부족)이 로그로 명확히 설명”
  - OOS 결과가 seed/기간 변경에 대해 **방향성이 유지**(완전 동일 수치 반복 금지)
  - 피처/라벨 타임스탬프 검증에서 **t일 종가로 t일 체결 같은 룩어헤드 패턴 0건**

---

## 3) (비용 미반영) 실거래 비용/슬리피지/대차비용 + 턴오버 제약을 “스코어에 직접 반영”
지금 상태는 “OOS mean은 괜찮은데 실전 불능” 혹은 반대로 “비용 반영 누락으로 실험 간 차이가 안 보임” 가능성이 큽니다. Tech/Healthcare 8~14종목 집중이면 **턴오버/슬리피지 영향이 더 크게** 나타납니다.

- (a) 왜 필요?
  - 비용이 모델 밖이면 최적화가 **거래를 통한 알파 착시**로 흐르기 쉽습니다.
  - 비용을 넣어야 실험 간 차이가 “움직일” 조건이 생깁니다(특히 미세한 개선).

- (b) 위험/부작용
  - 성능 급락 가능(특히 고회전 전략).
  - 비용 파라미터 과대 설정 시 과도한 보수화로 기회 상실.

- (c) 최소 실험(2~3개)
  - **E3(필수)** + E1(비용 breakdown 로깅) + E5(노출 제한으로 불필요 거래 감소)

- (d) PASS 조건
  - 비용 포함 후에도 OOS mean이 **양(+) 유지** 또는 하락하더라도 **턴오버/슬리피지 민감도**가 리포트로 설명 가능
  - `turnover`, `trade_count`, `avg_hold_days`가 목표 범위로 수렴(예: 과도한 데일리 올인/올아웃 패턴 제거)
  - “비용 0 vs 비용 On” 비교에서 성능 차이가 합리적인 크기로 나타남(0이면 비용이 적용 안 된 것)

---

## 4) (서바이버십/유니버스) 포인트-인-타임 유니버스 + 상장폐지/합병/스플릿 처리 + 8~14 Tech/Healthcare 강제
Tech/Healthcare 중심 8~14종목은 가능하지만, **서바이버십/코퍼레이트 액션 처리**가 약하면 OOS가 “고정”되거나 비현실적으로 좋아집니다.

- (a) 왜 필요?
  - 유니버스가 현재 시점 종목으로만 구성되면 과거 성능이 왜곡됩니다.
  - 8~14로 “집중”할수록 종목 교체/상폐 이벤트의 영향이 커서 PIT 정합성이 핵심입니다.

- (b) 위험/부작용
  - 데이터 소스에 PIT 정보가 없으면 구현 난이도↑(대신 최소한의 방어 로직은 가능).
  - 유니버스 축소로 백테스트 표본이 줄어 변동성↑.

- (c) 최소 실험(2~3개)
  - **E4(필수)** + E2(시간 정렬) + E3(유동성/ADV 기반 슬리피지 반영)

- (d) PASS 조건
  - 과거 특정 날짜에 존재하지 않던 티커가 유니버스에 들어오는 케이스 0
  - 상장폐지/거래정지 발생 시 포지션 처리 규칙이 명시되고 로그로 재현됨(“가격 0” 같은 비정상 데이터 제거)
  - 포트폴리오가 항상 **8~14종목**(결측 시 현금/대체 규칙 명시), 섹터는 Tech+Healthcare로 제한

---

## 5) (운영/리스크) 노출(exposure)·MDD 산출 누락 해결 + 레짐/리스크 가드레일로 “노출이 흔들려 성능이 안 움직이는 문제” 제거
현재 champion에 `worst_mdd: None`, exposure가 `0.0 / 0.8388`로 찍히는 점은 **리스크 산출 파이프라인 누락** 또는 “가끔 완전 미노출” 상태일 가능성이 있습니다. 성능이 안 움직일 때 흔한 원인이 **신호는 바뀌지만, 게이트/클리핑으로 포지션이 0이 되는 현상**입니다.

- (a) 왜 필요?
  - 노출이 0이면 어떤 신호 개선도 PnL에 반영되지 않습니다.
  - 레짐(VIX/금리/나스닥 변동)별로 위험을 조절해야 집중 포트폴리오가 운영 가능합니다.

- (b) 위험/부작용
  - 과도한 가드레일은 알파를 깎고 “항상 비슷한 포지션”으로 수렴(다양성 감소).
  - 변동성 타겟팅이 잦은 리밸런스를 유발할 수 있음(→ E3로 비용 동시 점검).

- (c) 최소 실험(2~3개)
  - **E5(필수)** + E3(비용/턴오버 동시) + E1(리스크 메트릭 로그 고정)

- (d) PASS 조건
  - `worst_mdd`가 항상 계산되고, `exposure_min`이 **의도한 하한 이상**(예: 0.1 이상)으로 유지
  - 성능이 정체되는 구간에서 “노출 0/클리핑/게이트 발동” 여부가 로그로 즉시 확인 가능
  - 레짐별(예: VIX 상/중/하) 성능 분해에서 특정 레짐에만 과도 의존하지 않음

# 유니크 실험 5개 (48시간 자동 루프에 넣을 정의/게이트/기대 관측치)

## E1) 리밸런스/체결/포지션 로그 스키마 고정 + base/cand 경로 자동 해소
- (1) 실험 정의
  - 매 run마다 `rebalance.jsonl`(또는 csv) 생성: timestamp, universe, target_w, executed_w, fill_price, slippage, costs, position_before/after
  - `run_hash/lane_hash` 생성 및 아티팩트에 저장, `worst_mdd`/exposure/turnover를 요약 메타로 저장
  - `aub_rebalance_pinpoint` 입력 경로를 “존재하는 최신 파일”로 자동 resolve(하드코딩 `--base-log` 제거)
- (2) 게이트
  - 도구 2개(`no_delta_diagnoser`, `rebalance_pinpoint`)가 **무오류 실행** + 리포트가 비어있지 않음
- (3) 기대 관측치
  - “성능이 안 움직임”의 원인이 **(a) 거래가 없었음 (b) 거래는 있었으나 비용으로 상쇄 (c) 노출 0** 중 하나로 분류 가능해짐

## E2) 시간 정렬/누수 차단 패치 + walk-forward/embargo 적용
- (1) 실험 정의
  - 모든 피처를 **t-1 기준으로만** 사용(예: t일 종가로 의사결정이면 체결은 t+1 시가/또는 t+1 VWAP 등으로 통일)
  - CV에 **embargo 1~5일**(최소 1일) 적용
  - 폴드별 표본 수/결측률/타깃 분포 로깅
- (2) 게이트
  - degenerate_folds 감소(0이 목표) + 폴드별 표본 수가 최소 기준 이상
- (3) 기대 관측치
  - OOS mean이 단기 하락할 수 있으나 **폴드 간 변동이 정상화**되고 실험 간 차이가 “움직이기 시작”

## E3) 비용/슬리피지/대차비용 + 유동성 기반 슬리피지(간단 모델) + 턴오버 페널티
- (1) 실험 정의
  - 커미션(예: $0.005/share) + 슬리피지(예: bps + size/ADV 기반) + 공매 대차비용(연율 bps, 단순 상수로 시작)
  - 목적함수/스코어에 turnover penalty를 추가(또는 리밸런스 threshold로 매매 빈도 제한)
- (2) 게이트
  - 비용 ON에서도 전략이 붕괴하지 않거나(양의 기대값 유지), 붕괴 시 **턴오버/슬리피지 민감도**로 원인이 명확
- (3) 기대 관측치
  - “좋아 보이던 실험”이 사라지고, **저회전·집중 포트폴리오에 맞는 신호**가 살아남음

## E4) 포인트-인-타임 유니버스 + Tech/Healthcare 필터 + 8~14종목 강제
- (1) 실험 정의
  - 각 날짜별 거래 가능 종목(상장/거래정지/상폐 반영)만 포함
  - 섹터는 Tech+Healthcare로 제한, 포트폴리오는 항상 8~14종목(결측 시 현금/대체 규칙 고정)
  - 기업행위(splits/dividends) 조정 일관성 체크
- (2) 게이트
  - 미래 티커 유입 0 + 결측/0가격 거래 0 + 종목 수 8~14 유지
- (3) 기대 관측치
  - 표본은 줄어도 **재현성/운영 가능성**이 급상승, fold degeneracy도 완화될 가능성

## E5) 노출/리스크 가드레일 + 레짐(ETF는 지표로만: QQQ/XLV/VIX 등) 조건부 스케일링
- (1) 실험 정의
  - 노출: net/gross 한도, 종목당 max weight, 섹터 편중 제한
  - 변동성 타겟팅(단순) + 드로우다운 기반 디레버(예: DD>10%면 risk scale 0.5)
  - 레짐 지표: QQQ/XLV 상대강도, VIX 구간을 **트레이드가 아니라 스케일 팩터**로만 사용
- (2) 게이트
  - exposure_min이 0에 붙지 않음 + worst_mdd가 항상 산출 + 비용(E3) 포함에도 턴오버 폭증 없음
- (3) 기대 관측치
  - 성능 평균이 약간 줄어도 **MDD/변동성 안정**, “노출 0 때문에 성능이 안 움직임” 문제 제거

# 성능이 안 움직일 때 원인 분해(트리거/적용/노출/비용/레짐) 체크 트리
아래를 **로그/리포트로 자동 산출**하게 만들면, “정체”가 전략 문제인지 파이프라인 문제인지 1시간 내 분류됩니다.

## A. 트리거(신호) 레이어
- 신호 분산이 거의 0인가? (cross-sectional std, time-series std)
- 상위/하위 랭크 종목이 매일 동일한가? (rank stability)
- 신호가 특정 종목에만 쏠리는가? (top-1 concentration)

## B. 적용(포지션 생성/리밸런스) 레이어
- 타깃 웨이트는 변하는데 executed가 0인가? (게이트/클리핑/거래불가)
- min trade threshold 때문에 대부분 무시되는가?
- 리밸런스 주기/캘린더 버그로 이벤트가 발생하지 않는가?

## C. 노출(Exposure) 레이어
- net/gross가 의도치 않게 0으로 수렴하는가? (`exposure_min`이 0 근처)
- 베타(예: QQQ) 노출이 과도하게 고정되어 알파가 묻히는가?
- 8~14종목 강제에서 현금 비중이 과도해지는가?

## D. 비용(Implementation) 레이어
- turnover가 높아 비용이 알파를 상쇄하는가?
