## 1. 우선순위 TOP 5 제안 (48시간 루프)

다음은 `Degenerate Folds` (1, 2, 3, 8) 문제를 해결하고, 로깅 오류를 수정하여 검증 가능한 상태로 만들기 위한 명령형 체크리스트입니다.

1.  **[Infra] Rebalance Log 포맷 강제 수정**: 현재 `rebalance.csv/jsonl` 파싱 에러는 치명적임. 트랜잭션 단위 JSONL로 통일하고 Flush 주기를 매 스텝으로 변경.
2.  **[Logic] Entry Threshold 이완 실험**: Fold 1, 2, 3(특정 하락/횡보 구간 추정)에서 거래가 '0'이거나 손실 확정 후 복구가 안 되는 상태임. 진입 장벽(Threshold)을 15% 낮춰 거래 빈도(Turnover) 강제 주입.
3.  **[Risk] Exposure Min/Max 댐핑(Damping)**: 현재 0.0 ~ 0.84의 극단적 스위칭은 과최적화의 전형. Min 0.1 / Max 0.6으로 강제하여 '항상 시장에 있되, 비중만 조절'하는 로직으로 변경.
4.  **[Universe] Bio/Tech 섹터 상관관계 헷지**: 헬스케어(XLV 등)와 테크(XLK 등)의 베타가 다름. 두 섹터 간 비중을 동적으로 조절하는 'Sector Regime Switch' 로직 도입 (ETF는 시그널로만 사용).
5.  **[Cost] 비용 가중치 스트레스 테스트**: 현재 OOS Mean 3.32는 비현실적. 슬리피지(Slippage) 모델을 2배(예: 5bps -> 10bps)로 설정 후 생존 여부 확인.

## 2. 실행 가능한 Patch/실험 (3 selected)

### 실험 A: [Infra] Logger Integrity Fix (최우선)
*   **(a) 필요성**: `Error loading ... Expecting value` 오류로 인해 챔피언 모델의 실제 매매 내역(Turnover, Holding period)을 검증할 수 없음. 맹목적 믿음 방지.
*   **(b) 위험/부작용**: 시스템 로직 변경 없음. 로그 파일 용량 증가 가능성.
*   **(c) 실험 정의 (48h Loop)**
    1.  **실험 정의**: `FileHandler`를 `JSONL` 모드로 고정하고, `rebalance` 이벤트 발생 시 즉시 `flush()` 호출. 기존 CSV 파서 제거.
    2.  **게이트(Pass/Fail)**:
        *   `aub_rebalance_pinpoint.py`가 에러 없이 실행될 것.
        *   생성된 로그 라인 수 == 백테스트 거래 일수와 일치할 것.
    3.  **기대 관측치**: `degenerate_folds` 구간에서 실제로 'No Trade'인지 'Whipsaw(손절 반복)'인지 판별 가능해짐.

### 실험 B: [Logic] Low-Vol Entry Relaxation (Fold 1,2,3 타겟)
*   **(a) 필요성**: Fold 1, 2, 3이 망가진(degenerate) 이유는 해당 기간의 변동성이나 모멘텀이 전략의 기준치에 미달했기 때문. 진입 조건을 완화하여 샘플 확보 필요.
*   **(b) 위험/부작용**: False Positive 진입 증가로 전체 승률(Win Rate) 하락 가능성. MDD 증가 위험.
*   **(c) 실험 정의 (48h Loop)**
    1.  **실험 정의**: 진입 트리거(예: RSI, Volatility Breakout 등)의 값을 기존 대비 **0.85배**로 낮춤. (예: RSI 30 -> 35, Vol > 2.0 -> Vol > 1.7). 대상 종목: Tech/Bio 상위 10개 고정.
    2.  **게이트(Pass/Fail)**:
        *   Degenerate Folds (1, 2, 3, 8) 중 최소 2개 이상에서 수익률 0.0 초과 또는 거래 횟수 > 5회 발생.
        *   전체 OOS Mean이 2.5 이하로 떨어지지 않을 것.
    3.  **기대 관측치**: 죽어있던 Fold의 수익 곡선이 활성화되며, OOS Mean은 약간 하락하더라도 Sharpe Ratio의 안정성이 개선됨.

### 실험 C: [Risk] Exposure Smoothing (Binary Switching 제거)
*   **(a) 필요성**: `exposure_min/max: 0.0 / 0.83`은 전형적인 타이밍 과신(Overconfidence). 빗나가면 바로 손실이거나 기회비용 발생.
*   **(b) 위험/부작용**: 하락장에서 0.0(현금)으로 도망치지 못해 MDD가 악화될 수 있음.
*   **(c) 실험 정의 (48h Loop)**
    1.  **실험 정의**: 포트폴리오 노출 비중 결정 시 `Sigmoid` 또는 `Step` 함수 대신 `Moving Average` 기반의 완만한 조절 적용.
        *   Rule: `Target_Exposure = 0.5 * Current_Signal + 0.5 * Prev_Exposure` (관성 추가).
        *   Constraint: Min Exposure 0.1 강제.
    2.  **게이트(Pass/Fail)**:
        *   Exposure 변동성(std dev)이 기존 대비 30% 이상 감소.
        *   `worst_mdd`가 검출될 것 (None이 아니어야 함).
    3.  **기대 관측치**: 수익률 곡선(Equity Curve)이 부드러워지고, 극단적인 OOS 수치가 현실적인 수준(Mean 1.5~2.0)으로 수렴.

## 3. 성능 정체 시 원인 분해 (Diagnosis Logic)

성능이 개선되지 않거나 지표가 움직이지 않을 경우, 다음 순서로 원인을 트리에서 제거하십시오.

1.  **Trigger Failure (신호 부재)**
    *   *Check*: Degenerate Fold 기간에 `Buy Signal` 자체가 0인가?
    *   *Action*: Universe(종목풀) 내 Tech/Bio 종목들이 해당 시기에 상장 폐지되었거나 데이터 누락(NaN)인지 확인.

2.  **Execution Block (주문 거부)**
    *   *Check*: 시그널은 떴는데 `Cash Constraint`나 `Volume Limit`에 걸려 체결이 안 되었는가?
    *   *Action*: 1주 단위 소액 거래로 로직 테스트.

3.  **Regime Mismatch (레짐 불일치)**
    *   *Check*: 해당 Fold가 금리 인상기(2022) 혹은 섹터 로테이션 시기인가?
    *   *Action*: Tech Only에서 Tech(7):Bio(3) 고정 비율로 변경하여 섹터 헷지 효과 확인.

4.  **Cost Drag (비용 잠식)**
    *   *Check*: 거래 횟수는 많은데 수익이 0에 수렴하는가?
    *   *Action*: 평균 보유 기간(Holding Period)이 3일 미만인지 확인 (초단타 과최적화 의심).
