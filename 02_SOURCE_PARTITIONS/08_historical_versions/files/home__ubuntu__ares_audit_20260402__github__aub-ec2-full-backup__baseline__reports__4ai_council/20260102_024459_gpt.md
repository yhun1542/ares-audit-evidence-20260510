## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — “명령형 체크리스트”
(누수/과최적화/서바이버십/비용/운영리스크 순서로 배치)

---

# 1) **누수(lookahead)·라벨 정렬·PIT(point-in-time) 강제**
### (a) 왜 필요한지
- Champion이 tuning 대비 lockbox 하락(3.47 → 2.89)인 상태에서 **가장 먼저 의심할 건 미세 누수/라벨 타이밍 불일치**.
- Tech/Healthcare는 이벤트(실적, FDA, 가이던스)로 점프가 많아 **리포팅 지연/거래가능 시점**이 조금만 틀려도 성능이 “조용히” 과대평가됨.

### (b) 위험/부작용
- PIT 강제하면 단기적으로 성능이 떨어질 수 있음(“진짜” 성능으로 재정렬).
- 데이터 소스/피처 일부가 무효화되어 모델 입력 차원이 줄 수 있음.

### (c) 최소 실험(1개 런에 2~3개 변형 포함)
**실험 정의 (48h 루프용 Patch-Exp #1): `PIT_GUARDRAIL`**
- 변형 A: 모든 피처를 **t 시점 결정 → t+1 체결**로 강제(최소 1-bar lag)
- 변형 B: 롤링/표준화/랭크 계산 시 **미래 포함 여부 검사(윈도 경계)** + “fit on past only”
- 변형 C: (펀더멘털/리포트성 피처가 있다면) **발표일+지연(예: +1~2영업일) 적용** 또는 해당 피처 off 비교

**게이트(자동 FAIL 조건)**
- (G1) 변형 A/B/C 중 하나라도 **lockbox_mean이 tuning_mean보다 과도하게 높아지는 형태의 비정상 갭이 재발**하면(=누수 의심 패턴) 해당 모듈 즉시 FAIL
- (G2) 데이터 타임스탬프/인덱스 단조성 위반, 결측 forward-fill이 미래를 당기는 패턴 탐지 시 FAIL

**기대 관측치**
- 누수가 있었으면: tuning 성능이 내려가고 fold 간 분산이 줄거나, lockbox에서 과장된 승률 패턴이 사라짐.
- 누수가 없으면: 성능은 비슷하되 **tuning↔lockbox 갭이 안정**.

### (d) PASS 조건
- lockbox_mean **유지 또는 소폭 개선(≥ +0.10)** AND worst_mdd **악화 없음(≤ -0.01p 악화까지만 허용)**  
- tuning↔lockbox 성능 격차가 **축소 또는 안정**(극단적 괴리 제거)

# 2) **비용(슬리피지/스프레드/충격/차입) 모델 반영 + 턴오버 게이트**
### (a) 왜 필요한지
- Tech/Healthcare 8~14종목은 보통 유동성은 좋지만, **신호가 잦으면 비용이 알파를 잠식**.
- 현재 지표가 “비용 반영 전”이면, lockbox에서 성능이 평평해지는 가장 흔한 원인.

### (b) 위험/부작용
- 현실 비용을 넣으면 대부분 전략이 성능 하락.
- 너무 보수적으로 잡으면 좋은 전략까지 제거(보수성 과다).

### (c) 최소 실험 (Patch-Exp #2): `COST_TURNOVER_REALISM`
**실험 정의**
- 변형 A: 고정 수수료+반스프레드(예: 1~3bp) + 슬리피지(거래대금 대비) 단순모델
- 변형 B: **거래량 기반 충격(참여율 cap)**: 일 거래대금의 x% 이상 체결 가정 금지(초과분은 다음 바로 이월하거나 신호 감쇠)
- 변형 C: **Short 비용/차입 불가 상황**을 보수적으로 반영(쇼트 허용 전략이면 반드시)

**게이트**
- (G1) 연환산 턴오버(또는 일평균 회전율) 상한 설정 후 초과 시 자동 FAIL  
- (G2) 비용 차감 후 Sharpe/목표지표가 0 근처로 붕괴하면 FAIL(비용 민감 전략 배제)

**기대 관측치**
- 비용을 넣어도 유지되는 전략은 대체로 **거래 빈도↓ / 보유기간↑ / 신호 강도↑**로 재정렬됨.

### (d) PASS 조건
- 비용 반영 후 lockbox_mean **≥ 기존 lockbox_mean - 0.10** (비용 모델 도입에 따른 “허용 가능한” 하락 범위 내)  
- worst_mdd **개선 또는 동일**, 턴오버 게이트 통과

# 3) **과최적화 방지: Time-series Purge/Embargo + 단순화(규제)**
### (a) 왜 필요한지
- Champion tuning이 높고 lockbox가 상대적으로 낮은 패턴은 **CV 누수/중복 샘플/레짐 특이 구간 과적합** 가능성이 큼.
- 특히 Tech/Healthcare는 2020/2022 같은 레짐 특이성이 커서 **Fold 분리 규칙이 약하면 과대평가**.

### (b) 위험/부작용
- Purge/embargo를 넣으면 tuning 성능이 눈에 띄게 하락 가능(하지만 “진짜”에 가까움).
- 파라미터 탐색 효율이 떨어짐.

### (c) 최소 실험 (Patch-Exp #3): `TS_CV_HARDENING`
**실험 정의**
- 변형 A: 이벤트/리밸런스 주기 기준으로 **purge window 적용**
- 변형 B: fold 경계에 **embargo(예: n일)** 적용해 정보 누설 차단
- 변형 C: 모델 복잡도 1단계 낮추기(피처 수/트리 깊이/정규화 강화 중 1개만)로 **단순화 민감도** 체크

**게이트**
- (G1) fold 간 성능 분산(표준편차) 과도하면 FAIL(=특정 구간 의존)
- (G2) 단순화에 성능이 급락하면 FAIL(=과도한 복잡도 의존)

**기대 관측치**
- “진짜 강한” 신호면 Purge/Embargo 후에도 lockbox가 안정.
- 과최적화면 tuning만 무너지고 lockbox가 더 안정적으로 재평가될 수 있음(나쁜 것 제거).

### (d) PASS 조건
- lockbox_mean **유지 또는 개선(≥ +0.05)**  
- worst_mdd **악화 없음** + fold 분산 감소

# 4) **레짐/리스크 오버레이(ETF는 관측지표로만) + 노출 게이트**
### (a) 왜 필요한지
- 성능이 “안 움직이는” 전략은 종종 **방향성 노출이 레짐에 휩쓸려 신호 알파가 상쇄**됨.
- Tech/Healthcare는 시장 베타 및 금리 민감도가 달라 **리스크 오버레이**로 MDD를 깎는 게 효율적.

### (b) 위험/부작용
- 오버레이가 과하면 알파까지 눌림(언더익스포저).
- 레짐 지표 선택이 과최적화 포인트가 될 수 있음(지표 남발 금지).

### (c) 최소 실험 (Patch-Exp #4): `REGIME_RISK_GATE`
**실험 정의**
- 관측지표(매매 금지): QQQ(Tech), XLV(Healthcare), VIX(또는 변동성 대용), UST10Y proxy(가능하면)
- 변형 A: 변동성 급등(VIX/실현변동 상단) 시 **gross exposure 50%로 축소**
- 변형 B: QQQ 추세 하락 레짐에서 **롱 바이어스 감소/중립화**
- 변형 C: 포지션별 손실 누적/포트폴리오 DD가 임계치면 **리밸런스 빈도↓(거래 억제)**

**게이트**
- (G1) 노출 축소 구간에서 turnover가 오히려 증가하면 FAIL(리스크 게이트가 거래만 유발)
- (G2) 레짐별 성과가 한 레짐에만 집중되면 FAIL(레짐 과적합 의심)

**기대 관측치**
- worst_mdd 및 fold14_mdd 개선이 가장 먼저 나타나야 정상.
- 수익률 평균은 비슷하더라도 **꼬리(왼쪽 tail) 절단**이 보이면 성공.

### (d) PASS 조건
- worst_mdd **개선(최소 +0.5%p)** 또는 동일  
- lockbox_mean **-0.05 이내**로만 희생(리스크 절감 대가 허용 범위)

# 5) **운영 리스크/서바이버십/유니버스 고정(Tech+Healthcare 8~14) + 재현성**
### (a) 왜 필요한지
- 자동 루프에서 가장 흔한 “조용한 실패”는 **유니버스 드리프트(구성 종목 변경), 티커 변경, 결측 처리 방식 변경, 재실행 비결정성(seed)**.
- 서바이버십이 있으면 장기 backtest가 미묘하게 부풀어 오름.

### (b) 위험/부작용
- 유니버스 고정은 기회 감소(하지만 평가 안정성↑).
- 데이터 정합성 체크가 빡세지면 실험이 느려질 수 있음.

### (c) 최소 실험 (Patch-Exp #5): `OPS_UNIVERSE_LOCK`
**실험 정의**
- 변형 A: Tech+Healthcare에서 **8~14개 티커를 “PIT 스냅샷”으로 고정**(기간별 교체 금지) 후 성능 재평가
- 변형 B: 티커/기업행위(합병, 스플릿) 이벤트 발생 시 **가격/리턴 연속성 체크** + 결측 처리 정책(삭제 vs 보간) 비교
- 변형 C: 모든 파이프라인에 seed 고정 + 산출물 해시 저장(동일 입력 → 동일 출력)

**게이트**
- (G1) 동일 커밋/동일 데이터로 실행 시 결과가 달라지면 FAIL(비결정성)
- (G2) 유니버스가 실행마다 바뀌면 FAIL(드리프트)

**기대 관측치**
- 성능 수치 자체보다 **분산/재현성 개선**이 먼저 확인됨.
- 이후 실험 해석 신뢰도가 올라감.

### (d) PASS 조건
- 2회 연속 재실행 시 주요 지표 차이(예: lockbox_mean)가 **허용오차 내(±0.02)**  
- 유니버스/데이터 품질 경고 0건

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **각 fold/lockbox에서 동일 포맷으로 로깅**해서 병목을 한 번에 찾도록 고정.

## A) Trigger(신호 발생) 문제
- 진단: 신호 상위/하위 분위 스프레드(예: top-bottom next-day return)가 **0에 수렴**하는지 확인
- 증상: 예측 점수 분포가 눌림(분산↓), 상위 종목이 매번 비슷, 이벤트 구간에서만 반응

## B) Apply(포지션 반영) 문제
- 진단: “원시 신호”와 “실제 포지션”의 상관/지연 확인(리밸런스 규칙이 신호를 죽이는지)
- 증상: 신호는 좋은데 포지션 제한/라운딩/캡으로 알파가 상쇄

## C) Exposure(노출) 문제
- 진단: 포트폴리오 베타(대상: QQQ/XLV는 관측만), 섹터 편향, net/gross, 상위 1~2종목 기여도(집중도)
- 증상: 알파는 있는데 **베타/금리/변동성**에 묻혀 성능 평평

## D) Cost(비용) 문제
- 진단: 턴오버 기여 손익 분해(“거래로 번 돈” vs “거래로 낸 돈”), 보유기간별 성과
- 증상: gross 성과는 있는데 net에서 사라짐(특히 잦은 리밸런스)

## E) Regime(레짐) 문제
- 진단: 레짐별(고변동/저변동, QQQ 상승/하락) 조건부 성과표를 고정 템플릿으로 생성
- 증상: 특정 레짐에서만 유효 → 평균으로 보면 “안 움직임”

## 즉시 적용(코드/리포트) 체크리스트(질문 없이 실행)
- [ ] 모든 피처에 “사용 가능 시점(timestamp)” 메타데이터 부여 후, 결정시점 초과 데이터 접근 시 예외 발생시키기
- [ ] 비용 모델(스프레드/슬리피지/충격/쇼트) ON/OFF 토글을 config 1줄로 만들기
- [ ] Purge/Embargo CV 옵션을 실험 스펙에 고정 추가
- [ ] 레짐 관측지표(QQQ/XLV/VIX)로 exposure gate만 추가(매매 금지 유지)
- [ ] 유니버스(Tech+Healthcare 8~14) 스냅샷 파일로 고정 + 재현성(seed/hash) 리포트 저장

위 5개 Patch-Exp만 돌려도 “성능 정체”의 80% 원인이 (누수/비용/과최적화/레짐/운영) 중 어디인지 48시간 내에 갈라집니다.
