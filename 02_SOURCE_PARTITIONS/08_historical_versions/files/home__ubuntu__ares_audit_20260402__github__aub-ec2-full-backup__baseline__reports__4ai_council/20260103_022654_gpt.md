# TOP5 우선순위 제안 (48시간 내 우선 처리 순)

## 1) [운영 리스크] 실험/리밸런스 “관측 가능성” 복구(재현성/감사 추적)
### (a) 왜 필요한지
- 현재 상태는 **성과가 움직여도 원인 분해가 불가능**하고, 잘못된 개선(우연/누수)도 잡아내기 어려움.
- `rebalance` 로그 미존재/파싱 실패는 **거래·비용·노출 디버깅을 봉쇄**.

### (b) 위험/부작용
- 로깅/스키마 변경으로 **기존 리포트/툴이 깨질 수 있음** → 버전 태깅 필요.
- 로그가 늘어 **스토리지/런타임 증가**.

### (c) 최소 실험 2~3개 (아래 “공용 실험” E1 사용)
- **E1-1**: 리밸런스 로그를 “항상” 생성하도록 강제  
- **E1-2**: `lane_hash/run_hash` 생성·고정(입력데이터 hash + 코드 git hash + config hash)  
- **E1-3**: `worst_mdd` 계산 파이프라인을 메트릭 필수 항목으로 강제(없으면 FAIL)

### (d) PASS 조건
- 모든 run에서 다음이 **무조건** 산출되어야 함  
  - `lane_hash`, `run_hash`, `worst_mdd`, `exposure_min/max`, `turnover`, `cost_paid`
  - `rebalance.jsonl(or csv)`가 1) 생성 2) 툴이 파싱 성공 3) 트레이드 단위로 “신호→목표비중→주문수량→체결가정→비용” 추적 가능

## 2) [누수/과최적화] Degenerate folds 제거 + Purge/Embargo로 시간 누수 차단
### (a) 왜 필요한지
- `degenerate_folds`가 여러 개면 **OOS mean이 의미 없어질 가능성**이 큼(폴드 길이 0, train/test 겹침, 누락된 구간 등).
- 특히 Tech/Healthcare 단일종목 전략은 **미세 누수에도 성과가 “가짜로” 튀는** 패턴이 흔함.

### (b) 위험/부작용
- 누수를 걷어내면 **성능이 떨어질 수 있음**(진실에 가까워지는 과정).
- 폴드 제약으로 탐색 공간이 줄어 **단기 OOS mean이 덜 좋아 보일 수 있음**.

### (c) 최소 실험 2~3개 (아래 “공용 실험” E2 사용)
- **E2-1**: 폴드 생성기 강제 검증(각 폴드에 최소 bar 수/거래일 수/종목 수 조건) 미달 시 폴드 폐기  
- **E2-2**: Purged K-Fold + Embargo(예: lookback window만큼 테스트 전후 구간 제거) 적용  
- **E2-3**: 피처/라벨 생성 시점에 “t 시점에서 t+1 이후 데이터 접근” 방지 어서션 추가(시계열 인덱스 기반)

### (d) PASS 조건
- `degenerate_folds == []` (0개)
- train/test 시점 겹침 0, embargo 적용 로그로 증명
- OOS mean이 떨어져도 괜찮음. 대신 **폴드별 분산/최저 성과(oos_min)**가 “설명 가능한 수준”으로 안정화

## 3) [비용 미반영] 거래비용/슬리피지/턴오버를 목적함수에 “하드” 반영
### (a) 왜 필요한지
- 현재 exposure 최대가 0.84 수준으로 보이고(현금 비중 변동 가능), 리밸런스 로그도 없어서 **턴오버 폭발/숨은 비용**이 성과를 갉아먹는지 판단 불가.
- Tech/Healthcare는 갭/이벤트가 잦아 **슬리피지 모델 미반영 시 OOS가 정체/붕괴**하기 쉬움.

### (b) 위험/부작용
- 비용 페널티가 너무 강하면 **거의 거래를 안 하는 퇴행(under-trading)**이 발생.
- 슬리피지 과대평가 시 유망 신호를 버릴 수 있음.

### (c) 최소 실험 2~3개 (아래 “공용 실험” E3 사용)
- **E3-1**: per-trade 고정 수수료 + 비례 비용 + 슬리피지(ATR 또는 변동성 기반) 반영  
- **E3-2**: **턴오버 상한(예: 일/주당)**을 게이트로 두고 위반 시 포지션 변경량 축소(“trade clipper”)  
- **E3-3**: 비용 반영 전/후를 동일 신호로 리플레이하여 “gross→net 손실 구간” pinpoint

### (d) PASS 조건
- net 기준 OOS mean 개선 또는 유지하면서  
  - turnover 감소(명시된 목표 대비)  
  - “비용/슬리피지로 인해 성과가 사라지는 구간”이 리포트로 분해됨(원인 규명 가능)

## 4) [운영+리스크] 노출/포지션 사이징/제약(8~14종목, 섹터 집중, 베타) 표준화
### (a) 왜 필요한지
- 현재 `exposure_min/max: 0.0 / 0.8388`이면 **현금화/리스크온-오프가 뒤섞여** 있을 수 있는데, 그 결정이 신호 때문인지(정상) 시스템 결측 때문인지(비정상) 불명.
- Tech+Healthcare는 상관이 높아 **“종목 수는 8~14인데 실질적으로 1~2 팩터에 올인”**이 되기 쉬움.

### (b) 위험/부작용
- 제약을 강하게 걸면 **단기 수익률이 희생**될 수 있음.
- 베타/섹터 중립을 과도하게 하면 **알파가 소거**될 수 있음.

### (c) 최소 실험 2~3개 (아래 “공용 실험” E4 사용)
- **E4-1**: 포지션 사이징을 변동성 타깃(예: 종목별 vol 스케일) + 종목당 최대비중 하드캡  
- **E4-2**: 포트폴리오 레벨 베타(대형지수/나스닥) 추정 후 목표 범위로 클립(현금 비중 포함으로만 조정; ETF 매매 금지 준수)  
- **E4-3**: 8~14 종목 유지 강제(미달 시 대체 후보 규칙/랭킹 보완) + 섹터(Tech/Healthcare) 내 편중 경보

### (d) PASS 조건
- 종목 수 8~14 안정 유지(강제 위반 0)
- 최대 단일 종목 비중, 포트폴리오 베타가 지정 범위 내
- worst_mdd가 최소한 “산출되고”, 개선/악화가 원인(노출 변화)로 설명 가능

## 5) [서바이버십+레짐] 미국주식 생존편향 제거 + ETF 관측지표로 레짐 태깅
### (a) 왜 필요한지
- 개별주 전략은 **상장폐지/인수합병/티커 변경**에서 생존편향이 자주 발생.
- “성능이 안 움직임”은 종종 **레짐(리스크온/오프, 금리, 방어주 선호)** 미스매치로 설명됨.
- ETF는 매매 금지지만 **관측지표로 레짐 라벨링**에는 최적.

### (b) 위험/부작용
- PIT(시점 일관) 유니버스 구성 비용/복잡도 증가.
- 레짐 피처가 누수로 변질될 수 있음(예: 미래 구간으로 레짐 레이블 확정).

### (c) 최소 실험 2~3개 (아래 “공용 실험” E5 사용)
- **E5-1**: 데이터에 **delisting return / ticker change 처리** 포함(가능한 소스 기준) + “유니버스 시점 고정”  
- **E5-2**: ETF 관측지표로 레짐 태그 생성(매매 X)  
  - 예: QQQ(성장/리스크), XLK(Tech), XLV(Healthcare), XLU(방어), IWM(중소형), TIP(실질금리 프록시)  
- **E5-3**: 레짐별 성과 분해 리포트(신호 히트율/노출/비용까지 같이)

### (d) PASS 조건
- 동일 기간에서 “서바이버십 ON/OFF” 성과 차이가 계량화되어 리포트로 남음(차이가 크면 즉시 경고)
- 레짐별로 성과 정체의 원인이 **신호 품질인지/노출인지/비용인지** 최소 1개 축으로 설명 가능

# 48시간 자동 루프용 “공용 실험(3~5개로 제한)” 정의
아래 **E1~E5 중 3~5개만** 돌려라. (권장: E1+E2+E3+E4 = 1차 / E5는 2차)

## E1) Observability Patch (로깅/해시/리밸런스 추적)
1) **실험 정의**: 리밸런스 로그 스키마 고정 + 해시 생성 + 리스크 메트릭 필수화  
2) **게이트**: 로그 파일 생성/파싱 성공, worst_mdd None 금지, run 재현 가능  
3) **기대 관측치**: “성과가 안 움직이는 이유”를 트레이드 단위로 추적 가능해짐(원인 분해 가능 상태로 전환)

## E2) Fold Sanity + Purge/Embargo (누수 차단)
1) **실험 정의**: degenerate fold 발생 조건을 FAIL로 두고, purge/embargo 적용  
2) **게이트**: degenerate_folds=0, train/test overlap=0  
3) **기대 관측치**: OOS mean이 변하더라도 폴드별 변동이 설명 가능해지고, “가짜 개선”이 줄어듦

## E3) Cost-aware Objective + Turnover Clipper
1) **실험 정의**: 슬리피지/비용을 net 성과에 반영 + 턴오버 상한  
2) **게이트**: turnover 목표 이하, net 성과 기준 비교 리포트 생성  
3) **기대 관측치**: gross는 같은데 net이 안 나오는 문제(“비용 블랙홀”)가 드러나거나 해결됨

## E4) Exposure/Risk Budgeting (사이징/베타/비중 캡)
1) **실험 정의**: 종목별 vol 스케일 + 최대비중/포트 베타 범위 클립 + 8~14 강제  
2) **게이트**: 제약 위반 0, 노출/베타 리포트 생성  
3) **기대 관측치**: 성과 정체가 “신호 문제”가 아니라 “노출 설계 문제”인지 분리 가능

## E5) Survivorship + Regime Tagging (ETF 관측지표만)
1) **실험 정의**: 유니버스 PIT 점검 + 레짐 태그로 성과 분해  
2) **게이트**: survivor ON/OFF 차이 리포트, 레짐별 KPI(히트율/비용/노출) 출력  
3) **기대 관측치**: 정체 원인이 레짐 미스매치인지 확인 가능

# 성능이 안 움직일 때: 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래 순서대로 “한 번에 하나씩” 고정/검증해라(케이스 폭발 방지).

## A. 트리거(리밸런스 발생) 문제
- 체크: 리밸런스 발생 횟수, 신호 갱신 주기, 트리거 조건 충족률  
- 징후: 거래가 거의 없거나(정체), 반대로 너무 잦음(비용에 눌림)  
- 조치: E1로 트리거 로그를 확보하고, E3로 turnover clipper 적용

## B. 적용(신호→목표비중→주문) 문제
- 체크: 목표비중이 계산되었는데 주문이 0이 되는 케이스(라운딩/최소수량/제약 충돌)  
- 징후: 신호는 움직이는데 포지션이 안 바뀜  
- 조치: E1에서 “pre/post weights + clipped amount + reason code” 기록

## C. 노출(베타/섹터/집중) 문제
- 체크: 단일 종목/상관 클러스터로의 실질 올인, 현금 비중이 시스템 결측으로 튀는지  
- 징후: 성과는 평평한데 변동성/드로우다운만 커짐(혹은 반대)  
- 조치: E4로 비중/베타/종목수 제약 표준화 후, 레짐별로 분해(E5)

## D. 비용(슬리피지/스프레드/갭) 문제
- 체크: gross는 괜찮은데 net이 죽는지, 특정 이벤트(실적/뉴스) 구간에서만 깨지는지  
- 징후: OOS mean 정체 + 거래 많은 구간에서만 악화  
- 조치: E3로 비용모델 온 + “비용 기여도 상위 날짜/종목” 리포트

## E. 레짐(시장 국면) 문제
- 체크: 리스크온(QQQ/XLK 강세)에서만 먹고, 리스크오프(XLU 강세)에서 죽는지  
- 징후: 전체 평균은 정체인데 레짐별로 극단적 편차  
- 조치: E5로 레짐 태그 후, “레짐별 신호 히트율/노출/비용” 동시 출력

---

## 실행 우선순위(24~48h) 요약 체크리스트
1) **E1 실행**: 로깅/해시/리밸런스 추적 복구(파싱 실패 0)  
2) **E2 실행**: degenerate fold 0 + purge/embargo 적용  
3) **E3 실행**: 비용/슬리피지 + turnover clipper로 net 기준 검증  
4) **E4 실행**: 8~14 강제 + vol 스케일 + 비중/베타 캡  
5) (여유 시) **E5 실행**: survivorship ON/OFF + ETF 관측지표 레짐 분해

이 5개를 끝내면, “성능이 안 움직이는” 상태가 최소한 **(1) 누수로 인한 착시인지 (2) 비용 블랙홀인지 (3) 노출 설계 문제인지 (4) 레짐 미스매치인지** 중 하나로 수렴하도록 관측 체계가 잡힌다.
