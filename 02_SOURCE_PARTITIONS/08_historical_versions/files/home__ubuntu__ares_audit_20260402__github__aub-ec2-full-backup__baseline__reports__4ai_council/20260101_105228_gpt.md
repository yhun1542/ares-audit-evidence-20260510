## 다음 24~48시간 TOP5 우선순위(명령형 체크리스트) — 누수/과최적화/서바이버십/비용/운영 리스크 우선

### 1) **데이터 누수 + 서바이버십 바이어스 “하드닝” (PIT 강제)**
**(a) 왜 필요한지**
- Tech/Healthcare 8~14종목 소유니버스는 **한 번의 누수/생존편향**이 성능을 “계속 잘 나오는 것처럼” 보이게 만들 확률이 큼.
- 특히 **리밸런싱 시점의 가격/재무/이벤트(실적발표일)** 정렬이 틀리면 lockbox가 좋아도 운영에서 붕괴.

**(b) 위험/부작용**
- PIT 강제/결측 처리 강화로 **성능 하락** 가능(정상적인 현상).
- 데이터 소스/파이프라인 변경 시 **재현성 깨짐**(seed/캐시/버전 고정 필요).

**(c) 최소 실험(2~3개 → “1개 실험 안의 서브테스트”로 묶어서 48h 자동 루프에 적합하게)**
- **실험 E1: PIT-Integrity Suite Patch**
  - 서브테스트1: 모든 feature를 “결정시점 t에 이용 가능한 정보만” 사용하도록 **강제 lag(예: close-to-close면 최소 1 bar lag)**.
  - 서브테스트2: corporate action(분할/병합), delisting/거래정지 처리 시 **미래가격/생존 종목만 남는 필터 금지**(delist return 반영 또는 마지막 거래가 처리 규칙 고정).
  - 서브테스트3: “유니버스(8~14)”가 **매 시점 동일 규칙으로 구성**되는지 검증(예: 과거에 존재하지 않던 티커가 과거에 등장하지 않게).

**(d) PASS 조건(게이트)**
- **Leakage Gate(필수 통과)**: 랜덤 시프트(피처를 +1 bar 더 늦춤) 시 성능이 “유사 유지”가 아니라 **유의미하게 하락**해야 정상(누수 의심 제거).
- **Lockbox Gate**: `lockbox_mean` ≥ 현 챔피언(1.3295) - 0.005 이내 유지(= 하드닝으로 소폭 하락 허용), `lockbox_min` 더 악화 금지(현 -0.05344 이하로 내려가면 FAIL).
- **Ops Gate**: 재실행 3회 성능 분산이 기준 이하(표준편차 상한 설정)로 “재현 가능”.

**48h 자동 루프 형태**
- (1) 실험 정의: `exp_pit_integrity_suite.json` (lag 강제 + delist 규칙 + universe PIT 검증)
- (2) 게이트: Leakage Gate → Lockbox Gate → Ops Gate
- (3) 기대 관측치: tuning 상승이 아니라 **tuning 하락/lockbox 유지**가 정상 신호(“가짜 알파 제거”)

### 2) **거래비용/슬리피지/체결 리스크를 성능지표에 “즉시 반영”**
**(a) 왜 필요한지**
- 8~14종목 집중 포트는 회전율이 튀면 **거래비용 미반영이 성능 정체/실전 붕괴의 1순위 원인**.
- lockbox_mean이 좋아도 실제로는 비용으로 먹히는 경우가 흔함.

**(b) 위험/부작용**
- 비용을 제대로 넣으면 백테스트 성능이 **즉시 하락**(정상).
- 너무 보수적인 비용 가정은 전략을 “아예 못 움직이게” 만들 수 있음.

**(c) 최소 실험(서브테스트 포함 단일 실험)**
- **실험 E2: Cost-First Objective Patch**
  - 서브테스트1: **고정 수수료 + 스프레드 + market impact(거래대금 대비)**의 3단 비용모델 추가(보수/기준/낙관 3시나리오를 한 번에 리포트).
  - 서브테스트2: **turnover penalty**를 목적함수에 포함(“수익/비용/회전” 동시 최적화).
  - 서브테스트3: 리밸런싱을 **2~3일 분할 체결**(가상 execution schedule)로 바꿔 체결 리스크 민감도 측정.

**(d) PASS 조건**
- **Net-of-Cost Gate(필수)**: 비용(기준 시나리오) 반영 후 `lockbox_mean`이 챔피언 대비 -0.01 이내 유지 + `worst_mdd` 악화 금지(현 챔피언 -0.0902보다 더 나쁘면 FAIL).
- **Turnover Gate**: turnover 상한(예: 월간/연간) 초과 시 FAIL(상한은 현재 운영 가정에 고정).
- **Sensitivity Gate**: 낙관↔보수 비용 가정 간 성능 괴리가 과도하면 FAIL(실전 민감도 과다).

**48h 자동 루프**
- (1) 실험 정의: `exp_cost_first_objective.json`
- (2) 게이트: Net-of-Cost → Turnover → Sensitivity
- (3) 기대 관측치: gross 수익은 감소해도 **net 안정성/최대낙폭 안정**이 개선

### 3) **과최적화 방지: Purged/Embargo CV + 모델 안정성(선택 일관성) 지표 도입**
**(a) 왜 필요한지**
- 현재 tuning vs lockbox 갭이 크지 않아도, 후보 간 미세 개선은 **폴드/구간 운빨**일 수 있음.
- Tech/Healthcare는 레짐 변화가 커서 “폴드 누수(시간 인접 정보)”가 있으면 성능이 부풀려짐.

**(b) 위험/부작용**
- purged/embargo 적용 시 tuning 성능이 내려가며 “진짜로 남는 알파만” 확인 가능.
- 계산량 증가(48h 루프에서 리소스 관리 필요).

**(c) 최소 실험**
- **실험 E3: Purged CV + Stability Metrics Patch**
  - 서브테스트1: 이벤트/리밸런싱 주변 구간 **purge + embargo** 적용(시간 인접 누수 차단).
  - 서브테스트2: “선택 종목/가중치”의 **일관성 지표** 추가(예: 상위 보유 종목의 유지율, weight entropy, 신호-포지션 상관).
  - 서브테스트3: 모델 하이퍼파라미터 탐색 폭을 줄이고 **nested 검증(간단 버전)**로 튜닝 과적합 억제.

**(d) PASS 조건**
- **Generalization Gate**: purged CV 적용 후 `lockbox_mean`이 챔피언 대비 -0.005 이내 + `lockbox_min` 악화 금지.
- **Stability Gate**: 보유 종목 유지율/가중치 변동성이 기준 이상으로 “널뛰기”면 FAIL(운영 리스크).
- **Fold Robustness Gate**: 최악 폴드 성능(또는 mdd)이 개선/유지될 것.

**48h 자동 루프**
- (1) 실험 정의: `exp_purged_cv_stability.json`
- (2) 게이트: Generalization → Stability → Fold Robustness
- (3) 기대 관측치: 평균 수익이 아니라 **최악 폴드/최악 MDD**가 우선 개선 신호

### 4) **노출(Exposure) 제어: 단일종목/섹터/변동성 타겟 + 드로우다운 가드레일**
**(a) 왜 필요한지**
- 8~14종목은 단일종목 리스크가 커서, 평균은 좋아도 **worst_mdd가 튀는 구조**가 자주 발생.
- 후보가 `worst_mdd: -0.0824`로 개선 중이므로, 다음은 “알파 유지 + tail 억제”가 효율적.

**(b) 위험/부작용**
- 노출 제한이 강하면 수익이 줄 수 있음.
- 변동성 타겟이 잘못되면 저변동 구간에서 과도 레버리지처럼 행동(레버리지는 안 쓰더라도 상대적 포지션 확대).

**(c) 최소 실험**
- **실험 E4: Exposure Guardrails Patch**
  - 서브테스트1: **max single-name weight**, **Tech/Healthcare 내 부분 섹터 편중 제한**, **현금(또는 저위험) 비중 허용 규칙** 고정.
  - 서브테스트2: **ex-ante volatility targeting**(포트 변동성 목표)으로 포지션 스케일링.
  - 서브테스트3: 드로우다운 기반 리스크 오프(예: rolling DD 임계 시 신규 진입 축소) — “ETF 매매 없이” 현금 비중으로만.

**(d) PASS 조건**
- **Tail Gate(핵심)**: `worst_mdd`가 챔피언(-0.0902) 대비 개선(예: -0.085 이상) 또는 후보 수준(-0.0824) 유지/개선.
- **Return Gate**: `lockbox_mean` ≥ 챔피언 -0.005.
- **Constraint Gate**: 모든 시점에서 8~14 종목 유지 + 제한 위반 0회.

**48h 자동 루프**
- (1) 실험 정의: `exp_exposure_guardrails.json`
- (2) 게이트: Tail → Return → Constraint
- (3) 기대 관측치: 평균 수익 “소폭 희생”하더라도 **worst_mdd/최악구간 회복력** 개선

### 5) **레짐(시장 상태) 관측지표로 “진입/리스크 스케일”만 제어 (ETF는 관측만)**
**(a) 왜 필요한지**
- Tech/Healthcare는 레짐 민감도가 커서, 동일 신호라도 **risk-on/off에서 성과가 뒤집히기** 쉬움.
- ETF는 매매 금지지만 **관측 지표**로는 유효(예: QQQ/XLV 상대강도, VIX).

**(b) 위험/부작용**
- 레짐 필터가 과하면 거래가 줄어 알파가 희석될 수 있음.
- 레짐 신호 자체가 누수/과최적화 대상이 될 수 있음(단순 규칙 유지).

**(c) 최소 실험**
- **실험 E5: Regime-Aware Scaling Patch (Observation-only)**
  - 서브테스트1: 관측지표(QQQ, XLV, VIX 등)로 **포지션 스케일(0~1)**만 조절(매매는 종목만).
  - 서브테스트2: 레짐이 나쁠 때는 “신호 방향 유지 + 사이즈 축소”로만 제한(진입 금지 같은 hard filter는 마지막).
  - 서브테스트3: 레짐 구간별 성과 리포트(성공/실패 레짐을 분리 기록).

**(d) PASS 조건**
- **Regime Robustness Gate**: 레짐별(상승/하락/고VIX)에서 최악 구간 성과가 개선되거나, 최소한 `worst_mdd` 악화 금지.
- **Simplicity Gate**: 레짐 파라미터 수 제한(고정 1~2개 임계치) + 튜닝 자유도 최소화(과최적화 방지).
- **Lockbox Gate**: `lockbox_mean` ≥ 챔피언 -0.005.

**48h 자동 루프**
- (1) 실험 정의: `exp_regime_scaling_observe_only.json`
- (2) 게이트: Regime Robustness → Simplicity → Lockbox
- (3) 기대 관측치: 평균보다 **하락 레짐 방어**가 개선되면 성공

## 24~48시간 실행 순서(명령형 체크리스트)
1) **E1(PIT/누수/서바이버십)부터 적용하고 FAIL이면 즉시 롤백**  
2) **E2(비용) 반영을 “항상-on”으로 만들고 net 기준으로만 비교**  
3) **E3(Purged CV + 안정성)로 튜닝 개선이 “진짜”인지 검증**  
4) **E4(노출 가드레일)로 tail 억제하면서 후보 수준 worst_mdd 유지/개선 노리기**  
5) **E5(레짐 스케일)로 하락/고변동 구간 방어력만 미세 조정**

## 성능이 안 움직일 때 “원인 분해” 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **순서대로** 분해해서, 어디가 병목인지 “한 번에 하나씩” 고정/해제하며 로그로 남겨라.

### A) Trigger(신호 생성) 문제
- **신호-미래수익 상관이 폴드별로 뒤집히는지** 확인(특정 구간에서만 작동하면 레짐 의존).
- **피처 lag를 +1 bar 더 늦춰도 성능이 비정상적으로 유지**되면 누수 의심.
- **분포 변화(드리프트)**: 피처 분포가 lockbox에서 변했는지(평균/분산/결측률 급변).

### B) Apply(적용/포트폴리오 구성) 문제
- 신호는 맞는데 **리밸런싱 주기/포지션 유지 규칙** 때문에 수익이 새는지 확인(“hit rate는 높은데 PnL이 작은” 패턴).
- **8~14 유지 제약**이 신호 강도를 희석하는지(약한 종목을 억지로 채우는지).

### C) Exposure(노출) 문제
- 성능 정체의 흔한 형태: 평균은 비슷한데 **tail만 악화**.  
  → 단일종목 비중, 섹터 편중, 변동성 타겟 부재를 점검.
- 포트 변동성이 시장 변동성(VIX 등)과 **동조**되면 방어가 없는 상태.

### D) Cost(비용/체결) 문제
- gross는 유지되는데 net이 안 나오면:
  - turnover 스파이크 구간을 찾아 **원인 신호/제약 위반**을 추적.
  - 슬리피지 가정(고정bps vs 거래대금비례)이 성능에 미치는 민감도를 리포트로 고정.

### E) Regime(시장 상태) 문제
- 레짐별로 수익 기여도를 분해:
  - risk-on(저VIX/상승장)에서만 벌면 필터/스케일 필요
  - risk-off(고VIX/하락장) 손실이 크면 **사이즈 축소**가 1순위(알파 구조 변경은 2순위)

---

원칙: **E1(무결성)과 E2(비용)를 먼저 고정**하지 않으면, 이후의 전략/아키텍처 개선은 대부분 “가짜 개선”로 끝날 가능성이 높다.
