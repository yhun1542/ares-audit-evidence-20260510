### 3. 성능 정체 시 원인 분해 (Debugging Checklist)

만약 위 실험들이 모두 실패하거나 성능이 움직이지 않을 경우, 다음 트리 구조로 원인을 진단하십시오.

1.  **트리거(Trigger) 부재**:
    *   *증상*: 매매 횟수가 극단적으로 적음 (연간 10회 미만).
    *   *액션*: 진입 장벽(Threshold)을 강제로 50% 낮추고 손실폭 확인.
2.  **노출(Exposure) 부족**:
    *   *증상*: 승률은 높으나 계좌 수익률(CAGR)이 예금 수준.
    *   *액션*: 포트폴리오 내 현금 비중 상한(Max Cash)을 20%로 제한(강제 투자).
3.  **비용(Cost) 과다**:
    *   *증상*: Gross Return은 우상향이나 Net Return이 횡보/하락.
    *   *액션*: 회전율(Turnover) 제약 조건 추가 (예: 일간 교체율 < 10%).
4.  **레짐(Regime) 불일치**:
    *   *증상*: `mrd` 모듈이 현재 시장을 항상 '현금 보유(Cash Safe)' 구간으로 오판.
    *   *액션*: 레짐 감지 로직의 윈도우 사이즈(Lookback Window)를 단축 (반응 속도 향상).
