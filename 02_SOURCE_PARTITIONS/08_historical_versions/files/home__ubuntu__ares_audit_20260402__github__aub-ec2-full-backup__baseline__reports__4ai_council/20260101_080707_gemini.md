[비상 점검: Lockbox 수치 동일 현상]
현재 `Candidate`와 `Champion`의 Lockbox Mean/Min 및 MDD가 **소수점 아래까지 완전히 동일**함.
이는 실험군(Candidate)의 로직이 **(1) 전혀 작동하지 않았거나(Signal = 0)**, **(2) 기존 로직에 의해 완전히 마스킹(Overridden)** 되었음을 의미. 새로운 실험이 무의미한 상태.

### 1. 우선순위 TOP 5 실행 체크리스트

#### Action 1: 신호 활성화 임계값 완화 (Signal Unclamping)
- **(a) 필요성:** `exp_mrd_ars_fsa_full` 전략이 챔피언과 똑같다는 것은 신호가 필터링되었거나 가중치 할당 단계에서 무시되었기 때문임. 신호가 실제 포트폴리오에 반영되도록 강제해야 함.
- **(b) 위험:** 과도한 회전율(Turnover) 발생, 노이즈 거래 증가.
- **(c) 실험 정의 (48h Loop):**
    1.  **Exp_A1_LowerThreshold:** 진입 신호(Z-score 등)의 임계값을 기존 대비 50% 낮춤 (예: 2.0 -> 1.0).
    2.  **Exp_A2_ForceAllocation:** 상위 N개 종목에 대해 최소 할당 비중(Min Weight > 0)을 강제 설정.
    3.  **Exp_A3_DisableFilters:** 변동성 필터 등 기존의 '거부(Veto)' 로직을 일시 해제.
- **(d) PASS 조건:** `Lockbox Mean`이 Champion과 **0.01이라도 다를 것**. (성능 하락이라도 변화가 있어야 함)

#### Action 2: "Min 0.05" 폴드 원인 분석 및 레짐 필터 추가 (Regime Filter)
- **(a) 필요성:** Tuning Min(0.05)은 특정 기간(Fold)에서 수익이 거의 0에 수렴하거나 막대한 손실을 입었다는 뜻. Tech/Healthcare는 금리 인상기나 기술주 조정기에 취약함.
- **(b) 위험:** 시장 타이밍을 맞추려다 상승장을 놓침(Type II Error).
- **(c) 실험 정의 (48h Loop):**
    1.  **Exp_B1_MacroFilter:** 벤치마크 ETF(SPY 또는 XLK)가 MA200 아래일 때, 현금 비중 50% 강제.
    2.  **Exp_B2_SectorRotation:** XLK(Tech) 모멘텀 < XLV(Health) 모멘텀일 때, Healthcare 비중을 최소 60%로 상향.
- **(d) PASS 조건:** Tuning Min > 0.5 (최악의 경우라도 -50% 방어 또는 보합 유지), Worst MDD > -0.15 유지.

#### Action 3: 유니버스 동적 교체 (Universe Refresh)
- **(a) 필요성:** 현재 8~14개 종목이 고정(Static)되어 있다면 서바이버십 편향이거나 현재 시장 주도주를 놓치고 있을 가능성. Tech/Health 내에서 모멘텀/퀄리티 상위 종목으로 매월 교체 필요.
- **(b) 위험:** 잦은 종목 교체로 인한 슬리피지 비용 급증.
- **(c) 실험 정의 (48h Loop):**
    1.  **Exp_C1_DynamicUniverse:** 매월 Tech/Healthcare 시총 상위 50위 중 12개월 모멘텀 상위 10개 선정.
    2.  **Exp_C2_LowVolSelect:** 동일 유니버스 내 변동성 하위 10개 선정 (방어적 구성).
- **(d) PASS 조건:** Lockbox Mean > 1.80 (기존 챔피언 상회), Turnover < 20%/month.

#### Action 4: 비용 민감도 스트레스 테스트 (Cost Stress Test)
- **(a) 필요성:** 현재 1.76이라는 높은 평균 수익률이 슬리피지를 과소평가한 결과인지 확인해야 함.
- **(b) 위험:** 전략 폐기(Deprecation) 가능성 높음. 하지만 실운용 전 필수.
- **(c) 실험 정의 (48h Loop):**
    1.  **Exp_D1_HighCost:** 거래 비용(bp)을 현재 설정의 2배로 적용 후 백테스트.
    2.  **Exp_D2_LiquidityPenalty:** 일일 거래량의 1% 이상 매매 시 페널티 부과 로직 적용.
- **(d) PASS 조건:** Tuning Mean > 1.2 유지 (비용 증가에도 수익성 유지).

#### Action 5: 손절매(Stop-loss) 로직 강화
- **(a) 필요성:** Worst MDD -11%는 양호하나, Tuning Min 0.05는 꼬리 위험(Tail Risk) 관리가 안 되고 있음을 시사. 개별 종목 급락 시 빠른 차단 필요.
- **(b) 위험:** 휩소(Whipsaw)로 인한 잦은 손절 후 반등 놓침.
- **(c) 실험 정의 (48h Loop):**
    1.  **Exp_E1_TrailingStop:** 개별 종목 고점 대비 -7% 하락 시 전량 매도.
    2.  **Exp_E2_VolatilityStop:** 종목 변동성(ATR)이 급증(2배)하면 비중 50% 축소.
- **(d) PASS 조건:** Worst MDD > -0.09 (MDD 개선), Tuning Min > 0.8.

### 2. 성능 정체(Flat) 원인 분해 및 대응 (Idea Tree)

성능이 움직이지 않을 때(Champion == Candidate) 다음 순서로 코드를 점검하시오.

1.  **Trigger Failure (신호 발생 실패)**
    *   *원인:* 지표 계산에 `NaN`이 포함되어 신호가 생성되지 않음.
    *   *확인:* 로그에서 `Signal Generated count`가 0인지 확인.
2.  **Allocation Clamping (비중 고정)**
    *   *원인:* 최적화(Optimizer) 단계에서 `Current Holdings` 유지 편향이 너무 강하거나, `Min Rebalance Threshold`가 너무 높음.
    *   *대응:* 리밸런싱 임계값을 0으로 설정하여 미세한 변화도 반영하도록 강제.
3.  **Universe Constraint (종목 제한)**
    *   *원인:* Tech/Healthcare 8~14개 종목 중 실제 매수 가능한(현금 여력, 가격 제한 등) 종목이 없음.
    *   *대응:* 현금 비중이 100%인지 확인(Idle state).
4.  **Data Alignment (데이터 정렬)**
    *   *원인:* ETF 지표(XLK, XLV) 날짜와 개별 주식 날짜 매핑 오류로 Look-ahead bias 방지 로직이 모든 거래를 차단.
    *   *대응:* 데이터 로더의 날짜 인덱스 정합성(Inner Join vs Outer Join) 점검.
