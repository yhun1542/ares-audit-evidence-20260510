## 다음 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — **명령형 체크리스트**

### 1) **누수(lookahead/asof) 최우선 감사 + 음성대조(negative control)로 “진짜 알파” 확인**
- **왜 필요한지**
  - 현재 lockbox_mean이 양호하고 lockbox_min이 얕게 보이지만, 이 구간은 누수/정렬 오류가 있어도 “그럴듯한” 성능이 나올 수 있음(특히 Tech/Healthcare의 갭/이벤트/리밸런스 타이밍에서).
  - 누수 검증은 성능 개선보다 우선(잘못된 개선을 막는 가장 큰 레버).
- **위험/부작용**
  - 누수 제거 시 성능 급락 가능(하지만 그게 정상).
  - 데이터 파이프라인 수정으로 과거 결과가 대규모로 변동 → 비교 어려움(따라서 gate를 먼저 정의하고 진행).
- **해당 우선순위에서 돌릴 최소 실험(아래 실험 묶음 재사용)**
  - **[Exp1] Leakage Sentinel Suite**
  - **[Exp5] Survivorship/Corporate Action PIT 재구축**
- **PASS 조건(게이트)**
  - Exp1의 음성대조에서 **성능이 “의도대로” 붕괴**(예: lockbox_mean이 ~0 근처/음수로 수렴)하고,
  - 실제 파이프라인 수정 후에도 **lockbox_min 악화가 제한적**(예: 현재 -0.0534 대비 -0.070 이하로 깨지지 않음)이며,
  - 수정 전/후 결과 차이가 “원인 설명 가능한” 형태(정렬/거래일/리밸런스 시점 변경에 따른 변화)로 로그에 남을 것.

---

### 2) **비용/슬리피지/회전율(턴오버) 모델을 목적함수/게이트에 강제 반영**
- **왜 필요한지**
  - 8~14 종목 집중 포트폴리오는 리밸런스가 잦으면 비용이 성과를 바로 압살함.
  - “튜닝에서만 좋은 후보”가 늘어나고 lockbox가 정체될 때, 실제론 비용/회전이 숨은 원인인 경우가 많음.
- **위험/부작용**
  - 비용을 넣으면 단기 성능(특히 tuning_mean) 하락 가능.
  - 비용 모델을 과도하게 보수적으로 잡으면 신호가 죽음(과소거래).
- **해당 우선순위에서 돌릴 최소 실험**
  - **[Exp2] Cost/Turnover Patch (슬리피지+커미션+턴오버 패널티 + 리밸런스 주기)**
  - **[Exp4] Concentration/Vol-Scaling(리스크 예산)로 불필요한 교체 감소**
- **PASS 조건**
  - 비용 반영 후에도 **lockbox_mean이 챔피언 대비 비열화 제한**(예: -0.005 이내) 또는 개선,
  - 동시에 **턴오버가 유의미하게 감소**(예: 중위수 기준 -20% 이상),
  - **worst_mdd가 악화되지 않을 것**(챔피언 -0.0902 대비 더 나빠지면 FAIL).

---

### 3) **서바이버십/유니버스 하드닝(Tech+Healthcare 8~14) + PIT(point-in-time) 데이터 일관성**
- **왜 필요한지**
  - 종목 풀을 “현재 존재하는 티커” 기준으로 고정하면 서바이버십 바이어스가 바로 들어감.
  - 8~14 종목 구성은 한 종목의 delist/merge/split 처리 오류가 전체 성능을 왜곡.
- **위험/부작용**
  - PIT 재구축 후 성능이 낮아질 수 있음(정상).
  - 구현 난이도(데이터 소스/코퍼레이트 액션)가 증가.
- **해당 우선순위에서 돌릴 최소 실험**
  - **[Exp5] Survivorship/Corporate Action PIT 재구축**
  - **[Exp1] Leakage Sentinel**(PIT 수정이 누수도 같이 제거하는지 확인)
- **PASS 조건**
  - PIT 적용 후에도 **전략이 동작 불능(종목수 부족/가격 결측)** 없이 48시간 루프에서 안정적으로 돌아갈 것,
  - 성과는 내려갈 수 있으나, **lockbox_min/최악구간이 비정상적으로 급락하지 않을 것**(데이터 결측/스플릿 오류 시 급락 패턴이 자주 나옴),
  - “어떤 이벤트(상장폐지/합병/스플릿)”에서 어떤 처리가 되었는지 리포트가 남을 것.

---

### 4) **레짐(변동성/추세) 기반 게이트: ETF는 “관측지표”로만 사용**
- **왜 필요한지**
  - Tech/Healthcare는 레짐 민감(금리/리스크온·오프). 전략이 좋은데 “언제 켜고/끄는지”가 없으면 worst_mdd가 쌓임.
  - ETF는 매매 금지지만 **시장/섹터 상태 관측**에는 최적(예: QQQ, XLK, XLV, IBB, SPY, VIX proxy).
- **위험/부작용**
  - 게이트가 과도하면 기회손실(under-exposure).
  - 레짐 정의를 과최적화하면 lockbox에서 붕괴.
- **해당 우선순위에서 돌릴 최소 실험**
  - **[Exp3] Regime Gate (ETF 지표로 익스포저/레버리지/현금비중 게이팅)**
  - **[Exp2] Cost/Turnover Patch**(게이트가 거래를 줄여 비용 개선되는지 동시 확인)
- **PASS 조건**
  - **worst_mdd 개선**(예: 챔피언 -0.0902 → -0.085 이하),
  - **lockbox_min 유지 또는 개선**(현재 -0.0534보다 더 나빠지지 않는 방향),
  - 게이트 발동 빈도/기간이 로그로 추적 가능(“왜 오늘 위험축소?” 설명 가능).

---

### 5) **운영 리스크(48시간 자동 루프) 점검: 재현성/결측/드리프트/알람**
- **왜 필요한지**
  - 성능이 안 움직일 때 “전략 문제”가 아니라 **파이프라인 드리프트/데이터 결측/실험 설정 불일치**가 원인인 경우가 많음.
  - 자동 루프에서는 “조용한 실패(silent failure)”가 가장 비쌈.
- **위험/부작용**
  - 모니터링/검증 추가로 런타임 증가.
  - 알람 과다(노이즈) → 무시하게 됨(알람 기준을 gate화해야 함).
- **해당 우선순위에서 돌릴 최소 실험**
  - **[Exp1] Leakage Sentinel**(CI 형태로 주기 실행)
  - **[Exp2] Cost/Turnover Patch**(비용/턴오버 리포트 표준화)
- **PASS 조건**
  - 매 48시간 루프마다 동일 입력이면 동일 출력(시드/정렬/데이터 스냅샷) 재현,
  - 결측/이상치/거래불가(가격 0, 볼륨 0 등) 발생 시 즉시 FAIL로 승격 + 리포트 생성.

---

## 48시간 자동 루프에 바로 넣을 **실행 가능한 patch/실험 5개** (3~5개 제한 준수)

아래 5개만 “패치/실험 단위”로 정의하고, TOP5 우선순위는 이 5개를 재조합해 평가하도록 고정.

---

### [Exp1] Leakage Sentinel Suite (누수 감지 패치)
1) **실험 정의**
   - (A) 모든 feature를 **+1 bar 지연**(또는 label을 -1로 당김)한 버전과 원본 비교
   - (B) “asof join” 대상(펀더멘털/리포트/이벤트)이 있다면 **발표일 기준으로 강제 컷오프** + 발표 전 접근 금지
   - (C) 음성대조: 타깃(label) 셔플 또는 미래수익을 과거로 섞는 등, **누수면 성능이 유지될 조작**을 일부러 넣어 감지
2) **게이트**
   - 음성대조(B/C)에서 lockbox_mean이 유지되면 **즉시 FAIL(누수 의심)**  
   - 지연(A)에서 성능이 “완만히” 감소하는 건 정상, **오히려 비정상적 유지면 FAIL**
3) **기대 관측치**
   - 누수가 없다면: 음성대조는 붕괴, 지연은 일부 하락  
   - 누수가 있다면: 음성대조/지연에서도 성능이 과도하게 유지

---

### [Exp2] Cost/Turnover Patch (비용/턴오버 내재화)
1) **실험 정의**
   - (A) 커미션+슬리피지(스프레드 기반 또는 ADV 기반 단순모델)를 PnL에 반영
   - (B) 목적함수에 **턴오버 패널티** 추가(예: 거래대금/포트가치 비율에 λ 부여)
   - (C) 리밸런스 주기 비교: 1D vs 2D/3D (동일 신호, 실행만 변경)
2) **게이트**
   - 비용 반영 후에도 lockbox_mean이 챔피언 대비 **-0.005 이내** 또는 개선
   - 턴오버 **-20% 이상**(중위수 기준) 감소
3) **기대 관측치**
   - 비용 반영 시 과거 “과매매로 만든 알파”가 제거되어도, 살아남는 신호는 lockbox에서 유지

---

### [Exp3] Regime Gate (ETF 관측지표 기반 익스포저 게이트)
1) **실험 정의**
   - ETF(예: SPY/QQQ/XLK/XLV/IBB)로만 관측:
     - (A) 시장 추세 필터(예: 50>200 MA면 risk-on)
     - (B) 변동성 레짐(예: VIX proxy 상승/하락 또는 SPY realized vol)
   - 게이트는 “매매 종목”이 아니라 **총 익스포저(현금 비중) / 포지션 스케일**만 조절
2) **게이트**
   - worst_mdd가 챔피언 대비 **개선**(예: -0.0902 → -0.085 이하)
   - lockbox_min이 **-0.070 이하로 악화되지 않음**
3) **기대 관측치**
   - 리스크오프 구간에서 손실 꼬리 감소, 정상 구간에서 평균 수익률 유지(또는 소폭 감소)

---

### [Exp4] Concentration & Vol-Scaling (8~14종목 운영 최적화: 과최적화 대신 제약으로)
1) **실험 정의**
   - (A) 종목당 최대비중 캡(예: 12~15%)
   - (B) 20D 변동성 기반 스케일링(고변동 종목 비중 자동 축소)
   - (C) 리밸런스 시 “변화량 임계값” 적용(작은 신호 변화로 매매하지 않기)
2) **게이트**
   - lockbox_mean 비열화 제한(예: -0.005 이내)
   - worst_mdd 또는 fold14_mdd가 **동일/개선**
3) **기대 관측치**
   - 소수 종목 급락에 대한 포트 충격 감소, 불필요한 매매 감소

---

### [Exp5] Survivorship/Corporate Action PIT Patch (유니버스/데이터 현실화)
1) **실험 정의**
   - (A) Tech+Healthcare 유니버스를 **PIT로 재구성**(해당 시점에 실제 상장/거래 가능 종목만)
   - (B) split/dividend/merge/delist를 가격/수익률에 일관되게 반영(조정주가 정책 고정)
2) **게이트**
   - 결측/스플릿 오류로 인한 비정상 수익률 스파이크(초대형 점프)가 제거될 것
   - 전략이 8~14종목 제약 하에서 “항상 종목 수 충족 실패”로 무너지는지 여부 확인(무너진다면 운영 규칙을 수정하는 게 맞음)
3) **기대 관측치**
   - 평균 수익률은 내려갈 수 있으나, 결과의 신뢰도가 상승하고 lockbox의 “이상한 강함”이 사라짐

---

## 성능이 안 움직일 때(정체/수렴) 원인 분해 아이디어 — **명령형 진단 트리**

아래는 “전략이 나빠서”가 아니라 “어디가 막혔는지”를 5갈래로 분해해 로그/리포트로 고정하는 절차.

### A) Trigger(신호 발생) 문제
- **신호 발생 빈도/분포를 고정 리포트로 출력**: 일별 상위/하위 점수 분포, 임계값 통과 비율
- **IC(정보계수)/hit rate를 구간별로 기록**: 전체/Tech/Healthcare 분리
- **점수-수익 단조성(monotonicity) 체크**: decile spread가 잠기는지 확인

### B) Apply(적용/실행) 문제
- **리밸런스 타이밍**(close-to-close, open-to-close, next open fill)별로 성능이 뒤집히는지 비교
- **주문 제약 반영**: 거래정지/가격결측/limit up/down 유사 상황(미국은 덜하지만 갭이 큼) 처리
- **포지션 구성 실패율**: 8~14 종목 제약에서 “종목 부족” 발생 횟수/원인 로그화

### C) Exposure(노출) 문제
- **섹터/팩터 노출 리포트**: 성장/가치, 퀄리티, 모멘텀, 저변동, 금리 민감도(프록시)  
- **단일 종목 기여도**(PnL attribution)로 “몇 개가 전부”인지 확인
- **베타/상관 드리프트**: QQQ/SPY 대비 포트 베타가 레짐마다 튀는지 확인

### D) Cost(비용) 문제
- **턴오버 분해**: 신호변경 vs 제약(캡/볼스케일/게이트)으로 인한 교체
- **슬리피지 민감도**: 슬리피지 1x/2x에서 성능 탄력성이 큰지(크면 실전 취약)
- **체결가정 바꿔보기**: next open vs VWAP 근사 등(일관되게 나쁜 가정에서도 살아남는지)

### E) Regime(레짐) 문제
- **레짐별 성능 테이블 고정**: (추세↑/↓) × (변동↑/↓) 4분면
- **손실 꼬리 구간의 공통 조건**(VIX 급등, 금리 급등 프록시 등) 자동 태깅
- **게이트 발동 로그**로 “왜 줄였는지/왜 늘렸는지” 사후 설명 가능하게 만들기

---

## 즉시 실행 순서(48시간 루프용) — 명령형 체크리스트
1) **Exp1(누수) 먼저 실행**하고 음성대조 붕괴 여부로 파이프라인 신뢰도 확정
2) **Exp5(PIT/서바이버십) 적용** 후 결과가 “비정상 스파이크 제거” 형태인지 확인
3) **Exp2(비용/턴오버) 적용** 후 lockbox_mean 유지 + 턴오버 감소를 동시에 만족시키기
4) **Exp3(레짐 게이트)로 worst_mdd 개선** 시도(ETF는 관측만)
5) **Exp4(집중/볼스케일 제약)로 꼬리 리스크/과매매를 추가로 압축**

위 5개 외에는 24~48시간 동안 새 아이디어를 늘리지 말고(케이스 폭발 금지), **현재 Champion vs Candidate vs (Exp1~5 조합)**만 비교 가능한 형태로 리포트/게이트를 고정해서 “정체의 원인”이 어디인지 수렴시키는 쪽으로 진행.
