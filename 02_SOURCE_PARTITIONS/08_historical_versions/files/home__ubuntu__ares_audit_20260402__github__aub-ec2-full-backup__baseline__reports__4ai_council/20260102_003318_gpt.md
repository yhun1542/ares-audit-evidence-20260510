아래는 **다음 24~48시간 자동 루프에서 바로 돌릴 수 있는 TOP5 우선순위 patch/실험(코드/아키텍처/전략)**입니다. 순서는 **누수/과최적화/서바이버십/비용 미반영/운영 리스크**를 먼저 때려잡는 순으로 정렬했습니다. (미국주식 only, **Tech+Healthcare 8~14종목**, **ETF는 매매 금지/관측지표만**)

## TOP1) “비용·슬리피지·유동성” 현실화 패치 (성과 착시 제거 1순위)
### (a) 왜 필요한지
- 현재 candidate가 lockbox에서 강하지만, **비용/슬리피지/체결 제약이 약하면** 개선이 “종이수익”일 수 있음.
- 특히 **8~14종목 집중 + 잦은 리밸런스**면 턴오버가 수익을 빠르게 갉아먹음.

### (b) 위험/부작용
- 단기적으로 성능(평균)이 떨어져 보일 수 있음(착시 제거).
- 거래 제한으로 신호 반응이 느려져 추세장 수익이 감소할 수 있음.

### (c) 최소 실험 2~3개
**실험 1: ADV 기반 슬리피지 + 스프레드 비용 모델**
- (1) 실험 정의:  
  - 거래비용 = 고정수수료 + (스프레드/2) + k * (주문금액 / ADV)^p 형태로 단순 모델 추가  
  - 체결가격: close→next open 또는 vwap 근사 중 하나로 일관 고정
- (2) 게이트:  
  - cost-adjusted 기준으로 **lockbox_mean 유지(또는 -5% 이내)** + **lockbox_min ≥ 0** 유지  
  - **turnover(일/주간)** 상한(예: 주간 200% 등) 초과 시 FAIL
- (3) 기대 관측치:  
  - raw는 비슷하더라도 **순수익이 과대였던 전략이 정리**되고, “진짜 강한” 후보만 남음

**실험 2: 리밸런스 주기/거래 임계치(Δweight threshold) 추가**
- (1) 실험 정의:  
  - 리밸런스는 48h 루프에 맞춰도 되지만, **포지션 변경은 (목표-현재) 차이가 임계치 이상일 때만** 실행  
  - 또는 “주 2회 고정” 같은 강제 다운샘플
- (2) 게이트:  
  - turnover 30~60% 감소 + **worst_mdd 악화 금지(<= 기존 candidate worst_mdd + 0.5%p)**  
- (3) 기대 관측치:  
  - 거래비용 민감도 감소, 성능 분산 축소(락박스 min 안정화)

**실험 3(옵션): 공매도/차입비용/HTB 차단**
- (1) 실험 정의:  
  - short 사용 시 **borrow cost** 또는 “HTB 리스트는 short 금지” 규칙 적용(최소는 일괄 3~10% 연비용 가정)
- (2) 게이트:  
  - short 비중이 있는 전략에서만 적용, lockbox_min이 음수로 뒤집히면 FAIL
- (3) 기대 관측치:  
  - 실거래 불가능한 수익원 제거

### (d) PASS 조건(요약)
- **비용 반영 후에도** lockbox_min ≥ 0 유지(최우선) + worst_mdd 악화 금지 + turnover 상한 준수

## TOP2) 누수/서바이버십/정렬(라벨·피처) “차단 테스트” 패치
### (a) 왜 필요한지
- 락박스가 좋아도, **피처가 미래 정보를 조금이라도 흡수**하면 개선 폭이 비정상적으로 커짐.
- 미국주식에서 **delist(상폐) 수익률 미반영**은 흔한 서바이버십 편향.

### (b) 위험/부작용
- 제대로 막으면 성능이 감소할 수 있음(정상).
- 데이터 소스/정렬 변경으로 백테스트 재현성 이슈가 생길 수 있음.

### (c) 최소 실험 2~3개
**실험 1: Purge/Embargo 교차검증(특히 48h 루프와 충돌하는 누수 차단)**
- (1) 실험 정의:  
  - 학습/튜닝에서 시계열 CV에 **purge window + embargo**를 강제(라벨 기간만큼 purge)
- (2) 게이트:  
  - tuning_mean이 떨어져도 ok, 대신 **tuning↔lockbox 갭이 축소**되어야 PASS  
  - gap 축소 기준: (lockbox_mean / tuning_mean) 비율이 개선되거나 안정
- (3) 기대 관측치:  
  - 과최적화 후보가 빠지고, 락박스 재현성이 올라감

**실험 2: Point-in-time 데이터 강제 + “발표일 지연” 적용**
- (1) 실험 정의:  
  - 재무/펀더멘털/가이던스 계열 피처는 **발표일+지연(예: +1~3영업일)** 이후에만 사용  
  - split/dividend adjustment가 신호에 미래 반영되지 않게 점검
- (2) 게이트:  
  - lockbox_min ≥ 0 유지 + worst_mdd 악화 금지
- (3) 기대 관측치:  
  - 미세 누수 제거로 과장된 샤프/평균이 정상화, 대신 하방 안정성은 유지되는 후보가 남음

**실험 3: Delisted return 포함(서바이버십 제거)**
- (1) 실험 정의:  
  - CRSP 스타일이든 대체 데이터든, **상폐 시점까지의 실제 수익률**을 포함(불가하면 conservative penalty)
- (2) 게이트:  
  - 락박스에서 tail 리스크가 증가하면 FAIL(특히 lockbox_min이 0 아래로 내려가면 즉시 컷)
- (3) 기대 관측치:  
  - “상폐 회피로 좋아 보이던” 전략이 제거됨

### (d) PASS 조건(요약)
- purge/embargo + point-in-time 후에도 **lockbox_min ≥ 0** 유지, tuning-lockbox 괴리 축소

## TOP3) 8~14 종목(Tech+Healthcare) 제약 하에서 “포트폴리오 구축/리스크 캡” 패치
### (a) 왜 필요한지
- 종목 수가 적으면 수익의 대부분이 **노출(베타/섹터/단일종목)**에서 오고, tail에서 깨짐.
- 현재 candidate는 worst_mdd가 개선됐지만, **운영 가능한 위험 한도**로 고정해야 함.

### (b) 위험/부작용
- 강한 트렌드장에서 알파가 일부 희석될 수 있음.
- 제약이 너무 빡세면 신호가 “평균화”되어 무색해질 수 있음.

### (c) 최소 실험 2~3개
**실험 1: 단일종목/섹터(Tech+HC) 내 하위산업 집중 캡**
- (1) 실험 정의:  
  - max position weight(예: 15~20%)  
  - 상위 3종목 합계 cap(예: 45~55%)  
  - (가능하면) GICS sub-industry 편중 cap
- (2) 게이트:  
  - worst_mdd 개선(또는 악화 금지) + lockbox_mean -3% 이내 유지
- (3) 기대 관측치:  
  - tail 감소, 락박스 min 안정화

**실험 2: 변동성 타게팅(포트폴리오 레벨)**
- (1) 실험 정의:  
  - 최근 N일 realized vol로 레버/현금비중 조절(목표 vol 고정)  
  - ETF는 매매 금지이므로, 지표로만(예: QQQ/XLV 변동성, VIX 대용 지표)
- (2) 게이트:  
  - worst_mdd 추가 개선(>= 0.5%p) 또는 최소 악화 금지  
  - turnover 증가 시 FAIL(거래비용과 충돌)
- (3) 기대 관측치:  
  - 레짐 변화(변동성 급등)에서 하락 방어

### (d) PASS 조건(요약)
- **집중도/변동성 규칙 적용 후** worst_mdd 비악화 + lockbox_min ≥ 0 유지

## TOP4) ETF “관측지표” 기반 레짐 게이트(적용/미적용 스위치) 패치
### (a) 왜 필요한지
- 성능이 안 움직이거나 불안정할 때, 원인이 “신호가 나쁜 게 아니라 **레짐이 안 맞는 것**”인 경우가 많음.
- ETF는 매매하지 않고 **상태 판단**만에 사용.

### (b) 위험/부작용
- 레짐 분류가 틀리면 기회비용 증가(수익 구간을 걸러냄).
- 규칙이 많아지면 과최적화 위험(그래서 1~2개 레짐만).

### (c) 최소 실험 2~3개
**실험 1: 2-레짐(리스크온/리스크오프) 스위치**
- (1) 실험 정의:  
  - 관측지표: QQQ(Tech proxy), XLV(Healthcare proxy), (가능하면) 금리/크레딧 대용  
  - 조건 예: QQQ 모멘텀<0 AND 변동성↑이면 “risk-off”: 포지션 축소/현금 비중↑  
- (2) 게이트:  
  - lockbox_min 개선(>= +0.05~0.10) 또는 worst_mdd 개선 중 하나 충족  
  - 평균 수익이 조금 줄어도 하방이 개선되면 PASS
- (3) 기대 관측치:  
  - tail이 잘리는지(락박스 min, worst_mdd)로 즉시 판단 가능

**실험 2: 신호 “적용 게이트”만 추가(신호 생성은 그대로)**
- (1) 실험 정의:  
  - 기존 알파 스코어는 그대로 두고, 레짐이 나쁠 때만 **신규 진입 금지/리밸런스 보류**
- (2) 게이트:  
  - turnover 감소 + lockbox_mean 유지
- (3) 기대 관측치:  
  - 거래비용/불필요한 왔다갔다 감소

### (d) PASS 조건(요약)
- 레짐 스위치로 **하방지표(lockbox_min, worst_mdd) 개선**이 확인될 것(평균 약간 희생 허용)

## TOP5) 운영 리스크/재현성: “48h 자동 루프” 안전장치 + 선택 편향 방지 패치
### (a) 왜 필요한지
- 자동 루프는 **데이터 갱신 타이밍/시드/환경 차이**로 재현성 깨지면 운영 리스크가 커짐.
- “select-best”가 반복되면 **선택 편향(데이터 스누핑)**이 축적될 수 있음.

### (b) 위험/부작용
- 실험 속도(throughput)가 감소할 수 있음(하지만 운영 안정성이 우선).
- 게이트를 빡세게 하면 PASS가 줄어듦(정상).

### (c) 최소 실험 2~3개
**실험 1: 고정 시드 + 아티팩트 해시 + 데이터 컷오프 스냅샷**
- (1) 실험 정의:  
  - 각 run에 (코드 커밋/데이터버전/피처스냅샷/시드) 해시 저장  
  - 동일 입력이면 동일 출력 보장(최소한 주요 지표)
- (2) 게이트:  
  - 동일 스냅샷 재실행 시 지표 오차 허용범위 이내(예: lockbox_mean ±0.5%p)
- (3) 기대 관측치:  
  - “좋았던 결과가 다시 안 나오는” 문제 제거

**실험 2: Champion 교체 게이트 강화(선택 편향 방지)**
- (1) 실험 정의:  
  - 교체 조건을 “lockbox_mean”만 보지 말고 **lockbox_min, worst_mdd, turnover** 동시 만족으로 변경  
- (2) 게이트(예시):  
  - lockbox_mean ≥ 현 champion * 1.02  
  - AND lockbox_min ≥ 0  
  - AND worst_mdd ≤ 현 champion worst_mdd + 0.5%p  
- (3) 기대 관측치:  
  - “평균만 좋고 꼬리에서 깨지는” 후보의 승격 방지

### (d) PASS 조건(요약)
- 재현성 보장 + 챔피언 교체가 “평균/하방/비용” 동시개선일 때만 발생

# 24~48시간 실행 “명령형 체크리스트”(질문 없음)
1) **비용 모델 패치부터 적용**: 슬리피지/스프레드/ADV/리밸런스 임계치 → cost-adjusted 리포트 강제 출력.  
2) **누수/서바이버십 차단 테스트**: purge/embargo CV + point-in-time(발표지연) + delist 반영(또는 보수 페널티).  
3) **포트폴리오 제약(8~14, Tech+HC) 하드코딩**: max weight/상위합 캡 + 변동성 타게팅 1개만.  
4) **ETF 관측지표 레짐 게이트 1개만 추가**: 적용/미적용 스위치(거래는 금지).  
5) **자동 루프 운영 안전장치**: 스냅샷/해시/시드 고정 + champion 승격 게이트를 다변량으로 강화.

# 성능이 안 움직일 때: 원인 분해(트리거/적용/노출/비용/레짐) 아이디어
아래 순서로 “어디서 죽는지”를 분리 진단(각 항목은 **로그/리포트에 한 줄 지표로 고정**).

## 1) Trigger(신호 생성) 문제
- 관측: 신호 분포가 평평(스코어 분산↓), 상위/하위 간 스프레드↓, 예측/실현 IC↓  
- 조치: 피처 스케일/결측 처리 변경이 신호를 죽였는지 diff, purge 후 IC 유지 여부 확인

## 2) Apply(적용/리밸런스/게이트) 문제
- 관측: 신호는 있는데 **거의 거래가 안 됨**(임계치 과도), 혹은 반대로 과도한 매매  
- 조치: “목표-현재 weight 차이” 히스토그램 + 실제 체결 수(거래수/일) 고정 출력

## 3) Exposure(노출) 문제
- 관측: 성과가 특정 1~2종목/단일 하위산업에 의존, 베타/모멘텀 팩터 노출 과대  
- 조치: 종목별 기여도(top contributors) + 포트폴리오 beta/sector weight time-series 리포트

## 4) Cost(비용) 문제
- 관측: gross는 괜찮은데 net이 무너짐, 특히 변동성 구간에서 슬리피지가 폭증  
- 조치: “총 비용(bps)/회전율/ADV충격”을 기간별로 분해(레짐별 비용도 같이)

## 5) Regime(레짐) 문제
- 관측: 특정 구간에서만 일관되게 깨짐(예: 변동성 급등, 금리 급변)  
- 조치: QQQ/XLV 모멘텀×변동성 2D 버킷으로 성과 테이블(ETF는 지표만)

## 6) Selection bias(선택 편향) 문제
- 관측: 튜닝은 계속 개선되는데 락박스는 정체/악화  
- 조치: 후보 채택 기준을 mean 중심→min/MDD/turnover 포함으로 변경, gap(튜닝-락박스) 추적

---

원샷으로 묶으면, **TOP1(비용 현실화) + TOP2(누수/서바이버십 차단) + TOP5(선택 편향/운영 안전장치)**가 “성과가 안 움직이는 진짜 원인”을 가장 빨리 드러내고, 그 다음에 **TOP3/4로 하방 안정성과 레짐 적합도를 개선**하는 흐름이 48시간 루프에 가장 잘 맞습니다.
