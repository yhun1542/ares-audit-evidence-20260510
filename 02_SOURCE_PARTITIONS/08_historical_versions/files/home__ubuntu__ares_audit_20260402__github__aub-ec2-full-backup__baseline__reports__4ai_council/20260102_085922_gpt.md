아래 5개를 **우선순위 순**으로 24~48시간 안에 “자동 48h 루프(실험 정의→게이트→기대 관측치)”로 돌릴 수 있게 **명령형 체크리스트**로 제시합니다. (누수/과최적화/서바이버십/비용/운영리스크를 최우선 점검)

## TOP1) 시간정렬/누수(Leakage) 차단 패치 (가장 먼저)
### (a) 왜 필요한지
- 현재 Champion에 `worst_mdd: None` 등 **핵심 리스크 메트릭 누락**이 보이며, oos_mean이 높아도 **누수/미정렬**이면 전부 무의미합니다.
- 특히 미국주식(일/분봉 혼합, corporate action, earning timestamp)에서 **미세 누수**가 성능을 “움직이지 않게” 만들거나 “가짜로 좋게” 만듭니다.

### (b) 위험/부작용
- 누수 제거 즉시 성능 급락 가능(정상).
- 피처/라벨 재생성으로 학습·백테스트 시간이 증가.

### (c) 최소 실험 2~3개
**실험 1 — Feature/Label 시간 잠금(Lock)**
- **정의:** 모든 피처를 `t` 시점 종가/체결 이후 생성 금지, 라벨은 `t+1..k` 수익률로만. (예: daily면 “당일 종가로 결정→다음날 시가/종가 체결”로 고정)
- **게이트:**  
  - (필수) 피처 타임스탬프 ≤ 의사결정 타임스탬프 만족률 100%  
  - (필수) “미래 참조 컬럼” 탐지(shift(-1)류/forward fill) 0건
- **기대 관측치:** oos_mean 감소해도 oos_min 안정화, fold 간 분산 감소

**실험 2 — Purged/Embargo CV로 교차검증 교체**
- **정의:** 기존 CV를 “Purged K-Fold + Embargo(예: 5~20일)”로 교체(라벨 구간 겹침 제거)
- **게이트:**  
  - degenerate_folds 발생 0  
  - oos_mean이 줄어도 **fold별 순위 일관성(Spearman > 0)** 유지
- **기대 관측치:** 과최적화 신호(훈련-검증 갭) 감소, OOS 재현성↑

**실험 3 — Earnings/News timestamp 누수 차단(있다면)**
- **정의:** 실적/가이던스/서프라이즈 계열은 “발표 시각 이후”에만 유효하도록 시프트/마스킹
- **게이트:** 발표일 당일 장중/장후 구분이 불가하면 해당 피처 전면 비활성화
- **기대 관측치:** 특정 이벤트 구간에서만 과대 성과가 나오는 패턴 완화

### (d) PASS 조건
- **누수 관련 게이트 100% 통과 +** oos_min이 의미 있게 악화하지 않음(예: 기존 대비 -20% 이내)  
- 훈련-검증 성능 격차(과최적화 지표)가 감소 방향

## TOP2) 비용/슬리피지/체결 불가능성 반영 + 회전율(턴오버) 게이트
### (a) 왜 필요한지
- 미국주식은 “좋아 보이는 알파”가 **비용 반영 즉시 사라지는** 경우가 많고, 48h 자동 루프에서 비용을 안 넣으면 계속 같은 착시를 학습합니다.
- 현재 exposure가 0.47~0.84로 **상시 고노출**에 가깝고, 비용/슬리피지 미반영 시 MDD/운영 리스크가 숨습니다.

### (b) 위험/부작용
- 성능 급감 가능(정상), 거래 빈도 줄면 신호 반응이 느려질 수 있음.

### (c) 최소 실험 2~3개
**실험 1 — 보수적 비용모델 기본 탑재**
- **정의:** per-trade 고정수수료(0에 가까워도) + 스프레드/슬리피지(예: 2~10bp) + 임팩트(ADV 대비 주문비율) 최소 모델 반영
- **게이트:**  
  - 비용 반영 후 oos_mean이 0 이하로 붕괴하면 “전략 구조 자체” 문제로 판정  
  - 체결가가 OHLC 범위 밖이면 백테스트 중단(데이터/로직 오류)
- **기대 관측치:** 거래가 많은 구간 성과가 크게 깎이며, “진짜 남는 구간”만 남음

**실험 2 — 턴오버 상한 + 리밸런싱 캘린더 고정**
- **정의:** 일일(또는 주간) 리밸런싱 고정 + 턴오버 상한(예: 포트 1.0x/일 이하) + 소폭 변경 밴드(드리프트 허용)
- **게이트:**  
  - 일별 턴오버 95퍼센타일이 상한 내  
  - 비용/슬리피지 반영 후 oos_min 개선 또는 MDD 개선
- **기대 관측치:** oos_mean 소폭 감소해도 변동성/MDD 개선

**실험 3 — 주문 가능성(유동성) 필터**
- **정의:** 20일 ADV·스프레드 기반으로 “주문 규모/슬리피지 예상”이 일정 임계 초과면 매매 금지
- **게이트:** 거래 대상 8~14종목 유지 실패 시(너무 줄면) 필터 완화 대신 “전략 재설계”로 분기
- **기대 관측치:** 체결 불가능 종목이 성과를 만드는 착시 제거

### (d) PASS 조건
- 비용 반영 후에도 **oos_mean 양수 유지 + worst_mdd 산출/기록 정상화 + 턴오버 게이트 충족**

## TOP3) 서바이버십/Point-in-Time 유니버스 고정 + (Tech+Healthcare 8~14) 강제
### (a) 왜 필요한지
- “현재 살아남은 종목만”으로 백테스트하면 서바이버십 편향이 생깁니다.
- 또한 요구사항(미국주식 only, Tech+Healthcare 중심, 8~14개)을 **코드 레벨로 강제**하지 않으면 루프가 점점 다른 방향으로 드리프트합니다.

### (b) 위험/부작용
- 데이터 소스/매핑(GICS, 상장폐지, ticker change) 작업이 필요.
- 유니버스가 작아지면 분산 감소로 MDD가 늘 수 있음(따라서 리스크 규칙 필요).

### (c) 최소 실험 2~3개
**실험 1 — Point-in-Time 구성요소 고정**
- **정의:** 각 시점 t에서의 섹터(GICS/NAICS), 상장상태, 시총/유동성 정보를 “t 시점 기준”으로만 사용
- **게이트:** ticker change / delist가 있을 때 룩어헤드 참조 0
- **기대 관측치:** 과거 특정 구간 과대 성과가 줄고, 재현성↑

**실험 2 — 유니버스 제약(Tech+Healthcare, 8~14) 하드코딩**
- **정의:** (i) 섹터=Technology/Health Care만, (ii) 리밸런스 시점마다 최종 보유 종목 수 8~14 강제, (iii) ETF 거래 금지(단 관측지표로만)
- **게이트:** 모든 백테스트 날짜에서 보유 종목 수 조건 위반 0
- **기대 관측치:** 성과는 일부 줄어도 운영/요구사항 일치 및 해석가능성↑

**실험 3 — “관측용 ETF” 레짐 지표 분리**
- **정의:** QQQ/XLK/XLV 등은 **신호(레짐/리스크 온오프) 관측용 피처로만** 사용, 주문대상에서 제외
- **게이트:** 주문 테이블에 ETF 티커 등장 0
- **기대 관측치:** 레짐 설명력은 유지, 제약 준수

### (d) PASS 조건
- 서바이버십/유니버스 게이트 100% + 종목 수 8~14 상시 유지 + ETF 미매매 100%

## TOP4) 포트폴리오 노출/리스크 규칙 패치 (MDD/운영 안정화)
### (a) 왜 필요한지
- 현재 exposure가 0.47~0.84로 **항상 베타 노출**이 크고, worst_mdd가 누락되어 리스크가 가려져 있습니다.
- 48h 자동 루프는 “조금 더 수익”보다 **망가지지 않는 제약**이 먼저입니다.

### (b) 위험/부작용
- 노출 제한으로 수익 상한이 내려갈 수 있음.
- 규칙이 과하면 알파 자체를 죽일 수 있음.

### (c) 최소 실험 2~3개
**실험 1 — 노출 목표(Vol target) + Max single-name**
- **정의:** 포트 변동성 타겟(예: 연 10~15%)으로 총 익스포저 조절 + 단일종목 비중 상한(예: 15~20%)
- **게이트:**  
  - exposure_min/max가 설정 범위 내(예: 0.2~0.9)  
  - 단일종목 상한 위반 0
- **기대 관측치:** MDD 감소, 수익률 분포 꼬리 완화

**실험 2 — 손실 국면 Kill-switch(레짐 방어)**
- **정의:** 관측용 ETF(예: XLK/XLV/QQQ)의 추세/변동 급증 시 현금 비중 확대(단, ETF는 거래하지 않음)
- **게이트:** 방어 발동 횟수가 과도하면(예: 월 10회↑) 신호 과민으로 판정하고 롤백
- **기대 관측치:** 급락 구간 손실 완화, oos_min 개선

**실험 3 — 리스크 예산(섹터 내) 균형**
- **정의:** Tech/Healthcare 간 리스크 기여를 제한(한 섹터 쏠림 방지)
- **게이트:** 섹터 리스크 기여가 임계(예: 70%) 초과일이 전체의 5% 이내
- **기대 관측치:** 특정 섹터 단독 베팅으로 인한 성과 편차 감소

### (d) PASS 조건
- worst_mdd 산출 정상 + MDD가 의미 있게 감소(예: 기존 대비 10% 이상 개선) + 제약 위반 0

## TOP5) 48h 자동 루프 운영/관측성(Observability) 패치 (실패 원인 추적 가능하게)
### (a) 왜 필요한지
- 현재 상태에서 “Next Commands (3 lines)”가 비어 있고, `worst_mdd: None`처럼 **관측/리포팅 누락**이 보입니다. 이 상태면 성능이 안 움직일 때 원인 분해가 불가능합니다.
- 자동 루프는 성능보다 먼저 **재현성/로그/가드레일**이 필요합니다.

### (b) 위험/부작용
- 엔지니어링 작업으로 단기 성능 개선 속도는 느려짐.
- 로그/저장 증가로 비용 상승(하지만 필수 비용).

### (c) 최소 실험 2~3개
**실험 1 — 필수 메트릭 강제 산출 + 누락 시 런 실패 처리**
- **정의:** oos_mean/oos_min/worst_mdd/turnover/cost_adj_return/exposure 범위/거래횟수/슬리피지/섹터 비중을 “필수”로; 하나라도 None이면 파이프라인 실패
- **게이트:** 필수 메트릭 누락 0
- **기대 관측치:** “좋다/나쁘다”가 아니라 “왜 그런지”가 매 런에서 남음

**실험 2 — Champion/Challenger 승격 규칙 고정**
- **정의:** 승격은 (i) 비용 반영 성과, (ii) oos_min, (iii) worst_mdd, (iv) 제약 위반 0을 모두 통과해야만
- **게이트:** 단일 지표(oos_mean)만으로 승격 금지
- **기대 관측치:** 성능 출렁임 감소, 회귀(regression) 방지

**실험 3 — 재현 가능한 아티팩트 저장(해시/데이터 스냅샷)**
- **정의:** lane_hash/run_hash에 대응하는 데이터 스냅샷 버전, 피처 정의, 시드, 비용 파라미터를 저장
- **게이트:** 동일 해시로 재실행 시 결과 편차 허용범위 내
- **기대 관측치:** “성능이 안 움직임/갑자기 변함”의 원인을 즉시 역추적 가능

### (d) PASS 조건
- 필수 메트릭/아티팩트 누락 0 + 승격 규칙 위반 0 + 동일 해시 재현성 확보

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **고정 순서로 디버그 루프**에 넣으세요(질문 없이 실행 항목만).

## 1) 트리거(신호 발생 자체) 문제
- **체크:** 신호(스코어) 분포가 거의 상수인지(표준편차/엔트로피), 상위/하위 분위 간 차이가 사라졌는지
- **조치:**  
  - 피처 중요도/상관이 0으로 수렴하면 “데이터 정렬/결측 처리/스케일링” 회귀 의심  
  - 신호가 발생해도 포지션이 안 바뀌면 “게이트/제약이 과도”한지 점검

## 2) 적용(포지션 변환) 문제
- **체크:** 스코어→목표비중 맵핑이 너무 완만/클리핑으로 눌려있는지, 8~14 종목 제약 때문에 랭킹이 평준화되는지
- **조치:**  
  - 스코어 분위수 기반(Top-K/Bottom-K)로 단순화한 A/B 변환을 1회만 돌려 비교  
  - 포지션 업데이트 주기(일/주) 고정 후 변화량이 0에 가까우면 로직 오류 가능

## 3) 노출(시장/섹터 베타) 문제
- **체크:** PnL의 대부분이 QQQ/XLK/XLV(관측용)와 상관으로 설명되는지(회귀로 베타 추정)
- **조치:**  
  - 베타가 성과를 지배하면 “알파가 아니라 레짐 베팅” → 노출 타겟/헷지(현금 비중) 규칙 강화  
  - Tech 쏠림이 과하면 Healthcare 비중 규칙으로 균형

## 4) 비용(턴오버/슬리피지) 문제
- **체크:** 비용 전/후 성과 격차가 커지는 구간이 특정 변동성 국면에 집중되는지
- **조치:**  
  - 비용 민감도(슬리피지 2/5/10bp) 스윕을 고정 템플릿으로 매 런 기록  
  - 턴오버 상한/드리프트 허용으로 구조적 개선

## 5) 레짐(시장 국면) 문제
- **체크:** 성과가 특정 레짐(금리 급등, 성장주 언더퍼폼, 헬스케어 방어장)에서만 발생/붕괴하는지
- **조치:**  
  - 관측용 ETF로 레짐 라벨링(예: XLK 상대강도, VIX 대체 지표 등) 후 레짐별 성과 테이블 자동 출력  
  - 레짐별로 “포지션 스케일만” 다르게 하는 최소 규칙부터 적용(모델 다중화는 후순위)
