## TOP5 우선순위(24~48h) — “명령형 체크리스트”
(누수/과최적화/서바이버십/비용 미반영/운영 리스크 순서로 먼저 잠금)

---

# 1) **운영 리스크 차단: 아티팩트/로그/리밸런스 데이터 무결성 복구**
현재 `lane_hash/run_hash=None`, champion `file:` 비어있음, `rebalance_pinpoint`가 **입력 포맷/경로 오류로 완전 실패** → 성능이 “안 움직이는” 게 아니라 **관측/디버그가 불가능한 상태**일 수 있음.

### (a) 왜 필요한지
- 리밸런스 로그가 없으면 “트리거는 바뀌었는데 적용이 안 됨(=0 delta)” 같은 케이스를 분해 못 함.
- champion 메타데이터 부재는 재현성/롤백/자동 루프 안정성에 치명적.

### (b) 위험/부작용
- 스키마 변경으로 과거 리포트 로더가 깨질 수 있음.
- 로그 저장량 증가(디스크/IO 비용).

### (c) 최소 실험(2~3개, **단일 패치(E1)** 안에서 토글로 수행)
**E1: “Rebalance Observability Patch” (48h 루프 필수 장착)**
1) **리밸런스 출력 강제 표준화(JSONL 1종으로 고정)**  
   - 매 리밸런스 시점마다 `timestamp, universe, target_w, executed_w, price, adv, est_cost, realized_cost, gross/net_exposure, turnover` 한 줄 저장.
2) **base-log 경로 자동 탐색/폴백**  
   - `--base-log`가 없으면 최근 run 디렉토리에서 `rebalance.jsonl` 자동 선택.
3) **champion 메타데이터 강제 채움 + fail-fast**  
   - `lane_hash, run_hash, git_sha, data_version, config_hash` 없으면 학습/백테스트를 실패 처리(조용히 진행 금지).

### (d) PASS 조건
- `aub_rebalance_pinpoint.py`가 **에러 없이 리포트 생성**.
- champion JSON에 `lane_hash/run_hash/file`가 **모두 non-null**.
- “No-Delta” 발생 시, 리포트에서 **(트리거→주문→체결→노출)** 어디에서 0이 됐는지 한 줄로 pinpoint 가능.

**48시간 자동 루프 형식**
- (1) 실험 정의: E1 패치 적용 후 동일 후보 1개를 재실행
- (2) 게이트: 리밸런스 로그 100% 생성 + pinpoint 리포트 생성 성공
- (3) 기대 관측치: “delta=0”이면 원인이 `constraint clip / rounding / exposure gate / missing universe` 중 하나로 분류되어 출력

# 2) **누수/서바이버십/포인트-인-타임(PTI) 검증: “Leakage Sentinel”**
지금처럼 OOS가 “안 움직이는” 국면에서 가장 흔한 원인:  
- (i) PTI 위반/누수로 이미 과적합 → 새로운 실험이 OOS에서 차이가 안 남  
- (ii) 반대로 과도한 클리핑/게이트로 실제로는 신호가 적용이 안 됨(=E1로 확인)

### (a) 왜 필요한지
- 미국주식(Tech/Healthcare)에서 기업행동(분할/배당), 지표 업데이트 시점(earnings/fundamental lag) 누수는 빈발.
- 서바이버십(현재 구성 종목만 과거에 넣는 것)도 무의식적으로 들어가기 쉬움.

### (b) 위험/부작용
- 테스트가 성능을 “낮추는” 게 정상일 수 있음(누수 제거하면 떨어짐).
- 데이터 소스가 PTI를 지원하지 않으면 일부 피처 폐기 필요.

### (c) 최소 실험(2~3개, **단일 실험(E2)**로 묶어서 수행)
**E2: “Leakage Sentinel Suite”**
1) **라벨 퍼뮤테이션 테스트(permute labels)**  
   - 동일 피처/파이프라인에서 수익률 라벨만 랜덤 셔플 → OOS 성능이 0 근처여야 정상.
2) **시간 시프트 테스트(lookahead shift)**  
   - 모든 피처를 +1일(또는 +1bar) 밀어 학습/예측 → 정상이라면 성능 급락.
3) **PTI 래그 강제(최소 1~2일 lag, 이벤트는 발표 후 반영)**  
   - earnings/fundamental 계열 피처는 “발표 시각 이후”로 강제 스냅.

### (d) PASS 조건
- 퍼뮤테이션 OOS mean이 **0에 수렴(예: |mean| < 0.1σ)**.
- 시간 시프트(+1)에서 성능이 **유의미하게 붕괴**.
- PTI 래그 적용 후에도 “기본 전략” OOS가 완전 사망하지 않고, 성능 변화가 **설명 가능한 방향**으로 나타남.

**48시간 자동 루프 형식**
- (1) 실험 정의: E2-1/2/3을 같은 코드로 세 번 돌리고 리포트에 나란히 출력
- (2) 게이트: permute/shift 케이스가 베이스와 비슷하면 **즉시 누수 경보**
- (3) 기대 관측치: 누수 있으면 permute/shift에서도 OOS가 높게 유지(=비정상)

# 3) **과최적화/폴드 붕괴(degenerate_folds) 제거: Purged Walk-Forward로 고정**
현재 `degenerate_folds: [1,2,3,8]` 는 “검증 체계가 깨져서”  
실험 간 차이가 OOS에 반영되지 않거나, 특정 폴드가 비어/상수 예측이 나오는 전형 패턴.

### (a) 왜 필요한지
- 폴드가 붕괴하면 평균 OOS가 숫자로는 존재해도 **비교가 무의미**.
- 특히 8~14 종목 소수 유니버스에서는 “자산-시간 불균형”이 쉽게 발생.

### (b) 위험/부작용
- 학습 데이터가 줄어 OOS mean이 내려갈 수 있음(대신 신뢰도↑).
- 실험 시간이 약간 증가.

### (c) 최소 실험(2~3개, **단일 실험(E3)**로 수행)
**E3: “CV Hardening (Purged/Embargo + Min-Sample)”**
1) **Purged Walk-Forward + Embargo(예: 5~20거래일)**  
   - 라벨 구간과 피처 구간 겹침 제거.
2) **폴드 최소 샘플/최소 리밸런스 이벤트 수 강제**  
   - 폴드에 “실제 리밸런스가 N회 미만”이면 폴드 자체를 생성하지 않음.
3) **자산-시간 균형 샘플링(동일 종목 과대표집 방지)**  
   - fold마다 종목별 샘플 비율 상한 적용.

### (d) PASS 조건
- `degenerate_folds`가 **빈 배열**.
- OOS min(현재 -0.0257)이 **개선(예: > -0.01)** 또는 최소한 더 악화되지 않음.
- fold별 성능 분산이 과도하게 크지 않음(“한 폴드만 대박” 패턴 완화).

**48시간 자동 루프 형식**
- (1) 실험 정의: E3 적용한 동일 전략을 2 seed로 반복 실행(재현성 체크)
- (2) 게이트: degenerate 발생 시 즉시 실패 처리
- (3) 기대 관측치: 평균이 약간 내려가도 min/분산이 안정화

# 4) **비용/체결/회전율을 성능 목표에 내장: Cost-Aware Rebalance**
리밸런스 로그가 비어 비용/체결 검증 자체가 막혀 있었음(E1로 해소 후).  
이제 “비용 미반영”을 먼저 잠가야 OOS가 의미 있게 움직임.

### (a) 왜 필요한지
- Tech/Healthcare 대형주는 스프레드는 낮아도 **잦은 리밸런스+슬리피지+임팩트**로 알파가 상쇄되기 쉬움.
- 비용을 모델에 넣지 않으면, 실험들이 “좋아 보이지만 실전 불가” 방향으로 수렴.

### (b) 위험/부작용
- turnover 억제하면 OOS mean이 줄 수 있음.
- 너무 강한 비용 페널티는 “항상 홀드”로 퇴화 가능.

### (c) 최소 실험(2~3개, **단일 실험(E4)**로 수행)
**E4: “Cost-Aware Portfolio Patch”**
1) **명시적 비용모델(commission=0 가정하더라도 slippage/impact는 필수)**  
   - 예: `slippage = a*spread + b*(|Δw|/ADV)` 형태(단순형이라도 넣기).
2) **turnover cap + min-hold(예: 2~5일) + weight-change deadband**  
   - 작은 신호 변화로 매번 갈아타는 것 방지.
3) **노출/레버리지 하드 가드레일**  
   - gross/net, 단일종목 max weight, 섹터 내 편중 제한(Tech/HC 내에서).

### (d) PASS 조건
- 평균 turnover가 **30% 이상 감소**(기존 대비).
- after-cost OOS mean이 **5% 이상 악화되지 않음**(또는 OOS min/드로우다운 개선으로 상쇄).
- 노출(`exposure_min/max`)이 설정 범위 내에서 안정(0~0.84 같은 변동이 의미 있게 설명되어야 함).

**48시간 자동 루프 형식**
- (1) 실험 정의: E4 적용 전/후 동일 기간 비교 리포트 자동 생성
- (2) 게이트: turnover cap 위반/비용 누락 시 실패
- (3) 기대 관측치: mean이 비슷하면 min/DD 개선, 아니면 “과도 회전 전략”임이 확정

# 5) **레짐/리스크 오프 게이트(ETF는 지표만): Tech↔Healthcare 스위칭**
ETF 매매는 금지이므로 **관측지표**로만 사용.  
OOS가 안 움직일 때는 레짐 차이(금리/리스크온오프)가 성능을 눌러 “실험 간 차이”가 희석되는 경우가 많음.

### (a) 왜 필요한지
- Tech는 금리/성장 레짐에 민감, Healthcare는 방어적 성격이 강함.
- 둘을 같은 트리거로 계속 돌리면 레짐에 따라 일괄적으로 눌려 OOS가 평평해짐.

### (b) 위험/부작용
- 게이트가 잘못되면 기회 손실(리스크온에서 too defensive).
- 지표(ETF 모멘텀)가 단기 노이즈면 잦은 스위칭 유발 → E4의 deadband와 같이 써야 함.

### (c) 최소 실험(2~3개, **단일 실험(E5)**로 수행)
**E5: “Regime Gate using ETFs (indicator-only)”**
1) **리스크온/오프 스칼라**  
   - 예: `gate = f(QQQ momentum, XLV relative strength, SPY vol proxy)`  
   - gate는 포지션 크기(노출)만 조절하고 종목 매매 로직은 유지.
2) **Tech/Healthcare 비중 스위치**  
   - gate가 risk-off면 Healthcare 쪽 목표비중 상향, Tech 하향(총 종목수 8~14 유지).
3) **게이트 히스테리시스(진입/이탈 임계 분리)**  
   - 스위칭 빈도 제한(운영 리스크/비용 방지).

### (d) PASS 조건
- OOS min 개선(예: -0.0257 → **>-0.015** 같은 하방 완화).
- 최대 낙폭/손실 구간에서 손실이 줄고, gate가 “리스크오프 구간”에만 주로 작동(E1 로그로 확인).
- 스위칭 빈도가 과도하지 않음(예: 월 4회 이하 수준으로 제한).

**48시간 자동 루프 형식**
- (1) 실험 정의: E5 on/off A/B 비교(동일 비용모델 E4 포함)
- (2) 게이트: 스위칭 과다/turnover 폭증 시 실패
- (3) 기대 관측치: 하방(min/DD) 개선이 핵심, mean은 약간 희생 가능

# 성능이 “안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래 트리는 **E1 로그가 생긴다는 전제**에서 10분 내 자동 판정 가능하게 구성하라.

## 1) Trigger(신호 생성) 레벨
- **증상**: 예측값/스코어 분포가 거의 고정(분산≈0), 실험 바꿔도 동일  
- **조치**:  
  - 피처 분산/결측률/클리핑 비율을 리밸런스 시점별로 출력  
  - 퍼뮤테이션/시프트(E2)에서 성능이 유지되면 누수 경보

## 2) Apply(포트폴리오 적용) 레벨
- **증상**: 신호는 변하는데 `target_w`가 늘 0 또는 동일 패턴  
- **가능 원인**: 제약조건이 과도(단일종목 max, 섹터 cap, 현금 비중 cap), 라운딩/최소 주문 단위, min-hold 충돌  
- **조치**: E1에 “clip reason code(왜 잘렸는지)”를 기록

## 3) Exposure(노출/리스크) 레벨
- **증상**: gross/net이 일정하게 눌림(항상 low exposure), 혹은 0↔0.84로 튐  
- **가능 원인**: vol targeting이 극단값을 만들거나, 리스크모델 입력(변동성)이 깨짐  
- **조치**: 노출 결정에 쓰인 vol/var 추정치의 시계열을 저장하고, 스파이크 구간을 자동 태깅

## 4) Cost(비용) 레벨
- **증상**: before-cost는 좋아 보이는데 after-cost는 평평/악화  
- **가능 원인**: 잦은 리밸런스, ADV 대비 과한 주문, 슬리피지 누락/과대  
- **조치**:  
  - `gross pnl` vs `cost` 분해를 리밸런스별로 출력  
  - turnover 상위 5 이벤트를 자동 덤프(가격/ADV/Δw 포함)

## 5) Regime(레짐) 레벨
- **증상**: 특정 기간(금리 급등/리스크오프)에서만 일괄적으로 죽고 실험 간 차이가 사라짐  
- **조치**:  
  - ETF 지표(관측용)로 구간 태깅(QQQ 모멘텀↓, 변동성↑ 등)  
  - 구간별 성능 테이블(리스크온/오프) 자동 생성 → E5로 연결

## 48시간 실행 순서(우선순위 그대로)
1) **E1(로그/무결성) 먼저**: pinpoint 리포트가 “반드시” 나오게 만들어라.  
2) **E2(누수 센티널)**: permute/shift 통과 못 하면 그 다음 실험은 전부 무의미.  
3) **E3(CV 하드닝)**: degenerate_folds 제거 후에만 OOS 비교를 신뢰.  
4) **E4(비용/턴오버 내장)**: 실전 적합성 확보.  
5) **E5(레짐 게이트)**: 하방(min/DD) 개선용, mean은 보조.

이 5개만 돌려도 “왜 성능이 안 움직였는지”가 **트리 레벨로 분해**되어 다음 사이클에서 전략 실험이 의미 있게 진행된다.
