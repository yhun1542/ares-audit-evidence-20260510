### [우선순위 TOP 3 제안: 24~48시간 실행 루프]

#### 1. Degenerate Folds(폴드 붕괴) 긴급 디버깅 및 예외 처리
**(a) 필요성**: 현재 `degenerate_folds: [1, 2, 3, 8]` 상태는 심각함. 전체 데이터셋의 40% 구간에서 전략이 작동하지 않거나(No Trade), NaN/Inf로 인해 0점 처리됨. 이 상태에서의 `oos_mean: 3.32`는 신뢰할 수 없는 허수임.
**(b) 위험/부작용**: 붕괴된 폴드를 살려낼 경우, 전체 평균 수익률이 급락할 수 있음(숨겨진 손실 드러남).
**(c) 실험 (Experiments)**
*   **EXP-01 [Data/Imputation]**: 입력 데이터(OHLCV)의 결측치 처리 방식을 `Forward Fill`에서 `Drop`으로 변경하거나, 지표 산출 시 `Min_Periods` 요건을 완화(예: 20일->5일)하여 신호 생성 강제.
*   **EXP-02 [Logic/Fallback]**: 변동성(ATR 등)이 0에 수렴하거나 계산 불가일 때, `Default Volatility(예: 1.5%)`를 강제 주입하는 Fallback 로직 추가.
*   **EXP-03 [Constraint/Relax]**: 해당 폴드 기간에 유니버스(Tech+Healthcare) 종목 수가 8개 미만인지 확인하고, 부족 시 시총 상위 대체 종목(Backup List) 허용.
**(d) PASS 조건**: `degenerate_folds` 개수가 0 또는 1 이하로 감소.

#### 2. Rebalance Log 포맷 통일 및 파이프라인 복구
**(a) 필요성**: `Error loading ... Expecting value` 및 `No such file` 에러 발생. 챔피언 모델과 후보 모델의 거래 내역(Rebalance Log)을 비교할 수 없어 성과 분석(Pinpoint)이 불가능함.
**(b) 위험/부작용**: 로깅 오버헤드로 인한 백테스트 속도 저하(미미함). 기존 로그 데이터 폐기 필요.
**(c) 실험 (Experiments)**
*   **EXP-04 [Infra/Format]**: 모든 거래 로그 출력을 `.csv`가 아닌 `JSONL` (Line-delimited JSON)로 통일하고, `timestamp`, `ticker`, `target_weight`, `execution_price` 필수 필드 강제 검증기(Validator) 부착.
*   **EXP-05 [Infra/Path]**: 실행 스크립트에서 `--base-log` 경로를 상대 경로가 아닌 절대 경로(`/home/ubuntu/AUB/...`)로 동적 매핑하도록 수정.
**(d) PASS 조건**: `aub_rebalance_pinpoint.py` 실행 시 에러 없이 리포트 생성 및 `worst_mdd` 값 정상 산출.

#### 3. Tech/Healthcare 집중형 유니버스 필터링 강화 (8~14 Stocks)
**(a) 필요성**: ETF 매매 제외 및 섹터 집중 규칙 준수 필요. 현재 `exposure_max: 0.83`이나 종목 구성이 불명확함. 과최적화를 막기 위해 섹터 내 주도주(Momentum/Quality)로 압축 필요.
**(b) 위험/부작용**: 분산 효과 감소로 인한 개별 종목 리스크(MDD) 증가.
**(c) 실험 (Experiments)**
*   **EXP-06 [Universe/Selection]**: 유니버스 선정 로직을 `Sector=Technology or Healthcare` AND `AvgVolume > 5M`으로 고정. 모멘텀(12M-1M) 상위 7개씩 추출 후 상관계수 0.7 이상 종목 제외(De-correlation). 최종 8~14개 유지.
*   **EXP-07 [Allocation/Cap]**: 개별 종목 비중 상한(Cap)을 15%로 설정하고, 현금 비중(Cash Buffer) 최소 10% 강제(운영 리스크 방어).
**(d) PASS 조건**: 포트폴리오 내 ETF 비중 0%, Tech/Health 비중 100%, 종목 수 항상 8~14개 유지 확인.

### [성능 정체 시 원인 분해 아이디어]

성능 지표가 움직이지 않거나(Flat), 개선되지 않을 때 다음 트리를 점검:

1.  **트리거 (Signal Trigger)**
    *   *현상*: 매매 횟수 0 또는 극소수.
    *   *점검*: 진입 임계값(Threshold)이 너무 높지 않은가? (예: RSI < 20 -> RSI < 30으로 완화). `degenerate_folds`의 주원인일 가능성 높음.

2.  **적용/필터 (Execution Filter)**
    *   *현상*: 신호는 발생했으나 주문이 나가지 않음.
    *   *점검*: `Allow_Wash_Sale=False` 설정이나, 최소 주문 금액($Limit) 제한에 걸렸는지 확인. Tech/Health 고가주(High Price)의 경우 1주 단위 매매가 자금 부족으로 실패했는지 체크.

3.  **노출 (Exposure Constraints)**
    *   *현상*: 수익은 나는데 전체 계좌 성과가 미미함.
    *   *점검*: `exposure_max`가 0.83인데 실제 평균 노출도는 0.3 수준인지 확인. 변동성 조절(Vol Targeting) 로직이 포지션 사이즈를 지나치게 축소하고 있는지 확인.

4.  **비용 (Cost Impact)**
    *   *현상*: Gross Profit은 좋으나 Net Profit이 나쁨.
    *   *점검*: 잦은 리밸런싱(Turnover)으로 슬리피지/수수료 누적. 리밸런싱 주기를 주간(Weekly)에서 격주(Bi-weekly)로 변경 고려.

5.  **레짐 (Regime Mismatch)**
    *   *현상*: 특정 연도(Fold)에만 손실 집중.
    *   *점검*: 금리 인상기(2022)나 헬스케어 정책 리스크 구간인지 확인. 해당 구간에는 Beta(시장지수) 헷지 비중을 늘리는 로직(Market Regime Filter) 작동 여부 확인.
