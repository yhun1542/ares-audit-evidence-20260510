# 실험/패치 5개(48시간 자동 루프 형태로 정의)

## [EXP-A] Rebalance/Trade 로그 포맷 표준화 + Pinpoint 복구 (아키텍처)
**(1) 실험 정의**
- 매 런마다 아래 아티팩트를 **필수 생성**:
  - `rebalance.jsonl`: timestamp, universe, target_weight, current_weight, order_qty, reason(signal/constraint/cash), expected_turnover
  - `fills.jsonl`: fill_price, qty, mid, spread_est, slippage_est
  - `costs.jsonl`: commission, slippage, spread_cost, total_cost
- `aub_rebalance_pinpoint.py`가 **CSV/JSONL 모두 자동 탐지**하도록 로더를 수정하고, 현재처럼 `--base-log`가 경로가 아닌 문자열일 때 **즉시 FAIL** 처리.

**(2) 게이트**
- `rebalance_pinpoint`가 “No rebalance data found”를 출력하면 **실험 런 자체를 FAIL**.
- `worst_mdd: None` 같은 결측이 나오면 **metrics schema FAIL**.

**(3) 기대 관측치**
- “성능이 안 움직임” 상황에서 원인 분해가 가능해짐:
  - 리밸런스 빈도/회전율/거래건수/비용이 **실험 간 동일한지**가 즉시 보임.
  - 특히 현재 로그 에러(파일 없음/JSON 파싱 실패)가 **0건**으로 떨어져야 함.

---

## [EXP-B] 비용 모델 OOS 강제 반영(스프레드+슬리피지) + 비용 민감도 스윕 (전략/평가)
**(1) 실험 정의**
- OOS score 계산에 비용을 강제 포함:
  - 기본: `cost = k_spread * spread + k_slip * ATR_based_slip + commission`
- 민감도 스윕(같은 신호/같은 종목/같은 리밸런스에서 비용 계수만 변경):
  - B1: (보수) `k_spread=1.0, k_slip=1.0`
  - B2: (완화) `k_spread=0.5, k_slip=0.5`

**(2) 게이트**
- 비용 포함 전/후에 **turnover가 동일**해야 함(같은 주문이 나가야 비용만 비교 가능).
- 비용이 포함되었는데도 성과가 거의 동일하면 → “거래가 거의 없음/노출이 고정” 가능성으로 자동 플래그.

**(3) 기대 관측치**
- OOS mean이 “비용 포함”에서 유의미하게 변해야 정상.
- 비용 포함 후 급락이면 → 현재 알파가 “비용에 취약” 또는 “과도한 회전율” 신호.

---

## [EXP-C] 누수/시간정렬/피처 프리징 게이트(리스크 최우선)
**(1) 실험 정의**
- 피처 생성/라벨/체결가격의 타임스탬프를 전부 분리:
  - feature_time <= decision_time < execution_time을 강제
- “의도적 누수 시드”를 1개 만들어 테스트:
  - 미래 리턴을 한 칸 당겨 넣는 더미 피처를 넣었을 때 성능이 폭발하면 → 게이트가 제대로 작동하는지 확인.

**(2) 게이트**
- 누수 더미 피처에서 성능이 상승하면 **테스트는 PASS**, 하지만 메인 파이프라인에선 해당 패턴이 감지되면 **즉시 FAIL**(차단 동작 확인).
- `asof merge` 미준수/forward-fill이 미래를 침범하면 FAIL.

**(3) 기대 관측치**
- 현재 “OOS mean 2.62였는데 챔피언은 1.88” 같은 비정상 갭이 **줄어들거나 원인(정렬/로그/비용)으로 분리**됨.

---

## [EXP-D] 노출/제약/퇴화 폴드 방지: 8~14 종목 고정 + 가중치/회전율 캡 (전략/운영)
**(1) 실험 정의**
- 유니버스를 8~14개로 고정하고(Tech+Healthcare), 제약을 명시:
  - 종목별 max weight: 12~18% (택1)
  - 포트폴리오 net exposure: 0.55~0.85 범위 강제(현재 0.47~0.84는 하단이 너무 낮아질 여지)
  - turnover cap: 예) 일 20% / 주 50% (둘 중 하나)
- 목적: “성능이 안 움직이는 이유 = 제약이 신호를 눌러버림/혹은 신호가 주문을 못 냄”을 분리.

**(2) 게이트**
- 각 폴드/구간에서 **거래 발생률(리밸런스 건수)**이 최소 기준 미달이면 FAIL(예: 주 1회 미만이면 신호가 죽어있음).
- exposure_min이 0.5 아래로 지속 하락하면 FAIL(현금화로 성과가 정체되는 경우 차단).

**(3) 기대 관측치**
- (정상) 거래건수/노출이 안정화되며 비용-성과의 관계가 선명해짐.
- (이상) 제약을 줘도 여전히 거래가 없다면 → 트리거/신호 적용 경로 문제 가능성↑.

---

## [EXP-E] 레짐/관측지표(ETF는 “관측만”) 기반의 온/오프 게이트 (전략)
**(1) 실험 정의**
- ETF는 매매 금지, **시장 상태 관측 지표로만** 사용:
  - QQQ(tech), XLV(healthcare), IWM(리스크), TLT(금리 민감), VIX proxy(가능하면)
- 레짐 온/오프 게이트 1개만 추가(단순):
  - 예: `QQQ 20D momentum > 0` AND `VIX proxy < threshold`일 때만 리밸런스 실행
  - 아니면 기존 포지션 유지(거래 억제)

**(2) 게이트**
- 게이트가 켜진 기간/꺼진 기간을 로그로 남기고, **켜짐 비율이 20~80%** 범위를 벗어나면 FAIL(항상 꺼지거나 항상 켜지면 의미 없음).

**(3) 기대 관측치**
- 성능이 안 움직이던 경우, 레짐별로 성과가 갈리면 → “레짐 미반영”이 정체 원인임이 드러남.
- 레짐별로도 변화가 없으면 → 신호/실행/비용/데이터 쪽 원인 가능성↑.

# 2) TOP5 제안별 정리(왜/위험/실험/패스 조건)

## TOP1) **리밸런스 데이터/로그 파이프라인 복구(현재 에러 직접 타격)**
**(a) 왜 필요한지**
- 현재 `aub_rebalance_pinpoint`가 **base-log 경로 오류 + JSON 파싱 실패 + 데이터 없음**으로 원인 분석이 막힘.
- “성능이 안 움직임”은 실제로는 **주문이 안 나가거나(트리거 dead)**, **제약으로 무력화**되거나, **비용이 누락**된 경우가 많음. 로그 없으면 분해 불가.

**(b) 위험/부작용**
- 로그를 강제하면 저장 용량/IO 증가.
- 스키마 변경으로 기존 리더들이 깨질 수 있음(그래서 게이트/마이그레이션 필요).

**(c) 최소 실험(공유 참조)**
- EXP-A, EXP-D

**(d) PASS 조건**
- 48시간 동안 모든 런에서:
  - `rebalance_pinpoint`가 정상 리포트 생성(“No rebalance data found” 0회)
  - `worst_mdd` 등 핵심 메트릭 결측 0회
  - 거래/비용/노출이 실험 간 비교 가능한 형태로 남음

---

## TOP2) **비용 미반영/비용 과소추정 제거(가짜 안정성 제거)**
**(a) 왜 필요한지**
- 비용이 빠지면 OOS가 “안 움직이는 것처럼” 보이거나, 반대로 과도한 회전 전략이 과대평가됨.
- Tech/Healthcare 대형주는 스프레드는 작아도 **슬리피지/갭/체결 지연**이 누적되면 충분히 성과를 깎음.

**(b) 위험/부작용**
- 비용을 넣으면 성과가 급락할 수 있음(하지만 그게 현실).
- 비용 모델 파라미터 선택이 또 다른 과최적화 지점이 될 수 있음(그래서 스윕은 2점만).

**(c) 최소 실험**
- EXP-B, EXP-A

**(d) PASS 조건**
- 비용 스윕(B1 vs B2)에서:
  - turnover 동일(주문 동일) + 성과 차이가 “비용 크기”에 일관되게 반응
  - 비용 포함 성과가 0에 수렴하면 → 다음 단계는 turnover cap/레짐 게이트로 개선 여지 확인(=실패가 아니라 진단 성공)

---

## TOP3) **누수/시간정렬/피처 프리징 게이트(리스크 최우선)**
**(a) 왜 필요한지**
- 누수는 “성능이 높게 고정”되거나 “실험이 바뀌어도 OOS가 안 움직이는” 착시를 만들 수 있음.
- 지금처럼 챔피언/리포트 간 수치 갭이 보일 때, **정렬/스냅샷 타이밍** 이슈가 흔함.

**(b) 위험/부작용**
- 게이트가 너무 엄격하면 유효 피처까지 막아 성과가 떨어질 수 있음.
- 하지만 장기적으로는 필수(특히 자동 루프).

**(c) 최소 실험**
- EXP-C, EXP-A

**(d) PASS 조건**
- 누수 더미 테스트에서:
  - 테스트는 누수를 “검출”하고, 메인 파이프라인은 누수 패턴을 “차단”하여 FAIL 처리 가능
- 모든 피처가 `as-of` 규칙을 만족한다는 증거 로그(최대 타임스탬프 차이 0)

## TOP4) **노출/제약/퇴화 폴드 방지(신호가 ‘주문으로 변환’되는지 확인)**
**(a) 왜 필요한지**
- 노출 하단이 0.47까지 내려가면(현금/저노출) 성과가 둔화되기 쉬움.
- “degenerate_folds: []”라도, 실제론 특정 기간에 거래가 거의 0이면 **실질적 퇴화**임.

**(b) 위험/부작용**
- 제약 강화는 알파를 깎을 수 있음.
- 고정 유니버스는 분산을 줄이므로 종목 리스크가 커질 수 있음(그래서 8~14 + weight cap 필요).

**(c) 최소 실험**
- EXP-D, EXP-B

**(d) PASS 조건**
- 주간 기준:
  - 거래 발생률/리밸런스 건수 최소치 충족(“신호가 살아있음”)
  - exposure_min ≥ 0.55 유지(현금화로 정체되는 상태 방지)
  - 비용 포함 성과가 개선되거나, 최소한 비용-회전율 트레이드오프가 선명해짐

## TOP5) **레짐 미반영 점검(ETF는 관측만)**
**(a) 왜 필요한지**
- Tech/Healthcare도 시장 레짐(금리/변동성/리스크온오프)에 따라 추세·반전 특성이 크게 달라짐.
- “실험 바꿔도 성능이 안 움직임”은 레짐이 지배하는데 신호가 레짐을 못 가르는 경우가 많음.

**(b) 위험/부작용**
- 게이트가 거래를 과도하게 억제하면 수익 기회도 줄어듦.
- 레짐 규칙을 복잡하게 만들면 과최적화(그래서 단일 게이트만).

**(c) 최소 실험**
- EXP-E, EXP-A

**(d) PASS 조건**
- 게이트 on/off 비율이 20~80% 범위
- 레짐별 성과 차이가 통계적으로/방향성 있게 나타나면(예: on 구간 성과↑, off 구간 MDD↓) 다음 반복에서 정교화 가치 있음

## 3) 성능이 “안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐)

아래를 **위에서 아래 순서로** 자르면 된다(명령형 트리).

### A. Trigger(트리거) — “주문이 실제로 발생하는가?”
- `rebalance.jsonl`에서 **리밸런스 발생 횟수/사유(reason)**를 집계하라.
- “신호 발생” vs “제약/현금/레짐 게이트로 취소”를 분리하라.
- **관측치**: 거래 0에 수렴하면 성능은 당연히 안 움직인다(모델 문제가 아니라 실행 경로 문제).

### B. Apply(적용) — “신호가 포지션으로 변환되는가?”
- target_weight와 실제 주문(order_qty) 간 괴리를 기록하라(제약으로 깎인 비율).
- 포지션 상한/하한, turnover cap, 최소 주문단위 때문에 **항상 같은 포지션으로 수렴**하는지 확인하라.
- **관측치**: 실험 바꿔도 target이 비슷하면 “신호가 무의미” 또는 “피처가 동결” 가능성.

### C. Exposure(노출) — “노출이 바뀌는가?”
- exposure_min/max뿐 아니라 **기간별 시계열**로 저장하라.
- cash 비중, 종목 집중도(HHI), 섹터 편중을 기록하라(Tech/Healthcare 내에서도 편중 가능).
- **관측치**: 노출이 항상 0.6 근처 고정이면 알파 변화가 성과로 안 번질 수 있음.

### D. Cost(비용) — “비용이 성과를 눌러서 평평해졌는가?”
- fills 기준으로 `mid 대비 체결 불리함(bps)`를 시계열로 저장하라.
- turnover와 net 성과의 상관을 보라.
- **관측치**: 비용 포함/미포함 성과가 동일하면 “거래가 없다/로그가 가짜/비용이 0으로 계산” 중 하나다.

### E. Regime(레짐) — “레짐이 성과를 결정하는데 신호가 레짐 불가지?”
- 관측 ETF(예: QQQ, XLV, TLT)로 레짐 라벨을 만들고, OOS를 레짐별로 쪼개라.
- **관측치**: 레짐별 성과 분산이 큰데 전체 평균만 보면 ‘안 움직이는’ 것처럼 보일 수 있음.

## 48시간 자동 루프 운영 지시(명령형)
1. **오늘 바로 EXP-A를 먼저 통과**시켜라(로그 없으면 나머지 실험은 전부 무의미).
2. EXP-B→EXP-C→EXP-D→EXP-E 순서로 **하나씩만** 켜고(동시 변경 금지), 각 실험은 최소 1회 OOS 리포트를 남겨라.
3. 각 런 종료 시 **게이트 실패면 즉시 중단하고 다음 실험으로 넘어가지 말라**(자동 루프에서 가장 큰 운영 리스크는 “깨진 실험을 계속 누적”하는 것).
4. 최종적으로 “성능 무변화”가 나오면, 위 원인 분해 트리(A~E)를 로그로 자동 출력해 **어디서 평평해졌는지**를 강제 표기하라.

이 5개만 통과시키면, “성능이 안 움직임”이 **(1) 로그/운영 문제**, **(2) 누수/정렬 문제**, **(3) 거래/노출 문제**, **(4) 비용 문제**, **(5) 레짐 문제** 중 어디인지 48시간 안에 확정적으로 갈라낼 수 있다.
