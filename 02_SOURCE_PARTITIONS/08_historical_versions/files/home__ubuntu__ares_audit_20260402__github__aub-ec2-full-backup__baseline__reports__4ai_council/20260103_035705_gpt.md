## 24~48시간 TOP5 우선순위(코드/아키텍처/전략) — **명령형 체크리스트**

### 1) **리밸런스/체결 로그 파이프라인 복구(관측 불능부터 제거)**
- **왜 필요한지**
  - `aub_rebalance_pinpoint`가 `--base-log` 파일 미존재 + `rebalance.csv`/`jsonl` 파싱 실패로 “원인 추적”이 막힘.
  - 현재 `worst_mdd: None`, `lane_hash/run_hash: None` → 실험/챔피언 재현성과 리스크 지표 산출이 깨진 상태.
- **위험/부작용**
  - 로그/스키마 강제 시 과거 아티팩트 일부가 읽히지 않아 비교가 일시 중단될 수 있음.
  - 추가 I/O로 런타임/스토리지 비용 증가.
- **연결 최소 실험(공통 풀에서 선택)**  
  - **E1**(아래 “48시간 자동 루프 실험 1”)을 적용.
  - **E3**(비용/회전율)과 함께 적용해 “왜 OOS가 안 움직이는지”를 거래단에서 분해 가능하게 만들기.
- **PASS 조건**
  - 리밸런스 로그가 **항상 생성**되고(실패율 0), `pinpoint`가 **base/cand 둘 다** 읽어서 “변경된 주문/포지션/비용” diff를 출력.
  - 모든 런에서 `worst_mdd`가 숫자로 채워지고, `lane_hash/run_hash`가 고정 규칙으로 기록.

---

### 2) **누수/과최적화/degenerate folds 제거(평가 신뢰도 복구)**
- **왜 필요한지**
  - `degenerate_folds: [1,2,3,8]`는 CV가 사실상 무력화된 구간이 존재함을 의미(학습/평가 분할이 깨지거나 샘플 수가 0에 가까운 폴드).
  - “No-Delta Diagnoser”에서 실험 9개가 성능 변동이 미미 → 개선이 없는 게 아니라 **평가가 둔감/오염**됐을 가능성 우선 제거.
- **위험/부작용**
  - 누수 방지(embargo/purge) 적용 시 표본 수 감소로 성능 수치가 일시 하락 가능.
  - 지나친 제약으로 “좋아 보이던” 전략이 사라질 수 있으나, 그게 목적(가짜 성능 제거).
- **연결 최소 실험**
  - **E2**(아래 “48시간 자동 루프 실험 2”) 적용.
  - **E1**과 묶어 “폴드별 리밸런스/노출/비용”을 같이 저장.
- **PASS 조건**
  - degenerate fold가 **0개**.
  - 시드/분할 고정 시 OOS 변동이 작은 대신(재현성↑) 폴드별 샤프/수익 분포가 **정상적으로** 나오고, 누수 테스트가 **fail→pass**로 전환.

---

### 3) **비용/슬리피지/회전율을 성능에 즉시 반영(과대평가 차단)**
- **왜 필요한지**
  - 현재 리밸런스 로그도 불완전하여 비용이 “미반영/부분반영”일 확률이 큼.
  - Tech+Healthcare 8~14종목 운용은 리밸런스 빈도/회전율이 성과 대부분을 좌우 → 비용 미반영이면 OOS가 “안 움직이는 게 아니라” 실제로는 비용에 눌려있을 수 있음.
- **위험/부작용**
  - 비용 모델이 과도하면 전략이 불필요하게 보수화(알파를 비용으로 착각)될 수 있음.
  - 회전율 제한은 레짐 전환 대응을 늦출 수 있음.
- **연결 최소 실험**
  - **E3**(아래 “48시간 자동 루프 실험 3”) 적용.
  - **E1**로 체결/비용 breakdown을 반드시 남기기.
- **PASS 조건**
  - (백테스트 기준) 비용 전/후 성과 갭이 논리적으로 설명 가능(턴오버 높은 구간에서 비용 급증).
  - OOS에서 “수익은 비슷한데 샤프가 개선” 같은 허상이 아니라, **턴오버↓ + 비용↓ + 성과 유지/개선**이 관측됨.

---

### 4) **서바이버십/코퍼레이트 액션/유니버스 고정(데이터 오염 제거)**
- **왜 필요한지**
  - “US 주식 only + Tech/Healthcare + 8~14개”는 유니버스가 작아 **종목 교체/상폐/분할**의 영향이 매우 큼.
  - 서바이버십이 조금만 섞여도 OOS는 ‘안 움직임’처럼 보이거나, 반대로 특정 구간에서만 과도하게 좋아질 수 있음.
- **위험/부작용**
  - PIT(시점정합) 데이터 적용 시 과거 성과 하락 가능(정상).
  - 유니버스 고정은 기회 손실 가능(대신 운영 일관성↑).
- **연결 최소 실험**
  - **E4**(아래 “48시간 자동 루프 실험 4”) 적용.
  - **E2**와 결합해 “폴드별 종목 수/거래가능 일수”를 게이트로 사용.
- **PASS 조건**
  - 각 폴드/기간에서 실제로 거래 가능한 종목 수가 8~14를 안정적으로 만족(결측/상폐로 빠지면 즉시 대체 규칙 작동).
  - 분할/배당/병합 반영으로 가격 점프에 의한 가짜 신호가 사라짐(이상치 트레이드 감소).

---

### 5) **운영 리스크(노출/드로우다운/레짐) 게이트를 전략 위에 “얇게” 추가**
- **왜 필요한지**
  - `exposure_max: 0.8388`로 보아 상황에 따라 노출이 크게 흔들림. Tech+Healthcare 집중 포트는 레짐(금리/리스크오프)에 취약.
  - ETF는 매매 제외지만, **관측지표(예: XLK/XLV/SPY, IWM, VIX proxy)**로 레짐을 잡아 노출 게이트를 거는 건 운영 안정성에 직결.
- **위험/부작용**
  - 게이트가 잦으면 알파를 스스로 차단(언더인베스트)할 수 있음.
  - 레짐 지표가 후행이면 고점/저점에서 늦게 반응 가능.
- **연결 최소 실험**
  - **E5**(아래 “48시간 자동 루프 실험 5”) 적용.
  - **E3**(턴오버 캡)과 같이 적용해 “게이트로 리밸런스 폭주” 방지.
- **PASS 조건**
  - MDD/변동성 지표가 의미 있게 하락(운영 안정성↑)하면서 OOS mean이 과도하게 훼손되지 않음.
  - 레짐 오프 구간에서 불필요한 거래(턴오버)와 비용이 같이 감소.

---

## 48시간 자동 루프용 “실행 가능한” 실험/패치 (총 5개, 재사용 방식)

아래 5개만 **자동 루프(48h)**에서 굴리고, 위 TOP5 제안들은 이 5개를 조합/재사용해서 검증하도록 고정.

---

### 실험 1 (E1) — **리밸런스/로그 스키마 강제 + 재현성 태깅**
1) **실험 정의**
   - 모든 런에서 다음 산출물을 **반드시** 생성:
     - `rebalance.jsonl`(타임스탬프, 종목, 목표/현재 비중, 주문수량, 예상체결가, 체결가(가능 시), 슬리피지, 수수료, turnover)
     - `metrics.json`에 `worst_mdd`, `lane_hash`, `run_hash`, `data_hash`, `config_hash`
   - `aub_rebalance_pinpoint` 입력 경로를 “옵션”이 아니라 **표준 위치**로 통일.
2) **게이트**
   - 로그 파일 0바이트/파싱 실패 시 런 **즉시 FAIL** 처리(성능 비교에서 제외).
3) **기대 관측치**
   - pinpoint 리포트에서 base vs cand의 거래 차이를 “어느 날짜/어느 종목/어떤 주문” 수준으로 추적 가능.

---

### 실험 2 (E2) — **Purged/Embargoed TimeSeries CV + degenerate fold 차단**
1) **실험 정의**
   - 시계열 CV에 purge+embargo 적용(룩어헤드 방지).
   - 각 폴드에 최소 거래일/최소 종목수/최소 거래가능 바 수를 강제하고 미달 폴드는 생성 자체를 금지.
2) **게이트**
   - `degenerate_folds == 0`
   - 폴드별 유효 샘플 수/거래일 수가 임계치 미달이면 FAIL.
3) **기대 관측치**
   - OOS mean이 “좋아 보이게” 튀는 현상은 줄고, 대신 폴드별 분산이 정상화.
   - 누수 의심 실험들이 일괄적으로 성과 하락/무효화되면 원인이 누수였음이 강하게 시사됨.

---

### 실험 3 (E3) — **비용/슬리피지/턴오버를 목적함수에 직접 반영**
1) **실험 정의**
   - 거래 비용 구성(최소):
     - 고정 수수료(0으로 두지 말고, 최소단위라도 부여)
     - 스프레드 기반 슬리피지(유동성/변동성 기반 간단 모델)
     - 임팩트(턴오버에 비례하는 페널티, 과최적화 방지용)
   - 일/주 단위 turnover cap(하드캡 + 초과 시 페널티) 도입.
2) **게이트**
   - 평균 turnover가 기준치 대비 감소 또는 동일.
   - 비용 차감 후 성과지표가 **음수로 붕괴**하면 FAIL(비용에 취약한 구조).
3) **기대 관측치**
   - “알파”가 거래 빈도에 의존하는지(=비용 모델 적용 후 붕괴) 즉시 판별.
   - 개선이 있다면 대부분 “턴오버↓/비용↓/MDD↓” 형태로 관측.

---

### 실험 4 (E4) — **유니버스(US Tech+Healthcare 8~14) 시점정합 고정 + 서바이버십 차단**
1) **실험 정의**
   - 운용 유니버스를 “사전 정의된 8~14 종목” 또는 “PIT 규칙으로만 갱신되는 8~14 종목”으로 고정(룰 기반).
   - 코퍼레이트 액션(분할/병합/배당) 반영 확인용 sanity 체크 추가(가격 점프 탐지).
2) **게이트**
   - 각 리밸런스 시점에 거래 가능 종목 수가 8 미만이면 FAIL(대체 규칙 미작동).
   - 상폐/거래정지/결측 처리 로그가 남지 않으면 FAIL.
3) **기대 관측치**
   - 특정 구간에서만 성과가 급변하는 현상이 줄고, 실현 가능한 곡선으로 수렴.

---

### 실험 5 (E5) — **레짐 관측(ETF는 지표만) + 노출/리스크 게이트**
1) **실험 정의**
   - 관측지표: SPY/XLK/XLV(매매 금지, 피처로만 사용), 금리 민감도 proxy(예: 장단기 금리 데이터가 있다면), 변동성 proxy.
   - 게이트 예:
     - 레짐 “risk-off”이면 총 노출 상한을 0.3~0.5로 clamp
     - 포트 변동성/드로우다운이 임계 초과 시 리밸런스 강도 축소(리스크 패리티가 아니라 **단순 감쇠**)
2) **게이트**
   - 언더인베스트 비율이 과도(예: 30% 이상 상시 현금화)면 FAIL.
   - MDD/변동성이 개선되지 않으면 FAIL.
3) **기대 관측치**
   - 급락/고변동 구간에서 손실 꼬리와 거래 폭주가 줄어듦.
   - 성과가 안 오르면 “게이트가 알파를 자르는지”를 로그로 확인 가능(차단된 신호/주문 카운트).

---

## 성능이 “안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐)

아래 순서대로 **위에서 아래로** 절단 진단(한 번에 한 축씩 고정/해제)하라.

1) **Trigger(신호 생성)**
   - 신호가 실제로 변하는지 확인: 일별 신호 분산/상위-하위 스프레드가 0에 수렴하면 “전략이 죽은 것”이 아니라 입력/정규화/스케일링 버그일 수 있음.
   - 누수 탐지: 미래값/리밸런스 시점 이후 가격을 참조하는 피처가 있는지(특히 리턴/랭킹 계산에서 shift 실수).

2) **Apply(포트 구성/제약 적용)**
   - 신호는 있는데 주문이 없으면 제약이 막는 것:
     - 포지션 상한/하한, 최소 주문단위, 리밸런스 임계치(threshold), clamp 로직 확인.
   - “항상 비슷한 포트”면: 랭킹 타이 브레이커/정렬 안정성/시드 고정으로 인한 경직 가능.

3) **Exposure(노출/집중)**
   - 총 노출이 들쑥날쑥하면 성과가 모델이 아니라 노출 변화에 의해 결정됨.
   - 섹터(Tech/Healthcare) 내 상관이 높아 “종목 수 8~14”라도 실질 베팅은 1~2개 팩터일 수 있음 → 팩터 노출(시장/성장/금리 민감) 모니터링을 지표로만 추가.

4) **Cost(비용/슬리피지/회전율)**
   - 비용 전/후 성과 차이를 날짜별로 분해:
     - “수익이 나는 날보다 거래비용이 큰 날”이 반복되면 구조적 문제(과잉 리밸런스).
   - 비용이 0 또는 비정상적으로 작게 찍히면(로그 부재 포함) 지금 보는 OOS는 신뢰 불가.

5) **Regime(레짐 의존)**
   - 성능이 특정 레짐에서만 나오면(예: risk-on에서만) “전략 개선”이 아니라 “노출/레짐 편승”일 수 있음.
   - 레짐별로 분해한 OOS(상승장/하락장/고변동/저변동)에서:
     - 전 레짐에서 비슷하게 나쁘면 신호 문제
     - 한 레짐에서만 나쁘면 게이트/노출 조정으로 해결 가능

---

## 24~48시간 실행 순서(고정)
1) **E1 → E2를 먼저 머지/적용**하라(관측 가능 + 평가 신뢰도 확보).
2) 그 다음 **E3**로 비용/턴오버를 “성과의 일부”로 만들어라.
3) 동시에 **E4**로 유니버스/서바이버십을 고정해 실험 변수를 줄여라.
4) 마지막으로 **E5**를 얇게 얹어 운영 리스크를 줄이고 레짐 민감도를 계측하라.
5) 모든 런에서 “폴드별: 신호분산/노출/턴오버/비용/MDD”를 동일 포맷으로 저장하라(비교 가능성이 최우선).
