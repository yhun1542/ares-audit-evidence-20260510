아래는 **다음 24~48시간 우선순위 TOP5**를 “명령형 체크리스트”로 정리한 것이고, **실험은 총 4개(E1~E4)로 고정**해 48시간 자동 루프에서 반복 가능하게 설계했습니다. (각 제안은 2~3개 실험을 “참조”하지만, **고유 실험 수는 4개로 제한**)

- [ ] **로그를 ‘원인 분해 가능’ 수준으로 확장**: 신호/체결/비용/노출/레짐별 PnL 분해를 한 파일에 남기기(아래 C 참고)

# 1) TOP5 우선순위 제안(코드/아키텍처/전략)

## P1) 누수(Leakage)·타임스탬프·룩어헤드 방지 “가드레일” 추가 (최우선)
**(a) 왜 필요한지**
- 현 챔피언이 lockbox 성능이 강한 편인데(평균 4.01), **누수는 lockbox에서도 ‘꾸준히 좋아 보이는’ 착시**를 만들 수 있음.
- 특히 “지표 계산 시점(as-of)”과 “체결 시점(다음 캔들)”이 조금이라도 섞이면, 성능이 **갑자기 안 움직이거나**(새 후보들 전부 비슷) **특정 후보만 비정상적으로 우세**해지는 형태가 자주 발생.

**(b) 위험/부작용**
- 성능 단기 하락 가능(진짜 알파가 아니라 누수였으면 급락).
- 데이터 처리 비용/시간 증가(검증 단계가 늘어남).

**(c) 최소 실험(참조)**
- E1(As-of/체결 정렬 강제) + E4(운영 재현성 체크)

**(d) PASS 조건**
- E1 게이트 통과(룩어헤드 의심 테스트/시프트 테스트에서 성능 붕괴가 “일관되게” 나타나지 않을 것)
- lockbox에서 **분포가 비정상적으로 뾰족해지거나** 특정 폴드만 급등/급락하는 패턴 감소(폴드 간 분산↓)

---

## P2) 비용(슬리피지/수수료/스프레드) “상한/하한 + 회전율 제약”을 전략 레벨에서 강제
**(a) 왜 필요한지**
- 후보 간 성능이 잘 안 벌어질 때, 실제로는 **비용이 실현 알파를 다 깎는** 경우가 많음.
- Tech/Healthcare 8~14개 종목은 유동성은 좋은 편이지만, **리밸런싱 빈도/회전율이 조금만 과해도** 비용이 알파를 잠식.

**(b) 위험/부작용**
- 거래 횟수 감소로 기회 손실(특히 단기 모멘텀형이면).
- 지나친 비용 보수화로 전략이 “움직이지 않는” 상태가 될 수 있음.

**(c) 최소 실험(참조)**
- E2(비용모델+turnover gate) + E3(노출/리밸런싱 규칙 패치)

**(d) PASS 조건**
- 비용 반영 후 lockbox 평균/최저치가 **동시에 악화되지 않을 것**(특히 min 방어)
- 연환산 회전율/거래횟수/평균 보유기간이 “상식 범위”로 내려가고, MDD가 악화되지 않을 것

## P3) 서바이버십/상장폐지/분할·합병/심볼 변경 처리 “데이터 무결성” 점검
**(a) 왜 필요한지**
- 미국주식 백테스트의 고질적 함정: **현재 구성 종목만으로 과거를 돌리는 서바이버십 바이어스**.
- Tech/Healthcare는 심볼 변경/스핀오프/인수합병이 잦아 **수익률 연속성**이 깨지기 쉬움(조정주가/코퍼레이트액션 처리 오류).

**(b) 위험/부작용**
- 데이터 정제 이후 성능 하락 가능(정상).
- 구현 난이도 대비 48시간 내 완전 해결이 어려울 수 있어, **감지/차단(guard)**부터 우선.

**(c) 최소 실험(참조)**
- E4(데이터 재현성+코퍼레이트액션 감지) + E1(시점 정렬)

**(d) PASS 조건**
- 동일 기간/동일 시드에서 결과가 완전 재현되고(결정론), 심볼/조정주가 이슈로 인한 “하루 급등락” 이상치가 로그에서 자동 플래그 처리될 것
- 특정 종목 1~2개가 PnL 대부분을 설명하는 “서바이버십형” 패턴 감소

## P4) 과최적화(Overfitting) 방지: “모델 복잡도↓ + 선택 편향↓(selection)”로 실험 설계 재정렬
**(a) 왜 필요한지**
- 현 상태에서 후보가 tuning과 lockbox 관계가 불안정(최근 PASS 후보는 lockbox min은 좋지만 MDD가 악화).  
- “선택 기준”이 미세하게 흔들리면 **서바이버십 + 선택편향**이 합쳐져 챔피언 교체가 의미 없어짐.

**(b) 위험/부작용**
- 탐색 속도 감소(덜 화려한 모델만 남김).
- 단기적으로 “개선이 안 보이는” 기간이 늘 수 있음(하지만 이것이 정상일 때가 많음).

**(c) 최소 실험(참조)**
- E3(단순화된 리밸/시그널 적용 규칙) + E4(실험 선택/레지스트리 고정)

**(d) PASS 조건**
- tuning 성능은 낮아져도 좋으니, lockbox의 **분산 감소 + MDD 안정화(worst_mdd 악화 금지)**가 확인될 것
- “한 번 이기고 다음에 크게 지는” 후보 빈도 감소

## P5) 운영 리스크: 48시간 자동 루프 “실패 안전장치 + 드리프트 감시” 추가
**(a) 왜 필요한지**
- 자동 루프는 **데이터 업데이트/라이브러리 변경/랜덤 시드/캐시 오염**으로 성능이 미묘하게 흔들릴 수 있음.
- 운영상 실패는 “전략 성능이 안 움직이는” 것처럼 보이게 만들기도 함(실은 파이프라인이 바뀜).

**(b) 위험/부작용**
- 초기에는 로깅/검증으로 실행시간 증가.
- 엄격한 게이트로 후보 생성이 줄 수 있음.

**(c) 최소 실험(참조)**
- E4(결정론·캐시·데이터 스냅샷 게이트) + E2(비용/체결 로직 고정)

**(d) PASS 조건**
- 동일 입력 스냅샷에서 결과 해시가 동일(재현성 100%)
- 데이터/코드 변경 시 “원인(커밋/데이터버전/파라미터)”이 자동으로 기록되어 성능 변화가 설명 가능

# 2) 48시간 자동 루프용 “실험 4개” 정의 (1) 실험 정의 (2) 게이트 (3) 기대 관측치

## E1) As-of/체결 정렬 + 룩어헤드 감지 실험
**(1) 실험 정의**
- 모든 피처/지표를 **t 시점 종가(또는 확정 가능한 시점)** 기준으로만 계산 → **포지션 적용은 t+1(다음 바 오픈/다음 종가 중 하나로 고정)**  
- “시프트 테스트”: 지표를 +1 bar 밀어도 성능이 비정상 유지되는지(의심), -1 bar 당기면 과도하게 좋아지는지(누수).

**(2) 게이트**
- 같은 기간에서 `shift(+1)`에서 성능이 챔피언 대비 **비정상적으로 유지되면 FAIL(누수 의심)**  
- `shift(-1)`에서 성능이 과도하게 상승하면 FAIL(룩어헤드 가능성)

**(3) 기대 관측치**
- 정상 전략이면: `shift(+1)` 성능 유의미 하락, `shift(-1)` 성능 악화 또는 비정상 급등이 없어야 함.
- 폴드별 성능 분산이 감소(특정 폴드에서만 신기하게 이기는 현상↓)

---

## E2) 비용모델/회전율(turnover) 게이트 실험
**(1) 실험 정의**
- 체결 비용을 “고정 수수료 + 스프레드/슬리피지(간단 선형)”로 최소 반영하고,
- 리밸런싱 결과에 대해 **turnover 상한**(예: 일/주 단위)을 두는 두 버전 비교:
  - vA: 비용만 추가
  - vB: 비용 + turnover cap(초과분은 포지션 변경량 축소/이월)

**(2) 게이트**
- 비용 반영 후 lockbox `min`이 0 아래로 내려가면 FAIL(비용에 취약)
- turnover cap 적용 시 거래량이 줄면서도 MDD가 악화되면 FAIL(리스크 억제 실패)

**(3) 기대 관측치**
- gross 성능은 약간 내려가도, net 성능의 **최저치(min) 개선/안정화**가 나타나야 정상.
- 후보 간 격차가 “현실적인 비용” 아래에서 다시 벌어져야 함(비용이 신호를 죽이고 있었는지 확인)

---

## E3) 노출(Exposure)·리밸런싱 룰 단순화 패치 실험 (Tech+Healthcare 8~14 강제 포함)
**(1) 실험 정의**
- 거래 유니버스: Tech/Healthcare에서 8~14개로 고정(동일 리스트 또는 룰 기반 선정이더라도 **선정 기준을 고정/로그화**)
- 포지션 상한: 단일 종목 비중 cap, 섹터 편중 cap(Tech/HC 내에서도 하위산업 편중 방지)
- 레짐 관측지표(ETF는 매매 금지): QQQ/XLV/SPY, VIX(또는 VIX proxy)로 “리스크 온/오프”를 관측만 하고, **리밸런싱 강도(변경폭)만 조절**

**(2) 게이트**
- 종목 수가 8~14에서 벗어나면 FAIL(운영 규격 위반)
- 특정 1~2개 종목 기여도가 과도(예: PnL 70% 이상)하면 FAIL(집중/서바이버십 의심)

**(3) 기대 관측치**
- MDD(worst_mdd) 완화 또는 최소한 악화 방지
- 성능이 “덜 화려해도 더 꾸준한” 형태(폴드 간 분산↓, min 방어↑)

---

## E4) 운영·재현성(결정론) + 데이터 스냅샷/코퍼레이트액션 감지 실험
**(1) 실험 정의**
- 실험 실행 시마다 아래를 아티팩트로 고정 저장:
  - 데이터 스냅샷 버전/해시, 심볼 매핑 테이블, 조정주가 사용 여부
  - 코드 커밋 해시, 파라미터 해시, 랜덤 시드
- 코퍼레이트액션/이상치(스플릿/병합/심볼 변경/비정상 갭) 감지 시 로그에 플래그.

**(2) 게이트**
- 동일 스냅샷/동일 시드에서 결과 해시 불일치하면 FAIL
- 조정주가/심볼 변경 이벤트 발생 시 “무플래그”면 FAIL

**(3) 기대 관측치**
- “성능이 안 움직인다/갑자기 변한다”가 발생해도, 원인이 데이터/코드/파라미터 중 무엇인지 즉시 분리 가능
- 백테스트 PnL의 하루 급등락이 이벤트 플래그와 동행(설명 가능)

- [ ] 챔피언 교체는 “PASS 게이트 전부 통과 + worst_mdd 악화 금지”를 만족할 때만 수행

# 4) 성능이 “안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래를 **한 번의 백테스트에서 동시에** 뽑아야 “정지 상태”를 빠르게 분해할 수 있습니다.

## A. Trigger(신호) 문제
- [ ] **신호 분포 드리프트**: 신호가 극단값/0 근처로 몰리는지(표준편차, 상위/하위 분위수 변화)
- [ ] **hit rate vs payoff 분해**: 승률은 유지되는데 기대손익이 줄었는지(평균 이익/평균 손실)
- [ ] **shift(+1/-1) 민감도**: E1 결과로 누수/시점오류 여부 즉시 판정

## B. Application(적용/체결) 문제
- [ ] 체결 가격 일관성: 신호 t, 체결 t+1 오픈(또는 종가) 고정 여부
- [ ] 리밸런싱이 “생각보다 안 일어남”: turnover cap/최소 주문단위/라운딩으로 포지션 변화가 0이 되는 케이스 로그화

## C. Exposure(노출) 문제
- [ ] 베타/상관 노출: 포트폴리오 수익률을 QQQ/XLV/SPY에 회귀해서 beta 추적  
  - 알파가 아니라 **그냥 QQQ 베타**면 후보 간 차이가 안 벌어짐
- [ ] 단일 종목/하위산업 집중: 상위 기여 종목 비중/기여도 상시 출력

## D. Cost(비용) 문제
- [ ] gross PnL vs cost vs net PnL을 분해(일자별 누적)  
  - “gross는 살아있는데 net이 죽음”이면 비용/회전율이 원인
- [ ] 거래당 기대값: 평균 거래 PnL이 스프레드/슬리피지보다 큰지

## E. Regime(레짐) 문제
- [ ] 레짐 버킷 성능: (리스크온/오프)로 나눠 수익률·MDD를 비교  
  - 예: VIX 상위 분위수 기간에만 망가지면 “리스크 축소/리밸 강도 감소”로 해결 가능
- [ ] 레짐별 turnover 변화: 변동성 구간에서 리밸이 과해져 비용 폭증하는지 확인

---

## 즉시 붙일 “PASS 공통 기준”(권장)
- [ ] **누수 게이트(E1) 통과**가 최상위(통과 못 하면 성능 개선은 전부 무의미)
- [ ] **비용 반영 후 lockbox min 방어(E2)** (min이 무너지면 운영 불가)
- [ ] **worst_mdd 악화 금지**(현 챔피언 worst_mdd ≈ -0.0815 대비 악화 시 승격 보류)
- [ ] **재현성 100%(E4)** (같은 입력에서 결과가 달라지면 실험 자체가 무효)

--- 

원하면, 위 E1~E4를 현재 파이프라인(`aub_autopilot.py`, `system_autopilot.py`)에 끼워 넣기 위한 **모듈 단위 패치 포인트(어느 단계에서 gate를 FAIL 처리할지)**만 추가로 “명령형 체크리스트”로 더 좁혀서 제시할 수 있습니다.
