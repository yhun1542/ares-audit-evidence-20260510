아래는 **24~48시간 내 우선순위 TOP5(코드/아키텍처/전략)**를 “명령형 체크리스트”로 정리한 것입니다.  
단, **실행 가능한 patch/실험은 총 5개(E1~E5)로 제한**하고, 각 우선순위는 **E1~E5 중 2~3개를 재사용**하도록 구성합니다(케이스 폭발 방지).  
(미국주식 only, Tech+Healthcare 중심, 8~14 종목, ETF는 관측 지표만)

---

## TOP1) 누수(Leakage) / 시점정합성(Time alignment) 1차 봉합
### (a) 왜 필요한지
- 지금 수치(Champion vs Candidate)가 **락박스 평균이 동일**하게 보이는 구간이 있어(특히 lockbox_mean/min가 그대로) **데이터/평가 파이프라인이 “변화에 둔감”하거나 누수/캐시/스냅샷 문제**일 가능성을 최우선 제거해야 함.
- 실전 운영에서 가장 치명적인 리스크는 “좋아 보이는데 실거래에서 사라지는 성능” → 거의 항상 **시점/누수/가격 이용 가능성**에서 발생.

### (b) 위험/부작용
- 누수 제거 후 단기적으로 성능 하락 가능(정상).
- 학습 데이터 유효 샘플 감소로 변동성 증가.

### (c) 최소 실험(재사용) 2~3개
- **E1(누수/시점정합 리그레션 테스트 추가)**  
- **E2(거래비용/체결 지연을 평가에 강제 반영)**  
- **E5(재현성/캐시 무효화/아티팩트 핀ning으로 “락박스 동일” 원인 제거)**  

### (d) PASS 조건(게이트)
- (정합성) **“의도적으로 1~2일 시프트”를 주면 성능이 즉시 붕괴**해야 함(누수 없다는 반증).  
- (민감도) feature/비용/지연 설정을 바꾸면 lockbox 지표가 **유의미하게 변동**해야 함(캐시/스냅샷 고착 방지).  
- (성능) 누수 제거 후에도 **worst_mdd가 -0.112보다 악화 폭이 1%p 이내**, lockbox_min이 **1.3469 대비 하방 급락(예: -5% 이상) 없을 것**.

---

## TOP2) 과최적화(Overfitting) 억제: “튜닝↑, 락박스→” 패턴 차단
### (a) 왜 필요한지
- tuning_mean이 흔들리는데 lockbox가 정체되면, 보통 **튜닝 공간에서만 이득**이거나 **레짐 고정/편향**일 가능성이 큼.
- 현재 챔피언은 MDD가 이미 준수(-11%대) → 다음 개선은 보통 “리스크/노출 정렬”에서 나옴(순수 alpha 추가보다).

### (b) 위험/부작용
- 규제(정규화/단순화)로 단기 성능이 내려갈 수 있음.
- 신호가 약해지면 매매 빈도가 줄며 샤프가 오히려 감소할 수 있음.

### (c) 최소 실험(재사용) 2~3개
- **E3(레짐/노출 게이트: Tech/Healthcare 내부 로테이션 + 리스크 타깃)**  
- **E4(포트폴리오 제약 정리: 8~14종목, 섹터 밸런스, 포지션 상한/하한)**  
- **E1(누수/정합 테스트로 튜닝 착시 제거)**  

### (d) PASS 조건(게이트)
- 튜닝 대비 락박스 갭 축소:  
  - `lockbox_mean / tuning_mean` 비율이 **기존 대비 개선**(튜닝만 먹는 모델 차단)
- `worst_mdd`는 **-0.1118 대비 +0.5%p 이상 악화 금지**(즉, -0.117 이상이면 FAIL로 단순화)
- **턴오버/거래비용 반영 후에도** lockbox_mean이 챔피언 대비 **동급 이상**(동급= ±0.01 이내) 유지

---

## TOP3) 서바이버십/코퍼레이트액션/델리스팅 처리(현실 데이터) 점검
### (a) 왜 필요한지
- US 개별주식은 split/dividend/merger/delist 영향이 큼.  
- Tech+Healthcare에서도 바이오(Healthcare) 쪽은 상폐/갭리스크가 성능 착시를 만들 수 있음.
- “8~14종목 집중”은 서바이버십 편향에 특히 취약.

### (b) 위험/부작용
- 데이터 소스/정제 비용 증가, 백테스트 표본 감소.
- 델리스팅 리턴을 반영하면 성능이 크게 떨어질 수 있음(정상).

### (c) 최소 실험(재사용) 2~3개
- **E1(시점정합/데이터 이용가능성 테스트에 corporate action 체크 포함)**  
- **E2(비용+갭/슬리피지 모델을 강화해 델리스팅/급락 근사)**  

### (d) PASS 조건(게이트)
- split/dividend 조정 방식 변경(Adj vs Raw) 시 **성능이 “좋게만” 움직이지 말 것**(특정 처리에서만 급상승하면 의심).
- 델리스팅/거래정지에 준하는 “가격 공백 시나리오” 주입 시에도 `worst_mdd`가 **-13% 이내** 유지(집중포트의 현실성 최소선).

---

## TOP4) 비용 미반영/체결 가정(운영 현실) 강제: “돈 되는지” 확인
### (a) 왜 필요한지
- 8~14 종목 집중 포트는 회전이 늘면 비용이 즉시 성과를 잠식.
- 락박스 성능이 정체일 때, 실제로는 **비용/슬리피지 모델이 단순**해서 차이가 안 보이는 경우가 흔함(지표 둔감).

### (b) 위험/부작용
- 현실 비용을 넣으면 대부분 성능이 하락(정상).
- 체결 지연/유동성 필터로 거래기회가 줄어들 수 있음.

### (c) 최소 실험(재사용) 2~3개
- **E2(비용/슬리피지/지연을 백테스트 스코어에 강제 반영)**  
- **E4(포트 제약으로 과도한 회전/편중 차단)**  

### (d) PASS 조건(게이트)
- “비용 ON”에서 lockbox_mean이 챔피언(비용 ON 기준) 대비 **-0.02 이내** 또는 개선.
- 평균 턴오버(일/주 단위) 상한 설정 후에도 성능이 유지될 것(턴오버 상한 내에서만 PASS).

---

## TOP5) 운영 리스크(재현성/캐시/자동루프 안전장치) 정리
### (a) 왜 필요한지
- 지금 출력에서 **락박스가 후보/챔피언 간 동일** → 운영상 “캐시 재사용/데이터 스냅샷 고정/seed 미고정/아티팩트 섞임” 가능성이 큼.
- 48시간 자동 루프는 **조용히 잘못된 결과를 내도 계속 굴러가는 형태**가 가장 위험.

### (b) 위험/부작용
- 캐시 무효화로 런타임 증가.
- 로그/아티팩트 저장으로 디스크/비용 증가.

### (c) 최소 실험(재사용) 2~3개
- **E5(재현성/아티팩트/캐시 키 분리 + 락박스 고정 검증)**  
- **E1(누수/정합 테스트를 CI 게이트로 승격)**  

### (d) PASS 조건(게이트)
- 동일 커밋/동일 시드에서 지표가 허용오차 내 재현(예: lockbox_mean ±0.005).
- 커밋 해시/데이터 스냅샷 해시/설정 해시가 리포트에 찍히고, 서로 다르면 결과도 달라져야 함(캐시 키 정상).

# 실행 가능한 Patch/실험 5개 (E1~E5): 48시간 자동 루프 형태
각 실험은 **(1) 실험 정의 → (2) 게이트 → (3) 기대 관측치**로 고정.

---

## E1) Leakage/시점정합 “리그레션 테스트 + 실패 주입(shift)” 패치
1) **실험 정의**
- 의사결정 시점 기준으로 feature/label/price의 이용가능성 체크를 자동화:
  - 주문 생성 시점 T에 대해 **T 종가/체결가를 feature로 쓰지 못하게** 강제(예: next-open 체결이면 T close 금지)
  - 라벨(미래수익) 생성 파이프라인에 **index alignment assert** 추가
- “실패 주입” 2종:
  - feature를 **+1일 미래로 시프트**한 버전
  - label을 **-1일 과거로 시프트**한 버전

2) **게이트**
- 실패 주입 버전의 tuning/lockbox가 **즉시 붕괴**(예: lockbox_mean 30% 이상 하락 또는 샤프 0 근처)하지 않으면 → 누수/정렬 문제로 FAIL.
- 정상 버전은 붕괴하지 않되, 챔피언 대비 `worst_mdd` **-0.13 이내** 유지.

3) **기대 관측치**
- “미래 시프트”는 성능이 비정상적으로 높아지는 게 아니라, 오히려 파이프라인이 차단되어 성능이 무너지는 형태가 정상(누수 방지).
- 정상/실패주입 간 지표 격차가 커져야 함(테스트가 민감하게 작동).

---

## E2) 비용/슬리피지/체결지연을 “스코어 함수”에 강제 반영
1) **실험 정의**
- 백테스트 체결 가정 고정:
  - 신호 생성: T close 이후
  - 체결: **T+1 open** (또는 T+1 VWAP 근사 중 하나로 통일)
- 비용 모델 최소 세트:
  - 고정 수수료(0에 가까워도 됨) + **슬리피지 bps(예: 5~20bps) 시나리오 2단**
  - 갭/급락(Healthcare 바이오 리스크) 완충: **하방 슬리피지 비대칭** 옵션 1개

2) **게이트**
- 비용 시나리오(낮음/높음)에서 전략 순위가 완전히 뒤집히면 → 비용 민감 전략(운영 취약)으로 FAIL.
- “높은 비용”에서도 lockbox_min이 **1.3469 대비 급락하지 않을 것**(예: -0.05 이상 악화 시 FAIL로 단순화 가능).

3) **기대 관측치**
- 평균 성과는 내려가되, **후보 간 상대순위**는 안정적으로 유지되는 게 정상(견고성).

---

## E3) 레짐/노출 게이트: Tech/Healthcare 내부 로테이션 + 리스크 타깃
1) **실험 정의**
- ETF는 매매 금지, **관측 지표로만 사용**:
  - Tech 레짐: XLK(또는 QQQ) 모멘텀/변동성
  - Healthcare 레짐: XLV(또는 IHI/XBI 중 하나) 모멘텀/리스크
- 레짐 게이트 규칙(단순 2상태만):
  - Risk-on: Tech 비중 상향 / Risk-off: Healthcare 비중 상향
- 포트 변동성 타깃(간단): 최근 N일 realized vol로 **총 노출 스케일링**

2) **게이트**
- 챔피언 대비 `worst_mdd` **개선 또는 동일**, 최소한 **-0.1118 대비 악화 +0.5%p 이내**.
- “레짐 전환 구간”에서 턴오버 폭증(기존 대비 2배 등)하면 FAIL(비용/운영 리스크).

3) **기대 관측치**
- 평균수익이 크게 안 오르더라도, **tail 구간 MDD/lockbox_min이 개선**되는 방향이 정상.

---

## E4) 포트폴리오 제약 정리: 8~14종목 고정 + 섹터 밸런스 + 편중 상한
1) **실험 정의**
- 유니버스(미국주식)에서 **Tech+Healthcare만** 사용(섹터 분류는 GICS/유사 기준).
- 매 리밸런스마다:
  - 보유 종목 수: **8~14 강제**
  - 섹터 최소/최대: 예) Tech 30~70%, Healthcare 30~70%
  - 단일 종목 비중 상한: 예) 15~20%
- “선정 신호”는 기존 모델/스코어를 그대로 쓰되, **최종 포트 구성만 제약으로 투영**

2) **게이트**
- 제약 추가 후 `fold14_mdd`가 **-0.0997 대비 -1.5%p 이상 악화 금지**(예: -0.115 이하로 악화하면 FAIL).
- 평균 보유 종목 수가 8~14를 벗어나면 FAIL(운영 일관성).

3) **기대 관측치**
- 평균 성능이 소폭 하락해도, **lockbox_min / worst_mdd가 안정화**되는 방향이 정상(집중 리스크 완화).

---

## E5) 자동루프 운영 안전장치: 재현성/캐시 키/락박스 스냅샷 핀ning
1) **실험 정의**
- 결과 산출의 3종 해시를 리포트에 강제 기록:
  - `code_commit_hash`
  - `data_snapshot_hash`(가격/펀더멘털/분류 데이터 버전)
  - `config_hash`(yaml/json 전체)
- 캐시 키를 위 3종 해시로 분리(하나라도 달라지면 재계산)
- 동일 조건 2회 실행 시 결과 재현 테스트를 nightly에 포함

2) **게이트**
- 동일 해시 조건에서 lockbox_mean이 **±0.005** 이상 흔들리면 FAIL(비결정성).
- 서로 다른 config_hash인데 lockbox가 완전히 동일(허용오차 내)하면 FAIL(캐시 오염/미적용).

3) **기대 관측치**
- “락박스 동일” 현상이 사라지고, 작은 변경에도 지표가 합리적으로 반응(민감도 회복).

---

# 성능이 안 움직일 때: 원인 분해(트리거/적용/노출/비용/레짐) 체크 트리
아래 순서대로 “상위에서 하위로” 절단 진단(질문 없이 실행 항목만).

## 0) 지표 둔감/고착 여부(가장 먼저)
- [ ] 후보들 간 lockbox가 계속 동일하면 **E5부터 실행**(캐시/스냅샷/설정 미적용 차단)
- [ ] 튜닝만 변하고 락박스가 고정이면 **락박스 데이터 스냅샷이 고정**인지 확인(해시 로그 필수)

## 1) Trigger(신호가 실제로 변하나?)
- [ ] 리밸런스 날짜별로 상위 스코어 종목 리스트가 바뀌는지 로그로 저장
- [ ] 스코어 분포(평균/표준편차/상하위 분위)가 시간에 따라 움직이는지 확인  
  → 안 움직이면: feature 상수화/정규화 오류/결측 처리로 정보 소실 의심(E1)

## 2) Apply(신호가 포지션으로 적용되나?)
- [ ] 스코어→목표비중→실현비중(제약/라운딩/현금) 3단계를 각각 저장
- [ ] 제약 때문에 늘 같은 종목/비중으로 “투영”되는지 확인  
  → 같으면: 제약이 너무 강하거나, 스코어 차이가 너무 작음(E4)

## 3) Exposure(실제 노출이 성과를 결정하나?)
- [ ] 섹터/팩터(베타, 사이즈, 모멘텀, 퀄리티) 노출을 주 단위로 계산
- [ ] 성과가 대부분 QQQ(관측) 방향 베타로 설명되면: **순수 알파 부족**  
  → 레짐 게이트/변동성 타깃(E3)로 tail 개선부터 노림

## 4) Cost(비용이 알파를 잠식하나?)
- [ ] 비용 0 / 낮음 / 높음 3단에서 성과 기울기 확인
- [ ] 턴오버 상한(예: 주간 50~100%)을 걸었을 때 성과가 급락하면: **비용 민감형**  
  → 체결지연/슬리피지 반영(E2) + 제약(E4)

## 5) Regime(어떤 장에서만 되나?)
- [ ] XLK/XLV(관측)로 2레짐(Tech 우세 vs Healthcare 우세) 구간을 나누고, 구간별 성과를 분해
- [ ] 한 레짐에서만 성과가 나면: **레짐 적응 로직 부재**  
  → E3로 단순 2상태 게이트부터

## 24~48시간 실행 순서(권장)
- [ ] **E5 먼저**(락박스 동일/캐시 고착 제거)  
- [ ] **E1 다음**(누수/정합 리그레션 + 실패주입)  
- [ ] **E2**(비용/지연 강제)  
- [ ] **E4**(8~14 + 섹터밸런스 + 편중상한)  
- [ ] **E3**(ETF 관측 기반 레짐 게이트 + vol 타깃)

이 순서대로면 “지표가 왜 안 움직이는지(운영/평가 고착)”와 “움직여도 왜 실전에서 죽는지(누수/비용/레짐)”를 48시간 루프에서 가장 빨리 분리해낼 수 있습니다.
