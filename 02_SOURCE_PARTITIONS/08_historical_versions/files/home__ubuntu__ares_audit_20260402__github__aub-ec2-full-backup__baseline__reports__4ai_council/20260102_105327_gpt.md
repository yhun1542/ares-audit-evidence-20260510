## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — 명령형 체크리스트

### 1) **누수/서바이버십/코퍼레이트 액션(분할·배당) 우선 감사**
- [ ] **룩어헤드 차단**: feature/label 생성 시점이 “t 시점에 관측 가능한 값만” 쓰는지 전수 점검(특히 리밸런스 직전 종가/체결가 참조).
- [ ] **서바이버십 제거**: 현재 생존 종목만으로 과거를 구성하지 않도록(상장폐지/합병/티커변경 포함) 데이터 소스/로더 확인.
- [ ] **조정가격 일관성**: split/dividend 조정 가격 사용 시, 수익률/거래가격/체결가 산출이 서로 다른 기준 섞이지 않게 단일화.
- [ ] **단위 테스트 추가**: “t 이후 정보가 feature에 들어가면 실패”하는 테스트를 CI에 강제.

**왜**: 챔피언(높은 평균) 대비 후보(낮은 MDD)가 나온 상황은, 모델이 “수익을 크게 만들지만 취약한 구간” 또는 “데이터/비용/액션 혼선”일 때 자주 발생. 누수/서바이버십이 있으면 튜닝에서는 좋아 보이나 락박스/실거래에서 무너짐.

---

### 2) **비용/슬리피지/턴오버를 목표함수에 강제 반영**
- [ ] **거래비용 모델을 PnL에 직접 차감**(고정 수수료 + 스프레드/임팩트 근사).
- [ ] **턴오버 패널티**를 학습/선택 기준에 포함(“락박스 평균↑”만 추구 금지).
- [ ] **리밸런스 빈도와 비용의 상호작용**(48시간 루프와 실제 체결 가정)을 동일 조건으로 고정.

**왜**: 미국 대형 Tech/Healthcare라도, 전략이 과매매면 평균이 유지돼도 “락박스 min”이 꺾이고(현재 후보 lockbox_min이 낮음), 운영 시 손익이 사라짐.

---

### 3) **운영 리스크(주문/체결/리밸런스) 방지용 ‘리스크 오버레이’ 최소 삽입**
- [ ] **변동성 타게팅(Vol targeting)** 으로 레버/노출 자동 스케일링.
- [ ] **드로다운 가드레일**(예: 최근 N일 DD가 임계치 초과 시 포지션 축소/중립).
- [ ] **단일 종목/섹터 비중 상한**(Tech+Healthcare 내에서도 단일 종목 쏠림 방지).

**왜**: 챔피언 worst_mdd(-9.3%)가 이미 의미 있게 큼. 평균을 유지하면서 꼬리를 줄이는 “운영 안정화”가 48시간 루프에서 최우선.

---

### 4) **레짐(장세) 기반 노출 스케일링 — ETF는 ‘관측지표’로만**
- [ ] QQQ/XLV/SPY, VIX(또는 realized vol)로 **리스크 온/오프 게이트**를 만들고 **노출만 조절**(ETF 매매 금지).
- [ ] 트렌드/변동성 국면에서 동일 신호를 동일 강도로 쓰지 않도록 **게이팅**.

**왜**: 평균이 “안 움직이는” 구간은 보통 레짐 불일치(신호가 먹는 장 vs 안 먹는 장) 때문에 발생. 신호 자체를 늘리기보다 “언제 덜 할지”가 빨리 먹힘.

---

### 5) **유니버스 고정(미국주식 only, Tech+Healthcare 8~14) + 과최적화 방지**
- [ ] 8~14개 **고정 유니버스**로 실험(티커 변경/상장폐지 이슈가 적은 대형주 중심).
- [ ] 워크포워드/락박스에서 **최소 성능 + 최소 안정성(최저값)** 기준을 승격 조건에 포함.

**권장 고정 유니버스(12)**  
Tech: AAPL, MSFT, NVDA, AMZN, GOOGL, META  
Healthcare: LLY, UNH, ABBV, MRK, TMO, ISRG  
(ETF는 관측만: QQQ, XLV, SPY)

## “3~5개”로 제한한 실행 가능한 Patch/실험 (48시간 자동 루프 형태)
아래 4개만 돌리면 됨(각 실험은 (1)정의 (2)게이트 (3)기대 관측치 포함).

---

## 실험 1) **Leakage/Survivorship/Adj-Price 감사 패치**
### (1) 실험 정의 (Patch)
- [ ] 데이터 로더에 **Point-in-time 보장 플래그**(가능하면 vendor의 PIT 테이블 사용) 또는 내부적으로 “feature cutoff time = t-1 close” 강제.
- [ ] **조정가격 기준 통일**: 리턴 계산/체결가격/슬리피지 산출이 모두 동일 기준(Adj 또는 Raw)으로만 계산되게 강제.
- [ ] **룩어헤드 탐지 테스트** 추가: 임의의 날짜 t에서 t+1 이후 값이 feature에 섞이면 테스트 실패.

### (2) 게이트(중단/진행 조건)
- [ ] 샘플 100일 랜덤 스팟체크에서 “feature timestamp <= decision timestamp” 위반 0건.
- [ ] split/dividend 발생 구간에서 **수익률 점프(비정상 outlier)** 발생률이 기존 대비 감소(예: 상위 0.1% 절대수익률 outlier 비중 ↓).

### (3) 기대 관측치
- 튜닝 평균이 소폭 내려가더라도 **lockbox_min 상승** 또는 **분산 감소**가 관측되는 게 정상.
- “후보에서 lockbox_min이 낮게 찍히는” 현상이 완화될 가능성.

**PASS 조건**
- [ ] lockbox_min ≥ **1.00** (현재 후보 0.334 대비 안정성 회복)
- [ ] worst_mdd ≥ **-0.09** 유지(챔피언 꼬리보다 악화 금지)
- [ ] tuning_min이 과도하게 음수로 붕괴하지 않을 것(예: ≥ -0.30; 룩어헤드 제거로 폭망하면 원인 확정 가능)

---

## 실험 2) **거래비용/슬리피지 + 턴오버 패널티를 선택 기준에 내장**
### (1) 실험 정의 (Patch)
- [ ] 비용 모델: `cost = commission + k1*spread + k2*|Δw|` 형태로 단순 시작(종목별 spread는 ATR/price proxy로 근사 가능).
- [ ] objective(또는 모델 선택 점수)에 **턴오버 패널티** 추가: `score = mean - λ*turnover - μ*mdd_penalty`.

### (2) 게이트
- [ ] 평균 턴오버가 챔피언 대비 **동일 또는 감소**.
- [ ] 비용 차감 후 Sharpe/평균이 “무의미하게” 붕괴하면(예: lockbox_mean 20%+ 하락) 비용 모델 파라미터 과대 가능 → k 조정.

### (3) 기대 관측치
- 튜닝에서만 좋아 보이던 해가 줄고, **락박스 안정성(lockbox_min, worst_mdd)이 개선**되는 방향이 정상.

**PASS 조건**
- [ ] cost-adjusted lockbox_mean ≥ **1.80** (챔피언 1.792 근처 상향)
- [ ] cost-adjusted worst_mdd ≥ **-0.085**
- [ ] lockbox_min ≥ **1.10** (챔피언 1.133에 근접 목표)

---

## 실험 3) **리스크 오버레이(Vol 타게팅 + DD 가드 + 비중상한)**
### (1) 실험 정의 (Patch)
- [ ] 포트 변동성 타겟(예: 연 15% 가정): `scale = target_vol / realized_vol(20d)`로 노출 스케일.
- [ ] DD 가드: 최근 20~60일 DD가 임계 초과 시(예: -6%~-8%) scale을 추가로 축소.
- [ ] 종목 비중 상한(예: 20~25%), 섹터(Tech/Healthcare) 쏠림 상한(예: 70/30 유지 등).

### (2) 게이트
- [ ] 노출 스케일링이 “항상 0에 가깝게” 되는지 확인(게이트가 너무 공격적이면 무력화).
- [ ] 월간 리밸런스 대비 48시간 루프에서 빈번한 오버레이 트리거가 발생하면(>30%) 임계 재조정.

### (3) 기대 관측치
- **worst_mdd 감소**, 락박스 min 상승.
- mean이 소폭 감소해도 “운영 가능성”이 크게 개선되는 게 정상.

**PASS 조건**
- [ ] worst_mdd ≤ **-0.07** 달성(챔피언 -0.093 대비 꼬리 절감)
- [ ] lockbox_mean ≥ **1.70** 유지(꼬리 줄이되 수익력 과도 훼손 금지)
- [ ] lockbox_min ≥ **1.10**

---

## 실험 4) **레짐 게이트(ETF는 관측만)로 노출만 조절**
### (1) 실험 정의 (Patch)
- [ ] 관측 지표: QQQ(Tech proxy), XLV(Healthcare proxy), SPY(시장), VIX 또는 realized vol.
- [ ] 규칙(예시):  
  - (a) SPY 50d 추세 양(>0) & VIX 낮음 → 노출 1.0  
  - (b) 추세 약/변동성 상승 → 노출 0.5  
  - (c) 급변(변동성 급등) → 노출 0.0~0.25  
- [ ] “신호 방향”은 기존 모델 유지, **크기만 조절**(케이스 폭발 방지).

### (2) 게이트
- [ ] 게이트 상태 전환 빈도 제한(예: 10거래일 내 3회 초과 시 히스테리시스 추가).
- [ ] QQQ/XLV 관측이 종목 신호에 룩어헤드로 섞이지 않도록 timestamp 정렬 테스트 통과.

### (3) 기대 관측치
- 레짐 불일치 구간에서 손실 누적이 줄고 **락박스 min과 worst_mdd가 개선**될 확률이 큼.
- 평균이 안 움직이던 구간에서 “손실 회피로 인해” risk-adjusted가 개선되는 형태.

**PASS 조건**
- [ ] lockbox_min ≥ **1.10**
- [ ] worst_mdd ≥ **-0.08**
- [ ] lockbox_mean ≥ **1.75**

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래는 질문 없이 바로 찍어보는 **진단 트리(명령형)**.

## A. Trigger(신호 발생) 문제
- [ ] **신호 발생률(=포지션 변경 이벤트 수)**이 기간별로 급감/급증했는지 확인
- [ ] 종목별로 **신호가 한쪽(항상 롱/항상 현금)**으로 고착되는지 확인
- [ ] 피처 분포 드리프트(평균/분산/결측률)가 특정 시점에 튀는지 확인(코퍼레이트 액션 의심)

## B. Apply(리밸런스/정렬) 문제
- [ ] “의사결정 시점”과 “체결 시점” 정렬 검증(오늘 종가로 결정했는데 오늘 종가로 체결하는 형태는 누수 성격)
- [ ] 리밸런스 캘린더(48시간 루프)가 휴장/반휴장/서머타임에서 어긋나지 않는지 확인
- [ ] 포지션 라운딩/최소 주문단위 때문에 신호가 사라지는지(특히 소액 포트) 확인

## C. Exposure(노출/집중) 문제
- [ ] 상위 1~2종목 기여도가 과도(수익/손실 기여 60%+)면 “단일 종목 베팅”으로 변질
- [ ] 베타(시장노출) 추정: SPY 회귀 베타가 기간별로 급변하는지 확인
- [ ] Tech/Healthcare 내부 편향(사실상 Tech 90%)이면 섹터 다각화 실패

## D. Cost(비용) 문제
- [ ] **턴오버 × 스프레드 proxy**로 비용 상한을 추정해, 총수익 대비 비용 비율이 일정 임계(예: 20~30%) 넘는지 확인
- [ ] 변동성 급등 구간에서 비용이 비선형으로 커졌는지(impact proxy) 확인

## E. Regime(장세) 문제
- [ ] “신호 성과를 레짐별로 분해”:  
  - SPY 추세(상/하) × 변동성(상/하) 4분면에서 평균/최저/승률을 각각 계산
- [ ] 특정 레짐에서만 먹히면 → **레짐 게이트로 노출 축소**가 1순위 처방

---

## 48시간 루프에 맞춘 실행 순서(명령형)
- [ ] `실험 1(누수/서바이버십/조정가)` → 먼저 고정(데이터 무결성 없으면 모든 실험이 무의미)
- [ ] `실험 2(비용+턴오버)` → 선택 기준을 “운영형”으로 바꿔 락박스 min을 끌어올리기
- [ ] `실험 3(리스크 오버레이)` → worst_mdd를 확실히 깎기
- [ ] `실험 4(레짐 게이트)` → 성능 정체 구간을 줄이기

(현재 제시된 autopilot 커맨드는 그대로 돌리되, 위 4개 패치를 각각 “candidate spec”으로만 추가해서 비교하면 48시간 내 결론이 가장 빨리 나옴.)
