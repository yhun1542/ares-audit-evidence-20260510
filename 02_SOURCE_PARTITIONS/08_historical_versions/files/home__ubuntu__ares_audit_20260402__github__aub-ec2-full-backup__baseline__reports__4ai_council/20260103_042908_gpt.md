아래는 **다음 24~48시간** 동안 “성능이 안 움직이는 상태”를 먼저 깨기 위한 **우선순위 TOP5**입니다. 전부 **누수/과최적화/서바이버십/비용 미반영/운영 리스크**를 최우선으로 점검하도록 구성했고, **실행은 총 5개 실험(E1~E5)**만 돌리면 되게 만들었습니다(각 제안은 E1~E5 중 2~3개를 재사용).

## 0) 즉시 관측된 위험 신호(ONE TRUTH 기반)
- `degenerate_folds: [1,2,3,8]` → **CV 분할/표본/라벨 생성** 쪽 결함 가능성(누수 또는 무효 폴드).
- `worst_mdd: None` → **리스크 평가 파이프라인이 끝까지 안 돌았거나 지표 누락**(운영 리스크).
- `lane_hash/run_hash: None` → **실험 식별/재현성 붕괴**(실험이 “안 움직이는” 대표 원인).
- Rebalance pinpoint가 **입력 로그 형식 미스매치**로 실패 → **리밸런스/체결/비용/턴오버 기여분 분해 불가**.

# 1) 우선순위 TOP5 제안(코드/아키텍처/전략)

## TOP1. “리밸런스/체결/비용” 로그를 표준화해서 원인분해 가능하게 만들기 (운영 리스크 1순위)
**(a) 왜 필요한지**
- 현재 rebalance pinpoint가 로그를 못 읽어 **적용(orders) 자체가 발생했는지**, **비용이 들어갔는지**, **턴오버가 어디서 생겼는지**를 확인 불가.
- “성능이 안 움직임”은 대개 **(i) 신호가 포지션에 반영 안 됨 (ii) 비용이 0으로 계산됨 (iii) 노출이 0에 수렴** 중 하나인데, 지금은 분해가 막힘.

**(b) 위험/부작용**
- 로그/아티팩트가 커져 저장비용 증가.
- 표준 스키마로 바꾸는 과정에서 기존 도구 호환 깨질 수 있음(그러나 48시간 루프 안정성을 위해 필요).

**(c) 최소 실험(공유 실험 ID 재사용)**
- **E1(표준 리밸런스 로그+재현성 해시)**  
- **E4(비용모델 on/off 민감도)**

**(d) PASS 조건**
- 모든 런에서 **rebalance.jsonl(or parquet)** 생성 + 도구가 로딩 성공.
- 각 리밸런스 시점에 대해 `pre_w`, `target_w`, `post_w`, `trades`, `turnover`, `cost`가 **누락 없이** 기록.
- 비용 on/off에서 **OOS PnL/Sharpe 차이가 “비용만큼” 단조롭게** 감소(비용이 실제로 반영된다는 증거).

## TOP2. Degenerate folds 제거: 누수/무효 폴드/라벨 정렬 오류를 단위테스트로 차단
**(a) 왜 필요한지**
- `degenerate_folds`는 “폴드에 거래일이 너무 적음/라벨이 상수/신호가 모두 NaN/피처가 누수로 미래를 봄” 등일 때 흔함.
- 이 상태에서 최적화하면 **과최적화 + OOS 무의미**가 되거나, 반대로 **모든 후보가 동일 성능(=no-delta)**처럼 보일 수 있음.

**(b) 위험/부작용**
- 폴드 규칙이 엄격해지면 학습 데이터가 줄어 **단기적으로 성능 하락** 가능.
- 과거 “좋아 보이던” 성능이 누수 제거로 사라질 수 있음(정상).

**(c) 최소 실험**
- **E2(폴드 무결성/누수 테스트 + 폴드 재정의)**  
- **E5(레짐/기간별 성능 분해 대시보드)**

**(d) PASS 조건**
- degenerate_folds가 **빈 배열** 또는 전체 폴드의 **유효 표본수/거래수 기준 충족**.
- “미래 참조” 가능성이 있는 피처/라벨 정렬 위반(예: t+1 수익을 t에 섞음) 탐지 시 **빌드 실패(gate fail)**.

## TOP3. 서바이버십/Point-in-time 유니버스 확정: “미국 Tech+Healthcare 8~14종목”을 PIT로 강제
**(a) 왜 필요한지**
- 백테스트에서 가장 흔한 착시: **현재 구성 종목으로 과거를 거래(서바이버십)**.
- 또한 “US only + Tech/Healthcare + 8~14개” 제약이 코드 레벨로 강제되지 않으면, 실험마다 유니버스가 달라져 **비교가 무의미**해짐.

**(b) 위험/부작용**
- PIT 메타데이터(상장/상폐/섹터 변경) 품질이 낮으면 유니버스가 흔들릴 수 있음.
- 종목 수 제약(8~14)으로 신호가 약해지는 구간이 생길 수 있음.

**(c) 최소 실험**
- **E3(PIT 유니버스/섹터 필터/종목수 제약 강제 + 서바이버십 A/B)**  
- **E2(폴드 무결성)**

**(d) PASS 조건**
- 모든 날짜에서 보유 종목이 **정확히 8~14개**, 그리고 전부 **US 상장 + (Tech|Healthcare)**.
- 서바이버십 A/B(현재 구성 vs PIT)에서 성능 차이가 크면(특히 과거 구간에서) → **PIT만 채택**, non-PIT는 폐기.

## TOP4. 비용(슬리피지/스프레드/수수료) + 턴오버 캡을 게이트로 박아 “비용 미반영”을 영구 차단
**(a) 왜 필요한지**
- 비용이 0이거나 과소평가되면 최적화가 **과도한 리밸런스**로 수렴(현실에서 붕괴).
- 지금은 rebalance 로그가 부재라 비용 검증이 막혀 있었음.

**(b) 위험/부작용**
- 턴오버 캡을 걸면 알파가 늦게 반영되어 단기 성능 감소 가능.
- 비용 파라미터가 과도하면 실제보다 보수적이 되어 기회를 놓칠 수 있음.

**(c) 최소 실험**
- **E4(비용 민감도 + 턴오버 캡 게이트)**  
- **E1(체결/비용 로그 표준화)**

**(d) PASS 조건**
- OOS에서 `cost=0` 발생률 **0%**.
- 턴오버(예: 일/주 단위)가 설정한 상한을 **위반 시 즉시 실험 실패**.
- 비용 파라미터를 0 → 기준 → 2배로 바꿔도 결과가 비정상적으로 불변이면(=비용 미적용) **즉시 FAIL**.

## TOP5. 노출/적용(Trigger→Order→Position) 파이프라인을 “48시간 자동 루프용”으로 고정(신호가 포지션에 반영되는지 검증)
**(a) 왜 필요한지**
- `exposure_min/max: 0.0 / 0.8388` → 구간에 따라 **현금 비중이 커지거나** 주문이 막혔을 가능성.
- “no-delta” 상황은 종종 **신호는 바뀌는데 포지션이 그대로**라서 발생(적용 로직/클리핑/제약).

**(b) 위험/부작용**
- 노출 하한을 강제하면 하락장에서 손실이 커질 수 있음(따라서 게이트로 관리).
- 8~14개 종목 강제 시 동률 처리/랭킹 타이브레이크가 중요해짐.

**(c) 최소 실험**
- **E1(리밸런스 로그로 적용 검증)**  
- **E5(Trigger→Target→Post 포지션 변화율 모니터 + 레짐 분해)**

**(d) PASS 조건**
- 신호 변화가 있을 때 `target_w`가 변하고, 그 다음 `post_w`도 최소한의 범위에서 변함(주문이 실제 반영).
- “신호 변화율” 대비 “포지션 변화율”이 장기간 0에 수렴하면 **FAIL(적용 파이프라인 문제)**.

# 2) 48시간 자동 루프용 “실행 가능한 실험” 5개(E1~E5)
아래 5개만 돌리면 위 TOP1~TOP5가 모두 커버됩니다.

## E1) 표준 Rebalance/Execution 로그 + run_hash/lane_hash 강제 (Patch)
- **(1) 실험 정의**
  - 모든 런에서 아래 산출물을 강제 생성:
    - `artifacts/<run_hash>/rebalance.jsonl` (또는 parquet)
    - 레코드 필드: `ts, universe, signal_version, pre_w, target_w, post_w, trades, turnover, est_spread_bps, est_slip_bps, fee, total_cost, cash_w`
  - `run_hash = hash(config + code_commit + data_signature)` 강제, `lane_hash`도 설정.
- **(2) 게이트**
  - 로그 파일 미생성/스키마 누락/NaN 필드 존재 시 **즉시 FAIL**.
  - `worst_mdd` 등 리스크 지표가 None이면 **FAIL**(평가 파이프라인 미완료).
- **(3) 기대 관측치**
  - pinpoint 도구가 파일을 읽고, 리밸런스 이벤트 수/턴오버/비용이 일관되게 출력됨.
  - “성능 무변화” 케이스에서 (신호 불변 vs 적용 불능 vs 비용 0) 중 하나로 즉시 분류 가능.

---

## E2) Fold 무결성/누수 테스트 + degenerate 폴드 제거 (Patch+Test)
- **(1) 실험 정의**
  - 폴드별 체크를 자동화:
    - 최소 거래일 수, 최소 리밸런스 횟수, 라벨 분산(상수 라벨 금지), 피처 NaN 비율 상한
    - 시간 정렬 테스트: 피처/라벨이 **미래 데이터를 참조하지 않음**(lookahead 방지)
  - 실패 폴드는 학습/평가에서 제외하거나, 폴드 정의(기간/버퍼)를 재설정.
- **(2) 게이트**
  - `degenerate_folds`가 0이 될 때까지 통과 금지(또는 전체 폴드의 95% 이상 유효).
  - 누수 의심(시계열 뒤섞임) 검출 시 **즉시 FAIL**.
- **(3) 기대 관측치**
  - OOS 평균이 단기적으로 흔들릴 수 있으나, 실험 간 분산이 줄고 “no-delta”가 줄어듦(유의미한 차이가 생김).

---

## E3) PIT 유니버스 + 섹터 필터 + 8~14 종목 제약 강제 + 서바이버십 A/B (Experiment)
- **(1) 실험 정의**
  - 유니버스 생성 단계에서:
    - US 상장만(ADR/OTC 제외 등 규칙 명시)
    - GICS 기준 Tech/Healthcare만
    - 보유 종목 수 8~14로 고정(랭킹 기반, 타이브레이크 규칙 고정)
  - A/B:
    - A: 현재 시점 구성(서바이버십 가능)  
    - B: PIT 구성(상장/섹터 변경 반영)
- **(2) 게이트**
  - 어떤 날짜라도 보유 종목 수가 8~14 밖이면 **FAIL**.
  - Tech/Healthcare 외 섹터 편입 시 **FAIL**.
- **(3) 기대 관측치**
  - A가 B보다 과거 구간에서 과도하게 좋으면(전형적 서바이버십) → B만 채택.
  - B 기준으로도 성능이 유지되면 “진짜” 개선 여지 확보.

---

## E4) 비용 민감도(0/기준/2배) + 턴오버 캡 게이트 (Experiment)
- **(1) 실험 정의**
  - 동일 신호/동일 유니버스에서 비용만 바꿔 3회 런:
    - cost=0
    - cost=baseline (스프레드+슬리피지+수수료)
    - cost=2x baseline
  - 동시에 턴오버 상한(예: 일/주 단위)을 설정하고 초과 시 주문을 클리핑하거나 FAIL 처리.
- **(2) 게이트**
  - 비용 0 → 기준 → 2배에서 OOS PnL이 단조 감소하지 않으면 **FAIL(비용 적용/로깅 문제)**.
  - 턴오버 상한 위반 시 **FAIL**.
- **(3) 기대 관측치**
  - 비용이 커질수록 성능이 점진적으로 악화(정상).
  - 최적화가 “비용 0 전제”에서만 잘되던 전략은 여기서 걸러짐.

---

## E5) “Trigger→Target→Post” 적용 검증 + 레짐/노출 분해 대시보드 (Patch)
- **(1) 실험 정의**
  - 매 리밸런스 시점마다 아래를 계산/저장:
    - 신호 변화율(Δsignal), 목표 비중 변화율(Δtarget_w), 실제 포지션 변화율(Δpost_w)
    - 노출(총 익스포저, 현금비중), 종목수, 섹터 비중
    - 레짐 태깅(예: VIX 상/하, 금리 변화, QQQ/XLV는 **관측지표로만** 사용)
  - 기간별 성능 분해(최근 6M/12M, 고변동/저변동 등) 출력.
- **(2) 게이트**
  - Δsignal이 유의미한데 Δpost_w가 장기간 0이면 **FAIL(적용 불능)**.
  - 노출이 비정상(예: 장기간 0 근접 또는 상한 근접 유지)하면 **FAIL(제약/클리핑/데이터 결측)**.
- **(3) 기대 관측치**
  - “성능 무변화” 원인이 트리거인지/적용인지/노출인지 즉시 분리됨.
  - 레짐별로만 성능이 살아나는 패턴이면, 이후 전략 수정 포인트가 명확해짐.

# 3) 성능이 안 움직일 때: 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래 순서대로 **체크만** 하면 원인이 거의 갈립니다(질문 없이 실행 체크리스트).

## A. Trigger(신호) 문제 분해
- **[체크]** 날짜별 `signal` 분산/순위변동(스피어만 상관, 상위 14개 교체율) 출력하라.
- **[트리거]** 상위 14개 교체율이 장기간 0에 가깝다면  
  → 신호가 사실상 상수(피처 고정/정규화 버그/리밸런스 주기 미적용).
- **[패치 연결]** E2(누수/정렬) + E5(Δsignal 로그).

## B. Apply(적용: 신호→주문→포지션) 문제 분해
- **[체크]** `pre_w → target_w → post_w` 3단계를 같은 타임스탬프로 저장하고, Δtarget과 Δpost의 상관을 보라.
- **[트리거]** Δtarget은 큰데 Δpost가 0이면  
  → 주문 생성/체결/클리핑/최소주문단위/거래정지 처리에서 막힘.
- **[패치 연결]** E1(리밸런스 로그) + E5(Δpost 추적).

## C. Exposure(노출) 문제 분해
- **[체크]** 총 익스포저, 현금비중, 종목수(8~14 유지 여부), 단일종목 상한을 시계열로 확인하라.
- **[트리거]** 노출이 자주 0으로 떨어지면  
  → 유니버스 결측/필터 과도/리밸런스 실패/리스크 모델이 전량 축소.
- **[패치 연결]** E3(유니버스 제약 강제) + E5(노출 로그).

## D. Cost(비용) 문제 분해
- **[체크]** 비용 on/off/2x에서 성능이 거의 같으면 비용이 적용되지 않은 것이다.
- **[트리거]** 비용을 올려도 PnL이 그대로면  
  → 비용 함수 미호출, turnover 계산 오류, 로그/스키마 누락.
- **[패치 연결]** E4(민감도) + E1(비용 필드 강제).

## E. Regime(레짐) 문제 분해
- **[체크]** 관측지표(예: QQQ/XLV 상대강도, VIX, 금리)로 구간을 나눠 OOS 성능을 쪼개라(ETF는 **매매 금지**, 분류용).
- **[트리거]** 특정 레짐에서만 성능이 나오면  
  → 전략 자체가 레짐 의존(개선은 “레짐 감지→노출 조절” 쪽으로).
- **[패치 연결]** E5(레짐 태깅/분해).

## 24~48시간 실행 순서(명령형 체크리스트)
1) **E1을 먼저 적용**해서 run_hash/lane_hash/리밸런스 로그가 100% 남게 만들어라.  
2) **E2를 돌려 degenerate_folds를 0으로** 만들고, 누수/정렬 위반을 게이트로 막아라.  
3) **E3로 PIT 유니버스 + Tech/Healthcare + 8~14 강제** 후 서바이버십 A/B 결과를 남겨라.  
4) **E4로 비용 민감도 + 턴오버 캡**을 통과시켜 “비용 미반영”을 영구 차단하라.  
5) **E5로 Δsignal/Δtarget/Δpost + 노출 + 레짐 분해**를 저장해 “안 움직임”의 원인을 자동 분류하라.

이 5개가 통과하면, 그 다음부터의 전략 개선은 “알파” 문제로 좁혀져서(=데이터/적용/비용/서바이버십/운영 리스크 제거) 48시간 루프에서 유의미한 델타가 나오기 시작합니다.
