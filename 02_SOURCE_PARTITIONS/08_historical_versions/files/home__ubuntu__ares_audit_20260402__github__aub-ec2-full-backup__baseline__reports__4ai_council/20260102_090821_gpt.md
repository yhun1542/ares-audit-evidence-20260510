## TOP1) 누수(Leakage) 차단 “Asof-Join + Purge/Embargo + 라벨정렬” 패치
### (a) 왜 필요한지
- 현재 Champion이 **worst_mdd: None**, file 공란 등 메타가 비정상이고, 이런 상태는 종종 **평가 파이프라인의 누락/비정합(lookahead 포함)** 과 같이 동반됩니다.
- 특히 Tech/Healthcare는 **실적/가이던스/뉴스 반영 타임스탬프**가 핵심이라, “일자 기준”으로 합치면 누수 확률이 큽니다.

### (b) 위험/부작용
- 누수 제거 시 OOS 성능이 단기적으로 **급락**할 수 있음(정상 신호).
- 엄격한 embargo/purge 적용 시 학습 데이터가 줄어 **분산 증가** 가능.

### (c) 최소 실험 2~3개 (48h 루프형)
**실험 1: Asof-Join 강제 + 피처 타임스탬프 감사**
- (1) 실험 정의: 모든 feature를 `feature_time <= decision_time` 조건으로만 조인(특히 펀더멘털/이벤트/리비전). 위반 row는 드랍/마스킹 후 카운트 로그화.
- (2) 게이트: 누수 위반 row 비율이 0.1% 초과 시 RUN FAIL(학습/백테스트 중단).
- (3) 기대 관측치: 위반 row가 존재하면 즉시 드러나며, 제거 후 OOS가 현실적으로 하향(정상화)될 수 있음.

**실험 2: Purged K-Fold + Embargo(예: 5~10 trading days)**
- (1) 실험 정의: 시계열 CV에 purge+embargo 적용(라벨 윈도우/홀딩기간에 맞춤).
- (2) 게이트: degenerate fold(빈 fold/수익률 NaN) 발생 시 FAIL.
- (3) 기대 관측치: 과거 대비 oos_mean이 내려가더라도 oos_min이 개선/안정화되면 “누수 제거+일반화” 신호.

**실험 3: 라벨 시프트/정렬 단위 테스트**
- (1) 실험 정의: `t`에서 결정 → `t+1 open` 또는 `t close` 등 체결 시점에 따라 라벨을 명시적으로 시프트하고, 상호 배타(둘 중 하나만)로 강제.
- (2) 게이트: 동일 seed에서 “체결시점만 바꿨는데 성능이 과도하게 유지”되면 누수 의심으로 FAIL(예: oos_mean 변화 < 2%p).
- (3) 기대 관측치: 체결 정의에 따라 성능이 민감하게 변해야 정상.

### (d) PASS 조건
- 누수 위반 row < 0.1%, 라벨 정렬 테스트 통과
- Purge/Embargo 적용 후에도 **oos_min ≥ 0.40 유지**(현재 0.431 근방) 또는 **oos_min 개선**
- degenerate_folds 빈 배열 유지

## TOP2) 서바이버십/코퍼레이트액션/상장폐지 수익률 “Point-in-time” 패치
### (a) 왜 필요한지
- 미국주식 백테스트는 **delist, split/dividend, ticker change**를 잘못 다루면 장기 성과가 부풀어지는 경우가 많습니다.
- Tech/Healthcare는 M&A/스핀오프도 잦아 **심각한 서바이버십 편향** 트리거가 됩니다.

### (b) 위험/부작용
- 데이터 소스가 delist return을 제공하지 않으면 구현이 까다롭고, 단기적으로 Universe가 줄어들 수 있음.
- point-in-time를 강제하면 과거 데이터 결측이 늘어 성능이 흔들릴 수 있음.

### (c) 최소 실험 2~3개
**실험 1: 코퍼레이트액션 정합성 체크(가격 vs 조정가격)**
- (1) 실험 정의: split/dividend 반영 방식(Adj Close 사용 여부)을 단일 규칙으로 고정하고, 주문/체결/수익률 계산이 동일 기준을 쓰도록 통합.
- (2) 게이트: 동일 기간에서 raw/adj 혼용 탐지 시 FAIL.
- (3) 기대 관측치: 특정 종목에서 비정상 갭 수익률이 사라지고, MDD/변동성이 현실화.

**실험 2: Delist/정지 이벤트 처리**
- (1) 실험 정의: 상장폐지/거래정지 시 마지막 거래일 이후 수익률을 0으로 두지 말고, delist return(가능 시) 또는 보수적 페널티(예: -100% 또는 -50% 캡) 규칙을 명시.
- (2) 게이트: delist 이벤트 발견 시 “미처리”면 FAIL.
- (3) 기대 관측치: 장기 꼬리리스크가 증가(정상), 과최적화된 전략이 약화.

**실험 3: Universe 고정(8~14) + 유동성 필터(운영 리스크 저감)**
- (1) 실험 정의: **미국 Tech+Healthcare 12종목 고정 바스켓**으로 먼저 검증(예: AAPL, MSFT, NVDA, AMZN, GOOGL, META, UNH, JNJ, LLY, ABBV, MRK, TMO). 추가로 최소 유동성(예: 20D ADV>$500M) 규칙 적용.
- (2) 게이트: 일별 거래 가능 종목 수가 8 미만이면 FAIL.
- (3) 기대 관측치: 과거 “우연히 좋았던 소형/이상치” 제거로 성과는 줄 수 있으나 재현성이 상승.

### (d) PASS 조건
- corporate action 혼용 0건, delist 미처리 0건
- Universe 가용 종목 ≥ 8 항상 유지
- OOS가 단기 하락해도 **성과 분산 감소(표준편차/폴드 간 편차 감소)** 확인

## TOP3) 비용/슬리피지/턴오버 “Net 성과” 패치 (비용 미반영 제거)
### (a) 왜 필요한지
- 현재 지표에 **비용 차감/턴오버/스프레드/시장충격**이 보이지 않습니다. Tech 대형주는 싸 보이지만, 잦은 회전이면 순성과가 급격히 무너집니다.
- exposure가 0.47~0.84로 **항상 풀인베스트가 아닌데**, 현금 수익률/담보이자 처리도 빠지면 왜곡됩니다.

### (b) 위험/부작용
- 비용 모델이 보수적으로 설정되면 성과가 “갑자기” 무너질 수 있음(정상).
- 턴오버 제한은 알파를 깎을 수 있음.

### (c) 최소 실험 2~3개
**실험 1: 고정+가변 비용(커미션+스프레드) 즉시 반영**
- (1) 실험 정의: 거래당 `commission + half_spread*|Δposition|` 차감. half_spread는 일별 스프레드 proxy(없으면 보수적 상수).
- (2) 게이트: gross 대비 net 성과 차이(비용 드래그)가 월 -Xbp(예: -50bp) 초과면 FAIL로 표시(전략 재설계 트리거).
- (3) 기대 관측치: 고빈도 회전 전략이 걸러지고, 진짜 유지 가능한 신호만 남음.

**실험 2: 턴오버 캡/리밸런싱 주기 실험**
- (1) 실험 정의: (a) 일간, (b) 주 2회, (c) 주 1회 리밸런싱 비교 + 1일 최대 turnover cap(예: 25%) 적용.
- (2) 게이트: net oos_mean이 gross 대비 70% 미만으로 붕괴하면 FAIL(비용 민감 과다).
- (3) 기대 관측치: 리밸런싱을 줄여도 성능이 유지되면 신호가 견고.

**실험 3: 현금/노출 처리(리스크프리)**
- (1) 실험 정의: 미투자 노출(1-exposure)에 대해 단기금리(관측지표: SHY/IEF 수익률 또는 SOFR proxy)를 적립하는 옵션을 켜고/끄고 비교.
- (2) 게이트: exposure 변동이 큰데 현금 처리를 안 한 성능이 더 좋으면(역전) 회계 왜곡 의심으로 FAIL.
- (3) 기대 관측치: 전략이 부분 투자일수록 net 성과 해석이 안정화.

### (d) PASS 조건
- net 기준으로도 oos_min이 급락하지 않음(예: 현재 0.43에서 0.35 미만으로 붕괴 금지)
- turnover, 비용 드래그, 현금수익 처리까지 포함해도 전략 순위(챔피언)가 일관

## TOP5) 과최적화 억제 + 레짐 게이팅(ETF는 관측지표만) + 노출 안정화 패치
### (a) 왜 필요한지

- 현재 exposure 0.47~0.84로 들쭉날쭉 → 레짐/리스크에 따라 노출이 출렁이는 구조일 수 있어, “좋을 때만 맞는” 패턴 가능.

### (b) 위험/부작용
- 게이팅은 거래 기회를 줄여 성과 상단을 낮출 수 있음.
- 과도한 규제는 알파를 죽일 수 있음.

### (c) 최소 실험 2~3개
**실험 1: 레짐 게이트(관측지표로 QQQ/XLK/XLV 사용, 매매는 종목만)**
- (1) 실험 정의: 레짐 변수(예: QQQ 20D 모멘텀, VIX proxy 없으면 SPY 변동성, XLK/XLV 상대강도)로 “리스크-온/오프”를 분류하고, 오프에서는 (a) 노출 하향, (b) 헷지 대신 현금 비중 증가.
- (2) 게이트: 오프 레짐에서 MDD가 온 레짐 대비 개선되지 않으면 FAIL(게이트 의미 없음).
- (3) 기대 관측치: oos_mean은 비슷하거나 조금 감소해도, worst_mdd/좌측꼬리(oos_min)가 개선.

**실험 2: 노출/가중치 안정화(단일종목 상한 + 최소분산 페널티)**
- (1) 실험 정의: 단일 종목 weight cap(예: 15~20%), 일별 weight 변화 패널티(거래비용과 별개로 L1/L2)를 추가.
- (2) 게이트: cap 적용 후에도 특정 1~2개 종목 기여도가 60% 초과면 FAIL(편향 과다).
- (3) 기대 관측치: 종목 집중이 완화되고, 성과가 특정 종목 이벤트에 덜 휘둘림.

**실험 3: 신호 단순화(수평선 테스트)**
- (1) 실험 정의: 현재 모델 신호를 “상위 N개 롱 / 하위 N개 언더웨이트(또는 현금)” 같은 단순 규칙으로 축약한 베이스라인을 함께 돌려 복잡 모델 대비 개선폭을 측정.
- (2) 게이트: 복잡 모델이 단순 모델 대비 net oos_mean 개선 < +3%p면 FAIL(복잡도 과다/과최적화 의심).
- (3) 기대 관측치: 단순 신호가 비슷하면 과최적화 가능성이 높고, 복잡도 줄이는 방향이 유리.

### (d) PASS 조건
- 레짐 오프에서 worst_mdd 개선(절대값 기준, 예: 15%p 이상 개선 또는 하위 5% 손실 개선)
- 단일 종목 기여도 편향 완화 + turnover 감소
- 단순 베이스라인 대비 의미 있는 순개선(net) 확보

# 성능이 “안 움직일 때” 원인 분해 아이디어 (Trigger / Apply / Exposure / Cost / Regime)
아래 트리로 로그/리포트를 자동 저장해 **어디서 막히는지**를 빠르게 고정밀로 분해하세요.

## 1) Trigger(신호 발생) 문제
- **신호 분포 붕괴**: 스코어 분산이 0에 수렴, 상하위 랭크가 매일 동일
- **결측/마스킹 증가**: feature null 비율 급증 → 사실상 랜덤
- 조치 로그: 일별 스코어 표준편차, 상하위 교체율, feature null heatmap

## 2) Apply(적용/체결) 문제
- **체결 시점 불일치**(close로 의사결정했는데 open 체결로 가정 등)
- **리밸런싱 캘린더 오프셋**(휴장/반일장)
- 조치 로그: decision_time vs fill_time, 주문 생성 수/체결 수 불일치, 캘린더 검증

## 3) Exposure(노출/포지션) 문제
- exposure가 **0.47~0.84**처럼 출렁이면 “신호”가 아니라 “제약/결측”이 포지션을 결정 중일 수 있음
- 조치 로그: 목표노출 vs 실제노출, 현금 비중의 원인(게이트/결측/리스크컷)

## 4) Cost(비용/회전) 문제
- gross는 개선되는데 net이 정체면 **턴오버/스프레드**가 원인
- 조치 로그: 일별 turnover, 비용 드래그(bp), 종목별 평균 체결비용 추정

## 5) Regime(레짐) 문제
- 특정 구간에서만 먹히는 전략: Tech 랠리 구간에만 성과, 헬스케어 방어장/금리상승기에서 붕괴
- 조치 로그: 레짐별(예: QQQ 모멘텀 상/하, XLK-XLV 상대강도 상/하, 변동성 상/하) 성과 테이블 + worst_mdd 비교
