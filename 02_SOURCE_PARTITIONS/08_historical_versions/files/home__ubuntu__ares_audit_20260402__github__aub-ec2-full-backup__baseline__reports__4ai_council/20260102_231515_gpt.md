## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략)
1) **누수/과최적화 방지용 평가 파이프라인 교정 (degenerate folds 제거 + purged/embargo CV)**  
2) **서바이버십/포인트-인-타임 Universe 고정 (Tech+Healthcare 8~14 종목 제약 포함)**  
3) **비용(수수료/슬리피지/스프레드/대차) 반영 + 리밸런스 로그 스키마 표준화(현재 실패 원인 제거)**  
4) **운영 리스크/재현성: run_hash/lane_hash/아티팩트 경로/리포트 생성 보장 (MDD 등 핵심 지표 누락 금지)**  
5) **노출/턴오버/리스크 가드레일 + 레짐(ETF는 “관측지표”) 기반 리스크-온/오프 실험**

> 아래는 **고유 실험/패치 4개(E1~E4)**로만 돌리되, 각 TOP5 제안에 **2~3개씩 매핑**해서 48시간 자동 루프에 넣는 형태로 구성.

## 공통 실험/패치 묶음 (고유 4개만 실행)
### E1) Purged Walk-Forward + Embargo CV + Fold 진단(degenerate 제거)
- **실험 정의**:  
  - 기존 CV를 **PurgedKFold(라벨 기간만큼 purge) + embargo(예: 5~20 trading days)**로 교체  
  - fold별 샘플 수/타깃 분포/결측률/누수 의심(동일 timestamp 재사용) 리포트 출력  
- **게이트**:  
  - `degenerate_folds == []`  
  - fold별 샘플 수가 최소 기준 이상(예: 각 fold n>5,000 등 프로젝트 기준)  
  - OOS mean/분산이 fold 1~N에서 “한 fold만 튀는” 현상 완화(표준편차 상한)  
- **기대 관측치**:  
  - 단기적으로 OOS mean 하락 가능(누수 제거의 정상 신호)  
  - 대신 **OOS min 악화가 줄거나**, fold 간 편차가 줄어 “진짜 개선 여지”가 보임

### E2) Point-in-Time Universe 고정(서바이버십 제거) + 8~14 종목 강제
- **실험 정의**:  
  - 일자 t에서 **그날 존재하던 종목만**(상장폐지/티커변경 반영) Universe 구성  
  - 섹터는 **Tech+Healthcare**로 제한하고, 포트폴리오는 **항상 8~14 종목**(미만/초과 시 룰 기반 보정)  
- **게이트**:  
  - backtest 내내 “미래에만 존재하는 티커” 등장 0건  
  - 일자별 holdings count가 8~14를 벗어나지 않음  
- **기대 관측치**:  
  - 과거 성과가 일부 감소해도 “현실적인 분포”로 수렴  
  - 리밸런스/턴오버 패턴이 더 안정적으로 변함

### E3) 비용 모델 반영 + Rebalance 로그 표준화/파싱 보장(현재 에러 제거)
- **실험 정의**:  
  - 거래비용: 수수료 + 슬리피지(ATR/일변동 기반) + 스프레드(간단 근사) + (숏이면) 대차비용  
  - 리밸런스 로그를 **항상 동일 스키마 JSONL/CSV로 저장**하고, 리포트 툴이 읽는 경로를 “실재 파일”로 보장  
  - 현재 에러(`--base-log` 파일 없음, CSV 파싱 실패)를 **실패 즉시 중단(fail-fast)**로 전환  
- **게이트**:  
  - `aub_rebalance_pinpoint`가 base/cand 모두에서 **0 에러로 리포트 생성**  
  - 비용 반영 후에도 turnover가 상식 범위(상한 설정)  
- **기대 관측치**:  
  - OOS mean은 내려갈 수 있으나, **전략 간 차이(델타)가 ‘비용/턴오버’로 설명 가능한 형태로 분해**됨  
  - “성능이 안 움직이는” 원인이 로그로 드러남(거래가 실제로 안 일어나거나, 비용이 델타를 잡아먹는 등)

### E4) 노출/리스크 가드레일 + 레짐(ETF는 지표) 조건부 위험축소
- **실험 정의**:  
  - 노출 상한/하한, 종목당 최대비중, 섹터 편중 제한(Tech+HC 내)  
  - 변동성 타게팅(예: 포트 20D vol 목표) + 급락 시 디레버/현금 비중 확대 룰  
  - 레짐 지표로 **XLK, XLV, VIX(또는 SPY 200D 추세)**를 “관측만” 해서 risk-on/off 스위치(ETF 매매 없음)  
- **게이트**:  
  - `exposure_max <= 0.85` 유지(현재 0.838은 OK, 상한을 시스템적으로 보장)  
  - `worst_mdd`가 **항상 계산/보고**되고, 기준(예: -X%) 이내  
- **기대 관측치**:  
  - 극단 구간의 OOS min 개선, MDD 개선  
  - 평균 수익이 같더라도 tail-risk가 줄면 운영 관점에서 “다음 실험 공간”이 열림

## TOP5 제안별 정리 (왜/위험/최소 실험/ PASS)

### 1) 누수/과최적화 방지 평가 교정
- (a) 왜 필요한지  
  - 현재 `degenerate_folds: [1,2,3,8]`는 **검증 셋이 비거나/레이블 분포가 깨졌거나/시계열 누수**가 있다는 강한 신호. 이 상태에선 OOS mean이 움직여도 신뢰 불가.
- (b) 위험/부작용  
  - 누수 제거 시 성과 하락(정상). 실험 간 비교가 “갑자기 나빠졌다”로 보일 수 있음.
- (c) 최소 실험(2~3개, 고유 실험 E1~E4 재사용)  
  - **E1 적용**(필수)  
  - **E3 함께 적용**(비용/리밸런스 로그가 없으면 fold 개선 후에도 원인 추적 불가)  
- (d) PASS 조건  
  - `degenerate_folds == []`  
  - Fold별 OOS 분포가 극단적으로 찢어지지 않음(편차 상한)  
  - 같은 전략/시드에서 재실행 시 OOS mean 변동이 허용범위 내(재현성)

---

### 2) 서바이버십/Universe 포인트-인-타임 고정 + 8~14 종목 강제
- (a) 왜 필요한지  
  - US 주식에서 서바이버십은 **가장 흔한 “가짜 알파”** 원인. 또한 “8~14 종목” 제약을 뒤늦게 넣으면 과거 최적화가 무의미해짐.
- (b) 위험/부작용  
  - 데이터 소스/매핑 오류(티커 변경, 병합, 상폐)로 결측이 늘고 성과가 감소할 수 있음.
- (c) 최소 실험  
  - **E2 적용**(필수)  
  - **E1 병행**(Universe가 바뀌면 fold 분포도 바뀌므로 검증 재정렬 필요)
- (d) PASS 조건  
  - 미래 티커 사용 0건(포인트-인-타임 위반 0)  
  - holdings count가 항상 8~14  
  - 성과 수준보다 **성과의 “형태”(턴오버/리밸런스/리스크)가 논리적으로 해석 가능**

---

### 3) 비용 미반영 제거 + 리밸런스 로그 표준화(현재 에러 우선 제거)
- (a) 왜 필요한지  
  - 지금 `aub_rebalance_pinpoint`가 **파일 없음/파싱 실패**로 리밸런스 분석이 막혀 있음 → “델타 없음” 상태에서 원인(거래 없음/거래 과다/비용 상쇄)을 못 봄.
- (b) 위험/부작용  
  - 비용을 넣으면 수익이 감소하고, 특정 전략은 즉시 사망. 단, 그게 현실.
- (c) 최소 실험  
  - **E3 적용**(필수)  
  - **E4 병행**(비용의 대부분은 turnover에서 나오므로 가드레일로 같이 제어)
- (d) PASS 조건  
  - pinpoint 리포트가 base/cand 모두에서 생성(0 에러)  
  - 비용 반영 후에도 “거래가 실제로 발생”하며, 델타가 turnover/비용으로 설명 가능

---

### 4) 운영 리스크/재현성(해시/아티팩트/지표 누락 방지)
- (a) 왜 필요한지  
  - 현재 `lane_hash: None`, `run_hash: None`, `worst_mdd: None`는 **실험 추적/비교 불능** 신호. 48시간 자동 루프에서 이건 치명적.
- (b) 위험/부작용  
  - fail-fast로 전환하면 “돌긴 도는데 결과가 없음” 대신 “자주 실패”로 보일 수 있음(정상적인 품질 게이트).
- (c) 최소 실험  
  - **E3 적용**(로그/아티팩트 표준화가 핵심)  
  - **E1 적용**(평가 리포트가 강제 생성되어야 지표 누락이 줄어듦)
- (d) PASS 조건  
  - 모든 run에 `run_hash/lane_hash` 생성, champion 파일 경로가 항상 유효  
  - `worst_mdd` 포함 핵심 지표가 항상 채워짐(누락 시 런 실패 처리)

---

### 5) 노출/리스크 가드레일 + 레짐 지표(ETF는 관측만)
- (a) 왜 필요한지  
  - 현재 exposure max 0.838은 우연히 그렇게 나온 것일 수 있어 “정책”으로 고정해야 함.  
  - Tech+HC는 레짐 민감(금리/리스크오프) → tail 방어 없으면 운영 중 중단 확률 상승.
- (b) 위험/부작용  
  - 방어 로직이 수익을 깎아 평균 성과가 내려갈 수 있음. 잘못 만들면 “항상 risk-off”로 굳어 알파를 죽임.
- (c) 최소 실험  
  - **E4 적용**(필수)  
  - **E2 병행**(8~14 종목 제약 하에서만 가드레일 의미가 일관됨)
- (d) PASS 조건  
  - worst-case 지표 개선(OOS min 또는 worst_mdd)  
  - risk-off 구간에서 노출 축소가 “실제로” 발생(로그로 확인)

## 48시간 자동 루프용 “명령형 체크리스트” (E1~E4만 굴리기)
1) **E3부터 고쳐라 (로그/비용/리밸런스)**
   - 리밸런스 로그를 단일 포맷으로 저장하라(JSONL/CSV 고정).  
   - `--base-log/--cand-log` 경로를 “실존 파일”로 만들고, 없으면 런을 실패 처리하라.  
   - 비용 모델을 켜고, 비용 항목별 기여도를 리포트에 출력하라.  
2) **E1을 적용해 검증을 다시 세워라**
   - Purged+Embargo walk-forward로 교체하라.  
   - fold 진단 리포트를 저장하고 degenerate면 즉시 실패 처리하라.  
3) **E2로 Universe를 포인트-인-타임으로 고정하라**
   - 상폐/티커변경 반영하라.  
   - Tech+Healthcare에서 8~14 종목 유지 룰을 강제하라.  
4) **E4로 운영 가능한 리스크 형태를 강제하라**
   - 노출 상한/종목당 비중/변동성 타게팅을 켜라.  
   - XLK/XLV/VIX는 “관측”만 해서 risk-on/off를 적용하라.  
5) **매 1회전마다 산출물을 강제 저장하라**
   - (필수) metrics JSON + rebalance log + holdings timeseries + 비용 분해 + mdd 산출물을 저장하라.  
   - 누락 시 성공 처리하지 마라.

## “성능이 안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래 순서로 **상위부터** 잘라내라(가장 흔한/치명적인 순).

1) **트리거가 실제로 변하나? (신호 자체)**
   - 예측/스코어의 일별 분산, 상위-하위 스프레드(예: top-decile vs bottom-decile 평균)를 기록하라.  
   - “항상 비슷한 점수”면 모델이 죽었거나 스케일링/결측 처리로 평탄화된 것이다.

2) **적용이 실제로 포지션으로 반영되나? (실행 레이어)**
   - target weights → clipped weights → filled weights(체결 반영) 단계별로 스냅샷 저장하라.  
   - “신호는 변하는데 포지션이 안 변함”이면 **제약(8~14, cap, min trade, cash buffer)** 또는 버그다.

3) **노출이 델타를 먹나? (리스크/스케일링)**
   - gross/net exposure, 종목 수, 상위 3개 비중, 섹터 편중, vol targeting 스케일을 일별로 저장하라.  
   - “항상 동일한 노출”이면 전략이 사실상 고정 베타로 굳은 것이다.

4) **비용이 델타를 상쇄하나? (턴오버/슬리피지)**
   - turnover(일/주), 비용 항목별(수수료/슬리피지/스프레드/대차) 기여도를 분해하라.  
   - “샤프는 개선인데 PnL은 동일/악화”면 비용이 먹고 있는 전형 패턴이다.

5) **레짐에 의해 평균이 상쇄되나? (구간별 성능)**
   - 관측지표: VIX 구간(상/중/하), 금리 급등 구간, XLK vs XLV 상대강도 구간으로 OOS를 슬라이스하라.  
   - “구간별로는 차이가 큰데 전체 평균은 0 델타”면 레짐 스위치(E4)가 의미 있다.

6) **평가가 죽었나? (degenerate folds/리포트 누락)**
   - degenerate fold가 있으면 어떤 델타도 의미 없다. E1을 통과하기 전까지 성능 논쟁을 중단하라.

---

### 실행 우선순위(시간 기준)
- **0~6시간**: E3(로그/비용/리밸런스 파서) fail-fast로 정리  
- **6~18시간**: E1(CV 교체) + degenerate 제거  
- **18~30시간**: E2(Universe PIT + 8~14 강제)  
- **30~48시간**: E4(가드레일+레짐) 및 구간별 분해 리포트 자동생성

이 4개가 통과되면, 그 다음부터의 “성능 개선 실험”은 델타가 생겨도 **원인(신호/실행/비용/레짐)**으로 추적 가능한 상태가 된다.
