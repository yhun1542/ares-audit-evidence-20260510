[진단 요약]
현재 'Champion'은 **허수(Fake Champion)**일 가능성이 매우 높음.
1. `degenerate_folds: [1, 2, 3, 8]` → 전체 검증 구간의 40%에서 거래가 없거나 로직이 붕괴됨.
2. `worst_mdd: None` → 리스크 계산 실패. 파산 위험이 은폐됨.
3. `Error loading...` → 로그 파이프라인 붕괴로 사후 분석 불가능.

즉시 전략 개선을 멈추고 **시스템 무결성 복구**와 **생존 편향 제거**에 집중하라.

### 1. 24~48시간 우선순위 TOP 5

#### P1. 로그 파이프라인 및 MDD 계산 로직 긴급 복구
*   **이유:** `rebalance.csv` 누락 및 `worst_mdd: None` 상태에서는 어떠한 성능 개선도 측정 불가. 맹목적 비행 상태임.
*   **위험:** 버그 수정 후 OOS Mean이 급락할 가능성 높음(현실 자각).
*   **실험 (Patch):**
    1.  **[Sys_Fix_Log]**: `aub_rebalance_pinpoint.py`의 JSON 파싱 에러 수정 및 로깅 강제 활성화 (`force_flush=True`).
    2.  **[Sys_Fix_MDD]**: 수익률 배열에 `NaN`이나 `Inf`가 있을 경우 0으로 치환 후 MDD 재계산 로직 추가.
*   **PASS 조건:** 모든 Fold에서 `worst_mdd`가 유효한 음수 값(예: -0.01 ~ -0.99)으로 출력될 것.

#### P2. Degenerate Folds (1, 2, 3, 8) 원인 규명 및 해소
*   **이유:** 특정 시기(Fold 1~3은 보통 과거 데이터)에 데이터가 없거나 로직이 작동하지 않음. 이는 서바이버십 바이어스(상장 폐지/데이터 누락)의 강력한 증거임.
*   **위험:** 해당 구간 복구 시 전체 평균 수익률 희석 가능성.
*   **실험:**
    1.  **[Data_Check_Univ]**: Tech/Healthcare 유니버스(8~14개)가 해당 Fold 기간에 데이터가 존재하는지 `count` 찍기.
    2.  **[Logic_Relax_Entry]**: 진입 장벽(Threshold)을 0.0으로 낮춰 거래 강제 유발 후 로직 작동 여부 확인.
*   **PASS 조건:** `degenerate_folds` 리스트가 빈 배열 `[]`이 될 것.

#### P3. Tech/Healthcare 유니버스 데이터 정합성 검증
*   **이유:** ETF 제외/개별주 위주 전략에서, 헬스케어 바이오 기업은 변동성이 크거나 합병/폐지가 잦음. 엉뚱한 티커를 참조 중일 수 있음.
*   **위험:** 유니버스 교체 시 전략의 성격이 완전히 바뀜.
*   **실험:**
    1.  **[Univ_TopCap_Filter]**: 시가총액 상위 10개(Tech 5, Health 5)로 고정하여 Backtest 재수행.
    2.  **[Univ_Survivorship]**: 현재 시점이 아닌, *과거 시점 기준* 유니버스 구성 시뮬레이션(Point-in-Time Data 확인).
*   **PASS 조건:** `exposure_max`가 0.8 이상 유지되면서 `degenerate_folds`가 발생하지 않음.

#### P4. 비용 구조(Cost Model) 현실화
*   **이유:** OOS Mean 3.32는 비정상적으로 높음. 슬리피지와 수수료가 `0`이거나 과소 계상되었을 확률 99%.
*   **위험:** 전략 폐기 수준으로 성과가 곤두박질칠 수 있음(그러나 이게 현실임).
*   **실험:**
    1.  **[Cost_Basis_10bps]**: 왕복 수수료+슬리피지 10bps(0.1%) 적용.
    2.  **[Cost_Basis_30bps]**: 왕복 수수료+슬리피지 30bps(0.3%) 적용 (소형 바이오주 감안).
*   **PASS 조건:** 10bps 적용 후에도 OOS Mean > 0.05 유지.

#### P5. 노출(Exposure) 강제 실험
*   **이유:** `exposure_min: 0.0`은 시장 상황에 따라 현금 100%를 의미할 수도 있으나, 버그로 인해 매매가 안 된 것일 수도 있음.
*   **위험:** 하락장에서 손실 확대.
*   **실험:**
    1.  **[Exp_Force_Min]**: `min_exposure`를 0.1로 강제 설정하여 유령 거래 방지.
*   **PASS 조건:** 모든 거래일의 90% 이상에서 포지션 보유 확인.

### 2. 48시간 자동 루프 설계 (Action Plan)

**실험 A: "System Reality Check" (시스템 정상화)**
1.  **실험 정의:** 로깅 수정, MDD 계산 수정, 비용 15bps 적용.
2.  **게이트:** `rebalance.csv` 생성됨 AND `worst_mdd` != None.
3.  **기대 관측치:** OOS Mean은 하락하겠지만, 신뢰할 수 있는 수치 확보. `degenerate_folds` 원인 로그 확인.

**실험 B: "Missing Data Patch" (데이터 결측 보완)**
1.  **실험 정의:** Fold 1,2,3,8 구간에 데이터가 있는 대형주(예: JNJ, MSFT 등)만으로 유니버스 임시 제한.
2.  **게이트:** `degenerate_folds` 개수 감소.
3.  **기대 관측치:** 해당 구간 거래 발생 시작. 전체 OOS Sharpe Ratio의 현실화.

**실험 C: "Aggressive Entry" (진입 로직 완화)**
1.  **실험 정의:** 매수 시그널 Threshold를 기존 대비 50% 하향 조정.
2.  **게이트:** `exposure_mean` 상승.
3.  **기대 관측치:** 거래 횟수 증가, 비용 증가로 인한 순수익 변화 관찰. 거래가 아예 안 되는 구조적 문제인지 판별.

### 3. 성능 정체 시 원인 분해 (Diagnosis Tree)

성능지표가 움직이지 않거나 0에 수렴할 때 다음 순서로 체크리스트 수행:

1.  **트리거(Trigger) 불발:**
    *   *체크:* 시그널 생성 함수가 `NaN`을 뱉고 있는가?
    *   *조치:* 기술적 지표(RSI, MA 등) 계산 시 `min_periods` 조건 완화.
2.  **필터(Filter) 과다:**
    *   *체크:* 유동성 필터(거래량 등)나 변동성 필터가 모든 종목을 걸러내는가?
    *   *조치:* 필터 조건을 `Pass All`로 두고 백테스트 수행.
3.  **비용(Cost) 장벽:**
    *   *체크:* 평균 거래 이익(Average Trade Profit) < 거래 비용(Cost)인가?
    *   *조치:* 타임프레임을 늘려(Daily -> Weekly) 거래 빈도 축소.
4.  **레짐(Regime) 불일치:**
    *   *체크:* Tech/Health가 동반 하락하는 구간(예: 금리 인상기)인가?
    *   *조치:* 상관관계가 낮은 방어주(ETF 제외이므로 대형 제약주 비중 확대) 로직 추가.
5.  **데이터(Data) 오류:**
    *   *체크:* OHLC 데이터의 0값, 조정주가(Split) 미반영 확인.
    *   *조치:* 데이터 전처리기(Preprocessor) 재검증.
