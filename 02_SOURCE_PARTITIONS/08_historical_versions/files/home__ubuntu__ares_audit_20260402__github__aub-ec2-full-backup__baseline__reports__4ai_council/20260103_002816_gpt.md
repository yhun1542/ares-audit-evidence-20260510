아래를 **24~48시간 내 우선순위 TOP5**로 처리하되, 전체 변경은 **48시간 자동 루프에서 바로 돌아가는 “패치/실험 5개(고정)”**로 묶어 실행하라. (각 제안은 동일한 실험 세트를 **재사용 참조**하여 케이스 폭발을 막는다.)

---

## TOP5 우선순위 제안 (코드/아키텍처/전략)

### 1) (운영 리스크) 리밸런스/메타데이터 로깅 표준화로 “원인 추적 불능”부터 제거
**(a) 왜 필요한지**
- `aub_rebalance_pinpoint`가 입력 포맷/파일 누락으로 실패 중 → **“왜 성능이 안 움직이는지”를 구조적으로 확인 불가**.
- Champion에 `worst_mdd=None`, `lane_hash/run_hash=None` → 결과 재현/비교/롤백/서바이벌 검증이 막힘.

**(b) 위험/부작용**
- 로그/스키마 변경으로 파이프라인 깨질 수 있음(특히 자동 루프).
- 리밸런스 상세 로그 저장으로 스토리지/IO 비용 증가.

**(c) 최소 실험(2~3개, 아래 공통 실험 재사용)**
- **EXP4 (필수)** 로깅/스키마 패치 + `rebalance_pinpoint`가 항상 도는지 검증
- **EXP1 (보조)** 폴드 헬스 리포트(퇴화 폴드)도 같은 런 아티팩트에 고정 저장

**(d) PASS 조건**
- 매 런마다 다음 파일이 **항상 생성**: `rebalance.jsonl(or csv)`, `metrics.json`, `fold_health.json`, `config_resolved.json`
- `aub_rebalance_pinpoint.py`가 **exit code 0** + 리포트에 리밸런스 이벤트가 1개 이상 표시
- `lane_hash/run_hash`가 항상 채워지고, champion 비교가 동일 키로 가능

---

### 2) (누수/과최적화) 폴드 퇴화(degenerate_folds) 제거 + 시간누수 차단을 최우선
**(a) 왜 필요한지**
- `degenerate_folds: [1,2,3,8]` → OOS 평균이 좋아도 **검증구조가 무너진 상태**일 가능성이 큼(누수/편향/데이터 공백/룰 기반 탈락).
- 퇴화 폴드가 있는 모델은 “안 움직임(no-delta)”뿐 아니라 “가짜 개선”도 자주 만든다.

**(b) 위험/부작용**
- 누수 차단/폴드 강화 후 **지표가 하락**할 수 있음(정상).
- 데이터 절단(purge/embargo)로 학습 샘플 수 감소.

**(c) 최소 실험**
- **EXP1 (필수)** Purge+Embargo 워크포워드 / 폴드 건강 게이트
- **EXP5 (보조)** 노출 규칙(최소 8종목 보유 등)으로 퇴화 원인(과도한 현금/0노출) 차단

**(d) PASS 조건**
- 퇴화 폴드 개수 **0** (또는 전체 폴드의 5% 이하)  
- 각 폴드에서 최소 거래 수/리밸런스 수/보유 종목 수가 기준 이상(아래 EXP1 게이트 참조)
- OOS 성능이 하락하더라도(가능) 지표가 **재현 가능**하고 fold별 편차가 급감(과최적화 신호 감소)

---

### 3) (서바이버십/데이터 무결성) PIT(시점고정) + corporate action + delist 반영 강제
**(a) 왜 필요한지**
- Tech/Healthcare 단일주 중심(8~14) 전략은 **개별 종목 이벤트/상장폐지/합병**에 매우 취약.
- PIT 미준수(예: 실적/가이던스 발표시점 누수) 또는 생존자 편향은 “OOS 평균 고정/불동”을 만들거나 가짜 안정성을 만든다.

**(b) 위험/부작용**
- PIT 데이터 소스/정합성 비용 증가, 결측 증가로 신호 약화 가능.
- delist 반영 시 과거 수익률 악화(정상).

**(c) 최소 실험**
- **EXP2 (필수)** PIT/서바이버십/조정주가 일괄 검증 + “누수 탐지용 음성 테스트(랜덤 시프트)” 추가
- **EXP1 (보조)** 폴드별 데이터 커버리지/결측률 로깅 강화

**(d) PASS 조건**
- “발표일 이전 데이터 사용” 탐지 규칙 위반 0건(피처 timestamp 검증)
- delist 포함 유니버스에서 백테스트가 동일 파이프라인으로 끝까지 완료
- 랜덤 시프트(예: 피처 +5영업일 이동)에서 성능이 **유의미하게 붕괴**(누수 없음의 간접 증거)

---

### 4) (비용 미반영) 슬리피지/스프레드/회전율을 1급 지표로 끌어올려 “실전 성능 고착” 제거
**(a) 왜 필요한지**
- 개별주 8~14종목은 리밸런스 때 체결비용이 성능을 잡아먹기 쉬움.
- 비용 미반영은 “백테스트는 좋은데 실전/워크포워드는 안 움직임”의 대표 원인.

**(b) 위험/부작용**
- 비용 모델을 넣으면 과거 성능 급락 가능(정상).
- 거래 감소(턴오버 제한)로 기회 손실 가능.

**(c) 최소 실험**
- **EXP3 (필수)** 비용 모델(스프레드+슬리피지+수수료) + 턴오버 캡을 학습/평가에 동시 반영
- **EXP5 (보조)** 포지션 스무딩(리밸런스 임계값/부분 리밸런스)로 회전율 억제

**(d) PASS 조건**
- 비용 차감 후 OOS mean이 기존 대비 크게 악화되지 않거나(목표: -X% 이내) **변동성이 감소**  
- turnover/거래횟수/총비용이 상한 이내(아래 EXP3 게이트)
- 비용 포함/미포함 성능의 괴리가 리포트로 항상 출력(숨김 금지)

---

### 5) (노출/레짐) “Tech+Healthcare 8~14종목” 제약 하에서 노출/레짐 게이트를 추가해 불안정·고착을 분리
**(a) 왜 필요한지**
- 현재 `exposure_max ~0.84`이고 min 0 → 어떤 구간에선 0노출/저노출로 “성능이 안 움직이는 구간”이 생길 수 있음.
- 레짐(금리/리스크온오프)에 따라 Tech/HC의 팩터 민감도가 달라져 **동일 신호가 무력화**될 수 있음.
- ETF는 매매 금지이므로 **관측 지표로만** QQQ/XLV/XLK, IHI 등(관측용) 사용.

**(b) 위험/부작용**
- 레짐 게이트가 과도하면 거래가 줄어 수익 기회 감소(서바이버십처럼 보이는 착시 가능).
- 규칙이 늘면 과최적화 위험(그래서 EXP 수를 제한).

**(c) 최소 실험**
- **EXP5 (필수)** 보유 종목 수(8~14) 강제 + 최소 노출 하한 + 변동성 타깃/리스크오프 게이트(ETF는 신호 관측만)
- **EXP3 (보조)** 레짐에서 거래비용/스프레드 확대로 비용 민감도 함께 체크

**(d) PASS 조건**
- 항상 보유 종목 수 8~14 준수(현금 과다/0노출 구간 제거)
- 레짐별(리스크온/오프) 성능 분해 리포트에서 특정 레짐만 과도하게 망가지는 현상이 완화
- max drawdown/worst-case 지표가 산출되고(None 금지), 게이트 위반 시 자동 중단

# 48시간 자동 루프용 “공통 실험 5개(고정)” 정의
아래 5개만 실행/반복하고, TOP5 제안은 이 실험들을 참조하여 패치한다.

---

## EXP1) 누수 차단 + 폴드 건강(퇴화 방지) 워크포워드
1) **실험 정의**
- Walk-forward split에 **purge(lookback만큼 제거)** + **embargo(거래 지연 구간 제거)** 적용
- 폴드별로: 샘플 수, 거래 수, 보유 종목 수, 결측률, 0노출 비중을 자동 산출/저장

2) **게이트(실패 시 런 폐기)**
- `degenerate_folds == 0`
- 각 폴드 거래 수 ≥ N, 평균 보유 종목 수 ≥ 8, 0노출 일수 비중 ≤ 5%
- 피처 timestamp가 target 이후를 참조하면 즉시 fail(룰 기반 검사)

3) **기대 관측치**
- OOS mean이 단기 하락해도 fold 간 분산 감소, 재현성↑
- “좋아 보이던 개선”이 사라지면 누수/퇴화가 원인이었음이 확인됨

---

## EXP2) PIT/서바이버십/조정주가+delist 검증 + 음성(누수) 테스트
1) **실험 정의**
- fundamental/이벤트 피처는 **as-of date** 강제(PIT)
- split/dividend 반영(조정주가), delist(상폐) 포함 수익률 처리
- 음성 테스트: 피처를 +5영업일 시프트하여 성능이 붕괴하는지 확인

2) **게이트**
- “발표일 이전 사용” 위반 0건
- delist 포함 백테스트 완주(중간 결측으로 크래시 금지)
- 음성 테스트에서 성능이 유의하게 악화(누수 의심 시 fail)

3) **기대 관측치**
- 성능이 내려가더라도 실전 일관성↑
- 특정 종목/기간에서만 발생하는 이상치(합병/상폐) 원인이 표면화

---

## EXP3) 비용/체결 모델 + 턴오버 캡을 학습/평가에 반영
1) **실험 정의**
- 거래비용 = (스프레드 기반 + 고정 bp 슬리피지 + 수수료)로 통합
- 턴오버 상한 및 리밸런스 임계값(변경 폭이 작으면 미체결) 옵션 제공
- 비용 전/후 성능, 총비용, 평균 스프레드(관측치)를 리포트로 저장

2) **게이트**
- 월/연 turnover 상한 준수
- 비용 차감 후에도 전략이 “항상 현금/항상 매수” 같은 극단으로 붕괴하면 fail
- 비용/거래 로그가 누락되면 fail

3) **기대 관측치**
- “백테스트는 좋은데 실전은 무덤덤” 원인이 비용이면, 비용 반영 후 성능이 설명 가능해짐(괴리 축소)

---

## EXP4) 아티팩트/로그 스키마 표준화 + rebalance pinpoint 복구
1) **실험 정의**
- 모든 런이 동일 스키마로 `rebalance.jsonl`, `metrics.json`, `positions_daily.parquet`, `config_resolved.json` 저장
- `lane_hash/run_hash` 필수, `worst_mdd` 필수 계산
- `aub_rebalance_pinpoint` 입력을 **단일 포맷**으로 고정(자동 변환 레이어 포함)

2) **게이트**
- 파일 누락 시 fail
- `rebalance_pinpoint.md` 생성 실패 시 fail
- champion/candidate 비교가 같은 키(lane_hash 등)로 join 불가하면 fail

3) **기대 관측치**
- “성능 불동(no-delta)”에서 **어느 구간/어느 리밸런스/어느 비용** 때문인지 즉시 추적 가능

---

## EXP5) 노출/보유 종목 수(8~14) 강제 + 레짐 관측(ETF는 지표만) + 리스크 오버레이
1) **실험 정의**
- 유니버스: **미국주식 only**, Tech+Healthcare에서 8~14개만 보유(개별주)
- 최소/최대 노출 하한/상한(예: 0.6~0.95) + 변동성 타깃(간단한 스케일링)
- 레짐 관측: QQQ/XLV/XLK(매매 금지)로 리스크온/오프 태그만 생성 → 성능을 레짐별로 분해 저장

2) **게이트**
- 보유 종목 수 8~14 위반 0회
- 0노출 일수 비중 ≤ 5%
- 레짐 태깅 실패/결측 시 fail

3) **기대 관측치**
- “안 움직이는 구간”이 (i) 0노출 때문인지 (ii) 레짐 불일치 때문인지 분리됨
- 레짐별 성능 편차가 큰 경우, 전략 신호가 특정 국면에서만 유효함이 드러남

---

# 성능이 안 움직일 때(“no-delta”) 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래 트리를 **리포트 항목으로 강제 출력**하라(질문 금지, 자동 산출).

## A. 트리거(신호 발생) 문제
- **신호 발생 빈도**(일/주당) 출력 → 0에 수렴하면 “신호가 죽음”
- 피처 결측률/상수화 비율(분산≈0) 출력 → 데이터 파이프 문제 탐지
- 음성 테스트(피처 시프트)로 누수 여부 간접 판정(EXP2)

## B. 적용(리밸런스/주문/제약) 문제
- 리밸런스 이벤트 수/실제 체결 수/제약으로 무산된 주문 수를 분리 출력(EXP4)
- 임계값(리밸런스 밴드) 때문에 “거의 안 바뀌는 포트폴리오”인지 확인(EXP3/5)

## C. 노출(포지션/현금/집중) 문제
- 일별 gross/net exposure, 현금 비중, 보유 종목 수(8~14 준수) 출력(EXP5)
- 상위 1~3종목 집중도(HHI) 출력 → 단일종목이 움직이지 않아 정체되는지 확인

## D. 비용(거래비용/슬리피지) 문제
- 비용 전/후 PnL 차이를 일별로 분해(EXP3)
- “거래로 번 돈보다 비용이 더 큰 구간”을 플래그 처리

## E. 레짐(시장 국면) 문제
- 레짐 태그(리스크온/오프)별 성능/승률/드로우다운 분해(EXP5)
- Tech/Healthcare 내부에서도 레짐 민감도가 다르면: 섹터 내 하위그룹(대형/중소형, 수익/성장) 노출을 관측 지표로만 기록(매매는 개별주 유지)

---

## 즉시 실행 순서(명령형 체크리스트)
1) **EXP4부터 머지**: 로그/스키마 고정 + `rebalance_pinpoint` 0에러 달성(운영 리스크 제거)
2) **EXP1 적용**: purge/embargo + 폴드 건강 게이트로 degenerate_folds=0 만들기(누수/과최적화 1차 차단)
3) **EXP2 적용**: PIT/서바이버십/delist + 음성 테스트로 데이터 무결성 확정
4) **EXP3 적용**: 비용/턴오버를 성능 평가의 1급 지표로 승격
