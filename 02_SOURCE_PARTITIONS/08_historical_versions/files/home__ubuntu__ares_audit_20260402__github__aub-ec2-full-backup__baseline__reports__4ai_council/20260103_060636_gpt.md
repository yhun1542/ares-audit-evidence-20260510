## 24~48시간 TOP5 우선순위(코드/아키텍처/전략) — 명령형 체크리스트

# 1) **아티팩트/로그/메트릭 무결성 복구(운영 리스크 1순위)**
### (a) 왜 필요한지
- 현재 Champion에 `file/lane_hash/run_hash=None`, `worst_mdd=None` → **재현 불가 + 성능 판단 불가**.
- `rebalance_pinpoint`가 `--base-log` 경로/JSON 파싱 실패 → **리밸런스·턴오버·비용 원인 추적이 막힘**.
- “성능이 안 움직임”은 종종 **실제 성능이 아니라 관측/로그 파손**에서 시작함.

### (b) 위험/부작용
- 로그 포맷 변경 시 기존 리포트/대시보드 파서 깨짐.
- 무결성 게이트가 강화되면 단기적으로 “유효 실험 수” 감소.

### (c) 최소 실험 2~3개(※ 1개 잡으로 변형 2~3개 동시 비교)
**실험 정의(1잡): `exp_logging_contract_v1`**
- Variant A: 현행 유지 + **필수 필드 강제 채움**(file/lane_hash/run_hash/worst_mdd/equity_curve_digest)
- Variant B: 리밸런스 로그를 **CSV+JSONL 동시 저장**(schema 고정) + 파서 호환 레이어
- Variant C: 실험 종료 시 **artifact registry(manifest.json)** 생성(입력데이터 해시, 유니버스, 비용모델, 시드)

**게이트(자동 실패 조건)**
- `Champion file == None` 또는 `lane_hash/run_hash == None` 이면 FAIL
- `worst_mdd`/`turnover`/`cost_breakdown` 중 1개라도 NaN/None이면 FAIL
- `rebalance.csv` 또는 `rebalance.jsonl` 미생성 시 FAIL
- `degenerate_folds`가 계산 자체 안 되면 FAIL

**기대 관측치**
- 진단툴(`no_delta_diagnoser`, `rebalance_pinpoint`)이 **0 에러로 완료**
- 모든 실험이 “동일 재현(run_hash로 재실행 시 결과 일치)” 가능

### (d) PASS 조건
- 최근 3개 실험 연속으로 **리밸런스 로그/메트릭 100% 생성** + 진단툴 에러 0건
- `worst_mdd` 산출 및 equity curve 저장 확인

# 2) **누수(Leakage)/시점 정합성(Time alignment) 최우선 점검**
### (a) 왜 필요한지
- OOS가 “안 움직이거나” “이상하게 안정적”일 때 누수/시점 오류가 가장 흔한 원인.
- 특히 리밸런스 기준가/체결가/시그널 생성 시점이 섞이면 **OOS가 무의미**해짐.

### (b) 위험/부작용
- 누수 제거 후 성능 급락 가능(하지만 그게 정상).
- 시점 보정으로 거래 타이밍이 바뀌며 turnover/비용 증가 가능.

### (c) 최소 실험 2~3개(※ 1개 잡으로 변형 3개 동시 비교)
**실험 정의(1잡): `exp_time_alignment_audit_v1`**
- Variant A: 시그널은 **t일 종가 데이터로 생성 → t+1일 시가(또는 VWAP) 체결** 강제
- Variant B: 모든 피처 join을 **asof join(<=t)** 로 강제 + “미래행 사용 카운트” 로깅
- Variant C: 레이블/수익률 계산을 **close-to-close vs open-to-close** 2종으로 분리 로깅(누수 징후 탐지용)

**게이트**
- “미래행 사용 카운트” > 0 이면 FAIL
- 피처 타임스탬프가 가격 타임스탬프보다 미래면 FAIL
- OOS에서 fold별 **degenerate_folds 증가**가 2 이상이면 FAIL(시점 보정으로 트리거가 죽는 케이스)

**기대 관측치**
- 누수 의심 지표(미래행 카운트)가 0으로 수렴
- OOS mean이 단기 하락하더라도, **oos_min/분산/턴오버/비용**이 설명 가능해짐

### (d) PASS 조건
- 미래행/미래타임스탬프 0건
- 동일 데이터에서 체결시점 변경(Variant A) 시 성능이 “극단적으로” 붕괴하지 않음(=기존이 누수였던 신호가 아님)

# 3) **서바이버십/코퍼레이트 액션/상장폐지 반영(미국주식 필수)**
### (a) 왜 필요한지
- US 단일종목 백테스트에서 **상장폐지/인수합병/티커 변경/분할/배당** 누락은 성능·리스크를 왜곡.
- Tech+Healthcare는 이벤트가 잦아 “평소엔 안 티 나다가 특정 구간에서 성능이 멈추는” 형태로 나타남.

### (b) 위험/부작용
- 데이터 소스에 따라 delisting return이 없어 보수적으로 처리하면 성능 하락.
- 과도한 보정은 거래가능성(유동성) 필터와 충돌.

### (c) 최소 실험 2~3개(※ 1개 잡으로 변형 2~3개 동시 비교)
**실험 정의(1잡): `exp_corpaction_survivorship_v1`**
- Variant A: 가격을 **split/dividend adjusted**로 통일 + 원시/조정 가격 혼용 금지 체크
- Variant B: 상장폐지 시 **delisting return(있으면 적용)**, 없으면 **보수적 페널티(-30%~-100% 구간 정책)** 2안 비교 로깅
- Variant C: “현재 존재 티커만 선택” 방지: 유니버스(8~14)는 고정하되, **백테스트 시작 시점에 이미 존재했던 티커만** 사용하도록 룰 고정(시점 기반 포함)

**게이트**
- 조정/비조정 혼용 탐지 시 FAIL
- delisting 이벤트 발생 시 리턴 처리 경로가 “None”이면 FAIL
- 티커 변경 매핑 누락 발견 시 FAIL

**기대 관측치**
- 특정 구간(이벤트)에서 equity curve가 “끊기거나” NaN이 되는 현상 제거
- 극단 수익/손실이 데이터 이슈인지 전략 이슈인지 분리 가능

### (d) PASS 조건
- 전 기간 결측/끊김 0건
- 이벤트 구간에서 거래/평가가 지속되고, 비용/수익 계산이 일관

# 4) **비용(슬리피지/스프레드/차입)/턴오버 현실화 + 비용 분해**
### (a) 왜 필요한지
- “OOS mean이 안 움직임”은 종종 **비용이 신호를 잠식**하거나, 반대로 **비용을 아예 안 넣어서 실험 간 차이가 사라지는** 문제.
- 특히 리밸런스 로그가 없던 상태라 비용-성과 연결이 끊겨 있음.

### (b) 위험/부작용
- 비용을 현실화하면 성능 하락(정상).
- 숏(있다면) 차입비용/하드투보로우 반영 시 전략이 사실상 불가 판정 날 수 있음.

### (c) 최소 실험 2~3개(※ 1개 잡으로 변형 3개 동시 비교)
**실험 정의(1잡): `exp_cost_model_v2`**
- Variant A: 고정 슬리피지(bps) + 커미션 기본형(현행 대체)
- Variant B: **거래대금 대비 참여율(participation) 기반 슬리피지**(ADV 사용) + 스프레드 절반
- Variant C: (숏 존재 시) **borrow fee + locate 실패 시 대체 규칙(현금/롱만 유지)**

**게이트**
- 일평균 turnover가 상한(예: 30~50%/day) 초과 시 FAIL
- 비용 차감 후 `oos_mean`이 비용 미차감 대비 “거의 동일”하면 FAIL(=비용이 계산에 반영 안 된 버그 의심)
- 거래 체결가격이 신호 생성 시점과 동일 봉이면 FAIL(누수/룩어헤드 재의심)

**기대 관측치**
- `gross_return`, `cost`, `net_return` 3분해가 리포트에 고정 출력
- 실험 간 차이가 “비용 항”에서 설명되기 시작(=정체 원인 분해 가능)

### (d) PASS 조건
- 비용 분해 리포트가 리밸런스 단위로 재현 가능
- 비용 모델 B에서 성능이 급락하더라도, turnover/참여율 지표가 함께 움직여 설명 가능

# 5) **트리거/적용/노출(Exposure) 안정화: degenerate fold 제거 + 포지션 규칙 단순화**
### (a) 왜 필요한지
- 현재 `degenerate_folds: [1,2,3,8]` → 폴드 다수가 **거래 0 / 포지션 0 / 신호 무효** 가능성이 큼.
- `exposure_min/max: 0.0 / 0.8388` → 현금 비중이 커질 수 있고, 실험 간 차이가 희석되어 “안 움직임”으로 보일 수 있음.

### (b) 위험/부작용
- 강제 노출/강제 거래는 과최적화/리스크 증가로 이어질 수 있음.
- 포지션 규칙 변경은 전략의 본질을 바꿔 비교가 어려워짐(그래서 **최소 패치**로 제한).

### (c) 최소 실험 2~3개(※ 1개 잡으로 변형 3개 동시 비교)
**실험 정의(1잡): `exp_trigger_exposure_stability_v1`** *(미국주식, Tech+Healthcare 8~14 종목, ETF 매매 금지 유지)*
- Variant A: 진입 임계값을 **분위수 기반(상위 K개 고정 선택)** 으로 변경(거래 0 방지)
- Variant B: 포지션 사이징에 **노출 하한(예: 30%)** + 상한(예: 90%) 클램프(현금 과다 방지)
- Variant C: 리밸런스 빈도(예: 2일/5일) 2안 비교 + turnover/비용 동시 로깅

**게이트**
- 폴드별 거래횟수 < 최소치(예: 5~10 trades/fold)면 FAIL
- `degenerate_folds` 개수 0이 아니면 FAIL(최소한 줄어야 함)
- 노출 하한 도입 후 `worst_mdd`가 계산 불가/NaN이면 FAIL

**기대 관측치**
- fold별 거래수가 안정적으로 발생
- 실험 간 차이가 “트리거→포지션→노출→비용” 경로로 관측됨(정체 해소)

### (d) PASS 조건
- `degenerate_folds`가 0(또는 기존 대비 -80% 이상 감소)
- 노출이 0으로 장기간 고정되는 구간 제거
- OOS min(바닥 성능)이 악화되지 않거나, 악화 시 비용/노출 변화로 설명 가능

## 48시간 자동 루프 운영 형태(공통 실행 지침)
- **T+0~6h:** 위 5개 실험을 “각 1잡(variant 포함)”으로 큐에 등록
- **T+6~24h:** 게이트 FAIL 실험은 자동 중단/리포트만 저장(승격 금지)
- **T+24~48h:** PASS 실험만 챔피언 후보로 재평가(단, 누수/서바이버십/비용 PASS 선행)

## 성능이 “안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래를 **순서대로** 분해(앞단이 깨지면 뒷단은 무의미):

1) **트리거(신호 발생)**
- 체크: 신호 분포(평균/분산), 상위K 점수 간격, “신호 0/NaN 비율”
- 트리거 정체 징후: 신호가 대부분 0/클리핑, 특정 구간만 활성, 폴드별 신호 스케일이 다름
- 조치: 분위수 선택(Top-K), 시그널 표준화(rolling zscore) 후 분포 로깅

2) **적용(주문/체결/리밸런스)**
- 체크: 신호→주문까지 1바 이상 지연이 있는지, 리밸런스 캘린더가 실제로 실행되는지
- 적용 정체 징후: 신호는 변하는데 포지션이 안 변함(주문 스킵/체결 실패/리밸런스 로그 없음)
- 조치: rebalance 로그 강제, “왜 주문이 스킵됐는지(reason code)” 기록

3) **노출(포지션/리스크)**
- 체크: 총 익스포저(0~1), 섹터/종목 집중도, 베타(대형 Tech에 과쏠림 여부)
- 노출 정체 징후: 현금 비중 과다, 상한 규칙 때문에 포지션이 항상 동일, 특정 종목만 고정 보유
- 조치: 노출 하한/상한 클램프, 상위K 고정 선택, 최대 종목 비중 제한

4) **비용(슬리피지/스프레드/차입/세금은 옵션)**
- 체크: gross vs net 차이, turnover와 cost의 상관, 비용이 항상 0으로 찍히는지
- 비용 정체 징후: 실험 변경에도 net이 gross와 동일(비용 미반영 버그), 혹은 turnover만 늘고 net이 평평
- 조치: 비용 3분해(gross/cost/net) 고정 출력, ADV 참여율 기반 슬리피지

5) **레짐(시장 환경)**
- 체크(관측지표로만 ETF/인덱스 사용): QQQ/XLV(매매 금지, 지표만), VIX, 10Y 금리, SPX 추세
- 레짐 정체 징후: 모든 실험이 동일하게 죽는 구간(예: 변동성 급증/금리 급등)
- 조치: 레짐 라벨(저/고 변동, 금리 상승/하락) 붙여 OOS를 조건부로 분해 리포트

## 실행 우선순위(실제 48시간 내 “승격” 순서)
1) **#1 로깅/메트릭 무결성** PASS 없이는 다음 단계 승격 금지  
2) **#2 누수/시점 정합성** PASS 없이는 성능 해석 금지  
3) **#3 서바이버십/코퍼액션** PASS 없이는 장기 OOS 해석 금지  
4) **#4 비용모델/비용분해** PASS 후에만 전략 튜닝  
5) **#5 트리거/노출 안정화**는 위 1~4 PASS 이후에만 챔피언 후보 평가

위 5개를 그대로 “자동 루프(실험 정의→게이트→기대 관측치)”로 넣으면, 지금 상태에서 가장 큰 병목(로그 파손/degenerate fold/비용 미분해)부터 제거하면서 성능 정체의 원인을 단계적으로 고립시킬 수 있음.
