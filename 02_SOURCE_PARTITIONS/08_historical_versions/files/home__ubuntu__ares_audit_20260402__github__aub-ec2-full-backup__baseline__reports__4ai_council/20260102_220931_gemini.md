[진단 요약]
현재 시스템은 **"데이터/메트릭 무결성 붕괴"** 상태입니다. `worst_mdd: None`과 `degenerate_folds: [1, 2, 3, 8]`은 백테스트 엔진이 특정 기간 동안 거래를 전혀 하지 않았거나(Silent Failure), 수익률 계산 로직이 NaN을 반환하고 있음을 시사합니다. 로그 파일 로딩 실패(`Errno 2`, `Expecting value`)로 인해 분석 도구마저 마비되었습니다. 전략 개선보다 **파이프라인 복구**가 최우선입니다.

### 1. 우선순위 TOP 5 (24~48시간 내)

1.  **[CRITICAL] 로그/데이터 파이프라인 정규화:** `rebalance.csv` 누락 및 JSON 파싱 에러 즉시 수정. 관측 불가능하면 개선 불가능.
2.  **[CRITICAL] MDD 계산 로직 디버깅:** `None` 반환 원인(거래 0건 또는 데이터 결측) 파악 및 수정.
3.  **[HIGH] Degenerate Folds(1,2,3,8) 해소:** 4개 Fold가 실패하는 원인(유동성 필터 과다, 데이터 누락) 제거를 위한 제약 완화.
4.  **[MED] 실행 비용(Slippage/Commission) 강제 주입:** OOS Mean 3.32(비정상적 고수익)가 비용 0 가정에서 온 것인지 검증.
5.  **[MED] 유니버스 생존 편향 점검:** 현재 유니버스가 2026년 시점에 상장 폐지된 종목을 포함하는지, 혹은 미래 시점의 우량주만 포함하는지 검증.

### 2. 실행 가능한 제안 (Actionable Patches)

#### 제안 A: 로그 포맷 통일 및 강제 생성 (Infrastructure Fix)
*   **왜 필요한가:** `AUB Rebalance Pinpoint`가 실패하여 전략이 왜, 언제 매매했는지 분석 불가.
*   **위험/부작용:** 로깅 오버헤드로 인한 백테스트 속도 저하(미미함).
*   **실험 정의:**
    1.  `Exp_Log_Fix_CSV`: `rebalance` 로그를 CSV 포맷으로 강제 저장하고 경로 하드코딩 확인.
    2.  `Exp_Log_Fix_JSONL`: JSONL 포맷 저장 시 `flush()` 강제 호출 및 인코딩 UTF-8 명시.
    3.  `Exp_Verify_Path`: 출력 디렉토리가 존재하지 않을 경우 `os.makedirs(exist_ok=True)` 추가.
*   **PASS 조건:** `aub_rebalance_pinpoint.py` 실행 시 에러 없이 리포트 생성 & 파일 용량 > 0KB.
*   **기대 관측치:**
    *   (1) 실험 정의: Logging Handler Patch
    *   (2) 게이트: Log File Exists & Parse Success
    *   (3) 관측: Rebalance History 시각화 가능

#### 제안 B: Degenerate Folds 탈출을 위한 '느슨한 제약' (Stability Fix)
*   **왜 필요한가:** Fold 4개가 터졌는데 OOS Mean이 높은 것은, 특정 Fold에서의 과최적화(Overfitting) 혹은 데이터 오류(Look-ahead)를 의미함.
*   **위험/부작용:** 수익률(OOS Mean)의 급격한 하락 가능성.
*   **실험 정의:**
    1.  `Exp_Relax_Liq`: 유동성(Volume) 필터 상위 30% -> 상위 70%로 완화 (거래 기회 확보).
    2.  `Exp_No_Hedge`: `hedge_025` 로직(인버스 ETF 등)을 일시 제거하고 Long-Only로 Degenerate 여부 확인.
    3.  `Exp_Min_Stocks`: 포트폴리오 최소 편입 종목 수를 8에서 4로 일시 축소 (종목 부족으로 인한 거래 실패 방지).
*   **PASS 조건:** `degenerate_folds` 리스트가 빈 배열 `[]`이 되거나 개수가 1개 이하로 감소.
*   **기대 관측치:**
    *   (1) 실험 정의: Constraint Relaxation
    *   (2) 게이트: Degenerate Folds == 0
    *   (3) 관측: OOS Mean 하락(정상화), MDD 값 생성됨.

#### 제안 C: 비용 스트레스 테스트 (Reality Check)
*   **왜 필요한가:** OOS Mean 3.32는 현실적이지 않음. 슬리피지/수수료 미반영 의심.
*   **위험/부작용:** 전략 폐기(전략이 비용을 이기지 못함).
*   **실험 정의:**
    1.  `Exp_Cost_5bps`: 매매당 수수료+슬리피지 5bps(0.05%) 적용.
    2.  `Exp_Cost_10bps`: 매매당 10bps(0.10%) 적용.
    3.  `Exp_Entry_Delay`: 진입 시그널 발생 후 '다음 날 시가(Next Open)' 대신 '다음 날 종가' 혹은 '슬리피지 포함가'로 체결 가정.
*   **PASS 조건:** OOS Mean > 0.5 (여전히 수익권 유지) AND MDD < -0.2 (20% 이내 방어).
*   **기대 관측치:**
    *   (1) 실험 정의: Cost Injection
    *   (2) 게이트: Sharpe Ratio > 1.0
    *   (3) 관측: OOS Mean 대폭 하락 예상, 현실적 기대 수익률 도출.

### 3. 성능 정체 시 원인 분해 (Debugging Logic)

성능 지표가 움직이지 않거나(0 또는 NaN), `degenerate`가 해결되지 않을 때 다음 체크리스트를 순차 수행하십시오.

1.  **트리거(Trigger) 확인:**
    *   *증상:* 매매 횟수 0.
    *   *점검:* 시그널 생성 임계값(Threshold)이 너무 높지 않은가? (예: `score > 0.99` -> `0.80`으로 완화)
    *   *데이터:* 입력 데이터(Tech/Healthcare Ticker)의 가격 데이터가 해당 Fold 기간에 존재하는가?

2.  **노출(Exposure) 확인:**
    *   *증상:* Exposure Max가 0.84에 머뭄.
    *   *점검:* 현금 비중이 강제로 설정되어 있는가? 혹은 헷지(Hedge) 포지션이 포트폴리오 순노출을 갉아먹고 있는가?
    *   *액션:* `target_exposure = 1.0` 설정 확인.

3.  **레짐(Regime) 불일치:**
    *   *증상:* 특정 연도(Fold 1,2,3,8)에만 실패.
    *   *점검:* 해당 시기(예: 2022년 하락장)에 Long-Only 전략이 손절매(Stop-loss)에 의해 모든 자산을 현금화하고 거래를 멈췄는가?
    *   *액션:* Stop-loss 로직을 "청산 후 일정 기간 대기"가 아닌 "비중 축소"로 변경.

4.  **운영 리스크(Op Risk - Data):**
    *   *증상:* `worst_mdd: None`.
    *   *점검:* 수익률 배열에 `NaN`이나 `Inf`가 하나라도 있으면 전체 집계가 실패함.
    *   *액션:* `fillna(0)` 처리 후 메트릭 계산 수행.
