### 3. 성과 정체 시 원인 분해 (Debugging Logic)

성능이 움직이지 않거나(flat), 개선되지 않을 때 다음 트리를 따라 디버깅할 것.

**A. 트리거(Trigger) 확인:**
*   *증상:* 거래 횟수 0 또는 극도로 적음.
*   *체크:* `Entry Threshold`가 너무 높은가? `Stop Loss`가 너무 타이트해서 진입하자마자 청산되는가?
*   *액션:* Threshold를 0으로 설정하여 모든 시그널에 대해 매매가 일어나는지 'Dummy Run' 수행.

**B. 적용(Execution) 확인:**
*   *증상:* 시그널은 있는데 포트폴리오 비중이 안 변함.
*   *체크:* `Rebalance Frequency`가 데이터 주기와 맞는가? (예: 일간 데이터인데 월간 리밸런싱 설정 등)
*   *액션:* 리밸런싱 로그에서 `Target Weight` vs `Actual Weight` 델타 확인.

**C. 레짐(Regime) 불일치:**
*   *증상:* 특정 연도(Fold)에서만 수익이 폭발하고 나머지는 손실.
*   *체크:* `Degenerate Folds`와 겹침. 2022년(하락장)이나 2020년(코로나) 등 특정 매크로 환경에서 로직이 붕괴됨.
*   *액션:* 매크로 변수(VIX, 금리 등)를 피처로 추가하거나, Regime 별로 파라미터를 이원화(Switching Model).

**D. 데이터(Survivorship) 확인:**
*   *증상:* 백테스트는 좋은데 최근 데이터에서 박살남.
*   *체크:* 현재 상장 폐지된 종목이 과거 데이터에 포함되어 있는지(Survivorship Bias Free), 혹은 합병/분할 데이터가 수정 주가(Adj Close)에 반영되었는지.
*   *액션:* `volume == 0` 인 데이터 포인트가 있는지 전수 조사.
