[절대 규칙 준수: 명령형 체크리스트 및 48시간 루프 제안]

### 1. 24~48시간 우선순위 TOP 5 제안

**P1. [INFRA] 결측 지표(MDD None) 및 로그 파이프라인 긴급 복구**
*   **(a) 이유:** `worst_mdd: None`은 리스크 계산 로직이 붕괴되었음을 의미. MDD를 모르면 전략 폐기 여부를 결정할 수 없음. 또한 `rebalance.csv` 파싱 에러로 인해 거래 내역 분석이 불가능한 상태(Blind Flying).
*   **(b) 위험:** 로직 수정 시 과거 성과 수치가 급락할 가능성(버그가 수익률을 뻥튀기했을 수 있음).
*   **(c) 실험 (Experiments):**
    1.  `fix_metrics_calc`: 수익률 시계열의 NaN/Inf 처리 로직 강화 후 MDD 재계산.
    2.  `log_format_patch`: JSONL/CSV 저장 시 인코딩 및 delimiter 강제 지정.
    3.  `dry_run_integrity`: 1개월분 데이터로 리밸런싱 로그 생성 후 파서(Parser) 호환성 테스트.
*   **(d) PASS 조건:** `worst_mdd`가 유효한 음수 값(예: -0.15)으로 출력됨 AND `aub_rebalance_pinpoint.py`가 에러 없이 리포트 생성.

**P2. [COST] 슬리피지/비용 가중치 스트레스 테스트 (Slippage Injection)**
*   **(a) 이유:** 현재 OOS Mean(1.88)과 이전 챔피언(2.62)의 괴리는 과최적화 혹은 비용 과소평가 가능성 시사. Tech/Bio 종목(8-14개)의 변동성을 고려할 때, 슬리피지 반영 시 승률이 급감하는지 확인 필수.
*   **(b) 위험:** 전략의 기대 수익률(Sharpe/CAGR)이 대폭 하락하여 현재 챔피언이 탈락할 수 있음.
*   **(c) 실험 (Experiments):**
    1.  `cost_bps_10`: 왕복 비용 10bps 적용 시 OOS 성과 측정.
    2.  `cost_bps_25`: 왕복 비용 25bps 적용(보수적) 시 OOS 성과 측정.
    3.  `execution_delay`: 시그널 발생 후 '다음 봉 시가' 체결 로직 강제 확인.
*   **(d) PASS 조건:** 25bps 적용 시에도 `oos_mean` > 1.0 유지 AND `oos_min` > 0.

**P3. [UNIVERSE] 유동성 필터 및 섹터 편향 점검 (Survivorship Check)**
*   **(a) 이유:** Tech+Healthcare 8~14개 종목 제한 환경에서, 거래량이 적은 소형 바이오주가 포함되어 수익률을 왜곡시켰는지 확인 필요.
*   **(b) 위험:** 유니버스 축소로 인해 분산 효과 감소, MDD 증가 가능성.
*   **(c) 실험 (Experiments):**
    1.  `filter_liq_50m`: 일평균 거래대금 $50M 미만 종목 배제 후 백테스트.
    2.  `sector_balance`: Tech와 Healthcare 비중을 최소 3:7 ~ 7:3 범위로 강제하는 제약 조건 추가.
*   **(d) PASS 조건:** 유동성 필터 적용 후에도 OOS 수익률 하락폭이 15% 이내일 것.

**P4. [LOGIC] 변동성 타겟팅(Exposure) 민감도 조정**
*   **(a) 이유:** 현재 Exposure가 0.47~0.84로 변동 폭이 큼. 하락장에서 노출을 줄이는 것이 실제 방어가 되는지, 아니면 단순한 기회비용 손실인지 검증 필요.
*   **(b) 위험:** 노출 범위 축소 시 급등장에서의 Upside Capture 능력 저하.
*   **(c) 실험 (Experiments):**
    1.  `exposure_static_09`: 변동성 조절 끄고 고정 노출 0.9로 설정.
    2.  `exposure_clamp_60_100`: 노출 하한을 0.6으로 상향 (과도한 쫄보 모드 방지).
*   **(d) PASS 조건:** `exposure_clamp` 모델의 Calmar Ratio가 현재 챔피언보다 높을 것.

**P5. [FEAT] 팩터 단순화 (Feature Pruning)**
*   **(a) 이유:** OOS 성능 차이가 발생했다는 것은 특정 피쳐가 최근 데이터에서 작동하지 않음을 의미. 과적합된 복잡한 피쳐 제거.
*   **(b) 위험:** 정보 손실로 인한 예측력 저하.
*   **(c) 실험 (Experiments):**
    1.  `feat_top5_only`: 중요도 상위 5개 팩터(모멘텀/변동성 위주)만 사용.
    2.  `feat_remove_interaction`: 상호작용 항(Interaction terms) 제거하고 선형 팩터만 유지.
*   **(d) PASS 조건:** 팩터 수를 절반으로 줄여도 OOS Mean이 기존 대비 90% 이상 유지될 것.

### 2. 실행 루프 설계 (48시간 자동화)

**Loop Cycle: 48h**

**(1) 실험 정의 (Experiment Definition)**
- **Baseline:** `run_champion_v5_latest` (복구된 버전)
- **Variants:**
    - `exp_A`: Cost 20bps + Delay Execution (비용 현실화)
    - `exp_B`: Min Liquidity $50M + Top 10 Tickers (유니버스 건전성)
    - `exp_C`: Exposure Clamp [0.6, 1.0] (적극적 투자)

**(2) 게이트 (Gate - Deployment Criteria)**
- **Critical:** `worst_mdd` != None (필수)
- **Performance:** `Variant OOS Mean` >= `Baseline OOS Mean` * 0.95 (비용 반영 후에도 성능 유지 시 합격)
- **Risk:** `Variant OOS Min` > 0.3 (최악의 구간에서도 방어력 입증)

**(3) 기대 관측치 (Expected Observations)**
- `rebalance.csv`가 정상 생성되어 `aub_rebalance_pinpoint` 도구가 작동해야 함.
- 비용 반영(`exp_A`) 시 성능이 20% 이상 급락한다면 현재 전략은 '과최적화' 판정 -> 폐기.
- Tech/Bio 특성상 `exp_B`에서 소형주 탈락으로 인한 변동성 감소 확인 필요.

### 3. 성능 정체 시 원인 분해 (Diagnosis Logic)

성능 지표(`OOS Mean/Min`)가 실험에도 불구하고 움직이지 않거나(Flat), 설명 불가능한 진동을 보일 때 다음 트리를 점검:

1.  **트리거 불일치 (Trigger Mismatch):**
    *   *가설:* 시그널은 발생했으나 자금 부족(Cash constraints)이나 포트폴리오 슬롯 제한(max 14)으로 매수 실패.
    *   *확인:* 백테스트 로그에서 `Rejected Orders` 비율 확인.

2.  **레짐 불일치 (Regime Disconnect):**
    *   *가설:* 전략이 '상승장'에만 최적화되어, 현재의 '횡보/하락' 구간(OOS)에서 아무것도 안 하고 있음(Exposure 최소화 상태).
    *   *확인:* 시장 지수(QQQ/XLV) 대비 베타(Beta)가 0에 수렴하는지 확인.

3.  **데이터 노이즈 (Data Noise):**
    *   *가설:* Tech/Bio 섹터의 개별 이슈(임상 실패, 실적 쇼크)가 팩터 로직을 압도.
    *   *확인:* 포트폴리오 내 개별 종목 기여도(Contribution) 확인. 특정 1~2개 종목이 전체 성과를 지배(Dominate)하는지 체크.

4.  **비용/슬리피지 은폐 (Hidden Costs):**
    *   *가설:* 잦은 리밸런싱으로 인한 수수료 누적을 수익으로 착각하고 있었음(로직 수정 전까지).
    *   *확인:* Turnover(회전율) 지표가 연 500% 이상인지 점검.
