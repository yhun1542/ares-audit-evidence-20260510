## 48시간 자동 루프용 “실행 가능한 Patch/실험” (총 5개로 제한)

아래 5개만 돌리고, 각 실험은 (정의 → 게이트 → 기대 관측치)로 고정 운영하라.

### **E1) Purged Walk-Forward + 시간정렬(ASOF) 강제 + 누수 유닛테스트**
1) 실험 정의  
- 모든 피처/라벨 결합을 **asof merge(시점 ≤ t)**로 통일  
- walk-forward에 **purge/embargo(예: 5~20 거래일 그리드)** 적용  
- “피처가 미래를 참조하는지” 자동 탐지(라벨 시프트/리턴 창 겹침/리밸런스 시점 이후 데이터 접근) 유닛테스트 추가
2) 게이트  
- 누수 테스트 0건  
- embargo 위반 0건  
- 동일 스냅샷 재실행 시 메트릭 재현(변동 허용범위 내)
3) 기대 관측치  
- 초기엔 OOS mean 하락 가능(정상)  
- 대신 폴드 간 편차 감소, degenerate fold/이상치 감소

---

### **E2) 거래비용/대차/충격비용 + Turnover 패널티(목표 회전율)**
1) 실험 정의  
- per-share/퍼센트 슬리피지 + bid-ask spread(근사) + 충격비용(거래대금 대비) 모델을 PnL에 반영  
- short 존재 시 대차비용(연율) 반영  
- 목적함수에 turnover 패널티(또는 리밸런스 시 거래량 상한) 추가
2) 게이트  
- 연환산 turnover 상한, 비용/거래일당 비용 상한 만족  
- 비용 포함 OOS에서 샤프/IR이 “0 근처로 붕괴”하지 않을 것(최소 하한)
3) 기대 관측치  
- 신호가 약한 종목/과도매매 전략이 자동으로 도태  
- 리밸런스 횟수 감소, 순수익의 현실성 증가

---

### **E3) 리밸런스 로그 스키마 고정 + pinpoint 도구 호환 어댑터 + run_hash 재현성**
1) 실험 정의  
- 매 런에서 `rebalance.jsonl` 반드시 생성(한 줄 = 한 리밸런스 이벤트)  
- 필수 필드: timestamp, universe(8~14 tickers), target_w, prev_w, trades, turnover, est_cost, realized_cost(가능시), prices_source, data_snapshot_hash, config_hash, run_hash  
- `aub_rebalance_pinpoint.py` 입력을 csv/jsonl 모두 지원(없으면 jsonl 생성하도록 어댑터)
2) 게이트  
- base/cand 로그 로드 100% 성공  
- 리포트에 turnover/비용/노출 변화가 항상 표시
3) 기대 관측치  
- “성능이 안 움직임”의 원인이 **전략이 아니라 운영/로그**인지 즉시 분리 가능  
- 실험 간 차이가 어디서 생겼는지(트레이드/비용/노출) 1분 내 추적

---

### **E4) 노출·변동성 타게팅 + 레짐 게이트(리스크 온/오프)**
1) 실험 정의  
- 포트 변동성 목표(예: 10~15% 연율)로 scale  
- drawdown/집중도/섹터偏중 상한 게이트 추가  
- 레짐 지표는 ETF “매매 금지, 관측만”: QQQ/XLV 변동성/추세로 risk-off 시 gross exposure 자동 축소
2) 게이트  
- max exposure 상한, min exposure 하한, single-name weight 상한 준수  
- risk-off 구간에서 MDD/ulcer 개선 확인
3) 기대 관측치  
- 추세장 수익 일부 감소 가능(정상)  
- 급락/변동성 확대 국면에서 손실/변동성 감소, OOS 안정성 증가

---

### **E5) 서바이버십-세이프 유니버스 스냅샷(Tech+Healthcare 8~14) + delist/티커변경 처리**
1) 실험 정의  
- 매 리밸런스 시점 t에 “그 시점에 거래 가능했던” 종목만 포함하는 유니버스 스냅샷 생성  
- delist는 마지막 거래일 이후 가격/리턴 처리 규칙 고정(예: 현금화, -100% 처리 금지/허용 등 정책을 명시)  
- Tech+Healthcare 중심 필터를 **GICS 시점정보** 기준으로 적용(미래 섹터 분류 참조 금지)
2) 게이트  
- 유니버스 크기 8~14 유지, 섹터 조건 위반 0건  
- delist/티커 변경 이벤트 발생 시도 런이 중단되지 않고 로그에 남을 것
3) 기대 관측치  
- 과거 성과가 더 보수적으로 변할 수 있음(정상)  
- 대신 시간에 따른 유니버스 변동이 통제되어 실험 비교 가능

---

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)

아래 트리를 **로그/리포트에서 자동으로 갈라** 원인을 즉시 특정하라(질문 없이 실행).

### A) Trigger(신호 발생) 문제
- 체크: 신호 분포가 상수화(표준편차 급감), 상위/하위 스코어 종목이 매번 동일, fold별 IC 붕괴  
- 액션: E1(시간정렬)로 누수 차단 후 **신호 자체가 사라졌는지** 확인

### B) Apply(리밸런스/포지션 반영) 문제
- 체크: 신호는 변하는데 target_w가 거의 고정, 또는 trade가 0에 수렴  
- 액션: E3로 리밸런스 이벤트별 `prev_w→target_w→trades`를 강제 기록, “적용단 버그” 즉시 탐지

### C) Exposure(노출) 문제
- 체크: gross/net exposure가 레짐과 무관하게 고정(현재처럼 0.47~0.84 범위 고착), single-name 과집중  
- 액션: E4로 변동성 타게팅 및 집중도 상한 게이트 적용 후 OOS 안정성 변화를 관측

### D) Cost(비용) 문제
- 체크: turnover는 높은데 비용 로그가 없거나(현재), 비용 반영 후 성과가 0 근처로 붕괴  
- 액션: E2로 비용을 계좌단에 반영하고, E3로 이벤트별 비용을 남겨 **“알파 < 비용”인지** 즉시 판정

### E) Regime(시장 국면) 문제
- 체크: 특정 국면(금리 급등/하락장/변동성 급등)에서만 급락, 그 외엔 정상  
- 액션: E4 레짐 게이트로 risk-off 시 노출을 줄였을 때 **손실 구간만 선택적으로 개선**되는지 확인

## 24~48시간 실행 순서(명령형)
1) **E3부터 적용**해서 `rebalance.jsonl` 생성/로더 호환을 고정하라(관측 불능 상태부터 제거).  
2) **E1을 즉시 병행**해서 누수/평가 불일치 가능성을 먼저 제거하라(스냅샷/해시 고정).  
3) **E2로 비용을 넣고** “알파가 비용을 이기는지”를 1차 판정하라.  
4) 비용 포함에서도 유효하면 **E4로 리스크/레짐 게이트**를 붙여 OOS 안정성을 올려라.  
5) 마지막으로 **E5로 유니버스/서바이버십**을 못 박아 실험 비교가 의미 있게 유지되도록 하라.
