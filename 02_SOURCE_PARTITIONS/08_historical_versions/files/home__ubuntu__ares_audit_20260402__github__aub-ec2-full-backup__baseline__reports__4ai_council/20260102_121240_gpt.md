아래는 **다음 24~48시간 우선순위 TOP5**를 “48시간 자동 루프용(실험 정의 → 게이트 → 기대 관측치)” 형태로, **누수/과최적화/서바이버십/비용 미반영/운영 리스크 우선**으로 정리한 **명령형 체크리스트**다.  
(미국주식 only, **Tech+Healthcare 8~14 종목**, **ETF는 관측지표만**)

## TOP1) 평가/로그 불일치 즉시 제거 (OOS mean 불일치 + MDD None + rebalance 로그 깨짐)
### 왜 필요한지
- 현재 **Champion OOS Mean이 1.8815**인데, Diagnoser는 **2.6276**으로 보고됨 → **평가 파이프라인/데이터 컷/비용/슬리피지/기간/시드** 중 하나가 다름.
- `worst_mdd: None` → 리스크 지표 미계산/누락 가능(운영 리스크 + 과최적화 방치).
- rebalance pinpoint가 **base-log 경로 오류/CSV 파싱 오류**로 작동 불가 → “성능이 안 움직일 때” 원인 분해가 막힘.

### 위험/부작용
- 단기적으로 성능 수치가 하락(지금까지 과대평가였을 경우).
- 로그 스키마 변경으로 기존 도구 호환 깨질 수 있음(버전 태깅 필수).

### 최소 patch/실험(동일 패치 패밀리 내 2~3 토글)
**[P1] Eval-Parity & Rebalance-Log 패치 (실험 패밀리 1개)**  
1) **실험 정의**
- (토글 A) “백테스트 평가 함수”를 단일 entrypoint로 고정(Champion/Dignoser/Autopilot 모두 동일 함수 호출).
- (토글 B) 모든 런에 **oos 기간, 비용 모델, 슬리피지, 리밸런스 주기, seed, universe hash**를 JSON header로 강제 기록.
- (토글 C) 리밸런스 로그를 **JSONL**로 표준화하고, `aub_rebalance_pinpoint.py`가 **CSV/JSONL 자동 감지**하도록 수정.  
  - 현재 오류: `--base-log`가 문자열 `--base-log` 자체로 들어가 파일 찾기 실패 + `rebalance.csv`가 JSON/빈 파일일 가능성 → “파일 존재/비어있음/스키마”를 먼저 검증하고 실패 시 원인 로그 출력.

2) **게이트(실행 중단 조건)**
- 동일 입력(동일 run_hash)에서 **Champion 평가 vs Diagnoser 평가의 OOS Mean 차이 > 1e-6**이면 즉시 FAIL.
- `worst_mdd`가 None이면 FAIL.
- rebalance 로그가 0라인이거나 파싱 실패면 FAIL.

3) **기대 관측치**
- 성능 수치(특히 OOS Mean)가 한 값으로 수렴.
- pinpoint 리포트에 “언제/어떤 종목이/왜 바뀌었는지”가 재현 가능하게 출력.

**PASS 조건**
- 3회 연속 런에서:  
  - OOS Mean(Champion vs Diagnoser) 완전 일치  
  - MDD 계산됨(숫자)  
  - rebalance pinpoint 리포트 생성 성공(빈 리포트 금지)

## TOP2) 누수/서바이버십/과최적화 게이트를 “자동 차단”으로 승격 (Purged/Embargo + 데이터 무결성)
### 왜 필요한지
- Tech/Healthcare는 이벤트(실적/임상/규제) 민감 → **미세 누수**가 OOS를 크게 부풀릴 수 있음.
- 서바이버십/리스트 변경(특히 벤치마크 구성/시총 상위 고정)도 암묵 누수로 작동 가능.
- “성능이 안 움직임”이 사실은 **탐색이 아니라 누수 제거로 상쇄**될 수 있음 → 먼저 방어벽 필요.

### 위험/부작용
- 성능 하락(정상).
- 데이터 준비 시간 증가(운영 비용 증가).

### 최소 patch/실험
**[P2] Leak/Survivorship Hard-Gate (실험 패밀리 1개)**  
1) **실험 정의**
- (토글 A) 시계열 CV를 **Purged K-Fold + Embargo(예: 5~10 거래일)**로 고정.
- (토글 B) feature/label 생성에 대해 **“최신 사용 시점” 단위 테스트** 추가(각 feature의 timestamp가 decision time을 초과하면 런 FAIL).
- (토글 C) Universe를 “현재 구성”이 아니라 **각 일자 시점의 상장/거래 가능 종목**으로 제한(최소: delist/IPO date로 거래 가능 여부 마스킹).

2) **게이트**
- feature timestamp > 주문결정 timestamp 발견 시 FAIL.
- fold 간 overlap(embargo 무시) 발견 시 FAIL.
- delist 이전/IPO 이전 구간에 포지션 존재 시 FAIL.

3) **기대 관측치**
- OOS Mean이 단기 하락하더라도, fold 간 분산이 줄고(불안정 감소) “degenerate folds”가 줄어드는 방향.

**PASS 조건**
- 누수 체크 0건 + delist/IPO 체크 0건 + purged/embargo 적용 로그가 모든 런에 남음.
- OOS Mean이 하락하더라도 **fold별 성능 분산(표준편차) 감소**가 확인되면 PASS.

## TOP3) 비용/슬리피지/턴오버를 모델에 고정 반영 (성과 무반응의 1순위 원인 후보)
### 왜 필요한지
- 리밸런스 기반 전략에서 “성능이 안 움직임”은 종종 **예상 수익 변화 < 비용 변화** 상태.
- 지금 로그가 깨져 비용 영향 분해가 어려움 → 비용을 먼저 강제 반영하고, “비용 전/후”를 항상 같이 기록해야 함.

### 위험/부작용
- 비용 반영 즉시 성능이 꺾일 수 있음(정상).
- 너무 보수적 비용이면 실제보다 과소평가 가능(파라미터 범위 실험 필요).

### 최소 patch/실험
**[P3] Cost & Turnover Attribution 패치 (실험 패밀리 1개)**  
1) **실험 정의**
- (토글 A) 거래비용을 **(commission + half-spread + slippage(k·vol/adv))** 형태로 고정하고, 종목별 ADV 기반 슬리피지 캡 적용.
- (토글 B) 매 리밸런스마다 **gross PnL / cost / net PnL / turnover**를 분해 기록(종목별/일자별).
- (토글 C) 턴오버 상한(예: 일별 30~60%) 게이트를 추가하고, 초과 시 주문을 proportionally scale-down.

2) **게이트**
- net PnL이 gross PnL의 60% 미만(= 비용 과대 영향) 상태가 지속되면 FAIL로 분류하고 원인(턴오버/슬리피지)을 로그에서 자동 표기.
- turnover 상한 미적용/누락 시 FAIL.

3) **기대 관측치**
- “성능 무반응”인 실험군에서 **턴오버↑ → 비용↑ → net 정체** 패턴이 명확히 드러남.
- 비용 상한/스케일다운으로 net의 분산이 감소.

**PASS 조건**
- 모든 런에 비용 분해 로그 존재 + cost attribution 리포트 자동 생성.
- 최소 1개 실험에서 turnover 감소와 함께 **net 성능(또는 MDD)이 개선**되면 PASS.

## TOP4) 포트폴리오 구성(노출/리스크) 안정화: 8~14 종목 강제 + 노출 타겟팅 + 리밸런스 규칙 명문화
### 왜 필요한지
- 노출 min/max가 0.47/0.84로 “항상 애매하게 덜 들어감” → 전략 의도가 아니라면 **스케일링/헤지/게이트 충돌** 가능.
- 8~14 종목 제약은 집중 포트폴리오에서 성능보다 **리스크/회전율/운영 안정성**을 좌우.

### 위험/부작용
- 종목 수 강제로 알파가 줄 수 있음(특히 신호가 빈약한 구간).
- 노출 타겟팅이 잘못되면 상승장에서 underperform.

### 최소 patch/실험
**[P4] Portfolio-Construction Determinism 패치 (실험 패밀리 1개)**  
1) **실험 정의**
- (토글 A) 종목 수를 **항상 8~14로 강제**(스코어 상위 N, 동점 처리 규칙 고정).
- (토글 B) 총 노출을 **타겟(예: 0.9)으로 수렴**시키는 간단한 vol targeting(최근 20일 포트 변동성 기반) 적용. 현금은 의도된 경우에만 남기도록 규칙화.
- (토글 C) 리밸런스 규칙을 “조건 기반”으로 단순화:  
  - (i) 신호 순위가 K 이상 변동 시  
  - (ii) 목표 비중 대비 편차가 x% 초과 시  
  - (iii) 변동성 급등 레짐이면 리밸런스 빈도 감소

2) **게이트**
- 종목 수가 8~14를 벗어나면 FAIL.
- 노출이 타겟 대비 지속적으로 ±0.15 벗어나면 FAIL(스케일/헤지 충돌 의심).
- 리밸런스 규칙이 런마다 달라지면 FAIL(비결정성).

3) **기대 관측치**
- 노출 분포가 좁아지고, 리밸런스가 설명 가능해짐.
- MDD/분산이 감소(특히 비용 포함 net 기준).

**PASS 조건**
- 3회 연속 런에서 종목 수/노출/리밸런스 규칙이 재현 가능.
- net 기준 MDD 개선 또는 동일 성능에서 변동성 감소가 확인되면 PASS.

## TOP5) 레짐(시장/섹터) 관측지표만으로 “거래 강도”를 조절 (ETF는 매매 금지, 신호 게이트만)
### 왜 필요한지
- Tech/Healthcare는 레짐 의존이 큼(금리/리스크온·오프).  
- ETF를 매매하지 않고도 **XLK/XLV/SPY/QQQ/VIX** 같은 관측 지표로 “포지션 크기/리밸런스 빈도/노출”을 조절하면 **과최적화 없이** 안정화 가능.

### 위험/부작용
- 레짐 게이트가 너무 강하면 알파를 스스로 차단.
- 지표 선택이 많아지면 과최적화 위험 → 소수 지표로 고정.

### 최소 patch/실험
**[P5] Regime-Gated Exposure 패치 (실험 패밀리 1개)**  
1) **실험 정의**
- (토글 A) 관측지표(매매 금지):  
  - SPY 200DMA 상/하,  
  - VIX(또는 VVIX) 상위 분위,  
  - XLK/XLV 상대강도(예: 63일)  
  위 2~3개만 사용해 레짐을 2~3상태로 단순 분류.
- (토글 B) 레짐별로 **총 노출 타겟/리밸런스 빈도/턴오버 상한**만 다르게 적용(종목 선택 로직은 그대로).
- (토글 C) 레짐 전환 직후 N일(예: 3~5일) **리밸런스 유예(embargo-like)**로 과잦은 교체 방지.

2) **게이트**
- 레짐 상태 수가 3개 초과로 늘어나면 FAIL(케이스 폭발 방지).
- 레짐 조건이 학습 구간에서만 좋아지고 OOS에서 무의미하면 FAIL(레짐 과최적화).

3) **기대 관측치**
- 급락/변동성 확대 구간에서 MDD가 줄고, 비용(특히 턴오버)이 감소.
- 상승장에서는 노출이 회복되어 기회비용을 최소화.

**PASS 조건**
- OOS에서 “레짐 고변동 구간”의 MDD/turnover가 동시에 개선되면 PASS(평균 수익이 소폭 감소해도 허용).

# 성능이 안 움직일 때: 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래를 **자동 리포트 섹션**으로 고정 출력하도록 만들 것(질문 없이 기계적으로 분해).

## 1) Trigger(신호 발생) 문제
- **체크리스트**
  - 신호 분포(스코어/확률)의 분산이 OOS에서 급격히 축소됐는지 확인.
  - 상위 N 종목이 매일 거의 동일하면(= 신호가 굳음) “신호 업데이트” 문제로 분류.
  - 신호가 자주 뒤집히면(= 노이즈) “과최적화/누수 제거 후 약화”로 분류.
- **지표**
  - daily rank turnover, score entropy, top-N stability.

## 2) Apply(포트 반영) 문제
- **체크리스트**
  - 신호는 변하는데 포지션이 안 변하면: 제약(종목수/노출/턴오버 캡)이 과도한지 확인.
  - 주문 스케일링/헤지/현금 규칙이 충돌하는지 확인.
- **지표**
  - desired_weight vs executed_weight MAE, constraint hit-rate.

## 3) Exposure(노출) 문제
- **체크리스트**
  - 노출이 항상 0.5~0.8에 갇히면: 리스크 타겟/헤지/현금규칙 중 하나가 상시 발동.
  - 노출과 성과의 상관(상승장 underexposure)을 분해.
- **지표**
  - exposure time-series, beta to SPY, capture ratio(up/down).

## 4) Cost(비용) 문제
- **체크리스트**
  - gross는 움직이는데 net이 정체면 비용 탓으로 확정.
  - 비용의 80%가 특정 종목/특정 요일/특정 레짐에 몰리는지 확인.
- **지표**
  - cost / gross pnl ratio, turnover attribution, slippage vs ADV.

## 5) Regime(시장 상태) 문제
- **체크리스트**
  - 레짐별로 성과표를 분해(예: SPY>200DMA, VIX 상위 20% 등).
  - 특정 레짐에서만 이기면: 레짐 게이트로 “거래 강도”만 조절(신호는 유지).
- **지표**
  - conditional performance table, regime transition confusion.

## 48시간 운영 순서(명령형)
1) **P1을 먼저 머지/배포**해서 “평가/로그/리밸런스 재현성”을 복구하라(여기서 막히면 나머지 실험은 무의미).  
2) P2를 적용해 **누수/서바이버십을 런타임 FAIL**로 만들고, OOS 수치 하락 여부와 무관하게 통과시키지 마라.  
3) P3로 **gross/net/비용/턴오버** 분해를 고정 출력하고, “무반응=비용”인지 즉시 판정 가능하게 하라.  
4) P4로 **8~14 종목/노출 타겟/리밸런스 결정성**을 강제해 운영 리스크를 줄여라.  
5) P5로 레짐은 **지표 2~3개만** 써서 “거래 강도”만 조절하고 케이스 폭발을 금지하라.

이 5개 패밀리는 서로 의존성이 강하므로, **P1→P2→P3**까지가 24시간 내 1차 목표, **P4→P5**가 48시간 내 2차 목표다.
