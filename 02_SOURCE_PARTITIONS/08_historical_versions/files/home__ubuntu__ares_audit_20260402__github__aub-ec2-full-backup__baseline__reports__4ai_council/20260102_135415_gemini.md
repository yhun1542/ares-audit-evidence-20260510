[우선순위 TOP 5 제안: 24~48시간 실행 루프]

### 1. [Infra/Data] 매매 로그(Rebalance Log) 무결성 복구
*   **이유:** `aub_rebalance_pinpoint.py`에서 `[Errno 2] No such file` 및 JSON 파싱 에러 발생 중. 체결 내역(Turnover, Cost)을 추적할 수 없는 상태에서는 모델 개선이 불가능함. Blind Optimization 방지.
*   **위험:** 로깅 로직 수정 중 파이프라인 중단 가능성.
*   **PASS 조건:** 백테스트 종료 후 `rebalance.jsonl`이 생성되고, JSON parser가 에러 없이 로드하며, `turnover` 수치가 0이 아님.
*   **실험 루프:**
    1.  **실험 정의:** `JSONL` 포맷 강제 적용 및 `NaN/Inf` 값 전처리 로직(Serialize Safe) 추가.
    2.  **게이트:** `rebalance_pinpoint.py` 스크립트가 exit code 0으로 정상 종료되는가?
    3.  **기대 관측치:** 일별 리밸런싱 종목 수와 비중 변경 로그가 사람이 읽을 수 있는 형태로 출력됨.

### 2. [Universe] Tech/Healthcare 섹터 강제 및 팩터 압축
*   **이유:** 현재 Universe가 전 종목 대상일 가능성 높음(One Truth에 섹터 언급 없음). 8~14개 종목으로 집중하려면 Tech(XLK)/Healthcare(XLV) 외 노이즈를 제거하여 승률을 높여야 함.
*   **위험:** 분산 효과 감소로 인한 변동성(Vol) 급증. 특정 섹터 악재 시 MDD 심화.
*   **PASS 조건:** 포트폴리오 내 Tech/Bio 비중 90% 이상 유지 & OOS Sharpe > 1.5.
*   **실험 루프:**
    1.  **실험 정의:** Universe 필터에 `Sector in [Tech, Health]` 조건 추가 후, 유동성 상위 50위 내에서 `High Beta` + `Low Volatility` 조합 랭킹 실험.
    2.  **게이트:** 종목 수 8~14개 범위 내 안착 여부 (Min 8 미만 시 Cash 전환).
    3.  **기대 관측치:** 기존 Champion 대비 MDD는 소폭 증가하더라도, Recovery Factor(회복 탄력성)가 2.0 이상으로 개선.

### 3. [Execution] Exposure Hysteresis (노출도 완충 장치)
*   **이유:** 현재 Exposure가 0.47~0.84로 변동폭이 큼. 잦은 진입/청산은 실제 운영 시 슬리피지와 수수료로 직결됨(비용 미반영 리스크).
*   **위험:** 시장 급변 시 반응 속도 저하(Lagging).
*   **PASS 조건:** Turnover 20% 이상 감소 & Net Profit(수수료 차감 후) 유지 또는 상승.
*   **실험 루프:**
    1.  **실험 정의:** 목표 Exposure 변경 분이 `threshold`(예: 0.05) 미만일 경우 포지션 변경 보류(No Action).
    2.  **게이트:** 일일 Turnover가 15% 미만으로 제어되는가?
    3.  **기대 관측치:** `oos_mean`의 명목 수치는 약간 하락하나, 비용 반영 후 `oos_min` 방어력 상승.

### 4. [Metric] Worst MDD 산출 로직 디버깅 (`None` 수정)
*   **이유:** `worst_mdd: None`은 치명적 결함. 데이터 누락(Gap)이나 계산 로직 오류(Divide by Zero 등)로 인해 리스크가 은폐되어 있음. 서바이버십 편향 가능성 농후.
*   **위험:** 실제 MDD가 예상보다 훨씬 커서(예: -40%) 전략 폐기 결정이 날 수 있음.
*   **PASS 조건:** `worst_mdd`가 유효한 음수(float)로 계산됨.
*   **실험 루프:**
    1.  **실험 정의:** 수익률 시계열(Series)의 결측치(`NaN`)를 0.0으로 채우는 `fillna` 처리 및 윈도우 계산 로직 점검.
    2.  **게이트:** 모든 Fold에서 MDD 값이 출력되는가?
    3.  **기대 관측치:** 숨겨진 MDD 구간(Drawdown Cluster) 발견 및 이를 회피하기 위한 Cash 비중 로직 트리거 확인.

### 5. [Strategy] ETF 관측 기반 Regime Switch (동적 할당)
*   **이유:** ETF 매매는 금지지만, QQQ/XLV의 모멘텀/변동성을 '신호등(Signal)'으로 사용하여 개별주 8~14개의 진입 강도를 조절해야 함.
*   **위험:** ETF 신호와 개별주 간 디커플링 시 손실 확대(False Positive).
*   **PASS 조건:** 하락장(Bear Market) 구간에서 Exposure가 0.5 미만으로 자동 축소.
*   **실험 루프:**
    1.  **실험 정의:** `QQQ_MA_50 > QQQ_MA_200` (Golden Cross) 상태에서만 Tech 비중 확대, 반대 시 Cash/Healthcare 비중 확대.
    2.  **게이트:** 상승/하락 구간별 섹터 비중이 의도대로 스위칭되는가?
    3.  **기대 관측치:** `oos_min` (최악의 구간 성능)이 0.43에서 0.8 수준으로 방어력 개선.

성능이 움직이지 않거나(Flat), 의도한 대로 개선되지 않을 때 아래 순서로 점검:

1.  **트리거(Trigger):** 모델이 매수/매도 시그널을 생성했는가?
    *   *Check:* Raw Alpha 값의 표준편차 확인 (0에 수렴하면 모델이 죽은 것).
2.  **적용(Application):** 시그널이 포트폴리오 제약조건(8~14종목, 섹터 제한)에 막히지 않았는가?
    *   *Check:* `Target Weight` vs `Constrained Weight` 차이 확인.
3.  **노출(Exposure):** 실제 주문이 나갔는가?
    *   *Check:* 현금 비중(Cash Ratio)이 비정상적으로 높게 유지되는지 (체결 불가/데이터 오류).
4.  **비용(Cost):** 수익이 비용에 의해 상쇄되었는가?
    *   *Check:* Gross Return vs Net Return 스프레드 확대 여부. (슬리피지 설정 과다 확인)
5.  **레짐(Regime):** 현재 시장이 전략과 맞지 않는 구간(예: 횡보장)인가?
    *   *Check:* 벤치마크(QQQ/SPY) 대비 Alpha 상관계수 확인. 시장 수익률 자체가 0에 수렴하는지 확인.
