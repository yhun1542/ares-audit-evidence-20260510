### PATCH-1 ▸ MDD 게이트 복구 (Critical)

**(a) 왜 필요한지**
- `worst_mdd: None` → 전 fold에서 drawdown 미측정 상태
- MDD 20% 초과 시 복구까지 장기간 소요; 실전에서 치명적

**(b) 위험/부작용**
- MDD 제한 추가 시 고수익 구간도 조기 청산 → Sharpe 하락 가능
- 과거 데이터 peak 계산 오류 시 false-trigger

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 1-A | `max_mdd ≤ 15%` hard-cap 적용 | 5-fold 모두 MDD 숫자 출력 | mean MDD ≤ 12%, min_oos ≥ 0.35 유지 |
| 1-B | `max_mdd ≤ 20%` soft-alert (청산X, 로그만) | 로그 트리거 횟수 | 연평균 < 2회 |

**(d) PASS 조건**
```
worst_mdd ≤ 0.18 AND oos_min ≥ 0.40
```

### PATCH-2 ▸ 슬리피지+커미션 현실화

**(a) 왜 필요한지**
- 현재 비용 미반영 가정 → 회전율 높을수록 over-estimated Sharpe
- IB 기준 편도 0.05% + 스프레드 0.03% ≈ **0.08%** 현실치

**(b) 위험/부작용**
- 비용 반영 시 Sharpe 5–15% 하락 예상
- 저빈도 전략에는 영향 미미 → 비용 민감도 왜곡 가능

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|

| 2-B | 편도 10bp (worst-case) 시뮬 | oos_min 재계산 | oos_min ≥ 0.30 |

## 3. 성능 불변 시 원인 분해 트리

```
Sharpe 안 움직임
├─ [트리거] 시그널 변화 ≈ 0 → 피처 saturation / 데이터 지연
├─ [적용] 시그널 → 포지션 매핑 오류 → position_diff 로그 확인
├─ [노출] exposure clamp가 시그널 상쇄 → pre/post clamp 비교
├─ [비용] 비용 미반영 상태에서 이미 saturated → 비용 삽입 후 재확인
└─ [레짐] 테스트 기간 전체가 동일 regime → walk-forward window 확장
```
