아래는 **다음 24~48시간**에 “성능이 안 움직이는 상태(no-delta)”를 깨기 위해, **누수/과최적화/서바이버십/비용/운영 리스크를 최우선으로** 잡는 **TOP5 우선순위**입니다.  
규칙에 맞춰 **48시간 자동 루프용**으로 각 항목을 **명령형 체크리스트** + (a)(b)(c)(d)로 제시하고, 전체 실험은 **공유된 5개 실험(E1~E5)**로 제한합니다(케이스 폭발 방지).  
(미국주식 only, Tech+Healthcare 8~14, ETF는 관측지표만)

---

## 지금 로그에서 드러난 “즉시 리스크”
- `degenerate_folds: [1,2,3,8]` → **검증 분할이 붕괴(과최적화/데이터 누수/표본 부족/타겟-피처 정렬 문제)** 가능성이 매우 큼.
- `worst_mdd: None` → **리스크 메트릭 계산 파이프라인 결함**(운영/게이트 자체가 무력화).
- `lane_hash/run_hash: None` → **실험 재현성/추적 불가**(오토루프에서 “변경→결과” 연결이 끊김).
- Rebalance pinpoint가 **파일/JSON 파싱 실패** → 비용/매매(턴오버/슬리피지) 분석 자체가 불가능.

# 공유 실험 세트 (총 5개만 운용)
- **E1 (OPS-LOG)**: 리밸런스 로그/메트릭 산출 복구(운영 리스크 제거)
- **E2 (CV-PURGE)**: Purged/Embargo CV + degenerate fold 차단(누수/과최적화 제거)
- **E3 (UNIV-SURV)**: 유니버스 고정(Tech+HC 8~14) + survivorship/코퍼레이트액션 점검(서바이버십 제거)
- **E4 (COST-TURN)**: 거래비용/슬리피지/턴오버 상한을 목적함수/게이트에 내장(비용 미반영 제거)
- **E5 (RISK-EXPO)**: 노출/레짐 게이트(노출 0↔과다, 헤지, 변동성 레짐)로 “안 움직임” 분해(노출/레짐 리스크 제거)

각 TOP5 우선순위는 아래 E1~E5 중 **2~3개만 호출**해 실행합니다(전체 실험 수는 그대로 5).

---

# TOP1) 리밸런스 로그/메트릭 파이프라인 복구 (E1 중심)
### (a) 왜 필요한지
- 현재 `rebalance.csv/jsonl` 로딩 실패 + `worst_mdd=None` → **비용/턴오버/슬리피지/리스크가 “측정 불가”**.  
- 오토루프는 “측정→게이트→진화”인데, 측정이 깨지면 **성능이 안 움직이는 게 정상**입니다.

### (b) 위험/부작용
- 로깅/메트릭 추가로 런타임/저장공간 증가.
- 과거 실험 결과와 포맷 불일치로 비교 어려움(이 경우 버전태그로 해결).

### (c) 최소 실험 2~3개 (공유 실험 사용)
- **E1 (OPS-LOG)**: 리밸런스 산출물을 **단일 표준 포맷(JSONL)** 로 강제 저장 + 경로/파일 존재 게이트.
- **E4 (COST-TURN)**: 로그가 복구되는 즉시, 비용/턴오버 메트릭을 리포트에 의무 포함(“측정만” 먼저).
- **E2 (CV-PURGE)**: degenerate fold 발생 시 해당 폴드의 입력/타겟/리밸런스 이벤트 수를 함께 덤프(디버그용).

### (d) PASS 조건 (게이트)
- (필수) 각 실험 런에 대해 `rebalance.jsonl` 생성 + 파싱 성공(0 error).
- (필수) `worst_mdd`가 수치로 산출되고 NaN/None이 아님.
- (필수) run_hash/lane_hash가 채워지고(재현성), 리포트가 동일 경로 규약으로 생성.

### 48시간 자동 루프 형식
- **(1) 실험 정의**: `E1_OPS_LOG` 켜고, 리밸런스 이벤트(주문 전/후 포지션, 체결가 가정, 비용) JSONL로 강제.
- **(2) 게이트**: “로그 파싱 0에러 + MDD 산출 + 해시 생성” 실패 시 즉시 fail-fast.
- **(3) 기대 관측치**: 비용/턴오버 분포, 리밸런스 빈도, 포지션 급변 구간이 식별 가능해짐(이후 개선 타겟 명확화).

---

# TOP2) 누수/과최적화 차단: Purged CV + degenerate fold 제거 (E2 중심)
### (a) 왜 필요한지
- `degenerate_folds`는 보통 아래 중 하나입니다:
  - 타겟과 피처 정렬 오류(미래 데이터 섞임)
  - 리밸런스 간격/호라이즌과 CV 분할 불일치(정보 누수)
  - 특정 폴드에서 표본/클래스가 사실상 0(유니버스/결측 처리 문제)
- 이 상태에서는 OOS가 “안 움직이는” 게 아니라 **검증이 무의미**해질 수 있습니다.

### (b) 위험/부작용
- Purged/Embargo 적용 시 학습 데이터가 줄어 **OOS 평균이 단기적으로 하락**할 수 있음(정상).
- 성능 개선보다 “정직한 성능”으로 수렴(단기 no-delta처럼 보일 수 있으나 필수).

### (c) 최소 실험 2~3개 (공유 실험 사용)
- **E2 (CV-PURGE)**: Purged K-fold + embargo(타겟 호라이즌만큼) 적용.
- **E2 변형(동일 실험 내 스위치 1개만)**: degenerate fold 감지 시
  - 해당 폴드 **학습/평가 제외**가 아니라
  - **즉시 실패 처리**로 바꿔(“통과한 실험만 남는” 서바이버십 방지).
- **E3 (UNIV-SURV)**: 유니버스 고정 후에도 degenerate가 남으면, 원인이 CV가 아니라 **결측/코퍼레이트액션/데이터 정렬** 쪽임을 확정.

### (d) PASS 조건 (게이트)
- degenerate_folds = 빈 리스트(0개) **연속 2회 런**.
- OOS mean이 떨어져도 상관없으나,
  - OOS min이 비정상(예: -inf/NaN)으로 튀지 않고,
  - 폴드별 샘플 수/리밸런스 수가 최소치 이상(예: 폴드당 리밸런스 이벤트 30+ 등) 충족.

### 48시간 자동 루프 형식
- **(1) 실험 정의**: `E2_CV_PURGE` 적용 + “degenerate 즉시 fail”.
- **(2) 게이트**: degenerate 발생 시 런 폐기 + 원인 덤프(타임스탬프 정렬/결측률/이벤트 수).
- **(3) 기대 관측치**: OOS가 일시적으로 내려가도 분산이 정상화되고, 폴드별 성능 분포가 의미를 갖기 시작.

---

# TOP3) 서바이버십/유니버스/코퍼레이트 액션 고정 (E3 중심)
### (a) 왜 필요한지
- “미국주식 Tech+Healthcare 8~14”인데 유니버스가 런마다 바뀌거나(상장폐지/합병/티커 변경 처리 미흡),
- 조정주가/분할/배당 반영이 폴드마다 다르면  
  → **검증 자체가 흔들려 no-delta처럼 보이거나, 운 좋게만 좋아지는 서바이버십 편향**이 생깁니다.

### (b) 위험/부작용
- 유니버스 고정 시 기회가 줄어 수익률이 단기적으로 둔화 가능.
- mega-cap만 남기면 팩터 다양성이 줄어 “비슷한 신호”로 수렴 가능(대신 운영 안정성↑).

### (c) 최소 실험 2~3개 (공유 실험 사용)
- **E3 (UNIV-SURV)**: 유니버스를 “고정 리스트(8~14)”로 잠그고, 데이터 가용성(전 기간 OHLCV 존재) 통과 못하면 **런 자체 실패**.
  - 예시 구성(Tech+HC, ETF 제외): AAPL, MSFT, NVDA, AMZN, GOOGL, META, LLY, UNH, JNJ, ABBV, MRK, TMO (12종) 같은 형태로 고정(실데이터 가용성 기준으로 조정).
- **E2 (CV-PURGE)**와 결합해, 유니버스 고정 후에도 degenerate가 뜨면 **정렬/결측 처리**가 원인임을 빠르게 확정.
- **E1 (OPS-LOG)**: 종목별 리밸런스/체결/포지션 로그를 남겨 특정 티커에서만 이상치가 나는지 확인.

### (d) PASS 조건 (게이트)
- 전 종목이 전 기간 데이터 커버리지/결측률 상한 통과(예: 결측률 < 0.5% 등 내부 기준).
- 종목별 포지션이 “항상 0”인 티커가 장기간 지속되지 않음(노출 경직 방지).
- 유니버스 변경이 0회(리스트 해시 고정).

### 48시간 자동 루프 형식
- **(1) 실험 정의**: `E3_UNIV_SURV` 켜고 유니버스 해시 고정.
- **(2) 게이트**: 데이터 가용성/조정주가 일관성 체크 실패 시 중단.
- **(3) 기대 관측치**: 폴드/런 간 변동 원인이 “전략”이 아니라 “데이터/유니버스”였는지 즉시 분리됨.

# TOP4) 비용/턴오버를 목적함수와 게이트에 강제 반영 (E4 중심)
### (a) 왜 필요한지
- 현재는 리밸런스 로그도 깨져 있고, exposure max가 0.84로 꽤 높습니다.  
  비용을 반영하지 않으면 **턴오버로 먹는 전략**이 “백테스트만” 좋아지고 OOS에서 no-delta가 됩니다.
- 특히 8~14개 종목 집중 포트폴리오는 리밸런스가 잦으면 비용이 성능을 상쇄합니다.

### (b) 위험/부작용
- 비용을 넣으면 OOS mean이 내려갈 수 있음(정상).
- 턴오버 제한이 너무 강하면 신호가 무력화(“안 움직임”이 더 심해질 수 있음 → 그래서 E5와 같이 봐야 함).

### (c) 최소 실험 2~3개 (공유 실험 사용)
- **E4 (COST-TURN)**: 커미션+슬리피지(보수적 상수라도)를 PnL에 직접 반영하고, 리포트에 net/gross를 분리.
- **E4 변형(동일 실험 내 스위치 1개만)**: 목적함수에 `- λ * turnover` 패널티(λ 1개 값만) 추가.
- **E1 (OPS-LOG)**: 비용이 실제로 어디서 발생하는지(특정 날짜/종목) pinpoint 가능하게 로그 필수화.

### (d) PASS 조건 (게이트)
- net 성능이 gross 대비 과도하게 붕괴하지 않음(예: net/gross 샤프 비율이 0.7 이상 같은 내부 기준).
- 턴오버(일/주) 상한 충족(내부 목표치) + 리밸런스 빈도 안정.
- “비용 반영 전후”의 순위가 뒤집히면(비용 민감 전략) 그 원인을 로그로 설명 가능.

### 48시간 자동 루프 형식
- **(1) 실험 정의**: `E4_COST_TURN`로 net PnL 기준 평가로 전환.
- **(2) 게이트**: 로그 없으면 비용 계산 실패 → 런 실패.
- **(3) 기대 관측치**: no-delta의 원인이 “알파 부족”인지 “비용 상쇄”인지 즉시 분리.

---

# TOP5) 노출(Exposure)·레짐·헤지의 게이트화 (E5 중심)
### (a) 왜 필요한지
- 현재 exposure min/max가 `0.0 / 0.8388` → “대부분 0이거나 특정 시점에만 확 올라가는” 형태일 수 있습니다.  
  이러면 성능이 “안 움직임”처럼 보일 수 있습니다(신호가 발동을 못 하거나, 발동 시점이 레짐에 종속).
- ETF 매매는 제외지만, **레짐 관측지표**로는 QQQ/XLK/XLV 같은 ETF의 추세/변동성/상관을 써서 “언제 쉬어야 하는지”를 정의할 수 있습니다.

### (b) 위험/부작용
- 게이트가 과하면 **항상 현금**(exposure=0)으로 수렴 → 진짜 no-delta.
- 레짐 신호가 후행이면 급락 방어에 늦을 수 있음(그래서 단순/보수적으로).

### (c) 최소 실험 2~3개 (공유 실험 사용)
- **E5 (RISK-EXPO)**: (관측용 ETF 기반) 변동성/추세 레짐에 따라 목표 노출 상한을 동적으로 조절(예: 위험 레짐에서 max exposure 하향).
- **E5 변형(동일 실험 내 스위치 1개만)**: “신호 스코어가 약하면 포지션 0”이 아니라 **최소 노출 바닥(min exposure floor)** 를 두어(예: 10~20%) “항상 0” 수렴을 방지.
- **E4 (COST-TURN)**: 레짐 게이트가 턴오버를 줄여 비용을 낮추는지 동시 관측.

### (d) PASS 조건 (게이트)
- exposure가 장기간 0에 붙지 않음(예: 평가 기간의 70% 이상이 exposure=0이면 fail).
- 위험 레짐에서 MDD/손실 꼬리(oos_min)가 의미 있게 개선(절대치 또는 상대치 기준).
- 레짐 전환 시 턴오버가 폭증하지 않음(“게이트가 오히려 매매를 늘리는” 역효과 방지).

### 48시간 자동 루프 형식
- **(1) 실험 정의**: `E5_RISK_EXPO`로 레짐별 목표 노출 상한/하한 적용(ETF는 관측만).
- **(2) 게이트**: exposure=0 고착 / 턴오버 폭증 시 실패.
- **(3) 기대 관측치**: 성능이 안 움직였던 원인이 “신호 미발동(노출 문제)”인지 “레짐 부적합”인지 분리.

## 24~48시간 실행 순서(명령형 체크리스트)
1) **E1(OPS-LOG) 먼저 고정**: 로그/메트릭 실패하면 이후 실험 전부 무의미하므로 fail-fast로 막아라.  
2) **E2(CV-PURGE) 적용 + degenerate 즉시 실패**: 누수/정렬/표본 문제를 강제로 드러내라.  
3) **E3(UNIV-SURV)로 유니버스 해시 고정**: 종목/데이터 흔들림 제거 후에도 문제가 남는지 확인하라.  
4) **E4(COST-TURN)로 net 기준 평가 전환**: 비용 상쇄가 no-delta 원인인지 판별하라.  
5) **E5(RISK-EXPO)로 노출/레짐 게이트를 최소 1개만 추가**: “노출 0 고착” vs “레짐 미스”를 갈라라.

# 성능이 안 움직일 때(=no-delta) 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래는 **원인을 ‘관측 가능한 지표’로 분해**해서 48시간 루프에서 자동으로 진단하도록 만드는 항목입니다(질문 없이 실행 가능한 형태).

## A) Trigger(신호 생성) 문제
- **체크**: 신호 분포가 너무 좁거나(거의 0), 상위/하위가 매번 같은 종목인지.
- **트리거 지표**: 날짜별 signal 표준편차, 종목별 순위 변동률, 상위 K 교체율.
- **판정**: 신호가 “거의 상수”면 학습이 아니라 피처/정렬/스케일링 문제 가능.

## B) Apply(적용/리밸런스) 문제
- **체크**: 신호는 변하는데 주문이 안 나가는지(제약/라운딩/포지션 한도/현금 처리).
- **트리거 지표**: “의사결정 포지션” vs “실제 체결 포지션” 차이, 주문 무시 사유 카운트.
- **판정**: 주문 무시가 많으면 제약이 전략을 죽이고 있어 no-delta.

## C) Exposure(노출) 문제
- **체크**: exposure=0 구간 비중, 목표 노출 대비 실제 노출 추적오차.
- **트리거 지표**: exposure time-in-market, exposure 히스토그램, 종목별 평균 포지션.
- **판정**: time-in-market가 과도하게 낮으면 “알파”가 아니라 “노출 설계” 문제.

## D) Cost(비용) 문제
- **체크**: gross는 움직이는데 net이 안 움직이는지.
- **트리거 지표**: gross-net gap, 비용/수익 비율, 턴오버-성과 상관.
- **판정**: gap이 크면 비용 모델/턴오버 억제가 우선.

## E) Regime(레짐) 문제
- **체크**: 특정 레짐(고변동/하락추세)에서만 성능이 깨지는지.
- **트리거 지표**: (관측 ETF로) QQQ/XLK/XLV의 추세/변동성/상관 레짐별 성과 테이블.
- **판정**: 레짐별 성과 편차가 크면 “전략 파라미터 미세조정”이 아니라 “레짐 게이트/리스크 오프”가 정답.

---

## 마지막으로: PASS/FAIL을 “자동 루프 게이트”로 고정하라(핵심)
- **Fail-fast**: 로그 파싱 실패, MDD None/NaN, degenerate fold 발생, 유니버스 해시 변동 → 즉시 실패.
- **진짜 개선 PASS**: OOS mean 소폭 개선보다,
  1) degenerate=0 유지  
  2) net 기준에서 일관성  
  3) exposure/time-in-market 정상화  
  4) 비용/턴오버 설명 가능  
  이 4개를 먼저 통과시키는 게 “no-delta 탈출”의 선행조건입니다.
