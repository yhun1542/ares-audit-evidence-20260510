## 🎯 TOP 5 우선순위 (24~48h)

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### P1. 실험 적용률(Exposure) 진단 도구 구축
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한가**
- lockbox 수치가 0.0001만 변동 → 실험 파라미터가 실제 매매에 영향 못 줌
- 조건 충족 빈도, 실제 시그널 발생 횟수 추적 없이는 원인 불명

**(b) 위험/부작용**
- 로깅 오버헤드 (< 5% 허용)
- 기존 백테스트 결과와 불일치 가능 (버그 발견 기회)

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|---|---|---|---|
| P1-E1 | `exposure_tracker.py` 추가: 각 모듈별 트리거 횟수/적용 비율 로깅 | 코드 작동 확인 | 모듈당 trigger_rate 0~100% 산출 |
| P1-E2 | Champion vs Candidate 간 exposure diff 리포트 생성 | diff > 1% 존재 | 어떤 모듈이 실제로 변화 유발했는지 식별 |
| P1-E3 | trigger_rate < 5% 모듈 리스트업 | 리스트 산출 | Dead code 후보 식별 |

**(d) PASS 조건**
```
✅ exposure_diff_report.json 생성됨
✅ 최소 1개 모듈에서 trigger_rate < 10% 발견 OR 모든 모듈 > 30%
```

### P2. 비용 모델 현실화 검증
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 왜 필요한가**
- 현재 슬리피지/스프레드 가정이 낙관적일 경우, 실제 운용에서 alpha 소멸
- tuning_min이 0.05로 극단적 → 특정 fold에서 비용 충격 의심

**(b) 위험/부작용**
- 비용 상향 시 전체 수익률 하락 (expected)
- 과도한 비용 가정 → 유효 전략도 reject

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|---|---|---|---|
| P2-E1 | 슬리피지 10bp → 15bp로 stress test | 실행 완료 | lockbox_mean Δ 측정 |
| P2-E2 | 소형주(SMCI 등) 별도 슬리피지 20bp 적용 | 실행 완료 | 소형주 기여도 재계산 |
| P2-E3 | 턴오버 vs 비용 scatter plot | 시각화 완료 | 고턴오버 구간 식별 |

**(d) PASS 조건**
```
✅ 15bp 시나리오에서 lockbox_mean > 1.5 (30% 버퍼 확보)
✅ 비용 민감도 리포트 생성됨
```

### P3. Regime 분해 및 Fold 실패 구간 분석
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

- 해당 구간의 시장 regime 파악 없이 개선 방향 설정 불가

**(b) 위험/부작용**

```
✅ 실패 구간 regime 라벨링 완료
```

## 🔍 성능 정체 원인 분해 트리

```
lockbox Δ ≈ 0 일 때 점검 순서:

1. [트리거] 조건 충족 자체가 없음?
   └─ 진단: trigger_rate by module
   └─ 처방: 조건 완화 or 파라미터 범위 확대

2. [적용] 트리거 됐으나 position 변화 없음?
   └─ 진단: position_diff before/after
   └─ 처방: 우선순위 로직 점검

3. [노출] position 바뀌었으나 수익 영향 없음?
   └─ 진단: 해당 종목의 기간 수익률
   └─ 처방: 종목 선정 로직 재검토

4. [비용] 수익 났으나 비용에 잡아먹힘?
   └─ 진단: gross vs net return
   └─ 처방: 턴오버 제한, 비용 모델 현실화

5. [레짐] 특정 구간에서만 작동/실패?
   └─ 진단: fold별 성과 분산
   └─ 처방: regime-aware 조건 추가
```
