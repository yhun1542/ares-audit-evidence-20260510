## 1. 우선순위 TOP 5 실험 제안

### ━━━ PRIORITY 1: 탐색 반경 확대 (Exploration Radius) ━━━

#### (a) 왜 필요한지
```
현재: candidate와 champion 차이 < 1%
→ 로컬 옵티멈에 갇힘 / 의미있는 개선 불가능
→ 다양성 부족 = 서바이버십 바이어스 누적
```

#### (b) 위험/부작용
- 과도한 탐색 → 노이즈 피팅
- 실험 실패율 증가 → 시간 낭비

#### (c) 최소 실험
| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| E1.1 | `mutation_sigma` 2x 증가 | lockbox_mean ≥ 1.30 | candidate 다양성 ↑ (std > 0.05) |
| E1.2 | 파라미터 3개 동시 변이 허용 | worst_mdd ≥ -0.12 | 새로운 regime 탐색 |
| E1.3 | 랜덤 시드 5개로 앙상블 후 중앙값 | fold 간 분산 < 0.02 | 안정성 확인 |

#### (d) PASS 조건
```
lockbox_mean ≥ 1.32 AND worst_mdd ≥ -0.10 AND candidate_diversity > 0.03
```

---

### ━━━ PRIORITY 2: 비용 모델 검증 (Cost Reality Check) ━━━

#### (a) 왜 필요한지
```
lockbox가 tuning보다 높음 = 실거래 비용 미반영 가능성
→ 백테스트 환상에서 깨어나야 함
```

#### (b) 위험/부작용
- 비용 과다 적용 시 전략 자체가 무효화
- 비용 모델 오류 시 잘못된 결론

#### (c) 최소 실험
| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| E2.1 | 슬리피지 5bp + 수수료 1bp 적용 | return ≥ 1.20 | 여전히 양수 alpha |
| E2.2 | 거래빈도별 비용 민감도 분석 | 연 회전율 < 400% | 과매매 탐지 |

#### (d) PASS 조건
```
cost_adjusted_lockbox ≥ 1.15 AND turnover ≤ 500%
```

---

### ━━━ PRIORITY 3: Fold 간 불균형 해소 ━━━

#### (a) 왜 필요한지
```
fold14_mdd (-0.049) vs worst_mdd (-0.090) = 1.8배 차이
→ 특정 기간 과최적화 / 레짐 의존성
```

#### (b) 위험/부작용
- 전체 성능 하락 가능
- 복잡도 증가

#### (c) 최소 실험
| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| E3.1 | worst fold 식별 후 해당 기간 특성 분석 | - | 레짐 특성 파악 |
| E3.2 | fold별 가중치 동일화 강제 | fold_std_mdd < 0.02 | 균형 개선 |
| E3.3 | worst fold만 OOS로 분리하여 재학습 | worst_mdd ≥ -0.07 | 취약점 보완 |

#### (d) PASS 조건
```
max(fold_mdd) / min(fold_mdd) ≤ 1.5 AND lockbox_mean ≥ 1.30
```

---

### ━━━ PRIORITY 4: 레짐 적응 메커니즘 (Regime Adaptation) ━━━

#### (a) 왜 필요한지
```
lockbox > tuning 역전 = 시장 레짐 변화에 전략이 뒤처짐
→ 적응형 모듈 필요
```

#### (b) 위험/부작용
- 레짐 오탐 → 잘못된 스위칭
- 복잡도 ↑ → 디버깅 난이도 ↑

#### (c) 최소 실험
| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| E4.1 | VIX 20 이상/이하 분기 룰 추가 | lockbox 분기별 일관성 | 레짐별 성능 분리 |
| E4.2 | 200MA 위/아래 노출 조절 | worst_mdd ≥ -0.08 | 하락장 방어 |

#### (d) PASS 조건
```
regime_A_sharpe > 0.8 AND regime_B_sharpe > 0.8 (둘 다 양수)
```

---

### ━━━ PRIORITY 5: 포지션 사이즈 상한 (Concentration Cap) ━━━

#### (a) 왜 필요한지
```
worst_mdd -9%는 개별 종목 집중 리스크 가능성
→ 8~14 종목이면 max weight 7~12% 자연스러움
```

#### (b) 위험/부작용
- 상한 너무 낮으면 확신 포지션 불가
- 리밸런싱 비용 증가

#### (c) 최소 실험
| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| E5.1 | max_weight 10% 강제 | worst_mdd ≥ -0.07 | MDD 개선 |
| E5.2 | max_weight 15% vs 10% 비교 | sharpe 차이 < 0.1 | 성능 손실 허용 범위 |

#### (d) PASS 조건
```
worst_mdd ≥ -0.075 AND lockbox_mean ≥ 1.28
```

## 2. 성능 불변 시 원인 분해 트리

```
성능이 안 움직인다
│
├─[1] 트리거 문제
│   └─ 시그널이 발생 안 함 → 임계값 확인
│   └─ 시그널 빈도 측정: signals_per_month < 1?
│
├─[2] 적용 문제  
│   └─ 시그널 → 주문 전환 실패
│   └─ position_change_count == 0?
│
├─[3] 노출 문제
│   └─ 포지션은 있으나 비중 미미
│   └─ avg_active_weight < 50%?
│
├─[4] 비용 문제
│   └─ 수익 = 비용으로 상쇄
│   └─ gross_return vs net_return 비교
│
└─[5] 레짐 문제
    └─ 전략이 맞는 장이 안 옴
    └─ regime_exposure 분포 확인
```

## 3. 48시간 자동 루프 스케줄

```yaml
# 자동실행 스케줄
T+0h:   
  - GATE-0 점검 스크립트 실행
  - E1.1, E2.1, E3.1 병렬 실행

T+12h:
  - E1.1~E3.1 결과 수집
  - PASS 시 → E1.2, E2.2, E3.2 진행
  - FAIL 시 → 원인분해 트리 실행

T+24h:
  - 중간 리포트 생성
  - E4.1, E5.1 실행

T+36h:
  - 전체 결과 통합
  - best candidate 선정

T+48h:
  - HANDOFF 문서 자동 생성
  - champion 교체 여부 결정
```
