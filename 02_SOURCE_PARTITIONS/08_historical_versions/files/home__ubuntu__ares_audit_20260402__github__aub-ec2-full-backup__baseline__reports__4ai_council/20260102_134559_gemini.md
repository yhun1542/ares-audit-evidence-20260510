[명령형 체크리스트: AUB 시스템 긴급 점검 및 실험 계획]

### 1. 24~48시간 우선순위 TOP 5

1.  **로그 파이프라인 정합성 복구 (최우선)**: `rebalance.csv` 로드 실패 및 JSON 파싱 에러 즉시 수정. 거래 비용과 턴오버가 측정되지 않는 실험은 무효임.
2.  **OOS 지표 불일치 해결**: ONE TRUTH(1.88)와 Diagnoser(2.62) 간의 괴리 원인 파악. 평가 구간(Window) 또는 비용 반영 여부 차이일 가능성 높음.
3.  **유니버스 생존 편향(Survivorship Bias) 제거**: 2026년 시점에서의 백테스트이므로, 현재 상장 폐지된 종목이 과거 유니버스에 포함되어 있었는지 검증.
4.  **섹터 밸런싱 강제 로직**: Tech/Healthcare 비중이 특정 섹터로 쏠리지 않도록(예: Tech 100% 방지) 섹터별 최소/최대 슬롯 할당.
5.  **게으른 리밸런싱(Lazy Rebalancing) 도입**: 잦은 매매로 인한 비용 누수를 막기 위해 포트폴리오 변경 델타값의 임계치(Threshold) 상향 조정.

### 2. 실행 가능한 Patch / 실험 제안 (3건)

#### 실험 A: [Infra] 거래 비용 가시화 및 로그 포맷 통일
*   **필요성**: 현재 `rebalance.csv` 로드 에러로 인해 비용 분석 불가. 실제 매매 시 슬리피지/수수료로 인한 성능 하락(Alpha Decay)을 막아야 함.
*   **위험/부작용**: 로그 포맷 변경 시 기존 분석 툴 호환성 깨짐(일시적 대시보드 마비).
*   **실험 정의**:
    1.  `TransactionCostModel`을 보수적으로 설정(Bps 10 -> 20)하여 챔피언 모델 재검증.
    2.  모든 거래 로그를 JSONL 형식으로 강제 변환 후 `aub_rebalance_pinpoint` 재가동.
*   **게이트**: 로그 파일 생성 확인 && 파싱 에러 `0`건.
*   **기대 관측치**: 비용 반영 후 OOS Mean이 1.88에서 1.5~1.6 수준으로 하락하더라도, `Sharpe`가 1.0 이상 유지되면 통과.

#### 실험 B: [Logic] 섹터 로테이션 트리거 (XLK/XLV 모멘텀)
*   **필요성**: Tech와 Healthcare 중심이므로, 두 섹터 ETF(XLK, XLV)의 상대 모멘텀을 관측 지표로 사용하여 비중 조절 필요. 현재 Exposure(0.47~0.84) 변동의 근거를 명확히 함.
*   **위험/부작용**: ETF 신호와 개별 주식(8~14개) 간의 디커플링 발생 시 손실 확대(Tracking Error).
*   **실험 정의**:
    1.  `exp_sector_mom_v1`: XLK > XLV(3개월 모멘텀) 일 때 Tech 비중 60%~80% 허용. 반대의 경우 Healthcare 비중 확대.
    2.  `exp_sector_neutral`: 시장 상황 무관하게 Tech:Health = 50:50 고정.
*   **게이트**: `worst_mdd`가 기존 챔피언 대비 악화되지 않음 (< -20% 유지).
*   **기대 관측치**: 하락장에서 Healthcare 비중 확대로 방어력(MDD 개선) 확인. OOS Min 값 상승(0.43 -> 0.5 이상).

#### 실험 C: [Execution] 변동성 기반 노출(Exposure) 캡핑
*   **필요성**: Exposure Max가 0.84까지 올라감. 하락장에서 과도한 노출은 치명적임. VIX 또는 시장 변동성 지표를 통해 최대 노출도를 동적으로 제한해야 함.
*   **위험/부작용**: 급반등 장세(V-shape recovery)에서 수익 기회 놓침 (Under-participation).
*   **실험 정의**:
    1.  `exp_vol_cap_tight`: VIX > 25 (또는 이에 준하는 변동성) 구간에서 Max Exposure 0.6으로 제한.
    2.  `exp_vol_cap_loose`: 변동성 구간에서 현금 비중 30% 강제 확보.
*   **게이트**: 턴오버(Turnover) 비율이 기존 대비 10% 이상 증가하지 않을 것.
*   **기대 관측치**: 변동성 구간에서의 드로다운(DD) 폭 15% 이상 감소.

### 3. 성능 정체 시 원인 분해 (Diagnosis Logic)

성능이 개선되지 않을 경우, 다음 5단계로 원인을 분해하여 리포트 생성할 것.

1.  **트리거(Trigger) 확인**: 시장 국면(Regime)이 바뀌었는데 모델이 이를 감지했는가? (ETF 지표와 포트폴리오 베타의 상관관계 확인)
2.  **적용(Application) 확인**: 시그널은 발생했으나, 자금 부족이나 슬롯 제한(8~14개)으로 인해 실제 매매가 거부되었는가?
3.  **노출(Exposure) 확인**: 선택된 종목들이 해당 섹터(Tech/Health)를 제대로 대표하고 있는가? (유니버스 내 "잡주" 혼입 여부 점검)
4.  **비용(Cost) 확인**: 리밸런싱 이득보다 거래 비용(Slippage + Commission)이 더 크지 않은가? (로그 복구 후 최우선 확인 사항)
5.  **레짐(Regime) 불일치**: 모델이 "강세장" 로직으로 "횡보/하락장"을 대응하고 있지 않은가? (최근 3개월 OOS 성과를 벤치마크 ETF와 비교)
