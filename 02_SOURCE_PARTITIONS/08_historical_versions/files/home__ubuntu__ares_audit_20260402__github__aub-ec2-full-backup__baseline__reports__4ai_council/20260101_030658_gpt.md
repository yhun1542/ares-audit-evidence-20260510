아래는 **24~48시간 우선순위 TOP5**를 **48시간 자동 루프에 바로 넣을 수 있는 “명령형 체크리스트”** 형태로 정리한 것입니다.  
(현재 tuning/lockbox가 거의 같은 수준으로 **정체 구간**이므로, “점수 올리기”보다 **누수·과최적화·서바이버십·비용·운영 리스크**부터 먼저 깨끗하게 만드는 패치에 우선순위를 둡니다.)

---

## 0) 24~48시간 실행 순서(고정 루프)
1) **E1(누수/서바이버십 감사) → E2(비용 민감도) → E3(노출/리스크 제약) → E4(레짐 게이트) → E5(운영/재현성)**
2) 각 실험은 공통 게이트를 통과해야 다음으로 진행:
   - **데이터 무결성 FAIL=즉시 중단**
   - lockbox_mean 개선 또는 최소 **lockbox_min / worst_mdd 악화 금지**
   - 비용 반영 후 성능이 “의미 있게 남는지” 확인

# TOP5 제안 (각 제안: 왜/위험/최소 실험 2~3개/ PASS 조건)
※ “실험”은 아래 공통 실험 세트 **E1~E5(총 5개)**로 제한하고, 각 제안에서는 해당 실험 ID를 **재사용**합니다(케이스 폭발 방지).

---

## 1) (최우선) 누수/서바이버십/코퍼릿액션 “락다운”
### (a) 왜 필요한가
- 현재 champion vs candidate가 **tuning/lockbox가 거의 동일**하게 움직임 → 모델 개선이 아니라 **데이터/평가 파이프라인의 상한**에 막혀 있을 가능성 큼.
- Tech+Healthcare 단일주(8~14) 전략은 **delisting/merger/액면분할/배당/심볼 변경** 처리 미흡 시 성능이 “그럴듯하게” 고정되는 전형적 패턴이 발생.

### (b) 위험/부작용
- 누수 제거/point-in-time 강화 후 **성능이 하락**할 수 있음(정상 반응).
- 데이터 조인/시계열 정렬 변경으로 과거 리포트와 단절.

### (c) 최소 실험(2~3개)
- **E1**: Point-in-time 감사 + lookahead 강제 차단(특징/라벨 asof-join, time shift, 발표시각 반영)
- **E5**: “락박스/튜닝 분리”를 코드 레벨에서 강제(특징 생성 캐시 키에 split_id 포함, 재사용 금지)
- **E2**: delisting return / corporate action 반영 여부에 따라 비용/수익이 비정상적으로 변하는지 민감도 체크(이상징후 탐지용)

### (d) PASS 조건(게이트)
- (필수) **누수 탐지 테스트 0건**(아래 중 하나라도 뜨면 FAIL)
  - 라벨/특징 timestamp 역전
  - split 간 피처 캐시 공유
  - 미래 가격 기반 지표 사용 흔적
- (성능) lockbox_mean **유지 이상**, 동시에 **lockbox_min 악화 금지**(현재 1.3469 기준 아래로 하락하면 FAIL)
- (리스크) worst_mdd **-11.18%보다 악화 금지**

---

## 2) 비용(수수료/스프레드/슬리피지/임팩트) 미반영 리스크를 “성능 게이트”로 승격
### (a) 왜 필요한가
- 단일주 8~14개 집중 포트는 **회전율이 조금만 올라가도** 실현 성과가 붕괴.
- tuning/lockbox가 비슷하게 정체일 때, 실제론 “거래비용을 빼면” 차이가 사라지는 경우가 많음.

### (b) 위험/부작용
- 비용 모델이 과보수적이면 트레이드가 과도하게 줄고 기회 손실.
- 단일주 유동성 편차(Tech vs Healthcare) 때문에 한쪽으로 바이어스 가능.

### (c) 최소 실험(2~3개)
- **E2**: 비용 민감도 스윕(낮음/기준/높음 3단) + 슬리피지(ATR 또는 $ADV 기반) 온/오프 비교
- **E3**: turnover 상한(예: 일/주 기준) 또는 거래량 대비 주문 크기 상한을 제약으로 추가
- **E4**: 변동성 레짐(ETF 지표)에서만 트레이드 허용/축소하여 불필요 매매 감소

### (d) PASS 조건(게이트)
- (필수) 비용 “높음” 시나리오에서도 **lockbox_mean이 기준 대비 -X% 이내(예: -5% 이내)**로 방어되면 PASS  
- (리스크) turnover 상한 적용 후에도 **포지션 수 8~14 유지**(과도한 현금화 금지)
- (안정성) 비용 반영 후 worst_mdd 악화 금지

---

## 3) 노출(섹터/베타/팩터/단일종목) 과집중을 제약으로 고정
### (a) 왜 필요한가
- Tech+Healthcare 중심 8~14개는 자칫 **빅테크 모멘텀/리스크온**에 사실상 단일 베팅이 됨.
- lockbox가 고정된 구간에서는 “알파”가 아니라 **노출 구조**가 성과를 결정하는 경우가 많음.

### (b) 위험/부작용
- 제약이 너무 강하면 알파가 사라져 성과 하락.
- 섹터 중립을 강제하면 Healthcare 내부 신호가 희석될 수 있음.

### (c) 최소 실험(2~3개)
- **E3**: 하드 제약 패치
  - 단일 종목 최대 비중
  - 섹터(Tech/Healthcare) 비중 밴드
  - 포트 베타/변동성 타겟(예: ex-ante vol target)
- **E2**: 제약 도입 후 거래비용/회전율이 실제로 내려가는지 동시 측정
- **E4**: 레짐이 나쁠 때(예: QQQ 약세/리스크오프) 자동으로 **Healthcare 쪽으로만 축소** 또는 **현금 비중 확대**

### (d) PASS 조건(게이트)
- (성능) lockbox_mean **유지 이상**
- (안정성) lockbox_min **유지 이상**
- (구조) 포지션 수 8~14 유지, 단일 종목 최대비중 위반 0건, 섹터 밴드 위반 0건

---

## 4) 레짐(리스크온/오프) 게이트를 “ETF 관측지표”로만 추가
### (a) 왜 필요한가
- 단일주 전략은 레짐에 따라 알파가 “켜졌다 꺼지는” 일이 흔함.
- ETF는 거래하지 않고 **관측 지표**로만 쓰면 요구사항(ETF 매매 제외) 충족하면서 레짐 대응 가능.

### (b) 위험/부작용
- 게이트가 잘못되면 “좋은 구간을 건너뛰는” 비용 발생.
- 레짐 룰이 과최적화되면 lockbox에서 무력화.

### (c) 최소 실험(2~3개)
- **E4**: 단순 레짐 게이트 2종만 비교(복잡화 금지)
  - Gate-A: QQQ 50D 모멘텀 < 0 또는 QQQ < 200D → 위험 축소
  - Gate-B: XLV/QQQ 상대강도(Healthcare 방어)로 포트 내 Tech:HC 비중 자동 조정
- **E2**: 게이트 도입으로 turnover/슬리피지가 실제 줄어드는지 비용 기준으로 평가
- **E3**: 게이트 ON 구간에서만 리스크 타겟(변동성)을 낮춰 MDD 방어 확인

### (d) PASS 조건(게이트)
- (핵심) worst_mdd **개선 또는 동일**, 최소한 **-11.18% 악화 금지**
- (성능) lockbox_mean **소폭 악화는 허용하되**(방어 목적), lockbox_min이 개선되면 PASS 가중
- (거래) 불필요 매매 감소(예: turnover 10~30% 감소) 관측되면 가점

---

## 5) 운영 리스크(재현성/캐시/실험 레지스트리/48h 자동 루프) “실패 방지 장치” 추가
### (a) 왜 필요한가
- 현재처럼 성능이 미세하게만 움직일 때, 실제 병목은 전략이 아니라 **실험 재현성/캐시 오염/스플릿 혼선**인 경우가 많음.
- 48시간 루프에서 “한 번의 이상치”가 다음 후보 선정(select-best)을 오염시키면 장기적으로 잘못된 방향으로 수렴.

### (b) 위험/부작용
- 로그/체크 강화로 런타임 증가.
- 엄격 게이트로 PASS가 줄어 탐색 속도 저하(대신 신뢰도 상승).

### (c) 최소 실험(2~3개)
- **E5**: 재현성 고정(seed, 데이터 스냅샷 해시, 피처 캐시 키에 split_id/commit hash 포함)
- **E1**: 데이터 품질 경보(결측 급증, 거래정지, 심볼 변경 감지 시 해당 기간/종목 제외 또는 플래그)
- **E2**: 비용/체결 모델이 꺼졌을 때와 켜졌을 때 결과가 “비정상적으로 동일”하면 FAIL 처리(비용 파이프라인 미적용 탐지)

### (d) PASS 조건(게이트)
- 동일 커밋/데이터 해시에서 재실행 시 성능 지표 변동이 허용오차 이내(예: Sharpe/목표지표 ±0.5%p)
- 비용 모델 on/off 결과가 “거의 동일”하면 FAIL(적용 누락 가능성)
- 실험 산출물(리포트/아티팩트) 누락 0건

# 공통 실험 세트 정의 (E1~E5) — 48시간 루프용
각 실험은 **(1) 실험 정의 (2) 게이트 (3) 기대 관측치**로 고정합니다.

## E1) Leak/Survivorship/CorporateAction Audit 패치
1) 실험 정의  
- feature/label에 **strict as-of join + 발표시각 반영 + 1-bar shift** 강제  
- delisting/merger/심볼변경 이벤트를 수익률에 반영하거나 해당 구간 마스킹
2) 게이트  
- 누수 탐지 0건, split 간 캐시 공유 0건
3) 기대 관측치  
- tuning이 소폭 하락해도 정상  
- lockbox_min이 오히려 더 안정화되는 경우가 많음(가짜 알파 제거)

## E2) 비용/슬리피지 민감도 스윕
1) 실험 정의  
- 비용 3단(낮음/기준/높음) + 슬리피지 모델(OFF/ON) 2×3 매트릭스(단, 동일 실험 ID로 묶어서 리포트만 6칸)
2) 게이트  
- “높음” 비용에서도 성능이 붕괴하지 않을 것  
- on/off가 완전히 동일하면 적용 누락으로 FAIL
3) 기대 관측치  
- turnover 높은 전략은 여기서 바로 드러남  
- 비용에 강한 전략만 다음 단계로

## E3) 노출/리스크 제약(8~14 종목 유지)
1) 실험 정의  
- 포지션 수 8~14 강제  
- 단일종목 max weight, 섹터 밴드, vol target, beta cap 중 **2개까지만** 먼저 적용(복잡화 금지)
2) 게이트  
- 위반 0건, worst_mdd 악화 금지
3) 기대 관측치  
- lockbox_mean은 비슷해도 tail risk가 줄어드는 형태가 목표

## E4) ETF 관측지표 기반 레짐 게이트(ETF 매매 없음)
1) 실험 정의  
- QQQ/XLV/SPY 등으로 risk-on/off 판단 → 포트 위험도/섹터 비중만 조절
2) 게이트  
- worst_mdd 개선 또는 동일  
- 거래 감소가 관측되면 가점
3) 기대 관측치  
- 수익률보다 **MDD/최저구간 방어**에서 차이 발생

## E5) 운영/재현성/캐시 오염 방지
1) 실험 정의  
- 실험 아티팩트에 (data_hash, git_commit, split_id, cost_model_version) 강제 기록  
- 캐시 키에 split_id 포함, lockbox 접근 금지 가드
2) 게이트  
- 재실행 변동 허용오차 이내  
- 아티팩트 누락 0건
3) 기대 관측치  
- 성능이 “움직이지 않는 이유”가 전략이 아니라 파이프라인임을 빠르게 배제/확정

# 성능이 안 움직일 때: 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래 순서대로 “증상 → 즉시 체크 → 결론”으로 분해하십시오(질문 없이 실행 항목만).

## A) 트리거(신호가 실제로 변하나?)
- **체크**: 예측/스코어의 시계열 분산, 종목 간 분산, 상위랭크 교체율(Top-K turnover) 리포트 생성  
- **결론 규칙**
  - 분산이 너무 낮음 → 신호가 상수화/정규화 버그/결측 대체로 평탄화
  - 교체율이 0에 가까움 → 리밸런싱/필터가 신호를 막거나 캐시가 고정

## B) 적용(신호가 포지션으로 전달되나?)
- **체크**: “원시 스코어 → 타깃 웨이트 → 실제 체결 웨이트” 3단계 로그를 샘플 날짜 20개 출력  
- **결론 규칙**
  - 타깃은 변하는데 실제가 고정 → 포지션 제한/주문 실패/리밸런싱 조건 문제
  - 타깃 자체가 8~14를 못 채움 → 유니버스 필터 과도 또는 데이터 결측 급증

## C) 노출(알파가 아니라 베타/섹터가 결정하나?)
- **체크**: 포트 수익을 (시장β, 섹터, 잔차)로 단순 분해(회귀로 충분)  
- **결론 규칙**
  - 설명력이 β/섹터에 쏠림 → 알파보다 레짐/섹터 베팅, E3/E4 우선

## D) 비용(거래가 수익을 먹나?)
- **체크**: 총수익–비용의 브리지(거래당 평균 비용, 일별 비용/수익 비율, 슬리피지 상위 10일)  
- **결론 규칙**
  - 비용이 특정 종목/특정 변동성 구간에 집중 → 유동성 제약 또는 레짐 게이트(E2/E4)

## E) 레짐(잘 되는 구간이 제한적인가?)
- **체크**: QQQ 추세/변동성 상태별 성과 테이블(예: QQQ>200D & VIX proxy high/low)  
- **결론 규칙**
  - 특정 상태에서만 유의미 → E4로 “그 상태에서만 켜기/리스크 낮추기”가 합리적

---

## 마지막으로: 바로 실행할 “명령형 체크리스트”(24~48h)
1) **E1부터 실행**: 누수/서바이버십/코퍼릿액션 감사 리포트 생성, FAIL이면 즉시 중단  
2) **E2 실행**: 비용(3단)×슬리피지(on/off) 민감도 매트릭스 리포트 생성, 비용에 약하면 전략 수정 없이 FAIL 처리  
3) **E3 실행**: 8~14 유지하면서 단일종목 max + vol target(또는 섹터 밴드) 2개만 적용해 lockbox 재평가
