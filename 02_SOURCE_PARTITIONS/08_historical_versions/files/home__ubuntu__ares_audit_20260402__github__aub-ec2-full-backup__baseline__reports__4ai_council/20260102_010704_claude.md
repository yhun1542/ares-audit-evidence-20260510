## 0. 사전 점검 체크리스트 (루프 진입 전 필수)

```
□ 누수 점검: candidate가 lockbox_min +0.33 vs champion -0.05 → 3σ 이상 격차, look-ahead 재점검
□ 과최적화: tuning_min -1.49 (candidate) vs lockbox_min +0.33 → tuning 분산 과다, fold별 편차 확인
□ 서바이버십: 종목 universe 고정일자 확인 (delisted 포함 여부)
□ 비용: 슬리피지 10bp + 수수료 적용 여부 로그 확인
□ 운영 리스크: worst_mdd -4.8% candidate가 실제 운용시 2배 가능성 (레버리지/갭)
```

## 1. PATCH #1: Tuning-Lockbox 분산 정합성 강화

| 항목 | 내용 |
|------|------|
| **왜 필요** | tuning_min -1.49 vs lockbox_min +0.33 = 1.8σ 이상 괴리 → 과최적화 또는 레짐 편향 의심 |
| **위험/부작용** | 필터 강화 시 PASS율 급감 → 실험 정체 |
| **최소 실험** | |

### 실험 정의

| ID | 내용 | 게이트 | 기대 관측치 |
|----|------|--------|-------------|
| P1-a | `tuning_std / lockbox_std < 1.5` 조건 추가 | ratio ≤ 1.5 | candidate 50% 이상 FAIL 예상 |
| P1-b | fold별 worst return을 lockbox 대비 ±20% 밴드 체크 | 14 folds 중 12+ 통과 | 이상치 fold 식별 |
| P1-c | tuning에서 worst 2 folds 제외 후 재계산 | 제외 후에도 lockbox 우위 유지 | 강건성 확인 |

**PASS 조건**: `(lockbox_mean - tuning_mean) / tuning_std < 0.5` AND `tuning_min > -1.0`

## 6. 성능 미변동 시 원인 분해 트리

```
성능 불변
├─ [트리거] 시그널 발생 빈도 동일? → 시그널 임계값 점검
├─ [적용] 시그널 → 주문 변환율? → 필터/제약 조건 점검
├─ [노출] 실제 포지션 크기 변화? → 사이징 로직 점검
├─ [비용] 회전율 증가로 비용 상쇄? → 순수익 vs 총수익 분리
└─ [레짐] 테스트 기간 레짐 단일? → 레짐별 성능 분해
```
