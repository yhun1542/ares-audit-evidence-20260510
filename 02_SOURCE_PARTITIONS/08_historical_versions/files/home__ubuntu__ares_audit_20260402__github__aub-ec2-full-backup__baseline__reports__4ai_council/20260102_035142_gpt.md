## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — **명령형 체크리스트**

### 1) **누수(Leakage)·시점 정렬(Time Alignment) 우선 감사**
- **즉시 수행**
  - 모든 피처에 대해 “관측 시점(available_at)” 메타데이터를 강제하고, 주문 시점(예: T+1 open) 대비 미래 데이터 접근을 차단하라.
  - 신호 생성 bar와 체결 bar를 분리(“close로 신호 → next open 체결” 등)하고, 동일 bar의 high/low/close를 체결에 사용하지 못하게 막아라.
  - 튜닝/락박스 간 성능 괴리가 커지는 피처(특히 재무/이벤트성)를 자동 플래그하라.

- **왜 필요한지**
  - 현재 Champion이 tuning_mean(3.47) 대비 lockbox_mean(2.89)로 “현장(락박스)”에서 약화되는 패턴이 보이며, 이는 **시점 누수/정렬 오류가 가장 흔한 원인**이다(과최적화보다 먼저 점검).

- **위험/부작용**
  - 누수를 제거하면 단기적으로 수익률이 하락할 수 있다(“진짜 성능”으로 정규화).
  - 피처가 대량 무효화되면 신호 밀도가 떨어져 거래가 줄어들 수 있다.

- **최소 실험(패키지 1: Leakage Sentinel) — 48시간 루프형**
  - (1) **실험 정의**
    - **Variant A**: 모든 가격/기술지표 피처를 `t`까지 관측 → `t+1 open` 체결로 강제(동일 bar 참조 금지).
    - **Variant B**: 재무/펀더멘털 피처에 “공시 지연(예: 10-Q/10-K는 보수적으로 +30~45일, 일간 피드도 +1~2일)”을 강제.
    - **Variant C**: “당일 종가 기반 랭킹”을 “전일 종가 기반 랭킹”으로 일괄 스위치(룩어헤드 의심 제거용).
  - (2) **게이트(사전 차단 조건)**
    - 피처별 `max(feature_timestamp) <= decision_timestamp` 위반이 0건이어야 실행 통과.
    - 튜닝 대비 락박스 괴리(`tuning_mean - lockbox_mean`)가 **기존 대비 악화**되면 즉시 중단(누수 제거가 아니라 다른 버그 가능).
  - (3) **기대 관측치**
    - tuning_mean은 다소 하락 가능, 대신 **lockbox_mean의 상대적 방어** 및 “tuning-lockbox 갭 축소”.
    - worst_mdd가 현재(-0.0704) 근처에서 **악화되지 않거나 소폭 개선**.

- **PASS 조건**
  - `lockbox_mean` **유지(±5%) 또는 개선**, 그리고 `tuning_mean - lockbox_mean` 갭 **10% 이상 축소**.
  - worst_mdd **악화 금지**(≤ -0.0704 유지 또는 개선).

### 2) **비용(수수료/스프레드/임팩트)·회전율을 성능에 “실제 반영”**
- **즉시 수행**
  - 체결 비용을 “고정 수수료”가 아니라 **스프레드+슬리피지(ADV/변동성 연동)**로 모델링하라.
  - turnover 상한/패널티를 모델에 직접 넣어 “과회전 알파”를 제거하라.
  - 백테스트 결과에 **gross/net 분리 리포트**(비용 전/후, 비용 항목별)를 자동 저장하라.

- **왜 필요한지**
  - Tech/Healthcare 8~14종목 집중은 괜찮지만, 리밸런스가 잦으면 **순성과가 급격히 붕괴**한다. 비용 미반영은 누수 다음으로 가장 큰 “가짜 알파” 원인.

- **위험/부작용**
  - 비용을 현실화하면 기존 전략이 무력화될 수 있다(하지만 이게 정상적인 정리 과정).
  - 슬리피지 모델 파라미터가 과보수면 트레이드가 과도하게 억제될 수 있다.

- **최소 실험(패키지 2: Cost Reality Patch)**
  - (1) **실험 정의**
    - **Variant A**: 스프레드 비용 = `k * (spread_bps)` + 슬리피지 = `c * (|qty|/ADV) * vol` 형태의 단순 임팩트 모델 추가.
    - **Variant B**: turnover penalty(예: 일/주간 turnover에 선형 패널티)를 목적함수에 포함.
    - **Variant C**: 리밸런스 빈도 3안(매일/주2회/주1회)만 테스트(케이스 폭발 금지).
  - (2) **게이트**
    - net 성과 리포트에서 “비용이 음수로 계산” 같은 회계 버그 0건.
    - 평균 일회전율이 상한(예: 30~50%/day 같은 비현실) 초과 시 자동 FAIL.
  - (3) **기대 관측치**
    - gross는 유지되나 net이 떨어지며, **turnover가 낮아진 변형이 lockbox에서 더 안정**적으로 보일 것.

- **PASS 조건**
  - 비용 반영 후에도 `lockbox_mean(net)`이 **Champion lockbox_mean의 80% 이상** 유지(≈ 2.31 이상) 또는 worst_mdd 개선이 동반될 것.
  - turnover(일 또는 주)가 **기존 대비 20%+ 감소**.

### 3) **서바이버십/코퍼레이트 액션(분할·배당·상폐) 처리로 “락박스 붕괴” 방지**
- **즉시 수행**
  - 가격은 **Total Return(배당/분할 반영)** 기준으로 통일하라(신호/체결/평가 모두 같은 기준).
  - 상폐/티커 변경/합병 이벤트에서 “0으로 가격 튐” 같은 데이터 결손을 **명시적으로 처리**하라.
  - 유니버스 구성에 **시점 일관성(point-in-time)**을 강제하라(특히 시총/거래대금 필터가 미래를 보면 누수).

- **왜 필요한지**
  - Tech/Healthcare 중심이더라도 바이오/헬스케어는 이벤트가 많고, 데이터/상폐 처리가 약하면 **서바이버십 편향**으로 튜닝만 좋아진다.

- **위험/부작용**
  - 상폐 종목이 포함되면 과거 성과가 악화될 수 있다(정상).
  - 데이터 공급원에 따라 상폐 리턴 처리가 어려워 구현 난이도가 있다.

- **최소 실험(패키지 3: Survivorship Hardening)**
  - (1) **실험 정의**
    - **Variant A**: point-in-time 유니버스 스냅샷(매 리밸런스 시점에만 종목 선정 근거를 저장) 적용.
    - **Variant B**: Total Return 시계열로 전환(가능하면) 또는 배당/분할 조정 단일화.
    - **Variant C**: 상폐/거래정지/가격 결손 발생 시 “거래 금지 + 평가가격 보수적 처리(전일가/청산가 규칙)”를 룰로 고정.
  - (2) **게이트**
    - “유니버스 선택에 사용한 지표의 timestamp가 미래”인 케이스 0건.
    - 코퍼레이트 액션 이벤트 데이의 수익률 outlier(예: ±80% 이상)가 원인 미상으로 다수 발생 시 중단.
  - (3) **기대 관측치**
    - 튜닝 성과 하락 가능, 대신 **락박스 min/하방이 개선**(현재 champion lockbox_min 1.53은 양호하지만, 장기적으로 안정성 강화).

- **PASS 조건**
  - `lockbox_min`이 **악화되지 않을 것**(≥ 1.53 유지 또는 소폭 개선).
  - fold별 outlier 원인 미상 케이스 **0건**(리포트로 증빙).

### 4) **Tech+Healthcare 8~14종목 제약 내에서 “노출(Exposure)·레짐(Regime) 게이트” 추가 (ETF는 관측만)**
- **즉시 수행**
  - 매매는 개별주만 유지하되, **QQQ/XLV/XBI/VIX/TLT(또는 IEF)**를 “리스크 온/오프 관측 지표”로만 사용하라.
  - 포지션 수(8~14) 유지 + 상관/집중도를 제한(단일 종목/단일 서브섹터 쏠림 제한)하라.
  - 레짐이 불리할 때는 “현금 비중”을 허용하라(ETF 매매 없이도 가능).

- **왜 필요한지**
  - Tech/Healthcare는 레짐(금리·변동성)에 민감하다. 레짐 게이트 없이 알파만 믿으면 **worst_mdd가 커지는 구간**이 생긴다.

- **위험/부작용**
  - 게이트가 과하면 기회 손실(상승장에서 덜 참여).
  - 레짐 지표가 지연되면 whipsaw 가능.

- **최소 실험(패키지 4: Regime/Exposure Gate)**
  - (1) **실험 정의**
    - **Variant A**: `VIX` 상단 임계 초과 시 총 노출(총 베타/총 투자비중) 30~50% 축소.
    - **Variant B**: `QQQ < QQQ_200DMA`이면 Tech 비중 상한 강화(예: 60%→40%), Healthcare는 유지/소폭 확대.
    - **Variant C**: `XLV/QQQ` 상대강도 악화 시(헬스케어도 동반 약세) 현금 비중 허용(최대 30%).
  - (2) **게이트**
    - 포지션 수 8~14를 깨지 말 것(단, 현금 허용 시 “종목 수는 유지하되 가중치 축소/0 허용”으로 구현).
    - 섹터 노출(Tech/Healthcare 외) 0에 가깝게 유지(분류 에러 시 자동 FAIL).
  - (3) **기대 관측치**
    - `worst_mdd`가 **의미 있게 감소**하고, lockbox_mean은 소폭 감소하거나 유지.

- **PASS 조건**
  - `worst_mdd` **10% 이상 개선**(예: -0.0704 → -0.063 이하) + `lockbox_mean` **5% 이상 악화 금지**.

### 5) **운영 리스크(데이터 지연/결측·어닝·유동성·체결 실패) “48시간 자동 루프”에 하드 가드레일 추가**
- **즉시 수행**
  - 데이터 최신성 체크(종가/분봉/기업행사)가 실패하면 **거래 자체를 스킵**하라(“잘못된 거래”가 최악).
  - 어닝(실적 발표) 전후 N일(예: -1~+1 또는 -2~+1) 블랙아웃 규칙을 옵션으로 추가하라.
  - 유동성/스프레드 필터(최소 ADV$, 최대 스프레드 bps)를 강제하라.

- **왜 필요한지**
  - 백테스트 성능이 좋아도 운영에서 깨지는 1순위가 “데이터/체결/이벤트”다. 특히 헬스케어는 갭·뉴스가 잦다.

- **위험/부작용**
  - 거래 빈도가 줄어 수익 기회가 감소.
  - 어닝 캘린더 품질이 낮으면 잘못된 블랙아웃이 생길 수 있다.

- **최소 실험(패키지 5: Ops Guardrails)**
  - (1) **실험 정의**
    - **Variant A**: “데이터 stale(예: 최신 bar 누락/거래정지 플래그)”면 그날 리밸런스/주문 전부 스킵.
    - **Variant B**: 어닝 블랙아웃(-1~+1) 적용 vs 미적용 비교(단 2안만).
    - **Variant C**: 유동성 필터(ADV$ 하한 + 스프레드 상한) 적용 후 성능/회전율 비교.
  - (2) **게이트**
    - 스킵 발생 시 로그/리포트에 원인 100% 기록(미기록 스킵=FAIL).
    - 주문 수량이 ADV 대비 과도(예: 1~2% 초과)면 자동 제한.
  - (3) **기대 관측치**
    - 성과가 드라마틱하게 오르기보다는 **꼬리 리스크/운영 실패 확률 감소**가 관측될 것.

- **PASS 조건**
  - “운영 규칙 위반(데이터 결측 거래, 거래정지 거래, 미기록 스킵)” 0건.
  - worst_mdd 악화 금지 + 거래 실패/이상치 리포트 감소.

## 48시간 자동 루프에 바로 꽂는 실행 순서(명령형)
1) **패키지 1~5를 각각 feature flag로 분리**하고, 동일한 평가 파이프라인에서 on/off만 바뀌게 만들라.  
2) 아래 커맨드를 **패키지별로 한 번씩** 돌려 “select-best”가 패키지 내 Variant를 고르게 하라.
```bash
python3 experiment_system/tools/aub_autopilot.py --registry experiment_system/config/module_registry.yaml --run --select-best
python3 experiment_system/tools/system_autopilot.py --spec experiment_system/config/system_candidates.yaml --run
python3 experiment_system/tools/aub_next_fix.py --registry experiment_system/config/module_registry.yaml --output baseline/reports/next_fix.md
```
3) **승급 규칙을 단일화**하라: “락박스(mean/min) + worst_mdd + turnover(net)” 4개 지표로만 PASS/FAIL을 결정하라.  
4) PASS한 패키지만 Champion에 머지하고, 나머지는 즉시 롤백하라.

## 성능이 안 움직일 때 “원인 분해 아이디어” (트리거/적용/노출/비용/레짐)
아래를 **같은 기간(rolling window)로** 나눠 리포트화하라. (질문 없이 바로 추가 가능한 진단축)

### A) Trigger(신호 자체 문제)
- **진단**
  - 신호의 정보계수(IC) / rank IC를 기간별로 추적하라.
  - “신호 생성 시점 vs 체결 시점” 수익률을 분리해 `signal->next_open`, `signal->close`를 각각 보라.
- **의심 트리거**
  - 피처 드리프트(특히 재무/뉴스/대체데이터)
  - 시점 정렬 오류(누수 제거 시 tuning만 감소하고 lockbox 안정화되는 패턴)

### B) Application(적용/리밸런스/포지션 구성)
- **진단**
  - 리밸런스 빈도별 성과/turnover 곡선을 만들라.
  - “선정 알파”와 “사이징 알파”를 분리(동일 종목 선택 후 equal-weight vs 현재 사이징 비교).
- **의심 트리거**
  - 과회전, 리밸런스 타이밍(갭 많은 종목에서 open 체결 손실)

### C) Exposure(원치 않는 베타/팩터/집중)
- **진단**
  - 포트폴리오 수익을 `QQQ, XLV`에 회귀해 베타를 굴려보라(ETF는 관측만).
  - 상위 1~3종목 기여도/드로우다운 기여도를 매 기간 계산하라.
- **의심 트리거**
  - 사실상 QQQ 롱(또는 금리 민감 성장주 롱)으로 변질
  - 헬스케어 내 바이오 쏠림(XBI 민감)

### D) Cost(비용/슬리피지/체결 실패)
- **진단**
  - gross → net 브리지(수수료/스프레드/임팩트/갭 비용)를 항목별로 쪼개라.
  - ADV 대비 주문비율, 스프레드 bps 분포를 저장하라.
- **의심 트리거**
  - 락박스에서만 성과가 무너질 때: 비용/유동성/체결 가정 차이가 원인인 경우가 많음

### E) Regime(레짐/매크로)
- **진단**
  - 금리(예: TLT/IEF 수익률), 변동성(VIX), QQQ 추세(200DMA)로 구간을 나눠 성과 매트릭스를 만들라.
- **의심 트리거**
