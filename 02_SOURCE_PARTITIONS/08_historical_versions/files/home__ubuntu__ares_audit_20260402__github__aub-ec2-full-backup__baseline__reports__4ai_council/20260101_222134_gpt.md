## 24~48시간 우선순위 TOP5 (명령형 체크리스트)

### 1) **누수/서바이버십/룩어헤드 “하드 차단”을 먼저 고정**
- **(a) 왜 필요한지**
  - 현재 후보가 lockbox에서 매우 강함에도( lockbox_min이 +로 유지) “구현상 누수”가 있으면 다음 구간에서 바로 붕괴합니다.
  - 특히 Tech/Healthcare 개별주(8~14) 구성은 **종목 마스터/상장폐지/티커 변경/기업행위**에서 서바이버십이 자주 터집니다.
- **(b) 위험/부작용**
  - 데이터가 point-in-time로 바뀌면 성능이 크게 꺾일 수 있음(정상).
  - 유효 샘플 수 감소 → 신호 불안정, 회전율 증가 가능.
- **(c) 최소 실험(아래 공용 실험 E1~E4 중 사용)**
  - **E1(데이터 무결성 게이트 강화)** 적용
  - **E2(서바이버십/기업행위 리플레이 게이트)** 적용
- **(d) PASS 조건**
  - (필수) **룩어헤드/미래값 사용 0건**(게이트 통과 로그로 확인)
  - (필수) lockbox에서 **mean 5% 이내 하락**이면 “통과”(누수 제거 비용으로 허용)
  - (권장) worst_mdd 악화가 **+2%p 이내**


### 2) **비용/슬리피지/회전율을 “락박스 기준”으로 보수적으로 반영**
- **(a) 왜 필요한지**
  - 개별주 8~14개 집중 포트는 **체결 미스/스프레드/갭**이 실현손익에 직접 반영됩니다.
  - 현재 지표들이 ‘이론 성과’에 가까우면, 실거래에서 성능이 “안 움직이는” 대표 원인이 됩니다(비용이 알파를 먹음).
- **(b) 위험/부작용**
  - 성능 급락 가능(정상), 대신 **현실적 생존성 증가**
  - 턴오버 제한 시 기회 손실로 평균수익 감소 가능
- **(c) 최소 실험**
  - **E3(보수 비용모델 + turnover cap + 거래불가일/갭 처리)** 적용
- **(d) PASS 조건**
  - (필수) lockbox_mean이 **기존 champion 대비 +5% 이상** 또는, mean이 비슷하더라도 **lockbox_min이 더 개선**되면 통과
  - (필수) 연환산 turnover/거래횟수가 **상한 이내**(게이트로 강제)
  - (권장) worst_mdd **-0.09 → -0.07 이하** 개선이면 강한 통과


### 3) **운영 리스크: 48시간 자동루프 “실패-안전(fail-safe)”를 우선 고정**
- **(a) 왜 필요한지**
  - 자동 루프에서 가장 치명적인 건 “성능”이 아니라 **중복 주문/데이터 결측 시 포지션 꼬임/리밸런싱 폭주**입니다.
  - 특히 8~14 집중은 단일 종목 장애가 포트 전체를 흔듭니다.
- **(b) 위험/부작용**
  - 방어 로직이 과하면 거래 빈도↓, 수익 기회↓
  - 장애 시 현금 비중↑(의도된 안전)
- **(c) 최소 실험**
  - **E4(운영 게이트: 데이터 결측/프라이스 점프/유동성 부족 시 HOLD + 포지션 동결)** 적용
- **(d) PASS 조건**
  - (필수) 48시간 동안 백테스트/리플레이/라이브 페이퍼에서 **중복 리밸런스 0건**
  - (필수) 결측/이상치 이벤트 주입 시 **거래 중단 후 정상 복귀**(포지션 수 불변)
  - (권장) 일별 거래횟수 상한 준수(게이트 로그)


### 4) **과최적화 억제: “선택/튜닝/락박스” 경로를 단순화하고 게이트로 고정**
- **(a) 왜 필요한지**
  - tuning_mean이 과도하게 높고 tuning_min이 깊게 음수인 패턴은 “좋아 보이는 조합만 선택”했을 가능성이 큼.
  - 지금 단계에선 성능 최대화보다 **일관성(분산 감소)**이 우선입니다.
- **(b) 위험/부작용**
  - 단기 평균수익 감소 가능
  - 실험 통과율 하락(정상, 대신 신뢰도↑)
- **(c) 최소 실험**
  - E1/E2에서 **게이트를 ‘선행 통과’ 조건**으로 하고, 그 다음에만 성능 비교(선 필터 후 선택)로 변경
- **(d) PASS 조건**
  - (필수) “락박스 기준”으로만 select-best 수행(로그/리포트로 확인)
  - (권장) tuning↔lockbox 괴리(예: mean 비율)가 **축소**


### 5) **노출 관리: Tech+Healthcare 8~14개 집중에서 ‘의도치 않은 베타/레짐’을 분리**
- **(a) 왜 필요한지**
  - QQQ/XLV 레짐(금리/리스크온오프)에 따라 동일한 신호가 먹히는 구간이 갈립니다.
  - ETF는 매매 제외지만 **관측지표(레짐 스위치/리스크 스케일)**로 쓰면 “성능이 안 움직이는” 기간을 줄일 수 있습니다.
- **(b) 위험/부작용**
  - 레짐 분류가 틀리면 신호를 꺼서 수익을 놓칠 수 있음
  - 과도한 조건 추가는 과최적화 유발 → 최소한으로
- **(c) 최소 실험**
  - E3에서 **리스크 스케일만** 추가(예: QQQ 추세/변동성 기반 포지션 크기 조정), 종목 선택 로직은 그대로
- **(d) PASS 조건**
  - (필수) worst_mdd가 **개선** 또는 동일 수준에서 lockbox_min 개선
  - (권장) 하락장 구간(리스크오프)에서 손실 꼬리 감소(분위수 손익 개선)

## 48시간 자동 루프에 바로 넣을 “실행 가능한 공용 실험 4개” (3~5개 제한 준수)

아래 4개만 돌리고, 위 TOP5의 항목들은 **이 4개 실험 결과로 판단**하세요(케이스 폭발 방지).

### E1) 데이터 누수 게이트 강화 (point-in-time / 라벨 시점 / 피처 지연)
1) **실험 정의**
   - 모든 피처에 `asof` 시점 강제, 다음 중 하나라도 위반 시 FAIL:
     - 당일 종가로 당일 체결을 가정하는 룩어헤드
     - 리밸런스 시점 이후 공시/재무 반영
     - 리턴 라벨이 피처보다 시간상 앞서는 오류
2) **게이트**
   - “룩어헤드 탐지 0건” + “피처 최대 시차 ≥ 1 bar” 고정
3) **기대 관측치**
   - tuning_mean 하락 가능(정상)
   - lockbox_mean 변화는 제한적이거나 소폭 하락
   - fold 간 분산 감소(안정성↑)

### E2) 서바이버십/기업행위 리플레이 게이트 (delist/merge/split)
1) **실험 정의**
   - 종목 마스터를 날짜 기준으로 스냅샷(상장/상폐/티커 변경 반영)
   - split/dividend 반영을 시점 일관되게 재생
2) **게이트**
   - 상폐 종목이 과거에 “영구 생존”으로 남아있으면 FAIL
   - 기업행위 조정 누락 시 FAIL
3) **기대 관측치**
   - 특정 구간 성능 급변(정상)
   - 극단적 드로우다운/급등이 완화되는 경우가 많음

### E3) 비용/회전율/포지션 제약 통합 (현실성 패치)
1) **실험 정의**
   - 거래비용: 고정 커미션 + 스프레드/슬리피지(보수적으로)
   - turnover cap(일/주 단위) + 리밸런스 최소 단위(불필요한 잔거래 제거)
   - 보유 종목 수 8~14 강제, Tech+Healthcare 중심 유지(섹터 드리프트 방지)
   - ETF(QQQ/XLV 등)는 **매매 금지**, 신호/리스크 스케일 지표로만 사용
2) **게이트**
   - 평균 보유종목수 8~14 유지 실패 시 FAIL
   - turnover cap 초과 시 FAIL
3) **기대 관측치**
   - gross 성과는 줄지만 net(비용 차감 후) 성과의 신뢰도↑
   - lockbox_min 개선(꼬리손실 완화)이 나오면 매우 긍정적

### E4) 운영 안전 게이트 (결측/급변/유동성/리밸런스 폭주 방지)
1) **실험 정의**
   - 데이터 결측/가격 점프/거래정지/유동성 급감 이벤트 시:
     - 해당 종목 주문 금지 + 포트 리밸런스 동결(hold) 또는 대체 규칙 수행
   - 리밸런스 쿨다운(예: n-bar 내 재조정 금지)로 폭주 방지
2) **게이트**
   - 중복 주문/중복 리밸런스 0건
   - 이벤트 주입 시 포지션 수/총 익스포저가 정책 범위를 벗어나면 FAIL
3) **기대 관측치**
   - 성과 자체는 큰 변화 없을 수 있으나,
   - “실거래에서 성능이 안 나오는” 운영 문제의 대부분이 제거됨

## 바로 실행할 커맨드 체크리스트 (24~48h)

1) **현재 자동 루프 그대로 1회 실행(기준 로그 확보)**
```bash
python3 experiment_system/tools/aub_autopilot.py --registry experiment_system/config/module_registry.yaml --run --select-best
python3 experiment_system/tools/system_autopilot.py --spec experiment_system/config/system_candidates.yaml --run
python3 experiment_system/tools/aub_next_fix.py --registry experiment_system/config/module_registry.yaml --output baseline/reports/next_fix.md
```

2) **E1~E4를 “게이트 선적용 → 그 다음 성능 비교”로 묶어서 1개 후보군으로 실행**
- 실행 방식은 기존 autopilot 파이프라인에서 **(a) 게이트 모듈 우선**, **(b) 비용/운영 제약 후처리** 순으로만 고정.
- 산출물: 각 실험에 대해 `tuning_mean/min`, `lockbox_mean/min`, `worst_mdd`, turnover, 평균 보유종목수, 섹터 비중 로그.

3) **PASS/FAIL을 lockbox 중심으로 자동 선택**
- `--select-best`가 tuning 기준이면, **lockbox 기준으로만** 고치거나 래핑 스크립트로 강제.

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)

아래 순서대로 “어디서 막히는지”만 확인하는 진단 트리(질문 없이 실행 관점).

1) **Trigger(신호 발생)**
- 체크: 신호가 실제로 발생하는가? (일별/주별 non-zero rate)
- 증상: 신호 발생률이 급감/0 → 성능 정체
- 조치: E1/E2 후 신호 발생률 변화 비교(데이터 시점/상폐 반영으로 트리거가 사라졌는지)

2) **Apply(게이트/필터에서 차단)**
- 체크: 신호는 뜨는데 게이트가 대부분 막는가? (gate pass rate)
- 증상: pass rate 과도하게 낮으면 “거래를 안 해서” 성능이 안 움직임
- 조치: 게이트 로그에 “FAIL 사유 상위 3개”를 집계해 한 가지만 완화(동시에 여러 개 손대지 않기)

3) **Exposure(노출/포지션 구성)**
- 체크: 8~14개 유지되는지, Tech/Healthcare 드리프트 없는지, 단일 종목 비중 과대 없는지
- 증상: 항상 비슷한 대형주로 쏠리면 벤치(QQQ/XLV)와 구분이 안 돼 “알파가 안 보임”
- 조치: E3에서 포지션 수/상한/섹터 바운더리 고정 후 alpha(벤치 대비)만 분리 관측

4) **Cost(비용이 알파를 상쇄)**
- 체크: gross(비용 전)와 net(비용 후) 격차, turnover와 손익의 상관
- 증상: gross는 좋은데 net이 평평 → 비용/슬리피지 문제
- 조치: E3 비용모델을 보수적으로 올렸을 때도 lockbox_min이 유지되는지로 생존성 판단

5) **Regime(시장 레짐 미스매치)**
- 체크: QQQ/XLV 추세, 금리/변동성(관측지표) 구간별 성과 분해
- 증상: 특정 레짐에서만 벌고 나머지에서 다 토함 → 전체로 보면 “안 움직임”
- 조치: ETF는 매매하지 말고, **리스크 스케일만**(포지션 크기/현금 비중) 최소로 적용(E3)

6) **Ops(운영/실행 리스크)**
- 체크: 리밸런스 중복, 데이터 결측 시 포지션 꼬임, 주문 거절 처리
- 증상: 백테스트는 괜찮은데 실거래/페이퍼에서 수익이 안 남
- 조치: E4의 HOLD/동결/쿨다운 게이트로 “실행 품질”부터 고정

### 결론적 우선순위(48h 내 실제로 이길 확률 순)
1) **E1+E2 (누수/서바이버십) 먼저 고정** → “진짜 성과”만 남기기  
2) **E3 (비용+턴오버+8~14 제약)로 현실화** → 성능 정체의 최빈 원인 제거  
3) **E4 (운영 안전)로 자동루프 사고 방지** → 장기적으로 성과보다 중요  

이 4개 실험만 통과시키면, 지금의 “후보가 강한데 불안한 상태”에서 “락박스 기준으로 재현 가능한 시스템”으로 빠르게 이동합니다.
