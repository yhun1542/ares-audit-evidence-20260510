아래는 **향후 24~48시간** 안에 “성능이 안 움직이는 상태”를 가장 먼저 깨는 데 필요한 **우선순위 TOP5(코드/아키텍처/전략)**와, 이를 **총 5개 실험(48시간 자동 루프에 바로 얹을 수 있는 형태)**로 묶은 실행 체크리스트다.  
(중요: 현재 로그에서 `file/lane_hash/run_hash` 비어있고, `degenerate_folds` 다수이며, rebalance 로그 로더가 깨져 **관측 불능(관측 실패=개선 불가)** 상태가 우선 병목이다.)

## 0) 48시간 자동 루프용 “실험 패키지(총 5개)” — 정의/게이트/기대관측치

### EXP-1) **누수/타임얼라인/서바이버십 가드레일 실험**
- (1) **실험 정의**
  - 모든 feature/label에 대해 **t시점 의사결정은 t-1(또는 t close 이후 확정 데이터)까지만 사용**하도록 강제(일괄 `shift(1)` + 린트).
  - corporate actions(분할/배당) **Adj Close 일관성** 검사 + delisted/merged 심볼 포함 여부 점검(서바이버십 방지).
  - “미래정보 가능성 높은 필드(예: 당일 종가 기반 지표, 당일 실적 반영, 수정주가 반영 타이밍)”를 자동 스캔하여 차단 리스트 생성.
- (2) **게이트(FAIL FAST)**
  - feature timestamp > decision timestamp 발견 시 즉시 FAIL.
  - 동일 파이프라인에서 **raw close vs adj close 혼용** 발견 시 FAIL.
  - 훈련 구간에서만 존재하는 심볼이 OOS에 과도하게 유리하게 작동(심볼 유니버스 드리프트)하면 FAIL.
- (3) **기대 관측치**
  - 단기적으로 OOS 평균이 내려갈 수 있으나, **fold별 편차/급등락 감소**, degenerate fold 감소.
  - 이후 비용/운영 반영 실험에서 “성능이 사라지는” 현상이 줄어듦(진짜 알파만 남음).

---

### EXP-2) **비용(수수료/슬리피지/스프레드) + 턴오버 제한 실험**
- (1) **실험 정의**
  - 거래비용을 최소한으로라도 고정 반영:  
    - (a) 수수료(0으로 두지 말 것)  
    - (b) 슬리피지(체결가=mid±k*spread 혹은 bps)  
    - (c) 스프레드(유동성 낮은 종목 패널티)  
  - 포트폴리오 **턴오버 캡**(예: 일/리밸런스당 총 거래대금 비율 상한) 추가.
- (2) **게이트**
  - 비용 반영 후 OOS_mean이 비용 미반영 대비 **과도 붕괴**하면(예: -30% 이상) FAIL → 알파가 거래에 민감한 구조.
  - 평균 턴오버가 상한을 지속 초과하면 FAIL → 신호/리밸런스가 과민.
- (3) **기대 관측치**
  - “성능이 안 움직이는 원인”이 비용인지 즉시 분해 가능.
  - 비용에 강한 신호만 남기면 이후 안정성↑.

---

### EXP-3) **CV(워크포워드) 퇴화(degenerate fold) 제거 실험**
- (1) **실험 정의**
  - time-series blocked CV에 **purge/embargo** 적용(인접 구간 정보누설 차단).
  - fold별 최소 거래수/리밸런스 횟수/노출시간 조건을 만족 못하면 fold를 무효 처리하지 말고 **실험 자체 FAIL**로 승격(지금은 degenerate fold가 “통과”하고 있는 정황).
  - OOS 산출 시 “거래 0/노출 0에 가까운 fold”를 평균에 섞지 않도록 정책화(평균 착시 방지).
- (2) **게이트**
  - `degenerate_folds`가 0이 아니면(또는 임계치 초과 시) FAIL.
  - fold별 exposure/turnover/trade_count 로그가 누락되면 FAIL.
- (3) **기대 관측치**
  - 성능 수치가 흔들릴 수 있으나, 이후 개선이 “진짜 개선”인지 판별 가능.
  - “개선이 안 보이는” 이유가 평가계측 문제였는지 즉시 확인.

---

### EXP-4) **리밸런스/주문/노출/리스크 메트릭 로깅 복구 실험 (관측가능성)**
- (1) **실험 정의**
  - 현재 rebalance pinpoint가 깨지는 원인(파일 포맷/경로/JSONL 스키마 불일치)을 해결:
    - 모든 런에서 `rebalance.jsonl`(또는 csv) **스키마 고정**: timestamp, symbol, target_w, delta_w, price_ref, est_cost, reason, fill_assumption
  - `worst_mdd: None` → MDD 계산 파이프라인 연결(리스크 메트릭 결측 제거).
  - `file/lane_hash/run_hash`를 반드시 아티팩트/리포트에 기록(재현성/추적성).
- (2) **게이트**
  - rebalance pinpoint 툴이 base/cand 모두에서 **에러 없이 로드**해야 PASS.
  - MDD/turnover/exposure min/max가 None이면 FAIL.
- (3) **기대 관측치**
  - “성능이 안 움직이는” 것이 신호 문제인지, 주문/리밸런스가 실제로는 거의 안 나가서인지 즉시 분해됨.
  - 이후 전략 패치가 원인-결과로 연결됨.

---

### EXP-5) **유니버스/집중도 제약(미국 Tech+Healthcare 8~14종목) 실험**
- (1) **실험 정의**
  - 거래 유니버스를 **US-listed + Tech/Healthcare**로 고정하고, 동시 보유 종목수를 **8~14**로 강제.
  - 포지션 구성 2-팔(같은 실험 프레임 안에서 두 세팅만 비교):
    - (A) 상위 N 동일가중(8~14)  
    - (B) 상위 N 신호가중(단, 단일종목 최대비중 캡)
  - ETF는 **거래 금지**, 관측 지표(레짐/리스크 프록시)로만 사용.
- (2) **게이트**
  - 보유 종목 수가 8~14 밖으로 벗어나면 FAIL.
  - 미국 외 종목/ETF 주문 발생 시 FAIL.
  - `exposure_max`가 사전 정의 상한(예: 0.9) 초과 시 FAIL(현재 max 0.838은 양호하나, min 0.0이면 “현금 대기 과다” 가능성도 함께 모니터).
- (3) **기대 관측치**
  - “알파가 유니버스에 퍼져있었는지(분산 알파)” vs “집중에서만 나오는지”가 명확해짐.
  - 운영 측면(거래가능/리밸런스 단순화) 리스크 감소.

# 1) 다음 24~48시간 우선순위 TOP5 제안 (코드/아키텍처/전략)

## P1. **누수/서바이버십/정합성(Adj/Raw, timestamp) 최우선 차단**
- (a) 왜 필요한지
  - 누수는 OOS가 “안 움직이거나/갑자기 무너지는” 가장 흔한 원인이고, 한번 섞이면 어떤 최적화도 무의미.
- (b) 위험/부작용
  - 단기 성능 하락(가짜 알파 제거), 데이터 준비 시간 증가.
- (c) 최소 실험 2~3개
  - **EXP-1**, **EXP-3**(누수는 CV 퇴화와 같이 터짐), (선택) **EXP-4**(추적성 없으면 누수 추적 불가)
- (d) PASS 조건
  - 누수 린트 0건 + raw/adj 혼용 0건 + degenerate fold=0(또는 정책 임계 이하) + 재현가능(run_hash 고정)

---

## P2. **비용 미반영(슬리피지/스프레드/턴오버) 제거: “실거래 가능한 알파”만 남기기**
- (a) 왜 필요한지
  - 비용이 0이면 최적화가 거래 과민 신호로 기울어 **OOS가 정체**하거나 실거래에서 즉시 붕괴.
- (b) 위험/부작용
  - 기대수익 감소, 거래 빈도/리밸런스 로직 재설계 필요.
- (c) 최소 실험 2~3개
  - **EXP-2**, **EXP-4**(주문/체결 가정 로그 없으면 비용 검증 불가)
- (d) PASS 조건
  - 비용 반영 후에도 OOS_mean이 “의미 있게” 유지(내부 기준치 대비) + 턴오버 상한 준수 + 거래비용/수익 기여가 리포트로 분해됨

---

## P3. **평가계측(CV/폴드 퇴화/평균 착시) 정상화**
- (a) 왜 필요한지
  - 현재 `degenerate_folds: [1,2,3,8]`는 “측정이 고장난 상태에서 학습/선정” 가능성이 큼. 성능이 안 움직이는 게 아니라 **측정이 움직이지 않는** 상황이 자주 발생.
- (b) 위험/부작용
  - 실험 FAIL이 늘어나며, 통과 실험 수가 줄어듦(정상).
- (c) 최소 실험 2~3개
  - **EXP-3**, **EXP-1**(purge/embargo와 누수는 세트), (선택) **EXP-4**
- (d) PASS 조건
  - 모든 fold에서 최소 거래/노출 조건 만족 + fold별 분산/최저 성과(oos_min) 모니터가 정상 출력 + “degenerate를 평균에 섞지 않음” 정책 고정

---

## P4. **운영 리스크/관측가능성(artifact, rebalance 로그, MDD) 복구**
- (a) 왜 필요한지
  - rebalance pinpoint가 파일을 못 읽고, champion 메타(file/hash)가 비어있고, worst_mdd가 None이면 **원인분해 자체가 불가능**. 개선이 아니라 “추측”만 하게 됨.
- (b) 위험/부작용
  - 로그 저장으로 I/O 증가, 저장공간 증가.
- (c) 최소 실험 2~3개
  - **EXP-4**, **EXP-3**(평가 파이프라인 정상화와 동행)
- (d) PASS 조건
  - base/cand 모두 rebalance pinpoint 1회 이상 성공 + MDD/turnover/exposure가 항상 채워짐 + run_hash로 재현 가능

---

## P5. **유니버스/집중도(US Tech+Healthcare 8~14) 제약으로 전략을 “운영 가능한 형태”로 고정**
- (a) 왜 필요한지
  - 유니버스가 흔들리면 성능도 흔들리고, 최적화가 “우연히 잘 된 종목 묶음”에 과적합하기 쉬움(서바이버십/리밸런스 문제와 결합).
- (b) 위험/부작용
  - 알파 소스가 더 넓은 유니버스에 있었다면 성능 하락.
  - 섹터 분류/심볼 매핑 오류 시 거래 제한이 과도해질 수 있음.
- (c) 최소 실험 2~3개
  - **EXP-5**, **EXP-2**(집중 포트폴리오는 비용 민감), (선택) **EXP-4**
- (d) PASS 조건
  - 보유종목수 8~14 유지 + ETF 주문 0 + 미국 외 주문 0 + 노출/종목상한 준수 + 비용 반영 후에도 전략이 유지됨

# 2) “성능이 안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **명령형 트리**로 고정해서, 매 런마다 자동 리포트로 토해내게 하라.

## A. Trigger(신호 발생) 레벨
- [ ] **상위 N 신호 종목 리스트가 기간 내 얼마나 바뀌는지**(rank stability) 출력
- [ ] 신호 분포(평균/표준편차/상위꼬리)가 OOS에서 **붕괴**하는지 확인
- [ ] 신호가 “늘 0 근처”면: feature 스케일/클리핑/결측 대체로 신호가 죽었는지 점검(과도한 정규화/윈저라이즈)

## B. Apply(적용/리밸런스) 레벨
- [ ] 리밸런스가 실제로 발생했는지: 리밸런스 횟수, 거래 수, 총 거래대금 출력
- [ ] “타겟 변경은 있는데 거래는 거의 없음”이면: 최소 주문단위/가격가정/턴오버캡이 과도한지 확인
- [ ] rebalance reason(예: 신호변화 vs 리스크캡 vs 종목수 제약)별로 거래를 분해

## C. Exposure(노출) 레벨
- [ ] exposure min/max, 평균 노출, 현금비중 시간비율 출력  
  - 현재 `exposure_min=0.0`이면 “현금 대기 과다”가 성능 정체를 만들 수 있음
- [ ] 섹터/단일종목 상한으로 인해 **항상 클리핑**되는지(clip rate) 출력
- [ ] 8~14 종목 제약 하에서 “항상 N 미달”이면 유니버스/필터가 너무 빡센 것

## D. Cost(비용) 레벨
- [ ] 총 비용(bps), 비용/수익 비율(cost drag), 비용이 큰 종목 TOP 출력
- [ ] 턴오버와 성과의 상관(턴오버가 높을수록 성과↓면 비용/슬리피지 문제)
- [ ] 스프레드 프록시(ADV, spread estimate)로 비용 민감 구간을 분리

## E. Regime(레짐) 레벨 — ETF는 “관측 지표”로만
- [ ] (관측) QQQ/XLV 등으로 **risk-on/off, tech vs health 상대강도** 레짐 라벨링(거래 금지)
- [ ] 레짐별 성과/승률/드로우다운을 분해(“전체 평균은 정체지만 레짐별로는 움직임” 확인)
- [ ] 레짐 전환 구간에서만 망가지면: 리밸런스 주기/노출 캡/손절 정책(있다면) 재점검

---

## 3) 지금 당장(오늘) 적용 순서 — 명령형 체크리스트
- [ ] **EXP-4 먼저**: run_hash/lane_hash/file 채우기 + rebalance 로그 스키마 고정 + MDD 계산 연결(관측 불능 상태 해제)
- [ ] **EXP-3 실행**: degenerate fold를 “통과”시키지 말고 실험 FAIL로 처리(평가계측 정상화)
- [ ] **EXP-1 실행**: shift/embargo/adj-raw 혼용 검사로 누수/서바이버십 차단
- [ ] **EXP-2 실행**: 비용+턴오버 캡 도입(실거래 가능성 평가)
- [ ] **EXP-5 실행**: US Tech+Healthcare, 8~14종목 강제(A 동일가중 vs B 신호가중)로 운영형 전략 형태 고정

이 5개를 48시간 루프로 돌리면, “성능이 안 움직이는 이유”가 최소한 **(1) 측정 고장, (2) 거래/리밸런스 미발생, (3) 비용 민감, (4) 누수/정합성, (5) 레짐 의존** 중 어디인지 자동으로 갈라진다.
