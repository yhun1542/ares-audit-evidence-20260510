### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### 1️⃣ Champion v5 음수 Fold 원인 격리
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 필요성**
- tuning_min = -0.026 → 특정 시장 구간에서 손실
- 이 fold가 어떤 레짐(금리 급등/테크 조정/유동성 위기)인지 모르면 실전 배치 위험

**(b) 위험/부작용**
- 해당 fold 제거 시 서바이버십 바이어스 발생
- 과도한 레짐 필터 추가 시 거래 기회 감소

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| 1-A | `--analyze-fold negative` → 음수 fold의 날짜/섹터/MDD 분해 | 리포트 생성 | 레짐 라벨 (rate_shock / tech_crash / liquidity) |
| 1-B | 해당 구간에서 발동된 alpha 모듈 on/off 비교 | A/B diff > 0.5% | 범인 모듈 식별 |
| 1-C | 음수 fold 구간 거래 빈도/비용 비율 추출 | cost_ratio < 30% | 비용 문제 배제 |

**(d) PASS 조건**
```
음수 fold 원인 ∈ {특정 모듈, 레짐, 비용} 중 하나로 귀속
→ 해당 요인 제거 후 tuning_min ≥ 0
```

### 2️⃣ Lockbox 4.01 vs Tuning 2.32 괴리 점검 (누수 의심)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**(a) 필요성**
- lockbox가 tuning의 1.7배 → look-ahead 누수 또는 lockbox 구간이 유리한 레짐일 가능성
- 실전에서 tuning 수준(2.32)도 기대하기 어려울 수 있음

**(b) 위험/부작용**
- 누수 발견 시 Champion 전체 폐기 필요
- false alarm 시 시간 낭비

**(c) 최소 실험**

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| 2-A | lockbox 구간의 VIX/SPY/금리 레짐 라벨 분포 vs tuning 비교 | chi-square p > 0.1 | 레짐 동질성 확인 |
| 2-B | feature 생성 시점 timestamp audit (T+1 이후 데이터 사용 여부) | 0 violations | 누수 없음 |
| 2-C | lockbox 구간만 50% 랜덤 샘플링 후 재테스트 | mean 변동 < 20% | 과적합 아님 |

**(d) PASS 조건**
```
2-A: 레짐 분포 동질 (p > 0.1)
2-B: timestamp 위반 = 0
→ 누수 없음 확정, lockbox 우위는 "운" 또는 유리 레짐
```

│   ├─ 보유 기간 vs 신호 decay 불일치 → holding period 그리드
│   └─ 진입 타이밍 지연 → T+0 vs T+1 비교
│
├─④ 비용 문제 (gross는 양수, net은 0)
│   ├─ turnover 대비 gross alpha 비율 → < 2x면 비용 지배
│   └─ 종목별 비용 분해 → 고비용 종목 제외 실험
│
└─⑤ 레짐 문제 (특정 구간만 작동)
    ├─ VIX/금리/섹터 모멘텀별 성과 분해
    └─ 현재 레짐에서 fire rate 0이면 대기 또는 레짐 적응 모듈 추가
```
