[분석 요약]
현재 `degenerate_folds: [1, 2, 3, 8]` 발생은 치명적 위험 신호입니다. 전체 데이터셋의 절반 가까운 구간에서 전략이 파탄(NaN, 무거래, 혹은 청산)나고 있습니다. 또한 `rebalance.csv` 파싱 에러로 인해 거래 비용 검증이 불가능한 상태입니다. 높은 OOS Mean은 생존 편향(Survivorship Bias)이나 운이 좋은 특정 구간(Fold)에 의해 왜곡되었을 가능성이 매우 높습니다.

### 1. 우선순위 TOP 4 제안 (48시간 루프)

#### P1. [Stability] 공분산 행렬 축소(Shrinkage) 및 정규화 적용
*   **이유:** `Degenerate Folds`의 주원인은 Tech/Healthcare 섹터 내 종목 간 높은 상관계수로 인한 최적화 해(Solution) 불안정(Singular Matrix)일 가능성이 큼.
*   **위험:** 신호 강도가 약해져 수익률(Mean)이 소폭 하락할 수 있음.
*   **실험 (Experiments):**
    1.  `EXP_COV_LEDOLF`: Ledoit-Wolf 축소 추정기 적용.
    2.  `EXP_L2_REG_01`: 최적화 목적함수에 L2 Regularization (weight^2 * 0.01) 추가.
    3.  `EXP_MIN_WEIGHT_LIMIT`: 최소 보유 비중 제약(예: >2%) 강제 (자잘한 노이즈 제거).
*   **PASS 조건:** `degenerate_folds` 개수가 0~1개로 감소 && `oos_min` > -0.05 유지.

#### P2. [Infra/Cost] 로깅 시스템 복구 및 슬리피지 스트레스 테스트
*   **이유:** `aub_rebalance_pinpoint.py` 실패는 현재 매매 회전율(Turnover)과 비용을 추적하지 못함을 의미. 비용 미반영 시 과최적화 확정.
*   **위험:** 실제 비용 반영 시 현재의 Champion 성과가 붕괴될 수 있음(Reality Shock).
*   **실험 (Experiments):**
    1.  `EXP_LOG_FIX_JSONL`: `rebalance` 로그 포맷을 CSV에서 JSONL로 통일 및 Flush 강제.
    2.  `EXP_COST_STRESS_10BPS`: 편도 비용 10bps(0.1%) 강제 적용 후 백테스트.
    3.  `EXP_COST_STRESS_20BPS`: 편도 비용 20bps 강제 적용.
*   **PASS 조건:** 로그 파일 정상 생성 && 비용 10bps 적용 시 `oos_mean` > 1.5 유지.

#### P3. [Allocation] Tech/Healthcare 섹터 편중 완화 (Max Sector Constraint)
*   **이유:** Tech 바이오 섹터는 변동성이 큼. 특정 섹터 몰빵 시 MDD 제어 불가. 8~14개 종목이 한쪽으로 쏠리는 것 방지.
*   **위험:** 강력한 모멘텀 구간에서 수익률 제한(Capping).
*   **실험 (Experiments):**
    1.  `EXP_SEC_CAP_50`: 단일 섹터(GICS 1 or 2 level) 비중 최대 50% 제한.
    2.  `EXP_TICKER_CAP_15`: 개별 종목 최대 비중 15% 제한.
*   **PASS 조건:** `worst_mdd` 개선(절대값 감소) && Exposure Max 0.9 이상 도달.

#### P4. [Logic] 하락장 노출 차단 (Regime-based Cash)
*   **이유:** `exposure_min: 0.0`은 긍정적이나, 어떤 로직으로 0이 되는지 명확하지 않음. 명시적 레짐 필터로 4, 8번 Fold(하락장 추정) 방어.
*   **위험:** 상승장 초입 진입 지연(Lagging).
*   **실험 (Experiments):**
    1.  `EXP_MA200_FILTER`: SPY(관측용) < MA200 일 때 전체 포트폴리오 Cash 100%.
    2.  `EXP_VIX_FILTER`: VIX > 30 일 때 Trading Halt.
*   **PASS 조건:** `oos_min` 방어력 상승 && `degenerate_folds` 내 수익률 개선.

### 2. 48시간 자동 루프 정의 (Checklist)

**Loop 1: 안정성 확보 (P1, P2)**
1.  **실험 정의:** `baseline/champion_v5` 복사 -> `optimize.py` 내 Covariance Matrix 계산 로직에 Ledoit-Wolf 적용.
2.  **게이트:** `python check_folds.py` -> `degenerate_folds` == [] (Empty).
3.  **기대 관측치:** OOS Mean은 3.3 -> 2.5 수준으로 하락하더라도, 모든 Fold에서 실행 완료될 것.

**Loop 2: 비용 검증 (P2)**
1.  **실험 정의:** Loop 1 통과 모델에 `sim_cost_model = 0.0015` (15bps) 설정.
2.  **게이트:** `rebalance.jsonl` 파일 용량 > 0KB 확인.
3.  **기대 관측치:** 회전율(Turnover)이 일 50% 미만인지 확인. 과도한 회전율 발생 시 `penalty` 로직 추가 필요.

### 3. 성능 정체 시 원인 분해 (Debugging Guide)

성능지표가 움직이지 않거나(Flat), `degenerate`가 해결되지 않을 때 다음을 점검:

1.  **트리거(Trigger) 불발:**
    *   선택된 8~14개 유니버스(Tech/Health)가 모두 필터(예: 시총 상위, 유동성)에서 탈락하여 `Available Universe`가 0이 되는 날짜가 있는지 확인.
2.  **비용(Cost) 잠식:**
    *   예측 알파(Alpha)보다 슬리피지가 큼. -> *Action: 목표 보유 기간(Holding Period)을 강제로 3일 이상으로 늘리는 제약 추가.*
3.  **최적화 실패(Solver Fail):**
    *   Scipy/CVXPY Solver가 수렴하지 못해 이전 포트폴리오를 그대로 유지(Frozen)하는 경우. -> *Action: Solver의 `max_iter` 증가 또는 `tol`(허용오차) 완화.*
4.  **데이터 누수(Leakage):**
    *   OOS 성능이 비정상적으로 높고(Sharpe > 4), Drawdown이 거의 없는 경우. -> *Action: Feature 생성 시 `shift(1)`이 정확히 적용되었는지 전수 조사.*
