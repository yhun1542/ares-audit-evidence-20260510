## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — **명령형 체크리스트**

### 1) **누수(lookahead) / 시간정렬(Point-in-Time) “강제 지연” 감사 패치**
- (a) 왜 필요한지  
  - 현재 Champion이 **lockbox 성능이 높고 MDD가 낮은 편**이라, 미세한 시간정렬 누수/리포트 시점 누수/리밸런싱 시점 누수만 있어도 성능이 과대평가될 수 있음.  
  - 특히 Tech/Healthcare는 이벤트(실적/가이던스) 영향이 커서 **발표 시각/데이터 반영 시점**이 1-bar만 틀려도 결과가 급변.
- (b) 위험/부작용  
  - 진짜 알파가 아니라면 성능이 크게 꺾여 “불편한 진실”이 드러남(단, 이게 목적).  
  - 지연/엠바고 적용으로 회전율·진입 타이밍이 바뀌며 단기 성과가 감소할 수 있음.
- (c) 최소 실험(2~3개)  *(아래 공용 실험 E1로 통일)*  
  - **E1-1**: 모든 시그널/피처에 **trade_delay=+1 bar** 강제  
  - **E1-2**: **purged/embargo** 적용(리밸런스 전후 N일 정보 누출 차단)  
  - **E1-3**: “close로 계산 → same-day close 체결” 금지(체결은 다음 bar로 고정)
- (d) PASS 조건  
  - lockbox_mean이 **Champion 대비 -20% 이내**로 유지되고, 최악 MDD(worst_mdd)가 **악화되지 않을 것**(≥ Champion worst_mdd - 0.01p 수준)  
  - +1 bar 지연에서도 성과가 유지되면 “구조적 알파” 가능성 ↑

---

### 2) **비용/슬리피지/체결 현실화(비용 미반영 리스크) 패치**
- (a) 왜 필요한지  
  - 8~14개 집중 포트는 **리밸런스/턴오버/스프레드**에 매우 민감.  
  - 비용을 과소계상하면 tuning/lockbox에서 모두 “그럴듯하게” 보일 수 있음.
- (b) 위험/부작용  
  - 비용을 현실화하면 성능이 급락할 수 있음(특히 잦은 매매).  
  - 지나치게 보수적인 비용모델은 유효 전략까지 죽일 수 있음 → **민감도 스윕으로만 판단**.
- (c) 최소 실험(2~3개) *(공용 실험 E2로 통일)*  
  - **E2-1**: 슬리피지 배수 0.5x/1x/2x 민감도 스윕  
  - **E2-2**: 거래비용을 “고정 bp + 변동(ADV/변동성 기반)” 2모델로 교차검증  
  - **E2-3**: 턴오버 상한(일/주 단위) 걸고 성능/안정성 비교
- (d) PASS 조건  
  - 2x 비용에서도 lockbox_mean이 **0 이상 유지** + worst_mdd가 **-0.10 이하로 악화되지 않을 것**  
  - 비용모델 변경에 따른 성능 순위가 크게 뒤집히지 않을 것(“모델 의존성” 낮음)

---

### 3) **서바이버십/상장폐지/기업행동(분할·합병) 반영 패치**
- (a) 왜 필요한지  
  - “현재 잘나가는 Tech/Healthcare만 남는” 편향이 끼면 lockbox가 좋아 보일 수 있음(서바이버십 편향).  
  - 상장폐지/인수/티커 변경이 들어가면 수익률·MDD가 크게 달라짐.
- (b) 위험/부작용  
  - 데이터 소스/정합성이 맞지 않으면 오히려 노이즈가 늘어남.  
  - 과거 구성 유니버스를 강제하면 “지금의 8~14개” 제약과 충돌할 수 있어, **백테스트용 as-of 유니버스**를 분리해야 함.
- (c) 최소 실험(2~3개) *(공용 실험 E3로 통일)*  
  - **E3-1**: delisting returns 포함 버전으로 동일 전략 재실행  
  - **E3-2**: corporate actions(분할/배당) 반영 여부 플래그 비교(총수익 vs 가격수익)  
  - **E3-3**: “현재 선정된 8~14”를 백테스트 전체에 고정 vs “as-of 선정(당시 기준)” 비교(성능 괴리 측정)
- (d) PASS 조건  
  - delisting/corp action 반영 후 성능이 **Champion 대비 -25% 이내**로 유지  
  - “고정 유니버스 vs as-of 유니버스” 괴리가 과도하지 않을 것(괴리 크면 서바이버십 경고)

---

### 4) **과최적화 방지(검증 아키텍처) 패치: Purged WF + Champion 안정성 가드**
- (a) 왜 필요한지  
  - tuning_mean이 높아도 min/분산/최악 구간이 약하면 실전에 약함.  
  - 현재 Candidate가 fold14/worst MDD가 크게 악화된 케이스가 이미 존재 → “한 구간에만 맞춘” 가능성 점검 필요.
- (b) 위험/부작용  
  - 검증을 엄격히 하면 당장 PASS하는 후보가 줄어듦(하지만 실전성은 증가).  
  - 계산 비용 증가.
- (c) 최소 실험(2~3개) *(E1을 재사용 + E4 일부 연동)*  
  - **E1(재사용)**: purged/embargo + 지연 강제  
  - **E4-1**: 후보 선택 기준에 “worst_mdd / fold별 일관성” 가중치 추가(평균만 보지 말 것)  
  - **E4-2**: 파라미터 탐색 폭 축소 + 조기중단(early stop)로 과탐색 방지
- (d) PASS 조건  
  - 새 선택 기준 적용 후에도 Champion 또는 근접 성능(평균↓를 감수하되 worst_mdd 개선)  
  - “tuning↑ lockbox↓” 형태의 괴리가 감소할 것(일반화 개선)

---

### 5) **운영 리스크(48시간 자동루프) + 레짐 게이트(ETF는 관측지표만) 패치**
- (a) 왜 필요한지  
  - 자동루프는 “데이터 지연/결측/이상치/급변동”에서 깨지기 쉬움.  
  - Tech/Healthcare는 레짐(금리/리스크온오프)에 민감 → **QQQ/XLK/XLV/IBB(관측만)**로 “리스크 스케일링”을 걸면 worst_mdd를 줄일 여지.
- (b) 위험/부작용  
  - 레짐 게이트는 잘못 설계하면 알파를 희석(항상 꺼짐/항상 켜짐)시킴.  
  - 운영 가드레일이 지나치면 거래 기회 손실.
- (c) 최소 실험(2~3개) *(공용 실험 E5로 통일)*  
  - **E5-1**: 관측 ETF(예: QQQ/XLK/XLV/IBB)의 20/60일 추세 & 변동성 상태로 **포지션 스케일(0.5x~1.0x)**  
  - **E5-2**: 급변동(예: 관측 변동성 상위 분위)에서 **신규 진입 금지/리밸런스 완화**  
  - **E5-3**: 운영 가드(데이터 결측 시 “현상유지”, 이상치 탐지 시 “거래중지”)를 백테스트에도 동일 적용
- (d) PASS 조건  
  - worst_mdd가 **Champion 대비 개선(더 작아짐)** 또는 최소 악화 없이 변동성/턴오버 감소  
  - 게이트 발동 빈도가 극단적이지 않을 것(항상 0.5x/항상 1.0x면 설계 실패)

## 48시간 자동 루프용 “공용 실험 5개” (3~5개 제한 준수)
각 실험은 **(1) 실험 정의 → (2) 게이트 → (3) 기대 관측치**로 고정 형식.

### E1) 누수/시간정렬 강제 감사 (Delay + Purge/Embargo)
1) 실험 정의  
- 모든 피처/시그널/리밸런스 체결을 **다음 bar**로 강제(+1).  
- purged walk-forward 또는 embargo 적용(리밸런스 주변 정보 차단).
2) 게이트  
- lockbox_mean < (Champion lockbox_mean * 0.8) 이면 FAIL  
- worst_mdd < -0.10 이면 FAIL
3) 기대 관측치  
- 진짜 알파면 성능이 “줄어도 살아남음”, 과대평가면 급락 + fold 편차 확대

---

### E2) 비용/슬리피지 민감도 스윕
1) 실험 정의  
- 슬리피지 0.5x/1x/2x + (고정bp vs ADV/변동성 기반) 2모델 교차.  
- 결과를 성능-턴오버 곡선으로 저장.
2) 게이트  
- 2x 비용에서 lockbox_mean ≤ 0 이면 FAIL  
- 턴오버 상한 적용 시 성능이 비정상적으로만 유지되면(“턴오버 덕”) FAIL
3) 기대 관측치  
- 비용에 둔감한 구조면 곡선이 완만, 비용 의존이면 급격히 꺾임

---

### E3) 서바이버십/상폐/기업행동 반영 회귀
1) 실험 정의  
- delisting returns 포함/미포함, total return vs price return 비교.  
- 고정 유니버스 vs as-of 유니버스(백테스트용) 괴리 측정.
2) 게이트  
- 반영 후 lockbox_mean이 Champion 대비 -25% 초과 하락이면 FAIL  
- 고정 vs as-of 괴리로 성능이 “반 토막”이면 FAIL(편향 경고)
3) 기대 관측치  
- 건전하면 성능 소폭 감소 + 리스크 지표는 더 현실적으로 변함

---

### E4) 리스크/회전율 제약 패치 (집중 포트 안정화)
1) 실험 정의  
- 단일 종목 최대 비중, 일/주 턴오버 캡, 변동성 타게팅(또는 포지션 스무딩) 1~2개만 적용.  
- “제약 없음 vs 제약 있음” A/B.
2) 게이트  
- lockbox_mean이 Champion 대비 -20% 초과 하락이면 FAIL  
- worst_mdd 개선이 전혀 없고(turnover만 감소)면 보류
3) 기대 관측치  
- 성공 시: 평균은 약간 희생하되 worst_mdd와 fold 분산이 개선

---

### E5) 레짐 게이트(ETF 관측지표 기반, 매매는 개별주만)
1) 실험 정의  
- QQQ/XLK/XLV/IBB의 추세/변동성 상태로 익스포저 스케일(0.5~1.0) 또는 신규진입 제한.  
- 항상 온/오프가 아닌 “조건부”로만 동작.
2) 게이트  
- 발동 비율이 5% 미만 또는 95% 초과면 FAIL(게이트 설계 붕괴)  
- worst_mdd 개선 없고 평균만 하락하면 FAIL
3) 기대 관측치  
- 리스크오프 구간 손실 감소, 회복 구간에서 참여율이 과도하게 낮지 않음

---

## 성능이 안 움직일 때 “원인 분해” 실행 체크리스트 (트리거/적용/노출/비용/레짐)
질문 없이 바로 로그/리포트에 추가해서 48시간 루프마다 자동 산출하도록 고정.

### A) Trigger(신호가 실제로 발생했나?)
- “일별/리밸런스별 **signal non-zero 비율**”, 상위 k랭크 변동, 점수 분포(평균/표준편차/왜도) 저장
- 신호가 평평하면: 피처 스케일/클리핑/결측처리/정규화 순서 오류를 의심

### B) Apply(신호가 포지션으로 제대로 반영됐나?)
- 목표비중→주문→체결→보유의 파이프라인을 단계별로 기록(드리프트/라운딩/캡으로 인한 손실)
- 리밸런스 타이밍(예: close 기반 산출인데 same close 체결) 누수 가능성 자동 경고

### C) Exposure(원치 않는 베타/섹터/팩터에 먹혔나?)
- 포트의 **market beta**, Tech vs Healthcare 비중, 상위 종목 집중도(HHI), 순/총 익스포저 추적
- 수익 기여(종목별/섹터별) + 손실 기여를 “상위 5”로 고정 출력

### D) Cost(거래비용이 다 먹었나?)
- turnover, 평균 스프레드 가정, 슬리피지 추정치로 “**비용/총수익 비율**”을 매 루프 출력
- 비용이 수익의 X%를 넘으면(내부 기준치) 즉시 “저회전 버전(E4)”만 후보로 남기기

### E) Regime(어떤 국면에서만 먹히나?)
- 관측 ETF(QQQ/XLK/XLV/IBB) 기반으로 국면을 4분면(상승/하락 × 저/고변동)으로 라벨링
- 국면별 성과 테이블(평균/최악/MDD/승률)을 자동 출력 → 특정 국면에서만 성과가 나오면 E5로 대응

---

### 바로 실행 순서(명령형)
1) **E1 → E2를 최우선**으로 돌려 “누수/비용”부터 걷어낼 것(여기서 무너지면 다른 개선은 의미 없음).  
2) E1/E2 통과 시에만 **E3(서바이버십/상폐) → E4(리스크제약) → E5(레짐게이트)** 순으로 진행할 것.  
3) 매 루프마다 원인분해 리포트(A~E)를 자동 저장하고, 성능 정체 시 “어느 블록이 평평해졌는지”만 보고 다음 패치를 선택할 것(케이스 확장 금지).
