## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — **명령형 체크리스트**
우선 점검 순서: **누수 → 과최적화 → 서바이버십 → 비용 미반영 → 운영 리스크**

---

### 1) **누수(lookahead)·시간정렬·라벨 정의 “하드 감사”를 CI 게이트로 고정**
**(a) 왜 필요한지**
- Champion(lockbox_mean 4.01)이 “너무 좋을” 때 가장 먼저 의심할 것은 **시간축 누수/정렬 오류/리밸런싱 시점 괴리**.
- candidate가 MDD 급증(fold14_mdd -0.099, worst_mdd -0.112)한 것은 **신호 자체보다 파이프라인 취약성**(정렬/결측 처리)이 원인일 수 있음.

**(b) 위험/부작용**
- 누수 제거 시 과거 성능이 크게 하락(“진짜 성능”으로 수렴).
- 일부 피처가 전면 폐기되어 탐색 공간이 줄어듦.

**(c) 최소 실험(아래 공용 실험 E1, E3 중 택)**
- E1(누수/정렬 유닛테스트+shadow)  
- E3(서바이버십/코퍼레이트액션 point-in-time 교차검증)

**(d) PASS 조건**
- **Leak-test 0건**(시간 역행/미래 데이터 참조/라벨-피처 동일시점 혼입).
- 동일 코드로 **seed 고정 재현성 100%**(tuning/lockbox 핵심 지표 편차 허용폭 내).
- 누수 제거 후에도 **lockbox_mean ≥ 3.5** AND **worst_mdd ≥ -0.085** 유지(“현실 성능” 방어선).

---

### 2) **비용(슬리피지/스프레드/체결지연) 모델을 “보수적으로” 강제 반영 + turnover 게이트**
**(a) 왜 필요한지**
- Tech+Healthcare 8~14종목 집중은 **회전율/체결비용**이 성과를 좌우.  
- 비용 미반영은 가장 흔한 “가짜 알파” 원인.

**(b) 위험/부작용**
- 성능 급락 가능(특히 단기 리밸런싱/빈번 매매).
- 과도한 비용 페널티는 신호를 죽여 “성능이 안 움직이는” 상태를 만들 수 있음.

**(c) 최소 실험(공용 실험 E2)**
- E2(비용모델 캘리브레이션 + turnover 페널티 스윕)

**(d) PASS 조건**
- 비용 포함 후 **lockbox_mean ≥ 3.5** AND **worst_mdd ≥ -0.085**.
- **평균 일간 turnover 상한**(예: 25~35% 구간 내) 만족 + 성능/변동성 지표가 비용 민감도 스윕에서 급붕괴하지 않을 것(단조적/완만한 감소 형태).

---

### 3) **서바이버십·델리스팅·코퍼레이트액션(point-in-time) “완전성” 고정**
**(a) 왜 필요한지**
- US 개별주에서 서바이버십/델리스팅 누락은 곧바로 **과대평가**로 연결.
- 8~14종목 집중이면 단일 이벤트(합병/상장폐지/거래정지)가 성과를 지배.

**(b) 위험/부작용**
- 데이터 소스/정합성 이슈로 백테스트가 불안정해질 수 있음(결측 증가).
- universe 축소로 신호 다양성 감소.

**(c) 최소 실험(공용 실험 E3)**
- E3(point-in-time universe + delist return + split/dividend 정합성)

**(d) PASS 조건**
- delist/corp-action 반영 후 **fold14_mdd 개선 또는 동일 수준 유지**(악화 금지: fold14_mdd ≤ -0.045로 더 악화되면 FAIL).
- 동일 기간에서 “거래가능 종목 수(8~14)” 충족률 **≥ 98%**(미충족 시 현금/대체 로직이 사전에 정의돼야 함).

---

### 4) **레짐/노출(베타·섹터·단일종목) 게이트 추가: “알파”가 아니라 “폭발 방지장치”**
**(a) 왜 필요한지**
- Tech/Healthcare 편중은 레짐(금리/리스크오프)에 취약.  
- candidate의 MDD 확대는 **노출 통제 실패**(베타/변동성/단일종목 비중) 가능성이 큼.

**(b) 위험/부작용**
- 과도한 중립화는 수익을 깎음.
- 게이트가 잦게 발동하면 “성과가 안 움직임”으로 보일 수 있음(거래 억제).

**(c) 최소 실험(공용 실험 E4)**
- E4(노출/레짐 게이트 + 섹터/종목 캡 + 드로우다운 스톱 규칙)

**(d) PASS 조건**
- worst_mdd **개선 목표: ≥ -0.075**(현 champion worst_mdd -0.081 대비 방어 강화).
- 베타/변동성 노출이 상한 내에서 안정(예: rolling beta |β| ≤ 1.1, 포트 변동성 상한) + lockbox_mean **≥ 3.5** 유지.

---

### 5) **운영 리스크(48시간 자동루프) 방어: 데이터 신선도·결측·주문 실패 “자동 감지→강등 모드”**
**(a) 왜 필요한지**
- 성능이 아니라 “시스템이 멈추거나 이상 주문”이 가장 큰 손실 요인.
- 48시간 루프는 **데이터 지연/부분 장애**를 상수로 봐야 함.

**(b) 위험/부작용**
- 보수적 강등 모드가 잦으면 기회비용 증가.
- 로깅/모니터링 추가로 계산 비용 증가.

**(c) 최소 실험(아래 E1과 결합, 운영 게이트로 처리)**
- E1의 shadow-run에 **데이터 신선도/결측률/주문 생성 수** 지표를 함께 기록해 운영 게이트로 승격

**(d) PASS 조건**
- 데이터 신선도 SLA(예: 종가 기준 T+0/1 허용범위) 위반 시 **자동으로 “거래 억제/현금 대기/포지션 유지”**가 발동되고, 재시작 후 일관성 유지.
- 결측률/가격 이상치(스파이크) 탐지 시 주문 0 또는 축소가 **재현 가능**하게 작동.

---

## 공용 “실행 가능한 patch/실험” 4개만 제시 (48시간 자동 루프용)
아래 4개만 돌리고, 각 TOP5 제안에 재사용(케이스 폭발 방지).

---

### E1) **Leakage & Alignment Audit Patch + 24h Shadow Run**
1) **실험 정의**
- 피처 생성~라벨~리밸런싱 시점에 대해 아래를 코드로 강제:
  - 모든 feature는 **t 시점 종가/공시 이후 데이터만 사용**
  - 리밸런싱 주문은 **t+1 시점 체결**로 통일(또는 명시한 체결 규칙)
  - “미래 참조” 의심 컬럼(리턴/변화율/리밸런스 후 산출값) 자동 탐지
- 동일 전략을 **shadow(주문 미발행)** 로 24h 돌려 로그 수집

2) **게이트**
- 누수 테스트 0건
- seed 고정 재현성(동일 입력→동일 출력) 충족
- shadow에서 “주문 수/포지션 수/노출”이 비정상 스파이크 없을 것(예: 하루 주문 수 상한)

3) **기대 관측치**
- 성능이 일부 하락해도 지표가 “매끈”해짐(급격한 알파 붕괴/급등락이 줄어듦)
- candidate류의 MDD 폭발 원인이 정렬/누수면 즉시 개선 신호 관측

---

### E2) **비용모델 보수화 + Turnover Penalty Sweep (3점 스윕)**
1) **실험 정의**
- 슬리피지 = k * (spread proxy + vol proxy) 형태로 단순 보수 캘리브레이션
- 페널티 강도 3점만 스윕(약/중/강) + 주문 최소단위(거래 억제 임계값) 적용

2) **게이트**
- lockbox_mean ≥ 3.5 유지
- worst_mdd ≥ -0.085 유지
- turnover 상한(사전 정의) 초과 시 FAIL

3) **기대 관측치**
- 비용 증가에 따라 성능이 완만히 감소하는 “정상적 민감도 곡선”
- 비용 반영 후에도 남는 알파가 진짜 알파 후보

---

### E3) **Point-in-time Universe + Delist/Corp-Action Integrity Patch**
1) **실험 정의**
- universe를 “현재 리스트”가 아니라 **해당 시점에 거래 가능했던 종목**으로 재구성
- delist return / split / dividend 처리 일관화
- 8~14종목 제약을 만족 못하면 **명시적 대체 규칙**(현금/상위 후보) 적용

2) **게이트**
- 거래가능 종목수 충족률 ≥ 98%
- fold14_mdd 악화 금지
- delist/corp-action 이벤트가 있는 구간에서 PnL 계산이 깨지지 않을 것

3) **기대 관측치**
- 과대평가된 구간이 정리되며 “성과가 현실화”
- 이벤트 리스크로 인한 단일 기간 MDD 스파이크 감소

---

### E4) **Exposure/Regime Guardrails (Beta/Sector/Single-name Caps + DD Stop)**
1) **실험 정의**
- Tech/Healthcare 내에서도 단일 종목 캡, 섹터 비중 캡(편중 완화)
- 포트 beta/변동성 상한
- rolling drawdown 기반 “리스크 오프 스위치”(포지션 축소/현금 비중 확대)

2) **게이트**
- worst_mdd ≥ -0.075 목표(개선)
- lockbox_mean ≥ 3.5 유지
- 게이트 발동 빈도 과도(예: 거래일의 30% 이상) 시 FAIL(전략 마비 방지)

3) **기대 관측치**
- 레짐 전환(금리 급등/리스크오프)에서 손실 꼬리 감소
- 수익률은 약간 감소해도 생존성(하방)이 개선

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래 순서대로 **관측→원인 분기**만 수행(질문 없이 바로 실행 가능한 체크).

### A) Trigger(신호 발생) 문제
- 체크: 예측/스코어 분산(표준편차)이 과거 대비 급감했는가?
- 체크: 상위-하위 스코어 간 향후 수익 스프레드(IC/RankIC)가 0에 수렴했는가?
- 분기:
  - 스코어가 평평 → **피처 결측/정렬 버그/정규화 파손**(E1로 회귀)
  - IC는 있는데 성과 없음 → 적용/비용/노출 문제로 이동

### B) Apply(주문/리밸런싱 적용) 문제
- 체크: 목표 포지션 vs 실현 포지션 괴리(추적오차)가 커졌는가?
- 체크: 거래가 “너무 적거나(억제 과다)” “너무 많거나(미세 신호 과매매)” 둘 중 하나인가?
- 분기:
  - 괴리 큼 → 체결 지연/거래제한/가격 이상치 처리 문제(운영 게이트 강화)
  - 거래 과다 → 비용/turnover 게이트(E2)로 이동

### C) Exposure(노출) 문제
- 체크: 베타/섹터/단일종목 기여도가 PnL을 지배하는가?
- 체크: 손실 구간에서 특정 1~2종목이 대부분 기여하는가?
- 분기:
  - 집중 손실 → 단일종목 캡/섹터 캡(E4)
  - 시장동조 손실 → beta 상한/리스크오프 스위치(E4)

### D) Cost(비용) 문제
- 체크: gross(비용 전) 성과는 있는데 net(비용 후)에서만 죽는가?
- 체크: 슬리피지 민감도 스윕에서 성능이 급격히 붕괴하는가?
- 분기:
  - net만 붕괴 → turnover/체결규칙/스프레드 모델(E2)
  - gross도 붕괴 → 트리거/레짐으로 이동

### E) Regime(시장 국면) 문제
- 체크: 금리/변동성/리스크오프 구간에서만 일관되게 깨지는가?
- 체크: Tech vs Healthcare 상대강도 레짐에서 방향성 편향이 있는가?
- 분기:
  - 특정 레짐에서만 FAIL → 레짐 필터/노출 게이트(E4)
  - 전 레짐에서 FAIL → 누수 제거 후 신호 재정의 필요(E1/E3 재점검)

---

## 실행 순서(48시간 루프에 바로 넣기)
1) **E1 실행(누수/정렬+shadow)** → 실패 시 나머지 실험 중단(가짜 성능 가능성 최우선 제거)  
2) **E2 실행(비용/turnover 스윕 3점)** → net 기준 생존 확인  
3) **E3 실행(서바이버십/델리스트/CA)** → 현실화된 백테스트 확보  
4) **E4 실행(노출/레짐 가드레일)** → MDD 꼬리 억제 확인  

이 4개만 통과하면, 그 다음 사이클에서야 “알파 확장”을 만질 자격이 생김(현재는 방어/정합성 우선).
