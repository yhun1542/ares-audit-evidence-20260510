아래는 **24~48시간 우선순위 TOP5**를 “명령형 체크리스트”로 정리한 실행안이다. 최우선으로 **누수/과최적화/서바이버십/비용 미반영/운영 리스크**를 먼저 잠근다.  
(미국주식 only, Tech+Healthcare 8~14종목, **ETF는 매매 금지(관측지표만)**)

## 0) 지금 즉시 경보로 취급할 신호(ONE TRUTH 기반)
- **degenerate_folds: [1,2,3,8]** → CV/워크포워드가 깨졌거나(빈 구간/거래 0), 라벨·룩백·필터로 샘플이 소실되는 구조(또는 누수 방지 실패) 가능성 큼.
- **worst_mdd: None** → 성과지표 계산 파이프라인이 완주하지 못했거나(에쿼티 커브/리밸런스 로그 누락), 리스크 측정이 무력화됨.
- **file/lane_hash/run_hash: None** + rebalance pinpoint가 **파일 로딩 실패** → 운영/재현성/감사 가능성이 깨져서 “성능이 안 움직이는” 원인이 **실험이 실제로 적용되지 않는 문제**일 수 있음.

# 1) 우선순위 TOP5 (코드/아키텍처/전략)

## TOP1. “실험이 실제로 적용됐는지”를 보장하는 **아티팩트/로그/재현성 패치**
### (a) 왜 필요한지
- 지금 상태는 **챔피언 파일 경로/해시가 비어있고**, 리밸런스 로그도 못 읽어 **적용/미적용을 판별 불가**.  
- “No-Delta”가 반복될 때 가장 흔한 원인은 **캐시/설정 미적용/결과 파일 덮어쓰기/로그 미생성**.

### (b) 위험/부작용
- 로그/아티팩트 저장이 늘어 **디스크/IO 비용 증가**.
- 해시/버전 강제는 기존 파이프라인과 충돌 가능(초기 1~2회 실패 감수).

### (c) 최소 실험(공유 실험 ID 사용)
- **[E1] 파이프라인 스모크 + 아티팩트 강제 생성 실험**
- **[E2] (겸용) 폴드/샘플 헬스 메트릭 로그 강제 출력**

### (d) PASS 조건
- 모든 런에서 **run_hash/lane_hash/file 경로가 채워지고**, 아래 아티팩트가 “0바이트/파싱 실패 없이” 생성될 것:  
  `rebalance.jsonl(or csv)`, `equity_curve`, `positions`, `metrics.json`, `config_snapshot.json`, `data_version.txt`  
- 챔피언/후보 비교 시 **동일 데이터 버전**이 메타데이터로 검증될 것.

---

## TOP2. **누수/과최적화 방지**: Purge+Embargo 워크포워드로 CV 재구성 + degenerate fold 제거
### (a) 왜 필요한지
- degenerate folds는 성능이 “우연히” 좋아지거나/나빠지거나/안 움직이는 현상을 만든다.
- 시계열에서 (특히 리밸런스/룩백) **라벨 누수**가 생기면 OOS 평균이 안정적으로 보이지만 실전에서 붕괴한다.

### (b) 위험/부작용
- 샘플 수가 줄어 **OOS 평균이 하락**할 수 있음(정상적인 디레버리징).
- 기존 챔피언 대비 “좋아 보이던” 결과가 사라질 가능성(정상).

### (c) 최소 실험
- **[E2] Purged Walk-Forward A/B 실험** (기존 split vs purge+embargo)
- **[E4] (겸용) PIT 유니버스 고정 시 샘플/폴드 정상화 확인**

### (d) PASS 조건
- `degenerate_folds == []` (0개)  
- 각 폴드에서 최소 요건 충족(예):  
  - 거래 발생 폴드 비율 ≥ 90%  
  - 폴드별 유효 샘플 수 하한선 충족(예: n>=X)  
- OOS mean이 단기적으로 소폭 하락해도 **OOS min/분산이 개선**되면 통과(과최적화 제거 신호).

---

## TOP3. **비용/슬리피지/회전율(턴오버) 반영**: “0비용 알파” 제거
### (a) 왜 필요한지
- 비용 미반영은 가장 흔한 “백테스트만 이기는” 원인.  
- 특히 Tech/Healthcare 단일종목은 유동성이 좋아도 **턴오버가 높으면 수익이 증발**한다.

### (b) 위험/부작용
- 기대수익 급락 가능(정상).  
- 수수료/슬리피지 모델 선택에 따라 결과가 흔들릴 수 있음 → 민감도 스윕으로 잠금.

### (c) 최소 실험
- **[E3] 비용 민감도 스윕(LOW/BASE/HIGH 3단계)**
- **[E5] (겸용) 리스크/노출 제약으로 턴오버 감소 효과 확인**

### (d) PASS 조건
- BASE 비용에서 **OOS mean이 0비용 대비 과도하게 붕괴하지 않을 것**(예: 유지율 ≥ 60~70%)  
- 턴오버 상한 만족(예: 일평균 turnover ≤ T, 리밸런스당 체결 비중 상한)  
- 비용 포함 후에도 OOS min이 급락하지 않을 것(꼬리 리스크 감소/유지).

---

## TOP4. **서바이버십/유니버스 규율**: Tech+Healthcare 8~14 종목을 PIT(시점정합)로 고정
### (a) 왜 필요한지
- 종목 선택이 “현재 기준”으로 고정되면 **서바이버십 바이어스**가 성능을 부풀린다.
- 유니버스가 런마다 미세 변경되면 성능이 안 움직이거나 요동(실험 비교 불가).

### (b) 위험/부작용
- PIT 데이터 준비가 없으면 구현이 번거로움 → 24~48시간은 “고정 바스켓”으로 먼저 잠금.
- 너무 적은 종목은 분산 부족 → 8~14로 제한 유지.

### (c) 최소 실험
- **[E4] 고정 바스켓(12종목) vs 기존 유니버스 A/B**
- **[E1] (겸용) 유니버스 스냅샷을 아티팩트로 저장/재현**

### (d) PASS 조건
- 런마다 동일 유니버스가 재현되고(해시 동일), 결측/상장폐지 처리로 런이 깨지지 않을 것.
- 고정 바스켓에서도 기본적인 성과/리스크 지표가 계산되며 `worst_mdd`가 None이 되지 않을 것.

**권장 “고정 바스켓(예: 12)”** *(미국주식, Tech+Healthcare 중심)*  
- Tech: AAPL, MSFT, NVDA, GOOGL, AMZN, META, AVGO, AMD  
- Healthcare: LLY, UNH, JNJ, ABBV  
(ETF(QQQ/XLV/VIX)는 **관측지표**로만 사용)

## TOP5. **운영 리스크 + 노출 관리(리스크 게이트)**: 노출/변동성 타게팅 + 레짐 관측
### (a) 왜 필요한지
- 현재 노출 max ~0.84로 보이지만, MDD가 None이면 **리스크가 측정/제어되지 않음**.  
- 48시간 자동 루프는 “나쁘면 자동으로 멈추거나 축소”하는 게이트가 없으면 누적 손실 위험이 큼.

### (b) 위험/부작용
- 리스크 게이트가 너무 강하면 수익 기회를 잘라 **평균 수익 감소** 가능.
- 레짐 필터는 과최적화 위험 → 관측지표(ETF/지수)로 단순화.

### (c) 최소 실험
- **[E5] 노출 캡 + 변동성 타게팅 + 드로다운 브레이크 실험**
- **[E3] (겸용) 비용 포함 환경에서 리스크 제약의 순효과 확인**

### (d) PASS 조건
- `worst_mdd`가 항상 계산되고, 상한을 만족(예: MDD ≤ 한도)  
- 노출 분포가 안정(예: exposure_max ≤ 0.6~0.8, 급격한 0↔MAX 점프 감소)  
- 리스크 게이트 발동 로그가 남고(언제/왜), 성과가 “멈춤”이 아니라 “보호”로 기능할 것(테일 손실 감소).

# 2) 48시간 자동 루프용 “실행 가능한 실험 5개”(전체 유니크 5개로 제한)

아래 5개만 돌려도 위 TOP1~TOP5를 모두 커버하도록 설계했다. (각 TOP 제안은 이 실험들을 재사용)

---

## [E1] 아티팩트/리밸런스 로그 강제 생성 스모크
**(1) 실험 정의**
- 모든 런에서 다음을 **강제 저장**: `run_hash`, `lane_hash`, `config_snapshot`, `data_version`, `rebalance.jsonl`, `equity_curve`, `positions`, `metrics`.
- rebalance pinpoint가 요구하는 입력 포맷을 표준화(JSONL/CSV 중 1개로 통일)하고, “--base-log” 같은 placeholder가 남지 않게 경로 결정을 강제.

**(2) 게이트(사전 차단)**
- 아티팩트가 하나라도 누락/0바이트/파싱 실패면 그 런은 **즉시 FAIL** 처리(성능 비교 금지).
- `file` 필드가 비어 있으면 FAIL.

**(3) 기대 관측치**
- “No-Delta” 발생 시에도 **적용 여부가 로그로 판명**됨(설정 diff / 해시 diff / 데이터 버전 diff).
- `worst_mdd: None` 발생 원인이 어디서 생기는지(에쿼티/리밸런스 누락) 즉시 추적 가능.

---

## [E2] Purged Walk-Forward(CV) + 폴드 헬스 메트릭
**(1) 실험 정의**
- 기존 split을 **purge+embargo**(레이블 윈도우/룩백 고려)로 교체.
- 폴드별로 `n_samples`, `n_trades`, `exposure_mean`, `exposure_nonzero_ratio`를 출력.

**(2) 게이트**
- degenerate fold(거래 0 또는 샘플 0) 발생 시 FAIL.
- 폴드 간 성능 편차가 비정상(예: 한 폴드만 과도하게 좋음)일 때 경고 플래그.

**(3) 기대 관측치**
- OOS mean이 다소 내려가도, **OOS min과 분산 안정**(과최적화 제거) 쪽으로 이동.
- 폴드 붕괴가 사라지면 “성능이 안 움직임” 원인이 split 문제였는지 분리 가능.

---

## [E3] 비용/슬리피지 민감도 스윕(LOW/BASE/HIGH)
**(1) 실험 정의**
- 동일 신호/동일 리밸런스에서 비용만 3단계로 바꿔 재평가.
- 지표: net OOS mean, turnover, 체결비용 기여도, 거래 빈도.

**(2) 게이트**
- BASE 비용에서 net 성과가 특정 기준 미만이면 FAIL(“0비용 알파” 판정).
- HIGH에서 완전 붕괴하면 전략이 비용에 과민 → 리밸런스/노출 제약 필요 플래그.

**(3) 기대 관측치**
- 비용을 올려도 성과가 완만히 감소하면 “실전가능성” 상승.
- 비용 민감도가 크면 턴오버/리밸런스 주기/포지션 변화량이 주범으로 드러남.

---

## [E4] 서바이버십 방지용 “고정 바스켓 12종목” A/B
**(1) 실험 정의**
- 유니버스를 위 12종목으로 고정하고, 유니버스 스냅샷 해시 저장.
- 기존 유니버스(가변)와 결과 비교.

**(2) 게이트**
- 데이터 결측/정지/스플릿/배당 처리 오류 발생 시 FAIL.
- 유니버스가 런마다 바뀌면 FAIL(해시 불일치).

**(3) 기대 관측치**
- 결과 변동성이 줄고, 실험 간 비교가 가능해짐.
- 성능이 크게 줄면 기존 성능이 유니버스/서바이버십에 의존했을 가능성 신호.

---

## [E5] 리스크/노출 제약 + 레짐 관측 게이트(ETF는 관측만)
**(1) 실험 정의**
- 포트폴리오 제약 추가:
  - gross/net exposure 상한
  - per-name cap
  - 변동성 타게팅(최근 n일 realized vol 기반)
  - 드로다운 브레이크(예: 최근 peak 대비 DD 초과 시 노출 축소)
- 레짐 관측지표(매매 금지): QQQ, XLV, VIX 등을 사용해 risk-off 구간에서 노출만 축소.

**(2) 게이트**
- 리스크 지표 미계산(MDD None 등) 시 FAIL.
- 노출이 상한을 반복 위반하면 FAIL.

**(3) 기대 관측치**
- tail loss 감소, exposure 분포 안정.
- 수익이 줄어도 “살아남는 곡선”으로 이동(48시간 루프 운영 안정성 개선).

# 3) “성능이 안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐)

아래 트리를 순서대로 태워서, 원인을 **한 번에 한 축씩** 고립시켜라(케이스 폭발 금지).

## A. 트리거(신호가 실제로 변하나?)
- **신호 시계열 diff를 아티팩트로 저장**: (t별 signal, rank, entry/exit flag)
- “패치 전/후 신호 상관 0.99+”면 → 전략 변화가 아니라 **적용 실패 또는 변화량이 너무 작음**
- 거래 수(`n_trades`)가 거의 동일하면 → 트리거 레이어는 동일, 아래 레이어(비용/노출/체결) 의심

## B. 적용(패치가 런에 반영됐나?)
- `config_snapshot`의 diff, `run_hash`/`lane_hash` diff를 강제 기록
- **캐시 키에 config/data_version 포함**(미포함이면 “항상 같은 결과” 발생)
- 리밸런스 파일 파싱 실패/누락이면 → 비교 자체가 무의미(먼저 TOP1)

## C. 노출(포지션이 실제로 달라지나?)
- `exposure_nonzero_ratio`, `position_count`, `max_weight`를 런별 비교
- 신호가 달라도 노출이 같으면 → **포지션 빌더/리밸런서가 신호를 무시**(클리핑/정규화/최소주문단위/현금제약)

## D. 비용(비용 때문에 차이가 상쇄되나?)
- gross PnL과 cost를 분리 기록: `gross_pnl`, `cost_pnl`, `net_pnl`
- “gross는 개선, net은 동일”이면 → 개선분이 비용으로 상쇄(턴오버/슬리피지)  
  → [E3]로 즉시 확인

## E. 레짐(시장 국면에 따라 무력화되나?)
- 관측지표(ETF/지수)로만 레짐 태깅: 예) QQQ 추세, XLV 상대강도, VIX 레벨
- 레짐별 성능 테이블(단 3구간 정도로 단순화): risk-on / neutral / risk-off
- 특정 레짐에서만 성능이 살아있으면 → [E5]처럼 “노출 스케일링”으로 운영 안정성 우선 확보

---

## 바로 실행 순서(24~48시간)
1) **E1부터 돌려서** 아티팩트/리밸런스/에쿼티 생성이 100% 되는지 먼저 잠가라(FAIL이면 성능 논의 금지).  
2) 다음으로 **E2**로 degenerate folds 제거 및 누수 방지 split 확정.  
3) 그 다음 **E3**로 비용 포함 실전가능성 컷.  
4) 동시에 **E4**로 유니버스/서바이버십 변동을 고정.  
5) 마지막으로 **E5**로 MDD/노출/레짐 기반 운영 게이트를 걸어 48시간 루프 안전장치를 완성.

이 순서를 따르면 “성능이 안 움직임”이 **(i) 적용 실패**인지, **(ii) CV/폴드 붕괴**인지, **(iii) 비용 상쇄**인지, **(iv) 유니버스 바이어스**인지, **(v) 레짐 민감도**인지가 48시간 내에 분리된다.
