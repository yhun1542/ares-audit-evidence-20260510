### [PRIORITY TOP 5] 다음 24~48시간 액션 플랜

#### 1. 인프라 긴급 복구: 로그 파싱 및 MDD 계산 로직 수정
*   **(a) Why:** `worst_mdd: None`과 `rebalance.csv` 로딩 에러는 치명적 결함. 리스크 계측 없이 수익률(OOS Mean 3.32)만 보는 것은 '눈 가리고 운전'하는 꼴.
*   **(b) Risk:** 로깅 수정 중 파이프라인 일시 중단 가능성. MDD 계산 시 실제 성과가 급락하여 현재 챔피언 폐기 가능성(사실 이게 필요함).
*   **(c) Experiments:**
    *   `FIX_LOG_FORMAT`: JSONL/CSV 헤더 불일치 수정 및 `worst_mdd`가 `NaN/None`일 때 0 또는 -1.0으로 강제 변환하는 예외처리 추가.
    *   `RECALC_METRICS`: 기존 로그 기반으로 메트릭 재계산만 수행.
*   **(d) PASS 조건:** `worst_mdd`가 숫자(float)로 출력됨 AND `rebalance_pinpoint.py`가 에러 없이 리포트 생성.

#### 2. Degenerate Folds [1, 2, 3, 8] 해소 (Fold별 '무거래' 타파)
*   **(a) Why:** 전체 Fold의 절반 가까이가 퇴행(degenerate). 이는 특정 기간(하락장 등)에 아예 매매를 안 하여(Exposure 0) 방어한 것이 아니라, 데이터 누락이나 로직 오류로 신호가 안 나온 '가짜 방어'일 확률 99%.
*   **(b) Risk:** 강제 매매 시 OOS Mean 대폭 하락 가능성. 그러나 이는 '숨겨진 손실'을 드러내는 과정임.
*   **(c) Experiments:**
    *   `EXP_LOOSE_ENTRY`: 진입 임계값(Threshold)을 20% 낮춰 거래 강제 유발.
    *   `EXP_FILL_DATA`: 해당 Fold 기간의 데이터 결측치(NaN)를 전일 종가(FFILL)로 채워 신호 생성 유도.
    *   `EXP_NO_SHORT`: 숏 포지션 로직이 있다면 일시 비활성화 후 롱 온리로 해당 Fold 재검증.
*   **(d) PASS 조건:** `degenerate_folds` 리스트가 빈 배열(`[]`)이 되거나 개수가 1개 이하로 감소.

#### 3. 유니버스 생존 편향(Survivorship Bias) 제거 및 섹터 검증
*   **(a) Why:** 2026년 시점 기준 Tech/Healthcare 상위 종목을 과거(Fold 1~3)에 적용했을 가능성. 당시 없었거나 비상장인 종목이 포함되면 백테스트는 무의미.
*   **(b) Risk:** 유니버스 교체 시 전체 파이프라인 재학습 필요(시간 소요). 수익률 급감 예상.
*   **(c) Experiments:**
    *   `EXP_DYNAMIC_UNIVERSE`: 고정 14개 종목 대신, 각 Fold 시작 시점 기준 시총 상위 Tech/Health 10개로 동적 구성.
    *   `EXP_MIN_HISTORY`: 최소 5년 이상 거래 내역 있는 종목으로만 유니버스 제한.
*   **(d) PASS 조건:** OOS Mean이 1.5 이상 유지되면서 `oos_min`이 -0.1보다 나쁘지 않음.

#### 4. 비용 구조(Cost Model) 현실화 테스트
*   **(a) Why:** 현재 OOS Mean 3.32는 슬리피지와 수수료가 0이거나 매우 낮게 설정되었을 때 나오는 전형적인 수치. 잦은 리밸런싱은 실제 계좌를 녹임.
*   **(b) Risk:** 턴오버가 높은 전략이었다면 성과가 마이너스로 전환될 수 있음.
*   **(c) Experiments:**
    *   `EXP_COST_10BPS`: 매매당 10bps(0.1%) 비용 강제 적용.
    *   `EXP_TURNOVER_CAP`: 일일 회전율(Turnover)을 10% 미만으로 제한하는 페널티 항 추가.
*   **(d) PASS 조건:** 비용 적용 후에도 OOS Mean > 1.0 유지.

#### 5. 레짐(Regime) 기반 동적 노출 제어 (ETF 관측 활용)
*   **(a) Why:** Tech/Healthcare는 금리/변동성에 민감. 개별 종목만 보지 말고 XLK(Tech), XLV(Health)의 이격도를 관측 지표로 삼아 전체 Exposure(0.0~0.83)를 조절해야 함.
*   **(b) Risk:** 지표 래깅(Lagging)으로 인한 진입 시점 지연.
*   **(c) Experiments:**
    *   `EXP_REGIME_FILTER`: XLK가 200일 이동평균 아래면 전체 Exposure Max를 0.4로 제한.
    *   `EXP_VOL_SCALE`: VIX 지수가 25 이상일 때 현금 비중 50% 강제.
*   **(d) PASS 조건:** `worst_mdd`가 -15% 이내로 방어됨 AND 샤프 비율 개선.

### [성능 정체 시 원인 분해 아이디어]

성능 지표가 움직이지 않거나(Flat), 개선되지 않을 때 아래 트리를 따라 디버깅할 것.

1.  **트리거(Trigger) 확인:**
    *   **증상:** 거래 횟수 0 또는 극단적으로 적음.
    *   **진단:** 진입 조건(Threshold)이 너무 높거나, 지표값(Feature)이 `NaN`으로 계산되어 필터링됨.
    *   **액션:** Feature Scaling(Z-score 등)이 정상 범위(-3 ~ 3) 내에 들어오는지 분포 확인.

2.  **노출(Exposure) 확인:**
    *   **증상:** 승률은 좋은데 총 수익이 낮음.
    *   **진단:** 베팅 사이즈(Position Sizing)가 너무 작음(예: 자산의 5%만 투입).
    *   **액션:** `exposure_max` 파라미터를 0.83 → 0.95로 상향하거나, 변동성 역가중(Inverse Volatility) 로직 점검.

3.  **비용(Cost) 민감도:**
    *   **증상:** Gross Return은 우상향이나 Net Return은 하락.
    *   **진단:** 평균 보유 기간(Holding Period)이 너무 짧음 (예: 1~2일).
    *   **액션:** 최소 보유 기간(3일) 강제 또는 이익 실현 폭(Take Profit) 확대.

4.  **레짐(Regime) 불일치:**
    *   **증상:** 특정 Fold(1, 2, 3 등)에서만 박살 나거나 퇴행.
    *   **진단:** 해당 기간의 시장 성격(하락장, 횡보장)에 전략이 역행.
    *   **액션:** 롱/숏 비중을 동적으로 조절하는지 확인(현재 상태는 Long Only 편향 가능성 높음).
