## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — *명령형 체크리스트*

### 1) **누수(Leakage)·과최적화(Overfit) 차단: “시간/조인/스플릿”을 하드 게이트로 고정**
- [ ] **PIT(Point-in-Time) 기준**으로 모든 feature/label 생성 파이프라인 `asof` 정렬 강제 (미래값 혼입 차단)
- [ ] CV에 **purge+embargo** 적용(특히 t+1 라벨/리밸런싱이면 최소 1~5일 purge)
- [ ] 실험 선택 기준을 **tuning이 아닌 lockbox 우선**으로 고정(현재 tuning>lockbox 갭이 누수/과최적화 의심 신호)

**(a) 왜 필요한지**
- 현재 Champion은 tuning_mean(1.90) 대비 lockbox_mean(1.79)로 갭이 작지만, “다음 후보 탐색”에서 누수/과최적화가 섞이면 탐색 효율이 급락함.
- 후보가 MDD는 개선(-0.041)했지만 mean이 크게 하락 → “리스크 감소형 과최적화/우연 적중” 패턴 가능.

**(b) 위험/부작용**
- [ ] purge/embargo로 표본이 줄어 tuning 성능 급락 가능(정상)
- [ ] PIT를 강제하면 기존 feature 일부가 무효화되어 단기적으로 성능 하락 가능(정상)

**(c) 최소 실험 2~3개 (아래 공용 실험 E1~E5 재사용)**
- [ ] **E1**(Leakage Audit Harness) 실행
- [ ] **E4**(Regime Gating)에서 regime feature가 미래 정보를 쓰는지 동시 점검(특히 ETF 지표의 종가 타이밍)

**(d) PASS 조건**
- [ ] E1에서 **lookahead/alignment 경고 0건**
- [ ] purge/embargo 적용 후에도 **lockbox_mean이 champion 대비 -0.05 이내**(과최적화 제거 후에도 유지되는지)
- [ ] tuning-lockbox 갭이 **절대값 0.20 이하**로 축소/유지

### 2) **비용·슬리피지·회전율(턴오버) “실거래 근사”를 백테스트에 강제 반영**
- [ ] 거래비용을 “고정 bps”가 아니라 **유동성/변동성 기반 슬리피지**로 치환
- [ ] **턴오버 상한**(일/주 단위) + 주문 분할(가정) + 체결 실패(패널티) 반영
- [ ] 결과 리포트에 **gross vs net**, 비용 기여도(cost attribution) 출력

**(a) 왜 필요한지**
- Tech/Healthcare 8~14 종목 집중이면 회전율과 슬리피지가 성과를 좌우.
- 비용 미반영 상태의 개선은 대부분 실전에서 증발(특히 리밸런싱 잦은 알파).

**(b) 위험/부작용**
- [ ] net 성과가 급락해 “좋아 보이던” 신호가 모두 사라질 수 있음(정상)
- [ ] 비용모델이 과도하면 보수적 편향으로 탐색이 멈출 수 있음(모델 캘리브레이션 필요)

**(c) 최소 실험 2~3개**
- [ ] **E2**(Cost/Slippage Model) 적용
- [ ] **E5**(Risk/Ops Overlay)에서 회전율 억제(리밸런싱 밴드/쿨다운) 동시 적용

**(d) PASS 조건**
- [ ] **net lockbox_mean ≥ champion_net_lockbox_mean - 0.03** (net 기준으로 비교)
- [ ] 평균 턴오버가 기존 대비 **20% 이상 감소** 또는 비용(연율)이 **명시한 상한 이하**
- [ ] worst_mdd 악화가 **-0.01 이내**(비용 반영이 리스크를 악화시키지 않음)

### 3) **서바이버십·코퍼레이트액션·유니버스 고정(US, Tech+Healthcare 8~14)**
- [ ] 종목 선택을 **GICS(Tech/Healthcare) + 미국 상장**으로 강제
- [ ] **8~14 종목** 유지(상한/하한 위반 시 리스크/현금 처리 룰 고정)
- [ ] **ADV(거래대금)·가격·스프레드 근사**로 유동성 필터
- [ ] (가능하면) **delisting return 포함** 및 심볼 변경/스플릿/배당 조정 확인

**(a) 왜 필요한지**
- 서바이버십/심볼 히스토리 오류는 lockbox에서 “이상하게 안정적인 성과”를 만들 수 있음.
- 유니버스가 흔들리면 전략이 아니라 데이터셋이 바뀌는 셈 → 실험 비교가 무의미해짐.

**(b) 위험/부작용**
- [ ] 유니버스 축소로 분산이 줄어 MDD 상승 가능
- [ ] delisting 반영 시 과거 성과가 급락할 수 있음(정상: 현실 반영)

**(c) 최소 실험 2~3개**
- [ ] **E3**(Universe+Survivorship Enforcement) 실행
- [ ] **E2**(Cost/Slippage)와 결합해 “유동성 부족 종목이 비용으로 자동 탈락”하는지 확인

**(d) PASS 조건**
- [ ] 모든 fold에서 **보유 종목 수 8~14 준수율 99%+**
- [ ] 유니버스 재현성(동일 시드/동일 기간) **매 런 동일 종목 풀**(PIT/룰 기반)
- [ ] lockbox 성과가 급락하더라도, **데이터 품질 경고 0건**(급락은 수용 가능, 오류는 불가)

### 4) **레짐(Regime) 분해 기반 게이팅(ETF는 “매매 금지”, 관측지표로만)**
- [ ] ETF 지표(예: **XLK, XLV, IBB, XBI, QQQ, SPY, TLT**, VIX proxy)를 **“관측/게이트” 전용**으로 사용
- [ ] 레짐별(추세/변동성/금리) 성과를 리포트로 고정 출력
- [ ] 레짐이 불리할 때는 **노출 축소(현금/저베타)** 또는 리밸런싱 빈도 감소

**(a) 왜 필요한지**
- Tech/Healthcare는 금리/리스크온오프에 민감. 신호가 맞아도 레짐이 역풍이면 성과가 정체.
- “안 움직임”의 대부분이 레짐 미스매치에서 발생.

**(b) 위험/부작용**
- [ ] 게이트가 과하면 트레이드 수가 감소 → 평균 수익 감소 가능
- [ ] 레짐 정의가 누수/과최적화되면 오히려 악화(그래서 E1과 같이 고정)

**(c) 최소 실험 2~3개**
- [ ] **E4**(Regime-aware Gating) 실행
- [ ] **E1**(Leakage Audit)로 ETF 지표 타이밍(종가 사용 시 t+1 적용) 검증

**(d) PASS 조건**
- [ ] lockbox에서 **worst_mdd가 0.01 이상 개선** 또는 tail(하위 10%) 손실이 의미 있게 축소
- [ ] 레짐별 성과 테이블에서 “최악 레짐”의 손실이 **명확히 감소**
- [ ] 트레이드 수/노출 감소가 있더라도 net 성과가 champion 대비 **-0.05 이내**

### 5) **운영 리스크(체결/결측/이벤트) 내성: “깨지지 않는” 48시간 루프**
- [ ] 데이터 결측/지연 시 **폴백(전일값/현금)** 룰 고정
- [ ] **실적발표(earnings) 윈도우** 전후 익스포저 제한(예: T-1~T+1)
- [ ] 포지션 상한(종목당 max weight), 섹터 캡(Tech/Healthcare 내에서도) 및 **DD 회로차단** 구현

**(a) 왜 필요한지**

- 8~14 집중 포트는 단일 이벤트(실적/임상) 충격에 취약.

**(b) 위험/부작용**
- [ ] earnings 회피로 알파 일부 상실 가능
- [ ] DD 회로차단이 반등 구간 수익을 제한 가능

**(c) 최소 실험 2~3개**
- [ ] **E5**(Risk/Ops Overlay) 실행
- [ ] **E2**(Cost/Slippage)와 함께 “운영 제약이 비용/턴오버를 줄이는지” 확인

**(d) PASS 조건**

- [ ] worst_mdd 악화 없이(≤ -0.01) tail 리스크가 감소

## 48시간 자동 루프에 넣을 “공용 실험(3~5개)” 정의 (총 5개로 고정)

> 아래 5개만 등록/실행하고, TOP5 제안은 이 5개를 공유해서 검증(케이스 폭발 방지).

### **E1. Leakage Audit Harness (누수/정렬/스플릿 게이트)**
1) **실험 정의**
- PIT/asof join 검사, feature timestamp 검사, label horizon 정합, purge+embargo CV 강제
2) **게이트**
- lookahead/alignment 오류 0
- tuning-lockbox 갭 상한(예: 0.20)
3) **기대 관측치**
- tuning 성과 일부 하락(정상), lockbox 안정성 증가 / 분산 감소

### **E2. Cost/Slippage/Turnover Netting (비용 내재화)**
1) **실험 정의**
- ADV/변동성 기반 슬리피지 + 수수료 + 스프레드 근사, 턴오버 상한/쿨다운 옵션
2) **게이트**
- gross→net 비용 기여도 리포트 필수
- 연율 비용/턴오버 상한 준수
3) **기대 관측치**
- 고회전 신호가 탈락, MDD 또는 tail 개선(또는 mean 감소)

### **E3. Universe+Survivorship Enforcement (US Tech+Healthcare, 8~14 고정)**
1) **실험 정의**
- GICS 필터 + 유동성 필터 + 보유 종목수 8~14 강제 + delisting/CA 점검
2) **게이트**
- 보유 종목수 규칙 위반 0(허용 예외는 “현금”으로만)
- 데이터 경고(심볼/CA) 0
3) **기대 관측치**
- 성과가 재현 가능해지고, “이상치 성과”가 사라질 수 있음

### **E4. Regime-aware Gating (ETF는 관측만)**
1) **실험 정의**
- XLK/XLV/IBB/XBI/QQQ/SPY/TLT, VIX proxy로 레짐 분류 → 노출 스케일링/리밸런싱 빈도 조절
2) **게이트**
- ETF 지표 타이밍(t vs t+1) 검증(E1 연동)
- 레짐별 성과 리포트 자동 출력
3) **기대 관측치**
- 최악 레짐 손실 감소, trade 수 감소 가능

### **E5. Risk/Ops Overlay (운영 내성)**
1) **실험 정의**
- 종목 비중 상한, DD 회로차단, earnings 윈도우 회피, 결측 폴백
2) **게이트**
- 상한 위반 0, NaN/결측 중단 0
- 주문/포지션 로그에 “왜 축소/현금화” 사유 기록
3) **기대 관측치**
- tail 리스크 감소, 평균 수익 소폭 감소 가능

## 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)

### A) **Trigger(신호 발생) 문제**
- [ ] 신호 발생 빈도(일/주) 추적: 과도 감소/증가 여부
- [ ] feature 분포 드리프트(훈련 vs 최근) KL/PSI 로그
- [ ] 상위 feature 중요도/계수 안정성(기간별) 저장

### B) **Apply(적용/리밸런싱) 문제**
- [ ] 리밸런싱 시점(t 종가? t+1 시가?) 일관성 점검(E1)
- [ ] 8~14 유지 규칙 때문에 “원하는 종목”이 빠지고 대체가 들어가는 비율 추적
- [ ] 쿨다운/밴드가 신호를 지나치게 억제하는지(미체결/미적용률) 로그

### C) **Exposure(노출) 문제**
- [ ] 팩터 노출 분해: beta(SPY), size, momentum, quality, sector(Tech/Health 내 하위산업)
- [ ] 상위 1~2 종목 기여도(성과/리스크) 과집중 여부
- [ ] 레버리지/현금 비중 시계열로 “실제로 베팅을 했는지” 확인

### D) **Cost(비용) 문제**
- [ ] gross→net 차이의 80%가 어디서 생기는지: (스프레드/슬리피지/수수료/회전율)
- [ ] 비용이 큰 종목/요일/변동성 구간(상위 10%) 식별 → 유동성 필터/게이트 개선(E2/E3)

### E) **Regime(레짐) 문제**
- [ ] 레짐별 성과 매트릭스: (SPY 추세/횡보)×(VIX 높음/낮음)×(금리 상승/하락)
- [ ] XLK vs XLV 상대강도, IBB/XBI 변동성으로 “헬스케어 바이오 리스크” 구간 분리
- [ ] 최악 레짐에서만 무너지는지 확인 후 E4 게이트의 스케일만 조정(구조 변경 금지)

- [ ] (1) 게이트 통과 못 하면 성능 비교 금지(누수/비용/유니버스부터 해결)
- [ ] (2) 통과한 설정만 `--select-best` 대상에 포함(락박스 우선)
