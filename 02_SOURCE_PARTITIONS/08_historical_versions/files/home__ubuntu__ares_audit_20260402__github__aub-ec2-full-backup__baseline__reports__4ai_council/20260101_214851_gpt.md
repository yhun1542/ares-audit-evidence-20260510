## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — “명령형 체크리스트”

### 1) **누수(Leakage)·타임라인 정합성(As-of) 최우선 봉인**
- **왜 필요한지**
  - 현재 후보가 lockbox가 좋게 나오고 있어도, *체결 시점/가격 참조/특징량 산출 시점* 누수 1개면 성능이 “가짜로 고정”될 수 있음.
  - 특히 `close로 신호 계산 → 같은 close에 체결` 또는 `당일 종가/거래대금/ETF 지표를 당일 체결에 사용`은 가장 흔한 누수 패턴.
- **위험/부작용**
  - 누수 제거 후 성능 급락 가능(정상). 단기적으로 “안 움직이는” 느낌이 강해질 수 있음.
- **최소 실험(아래 공통 실험 중 선택)**
  - **[E1] 누수 가드레일(시프트/체결시점 강제)**
  - **[E4] 레짐·노출 감사(특히 이벤트/갭 구간 분리)**
- **PASS 조건**
  - (게이트) **E1에서** `lockbox_min > 0` 유지 + `tuning→lockbox 괴리(평균) ≤ 0.35`  
  - (게이트) **E1에서** “체결을 next-open으로 강제”해도 `worst_mdd ≥ -0.08` 유지  
  - (관측) 누수 제거로 수익이 줄더라도 *손익곡선의 형태가 유지*되고, 성능이 특정 구간(예: 대형 갭 구간)에만 의존하지 않음

---

### 2) **서바이버십·유니버스(Tech+Healthcare 8~14) PIT(Point-in-Time) 재정의**
- **왜 필요한지**
  - “미국주식 Tech+Healthcare only, 8~14종목”은 **유니버스 규칙이 곧 알파**가 됨.  
  - 현재 유니버스가 *현재 시점 티커 기준 고정*이면 서바이버십/리밸런싱 편향이 생기고, lockbox가 우연히 좋아질 수 있음.
- **위험/부작용**
  - PIT 유니버스로 바꾸면 종목 교체/거래 빈도가 증가(비용↑, 운영 복잡도↑).
- **최소 실험(공통 실험 매핑)**
  - **[E2] PIT 유니버스·상장폐지 스트레스**
  - **[E3] 비용 현실화 스윕(회전율 증가의 손익 영향 확인)**
- **PASS 조건**
  - (게이트) **E2에서** 종목 교체가 포함돼도 `lockbox_mean ≥ 1.45` 또는 (보수적으로) `기존 후보 lockbox_mean 대비 -10% 이내`
  - (게이트) 유니버스 교체 후 `max single-name contribution(절대값) ≤ 전체 PnL의 35%` (특정 생존자 1개가 성과를 지배하면 FAIL)
  - (관측) 성과 기여가 Tech/Healthcare 내 *복수 종목*으로 분산되고, 특정 기간·단일 이벤트 드리븐이 약해짐

---

### 3) **비용(슬리피지/스프레드/수수료/차입) 미반영 제거 + 회전율 상한**
- **왜 필요한지**
  - 8~14 종목 집중은 *포지션당 거래 규모가 커지고*, 작은 슬리피지 가정 오류가 전체 성과를 삼킴.
  - (롱/숏 여부와 무관하게) **스프레드+슬리피지+수수료+HTB/borrow**를 넣어도 살아남아야 “자동 루프 운영” 가능.
- **위험/부작용**
  - 비용 반영 후 성능 하락, 거래 빈도 감소로 신호가 둔화될 수 있음.
- **최소 실험(공통 실험 매핑)**
  - **[E3] 비용 현실화 스윕(보수/공격 비용 시나리오)**
  - **[E1] next-open 체결 강제(갭/슬리피지 체감)**
- **PASS 조건**
  - (게이트) **E3에서** “보수적 비용” 시나리오에서도 `lockbox_min > 0` 유지
  - (게이트) 비용을 2배로 올려도 `lockbox_mean`이 **-15% 이내**로만 감소(민감도 과하면 FAIL)
  - (관측) turnover 상한을 걸어도 성과가 완전히 붕괴하지 않고, 수익원이 “초단기 미세구조”가 아닌 방향성/중기 신호로 이동

---

### 4) **과최적화(튜닝 성능↑, 락박스 우연↑) 방지용 ‘스트레스 변형’ 고정 세트**
- **왜 필요한지**
  - 현재 후보는 tuning/lockbox가 모두 좋지만, **파라미터/데이터 변형에 취약**하면 48시간 자동 루프에서 “조금만 바뀌어도 급사”함.
- **위험/부작용**
  - 강건성 규제(제약/변형)를 넣으면 peak 성능은 내려갈 수 있음(정상).
- **최소 실험(공통 실험 매핑)**
  - **[E4] 레짐 분리 + 노출 감사(변형 포함)**
  - **[E3] 비용 변화 민감도(=실전 변형)**
- **PASS 조건**
  - (게이트) **E4에서** 레짐(저변동/고변동, 금리상승/하락, 빅테크 강세/약세) 분할 시 **모든 레짐에서** `lockbox_min ≥ 0` 또는 최소 `-0.2` 이상(레짐 한 곳에서 대형 붕괴하면 FAIL)
  - (게이트) `fold14_mdd` 수준이 **-0.06 이하로 악화되지 않음**(현재 후보 -0.041 근처 유지 기대)
  - (관측) 성과가 특정 레짐/한두 달에 “몰빵”되지 않고 분산

---

### 5) **운영 리스크(결측/정지/급갭/이벤트) 및 48시간 루프 안전장치**
- **왜 필요한지**
  - Tech/Healthcare는 **실적·FDA·가이던스**로 급갭/서킷브레이커 위험이 높음.
  - 자동 루프는 “데이터 결측/지연/스플릿/티커 변경”에 대한 방어가 없으면 실전에서 즉시 망가짐.
- **위험/부작용**
  - 안전장치(거래 중지/포지션 축소)가 과도하면 수익 기회 상실.
- **최소 실험(공통 실험 매핑)**
  - **[E4] 이벤트/갭 구간 분리 성과(갭 큰 날 제거/축소)**
  - **[E1] 체결 시점 강제 + 결측 시 no-trade 규칙 적용**
- **PASS 조건**
  - (게이트) 갭 상위 p% 구간(예: 상위 1~5%) 제거/축소해도 `lockbox_mean`이 **-20% 이내** 감소(갭 의존 과도하면 FAIL)
  - (게이트) 결측/이상치 주입(가격 1일 결측 등) 시 **시스템이 중단 없이 안전하게 no-trade로 수렴**
  - (관측) 대형 손실이 “단일 이벤트 1~2회”에 의해 발생하는 패턴이 감소

---

## 공통 “실행 가능한 patch/실험” 4개만 운용 (48시간 자동 루프 형태)
아래 4개만 돌리고, 위 TOP5는 **이 4개를 공유**해서 검증합니다. (케이스 폭발 방지)

---

### [E1] 누수 가드레일 실험 (Shift + Next-Open Execution 고정)
1) **실험 정의**
   - 모든 feature를 **최소 1 bar(1일) 시프트**(당일 close 기반이면 다음날부터 사용).
   - 체결은 **next-open**(또는 next-vwap)로 강제.  
   - “당일 종가로 계산된 지표로 당일 체결” 경로 전부 차단.
2) **게이트**
   - `lockbox_min > 0` 유지
   - `worst_mdd ≥ -0.08`
   - `tuning_mean - lockbox_mean ≤ 0.35`
3) **기대 관측치**
   - 성과가 약간 감소하더라도, *락박스의 최저 성과가 양수로 유지*되면 누수 의존이 낮음.
   - 급격한 붕괴면: 신호가 “체결/가격참조 누수”에 의존했을 가능성 큼.

---

### [E2] PIT 유니버스 + 서바이버십 스트레스 (Tech+Healthcare 8~14 유지)
1) **실험 정의**
   - 유니버스를 “현재 목록 고정” 금지. 매일 **PIT 기준**으로만 구성:
     - 시가총액/유동성 필터는 **t 시점에서 관측 가능한 데이터로만**
     - 티커 변경/상폐는 가능한 범위에서 반영(데이터가 없으면 최소한 “상폐/거래정지 시 no-trade & 강제 청산 규칙”으로 근사)
   - 최종 보유 종목 수는 8~14로 고정(규칙 유지).
2) **게이트**
   - `lockbox_mean`이 기존 후보 대비 **-10% 이내**(또는 절대값 기준 `≥ 1.45`)
   - 단일 종목 PnL 기여 상한(예: 35%) 초과 시 FAIL
3) **기대 관측치**
   - 성과가 특정 “살아남은 초대형주”에 편향돼 있으면 눈에 띄게 악화/편중이 드러남.
   - 정상이라면 성과 기여 분산 + 교체 비용 증가에도 견딤.

---

### [E3] 비용 현실화 스윕 (슬리피지/스프레드/수수료/borrow + 회전율 캡)
1) **실험 정의**
   - 비용 시나리오 3단(낙관/기준/보수)만:
     - 커미션(고정) + 스프레드(고정 또는 ATR 비례) + 슬리피지(bps)  
     - (숏이면) borrow/HTB 비용(보수 가정)
   - 동시에 **turnover cap**(예: 일간 교체/리밸런싱 상한) 한 번만 적용.
2) **게이트**
   - 보수 비용에서도 `lockbox_min > 0`
   - 비용 2배 시 `lockbox_mean` 감소폭 **≤ 15%**
3) **기대 관측치**
   - “비용이 알파를 잡아먹는 구조”인지 즉시 판별.
   - 회전율을 눌렀을 때도 살아남으면 실전 지속 가능성이 급상승.

---

### [E4] 레짐·노출 감사 + 이벤트(갭) 의존도 분리
1) **실험 정의**
   - 레짐 분할 백테스트(고정 분할만):  
     - 변동성 상/하(예: VIX/또는 ETF 관측지표: QQQ, XLK, XLV, XBI는 **지표로만**)  
     - 금리/리스크오프 근사(장단기 금리 프록시가 없으면 QQQ drawdown 구간으로 대체)
   - 노출 리포트 고정 산출:
     - 시장베타, 섹터 비중(Tech/Healthcare 내), 단일종목 집중, 롱/숏 넷(있다면)
   - 갭 상위 구간(예: 상위 1~5%) 성과 분리(제거/축소) 비교.
2) **게이트**
   - 레짐별 `min`이 과도 붕괴 금지(예: `≥ -0.2`, 이상이면 FAIL)
   - 갭 구간 제거 시 `lockbox_mean` 감소 **≤ 20%**
3) **기대 관측치**
   - 성과가 특정 레짐/갭 이벤트에 의존하면 분리 순간 급격히 무너짐.
   - 정상이라면 레짐별 성과 분산 + 노출이 과도하게 한 팩터에 고정되지 않음.

---

## 성능이 “안 움직일 때” 원인 분해 아이디어 (Trigger / 적용 / 노출 / 비용 / 레짐)
아래는 **진단 트리**로 바로 로그/리포트에 붙일 항목들입니다.

### A) Trigger(신호가 발생하나?)
- 신호 분포 드리프트: 평균/표준편차/상위분위 값이 과거 대비 수축(=거래 기회 실종)
- cross-sectional rank가 매일 비슷(=정렬이 무의미)
- 신호와 다음날 수익률 상관(IC) 롤링이 0 부근 고정

### B) 적용(제약·리밸런싱·체결이 신호를 죽이나?)
- 포지션이 목표 대비 항상 “클리핑(clipping)”됨: max weight, gross cap에 계속 걸림
- 리밸런싱 빈도/우선순위 때문에 실제 주문이 거의 안 나감(“신호는 있는데 주문이 없음”)
- 결측/가격 이상치 처리로 no-trade가 과도하게 발생

### C) 노출(원하는 베팅이 맞나? 의도치 않은 팩터가 지배하나?)
- 베타가 0을 목표했는데 계속 양(+)으로 유지 → 사실상 QQQ 롱 대체
- Tech/Healthcare 내부에서도 한 쪽(예: 빅테크)으로 사실상 쏠림
- 단일 종목/단일 주에 성과가 과도 집중(서바이버십/이벤트 의존)

### D) 비용(거래가 이기고 있어도 비용이 다 가져가나?)
- turnover 대비 예상 비용이 일 기대수익을 상회
- “승률은 괜찮은데 기대값이 0” → 슬리피지/갭 손실이 tail에 몰려 있을 확률
- 체결을 close→open으로 바꾸면 성과가 사라짐 → 미세구조/누수 의심

### E) 레짐(시장 환경이 바뀌면 망가지나?)
- 고변동 구간에서만 망가짐(리스크 모델/포지션 스케일 문제)
- 금리상승/리스크오프에서만 망가짐(성장주/바이오 팩터 노출 과다)
- 이벤트(실적/FDA) 구간에서만 tail loss 발생(운영 안전장치 필요)

---

## 즉시 실행 순서(48시간 루프에 맞춘 “명령형”)
1) **E1 실행 → 누수/체결시점 강제 통과 못 하면 이후 실험 보류**
2) **E3 실행 → 비용 민감도/turnover cap로 실전성 하한 확보**
3) **E2 실행 → PIT 유니버스/서바이버십 리스크 제거**
4) **E4 실행 → 레짐/갭 의존도와 노출 리포트로 ‘살아남는 구조’인지 확정**
5) **PASS한 설정만 candidate로 등록 → 자동 루프에서 select-best로 승격**

(현재 자동 커맨드 3줄은 유지하되, 위 실험들이 설정 파일/스펙으로 강제되도록 patch를 먼저 적용하는 쪽이 우선입니다.)
