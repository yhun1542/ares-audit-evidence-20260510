## 24~48시간 우선순위 TOP5 (명령형 체크리스트)

1) **누수/서바이버십/시점정렬(As-Of) 하드 차단 패치 적용**
- 데이터 로더/피처/라벨 생성 전 구간에 **as-of timestamp, 발표지연, corporate action 반영, delist 포함**을 강제.
- **Purged/Embargo CV**로 전환(특히 이벤트/리밸런싱 주기 주변).

2) **비용(수수료·슬리피지·스프레드·임팩트) + 회전율 페널티를 “학습/선정”에 내재화**
- 백테스트만 비용 반영이 아니라, **스코어링/선정(=실험 PASS 판단)** 자체를 비용 후 성과로 통일.
- turnover 급증 실험 자동 컷 게이트 추가.

3) **레짐(Tech/HC 리스크) 관측지표(ETF 등)로 “노출 게이트/리스크 오버레이” 추가 (매매는 개별주만)**
- QQQ/XLK/XLV/XBI/IWM/VIX 등은 **관측지표**로만 사용해 포지션 사이징/현금비중/리스크온오프를 제어.

4) **포트폴리오 구성(8~14개)에서 운영 리스크 낮추는 제약/안정화**
- 단일 종목/서브섹터 쏠림, 유동성 부족, 갭리스크를 제약으로 완화.
- “같은 시그널인데 MDD만 요동”을 줄이는 쪽으로 PC(Portfolio Construction) 개선.

5) **과최적화 방지(단순화/정규화/파라미터 민감도 게이트)**
- 튜닝 평균은 좋은데 min/lockbox가 흔들리는 패턴을 우선 제거.
- “튜닝-락박스 간 갭”을 정량 게이트로 박음.

## 48시간 자동 루프용 “실행 가능한 Patch/실험” 5개 (공유 풀)
아래 5개만 돌리고(케이스 폭발 금지), TOP5 제안별로 이 실험들을 조합/재사용.

### E1) Leakage/Survivorship/As-Of 강제 + Purged CV
- **실험 정의**
  - (코드) 데이터 파이프라인에 `as_of_time` 필드 강제, 피처별 “사용 가능 시점” 검사(발표지연/리비전 포함).
  - (검증) Purged/Embargo CV 적용(리밸런싱 윈도우 주변 데이터 purge).
  - (유니버스) delist/인수합병/티커변경 포함(서바이버십 제거).
- **게이트**
  - “미래 참조” 정적 검사/런타임 assert: 피처 timestamp > 거래결정 timestamp 발생 시 즉시 FAIL.
  - 튜닝-락박스 갭: `tuning_mean - lockbox_mean <= 0.15` 아니면 FAIL(과최적화 시그널).
- **기대 관측치**
  - 튜닝 성과는 보통 하락하나, **lockbox_min 상승/분산 감소**, fold 간 일관성 증가.

### E2) 비용·슬리피지·임팩트 내재화 + Turnover 컷
- **실험 정의**
  - (비용모델) 고정 수수료 + 스프레드(ATR/price 기반) + 슬리피지(ADV 대비 주문비중)로 단순 모델부터 적용.
  - (최적화/선정) 목적함수/스코어를 “net(after cost)”로 바꿔 후보 선정 자체를 비용 후로 통일.
  - (제약) 리밸런싱당 turnover 상한(예: 30~50%) 초과 시 포지션 변경을 클립.
- **게이트**
  - 평균 turnover, 상위 5% turnover 구간에서의 성과가 비용 후 플러스로 유지 못 하면 FAIL.
  - 비용 전/후 성과 괴리(`gross - net`)가 특정 임계(예: 연 -3%p) 넘으면 FAIL.
- **기대 관측치**
  - gross는 소폭 하락, **net Sharpe/lockbox_min 개선**(특히 min/최악구간).

### E3) 레짐 관측지표로 노출 게이트(리스크 오버레이)
- **실험 정의**
  - (지표) QQQ/XLK/XLV/XBI/IWM, VIX(또는 VIX proxy)로 risk-on/off 스코어 생성(추세/변동/크레딧 대용).
  - (적용) 개별주 알파는 유지하되, 스코어가 위험구간이면 **총 익스포저(또는 포지션 수/현금비중) 축소**.
- **게이트**
  - 레짐별(상승/하락/고변동) 성과 분해에서 “최악 레짐”의 MDD가 개선되지 않으면 FAIL.
- **기대 관측치**
  - 전체 mean은 비슷하거나 약간 감소, 대신 **worst_mdd 개선**이 관측되는 게 정상.

### E4) 포트폴리오 구성 제약(8~14개) + 변동성 타깃
- **실험 정의**
  - (제약) 종목당 최대 비중, 서브섹터/팩터(대형성장 편향) 쏠림 상한, 단일 종목 갭리스크 완화.
  - (사이징) 동일가중 → 리스크패리티(단순 inverse vol) 또는 변동성 타깃(포트 vol 일정화).
- **게이트**
  - 최대 비중/섹터쏠림 위반 시 FAIL.
  - 변동성 타깃 적용 후 **worst_mdd**가 개선되지 않으면 FAIL.
- **기대 관측치**
  - tail risk 완화로 **lockbox_min / worst_mdd 개선**, 평균은 소폭 변동.

### E5) 과최적화 억제 게이트(파라미터 민감도/단순화/정규화)
- **실험 정의**
  - (민감도) 핵심 하이퍼파라미터 ±10~20% 흔들어도 성과가 급변하지 않는지 “로컬 견고성” 체크.
  - (단순화) 피처 수/룰 수 축소, 규칙 기반이면 룰 pruning, 모델이면 정규화 강화.
- **게이트**
  - 민감도 스윕에서 lockbox_mean 표준편차가 임계 초과 시 FAIL(불안정).
  - 특정 fold만 과도하게 끌어올린 경우(“single-fold hero”) FAIL.
- **기대 관측치**
  - 튜닝 피크는 낮아져도 **락박스 평균/최저치가 안정**.

## TOP5 제안별: (a) 필요성 (b) 위험/부작용 (c) 최소 실험 2~3개 (d) PASS 조건
※ 각 제안은 아래 E1~E5 “공유 실험”에서 2~3개만 선택해 실행.

---

### 1) 누수/서바이버십/시점정렬 차단
- **(a) 왜 필요한지**
  - 현 챔피언이 튜닝/락박스 모두 강한 편이라, 다음 성능 개선이 안 뜨는 상황에서 **가장 먼저 의심해야 할 건 ‘숨은 누수로 만들어진 가짜 상한’** 또는 반대로 후보들이 누수 제거 없이 흔들리며 “진짜 개선”이 묻히는 케이스.
- **(b) 위험/부작용**
  - 튜닝 성과 급락(정상), 실험 실패가 늘어 “진행이 느려 보이는” 착시.
- **(c) 최소 실험(2~3)**
  - **E1**, **E5**(누수 제거 후 과최적화 억제까지 같이), (선택) **E2**(누수가 비용모델로 가려지는 경우 차단)
- **(d) PASS 조건**
  - `tuning_mean - lockbox_mean <= 0.15`
  - `lockbox_min >= 1.05` 유지 + fold 간 분산 감소(최저 fold 개선이 보이면 가점)
  - 누수 assert 0건(한 건이라도 발생 시 해당 후보 즉시 폐기)

---

### 2) 비용 미반영/회전율 과다(운영 불가) 우선 제거
- **(a) 왜 필요한지**
  - 8~14개 집중 포트는 리밸런싱이 잦으면 비용/슬리피지가 성과를 잠식. 특히 Tech/HC는 이벤트 갭이 커서 체결비용이 비선형으로 튐.
- **(b) 위험/부작용**
  - gross 성과 하락, “알파가 사라진 것처럼” 보일 수 있음(정상: 원래 알파가 비용으로 사라지는 전략이었을 가능성).
- **(c) 최소 실험(2~3)**
  - **E2**, **E4**(포지션 안정화로 turnover 감소), (선택) **E3**(레짐 악화 시 불필요 매매 축소)
- **(d) PASS 조건**
  - **비용 후(net) 기준** `lockbox_mean >= 1.76` AND `lockbox_min >= 1.05`
  - turnover 상위 구간에서도 net이 붕괴하지 않을 것(“고회전=필패” 패턴 제거)
  - 운영 게이트: 리밸런싱당 turnover 상한 위반 0회

---

### 3) 레짐(변동성/리스크오프)에서의 최악구간 개선
- **(a) 왜 필요한지**
  - 챔피언의 `worst_mdd ≈ -9.3%`는 나쁘지 않지만, 다음 후보가 “평균은 낮고 MDD만 개선”하는 패턴(직전 candidate)이 이미 관측됨. **평균을 크게 훼손하지 않으면서 tail만 깎는** 방향이 48시간 내 가장 현실적인 개선축.
- **(b) 위험/부작용**
  - 리스크오프 구간에서 과도한 디레버리징 → 반등장에서 기회비용 증가.
- **(c) 최소 실험(2~3)**
  - **E3**, **E4**, (선택) **E2**(레짐에서 매매 빈도 줄어 비용도 동반 개선)
- **(d) PASS 조건**
  - `worst_mdd >= -0.085` (챔피언 대비 tail 개선을 명시적으로 요구)
  - 동시에 `lockbox_mean >= 1.76` 유지(평균 훼손 제한)

---

### 4) 포트폴리오 제약/사이징으로 운영 리스크(집중·유동성·갭) 낮추기
- **(a) 왜 필요한지**
  - 8~14개는 종목 선택이 조금만 삐끗해도 성과가 요동. 운영 측면(체결/갭/공시)에 취약해 “백테스트는 되는데 실전은 흔들리는” 전형적 구간.
- **(b) 위험/부작용**
  - 제약이 알파를 희석(특히 상위 확신 종목에 못 싣는 문제).
- **(c) 최소 실험(2~3)**
  - **E4**, **E2**, (선택) **E1**(유동성/티커변경/상폐 처리 누락이 운영리스크로 직결)
- **(d) PASS 조건**
  - 최대비중/쏠림/유동성 제약 위반 0
  - `lockbox_min` 또는 `worst_mdd` 중 하나는 명확히 개선(둘 다 악화 시 즉시 폐기)

---

### 5) 과최적화/불안정성(파라미터 민감·fold 편식) 게이트 강화
- **(a) 왜 필요한지**
  - 챔피언이 강할수록, 신규 후보는 “튜닝에서는 좋아 보이나 lockbox에서 무너지는” 과최적화가 빈번. **선정 게이트를 강하게 만들어 탐색 비용을 줄이는 게** 48시간 루프 효율이 좋음.
- **(b) 위험/부작용**
  - 탐색 공간이 줄어 “새로운 알파 발견” 속도가 느려질 수 있음.
- **(c) 최소 실험(2~3)**
  - **E5**, **E1**, (선택) **E2**(비용 모델이 들어가면 과최적화 양상이 달라져 재차 안정성 필요)
- **(d) PASS 조건**
  - 민감도 스윕에서 lockbox_mean 급락 케이스 제거(로컬 견고성 통과)
  - `tuning_mean - lockbox_mean <= 0.15`
  - single-fold hero 패턴(특정 fold만 과대) 탐지 시 FAIL

## “성능이 안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래는 **원인→진단 순서**로 바로 자동 리포트에 넣기 좋은 체크리스트.

### A) 트리거(신호가 실제로 예측력이 있는가?)
- **진단**
  - 신호 분포가 시간에 따라 드리프트(평균/분산/상위 quantile 빈도 변화)하는지.
  - 상위 신호 종목의 다음기간 수익 분포가 “비대칭적으로” 사라졌는지(알파 소멸).
- **조치**
  - 신호를 1) 단순화(E5) 2) as-of 재검증(E1) 3) 레짐조건부(E3)로 분해해 재평가.

### B) 적용(신호가 포트로 전환될 때 깨지는가?)
- **진단**
  - 같은 신호라도 포트 구성 방식(동일가중 vs vol타깃 vs 제약)에서 성과가 크게 갈리는지.
  - 리밸런싱 타이밍(월/주/일) 변경에 민감한지(민감하면 과최적화/비용 이슈).
- **조치**
  - PC를 바꿔도 신호가 유지되는지(E4), turnover 컷이 성과를 오히려 올리는지(E2) 확인.

### C) 노출(원치 않는 팩터/섹터/단일종목 베팅이 알파로 착각되는가?)
- **진단**
  - 성과가 사실상 “대형 성장/모멘텀/저변동” 같은 공통 요인에 의해 설명되는지(팩터 노출 회귀).
  - 1~2개 종목이 전체 성과 대부분을 설명하는지(기여도 상위 종목 비중).
- **조치**
  - 쏠림 제약 + 기여도 상한(E4), 레짐 오버레이(E3)로 tail 제거 후 잔여 알파 확인.

### D) 비용(백테스트 수익이 체결 현실에서 사라지는가?)
- **진단**
  - gross는 유지되는데 net에서만 붕괴하는지(비용 민감).
  - ADV 낮은 종목/갭 큰 종목에 성과가 집중되는지(운영 불가 알파).
- **조치**
  - 비용모델 강화 + turnover 컷(E2), 유동성 제약(E4).

### E) 레짐(특정 구간에서만 먹히는가?)
- **진단**
  - 변동성 급등/금리 쇼크/리스크오프에서만 손실이 집중되는지(조건부 성과표).
- **조치**
  - ETF/VIX 관측지표 기반 익스포저 게이트(E3)로 최악구간을 먼저 절단.

## 48시간 루프 실행 순서(명령형)
1) **E1→E2→E3→E4→E5 순으로 최소 변경 단위 커밋**(각 실험별 기능 플래그로 on/off 가능하게 유지).  
2) 각 실험은 “후보 1개만” 생성해 자동 루프에 태움(동시에 여러 갈래 금지).  
3) 매 실험 결과에서 다음 4개만 대시보드 고정 출력: `lockbox_mean / lockbox_min / worst_mdd / tuning-lockbox gap`.  
4) PASS면 champion 교체 후보로 승격, FAIL이면 즉시 롤백하고 다음 실험으로 이동.  
5) 마지막에 기존 커맨드 3줄 그대로 실행해 best-select + next_fix 리포트 생성.

```bash
python3 experiment_system/tools/aub_autopilot.py --registry experiment_system/config/module_registry.yaml --run --select-best
python3 experiment_system/tools/system_autopilot.py --spec experiment_system/config/system_candidates.yaml --run
```
