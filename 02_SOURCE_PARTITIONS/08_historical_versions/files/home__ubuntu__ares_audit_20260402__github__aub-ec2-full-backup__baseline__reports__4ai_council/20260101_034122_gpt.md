## 0) 24~48h 실행 순서(명령형 체크리스트)

1) **비용/유동성/체결 모델이 “실거래 보수적”인지 먼저 고정**
- 슬리피지/수수료/스프레드/임팩트/거래단위/프리마켓 금지 등 강제
- 유동성 필터(ADV, 가격, 스프레드 proxy)로 **거래 가능 우주**를 명시

2) **누수/서바이버십/피처 타이밍 “게이트”를 테스트로 막기**
- 모든 피처에 “as-of timestamp” 강제(시점정렬 실패 시 실험 중단)
- delisted 포함 여부/기업행동(스플릿/배당) 정합성 확인

3) **노출(리스크) 오버레이로 MDD/테일 리스크부터 안정화**
- 8~14개 종목, 종목/섹터 상한, 변동성 타겟, 턴오버 상한

4) **레짐(시장 국면) 필터는 ETF를 “관측 지표”로만 사용**
- QQQ/XLV/IEF(TLT)/HYG/VIX 등으로 risk-on/off 또는 Tech↔Healthcare 비중만 조절(매매는 개별주만)

5) **성능 정체 시 원인분해 리포트를 자동 생성**
- “트리거→적용→노출→비용→레짐” 단계별로 어디서 죽는지 수치로 쪼개기

## 1) 우선순위 TOP5 제안(요약)

1. **(비용+유동성) 거래 현실성 패치**: 성과 과대평가/운영 리스크 즉시 제거  
2. **(누수+서바이버십) 데이터 타이밍/우주 고정 게이트**: “진짜 알파”만 남김  
3. **(노출) 포지션/턴오버 리스크 오버레이**: MDD/테일 억제, 락박스 안정화  
4. **(레짐) ETF-지표 기반 리스크 온/오프 스위치**: 불리한 국면에서 손실 구간 축소  
5. **(정체 분해) 원인분해/어트리뷰션 자동 리포트**: 성능이 안 움직이는 이유를 계량적으로 고정

이하 각 항목은 **(a) 필요성 (b) 위험/부작용 (c) 최소 실험 2~3개(=동일 patch 내 변형 A/B/C) (d) PASS 조건**을 포함하고, **48h 루프 형태: (1) 실험 정의 (2) 게이트 (3) 기대 관측치**로 제시합니다.

## 2) TOP5 상세 (각각 1개의 patch/실험, 내부 변형 2~3개)

### 1) 비용+유동성 “거래 현실성” 패치 (운영/과최적화 방지 1순위)
**(a) 왜 필요한지**
- 현재 챔피언/후보의 수치가 좋아도, **비용(슬리피지/스프레드/임팩트) 미반영**이면 락박스가 좋아 보이는 “허상”이 생깁니다.
- Tech/Healthcare라도 이벤트/실적 시즌에는 체결비용이 급증 → **MDD/샤프 붕괴**로 직결.

**(b) 위험/부작용**
- 단기적으로 성과(특히 tuning_mean)가 떨어질 수 있음(정상).
- 너무 보수적으로 잡으면 트레이드가 거의 없어져 “알파 탐지”가 둔화.

**(c) 최소 실험(동일 patch 내 A/B/C 변형)**
- **A. 비용 모델 ON(보수적)**: 고정 bps + 변동성 연동 슬리피지(최소값 존재)
- **B. 유동성 게이트 강화**: ADV 하한, 가격 하한, 스프레드 proxy 상한(예: 일중 변동/거래대금 기반)
- **C. 턴오버 캡**: 일/주 단위 turnover 상한 도입(초과 시 리밸런싱 스킵 또는 축소)

**(d) PASS 조건**
- 락박스(lockbox)에서  
  - **lockbox_mean이 1~3% 이내만 하락**하거나, 하락하더라도  
  - **worst_mdd가 개선(예: -0.1118 → -0.105 이상)**,  
  - 그리고 **거래당 비용/슬리피지 추정치가 비정상적으로 낮지 않음**(0에 수렴하면 FAIL)
- “비용 ON vs OFF” 격차가 과도(예: 성과 20%+ 급락)하면 → 기존 성과가 비용 민감/과최적화 신호로 간주(FAIL 처리 후 2~4번 패치로 구조 개선)

**48h 루프**
- (1) 실험 정의: `execution_cost_model_v1 + liquidity_gate_v1 + turnover_cap_v1`  
- (2) 게이트: 비용/슬리피지 파라미터가 0/비현실 값이면 즉시 중단, 거래수 너무 적으면(예: 분기당 거래 < 특정 하한) “비교불가”로 중단  
- (3) 기대 관측치: 샤프 소폭 하락 또는 유지, MDD/테일/턴오버 지표 개선

---

### 2) 누수/서바이버십/타이밍 “데이터 정합성 게이트” 패치
**(a) 왜 필요한지**
- **lookahead(미래 데이터 참조)**, **리밸런싱 시점과 피처 as-of 불일치**, **서바이버십(상장폐지 미포함)**은 tuning/lockbox를 동시에 “그럴듯하게” 올립니다.
- 성능이 잘 안 움직이는 상태에서도, 누수 점검을 안 하면 “개선이 안 되는 게 아니라 이미 허상일 수” 있습니다.

**(b) 위험/부작용**
- 누수를 막으면 성과가 떨어질 수 있음(정상).
- 데이터 파이프라인이 엄격해져 결측/지연이 늘고, 거래 기회가 줄 수 있음.

**(c) 최소 실험(A/B/C)**
- **A. 피처 시점 강제**: 모든 피처에 `feature_timestamp <= decision_time - lag` 강제(예: 1D lag), 위반 시 해당 피처/종목 제외
- **B. 우주 고정(월/분기 단위)**: 리밸런스 구간 내 우주가 뒤에서 바뀌지 않도록 “선정 시점” 고정
- **C. delisted/기업행동 검증 테스트**: (가능하면) delisted 포함 백테스트/리턴 재구성 검증을 “테스트로” 추가(불가하면 최소한 delisted 발생 시 처리 로직 강제)

**(d) PASS 조건**
- “게이트 ON” 후에도 락박스가  
  - **lockbox_min이 의미 있게 무너지지 않을 것**(현재 1.3469 수준을 크게 하회하면 FAIL)  
  - 또는 성과 하락이 있더라도 **성과 하락 원인이 특정 피처/우주 처리에서 발생**함이 로그로 분해되어 다음 수정으로 연결 가능하면 PASS(=디버그 가치)
- 피처 시점 위반/우주 변동이 한 건이라도 발견되면 → 해당 경로는 즉시 FAIL(수정 우선순위 최상단)

**48h 루프**
- (1) 실험 정의: `data_integrity_gate_v1`(타임스탬프/우주고정/delisted 처리 테스트)  
- (2) 게이트: 위반 발견 즉시 실험 중단 + 리포트 생성  
- (3) 기대 관측치: 성과가 “더 진짜”가 되고, 변동성/테일의 과대평가가 줄어듦

### 3) 노출(리스크) 오버레이 패치: 8~14종목 제약 하 안정화
**(a) 왜 필요한지**
- 8~14종목 집중 포트는 **단일종목/서브섹터/실적 이벤트**에 MDD가 쉽게 악화됩니다.
- 현재 worst_mdd(-0.1118)를 더 낮추려면 “시그널 강화”보다 **노출 제어**가 효율적일 때가 많습니다.

**(b) 위험/부작용**
- 알파가 강한 구간에서 수익 상단이 깎일 수 있음.
- 제약이 너무 강하면 “평균 수익은 비슷한데 거래만 줄어” 개선이 안 보일 수 있음.

**(c) 최소 실험(A/B/C)**
- **A. 변동성 타겟팅**: 포트폴리오 ex-ante vol 목표(예: 연 10~12%)로 레버/현금 비중 조정(단, 매매는 주식만/현금은 무위험으로 가정)
- **B. 단일 종목 상한/동일 서브섹터 상한**: 최대 비중(예: 12~15%), Tech/Healthcare 내부도 과쏠림 제한
- **C. 이벤트 리스크 컷(실적/가이던스)**: 실적 전후 N일은 신규 진입 축소/금지(룰 기반, 데이터 누수 주의: “실적일 캘린더는 사전에 알려진 일정만” 사용)

**(d) PASS 조건**
- 락박스에서  
  - **worst_mdd 개선**(최소 0.5~1.0%p라도 개선이면 유의미)  
  - **lockbox_mean 유지 또는 소폭 개선**,  
  - **턴오버 감소 또는 동일**(비용 패치와 궁합)
- 종목 수가 8 미만 또는 14 초과가 빈번하면 FAIL(운영 제약 위반)

**48h 루프**
- (1) 실험 정의: `risk_overlay_v1(vol_target + caps + earnings_buffer)`  
- (2) 게이트: 종목수/상한 위반 시 즉시 FAIL, 변동성 추정치 결측 시 안전모드(리밸 스킵)  
- (3) 기대 관측치: 수익률은 유사, MDD/테일/일간 손실 꼬리 개선

### 4) 레짐 필터 패치(ETF는 “관측 지표”만): 리스크 온/오프 & Tech↔Healthcare 틸트
**(a) 왜 필요한지**
- 성능 정체는 종종 “알파가 없어서”가 아니라 **레짐 미스매치**(risk-off에서 성장주/바이오 베타 노출) 때문입니다.
- ETF는 매매하지 않고도, **시장 스트레스/금리/크레딧**을 저비용으로 관측 가능합니다.

**(b) 위험/부작용**
- 레짐 필터가 과민하면 whipsaw(잦은 온오프)로 오히려 비용 증가.
- 룰이 복잡해지면 과최적화 위험 증가 → 반드시 단순/사전정의.

**(c) 최소 실험(A/B/C)**
- **A. Risk-off 스위치(단순)**: (예) `HYG/IEF` 모멘텀 음수 또는 `VIX` 급등 시 → 포트 위험 50%로 축소(현금 비중 증가)
- **B. Tech vs Healthcare 틸트**: QQQ 상대강도↑면 Tech 비중 상한 완화, XLV 상대강도↑면 Healthcare 상한 완화(종목 선택은 기존 로직 유지)
- **C. 쿨다운(안티-위프쏘)**: 레짐 전환 후 최소 N일 유지(예: 5~10영업일)

**(d) PASS 조건**
- 락박스에서  
  - **worst_mdd 추가 개선** 또는  
  - **lockbox_min 개선**(최저 구간 방어가 목적)  
- 레짐 전환 횟수가 과도(예: 월 4회 이상 상시 발생)하면 FAIL(운영/비용 리스크)

**48h 루프**
- (1) 실험 정의: `regime_filter_v1(ETF indicators only) + cooldown`  
- (2) 게이트: ETF 데이터 결측 시 레짐 필터 OFF(보수적으로 위험 축소하지 말고 “현상 유지” 또는 사전정의 안전모드)  
- (3) 기대 관측치: 평균은 유사, 최저/테일/드로다운 구간 개선

### 5) 성능 정체 원인분해(트리거/적용/노출/비용/레짐) 자동 리포트 패치
**(a) 왜 필요한지**
- 지금처럼 챔피언과 후보가 같게 나오면(“성능이 안 움직임”), 원인은 대개:
  - 새로운 변경이 **실제로 적용이 안 됨**(플래그/설정 미반영),
  - 게이트/제약으로 **행동이 동일해짐**,
  - 비용/리스크 오버레이가 **전부 상쇄**,
  - 레짐에서 **노출이 잘못 고정**,
  - 또는 탐색 공간이 “이미 포화”.
- 이걸 자동으로 쪼개지 않으면, 48h 루프가 “같은 결과를 반복”합니다.

**(b) 위험/부작용**
- 리포트/로그가 늘어 운영 복잡도 증가.
- 지표를 잘못 선택하면 “잘못된 최적화 목표”로 끌려갈 수 있음.

**(c) 최소 실험(A/B/C)**
- **A. 적용 검증(Activation test)**: 실험별로 “변경 전/후” 핵심 메트릭(턴오버, 평균 보유기간, 비용, 종목수, 섹터비중)이 변했는지 강제 체크(안 변하면 FAIL)
- **B. 단계별 PnL 어트리뷰션**:  
  - (i) 시그널만(이상적 체결)  
  - (ii) 리스크 오버레이 적용 후  
  - (iii) 비용 적용 후  
  - (iv) 레짐 필터 적용 후  
  단계별로 샤프/MDD 변화량을 표로 저장
- **C. 레짐/노출 진단 대시**: 포트 베타(대략적), Tech/Healthcare 비중, 상위 3종목 기여도, 이벤트(실적) 노출을 기간별로 출력

**(d) PASS 조건**
- “정체 원인”이 최소 1개 이상 명확히 식별되어 다음 사이클의 수정이 **단일 타겟으로 수렴**하면 PASS  
- 변경이 적용되지 않았는데 성과 비교만 반복하는 경우는 즉시 FAIL(루프 낭비)

**48h 루프**
- (1) 실험 정의: `diagnostics_report_v1(activation + attribution ladder + exposure panel)`  
- (2) 게이트: 변경 미적용(activation fail) 시 백테스트 결과 폐기  
- (3) 기대 관측치: “왜 안 움직이는지”가 수치로 고정되고, 다음 패치가 좁혀짐

## 3) 성능이 안 움직일 때 “원인 분해” 아이디어 (트리거/적용/노출/비용/레짐)

아래를 **트리 형태로 로그/리포트에 강제 출력**하도록 패치 5번에서 자동화하세요.

### A. Trigger(신호가 실제로 변했나?)
- 신호 분포(스코어 평균/분산, 상위10% 스코어) 기간별 비교
- 상위 랭크 종목의 **교집합 비율**(전일/전주 대비)  
  - 교집합이 과도하게 높으면 → 신호가 “고정” 또는 우주가 너무 좁음
- 실적 시즌/금리 급변 구간에서 신호 품질(다음날/다음주 방향성) 악화 여부

### B. Apply(전략이 실제로 실행되었나?)
- 백테스트에서 **주문 발생 수**, 리밸런싱 스킵 횟수(게이트/결측 때문에)
- 변경한 파라미터가 런에서 로드됐는지(설정 해시/체크섬)
- 포지션 수(8~14) 준수 여부, 리밸 주기/시간대 준수 여부

### C. Exposure(노출이 수익을 잡아먹나?)
- 포트 베타(대략), 섹터/서브섹터 쏠림, 단일종목 기여도 상위 편중
- “이익 대부분이 1~2종목에서 발생”이면 → 서바이버/특정 이벤트 의존 가능성
- 변동성 타겟/상한 때문에 알파 구간에서 사이즈가 줄어드는지

### D. Cost(비용이 알파를 상쇄하나?)
- 총비용 = 수수료 + 슬리피지 + 스프레드 proxy의 기간별 기여
- 턴오버와 성과의 상관(턴오버↑ 구간에서 성과↓면 비용 민감)
- 체결 가정(OHLC 어디?)이 성과를 좌우하면 → 실행가능성 리스크

### E. Regime(국면이 틀렸나?)
- Risk-on/off 지표(예: HYG/IEF 모멘텀, VIX, 금리) 별로 성과를 **조건부 분해**
- Tech 우위 레짐 vs Healthcare 방어 레짐에서 각각 성과/손실이 어디서 났는지
- 레짐 전환의 지연/과민 여부(쿨다운 없으면 위프쏘)
