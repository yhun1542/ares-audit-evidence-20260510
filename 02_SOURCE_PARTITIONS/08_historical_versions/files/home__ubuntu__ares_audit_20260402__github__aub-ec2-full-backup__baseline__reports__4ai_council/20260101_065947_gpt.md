## TOP5 우선순위 (24~48h) — **명령형 체크리스트**  
(누수/과최적화/서바이버십/비용/운영리스크를 먼저 박살내고, 그 다음 성능을 움직이는 순서)

---

# 1) **데이터 누수(lookahead/as-of) + 리밸런싱 타이밍 정합성**을 “자동 차단”으로 고정
### (a) 왜 필요한지
- 지금 챔피언/후보 성능이 **lockbox는 좋고 tuning이 흔들리는 형태**라서, 작은 누수/타이밍 미스매치가 있으면 후보군 탐색이 전부 “가짜 알파”로 오염됨.
- 특히 **일봉 종가 기반 신호**에서 `t`에 생성한 신호를 `t` 체결로 처리하는 순간, 누수는 성능을 “안 움직이거나” “과도하게 좋아 보이게” 만들고 이후 잠김.

### (b) 위험/부작용
- 누수 차단 후 성능이 **단기적으로 하락**할 수 있음(정상).
- 체결 타이밍을 보수적으로 바꾸면 회전율/체결 빈도가 줄어 **수익 기회 감소** 가능.

### (c) 최소 실험(2~3 arms, **1개 패치 안에서 A/B/C 동시 실행**)  
**실험 정의 (Patch #1: `execution_time_sanity`)**
- Arm A: **신호는 D-1 종가 기준으로 생성 → D 시가 체결**(완전 보수)
- Arm B: 신호 D 종가 생성 → **D+1 시가 체결**(가장 안전)
- Arm C: 신호 D 종가 생성 → **D 종가 체결 금지(차단)** + 백테스트에서 강제 에러/경고

**게이트(자동 실패 조건)**
- (필수) 어떤 Arm에서도 `signal_timestamp >= fill_timestamp` 위반 0건
- (필수) “가격/펀더멘털/리비전”류 피처에 대해 **as-of join unit-test** 통과(미래행 참조 0)
- (권장) 위반 감지 시 해당 실험 전체를 **FAIL로 강제 종료**

**기대 관측치**
- 누수가 있었으면: Arm A/B에서 성능이 수렴하며, 기존 대비 과대 성과가 줄어듦
- 누수가 없으면: Arm A/B/C 결과가 일관되고 MDD/샤프 변화가 제한적

### (d) PASS 조건
- Arm A 또는 B가 **lockbox_mean이 챔피언 -0.03 이내** 유지 AND worst_mdd가 **-0.115 이하로 악화되지 않음**
- “타임스탬프 위반 0 + as-of 테스트 0”을 **항상 만족**(성능보다 우선)

---

# 2) **거래비용/슬리피지/유동성(ADV) 미반영 리스크를 선제 반영** (성과 “정지”의 1순위 원인)
### (a) 왜 필요한지
- 비용을 과소평가하면: 후보들이 “회전율 기반 가짜 우수”로 잠기고, lockbox에서 더 이상 개선이 안 됨.
- Tech/Healthcare 개별주(8~14종)에서는 **스프레드/충격비용 + 급락 갭**이 체감 성과를 크게 좌우.

### (b) 위험/부작용
- 비용모형이 과도하면 **과도한 보수화로 수익 기회 소멸**.
- ADV 필터가 강하면 종목 풀이 좁아져 **서바이버십/편향**이 생길 수 있음(그래서 “관측+완만한 게이트”로 시작).

### (c) 최소 실험(2~3 arms, **1개 패치**)  
**실험 정의 (Patch #2: `cost_liquidity_guardrail`)**
- Arm A(기본): 고정 bps(예: 5~15bps) + 스프레드 1/2 반영
- Arm B(충격): `slippage = k * (order_notional / ADV)^α` 형태(단순 충격비용)
- Arm C(유동성 게이트): **주문금액/ADV < x%** 위반 시 포지션 스킵(또는 비중 캡)

**게이트**
- (필수) 평균 회전율(turnover)이 특정 상한(예: 주간 150% 등) 초과 시 FAIL
- (필수) 비용 반영 후도 lockbox_mean이 **챔피언 -0.05 이내** 유지 못하면 FAIL
- (필수) “거래 정지/결측/가격 급갭” 이벤트에서 체결/포지션이 NaN 없이 끝까지 재현

**기대 관측치**
- 비용 반영 후 **성과가 조금 내려가더라도** 후보 간 순위가 더 안정화
- 회전율이 높던 후보는 급격히 약화 → “진짜 알파” 후보만 남음

### (d) PASS 조건
- Arm B 또는 C에서 **lockbox_mean ≥ 챔피언 -0.03** AND worst_mdd **악화 ≤ 0.01p**
- 비용/유동성 경고가 “항상 로그로 남고”, 백테스트 재현성 100%

# 3) **서바이버십/유니버스 고정(US Tech+Healthcare 8~14개) + 룩백 가능한 ‘상장폐지/인수’ 처리**
### (a) 왜 필요한지
- “성과가 안 움직이는” 상황에서 가장 흔한 구조적 원인:  
  유니버스가 현재 기준으로 고정되면 과거에 존재하지 않던 승자만 남아 **모델이 더 이상 개선될 여지가 사라짐(착시 안정화)**.
- Tech/Healthcare는 M&A/상장폐지/티커변경이 빈번.

### (b) 위험/부작용
- 진짜로 survivorship가 있었으면 성능이 **의미 있게 하락**할 수 있음(정상).
- 데이터 소스/매핑 품질이 낮으면 결측이 늘어 **운영 리스크** 증가.

### (c) 최소 실험(2~3 arms, **1개 패치**)  
**실험 정의 (Patch #3: `universe_asof_survivorship`)**
- Arm A: 현재 방식 유지(대조군) + “티커/상장상태” 로그만 추가
- Arm B: as-of 유니버스(해당 시점 상장/거래 가능 종목만)로 구성
- Arm C: “인수/상폐” 이벤트에서 **현금전환 규칙**(delist → cash) 강제

**게이트**
- (필수) 각 날짜별 유니버스 크기/섹터 비중 변동이 로그로 추적 가능
- (필수) 상폐 발생 시 포지션/PNL 처리 규칙이 단일(예외 없이) 적용
- (권장) 유니버스가 과도 축소되면(예: < 30종) FAIL로 처리(데이터 품질 경고)

**기대 관측치**
- survivorship가 있으면 Arm B/C에서 성능이 하락하지만 **일관성/현실성** 상승
- 없으면 Arm A/B/C 결과가 유사

### (d) PASS 조건
- Arm B 또는 C가 **worst_mdd 악화 없이(≤0.01p)** lockbox_mean **챔피언 -0.04 이내**
- 상폐/티커변경 케이스가 “런타임 에러 0, 현금전환 규칙 100% 적용”

# 4) **노출(Exposure) 통제: 8~14개 집중 포트에서의 베타/섹터/단일종목 리스크 자동 제한**
### (a) 왜 필요한지
- Tech+Healthcare는 레짐에 따라 동반 급락이 심함.  
  알파가 있어도 **베타/변동성/상관**을 방치하면 성과가 “MDD 벽”에서 멈춤.
- “성능이 안 움직임”은 종종 신호 문제가 아니라 **리스크 예산 배분 문제**.

### (b) 위험/부작용
- 과한 제약은 수익을 깎고, “비슷비슷한 포트”만 만들어 탐색이 죽음.
- 노출 제약이 잘못되면 역으로 **리밸런싱 증가(비용↑)**.

### (c) 최소 실험(2~3 arms, **1개 패치**)  
**실험 정의 (Patch #4: `exposure_budget_controller`)**
- Arm A: 단일종목 최대비중(예: 12~15%) + 8~14개 강제
- Arm B: 포트폴리오 베타(대상: QQQ/XLV는 **지표용**)를 목표 범위로 클리핑
- Arm C: 섹터 바스켓(Tech/Healthcare 내부) 상관 급등 시 **총 익스포저 스케일다운**(간단한 vol targeting)

**게이트**
- (필수) 종목 수 8~14 유지(미달/초과 시 FAIL)
- (필수) 단일종목 비중 위반 0
- (권장) turnover가 비용 패치(#2) 게이트를 동시에 통과

**기대 관측치**
- MDD tail이 줄거나, worst_mdd가 개선/유지
- 평균 수익률이 약간 줄어도 샤프/소르티노가 개선

### (d) PASS 조건
- Arm B 또는 C에서 **worst_mdd ≤ 챔피언 worst_mdd + 0.005p** AND lockbox_mean **챔피언 -0.02 이내**
- 회전율/비용 게이트 동시 통과

# 5) **과최적화(튜닝) 억제: 실험 탐색을 “단순화 + 불확실성 페널티”로 재설계**
### (a) 왜 필요한지
- tuning_mean/min이 흔들리고 후보가 챔피언을 못 넘는 패턴은  
  대개 “탐색공간이 너무 크거나(케이스 폭발), 스코어가 운에 민감”해서 발생.
- 지금은 성능을 끌어올리기보다, **일관성 있는 개선을 선택할 수 있게** 실험 시스템을 고쳐야 함.

### (b) 위험/부작용
- 탐색이 보수적으로 변해 “대박 후보”를 늦게 찾을 수 있음.
- 페널티를 과하게 주면 혁신이 멈춤.

### (c) 최소 실험(2~3 arms, **1개 패치**)  
**실험 정의 (Patch #5: `anti_overfit_scoring`)**
- Arm A: 기존 스코어(대조)
- Arm B: `score = lockbox_mean - λ * (lockbox_std or fold_dispersion)` (불확실성 페널티)
- Arm C: “복잡도 페널티” (피처 수/규칙 수/회전율 기반) 추가

**게이트**
- (필수) 선택된 best가 **lockbox_min**을 일정 수준 이상 유지(예: 챔피언 lockbox_min -0.05 이내)
- (필수) fold14_mdd 악화 시 자동 탈락
- (권장) “선택 결과”가 2회 연속 재실행에도 동일(재현성)하면 가점

**기대 관측치**
- 후보 점수는 낮아져도 “교체 빈도”가 줄고, 다음 세대 후보가 **안정적으로 누적 개선** 가능
- lockbox_min이 올라가면 운영 친화성 증가

### (d) PASS 조건
- Arm B 또는 C가 “선정된 best” 기준으로 **lockbox_min 개선 또는 유지** + worst_mdd 비악화
- 48시간 루프에서 **교체/롤백 횟수 감소**(운영 안정성 지표)

# 성능이 안 움직일 때 “원인 분해” 명령형 아이디어 (Trigger / Apply / Exposure / Cost / Regime)

## A) Trigger(신호 발생) 점검
- **신호 발생 빈도(일/주/월)**와 “상위 스코어 종목의 교체율”을 분리 로깅하라  
- 스코어 분포가 납작해졌는지(상위-하위 스프레드 축소) 확인하라  
- (지표용 ETF) QQQ, XLV, IHI, SOXX의 추세/변동과 **신호 빈도의 상관**을 기록하라

## B) Apply(적용/체결) 점검
- “신호일 vs 체결일”의 오프셋을 강제 표준화하고 위반 시 즉시 FAIL 처리하라  
- 부분체결/결측/거래정지 시 **포지션 업데이트 규칙**을 단일화하라(예외 금지)

## C) Exposure(노출) 점검
- 포트의 **베타(대상: QQQ, XLV), 순/총 익스포저, 상관(내부)**을 매 리밸런싱마다 저장하라  
- 성능 정체 시, 알파가 아니라 **베타/변동성에 PnL이 잠식**되는지(기여도 분해) 확인하라  
- 8~14개에서 단일종목/서브섹터 편중이 발생하는지(예: 반도체/대형 플랫폼) 경고하라

## D) Cost(비용) 점검
- 비용 “전/후” 성과를 항상 함께 출력하라:  
  - gross return, net return, turnover, ADV 위반률  
- 정체 구간에서 net만 나빠지면: **회전율/슬리피지**가 원인이다 → #2 강화하라

## E) Regime(레짐) 점검
- 레짐을 단 2~3개로만 쪼개라(케이스 폭발 금지):  
  1) QQQ 추세상/하, 2) 변동성 상/하(예: VIX/QQQ realized vol)  
- 각 레짐에서 **승률/기대값/MDD**를 따로 찍고, 특정 레짐에서만 망가지면  
  → #4의 익스포저 스케일링(또는 리스크 오프)만 제한적으로 켜라

---

## 마지막으로: 운영 리스크(자동 루프 안정성) 우선 체크
- 모든 Patch에 대해 **“FAIL-fast + 로그 표준”**을 강제하라(침묵 실패 금지)
- 결과 산출물에 다음을 고정 포함하라:  
  `signal_time`, `fill_time`, `turnover`, `net_vs_gross`, `ADV_violation`, `positions_count(8~14)`, `largest_weight`, `beta_to_QQQ/XLV`

위 5개 패치는 “성능을 올리는 트릭”보다, **성능이 더 이상 안 움직이는 구조적 이유(누수/비용/유니버스/노출/과최적화)**를 먼저 제거하도록 설계되어 있고, 48시간 자동 루프에서 바로 PASS/FAIL이 갈리게 구성했다.
