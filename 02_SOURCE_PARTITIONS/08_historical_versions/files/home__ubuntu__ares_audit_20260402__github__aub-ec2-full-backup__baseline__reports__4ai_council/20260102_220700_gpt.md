## 24~48h 우선순위 TOP5 (명령형 체크리스트)
1) **누수(Leakage)/시간정렬/체결시점**을 먼저 “증명”하라 (성능 상승보다 우선)  
2) **비용(수수료·스프레드·슬리피지·임팩트) 미반영**을 강제 반영하라 (과최적화 방지)  
3) **서바이버십/유니버스 구성(Tech+Healthcare 8~14) 고정 규칙**을 점검·강제하라  
4) **운영 리스크(리밸런싱, 주문 가능성, 포지션 한도) + 리스크 오버레이**를 레이어로 추가하라  
5) **레짐(Tech↔Healthcare) 전환/리스크오프 게이트**를 “ETF 관측지표만”으로 넣어 MDD를 깎아라

# 실행 가능한 Patch/실험 5개 (각 48시간 자동 루프 형태)
아래 5개만 돌려서 케이스 폭발을 막는다. 각 실험은 **(1) 실험 정의 → (2) 게이트 → (3) 기대 관측치**로 고정한다.  
(모두 **미국주식 only**, 매매 종목은 **Tech+Healthcare 8~14개**, **ETF는 관측지표로만** 사용)

## EXP-1) `pt_execution_guard_v1` : 누수/체결시점/라벨정렬 하드가드
### (a) 왜 필요한지
- 현재 Champion이 lockbox 성과가 좋은데(평균 4.01) **실전 배치에서 망가지는 1순위 원인**이 “같은 봉 정보로 의사결정/체결” 류의 **암묵적 누수**다.
- 누수는 튜닝에서만 좋아지고, lockbox/실거래에서 갑자기 붕괴하는 패턴을 만든다.

### (b) 위험/부작용
- 단기적으로 성능 하락(정상).  
- 성능 하락 폭이 크면 기존 성과가 누수 의존이었을 가능성 → “불편하지만 좋은 신호”다.

### (c) 최소 실험 2~3개 (한 번에 스윕으로 묶어서 1팩으로 실행)
- **Variant A**: 시그널은 `D-1 close`까지, 체결은 `D open` (기본)  
- **Variant B**: 시그널은 `D-2 close`까지, 체결은 `D open` (1일 추가 지연)  
- **Variant C**: “리밸런스 빈도”만 고정(예: 주 1회) + 위 A 적용 (리밸런스-봉정렬 문제 분리)

### (d) PASS 조건 (Gate)
- **Leakage sanity**:  
  - 어떤 feature도 “체결가격 이후 정보”를 참조하지 않음을 로그로 증명(피처 타임스탬프 < 체결 타임스탬프).  
- **성능 게이트(보수적)**:  
  - `worst_mdd >= -0.085` 유지 (Champion worst_mdd -0.081 대비 악화 금지)  
  - lockbox_mean이 Champion 대비 **-20% 이내**면 통과(누수 제거 실험은 하락 허용)  
- **운영 게이트**: 리밸런스/체결 룰이 “항상 다음 오픈”으로 일관됨(예외 없음)

### (3) 기대 관측치
- Variant A/B 간 성과 갭이 크면: 기존 모델이 “즉시성/미세 누수”에 민감.  
- 성과가 비슷하면: 누수 위험 낮고 다음(비용/유니버스)로 넘어갈 근거 확보.

## EXP-2) `cost_impact_model_v2` : 비용·슬리피지·스프레드 강제 반영
### (a) 왜 필요한지
- 8~14개 집중 포트폴리오는 **턴오버가 곧 성과**를 좌우한다.  
- 비용 미반영은 과최적화를 부르고, lockbox는 좋아도 실전에서 손익이 “0 근처로 수렴”한다.

### (b) 위험/부작용
- 전략이 “비용을 못 견디는 구조”면 성과가 크게 꺾인다(정상 진단).  
- 비용 모델이 과도하면 유망 전략을 과소평가할 위험 → 스윕으로 안정 영역 찾기.

### (c) 최소 실험 2~3개 (스윕)
- **Variant A (Lite)**: 고정 왕복비용 5bp + 주당 수수료(또는 최소수수료)  
- **Variant B (Base)**: 스프레드(예: 10~20bp 상한) + 거래대금 기반 슬리피지(ADV 대비)  
- **Variant C (Harsh)**: Variant B + “오픈 체결 슬리피지” 추가(갭 리스크 반영)

### (d) PASS 조건 (Gate)
- **비용 내구성**: Variant B에서 lockbox_mean이 Champion 대비 **-25% 이내**  
- **턴오버 제약**: 평균 월간 회전율이 기준치 이하(예: 200%/month 이하 같은 내부 기준)로 떨어지거나, 성과 대비 턴오버가 개선될 것  
- **MDD 유지**: `worst_mdd >= -0.085`

### (3) 기대 관측치
- 성과가 비용에 과민하면: 알파가 “미세 리밸런스/노이즈”에서 나왔을 확률↑ → 트리거/리밸런스 재설계로 이동.

## EXP-3) `universe_survivorship_pit_v1` : 서바이버십/유니버스 고정 (Tech+Healthcare 8~14)
### (a) 왜 필요한지
- “현재 생존 종목만”으로 과거 백테스트를 하면 **서바이버십 편향**으로 성과가 부풀려진다.  
- Tech/Healthcare는 상장폐지/인수합병 이벤트가 잦아 편향이 커질 수 있다.

### (b) 위험/부작용
- 데이터 소스가 PIT(당시 시점) 지원이 약하면 구현 난이도↑.  
- 유니버스 규칙이 바뀌면 과거 성과가 흔들릴 수 있다(정상).

### (c) 최소 실험 2~3개 (스윕)
- **Variant A (Rebalance-time top cap)**: 리밸런스 시점에만 시총/유동성 필터로 Tech+Healthcare 상위 N에서 선택 (N은 충분히 크게, 최종 보유는 8~14)  
- **Variant B (Delist handling)**: delisting/인수합병 시 “마지막 거래가능일 + 합리적 청산가격(또는 delist return)” 처리  
- **Variant C (Freeze list)**: 룩백 구간마다 유니버스 후보군을 “해당 시점 스냅샷”으로 고정(룩어헤드 차단)

### (d) PASS 조건 (Gate)
- **편향 검출**: A/B/C 간 성과 차이가 “비정상적으로” 크면(예: lockbox_mean 급락 + 특정 기간만 붕괴) → 기존 파이프라인 편향 가능성으로 FAIL 처리 후 원인 로그 고정  
- **정상 통과 기준**: Variant B 적용 후에도 `worst_mdd >= -0.09` 유지 + lockbox_mean이 Champion 대비 -30% 이내(편향 제거 목적이라 일부 하락 허용)

### (3) 기대 관측치
- 유니버스 보정 후에도 성능 유지되면: 전략 신뢰도 상승(다음 단계인 리스크/레짐으로 확장 가능).

## EXP-4) `risk_overlay_vol_beta_v1` : 운영 가능 + MDD 억제 오버레이
### (a) 왜 필요한지
- Champion의 worst_mdd가 -8.15%로 나쁘진 않지만, Candidate에서 -11%까지 밀린 전례가 있음 → **리스크 레이어가 성능 변동성을 줄이는 보험**이 된다.
- 8~14개 집중은 개별 종목 이벤트(실적, FDA, 규제)에 취약 → “개별 리스크 한도”가 운영 핵심.

### (b) 위험/부작용
- 과도한 헤지/중립화는 알파를 죽일 수 있음.  
- 리스크 타겟팅이 비용(턴오버) 증가로 이어질 수 있음.

### (c) 최소 실험 2~3개 (스윕)
- **Variant A (Vol targeting)**: 포트폴리오 변동성 타겟(예: 10~12% ann)으로 포지션 스케일  
- **Variant B (Beta clamp)**: SPY 대비 베타를 범위 내로 제한(예: 0.6~1.2), 단 **매매는 현금/주식만**(베타 조정은 포지션 스케일로)  
- **Variant C (Single-name risk cap)**: 종목당 최대 비중(예: 15% 상한) + 갭리스크 큰 이벤트 전후 감산(실적일 캘린더 기반이면 PIT 주의)

### (d) PASS 조건 (Gate)
- **드로우다운 개선**: `worst_mdd`가 Champion 대비 **동일 또는 개선(>-0.0815)**  
- **성과 보존**: lockbox_mean이 Champion 대비 **-15% 이내**  
- **운영 게이트**: 리밸런스/리스크 조정이 “하루에 1회 규칙”으로 닫힘(무한 미세조정 금지)

### (3) 기대 관측치
- MDD가 줄고 성과가 크게 안 깎이면: 이후 레짐 게이트와 결합 가치↑.

## EXP-5) `regime_gate_xlk_xlv_v1` : 레짐(Tech↔Healthcare/리스크오프) 게이트 (ETF는 관측만)
### (a) 왜 필요한지
- Tech와 Healthcare는 **레짐 반응이 다름**(금리/성장/리스크온).  
- 레짐이 안 맞는 시기에 알파가 “안 움직이는” 현상이 빈번 → 게이트로 노출을 줄이는 게 실전형.

### (b) 위험/부작용
- 게이트가 과민하면 매매가 늘고(비용↑) 알파가 줄 수 있음.  
- ETF 지표 자체도 리드/래그가 있어서 잘못 쓰면 역효과.

### (c) 최소 실험 2~3개 (스윕)
- **Variant A (XLK vs XLV 상대강도)**: XLK/XLV 모멘텀(예: 20/60일)로 Tech 바스켓 vs Healthcare 바스켓 비중을 스케일  
- **Variant B (Risk-off filter)**: VIX 대용(예: VIX 지수 or VIX 관련 지표 *관측만*)이 임계 이상이면 전체 익스포저 50% 감산  
- **Variant C (Rates proxy)**: 장기금리 민감도 대용(예: TLT 모멘텀 *관측만*)로 성장주(Tech) 익스포저 감산

> 매매는 항상 US 주식(Tech/Healthcare) 및 현금만. ETF는 신호 산출에만 사용.

### (d) PASS 조건 (Gate)
- **레짐별 안정성**: fold14 같은 특정 구간 MDD가 유의미하게 감소(예: fold14_mdd가 -0.039 → -0.03 이하로)  
- **전체 성과 유지**: lockbox_mean Champion 대비 -10~15% 이내  
- **턴오버 게이트**: EXP-2의 비용 모델 Variant B에서 성과가 유지될 것(비용 내구성 동시 충족)

### (3) 기대 관측치
- 레짐 게이트가 효과 있으면: “성능이 안 움직임”의 원인이 **레짐 미스매치**였다는 강한 신호.

# 24~48h 운영 실행 순서 (명령형)
1) **EXP-1 실행 → 누수 로그/정렬 증빙 파일 아카이브**하라  
2) **EXP-2 실행 → 비용 스윕에서 생존하는 조합만 남겨라**  
3) **EXP-3 실행 → 유니버스/상폐 처리 결과가 바뀌는지 차이를 리포트로 고정하라**  
4) **EXP-4 실행 → MDD 개선되는 오버레이만 채택하라(성과 보존 조건 필수)**  
5) **EXP-5 실행 → 레짐별 성과 분해 리포트를 자동 저장하라**  

(현재 네가 가진 autopilot 커맨드 체계에 맞춰, 실험팩 5개를 system_candidates에 등록하고 `--select-best`가 “Gate 통과한 것 중 최고”만 뽑도록 고정하라.)

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **로그/리포트로 자동 산출**하도록 만들어야 다음 디버깅이 빨라진다.

## 1) Trigger(신호 발생) 분해
- **신호 발생 빈도**(일/주 단위) vs **실제 매매 빈도**를 분리해 집계하라  
- 상위 k개 종목의 **신호 점수 분포가 납작한지(구분력 상실)** 확인하라  
- “상위 8~14 선택”에서 **경계선 종목이 매번 바뀌는지(노이즈)**를 측정하라(교체율)

## 2) Apply(적용/체결) 분해
- 신호 생성 시점과 체결 시점의 **가격 갭(open gap)** 분포를 저장하라  
- 체결지연(Next open/Next close/2-day lag)에 따른 성과 민감도를 곡선으로 그려라 → 누수/즉시성 의존 검출

## 3) Exposure(노출) 분해
- 포트폴리오 **베타/변동성/섹터(Tech vs Healthcare) 비중**의 시간변화를 저장하라  
- 수익을 **팩터(시장/퀄리티/모멘텀/밸류 대용)**로 회귀 분해해 “진짜 알파 vs 팩터 베팅”을 갈라라  
- 종목 이벤트(실적/FDA) 근처 손익이 과도한지(점프리스크) 측정하라

## 4) Cost(비용) 분해
- 총 비용을 **스프레드/슬리피지/수수료/임팩트**로 분해해 “무엇이 성과를 죽이는지”를 찍어라  
- 비용이 큰 날의 공통점(변동성 급등, 거래대금 감소, 갭 확대)을 태깅하라

## 5) Regime(레짐) 분해
- 레짐 라벨을 2~3개만 두고(예: Risk-on / Risk-off / Rates-up) 각 레짐별:
  - 평균 수익, MDD, 히트레이트, 턴오버를 테이블로 저장하라
- 특히 **Tech 우세(XLK>XLV)** 구간과 **Healthcare 우세** 구간에서 전략이 “어느 쪽에 노출돼 있었는지”를 교차표로 고정하라

---

## PASS의 공통 원칙(전체 실험에 적용)
- **누수 의심 신호가 나오면 성능이 좋아도 FAIL** 처리하라  
- **비용 모델 Variant B에서 살아남는 것만** 다음 단계로 올려라  
- **worst_mdd 악화(-0.0815 → 더 나빠짐)**는 기본적으로 FAIL 쪽에 가중치를 둬라(운영 리스크 우선)

이 5개 실험팩이 48시간 자동 루프에서 “증명(누수/비용/서바이버십) → 안정화(리스크/레짐)” 순서로 굴러가면, 지금처럼 Champion은 좋은데 Candidate가 흔들리는 패턴을 가장 빠르게 줄일 수 있다.
