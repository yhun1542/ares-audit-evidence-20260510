### 1. 24~48시간 우선순위 TOP 5 제안

현재 시스템은 `degenerate_folds`가 4개(거의 절반) 발생하고, 로깅 파이프라인(JSON/CSV 파싱 에러)이 깨져 있어 **"장님 상태의 과최적화"** 위험이 매우 높음. 즉시 수정 필요.

#### P1. [Data Pipeline] 로깅 포맷 정규화 및 에러 핸들링 패치
*   **Why:** `Error loading ... Expecting value` 및 `MDD: None`은 시스템이 현재 상태를 정확히 진단하지 못함을 의미. 계기판 복구가 최우선.
*   **Risk:** 로깅 로직 수정 중 런타임 오버헤드 증가 가능성(미미함).
*   **Experiments:**
    1.  `fix_logger_json`: JSONL vs JSON 포맷 명시적 분리 및 Flush 강제 수행 코드 적용.
    2.  `calc_mdd_explicit`: MDD 계산 로직에 `fillna(0)` 및 예외처리 추가하여 `None` 반환 방지.
*   **PASS 조건:** 로그 파일 정상 생성 확인 + `worst_mdd`가 수치(Float)로 출력됨.

#### P2. [Universe] Tech/Healthcare "Top-Tier" 고정 유니버스 테스트 (8~14종)
*   **Why:** 현재 어떤 종목이 도는지 불명확. 서바이버십 바이어스 제거 및 섹터 집중을 위해 유동성 풍부한 대형주로 모집단을 강제 고정하여 베이스라인 확보.
*   **Risk:** 특정 종목의 개별 악재(Idiosyncratic Risk)에 노출.
*   **Experiments:**
    1.  `univ_top_tech_bio`: [MSFT, NVDA, AAPL, GOOGL, LLY, UNH, JNJ, ABBV, VRTX, TMO] (10개)로 유니버스 하드코딩.
    2.  `univ_momentum_select`: 위 10개 중 모멘텀 상위 5개만 매수.
*   **PASS 조건:** `degenerate_folds` 개수 감소 (데이터 결측/상장폐지 이슈 제거 효과).

#### P3. [Regime] ETF 관측 기반 Exposure Gating (Market Timing)
*   **Why:** `oos_min`이 음수이나 `exposure_max`가 0.83임. 하락장에서 노출을 줄이지 못하고 있음. ETF(QQQ/XLV)를 **매매하지 않고 지표로만** 활용하여 노출도 조절.
*   **Risk:** 휩소(Whipsaw)로 인한 기회비용 발생, 진입 시점 지연.
*   **Experiments:**
    1.  `gate_qqq_ma200`: QQQ < 200일 이평선일 때 전체 포트폴리오 현금 비중 50% 강제.
    2.  `gate_vol_filter`: VIX(또는 동등 변동성 지표) > 30일 때 매수 중단.
*   **PASS 조건:** OOS Min Drawdown 개선 (0에 가까워짐) 및 MDD < -15% 방어.

#### P4. [Cost/Reality] 보수적 비용 구조 강제 주입
*   **Why:** `oos_mean: 3.32`는 비현실적. 슬리피지와 수수료가 반영되지 않았을 확률 99%. 과최적화된 신호를 걸러내야 함.
*   **Risk:** Sharpe Ratio 급락으로 기존 챔피언 모델 폐기 가능성.
*   **Experiments:**
    1.  `cost_bps_15`: 편도 거래비용 15bps(0.15%) 강제 적용 시뮬레이션.
    2.  `cost_delay_entry`: 시그널 발생 다음날 시가(Open) 진입 + 0.1% 페널티 적용.
*   **PASS 조건:** 여전히 양(+)의 수익률 유지 시 유효 전략으로 인정.

#### P5. [Solver] 최적화 제약 조건 완화 (Relaxation)
*   **Why:** `degenerate_folds` 다수 발생은 Solver가 해를 찾지 못했음을 의미. 제약조건(비중 합, 개별 비중 한도 등)이 너무 빡빡함.
*   **Risk:** 포트폴리오 분산 효과 감소(특정 종목 쏠림).
*   **Experiments:**
    1.  `relax_weight_bound`: 개별 종목 최대 비중을 20% -> 40%로 상향.
    2.  `allow_cash_buffer`: 최적화 실패 시 전액 현금 보유 대신 '동일 비중(1/N)'으로 Fallback 로직 추가.
*   **PASS 조건:** `degenerate_folds` = 0 달성.

### 3. 성능 정체(Stagnation) 시 원인 분해 트리

성능이 움직이지 않거나(Flat), 개선되지 않을 때 다음 순서로 디버깅을 수행하라.

1.  **트리거(Trigger) 확인:**
    *   *현상:* 매수/매도 시그널 자체가 0건.
    *   *체크:* 기술적 지표(RSI, MA 등)의 임계값이 너무 극단적인가? (예: RSI < 10)
    *   *액션:* 임계값 완화 (Relax Thresholds).

2.  **노출(Exposure) 제한 확인:**
    *   *현상:* 시그널은 있으나 포지션 사이즈가 0.01% 수준.
    *   *체크:* 리스크 패리티나 변동성 조절 로직이 포지션을 과도하게 축소시키는가?
    *   *액션:* Min Weight Constraint(최소 비중 5% 등) 설정.

3.  **비용(Cost) 장벽 확인:**
    *   *현상:* Gross Return은 좋으나 Net Return이 0 또는 음수.
    *   *체크:* 회전율(Turnover)이 너무 높은가?
    *   *액션:* 리밸런싱 주기를 주간/월간으로 변경하거나, 교체 매매 임계값(Buffer) 도입.

4.  **레짐(Regime) 불일치:**
    *   *현상:* 특정 연도(Fold)에서만 성능이 박살남.
    *   *체크:* 해당 기간이 Tech/Bio 섹터 전체의 하락장(예: 2022년)인가?
    *   *액션:* ETF(QQQ/XLV) 모멘텀 필터 작동 여부 확인.

5.  **데이터/코드 오류:**
    *   *현상:* `degenerate_folds` 지속 발생.
    *   *체크:* Look-ahead Bias(미래 참조) 혹은 데이터 누락(NaN).
    *   *액션:* 코드 레벨 디버거(Diagnoser)로 Feature 생성 단계 검증.
