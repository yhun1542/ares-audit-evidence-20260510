## 📋 우선순위 TOP 5 액션 (48H 루프용)

### **P0. 파이프라인 복구 — 측정 없이 개선 없음**

**(a) 왜 필요한가**
- `rebalance.csv` 로드 실패 → 비용/슬리피지 반영 여부 검증 불가
- `worst_mdd: None` → 리스크 게이트 작동 안 함
- OOS 값 불일치 (3.32 vs 2.63) → 어느 것이 진실인지 불명

**(b) 위험/부작용**
- 파이프라인 수정 중 기존 로그 덮어쓰기 가능
- 시간 소모 (전략 실험 지연)

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 0-1 | `rebalance.jsonl` 스키마 검증 + 파서 수정 | 파일 로드 성공 | 최소 100행 파싱 |
| 0-2 | MDD 계산 로직 강제 실행 + 로그 | `worst_mdd != None` | 숫자값 출력 |
| 0-3 | OOS 계산 경로 2개 diff | 값 일치 또는 원인 식별 | delta < 0.01 또는 버그 로케이션 |

**(d) PASS 조건**
```
✅ rebalance 로드 성공
✅ worst_mdd 숫자 출력
✅ OOS 단일값 확정
```

---

### **P1. Degenerate Fold 원인 분해**

**(a) 왜 필요한가**
- 4/10 폴드가 degenerate = 모델이 40% 구간에서 "no signal" 또는 "all cash"
- 이 상태로 OOS 집계하면 survivorship bias (좋은 폴드만 평균)

**(b) 위험/부작용**
- 폴드별 진단 추가 시 연산 비용 증가
- 근본 원인이 데이터(레짐)인 경우 전략 수정으로 해결 불가

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 1-1 | Fold 1,2,3,8의 기간/섹터/변동성 프로파일 추출 | 리포트 생성 | 공통 패턴 식별 (예: 고변동성/저모멘텀) |
| 1-2 | 해당 폴드에서 exposure=0 비율 계산 | 수치 출력 | >50%면 신호 부재 확정 |
| 1-3 | Degenerate 판정 임계값 완화 후 재실행 | OOS 변화 관측 | 민감도 파악 |

**(d) PASS 조건**
```
✅ Degenerate 원인 1개 이상 식별
✅ 해당 원인에 대한 수정 가설 도출
```

### **P2. 비용 미반영 누수 점검**

**(a) 왜 필요한가**
- Rebalance 로그 없음 → 거래 빈도/비용 검증 불가
- OOS 3.32가 gross return일 가능성 (net으로 1.5~2.0 하락 가능)

**(b) 위험/부작용**
- 비용 반영 시 수익률 급락 → 심리적 충격
- 비용 모델 파라미터(슬리피지 bps) 자체가 가정치

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 2-1 | 강제로 10bps 왕복비용 적용 후 OOS 재계산 | 수치 출력 | Delta 관측 |
| 2-2 | 연간 turnover 추정 (position change 횟수) | 숫자 출력 | >500%면 과매매 경고 |
| 2-3 | 비용 반영 전/후 샤프 비교 | Sharpe delta | >0.3 하락 시 구조 재검토 |

**(d) PASS 조건**
```
✅ Net OOS 산출
✅ Turnover 수치 확보
✅ Gross-Net 갭 < 30% (그 이상이면 과매매)
```

---

### **P3. Exposure 0 구간 진단**

**(a) 왜 필요한가**
- `exposure_min: 0.0` = 완전 현금 구간 존재
- 의도된 것인지 (리스크오프) vs 버그인지 (신호 없음) 구분 필요

**(b) 위험/부작용**
- 강제 노출 최소값 설정 시 drawdown 증가 가능

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 3-1 | Exposure=0 일자 추출 + 시장 상황 매핑 | 리포트 | VIX>30 등 리스크오프 상관 |
| 3-2 | 최소 노출 10% 강제 후 백테스트 | OOS/MDD 변화 | 수익↑ but MDD↑ 트레이드오프 |

**(d) PASS 조건**
```
✅ Exposure=0 원인 식별 (의도/버그)
✅ 의도라면 문서화, 버그라면 수정
```

---

### **P4. 레짐 필터 과최적화 점검**

**(a) 왜 필요한가**
- Degenerate fold 다수 = 레짐 필터가 너무 공격적일 가능성
- "나쁜 시장에서 안 한다" → 좋은 폴드만 남아 OOS 부풀려짐

**(b) 위험/부작용**
- 필터 완화 시 MDD 증가
- 필터 자체가 핵심 알파인 경우 제거 불가

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 4-1 | 레짐 필터 OFF 상태로 전체 백테스트 | OOS/MDD 출력 | 베이스라인 대비 delta |
| 4-2 | 필터 임계값 50% 완화 후 재실행 | Degenerate fold 수 | 4 → 2 이하 목표 |

**(d) PASS 조건**
```
✅ 필터 ON/OFF 비교표 생성
✅ Degenerate ≤ 2 달성 가능 경로 확인
```

## 🔍 성능 불변 시 원인 분해 트리

```
OOS 안 움직인다
│
├─ [트리거] 신호 자체가 발생 안 함?
│   └─ 체크: position_count / signal_count per fold
│
├─ [적용] 신호는 있으나 필터에서 차단?
│   └─ 체크: pre-filter vs post-filter signal ratio
│
├─ [노출] 포지션 잡았으나 사이즈가 0에 가까움?
│   └─ 체크: mean position size when active
│
├─ [비용] Gross는 좋으나 Net에서 소멸?
│   └─ 체크: gross - net gap
│
└─ [레짐] 특정 시장 구간에서만 작동?
    └─ 체크: fold별 OOS 분산 (std > 2면 레짐 의존)
```
