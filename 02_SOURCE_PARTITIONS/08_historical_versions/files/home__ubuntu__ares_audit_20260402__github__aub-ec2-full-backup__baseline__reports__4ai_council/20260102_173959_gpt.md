## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — “명령형 체크리스트”
(우선순위는 **누수/과최적화/서바이버십/비용 미반영/운영 리스크** 순으로 배치)

---

# 1) 데이터 누수·라벨 정렬(lookahead) “하드 게이트” 삽입
### (a) 왜 필요한지
- 현재 Champion이 lockbox 성능이 높은 편인데(4.01) 이런 케이스는 **미세한 타임라인 누수**가 있으면 가장 먼저 “비정상적으로 잘 나오는 구간”이 생김.
- “성능이 안 움직임”도 종종 **누수 방지 로직이 이미 깨져 고정된 오류 상태**(예: 미래 데이터가 상시 섞여서 변경해도 결과가 비슷)일 때 나타남.

### (b) 위험/부작용
- 누수 차단 후 **성능 급락** 가능(하지만 이게 정상이면 오히려 조기 발견이 이득).
- 피처 생성 파이프라인에 **계산량 증가/캐시 무효화** 발생.

### (c) 최소 실험 2~3개 (48h 루프용)
**실험 1: Time-Shift Canary (누수 탐지)**
- (1) 실험 정의: 모든 피처/라벨에 대해 `t+1` 또는 `t+K`로 일부러 시프트한 “의도적 오류” 버전을 만들고 성능이 **크게 무너지는지** 확인.
- (2) 게이트: tuning/lockbox mean이 기존 대비 **-50% 이상 하락**(또는 min이 음수로 악화)해야 PASS(=누수 방어 정상).
- (3) 기대 관측치: 정상 파이프라인이면 성능 붕괴 + 샤프/승률 급락.

**실험 2: Strict As-Of Join/Calendar Gate**
- (1) 실험 정의: 리턴/펀더멘털/이벤트/리비전 데이터는 전부 **as-of timestamp** 기반 조인(발표시각/거래가능시각)으로 강제하고, EOD 기준이면 “다음 거래일 적용” 룰 강제.
- (2) 게이트: 재현성(동일 seed/동일 기간 결과 동일) + 누수 카나리에서 성능 붕괴가 유지되면 PASS.
- (3) 기대 관측치: 기존 대비 성능 소폭 하락 가능, 대신 fold 간 분산 감소.

**실험 3(선택): Purged Walk-Forward + Embargo**
- (1) 실험 정의: 현재 CV가 일반 k-fold면 **purge+embargo**(event overlap 제거)로 교체.
- (2) 게이트: tuning_mean이 내려가도 lockbox_mean 대비 격차가 줄고, worst_mdd 악화가 제한되면 PASS.
- (3) 기대 관측치: tuning 과대추정 감소, 안정성 지표 개선.

### (d) PASS 조건(요약)
- **누수 카나리에서 성능 붕괴** 확인 + 결과 재현성 확보 + lockbox/tuning 갭 축소(과최적화 징후 감소)

# 2) 비용·슬리피지·회전율(턴오버) “실거래형” 모델로 고정
### (a) 왜 필요한지
- 미국주식 Tech+Healthcare 8~14종목은 포지션 수가 적어 **리밸런싱 비용/슬리피지**가 성과 대부분을 잠식 가능.
- 비용을 과소추정하면 후보들이 “알파처럼 보이는 노이즈”로 우승해 운영에서 붕괴.

### (b) 위험/부작용
- 비용 반영 후 성능 하락 → “개선이 없다”처럼 보일 수 있음(하지만 운영 적합성은 상승).
- 슬리피지 모델이 과도하면 기회 상실.

### (c) 최소 실험 2~3개
**실험 1: 거래비용 스트레스 테스트(3단계)**
- (1) 실험 정의: 고정 커미션+스프레드+시장충격(간단 모델) 비용을 **Low/Base/High** 3단계로 백테스트.
- (2) 게이트: Base→High로 갈 때 lockbox_mean이 **선형적으로만 감소**하고 sign flip(수익→손실)이 안 나면 PASS.
- (3) 기대 관측치: 턴오버 높은 전략은 High에서 급락 → 즉시 제거.

**실험 2: 턴오버 캡 + 거래 임계치(“no-trade band”)**
- (1) 실험 정의: (i) 일/주간 turnover 상한 (ii) 목표비중 변화가 Xbp 이하면 미체결(밴드) 적용.
- (2) 게이트: worst_mdd 개선 또는 동일 수준 유지 + lockbox_mean 10% 이내 감소면 PASS.
- (3) 기대 관측치: 거래 횟수↓, 비용 민감도↓, 성과의 “두께” 증가.

**실험 3(선택): 체결 지연(1-bar delay)**
- (1) 실험 정의: 신호 생성 다음 캔들/다음 날 체결로 강제(룩어헤드·미세체결 착시 방지).
- (2) 게이트: lockbox_mean이 과도 붕괴하지 않으면 PASS.
- (3) 기대 관측치: 지나치게 단기 신호는 사라지고 중기 신호만 남음.

### (d) PASS 조건
- 비용 High에서도 **수익 구조 유지**, 턴오버 억제 후 MDD/안정성 개선

# 3) 서바이버십/유니버스 고정 + “8~14 Tech+Healthcare” 운영 제약을 코드로 잠금
### (a) 왜 필요한지
- 서바이버십(현재 살아남은 종목만)이나 유니버스 변동이 있으면 lockbox가 뻥튀기될 수 있음.
- 운영 제약(미국, Tech+Healthcare, 8~14, ETF 매매 금지)을 실험마다 흔들리면 결과 비교가 무의미.

### (b) 위험/부작용
- 고정 유니버스가 너무 보수적이면 기회 감소.
- 분류(Tech/Healthcare) 데이터 소스/시점에 따라 룩어헤드 가능.

### (c) 최소 실험 2~3개
**실험 1: Point-in-Time Universe 스냅샷**
- (1) 실험 정의: 각 리밸런스 시점의 “그때 존재/상장/섹터”를 반영한 PIT 유니버스 테이블로 강제.
- (2) 게이트: PIT 적용 후에도 lockbox_mean이 유지(±15% 이내)되면 PASS.
- (3) 기대 관측치: 기존 성능이 과대였으면 하락 + 변동성 증가.

**실험 2: 섹터 잠금 + 종목수 잠금(8~14)**
- (1) 실험 정의: (i) Tech+Healthcare 외 종목 자동 제외 (ii) 항상 8~14개 보유 강제(부족 시 현금/대체 규칙 명확히).
- (2) 게이트: 노출(섹터/종목수) 위반 0건 + 성능/리스크 지표 재현되면 PASS.
- (3) 기대 관측치: 포트폴리오 특성이 안정화, 비교 가능성 상승.

**실험 3(선택): ETF는 관측지표로만**
- (1) 실험 정의: XLK/XLV 같은 ETF는 “레짐/상대강도/변동성” 지표로만 사용하고 거래 금지 unit test 추가.
- (2) 게이트: ETF trade order 발생 시 테스트 실패하도록.
- (3) 기대 관측치: 운영 규정 위반 리스크 0으로 수렴.

### (d) PASS 조건
- PIT 유니버스에서도 성능이 “살아남고”, 제약 위반 0건

# 4) 과최적화 방지: “단순화 + 강건성” 우승 규칙으로 교체
### (a) 왜 필요한지
- Champion tuning_mean(2.32) 대비 lockbox_mean(4.01)이 커서 “우연히 lockbox에 맞은” 가능성도 존재.
- 후보가 성능이 안 움직이면, 탐색이 “복잡도만 증가”하며 일반화가 안 되는 상태일 수 있음.

### (b) 위험/부작용
- 단순화는 단기적으로 평균 수익을 깎을 수 있음.
- 너무 강한 규제는 알파 자체를 제거 가능.

### (c) 최소 실험 2~3개
**실험 1: 규제 강도 스윕(모델 복잡도↓)**
- (1) 실험 정의: 피처 수/트리 깊이/정규화 강도를 2~3단계로만 스윕(케이스 폭발 금지).
- (2) 게이트: lockbox_mean 유지 + fold 간 분산 감소(표준편차↓)하면 PASS.
- (3) 기대 관측치: tuning은 떨어져도 lockbox 안정성↑.

**실험 2: “Winner Rule” 변경 (리스크-조정 + 안정성 우선)**
- (1) 실험 정의: select-best 기준을 (예) `lockbox_mean - λ*worst_mdd - μ*turnover` 형태로 변경(λ, μ는 고정 1~2개 값만).
- (2) 게이트: 새 기준으로 뽑힌 top 모델의 worst_mdd가 현 champion worst_mdd(-0.081)보다 **개선 또는 동일**이면 PASS.
- (3) 기대 관측치: 평균이 약간 줄어도 꼬리위험/거래비용 민감도 감소.

**실험 3(선택): Seed/기간 미세변경 강건성**
- (1) 실험 정의: seed 2개, 시작일/종료일 ±N일만 흔들어도 순위가 유지되는지 체크.
- (2) 게이트: 상위 모델이 2/3 이상 재등장하면 PASS.
- (3) 기대 관측치: 진짜 신호는 순위가 잘 안 바뀜.

### (d) PASS 조건
- “평균”보다 **최악구간/턴오버/분산**이 개선되고, 선택 규칙 변경 후에도 상위권이 안정적

# 5) 운영 리스크(48시간 자동 루프) 강화: 실패-안전(fail-safe) + 리포트 표준화
### (a) 왜 필요한지
- 48시간 자동 루프는 “조용한 실패”(데이터 결측, 캐시 오염, 부분 실행)가 누적되면 성능이 안 움직이는 것처럼 보이게 만듦.
- 운영 단계에서 가장 치명적인 건 성과가 아니라 **잘못된 주문/중복 주문/제약 위반**.

### (b) 위험/부작용
- 초기에는 테스트/검증 코드로 실행 시간이 늘어남.
- 너무 엄격하면 실험이 자주 실패해 throughput 감소.

### (c) 최소 실험 2~3개
**실험 1: 파이프라인 불변성(Immutable artifacts)**
- (1) 실험 정의: 데이터 스냅샷 해시/피처 해시/모델 해시를 아티팩트로 저장하고, 결과 리포트에 강제 포함.
- (2) 게이트: 동일 해시 → 동일 성과(허용 오차 내)면 PASS.
- (3) 기대 관측치: “안 움직임”의 원인이 캐시/스냅샷 문제인지 즉시 드러남.

**실험 2: 제약/주문 단위테스트**
- (1) 실험 정의: (i) 8~14 종목 (ii) Tech+Healthcare (iii) ETF 주문 금지 (iv) 최대 포지션/일별 주문수 제한을 테스트로 강제.
- (2) 게이트: 위반 시 즉시 fail.
- (3) 기대 관측치: 운영 규정 위반이 사전에 차단.

**실험 3(선택): “중단/재시작” 복구 테스트**
- (1) 실험 정의: 루프 중간 강제 종료 후 재시작해도 동일 상태로 이어지는지(원자적 체크포인트).
- (2) 게이트: 재시작 후 결과/로그 일관성 유지면 PASS.
- (3) 기대 관측치: 장시간 루프에서 유령 실패 제거.

### (d) PASS 조건
- 재현성/제약 준수/장애 복구가 자동으로 보장

# 성능이 안 움직일 때 “원인 분해” 아이디어 (트리거/적용/노출/비용/레짐)
아래 순서로 진단 로그/리포트를 고정 출력하라(질문 없이 자동 점검).

## A. 트리거(신호 발생) 문제
- 신호 분포가 **0 근처로 붕괴**했는지(표준편차, 상하위 분위수, non-zero 비율).
- 상위/하위 랭크 종목의 교체율이 너무 낮은지(항상 같은 종목이면 신호가 죽었을 가능성).
- 피처 결측/클리핑으로 신호가 “평평해졌는지”.

## B. 적용(포트폴리오 변환) 문제
- 신호 → 목표비중 변환에서 **스케일링/정규화가 과도**해 전부 비슷한 비중이 되는지.
- 8~14 강제 로직에서 tie-break가 매번 동일하게 작동해 다양성이 사라졌는지.
- 리밸런스 주기/밴드가 너무 강해 실질 거래가 거의 없는지(no-trade band 과다).

## C. 노출(리스크/팩터) 문제
- 베타/섹터 편향이 일정하게 고정되어 “알파”가 아니라 “팩터”만 먹는지.
- Tech/Healthcare 내부에서도 mega-cap 쏠림으로 사실상 1~2종목 베팅이 되었는지(유효 종목수, HHI).
- 변동성 타게팅/리스크패리티가 신호를 상쇄하고 있는지.

## D. 비용(거래) 문제
- turnover가 올라가며 비용이 알파를 상쇄하는지(“gross는 움직이는데 net이 안 움직임” 패턴).
- 체결 지연/슬리피지 반영 후 신호의 엣지가 사라지는지(초단기 착시 여부).

## E. 레짐(시장 상태) 문제 — ETF는 “관측지표”로만 사용
- XLK/XLV(거래 금지, 관측만) 상대강도/변동성으로 레짐 태깅 후,
  - 레짐별 성능이 특정 구간에서만 나오면: **신호가 레짐 의존** → 레짐 게이트(거래 축소/중단) 고려.
- 금리/AI 모멘텀/바이오 이벤트 등으로 Tech/Healthcare 내부 상관이 급변했는지(상관행렬 변화율).

## “제안은 3~5개 patch/실험” 제한 준수 요약
- 위 TOP5는 각각 **하나의 패치 번들**로 취급하고, 각 번들에서 **실험 2개 중심**으로만 48시간 루프에 태워라.
- 교체 기준은 평균 수익이 아니라 **누수 방어 + 비용 내성 + 최악구간 + 제약 준수**를 통과한 것만 승격하라.
