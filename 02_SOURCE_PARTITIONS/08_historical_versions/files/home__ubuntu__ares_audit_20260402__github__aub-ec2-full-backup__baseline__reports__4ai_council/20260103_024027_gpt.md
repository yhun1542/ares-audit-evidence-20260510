## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — “명령형 체크리스트”
(공통 선행 점검 우선순위: **누수 → 과최적화 → 서바이버십 → 비용 미반영 → 운영 리스크**)

---

# 1) **리밸런스/아티팩트 관측성 복구(운영 리스크 최우선)**
현 상태에서 `champion file: (empty)`, `lane_hash/run_hash: None`, `rebalance_pinpoint`가 **로그 포맷/경로 오류로 작동 불가** → “성능이 왜 안 움직이는지”를 구조적으로 추적 불가.

### (a) 왜 필요한지
- 성능이 “No-Delta”로 보일 때 원인이 **실제 전략 무변화**인지, **실험 적용 실패/로그 누락**인지 구분이 안 됨.
- 리밸런스 로그가 깨져있으면 비용/턴오버/노출 변화가 있었는지 검증 불가(=운영 리스크).

### (b) 위험/부작용
- 로그/아티팩트 저장으로 디스크/IO 증가.
- 스키마 강제 시 과거 실험 로더 깨질 수 있음(마이그레이션 필요).

### (c) 최소 실험(아래 공용 실험 ID 참조) 2~3개
- **E1** 실행: 리밸런스 트레이스 스키마 고정 + 진단툴 입력 호환
- **E2** 실행(부분 적용): fold별 “거래/노출/턴오버” 요약을 강제 기록(퇴화 fold 원인 추적)
- **E3** 실행(부분 적용): 비용항목(스프레드/슬리피지/수수료) 로그에 “추정치/실현치” 컬럼 추가

### (d) PASS 조건
- `aub_rebalance_pinpoint.py`가 **에러 없이** 리포트 생성
- 모든 run에 `run_hash`, `lane_hash`, `champion_file_path`가 **non-null**
- 각 fold별 `num_trades, avg_exposure, turnover`가 **0/NaN 없이** 출력
- “성능 무변화” 발생 시, **(전략 신호 무변화 vs 실행/적용 실패)**를 1회 리포트로 분리 가능

---

# 2) **데이터 누수/퇴화 fold(과최적화) 즉시 차단**
`degenerate_folds: [1,2,3,8]`는 보통 아래 중 하나입니다:  
(1) fold 기간에 유니버스/신호가 비어버림 (2) 피처가 상수/결측 (3) 학습/예측이 미래정보를 끌어옴(누수) (4) 포지션 게이트가 너무 빡세 매매 0.

### (a) 왜 필요한지
- 누수/퇴화가 있으면 OOS mean이 “좋아 보이거나/아예 안 움직이거나” 둘 다 가능.
- fold 퇴화는 **모델 비교 자체를 무의미**하게 만듦(선정 편향).

### (b) 위험/부작용
- 누수 제거/워크포워드 강화 시 **단기 OOS 하락** 가능(정상적인 디레버리징).
- 게이트 강화로 거래 수가 줄어 **수익 기회 감소** 가능.

### (c) 최소 실험 2~3개
- **E2** 실행: Purged Walk-Forward + embargo + as-of join 강제 + 1-bar feature shift
- **E2-ALT**(E2에 포함): “라벨 permutation(무작위 셔플)”로 누수 스모크 테스트
- **E1**(관측성 연동): fold별 “신호분산/결측률/거래건수” 로그 강제

### (d) PASS 조건
- `degenerate_folds`가 **0 또는 1 이하**로 감소
- permutation 테스트에서 OOS mean이 **0 근처(예: |mean| < 0.2)**로 수렴(알파가 남으면 누수 의심)
- OOS min이 **의미 있게 악화되지 않음**(예: 기존 대비 -20%p 이상 붕괴 시 원인 재점검)

---

# 3) **비용/턴오버 미반영 제거(현실성 게이트)**
미국주식(Tech+Healthcare) 8~14종목 구조는 리밸런스 빈도/턴오버에 따라 비용이 성과를 전부 잡아먹을 수 있음. 지금은 리밸런스 로그도 깨져 비용 검증이 더 불가.

### (a) 왜 필요한지
- 비용이 빠지면 “좋은 OOS”가 실제 운용에서 0 또는 음수가 되는 경우가 흔함.
- “성능이 안 움직임”이 사실은 **비용이 상쇄**시키는 현상일 수 있음(특히 신호가 미세할 때).

### (b) 위험/부작용
- 비용 모델 파라미터가 과보수면 전략이 과도하게 보수화되어 알파가 사라질 수 있음.
- 턴오버 캡이 신호 반응을 늦춰 레짐 전환에서 손해 가능.

### (c) 최소 실험 2~3개
- **E3** 실행: 비용모델(스프레드+임팩트) + net objective로 재학습/재평가
- **E3-ALT**(E3에 포함): 턴오버 캡(예: rebalance당 20~30%) + 최소 보유기간(예: 2~3일)
- **E1**(관측성): 거래별 비용/턴오버 분해 로그 출력(예: spread vs impact)

### (d) PASS 조건
- **Net 기준** OOS mean이 개선 또는 유지(예: gross↓, net↑ 형태 허용)
- 평균 턴오버가 캡 이내 + 거래건수 “0으로 붕괴”하지 않음
- OOS min(최악 구간)이 개선(비용로 인한 급락 완화)

---

# 4) **서바이버십/코퍼레이트액션(분할/상폐) 파이프라인 고정**
US 개별주 백테스트는 서바이버십/상폐리턴/분할조정이 조금만 틀려도 성능이 “좋아 보이거나 / 안 움직이거나”로 왜곡됨. Tech/Healthcare는 합병/상폐/분할 이벤트도 잦음.

### (a) 왜 필요한지
- “8~14개 고정 유니버스”처럼 보이는 구조에서 특히 **과거에 살아남은 종목만 남는 편향**이 치명적.
- 상폐 리턴(마지막 가격→0 또는 현금정산)을 모델링하지 않으면 tail이 비현실적으로 작아짐.

### (b) 위험/부작용
- 데이터 소스/정합성 맞추는 동안 결측이 늘어 단기 성능 저하 가능.
- 유니버스 재구성이 바뀌면 과거 실험과 직접 비교가 어려워질 수 있음(버전 태깅 필수).

### (c) 최소 실험 2~3개
- **E4** 실행: “as-of 유니버스” + 상폐/합병 이벤트 처리 + split/dividend 조정 일관화
- **E4-ALT**(E4에 포함): survivorship audit 리포트(당시 존재했어야 할 티커 대비 누락률)
- **E1**(관측성): 각 일자 유니버스/가격 유효성(결측률) 로그

### (d) PASS 조건
- 유니버스 누락률/미존재 티커 사용률이 **0에 수렴**
- “서바이버십 ON/OFF” 비교 시 성과 괴리가 과도하지 않음(괴리가 크면 기존 성과 신뢰도 하락으로 판단)
- 코퍼레이트액션 이벤트 구간에서 수익률 스파이크/NaN 제거

# 5) **노출/레짐/안전장치(실운용 리스크) — 성능 ‘무변화’ 원인도 여기서 자주 발생**
현재 `exposure_max ~0.84`, `exposure_min 0.0` → 현금 비중이 크거나 게이트로 거래가 막히는 구간이 존재. “전략이 안 움직이는 것”이 아니라 **포지션이 안 생기는 것**일 수 있음.

### (a) 왜 필요한지
- Tech/Healthcare는 레짐(금리/리스크온오프)에 따라 상관구조가 급변 → 단일 신호는 무력화 가능.
- 실운용에서 가장 위험한 건 “원인 모르는 노출 0” 또는 “갑자기 0.84까지 점프”.

### (b) 위험/부작용
- 레짐 필터가 과하면 기회 손실(항상 현금).
- 노출 타겟팅이 잘못되면 변동성 확대 가능(특히 급변장).

### (c) 최소 실험 2~3개
- **E5** 실행: 노출 타겟(예: vol targeting) + 신호 신뢰도 기반 exposure throttle
- **E5-ALT**(E5에 포함): 관측지표로 ETF 사용(매매 금지) — 예: XLK/XLV/SPY/VIX로 risk-off에서 노출 축소
- **E1**(관측성): 노출 0 발생 트리거(게이트/결측/리스크리밋) 로그로 원인코드 남김

### (d) PASS 조건
- 노출 0 구간이 “의도된 레짐 필터 결과”로 코드상 명확히 분류됨(Unknown=0)
- OOS min(최악)이 개선 + MDD 감소
- 노출 변동(일간 Δexposure)이 상한 내(급격 점프 감소)

## 공용 “실행 가능한 patch/실험” 5개만 정의 (48시간 자동 루프용)
아래 **E1~E5만** 돌리면 위 TOP5를 모두 커버하도록 설계.

### E1) Rebalance Trace & Artifact Integrity Patch
1) **실험 정의**
- 리밸런스 출력 스키마를 JSONL/Parquet로 고정 저장:  
  `date, universe(list), target_w, filled_w, price, adv, est_cost, realized_cost(optional), turnover, exposure, constraints_hit(reason_code)`
- `run_hash/lane_hash/champion_path`를 모든 결과물 헤더에 강제 기록
- `aub_rebalance_pinpoint`가 읽는 포맷으로 변환 어댑터 추가

2) **게이트**
- 리밸런스 로그 파서 에러 0
- 각 run마다 필수 키 non-null
- fold별 요약(거래수/노출/턴오버/결측률) 자동 생성

3) **기대 관측치**
- “No-Delta” 발생 시: **신호 동일/실행 실패/게이트 차단/데이터 결측** 중 하나로 1분 내 분류 가능

---

### E2) Leakage & Degenerate Fold Kill-Switch
1) **실험 정의**
- Purged walk-forward + embargo(예: 5~10 bars) 적용
- 모든 피처 **t시점 예측에 t+1 이후 정보 사용 금지**(as-of join + 최소 1-bar shift)
- permutation test(라벨 셔플) 자동 실행하여 누수 감지

2) **게이트**
- degenerate_folds ≤ 1
- permutation OOS mean ≈ 0
- 피처 결측률/상수비율 임계치 초과 시 즉시 FAIL(학습 중단)

3) **기대 관측치**
- 누수 있었다면: 기존 성과 급락 + permutation에서도 알파 잔존(=빨간불)
- 누수 없었다면: 성과 유사 + fold 퇴화 감소

---

### E3) Cost-Aware Objective + Turnover Guard
1) **실험 정의**
- 비용모델(스프레드+임팩트) 도입 후 **net 성과 최적화**
- 턴오버 캡 + 최소 보유기간 적용(과매매 억제)

2) **게이트**
- net OOS mean 유지/개선
- turnover cap 준수 + 거래 0으로 붕괴 금지
- 비용이 성과를 상쇄하는 구간(예: net<0)에서 원인 로그 출력

3) **기대 관측치**
- gross는 내려가도 net이 안정화
- OOS min/MDD 개선(특히 변동성 큰 구간)

---

### E4) Survivorship & Corporate Actions Hardening
1) **실험 정의**
- “당시 존재하던 유니버스”로만 거래 가능하게 구성(as-of membership)
- split/dividend 조정 일관화 + delist return 처리

2) **게이트**
- 미래 티커/미존재 티커 사용 0
- 상폐/분할 이벤트 구간 NaN/스파이크 0
- survivorship audit 리포트 자동 생성

3) **기대 관측치**
- 기존 과대평가 성과가 현실화(단기 하락 가능하지만 신뢰도 상승)
- tail risk 추정이 보수적으로 변함

---

### E5) Exposure/Regime Throttle + Safety Reasons
1) **실험 정의**
- 노출 타겟팅(vol targeting) + 신호 신뢰도 기반 노출 스케일
- 관측지표(ETF: SPY/XLK/XLV, VIX 등)로 risk-off 감지(매매는 개별주만)
- 노출 0/급변의 사유를 `reason_code`로 기록

2) **게이트**
- 노출 0 구간이 전부 reason_code로 설명 가능(Unknown=0)
- OOS min 개선 + MDD 감소
- Δexposure 상한 준수

3) **기대 관측치**
- 레짐 전환 구간에서 손실 꼬리 감소
- “성능 무변화”가 노출 문제인지 즉시 식별

---

## 성능이 안 움직일 때 “원인 분해” 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **매 48시간 루프 리포트에 자동 표로 고정 출력**(질문 없이 기계적으로 점검).

### A) Trigger(신호 발생) 문제
- 체크: `signal_std`, `top-bottom spread`, `active_names_count(8~14 충족 여부)`
- 트리거 실패 패턴: 신호가 상수/결측 → 거래 0 → 성과 무변화
- 즉시 패치: E2(결측/상수 게이트) + E1(신호 요약 로그)

### B) Apply(포지션 반영) 문제
- 체크: `target_w` vs `filled_w` 괴리, `constraints_hit` 빈도(클리핑/리스크리밋/현금부족)
- 실패 패턴: 신호는 있는데 제약으로 다 잘려서 결과가 동일
- 즉시 패치: E1(reason_code) + E5(노출/제약 사유 분리)

### C) Exposure(노출) 문제
- 체크: 평균 노출, 노출 0 일수, 노출 상단(0.84 같은 ceiling) 고착 여부
- 실패 패턴: 대부분 기간 현금 → 성과가 지수와 무상관 + 변동 거의 없음
- 즉시 패치: E5(노출 타겟/스케일) + E1(노출 0 사유 코드)

### D) Cost(비용) 문제
- 체크: gross vs net 차이, turnover, ADV 대비 거래비중, 비용이 수익을 상쇄한 날짜 비율
- 실패 패턴: gross는 움직이는데 net이 눌려 “평평해 보임”
- 즉시 패치: E3(비용내재화) + E1(비용 분해 로그)

### E) Regime(레짐) 문제
- 체크: 레짐별 성과 분해(예: VIX 상/하, SPY 추세 상/하), 팩터 노출(시장/섹터 베타)
- 실패 패턴: 특정 레짐에서만 작동 → 최근 24~48h 창에서는 무반응
- 즉시 패치: E5(레짐 스로틀) + E1(레짐 태그 로그)

## 48시간 루프 실행 순서(권장, 그대로 실행)
1) **E1 먼저**: 로그/아티팩트가 서야 나머지 실패 원인을 추적 가능  
2) **E2 동시**: 퇴화 fold/누수 의심을 최우선 제거  
3) **E3**: 비용/턴오버 현실화로 “가짜 알파” 제거
