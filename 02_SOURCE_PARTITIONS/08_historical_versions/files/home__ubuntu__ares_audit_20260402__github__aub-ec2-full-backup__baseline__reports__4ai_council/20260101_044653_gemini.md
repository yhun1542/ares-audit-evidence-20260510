### 2. 제안별 상세 실험 스펙 (Actionable Patch)

#### #1. Pipeline Integrity Check (캐시/시드 초기화)
*   **(a) 필요성:** `lockbox_mean`과 `fold14_mdd`가 버전 간 완벽히 일치하는 비정상 상황 해결.
*   **(b) 위험:** 없음 (시스템 점검).
*   **(c) 실험 (Experiments):**
    1.  `Exp_A`: 모든 캐시(`__pycache__`, `.pkl`) 삭제 후 기존 Champion 재실행 -> 결과 동일 여부 확인.
    2.  `Exp_B`: Random Seed를 변경(42 -> 123)하여 실행 -> 결과 변동성 확인.
*   **(d) PASS 조건:** `Exp_A`는 결과 일치, `Exp_B`는 결과 **불일치**(미세한 차이라도 발생해야 함).

#### #2. Dynamic Universe: Top-Tier Tech/Bio Rotation
*   **(a) 필요성:** 2026년 시점까지 특정 소수 종목(Nvidia 등)만 들고 가는 과최적화 방지.
*   **(b) 위험:** 잦은 교체로 인한 Turnvoer/비용 증가. 소형 바이오주 편입 시 변동성 폭발.
*   **(c) 실험 (Experiments):**
    1.  `Exp_Univ_Liquid`: 월말 기준 S&P500 내 Tech/Health 섹터 중 거래대금 상위 30개 중 10개 선별.
    2.  `Exp_Univ_Quality`: 위 조건 + ROE > 0 (적자 바이오 제외).
    3.  `Exp_Univ_Static_Control`: 현재 고정 유니버스 유지(대조군).
*   **(d) PASS 조건:** `lockbox_mean` > 1.80 AND `Turnover` < 20% (월간).

#### #3. ETF-Observed Regime Filter (XLK/XLV)
*   **(a) 필요성:** 섹터 전체가 무너질 때 개별 주식 알파는 무의미함. 거시적 방어 기제 필요.
*   **(b) 위험:** 휩소(Whipsaw)로 인한 진입 시점 지연(Missing Out).
*   **(c) 실험 (Experiments):**
    1.  `Exp_Filter_MA`: XLK 또는 XLV가 200일 이평선 하회 시 해당 섹터 비중 0% 처리.
    2.  `Exp_Filter_RSI`: XLK/XLV 주간 RSI < 30 일 때 해당 섹터 매수 금지.
*   **(d) PASS 조건:** `worst_mdd` 개선 (> -0.10) AND `tuning_mean` 하락폭 5% 이내 방어.

#### #4. Transaction Cost & Execution Reality
*   **(a) 필요성:** 리밸런싱 비용 미반영 리스크 최우선 점검 항목.
*   **(b) 위험:** 수익률 급감으로 인한 전략 폐기 가능성.
*   **(c) 실험 (Experiments):**
    1.  `Exp_Cost_10bps`: 슬리피지+수수료 왕복 10bps 적용 시뮬레이션.
    2.  `Exp_Cost_30bps`: 슬리피지+수수료 왕복 30bps 적용 (보수적).
    3.  `Exp_Limit_Turnover`: 리밸런싱 시 기존 비중의 10% 이상 변동 시에만 매매 실행 (Buffer).
*   **(d) PASS 조건:** 30bps 적용 시에도 `tuning_mean` > 1.2 유지.

#### #5. Feature Swap: Volatility-Adjusted Momentum
*   **(a) 필요성:** 기존 지표(`mrd_ars_fsa`)의 영향력 부재 확인. Tech/Bio 특성상 '상승 중 변동성 축소'가 진짜 시그널.
*   **(b) 위험:** 급등주(High Vol + High Mom) 제외로 인한 수익 포기.
*   **(c) 실험 (Experiments):**

    2.  `Exp_Feat_InvVol`: 단순 변동성 역가중(Low Vol) 전략과 비교.
*   **(d) PASS 조건:** `fold14_mdd` 개선 (> -0.09) AND `sharpe` > Champion.

### 3. 성과 정체(Stagnation) 원인 분해 & 디버깅

성능이 움직이지 않을 때 다음 순서로 코드를 점검하고 조치하십시오.

1.  **Exposure (노출)**
    *   **체크:** 선택된 상위 N개 종목이 Champion과 Candidate 간에 실제로 다른가?
    *   **액션:** 일자별 보유 종목 리스트(Holdings Diff)를 출력하여 비교. 차이가 없다면 Scoring 함수가 작동하지 않는 것.

2.  **Constraints (제약)**
    *   **체크:** `Maximize Return` 목적함수에서 `Min/Max Weight` 제약이 너무 좁지 않은가? (예: 0.08 ~ 0.12로 고정 시 최적화 불가능)
    *   **액션:** 개별 종목 허용 비중을 0.0 ~ 0.30 으로 대폭 완화하여 Optimizer가 작동할 공간 부여.

3.  **Costs (비용)**
    *   **체크:** 작은 알파가 거래 비용으로 인해 상쇄되어 최종 곡선이 비슷하게 수렴하는가?
    *   **액션:** 거래 비용 0으로 설정 후 백테스트하여 순수 로직의 차이 확인.

4.  **Regime (시장 국면)**
    *   **체크:** 2025-2026 기간이 강한 상승장이어서 어떤 로직이든 Beta만 추종하는가?
    *   **액션:** Benchmark(QQQ/XLK) 대비 초과 수익(Alpha) 그래프 확인. Alpha가 0에 수렴하면 전략 폐기.

**명령어 실행 순서:**
1. Pipeline Integrity Check (`__pycache__` 삭제)
2. Cost Sensitivity Test (30bps)
3. Dynamic Universe & Regime Filter 실험 순차 실행
