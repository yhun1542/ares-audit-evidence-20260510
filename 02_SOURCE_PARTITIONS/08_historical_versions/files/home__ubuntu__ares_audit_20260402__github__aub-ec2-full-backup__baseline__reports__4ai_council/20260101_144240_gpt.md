# TOP5 우선순위 제안 (각각 1개 “패치/실험”로 매핑 = 총 5개)

## 1) (최우선) **시간정렬/누수 차단 강화**: as-of join, 발표시점, 리밸런스 시점 엄격화
### (a) 왜 필요한지
- 현재 tuning/lockbox 모두 양호하지만 **개선 폭이 작고 안정적**이라, 작은 누수/정렬 오류가 “계속 비슷한 성능”을 만드는 전형적 패턴일 수 있음.
- Tech/Healthcare는 **실적/가이던스/임상 이벤트** 등 “발표시점” 민감 → 하루 단위 누수도 성능을 과대평가 가능.

### (b) 위험/부작용
- 누수 제거 후 단기적으로 성능 하락 가능(“진짜 실력”만 남음).
- 일부 피처가 무력화되면 신호 빈도 감소(포지션 수/턴오버 변화).

### (c) 최소 실험(여기서는 1개 실험 안에 2~3개 토글로만 구성)
**[실험 E1] Strict As-Of & Execution Lag 패치**
- 토글 A: 모든 피처/라벨을 **t 시점 주문이면 t-1 종가/데이터만 사용**(최소 1 bar lag 강제)
- 토글 B: 펀더멘털/이벤트성 데이터가 있다면 **발표 timestamp 기준 as-of join**(없으면 “항상 +1 trading day lag”로 보수화)
- 토글 C: 리밸런스 실행가를 `close`가 아니라 **next open 또는 VWAP proxy**로 바꿔 누수/체결 환상 축소

### (d) PASS 조건(게이트)
- **Lockbox_mean ≥ Champion + 0.006** (≈ +0.45%p) *또는*  
  **Worst_MDD 개선(덜 음수) ≥ +0.005**를 달성하면서 Lockbox_mean이 Champion 대비 -0.003 이내
- `lockbox_min`이 **-0.060 아래로 악화 금지**
- 포지션 수(8~14) 유지 및 Tech+Healthcare 비중 규칙 위반 0건

### 48h 자동 루프 형태
- (1) 실험 정의: E1 토글 A/B/C
- (2) 게이트: 위 PASS 조건
- (3) 기대 관측치: 성능이 유지/소폭 하락하더라도 **턴오버↓, 샤프 안정**, 폴드 간 분산↓가 나오면 “누수 제거 성공” 신호

## 2) **서바이버십/유니버스 편향 제거**: “그때 존재하던” 종목만, Tech+Healthcare 8~14 강제
### (a) 왜 필요한지
- Tech/Healthcare는 **상장폐지·M&A·임상 실패** 등 탈락 이벤트가 빈번 → survivorship가 있으면 백테스트가 과대평가.
- 유니버스가 은근히 넓어지면(필터 완화) “선택 편향”으로 성능이 고정/왜곡.

### (b) 위험/부작용
- 과거 유동성/데이터 결측 증가 → 트레이드 가능일 감소.
- 유니버스가 좁아지며 신호가 덜 나와 성능 하락 가능.

### (c) 최소 실험
**[실험 E2] Point-in-Time Universe & Listing-Age 패치**
- 토글 A: 각 날짜별 **상장 상태/거래 가능/가격 존재** 조건을 point-in-time로 강제
- 토글 B: **상장 후 N일(예: 252일) 경과** 종목만(초기 변동성·데이터 불안 제거)
- 토글 C: 섹터 필터를 **Tech + Healthcare만**으로 고정하고, 포트폴리오 종목 수 **항상 8~14** 유지(부족 시 현금/대기 규칙 명시)

### (d) PASS 조건
- Lockbox_mean이 Champion 대비 **-0.003 이내로 유지**하면서
  - Worst_MDD **개선 ≥ +0.003** *또는* fold 간 성능 분산(표준편차) 감소
- “거래일 수/리밸런스 횟수” 급감 시(예: -20% 초과) FAIL(전략 운용 불가 리스크)

### 48h 자동 루프
- (1) 실험 정의: E2 토글 A/B/C
- (2) 게이트: 성능 + 운용가능성(거래일/리밸런스 유지)
- (3) 기대 관측치: 평균 성능이 약간 내려도 **최악 구간(worst_mdd) 완화**되면 장기 운용 적합도↑

## 3) **비용(슬리피지/스프레드/충격비용/회전율) 미반영 리스크를 “의도적으로” 악화시켜 내성 테스트**
### (a) 왜 필요한지
- 현재 수치가 안정적으로 좋아 보여도, 비용 모델이 약하면 “실전에서만 무너지는” 형태가 됨.
- Tech/Healthcare는 뉴스/갭이 잦아 **open 체결/슬리피지**가 핵심.

### (b) 위험/부작용
- 비용을 올리면 당연히 성능 하락 → 하지만 이 실험 목적은 “취약성 위치” 식별.
- 너무 보수적이면 유효전략을 잘못 폐기할 수 있음(그래서 단계적 민감도만).

### (c) 최소 실험
**[실험 E3] Cost Stress Test(민감도 3단)**
- 토글 A: 수수료+스프레드 기본치 적용
- 토글 B: 슬리피지 2배(또는 bps +X)로 상향
- 토글 C: **거래대금 대비 참여율 캡**(예: ADV의 1~2%) + 충격비용(선형) 추가

### (d) PASS 조건
- 비용 B/C에서 Lockbox_mean이 Champion 대비 하락하더라도
  - 하락폭이 단계적으로 “예상 범위” 내(예: A→B→C 단조 감소)이고
  - Worst_MDD가 급격히 악화되지 않을 것(Champion 대비 **-0.010p 이상 악화 금지**)
- 만약 B에서 이미 성능 붕괴면: 해당 전략은 **턴오버/진입방식 개선**이 우선이라는 결론을 자동 채택

### 48h 자동 루프
- (1) 실험 정의: E3 토글 A/B/C
- (2) 게이트: 비용 민감도 “완만함” + MDD 악화 제한
- (3) 기대 관측치: 전략의 알파가 “비용에 얼마나 얇은지”가 수치로 드러남(개선 방향이 바로 정해짐)

## 4) **과최적화(폴드 적합) 완화**: Purged/Embargo CV, 단순화/규제(regularization) 우선
### (a) 왜 필요한지
- tuning_mean이 lockbox_mean과 함께 움직이지만, 개선 폭이 작을 때는 “조금씩 폴드에 맞춘” 상태일 수 있음.
- 특히 이벤트 드리븐 성격(Tech/Healthcare)은 자기상관/클러스터가 있어 일반 CV가 낙관적.

### (b) 위험/부작용
- 모델 단순화로 평균 수익률이 줄 수 있음.
- embargo/purge 적용 시 학습 데이터가 줄어 분산 증가 가능.

### (c) 최소 실험
**[실험 E4] Purged+Embargo CV & Regularization 패치**
- 토글 A: Purged K-fold(시간창 purge) + embargo(예: 5~10일) 적용
- 토글 B: 피처 수 상한/정규화 강화(L1/L2 또는 트리 깊이 제한 등 “한 가지”만)
- 토글 C: 하이퍼파라미터 탐색 폭 축소(탐색 예산↓ → 과최적화↓)

### (d) PASS 조건
- tuning_mean이 소폭 내려도 무관하나, **lockbox_mean이 Champion 대비 +0.003 이상**이면 PASS  
  (또는 lockbox_min 개선)
- fold14_mdd가 악화되지 않을 것(Champion 대비 **-0.005p 이상 악화 금지**)

### 48h 자동 루프
- (1) 실험 정의: E4 토글 A/B/C
- (2) 게이트: lockbox 중심 + MDD 방어
- (3) 기대 관측치: tuning- lockbox 갭 축소, 성능 변동성 감소

## 5) **레짐(시장국면) 기반 위험 게이트**: ETF는 “관측지표”로만 사용(매매 X)
### (a) 왜 필요한지
- Tech/Healthcare는 금리/리스크온오프에 민감. 동일 신호라도 레짐에 따라 기대값이 반전될 수 있음.
- 성능이 “안 움직이는” 이유가, 신호 자체가 아니라 **노출이 잘못된 레짐에서 유지**되기 때문일 수 있음.

### (b) 위험/부작용
- 게이트가 과하면 트레이드가 줄어 기회비용 증가.
- 레짐 신호도 과최적화 위험 → 단순 지표 1~2개로 제한.

### (c) 최소 실험
**[실험 E5] Regime Risk Gate(지표: QQQ/XLV/10Y/VIX 중 1~2개만)**
- 토글 A: QQQ 추세(예: 50>200)일 때만 Tech 비중 확대, 아니면 축소
- 토글 B: XLV 상대강도( XLV / SPY )가 상승일 때 Healthcare 비중 확대
- 토글 C: 변동성(VIX 또는 VIX proxy) 상단 구간에서는 포지션 스케일 다운(레버리지/노출 축소)

### (d) PASS 조건
- Lockbox_mean **+0.003 이상** 또는 Worst_MDD **+0.005 이상 개선**
- 포지션 수 8~14 유지 실패(현금 대기 규칙 포함) 시 FAIL
- 연속 “미진입 기간”이 과도(예: 전체의 30% 초과)하면 FAIL(운용 불능)

### 48h 자동 루프
- (1) 실험 정의: E5 토글 A/B/C
- (2) 게이트: MDD 개선 우선 + 운용 가능성
- (3) 기대 관측치: 평균 수익이 비슷해도 **최악 낙폭/꼬리손실이 줄면** 성공

# 성능이 “안 움직일 때” 원인 분해 아이디어(트리거/적용/노출/비용/레짐)
아래를 **실험마다 자동 리포트**로 남기도록 계측(telemetry) 항목을 고정하라.

## A. Trigger(신호 발생) 문제
- [ ] 신호 발생률(% days with position change), 종목별 엔트리 빈도
- [ ] 상위 신호 스코어 분포(상위 5%가 매번 같은 종목인지)
- [ ] 신호가 “항상 포화(clip)”인지 확인(스케일/정규화 버그)

**정체 패턴**
- 신호 빈도↓ + 포지션 고정 → 성능 변화가 거의 없음(‘노출이 고정’)

## B. Apply(주문/체결/리밸런스) 문제
- [ ] 리밸런스 시점(종가/시가)과 가격 참조가 일관적인지
- [ ] 체결가/슬리피지 적용 여부(0으로 들어간 구간이 없는지)
- [ ] 리밸런스 캘린더(휴장/half-day) 처리

**정체 패턴**
- 체결 모델이 너무 낙관/고정이면 후보 변경이 성능에 거의 반영되지 않음

## C. Exposure(노출) 문제
- [ ] 섹터(Tech/Healthcare) 비중 준수율, 종목 수(8~14) 준수율
- [ ] 베타/시장노출(대략 SPY 회귀), 금리 민감도(10Y 변화와 손익 상관)
- [ ] 단일 종목 기여도(Top1~Top3 PnL 기여가 과도한지)

**정체 패턴**
- “같은 2~3개 종목이 다 해먹는” 구조면, 모델 개선이 포트에 반영돼도 변화가 미미

## D. Cost(비용) 문제
- [ ] 회전율(turnover), 거래 횟수, 평균 보유기간
- [ ] 비용 차감 전/후 성능 갭(알파가 비용에 잠식되는지)
- [ ] 거래대금 대비 주문 크기(참여율)

**정체 패턴**
- 원시 알파는 있는데 비용이 거의 전부 잡아먹으면, 어떤 패치도 “lockbox에서” 안 움직임

## E. Regime(국면) 문제
- [ ] QQQ 추세/변동성/금리 레짐별로 성능을 버킷팅(간단히 4분면)
  - 예: (QQQ up/down) × (VIX high/low)
- [ ] 레짐별 hit-rate/avg win/avg loss 분해

**정체 패턴**
- 특정 레짐에서만 돈 버는데 레짐 가중이 평균에 묻히면, 전체 성능이 잘 안 움직임 → 게이트가 답

## 24~48시간 실행 순서(명령형 체크리스트)
- [ ] **E1(누수/정렬)** 먼저 적용 → 통과/실패 여부 확정
- [ ] **E2(서바이버십/유니버스)** 적용 → 운용가능성(거래일/리밸런스) 확인
- [ ] **E3(비용 스트레스)**로 “알파 두께” 측정
- [ ] **E4(과최적화 완화)**로 lockbox 갭 축소 시도
- [ ] **E5(레짐 게이트)**로 tail-risk 개선 시도
- [ ] 각 실험 끝날 때마다: lockbox_mean/min, worst_mdd, turnover, 종목수(8~14) 준수율을 **동일 포맷**으로 리포트에 자동 기록

원하면, 위 5개 실험을 `module_registry.yaml`/`system_candidates.yaml`에 바로 꽂을 수 있는 형태(필드명/토글 키/리포트 항목 스키마)로 “패치 템플릿”만 추가로 정리해 줄 수 있음.
