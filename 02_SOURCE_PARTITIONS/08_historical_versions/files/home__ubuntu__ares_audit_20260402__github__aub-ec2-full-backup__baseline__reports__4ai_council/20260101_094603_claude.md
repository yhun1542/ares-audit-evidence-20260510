## 1. 우선순위 TOP 5 Patches

### PATCH-1: Tuning Min 0.05 Fold 진단 및 격리

| 항목 | 내용 |
|------|------|
| **(a) 왜 필요** | tuning_min=0.05는 1개 fold가 사실상 실패. 이 fold가 lockbox와 유사 레짐이면 실전 붕괴 |
| **(b) 위험** | 해당 fold 제거 시 과최적화 가속. fold 자체가 outlier인지 전략 실패인지 구분 필수 |
| **(c) 실험** | ① fold별 return 분포 시각화 → worst fold 특성 추출<br>② worst fold 기간 VIX/SPY drawdown 매핑<br>③ worst fold만 별도 backtest → 어떤 signal 실패? |
| **(d) PASS** | worst fold 원인 규명 완료 + 해당 레짐 필터 적용 시 fold_min > 0.3 |

```yaml
# experiment_system/config/exp_fold_diagnosis.yaml
experiment_id: "exp_fold_diagnosis_v1"
module: "fold_analyzer"
params:
  target_metric: "tuning_min"
  threshold: 0.1
gate:
  condition: "worst_fold_cause_identified == True"
expected_obs:
  - "fold_id: int"
  - "regime_label: str (high_vol / bear / sector_rotation)"
```

### PATCH-3: Regime Filter 모듈 추가 (VIX/SPY 기반)

| 항목 | 내용 |
|------|------|
| **(a) 왜 필요** | worst_mdd -11.2%가 특정 레짐(고변동/급락장)에 집중 가능성 |
| **(b) 위험** | 레짐 필터 과적합 → 실제 위기 시 늦은 진입/조기 청산 |
| **(c) 실험** | ① VIX > 25 기간 exposure 50% 축소 룰 적용<br>② SPY 20D MDD > -5% 시 신규 진입 중단<br>③ 두 조건 AND/OR 조합 비교 |

### PATCH-4: Position Sizing 로직 점검 (Equal → Vol-Parity)

| 항목 | 내용 |

## 2. 성능 미변동 시 원인 분해 프레임워크

```
[성능 정체 원인 트리]

1. TRIGGER (신호 발생)
   └─ 신호가 애초에 발생 안 함?
      → signal_count per period 체크
      → 너무 strict한 필터?

2. APPLICATION (포지션 반영)
   └─ 신호 → 실제 포지션 전환율?
      → 유동성/거래제한으로 skip된 비율?

3. EXPOSURE (시장 노출)
   └─ 포지션 잡았으나 exposure 시간 부족?
      → 평균 holding days vs signal decay

4. COST (비용 차감)
   └─ gross return은 있으나 net에서 소멸?
      → turnover × cost drag 계산

5. REGIME (시장 환경)
   └─ 전략 유효 레짐이 test 기간에 부재?
      → 레짐별 성과 분해 필수
```
