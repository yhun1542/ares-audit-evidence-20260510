# 2) TOP5 제안별 (a) 필요성 (b) 위험/부작용 (c) 최소 실험 2~3개 (d) PASS 조건  
※ “케이스 폭발” 방지를 위해 **실험(Experiment)은 총 5개(E1~E5)만** 정의하고, 각 제안은 해당 실험의 **서브테스트(2~3개)**로 처리한다.  
※ 모든 실험은 **48시간 자동 루프 형태: (1) 실험 정의 → (2) 게이트 → (3) 기대 관측치**로 구성한다.

## 제안 1) 누수(lookahead) + 데이터 정합성(PIT) 강제  → **E1**
### (a) 왜 필요한지
- 현재 **tuning 대비 lockbox 개선이 미미**(챔피언과 후보가 lockbox_mean 거의 동일). 이 패턴은 “진짜 개선 부재” 외에 **미세 누수/피처 타임스탬프 오류**로 튜닝만 좋아지고 실전(락박스)에서 더 이상 안 움직이는 경우가 잦다.
- 특히 매크로/펀더멘털/리밸런싱 캘린더가 섞이면 **asof-join 누수**가 가장 흔한 실패원인.

### (b) 위험/부작용
- 성능이 단기적으로 떨어질 수 있다(= 기존 성능 일부가 누수였음을 의미).
- 데이터 계약이 엄격해지면 결측 처리/지연 반영으로 거래 빈도가 줄 수 있다.

### (c) 최소 실험(서브테스트 2~3개) — **E1: PIT/누수 하니스**
**(1) 실험 정의**
- [ ] 모든 비가격(펀더멘털/매크로/대체데이터) 피처에 대해 **“발행시각/반영가능시각”을 강제**하고, 백테스트 조인 방식을 **asof(<=t)만 허용**하도록 패치해라.
- [ ] 동일 전략을 아래 3가지로 재학습/재평가:
  - E1-A: 비가격 피처 **+1거래일 lag 강제**
  - E1-B: 비가격 피처 **+5거래일 lag 강제**
  - E1-C: “의심 피처군(매크로/리밸런싱 캘린더/리포트일)”을 **통째로 제거**한 ablation

**(2) 게이트(자동 FAIL 조건)**
- [ ] lag를 늘릴수록 성능이 비정상적으로 “좋아지면” 즉시 FAIL(누수/조인 오류 가능성).
- [ ] E1-C(의심 피처 제거)에서 성능이 거의 동일하면 → 해당 피처군은 “무의미 or 누수 의심”으로 분류하고 차단.

**(3) 기대 관측치**
- 정상이라면 lag 증가 시 **완만한 성능 저하** 또는 **변동성 증가**가 관측된다(급격한 개선/급격한 붕괴가 아니어야 함).

### (d) PASS 조건
- [ ] E1-A(1일 lag)에서도 **lockbox_mean이 챔피언 대비 -0.05 이내**로 유지(누수 제거해도 구조가 버팀)  
- [ ] E1-B(5일 lag)에서 **패턴이 합리적**(극단적 역전 없음)  
- [ ] E1-C에서 성능이 크게 무너지지 않으면(예: lockbox_mean -0.10 이내) → “피처 의존도/누수 위험 낮음” 판정

## 제안 2) 비용(슬리피지/스프레드) 반영 + 턴오버 제어  → **E2**
### (a) 왜 필요한지
- 8~14종목 집중전략은 리밸런싱/체결비용의 영향이 **수익률을 통째로 깎는 1순위 요인**이 된다.
- 비용을 제대로 넣지 않으면 락박스가 “더는 안 오르는” 상태에서 실전은 악화된다(비용 미반영이 과최적화처럼 작동).

### (b) 위험/부작용
- 비용 모델이 과도하면 좋은 전략도 죽인다(보수적 스트레스는 하되, 기본 모델은 현실선 유지).
- 턴오버 억제가 알파를 둔화시킬 수 있다(특히 모멘텀 단기형).

### (c) 최소 실험 — **E2: Cost+Turnover 패치**
**(1) 실험 정의**
- [ ] 거래비용을 “고정bps”가 아니라 **유동성 연동(ADV, 스프레드 프록시)**로 바꿔라. (예: 슬리피지 = k1*spread + k2*|qty|/ADV)
- [ ] 아래 3개 서브테스트를 **동일한 기간/유니버스에서** 수행해라:
  - E2-A: 비용 1.0x(기본) + 일간 리밸런스
  - E2-B: 비용 2.0x(스트레스) + 일간 리밸런스
  - E2-C: 비용 1.0x + **노트레이드 밴드/부분리밸런스**(예: 목표비중 대비 편차가 일정 임계 미만이면 주문 금지)

**(2) 게이트**
- [ ] E2-B(2.0x)에서 성능이 “괴멸”하면(예: lockbox_mean이 1.0 미만으로 급락) → 전략이 비용 민감/실전 취약 판정.
- [ ] E2-C에서 턴오버가 줄었는데 성능이 거의 같으면 → 즉시 채택 후보.

**(3) 기대 관측치**
- 비용 스트레스에서 완만히 감소하되, **락박스 min/드로다운이 안정화**되는 방향이 정상.

### (d) PASS 조건
- [ ] E2-C 적용 시 **턴오버 20~40% 이상 감소**(프로젝트 내 정의된 turnover metric 기준)  
- [ ] lockbox_mean이 챔피언 대비 **-0.03 이내 유지** 또는 **lockbox_min 개선**  
- [ ] worst_mdd가 **동일 또는 개선(더 작아짐)**

## 제안 3) 서바이버십/상장폐지/유니버스 정의 고정(Tech+Healthcare 8~14)  → **E3**
### (a) 왜 필요한지
- “현재 시점 상장 종목만”으로 학습되면 **서바이버십 바이어스**로 과거 성능이 부풀려진다.
- 8~14종목은 유니버스/리밸런스 규칙이 조금만 흔들려도 결과가 크게 변한다(재현성/운영리스크).

### (b) 위험/부작용
- PIT 유니버스/상폐수익 반영 시 과거 성능이 하락할 수 있다(정상).
- 유동성 필터 강화로 종목 풀이 줄어 알파 기회가 감소할 수 있다.

### (c) 최소 실험 — **E3: PIT 유니버스 + 상폐수익 + 히스테리시스**
**(1) 실험 정의**
- [ ] 유니버스를 “Tech+Healthcare 내”에서 다음을 동시에 만족하도록 고정해라:
  - 상장폐지/티커변경/합병 이벤트 **총수익 반영**
  - **PIT(당시 접근 가능한 구성)** 기준 종목 풀 생성
  - 유동성(예: ADV 하한) + 가격 하한(페니 제외)
  - 보유종목 수 **항상 8~14 유지**
- [ ] 서브테스트 3개:
  - E3-A: 현행 유니버스(컨트롤)
  - E3-B: PIT+상폐수익 반영 유니버스
  - E3-C: E3-B + **진입/퇴출 히스테리시스**(빈번한 구성 변경 억제)

**(2) 게이트**
- [ ] E3-B에서 수익이 하락해도, 결과가 “더 현실적”이면 유지(여기선 성능보다 **편향 제거**가 목적).
- [ ] E3-C에서 종목 교체율이 줄지 않으면(변화 없음) → 히스테리시스 구현 오류로 FAIL.

**(3) 기대 관측치**
- PIT 반영 후에도 전략의 상대적 강점(특히 락박스 min/드로다운)이 유지되면 “진짜 실력” 가능성이 커진다.

### (d) PASS 조건
- [ ] E3-C에서 **종목 교체 빈도 감소** + **lockbox_min 개선 또는 worst_mdd 개선**  
- [ ] lockbox_mean이 챔피언 대비 **-0.05 이내**로 버티면 채택(편향 제거 비용으로 허용)

## 제안 4) 노출(베타/섹터/단일종목/변동성) 제약 + 리스크 기반 사이징  → **E4**
### (a) 왜 필요한지
- 8~14종목은 단일종목/팩터(나스닥 베타, 대형성장) 노출로 **드로다운이 한 번에 커질** 수 있다.
- 현재 챔피언 worst_mdd가 약 -9.3% 수준으로 준수하지만, **락박스 확장**을 위해선 tail 리스크를 더 제어하는 편이 “지속가능한 개선”으로 이어진다.

### (b) 위험/부작용
- 제약이 과하면 알파가 눌린다(특히 테크 랠리 구간에서 언더퍼폼).
- 최적화기 수렴/불안정(공분산 추정) 이슈가 생길 수 있다.

### (c) 최소 실험 — **E4: 제약형 포트폴리오 레이어**
**(1) 실험 정의**
- [ ] 시그널(알파)은 그대로 두고, **포트폴리오 매핑 레이어**만 교체해라:
  - 단일종목 최대비중(예: 12~15%)
  - 섹터(Tech/Healthcare) 비중 상한(한쪽 과쏠림 방지)
  - 포트폴리오 베타 타겟(예: 0.6~1.0 범위) 또는 변동성 타겟
- [ ] 서브테스트:
  - E4-A: 현행(컨트롤)
  - E4-B: 단일종목 캡 + 섹터 캡
  - E4-C: E4-B + 변동성 타겟(리스크 패리티/역변동성 가중)

**(2) 게이트**
- [ ] 제약 적용 후 **보유 종목 수가 8~14에서 벗어나면** FAIL(요구조건 위반).
- [ ] 제약 때문에 현금비중이 과도해지면(예: 상시 미투자) FAIL.

**(3) 기대 관측치**
- lockbox_mean이 약간 줄더라도 **lockbox_min / worst_mdd가 개선**되는 패턴이 정상.

### (d) PASS 조건
- [ ] worst_mdd가 **1.0%p 이상 개선**(예: -9.3% → -8.3% 이하)  
- [ ] lockbox_mean이 챔피언 대비 **-0.03 이내** 또는 lockbox_min 개선

## 제안 5) 레짐(Tech vs Healthcare / risk-on/off) 관측지표(ETF는 지표만) 기반 알파 믹싱  → **E5**
### (a) 왜 필요한지
- Tech/Healthcare는 레짐에 따라 “주도 섹터”가 바뀐다. 고정 알파는 레짐 미스매치에서 성능이 정체되기 쉽다.
- ETF는 매매하지 않더라도 **레짐 관측 지표**로는 매우 유용(규칙 준수).

### (b) 위험/부작용
- 레짐 분류가 과최적화되면 오히려 나빠진다(특히 경계 구간에서 잦은 스위칭).
- 운영상 지표 지연/결측 시 잘못된 모드로 들어갈 수 있다(운영리스크).

### (c) 최소 실험 — **E5: 레짐-조건부 알파 가중**
**(1) 실험 정의**
- [ ] 레짐 지표는 ETF “가격”만 사용(매매 금지, 관측만):
  - 예: QQQ(Tech 프록시), XLV(Healthcare 프록시), SPY(시장), (가능하면) VIX 프록시
- [ ] 알파 2개 모드만 두고(케이스 폭발 금지) 레짐에 따라 가중치를 바꿔라:
  - 모드1: risk-on(모멘텀/성장 기울기)
  - 모드2: risk-off(퀄리티/방어/저변동 기울기)
- [ ] 서브테스트:
  - E5-A: 단순 임계값(예: QQQ/XLV 상대강도 + 변동성 지표)
  - E5-B: 로지스틱(2-state)로 확률 레짐 → 연속 가중
  - E5-C: 스위칭 비용(모드 변경 페널티) 추가

**(2) 게이트**
- [ ] 레짐 스위치가 과도하면 FAIL(예: 월 평균 N회 이상; 프로젝트 기준으로 상한을 둬라).
- [ ] 레짐 지표 1~2일 지연을 주었을 때 결과가 크게 역전되면 FAIL(운영 취약).

**(3) 기대 관측치**
- 평균보다 **락박스 min/최악 구간 개선**이 먼저 나타나는 게 정상(레짐은 tail 완화에 강점).

### (d) PASS 조건
- [ ] lockbox_min이 **유의미하게 개선**(챔피언 대비 +0.05 이상 같은 “최저 성능” 개선)  
- [ ] worst_mdd **동일 또는 개선**, 턴오버 증가가 과도하지 않을 것

# 3) 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **체크리스트 순서대로 분해**해서, “개선이 안 되는 지점”을 한 칸씩 고정해라.

## A. Trigger(신호가 실제로 발생하나?)
- [ ] 예측 스코어 분포(평균/표준편차/꼬리)가 시간에 따라 **붕괴(0에 수렴)**하는지 확인해라.
- [ ] 상위/하위 랭크 간 **스프레드(Top-Bottom 기대수익)**가 기간별로 살아있는지 확인해라.
- [ ] 종목 수 8~14에서 **항상 꽉 차는지**(신호 부족으로 현금화/미투자되는지) 확인해라.

## B. Apply(신호→포트폴리오 변환에서 죽나?)
- [ ] 제약조건이 상시 바인딩되는지(단일종목 캡/섹터 캡/리스크 캡 때문에) “바인딩 비율”을 로깅해라.
- [ ] 리밸런스 룰이 신호를 무시하는지(예: 노트레이드 밴드가 너무 커서 거래가 거의 없음) 확인해라.
- [ ] 스코어는 바뀌는데 포지션이 안 바뀌면 → 매핑 레이어 문제로 판정해라.

## C. Exposure(의도치 않은 베타/팩터/섹터 노출로 상쇄되나?)
- [ ] 일별/주별 포트폴리오 베타(대략 SPY 회귀) 추정해서 **베타가 레짐마다 흔들리는지** 확인해라.
- [ ] Tech vs Healthcare 비중이 한쪽으로 고정되는지(사실상 “QQQ 롱”이 되는지) 확인해라.
- [ ] 단일종목 기여도(리턴/리스크 기여)가 과도하면 → “집중 리스크가 알파를 가린다”로 판정해라.

## D. Cost(거래비용/슬리피지가 알파를 먹나?)
- [ ] 비용 차감 전/후 PnL을 동시에 기록해라: **Gross Sharpe vs Net Sharpe 갭**이 핵심.
- [ ] 턴오버, 거래횟수, ADV 대비 주문크기 분포를 뽑아라.
- [ ] 특정 종목에서만 비용이 폭발하면 → 유동성 필터/주문 상한이 필요하다고 판정해라.

## E. Regime(레짐 미스매치로 “평균은 비슷한데 구간별로 깨지나?”)
- [ ] QQQ vs XLV 상대성과(관측지표)로 구간을 나누고, 구간별 성능을 비교해라.
- [ ] 변동성(시장 변동 확대/축소) 구간별로 IC/성과가 달라지는지 확인해라.
- [ ] “특정 구간에서만 벌고 나머지에서 본다”면 → 레짐 믹싱(E5) 또는 제약형 리스크(E4) 우선 적용해라.

---

## 24~48시간 운영 우선순위(실행 순서)
- [ ] **E1(누수/PIT)** 먼저 돌려서 “성능 정체가 착시인지”부터 확정해라.
- [ ] **E2(비용/턴오버)**로 실전 생존성 게이트를 세워라.
- [ ] **E3(서바이버십/유니버스)**로 결과 재현성과 운영 리스크를 잠가라.
- [ ] 그 다음 **E4(노출/리스크)** → **E5(레짐)** 순으로 tail을 개선해라.

이 5개(E1~E5)만으로도 “성능이 왜 안 움직이는지”를 **누수/비용/편향/노출/레짐** 축으로 강제 분해할 수 있고, 48시간 자동 루프에 그대로 얹을 수 있다.
