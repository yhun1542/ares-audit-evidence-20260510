현재 `oos_mean: 3.32`는 비정상적으로 높으며, `degenerate_folds: [1, 2, 3, 8]` (전체 폴드의 40% 실패)와 `worst_mdd: None`은 **치명적인 데이터 누수(Look-ahead Bias)** 혹은 **거래 기록 누락(Phantom Trades)**을 시사함. Rebalance Log 로딩 실패는 비용 분석을 불가능하게 하므로 즉시 수정 필요.

### [Phase 1: 48시간 내 우선순위 TOP 5 제안]

#### 1. [INFRA] 거래 로그/MDD 계산 로직 강제 패치
*   **필요성:** `worst_mdd: None`과 Rebalance log 로딩 실패는 시스템이 '손실'을 인식하지 못하고 있음을 의미. 맹목적인 과최적화 상태.
*   **위험:** 패치 후 성과 지표가 급락할 가능성(실제 현실 반영).
*   **실험 정의:**
    *   (1) `rebalance.csv` 형식을 JSONL로 통일하거나 파서(Parser) 수정.
    *   (2) MDD 계산 시, 거래가 0건인 구간을 'Flat(0%)'이 아닌 'Penalized'로 처리하는 로직 추가.
*   **PASS 조건:** `worst_mdd`가 수치(Float)로 산출되고, 로그 파일 경로 에러 소멸.

#### 2. [STRATEGY] 진입 장벽 완화 (FSA Threshold Relaxation)
*   **필요성:** 현재 `degenerate_folds`가 다수 발생한 원인은 진입 조건(FSA > 0.90 추정)이 너무 엄격하여 특정 기간에 거래가 전혀 없기 때문일 가능성 99%.
*   **위험:** 거래 횟수 증가로 인한 승률 하락 및 비용 증가.
*   **실험 정의:**
    *   (1) `exp_fsa_080`: 진입 임계값 0.90 → 0.80 하향.
    *   (2) `exp_fsa_070`: 진입 임계값 0.90 → 0.70 하향.
    *   (3) `exp_min_holding`: 최소 보유일 3일 강제 (노이즈 필터).
*   **PASS 조건:** Degenerate Folds 개수가 0~1개로 감소 & 거래 횟수 폴드 당 평균 30회 이상.

#### 3. [RISK] ETF 변동성 기반 노출 제한 (Regime Filter)
*   **필요성:** Tech/Healthcare는 개별 종목 리스크보다 섹터 리스크가 큼. ETF(XLK, XLV)가 하락 추세일 때 개별 종목 롱 포지션 진입을 차단해야 함.
*   **위험:** 급반등(V자 반등) 구간에서의 기회비용 손실.
*   **실험 정의:**
    *   (1) Filter: `XLK` 또는 `XLV`의 20일 이동평균선 < 현재가 일 때만 진입 허용.
    *   (2) Scale: ETF Volatility(20d)가 상위 20%일 때, 개별 종목 포지션 사이즈 50% 축소.
*   **PASS 조건:** MDD -5%p 개선 & 샤프 지수(Sharpe) 유지.

#### 4. [UNIVERSE] 유동성/서바이버십 필터 강화
*   **필요성:** Tech/Bio 소형주는 상장폐지 빈도가 높음. 현재 유니버스가 2026년 기준 생존 종목만 포함하고 있다면 `oos_mean: 3.32`는 허상임.
*   **위험:** 유니버스 축소로 인한 분산 효과 감소.
*   **실험 정의:**
    *   (1) 각 시점(Point-in-Time) 기준, 시가총액 하위 20% 및 $5 미만 종목 즉시 제외.
    *   (2) 거래대금(Dollar Volume) 10M 미만 제외.
*   **PASS 조건:** 백테스트 성과가 하락하더라도, OOS 결과의 신뢰구간이 좁아질 것.

#### 5. [COST] 슬리피지/수수료 모델링 강화 (Conservative)
*   **필요성:** Rebalance log가 없는 상태에서 비용 미반영 가능성 높음.
*   **위험:** 기존 챔피언 모델 폐기 가능성.
*   **실험 정의:**
    *   (1) 매매 시 `bp=15` (0.15%) 비용 강제 주입 후 재실행.
    *   (2) 회전율(Turnover) 연 500% 이상 시 페널티 부여.
*   **PASS 조건:** 비용 반영 후에도 OOS Mean > 0.5 유지.

### [Phase 3: 성능 정체 시 원인 분해 (Debugging Logic)]

성능 지표가 움직이지 않거나 0에 수렴할 때 다음 순서로 점검:

1.  **트리거(Trigger) 확인:**
    *   *현상:* 거래 횟수 0.
    *   *원인:* 지표(FSA 등)가 `NaN`이거나, 필터 조건(AND 조건 과다)이 너무 빡빡함.
    *   *액션:* 모든 필터를 끄고 `Random Entry`로 거래가 체결되는지 확인 (파이프라인 테스트).

2.  **적용(Application) 확인:**
    *   *현상:* 시그널은 뜨는데 포지션 사이즈가 0.
    *   *원인:* 자금 관리(Risk Model)에서 변동성 과다로 사이즈를 0으로 계산하거나, 가용 현금(Cash) 계산 오류.
    *   *액션:* `Fixed Fraction (0.1)`로 사이즈 로직 단순화 실험.

3.  **노출(Exposure) 확인:**
    *   *현상:* 매수 후 즉시 매도.
    *   *원인:* 손절(Stop Loss)이나 이익 실현(Take Profit)이 노이즈 레벨(0.5% 등)로 설정됨.
    *   *액션:* ATR 기반 유동적 밴드로 변경.

4.  **레짐(Regime) 불일치:**
    *   *현상:* 특정 연도(Fold)에서만 전멸.
    *   *원인:* Tech/Health 섹터 특성상 금리 인상기/임상 실패 시즌에 취약.
    *   *액션:* 매크로 지표(US10Y 등)를 팩터로 추가하기보다, ETF 모멘텀을 On/Off 스위치로 사용.
