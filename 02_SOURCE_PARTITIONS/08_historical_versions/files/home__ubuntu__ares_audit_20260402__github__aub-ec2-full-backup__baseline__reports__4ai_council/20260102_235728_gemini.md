[절대 규칙 준수: 명령형 체크리스트 형태 제안]

### 1. 24~48시간 우선순위 TOP 5 (Action Plan)

#### **Priority 1: `worst_mdd: None` 및 로그 누락 긴급 패치 (시스템 무결성)**
*   **(a) 이유:** MDD가 계산되지 않는 챔피언 모델은 신뢰 불가. `Rebalance Pinpoint`에서 로그 파일 경로 에러가 발생하여 트레이딩 로직 분석이 불가능한 상태(Blind Spot).
*   **(b) 위험:** 잘못된 승리감(False Confidence)으로 실제 운영 시 계좌 파산 가능성.
*   **(c) 실험:**
    1.  **[SYS-01]** MDD 계산 모듈에 `NaN` 처리 및 `min_periods` 예외 처리 추가.
    2.  **[SYS-02]** JSONL 로거 경로 절대 경로로 강제 지정 및 파일 생성 권한/헤더 확인 스크립트 실행.
*   **(d) PASS 조건:** `worst_mdd`가 실수(float)로 출력되고, `rebalance_pinpoint.py`가 에러 없이 실행될 것.

#### **Priority 2: Degenerate Folds [1, 2, 3, 8] 해결 (과적합/데이터 편향)**
*   **(a) 이유:** 전체 Fold 중 절반 가까이(4개)가 퇴화(Degenerate)됨. 특정 기간 데이터의 이상치(Outlier)나 제로 그라디언트 문제로 모델이 학습을 포기했거나 특정 값에 고착됨.
*   **(b) 위험:** OOS Mean(3.32)이 나머지 Fold에서의 과도한 베팅으로 인한 착시일 가능성 높음. 라이브 투입 시 즉시 손실 위험.
*   **(c) 실험:**
    1.  **[STAB-01] Robust Scaling:** 입력 Feature에 `RobustScaler`(IQR 기반) 적용하여 이상치 영향 제거.
    2.  **[STAB-02] Target Clipping:** 학습용 Target(수익률)을 -10% ~ +10%로 클리핑하여 극단적 변동성 구간 학습 제외.
    3.  **[STAB-03] L2 Reg Boost:** 모델의 L2 Regularization 강도를 현재의 2배~5배로 상향.
*   **(d) PASS 조건:** Degenerate Folds 개수가 0~1개로 감소하고, `oos_min`이 -0.05 이상 유지.

#### **Priority 3: ETF 관측 기반 Regime Filter 도입 (시장 리스크)**
*   **(a) 이유:** Tech/Healthcare는 변동성이 큼. 하락장에서 숏(Short)이나 현금 비중을 늘리지 않으면 MDD 방어 불가. (ETF 매매는 금지지만 지표로는 활용 가능).
*   **(b) 위험:** 과도한 필터링으로 인한 수익 기회 상실(False Negative).
*   **(c) 실험:**
    1.  **[VIX-Gate]** VIX(또는 UVXY 대용 데이터) > 25 구간에서 전체 Exposure 상한을 0.5로 제한.
    2.  **[XLV-Trend]** XLV(Healthcare ETF) 20일 이평 < 60일 이평 시 Healthcare 종목 매수 금지.
*   **(d) PASS 조건:** MDD가 10% 이상 개선(감소)되고, 샤프 지수(Sharpe) 상승.

#### **Priority 4: 유니버스 압축 및 섹터 밸런싱 (집중도 관리)**
*   **(a) 이유:** 8~14개 종목 제한 상황에서 Tech/Healthcare 쏠림 발생 시 상관계수 1에 수렴하여 분산 효과 실종.
*   **(b) 위험:** 주도주(Alpha)를 제외하게 되어 수익률 저하.
*   **(c) 실험:**
    1.  **[UNI-Top10]** 시가총액/유동성 상위 20개 중 모멘텀/퀄리티 상위 10개로 유니버스 동적 축소.
    2.  **[SEC-Bal]** Tech와 Healthcare 비중 차이가 20%p 이상 벌어지지 않도록 하드 코딩 제약(Penalty) 추가.
*   **(d) PASS 조건:** 특정 섹터 일일 변동폭이 포트폴리오 전체 변동폭의 80%를 넘지 않을 것.

#### **Priority 5: 슬리피지/수수료 가중 적용 (비용 현실화)**
*   **(a) 이유:** 현재 `oos_mean: 3.32`는 비용이 과소평가되었을 가능성 99%. 잦은 리밸런싱은 수익을 갉아먹음.
*   **(b) 위험:** 전략의 기대 수익률이 급격히 하락하여 폐기될 수 있음(그러나 이는 필요한 고통임).
*   **(c) 실험:**
    1.  **[COST-Hi]** 매매 수수료 10bps + 슬리피지 10bps 강제 적용 백테스트.
    2.  **[TO-Limit]** 일일 회전율(Turnover) 10% 미만으로 제약 조건 추가.
*   **(d) PASS 조건:** 비용 적용 후에도 OOS Mean > 1.0 유지.

### 2. 성능 정체(Stagnation) 원인 분해 아이디어

성능이 움직이지 않거나 `degenerate` 상태가 지속될 때 다음 순서로 디버깅:

1.  **트리거(Trigger) 불감증:**
    *   *원인:* 예측값(Score)의 표준편차가 너무 작아 매매 임계값(Threshold)을 넘지 못함.
    *   *확인:* `pred_score`의 히스토그램 확인. 분포가 중앙에 쏠려 있는지 점검.
2.  **노출(Exposure) 제약:**
    *   *원인:* 리스크 관리 모듈(Vol Control 등)이 상시 작동하여 포지션 진입을 막고 있음.
    *   *확인:* `exposure_min/max` 로그 확인. 0.0 근처에서 머무는지 체크.
3.  **비용(Cost) 장벽:**
    *   *원인:* 예측된 알파가 수수료보다 작아 최적화기(Optimizer)가 '매매 없음'을 선택.
    *   *확인:* 비용 파라미터를 0으로 설정 후 백테스트하여 거래량 변화 관측.
4.  **레짐(Regime) 불일치:**
    *   *원인:* Tech/Bio 섹터가 횡보장일 때 모멘텀 전략은 작동 안 함.
    *   *확인:* 벤치마크(QQQ/XLV) 대비 상대 수익률(Active Return) 확인.

### 3. 48시간 자동 루프 정의 (Auto-Loop Configuration)

다음 포맷으로 자동화 시스템에 주입:

**(1) 실험 정의: Fold Stabilization (Robustness)**
*   **Config:** `features.scaler = "RobustScaler"`, `training.loss_function = "HuberLoss"`, `regularization.l2 = 1e-4`
*   **Target:** Tech(NVDA, MSFT, AAPL...), Health(LLY, UNH, JNJ...) 상위 유동성 종목.
*   **Action:** Feature 전처리를 이상치에 강한 방식으로 변경하고 손실 함수 교체.

**(2) 게이트 (Gate)**
*   `worst_mdd` is not None
*   `len(degenerate_folds) <= 1`
*   `oos_sharpe > 1.2`

**(3) 기대 관측치 (Expected Observation)**
*   기존 OOS Mean(3.32)은 하락할 것이나, Fold별 성능 편차가 줄어들어야 함.
*   Degenerate Fold가 사라지고 모든 기간에서 유의미한 거래 빈도 발생.
