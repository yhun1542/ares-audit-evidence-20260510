### PATCH-1: 측정 파이프 복구 (Critical)

#### (a) 왜 필요한가
- `worst_mdd=None` → 실제 drawdown 모니터링 불가
- rebalance.csv 미생성 → 거래 비용/슬리피지 검증 불가
- OOS 수치 불일치 (3.32 vs 2.63) → 어느 게 진짜인지 모름

#### (b) 위험/부작용
- 파이프 수정 중 기존 아티팩트 덮어쓰기 위험
- 로깅 오버헤드 증가 (무시할 수준)

#### (c) 최소 실험

| ID | 실험 정의 | 게이트 |
|----|-----------|--------|
| P1-A | `backtester.py`에 MDD 계산 추가, JSON에 `worst_mdd` 필드 강제 출력 | `worst_mdd ≠ None` |
| P1-B | rebalance 이벤트를 JSONL로 출력하도록 수정 | 파일 존재 & 파싱 성공 |
| P1-C | diagnoser vs handoff OOS 계산 로직 diff | 차이 원인 문서화 |

#### (d) PASS 조건
```
[ ] worst_mdd 숫자 출력 (예: -0.15)
[ ] rebalance.jsonl 100줄 이상 & JSON 파싱 OK
[ ] OOS Mean 계산식 단일화 완료
```

### PATCH-2: Degenerate Fold 원인 분리

#### (a) 왜 필요한가
- 4/10 폴드 실패 = **특정 레짐에서 전략 무력화** 또는 **데이터 누수**
- 폴드 1,2,3 = 초기 구간 → 훈련 데이터 부족 or 레짐 상이

#### (b) 위험/부작용
- 폴드별 분석에 시간 소요 (자동화 필요)
- 원인이 레짐이면 전략 근본 수정 필요

#### (c) 최소 실험

| ID | 실험 정의 | 게이트 |
|----|-----------|--------|
| P2-A | 폴드별 (1) 평균 return (2) 종목 수 (3) 시장 레짐(SPY 20d vol) 덤프 | 리포트 생성 |
| P2-B | 폴드 1-3 제외하고 OOS 재계산 | `oos_mean 변화율 < 20%`이면 레짐 문제, `> 50%`이면 누수 의심 |
| P2-C | Walk-forward purge gap 2배로 (현재값 → 2×) | degenerate 폴드 수 ≤ 2 |

#### (d) PASS 조건
```
[ ] 폴드별 레짐 리포트 생성
[ ] Degenerate 원인 태그: {DATA_LEAK | REGIME | SAMPLE_SIZE}
[ ] purge gap 조정 후 degenerate ≤ 2
```

### PATCH-3: 비용 현실화 점검

#### (a) 왜 필요한가
- OOS 3.32가 비용 반영 전 수치일 가능성
- 현재 슬리피지/수수료 설정값 불명

#### (b) 위험/부작용
- 비용 높이면 OOS 급락 가능 (그게 현실)

#### (c) 최소 실험

| ID | 실험 정의 | 게이트 |
|----|-----------|--------|
| P3-A | 현재 비용 파라미터 추출 & 문서화 | config에서 slippage_bps, commission 확인 |
| P3-B | slippage 10bps → 20bps로 변경 후 재실행 | `oos_mean ≥ 2.0` 유지 |
| P3-C | 턴오버 제한 (월 50% cap) 추가 | 턴오버 감소 & `oos_mean ≥ 2.5` |

#### (d) PASS 조건
```
[ ] 비용 파라미터 명시적 문서화
[ ] 20bps 기준 OOS ≥ 2.0
[ ] 턴오버 월 50% 이하
```

[ ] 단일 종목 max 15%

### PATCH-5: 시그널-노출 연결 검증

#### (a) 왜 필요한가
- 시그널은 발생하는데 실제 포지션 변화 없을 수 있음
- 필터/게이트가 과도하면 시그널 사장

#### (b) 위험/부작용
- 필터 완화 시 노이즈 트레이드 증가

#### (c) 최소 실험

| ID | 실험 정의 | 게이트 |
|----|-----------|--------|
| P5-A | 시그널 발생 수 vs 실제 리밸런스 수 비율 | `action_rate ≥ 30%` |
| P5-B | 필터 임계값 10% 완화 | `oos_mean 변화` 관찰 |
| P5-C | 시그널 강도 상위 10% only 실행 | 수익 기여도 집중 확인 |

#### (d) PASS 조건
```
[ ] 시그널→액션 전환율 문서화
[ ] 필터 완화 시 OOS 변화 ±10% 이내
[ ] Top-10% 시그널 수익 기여 ≥ 70%
```

## 2. 성능 정체 시 원인 분해 트리

├─ [비용] 수익 있으나 거래비용에 잠식
│   └─ 점검: gross_return vs net_return 차이
│
└─ [레짐] 현재 시장 레짐이 전략 불리
    └─ 점검: SPY vol > 25 구간 성과 별도 계산
