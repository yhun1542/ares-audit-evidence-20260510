## 다음 24~48시간 TOP5 우선순위 (코드/아키텍처/전략) — **명령형 체크리스트**
1) **누수/서바이버십/point-in-time 강제**(데이터 계층)  
2) **비용(슬리피지/스프레드/충격) + 턴오버 제약을 “학습/선정”에 반영**(평가 계층)  
3) **노출(섹터/베타/볼/싱글네임) 제어 + 8~14개 집중 포트폴리오 규칙을 하드 제약화**(포트폴리오 계층)  
4) **레짐(리스크온/오프) 관측지표(ETF) 기반 리스크 스케일링**(전략 계층; ETF는 매매 금지, 지표만)  
5) **운영 리스크(결측/기업행위/스케줄/재현성) 하드닝 + 텔레메트리 추가**(운영 계층)

아래는 **48시간 자동 루프**에서 바로 돌릴 수 있도록, 각 제안을 **“패치/실험 5개(각 2~3 arms 포함)”**로 제한해 제시합니다.

# P1) 누수/서바이버십/point-in-time 강제 (데이터 계층)
### (a) 왜 필요한지
- 현재 챔피언/후보가 lockbox에서 비슷하게 정체면, **진짜 개선 여지**는 보통 “알파”가 아니라 **평가의 정직성(누수 제거) + 비용 반영 + 노출 제어**에서 나옵니다.
- 특히 Tech/Healthcare는 이벤트(실적/임상/규제) 민감 → **실적일/발표 시간/리비전** 관련 누수 가능성이 흔합니다.
- 서바이버십(상장폐지/인수/합병 누락)도 MDD/수익률을 과대평가하기 쉬움.

### (b) 위험/부작용
- 누수 차단 후 성능이 하락할 수 있음(“좋았던 성능”이 사실상 누수였던 경우).
- 데이터 커버리지 저하로 유니버스가 줄어 8~14개 유지가 어려워질 수 있음.

### (c) 최소 실험(패치) 2~3 arms (단일 패치 E1로 실행)
**E1: Point-in-time & Corporate-action Sanitizer**
- **Arm A (baseline)**: 현행 그대로 재현(스냅샷 고정)
- **Arm B (PIT 강제)**:  
  - 재무/이벤트/어닝스 특징이 있다면 **발표 시점 이후 T+1부터만 사용**(lookahead 차단)  
  - 시가총액/분류(GICS 등)도 **월초 리밸런스 시점 스냅샷**으로 고정
- **Arm C (서바이버십 강화)**:  
  - delisted/merged tickers 포함 가능한 데이터면 포함(불가 시 “상장폐지 발생일 이후 거래 불가 + 마지막 거래가 처리” 명시)  
  - 스플릿/배당 조정이 혼재 시 **Adj Close 단일 기준으로 통일 + 체결가격 정합성 체크**

### (d) PASS 조건 (게이트)
- **Gate-0(정적)**:  
  - feature timestamp ≤ decision timestamp 검증 로그 0건(위반 0)  
  - split/dividend 처리 후 수익률 outlier(예: |daily ret|>50%) 플래그 감소/0
- **Gate-1(성능/안정성)**:  
  - lockbox_mean ≥ champion - 0.01 (누수 제거로 급락 방지)  
  - lockbox_min ≥ champion_min (1.3469) 유지  
  - worst_mdd 악화폭 ≤ 0.005p
- **기대 관측치**:  
  - 성능이 약간 내려도 **폴드 간 분산 감소 / 극단 수익률 감소**가 관측되면 “정상화 성공”으로 간주하고 다음 패치(비용/노출)로 진행

# P2) 비용(슬리피지/스프레드/충격) + 턴오버 제약을 선정에 반영 (평가 계층)
### (a) 왜 필요한지
- 8~14개 집중 포트폴리오는 **리밸런스/교체 빈도**가 성과를 좌우.  
- 현재 지표가 좋아도 비용 미반영이면 lockbox에서 “비슷하게 정체”가 발생(현실성/강건성 부족).
- Tech/Healthcare는 대형주도 많지만, 중형/바이오로 내려가면 스프레드/충격이 급증.

### (b) 위험/부작용
- 비용 모델이 과하면 알파가 눌려 성능이 떨어질 수 있음.
- 지나친 턴오버 억제는 레짐 전환 대응을 늦출 수 있음.

### (c) 최소 실험(패치) 2~3 arms (단일 패치 E2로 실행)
**E2: Cost-aware Backtest + Turnover Regularization**
- **Arm A (spread-only)**: 거래비용 = `half_spread`(일별 추정치 또는 고정 bps)
- **Arm B (spread+impact)**: 거래비용 = `half_spread + k * (|trade_value| / ADV)^α` (보수적으로 k만 튜닝 금지, 고정 2~3수준)
- **Arm C (turnover cap)**:  
  - 일/주 리밸런스 시 **turnover 상한(예: 40~60%/rebalance)** 초과분은 다음 리밸런스로 이월(부분 체결)

### (d) PASS 조건 (게이트)
- **Gate-0(정적)**: 비용이 “거래 발생 시에만” 적용되는지 체크(홀딩 구간 비용 0)
- **Gate-1(성과/현실성)**:  
  - lockbox_mean ≥ champion_mean - 0.02 (비용 반영 감안)  
  - **평균 turnover**가 baseline 대비 ≥ 15% 감소 또는 비용/수익 비율이 개선  
  - worst_mdd 개선 또는 동일(악화폭 ≤ 0.003p)
- **기대 관측치**:  
  - 성능이 크게 변하지 않더라도 “비용 민감도 곡선(Arm A→B→C)”이 매끄러우면 운영 가능성이 올라감(다음 노출 제어로 이동)

# P3) 노출 제어 + 8~14개 집중 규칙 하드 제약화 (포트폴리오 계층)
### (a) 왜 필요한지
- Tech/Healthcare 중심이라도, 팩터/베타/변동성 노출이 무의식적으로 한쪽으로 쏠리면 lockbox에서 “정체+MDD 유사” 패턴이 나옴.
- 8~14개면 단일 종목/테마 쏠림이 곧 MDD로 직결.

### (b) 위험/부작용
- 제약이 과하면 알파가 죽고 수익률이 평준화될 수 있음.
- 섹터 제약이 강할수록 유니버스 결측 시 매매 불능 케이스 증가.

### (c) 최소 실험(패치) 2~3 arms (단일 패치 E3로 실행)
**E3: Exposure Guardrails (Hard constraints)**
- **Arm A (sector cap)**:  
  - Tech+Healthcare 합산 80~100% 유지(전제 유지), **단일 GICS 산업군/테마 최대 비중 cap**(예: 35~45%)
- **Arm B (single-name cap + equal-risk)**:  
  - 단일 종목 max weight(예: 12~15%) + **리스크 패리티(최근 20~60d vol 기반)로 가중치 조정**
- **Arm C (beta/vol targeting)**:  
  - 포트폴리오 **ex-ante vol 타깃**(예: 10~14% annualized) 또는 beta(예: 0.8~1.1) 범위로 스케일

### (d) PASS 조건 (게이트)
- **Gate-0(정적)**: 항상 보유 종목 수 8~14 유지(위반 0 또는 허용오차 1일 이내)
- **Gate-1(성과/리스크)**:  
  - worst_mdd ≤ champion_worst_mdd + 0.002p (가급적 개선)  
  - fold별 mdd 분산 감소(최악 폴드 개선 우선)  
  - lockbox_min 유지 또는 개선
- **기대 관측치**:  
  - 평균 성과가 비슷해도 “최악 구간 안정화(특히 fold14)”가 보이면 다음 레짐 스케일링과 결합 가치 큼

# P4) 레짐 관측(ETF) 기반 리스크 스케일링 (전략 계층)
*(ETF 매매 금지 준수: QQQ/XLV/SPY/IEF/VIX 등은 “지표”로만 사용)*

### (a) 왜 필요한지
- Tech/Healthcare는 리스크온/오프에 대한 민감도가 다름.  
- 동일 알파라도 **레짐에 따라 기대값이 바뀌는데**, 이걸 무시하면 lockbox 평균은 비슷하고 MDD만 반복될 수 있음.

### (b) 위험/부작용
- 레짐 필터가 오탐이면 수익 기회를 놓침(under-investment).
- 레짐 전환이 빠르면 “스위칭 비용”이 증가.

### (c) 최소 실험(패치) 2~3 arms (단일 패치 E4로 실행)
**E4: Regime-based Risk Scalar (No trading ETFs)**
- **Arm A (credit/rates proxy)**: IEF(또는 TLT) 모멘텀/변동으로 risk-off 감지 → 포트 gross exposure 1.0→0.5
- **Arm B (equity vol proxy)**: VIX(가능 시) 또는 SPY realized vol 상승 시 exposure 축소(완전 현금화 금지, 하한 0.4~0.6)
- **Arm C (sector relative)**: XLV/QQQ 상대강도(지표)로 **Tech/Healthcare 내 비중만 재분배**(총 노출은 유지)

### (d) PASS 조건 (게이트)
- **Gate-0(정적)**: ETF 주문/포지션 생성 0건(로그로 강제)
- **Gate-1(성과/레짐 일관성)**:  
  - worst_mdd 개선(목표: +0.5~1.5%p) 또는 tail(하위 5%) 일수 감소  
  - lockbox_mean이 0.00~0.02 범위 내 유지(수익 희생 최소화)
- **기대 관측치**:  
  - “리스크 축소 시점의 손실 기여도”가 줄고, 반등 구간 참여율은 과도하게 훼손되지 않음

# P5) 운영 리스크 하드닝 + 텔레메트리 (운영 계층)
### (a) 왜 필요한지
- 성능이 안 움직일 때 원인이 “전략”이 아니라 **파이프라인 오류/결측 처리/리밸런스 타이밍/리프로덕션 불가**인 경우가 많음.
- 자동 루프(48h)에서는 특히 “조용한 실패(silent failure)”를 막아야 함.

### (b) 위험/부작용
- 로그/검증 추가로 런타임이 늘어날 수 있음.
- 너무 많은 경고로 신호/잡음비가 떨어질 수 있음(필수 지표만 남겨야 함).

### (c) 최소 실험(패치) 2~3 arms (단일 패치 E5로 실행)
**E5: Telemetry + Determinism + Fail-fast**
- **Arm A (deterministic build)**: 시드/데이터 스냅샷/유니버스 스냅샷 해시를 artifact로 고정 저장
- **Arm B (fail-fast guards)**:  
  - 결측률/거래불가(halts)/가격 0/스플릿 이상치 감지 시 즉시 실패(또는 안전모드로 축소)  
- **Arm C (attribution logs)**:  
  - 매 리밸런스마다 `turnover`, `cost`, `#positions`, `top contributors`, `exposure(beta/vol/sector)`를 JSON으로 저장

### (d) PASS 조건 (게이트)
- **Gate-0(정적/운영)**: 동일 스냅샷 재실행 시 성과 완전 동일(허용오차 0)
- **Gate-1(품질)**: 경고/에러가 “원인-결과”로 추적 가능(리밸런스 1회당 핵심 KPI 로그 1세트 존재)
- **기대 관측치**:  
  - 성능 정체 시에도 “어디서 안 움직이는지”가 수치로 바로 분해됨(아래 원인 분해 트리와 연결)

# 성능이 안 움직일 때 “원인 분해” 아이디어 (트리거/적용/노출/비용/레짐)
아래는 “정체”를 **알파 부재**로 단정하지 않고, 어디가 막혔는지 쪼개는 진단 트리입니다.

## 1) Trigger(신호 발생) 문제
- **증상**: 포지션 교체가 거의 없거나, 항상 비슷한 종목만 선택
- **점검/로그**:
  - 리밸런스 시점별 **신호 분포(평균/표준편차/상위-하위 스프레드)**  
  - 상위 N 랭크의 **교체율**, 랭크 자기상관
- **원인 후보**:
  - 특성값이 평평(스케일링/결측 대체로 신호가 죽음)
  - 유니버스 필터가 과도(항상 같은 대형주만 남음)

## 2) Apply(적용/실행) 문제
- **증상**: 신호는 움직이는데 포트폴리오가 안 바뀜(또는 반대로 과도하게 바뀜)
- **점검/로그**:
  - “목표 가중치 vs 실제 체결 가중치” 차이
  - 리밸런스 룰(부분 체결/턴오버 cap)로 인한 **이월량(backlog)**
- **원인 후보**:
  - 턴오버 제약이 너무 강함
  - 거래불가/결측으로 실행이 skip됨(운영 리스크)

## 3) Exposure(노출) 문제
- **증상**: 평균 성과는 비슷한데 worst_mdd가 계속 동일 패턴
- **점검/로그**:
  - 포트폴리오 beta/vol/섹터/산업군/단일종목 최대비중 시계열
  - 손실 구간에서 **상관(특히 QQQ/SPY와의 상관)** 급등 여부
- **원인 후보**:
  - 사실상 “QQQ 레버리지 유사” 노출
  - 바이오(헬스케어) 이벤트 드리븐 tail이 통제되지 않음(싱글네임 cap 부재)

## 4) Cost(비용) 문제
- **증상**: gross 성과는 좋은데 net에서 정체 / 후보 간 차이가 lockbox에서 사라짐
- **점검/로그**:
  - PnL을 **gross / cost / net**으로 분해
  - 비용의 대부분이 특정 종목/특정 날(리밸런스)에 집중되는지
- **원인 후보**:
  - ADV 대비 과도한 주문(impact)
  - 스프레드 큰 바이오 종목이 반복적으로 드나듦

## 5) Regime(레짐) 문제
- **증상**: 전체 평균은 비슷한데 특정 국면에서만 반복 손실(최악 폴드 고정)
- **점검/로그**:
  - 레짐 지표(IEF 모멘텀, SPY vol, XLV/QQQ 상대강도)와 성과의 조건부 평균
  - 레짐 전환 시점의 **drawdown 기여도**
- **원인 후보**:
  - 리스크오프에서 Tech/High-beta가 급락할 때 방어 부재
  - 헬스케어도 바이오 비중이 높으면 방어가 아니라 tail이 됨

## 최종 운영 원칙(우선순위 고정)
- [ ] **E1(누수/서바이버십) 통과 전에는** 어떤 알파/튜닝도 “의미 없음”으로 간주  
- [ ] **E2(비용/턴오버) 없이는** lockbox 개선이 실거래로 연결되지 않는다고 가정  
- [ ] **E3~E4는** E1/E2 통과 후 “최악 폴드/MDD 안정화” 목적의 리스크 패치로만 적용  
- [ ] **E5 텔레메트리 없이는** 정체 원인 규명이 불가능하므로 항상 병행

원하면, 위 E1~E5를 바로 `system_candidates.yaml`에 꽂을 수 있도록 **실험 arm 네이밍/게이트 항목을 동일 키로 정규화**하는 형태(artifact schema)로도 정리해서 제공하겠습니다.
