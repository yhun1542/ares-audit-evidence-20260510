### 1. 24~48시간 긴급 우선순위 (TOP 3)

현재 `exp_mrd_fsa` 후보가 챔피언 대비 수익률(Mean)은 높고 MDD는 절반 수준으로 낮추는 비정상적인 효율성을 보임. 이는 **과최적화(Overfitting)** 또는 **미래 참조(Look-ahead Bias)** 가능성이 매우 높음. 즉시 다음 3가지를 검증하라.

1.  **[검증] Cost Sensitivity Analysis (비용 민감도 테스트)**
    *   **Why:** `tuning_mean`과 `lockbox_mean`의 차이가 큼. 거래 빈도가 늘어나 슬리피지/수수료 반영 시 수익이 급감하는지 확인 필요.
    *   **Action:** 슬리피지를 현재 설정의 2배(예: 5bps -> 10bps)로, 수수료를 $0 -> $0.005/share로 강제 상향 후 재실행.

2.  **[로직] Sector Decoupling (Tech vs Healthcare 분리)**
    *   **Why:** Tech(XLK)와 Healthcare(XLV)는 상관관계가 다름. 통합 모델이 특정 시기(예: 2025년 Tech 랠리)에 편승해 Healthcare의 손실을 가리고 있는지 확인.
    *   **Action:** 포트폴리오 내 섹터 비중 강제 할당(예: Tech Max 60%, Health Max 40%) 또는 섹터별 별도 스코어링 로직 적용.

3.  **[데이터] Feature Count Constraint (피처 개수 제한)**
    *   **Why:** `FSA`(Feature Selection) 이름으로 보아 피처 조합이 복잡해졌을 가능성. 8~14개 종목 소형 유니버스에서 피처가 많으면 노이즈를 학습함.
    *   **Action:** 모델이 사용하는 Top Feature를 3개 이하로 강제 제한(Lasso/Tree Importance 기반)하여 성능 유지 여부 확인.

### 3. 성능 정체 원인 분해 (Debugging Checklist)

만약 위 실험들이 모두 실패하거나 성능이 횡보할 경우, 원인을 아래 4단계로 분해하여 리포팅하라.

1.  **트리거 (Trigger) 과민성:**
    *   *현상:* 매매 횟수가 너무 적거나(주당 1회 미만), 너무 많음(일 10회 이상).
    *   *액션:* 변동성(ATR) 기반 동적 임계값(Dynamic Threshold) 도입 여부 확인.
2.  **노출 (Exposure) 실패:**
    *   *현상:* 시그널은 맞았으나, 포트폴리오 비중이 너무 작아 수익 기여 못함.
    *   *액션:* Volatility Scaling(변동성 역가중) 로직이 과도하게 작동하여 Tech 종목 비중을 0에 가깝게 죽이는지 확인.
3.  **레짐 (Regime) 불일치:**
    *   *현상:* 상승장에서는 벤치마크를 못 따라가고, 하락장에서만 선방함.
    *   *액션:* Bull Market 감지 시 필터를 느슨하게 푸는 'Risk-On' 모듈이 작동하는지 점검. (현재 MDD가 너무 낮은 것은 상승장을 놓치고 있다는 신호일 수 있음).
4.  **유니버스 (Universe) 오염:**
    *   *현상:* 특정 1~2개 종목(예: 소형 바이오)이 전체 수익의 90%를 차지.
    *   *액션:* 종목별 수익 기여도(Contribution) 히트맵 확인. 특정 종목 제외 시 전체 시스템 붕괴 여부 테스트.
