## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — **명령형 체크리스트**
> 우선 점검 순서: **누수 → 과최적화 → 서바이버십 → 비용 미반영 → 운영 리스크**  
> 제안/실험은 **E1~E5 (총 5개)만 수행**하고, 각 TOP5는 이 실험들을 **재사용**해 검증.

---

# TOP1) **누수(lookahead)·정렬(as-of) 방화벽 구축**
### (a) 왜 필요한지
- 현재 `worst_mdd: None` 같은 “리포팅 공백”이 존재 → **백테스트 파이프라인 신뢰성 자체가 불명확**.
- OOS가 좋아 보여도 **타임스탬프 정렬/리밸런스 시점/지표 계산**에서 1틱이라도 미래가 섞이면 OOS_mean이 의미 없어짐.

### (b) 위험/부작용
- 누수 제거 후 성능이 **즉시 하락** 가능(진짜 실력 확인).
- 데이터 준비가 엄격해지며 실험 속도 저하.

### (c) 최소 실험(재사용) 2~3개
- **E1: Time-shift leakage probe**
- **E2: Purged/Embargo walk-forward CV**
- **E5: Inference parity(학습/실행 동형) 테스트** *(운영 시점 누수 포함)*

### (d) PASS 조건
- E1에서 **t+1로 밀면 성능이 유의미하게 붕괴**, t-1로 당기면 개선되지 않음(대칭성 확인).
- E2에서 fold별 성능 분산이 과도하지 않고, `degenerate_folds`가 0 유지.
- E5에서 “백테스트 산출 포지션”과 “실제 실행 엔진 산출 포지션”이 **동일 입력이면 100% 일치**.

---

# TOP2) **과최적화 억제(검증 구조 개편 + 모델 자유도 제한)**
### (a) 왜 필요한지
- 현재 챔피언의 `oos_min`이 낮게 찍히는 편(0.43) → 특정 구간 취약 가능.
- 48시간 자동 루프에서는 “조금씩 튜닝하다가” **검증 구조가 약하면 자동으로 과최적화로 흘러감**.

### (b) 위험/부작용
- 모델/전략 자유도 제한으로 단기 OOS_mean 하락 가능.
- 탐색 공간 축소로 “큰 점프”가 늦게 올 수 있음.

### (c) 최소 실험 2~3개
- **E2: Purged/Embargo walk-forward CV** (고정)
- **E1: Time-shift leakage probe** (누수와 과최적화 동시 방어)
- **E4: 비용/턴오버 sweep** (과최적화가 비용 무시에서 오는 경우 컷)

### (d) PASS 조건
- E2에서 **fold별 성능의 하방(예: 20% 분위수)**이 개선되거나 최소 유지.
- E4에서 비용을 올려도 성능이 **급격히 0 이하로 붕괴하지 않음**(비용 민감도 완화).

---

# TOP3) **서바이버십/유니버스 규율(미국 Tech+Healthcare 8~14 종목)**
### (a) 왜 필요한지
- “미국주식 only, Tech+Healthcare 중심, 8~14”가 규칙이면 유니버스가 작아 **구성 변화(리밸런스/상장폐지/인수합병)**가 성능에 치명적.
- 흔한 함정: 현재 살아남은 대형주 위주로 과거도 동일 종목으로 돌려 **서바이버십 편향** 발생.

### (b) 위험/부작용
- 포인트-인-타임(과거 시점에 존재하던 종목) 강제 시 성능 하락 가능.
- 데이터 소스 품질(상장폐지 가격/정지 처리)에 따라 구현 난이도 상승.

### (c) 최소 실험 2~3개
- **E3: Universe stress test (frozen vs point-in-time/rolling)**
- **E2: Purged walk-forward CV** (유니버스 변경이 fold 성능을 망치지 않는지)
- **E5: 운영 동형 테스트** (티커 변경/스플릿 반영이 실시간에서도 동일한지)

### (d) PASS 조건
- E3에서 유니버스 정의를 바꿔도 핵심 성능이 **동일 방향성** 유지(“유니버스가 성능을 만든다”를 배제).
- 상장폐지/거래정지 이벤트가 있어도 **백테스트가 중단되지 않고**, 포지션이 비정상적으로 0/무한대로 튀지 않음.

---

# TOP4) **비용(수수료·스프레드·슬리피지) + 턴오버/노출 제약을 ‘게이트’로 승격**
### (a) 왜 필요한지
- 지금 노출이 `0.47~0.84`로 꽤 높음 → 실거래에서 비용/슬리피지 영향 큼.
- 비용을 “나중에” 빼면 자동 루프가 **비용 무시한 전략으로 계속 치우침**.

### (b) 위험/부작용
- 비용을 현실화하면 성능이 크게 하락할 수 있음(특히 고회전).
- 지나치게 보수적 비용 가정은 유망 전략을 조기 폐기.

### (c) 최소 실험 2~3개
- **E4: 비용/슬리피지/턴오버 sweep + turnover cap**
- **E2: Walk-forward CV** (비용 포함 시 구간별 안정성 확인)
- **E5: 실행 제약(체결 단위/거래가능성) 동형 테스트**

### (d) PASS 조건
- E4에서 “기준 비용” 대비 2배 비용에서도 **OOS_mean이 양수 유지** 또는 하방이 과도하게 무너지지 않음.
- 턴오버 cap을 걸어도 성능이 **완전 붕괴하지 않고**, 노출/회전이 안정화.

---

# TOP5) **운영 리스크 제거(48시간 자동 루프: 재현성/아티팩트/롤백/모니터링)**
### (a) 왜 필요한지
- 자동 루프에서 가장 비싼 실패는 “성능 저하”가 아니라 **조용한 데이터/코드 드리프트로 잘못된 챔피언이 고정**되는 것.
- `worst_mdd None`은 “리스크 리포트 파이프라인 미완” 신호일 가능성 → 운영 사고로 연결.

### (b) 위험/부작용
- 단기적으로 개발 리소스 소모.
- 게이트 강화로 챔피언 교체 빈도가 줄어 “개선이 안 보이는” 기간이 늘어날 수 있음(정상).

### (c) 최소 실험 2~3개
- **E5: Inference parity + 재현성(시드/데이터 스냅샷) 테스트**
- **E2: Walk-forward CV 결과 아티팩트 고정/검증**
- **E1: 누수 프로브를 CI 게이트로 상시화**

### (d) PASS 조건
- 동일 커밋/동일 데이터 스냅샷에서 결과가 **완전 재현**(해시 동일).
- 챔피언 교체는 “성능”뿐 아니라 **비용/리스크/운영 게이트**를 모두 통과할 때만 발생.
- 리포트에 `worst_mdd`, turnover, 비용, 노출이 **항상 채워짐(None 금지)**.

---

## 48시간 자동 루프에 넣을 **실험 패키지 E1~E5** (각각: 1)정의 2)게이트 3)기대 관측치)

### E1) **Time-shift Leakage Probe**
1) **실험 정의**: 모든 피처/지표/라벨 파이프라인에 대해 입력을 `t→t+1`, `t→t-1`로 인위 이동한 버전을 생성해 동일 학습/검증 실행  
2) **게이트**:  
   - `shift +1` 성능이 기준 대비 **유의미하게 나빠져야 함**  
   - `shift -1`이 기준을 **유의미하게 이기면 즉시 실패(누수 의심)**  
3) **기대 관측치**: 정상 전략이면 `+1`에서 급락, `-1`에서 개선 없음(또는 악화)

### E2) **Purged + Embargo Walk-forward CV (Nested 가능)**
1) **실험 정의**: 리밸런스 주기 기준으로 purge window + embargo를 둔 워크포워드 분할(튜닝이 있으면 nested)  
2) **게이트**: fold별 성능 하방(예: 20% 분위수), fold간 분산, degenerate fold 0  
3) **기대 관측치**: “한두 구간만 잘 먹히는” 전략이 걸러지고, 취약 구간이 명확히 드러남

### E3) **Universe Stress: Frozen 8~14 vs Point-in-time/Rolling**
1) **실험 정의**:  
   - A: 고정 8~14(운영 후보 리스트)  
   - B: 포인트-인-타임/롤링(가능하면 상장폐지/인수합병 반영)  
   동일 전략을 A/B에서 비교  
2) **게이트**: A/B 결과 방향성 일치, 특정 종목/기간에만 의존하지 않음  
3) **기대 관측치**: 서바이버십이면 A에서만 성능이 비정상적으로 높게 나옴

### E4) **Cost/Slippage/Turnover Sweep + Cap**
1) **실험 정의**: 수수료+스프레드+슬리피지를 3단(기준/2배/3배)로 스윕, turnover cap(예: 일/주 기준) on/off  
2) **게이트**: 비용 증가에도 양(+) 성과 유지/급붕괴 방지, turnover 안정화  
3) **기대 관측치**: 진짜 엣지는 비용에 둔감, 가짜 엣지는 비용에서 즉시 소멸

### E5) **Inference Parity + Ops Hardening**
1) **실험 정의**: 백테스트 엔진과 실거래(또는 실거래 모의) 엔진을 동일 입력(가격/캘린더/코퍼액션)으로 돌려 포지션/주문이 동일한지 비교 + 아티팩트(데이터 스냅샷/모델) 해시 고정  
2) **게이트**: 포지션/시그널 100% 일치, 리포트 지표 None 금지, 실패 시 자동 롤백  
3) **기대 관측치**: 운영 드리프트/캘린더/코퍼액션 문제를 조기에 탐지

# 성능이 “안 움직일 때” 원인 분해 아이디어 (트리거/적용/노출/비용/레짐)
아래를 **로그 지표로 고정**하고, 변화가 멈춘 지점을 자동으로 분류(원인 태깅)하도록 구성.

## 1) Trigger(신호 발생) 문제
- 체크: **신호 발생 빈도**, 신호 강도 분포(quantile), 0 신호 비율
- 트리거 불능 징후: 신호가 과거 대비 급감/급증, 특정 시간대만 발생
- 처방 연결: E1(누수/정렬), E5(운영 동형), 캘린더/휴장/분할 반영 점검

## 2) Apply(적용/체결/리밸런스) 문제
- 체크: 목표 포지션 대비 실제 포지션 추적 오차, 리밸런스 지연, 주문 거절/가격결측
- 적용 실패 징후: 백테스트는 바뀌는데 실거래(모의)는 포지션이 정체
- 처방 연결: E5(동형/재현성), 거래가능성(거래정지/급락락) 처리

## 3) Exposure(노출/포지션 크기) 문제
- 체크: 평균/최대 노출, 순/총 노출, 종목 편중(HHI), 섹터 편중(Tech/HC 내)
- 노출 정체 징후: 노출이 상한에 붙어서 더 이상 알파 반영 불가, 혹은 하한에 붙어서 거의 현금화
- 처방 연결: E4(turnover cap과 함께), 리스크 오버레이(E5 결과로 리포트 고정)

## 4) Cost(비용) 문제
- 체크: **총 비용 기여도**, 매매당 기대수익 대비 비용 비율, 턴오버
- 비용 잠식 징후: 총 PnL은 제자리인데 Gross는 움직임(=비용이 먹음)
- 처방 연결: E4(비용 스윕), 리밸런스 빈도/임계값 상향

## 5) Regime(레짐) 문제 — ETF는 “관측지표”로만 사용
- 관측지표 예시(매매 금지): **XLK, XLV, IBB, VIX, UST 2Y/10Y**
- 체크:  
  - XLK vs XLV 상대강도(Tech/HC 선호 레짐)  
  - 변동성(VIX) 상/하 구간 성과 분해  
  - 금리(2Y/10Y) 급변 구간 성과 분해
- 레짐 미스 징후: 특정 레짐에서만 일관된 손실
- 처방: 레짐 필터를 “추가”하기 전에 **리포트 분해로 레짐 의존성부터 확정**(E2 fold와 교차)

---

## 마지막으로: 24~48시간 실행 순서(명령형)
1) **E5 먼저**: 리포트에서 `worst_mdd None` 제거, 재현성/동형성 게이트를 CI로 고정  
2) **E1 실행**: time-shift 프로브로 누수 여부를 단번에 판정  
3) **E2 실행**: purged/embargo walk-forward로 과최적화/구간취약 확인  
4) **E4 실행**: 비용/슬리피지/턴오버 스윕으로 “실거래 가능 엣지”만 남김  
5) **E3 실행**: 8~14 유니버스 서바이버십 스트레스 테스트로 유니버스 의존 제거  

위 5개(E1~E5) 결과가 모이면, 다음 사이클에서 “전략 아이디어 추가”가 아니라 **어느 축(트리거/적용/노출/비용/레짐)이 막혔는지**가 자동으로 라벨링되게 됩니다.
