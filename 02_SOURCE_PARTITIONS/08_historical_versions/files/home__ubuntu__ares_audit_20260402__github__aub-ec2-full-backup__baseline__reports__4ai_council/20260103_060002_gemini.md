[우선순위 TOP 5 명령형 체크리스트]

1.  **[CRITICAL] Degenerate Folds(1,2,3,8) 해결**: 40%의 Fold가 거래가 없거나(Flat) 손실이 미미함. 이는 과적합 혹은 데이터 누락을 의미. 예측 Threshold를 강제로 낮춰 거래를 발생시켜야 함.
2.  **[CRITICAL] Rebalance Log 파이프라인 복구**: `Errno 2`, `JSON parse error`로 인해 거래 비용/슬리피지가 반영된 '진짜 수익률' 확인 불가. 로깅 포맷 통일 및 경로 수정 즉시 적용.
3.  **Look-ahead Bias(선견 편향) 점검**: `oos_mean: 3.32`는 현실적으로 지나치게 높음. Feature 생성 시점과 Target 시점 간의 Lag가 정확히 적용되었는지 확인 (Close-to-Close vs Open-to-Close).
4.  **Universe Survivorship 점검**: 과거 Fold(1,2,3)에서 Tech/Healthcare 8~14개 종목의 데이터가 존재하는지 확인. 상장 폐지/합병 전 데이터가 없어 거래를 못 했을 가능성.
5.  **Cost Model 강화**: 현재 비용 미반영 가능성 높음. 슬리피지(5bps)와 수수료(10bps) 강제 주입 후 성능 하락폭 관측.

### [제안 1] Degenerate Folds 활성화 (Threshold Relaxation)

*   **(a) 필요성**: Fold 1, 2, 3, 8이 'Degenerate' 상태(거래 없음 또는 상수 예측)임. 모델이 특정 구간에서 Risk 회피가 아닌 '작동 불능' 상태일 확률 높음.
*   **(b) 위험/부작용**: 거래 횟수 급증으로 인한 수수료 폭탄, MDD 증가 가능성.
*   **(c) 실행 실험 (Patch/Experiment)**:
    1.  **EXP_LOWER_THR**: 진입/청산 Threshold를 현재 값의 50%로 하향 조정 (예: 0.5 -> 0.25).
    2.  **EXP_FORCE_MIN_EXP**: 포트폴리오 최소 노출도(Exposure)를 0.1로 강제 설정하여 Cash 100% 방지.
    3.  **EXP_NO_REGULARIZATION**: 모델의 Regularization(L1/L2) 강도를 1/10로 줄여 과소적합 탈피.
*   **(d) PASS 조건**:
    *   `degenerate_folds` 개수가 0 또는 1로 감소.
    *   `worst_mdd`가 `None`이 아닌 유효한 수치(예: -0.05 ~ -0.15)로 잡힐 것.

### [제안 2] 데이터 누수 및 비용 검증 (Leakage & Cost Audit)

*   **(a) 필요성**: `oos_mean: 3.32`는 비정상적. 미래 데이터를 참조했거나 비용이 0일 가능성 99%. Rebalance Log 오류로 검증조차 안 됨.
*   **(b) 위험/부작용**: 성능(Sharpe/Mean)이 급락하여 기존 챔피언 폐기 가능성 (그러나 이것이 진실임).
*   **(c) 실행 실험 (Patch/Experiment)**:
    1.  **EXP_LAG_INJECTION**: 모든 기술적 지표 계산 후 `shift(1)` 강제 적용 재학습.
    2.  **EXP_HIGH_COST**: 편도 거래 비용을 15bps(0.15%)로 설정하고 백테스트 수행.
    3.  **EXP_FIX_LOG**: `aub_rebalance_pinpoint.py`가 읽을 수 있도록 JSONL 포맷 로깅 코드 수정 및 재실행.
*   **(d) PASS 조건**:
    *   `oos_mean`이 0.5 ~ 1.5 수준으로 하락하더라도 `oos_min`이 -0.1 이상 방어.
    *   로그 파일 정상 생성 및 비용 차감 확인.

### [제안 3] 유니버스 및 섹터 밸런스 점검 (Universe Density)

*   **(a) 필요성**: Tech/Healthcare 중심이나, 과거 시점(Fold 1~3)에 해당 티커들의 유효 데이터가 부족할 수 있음.
*   **(b) 위험/부작용**: 유니버스 교체 시 전체 파이프라인 재학습 비용 발생.
*   **(c) 실행 실험 (Patch/Experiment)**:
    1.  **EXP_UNIVERSE_FILL**: 결측치가 많은 종목 제외하고, S&P500 내 Tech/HC 대형주(상장 10년 이상)로 교체.
    2.  **EXP_SECTOR_HEDGE**: Tech/HC 종목 롱 + XLK/XLV(ETF) 인버스 시그널을 Feature로 추가(매매는 안 함).
*   **(d) PASS 조건**:
    *   모든 Fold에서 일평균 거래 대금이 0보다 클 것.
    *   특정 섹터(Tech) 폭락 구간에서 숏/현금화가 작동하는지 확인.

### [48시간 자동 루프 정의]

**Cycle 1: Degenerate Debugging (0h - 24h)**
1.  **실험 정의**: `EXP_LOWER_THR` (Threshold 0.5x), `EXP_FIX_LOG` (로깅 수정).
2.  **게이트 (Gate)**:
    *   `degenerate_folds` 리스트가 비어있거나 `[ ]`로 변해야 함.
    *   Rebalance Log 파일 크기 > 0KB.
3.  **기대 관측치**: `oos_mean` 하락 예상, 그러나 거래 빈도(Turnover) 상승 및 MDD 측정 가능해짐.

**Cycle 2: Cost & Leakage Check (24h - 48h)**
1.  **실험 정의**: Cycle 1 통과 모델에 `EXP_HIGH_COST` (15bps) 적용 + `EXP_LAG_INJECTION`.
2.  **게이트 (Gate)**:
    *   OOS Sharpe Ratio > 1.0 유지.
    *   비용 반영 후에도 우상향 곡선 유지.
3.  **기대 관측치**: 거품 제거된 현실적인 수익률 곡선 확인.

### [성능 정체 원인 분해 아이디어]

만약 위 조치에도 성능이 제자리라면 다음 트리를 점검:

1.  **트리거 (Trigger) 실패**:
    *   시그널이 발생하지만 `Order Execution` 단계에서 잔고 부족/슬리피지 제한으로 거절되는가? -> **체결 로그 확인.**
2.  **적용 (Application) 실패**:
    *   `run_hash`는 바뀌는데 실제 가중치(Weight) 파일이 업데이트 안 되는가? -> **Artifact 경로 해시 충돌 점검.**
3.  **노출 (Exposure) 부족**:
    *   베팅 사이즈(Position Sizing) 로직이 Volatility를 너무 높게 평가하여 사이즈를 0으로 줄이는가? -> **Vol Targeting 로직 완화.**
4.  **레짐 (Regime) 불일치**:
    *   학습 데이터(과거)와 검증 데이터(미래)의 시장 구조(상승장 vs 횡보장)가 정반대인가? -> **Regime classifier 정확도 확인.**
