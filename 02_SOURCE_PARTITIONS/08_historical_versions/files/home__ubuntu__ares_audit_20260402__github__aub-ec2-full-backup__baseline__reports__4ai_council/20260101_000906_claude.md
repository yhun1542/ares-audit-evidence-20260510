## 1. 우선순위 TOP 5 패치/실험

---

### PATCH-1: 포지션 사이징 누수 점검
**우선도: P0 (즉시)**

#### (a) 왜 필요한지
- lockbox 결과가 candidate 간 동일 → 사이징 로직이 실제로 적용 안 되고 있을 가능성
- 로그상 모듈 호출은 되나 weight가 덮어쓰기될 수 있음

#### (b) 위험/부작용
- 디버그 오버헤드 (2~4시간)
- 잘못 수정 시 전체 파이프라인 break

#### (c) 최소 실험

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P1-E1 | `--dry-run` 모드에서 weight 변화 로그 추가 | 로그 파일 생성 | weight ≠ 0 인 변경 최소 1회/폴드 |
| P1-E2 | 강제로 sizing=0.5 고정 후 lockbox 재실행 | lockbox 결과 ≠ 현재 | mean 변화폭 ≥ 0.05 |
| P1-E3 | module_registry에서 sizing 모듈 disable 후 비교 | 결과 동일하면 누수 확정 | champion과 차이 無 = 누수 |

#### (d) PASS 조건
```
P1-E2 결과 변화폭 ≥ 0.05 AND P1-E3 결과 ≠ champion
→ 누수 없음 확인 → PASS
```

---

### PATCH-2: 레짐 필터 실효성 검증
**우선도: P0**

#### (a) 왜 필요한지
- 동일 MDD 유지 → 레짐 필터가 drawdown 구간에서 작동 안 할 가능성
- 과최적화 or 임계값이 현재 시장에 무효화

#### (b) 위험/부작용
- 필터 해제 시 MDD 악화 가능
- 백테스트 시간 증가

#### (c) 최소 실험

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P2-E1 | 레짐 필터 완전 disable 후 lockbox | MDD 변화 관측 | worst_mdd ≤ -15% (악화) |
| P2-E2 | 필터 임계값 ±20% 조정 (2개 variant) | 최소 1개 lockbox_mean > 1.80 | 분산 > 0.02 |

#### (d) PASS 조건
```
P2-E1 MDD 악화 ≥ 3%p → 필터 작동 확인 → PASS
```

### PATCH-3: 비용 모델 현실화
**우선도: P1**

#### (a) 왜 필요한지
- 현재 slippage/commission 설정 미확인
- 실거래 대비 낙관적 가정 시 lockbox 수익률 과대평가

#### (b) 위험/부작용
- 비용 상향 시 수익률 급락 → 전략 폐기 리스크
- 과소 설정 시 실전 괴리

#### (c) 최소 실험

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P3-E1 | slippage 0bp → 10bp 변경 | lockbox_mean 변화 | Δ ≥ -0.05 허용, 그 이상이면 위험 신호 |
| P3-E2 | commission 0 → 0.1% 왕복 적용 | 동일 | Δ ≤ -0.10 이면 비용 민감도 과다 |

#### (d) PASS 조건
```
P3-E1 + P3-E2 합산 Δ ≤ -0.15 → 비용 민감도 수용 범위 → PASS
비용 반영 후 lockbox_mean ≥ 1.60 유지 필수
```

- 분산 강제 시 alpha 희석
- 유니버스 변경은 백테스트 전체 재실행 필요

#### (c) 최소 실험

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P4-E1 | 현재 포트폴리오 Top3 종목 weight 합계 로그 | 매 폴드 출력 | Top3 ≤ 60% |
| P4-E2 | 강제 cap 40% per stock 적용 | lockbox 재실행 | MDD 개선 or 동일 |

#### (d) PASS 조건
```
P4-E1 Top3 ≤ 60% 전 폴드 충족 → 집중도 정상 → PASS
```

### PATCH-5: 시그널 트리거 빈도 점검
**우선도: P2**

#### (a) 왜 필요한지
- 성능 불변 = 트리거 자체가 희소하여 포지션 변경 미발생 가능
- 과민 필터로 인한 "항상 현금" 상태 점검

#### (b) 위험/부작용
- 트리거 완화 시 과잉매매 → 비용 증가

#### (c) 최소 실험

| ID | 실험 정의 | 게이트 | 기대 관측치 |
|----|-----------|--------|-------------|
| P5-E1 | 폴드별 trade count 로그 추가 | 파일 생성 | 월평균 ≥ 2회 |
| P5-E2 | 시그널 임계값 -10% 완화 variant | lockbox 비교 | trade count 증가 ≥ 30% |

#### (d) PASS 조건
```
P5-E1 월평균 ≥ 2회 → 트리거 정상 → PASS
< 1회 시 PATCH-5-E2 필수 실행
```
