(절대 우선: **누수/과최적화/서바이버십/비용 미반영/운영 리스크**)

## TOP5 우선순위(코드/아키텍처/전략)

### 1) (최우선) 시간누수/리벨링 누수 차단(ASOF/시차/리밸런스 캘린더)
**(a) 왜 필요한지**  
- 지금 지표는 lockbox가 좋지만, 누수는 “특정 폴드/구간에서만” 성능을 띄우고 **min(최악)**·**tail**을 망가뜨리거나, 실거래에서 즉시 붕괴합니다.  
- 특히 Tech/Healthcare는 실적/가이던스 이벤트로 **데이터 timestamp/가용시점**이 조금만 어긋나도 누수가 자주 발생.

**(b) 위험/부작용**  
- 누수를 제거하면 단기적으로 성능이 떨어질 수 있음(“진짜 실력”만 남음).  
- 학습/검증 코드에 **purged/embargo** 들어가면 학습 데이터가 줄어 분산 증가.

**(c) 최소 실험(통합 실험 E1에 포함; 1개의 실험 안에 2~3개 체크를 묶음)**  
- E1-1: 모든 feature/label을 **asof-merge 강제**(미래 row 접근 차단)  
- E1-2: 리밸런스 시점 기준 **t+1(or t+2) 실행 지연** 강제(신호-체결 시차)  
- E1-3: **Purged K-fold + embargo**로 교차검증(이벤트/자기상관 누수 차단)

**(d) PASS 조건**  
- 누수 차단 후에도:  
  - `lockbox_mean` **하락폭 ≤ 1%p** (또는 유지/상승)  
  - `worst_mdd` **악화 금지**(현재 -0.0902보다 더 나빠지면 FAIL)  
  - “min”/tail 지표(최악 구간) 악화 시 FAIL (특히 tuning_min 같은 극단치가 더 커지면 중단)

---

### 2) 서바이버십/상폐/기업행동(CA) 반영(“살아남은 종목만” 방지)
**(a) 왜 필요한지**  
- Tech/Healthcare는 합병/상폐/스핀오프 빈도가 높아 **상폐 수익률/CA 미반영**이면 과대평가가 흔함.  
- 특히 “우주(universe) 구성”이 현재 종목 리스트 기반이면 서바이버십이 자동으로 들어감.

**(b) 위험/부작용**  
- 데이터 소스/파이프라인 복잡도 증가, 재현성 이슈(데이터 버전 고정 필요).  
- 과거 성과가 내려갈 가능성 큼(정상).

**(c) 최소 실험(통합 실험 E2로)**  
- E2-1: **Point-in-time universe**(당시 상장/거래 가능 종목만)로 재구성  
- E2-2: **상폐/합병 종목의 delisting return** 포함 재백테스트  
- E2-3: split/dividend 등 **기업행동 조정**을 “가격/수익률 한쪽만” 하지 않도록 일관화

**(d) PASS 조건**  
- 서바이버십 제거 후:  
  - `lockbox_mean` **유지 또는 -2%p 이내 감소**(감소폭이 크면 전략이 서바이버십 의존)  
  - `worst_mdd` 악화 금지  
  - 특정 기간(예: 2020~2022 변동성 구간)에서 성능이 급락하면 FAIL → 해당 구간 원인 추적(섹터/베타/이벤트)

---

### 3) 비용(슬리피지/스프레드/회전율) 미반영 제거 + “실거래 가능한” 회전율 게이트
**(a) 왜 필요한지**  
- 8~14종목 집중 포트는 리밸런스가 잦으면 비용이 곧 PnL을 잡아먹음.  
- lockbox가 좋아도 비용을 넣으면 알파가 사라지는 케이스가 가장 흔함.

**(b) 위험/부작용**  
- 비용 모델이 과보수면 좋은 전략을 죽임(하지만 운영 관점에선 보수적이 더 안전).  
- 회전율 억제는 레짐 전환 대응이 느려질 수 있음.

**(c) 최소 실험(통합 실험 E3로)**  
- E3-1: **거래비용 모델**(고정 + 스프레드 기반 + ADV 기반 market impact) 추가  
- E3-2: 최적화/스코어링에 **turnover penalty** 또는 **max turnover cap** 추가  
- E3-3: (숏이 있으면) **borrow cost/locate 불가**를 보수적으로 반영, 아니면 long-only로 고정

**(d) PASS 조건**  
- 비용 반영 후에도:  
  - `lockbox_mean` **유지 또는 개선**(최소한 의미 있는 하락 금지: -1%p 초과 하락 시 FAIL)  
  - 평균 회전율이 목표 상한(예: 주간 50~100% 등 내부 기준) 초과 시 FAIL  
  - tail 구간에서 비용이 손실을 확대하면 FAIL(“손절+재진입” 과잉 여부 점검)

---

### 4) 노출(Exposure) 통제: Tech+Healthcare 내부에서만 알파를 만들고, 레짐 필터는 “ETF 관측지표”로만
**(a) 왜 필요한지**  
- “성과가 안 움직임”은 종종 알파가 아니라 **베타/변동성/금리 레짐** 노출로 먹고 있는 경우.  
- ETF는 매매 금지지만 **레짐 관측(금리/성장/리스크온오프)**에 매우 유효.

**(b) 위험/부작용**  
- 과도한 중립화는 알파까지 제거할 수 있음.  
- 레짐 필터는 과최적화되면 “신호 차단기”가 되어 기회를 놓침.

**(c) 최소 실험(통합 실험 E4로)**  
- E4-1: **8~14종목**, **Tech+Healthcare만**, 섹터 비중 상/하한(예: 각 섹터 최소 25% 등) 게이트  
- E4-2: ETF 관측지표(예: QQQ/XLK/XLV, IEF/TLT, HYG 등)로 **레짐 상태(리스크온/오프, 금리상승/하락)** 분류 → 포지션 사이징만 조정(매매는 종목만)  
- E4-3: 베타/변동성/모멘텀(팩터) 노출 로그를 저장하고 **노출 예산 초과 시 리밸런스 억제**

**(d) PASS 조건**  
- 레짐/노출 게이트 적용 후:  
  - `worst_mdd` 개선 또는 동일(악화 금지)  
  - 성과가 유지되면서 노출 변동(베타/변동성)이 줄어들 것(관측치로 확인)  
  - 종목 수(8~14) 및 섹터 제약 위반 0건

---

### 5) 운영 리스크: 48시간 무인 루프에서 “재현성/데이터 신선도/실패 안전장치” 고정
**(a) 왜 필요한지**  
- 운영에서 가장 자주 나는 사고는 “전략이 나빠서”가 아니라 **데이터/버전/스케줄/예외처리**입니다.  
- 자동 루프는 작은 nondeterminism이 누적되면 성과 비교가 무의미해짐.

**(b) 위험/부작용**  
- 로깅/검증이 늘어나 실행 시간이 증가.  
- 일부 실패를 “조기 중단”시켜 탐색 폭이 줄 수 있음(하지만 안전이 우선).

**(c) 최소 실험(별도 실험으로 만들지 말고, E1~E4 공통 게이트로 포함)**  
- seed 고정 + 데이터 버전 해시 + 결과물 체크섬  
- 데이터 freshness/결측률/이상치 모니터링(실패 시 거래/학습 중단)  
- 장애 시 “마지막 champion 유지” + 알림/리포트 자동 생성

**(d) PASS 조건**  
- 48시간 동안: 동일 입력이면 결과 재현(지표 편차 허용범위 내)  
- 데이터 결측/지연 발생 시 **안전 중단**이 정상 동작  
- champion 파일/리포트가 항상 생성되고, 비교가 가능할 것

## 48시간 자동 루프용 “실행 가능한 Patch/실험” (총 4개만)

아래 4개만 돌리면 위 TOP5를 대부분 커버합니다(케이스 폭발 방지).

### [E1] Temporal Integrity Patch (누수 차단)
**(1) 실험 정의(명령형 체크리스트)**  
- ASOF merge 강제 + 미래값 접근 차단  
- 신호→체결 지연(t+1/t+2) 옵션 고정  
- Purged K-fold + embargo 적용

**(2) 게이트**  
- 누수 의심 패턴(특정 폴드만 급등, 극단 min 확대) 나오면 즉시 FAIL  
- lockbox_mean 하락폭 > 1%p면 FAIL

**(3) 기대 관측치**  
- 평균 성과는 비슷하거나 소폭 하락 가능  
- tail/최악구간 지표가 “더 현실적으로” 안정화되는 방향

---

### [E2] Survivorship + Corporate Actions Patch
**(1) 실험 정의**  
- Point-in-time universe로 재생성  
- delisting return 포함  
- split/dividend 조정 일관화

**(2) 게이트**  
- 특정 기간 성능 붕괴 시(예: 한 레짐에서만 급락) 원인 로그(우주 변화/상폐 이벤트) 없으면 FAIL

**(3) 기대 관측치**  
- 과대평가가 제거되며 평균 성과가 내려갈 수 있으나, 운영 신뢰도 상승  
- “이상하게 좋던” 구간이 정상화

---

### [E3] Cost-aware Backtest + Turnover Control Patch
**(1) 실험 정의**  
- 스프레드/ADV 기반 슬리피지 + 고정수수료 반영  
- turnover penalty 또는 cap 도입  
- (숏이면) borrow cost 보수 반영 / 아니면 long-only 고정

**(2) 게이트**  
- 비용 반영 후 lockbox_mean -1%p 초과 하락이면 FAIL  
- 회전율 상한 위반 지속 시 FAIL

**(3) 기대 관측치**  
- “자주 갈아타서 먹던 성과”가 줄고, 남는 알파만 확인 가능  
- MDD가 개선되거나 변동이 줄어드는 경향

---

### [E4] Exposure + Regime Gate Patch (ETF는 관측만)
**(1) 실험 정의**  
- 종목수 8~14, Tech+Healthcare만 강제  
- ETF 관측(예: QQQ/XLK/XLV + IEF/TLT)로 레짐 분류 → 사이징/리밸런스 강도만 조절  
- 베타/변동성/팩터 노출 예산 초과 시 리밸런스 억제

**(2) 게이트**  
- worst_mdd 악화 금지  
- 제약 위반 0건(섹터/종목수)

**(3) 기대 관측치**  
- 레짐 나쁠 때 노출 축소로 tail 방어  
- 성과가 “안 움직이는” 원인이 베타였는지 분해 가능

## “성능이 안 움직일 때” 원인 분해 아이디어 (트리거→적용→노출→비용→레짐)
아래 트리는 질문 없이 그대로 로그/리포트 항목으로 추가해서 원인을 쪼개면 됩니다.

### A) Trigger(신호 자체가 약함)
- **IC/RankIC**(예측 스코어 vs 다음기간 수익) 평균/분산/레짐별  
- 신호의 **staleness**: 같은 종목이 며칠 연속 동일 신호인지(업데이트가 없는지)  
- 신호 분포 붕괴: 상/하위 분위 간 스프레드가 줄었는지

### B) Apply(신호가 포지션으로 제대로 변환되지 않음)
- 리밸런스 후 실제 보유가 “목표”를 따라갔는지(제약 때문에 눌리는지)  
- 종목수 8~14 제약 때문에 **상위 신호가 잘리는 비율**  
- 포지션 한도/섹터 한도에 의해 신호가 상시 클리핑되는지

### C) Exposure(알파가 아니라 베타/팩터 노출)
- 포트폴리오 **시장베타, 섹터베타, 금리 민감도**(관측 ETF/지수로 회귀)  
- 변동성 타게팅이 없으면, 성과 정체가 “변동성 확대 구간에서 사이징 과대” 때문인지  
- Tech vs Healthcare 내부 로테이션에 의해 한쪽에 쏠려 손익이 상쇄되는지

### D) Cost(비용이 알파를 상쇄)
- turnover × (스프레드/슬리피지)로 **비용 기여분(%)**을 분리  
- “손절-재진입” 반복으로 소액 손실이 누적되는지(거래 빈도/평균 보유기간)  
- 대형주/중소형주로 나눠 비용 민감도 비교(ADV 대비 주문비율)

### E) Regime(레짐 미스매치)
- ETF 관측(QQQ/XLK/XLV + IEF/TLT 등)로 레짐을 2~4개로 나눠  
  - 레짐별 평균/최악/승률/회전율을 테이블로 고정 출력  
- “좋았던 레짐”이 사라졌는지 vs “나쁜 레짐”에서만 돈을 잃는지

---

이 4개(E1~E4)만 48시간 루프에 태우면, **누수/서바이버십/비용/노출/레짐/운영**을 한 번에 정리하면서도 실험 수를 통제할 수 있습니다.
