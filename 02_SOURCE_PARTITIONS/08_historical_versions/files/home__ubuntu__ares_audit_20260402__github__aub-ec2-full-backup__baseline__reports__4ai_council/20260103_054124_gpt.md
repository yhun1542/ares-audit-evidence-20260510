아래는 **다음 24~48시간** 동안 “성능 정체(no-delta) + 리스크(누수/과최적화/서바이버십/비용 미반영/운영)”를 **우선 제거**하면서, **미국주식(Tech+Healthcare, 8~14종목, ETF는 지표만)** 조건에서 **48시간 자동 루프**로 돌릴 수 있는 **TOP5 우선순위**입니다.  
(실험은 **총 4개 패키지(E1~E4)**로 제한하고, 각 제안은 그 안의 **2~3개 변형(variant)**으로 처리합니다.)

## TOP5 우선순위 (24~48h)

### 1) [운영/코드] 리밸런스 로그/아티팩트 파이프라인 복구 (현재 에러 즉시 차단)
**(a) 왜 필요한지**
- `aub_rebalance_pinpoint`가 **입력 파일 미존재/JSON 파싱 실패**로 리밸런스 원인 분석이 불가.
- “성능이 안 움직임”의 1순위 원인은 종종 **실제로는 리밸런스/거래가 안 일어났거나, 로그가 깨져서 관측이 불가능**한 운영 이슈.
- `worst_mdd: None`, `lane_hash/run_hash: None`도 **메트릭/추적 누락** 신호.

**(b) 위험/부작용**
- 로깅 강화로 디스크/IO 증가, 런타임 소폭 증가.
- 스키마 강제 시 기존 아티팩트 일부가 실패할 수 있음(의도된 fail-fast).

**(c) 최소 실험 2~3개 (E1 패키지로 처리)**
- **E1-V1 (Schema fail-fast)**: 리밸런스 로그를 **반드시 JSONL(한 줄=한 이벤트) + schema validation**으로 저장. 누락/파싱 실패 시 실험 자체를 FAIL로 종료.
- **E1-V2 (Dual-write)**: JSONL + CSV를 **동시 생성**(pinpoint 도구는 CSV, 진단은 JSONL).
- **E1-V3 (Artifact contract test)**: 백테스트 종료 시 `rebalance.jsonl`, `orders.jsonl`, `fills.jsonl`, `metrics.json` 존재/0바이트 검사 + 해시 기록(lane_hash/run_hash 강제).

**(d) PASS 조건 (게이트)**
- 100% 런에서 `rebalance_*` 로드 성공(파싱 오류 0).
- `worst_mdd` 값이 None이 아닌 숫자로 기록.
- `lane_hash/run_hash`가 항상 채워지고, 재현 실행에서 동일 설정이면 동일 hash.

### 2) [리서치/평가] 누수/폴드 퇴화(degenerate_folds) 제거: Purged Walk-Forward + Fold Health Gate
**(a) 왜 필요한지**
- 현재 `degenerate_folds: [1,2,3,8]`는 **(i) 데이터/레이블 누수, (ii) 트레이드 0건, (iii) 상수 예측, (iv) 종목/기간 편중** 중 하나일 확률이 높음.
- OOS mean이 높아 보여도 **누수/폴드 퇴화가 있으면 신뢰 불가**.

**(b) 위험/부작용**
- 더 엄격한 CV로 OOS 성능 하락 가능(진짜 성능만 남음).
- 데이터 부족 구간에서 트레이드 수가 줄어 분산↑.

**(c) 최소 실험 2~3개 (E2 패키지로 처리)**
- **E2-V1 (Purged + Embargo)**: 이벤트/피처가 겹치는 구간 제거(lookahead 차단) + embargo(예: 5~20 거래일 범위로 고정).
- **E2-V2 (Walk-forward + minimum trades)**: 순차적 walk-forward 폴드로 변경하고 **폴드별 최소 트레이드 수/리밸런스 수 게이트** 추가(미달 시 FAIL).
- **E2-V3 (Ticker-group split stress)**: 동일 기간이라도 ticker 기준 그룹 분리로 “종목 간 정보누수/유니버스 치팅” 스트레스 테스트.

**(d) PASS 조건 (게이트)**
- degenerate_folds 비율 ≤ 10% (또는 0개 목표).
- 각 폴드: 트레이드 수/리밸런스 수가 최소치 이상(예: 리밸런스 10회 이상)이고, 포지션이 상수(항상 0 또는 항상 풀투자)가 아님.
- OOS mean이 하락하더라도 **폴드 분산 감소 + 극단 폴드 제거**가 확인되면 PASS(“신뢰도 개선”이 목표).

### 3) [전략/현실성] 비용(슬리피지/스프레드/대차/수수료) + 턴오버 캡을 “게이트”로 승격
**(a) 왜 필요한지**
- “성능이 안 움직임”은 종종 **비용을 반영하면 미세 알파가 소거**되거나, 반대로 비용을 안 넣으면 과대추정.
- Tech/Healthcare는 대형주도 많지만, 8~14종목 집중이면 **리밸런스 잦을 때 비용 민감**.

**(b) 위험/부작용**
- 비용을 올리면 성능 급락 가능(하지만 그게 현실).
- 턴오버 캡은 기회손실(신호가 좋아도 못 바꿈).

**(c) 최소 실험 2~3개 (E3 패키지로 처리)**
- **E3-V1 (Cost tier sweep)**: Low/Base/High 3단 비용(스프레드+슬리피지)로 동일 전략 재평가.
- **E3-V2 (Borrow/short add-on)**: 숏이 존재하면 대차비용/제약(하드투보로우는 거래 불가 또는 비용 가중) 추가.
- **E3-V3 (Turnover cap)**: 일/주간 턴오버 상한(예: 주간 100% 등) + 위반 시 주문 축소(re-scale) 규칙 적용.

**(d) PASS 조건 (게이트)**
- Base~High 비용에서도 OOS mean이 **부호 유지(+)** 또는 성능 하락폭이 “턴오버 감소와 함께” 설명 가능.
- 턴오버 캡 적용 후 **거래 수/비용/순수익(After cost) 분해**에서 비용 기여도가 통제되는 방향으로 이동.

---

### 4) [포트폴리오] 8~14종목 강제 + 유동성/집중도/익스포저 규칙으로 “퇴화 노출” 방지
**(a) 왜 필요한지**
- 현재 `exposure_min/max: 0.0 / 0.8388`는 구간에 따라 **현금화(0) 또는 애매한 부분 투자**가 반복될 수 있음. 이게 의도인지(리스크오프) 아니면 신호/리밸런스 문제인지 분리 필요.
- 8~14종목 규칙이 없으면 “우연히 몇 종목에 과집중” → 과최적화/서바이버십처럼 보일 위험.

**(b) 위험/부작용**
- 종목수 강제는 신호 약할 때 억지 매수/매도로 성능 저하 가능.
- 유동성 필터는 기회 축소.

**(c) 최소 실험 2~3개 (E4 패키지의 구성요소로 처리)**
- **E4-V1 (Holdings count constraint)**: 항상 보유 종목 수를 8~14로 유지(신호 부족 시: 상위 점수에서 채우되 개별 비중 상한).
- **E4-V2 (Liquidity + position cap)**: ADV/달러거래대금 하한, 단일종목 최대비중(예: 12~15%), 섹터 편중 상한(Tech/HC 내에서도 과편중 방지).
- **E4-V3 (Exposure floor/ceiling with “cash = regime” 분리)**: 익스포저 0이 “신호 부재” 때문인지 “레짐 게이트” 때문인지 분리. (레짐 OFF일 때만 0 허용, 그 외엔 최소 익스포저 적용)

**(d) PASS 조건 (게이트)**
- 전 기간에서 보유 종목 수 규칙 위반률 0.
- 최대 단일비중, 유동성 조건 위반률 0.
- 익스포저 0 발생 시점이 **레짐 OFF와 90% 이상 일치**(의도된 현금화로 설명 가능).

### 5) [레짐/헤지] ETF는 “관측 지표”로만 사용: 레짐 게이트가 실제로 성능/리스크를 움직이는지 검증
**(a) 왜 필요한지**
- Tech/Healthcare는 금리/리스크온오프에 민감. 레짐을 안 나누면 한 레짐 최적화가 다른 레짐에서 상쇄되어 “평균적으로 안 움직임”이 자주 발생.
- ETF 매매는 금지지만, **QQQ/XLK/XLV/IHI, SPY, VIX(또는 VIX proxy), UST10Y** 등은 레짐 지표로 강력.

**(b) 위험/부작용**
- 레짐 게이트가 과하게 작동하면 트레이드 기회 감소(언더퍼폼).
- 레짐 지표 자체가 누수(미래 값)로 들어가면 치명적 → 반드시 시점정합/지연 적용.

**(c) 최소 실험 2~3개 (E4 패키지에 포함)**
- **E4-V4 (Risk-on/off gate)**: (예) QQQ 50D/200D 추세 + VIX 상단 임계 조합으로 익스포저 스케일링(매매는 개별주만).
- **E4-V5 (Sector relative regime)**: XLK/XLV 상대강도(지표)로 Tech vs HC 가중치 틸트.
- **E4-V6 (Rates sensitivity gate)**: 10Y 금리 상승 구간에서 성장주(Tech) 익스포저 상한, HC 방어적 상향(단, 종목은 Tech/HC 내에서만).

**(d) PASS 조건 (게이트)**
- 레짐 ON/OFF에 따라 **(i) 변동성, (ii) MDD, (iii) 비용 이후 수익** 중 최소 2개가 개선.
- 레짐 지표는 모두 **지연(예: t-1)** 적용, 누수 테스트(E2)에서 통과.

# 48시간 자동 루프용 “실험 패키지 4개” (정의/게이트/기대 관측치)

## E1. 로깅/아티팩트 계약 테스트(운영 안정화)
- **(1) 실험 정의**: rebalance/orders/fills/metrics를 JSONL+CSV로 저장, schema 검증, hash 기록, 누락 시 FAIL.
- **(2) 게이트**: 파일 존재/파싱/스키마 100% 통과, worst_mdd 산출.
- **(3) 기대 관측치**: pinpoint/diagnoser가 항상 작동 → “안 움직임” 원인이 **전략 vs 운영**으로 분리됨.

## E2. 누수/폴드 퇴화 제거 CV 스위트
- **(1) 실험 정의**: purged walk-forward + embargo + minimum-trades gate + ticker-group stress.
- **(2) 게이트**: degenerate_folds ≤ 10%, 폴드별 트레이드 최소치 충족.
- **(3) 기대 관측치**: OOS mean이 조정되더라도 분산/퇴화가 줄고, 재현 가능한 성능으로 수렴.

## E3. 비용/대차/턴오버 현실화
- **(1) 실험 정의**: 비용 3티어 + 숏 대차비용 + 턴오버 캡 적용.
- **(2) 게이트**: After-cost 성능이 Low/Base/High에서 일관된 방향(최소 부호 유지) 또는 하락 원인이 비용/턴오버로 설명 가능.
- **(3) 기대 관측치**: “미세 알파가 비용에 먹히는지” 즉시 판별, 불필요한 고빈도 리밸런스 억제.

## E4. 8~14종목 강제 + 익스포저/레짐 게이트(ETF는 지표만)
- **(1) 실험 정의**: 보유 종목수/비중/유동성/섹터편중 제약 + 레짐 기반 익스포저 스케일링.
- **(2) 게이트**: 제약 위반 0, 익스포저 0은 레짐 OFF에서만 발생(설명가능성).
- **(3) 기대 관측치**: 성능이 “평균적으로 안 움직임”이면 레짐별 성과 분리가 나타나고, 리스크 지표(MDD/vol)가 개선.

# 성능이 안 움직일 때 “원인 분해” 아이디어 (트리거/적용/노출/비용/레짐)

아래 트리를 **매 48시간 루프 리포트에 고정 섹션**으로 넣고, 하나라도 FAIL이면 다음 실험을 막는 방식으로 운영하세요.

## 1) Trigger(신호 발생) 레벨
- **체크**: 신호가 실제로 변하는가? (일별 점수 분산, 상위/하위 랭크 교체율)
- **증상→원인**
  - 점수 거의 고정: 피처/라벨 정렬 오류, 결측 처리로 상수화, 스케일링 버그
  - 특정 구간만 0: 데이터 누락/거래정지 구간 처리 문제

## 2) Apply(리밸런스/주문 생성) 레벨
- **체크**: 신호→타겟 포지션 변환이 일어나는가? (리밸런스 이벤트 수, 주문 수, 타겟 변경량)
- **증상→원인**
  - 신호는 변하는데 주문 0: 리밸런스 스케줄/캘린더 버그, 게이트가 항상 OFF
  - 주문은 있는데 포지션 변화 0: 최소주문단위/리스크 제한에 의해 전부 컷

## 3) Exposure(노출/구성) 레벨
- **체크**: 종목 수(8~14) 유지, 단일비중 상한, 순/총 익스포저, 섹터 비중(Tech/HC 내)
- **증상→원인**
  - 익스포저가 자주 0: 레짐 게이트 상시 OFF 또는 신호 부족
  - 1~2종목 과집중: 랭킹 타이브레이크/유동성 필터 결함, 제약 미적용

## 4) Cost(비용) 레벨
- **체크**: 총 거래대금, 턴오버, 비용(스프레드/슬리피지/대차) 기여도 분해
- **증상→원인**
  - Gross는 +인데 After-cost가 0 근처: 리밸런스 과다/알파 미세
  - High cost에서만 붕괴: 유동성 부족 종목 포함, 포지션 사이징 과다

## 5) Regime(레짐) 레벨
- **체크**: 레짐별 성과 분해(예: VIX 상/하, QQQ 추세 상/하, 금리 상승/하락)
- **증상→원인**
  - 전체 성과 0이지만 레짐별로 +/− 상쇄: 레짐 게이트/틸트로 분리해야 함
  - 레짐 지표 적용 후 더 나빠짐: 지표 지연 미적용(누수) 또는 과도한 게이트로 기회 상실

---

## 실행 순서(명령형 체크리스트)
1) **E1 먼저 적용**: 로깅/아티팩트 계약 테스트를 넣고, 파싱 오류/누락이 0이 될 때까지 실패시키기.  
2) **E2 실행**: purged walk-forward + minimum-trades 게이트로 degenerate_folds 제거.  
3) **E3 실행**: 비용 3티어 + 대차 + 턴오버 캡으로 After-cost 기준에서 생존 여부 확인.  
4) **E4 실행**: 8~14종목/집중도/유동성 제약 + 레짐(ETF는 지표)로 “안 움직임”의 상쇄 구조를 분해.  
5) 위 1~4의 리포트를 기반으로, 다음 루프에서는 **가장 먼저 FAIL 난 게이트를 고치는 패치만** 추가(케이스 폭발 금지).

원하면 위 게이트들을 “실험 시스템”에서 바로 실패 조건으로 걸 수 있도록, `metrics.json`에 넣어야 할 최소 필드(리밸런스 수/주문 수/턴오버/after-cost pnl/폴드별 트레이드 수/레짐별 성과)까지 한 번에 고정 스키마로 정리해도 됩니다.
