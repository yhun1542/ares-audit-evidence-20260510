### 1. 48시간 우선순위 TOP 5 (Action Checklist)

1.  **[검증] Candidate Tuning Min(-1.49) 원인 규명 및 Patch**
    *   **Why:** Lockbox 성능이 좋아도 Training Min이 이 정도로 낮으면 실전 운영 시 'Unseen Regime'에서 계좌가 파산할 수 있음.
    *   **Risk:** 특정 종목(바이오 등)의 개별 악재가 필터링되지 않았을 가능성.
    *   **Action:** Tuning 과정에서 손실이 발생한 날짜/종목을 추출하고, 공통된 팩터(예: 실적 발표일, 임상 데이터 발표일)가 있었는지 확인.

2.  **[로직] ETF(XLK, XLV) 기반 매크로 필터 강화**
    *   **Why:** Tech/Healthcare 집중 포트폴리오임. 섹터 자체가 하락할 때 개별 종목 Mean Reversion은 "떨어지는 칼날"임.
    *   **Risk:** 신호 지연(Lag)으로 인한 진입 기회 상실.
    *   **Action:** XLK(Tech), XLV(Health)의 단기 이격도가 하방 임계치 이탈 시 매수 금지 로직 추가.

3.  **[비용] 거래 비용(Slippage/Fee) 민감도 테스트**
    *   **Why:** Tuning/Lockbox 괴리가 크다면, 실제 거래 비용 반영 시 Alpha가 사라지는 구조일 수 있음.
    *   **Risk:** 잦은 매매(High Turnover) 전략일 경우 실제 수익률 급감.
    *   **Action:** 거래 비용을 현재 설정의 1.5배~2배로 높여서 Candidate 재평가.

4.  **[유니버스] Healthcare 종목의 생존 편향(Survivorship Bias) 재점검**
    *   **Why:** 헬스케어 8~14 종목 중 과거에 상장 폐지되거나 인수된 종목이 데이터셋에 포함되어 있는지 확인(Point-in-Time).
    *   **Risk:** 이미 성공한(살아남은) 종목만으로 백테스트하여 성능이 부풀려짐.
    *   **Action:** 과거 시가총액/유동성 기준으로 유니버스 선정 로직이 동적으로 작동하는지 코드 레벨 검수.

5.  **[실험] 변동성 기반 포지션 사이징(Volatility Targeting)**
    *   **Why:** Tech와 Healthcare의 변동성 성격이 다름. 동일 비중보다 변동성 역가중이 MDD 방어에 유리.
    *   **Risk:** 저변동성 종목(대형 제약사 등) 비중 과다로 인한 수익률 저하.
    *   **Action:** ATR 또는 Historical Volatility 기반 비중 조절 모듈 적용.

### 2. 실행 가능한 Patch/실험 (48시간 루프)

다음 3가지 실험을 병렬 또는 순차 수행하여 `candidate`를 `champion`으로 승격시키거나 폐기하시오.

#### 실험 A: "Sector Guard" (ETF 관측 지표 활용)
*   **목표:** Tuning Min 하락 방어. 섹터 전체가 무너질 때 개별 종목 매수 제한.
*   **정의:**
    *   매수 시점 `XLK` 또는 `XLV`의 `RSI(14) < 30` 이거나 `MA(20) < MA(60)` 데드크로스 발생 직후 3일간 매수 금지.
*   **게이트(Pass Condition):**
    *   Tuning Min > -1.0 (손실폭 축소)
    *   Lockbox Mean 감소폭 < 5% (수익성 유지)
*   **기대 관측치:** 거래 횟수는 감소하나, Tuning Fold 내의 큰 낙폭(Deep Drawdown)이 제거됨.

#### 실험 B: "Aggressive Cut" (손절 로직 강화)
*   **목표:** Tuning Min의 Extreme Value 제거.
*   **정의:**
    *   기존 로직 유지하되, 진입 후 `24시간 내 수익률 < -2.0%` 발생 시 조건 없이 시장가 청산(Time-based hard stop).
    *   Tech/Bio 특성상 초반 방향성이 틀리면 모멘텀으로 이어지는 경우가 많음.
*   **게이트(Pass Condition):**
    *   Worst MDD > -0.04 (현재 -0.048보다 개선)
    *   Win Rate > 55% 유지
*   **기대 관측치:** "잘못된 진입"을 빠르게 인정하여 누적 손실 방지. 승률은 낮아질 수 있으나 손익비(Payoff Ratio) 개선.

#### 실험 C: "Cost Stress Test" (비용 민감도)
*   **목표:** 과최적화 여부 판별.
*   **정의:**
    *   Slippage를 기존 5bps에서 10bps(0.1%)로 상향 설정 후 `candidate` 모델 재구동.
*   **게이트(Pass Condition):**
    *   Lockbox Mean > 1.2 (기존 1.55에서 급격히 무너지지 않아야 함)
*   **기대 관측치:** 만약 성능이 절반 이하로 떨어진다면, 현재 모델은 "노이즈를 거래"하고 있는 것임. 이 경우 진입 Threshold를 높여야 함.

### 3. 성능 정체 시 원인 분해 (Debugging Logic)

지표가 움직이지 않거나 `Inconclusive` 상태가 지속될 때 다음 순서로 점검.

1.  **트리거(Trigger) 빈도 확인:**
    *   *현상:* 거래 횟수가 0 또는 극단적으로 적음.
    *   *원인:* 진입 조건(Threshold)이 너무 높아 최근 시장 변동성(VIX) 감소 구간에 신호가 안 나옴.
    *   *해결:* 변동성(ATR)에 비례하여 진입 Threshold 동적 조정 (Adaptive Threshold).

2.  **노출(Exposure) 확인:**
    *   *현상:* 신호는 나오는데 포지션이 안 잡힘.
    *   *원인:* 자금 관리 룰(예: 한 종목당 최대 10%, 현금 비중 50% 유지 등)에 의해 주문이 거부됨.
    *   *해결:* `Cash Utilization Rate` 로그 확인 후 포지션 사이징 로직 완화.

3.  **레짐(Regime) 불일치:**
    *   *현상:* 롱(Long) 신호만 계속 나오는데 시장은 하락장.
    *   *원인:* Mean Reversion 전략이 강력한 하락 추세(Momentum)를 "저점 매수 기회"로 오판.
    *   *해결:* ADX(추세 강도) 지표가 일정 수준(예: 30) 이상일 때는 역추세 매매 금지.

4.  **데이터 무결성(Data Integrity):**
    *   *현상:* 특정 종목만 수익률이 이상하게 높거나 낮음.
    *   *원인:* 주식 분할(Split)이나 배당락(Dividend) 데이터가 제대로 보정(Adjusted)되지 않음.
    *   *해결:* 데이터 공급 파이프라인의 `Adjusted Close` 재확인.
