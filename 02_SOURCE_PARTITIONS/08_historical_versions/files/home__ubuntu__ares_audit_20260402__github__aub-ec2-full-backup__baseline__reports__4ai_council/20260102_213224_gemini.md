## [시스템 진단 및 액션 명령]

현재 **Champion v5**의 `lockbox_mean`(4.01)이 `tuning_mean`(2.32)보다 2배 가까이 높은 현상은 **'미래 참조(Look-ahead Bias)'** 혹은 **'특정 구간 과최적화(Overfitting)'**의 강력한 신호임. 일반적인 모델은 OOS(Lockbox)에서 성능이 하락함.

따라서 다음 48시간의 최우선 순위는 **"수익률 증대"가 아닌 "승자의 유효성 검증(Sanity Check)"**에 집중해야 함.

### 1. 우선순위 TOP 5 제안 (Actionable Patch)

#### **Proposal 1: Feature Lag 강제 주입 (Leakage Hunter)**
*   **(a) 필요성:** Champion v5의 비정상적 Lockbox 수익률 원인이 `Close` 가격을 당일 시그널 생성에 포함했는지(Open-Close 간 시차 무시) 확인 필요.
*   **(b) 위험/부작용:** 실제 알파였을 경우 성능이 급락하여 폐기될 수 있음(False Negative).
*   **(c) 실험 정의:**
    *   `EXP_L1_FORCE_LAG`: 모든 Feature 생성 파이프라인 마지막에 `.shift(1)` 강제 적용 후 Backtest.
    *   `EXP_L2_NEXT_OPEN`: 매매 실행을 `Close`가 아닌 `Next Open`으로 변경하여 체결 시차 반영.
*   **(d) PASS 조건:**
    *   `tuning_mean`이 1.5 이상 유지되면서 `worst_mdd`가 -15% 이내일 것. (수익률 반토막은 허용하되, 파산하면 안 됨)

#### **Proposal 2: Tech/Healthcare 상관관계 디커플링 (Sector Hedge)**
*   **(a) 필요성:** Tech와 Healthcare가 동시에 무너지는 구간(금리 인상기 등) 방어력이 부족할 수 있음. 두 섹터의 롱온리(Long-only) 포트폴리오라면 상관관계가 1에 수렴할 때 MDD가 급증함.
*   **(b) 위험/부작용:** 상승장에서 헷지 비용으로 인해 수익률(CAGR) 저하.
*   **(c) 실험 정의:**
    *   `EXP_S1_CORR_FILTER`: Tech와 Healthcare ETF(XLK, XLV) 간 60일 상관계수가 0.8 이상일 때, 변동성이 낮은 섹터 비중만 남기고 현금화.
    *   `EXP_S2_ADAPTIVE_ALLOC`: 두 섹터의 모멘텀 점수(Momentum Score) 격차가 클 때만 강한 섹터에 100% 몰아주기 (집중 투자).
*   **(d) PASS 조건:**
    *   `fold14_mdd` 개선 (기존 -0.039 -> -0.030 수준 유지 혹은 개선) 및 `Sharpe` > 2.0 유지.

#### **Proposal 3: 'Macro Alpha Shadow' 필터 이식 (Regime Integration)**
*   **(a) 필요성:** Candidate(`macro_alpha_shadow`)는 수익률은 낮지만 MDD 방어 로직이 포함된 것으로 보임. Champion v5의 진입 로직에 이 필터를 AND 조건으로 결합.
*   **(b) 위험/부작용:** 거래 횟수 급감(Overtightening)으로 표본 부족 발생 가능.
*   **(c) 실험 정의:**
    *   `EXP_M1_HYBRID_FILTER`: Champion v5의 진입 시그널 발생 시, `macro_alpha_shadow`의 `regime_condition == True` 일 때만 진입 허용.
    *   `EXP_M2_VOL_SCALING`: 매크로 불안정 시(VIX > 20 등) 포지션 사이즈를 50%로 축소.
*   **(d) PASS 조건:**
    *   `lockbox_min` 수익률이 0.73(기존) 이상 유지되며, 거래 횟수가 연평균 100회 이상일 것.

#### **Proposal 4: 비용 스트레스 테스트 (Realistic Cost)**
*   **(a) 필요성:** 8~14개 종목의 잦은 리밸런싱은 슬리피지/수수료에 취약함. 현재 Champion 성능이 비용 과소평가로 인한 것인지 확인.
*   **(b) 위험/부작용:** 엣지가 작은 전략은 즉시 탈락(Fail) 처리됨.
*   **(c) 실험 정의:**
    *   `EXP_C1_DOUBLE_COST`: Transaction Cost를 기본 설정의 2배(예: 10bps -> 20bps)로 설정 후 재검증.
    *   `EXP_C2_TO_PENALTY`: 회전율(Turnover) 기반 페널티 항을 목적함수에 추가하여 최적화 다시 수행.
*   **(d) PASS 조건:**
    *   2배 비용 적용 시에도 `tuning_mean` > 1.0 (플러스 알파) 유지.

#### **Proposal 5: 유동성 기반 동적 유니버스 (Survivor Bias Check)**
*   **(a) 필요성:** 2026년 기준 우량주(NVIDIA, Lilly 등)를 2010년부터 고정해서 백테스트했는지 확인 필요. 당시엔 중소형주였을 수 있음.
*   **(b) 위험/부작용:** 유니버스 교체 로직 오류 시 데이터 정합성 깨짐.
*   **(c) 실험 정의:**
    *   `EXP_U1_ROLLING_TOP`: 매월 말 시총+거래대금 상위 Tech/Health 종목을 다시 선정(Re-ranking)하여 다음 달 유니버스로 사용. (고정 리스트 폐기)
*   **(d) PASS 조건:**
    *   고정 유니버스 대비 성능 하락폭이 20% 이내일 것. (크게 하락하면 생존편향임)

### 2. 48시간 자동 루프 정의

아래 포맷을 시스템에 주입하여 실행하십시오.

#### [LOOP CONFIG]
**Target:** `champion_v5_latest.json`

**(1) 실험 정의 (Experiments)**
1.  **EXP_LEAK_CHK**: `input_features` 전체 `shift(1)` 적용.
2.  **EXP_REGIME_MERGE**: `entry_rule` = `champion_v5.entry` AND `candidate_shadow.regime_ok`.
3.  **EXP_COST_STRESS**: `sim_params.cost_bps` = 20 (or 2x current).

**(2) 게이트 (Gate Logic)**
*   **PASS_LEAK**: `tuning_mean` > 1.0 AND `mdd` > -0.15 (리키지 제거 후에도 수익 나면 인정)
*   **PASS_MERGE**: `worst_mdd` > `champion_v5.worst_mdd` (MDD 개선 확인)
*   **PASS_COST**: `sharpe` > 1.5 (비용 증가 후에도 샤프지수 유지)

**(3) 기대 관측치 (Expected Observations)**
*   **IF** `EXP_LEAK_CHK` fails (returns -> 0): Champion v5는 리키지 모델임. 즉시 폐기(`DISCARD`) 및 Candidate 복구.
*   **IF** `EXP_COST_STRESS` fails: 회전율을 낮추는 로직(Holding Period 증가)을 다음 이터레이션에 추가.
*   **IF** `EXP_REGIME_MERGE` works: v5의 공격력 + Shadow의 방어력을 갖춘 `v6_hybrid` 생성.

### 3. 성능 정체(Stagnation) 시 원인 분해 트리

성능지표가 움직이지 않거나 개선되지 않을 때 아래 트리를 따라 디버깅할 것.

1.  **트리거(Trigger) 확인**: 매수/매도 시그널 자체가 발생하는가?
    *   *Check:* `trade_logs`의 연간 거래 횟수 확인. 0에 수렴하면 진입 조건(Threshold)이 너무 높거나 데이터 누락(NaN) 발생 중.
    *   *Fix:* 진입 임계값(Threshold) 완화 (예: RSI < 30 -> RSI < 40).

2.  **노출(Exposure) 확인**: 시그널은 있는데 포지션을 못 잡는가?
    *   *Check:* 현금 비중(Cash Ratio) 시계열 확인. 현금이 계속 100%라면 자금 관리(Position Sizing) 로직에서 `risk_per_trade`가 너무 작거나 증거금 부족 로직 작동.
    *   *Fix:* `target_volatility` 목표치 상향 조정.

3.  **비용(Cost) 장벽**: 총수익(Gross)은 좋은데 순수익(Net)이 나쁜가?
    *   *Check:* 평균 손익(Avg PnL per trade) vs. 수수료(Commision+Slippage). 
    *   *Fix:* 평균 익절폭이 수수료의 5배 미만이면, 진입 필터를 강화하여 "확실할 때만" 들어가게 수정하거나 익절 목표 상향.

4.  **레짐(Regime) 불일치**: 시장은 오르는데 내 전략만 떨어지는가?
    *   *Check:* Tech/Health 지수(Benchmark)와의 베타(Beta) 확인. 베타가 음수이거나 0에 가까우면 역추세(Mean Reversion) 전략이 추세장(Trend)에서 갈리고 있는 것.
    *   *Fix:* 모멘텀 필터(200일 이평선 위에서만 롱) 추가.
