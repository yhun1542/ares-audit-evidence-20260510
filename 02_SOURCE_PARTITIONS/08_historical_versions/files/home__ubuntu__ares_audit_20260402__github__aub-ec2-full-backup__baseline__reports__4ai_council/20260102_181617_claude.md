## 1. 우선순위 TOP 5 액션

### ⬛ P0: Degenerate Fold 원인 분해 (BLOCKING)

**(a) 왜 필요한가**
- 4/8 fold degenerate = 모델이 50% 시장 조건에서 무의미
- 이 상태에서 파라미터 튜닝은 noise fitting

**(b) 위험/부작용**
- 분석 시간 소요 (4~8시간)
- 근본 원인이 데이터 부족이면 해결책 제한

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 0-1 | 각 degenerate fold(1,2,3,8)의 기간/레짐 매핑 | 완료 | fold별 시장 특성 테이블 |
| 0-2 | 해당 기간 exposure=0 원인 추적 (signal 없음 vs 필터 과다) | signal_count > 0 확인 | 병목 지점 식별 |
| 0-3 | Non-degenerate fold(4,5,6,7)와 feature importance 비교 | diff > 20% 항목 존재 | 레짐별 분기 후보 |

**(d) PASS 조건**
```
degenerate_cause IN ['regime_filter', 'signal_sparsity', 'data_gap'] 
AND remediation_path identified
```

### ⬛ P1: MDD 측정 파이프라인 복구

**(a) 왜 필요한가**
- `worst_mdd: None` = 리스크 블라인드
- OOS mean만으로 전략 평가는 서바이버십 함정

**(b) 위험/부작용**
- 측정 추가 시 런타임 +10~15%
- 기존 결과와 비교 불가 (새 메트릭)

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 1-1 | `calc_max_drawdown()` 함수 champion 파이프라인에 삽입 | 에러 없음 | mdd_pct 숫자 출력 |
| 1-2 | Fold별 MDD 분포 생성 | 8개 fold 전부 값 존재 | mdd_mean, mdd_worst 리포트 |

**(d) PASS 조건**
```
worst_mdd IS NOT NULL AND worst_mdd > -30%
```

### ⬛ P2: Rebalance 로그 복구 및 비용 반영 검증

**(a) 왜 필요한가**
- 현재 rebalance.csv 파싱 실패 → 회전율/비용 미관측
- 비용 미반영 시 OOS 3.32는 허수일 가능성

**(b) 위험/부작용**
- 로그 포맷 변경 시 기존 분석 도구 호환성 깨짐
- 비용 반영 후 수익률 급락 가능

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 2-1 | rebalance.jsonl 파서 수정 및 출력 검증 | row_count > 0 | 거래 내역 테이블 |
| 2-2 | 연간 turnover 계산 | 값 산출 | turnover_annual (목표 <400%) |
| 2-3 | 비용 반영 OOS 재계산 (10bps 편도) | 완료 | oos_mean_net vs oos_mean_gross |

**(d) PASS 조건**
```
turnover_annual < 400% AND (oos_mean_gross - oos_mean_net) < 0.5
```

### ⬛ P3: Overfitting 검증 (OOS Mean 급등 원인)

**(a) 왜 필요한가**
- Champion OOS 2.63 → 현재 3.32 (+26% 점프)
- Degenerate fold 50%인데 mean 상승 = 살아남은 fold 과적합 의심

**(b) 위험/부작용**
- 검증 실패 시 현재 "champion" 폐기 필요
- 롤백 결정 지연 시 잘못된 방향 탐색

**(c) 최소 실험**

| # | 실험 정의 | 게이트 | 기대 관측치 |
|---|-----------|--------|-------------|
| 3-1 | IS vs OOS gap 분석 (fold 4,5,6,7만) | gap < 2x | is_mean, oos_mean 비율 |
| 3-2 | 파라미터 sensitivity: ±10% 변경 후 OOS 변화 | 변화 < 20% | robustness_score |
| 3-3 | Baseline champion_v5 재실행 (동일 데이터) | 재현성 | oos_mean diff < 0.1 |

**(d) PASS 조건**
```
is_oos_gap < 2.0 AND param_sensitivity < 20% AND baseline_reproducible
```

## 2. 성능 불변 시 원인 분해 트리

```
성능이 안 움직인다
│
├─ [트리거] Signal 자체가 발생 안 함
│   ├─ 점검: signal_count_per_day 분포
│   └─ 실험: 필터 임계값 완화 (threshold *= 0.8)
│
├─ [적용] Signal → Position 전환 실패
│   ├─ 점검: signal_to_trade_ratio
│   └─ 실험: position sizing 로직 단순화
│
├─ [노출] Position 있으나 exposure 미미
│   ├─ 점검: avg_exposure vs max_exposure
│   └─ 실험: exposure cap 상향 (0.84 → 0.90)
│
├─ [비용] Gross → Net 전환 시 소멸
│   ├─ 점검: turnover × cost vs gross_return
│   └─ 실험: 리밸런스 주기 연장 (daily → weekly)
│
└─ [레짐] 특정 시장 조건에서만 작동
    ├─ 점검: fold별 VIX/SPY 상관관계
    └─ 실험: 레짐 필터 제거 후 baseline
```
