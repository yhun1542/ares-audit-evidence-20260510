## 24~48시간 우선순위 TOP5 (코드/아키텍처/전략) — **명령형 체크리스트**
> 우선 점검 순서: **누수 → 과최적화 → 서바이버십 → 비용(슬리피지) → 운영 리스크**  
> 제약 준수: **미국주식 only / Tech+Healthcare 중심 / 8~14 종목 / ETF 매매 금지(관측지표로만 사용)**  
> 아래는 **“고유 실험 5개(E1~E5)”만** 정의하고, 각 제안에서 **이 5개를 2~3개씩 재사용**합니다(케이스 폭발 방지).

# (공통) 48시간 자동 루프용 실험 세트 (E1~E5, 총 5개만)
각 실험은 (1)정의 (2)게이트 (3)기대 관측치로 고정.

### E1) **Leak Sentinel (누수/정렬/미래참조 탐지)**
- (1) **실험 정의**
  - 피처/라벨 정렬을 **+1bar 지연(shift)** / **-1bar 당김(불가능 케이스)** 두 버전으로 백테스트.
  - 이벤트/펀더멘털류(헬스케어 포함) 피처는 **발표시간 기준 “사용 가능 시점” 강제**(가능 시점 이전은 NaN).
- (2) **게이트**
  - “-1bar 당김(불가능)”에서 성능이 유지되면 **즉시 FAIL(누수 의심)**.
  - “+1bar 지연”에서 성능이 완만히만 하락하면 PASS(정렬 정상 가능성↑).
- (3) **기대 관측치**
  - -1bar 당김: 샤프/평균수익이 비정상적으로 높아지면 누수.
  - +1bar 지연: 성능 일부 하락(정상), MDD는 비슷하거나 소폭 증가.

### E2) **Survivorship/CorpAction Consistency (서바이버십/상장폐지/분할)**
- (1) **실험 정의**
  - 동일 기간을 **(A) survivorship-free 소스/설정** vs **(B) 현재 설정**으로 비교.
  - delist 리턴/분할/배당 조정(Adj close vs raw) 처리 일관성 체크.
- (2) **게이트**
  - (A)→(B) 변경 시 성능이 유의미하게 급증하면 FAIL(서바이버십/조정 오류 의심).
- (3) **기대 관측치**
  - survivorship-free 적용 후 평균수익은 약간 낮아질 수 있으나, 챔피언의 “락박스 우위”는 유지되어야 정상.

### E3) **Cost/Slippage/Turnover Reality (비용/회전율/체결)**
- (1) **실험 정의**
  - 커미션 + 스프레드 + 슬리피지(고정bps + 거래대금 기반 impact 중 택1)를 **보수적**으로 주입.
  - 턴오버 상한(예: 일별/리밸런스별) 패널티 또는 하드캡을 1개 버전으로 추가.
- (2) **게이트**
  - 비용 반영 후 락박스 성능이 **치명적으로 붕괴**하면 FAIL(엣지가 “거래비용 이전”에만 존재).
  - 턴오버 캡 적용 후 성능이 소폭만 하락하면 PASS(엣지 구조가 건전).
- (3) **기대 관측치**
  - 비용 적용 시 평균수익↓, MDD는 비슷하거나 개선(과매매 감소 시).
  - 턴오버 캡 버전이 더 안정적이면 “실전 친화”.

### E4) **Regime/Exposure Control w/ ETF Indicators (레짐/노출 관리)**
- (1) **실험 정의**
  - ETF는 **관측지표로만** 사용: 예) QQQ(성장), XLV(헬스케어), SPY(시장), IWM(리스크온), TLT(금리 민감) 등.
  - 레짐 게이트(예: QQQ vs SPY 모멘텀/변동성)로 **포지션 크기 스케일** 또는 **현금 비중/총 익스포저 축소**.
  - Tech/Healthcare 내에서도 **단일 종목/서브섹터 집중 상한**(8~14 종목 강제 유지) 적용.
- (2) **게이트**
  - worst_MDD 또는 fold14_MDD가 유의미하게 개선되면 PASS(방어력↑).
  - 평균수익이 소폭 감소해도 MDD 개선폭이 크면 PASS(실전성↑).
- (3) **기대 관측치**
  - “락박스 최저 성과/최대낙폭”이 개선.
  - 특정 레짐(금리 급등/리스크오프)에서 손실이 줄어듦.

### E5) **Ops Guardrails (운영/자동루프 안정성 + 과최적화 억제)**
- (1) **실험 정의**
  - 시드/데이터 스냅샷/환경 고정(컨테이너/requirements lock) + 결과 재현성 체크.
  - “선정 기준”에 **다중검정/과최적화 페널티**(예: 튜닝-락박스 괴리 큰 후보 자동 탈락) 추가.
- (2) **게이트**
  - 동일 커밋/동일 데이터에서 결과가 흔들리면 FAIL(운영 리스크).
  - 튜닝↑인데 락박스↓ 후보가 자동 배제되면 PASS(과최적화 억제).
- (3) **기대 관측치**
  - “가끔 터지는 후보”가 줄고, 챔피언 교체 빈도 감소(안정화).

# TOP5 제안 (각 제안별 a~d)

## 1) (최우선) **누수/정렬/미래참조 차단을 “테스트로 고정”**
- (a) 왜 필요한지  
  - 챔피언 락박스 평균이 큰 상황(4.01)에서, 다음 후보들이 튜닝/락박스 괴리로 흔들리면 **누수/정렬 미세 오류**가 가장 흔한 원인입니다.
- (b) 위험/부작용  
  - 과도한 “가능시점 보수화”로 단기 성능이 하락할 수 있음(정상).
- (c) 최소 실험(재사용)  
  - **E1 실행**(shift ±1 + 발표시점 강제)  
  - **E5 실행**(재현성/선정기준에 튜닝-락박스 괴리 페널티)  
- (d) PASS 조건  
  - -1bar 당김에서 성능이 좋아지면 **즉시 FAIL**(누수).  
  - +1bar 지연에서 성능 하락이 “완만”하고 락박스 신뢰가 유지되면 **PASS**.  
  - 재현성: 동일 조건 재실행 시 주요 지표 오차가 허용범위 내면 **PASS**.

---

## 2) **거래비용/슬리피지/회전율을 “락박스 게이트의 1순위”로 편입**
- (a) 왜 필요한지  
  - 기술주/헬스케어는 갭/이벤트가 많아 **체결 가정**이 수익의 상당 부분을 좌우합니다.  
  - 비용 미반영은 “백테스트만 이기는 전략”의 최우선 원인.
- (b) 위험/부작용  
  - 비용모델을 과도하게 보수적으로 잡으면 유망 전략을 과도 탈락시킬 수 있음(단, 운영 안전성은 올라감).
- (c) 최소 실험(재사용)  
  - **E3 실행**(보수적 비용 + 턴오버 캡 1버전)  
  - **E5 실행**(선정기준에 turnover/cost-penalty 반영)  
- (d) PASS 조건  
  - 비용 반영 후에도 락박스 성능이 “의미 있게” 남아있고, 턴오버 캡 적용 시 worst_MDD가 악화되지 않으면 **PASS**.  
  - 비용 반영으로 성능이 붕괴하면 **FAIL(엣지의 출처 재검토)**.

---

## 3) **서바이버십/상장폐지/분할·배당 조정 일관성 점검 + 유니버스(8~14) 강제**
- (a) 왜 필요한지  
  - “현재 살아남은 종목만”으로 구성된 백테스트는 Tech에서 특히 성능이 과대평가됩니다.  
  - 또한 8~14 종목 제약이 느슨하면, 우연히 소수 종목에 베팅한 결과가 챔피언처럼 보일 수 있습니다(서바이버십+집중 리스크 결합).
- (b) 위험/부작용  
  - survivorship-free로 바꾸면 평균수익이 내려갈 수 있음(정상).  
  - 유니버스 강제는 단기 성능을 희생하고 안정성을 얻는 방향.
- (c) 최소 실험(재사용)  
  - **E2 실행**(survivorship-free vs 현재)  
  - **E4 실행**(8~14 강제 + 집중 상한)  
- (d) PASS 조건  
  - survivorship-free에서도 챔피언의 락박스 우위가 “형태”를 유지하면 **PASS**.  
  - 유니버스 강제 후 fold14/worst_MDD가 개선 또는 유사하면 **PASS**.  
  - survivorship-free에서만 성능이 붕괴하면 **FAIL(데이터/조정/편향 재수정)**.

---

## 4) **레짐(리스크온/오프) + 익스포저(베타/섹터/단일종목) 관리: ETF는 ‘계기판’으로만 사용**
- (a) 왜 필요한지  
  - 후보(exp_macro_alpha_shadow)가 MDD가 커진 것은(대략 -0.11) “레짐에서 맞으면 크게 깨지는 노출” 가능성이 큼.  
  - Tech/Healthcare는 금리/리스크 프리미엄 변화에 민감하여, 레짐 스케일링이 방어력을 크게 좌우.
- (b) 위험/부작용  
  - 레짐 게이트가 과하면 “좋은 구간” 수익도 깎아 평균이 감소할 수 있음.
- (c) 최소 실험(재사용)  
  - **E4 실행**(QQQ/XLV/SPY/TLT 등 관측지표로 스케일링)  
  - **E3 실행**(턴오버 캡과 결합 시 과매매 감소 확인)  
- (d) PASS 조건  
  - worst_MDD 또는 특정 폴드(MDD 나쁜 구간)의 손실이 유의미하게 줄면 **PASS**.  
  - 락박스 평균이 약간 하락해도 “최저 성과/최대낙폭”이 개선되면 **PASS**.

---

## 5) **자동선정(autopilot) 아키텍처 가드레일: 과최적화 억제 + 실패 모드 자동 격리**
- (a) 왜 필요한지  
  - “튜닝에서만 잘 되는 후보”가 자주 나오면(현재 후보가 그 패턴) 자동 루프가 **과최적화 방향으로 끌려갈** 확률이 큼.  
  - 48시간 루프는 운영 안정성이 성능만큼 중요(실험 폭주/결과 재현 불가/데이터 드리프트).
- (b) 위험/부작용  
  - 가드레일이 강하면 탐색 속도가 느려지고, 급격한 성능 점프 후보를 놓칠 수 있음.
- (c) 최소 실험(재사용)  
  - **E5 실행**(재현성 + 튜닝-락박스 괴리 페널티 + 결과 캐시/스냅샷)  
  - **E1 실행**(누수 sentinel을 “통과 못하면 후보 자동 폐기”)  
- (d) PASS 조건  
  - 동일 커밋/동일 데이터에서 결과가 안정적이고, 누수/괴리 후보가 자동 탈락하면 **PASS**.  
  - “락박스 최소 성과(min) 기준”을 넘지 못하면 자동 격리되면 **PASS**.

# 성능이 안 움직일 때 “원인 분해” 체크리스트 (트리거/적용/노출/비용/레짐)
> 질문 금지 조건에 맞춰, 바로 로그/리포트에 추가할 **분해 항목**만 제시합니다.

## A) Trigger(신호 발생) 문제
- **명령형 체크**
  - 피처별 **IC(Information Coefficient)**, hit-rate, sign-stability를 롤링 윈도우로 출력.
  - “신호 발생 빈도(트레이드 수)”가 특정 구간에서 0에 수렴하는지 확인.
- **해석**
  - IC≈0인데 수익이 난다면 누수/비용/노출 착시 가능성↑.

## B) Application(적용/정렬/리밸런스 타이밍) 문제
- **명령형 체크**
  - 신호 시점→주문 시점→체결 시점의 타임스탬프를 1줄 로그로 남기고, **T+0 사용 여부**를 강제 표기.
  - 리밸런스 캘린더(일/주/월) 변경 시 성능 변화 비교.
- **해석**
  - “타임스탬프 불일치”는 누수/환상 수익의 1순위.

## C) Exposure(노출/집중/팩터 베팅) 문제
- **명령형 체크**
  - 포트폴리오의 **시장베타(SPY), 성장베타(QQQ), 금리(TLT proxy)** 노출을 회귀로 추정해 저장.
  - **단일 종목 기여도(contribution)** 상위 3개가 전체 PnL의 과반을 차지하는지 체크.
- **해석**
  - 성능 정체인데 노출이 일정하면 “알파가 아니라 베타”일 가능성↑.

## D) Cost(비용/슬리피지/회전율) 문제
- **명령형 체크**
  - 거래당 비용, 일별 turnover, 평균 보유기간을 고정 리포트로 출력.
  - 성능이 정체될수록 비용이 증가하는 “악순환(과매매)” 여부 확인.
- **해석**
  - gross는 유지되는데 net만 정체면 비용/체결 가정 문제.

## E) Regime(레짐) 문제
- **명령형 체크**
  - 레짐 라벨(예: QQQ vs SPY 모멘텀, 변동성 상/하위)별로 성과를 **조건부 분해**.
  - “최악 레짐”에서만 MDD가 터지면 **E4 레짐 스케일링** 우선.
- **해석**
  - 평균은 괜찮지만 worst_MDD가 악화되면 레짐 방어 부재.

---

## PASS 기준(전체 공통, 자동선정용 권장)
- **누수 게이트(E1)**: 불가능(-1bar) 케이스에서 성능 개선 시 즉시 FAIL  
- **서바이버십(E2)**: survivorship-free에서 형태 유지 못하면 FAIL  
- **비용(E3)**: 비용 반영 후에도 락박스가 의미 있게 남아야 PASS  
- **레짐/노출(E4)**: worst_MDD 개선 또는 최소 성과(min) 개선이 있으면 PASS  
- **운영(E5)**: 재현성/결과 안정성 확보 못하면 FAIL

이 구성으로 48시간 루프를 돌리면, “성능을 올리는 시도”보다 먼저 **성능이 진짜인지(누수/편향/비용) 확정**하고, 그 다음에만 레짐/노출로 방어력을 올리는 방식으로 안정적으로 전진합니다.
