## 24~48h 우선순위 TOP5 (코드/아키텍처/전략) — **명령형 체크리스트**
> 우선 점검 순서: **누수 → 과최적화 → 서바이버십 → 비용 미반영 → 운영 리스크**  
> 제안은 **유니크 실험/패치 5개(E1~E5)**로 제한하고, TOP5는 이 5개를 **재사용**해 충족.

---

# 0) 공통 “하드 게이트(즉시 적용)”
- [ ] **락박스/튜닝 분리 규칙 강화**: 어떤 실험도 락박스 결과로 하이퍼파라미터/룰 변경 금지(오토파일럿에서 자동 차단).
- [ ] **누수 탐지 자동 실패 처리**: 시간정렬/가용시점 위반 발견 시 해당 런을 FAIL로 마킹하고 챔피언 교체 후보에서 제외.
- [ ] **비용 포함 성능만 표준 지표로 채택**: 비용=0 백테스트 결과는 “진단용”으로만 남기고 PASS 판단에서 제외.
- [ ] **US 주식 only + Tech/Healthcare 중심 + 8~14종목** 제약을 시스템 레벨에서 강제(ETF 매매 금지, ETF는 관측지표로만).

---

# TOP1) **누수(lookahead/label leakage) + 과최적화(embargo 부재) 차단**
### (a) 왜 필요한지
- 현재 챔피언이 락박스가 강함(lockbox_mean 4.01) → **작은 누수도 “좋은 챔피언”을 더 좋게 보이게 만드는 착시** 위험이 큼.
- 48h 자동 루프에서는 **데이터 가용 시점(예: 종가/체결/공시)** 어긋남이 가장 흔한 숨은 버그.

### (b) 위험/부작용
- 누수 차단 시 **수익 급락**이 나타날 수 있음(“기존 성능”의 일부가 누수였던 경우).
- 신호가 느려져 **회전율/타이밍**이 바뀜.

### (c) 최소 실험(재사용) 2~3개
- **E1**(누수 차단 패치) + **E5**(관측/감사 로깅)  
- **E1** + **E3**(비용 민감도 동시 확인: 누수 제거 후 비용에 더 취약해지는지)

### (d) PASS 조건(하드 + 소프트)
- **하드 PASS**
  - [ ] 누수 탐지 0건(가용시점 위반/미래값 참조/정렬 오류)
  - [ ] 락박스 min이 **0 미만으로 붕괴하지 않을 것**(현재 챔피언 lockbox_min 0.735)
- **소프트 PASS(성능)**
  - [ ] lockbox_mean ≥ **3.6** (챔피언 4.01의 ~90% 유지)
  - [ ] worst_mdd ≥ **-0.09** (챔피언 -0.081 대비 악화 제한)

# TOP2) **서바이버십/델리스팅/기업행동 반영 (유니버스 “포인트-인-타임” 정합성)**
### (a) 왜 필요한지
- Tech/Healthcare는 합병/상장폐지/심볼변경이 빈번 → **델리스팅 수익률 누락**은 장기 성능을 과대평가.
- 8~14종목 집중 포트폴리오는 **한 종목의 이벤트 누락이 전체 성능을 왜곡**.

### (b) 위험/부작용
- 데이터 소스가 빈약하면 “정합성 강화”가 곧 **결측 증가/트레이드 감소**로 이어짐.
- 델리스팅 반영 후 변동성이 증가할 수 있음.

### (c) 최소 실험 2~3개
- **E2**(PIT 유니버스/델리스팅/기업행동 패치) + **E5**
- **E2** + **E1**(PIT 적용 후 시점 누수 재검증)

### (d) PASS 조건
- [ ] 델리스팅/심볼변경 케이스가 로그에 “누락 없이” 기록(미해결 이벤트 0건)
- [ ] 락박스에서 트레이드 수/보유 종목 수가 **8~14 범위**를 안정적으로 유지(극단적 공백 주간 발생 시 FAIL)
- [ ] lockbox_mean ≥ **3.6** 또는 (성능 하락 시) **MDD 개선/회전율 감소/비용 감소** 중 2개 이상 동반

---

# TOP3) **비용 미반영(슬리피지/스프레드/임팩트/차입비용) → “실현 가능성” 게이트**
### (a) 왜 필요한지
- 자동 루프는 잦은 리밸런싱으로 흐르기 쉬움 → **슬리피지 20~60bp만 추가돼도 알파가 소거**될 수 있음.
- Tech/Healthcare는 이벤트 시 **스프레드 급등** 구간이 잦아 “평균 스프레드” 모델이 취약.

### (b) 위험/부작용
- 비용을 현실화하면 성능이 크게 떨어질 수 있음(특히 단기 모멘텀/리버설 계열).
- 숏이 포함되면 차입비용/리콜 리스크로 실행 불가 영역이 생김.

### (c) 최소 실험 2~3개
- **E3**(비용/슬리피지/임팩트 모델 패치) + **E5**
- **E3** + **E4**(레짐 게이트로 불리한 고변동 구간 회피 시 비용 탄력성 개선 확인)

### (d) PASS 조건
- [ ] “비용=0” 대비 “현실 비용”에서 성능 하락폭이 **허용 범위 내**(예: lockbox_mean 감소 ≤ 20%)
- [ ] 연간/월간 회전율이 상한을 넘으면 FAIL(운영 리스크 게이트): 예) 월 turnover > 사전 정의 상한
- [ ] 비용 구성(스프레드/임팩트/차입) 중 **단일 항목이 손익을 지배**하면 FAIL(모델이 특정 가정에 과민)

---

# TOP4) **US 주식 Tech+Healthcare 8~14종목 집중 포트폴리오 제약 하에서의 “노출(베타/섹터/팩터) 통제”**
### (a) 왜 필요한지
- 챔피언이 강해도, 실제로는 **QQQ/XLK 방향성 베타**로 벌었을 가능성 존재.
- 8~14종목은 idiosyncratic risk가 커서 **레짐/변동성 필터** 없으면 worst_mdd가 갑자기 커질 수 있음.

### (b) 위험/부작용
- 노출 통제는 알파를 깎을 수 있음(“이기던 방식”이 베타였던 경우).
- 게이트가 과도하면 **거래 공백**으로 기회손실 발생.

### (c) 최소 실험 2~3개
- **E4**(레짐/노출 게이트 패치: ETF는 관측지표로만) + **E5**
- **E4** + **E3**(고변동 회피가 비용/슬리피지에도 유리한지 동시 평가)

### (d) PASS 조건
- [ ] 보유 종목 수: **항상 8~14 유지**(현금 과다/과집중 방지)
- [ ] QQQ/XLK/XLV(관측지표) 대비 **포트폴리오 베타가 상한**을 넘으면 FAIL(예: |β_QQQ| > 0.6 같은 룰)
- [ ] worst_mdd가 **챔피언 대비 유사하거나 개선**(≥ -0.081 ~ -0.09 범위 유지)

---

# TOP5) **운영 리스크(48h 자동 루프) 관측/재현성/드리프트 감시 강화**
### (a) 왜 필요한지
- “성능이 안 움직임”의 상당수는 전략 문제가 아니라 **파이프라인/게이트/데이터 업데이트/신호 발생 빈도** 문제.
- 자동 루프에서는 “조용한 실패(silent failure)”가 가장 비쌈.

### (b) 위험/부작용
- 로깅/계측이 늘어 **런타임/스토리지 비용 증가**.
- 게이트를 촘촘히 하면 실험 throughput이 감소.

### (c) 최소 실험 2~3개
- **E5**(관측/분해 텔레메트리 패치) + **E1**(누수 로깅 동반)
- **E5** + **E3**(비용 항목별 손익 분해 자동 리포트)

### (d) PASS 조건
- [ ] 매 48h 루프마다 “분해 리포트” 자동 생성(트리거→적용→노출→비용→레짐)
- [ ] 재현성: 동일 시드/동일 데이터 스냅샷에서 결과가 허용 오차 내(큰 변동 시 FAIL)
- [ ] 실패 원인이 “전략”인지 “데이터/운영”인지 1회 루프 내 식별 가능(미분류 FAIL 0)

## 유니크 패치/실험 5개(E1~E5) — 48시간 자동 루프 형태로 정의
아래 5개만 돌려도 TOP1~TOP5를 모두 커버하도록 설계.

---

## E1) 누수 차단 패치 (Timestamp alignment + 1-bar delay + embargo)
**(1) 실험 정의**
- [ ] 모든 피처를 “실제로 알 수 있는 시점” 기준으로 재정렬(종가 기반이면 다음 bar에서만 사용).
- [ ] 라벨(수익률)과 피처 사이에 **embargo window** 적용(근접 시점 샘플 학습 제외).
- [ ] “미래 참조 가능성”이 있는 컬럼 자동 스캔(예: 다음날 종가/확정 지표 등) 후 차단.

**(2) 게이트**
- [ ] 누수 탐지 1건이라도 발생 시 FAIL
- [ ] tuning-lockbox 괴리가 과도하면 FAIL(예: tuning_mean - lockbox_mean > 2.0)

**(3) 기대 관측치**
- [ ] tuning_mean은 하락할 수 있으나 **lockbox 안정성 유지**
- [ ] “신호 발생 시점”이 1 bar 지연되어도 트레이드 빈도/수익 구조가 합리적으로 유지

---

## E2) PIT 유니버스 + 델리스팅/기업행동 반영 패치
**(1) 실험 정의**
- [ ] 유니버스 구성에 **포인트-인-타임** 적용(당시 존재/거래 가능 종목만).
- [ ] 델리스팅 수익률/현금정산 반영.
- [ ] 스플릿/머지/심볼변경을 포지션/가격에 일관 반영.

**(2) 게이트**
- [ ] 기업행동 이벤트 미해결(UNRESOLVED) 로그 존재 시 FAIL
- [ ] 보유 종목 수가 8 미만이 되는 구간이 일정 비율(예: 5% bars) 초과 시 FAIL

**(3) 기대 관측치**
- [ ] 성능이 소폭 하락해도 **MDD/테일 리스크가 더 현실적**으로 관측
- [ ] “너무 매끈한” 에쿼티 곡선이 깨지고, 대신 리스크 지표가 신뢰 가능해짐

---

## E3) 현실 비용 모델 패치 (슬리피지/스프레드/임팩트/차입)
**(1) 실험 정의**
- [ ] 거래비용 = 고정 수수료 + bid/ask 스프레드 + 거래대금 대비 임팩트(참여율 기반).
- [ ] 숏 가능 시 차입비용/리콜 리스크를 보수적으로 반영(최소 차입비용 floor).
- [ ] 비용 민감도 스윕(예: 비용 0.5x/1x/2x) 결과를 함께 저장.

**(2) 게이트**
- [ ] 비용 2x에서 lockbox_mean이 0 이하로 붕괴하면 FAIL(비용 탄력성 과도)
- [ ] 월 turnover 상한 초과 시 FAIL

**(3) 기대 관측치**
- [ ] “비용=0”에서만 좋은 전략이 걸러지고, 실행 가능한 전략만 남음
- [ ] 신호가 진짜면 비용을 올려도 완만히 감소하는 형태

---

## E4) 레짐/노출 게이트 패치 (ETF는 관측지표로만)
**(1) 실험 정의**
- [ ] 매매 유니버스: **미국 Tech+Healthcare 중심 8~14개 종목**(개별주만 거래).
- [ ] 관측지표(매매 금지): QQQ, XLK, XLV, VIX(또는 변동성 지표).  
- [ ] 레짐 게이트 예시(개념):  
  - 위험-on: QQQ 추세 양호 & 변동성 낮음 → 정상 운용  
  - 위험-off: 변동성 급등/추세 붕괴 → 포지션 축소/현금 비중 증가/리스크 패리티 강화  
- [ ] 베타/섹터/단일종목 비중 상한을 강제(과집중 방지).

**(2) 게이트**
- [ ] 보유 종목 수 8~14 위반 시 FAIL
- [ ] |β_QQQ| 상한 위반 지속 시 FAIL
- [ ] 게이트로 인한 “거래 공백”이 과도(예: 30% bars 이상 무포지션)하면 FAIL

**(3) 기대 관측치**
- [ ] worst_mdd가 완화되거나, 동일 MDD에서 평균 수익이 유지
- [ ] 비용(E3)과 결합 시 슬리피지 급등 구간 노출 감소

---

## E5) 성능 정체 원인 분해 텔레메트리/리포트 패치 (48h 루프 필수)
**(1) 실험 정의**
- [ ] 매 런마다 아래를 자동 저장(리포트 + JSON):
  - Trigger 단계: 신호 발생 횟수/강도 분포/누락률
  - Apply 단계: 게이트 통과율(레짐/리스크/유니버스 제약별로)
  - Exposure 단계: 보유 종목 수 분포, 섹터 비중, β(대상: QQQ/XLK/XLV), gross/net, 상위 기여 종목
  - Cost 단계: 스프레드/임팩트/수수료/차입 항목별 손익 기여
  - Regime 단계: 위험-on/off 구간 성과 분해
- [ ] 실패를 “데이터/운영/전략/비용/레짐” 중 하나로 자동 분류.

**(2) 게이트**
- [ ] 분해 리포트 누락 시 FAIL(자동 루프에서 관측 불가=운영 실패)
- [ ] 재현성 깨짐(동일 스냅샷 대비 결과 급변) 탐지 시 FAIL

**(3) 기대 관측치**
- [ ] “안 움직임”이 **신호 부족인지 / 게이트 과도인지 / 비용 드래그인지** 즉시 구분
- [ ] 다음 패치가 감이 아니라 계측 기반으로 좁혀짐

# 성능이 “안 움직일 때” 원인 분해 아이디어 (Trigger/적용/노출/비용/레짐) — 체크리스트
아래는 E5 리포트에서 바로 계산/표시하도록 고정 지표화.

## 1) Trigger(신호) 문제
- [ ] 신호 발생 빈도(일/주) 급감 여부
- [ ] 신호 강도 분포가 0 근처로 수렴했는지(스케일/정규화 버그 가능)
- [ ] 특정 종목/특정 시간대에만 신호가 몰리는지(데이터 결측/정렬 오류 가능)

## 2) Apply(게이트/제약 적용) 문제
- [ ] 레짐 게이트 통과율이 과도하게 낮은지(“항상 위험-off”)
- [ ] 8~14 종목 제약 때문에 주문이 잘리는 비율(클리핑) 급증 여부
- [ ] 리스크 제한(단일종목 상한/베타 상한) 위반으로 대부분 리젝트 되는지

## 3) Exposure(노출) 문제
- [ ] 실제 보유 종목 수가 8 미만으로 자주 떨어지는지(유니버스/데이터 문제)
- [ ] QQQ/XLK/XLV 베타가 의도와 다르게 1에 근접하는지(베타 전략화)
- [ ] 상위 1~2종목 PnL 기여도가 과도한지(집중 리스크/서바이버십 착시)

## 4) Cost(비용) 문제
- [ ] 총 손익 중 비용 비중이 일정 임계치 초과인지(예: 비용이 gross PnL의 30%+)
- [ ] 임팩트(거래대금 기반) 항목이 지배적인지(유동성/참여율 과다)
- [ ] 숏 차입비용이 특정 종목에서 폭증하는지(실거래 불가 신호)

## 5) Regime(레짐) 문제
- [ ] 위험-on에서는 좋고 위험-off에서 크게 깨지는지(필터 미흡)
- [ ] 변동성 급등 구간에서만 손실이 집중되는지(스프레드/갭 리스크)
- [ ] 레짐별 성과가 뒤바뀌었는지(최근 기간 구조 변화 → 피처/게이트 재설계 필요)
