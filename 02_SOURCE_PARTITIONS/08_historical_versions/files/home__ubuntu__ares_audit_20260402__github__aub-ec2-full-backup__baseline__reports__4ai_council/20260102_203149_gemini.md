### 1) 24~48시간 우선순위 TOP 5 제안

#### 1. [INFRA] 리밸런싱 로그 포맷/경로 긴급 수정 (Priority: Critical)
*   **이유:** `aub_rebalance_pinpoint`가 실패(FileNotFound/JSON Error)하고 있음. 매매 내역(Turnover, Slippage 반영 여부)을 볼 수 없으면 개선 불가.
*   **위험:** 로깅 로직 수정 시 백테스트 엔진 일시 중단 필요.
*   **실험:**
    *   `FIX_LOG_01`: 로그 출력을 CSV 대신 표준 JSONL로 통일 및 경로 하드코딩 제거.
    *   `VAL_LOG_01`: 더미 데이터로 백테스트 1회 구동 후 파서가 에러 없이 읽는지 검증.
*   **PASS 조건:** `aub_rebalance_pinpoint.py` 실행 시 Exit Code 0 반환 및 DataFrame 출력 확인.

#### 2. [DATA] 유니버스 Tech/Healthcare 상위 20 종목 강제 고정 (Priority: High)
*   **이유:** `degenerate_folds` 발생 원인은 대부분 소형주/상폐 종목 데이터 누락 혹은 유동성 부족. Tech/HC 대형주로 한정하여 데이터 퀄리티 확보 필요.
*   **위험:** 유니버스 축소로 인한 잠재적 알파 기회 상실(그러나 안정성이 우선).
*   **실험:**
    *   `UNIV_TOP20_LIQUID`: S&P500 Tech/HC 섹터 중 거래대금 상위 20개로만 유니버스 제한.
    *   `UNIV_DATA_STRICT`: 결측치 1% 이상 종목 유니버스에서 영구 제외.
*   **PASS 조건:** `degenerate_folds` 개수가 0 또는 1개 이하로 감소.

#### 3. [STRATEGY] 현금 비중 제약 완화 및 변동성 타겟팅 (Priority: Med)
*   **이유:** `exposure_max`가 0.84임에도 MDD 제어가 안 될 수 있음(집중 투자 리스크). `oos_min` 방어를 위해 변동성 기반 포지션 축소 로직 필요.
*   **위험:** 상승장에서 현금 비중 과다로 벤치마크 언더퍼폼.
*   **실험:**
    *   `VOL_TGT_15`: 포트폴리오 연환산 변동성 > 15% 예상 시 현금 비중 확대.
    *   `MAX_EXP_095`: Exposure Max를 0.95로 올리되, 개별 종목 Max 0.15 제한(분산 강제).
*   **PASS 조건:** OOS Min > -0.02 (손실폭 축소) 확인.

#### 4. [COST] 슬리피지/수수료 페널티 모델 강화 (Priority: Med)
*   **이유:** `oos_mean` 3.32는 과도하게 높음. 거래 비용이 0이거나 비현실적으로 낮게 설정되었을 확률 99%. 과최적화된 신호 제거 필요.
*   **위험:** 기존 챔피언 모델의 퍼포먼스 수치 급락(거품 제거 과정).
*   **실험:**
    *   `COST_BPS_10`: 매매당 비용 10bps 강제 적용.
    *   `TO_PENALTY`: 목적 함수에 Turnover * Cost 항 추가하여 잦은 매매 억제.
*   **PASS 조건:** OOS Mean이 현실적 범위(0.5~1.5)로 내려오되, Sharpe Ratio 유지.

#### 5. [REGIME] ETF(XLK, XLV) 모멘텀 필터 적용 (Priority: Low)
*   **이유:** Tech/HC 섹터 전체가 하락세일 때 개별 종목 롱온리는 필패. 섹터 ETF를 '관측 지표'로만 사용하여 전체 노출 조절.
*   **위험:** 휩소(Whipsaw) 구간에서 진입/청산 반복으로 손실 누적.
*   **실험:**
    *   `REGIME_MA200`: XLK 또는 XLV가 200일 이동평균 하회 시 해당 섹터 종목 매수 금지.
*   **PASS 조건:** 하락장(2022년 등) 구간에서의 MDD 10%p 이상 개선.

### 2) 실행 가능한 실험 패치 (48hr Auto-Loop)

#### 실험 A: `FIX_UNIV_STABILITY`
1.  **실험 정의:** 유니버스를 '최근 5년 데이터 완전성 99% 이상'인 Tech+HC 종목 상위 15개로 고정하고, 코너 솔루션(특정 종목 몰빵) 방지를 위해 개별 종목 비중 상한 20% 설정.
2.  **게이트:**
    *   `len(degenerate_folds) == 0`
    *   `exposure_max <= 0.98`
3.  **기대 관측치:** OOS Mean은 다소 하락하더라도, 폴드 간 성능 편차가 줄어들어야 함.

#### 실험 B: `LOG_REPAIR_AND_COST`
1.  **실험 정의:** 로깅 포맷을 JSONL로 수정하고, 백테스트 엔진에 `transaction_cost_model` (bps=10) 주입.
2.  **게이트:**
    *   `os.path.exists(log_file)` == True
    *   `Turnover` (연환산) < 500%
3.  **기대 관측치:** 기존 대비 수익률 곡선이 완만해지며, '톱니바퀴' 모양의 자산 곡선(비용 누적)이 관측되면 성공적인 현실 반영임.

#### 실험 C: `REGIME_FILTER_XLK`
1.  **실험 정의:** 매 리밸런싱 시점, `XLK(Tech ETF)`의 종가가 `SMA(200)`보다 낮으면 Tech 종목의 타겟 비중을 `original_weight * 0.5`로 강제 축소.
2.  **게이트:**
    *   `Downside Deviation` 감소 확인
3.  **기대 관측치:** 2022년 하락장에서 Cash 비중이 50% 이상으로 유지되는지 확인.

### 3) 성능 정체 시 원인 분해 (Debug Logic)

만약 위 조치 후에도 성능이 개선되지 않거나 0에 수렴한다면 다음 순서로 체크리스트 수행:

1.  **트리거 (Signal Trigger):** 신호가 너무 드물게 발생하는가?
    *   *Check:* 최근 1년 매매 횟수(Trade Count)가 20회 미만이면 조건 완화 필요.
2.  **적용 (Execution Gap):** 신호는 떴는데 자금 부족/제약조건으로 체결이 안 되는가?
    *   *Check:* 로그에서 `Order Reject` 또는 `Cash Shortage` 메시지 검색.
3.  **노출 (Exposure Mismatch):** 롱(Long) 비중이 너무 낮은가?
    *   *Check:* `exposure_min`이 장기간 0.0 근처에 머무는지 확인 (쫄보 알고리즘).
4.  **비용 (Cost Drag):** 수익이 비용으로 다 나가는가?
    *   *Check:* `Gross Return`과 `Net Return`의 차이가 연 5% 이상 벌어지는지 확인.
5.  **레짐 (Regime Fit):** 현재 시장(Tech 강세/약세)과 전략 성향이 반대인가?
    *   *Check:* 벤치마크(XLK) 대비 상관계수(Correlation)가 음수이거나 0에 가까운지 확인.
