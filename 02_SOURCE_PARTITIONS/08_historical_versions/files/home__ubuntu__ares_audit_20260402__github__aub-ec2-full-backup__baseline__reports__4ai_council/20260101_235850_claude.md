## 1. Priority TOP 5 Patches

### PATCH #1: Regime-Specific Exposure Cap (레짐별 노출 한도)

#### (a) 왜 필요한가
- tuning_min이 -1.50으로 악화 → 특정 fold(=레짐)에서 과노출
- Lockbox 좋아도 OOS 레짐 변화 시 MDD 폭발 가능

#### (b) 위험/부작용
- 과도한 cap → 수익 ceiling 발생
- 레짐 분류 오류 시 역효과

#### (c) 최소 실험

| 실험 ID | 설정 | 게이트 |
|---------|------|--------|
| `exp_regime_cap_v1` | VIX>25 시 max_position=0.6 | tuning_min > -1.35 |
| `exp_regime_cap_v2` | SPY 20d momentum<0 시 max_position=0.5 | worst_mdd < -0.06 |
| `exp_regime_cap_v3` | 둘 다 적용 (AND 조건) | 둘 다 충족 |

#### (d) PASS 조건
```
tuning_min > -1.35 AND lockbox_mean > 1.50 AND worst_mdd < -0.055
```

### PATCH #2: Cost Model Stress Test (비용 민감도)

#### (a) 왜 필요한가
- 현재 슬리피지/수수료 가정이 낙관적일 가능성
- 실거래 시 성과 30~50% 감소 흔함

#### (b) 위험/부작용
- 과도한 비용 가정 → 유효 전략 폐기
- 턴오버 기반 전략 전멸 가능

#### (c) 최소 실험

| 실험 ID | 비용 설정 | 게이트 |
|---------|-----------|--------|
| `exp_cost_10bps` | 편도 10bps (현행 가정) | baseline |
| `exp_cost_20bps` | 편도 20bps | lockbox_mean > 1.20 |
| `exp_cost_30bps` | 편도 30bps (스트레스) | lockbox_mean > 1.00 |

#### (d) PASS 조건
```
exp_cost_20bps: lockbox_mean > 1.20 → 실전 배포 OK
exp_cost_30bps: lockbox_mean > 1.00 → 전략 robust
```

---

### PATCH #3: Signal Decay Analysis (신호 유효기간)

#### (a) 왜 필요한가
- 현재 신호가 t+1에만 유효한지, t+2~t+5까지 지속인지 미확인
- Decay 빠르면 실행 지연에 취약

#### (b) 위험/부작용
- Decay 느린 신호만 선별 시 수익 감소
- 거래 빈도 변화로 비용 구조 변경

#### (c) 최소 실험

| 실험 ID | 설정 | 게이트 |
|---------|------|--------|
| `exp_decay_lag1` | 신호 t+1 실행 (현행) | baseline |
| `exp_decay_lag2` | 신호 t+2 실행 | return_degradation < 20% |
| `exp_decay_lag3` | 신호 t+3 실행 | return_degradation < 35% |

#### (d) PASS 조건
```
lag2 degradation < 20% → 실행 여유 확보됨
lag3 degradation < 35% → 운영 리스크 낮음
```

### PATCH #4: Concentration Risk Limit (집중도 제한)

#### (a) 왜 필요한가
- 8~14 종목 중 상위 3개가 60%+ 비중 가능
- 단일 종목 이벤트(실적, 소송)에 MDD 폭발

#### (b) 위험/부작용
- 분산 강제 시 conviction 높은 베팅 희석
- 수익 ceiling 발생

#### (c) 최소 실험

| 실험 ID | 설정 | 게이트 |
|---------|------|--------|
| `exp_conc_max20` | 종목당 max 20% | worst_mdd < -0.06 |
| `exp_conc_max15` | 종목당 max 15% | worst_mdd < -0.05 |
| `exp_conc_hhi` | HHI < 0.15 강제 | worst_mdd < -0.05 AND lockbox > 1.40 |

#### (d) PASS 조건
```
worst_mdd < -0.05 AND lockbox_mean drop < 10%
```

### PATCH #5: Survivorship Leak Audit (생존편향 점검)

#### (a) 왜 필요한가
- 현재 유니버스가 "현재 시점 상장 종목"만 포함 가능
- 과거 상장폐지/인수 종목 누락 시 성과 부풀림

#### (b) 위험/부작용
- 점검 결과 성과 급락 시 전략 폐기 필요
- 데이터 수급 비용 발생

#### (c) 최소 실험

| 실험 ID | 설정 | 게이트 |
|---------|------|--------|
| `audit_surv_list` | 2015~현재 상폐/인수 종목 리스트 추출 | 리스트 > 0 |
| `audit_surv_impact` | 해당 종목 포함 재백테스트 | lockbox 차이 < 15% |
| `audit_surv_fix` | point-in-time 유니버스 적용 | lockbox 차이 < 10% |

#### (d) PASS 조건
```
생존편향 보정 후 lockbox_mean > 1.30 → 전략 유효
보정 후 하락 > 25% → 전략 의심, 재설계
```

## 2. 성능 안 움직일 때 원인 분해 트리

```
성능 정체
├─ [1] 트리거 문제 (Signal not firing)
│   ├─ 조건 너무 strict → 거래 횟수 < 월 2회
│   └─ 점검: trade_count / month 측정
│
├─ [2] 적용 문제 (Position not taken)
│   ├─ 리스크 모듈이 신호 override
│   └─ 점검: signal_fired vs position_taken 비율
│
├─ [3] 노출 문제 (Size too small)
│   ├─ 변동성 조절이 position 축소
│   └─ 점검: avg_position_size 추적
│
├─ [4] 비용 문제 (Eaten by cost)
│   ├─ 턴오버 높아 수익 잠식
│   └─ 점검: gross vs net return gap
│
└─ [5] 레짐 문제 (Regime mismatch)
    ├─ 현재 시장이 전략 비선호 레짐
    └─ 점검: 레짐별 성과 분해
```

**디버그 우선순위**: `[4] 비용` → `[3] 노출` → `[1] 트리거` → `[5] 레짐` → `[2] 적용`
