### 1. Degenerate Folds(1, 2, 3, 8) 긴급 복구
**a) 필요성:** 전체 Fold의 약 40%가 파산(Degenerate) 상태임. 현재의 높은 `oos_mean(3.32)`은 생존한 Fold만의 편향된 결과일 확률이 매우 높음(Survivorship Bias).
**b) 위험/부작용:** 죽어있던 Fold가 살아나면 전체 평균 수익률은 급락할 수 있음. 그러나 이것이 '진짜' 성능임.
**c) 실험 (Patch):**
   - **Exp 1-1 (Data Imputation):** 데이터 전처리 단계에서 `NaN` 또는 `0` 거래량 발생 시 직전 값(Forward Fill) 강제 적용 후 재실행.
   - **Exp 1-2 (Constraint Relax):** 손절매(Stop-loss) 또는 진입 장벽(Threshold)을 50% 완화하여 최소 1회 이상 거래가 발생하도록 유도.
   - **Exp 1-3 (Fallback Logic):** 모델 신호가 없을 때 현금 100%가 아닌, SPY 10% 보유로 로직 변경하여 지표 산출 강제.
**d) PASS 조건:** `degenerate_folds` 리스트가 Empty(`[]`)가 될 것. `oos_min`이 -1.0 이상으로 방어될 것.

### 2. 로깅 파이프라인 정비 및 비용 현실화
**a) 필요성:** `Error loading .../rebalance.csv` 오류 발생. 거래 내역이 없으면 슬리피지와 회전율(Turnover)을 측정할 수 없음. 과최적화의 주범.
**b) 위험/부작용:** 로깅 오버헤드로 백테스트 속도 저하 가능성. 비용 반영 시 성과가 음수로 전환될 수 있음.
**c) 실험 (Patch):**
   - **Exp 2-1 (JSONL Enforcement):** 로거 포맷을 CSV에서 JSONL로 강제 변환 및 `flush=True` 옵션 추가.
   - **Exp 2-2 (Cost Stress Test):** 거래당 비용(TC)을 10bps에서 20bps로 상향 설정하여 검증.
**d) PASS 조건:** `rebalance_pinpoint.py`가 에러 없이 실행되고, 회전율(Turnover)이 일 10% 이하로 관측될 것.

### 3. Tech+Healthcare Universe 강제 및 압축
**a) 필요성:** 요구사항(Tech+Healthcare, 8~14 종목) 준수 및 분산 효과 극대화. 잡다한 종목 제거.
**b) 위험/부작용:** 종목 풀이 좁아져 특정 개별주 리스크(Idiosyncratic Risk) 노출 증가.
**c) 실험 (Patch):**
   - **Exp 3-1 (Sector Hard-Filter):** GICS 섹터 기준 IT, Health Care만 남기고 나머지 drop. 시가총액 상위 50위 내 14개 종목 선정(예: NVDA, MSFT, LLY, UNH 등).
   - **Exp 3-2 (Correlation Cut):** 종목 간 상관계수가 0.7 이상인 쌍 중 변동성이 낮은 종목 제거하여 8~10개로 압축.
**d) PASS 조건:** 포트폴리오 내 섹터 비중이 Tech/Bio 합산 100%, 종목 수 8~14개 유지.

### 4. Downside Volatility 제어 (Exposure 0.83 -> Dynamic)
**a) 필요성:** `oos_min` 음수 방어. 현재 최대 노출 0.83은 하락장에서 여전히 위험함.
**b) 위험/부작용:** 상승장에서 수익률 제한(Lagging).
**c) 실험 (Patch):**
   - **Exp 4-1 (VIX Gate):** ETF 관측 지표 활용. VIX(또는 VXN) 20 이상 시 최대 Exposure를 0.5로 제한.
   - **Exp 4-2 (Drawdown Cut):** 개별 종목 MDD가 10% 초과 시 해당 종목 비중 0으로 강제 청산(Cool-down 5일).
**d) PASS 조건:** `oos_min` > -0.01 (손실 폭 축소), Worst MDD < 15%.

### 5. Look-ahead Bias 점검 (Feature Lag)
**a) 필요성:** 높은 OOS Mean(3.32)은 미래 데이터 참조(Look-ahead) 가능성 시사. 특히 종가(Close) 사용 시 주의.
**b) 위험/부작용:** 시그널이 늦게 발생하여 진입 시점을 놓칠 수 있음.
**c) 실험 (Patch):**
   - **Exp 5-1 (Lag enforcement):** 모든 입력 Feature(Open, High, Low, Close, Volume)에 `shift(1)` 강제 적용.
   - **Exp 5-2 (Execution Delay):** 시그널 발생일(T)의 종가가 아닌 익일 시가(T+1 Open)로 체결 가격 변경.
**d) PASS 조건:** 패치 후에도 `oos_mean`이 1.5 이상 유지되면 유효한 알파로 인정. 급락 시 폐기.
