# 우선순위 TOP 5 제안 (24~48시간 실행 계획)

### 1. [CRITICAL] 로그 파이프라인 복구 및 데이터 무결성 검증
*   **(a) 필요성:** `rebalance.csv` 로딩 에러(Empty file/JSON parsing error)로 인해 트레이딩 내역(Pinpoint) 분석이 불가능함. 맹인 상태.
*   **(b) 리스크:** 로깅 로직 수정 중 운영 데몬 재시작 필요. 데이터 포맷 변경 시 기존 분석 툴 호환성 파괴.
*   **(c) 실험 (Experiments):**
    1.  **EXP_LOG_FIX_01:** `aub_rebalance_pinpoint`가 참조하는 로그 경로를 절대 경로로 하드코딩하고, CSV 헤더 강제 출력 패치 적용.
    2.  **EXP_LOG_JSONL:** CSV 대신 JSONL 포맷으로 출력 통일(파싱 오류 방지).
*   **(d) PASS 조건:** `aub_rebalance_pinpoint.py` 실행 시 에러 없이 리포트 생성 및 진입/청산 종목 3개 이상 확인.

### 2. [SANITY] 비용 모델 가압 테스트 (Reality Check)
*   **(a) 필요성:** OOS Mean 3.32는 비현실적 수치. 과최적화(Overfitting) 혹은 수수료/슬리피지 "0" 설정 의심. 서바이버십 바이어스 가능성 높음.
*   **(b) 리스크:** 샤프 비율 급락으로 인한 전략 폐기(Champion 탈락). 멘탈 붕괴.
*   **(c) 실험 (Experiments):**
    1.  **EXP_COST_BPS_10:** 매매 수수료/슬리피지 합산 10bps(0.1%) 강제 적용 후 백테스트.
    2.  **EXP_EXEC_DELAY_1:** 시그널 발생 후 `next_open`이 아닌 `next_close` 혹은 `T+1 open` 진입으로 지연(Look-ahead 방지).
*   **(d) PASS 조건:** OOS Mean > 1.0 유지하면서 MDD < 15%. (3.32 -> 1.x대로 하락하는 것이 정상)

### 3. [DEGENERACY] 죽은 폴드(Fold 1,2,3,8) 심폐소생
*   **(a) 필요성:** 전체 10개(추정) 폴드 중 4개가 Degenerate 상태. 특정 레짐(하락장 혹은 횡보장)에서 거래가 전무하거나 로직이 터짐. Tech/Health 섹터 특유의 변동성 때문일 수 있음.
*   **(b) 리스크:** 억지로 거래를 발생시키려다 MDD 폭발.
*   **(c) 실험 (Experiments):**
    1.  **EXP_THRES_LOOSE:** 진입 임계값(Threshold)을 기존 대비 80% 수준으로 완화.
    2.  **EXP_UNIVERSE_CHECK:** 해당 폴드 기간(예: 2022년 하락장)에 유효한 Tech/Health 티커가 Universe에 존재하는지 확인(상장폐지/합병 종목 누락 체크).
*   **(d) PASS 조건:** Degenerate Folds 개수 0~1개로 감소.

### 4. [CONSTRAINTS] Tech/Health 섹터 편중 리스크 제어
*   **(a) 필요성:** Tech와 Healthcare는 상관계수가 낮을 때도 있지만, 매크로(금리)에 민감함. 8~14개 종목 제한 시 개별 종목 리스크 노출 극대화.
*   **(b) 리스크:** 헷지 수단(ETF 등) 부재로 인한 변동성 그대로 노출.
*   **(c) 실험 (Experiments):**
    1.  **EXP_SECTOR_BAL:** 포트폴리오 내 Tech:Health 비중을 강제로 6:4 ~ 4:6 범위로 제한(Soft constraint).
    2.  **EXP_VOL_SCL:** 개별 종목 변동성 역가중(Inverse Volatility) 비중 할당 적용.
*   **(d) PASS 조건:** `exposure_max`가 0.9 이상으로 상승하며, 특정 섹터 몰빵 현상 방지 확인.

### 5. [EXECUTION] 현금 유휴화(Cash Drag) 최소화
*   **(a) 필요성:** 현재 `exposure_max`가 0.838. 강세장에서 16% 현금 보유는 수익률 저하 요인. 8~14개 종목이라면 슬롯이 꽉 차야 함.
*   **(b) 리스크:** 무리한 진입으로 인한 승률(Win rate) 하락.
*   **(c) 실험 (Experiments):**
    1.  **EXP_FILL_RANK:** 시그널 강도 상위 N개 무조건 진입 (Threshold 제거, Ranking 시스템 도입).
    2.  **EXP_REBAL_FREQ:** 리밸런싱 주기를 단축하여 현금 소진 속도 향상.
*   **(d) PASS 조건:** `exposure_mean` > 0.8 달성.

# 성능 정체 시 원인 분해 (Debug Tree)

성능이 움직이지 않거나 0에 수렴할 때 다음 순서로 체크리스트 수행.

1.  **Trigger (신호 발생 여부)**
    *   [ ] Universe 내 Tech/Healthcare 14개 종목 중 Active한 종목이 5개 미만인가? (데이터 누락 확인)
    *   [ ] Feature 값들이 `NaN`이나 `Infinity`로 발산하여 필터링 되는가?
    *   [ ] *Action:* `feature_summary.csv` 추출하여 통계 확인.

2.  **Execution (주문 집행)**
    *   [ ] 주문 금액이 최소 거래 단위(Lot size) 미만이라 거부되는가?
    *   [ ] 가용 현금(Buying Power) 계산 로직에서 `Locked Cash`가 해제되지 않는 버그가 있는가?
    *   [ ] *Action:* 주문 로그에서 `Order Rejected` 카운트 집계.

3.  **Cost & Exposure (비용 및 노출)**
    *   [ ] 매매 회전율(Turnover)이 너무 높아 수익이 수수료로 상쇄되는가?
    *   [ ] `exposure_min`이 0.0인 기간이 전체의 50%를 넘는가? (겁쟁이 알고리즘)
    *   [ ] *Action:* 일별 PnL 분해(Gross PnL vs Net PnL) 비교 차트 생성.

4.  **Regime (시장 국면)**
    *   [ ] Tech/Health 섹터가 동시에 하락하는 구간(Correlated Drawdown)인가?
    *   [ ] *Action:* 벤치마크(XLK, XLV) 대비 베타(Beta)값 시계열 확인. 베타가 음수거나 0에 가까우면 로직 변경 필요.
