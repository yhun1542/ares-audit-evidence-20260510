## 1. 우선순위 TOP 5 패치

### P1. 🚨 파이프라인 복구 (Blocking)

**(a) 필요성**
- rebalance.csv/jsonl 로딩 실패 → 어떤 종목/날짜에서 손실 발생했는지 추적 불가
- 블라인드 상태에서 전략 수정은 과최적화 위험

**(b) 위험/부작용**
- 파일 포맷 불일치 시 기존 로그 유실 가능
- 수정 중 autopilot 충돌

**(c) 실험**

| ID | 실험 | 게이트 | 기대 관측치 |
|----|------|--------|-------------|
| P1-A | `rebalance.csv` 경로/존재 확인 스크립트 | 파일 존재 & row > 100 | 경로 출력, 행 수 |
| P1-B | JSON→CSV 변환 fallback 추가 | 변환 성공 & pinpoint 실행 | diff 리포트 생성 |
| P1-C | `--base-log` 인자 하드코딩 제거, config에서 읽기 | argparse 에러 0 | 정상 실행 로그 |

**(d) PASS 조건**
```
aub_rebalance_pinpoint.py 실행 시 
"Generated pinpoint report" + 실제 diff 테이블 출력
```

### P3. 💰 비용 모델 검증

**(a) 필요성**
- OOS 하락이 "실제 손실" vs "비용 미반영 환상" 구분 필요
- 슬리피지/스프레드 0.1% 가정이 현실적인지

**(b) 위험/부작용**
- 비용 과다 적용 시 시그널 자체가 죽음
- 소형주 비중 높으면 비용 영향 과대

**(c) 실험**

| ID | 실험 | 게이트 | 기대 관측치 |
|----|------|--------|-------------|
| P3-A | 비용 0bp로 재실행 → 비용 영향 측정 | OOS diff < 0.3 | 비용 기여도 |
| P3-B | 턴오버 리포트 (월간 회전율) | < 30%/월 | 회전율 수치 |
| P3-C | 스프레드 10bp→15bp 민감도 | OOS 하락 < 10% | Sharpe 변화 |

**(d) PASS 조건**
```
비용 0bp OOS - 비용 10bp OOS < 0.3
→ 비용이 주 원인 아님 확인
```
