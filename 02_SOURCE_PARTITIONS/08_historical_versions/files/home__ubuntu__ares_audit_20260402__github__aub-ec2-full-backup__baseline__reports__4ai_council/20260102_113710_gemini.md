*   **실험 정의**:

    *   `verify_empty`: 거래가 한 건도 발생하지 않아 빈 파일이 생성되는 케이스 예외 처리.
*   **게이트**: `rebalance.jsonl` 파일 용량 > 0KB AND Valid JSON check pass.
*   **기대 관측치**: 거래 내역(Ticker, Qty, Price, Cost) 정상 파싱.

*   **위험/부작용**: 잦은 유니버스 교체로 인한 턴오버 증가.

*   **기대 관측치**: OOS 성능 하락하더라도, 실전 적합성(Robustness) 확보.

### 성능 정체 원인 분해 (Debugging Stagnant Performance)

성능이 움직이지 않거나(Flat), 지표 간 괴리가 클 때 다음 순서로 점검:

1.  **Trigger Failure (신호 발생)**
    *   *가설*: Feature 전처리 과정에서 `NaN` 발생으로 신호가 0으로 수렴.
    *   *확인*: `degenerate_folds`는 비어있으나, 개별 종목의 Entry Signal Count가 0인지 확인.

2.  **Filter/Gate Blocking (신호 차단)**
    *   *가설*: 하드코딩된 리스크 관리 룰(예: `stop_loss`)이 너무 타이트하여 진입 즉시 청산.
    *   *확인*: 평균 보유 기간(Average Holding Period)이 1일 미만인지 체크.

3.  **Cost Decay (비용 잠식)**
    *   *가설*: Gross Profit은 우상향이나, Net Profit이 횡보. (OOS 1.88 vs 2.62 괴리 원인 유력).
    *   *확인*: `Total Transaction Cost / Gross Profit` 비율이 30%를 초과하는지 확인.

4.  **Regime Mismatch (시장 환경)**
    *   *가설*: 2026년의 시장 데이터(Tech/Health)가 훈련 데이터(과거)와 분포가 다름(Covariate Shift).
    *   *확인*: 최근 3개월 데이터의 Feature 분포가 훈련 전체 분포의 2-Sigma를 벗어나는지 확인.
