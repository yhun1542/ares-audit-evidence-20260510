## 📋 TOP 5 우선순위 (48h 체크리스트)

### P0. 파이프라인 복구 (BLOCKER)

#### (a) 왜 필요한가
- `rebalance.csv` 로딩 실패 → 비용/슬리피지 검증 불가
- `worst_mdd: None` → 리스크 게이트 무력화
- 퇴화 fold 원인 추적 불가

#### (b) 위험/부작용
- 복구 중 기존 로그 덮어쓰기 위험
- 스키마 변경 시 하위호환 깨짐

#### (c) 최소 실험

| ID | 실험 | 게이트 | 기대 관측치 |
|----|------|--------|-------------|
| P0-1 | `rebalance.jsonl` 스키마 검증 + CSV 변환기 | 파싱 성공률 100% | 전체 리밸 이벤트 복원 |
| P0-2 | MDD 계산 로직 fold별 분리 실행 | 10개 fold 모두 수치 반환 | worst_mdd ∈ [-0.5, 0] |
| P0-3 | Degenerate fold 로그 덤프 (fold 1,2,3,8) | 원인 태그 3종 이상 | {no_signal, zero_exposure, crash} |

#### (d) PASS 조건
```
ALL(
  rebalance_parse_rate == 1.0,
  worst_mdd != None,
  degenerate_fold_count <= 2
)
```

### P1. Degenerate Fold 원인 분해

#### (a) 왜 필요한가
- 4/10 fold 퇴화 = OOS 신뢰구간 ±50% 이상 오염
- 특정 레짐(코로나, 금리인상기) 집중 가능성

#### (b) 위험/부작용
- 해당 구간 제거 시 survivorship bias
- 과거 레짐 재발 시 실패 반복

#### (c) 최소 실험

| ID | 실험 | 게이트 | 기대 관측치 |
|----|------|--------|-------------|
| P1-1 | Fold별 날짜 범위 + 섹터 노출 히트맵 | 퇴화 fold 공통 패턴 1개 이상 | 예: "2022Q2-Q4 Healthcare 0%" |
| P1-2 | 퇴화 fold에서 signal 분포 vs 정상 fold | KS-test p < 0.05 | signal 평균 차이 > 0.3σ |
| P1-3 | 강제 min_exposure=10% 로 재실행 | 퇴화 fold 2개 이하로 감소 | OOS mean 하락 ≤ 15% |

#### (d) PASS 조건
```
degenerate_folds <= 2 AND oos_mean >= 2.5
```

### P2. 과최적화 검증 (OOS 점프 원인)

#### (a) 왜 필요한가
- OOS 2.63 → 3.32 (+26%) 단일 실험에서 발생
- 동시에 퇴화 fold 증가 = 전형적 overfitting 시그니처

#### (b) 위험/부작용
- 진짜 개선을 과최적화로 오판할 위험
- 검증 과정에서 compute 2x 소모

#### (c) 최소 실험

| ID | 실험 | 게이트 | 기대 관측치 |
|----|------|--------|-------------|
| P2-1 | IS/OOS gap 계산: `(IS_mean - OOS_mean) / IS_std` | gap < 1.5 | 현재 예상: gap > 2.0 |
| P2-2 | Walk-forward 5-fold → 10-fold 교차검증 | OOS std 감소 | std 변화율 < 20% |
| P2-3 | 파라미터 ±10% perturbation sensitivity | OOS 변동 < 0.5 | 변동 > 1.0이면 취약 |

#### (d) PASS 조건
```
is_oos_gap < 1.5 AND param_sensitivity < 0.5
```

### P3. 비용/슬리피지 현실화

#### (a) 왜 필요한가
- 리밸런스 로그 깨짐 → 현재 비용 반영 여부 불명
- Tech 고베타 종목 슬리피지 과소평가 가능

#### (b) 위험/부작용
- 비용 과다 적용 시 전략 사망 오판
- 종목별 차등 비용은 복잡도 폭발

#### (c) 최소 실험

| ID | 실험 | 게이트 | 기대 관측치 |
|----|------|--------|-------------|
| P3-1 | 현재 cost model 파라미터 출력 | 명시적 값 확인 | {spread_bps, commission, slippage_model} |
| P3-2 | cost × 1.5 스트레스 테스트 | OOS mean 하락 < 30% | 하락 > 50%면 비용 민감 |
| P3-3 | 턴오버 상한 20% → 15% 제약 | 비용 후 OOS 개선 | turnover 감소 + net return 유지 |

#### (d) PASS 조건
```
cost_stressed_oos >= 0.7 * base_oos AND turnover <= 0.15
```

│   └── 슬리피지 모델 현실 괴리

└── [레짐] 특정 구간만 실패?
