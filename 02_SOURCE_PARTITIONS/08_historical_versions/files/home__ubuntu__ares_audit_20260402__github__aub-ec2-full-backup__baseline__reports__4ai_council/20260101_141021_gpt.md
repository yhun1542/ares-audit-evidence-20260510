## TOP5 우선순위(24~48h) — “명령형 체크리스트”
1) **누수/타이밍/서바이버십 1차 봉쇄**
2) **비용(수수료·스프레드·슬리피지) + 턴오버 제어를 목적함수에 반영**
3) **노출(베타/섹터/단일종목/팻테일) 리스크 게이트를 시스템 레벨로 고정**
4) **레짐(Tech vs Healthcare, Risk-on/off) 관측지표(ETF)로 위험예산만 가변**
5) **운영 리스크(재현성·데이터 드리프트·실패 안전장치) 자동 점검 루프에 편입**

아래는 각 제안별 (a)왜 (b)위험 (c)최소 실험/점검 2~3개 (d)PASS 조건.  
※ 48시간 “자동 루프에 실제로 태울” **Primary 실험은 총 4개로 제한**하고, 나머지는 **Secondary(후보 폭발 없이 빠른 점검/리포트)**로 둠.

---

# 1) 누수/타이밍/서바이버십 1차 봉쇄
### (a) 왜 필요한지
- 지금 수치(락박스 mean ~1.33, MDD ~-9%) 구간에서 개선이 멈추는 가장 흔한 원인이 **미세 누수(정렬/발표시점/리밸런스 시각)** 또는 **서바이버십(현재 구성 종목만 사용)**임.
- “조금 좋아졌다”가 반복될수록, 실제로는 **락박스가 누수에 관대**하거나 **튜닝이 과최적화**일 가능성부터 제거해야 함.

### (b) 위험/부작용
- 누수 차단 후 성능이 하락할 수 있음(정상).
- 데이터 파이프라인 변경으로 과거 결과 재현이 깨질 수 있음(운영 리스크).

### (c) 최소 실험/점검 2~3개
**Primary-1 (48h 루프 투입)**  
- **실험 정의:** “피처/라벨 `asof` 타이밍 강제 + 발표지연(embargo) + purged CV” 패치  
  - 모든 피처에 대해 “사용 가능 시점”을 명시하고, 리밸런스 컷오프 이후 값 접근 차단  
  - 이벤트성 데이터(실적/가이던스 등)는 최소 +1~2 trading day 지연(보수적) 옵션
- **게이트:**  
  - (필수) 동일 코드로 **과거 리포트 재현 오차 0**(seed 고정)  
  - (필수) “피처 timestamp <= 의사결정 timestamp” 위반 0건  
- **기대 관측치:**  
  - 튜닝 평균이 일부 떨어져도, **락박스-튜닝 괴리 감소(과최적화 감소)**, 최악 MDD 악화 방지

**Secondary 점검-1**  
- **서바이버십 감사 리포트 생성:** 백테스트 시작 시점에 존재하지 않던 티커 포함 여부, 상장폐지/합병 처리 방식(미국주식 corporate action) 로그화

**Secondary 점검-2**  
- **리밸런스/체결 시각 일관성 검사:** “신호 생성(종가) → 다음날 시가/종가 체결” 규칙을 코드로 강제하고 어긋난 케이스 카운트 출력

### (d) PASS 조건
- (누수 게이트) 타임라인 위반 0 + 서바이버십 경고 0(또는 예외 목록 명시)
- (성능) **락박스 mean ≥ Champion(1.3295) - 0.002** 이내 유지하면서  
  **worst_mdd ≤ -0.0902 악화 금지**, lockbox_min 악화 금지(더 음수로 가지 않기)

---

# 2) 비용 반영 + 턴오버 제어(“비용 미반영” 우선 제거)
### (a) 왜 필요한지
- Tech/Healthcare 8~14종목은 리밸런스가 조금만 잦아도 **거래비용이 알파를 씹어먹는 구조**가 되기 쉬움.
- 현재 지표가 좋아도 “비용 0 가정”이면 실전에서 바로 붕괴 가능.

### (b) 위험/부작용
- 비용 모델이 과도하면 거래가 거의 멈추고 성능/다양성이 줄 수 있음.
- 과도한 턴오버 페널티는 레짐 전환 대응을 늦춤.

### (c) 최소 실험/점검 2~3개
**Primary-2 (48h 루프 투입)**  
- **실험 정의:** “슬리피지(스프레드+충격) + 커미션 + 턴오버 페널티를 목적함수에 추가”  
  - 단순 고정 bps(예: 2~10bps) + 거래대금 대비 충격(보수적으로) 중 하나를 선택해 일괄 적용  
  - 최적화가 있다면 목적함수에 `- cost_estimate - λ*turnover` 추가
- **게이트:**  
  - 평균 일일 turnover 상한(예: 25~40%/day 범위 중 하나로 고정) 위반 시 FAIL  
  - 비용 차감 전/후 성과 모두 리포트(“비용 민감도”가 보이게)
- **기대 관측치:**  
  - 비용 차감 후 락박스 mean 방어 + MDD 완화(거래가 줄며 꼬리 리스크 감소)

**Secondary 점검-1**  
- “비용 민감도 스윕”을 **후보 생성 없이** 리포트로만: 0/2/5/10bps에서 락박스 mean 변형 곡선 출력(탄력성 확인)

**Secondary 점검-2**  
- “거래 집중도” 점검: 특정 날짜/특정 종목에 거래가 몰리는지(운영·체결 리스크) 상위 10 케이스 출력

### (d) PASS 조건
- 비용 포함 락박스에서 **Champion 대비 mean +0.003 이상** 또는  
  mean이 비슷하면 **worst_mdd를 -0.0902보다 개선(덜 음수)**  
- turnover 상한 위반 0, 거래 집중도(상위1일 비중) 과도 시 FAIL(운영 리스크)

# 3) 노출/리스크 게이트(베타·섹터·단일종목·팻테일) 시스템 고정
### (a) 왜 필요한지
- 8~14개 종목은 **단일 종목/섹터 편향**이 생기면 “락박스에서 잘 보이는 운”이 나올 수 있음(서바이버십/레짐 편향).
- MDD 관리가 모델 성능보다 운영 지속성을 좌우.

### (b) 위험/부작용
- 노출 제한이 너무 강하면 알파가 줄고 “그냥 저베타”가 될 수 있음.
- 게이트가 과하면 후보들이 전부 FAIL(탐색 정지).

### (c) 최소 실험/점검 2~3개
**Primary-3 (48h 루프 투입)**  
- **실험 정의:** “포지션 사이징 표준화 + 하드 캡”  
  - 단일 종목 최대 비중(예: 12~18%) 하드캡  
  - 포트폴리오 목표 변동성(예: 연 10~14%)으로 스케일링(현금 비중 허용)  
  - (가능하면) 시장 베타 목표 범위(예: 0.2~0.8)로 gross 조절
- **게이트:**  
  - 단일종목 cap 위반 0  
  - realized beta/vol 목표 범위 이탈 비율(%) 상한 설정
- **기대 관측치:**  
  - worst_mdd 개선, 락박스 min(최악 구간) 완화, 성과가 약간 줄어도 “하방 안정성” 증가

**Secondary 점검-1**  
- “기여도 분해” 리포트: 락박스 수익의 상위 3종목 기여도/상위 5일 기여도 비중이 과도하면 경고(서바이버십/운빨 체크)

**Secondary 점검-2**  
- “Tail day 행동” 점검: -2σ 일에 포지션이 어떻게 변했는지(리밸런스가 악화시키는지) 로그화

### (d) PASS 조건
- **worst_mdd ≤ -0.0824(최근 PASS 후보 수준) 개선**을 1차 목표로  
- 락박스 mean이 Champion 대비 -0.005 이내면 허용(대신 MDD/최악구간 개선이 명확해야 함)

---

# 4) 레짐 관측(ETF는 지표만)으로 위험예산만 가변
### (a) 왜 필요한지
- Tech/Healthcare는 레짐이 뚜렷함(금리/리스크온오프/섹터 로테이션).
- 종목 선택 로직을 자주 갈아엎기보다, **“노출 크기(gross/net)”만 레짐에 따라 조절**하는 게 과최적화/운영 리스크가 낮음.
- ETF는 매매 금지(규칙), 대신 **관측 지표**로 활용.

### (b) 위험/부작용
- 레짐 신호가 늦으면 “늦게 줄이고 늦게 늘리는” 역효과.
- 지표가 많아지면 과최적화(레짐 분기 과다).

### (c) 최소 실험/점검 2~3개
**Primary-4 (48h 루프 투입)**  
- **실험 정의:** ETF 기반 레짐 1개만 써서 gross 스케일링(매매는 주식만)  
  - 예시 지표(택1, 1개만):  
    - `QQQ` 20/60일 모멘텀(또는 추세)  
    - `QQQ/XLV` 비율 추세(Tech vs Healthcare 상대강도)  
    - 변동성 프록시(예: `VIX` 지수 데이터가 있으면 사용, 없으면 관련 ETF는 “지표로만”)
  - 레짐이 risk-off면 gross 0.3~0.6배, risk-on이면 0.9~1.1배
- **게이트:**  
  - 레짐 분기 조건은 “1개 지표 + 1개 임계”로 고정(복잡도 제한)  
  - 레짐별 표본 수가 너무 적으면 FAIL(서브샘플 과최적화 방지)
- **기대 관측치:**  
  - lockbox_min 개선(꼬리 보호), worst_mdd 완화, 평균은 유지 또는 소폭 감소

**Secondary 점검-1**  
- 레짐별 성과표 자동 출력: risk-on/off에서 hit rate, avg win/loss, turnover 비교

**Secondary 점검-2**  
- 레짐 전환일 주변(±5일) 성과/거래량만 따로 집계(“전환이 성과를 망치는지” 확인)

### (d) PASS 조건
- lockbox_min(현재 -0.05344) **악화 금지**, 가능하면 개선  
- worst_mdd 개선 또는 동일 + 비용 포함 성과 방어

# 5) 운영 리스크: 재현성·드리프트·실패 안전장치(자동 루프에 편입)
### (a) 왜 필요한지
- 48시간 자동 루프에서 가장 큰 손실은 “성능”이 아니라 **잘못된 배포/재현 불가/데이터 갱신으로 인한 silent break**에서 발생.
- 특히 위 1)~4) 패치를 넣으면 파이프라인 변경이 잦아져 운영 리스크가 급증.

### (b) 위험/부작용
- 테스트/로깅이 과하면 속도가 느려져 탐색량이 줄어듦.
- 과도한 실패-중단은 후보가 안 나오는 상황을 만들 수 있음(게이트 밸런스 필요).

### (c) 최소 실험/점검 2~3개
**Secondary 점검-1 (추천: 즉시 적용, 후보 폭발 없음)**  
- “원클릭 재현성 번들” 고정: 데이터 스냅샷 해시 + 코드 커밋 + seed + 환경정보를 결과 json에 강제 기록

**Secondary 점검-2**  
- “데이터 드리프트 센티널”: 최근 N일(예: 60일)에서 가격 결측/급변/거래정지/스플릿 처리 이상치 카운트가 임계 넘으면 루프 중단 + 리포트

**Secondary 점검-3**  
- “주문 가능성 체크(모의)” : 선택된 8~14 종목에 대해 최소 유동성(거래대금 하한) 위반 시 경고/제외(운영 체결 리스크)

### (d) PASS 조건
- 재현성 해시 불일치 0
- 센티널 경고 발생 시 원인/티커/날짜가 자동 리포트에 포함(“침묵 실패” 금지)

## 48시간 루프에 실제로 태울 “Primary 4개” 요약(형식 통일)
1. **Primary-1 누수 차단(purged+asof+embargo)**  
   - 게이트: 타임라인 위반 0 / 재현성 OK  
   - 기대: 튜닝-락박스 괴리 감소, 과최적화 완화
2. **Primary-2 비용+턴오버 페널티**  
   - 게이트: turnover 상한 준수 / 비용 전후 리포트  
   - 기대: 비용 후 성과 방어 + 꼬리 개선
3. **Primary-3 포지션 캡+변동성 타게팅**  
   - 게이트: 단일종목 cap/beta/vol 이탈 제한  
   - 기대: worst_mdd 개선
4. **Primary-4 ETF(지표만) 레짐으로 gross 스케일링**  
   - 게이트: 지표 1개로 단순 분기 / 레짐 표본 수 충분  
   - 기대: lockbox_min·MDD 개선

# 성능이 안 움직일 때: 원인 분해(트리거/적용/노출/비용/레짐) “진단 트리”
아래 순서대로 **로그/리포트로 수치화**해서 어디가 막혔는지 한 번에 좁혀라.

## A. Trigger(신호가 발생하나?)
- **지표:** 리밸런스 시점별 “목표 포지션 변화량 L1”, 진입/청산 횟수, 8~14 종목 제약으로 인한 **선택 불가율**
- **증상→원인**
  - 거래가 거의 없음 → 게이트/비용/턴오버 페널티 과도, 신호 스케일이 너무 작음
  - 거래는 많은데 성과 정체 → 비용/슬리피지 미스, 신호 품질 낮음

## B. Apply(적용이 의도대로 되나? 실행·정렬·체결)
- **지표:** 신호 시각 vs 체결 시각, 가격 사용(종가/시가/중간가), 결측 대체 발생 횟수
- **증상→원인**
  - 특정 구간에서만 급락/급등 → 데이터 정렬 오류(lookahead) 또는 corporate action 처리 오류
  - 특정 요일/월말에만 과도한 거래 → 캘린더/리밸런스 스케줄 버그

## C. Exposure(노출이 수익을 먹고 있나?)
- **지표:** 포트폴리오 베타, 섹터(Tech/Healthcare) 비중, 상위 종목 기여도, 팩터(모멘텀/밸류/퀄리티) 근사 노출
- **증상→원인**
  - 수익이 상위 1~2종목에 과도 집중 → 서바이버십/운빨/레짐 편향 위험
  - 시장 급락일에 같이 크게 빠짐 → 베타 과다(헤지/현금 스케일 필요)

## D. Cost(비용이 알파를 상쇄하나?)
- **지표:** 비용 전/후 샤프, 비용이익비(Cost / Gross PnL), 턴오버·거래집중도
- **증상→원인**
  - 비용 전에는 좋은데 후에 무너짐 → 전략이 구조적으로 고빈도/저엣지

## 실행 순서(오늘 바로 적용 우선순위)
1) **Primary-1 누수 차단** 먼저 병합/실행(성능이 떨어져도 정상)  
2) 그 다음 **Primary-2 비용/턴오버**를 넣고 “비용 후 락박스”를 기준으로 재평가  
3) 그 다음 **Primary-3 리스크 캡/변동성 타게팅**으로 MDD를 먼저 안정화  
4) 마지막으로 **Primary-4 레짐 gross 스케일링**(지표 1개로 단순하게)

위 4개가 돌아가는 동안 Secondary 점검 리포트(서바이버십/기여도/드리프트/비용민감도)만 자동 생성되게 붙여서, “왜 안 움직이는지”를 수치로 바로 분해해라.
